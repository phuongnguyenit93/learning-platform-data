# Import Roadmap YAML into Oracle MODULE_ROADMAP

The importer `script/database/all-module/import-module-roadmaps.py` imports **one row per milestone**
from each source `module/**/content/roadmap/<lang>/roadmap.yml`. Only folders
with a real `master.json` are considered. Paths under `build/`, `backup/`,
`content/` (as nested traversal), `src/`, and other generated/vendor folders
are excluded. Files under `build/learning-data/` are never an import source.

## Database prerequisites

Run `learning-platform-backend/sql/06_module_roadmap.sql` in Oracle as the schema
owner after `03_module_structure.sql` and `04_language.sql`. The importer does
**not** create tables or update the structure/language catalogs.

It uses `master.json.SERVICE_NAME.VALUE` -> `MODULE_STRUCTURE.NODE_KEY` ->
`ID_STRUCTURE`. Only `NODE_TYPE = 'MODULE'` and active `LANGUAGE` values
are eligible. Missing modules, GROUPs and missing/inactive languages are SKIPs,
not automatic inserts into the catalogs.

For a separate importing user, grant `SELECT` on `MODULE_STRUCTURE` and
`LANGUAGE`, and `SELECT`, `INSERT`, `DELETE` on `MODULE_ROADMAP`.
UPDATE is not needed. Do not use the application's SELECT-only user.
Use `ORACLE_SCHEMA=LEARNING_PLATFORM` if the importer connects as another user.

## Install and configure (Windows)

```powershell
python -m pip install -r script/requirements-oracle-roadmap.txt
```

The script defaults to the same **untracked**
`learning-platform-data/.env.oracle-overview` file used by the Overview
importer (at `.env.oracle-overview` when working inside this repository).
Alternatively use `--env-file <path>` or set the
variables in the current process:

```dotenv
ORACLE_USER=YOUR_IMPORT_USER
ORACLE_PASSWORD=YOUR_PASSWORD
ORACLE_DSN=(description=(address=(protocol=tcps)(port=1521)(host=YOUR_ADB_HOST))(connect_data=(service_name=YOUR_SERVICE_NAME))(security=(ssl_server_dn_match=yes)))
# ORACLE_SCHEMA=LEARNING_PLATFORM
```

The DSN is a **python-oracledb Thin TLS** connection string (not
`jdbc:oracle:thin:@...`). No Instant Client is required for TLS. Do not commit
credentials, copy them into logs, or supply secrets as CLI arguments.

## Commands

```powershell
# No DB connection, validates source files and writes a JSON inventory:
python script/database/all-module/import-module-roadmaps.py --dry-run --offline

# Default: connects to Oracle, issues SELECTs only, previews actions:
python script/database/all-module/import-module-roadmaps.py --dry-run

# Restrict work to one MODULE_STRUCTURE.NODE_KEY and language:
python script/database/all-module/import-module-roadmaps.py --dry-run --module COLLABORATION_AZURE_DEVOPS --lang vi

# Explicitly modify Oracle after reviewing the report:
python script/database/all-module/import-module-roadmaps.py --apply --module COLLABORATION_AZURE_DEVOPS --lang vi

# All authored Roadmaps (only when intentionally requested):
python script/database/all-module/import-module-roadmaps.py --apply

# Show all options, including --module-root, --env-file and --report:
python script/database/all-module/import-module-roadmaps.py --help
```

Dry-run is the default. `--offline` never uses Oracle and is incompatible with
`--apply`. `--module` accepts an exact uppercase `NODE_KEY` (not a URL slug).
`--lang` is a language code such as `vi` or `en`. When no source matches
an explicit filter the script exits nonzero instead of silently succeeding.

## Mapping and replacement semantics

| Source | Oracle destination |
| --- | --- |
| `master.json.SERVICE_NAME.VALUE` | Resolve `ID_STRUCTURE` via `NODE_KEY` |
| `content/roadmap/vi/roadmap.yml` | `LANGUAGE_CODE = 'vi'` |
| `roadmap[*].title` | `TITLE` |
| `roadmap[*].purpose` | `PURPOSE` |
| `roadmap[*].objectives` | `OBJECTIVE`, newline-separated |
| Position in `roadmap` array | `SORT_ORDER`, 1-based |
| Not in YAML | `ID_ROADMAP` generated by Oracle Identity |

YAML milestone `id` is validated for presence and uniqueness in its file,
but intentionally **not stored** in Oracle. The importer ignores
`dependsOn`, `relatedKnowledge` and `relatedModules` because those fields
are not in the backend table.

Because there is no stable milestone key, import **does not MERGE by title or
array position**. Each module/language is compared as an ordered list
(`TITLE`, `PURPOSE`, `OBJECTIVE`, `SORT_ORDER`):

- `INSERT`: no existing milestones; batch-insert all source milestones.
- `REPLACE`: existing list differs; delete all rows for only that
  `(ID_STRUCTURE, LANGUAGE_CODE)`, then insert the complete new list.
- `UNCHANGED`: lists match; perform no writes, preserving `ID_ROADMAP`.
- `SKIP_EMPTY`: `roadmap: []` or empty/comment-only YAML; **do not delete**
  any existing Oracle rows. Missing files likewise never remove data.
- `SKIP_*`: missing module, GROUP node or missing/inactive language; no writes.

The `--apply` transaction covers **all actionable module/language pairs**;
an error rolls back all changes. It locks/rechecks the module, language and
existing Roadmap rows before replacing them and aborts if the existing rows
have changed since preflight. Direct concurrent writers outside this protocol
should still be avoided.

**Important:** When content changes, replace generates new `ID_ROADMAP` values.
Do not reference those IDs from durable progress/bookmark tables unless the
design changes. The importer only updates Roadmap; it never modifies YAML,
`MODULE_STRUCTURE`, or `LANGUAGE`.

Each nonblank YAML objective must be a single line so the API can split
`OBJECTIVE` by line. The importer validates `VARCHAR2` character limits
(`TITLE` 300, `PURPOSE` 1000, `OBJECTIVE` 2000) and the conservative
4000-byte limit for Oracle `MAX_STRING_SIZE=STANDARD`.

## Reports and tests

JSON reports are written atomically to
`build/reports/module-roadmap-import.json` (or `--report <path>`).
Reports contain paths, statuses, milestone counts and content SHA-256, **not**
YAML text or database credentials. `READY_LOCAL_ONLY` does not mean a DB
row exists. DRY_RUN makes zero database writes.

```powershell
python -m unittest script/tests/test_import_module_roadmaps.py -v
```

Integration with Oracle must be tested separately using an authorized import
user. No test connects to a live Oracle database.
