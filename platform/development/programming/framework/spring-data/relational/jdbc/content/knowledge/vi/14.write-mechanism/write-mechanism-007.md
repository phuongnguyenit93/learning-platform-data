# @ReadOnlyProperty cho dữ liệu chỉ đọc từ cơ sở dữ liệu

Trong **Spring Data Relational JDBC (Spring Data JDBC)**, có những thuộc tính cần được đọc từ cơ sở dữ liệu nhưng không nên được ứng dụng ghi trực tiếp. Ví dụ: giá trị được tính bằng generated column, thời điểm do trigger cập nhật, hoặc trường do một quy trình bên ngoài quản lý. Annotation **`@ReadOnlyProperty`** đánh dấu một thuộc tính theo đúng mục đích đó: Spring Data JDBC vẫn ánh xạ thuộc tính khi đọc entity, nhưng không đưa thuộc tính vào thao tác ghi khi lưu entity.

Annotation này hữu ích khi database là nơi sở hữu giá trị cuối cùng. Nó giúp tránh việc ứng dụng vô tình ghi đè giá trị do database tạo, đồng thời cho phép entity vẫn hiển thị giá trị đó sau khi đọc lại.

## 1. Ý nghĩa của @ReadOnlyProperty

`@ReadOnlyProperty` thuộc package `org.springframework.data.annotation`:

~~~java
import org.springframework.data.annotation.ReadOnlyProperty;
~~~

Hãy hiểu hợp đồng của annotation qua hai chiều:

| Hoạt động | Hành vi đối với thuộc tính có `@ReadOnlyProperty` |
|---|---|
| Đọc entity từ database | Thuộc tính vẫn được ánh xạ từ cột tương ứng |
| Insert entity | Thuộc tính không được ghi vào câu INSERT |
| Update entity | Thuộc tính không được ghi vào câu UPDATE |
| Đọc lại sau khi database tự tính/cập nhật | Giá trị mới được lấy từ database khi entity được đọc |

Ví dụ, bảng `products` có cột `stock_value` do database tính từ `unit_price * stock_quantity`. Java entity cần hiển thị `stockValue`, nhưng không được gửi giá trị đó trong câu INSERT/UPDATE.

~~~mermaid
flowchart TB
    App["Application<br/>Product fields"]
    Repo["ProductRepository.save(product)"]
    Write["INSERT / UPDATE<br/>không ghi stock_value"]
    DB[("Database")]
    Calc["Generated column / trigger<br/>tạo giá trị stock_value"]
    Read["SELECT product"]
    Entity["Product.stockValue<br/>được ánh xạ khi đọc"]

    App --> Repo --> Write --> DB
    DB --> Calc
    Calc --> DB
    DB --> Read --> Entity
~~~

`@ReadOnlyProperty` là **chỉ dẫn ánh xạ ở tầng Spring Data**. Nó không tạo generated column, không tạo trigger, không tự cấp quyền chỉ đọc ở database và không ngăn code Java thay đổi field trong bộ nhớ.

## 2. Trường hợp sử dụng phù hợp

Một số loại dữ liệu thường do database quản lý:

| Dữ liệu | Nơi tạo/cập nhật | Vì sao đánh dấu read-only |
|---|---|---|
| Giá trị tổng từ giá đơn vị × số lượng | Generated column | Ứng dụng không nên tự ghi lại giá trị đã tính |
| Thời điểm tạo bản ghi | Default `CURRENT_TIMESTAMP` hoặc trigger | Database cung cấp thời điểm chính thức |
| Thời điểm cập nhật gần nhất | Trigger khi UPDATE | Mọi nguồn ghi đều dùng cùng quy tắc |
| Giá trị chuẩn hóa từ các cột khác | Generated column/view | Không cho ứng dụng gửi giá trị không nhất quán |
| Số liệu tổng hợp từ view | View hoặc truy vấn database | Entity cần đọc kết quả nhưng không sở hữu việc ghi |

Không phải mọi trường không cho người dùng sửa đều cần `@ReadOnlyProperty`. Nếu ứng dụng vẫn là chủ thể ghi giá trị, hãy dùng quy tắc domain, DTO đầu vào, validation hoặc phân quyền phù hợp. Annotation này dành cho trường hợp **Spring Data JDBC không được ghi thuộc tính đó**.

## 3. Ví dụ: cột stock_value do database tính

Giả sử một sản phẩm có giá đơn vị `unit_price` và số lượng tồn `stock_quantity`. Giá trị tồn kho quy đổi `stock_value` luôn bằng tích của hai trường nguồn:

\[
\text{stockValue} = \text{unitPrice} \times \text{stockQuantity}
\]

Ứng dụng chỉ thay đổi giá đơn vị hoặc số lượng; database tự tính tổng.

### PostgreSQL

~~~sql
CREATE TABLE products (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    sku VARCHAR(40) NOT NULL UNIQUE,
    unit_price NUMERIC(12, 2) NOT NULL
        CHECK (unit_price >= 0),
    stock_quantity INTEGER NOT NULL
        CHECK (stock_quantity >= 0),
    stock_value NUMERIC(14, 2)
        GENERATED ALWAYS AS (unit_price * stock_quantity) STORED
);
~~~

### MySQL 8.4

~~~sql
CREATE TABLE products (
    id BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY,
    sku VARCHAR(40) NOT NULL UNIQUE,
    unit_price DECIMAL(12, 2) NOT NULL,
    stock_quantity INTEGER NOT NULL,
    stock_value DECIMAL(14, 2)
        GENERATED ALWAYS AS (unit_price * stock_quantity) STORED,
    CONSTRAINT ck_product_price CHECK (unit_price >= 0),
    CONSTRAINT ck_product_stock CHECK (stock_quantity >= 0)
) ENGINE=InnoDB;
~~~

Hai đoạn DDL là hai phương án thay thế nhau, không chạy cả hai trên cùng database. PostgreSQL và MySQL có cú pháp/chi tiết generated column khác nhau; ví dụ này sử dụng kiểu **STORED** để kết quả được lưu và tính lại khi các cột nguồn thay đổi.

Vì `stock_value` là generated column, câu INSERT/UPDATE không được tự truyền giá trị cho nó. Nếu ứng dụng gửi một giá trị vào cột này, database có thể từ chối thao tác. Đây chính là lúc `@ReadOnlyProperty` giúp mapping không cố ghi cột đó.

## 4. Ánh xạ Product bằng Spring Data JDBC

~~~java
package com.example.inventory;

import java.math.BigDecimal;

import org.springframework.data.annotation.Id;
import org.springframework.data.annotation.ReadOnlyProperty;
import org.springframework.data.relational.core.mapping.Column;
import org.springframework.data.relational.core.mapping.Table;

@Table("products")
public class Product {

    @Id
    private Long id;

    private String sku;

    @Column("unit_price")
    private BigDecimal unitPrice;

    @Column("stock_quantity")
    private int stockQuantity;

    @ReadOnlyProperty
    @Column("stock_value")
    private BigDecimal stockValue;

    protected Product() {
        // Dành cho Spring Data JDBC.
    }

    public Product(String sku, BigDecimal unitPrice, int stockQuantity) {
        if (sku == null || sku.isBlank()) {
            throw new IllegalArgumentException("SKU is required");
        }
        if (unitPrice == null || unitPrice.signum() < 0) {
            throw new IllegalArgumentException("Invalid unit price");
        }
        if (stockQuantity < 0) {
            throw new IllegalArgumentException("Invalid stock quantity");
        }
        this.sku = sku;
        this.unitPrice = unitPrice;
        this.stockQuantity = stockQuantity;
    }

    public Long getId() {
        return id;
    }

    public String getSku() {
        return sku;
    }

    public BigDecimal getUnitPrice() {
        return unitPrice;
    }

    public int getStockQuantity() {
        return stockQuantity;
    }

    public BigDecimal getStockValue() {
        return stockValue;
    }

    public void changeStockQuantity(int quantity) {
        if (quantity < 0) {
            throw new IllegalArgumentException("Quantity must be non-negative");
        }
        this.stockQuantity = quantity;
    }
}
~~~

Repository:

~~~java
package com.example.inventory;

import org.springframework.data.repository.CrudRepository;

public interface ProductRepository
        extends CrudRepository<Product, Long> {
}
~~~

`@ReadOnlyProperty` được đặt trên `stockValue`. Các thuộc tính `sku`, `unitPrice` và `stockQuantity` vẫn được ghi bình thường. Điều này có nghĩa annotation chỉ tác động đến **một property**, không biến toàn bộ Product thành entity chỉ đọc.

### Lưu mới

~~~java
Product product = new Product(
    "BOOK-01",
    new BigDecimal("150000.00"),
    4
);

Product saved = productRepository.save(product);
Long productId = saved.getId();
~~~

Khi insert, Spring Data JDBC ghi các trường có thể ghi như `sku`, `unit_price` và `stock_quantity`. `stock_value` bị loại khỏi phần ghi; database tính giá trị từ hai cột nguồn.

### Đọc lại giá trị do database tính

~~~java
Product loaded = productRepository.findById(productId)
    .orElseThrow();

System.out.println(loaded.getStockValue()); // 600000.00
~~~

Khi đọc, `stock_value` vẫn được ánh xạ vào `Product.stockValue`. Annotation không làm thuộc tính biến mất khỏi SELECT/mapping.

**Lưu ý về giá trị trả về của save:** `@ReadOnlyProperty` quy định property không được ghi. Không nên suy ra rằng mọi giá trị do trigger/generated column tạo ra sẽ tự động được tải lại vào chính instance trả về từ `save`. Nếu use case cần giá trị database vừa tính ngay sau insert/update, hãy đọc lại entity bằng repository hoặc dùng truy vấn đọc tường minh sau khi thao tác ghi, trong transaction phù hợp.

## 5. Cập nhật các cột nguồn

Giả sử tồn kho thay đổi từ 4 lên 7:

~~~java
Product current = productRepository.findById(productId)
    .orElseThrow();

current.changeStockQuantity(7);
Product saved = productRepository.save(current);

// Khi cần giá trị stock_value mới nhất, đọc lại từ DB.
Product refreshed = productRepository.findById(productId)
    .orElseThrow();

System.out.println(refreshed.getStockValue()); // 1050000.00
~~~

Spring Data JDBC ghi thay đổi của `stockQuantity`. Cột `stock_value` được database tính lại theo generated-column expression. Khi đọc lại, framework ánh xạ giá trị mới.

Không thêm setter công khai cho `stockValue` chỉ để cho phép controller truyền giá trị vào. Domain chỉ cần cho phép thay đổi các thành phần nguồn; giá trị tính toán do database sở hữu.

## 6. Database default và trigger cũng có thể tạo dữ liệu read-only

Generated column là một trường hợp rõ ràng, nhưng annotation còn phù hợp với giá trị do default hoặc trigger quản lý.

### created_at do database cấp khi insert

PostgreSQL:

~~~sql
CREATE TABLE audit_records (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    event_name VARCHAR(100) NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE NOT NULL
        DEFAULT CURRENT_TIMESTAMP
);
~~~

Entity:

~~~java
import java.time.OffsetDateTime;
import org.springframework.data.annotation.Id;
import org.springframework.data.annotation.ReadOnlyProperty;
import org.springframework.data.relational.core.mapping.Column;
import org.springframework.data.relational.core.mapping.Table;

@Table("audit_records")
public class AuditRecord {

    @Id
    private Long id;

    private String eventName;

    @ReadOnlyProperty
    @Column("created_at")
    private OffsetDateTime createdAt;
}
~~~

Ứng dụng không gửi `created_at`; database áp dụng default khi insert. Khi đọc bản ghi, `createdAt` được ánh xạ từ cột.

### updated_at do trigger cập nhật

Một số hệ thống cần mọi nguồn ghi đều cập nhật `updated_at`. Có thể dùng trigger ở database. Ví dụ PostgreSQL:

~~~sql
CREATE TABLE inventory_notes (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    note TEXT NOT NULL,
    updated_at TIMESTAMP WITH TIME ZONE NOT NULL
        DEFAULT CURRENT_TIMESTAMP
);

CREATE FUNCTION set_inventory_note_updated_at()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = CURRENT_TIMESTAMP;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_inventory_note_updated_at
BEFORE UPDATE ON inventory_notes
FOR EACH ROW
EXECUTE FUNCTION set_inventory_note_updated_at();
~~~

Trong entity, `updatedAt` có thể được đánh dấu `@ReadOnlyProperty` để Spring Data JDBC không ghi đè giá trị do trigger quản lý. Khi cần thời điểm cập nhật mới nhất ngay trong response, đọc lại bản ghi sau thao tác update.

**Default và trigger có ngữ nghĩa khác nhau:** default thường áp dụng khi insert bỏ qua cột; trigger có thể can thiệp vào mỗi lần update. Nếu ứng dụng gửi `NULL` tường minh, default không nhất thiết được áp dụng. Với trigger, database có thể thay giá trị ngay cả khi câu UPDATE không ghi cột `updated_at`.

## 7. @ReadOnlyProperty khác gì @Transient, @Id và @Column?

Các annotation có mục đích khác nhau:

| Annotation | Vai trò | Property có được đọc từ DB? | Property có được ghi? |
|---|---|---|---|
| `@ReadOnlyProperty` | Ánh xạ đọc, loại khỏi thao tác ghi | Có | Không |
| `@Transient` (Spring Data) | Loại property khỏi persistence mapping | Không qua mapping thông thường | Không |
| `@Id` | Đánh dấu khóa chính | Có | Phụ thuộc cơ chế ID/newness và generated ID |
| `@Column` | Khai báo tên cột | Có | Có, nếu không có chỉ dẫn loại trừ ghi khác |
| `@Version` | Quản lý optimistic locking | Có | Framework quản lý phiên bản |

Ví dụ, nếu `stockValue` đánh dấu `@Transient`, Spring Data JDBC không xem nó là cột cần đọc/ghi thông thường. Khi đánh dấu `@ReadOnlyProperty`, framework vẫn đọc `stock_value` nhưng không ghi property đó.

Không nhầm `@ReadOnlyProperty` với annotation `@Column(insertable = false, updatable = false)` của JPA. Spring Data JDBC dùng annotation riêng của Spring Data Relational; không mang các thuộc tính cấu hình của JPA sang đây.

## 8. @ReadOnlyProperty không phải bảo vệ quyền ghi ở database

Annotation chỉ ảnh hưởng cách Spring Data JDBC tạo thao tác ghi cho property được đánh dấu. Các đường ghi khác vẫn có thể thay đổi cột:

- SQL chạy trực tiếp từ công cụ quản trị.
- Một ứng dụng khác sử dụng JDBC.
- Stored procedure hoặc trigger.
- Một repository/custom SQL khác không áp dụng cùng mapping.

Nếu yêu cầu bảo mật là **ứng dụng không có quyền UPDATE một cột hoặc bảng**, phải dùng quyền database, view, stored procedure hoặc kiến trúc phân quyền tương ứng. Không dựa vào annotation như một ranh giới bảo mật.

Tương tự, field Java vẫn có thể bị thay đổi trong bộ nhớ nếu có setter hoặc code nội bộ. Việc Spring Data JDBC bỏ qua property khi ghi không đồng nghĩa Java object là immutable.

## 9. Dùng entity cho database view

Một view có thể cung cấp dữ liệu tổng hợp để đọc:

~~~sql
CREATE VIEW product_stock_summary AS
SELECT
    id,
    sku,
    stock_quantity,
    unit_price * stock_quantity AS stock_value
FROM products;
~~~

Entity đọc view có thể ánh xạ cột tính toán bằng `@ReadOnlyProperty`:

~~~java
import java.math.BigDecimal;
import org.springframework.data.annotation.Id;
import org.springframework.data.annotation.ReadOnlyProperty;
import org.springframework.data.relational.core.mapping.Column;
import org.springframework.data.relational.core.mapping.Table;

@Table("product_stock_summary")
public class ProductStockSummary {

    @Id
    private Long id;

    private String sku;

    @Column("stock_quantity")
    private Integer stockQuantity;

    @ReadOnlyProperty
    @Column("stock_value")
    private BigDecimal stockValue;
}
~~~

Trong thực tế, view có thể không updatable hoặc chỉ updatable theo những điều kiện nhất định tùy database. Đánh dấu một property read-only **không làm các property còn lại của entity trở thành read-only**. Nếu view chỉ dành cho đọc, không expose thao tác `save`/`delete` qua repository CRUD thông thường; dùng repository truy vấn riêng, projection hoặc quyền database chỉ đọc.

## 10. Ảnh hưởng tới aggregate và object con

`@ReadOnlyProperty` có thể áp dụng cho property ở entity/aggregate được Spring Data JDBC ánh xạ. Khi đánh dấu một trường tính toán trong aggregate root, các trường khác của root vẫn được ghi. Nếu một aggregate có collection con, annotation trên property của root không tự biến toàn bộ collection thành read-only.

Ví dụ:

~~~java
import java.util.List;
import org.springframework.data.annotation.Id;
import org.springframework.data.annotation.ReadOnlyProperty;
import org.springframework.data.relational.core.mapping.Column;
import org.springframework.data.relational.core.mapping.MappedCollection;
import org.springframework.data.relational.core.mapping.Table;

@Table("orders")
public class Order {

    @Id
    private Long id;

    private String status;

    @ReadOnlyProperty
    @Column("item_count")
    private Integer itemCount;

    @MappedCollection(idColumn = "order_id")
    private List<OrderItem> items;
}
~~~

Nếu `item_count` do trigger hoặc generated column quản lý, property này không được Spring Data JDBC ghi. Tuy nhiên, danh sách `items` vẫn được lưu theo mapping aggregate bình thường. Cần xem xét cách database tính `item_count` và cách đọc lại sau khi thay đổi collection.

Không sử dụng `@ReadOnlyProperty` để che giấu một mô hình aggregate không rõ ràng. Nếu giá trị là một phần của bất biến nghiệp vụ và cần được tính trong domain trước khi ghi, có thể để domain tự tính và lưu như property ghi bình thường. Chỉ giao quyền tạo giá trị cho database khi database thực sự là nơi sở hữu phép tính hoặc quy tắc đó.

## 11. Kiểm tra SQL thực tế

Khi làm việc với `@ReadOnlyProperty`, hãy xác minh cả câu lệnh ghi và dữ liệu đọc:

1. Tạo entity mới với các cột nguồn.
2. Lưu qua repository.
3. Kiểm tra generated column có giá trị trong database.
4. Đọc lại entity và kiểm tra property read-only được ánh xạ.
5. Cập nhật cột nguồn, lưu lại và kiểm tra database tính lại giá trị.

Ví dụ SQL:

~~~sql
SELECT
    id,
    sku,
    unit_price,
    stock_quantity,
    stock_value
FROM products
ORDER BY id;
~~~

Nếu cần quan sát SQL do Spring Data JDBC thực thi, có thể bật log phù hợp cho package Spring JDBC/Relational trong môi trường phát triển. Tên logger và chi tiết câu lệnh có thể thay đổi theo phiên bản; không dựa vào log ở production nếu nó có thể tiết lộ dữ liệu nhạy cảm.

## 12. Những lỗi thường gặp

| Lỗi | Hệ quả | Cách xử lý |
|---|---|---|
| Đánh dấu `@ReadOnlyProperty` nhưng không có generated column/default/trigger | Giá trị đọc có thể luôn null hoặc không đổi | Đảm bảo database thực sự tạo/cập nhật giá trị |
| Không đánh dấu property generated | Spring Data JDBC cố ghi giá trị vào cột do DB quản lý và có thể bị từ chối | Đánh dấu property bằng `@ReadOnlyProperty` |
| Nghĩ property read-only không được đọc | Entity không nhận giá trị từ SELECT | Nhớ rằng annotation chỉ loại khỏi ghi, không loại khỏi đọc |
| Kỳ vọng `save()` luôn trả giá trị computed mới | Instance trả về có thể chưa được refresh từ DB | Đọc lại entity hoặc chạy query đọc sau khi ghi |
| Dùng annotation như cơ chế bảo mật | Đường ghi khác vẫn có thể sửa cột | Thiết lập quyền database/view và kiểm soát các writer |
| Đánh dấu toàn entity read-only bằng một field annotation | Các property khác vẫn có thể bị ghi | Annotation áp dụng theo property; thiết kế repository/query-only nếu toàn entity chỉ đọc |
| Dùng `@Transient` thay cho `@ReadOnlyProperty` | Property không được ánh xạ từ DB | Dùng đúng annotation theo mục đích |
| Dùng kiểu Java primitive cho cột generated nullable | Không biểu diễn được SQL NULL | Dùng wrapper/reference type nếu cột có thể null |
| Tự tính lại computed property trong Java và ghi vào DB | Có hai nguồn sự thật, có thể lệch nhau | Chọn một nơi sở hữu phép tính và giữ nhất quán |

## 13. Bài thực hành

1. Tạo bảng `products` với `stock_value` là generated column trên PostgreSQL hoặc MySQL.
2. Tạo entity Product có `@ReadOnlyProperty` trên `stockValue` và repository CRUD.
3. Insert một sản phẩm giá 150.000, số lượng 4. Đọc lại và xác nhận stock value là 600.000.
4. Thay số lượng thành 7, gọi save và đọc lại. Xác nhận stock value là 1.050.000.
5. Bỏ `@ReadOnlyProperty` trong môi trường thực hành, thử ghi một entity. Quan sát database phản ứng khi Spring Data JDBC cố ghi generated column.
6. Tạo trường `createdAt` có default CURRENT_TIMESTAMP. Đánh dấu read-only và so sánh giá trị database với entity sau khi đọc lại.
7. Tạo view `product_stock_summary` và entity đọc view. Xác định vì sao không nên dùng CRUD repository thông thường để cập nhật view chỉ đọc.
8. Thảo luận: trường nào nên được tính ở domain service và trường nào nên giao cho database? Nêu lợi ích và rủi ro khi có hai nguồn tính toán.

## 14. Ghi nhớ

`@ReadOnlyProperty` cho Spring Data JDBC biết rằng một property **vẫn cần được đọc từ database nhưng không được ghi khi insert/update qua mapping đó**. Đây là lựa chọn phù hợp cho generated column, dữ liệu do trigger/default quản lý và một số giá trị đọc từ view.

Annotation không tự tạo giá trị trong database, không refresh mọi giá trị computed ngay sau `save`, không làm entity immutable và không thay thế quyền chỉ đọc ở database. Hãy thiết kế DDL để database thật sự tạo giá trị, đánh dấu property trong entity, và đọc lại khi use case cần giá trị mới nhất sau khi ghi.
