# Kết hợp `And`, `Or` và cách hiểu độ ưu tiên điều kiện

Trong **Spring Data JDBC**, tên phương thức repository có thể kết hợp nhiều điều kiện bằng các từ khóa `And` và `Or`. Spring Data phân tích tên method, nhận diện property của entity và tạo truy vấn SQL tương ứng. Khi một method có cả hai từ khóa, cách nhóm điều kiện quyết định bản ghi nào được trả về.

Quy tắc quan trọng cần nắm là: **các điều kiện nối bằng `And` được nhóm thành từng cụm; các cụm đó được nối với nhau bằng `Or`**. Vì vậy, một method như `findByStatusAndPriorityOrAssignedTeam` có ý nghĩa:

```text
(status = ? AND priority = ?) OR assignedTeam = ?
```

Đây cũng phù hợp với độ ưu tiên toán tử SQL thông dụng: `AND` được đánh giá trước `OR`. Tuy nhiên, khi biểu thức nghiệp vụ cần một cách nhóm khác, tên method không cung cấp cú pháp ngoặc tùy ý. Khi đó nên dùng `@Query` với dấu ngoặc rõ ràng.

## 1. Ví dụ xuyên suốt: tìm phiếu hỗ trợ

Giả sử hệ thống có các phiếu hỗ trợ (`SupportTicket`). Mỗi phiếu có trạng thái, mức ưu tiên và nhóm phụ trách.

DDL minh họa:

```sql
CREATE TABLE support_tickets (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    title VARCHAR(180) NOT NULL,
    status VARCHAR(30) NOT NULL,
    priority VARCHAR(20) NOT NULL,
    assigned_team VARCHAR(60) NOT NULL
);
```

Entity:

```java
import org.springframework.data.annotation.Id;
import org.springframework.data.relational.core.mapping.Table;

@Table("support_tickets")
public record SupportTicket(
        @Id Long id,
        String title,
        String status,
        String priority,
        String assignedTeam
) {}
```

Với naming strategy mặc định, `assignedTeam` được ánh xạ thành cột `assigned_team`. Trong tên method derived query, ta dùng **property Java** `assignedTeam`; trong SQL viết tay, ta dùng **tên cột vật lý** `assigned_team`.

Repository:

```java
import java.util.List;
import org.springframework.data.repository.ListCrudRepository;

public interface SupportTicketRepository
        extends ListCrudRepository<SupportTicket, Long> {

    List<SupportTicket> findByStatusAndPriorityOrAssignedTeam(
            String status,
            String priority,
            String assignedTeam
    );
}
```

Spring Data không cần ta tự viết implementation cho method này. Khi khởi tạo repository, framework phân tích tên method và tạo query phù hợp với metadata của `SupportTicket`.

## 2. `And`: tất cả điều kiện trong cụm phải đúng

Method:

```java
List<SupportTicket> findByStatusAndPriority(
        String status,
        String priority
);
```

Ý nghĩa logic:

```text
status = :status AND priority = :priority
```

SQL có ý nghĩa tương đương:

```sql
SELECT id, title, status, priority, assigned_team
FROM support_tickets
WHERE status = ?
  AND priority = ?;
```

Nếu gọi:

```java
repository.findByStatusAndPriority("OPEN", "HIGH");
```

thì một phiếu chỉ được chọn khi **đồng thời** có `status = 'OPEN'` và `priority = 'HIGH'`. Nếu một trong hai điều kiện sai, phiếu không nằm trong kết quả.

`And` phù hợp khi một use case yêu cầu nhiều tiêu chí cùng được đáp ứng, ví dụ “phiếu đang mở và có mức ưu tiên cao”.

## 3. `Or`: chỉ cần một nhánh đúng

Method:

```java
List<SupportTicket> findByStatusOrAssignedTeam(
        String status,
        String assignedTeam
);
```

Ý nghĩa:

```text
status = :status OR assignedTeam = :assignedTeam
```

SQL tương đương:

```sql
SELECT id, title, status, priority, assigned_team
FROM support_tickets
WHERE status = ?
   OR assigned_team = ?;
```

Với lời gọi:

```java
repository.findByStatusOrAssignedTeam("OPEN", "OPS");
```

phiếu được trả về nếu đang mở **hoặc** thuộc nhóm `OPS`, kể cả khi chỉ một trong hai điều kiện đúng. Nếu cả hai cùng đúng, một hàng vẫn chỉ xuất hiện một lần trong kết quả SQL thông thường.

## 4. Khi kết hợp cả `And` và `Or`

Đây là phần dễ gây nhầm lẫn nhất. Spring Data phân tích derived query thành các nhóm `OrPart`; mỗi nhóm chứa một hoặc nhiều điều kiện `Part` nối với nhau bằng `And`.

Ví dụ:

```java
List<SupportTicket> findByStatusAndPriorityOrAssignedTeam(
        String status,
        String priority,
        String assignedTeam
);
```

Biểu thức được nhóm thành:

```text
(status = :status AND priority = :priority)
OR
(assignedTeam = :assignedTeam)
```

Hay viết gọn:

```text
A AND B OR C
```

được hiểu là:

```text
(A AND B) OR C
```

SQL có ý nghĩa tương đương:

```sql
SELECT id, title, status, priority, assigned_team
FROM support_tickets
WHERE (status = ? AND priority = ?)
   OR assigned_team = ?;
```

Trong SQL thực tế do framework sinh ra, dấu ngoặc có thể được thể hiện khác nhau; điều cần giữ là **ngữ nghĩa nhóm điều kiện**. SQL chuẩn đánh giá `AND` trước `OR`, nên biểu thức không có ngoặc `status = ? AND priority = ? OR assigned_team = ?` cũng có cùng kết quả.

## 5. Độ ưu tiên: `And` được nhóm trước `Or`

Có thể ghi nhớ quy tắc bằng bảng:

| Tên method | Cách nhóm | Ý nghĩa |
|---|---|---|
| `findByAAndBOrC` | `(A AND B) OR C` | Cả A và B đúng, hoặc C đúng |
| `findByAOrBAndC` | `A OR (B AND C)` | A đúng, hoặc cả B và C đúng |
| `findByAAndBOrCAndD` | `(A AND B) OR (C AND D)` | Một trong hai nhóm điều kiện cùng đúng |
| `findByAOrBOrC` | `A OR B OR C` | Ít nhất một điều kiện đúng |
| `findByAAndBAndC` | `A AND B AND C` | Tất cả điều kiện đều đúng |

Điều này tương ứng với cấu trúc phân tích tên method: mỗi cụm `And` được tạo thành một nhóm, sau đó các nhóm được nối bằng `Or`. Nó cũng phù hợp với quy tắc precedence trong SQL thông dụng: `AND` cao hơn `OR`.

### Ví dụ ngược dễ nhầm

Method:

```java
List<SupportTicket> findByStatusOrPriorityAndAssignedTeam(
        String status,
        String priority,
        String assignedTeam
);
```

**Không** được hiểu là:

```text
(status = :status OR priority = :priority)
AND assignedTeam = :assignedTeam
```

Nó được hiểu là:

```text
status = :status
OR
(priority = :priority AND assignedTeam = :assignedTeam)
```

SQL tương đương:

```sql
WHERE status = ?
   OR (priority = ? AND assigned_team = ?)
```

Vì vậy, khi đọc method có cả hai từ khóa, không nên đọc từ trái sang phải như thể mọi toán tử có cùng độ ưu tiên. Hãy tách thành các cụm `And`, rồi xem các cụm đó được nối bởi `Or` như thế nào.

## 6. Minh họa bằng dữ liệu và kết quả

Giả sử các hàng sau đang có trong bảng:

| id | status | priority | assigned_team |
|---:|---|---|---|
| 1 | OPEN | HIGH | APP |
| 2 | OPEN | LOW | OPS |
| 3 | CLOSED | HIGH | OPS |
| 4 | CLOSED | LOW | APP |
| 5 | OPEN | HIGH | OPS |

Với điều kiện `status = 'OPEN'`, `priority = 'HIGH'`, `assignedTeam = 'OPS'`:

```text
(status = OPEN AND priority = HIGH) OR assignedTeam = OPS
```

Kết quả gồm:

- ID 1: `OPEN AND HIGH` đúng.
- ID 2: nhánh đầu sai, nhưng `assignedTeam = OPS` đúng.
- ID 3: nhánh đầu sai, nhưng `assignedTeam = OPS` đúng.
- ID 5: cả hai nhánh đều đúng; hàng vẫn chỉ xuất hiện một lần.

ID 4 không thỏa nhánh nào nên không được trả về.

Nếu dùng cách nhóm khác:

```text
(status = OPEN OR priority = HIGH) AND assignedTeam = OPS
```

thì kết quả chỉ gồm ID 2, ID 3 và ID 5. ID 1 bị loại vì không thuộc nhóm `OPS`, dù thỏa `status = OPEN OR priority = HIGH`. Đây là khác biệt nghiệp vụ đáng kể chỉ do vị trí dấu ngoặc.

## 7. Tên property trong method và thứ tự tham số

Tên method được phân tích theo **property của entity**, không theo tên cột SQL. Với entity:

```java
public record SupportTicket(
        @Id Long id,
        String title,
        String status,
        String priority,
        String assignedTeam
) {}
```

method dùng `findByAssignedTeam`, không dùng `findByAssigned_team`. Nếu property Java là `assignedTeam`, metadata sẽ ánh xạ nó sang `assigned_team` theo naming strategy.

Thứ tự tham số đi theo thứ tự các property xuất hiện trong tên method:

```java
findByStatusAndPriorityOrAssignedTeam(status, priority, assignedTeam)
```

Các tham số lần lượt tương ứng với `status`, `priority`, `assignedTeam`. Khi method có nhiều điều kiện, đặt tên biến tham số rõ ràng và xuống dòng chữ ký để người đọc dễ đối chiếu.

Nếu tên property có thể bị phân tích mơ hồ thành property path, có thể dùng dấu gạch dưới `_` theo quy tắc property traversal của Spring Data để phân tách đường dẫn. Với bài toán `And`/`Or` cơ bản, hãy ưu tiên tên property rõ ràng, tránh tên method quá dài hoặc chứa nhiều đoạn có thể gây nhầm lẫn.

## 8. Khi tên method không diễn đạt được nhóm điều kiện mong muốn

Tên derived query hỗ trợ kết hợp `And` và `Or`, nhưng không phải ngôn ngữ biểu thức Boolean đầy đủ. Nó không có cú pháp ngoặc tùy ý như:

```text
(A OR B) AND (C OR D)
```

Nếu viết:

```java
findByStatusOrPriorityAndAssignedTeam(...)
```

thì kết quả là `A OR (B AND C)`, không phải `(A OR B) AND C`. Không thể chèn dấu ngoặc vào tên method để thay đổi cách nhóm.

Khi yêu cầu nghiệp vụ cần nhóm rõ ràng, hãy dùng `@Query` để viết SQL và đặt ngoặc trực tiếp.

Ví dụ muốn tìm phiếu có **status OPEN hoặc priority HIGH, đồng thời thuộc nhóm OPS**:

```java
import java.util.List;
import org.springframework.data.jdbc.repository.query.Query;
import org.springframework.data.repository.query.Param;

public interface SupportTicketRepository
        extends ListCrudRepository<SupportTicket, Long> {

    @Query("""
        SELECT id, title, status, priority, assigned_team
        FROM support_tickets
        WHERE (status = :status OR priority = :priority)
          AND assigned_team = :team
        """)
    List<SupportTicket> findByStatusOrPriorityWithinTeam(
            @Param("status") String status,
            @Param("priority") String priority,
            @Param("team") String team
    );
}
```

Ở đây `@Query` chứa SQL thực tế, nên phải dùng tên bảng/cột vật lý như `support_tickets` và `assigned_team`. `:status`, `:priority`, `:team` là tham số được bind, không nối chuỗi dữ liệu người dùng vào SQL.

Ngoặc trong SQL thể hiện chính xác yêu cầu `(A OR B) AND C`, bất kể thứ tự ưu tiên mặc định. Với điều kiện phức tạp hơn, việc viết ngoặc tường minh giúp bảo trì dễ hơn so với một method name rất dài.

## 9. Khi nào nên tách thành nhiều method?

Nếu biểu thức chỉ có một vài cụm rõ ràng, derived query vẫn dễ đọc. Nhưng khi tên method dài và có nhiều nhánh, có thể cân nhắc:

- Tách thành các query method nhỏ hơn nếu chúng đại diện cho các thao tác có ý nghĩa riêng.
- Dùng `@Query` với ngoặc nếu cần kiểm soát chính xác biểu thức SQL.
- Dùng repository fragment/JdbcTemplate nếu query cần điều kiện động, nhiều join, projection hoặc tối ưu đặc thù.
- Đưa logic chọn bộ lọc vào một query builder phù hợp nếu điều kiện phụ thuộc nhiều tham số tùy chọn.

Không nên tách query thành nhiều lần gọi repository rồi ghép danh sách trong Java một cách tùy tiện. Cách đó có thể gây truy vấn thừa, trùng kết quả, khó phân trang và có thể đọc dữ liệu ở các thời điểm khác nhau. Nếu một biểu thức có thể thực hiện trong một SQL rõ ràng, thường nên để database áp dụng điều kiện và trả kết quả cần thiết.

## 10. Kết hợp `And`/`Or` với các toán tử property

Spring Data query derivation hỗ trợ nhiều keyword ngoài `And` và `Or`, tùy module và phiên bản. Ví dụ các toán tử phổ biến gồm:

```java
List<SupportTicket> findByPriorityAndStatusIn(
        String priority,
        Collection<String> statuses
);

List<SupportTicket> findByTitleContainingIgnoreCaseOrAssignedTeam(
        String keyword,
        String team
);
```

Ý nghĩa của method đầu là priority bằng giá trị truyền vào **và** status thuộc tập được truyền vào. Method thứ hai tìm title chứa từ khóa không phân biệt hoa thường **hoặc** thuộc nhóm được chỉ định. Các toán tử `In`, `Containing`, `IgnoreCase` áp dụng cho property tương ứng; `And`/`Or` vẫn dùng để kết hợp các predicate.

Khi thêm nhiều keyword, cần đọc method thành từng predicate cụ thể và xác định nhóm logic trước khi sử dụng. Đừng giả định một hậu tố như `IgnoreCase` thay đổi độ ưu tiên của `And`/`Or`; nó chỉ thay đổi cách so sánh property tương ứng.

## 11. Giá trị `NULL` và logic ba trạng thái của SQL

SQL có ba trạng thái logic: `TRUE`, `FALSE` và `UNKNOWN`. So sánh `column = NULL` không cho kết quả `TRUE`; phải dùng `IS NULL` để kiểm tra null. Điều này quan trọng khi kết hợp `And` và `Or`.

Ví dụ, nếu `assigned_team` có thể `NULL`, điều kiện:

```sql
status = 'OPEN' AND assigned_team = 'OPS'
```

sẽ không đúng với hàng có `assigned_team IS NULL`; biểu thức so sánh cho `UNKNOWN`. Khi cần tìm các hàng không có nhóm phụ trách, khai báo method có keyword null:

```java
List<SupportTicket> findByAssignedTeamIsNull();
```

Hoặc kết hợp:

```java
List<SupportTicket> findByStatusAndAssignedTeamIsNullOrPriority(
        String status,
        String priority
);
```

Method này có ý nghĩa:

```text
(status = :status AND assignedTeam IS NULL)
OR priority = :priority
```

Nếu property là bắt buộc như DDL ví dụ `assigned_team NOT NULL`, nhánh `IS NULL` không có kết quả trong dữ liệu hợp lệ. Chỉ dùng điều kiện null khi mô hình và schema thực sự cho phép giá trị đó.

## 12. Các lỗi thường gặp khi đọc method có nhiều điều kiện

| Nhầm lẫn/triệu chứng | Nguyên nhân | Cách xử lý |
|---|---|---|
| `AOrBAndC` bị hiểu thành `(A OR B) AND C` | Đọc tên method từ trái sang phải, bỏ qua nhóm `And` | Đọc thành `A OR (B AND C)` |
| Kết quả có thêm hàng thỏa riêng nhánh cuối | `OR` cho phép một nhánh độc lập đúng | Kiểm tra xem đó có đúng yêu cầu nghiệp vụ không |
| Dùng tên cột trong method derived query | Derived query tham chiếu property Java | Dùng tên property entity |
| Muốn thêm ngoặc trong method name | Derived query không cung cấp cú pháp ngoặc tùy ý | Viết `@Query` với ngoặc SQL |
| Tham số bị truyền sai thứ tự | Method có nhiều predicate, chữ ký khó đọc | Đối chiếu thứ tự property và tên tham số |
| Query trả kết quả sai khi có null | SQL dùng logic ba trạng thái | Dùng `IsNull`/`IsNotNull` và kiểm tra nullability |
| Method quá dài, khó bảo trì | Quá nhiều `And`/`Or` và toán tử | Tách query hoặc dùng `@Query`/fragment |
| `@Query` báo thiếu cột | Dùng property name thay cho cột vật lý hoặc thiếu cột mapping | Kiểm tra DDL, `@Column` và danh sách `SELECT` |

Khi debug, có thể bật log Spring JDBC trong môi trường phát triển để xem SQL được thực thi. Đối chiếu điều kiện `WHERE`, ngoặc, tên cột và tham số bind. Không nên chỉ dựa vào tên method để phỏng đoán kết quả nếu biểu thức có nhiều nhánh.

## 13. Quy trình đọc một method phức tạp

Với method:

```java
findByStatusAndPriorityOrAssignedTeamAndTitleContaining(...)
```

hãy đọc theo trình tự:

1. Tách tại `Or` để tạo các nhóm.
2. Trong từng nhóm, tách các predicate tại `And`.
3. Ghép các predicate trong nhóm bằng `AND`.
4. Ghép các nhóm bằng `OR`.
5. Đối chiếu mỗi property với entity, xác định toán tử cụ thể và thứ tự tham số.
6. Viết biểu thức Boolean có ngoặc ra giấy trước khi dùng trong use case.
7. Nếu biểu thức không trùng yêu cầu nghiệp vụ, chuyển sang `@Query` và viết ngoặc SQL rõ ràng.

Ví dụ trên được đọc thành:

```text
(status = ? AND priority = ?)
OR
(assignedTeam = ? AND title CONTAINS ?)
```

Đây là cách đọc giúp nhìn thấy cấu trúc nhóm ngay lập tức và hạn chế nhầm lẫn khi method dài.

## 14. Bài thực hành: kiểm tra độ ưu tiên điều kiện

Với bảng `support_tickets` và dữ liệu mẫu ở phần 6, hãy khai báo hai method:

```java
List<SupportTicket> findByStatusAndPriorityOrAssignedTeam(
        String status, String priority, String assignedTeam);

List<SupportTicket> findByStatusOrPriorityAndAssignedTeam(
        String status, String priority, String assignedTeam);
```

Gọi cả hai với các giá trị `OPEN`, `HIGH`, `OPS`. Ghi ID được trả về và giải thích theo hai biểu thức:

```text
Method 1: (status = OPEN AND priority = HIGH) OR assignedTeam = OPS
Method 2: status = OPEN OR (priority = HIGH AND assignedTeam = OPS)
```

Sau đó, viết một `@Query` có điều kiện:

```text
(status = OPEN OR priority = HIGH) AND assignedTeam = OPS
```

So sánh ba tập kết quả. Cuối cùng, thay một hàng có `assigned_team = NULL` nếu schema cho phép, rồi thử điều kiện `IsNull` để quan sát logic SQL ba trạng thái.

## 15. Nguyên tắc ghi nhớ

- `And` kết hợp các điều kiện trong cùng một nhóm; mọi điều kiện trong nhóm phải đúng.
- `Or` nối các nhóm; chỉ cần một nhóm đúng là hàng có thể được chọn.
- `findByAAndBOrC` được hiểu là `(A AND B) OR C`.
- `findByAOrBAndC` được hiểu là `A OR (B AND C)`.
- Derived query dùng property Java; SQL trong `@Query` dùng tên bảng/cột vật lý.
- Tên method không có cú pháp ngoặc tùy ý. Dùng `@Query` khi cần nhóm như `(A OR B) AND C`.
- Giá trị `NULL` cần xử lý bằng `IsNull`/`IsNotNull`; SQL có logic ba trạng thái.
- Với method dài, hãy tách nhóm điều kiện ra thành biểu thức Boolean có ngoặc trước khi sử dụng.

Trong Spring Data JDBC, `And` và `Or` giúp mô tả các bộ lọc phổ biến ngay trong tên repository method. Để tránh sai lệch nghiệp vụ, hãy luôn đọc method theo các nhóm `And` được nối bằng `Or`, kiểm tra property và thứ tự tham số, rồi dùng `@Query` với ngoặc tường minh khi cần biểu thức phức tạp hơn. Cách làm này khiến truy vấn dễ hiểu, dễ kiểm chứng và ít gây bất ngờ khi dữ liệu thực tế có nhiều tổ hợp điều kiện.
