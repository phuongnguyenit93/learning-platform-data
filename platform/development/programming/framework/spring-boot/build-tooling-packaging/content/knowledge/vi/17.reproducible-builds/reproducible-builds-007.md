# Loại bỏ ảnh hưởng của đường dẫn tuyệt đối, múi giờ và locale đối với bản dựng Spring Boot tái lập

## 1. Bài toán: vì sao cùng source nhưng hai JAR có thể khác SHA-256?

**Bản dựng tái lập (reproducible build)** là bản dựng mà cùng mã nguồn, cùng dữ liệu đầu vào, cùng hướng dẫn build và các yếu tố môi trường đã quy định có thể tạo ra **artifact giống hệt từng byte**, không chỉ cùng chức năng. Hai executable Spring Boot JAR có thể chạy cùng API nhưng khác checksum vì chứa metadata thời gian, đường dẫn máy developer, tên người dùng, giá trị định dạng phụ thuộc locale hoặc file ZIP entries theo thứ tự không ổn định.

Ba nhóm đầu vào ẩn được nhấn mạnh trong bài:

1. **Đường dẫn tuyệt đối và trạng thái máy:** `/home/alice/work/app` khác `C:\build\app` hoặc `/agent/_work/42`. Nếu generator ghi đường dẫn này vào resource, manifest, metadata hay JSON được đóng trong archive thì JAR sẽ khác.
2. **Múi giờ và thời gian:** cùng một `Instant` có thể được in thành hai giờ địa phương khác nhau; thời điểm file ZIP/JAR, build metadata `build.time`, mã generator gọi `Instant.now()` hoặc `new Date()` khiến kết quả thay đổi.
3. **Locale, charset và quy tắc vùng:** chữ hoa/thường tiếng Thổ Nhĩ Kỳ, dấu phân cách số của Pháp, định dạng ngày/tiền tệ, cách sort, encoding mặc định và line endings có thể làm bytes của file được tạo khác.

```text
Cùng Git commit + cùng dependencies
      |
      +-- Máy A: /home/alice/repo, UTC, en_US, Linux
      |       -> build-info, generated.txt, jar entries
      |
      +-- Máy B: C:\agent\repo, Asia/Tokyo, tr_TR, Windows
              -> build-info, generated.txt, jar entries
      |
      v
Mục tiêu: SHA-256(artifact A) == SHA-256(artifact B)
```

**Phân biệt chính xác:**
- *Deterministic code:* một bước tạo đầu ra ổn định khi các input của nó bằng nhau.
- *Reproducible artifact:* toàn bộ chuỗi build tạo **cùng bytes** khi lặp lại dưới điều kiện đã công bố.
- *Hermetic build:* build được cách ly khỏi những nguồn môi trường ngoài đã không khai báo. Hermeticity giúp reproducibility nhưng không đồng nghĩa tự động có checksum giống nhau.
- *Functional equivalence:* hai JAR chạy hành vi tương đương; chưa chắc có checksum bằng nhau.

Không hứa rằng chỉ đặt `TZ=UTC` hoặc bật một flag Maven/Gradle là mọi project tự nhiên reproducible. Phải kiểm tra cả **generated code/resources, compiler/toolchain, archive metadata, dependency locking và plugin behavior**.

## 2. Bản đồ những đầu vào môi trường cần kiểm soát

| Yếu tố | Dạng rò rỉ thường gặp | Hậu quả | Cách loại bỏ/kiểm soát |
| --- | --- | --- | --- |
| `project.basedir`, `user.dir`, `projectDir.absolutePath` | Ghi vào generated JSON/manifest/config | Nội dung artifact chứa workspace path khác nhau | Dùng đường dẫn logic tương đối hoặc artifact coordinates |
| `user.home`, `user.name`, `HOME` | Người build được ghi vào metadata | Artifact khác theo tài khoản | Không đưa vào output nếu không phải input hợp lệ |
| `Instant.now()`, `new Date()` | Build timestamp chạy theo đồng hồ | Mỗi build khác | Dùng timestamp release cố định hoặc loại trường time |
| ZIP/JAR entry timestamps | Copy timestamps từ filesystem | Archive checksum đổi | Maven `project.build.outputTimestamp`; Gradle archive flags |
| `ZoneId.systemDefault()` | Chuyển Instant sang local time | Giá trị khác theo host | Dùng UTC/ZoneOffset.UTC cho metadata |
| `Locale.getDefault()` | Format số, ngày, chữ hoa/thường | Generated text thay đổi | Dùng `Locale.ROOT` hoặc locale nghiệp vụ tường minh |
| `Charset.defaultCharset()` | Đọc/ghi resource theo platform | Byte khác hoặc Unicode lỗi | Chọn `StandardCharsets.UTF_8` và compiler encoding |
| `System.lineSeparator()` / CRLF | Text generated trên Windows khác Unix | Checksum file khác | Quy định LF cho artifact text, `.gitattributes` |
| Duyệt thư mục không sắp xếp | `Files.list`/`File.listFiles` order khác FS | File order/JSON keys khác | Sort theo tên logic chuẩn hóa trước khi sinh output |
| JDK/compiler/vendor/version | Generated bytecode, resources có thể khác | JAR khác dù Java major giống | Pin JDK toolchain cụ thể cho gate nghiêm ngặt |
| Version range / SNAPSHOT / plugin mutable | Dependency resolution khác | Classpath/archive khác | Pin/lock dependency/plugin, kiểm soát repository |
| Locale-sensitive ZIP metadata | Filename encoding/permissions | Archive khác OS | Dùng UTF-8 và archive task/plugin reproducible |
| File bất biến bị generated task viết lại | Task phụ thuộc clock hay environment | Build cache hit sai hoặc luôn miss | Khai báo inputs/outputs và tránh implicit state |

**Nơi phát hiện ảnh hưởng:** xem `jar tf`, `META-INF/MANIFEST.MF`, `META-INF/build-info.properties`, `BOOT-INF/classes`, generated sources/resources, nested JARs và checksum. Log console có thể khác theo múi giờ nhưng **không** làm artifact khác nếu không được ghi ngược vào sản phẩm; phải phân biệt hai lớp này.

## 3. Đường dẫn tuyệt đối: điều gì nguy hiểm và điều gì không?

Đường dẫn absolute là một **địa chỉ trên máy đang build**, không phải định danh của tài nguyên ứng dụng. Ví dụ:

```text
/home/mai/projects/billing-service
/var/lib/ci/work/7/billing-service
C:\agent\_work\billing-service
```

Cả ba có thể chứa cùng repository revision, nhưng nếu code generator dùng:

```java
String workspace = System.getProperty("user.dir");
String machine = System.getProperty("user.name");
String value = Path.of("src/main/resources").toAbsolutePath().toString();
```

và ghi các chuỗi đó vào `build-info.properties`, generated Java source hoặc manifest, bytes artifact sẽ khác.

### 3.1. Dùng tên resource theo classpath

Đối với resource phải đi cùng ứng dụng:

```java
// Trong mã Spring Boot; đây là đoạn thuộc một method, không phải file .java độc lập.
try (var input = new org.springframework.core.io.ClassPathResource(
        "rules/defaults.txt").getInputStream()) {
    String text = new String(input.readAllBytes(),
            java.nio.charset.StandardCharsets.UTF_8);
    // Dùng text...
}
```

Tên `rules/defaults.txt` là định danh **logic** trong classpath. Maven/Gradle đóng resource vào `BOOT-INF/classes/rules/defaults.txt`, và Boot Loader xử lý classpath khi chạy executable JAR.

**Không dùng** đường dẫn `/home/mai/.../src/main/resources/rules/defaults.txt` trong code runtime, cũng đừng gọi `ClassPathResource.getFile()` một cách mặc định: resource nằm **trong executable JAR** có thể không tồn tại dưới dạng file riêng trên filesystem.

### 3.2. Nếu generator cần đi qua filesystem, tách root và relative path

Một task build sinh tài liệu từ `src/main/resources/schemas` vẫn cần đọc file thật trên disk. Nhưng dữ liệu **ghi ra** phải dùng đường dẫn tương đối tính từ root có ý nghĩa:

```java
Path root = Path.of(args[0]).toAbsolutePath().normalize();
Path source = root.resolve("src/main/resources/schemas/model.json").normalize();

if (!source.startsWith(root)) {
    throw new IllegalArgumentException("Resource escaped project root");
}

String portable = root.relativize(source)
        .toString()
        .replace('\\', '/');
```

Đây là **đoạn Java trong một method có import `Path`**, chưa phải chương trình chạy độc lập. Biến `portable` nhận `src/main/resources/schemas/model.json` trên hệ thống phù hợp, trong khi `root` tuyệt đối khác nhau giữa máy. Chuyển dấu `\` sang `/` giúp tên logic xuất ra trong metadata không phụ thuộc separator Windows/Unix. Khi xác minh path trust boundary, cần kiểm tra symlink/real path nếu input là đường dẫn không tin cậy; `normalize` không tự ngăn mọi trường hợp symlink escape.

**Không được cắt chuỗi absolute path bằng độ dài cố định** hoặc replace tên người dùng; việc đó dễ hỏng khi có Unicode, junction/symlink, ổ đĩa khác và modules lồng nhau. Hãy tính relative từ base directory **đã xác định rõ**.

### 3.3. Những đường dẫn không cần loại khỏi build log

Vẫn có những đường dẫn tuyệt đối hợp lý:
- Maven báo lỗi compiler tại `/workspace/.../MyClass.java`.
- Gradle log chỉ ra `build/tmp/compileJava`.
- Test report đặt ở directory do CI tạo.
- Stack trace runtime chứa path phục vụ chẩn đoán.

Chúng **chỉ ảnh hưởng reproducible artifact nếu được ghi vào bytes của artifact hoặc ảnh hưởng đầu vào build**. Không cần cố xóa mọi path khỏi console logs, nhưng cần tránh log lộ thông tin nhạy cảm.

## 4. Múi giờ, thời gian và tính tái lập: ba tầng khác nhau

### 4.1. Instant không phụ thuộc múi giờ; cách biểu diễn thì có

Một thời điểm cố định:

```text
2024-01-02T03:04:05Z
```

là một `Instant` duy nhất. Nếu convert bằng `ZoneId.systemDefault()`, máy ở Tokyo và New York sẽ in **local wall-clock time khác nhau**. Nếu generator ghi local date/time vào file, artifact có thể khác dù cùng `Instant`.

Dùng:

```java
Instant fixed = Instant.parse("2024-01-02T03:04:05Z");
String stable = java.time.format.DateTimeFormatter.ISO_INSTANT.format(fixed);
```

`stable` chính xác là `2024-01-02T03:04:05Z`. Đây là **đoạn Java**, cần import `java.time.Instant`, không phải chương trình độc lập.

Nếu nghiệp vụ cần string theo zone cố định:

```java
var formatter = java.time.format.DateTimeFormatter
        .ofPattern("yyyy-MM-dd'T'HH:mm:ssXXX", java.util.Locale.ROOT)
        .withZone(java.time.ZoneOffset.UTC);

String stable = formatter.format(
        java.time.Instant.parse("2024-01-02T03:04:05Z"));
```

Output có UTC offset theo pattern, ví dụ `2024-01-02T03:04:05Z`; không đọc múi giờ mặc định của máy.

**Không dùng `LocalDateTime.now()` để đóng dấu artifact** trừ khi yêu cầu phải ghi thời điểm build; nếu cần provenance, timestamp đó phải là một input **được cố định và có thể tái tạo**, ví dụ commit timestamp của release, chứ không phải wall clock của lần build.

### 4.2. Thời gian của các ZIP/JAR entries

ZIP/JAR lưu metadata thời gian cho entries. Nếu Maven/Gradle giữ mtime từ filesystem hoặc dùng “bây giờ”, một file nguồn không đổi vẫn có thể được đóng với thời gian khác.

Đây là lý do:
- Chỉ ổn định nội dung `.class` chưa đủ.
- Hai archive có cùng danh sách entries/chức năng vẫn có thể khác SHA-256.
- So sánh sau `jar tf` (chỉ tên file) chưa đủ; cần kiểm tra ZIP metadata, timestamps, order và bytes.

**Maven:** dùng `project.build.outputTimestamp` cùng các plugin hỗ trợ reproducible archives.

**Gradle:** dùng `isPreserveFileTimestamps = false` và `isReproducibleFileOrder = true` cho archive tasks nếu cần tương thích Gradle cũ; từ **Gradle 9.0** các archive tasks đã dùng defaults tái lập tương đương. Dù archive metadata ổn định, file generated **bên trong** vẫn có thể chứa timestamp tùy máy.

### 4.3. Spring Boot build-info chứa build.time

Nếu project bật Maven goal `spring-boot:build-info` hoặc Gradle `springBoot { buildInfo() }`, file `META-INF/build-info.properties` có thể chứa `build.time`.

- Với **Spring Boot Maven Plugin**, thời gian mặc định có thể lấy `project.build.outputTimestamp` nếu được đặt; nếu không, dùng thời gian session request start. Có thể bỏ time bằng `<time>off</time>` hoặc exclude trường `time`.
- Với **Spring Boot Gradle Plugin**, `bootBuildInfo` mặc định ghi thời gian thực lúc build. Tài liệu Spring Boot chỉ rõ điều này làm task luôn thay đổi, không up-to-date và cản trở repeatable builds; có thể loại thuộc tính `time`.

Nếu chỉ cần trace version/commit, thường tốt hơn giữ **version đã pin và commit hash do CI truyền vào** thay vì luôn ghi current build time. Nếu pháp lý/audit yêu cầu timestamp thời điểm build, phải nêu rõ đây là một input làm thay đổi artifact, và không tuyên bố hai lần build độc lập là byte-identical nếu dùng timestamp khác nhau.

## 5. Locale và charset: dữ liệu dễ biến đổi mà không có lỗi biên dịch

### 5.1. Chữ hoa/thường không nên mặc định theo locale cho key máy đọc

Java có:

```java
String key = "IMAGE".toLowerCase();
```

Kết quả có thể phụ thuộc locale mặc định. Với locale tiếng Thổ Nhĩ Kỳ, chữ `I` có thể thành `ı` (dotless i), khác `i` ASCII mà cấu hình/resource key mong đợi.

Với identifiers, key, enum-like labels, tên file logic và canonical machine-readable text:

```java
String key = "IMAGE".toLowerCase(java.util.Locale.ROOT);
```

Kết quả chính xác là `image`, độc lập `user.language`/`user.country`. Với dữ liệu hiển thị cho người dùng theo ngôn ngữ cụ thể, chọn locale nghiệp vụ rõ ràng (`Locale.forLanguageTag("vi-VN")`, `Locale.US`...) thay vì ép tất cả thành ROOT.

### 5.2. Formatting số và ngày

`String.format("%.2f", 12.5)` dùng default formatting locale. Một số locale dùng **dấu phẩy thập phân** thay dấu chấm; giá trị bên trong generated SQL/JSON/manifest có thể thay đổi.

Dùng:

```java
String number = String.format(java.util.Locale.ROOT, "%.2f", 12.5);
```

Kết quả ổn định `12.50`. Tương tự:
- `NumberFormat.getInstance()` và `DateTimeFormatter.ofPattern(...)` có thể phụ thuộc locale nếu không chỉ định.
- `Collator.getInstance()` dùng locale-dependent sort; nếu cần thứ tự máy đọc, dùng comparator rõ ràng và định dạng Unicode được xác định trước.
- Chọn `Locale.ROOT` cho **serialization nội bộ**, không nhất thiết cho UI/biểu mẫu tiền tệ của người sử dụng.

### 5.3. Định dạng file text, encoding và newline

Trên Java 17, những API không chỉ rõ charset có thể phụ thuộc runtime/platform. Đừng dựa vào:

```java
// Không nên dùng để tạo artifact byte-identical:
new String(bytes);
text.getBytes();
new java.io.FileWriter("generated.txt");
System.lineSeparator();
```

Các phương thức có default encoding/newline có thể làm generated file khác. Tốt hơn:

```java
byte[] bytes = text.replace("\r\n", "\n")
        .getBytes(java.nio.charset.StandardCharsets.UTF_8);
java.nio.file.Files.write(
        java.nio.file.Path.of("generated.txt"), bytes);
```

**Chú ý:** `replace("\r\n", "\n")` chỉ là cách chuẩn hóa ví dụ. Nếu input có line ending `\r` đơn độc hoặc định dạng binary/chữ ký đòi nguyên bytes, cần định nghĩa policy cụ thể, không tự chuyển đổi mù. Đối với văn bản do generator chủ động tạo, xuất chuỗi chứa `\n` và encode UTF-8 sẽ kiểm soát tốt hơn.

### 5.4. Git checkout và CRLF

Đặt `.gitattributes` phù hợp:

```gitattributes
*.java        text eol=lf
*.properties  text eol=lf
*.yml         text eol=lf
*.yaml        text eol=lf
*.json        text eol=lf
*.sh          text eol=lf
*.bat         text eol=crlf
*.png         binary
*.jpg         binary
*.jar         binary
```

Đây là **ví dụ policy**, không phải cấu hình duy nhất cho mọi repo. Với file đã được checkout/commit nhiều kiểu line ending, cần normalize trong một commit rõ ràng (`git add --renormalize .` sau khi review) để tránh diff khổng lồ. Không dùng text conversion cho binary. Thay đổi line endings có thể ảnh hưởng generated code/script, vì vậy cần test trên môi trường đích.

## 6. Java 17 runnable: cùng stdout ở hai đường dẫn, múi giờ và locale

Phần này là chương trình Java **không cần Spring Boot dependency** nhằm cô lập ba nguyên nhân. Chỉ cần JDK 17+ và hai file. Nó xuất relative resource path, text, lowercase key, timestamp và số **đúng bytes UTF-8/LF**.

Cấu trúc:

```text
portable-report/
├── ReproProbe.java
└── data/
    └── greeting.txt
```

**`data/greeting.txt`:**

```text
hello
```

**`ReproProbe.java`:**

```java
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.nio.file.Path;
import java.time.Instant;
import java.time.format.DateTimeFormatter;
import java.util.Locale;

public class ReproProbe {
    public static void main(String[] args) throws Exception {
        if (args.length != 1) {
            throw new IllegalArgumentException("Expected project root path");
        }

        Path root = Path.of(args[0]).toAbsolutePath().normalize();
        Path resource = root.resolve("data/greeting.txt").normalize();

        if (!resource.startsWith(root)) {
            throw new IllegalArgumentException("Resource outside project");
        }

        String portableName = root.relativize(resource)
                .toString()
                .replace('\\', '/');
        String content = Files.readString(resource, StandardCharsets.UTF_8)
                .strip();
        String key = "IMAGE".toLowerCase(Locale.ROOT);

        Instant fixed = Instant.parse("2024-01-02T03:04:05Z");
        String timestamp = DateTimeFormatter.ISO_INSTANT.format(fixed);
        String decimal = String.format(Locale.ROOT, "%.2f", 12.5);

        String report = "resource=" + portableName + "\n"
                + "content=" + content + "\n"
                + "key=" + key + "\n"
                + "instant=" + timestamp + "\n"
                + "decimal=" + decimal + "\n";

        System.out.write(report.getBytes(StandardCharsets.UTF_8));
    }
}
```

Dùng `javac`/`java` (Linux/macOS, thư mục root là `portable-report`):

```bash
mkdir -p out
javac -encoding UTF-8 -d out ReproProbe.java

# Chạy với một locale và timezone:
java -Duser.language=en -Duser.country=US -Duser.timezone=UTC \
  -cp out ReproProbe "$PWD"

# Chạy với locale Thổ Nhĩ Kỳ và timezone Nhật:
java -Duser.language=tr -Duser.country=TR -Duser.timezone=Asia/Tokyo \
  -cp out ReproProbe "$PWD"
```

**Stdout chính xác của mỗi lần chạy:**

```text
resource=data/greeting.txt
content=hello
key=image
instant=2024-01-02T03:04:05Z
decimal=12.50
```

Kết quả giống nhau vì:
- Absolute `root` chỉ dùng để **đọc input**, không được serialize vào output.
- `root.relativize(resource)` tạo tên logic và `replace('\\', '/')` giữ slash ổn định.
- `Files.readString(..., UTF_8)` cố định charset; `strip()` bỏ newline cuối nguồn ở ví dụ.
- `Locale.ROOT` dùng cho key và số.
- Timestamp là `Instant` cố định, format ISO ở UTC.
- `System.out.write(... UTF_8)` in bytes có newline `\n`, không gọi `System.lineSeparator()`.

**Kiểm tra với hai workspace khác nhau:** copy chính `ReproProbe.java` và `data/greeting.txt` sang hai thư mục khác nhau (ví dụ `/tmp/probe-a` và `/tmp/probe-b`), compile trong mỗi thư mục rồi chạy với đối số `"$PWD"` tương ứng. Nếu file input giống nhau, stdout giữ nguyên. Trên Windows PowerShell, dùng `(Get-Location).Path` thay `"$PWD"` và đặt các `-D` JVM options trước `-cp`.

Không nên dùng ví dụ này để khẳng định mọi project Java byte-identical tự động: nó chỉ chứng minh một **generator nhỏ đã được thiết kế loại bỏ ba đầu vào ẩn**.

## 7. Duyệt thư mục, thứ tự map và đường dẫn làm lệch generated resources

Một code generator thường cần liệt kê file từ directory:

```java
Files.list(root.resolve("schemas"))
        .forEach(path -> writeSchema(path));
```

Đoạn này (giả định method `writeSchema` tồn tại) không nên coi thứ tự entries của filesystem là ổn định. Nếu generator append các mục vào một JSON/manifest, thứ tự khác sẽ làm bytes khác.

Hãy:
1. Chuyển absolute files thành **relative logical paths**.
2. Chuẩn hóa separator `/`.
3. Sort theo comparator ổn định.
4. Serialize bằng thứ tự ổn định và UTF-8/LF.

**Đoạn Java 17 trong một method** (import `Path`, `Files`, `Comparator`, `List`, `Stream`) để lấy file names ổn định:

```java
try (var paths = Files.walk(root.resolve("schemas"))) {
    List<String> names = paths
        .filter(Files::isRegularFile)
        .map(path -> root.relativize(path).toString().replace('\\', '/'))
        .sorted()
        .toList();

    for (String name : names) {
        System.out.println(name);
    }
}
```

`Stream.sorted()` trên strings sử dụng thứ tự so sánh của Java String (không phải Collator mặc định). Với file name có Unicode normalization khác nhau giữa OS, quy định thêm NFC/NFD và chính sách không trùng tên khi case-insensitive; thứ tự byte-identical cần đồng nhất **cả tên file lẫn nội dung**. `Files.walk` có thể gặp symlink/permission khác nhau; cần kiểm soát đường đi và lỗi.

Tương tự, khi generated JSON/manifest lấy từ `HashMap` hoặc database query không có `ORDER BY`, hãy sort keys/records theo một comparator xác định trước khi serialize. Không cố tình dựa vào sự ổn định tình cờ của iteration order trên một máy.

## 8. Maven: cấu hình executable Spring Boot JAR có timestamp tái lập

Đây là project **độc lập** tạo một Spring Boot web JAR, dành cho mục đích chứng minh archive reproducibility. Ví dụ cố định **Spring Boot 3.5.0 và Java 17**, parent plugin version do Spring Boot quản lý; muốn nâng cấp hãy kiểm chứng plugin và runtime trên nhánh thực.

Cấu trúc:

```text
repro-app/
├── pom.xml
└── src/main/java/com/example/repro/ReproApplication.java
```

**`pom.xml` đầy đủ:**

```xml
<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0
                             https://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>

    <parent>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-parent</artifactId>
        <version>3.5.0</version>
        <relativePath/>
    </parent>

    <groupId>com.example</groupId>
    <artifactId>repro-app</artifactId>
    <version>0.1.0</version>
    <name>repro-app</name>
    <packaging>jar</packaging>

    <properties>
        <java.version>17</java.version>
        <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
        <project.reporting.outputEncoding>UTF-8</project.reporting.outputEncoding>
        <!-- Minh họa timestamp cố định, thật sự là input của bản phát hành. -->
        <project.build.outputTimestamp>2024-01-02T03:04:05Z</project.build.outputTimestamp>
    </properties>

    <dependencies>
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-web</artifactId>
        </dependency>
    </dependencies>

    <build>
        <plugins>
            <plugin>
                <groupId>org.springframework.boot</groupId>
                <artifactId>spring-boot-maven-plugin</artifactId>
            </plugin>
        </plugins>
    </build>
</project>
```

**`src/main/java/com/example/repro/ReproApplication.java`:**

```java
package com.example.repro;

import java.time.Instant;
import java.time.format.DateTimeFormatter;
import java.util.Locale;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@SpringBootApplication
@RestController
public class ReproApplication {

    public static void main(String[] args) {
        SpringApplication.run(ReproApplication.class, args);
    }

    @GetMapping("/proof")
    public String proof() {
        String key = "IMAGE".toLowerCase(Locale.ROOT);
        String stamp = DateTimeFormatter.ISO_INSTANT.format(
                Instant.parse("2024-01-02T03:04:05Z"));
        return key + "|" + stamp;
    }
}
```

Chạy:

```bash
mvn -B -ntp clean package
java -jar target/repro-app-0.1.0.jar
```

Gọi `curl -fsS http://localhost:8080/proof` ở terminal khác. **Body chính xác:** `image|2024-01-02T03:04:05Z`. Nếu port 8080 đã bị chiếm, chạy JAR thêm `--server.port=9090` và đổi URL. Dừng app bằng Ctrl+C.

**Vai trò của từng phần:**
- `<java.version>17</java.version>`: yêu cầu compiler target thích hợp dưới Spring Boot starter parent.
- `<project.build.sourceEncoding>UTF-8</...>`: chốt encoding cho source/resources được plugin liên quan hỗ trợ.
- `<project.build.outputTimestamp>2024-01-02T03:04:05Z</...>`: cung cấp **một timestamp ổn định** cho Maven plugins hỗ trợ reproducible archive, gồm Maven JAR Plugin và Spring Boot Maven Plugin repackage.
- `spring-boot-maven-plugin`: tạo executable JAR từ JAR nguồn; với starter parent, execution `repackage` được bind sẵn vào `package`.

Một số Maven phiên bản/plugin mới hỗ trợ reproducible mode mặc định, nhưng **không dựa vào mặc định mà bỏ kiểm chứng**; khai báo timestamp release rõ ràng giúp tài liệu build xác định. Giá trị thời gian của ví dụ là một input được chọn trước; ở dự án thật có thể dùng timestamp của release commit, nhưng phải duy trì ổn định xuyên suốt build tương ứng.

### 8.1. project.build.outputTimestamp làm gì và không làm gì?

Nó thường giúp:
- Maven archiver dùng ZIP/JAR entry timestamps có tính tái lập.
- Spring Boot repackaging chuẩn hóa archive entry times theo input đã chọn.
- Một số plugin build metadata có thể dùng timestamp này để tránh gọi wall-clock.

Nó **không tự bảo đảm**:
- Java code generator không gọi `Instant.now()`.
- Không có absolute paths trong generated sources.
- Dependencies/plugins/JDK binary giống nhau.
- Tất cả plugins đều hỗ trợ reproducible output.
- Container image hoặc file ký số đều có checksum bất biến.

Maven chính thức khuyến nghị cập nhật plugin versions hỗ trợ reproducible builds và dùng `maven-artifact-plugin` để kiểm tra. Với Maven 3.9.x và plugin cũ, tính năng mặc định có thể khác; xác nhận bằng effective POM và artifact thực.

### 8.2. Plugin build-info cần kiểm soát thêm

**Chỉ nếu ứng dụng thật sử dụng goal `spring-boot:build-info`**, Spring Boot Maven Plugin có thể thêm `META-INF/build-info.properties` chứa `build.time`.

Có hai cách:
- Giữ build time nhưng dùng `project.build.outputTimestamp` cố định; plugin hỗ trợ dùng giá trị này.
- Bỏ build time hẳn bằng `<time>off</time>` hoặc exclude property `time`.

Ví dụ **đoạn cấu hình thay thế bên trong phần `spring-boot-maven-plugin` của POM** nếu muốn chạy build-info mà không ghi time:

```xml
<executions>
    <execution>
        <id>build-info</id>
        <goals>
            <goal>build-info</goal>
        </goals>
        <configuration>
            <time>off</time>
        </configuration>
    </execution>
</executions>
```

Đây **không phải một `pom.xml` hoàn chỉnh**. Với starter parent, execution `repackage` đã tồn tại và không bị đoạn trên thay thế khi thêm một execution mới ID `build-info`. Nếu project không cần build-info, **không cần bật** goal này. Tránh tự động thêm timestamp bằng các plugin Git/build-number khác nếu mục tiêu là byte-identical.

## 9. Maven: cấu hình tests và build JVM để không phụ thuộc timezone/locale

### 9.1. Đừng nhầm build JVM với test JVM

Maven chạy bằng một JVM; Maven Surefire/Failsafe có thể khởi chạy **forked test JVM**. Đặt `TZ=UTC` cho shell không phải một lời đảm bảo rằng mọi test dùng cùng Java timezone, đặc biệt khi có override `user.timezone` hoặc khi plugin chọn JVM khác.

Nếu tests hiện tại dùng API phụ thuộc default timezone/locale, bạn có thể **tạm khóa môi trường test** để tạo baseline:

```xml
<plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-surefire-plugin</artifactId>
    <configuration>
        <argLine>
            -Duser.timezone=UTC -Duser.language=en -Duser.country=US
        </argLine>
    </configuration>
</plugin>
```

Đây là **plugin fragment** cần đặt trong `<build><plugins>` của POM hợp lệ. Với Spring Boot starter parent, Surefire version được quản lý phù hợp; với parent tùy chỉnh, pin plugin version và kiểm tra JUnit Platform support.

**Quan trọng:** `argLine` trên Surefire ảnh hưởng test JVM. Nếu project dùng JaCoCo hoặc tooling có thêm JVM agent qua `argLine`, ghi đè block đơn giản này có thể mất agent; phải merge/resolve property `argLine` theo cấu hình plugin tương ứng. `systemPropertyVariables` của Surefire dùng được cho nhiều property, nhưng với các property ảnh hưởng VM bootstrap như locale/encoding, đặt chúng vào command line của **forked JVM** là rõ ràng hơn.

Tuy nhiên, cách loại bỏ dependency tốt nhất là **sửa code** dùng `Locale.ROOT` và `ZoneOffset.UTC` nơi semantics không phụ thuộc môi trường. Nếu chỉ luôn ép UTC/en-US, tests có thể PASS và che bug khi triển khai trên máy có timezone khác. Nên có thêm test matrix cố ý đổi các giá trị này.

### 9.2. Chạy Maven ở nhiều timezone/locale

Trên Linux/macOS, có thể truyền JVM options cho **Maven process** bằng `MAVEN_OPTS`:

```bash
MAVEN_OPTS="-Duser.timezone=UTC -Duser.language=en -Duser.country=US" \
  mvn -B -ntp clean verify

MAVEN_OPTS="-Duser.timezone=Asia/Tokyo -Duser.language=tr -Duser.country=TR" \
  mvn -B -ntp clean verify
```

Các lệnh này được chạy **riêng từng lần**. `MAVEN_OPTS` tác động JVM chạy Maven, còn forked test JVM/other tools có thể cần cấu hình riêng. Lúc so sánh artifact, hãy bảo đảm hai lần build dùng cùng source/dependency/plugin/JDK, và không có generated resources nào bị giờ thực/locale chi phối.

## 10. Gradle Kotlin DSL: archive order, timestamp và Java toolchain

Gradle có cơ chế reproducible archive tasks. **Từ Gradle 9.0**, `AbstractArchiveTask` (JAR/ZIP/WAR/EAR/TAR tùy loại) đã có mặc định tương đương:
- `preserveFileTimestamps = false`;
- `reproducibleFileOrder = true`;
- metadata permissions được chuẩn hóa theo loại archive.

Với Gradle cũ hơn, **đặt hai cờ một cách tường minh**. Cấu hình này không buộc mọi generator/task khác của build trở nên deterministic.

Ví dụ Spring Boot app tương đương phần Maven, tái dùng nguyên `src/main/java/com/example/repro/ReproApplication.java` ở mục 8, nhưng **không giữ `pom.xml` trong một demo chỉ dùng Gradle**.

**`settings.gradle.kts`:**

```kotlin
rootProject.name = "repro-app"
```

**`build.gradle.kts`:**

```kotlin
import org.gradle.api.tasks.bundling.AbstractArchiveTask
import org.gradle.api.tasks.compile.JavaCompile

plugins {
    java
    id("org.springframework.boot") version "3.5.0"
    id("io.spring.dependency-management") version "1.1.7"
}

group = "com.example"
version = "0.1.0"

java {
    toolchain {
        languageVersion = JavaLanguageVersion.of(17)
    }
}

repositories {
    mavenCentral()
}

dependencies {
    implementation("org.springframework.boot:spring-boot-starter-web")
}

tasks.withType<JavaCompile>().configureEach {
    options.encoding = "UTF-8"
    options.release.set(17)
}

tasks.withType<AbstractArchiveTask>().configureEach {
    isPreserveFileTimestamps = false
    isReproducibleFileOrder = true
}
```

**Giải thích:**
- `java.toolchain` chọn version compiler/JVM tooling của project thay vì lấy mặc định ngẫu nhiên từ `JAVA_HOME`.
- `options.encoding` tránh ảnh hưởng default file encoding khi compiler đọc Java source.
- `options.release=17` ràng buộc Java API/bytecode target trong toolchain thích hợp.
- `withType<AbstractArchiveTask>()` tác động `jar`, `bootJar` và các archive tasks phù hợp, không sửa format XML/resources khác.
- `Gradle 9+` đã mặc định reproducible archives, nên hai assignment thường không cần nếu dự án chỉ hỗ trợ Gradle 9+. Khi hỗ trợ Gradle 8.x, khai báo rõ giúp ít bất ngờ hơn.
- Cần Gradle Wrapper có **phiên bản tương thích với Spring Boot plugin 3.5**; không tự lấy Gradle “latest” nếu chưa kiểm thử.

Chạy:

```bash
./gradlew clean bootJar
java -jar build/libs/repro-app-0.1.0.jar
```

Lệnh dùng project đã có Gradle Wrapper. Trên Windows chạy `gradlew.bat`. Nếu không có wrapper, dùng Gradle đã cài tương thích để tạo wrapper trước; không giả định `./gradlew` tồn tại khi chưa khởi tạo project. Endpoint `/proof` có response giống Maven demo.

### 10.1. Spring Boot Gradle buildInfo: loại timestamp thay đổi liên tục

Khi dự án cần `META-INF/build-info.properties` cho Actuator, thêm cấu hình:

```kotlin
springBoot {
    buildInfo {
        excludes.set(setOf("time"))
    }
}
```

Đây là **đoạn thêm vào build.gradle.kts đã áp dụng Spring Boot plugin**. Nó yêu cầu task `bootBuildInfo` sinh các thuộc tính khác, không ghi `build.time`. Tài liệu Spring Boot cho biết default `build.time` là thời điểm chạy build, khiến task output thay đổi và có thể kéo theo build không repeatable; loại `time` vừa ổn định output vừa cải thiện khả năng up-to-date.

Nếu cần build time thật sự cho audit, dùng input release cố định và API/plugin version hỗ trợ; đừng ghi `Instant.now()` vào resource rồi kỳ vọng `bootJar` tự xóa.

### 10.2. Gradle Test JVM: cấu hình một baseline

Để test suite có một baseline rõ:

```kotlin
tasks.withType<Test>().configureEach {
    useJUnitPlatform()
    systemProperty("user.timezone", "UTC")
    systemProperty("user.language", "en")
    systemProperty("user.country", "US")
}
```

Đây là **đoạn bổ sung**; cần có test dependencies/`Test` tasks phù hợp. Trong Gradle plugin Java, test JVM có phạm vi khác Gradle daemon. Cài đặt này giúp kiểm soát test runtime, nhưng bản thân nó không chứng minh mã không phụ thuộc locale/timezone. Tạo thêm test chạy dưới `tr_TR`/`Asia/Tokyo` để bắt các lỗi ẩn.

### 10.3. Tránh path leak trong custom Gradle tasks

**Không nên tạo artifact text như sau:**

```kotlin
// Minh họa một anti-pattern, không đưa vào build.gradle.kts.
val absolute = project.projectDir.absolutePath
val buildDate = java.time.Instant.now().toString()
```

Nếu các giá trị này được ghi vào resource, JAR sẽ khác giữa CI agents và các lần build. Hãy dùng:
- `providers.gradleProperty(...)` cho build metadata được khai báo rõ.
- Relative path names từ source root đã xác định.
- Các `Property<T>`/`RegularFileProperty` và task `@Input`/`@OutputFile` của Gradle nếu viết custom task cần cache/up-to-date.
- Stable release metadata từ Git commit hoặc CI input thay vì current time.

**Không tự coi Gradle cache là bằng chứng reproducibility:** cache có thể trả output cũ cùng task inputs mà bạn khai báo, nhưng khi task đọc `System.getenv`/`user.dir` không khai báo, task fingerprint có thể thiếu biến môi trường và gây output sai. Reproducibility đòi cả **task input modeling** lẫn byte-identical output.

## 11. So sánh hai bản build ở hai workspace và hai múi giờ

Một lần build thành công không chứng minh reproducibility. Cần **hai lần clean build độc lập** từ cùng Git commit, ở hai đường dẫn khác nhau, với timezone/locale khác nhau, sau đó so sánh SHA-256 hoặc bytes.

### 11.1. Bash demo Maven ở hai thư mục

Đoạn sau giả sử bạn đang đứng trong **Git repository của dự án Maven ở mục 8**, các file đã commit ở `HEAD`, có `git`, `tar`, Maven/JDK và công cụ `sha256sum`/`cmp` trên Linux. Không dùng lệnh này với đường dẫn có dữ liệu quan trọng cần bảo vệ, vì nó sẽ tạo hai thư mục mới.

```bash
mkdir -p /tmp/repro-a /tmp/repro-b

# Chỉ lấy file đã được commit trong HEAD, không kèm target/ hoặc local cache.
git archive HEAD | tar -x -C /tmp/repro-a
git archive HEAD | tar -x -C /tmp/repro-b

(
  cd /tmp/repro-a
  MAVEN_OPTS="-Duser.timezone=UTC -Duser.language=en -Duser.country=US" \
    mvn -B -ntp clean package
)

(
  cd /tmp/repro-b
  MAVEN_OPTS="-Duser.timezone=Asia/Tokyo -Duser.language=tr -Duser.country=TR" \
    mvn -B -ntp clean package
)

sha256sum /tmp/repro-a/target/repro-app-0.1.0.jar
sha256sum /tmp/repro-b/target/repro-app-0.1.0.jar

if cmp -s /tmp/repro-a/target/repro-app-0.1.0.jar \
          /tmp/repro-b/target/repro-app-0.1.0.jar; then
  echo "ARCHIVE_EQUAL"
else
  echo "ARCHIVE_DIFFERENT"
fi
```

**Kỳ vọng:** hai checksum phải bằng nhau và script in `ARCHIVE_EQUAL` nếu mọi yếu tố ảnh hưởng artifact đã được kiểm soát. Không cung cấp một SHA-256 giả vì checksum thực phụ thuộc đúng dependency/plugin/JDK/toolchain được dùng. **Nếu in `ARCHIVE_DIFFERENT`**, đó là kết quả kiểm tra có giá trị: cần điều tra nguyên nhân, không tự đánh dấu PASS.

**Giới hạn phép thử:** nó thay path và một số JVM defaults, nhưng vẫn dùng cùng máy/JDK/OS/network/cache Maven; chưa chứng minh một bên thứ ba trên OS khác có thể rebuild byte-for-byte. Để xác nhận mạnh hơn, chạy trên hai CI agents/container images độc lập đã pin versions và so sánh artifact. Ngoài ra, Maven forked tests có thể không nhận toàn bộ `MAVEN_OPTS`; nếu muốn kiểm tra test behavior, điều khiển Surefire JVM riêng.

### 11.2. Với Gradle

Từ hai checkout khác nhau, cùng commit và cùng Gradle Wrapper:

```bash
(
  cd /tmp/repro-a
  ./gradlew --no-build-cache clean bootJar
)

(
  cd /tmp/repro-b
  ./gradlew --no-build-cache clean bootJar
)

sha256sum /tmp/repro-a/build/libs/repro-app-0.1.0.jar
sha256sum /tmp/repro-b/build/libs/repro-app-0.1.0.jar
```

Đây là **đoạn minh họa cho hai directories chứa project Gradle và Wrapper**, không dùng nguyên directories xuất từ Maven-only POM nếu chưa tạo settings/build Gradle. `--no-build-cache` giúp mỗi bên thực hiện công việc thay vì nhận artifact từ build cache; nhưng Gradle vẫn có thể dùng dependency cache để resolve **cùng** versions. Dùng JVM options cho Gradle daemon hoặc test JVM có chủ đích khi mở rộng sang timezone/locale matrix. Nếu task bị up-to-date trong cùng workspace, `clean` và input modeling phải được xem xét.

### 11.3. So sánh checksum vs chức năng

- `SHA-256 A == SHA-256 B`: bằng chứng hai file **có cùng hash**, trong thực tế kiểm tra rất mạnh về byte equality; `cmp` xác nhận trực tiếp bytes.
- `java -jar A` và `java -jar B` cùng trả `/proof`: chứng minh hành vi ví dụ giống nhau, **không** chứng minh bytes bằng nhau.
- Hai file có cùng `jar tf`: chỉ tên entries giống nhau, **không** chứng minh timestamps/permissions/compression/layout giống nhau.
- Hai build log tương đương: không chứng minh output.
- Kết quả Maven/Gradle `BUILD SUCCESS`: chưa liên quan bit-for-bit equality nếu không có comparison.

## 12. Khi hash khác: tìm sự khác biệt nằm ở đâu?

Một quy trình chẩn đoán hiệu quả:

1. Xác nhận **cùng commit, same POM/Gradle config, version JDK/compiler/plugins/dependencies**.
2. So sánh kích thước và SHA-256.
3. Liệt kê ZIP entries và timestamps, thứ tự, permissions.
4. Giải nén vào hai thư mục tạm và diff các file **bên trong**.
5. Tập trung file tạo tự động: `META-INF/build-info.properties`, manifest, generated sources/resources, SBOM, index files, XML/JSON.
6. Nếu khác `.class`, kiểm tra toolchain, compiler flags, generated source, annotation processors.
7. Nếu bytes entry giống nhưng JAR hash khác, so sánh ZIP metadata/order/compression/signatures.
8. Xác định **task/plugin tạo ra khác biệt** và sửa tại nguồn, không chỉ sửa JAR sau khi build.

Các lệnh Bash hữu ích:

```bash
jar tf /tmp/repro-a/target/repro-app-0.1.0.jar > /tmp/list-a.txt
jar tf /tmp/repro-b/target/repro-app-0.1.0.jar > /tmp/list-b.txt
diff -u /tmp/list-a.txt /tmp/list-b.txt

unzip -l /tmp/repro-a/target/repro-app-0.1.0.jar
unzip -l /tmp/repro-b/target/repro-app-0.1.0.jar
```

`unzip -l` cho phép xem entry sizes/times; do ZIP timestamps và timezone conversion có nhiều đặc điểm, không xem riêng thời gian hiển thị trong một terminal là tuyệt đối. Nếu cần phân tích sâu, dùng `zipinfo`, giải nén/diff hoặc **diffoscope**:

```bash
diffoscope /tmp/repro-a/target/repro-app-0.1.0.jar \
           /tmp/repro-b/target/repro-app-0.1.0.jar
```

`diffoscope` là công cụ cần cài đặt riêng, không có mặc định trong JDK. Nó có thể hỗ trợ tìm ZIP metadata, manifest, generated file khác; không thay cho việc đọc source/config plugin.

### 12.1. Maven artifact plugin hỗ trợ so sánh

Apache Maven có workflow dùng `maven-artifact-plugin`:

```bash
mvn clean install
mvn clean verify artifact:compare
```

Lệnh đầu xây/cài một reference artifact, lệnh sau build lại và so sánh theo plugin. Cần Maven Artifact Plugin/version hỗ trợ các goals này và môi trường repository hợp lệ; plugin có thể phải tải lần đầu.

**Giới hạn:** hai lần build trên cùng máy không phát hiện hết path/locale/OS leak. Đây là một kiểm tra cục bộ tốt, nhưng cần kiểm chứng độc lập ở workspace khác, môi trường khác, hoặc sử dụng reproducible builds verification đúng nghĩa.

## 13. Múi giờ của artifact không giống múi giờ của ứng dụng runtime

Một dịch vụ Spring Boot cần trả dữ liệu cho user ở các múi giờ địa phương. Đặt tất cả users sang UTC không phải mục tiêu bài này.

**Tách hai phạm vi:**
- *Build metadata / artifact identity:* chuẩn hóa timestamp, format và các input để JAR có thể tái lập.
- *Business runtime behavior:* lưu timestamp chính xác theo `Instant`/UTC, **format hiển thị theo timezone và locale của người dùng** đã được lựa chọn rõ; đây là một **input hợp lệ của request**, không phải môi trường ẩn.

Ví dụ Java runtime:

```java
Instant orderTime = Instant.parse("2024-01-02T03:04:05Z");
ZoneId customerZone = ZoneId.of("Asia/Ho_Chi_Minh");
String visible = DateTimeFormatter
        .ofPattern("dd/MM/yyyy HH:mm", Locale.forLanguageTag("vi-VN"))
        .withZone(customerZone)
        .format(orderTime);
```

Đoạn này nằm trong một method với imports `Instant`, `ZoneId`, `DateTimeFormatter` và `Locale`; output sẽ là `02/01/2024 10:04` trong vùng `Asia/Ho_Chi_Minh`. Nó **deterministic vì zone và locale là input rõ**, không vì bắt mọi máy phải ở Việt Nam.

Đối với tests:
- Test format ngày giờ phải có `Instant` và `ZoneId` rõ ràng, tránh phụ thuộc máy developer.
- Test định dạng nhiều ngôn ngữ nên chạy nhiều locales theo dữ liệu test.
- Test chuyển DST phải dùng zone có DST (ví dụ `Europe/Berlin`) và kiểm tra instants quanh thời điểm chuyển.
- Không dùng `LocalDateTime.now()` cho assertion cố định; dùng `Clock.fixed(...)` được inject vào service.

Nếu sản phẩm có lịch theo ngày địa phương, chọn `LocalDate`/`ZonedDateTime` theo nghiệp vụ, không ép mọi khái niệm thành UTC string rồi làm mất ý nghĩa local date.

## 14. Clock injection: làm test và generator ổn định

Đôi khi mã **cần biết thời điểm** (ví dụ tạo metadata phát hành hoặc test expiry). Thay vì gọi đồng hồ hệ thống trong mỗi function, hãy đưa `Clock` như dependency.

Ví dụ Java 17 độc lập:

**`ClockProbe.java`:**

```java
import java.time.Clock;
import java.time.Instant;
import java.time.ZoneOffset;

public class ClockProbe {
    static String createdAt(Clock clock) {
        return Instant.now(clock).toString();
    }

    public static void main(String[] args) {
        Clock frozen = Clock.fixed(
                Instant.parse("2024-01-02T03:04:05Z"),
                ZoneOffset.UTC);
        System.out.println(createdAt(frozen));
    }
}
```

Chạy:

```bash
javac -encoding UTF-8 ClockProbe.java
java ClockProbe
```

Stdout **chính xác**:

```text
2024-01-02T03:04:05Z
```

Để test doanh nghiệp, tạo một `@Bean Clock` trong Spring Boot và inject qua constructor; production có thể dùng `Clock.systemUTC()`, còn test có `Clock.fixed(...)`. Trong **build-generated resource**, nếu mục tiêu reproducible thì clock cần nhận một **release timestamp được pin** thay vì production clock. `Clock.systemUTC()` chỉ cố định timezone, **không** cố định thời điểm; hai lần gọi khác nhau vẫn có thể ra timestamps khác nhau.

## 15. Những việc không nên đưa vào artifact

### 15.1. Workspace path, OS account và config máy

Ví dụ một Maven manifest entry **không nên** dùng:

```xml
<!-- Anti-pattern nếu đưa các giá trị này vào artifact -->
<manifestEntries>
    <Workspace>${project.basedir}</Workspace>
    <Builder>${user.name}</Builder>
</manifestEntries>
```

Nó có thể khiến JAR chứa absolute path và local user. Để truy vết release, tốt hơn dùng groupId/artifactId/version, **Git commit ID đã pin** và thông tin provenance nằm trong CI attestations. Nếu có yêu cầu ghi builder identity, ghi thành input chính thức và chấp nhận rằng artifact sẽ khác nếu identity khác; đừng tuyên bố reproducibility vô điều kiện.

Trong Gradle, anti-pattern tương ứng là lấy `project.projectDir.absolutePath`, `System.getProperty("user.home")` hoặc `System.getenv("WORKSPACE")` để sinh metadata.

### 15.2. Thời điểm build “bây giờ”

`LocalDateTime.now()` và `Instant.now()` được dùng trong generator sẽ làm file output khác ở mỗi lần build. Spring Boot `build.time` cũng cần được loại bỏ/pin nếu sử dụng build-info.

Có thể thay bằng:
- Release timestamp được cố định và ghi nhận trong CI/manifest.
- Commit timestamp đã chuẩn hóa UTC và cùng commit cho mọi lần rebuild (nếu chính sách release sử dụng).
- Hoặc **không ghi timestamp** trong artifact khi không có yêu cầu.

`SOURCE_DATE_EPOCH` là một convention phổ biến để biểu diễn nguồn thời gian ổn định bằng Unix seconds, nhưng **không mặc định Maven, mọi Gradle plugin và mọi code generator đều tự đọc biến này**. Phải chuyển nó vào config plugin thích hợp (`project.build.outputTimestamp`, task property, metadata generator) và kiểm tra giá trị.

### 15.3. Dữ liệu sắp xếp bằng locale hoặc filesystem

Không tạo resource từ query không có `ORDER BY`, random iteration hoặc `Collator.getInstance()` không có locale xác định. Nếu serialized JSON/CSV cần thứ tự stable, sort theo một key logic ổn định, normalize Unicode/charset và dùng serialization options cụ thể.

### 15.4. Data runtime/secret đưa vào build

Mã nguồn phát hành không nên đóng:
- Database URL/password của môi trường cụ thể.
- API tokens, local certificates/private keys.
- Random session IDs.
- Local service endpoints chỉ CI agent dùng.
- Kết quả test có timing, hostnames, usernames.

Đây vừa là vấn đề **bảo mật** vừa là nguồn **non-determinism**. Cấp các giá trị runtime qua Spring Config Data/environment/secret store sau khi artifact đã được build và xác minh.

## 16. Nguyên tắc dành cho CI/CD và multi-module Spring Boot

### 16.1. Pin toolchain và dependency versions

Khi mục tiêu là bit-for-bit reproducibility giữa nhiều môi trường:
- Ghi Maven/Gradle Wrapper version và xác minh wrapper files được commit.
- Pin Spring Boot plugin, Maven plugin/JDK toolchain và dependency versions (không dùng version ranges thay đổi theo thời gian cho release).
- Với Gradle, cân nhắc dependency locking/verification; với Maven, dependency management/Enforcer/repository policy.
- Kiểm soát annotation processors/code generators, native tools, locale/tzdata database và những tool version có thể ảnh hưởng output.
- Đừng thay đổi build flags giữa hai lần so sánh.
- Trên Windows/Unix, thống nhất source line endings và UTF-8; không mặc nhiên mọi tool tạo output giống trên hai OS.
- Cùng major JDK chưa đủ cho gate nghiêm ngặt; một số compiler/vendor/patch/OS flags có thể sinh bytecode/resources khác. Ghi rõ image digest/toolchain.

### 16.2. Xử lý multi-module

Một parent Maven POM có `project.build.outputTimestamp` có thể giúp child modules kế thừa property; nhưng **mỗi module** vẫn có thể có plugin/task riêng sinh file không tái lập. Kiểm tra từng artifact:
- Plain library JAR modules.
- Spring Boot executable JAR module.
- Generated client/source/schema modules.
- Integration test module artifacts nếu được publish.
- OCI image/buildpacks layers nếu thuộc đầu ra bàn giao.

Với Gradle multi-project, `tasks.withType<AbstractArchiveTask>().configureEach` trong một subproject chỉ áp dụng các tasks của subproject đó. Nếu cần policy toàn repo, dùng convention plugin được áp dụng có chủ đích ở từng project; tránh viết config script tùy tiện vi phạm configuration-cache/isolation. Chỉ khai báo outputTimestamp ở Maven root cũng không ép một plugin custom không hỗ trợ nó trở nên deterministic.

### 16.3. Release candidate reproducibility gate

Một quy trình CI có thể là:

```text
Git commit cố định
    |
    +-- Build A: workspace A, UTC/en_US, pinned JDK + deps
    |        -> app-a.jar + sha256
    |
    +-- Build B: workspace B, Asia/Tokyo/tr_TR, pinned JDK + deps
             -> app-b.jar + sha256
    |
    +-- So sánh byte-level và phân tích diff
             |
             +-- Equal: reproducibility check PASS
             +-- Different: FAIL, lưu diff an toàn, sửa nguyên nhân
```

Một build CI vẫn có thể cần secret để tải private dependencies; không đưa giá trị secret vào output. Dùng artifact repository có checksum/immutable release policy và xác minh supply-chain provenance riêng. **Reproducibility không tự chứng minh an toàn nội dung, không thay SBOM/vulnerability scanning**.

### 16.4. Hai mức test khác nhau

1. **Build reproducibility tests:** so sánh SHA-256/JAR bytes giữa hai lần build sạch.
2. **Locale/timezone behavior tests:** chạy unit/integration tests dưới nhiều `user.language`, `user.country`, `user.timezone` và assert đúng kết quả.

Một project có thể pass (1) vì artifact không chứa locale-dependent bytes nhưng vẫn fail (2) khi runtime UI format sai. Ngược lại, app runtime hoàn toàn đúng ở nhiều locales nhưng archive hash khác do ZIP timestamps. Không gộp hai mức kiểm tra thành một chỉ số.

## 17. Bảng lỗi thường gặp

| Triệu chứng | Nguyên nhân có thể | Cách kiểm tra và sửa |
| --- | --- | --- |
| Hai JAR có cùng class/resource names nhưng SHA khác | ZIP entry timestamps/order/permissions khác | Inspect archive metadata, Maven outputTimestamp hoặc Gradle archive flags |
| Cùng source khác path → generated JSON khác | `project.basedir`/`user.dir` bị serialize | Đổi sang relative logical paths |
| Build-info luôn thay đổi | `build.time` lấy wall clock | Maven dùng timestamp pin/`time=off`; Gradle exclude time |
| String key khác trong tr_TR | `toLowerCase()` dùng default locale | Dùng `toLowerCase(Locale.ROOT)` với machine identifiers |
| Decimal là `12,50` thay `12.50` | `String.format` dùng default locale | Chọn `Locale.ROOT` hoặc locale nghiệp vụ rõ |
| Date/time chuyển ngày khi CI chạy vùng khác | `ZoneId.systemDefault()` | Dùng `Instant` và explicit zone |
| UTF-8 resource đổi hoặc lỗi Unicode | Default charset/compiler encoding khác | Dùng UTF-8 explicit; normalize text resources |
| Generated text trên Windows khác Linux | CRLF/LF và `System.lineSeparator()` | `.gitattributes`, generator dùng LF cho machine-readable output |
| File manifest/liệt kê schema thay thứ tự | Duyệt filesystem/Map không sort | Stable comparator và relative names |
| Gradle `bootJar` vẫn khác dù archive flags bật | Generated file có current time/path hoặc dependency mismatch | Diff contents, kiểm tra `bootBuildInfo`/custom tasks |
| Maven outputTimestamp không có tác dụng | Plugin cũ/không hỗ trợ hoặc giá trị sai format | Cập nhật plugin, kiểm tra effective POM, inspect entry times |
| So sánh cùng máy PASS nhưng máy khác FAIL | JDK/OS/locale/plugin state chưa kiểm soát | Rebuild độc lập trên CI agents khác và diffoscope |
| Build cache che lỗi non-determinism | Custom task đọc hidden env/time không khai báo input | Khai báo inputs, chạy clean no-cache verification |
| Test chỉ fail ở CI | Default timezone/locale khác, Java/JUnit/tool khác | Test với explicit Clock/Locale/ZoneId, matrix CI |
| Maven Surefire test khác với Maven JVM | Test forked JVM không nhận config mong muốn | Cấu hình Surefire JVM args đúng scope |
| Artifact khớp nhưng image OCI khác | Image layer metadata/base image/digest/build-time env khác | Pin image/base, cấu hình reproducible image build riêng |
| Runtime vẫn thấy config vùng cũ | Build-time và runtime config bị trộn | Tách immutable JAR khỏi external Spring Config Data |
| Class file khác dù source giống | JDK/compiler/annotation processor/generated sources khác | So sánh toolchain, compiler args và generator output |

## 18. Bài thực hành QA theo mức tăng dần

### Bài A — Chứng minh locale leak

Thử chương trình Java nhỏ:

```java
import java.util.Locale;

public class LocaleLeak {
    public static void main(String[] args) {
        System.out.println("IMAGE".toLowerCase());
        System.out.println("IMAGE".toLowerCase(Locale.ROOT));
    }
}
```

Chạy:

```bash
javac -encoding UTF-8 LocaleLeak.java
java -Duser.language=tr -Duser.country=TR LocaleLeak
```

Hai dòng kỳ vọng tương ứng **`ımage`** (dotless `ı`) và **`image`**. Trên những JDK hiện đại có locale data phù hợp, ví dụ cho thấy default locale ảnh hưởng string key. Với `Locale.ROOT`, kết quả là `image` bất kể vùng.

### Bài B — Chứng minh timezone leak

```java
import java.time.Instant;
import java.time.ZoneId;
import java.time.ZonedDateTime;

public class ZoneLeak {
    public static void main(String[] args) {
        Instant fixed = Instant.parse("2024-01-02T03:04:05Z");
        System.out.println(ZonedDateTime.ofInstant(fixed,
                ZoneId.systemDefault()));
        System.out.println(fixed);
    }
}
```

Chạy hai lệnh:

```bash
javac ZoneLeak.java
java -Duser.timezone=UTC ZoneLeak
java -Duser.timezone=Asia/Tokyo ZoneLeak
```

Dòng đầu có zone/offset local khác nhau; dòng thứ hai **luôn** là `2024-01-02T03:04:05Z`. Đừng hardcode kỳ vọng chính xác dòng đầu vì `ZonedDateTime.toString()` biểu thị zone ID/offset khác theo cấu hình được đưa vào.

### Bài C — Phát hiện absolute path trong artifact

Build cùng commit ở hai checkout khác path. Nếu hash khác, kiểm tra:
- `META-INF/MANIFEST.MF` có `Workspace`, `Builder` hoặc path không?
- `BOOT-INF/classes/META-INF/build-info.properties` có field thời gian/path không?
- Generated sources/resources có `/home/...`, `C:\...` hoặc username không?
- `BOOT-INF/lib` có dependency khác version không?
- Archive metadata/order đã được chuẩn hóa chưa?

**Không chạy scanner in toàn bộ secret** ra CI log. Chỉ trích xuất file/cấu trúc cần chẩn đoán vào workspace được bảo vệ. Không kết luận absolute path leak từ build logs nếu path không được ghi vào artifact.

### Bài D — Đặt quality gate

Một release candidate được coi đạt mục tiêu tái lập đã chọn khi:
1. Hai checkout độc lập cùng source revision và dependency set.
2. Toolchain/plugin/configuration xác định rõ.
3. Có thay đổi có chủ đích giữa path, timezone và locale.
4. Hai executable JAR có bytes giống nhau (có `cmp` hoặc tương đương).
5. Test runtime cũng chạy dưới nhiều timezone/locale và không lệ thuộc defaults nếu không phải requirement.
6. Metadata phát hành (version/commit) ổn định, không ghi secret hay host-specific data.

Nếu bước 4 fail, lưu evidence và tìm nguồn khác biệt; không sửa hash bằng cách ghi đè binary hay tắt kiểm tra.

## 19. Checklist triển khai trong dự án thật

- [ ] Xác định loại artifact cần reproducible: plain JAR, Boot JAR, WAR, container image hay tất cả.
- [ ] Pin source revision, Maven/Gradle Wrapper, plugin/dependency versions và JDK toolchain.
- [ ] Không ghi absolute workspace path, username, hostname, home directory vào generated resources/manifest.
- [ ] Dùng resource/classpath identifiers hoặc relative paths với separator ổn định.
- [ ] Các file generated từ directory/map/database được sort trước khi serialize.
- [ ] Không ghi `Instant.now()`/`LocalDateTime.now()` vào artifact; pin release timestamp hoặc loại trường.
- [ ] Maven dùng `project.build.outputTimestamp`, các archive plugins hỗ trợ tính tái lập.
- [ ] Gradle archive tasks dùng `preserveFileTimestamps=false`, `reproducibleFileOrder=true` (mặc định từ Gradle 9).
- [ ] Nếu bật Spring Boot build-info, xử lý `build.time` ở Maven/Gradle.
- [ ] Generated text dùng UTF-8 và newline convention được xác định; Git attributes được review.
- [ ] Dữ liệu machine-readable dùng `Locale.ROOT`/locale explicit và `Instant`/zone explicit.
- [ ] Tests có Clock injection, chạy matrix với nhiều locale/timezone.
- [ ] Tách build JVM, test JVM và runtime Spring Boot JVM khi đặt flags.
- [ ] Khai báo input/output cho custom tasks, không để Gradle cache che hidden state.
- [ ] Hai clean builds ở hai workspace thực sự được so sánh SHA-256/bytes.
- [ ] Khi mismatch, inspect ZIP metadata, generated files, toolchain và dependencies trước.
- [ ] Runtime secrets/config nằm ngoài immutable artifact.
- [ ] CI phát hành đúng artifact đã kiểm thử, cùng version/digest và lưu evidence QA.

- Oracle Java 17 – [Locale](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/Locale.html): locale-sensitive behavior và default locale.
- Java 17 – [Instant](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/time/Instant.html), [Clock](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/time/Clock.html), [ZoneId](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/time/ZoneId.html): thời gian với explicit inputs.

**Ghi nhớ:** để loại bỏ ảnh hưởng của **đường dẫn tuyệt đối, múi giờ và locale**, hãy biến chúng từ *đầu vào ngầm* thành *đầu vào được kiểm soát hoặc bị loại khỏi artifact*. Dùng **relative resource names**, **UTC/Instant hoặc timezone explicit**, **Locale.ROOT/locale nghiệp vụ explicit**, **UTF-8/LF**, timestamp archive ổn định và toolchain/dependency đã pin. Chốt bằng **hai lần clean build ở hai workspace với locale/timezone khác nhau và so sánh bytes thật**; chỉ vậy mới có bằng chứng bản dựng Spring Boot đang đạt tiêu chí reproducibility đã định.
