# Spring Cloud Service Communication — Load Balancing

**Spring Cloud LoadBalancer** hỗ trợ cân bằng tải phía client (*client-side load balancing*) khi một dịch vụ có nhiều instance. Thay vì mã gọi HTTP giữ địa chỉ IP/port cố định, ứng dụng gọi bằng **service ID** và để LoadBalancer chọn một `ServiceInstance` phù hợp. Danh sách instance có thể đến từ service discovery như Eureka hoặc từ cấu hình đơn giản để học và kiểm thử. Đây là tầng lựa chọn điểm đích ở ứng dụng; cần phân biệt với load balancer phía server hoặc cơ chế phân phối lưu lượng sẵn có của hạ tầng.

Module dành cho người đã biết Java, Spring Boot, HTTP và các khái niệm microservices cơ bản. Bạn sẽ tìm hiểu `DiscoveryClient`, `ServiceInstanceListSupplier`, starter `spring-cloud-starter-loadbalancer` và cách chọn giữa Round Robin với Random. Tiếp theo, bạn thực hành gọi `http://service-id/...` bằng `@LoadBalanced RestClient.Builder` hoặc `WebClient.Builder`, rồi đối chiếu với OpenFeign. Khi dùng `@FeignClient(name = "...")` không cấu hình URL tĩnh, Feign có thể phối hợp với LoadBalancer để tìm instance; ngược lại, khai báo URL cụ thể thường bỏ qua bước cân bằng tải theo service name.

Phần cuối tập trung vào danh sách instance được cache, health check, ưu tiên theo zone/hint, retry và giới hạn phục hồi. Đặc biệt, không nên retry bừa bãi các thao tác có tác dụng phụ như tạo đơn hàng hoặc chuyển tiền nếu chưa bảo đảm tính idempotent. Qua demo nhiều instance, bạn sẽ kiểm tra phân phối request, tình huống một instance lỗi và thống kê `loadbalancer.requests` bằng Micrometer. Hoàn thành module, bạn có thể thiết lập đường gọi liên dịch vụ đơn giản, giải thích vì sao instance được chọn và nhận diện những rủi ro vận hành của load balancing phía client.
