# Namespace và mapping

Trong Spring Batch, cấu hình XML dùng namespace để phân biệt các vocabulary của Spring Framework, Spring Batch và những thư viện khác. Namespace cho phép một file XML chứa nhiều loại phần tử mà không nhầm lẫn các tên như `job`, `step`, `bean` hoặc `property`. Schema tương ứng mô tả phần tử và thuộc tính hợp lệ; Spring namespace parser đọc các phần tử đó và chuyển chúng thành bean definition cùng cấu hình runtime.

Khi khai báo một job bằng XML, thường gặp các phần chính:

- `xmlns:batch` ánh xạ prefix `batch` tới namespace URI của Spring Batch.
- `xsi:schemaLocation` ánh xạ namespace URI tới vị trí XSD dùng để kiểm tra cấu trúc XML.
- `batch:job`, `batch:step`, `batch:chunk` mô tả cấu trúc job và step.
- `bean` và `property` thuộc Spring Beans namespace để khai báo object và dependency.
- Các thuộc tính như `reader`, `processor`, `writer`, `job-repository` tham chiếu tới bean đã đăng ký trong application context.

Có hai loại mapping cần hiểu riêng: mapping namespace URI tới XSD để XML được nhận diện/kiểm tra, và mapping tên bean/thuộc tính XML tới object mà Spring Batch sử dụng khi chạy. Khai báo đúng namespace nhưng tham chiếu sai bean vẫn làm application context không khởi tạo được; tham chiếu bean đúng nhưng namespace/XSD sai thì XML parser không hiểu phần tử batch.

## Namespace trong XML là gì?

XML namespace là cơ chế định danh tên phần tử và thuộc tính bằng một URI. URI giúp phân biệt các vocabulary ngay cả khi chúng dùng cùng local name.

Ví dụ hai thư viện có thể cùng định nghĩa phần tử `job`. Nếu một phần tử thuộc namespace A và phần tử kia thuộc namespace B, XML parser phân biệt chúng bằng cặp namespace URI và local name, không chỉ dựa trên chữ `job`.

Trong Spring XML, prefix thường được dùng để viết tên có namespace:

```xml
<beans xmlns="http://www.springframework.org/schema/beans"
       xmlns:batch="http://www.springframework.org/schema/batch">

    <bean id="dataSource" class="..."/>

    <batch:job id="importJob">
        <!-- Các phần tử thuộc vocabulary Spring Batch -->
    </batch:job>
</beans>
```

Ở đây:

- `beans` không có prefix vì namespace Spring Beans được khai báo làm default namespace.
- `batch:job` có prefix `batch`, nên thuộc Spring Batch namespace.
- `id` là attribute không có prefix; theo quy tắc XML namespace, attribute không prefix không tự động thuộc default namespace.

Namespace URI là định danh vocabulary, không nhất thiết là URL mà ứng dụng phải tải trực tiếp khi chạy. Spring và XML tooling có thể resolve schema thông qua tài nguyên được đóng gói trong dependency.

## Prefix và namespace URI

Prefix như `batch`, `beans`, `xsi` là bí danh cục bộ trong tài liệu XML. Namespace URI mới là định danh thực sự.

Hai cách khai báo dưới đây có cùng ý nghĩa về namespace của Spring Batch:

```xml
<beans xmlns="http://www.springframework.org/schema/beans"
       xmlns:batch="http://www.springframework.org/schema/batch">
    <batch:job id="importJob"/>
</beans>
```

```xml
<beans xmlns="http://www.springframework.org/schema/beans"
       xmlns:sb="http://www.springframework.org/schema/batch">
    <sb:job id="importJob"/>
</beans>
```

Trong ví dụ thứ hai, prefix `sb` thay cho `batch`. XML parser vẫn nhận diện phần tử là Spring Batch `job` vì namespace URI không đổi.

Nên giữ prefix quen thuộc `batch` để người đọc dễ nhận ra cấu hình Spring Batch. Việc đổi prefix không làm thay đổi bean hoặc flow runtime, miễn là URI được giữ chính xác.

### Cùng local name nhưng khác namespace

Ví dụ `bean` trong Spring Beans namespace và một phần tử `bean` thuộc vocabulary khác là hai tên XML khác nhau. XML parser phân biệt theo namespace URI + local name.

Điều này giải thích vì sao có thể đặt các vocabulary cạnh nhau:

```xml
<bean id="orderReader" class="com.example.OrderReader"/>

<batch:step id="importStep">
    <batch:tasklet>
        <batch:chunk reader="orderReader" writer="orderWriter"
                     commit-interval="100"/>
    </batch:tasklet>
</batch:step>
```

`bean` khai báo object; `batch:step`, `batch:tasklet` và `batch:chunk` mô tả cấu trúc batch. Chúng có thể cùng tồn tại vì thuộc các namespace vocabulary khác nhau.

## Khai báo Spring Batch namespace

Một file cấu hình thường khai báo ba namespace quan trọng:

```xml
<beans xmlns="http://www.springframework.org/schema/beans"
       xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
       xmlns:batch="http://www.springframework.org/schema/batch"
       xsi:schemaLocation="
           http://www.springframework.org/schema/beans
           https://www.springframework.org/schema/beans/spring-beans.xsd
           http://www.springframework.org/schema/batch
           https://www.springframework.org/schema/batch/spring-batch.xsd">

    <!-- Bean và cấu hình Spring Batch đặt ở đây -->

</beans>
```

Ý nghĩa:

| Khai báo | Vai trò |
| --- | --- |
| `xmlns=".../beans"` | Đặt Spring Beans làm default namespace |
| `xmlns:xsi=".../XMLSchema-instance"` | Khai báo namespace cho các attribute chuẩn như `xsi:schemaLocation` |
| `xmlns:batch=".../batch"` | Đặt prefix `batch` cho phần tử Spring Batch |
| `xsi:schemaLocation` | Cung cấp các cặp namespace URI và vị trí XSD tương ứng |

Namespace URI của Spring Batch thường là `http://www.springframework.org/schema/batch`. Schema location trỏ tới `spring-batch.xsd`. Với Spring Beans, namespace URI thường là `http://www.springframework.org/schema/beans` và schema là `spring-beans.xsd`.

Trong ví dụ, URI namespace dùng `http`, còn schema location dùng `https`. Điều này không có nghĩa hai namespace khác nhau: namespace identity nằm ở URI trong `xmlns`, còn schema location là địa chỉ tài nguyên XSD. Có thể gặp cấu hình dùng `http` cho cả hai trong tài liệu hoặc dự án cũ; quan trọng là URI namespace phải đúng và schema location phải resolve được theo môi trường.

## xsi:schemaLocation ánh xạ namespace tới XSD

`xsi:schemaLocation` nhận danh sách các cặp giá trị:

```text
namespace-URI-1 schema-URL-1
namespace-URI-2 schema-URL-2
...
```

Mỗi cặp gồm namespace URI và vị trí schema dùng để mô tả vocabulary đó. Trong XML, khoảng trắng hoặc xuống dòng chỉ dùng để phân tách các giá trị; không phải mỗi dòng là một khai báo độc lập.

Ví dụ:

```xml
xsi:schemaLocation="
    http://www.springframework.org/schema/beans
    https://www.springframework.org/schema/beans/spring-beans.xsd
    http://www.springframework.org/schema/batch
    https://www.springframework.org/schema/batch/spring-batch.xsd">
```

Ở đây có hai cặp mapping: Spring Beans namespace tới `spring-beans.xsd`, và Spring Batch namespace tới `spring-batch.xsd`.

`xsi:schemaLocation` không phải là namespace declaration và cũng không đổi prefix. `xmlns:batch` khai báo vocabulary; `xsi:schemaLocation` cung cấp schema location để validator/tooling kiểm tra vocabulary đó.

### Namespace URI và schema URL không phải một thứ

| Thành phần | Ví dụ | Chức năng |
| --- | --- | --- |
| Namespace URI | `http://www.springframework.org/schema/batch` | Định danh tên phần tử Spring Batch |
| Schema location | `https://www.springframework.org/schema/batch/spring-batch.xsd` | Vị trí XSD mô tả cấu trúc phần tử/attribute |
| Prefix | `batch` | Bí danh ngắn để viết tên phần tử |
| Local name | `job` | Tên phần tử bên trong vocabulary |

Một phần tử như `<batch:job>` được nhận diện bằng namespace URI của `batch` và local name `job`. XSD giúp xác định `job` có hợp lệ không, có thuộc tính nào và chứa các phần tử con nào.

## Spring namespace parser và bean definition

Spring XML namespace không chỉ phục vụ kiểm tra cú pháp. Spring có cơ chế namespace handler/parser để chuyển các phần tử đặc biệt thành bean definition.

Ví dụ:

```xml
<batch:job id="importJob">
    <batch:step id="importStep">
        ...
    </batch:step>
</batch:job>
```

Namespace parser của Spring Batch đọc cấu trúc này và tạo cấu hình runtime tương ứng, bao gồm job, step, flow và các thành phần hạ tầng liên quan theo cấu hình namespace. Người dùng không phải tự tạo từng factory object nội bộ cho mỗi phần tử.

Trong khi đó, phần tử:

```xml
<bean id="orderReader" class="com.example.OrderReader"/>
```

thuộc Spring Beans namespace và được bean definition parser chuyển thành bean definition có tên `orderReader`.

Khi `batch:chunk` tham chiếu `reader="orderReader"`, namespace parser Spring Batch liên kết thuộc tính đó với bean có ID tương ứng trong application context.

## Ví dụ cấu hình job hoàn chỉnh

Ví dụ sau minh họa một chunk step đọc dữ liệu và ghi vào database. Các class reader, processor và writer là class ứng dụng; ví dụ tập trung vào cấu trúc namespace và mapping bean reference.

```xml
<beans xmlns="http://www.springframework.org/schema/beans"
       xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
       xmlns:batch="http://www.springframework.org/schema/batch"
       xsi:schemaLocation="
           http://www.springframework.org/schema/beans
           https://www.springframework.org/schema/beans/spring-beans.xsd
           http://www.springframework.org/schema/batch
           https://www.springframework.org/schema/batch/spring-batch.xsd">

    <bean id="orderReader" class="com.example.batch.OrderReader"/>
    <bean id="orderProcessor" class="com.example.batch.OrderProcessor"/>
    <bean id="orderWriter" class="com.example.batch.OrderWriter"/>

    <batch:job id="importOrdersJob">
        <batch:step id="importOrdersStep">
            <batch:tasklet>
                <batch:chunk reader="orderReader"
                             processor="orderProcessor"
                             writer="orderWriter"
                             commit-interval="100"/>
            </batch:tasklet>
        </batch:step>
    </batch:job>

</beans>
```

Mapping trong ví dụ:

| XML | Được hiểu là |
| --- | --- |
| `id="importOrdersJob"` | Tên bean job được đăng ký trong application context |
| `batch:step id="importOrdersStep"` | Một step thuộc job |
| `reader="orderReader"` | Tham chiếu bean reader có ID `orderReader` |
| `processor="orderProcessor"` | Tham chiếu bean processor có ID `orderProcessor` |
| `writer="orderWriter"` | Tham chiếu bean writer có ID `orderWriter` |
| `commit-interval="100"` | Số item tối đa trong một chunk trước khi commit theo cấu hình step |

Ví dụ này giả định các bean được triển khai đúng interface Spring Batch và có các dependency cần thiết. Trong cấu hình thực tế, reader/writer thường cần các property như `dataSource`, `resource`, `lineMapper` hoặc SQL. Các property đó được inject qua Spring Beans XML hoặc constructor của bean.

## Khác nhau giữa bean definition và bean reference

Khai báo bean tạo ra object trong application context. Reference liên kết một thành phần khác với object đó.

```xml
<bean id="orderWriter" class="com.example.batch.OrderWriter">
    <property name="dataSource" ref="dataSource"/>
    <property name="sql" value="INSERT INTO orders(order_id) VALUES (?)"/>
</bean>
```

Trong ví dụ:

- `id="orderWriter"` đặt tên bean.
- `class` xác định implementation class.
- `property name="dataSource"` chọn property cần inject.
- `ref="dataSource"` tham chiếu một bean khác.
- `value="..."` inject một giá trị literal/string.

`ref` và `value` không thể thay thế tùy ý. Nếu property yêu cầu `DataSource`, dùng `ref` tới bean datasource. Nếu property nhận chuỗi SQL, dùng `value`.

### ID và alias

Bean có thể có một ID chính và các alias. Khi một thuộc tính batch tham chiếu bean, tên được dùng phải được Spring resolve thành bean duy nhất.

```xml
<bean id="orderReader" name="ordersInputReader,primaryOrderReader"
      class="com.example.batch.OrderReader"/>
```

Các tên alias có thể giúp tương thích với cấu hình khác, nhưng nên chọn một tên nhất quán để dùng trong `reader`, `processor`, `writer` và các property `ref`. Tránh trùng bean ID hoặc alias gây ambiguity.

## Default namespace và prefix

Nếu Spring Beans là default namespace, các phần tử `bean`, `property`, `constructor-arg` có thể viết không prefix. Spring Batch elements cần prefix `batch`.

```xml
<beans xmlns="http://www.springframework.org/schema/beans"
       xmlns:batch="http://www.springframework.org/schema/batch">

    <bean id="reader" class="com.example.Reader"/>

    <batch:job id="job">
        ...
    </batch:job>
</beans>
```

Nếu không khai báo default namespace, có thể dùng prefix cho cả Spring Beans:

```xml
<beans:beans xmlns:beans="http://www.springframework.org/schema/beans"
             xmlns:batch="http://www.springframework.org/schema/batch">

    <beans:bean id="reader" class="com.example.Reader"/>
    <batch:job id="job">...</batch:job>

</beans:beans>
```

Hai kiểu đều hợp lệ nếu namespace URI và schema mapping chính xác. Dùng default namespace cho beans và prefix `batch` thường dễ đọc trong file cấu hình Spring.

### Default namespace không áp dụng tự động cho attribute

Quy tắc XML namespace quan trọng: default namespace áp dụng cho tên element không prefix, nhưng không áp dụng cho attribute không prefix.

Ví dụ:

```xml
<bean id="orderReader" class="com.example.OrderReader"/>
```

Phần tử `bean` thuộc default Spring Beans namespace. Các attribute `id` và `class` không có namespace prefix. Đây là cách schema Spring định nghĩa và mong đợi chúng.

Không thêm prefix vào attribute tùy tiện, chẳng hạn `batch:id`, nếu schema không khai báo attribute đó trong Batch namespace. Hãy tuân theo tên attribute của XSD.

## Mapping các thành phần job, step và flow

Spring Batch namespace ánh xạ cấu trúc XML thành mô hình job flow.

### Job và step

```xml
<batch:job id="dailyImportJob">
    <batch:step id="readStep" next="validateStep">
        <batch:tasklet ref="readTasklet"/>
    </batch:step>

    <batch:step id="validateStep">
        <batch:tasklet ref="validateTasklet"/>
    </batch:step>
</batch:job>
```

`batch:job` là container cho flow; `batch:step` định nghĩa một step. `next` biểu thị bước tiếp theo theo flow tuyến tính. `ref` trong `batch:tasklet` tham chiếu tasklet bean đã khai báo. Cú pháp cụ thể của tasklet/chunk cần tuân theo XSD của phiên bản Spring Batch trong dự án.

### Flow và transition

Với flow có nhánh theo exit status, XML namespace cho phép mô tả transition bằng các phần tử/thuộc tính flow tương ứng. Mỗi transition ánh xạ một trạng thái kết quả của step sang step hoặc flow tiếp theo.

Ví dụ khái niệm:

```text
validateStep
   |
   +-- COMPLETED --> importStep
   |
   +-- FAILED ----> errorHandlingStep
   |
   +-- * ---------> end / fail theo flow definition
```

Trong XML, các transition phải dùng đúng phần tử và thuộc tính mà XSD của Spring Batch version hỗ trợ. Không tự đặt attribute như `onSuccess` hoặc `onFailure` nếu schema không định nghĩa. Dùng IDE completion hoặc XSD tương ứng để xác nhận cú pháp `next`, `on`, `to`, `end`, `fail` và các element flow trong dự án.

## Mapping job repository và transaction manager

Job và step cần hạ tầng để lưu metadata, checkpoint và transaction. Trong XML, các thành phần này được tham chiếu bằng bean ID.

Ví dụ khai báo infrastructure bean theo cách tường minh:

```xml
<bean id="dataSource" class="...">
    <!-- Cấu hình datasource -->
</bean>

<bean id="transactionManager" class="...">
    <constructor-arg ref="dataSource"/>
</bean>

<batch:job-repository id="jobRepository"
                      data-source="dataSource"
                      transaction-manager="transactionManager"/>
```

Đây là dạng cấu hình minh họa; class cụ thể của datasource và transaction manager phụ thuộc database/provider. Tên thuộc tính và cách khai báo repository phải khớp XSD Spring Batch version đang dùng.

Khi job/step dùng repository hoặc transaction manager tường minh, các bean ID phải resolve được trong application context. Không nhầm namespace parser với việc tự động tạo ra một datasource có cấu hình kết nối thực tế; ứng dụng vẫn phải cung cấp datasource và thông tin kết nối.

## Mapping property bằng ref và value

Spring Beans namespace cung cấp cách inject dependency vào bean:

```xml
<bean id="orderWriter" class="com.example.batch.OrderWriter">
    <property name="dataSource" ref="dataSource"/>
    <property name="sql" value="INSERT INTO orders(order_id) VALUES (?)"/>
    <property name="batchSize" value="100"/>
</bean>
```

Spring chuyển đổi string literal sang kiểu property khi có converter phù hợp. `ref` dùng khi property cần một bean/object; `value` dùng cho literal. Với collection hoặc map, có thể dùng các phần tử Spring Beans/Util namespace tương ứng.

Nếu dùng `util` namespace, cần khai báo thêm URI và XSD:

```xml
<beans xmlns="http://www.springframework.org/schema/beans"
       xmlns:util="http://www.springframework.org/schema/util"
       xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
       xsi:schemaLocation="
           http://www.springframework.org/schema/beans https://www.springframework.org/schema/beans/spring-beans.xsd
           http://www.springframework.org/schema/util https://www.springframework.org/schema/util/spring-util.xsd">

    <util:map id="statusCodes">
        <entry key="NEW" value="N"/>
        <entry key="COMPLETED" value="C"/>
    </util:map>
</beans>
```

Đây là ví dụ namespace phụ trợ của Spring, không phải Spring Batch namespace. Mỗi vocabulary mới cần namespace declaration và schema mapping tương ứng.

## Late binding trong XML bằng StepScope

Một số bean chỉ có thể được cấu hình khi job/step đã bắt đầu, ví dụ reader cần lấy input file từ `JobParameters` hoặc `jobExecutionContext`. XML có thể khai báo bean với `scope="step"` và dùng SpEL trong property value.

```xml
<bean id="orderReader"
      class="com.example.batch.OrderReader"
      scope="step">
    <property name="resource"
              value="file:#{jobParameters['inputFile']}"/>
</bean>
```

`scope="step"` trì hoãn việc tạo target bean tới khi có `StepExecution` hiện tại. Biểu thức SpEL có thể đọc `jobParameters`, `jobExecutionContext` hoặc `stepExecutionContext` theo scope.

Ví dụ đọc file đã được step trước promote lên job context:

```xml
<bean id="stagingReader"
      class="com.example.batch.StagingReader"
      scope="step">
    <property name="resource"
              value="file:#{jobExecutionContext['generatedFile']}"/>
</bean>
```

Nếu giá trị được ghi vào step context của step trước, cần promote lên job context trước khi step sử dụng. Namespace không tự động chuyển mọi key từ step context sang job context.

Trong XML, cần bảo đảm scope `step` được đăng ký bởi cấu hình Spring Batch namespace/infrastructure phù hợp. Khi inject scoped bean vào bean singleton, Spring sử dụng scoped proxy theo cấu hình scope; nếu có lỗi khởi tạo sớm, kiểm tra cách khai báo scope và proxy trong phiên bản dự án.

## Mapping XML với Java configuration

XML namespace và Java configuration có thể mô tả cùng một mô hình job/step, nhưng cú pháp khác nhau.

| Khái niệm | XML namespace | Java configuration |
| --- | --- | --- |
| Job | `<batch:job id="importJob">` | `new JobBuilder("importJob", jobRepository)` |
| Step | `<batch:step id="importStep">` | `new StepBuilder("importStep", jobRepository)` |
| Reader reference | `reader="orderReader"` | `.reader(orderReader)` |
| Processor reference | `processor="orderProcessor"` | `.processor(orderProcessor)` |
| Writer reference | `writer="orderWriter"` | `.writer(orderWriter)` |
| Chunk size | `commit-interval="100"` | `.chunk(100, transactionManager)` |
| Bean dependency | `ref="dataSource"` | Constructor/method parameter injection |

Ví dụ Java tương ứng với chunk XML:

```java
@Bean
Job importOrdersJob(JobRepository jobRepository, Step importOrdersStep) {
    return new JobBuilder("importOrdersJob", jobRepository)
            .start(importOrdersStep)
            .build();
}

@Bean
Step importOrdersStep(
        JobRepository jobRepository,
        PlatformTransactionManager transactionManager,
        ItemReader<Order> orderReader,
        ItemProcessor<Order, Order> orderProcessor,
        ItemWriter<Order> orderWriter) {

    return new StepBuilder("importOrdersStep", jobRepository)
            .<Order, Order>chunk(100, transactionManager)
            .reader(orderReader)
            .processor(orderProcessor)
            .writer(orderWriter)
            .build();
}
```

Chọn một phong cách cấu hình nhất quán cho một phần job. Ứng dụng có thể import XML và Java configuration cùng nhau, nhưng cần tránh khai báo trùng bean/job ID hoặc tạo hai job cùng tên không chủ ý.

## Namespace phụ trợ thường gặp

Một file Spring XML có thể khai báo nhiều namespace:

| Prefix | Namespace thường dùng | Mục đích |
| --- | --- | --- |
| Không prefix | Spring Beans | `bean`, `property`, `constructor-arg` |
| `batch` | Spring Batch | `job`, `step`, `chunk`, `tasklet`, flow |
| `xsi` | XML Schema Instance | `schemaLocation`, `nil` |
| `util` | Spring Util | `map`, `list`, `set`, `properties` |
| `context` | Spring Context | component scan, property placeholder/configuration |
| `tx` | Spring TX | transaction advice và annotation-driven transaction |
| `aop` | Spring AOP | proxy và pointcut cấu hình XML |

Chỉ khai báo namespace thực sự cần dùng. Mỗi namespace thêm vào cần URI chính xác và cặp schema location nếu cần XSD validation.

Ví dụ kết hợp `context` và `batch`:

```xml
<beans xmlns="http://www.springframework.org/schema/beans"
       xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
       xmlns:batch="http://www.springframework.org/schema/batch"
       xmlns:context="http://www.springframework.org/schema/context"
       xsi:schemaLocation="
           http://www.springframework.org/schema/beans https://www.springframework.org/schema/beans/spring-beans.xsd
           http://www.springframework.org/schema/batch https://www.springframework.org/schema/batch/spring-batch.xsd
           http://www.springframework.org/schema/context https://www.springframework.org/schema/context/spring-context.xsd">

    <context:component-scan base-package="com.example.batch"/>

    <batch:job id="importJob">
        ...
    </batch:job>
</beans>
```

`context:component-scan` thuộc Spring Context namespace, còn `batch:job` thuộc Spring Batch namespace. Hai parser xử lý hai vocabulary riêng trong cùng application context.

## XML schema và version compatibility

XSD mô tả cấu trúc mà một phiên bản namespace hỗ trợ. Nếu dependency Spring Batch và schema mà IDE/parser dùng không tương thích, có thể gặp các lỗi:

- IDE báo element hoặc attribute không tồn tại.
- XML validation từ chối thuộc tính hợp lệ ở version khác.
- Runtime namespace parser không hiểu một phần tử mới.
- Cấu hình cũ bị deprecated hoặc thay đổi semantics khi nâng cấp.

Khi nâng Spring Batch version:

1. Kiểm tra version dependency thực tế trong build.
2. Dùng schema Spring Batch tương thích với dependency.
3. Kiểm tra release notes và migration guide cho XML namespace.
4. Validate XML bằng cùng classpath/runtime mà ứng dụng dùng.
5. Chạy integration test khởi tạo application context và launch job.

Không nên chỉ sửa schema URL để làm IDE hết gạch đỏ nếu runtime vẫn dùng thư viện cũ. Schema location và namespace parser trong dependency phải thống nhất.

Spring thường cung cấp schema mapping trong các JAR để resolver có thể tìm XSD từ classpath. Vì vậy, một dự án có thể validate schema mà không cần tải XSD trực tiếp từ internet, tùy cấu hình XML parser và tooling. Nếu IDE không resolve schema offline, kiểm tra catalog/cache và dependency thay vì đổi namespace URI.

## Validation XML trong IDE và lúc khởi động

IDE có thể dùng XSD để gợi ý element, attribute và phát hiện cấu trúc sai. Runtime Spring cũng parse XML và đăng ký bean definitions. Hai bước kiểm tra có liên quan nhưng không hoàn toàn giống nhau.

Schema validation có thể phát hiện:

- Sai tên element, ví dụ viết `batch:jobs` thay vì `batch:job`.
- Thiếu attribute bắt buộc theo XSD.
- Đặt element con ở vị trí không hợp lệ.
- Giá trị attribute không thuộc kiểu/enum được schema mô tả.
- Namespace prefix chưa được khai báo.

Application context initialization còn có thể phát hiện:

- Bean ID được tham chiếu nhưng không tồn tại.
- Bean class không có constructor/property phù hợp.
- Dependency injection bị ambiguity.
- Class không implement đúng interface Spring Batch yêu cầu.
- Job/step cấu hình sai về repository, transaction manager hoặc flow.

Một file XML có thể hợp lệ theo XSD nhưng vẫn không khởi động được vì `reader="missingReader"` không tìm thấy bean. Ngược lại, bean có tồn tại nhưng element batch sai namespace thì parser không thể xử lý đúng.

## Lỗi namespace thường gặp

### Quên khai báo prefix

Nếu viết `<batch:job>` mà không có `xmlns:batch`, XML parser báo prefix chưa được khai báo. Thêm namespace declaration đúng ở element gốc hoặc ancestor.

### Dùng sai namespace URI

Prefix có thể đúng tên `batch` nhưng URI bị gõ sai. Parser sẽ xem đó là một vocabulary khác và không tìm thấy Batch namespace handler. Copy URI canonical từ cấu hình tương thích thay vì tự gõ.

### Khai báo namespace nhưng thiếu schema mapping

XML parser vẫn có thể nhận diện expanded name, nhưng tooling/schema validation có thể không biết XSD tương ứng. Thêm cặp namespace URI và XSD location trong `xsi:schemaLocation`.

### Đảo thứ tự cặp schemaLocation

`schemaLocation` là danh sách các cặp URI-location. Nếu thiếu một location hoặc đặt sai thứ tự, validator có thể tải nhầm schema hoặc báo lỗi. Kiểm tra từng cặp theo đúng thứ tự.

### Đặt Batch làm default nhưng quên prefix Beans

Nếu default namespace là Batch, phần tử `bean` không prefix sẽ bị hiểu là phần tử Batch thay vì Spring Beans. Có thể giữ Beans làm default và dùng `batch:` cho Batch, hoặc prefix rõ cả hai namespace.

### Dùng prefix không nhất quán

Prefix có thể tùy chọn, nhưng trong một file nên dùng một alias nhất quán cho mỗi namespace. Trộn `batch`, `sb`, `springBatch` làm cấu hình khó đọc và dễ nhầm.

### Dùng `ref` cho literal hoặc `value` cho bean

`ref` cần tên bean; `value` cần literal/property expression. Dùng sai loại làm Spring không convert được dependency hoặc tìm bean không tồn tại.

### Tham chiếu sai bean ID

`reader="orderReader"` phải trỏ tới bean ID/alias thực tế. Tên class hoặc tên property không tự động trở thành bean ID nếu không khai báo như vậy.

### Trùng bean ID hoặc job ID

Nhiều file XML import vào cùng context có thể khai báo trùng ID. Tùy cấu hình bean overriding, context có thể báo lỗi hoặc bean bị ghi đè. Dùng ID rõ ràng, duy nhất và kiểm soát file import.

### XSD và dependency khác version

IDE có thể validate theo schema khác runtime. Đồng bộ dependency và schema mapping, rồi kiểm tra application context bằng đúng classpath.

## Quy trình chẩn đoán lỗi mapping

Khi Spring không parse hoặc khởi tạo được cấu hình XML, có thể kiểm tra theo trình tự:

1. Xác định element lỗi và expanded namespace URI của nó.
2. Kiểm tra prefix được khai báo đúng ở element gốc/ancestor.
3. Kiểm tra `xsi:schemaLocation` có cặp URI-XSD tương ứng.
4. Xác nhận XSD tương thích với Spring Batch dependency.
5. Kiểm tra cấu trúc element/attribute theo schema.
6. Kiểm tra bean ID/alias mà Batch elements tham chiếu.
7. Kiểm tra class, constructor, property và kiểu dependency của bean.
8. Kiểm tra `JobRepository`, `DataSource` và transaction manager.
9. Khởi tạo application context trong test để phát hiện lỗi wiring.
10. Launch job với dữ liệu test để xác nhận flow và component mapping runtime.

Đọc root cause trong stack trace. Một lỗi schema validation khác với `NoSuchBeanDefinitionException`, `BeanCreationException` hoặc lỗi khi step thực thi. Sửa đúng tầng giúp tránh thay namespace URI để xử lý một lỗi thực chất là bean reference.

## Kiểm thử cấu hình namespace và mapping

Nên có integration test nạp file XML trong application context, xác nhận job bean tồn tại và chạy được với fixture nhỏ.

### Kiểm tra application context

Ví dụ:

```java
@SpringJUnitConfig(locations = "classpath:/batch/import-job.xml")
class ImportJobXmlConfigurationTest {

    @Autowired
    private ApplicationContext applicationContext;

    @Autowired
    @Qualifier("importOrdersJob")
    private Job importOrdersJob;

    @Test
    void loadsBatchNamespaceAndBeanReferences() {
        assertNotNull(importOrdersJob);
        assertTrue(applicationContext.containsBean("orderReader"));
        assertTrue(applicationContext.containsBean("orderProcessor"));
        assertTrue(applicationContext.containsBean("orderWriter"));
    }
}
```

Test này xác nhận XML parser đã tạo job và các bean reference tồn tại. Nó không chứng minh job thực thi đúng dữ liệu; cần thêm test launch.

### Kiểm tra job execution

Với Spring Batch test support, có thể dùng `JobLauncherTestUtils` để chạy job và xác nhận `JobExecution` cùng `StepExecution` đạt trạng thái mong muốn. Đảm bảo test context nạp đúng job XML và chỉ định job nếu context có nhiều job.

```java
JobExecution execution = jobLauncherTestUtils.launchJob(testParameters);
assertEquals(BatchStatus.COMPLETED, execution.getStatus());
```

Sau đó kiểm tra business output trong database/file. Job `COMPLETED` chỉ xác nhận flow kết thúc thành công theo metadata; không thay thế việc kiểm tra dữ liệu đã được mapping đúng.

### Kiểm tra lỗi reference

Có thể tạo một cấu hình test cố ý tham chiếu bean không tồn tại để xác nhận context fail ở bước khởi tạo. Không cần giữ cấu hình lỗi trong production; đây là test cho cơ chế wiring hoặc tài liệu nội bộ nếu dự án có yêu cầu.

## Nguyên tắc tổ chức file XML

Khi dự án có nhiều job, có thể tách cấu hình thành các file theo trách nhiệm:

```text
config/
  batch-infrastructure.xml
  import-orders-job.xml
  export-orders-job.xml
  shared-readers.xml
  shared-writers.xml
```

File infrastructure khai báo repository, datasource và transaction manager. File job khai báo flow. File shared components khai báo bean có thể tái sử dụng.

Khi import file:

```xml
<import resource="classpath:/config/batch-infrastructure.xml"/>
<import resource="classpath:/config/shared-readers.xml"/>
```

`import` thuộc Spring Beans namespace và nạp thêm bean definitions vào cùng application context. Cần quản lý ID để tránh trùng và tránh import vòng.

Không tách file quá nhỏ tới mức người đọc không biết job đang tham chiếu bean ở đâu. Có thể giữ một file job tự chứa các bean đặc thù và import phần infrastructure/shared dùng chung.

## Nguyên tắc thiết kế namespace và mapping

Khi viết cấu hình Spring Batch XML, hãy xác định:

1. File dùng những vocabulary nào: Beans, Batch, Context, TX, Util hoặc AOP?
2. Mỗi prefix có namespace URI chính xác chưa?
3. `xsi:schemaLocation` có đủ từng cặp namespace URI và XSD chưa?
4. XSD có tương thích với version Spring Batch/Spring Framework trong classpath không?
5. `batch:job`, `batch:step`, `batch:chunk` được đặt đúng cấu trúc theo schema chưa?
6. Các `reader`, `processor`, `writer`, `tasklet`, `job-repository` tham chiếu đúng bean ID chưa?
7. `ref` và `value` có được dùng đúng theo kiểu dependency không?
8. Scope và SpEL có được cấu hình cho late binding đúng thời điểm không?
9. Bean ID và job/step ID có duy nhất trong application context không?
10. Integration test đã nạp XML, resolve bean và chạy job với dữ liệu đại diện chưa?

Giữ Spring Beans làm default namespace và dùng prefix `batch` cho phần tử Spring Batch thường làm cấu hình dễ đọc. Namespace URI định danh vocabulary; schema location cung cấp XSD; namespace parser biến XML thành bean/job definitions; bean ID và reference liên kết các thành phần runtime. Hiểu rõ từng lớp mapping giúp phân biệt lỗi XML schema với lỗi wiring và lỗi thực thi job.

## Ghi nhớ

Spring Batch XML dùng namespace để phân biệt vocabulary và namespace parser để chuyển element thành cấu hình job/step. `xmlns:batch` ánh xạ prefix tới URI `http://www.springframework.org/schema/batch`; `xsi:schemaLocation` cung cấp cặp namespace URI và XSD `spring-batch.xsd` để validation/tooling. Prefix chỉ là bí danh; URI mới định danh namespace. `batch:job`, `batch:step` và `batch:chunk` mô tả flow, còn bean ID và các thuộc tính `reader`, `processor`, `writer`, `ref` ánh xạ tới object trong Spring application context. Dùng `ref` cho dependency bean, `value` cho literal/SpEL, và `scope="step"` cho late binding theo execution. Giữ schema tương thích dependency, ID duy nhất và kiểm thử cả context initialization lẫn job execution để phát hiện lỗi namespace, XSD và bean mapping.
