# Map.getOrDefault và phân biệt khóa vắng với giá trị null trong Java

## 1. Vấn đề cốt lõi: một Map có ba trạng thái quan trọng

`Map<K, V>` ánh xạ mỗi **khóa** tới tối đa một **giá trị**. Trong một số implementation như `HashMap` hoặc `LinkedHashMap`, giá trị được phép là `null`. Vì vậy, ba trạng thái sau **khác nhau**:

1. **Không có khóa**: Map chưa có mapping cho khóa được hỏi.
2. **Có khóa nhưng giá trị là `null`**: Map vẫn có mapping, chỉ là giá trị mapping được lưu là `null`.
3. **Có khóa và giá trị khác `null`**: Map trả giá trị đã lưu, kể cả `0`, `false` hoặc chuỗi rỗng `""`.

`Map.getOrDefault(key, defaultValue)` có từ **Java 8** và vẫn được sử dụng trong Java hiện đại. Phương thức này có quy tắc quan trọng:

> **Chỉ trả `defaultValue` nếu Map không chứa mapping cho khóa. Nếu khóa có mapping với giá trị `null`, kết quả là `null`, không phải default.**

Đây là điểm thường bị hiểu nhầm khi đọc tên `getOrDefault`: nó **không** có nghĩa là “lấy default bất cứ khi nào `get(key)` trả null”.

Ví dụ:

```java
Map<String, String> states = new HashMap<>();
states.put("ready", "OK");
states.put("pending", null);

states.getOrDefault("ready", "UNKNOWN");   // "OK"
states.getOrDefault("pending", "UNKNOWN"); // null
states.getOrDefault("missing", "UNKNOWN"); // "UNKNOWN"
```

Các dòng trên là **đoạn minh họa trong phương thức** đã import `java.util.Map` và `java.util.HashMap`. Giá trị `"pending"` đã được lưu với `null`; `"missing"` chưa có mapping. Bài học sẽ phân biệt hai trường hợp đó bằng `containsKey` và trình bày cách xử lý khi muốn coi giá trị null cũng là “không có giá trị”.

Các API trong bài đều còn áp dụng; ví dụ đầy đủ chạy trên **JDK 17+**. `Map.getOrDefault`, `containsKey`, `computeIfAbsent`, `putIfAbsent` có từ Java 8; `Map.of` và `Objects.requireNonNullElse` cần Java 9+.

## 2. Đọc chính xác `get`, `containsKey` và `getOrDefault`

Chữ ký ba phương thức trong giao diện `Map<K, V>`:

```java
V get(Object key);

boolean containsKey(Object key);

default V getOrDefault(Object key, V defaultValue);
```

| Tình trạng mapping | `get(k)` | `containsKey(k)` | `getOrDefault(k, "FALLBACK")` |
| --- | --- | --- | --- |
| Khóa `k` vắng mặt | `null` | `false` | `"FALLBACK"` |
| Khóa `k` tồn tại, giá trị `null` | `null` | `true` | `null` |
| Khóa `k` tồn tại, giá trị `"OK"` | `"OK"` | `true` | `"OK"` |
| Khóa `k` tồn tại, giá trị `""` | `""` | `true` | `""` |

**`get(k) == null` không đủ để kết luận “khóa vắng mặt”** với Map cho phép lưu null. Khi cần phân biệt có mapping hay không, dùng `containsKey(k)`.

Một mẫu kiểm tra rõ ràng:

```java
if (!map.containsKey(key)) {
    // Khóa không tồn tại.
} else if (map.get(key) == null) {
    // Có khóa, nhưng giá trị được lưu là null.
} else {
    // Có khóa và giá trị khác null.
}
```

Đoạn này là **minh họa**: cần có biến `map` và `key`. Nếu Map đang bị thay đổi đồng thời, hai lần tra cứu `containsKey` và `get` không tạo thành phép đọc nguyên tử; xem mục về concurrency phía dưới.

### “Giá trị mặc định” không làm thay đổi Map

`getOrDefault` chỉ **đọc** và trả một giá trị. Nó không gọi `put`, không lưu mapping mới và không thay `null` đang tồn tại bằng default:

```java
Map<String, String> flags = new HashMap<>();
String name = flags.getOrDefault("mode", "standard");
// name = "standard"
// flags.containsKey("mode") == false
```

Nếu bạn cần **thêm dữ liệu thật** vào Map khi thiếu, đó là trách nhiệm của các phương thức thay đổi Map như `putIfAbsent`, `computeIfAbsent` hoặc `merge`, không phải `getOrDefault`.

### Dữ liệu không null vẫn có thể mang nghĩa “rỗng”

`getOrDefault` không coi những giá trị sau là thiếu:

- `0` hoặc `0L`.
- `false`.
- `""` hoặc `"   "`.
- `List.of()` — danh sách có thật nhưng rỗng.
- Một đối tượng domain mang trạng thái `UNKNOWN`.

Nếu khóa có mapping với các giá trị đó, `getOrDefault` trả chính giá trị đã lưu. Việc “0 nghĩa là thiếu” hay “chuỗi rỗng cần thay bằng tên mặc định” là **quy tắc nghiệp vụ riêng**, không phải hợp đồng `Map.getOrDefault`.

## 3. Ví dụ đầy đủ: ba trạng thái trên `LinkedHashMap`

Tạo tệp `MapLookupDemo.java`:

```java
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

public class MapLookupDemo {
    public static void main(String[] args) {
        Map<String, String> statuses = new LinkedHashMap<>();
        statuses.put("ready", "OK");
        statuses.put("pending", null);
        statuses.put("blank", "");

        for (String key : List.of(
                "ready", "pending", "missing", "blank")) {
            System.out.println(key
                    + " => contains=" + statuses.containsKey(key)
                    + ", get=" + statuses.get(key)
                    + ", default="
                    + statuses.getOrDefault(key, "FALLBACK"));
        }

        statuses.put(null, "NULL-KEY");

        System.out.println("null key exists = "
                + statuses.containsKey(null));
        System.out.println("null key default = "
                + statuses.getOrDefault(null, "FALLBACK"));
        System.out.println("null value exists = "
                + statuses.containsValue(null));
    }
}
```

Lệnh biên dịch và chạy:

```bash
javac -encoding UTF-8 MapLookupDemo.java
java MapLookupDemo
```

Stdout:

```text
ready => contains=true, get=OK, default=OK
pending => contains=true, get=null, default=null
missing => contains=false, get=null, default=FALLBACK
blank => contains=true, get=, default=
null key exists = true
null key default = NULL-KEY
null value exists = true
```

Đọc kết quả:

- `ready` có khóa và giá trị `"OK"` ⇒ cả `get` lẫn `getOrDefault` trả `"OK"`.
- `pending` có khóa nhưng giá trị `null` ⇒ `getOrDefault` **vẫn trả `null`**, không trả `"FALLBACK"`.
- `missing` không có khóa ⇒ `get` trả `null`, còn `getOrDefault` trả `"FALLBACK"`.
- `blank` chứa chuỗi rỗng `""` ⇒ giá trị là chuỗi rỗng, **không phải null**, nên default không được dùng. Dòng in có `get=, default=` không phải mất khóa.
- `LinkedHashMap` cho phép khóa `null` và giá trị `null`; các dòng cuối kiểm chứng điều đó. Không suy rộng tính năng khóa null sang mọi Map implementation.
- `List.of` trong đoạn mẫu cần Java 9+, nên toàn chương trình chạy trên Java 17+. `getOrDefault` vẫn là API từ Java 8.

`System.out.println` hiển thị tham chiếu `null` bằng chữ `null` thông qua phép nối chuỗi; **Map không lưu chuỗi `"null"`** trong ví dụ này. Để phân biệt giá trị null thật với chuỗi literal `"null"`, cần kiểm tra `value == null` hoặc kiểu dữ liệu, không chỉ nhìn log.

## 4. Một bảng quyết định cho nghiệp vụ

Giả sử Map dùng để lưu trạng thái phê duyệt:

| Khóa | Mapping | Diễn giải có thể có |
| --- | --- | --- |
| `request-1` | `"APPROVED"` | Đã có quyết định duyệt |
| `request-2` | `null` | Có hồ sơ nhưng chưa có kết quả; hoặc dữ liệu bị thiếu |
| `request-3` | **không có mapping** | Hồ sơ không thuộc tập dữ liệu đang xét |
| `request-4` | `"UNKNOWN"` | Đã ghi rõ trạng thái UNKNOWN |

Nếu ứng dụng dùng `getOrDefault(id, "NOT_FOUND")` thì **chỉ `request-3`** nhận `"NOT_FOUND"`. `request-2` trả `null`, còn `request-4` trả `"UNKNOWN"`.

Đừng tự quyết định rằng giá trị null tương đương không có khóa khi hợp đồng domain chưa nói như vậy. Có lúc cần phân biệt rõ **“chưa có bản ghi”**, **“có bản ghi nhưng dữ liệu chưa biết”** và **“có giá trị hợp lệ”**. Đây là các trạng thái khác nhau khi tạo báo cáo, đồng bộ hệ thống hoặc điều tra lỗi.

Nếu một Map chỉ chứa mapping không null theo hợp đồng, hai trạng thái “vắng khóa” và “giá trị null” sẽ không cùng xuất hiện. Nhưng khi map đến từ nhiều nguồn hoặc một framework có khả năng lưu null, phải kiểm chứng đặc tính đó trước khi bỏ qua `containsKey`.

## 5. Số `0`, `null`, khóa vắng và lỗi unboxing

Với `Map<String, Integer>`, `0` là một đối tượng `Integer` chứa số không, **không phải null**. Đọc kiểu `int` từ `Integer null` buộc Java unbox và ném `NullPointerException`.

Ví dụ đầy đủ `MapNumericDemo.java`:

```java
import java.util.HashMap;
import java.util.Map;
import java.util.Optional;

public class MapNumericDemo {
    public static void main(String[] args) {
        Map<String, Integer> scores = new HashMap<>();
        scores.put("zero", 0);
        scores.put("unknown", null);
        scores.put("positive", 7);

        System.out.println("zero default = "
                + scores.getOrDefault("zero", -1));
        System.out.println("missing default = "
                + scores.getOrDefault("missing", -1));
        System.out.println("unknown default = "
                + scores.getOrDefault("unknown", -1));

        System.out.println("zero exists = "
                + scores.containsKey("zero"));
        System.out.println("missing exists = "
                + scores.containsKey("missing"));
        System.out.println("unknown exists = "
                + scores.containsKey("unknown"));

        try {
            int number = scores.getOrDefault("unknown", 0);
            System.out.println(number);
        } catch (NullPointerException ex) {
            System.out.println("null unboxing = NullPointerException");
        }

        System.out.println("optional zero = "
                + Optional.ofNullable(scores.get("zero")));
        System.out.println("optional unknown = "
                + Optional.ofNullable(scores.get("unknown")));
        System.out.println("optional missing = "
                + Optional.ofNullable(scores.get("missing")));
    }
}
```

```bash
javac -encoding UTF-8 MapNumericDemo.java
java MapNumericDemo
```

```text
zero default = 0
missing default = -1
unknown default = null
zero exists = true
missing exists = false
unknown exists = true
null unboxing = NullPointerException
optional zero = Optional[0]
optional unknown = Optional.empty
optional missing = Optional.empty
```

**Ba bài học:**

1. `zero` và `missing` có thể cùng cho số `0` nếu bạn gọi `getOrDefault(key, 0)`; **giá trị 0 một mình không nói khóa đã tồn tại**.
2. `unknown` tồn tại với `null`: `getOrDefault("unknown", 0)` vẫn trả null. Khi gán kết quả đó vào `int`, việc unboxing gây `NullPointerException`.
3. `Optional.ofNullable(scores.get(key))` cũng không giữ được thông tin “khóa vắng” so với “khóa có giá trị null”: cả hai biến thành `Optional.empty()`. Nếu sự khác biệt quan trọng, dùng `containsKey` trước khi chuyển Optional hoặc định nghĩa một kiểu kết quả mang trạng thái riêng.

Mẫu an toàn nếu muốn giữ cả sự tồn tại và giá trị:

```java
String key = "unknown";
boolean present = scores.containsKey(key);
Integer stored = scores.get(key);

if (!present) {
    System.out.println("ABSENT");
} else if (stored == null) {
    System.out.println("PRESENT_NULL");
} else {
    System.out.println("PRESENT_VALUE=" + stored);
}
```

Đây là đoạn mã minh họa dùng `scores` của chương trình trên. Nếu các phần khác của ứng dụng đang sửa Map đồng thời, phải dùng cách đồng bộ/snapshot phù hợp thay vì coi `containsKey` + `get` là một read transaction.

## 6. `getOrDefault` khác với “dùng fallback nếu giá trị null”

Có **hai chính sách** cần phân biệt rõ:

- **Chính sách A — fallback khi không có mapping:** `map.getOrDefault(key, fallback)`. Nếu có khóa gắn null, trả null.
- **Chính sách B — fallback khi kết quả giá trị là null:** `Objects.requireNonNullElse(map.get(key), fallback)` trên Java 9+, hoặc biểu thức kiểm tra null. Cách này thường **gộp** khóa thiếu và khóa có giá trị null thành một tình huống.

Ví dụ trong một phương thức đã import `java.util.Objects`, `java.util.Map`:

```java
String a = map.getOrDefault(key, "FALLBACK");

String b = Objects.requireNonNullElse(
        map.get(key), "FALLBACK"); // Java 9+

String raw = map.get(key);
String c = (raw != null) ? raw : "FALLBACK"; // Java 8+
```

Nếu `map` chứa `key → null` thì `a == null`, còn `b` và `c` đều là `"FALLBACK"`. Nếu thiếu `key` thì cả ba biểu thức trả `"FALLBACK"`. Nếu mapping là một giá trị khác null, cả ba giữ giá trị ấy.

`Objects.requireNonNullElse` yêu cầu **default cũng không null**; nếu cần cho phép fallback null, dùng điều kiện rõ ràng. Đừng chọn chính sách B chỉ vì sợ NPE trong khi null đang là thông tin có nghĩa của domain.

### Nếu thực sự cần giữ ba trạng thái

Một số hệ thống không nên ép cả ba thành `String`. Có thể mô tả bằng kết quả có `boolean present` và `V value`, hoặc dùng một sealed hierarchy/record phù hợp với phiên bản Java và domain. Cách đơn giản nhất trong một khối đọc ổn định là kiểm tra `containsKey` rồi phân loại giá trị, như ví dụ mục 5.

Mẫu thiết kế API có thể phân biệt:
- `NOT_FOUND` — không có mapping.
- `PRESENT_BUT_UNKNOWN` — có mapping với null.
- `PRESENT_WITH_VALUE` — có dữ liệu thực.

Nếu xử lý đồng thời hoặc cần nhất quán qua nhiều lần đọc, phải bảo đảm snapshot/lock phù hợp để các trạng thái không thay đổi giữa hai phép tra cứu.

## 7. Bẫy thứ hai: default argument được đánh giá dù không dùng

`getOrDefault` nhận **giá trị `V`**, không nhận `Supplier<V>`. Theo quy tắc Java, biểu thức đối số được đánh giá **trước khi gọi method**. Vì vậy:

```java
String value = map.getOrDefault(
        "existingKey", createExpensiveDefault());
```

`createExpensiveDefault()` vẫn được gọi ngay cả nếu `existingKey` đang có mapping hợp lệ. Đây không phải lời gọi lazy, và `getOrDefault` không có overload chuẩn nhận `Supplier`.

Nếu fallback chỉ là hằng `"UNKNOWN"` hoặc số `0` thì không đáng lo. Nếu fallback là một request DB, tính toán nặng, sinh mã hay side effect thì **không nên gọi trực tiếp trong đối số** chỉ vì mong nó chạy khi thiếu khóa.

Với Map không bị chỉnh sửa trong khoảng tra cứu, có thể viết:

```java
String value = map.containsKey(key)
        ? map.get(key)
        : createExpensiveDefault();
```

Cách này giữ chính sách A: nếu khóa tồn tại với null, kết quả là null. Nhưng kiểm tra rồi lấy giá trị là **hai thao tác**, không phải atomic trong môi trường concurrent.

Nếu chỉ muốn fallback khi giá trị `get` là null (chấp nhận coi null mapping như absent), có thể dùng `Optional.ofNullable(map.get(key)).orElseGet(...)`; lúc này hãy nhận thức rằng bạn **đã đổi chính sách** sang B và mất phân biệt ba trạng thái.

## 8. `computeIfAbsent`, `putIfAbsent` và `merge` không giống `getOrDefault`

Ba phương thức này thường xuất hiện gần `getOrDefault`, nhưng có **mục đích thay đổi Map**; chúng không phải chỉ là cách khác để đọc với default.

| Phương thức | Khi khóa vắng | Khi khóa có mapping `null` | Có thể sửa Map? |
| --- | --- | --- | --- |
| `getOrDefault(k, fallback)` | Trả fallback | Trả `null` | **Không** |
| `computeIfAbsent(k, f)` | Tính `f` và có thể lưu giá trị khác null | **Cũng tính `f`** và có thể lưu | **Có** |
| `putIfAbsent(k, v)` | Gắn `v` nếu được hỗ trợ | **Có thể thay null bằng `v`** | **Có** |
| `merge(k, v, remap)` | Gắn `v` không null | Xử lý như chưa có giá trị khác null và gắn `v` | **Có** |

Đối với implementation cho phép mapping null, `computeIfAbsent` coi hai trường hợp “khóa thiếu” và “khóa có giá trị null” là tình huống cần tính giá trị mới. Nếu hàm tính trả null, Map **không ghi mapping mới** (với khóa trước đó được gắn null, mapping null vẫn có thể ở đó).

`merge` yêu cầu đối số `value` không null; hàm remapping có thể tạo giá trị mới hoặc trả null để xóa mapping theo hợp đồng. `putIfAbsent` không luôn đồng nghĩa “chỉ put khi khóa hoàn toàn vắng” trong Map cho phép null: mapping null cũng bị coi là thiếu giá trị để thay.

**Quan trọng:** các phương thức cập nhật Map có thể bị giới hạn bởi implementation, ví dụ Map không thể sửa. `getOrDefault` là thao tác đọc nên vẫn dùng được trên Map không thể sửa.

### Ví dụ đầy đủ: phân biệt đọc fallback và lưu giá trị mới

Tạo tệp `MapMutationDemo.java`:

```java
import java.util.HashMap;
import java.util.Map;
import java.util.concurrent.atomic.AtomicInteger;

public class MapMutationDemo {
    static String buildFallback(AtomicInteger calls) {
        calls.incrementAndGet();
        return "GENERATED";
    }

    public static void main(String[] args) {
        AtomicInteger calls = new AtomicInteger();
        Map<String, String> values = new HashMap<>();
        values.put("present", "VALUE");
        values.put("nullMapped", null);

        System.out.println("present getOrDefault = "
                + values.getOrDefault(
                        "present", buildFallback(calls)));
        System.out.println("calls after getOrDefault = "
                + calls.get());

        System.out.println("null getOrDefault = "
                + values.getOrDefault("nullMapped", "BACKUP"));

        System.out.println("null computeIfAbsent = "
                + values.computeIfAbsent(
                        "nullMapped", k -> buildFallback(calls)));
        System.out.println("missing computeIfAbsent = "
                + values.computeIfAbsent(
                        "missing", k -> buildFallback(calls)));
        System.out.println("present computeIfAbsent = "
                + values.computeIfAbsent(
                        "present", k -> buildFallback(calls)));

        System.out.println("calls after compute = "
                + calls.get());
        System.out.println("null mapping now = "
                + values.get("nullMapped"));
        System.out.println("missing mapping now = "
                + values.containsKey("missing"));
    }
}
```

```bash
javac -encoding UTF-8 MapMutationDemo.java
java MapMutationDemo
```

```text
present getOrDefault = VALUE
calls after getOrDefault = 1
null getOrDefault = null
null computeIfAbsent = GENERATED
missing computeIfAbsent = GENERATED
present computeIfAbsent = VALUE
calls after compute = 3
null mapping now = GENERATED
missing mapping now = true
```

Lần gọi `getOrDefault("present", buildFallback(calls))` trả `"VALUE"` nhưng **vẫn tăng biến đếm**, vì Java đã tính tham số. Trong khi đó, `computeIfAbsent` chạy callback ở `nullMapped` và `missing`, rồi ghi `"GENERATED"` vào các mapping; với `present` không chạy callback. Bài học không khuyến nghị dùng `computeIfAbsent` chỉ để tạo fallback **mà không muốn lưu**: vì nó **làm thay đổi Map**.

Nếu Map đã được chia sẻ cho nhiều thread, tính nguyên tử và số lần thực thi callback của `computeIfAbsent` phải xem hợp đồng implementation tương ứng. `ConcurrentHashMap.computeIfAbsent` có bảo đảm nguyên tử phù hợp, nhưng callback cần ngắn, không tự sửa chính Map theo cách gây cập nhật đệ quy hoặc chặn kéo dài.

## 9. Không phải implementation nào cũng chấp nhận `null`

`Map` là giao diện; từng implementation có quy tắc riêng về khóa và giá trị null. Không suy luận từ `HashMap` rằng mọi Map có thể chứa `null`.

| Map implementation / factory | Khóa `null` | Giá trị `null` | Ghi chú |
| --- | --- | --- | --- |
| `HashMap` | Có | Có | Không thread-safe cho cập nhật đồng thời không kiểm soát |
| `LinkedHashMap` | Có | Có | Giữ iteration order theo insertion order mặc định |
| `TreeMap` với natural ordering | Thông thường không | Có | Khóa phải so sánh được; comparator cụ thể có thể thay đổi khả năng xử lý khóa null |
| `ConcurrentHashMap` | **Không** | **Không** | Concurrent map, null không biểu diễn mapping hợp lệ |
| `Map.of(...)` / `Map.copyOf(...)` (Java 9+/10+) | **Không** | **Không** | Tạo Map không thể sửa; null bị từ chối |
| `Collections.unmodifiableMap(mutableMap)` | Tùy Map nguồn | Tùy Map nguồn | View không sửa được, nhưng có thể phản ánh mapping null nếu Map nền cho phép |

`Map.copyOf` có từ Java 10 (không phải Java 9). `Collections.unmodifiableMap` là một **view** trên Map nền; nó không tự xóa mapping null, và những thay đổi thông qua tham chiếu Map nền có thể được phản ánh trên view.

**`getOrDefault` tuân theo hợp đồng chung:** mặc định khi **không có mapping**, không mặc định khi mapping có giá trị null. Với implementation không cho null như `ConcurrentHashMap` hoặc `Map.of`, trạng thái “có khóa, giá trị null” không tồn tại, nên `get(key) == null` có thể là tín hiệu không có mapping tại thời điểm đọc (trừ khi có hành vi khác được implementation định nghĩa).

Đọc/ghi khóa null cũng phụ thuộc implementation: `hashMap.getOrDefault(null, fallback)` hợp lệ, nhưng `concurrentHashMap.getOrDefault(null, fallback)` ném `NullPointerException`.

## 10. Ví dụ đầy đủ: `ConcurrentHashMap` và `Map.of`

Tạo tệp `MapImplementationDemo.java`:

```java
import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;

public class MapImplementationDemo {
    public static void main(String[] args) {
        Map<String, String> concurrent = new ConcurrentHashMap<>();
        concurrent.put("present", "YES");

        System.out.println("concurrent present = "
                + concurrent.getOrDefault("present", "FALLBACK"));
        System.out.println("concurrent missing = "
                + concurrent.getOrDefault("missing", "FALLBACK"));

        try {
            concurrent.put("bad", null);
        } catch (NullPointerException ex) {
            System.out.println(
                    "concurrent null value = NullPointerException");
        }

        try {
            concurrent.getOrDefault(null, "x");
        } catch (NullPointerException ex) {
            System.out.println(
                    "concurrent null key = NullPointerException");
        }

        Map<String, String> immutable = Map.of("known", "YES");
        System.out.println("immutable missing = "
                + immutable.getOrDefault("missing", "FALLBACK"));

        try {
            Map.of("bad", (String) null);
        } catch (NullPointerException ex) {
            System.out.println(
                    "Map.of null = NullPointerException");
        }
    }
}
```

```bash
javac -encoding UTF-8 MapImplementationDemo.java
java MapImplementationDemo
```

```text
concurrent present = YES
concurrent missing = FALLBACK
concurrent null value = NullPointerException
concurrent null key = NullPointerException
immutable missing = FALLBACK
Map.of null = NullPointerException
```

`ConcurrentHashMap` không cho phép null key/value; `getOrDefault` trên khóa vắng trả fallback, nhưng không thể dùng “mapping null” làm trạng thái dữ liệu trong loại Map này. `Map.of` cũng cấm null và tạo Map không thể sửa, nhưng vẫn đọc được bằng `getOrDefault`.

Không nên thay mọi `HashMap` thành `ConcurrentHashMap` chỉ để tránh null: thay đổi loại Map còn ảnh hưởng chi phí, khả năng concurrent và thiết kế dữ liệu. Nếu nghiệp vụ thật sự cần trạng thái “đã có khóa nhưng giá trị chưa biết”, hãy biểu diễn bằng domain object/sentinel/enum thay vì cố lưu null vào một Map cấm null.

## 11. `containsKey` + `get` không phải atomic transaction

Với Map thường không bị thay đổi trong lúc đọc, mã sau đủ để phân biệt khóa vắng và mapping null:

```java
if (!map.containsKey(key)) {
    handleMissing();
} else {
    handlePresent(map.get(key));
}
```

Nhưng trong môi trường **nhiều thread có cập nhật đồng thời**, hai phép đọc diễn ra **ở hai thời điểm khác nhau**. Một thread khác có thể xóa hoặc thay mapping giữa `containsKey` và `get`. Do đó, một kết quả `containsKey=true` không bảo đảm `get` ngay sau thấy cùng mapping.

Các lưu ý:

- `HashMap`/`LinkedHashMap` không thích hợp để nhiều thread ghi đồng thời mà không đồng bộ hóa bên ngoài.
- `ConcurrentHashMap` hỗ trợ truy cập đồng thời; vì **không cho phép giá trị null**, `get(key) == null` có ý nghĩa “không có mapping được quan sát tại lần đọc đó”, nhưng không có nghĩa khóa không thể được thêm ngay sau đó.
- `Map.getOrDefault` là **một lời gọi API**, nhưng default implementation của `Map` **không bảo đảm atomicity**; các implementation concurrent có thể override với hành vi được tài liệu hóa. Không dùng nó để suy ra một transaction liên quan tới nhiều thao tác trên Map.
- Nếu cần **thao tác đọc rồi ghi nguyên tử**, hãy dùng API atomic đúng hợp đồng của concurrent implementation (như `ConcurrentHashMap.computeIfAbsent`/`compute`/`merge`), hoặc lock/snapshot/transaction tùy yêu cầu. Không coi `containsKey` + `put` là “check then set” an toàn dưới concurrency.
- Khi cần ảnh chụp nhất quán của nhiều entry, cần chiến lược đồng bộ/snapshot phù hợp; việc đọc các key riêng lẻ trên concurrent Map không tự tạo ra snapshot toàn bộ.

Đừng đưa tác động phụ kéo dài như network request hoặc gọi ngược vào cùng Map trong remapping function của `ConcurrentHashMap.computeIfAbsent`. Ngoài việc gây contention, Java có thể phát hiện cập nhật đệ quy không hợp lệ.

## 12. Khi dùng `Optional` để đọc Map, có mất thông tin không?

`Optional.ofNullable(value)` có thể đổi một giá trị nullable thành `Optional<T>`. Tuy nhiên:

```java
Map<String, String> map = new HashMap<>();
map.put("pending", null);

Optional<String> a = Optional.ofNullable(map.get("pending"));
Optional<String> b = Optional.ofNullable(map.get("missing"));
// Cả a và b đều là Optional.empty().
```

Đây là đoạn minh họa đã import `Map`, `HashMap`, `Optional`. **Nếu cần phân biệt**, không được chỉ dùng `Optional.ofNullable(map.get(key))`: nó cố ý gộp trường hợp value null và key absent thành Optional empty.

Nếu chỉ cần **giá trị không null nếu có**, thì `Optional.ofNullable` vẫn có ích. Nhưng nếu domain yêu cầu ba trạng thái, biểu diễn bằng record/enum kết quả:

```java
// Java 17+: ví dụ kiểu kết quả không đánh mất sự tồn tại.
record LookupResult<V>(boolean keyPresent, V value) {}

static <K, V> LookupResult<V> lookup(Map<K, V> map, K key) {
    if (!map.containsKey(key)) {
        return new LookupResult<>(false, null);
    }
    return new LookupResult<>(true, map.get(key));
}
```

Đây là **đoạn mã minh họa trong class**, không phải tệp có thể chạy độc lập. Kiểu record có thể có `keyPresent=true` và `value=null`, khác với `keyPresent=false`. Trên Java 8, dùng class bất biến có các field/getter tương đương.

Tương tự, một `Map<K, List<V>>` có thể lưu `List.of()` (danh sách tồn tại nhưng rỗng) và đó **không phải** missing key. Hãy xác định ý nghĩa của trạng thái “không có danh sách” so với “có danh sách 0 phần tử”.

## 13. Những lỗi thường gặp

1. **Nhầm `getOrDefault` với null-coalescing.** `getOrDefault("x", fallback)` trả null nếu `x` có mapping null. Muốn fallback khi value null, dùng quy tắc B có chủ đích, không vô tình đổi hợp đồng.
2. **Dùng `map.get(key) == null` để kết luận không có khóa.** Với `HashMap` và `LinkedHashMap`, khóa có thể tồn tại với null. Dùng `containsKey` khi cần phân biệt.
3. **Dùng `getOrDefault(key, 0)` để khẳng định nhóm tồn tại.** Khóa thiếu được trả 0, khóa có giá trị 0 cũng trả 0; lưu thêm trạng thái presence.
4. **Gán `Map<String,Integer>.getOrDefault(...)` vào `int` khi value có thể null.** Unboxing null gây `NullPointerException`, dù default là 0.
5. **Đặt `computeIfAbsent` thay `getOrDefault` chỉ vì muốn đọc default.** `computeIfAbsent` có thể ghi mapping mới và coi present-null như cần tạo giá trị.
6. **Nghĩ `putIfAbsent` bỏ qua mapping null.** Trong Map cho phép null, mapping null thường được xem là chưa có giá trị hiện diện; có thể bị thay bằng giá trị mới.
7. **Gọi `getOrDefault(k, expensive())` rồi tưởng expensive lazy.** Đối số Java được tính trước, kể cả khóa đã có. Tách ra hoặc dùng phương án lazy có ngữ nghĩa đúng.
8. **Giả định mọi Map chứa được null.** `ConcurrentHashMap` và `Map.of` cấm null; `TreeMap` còn có yêu cầu so sánh khóa.
9. **Giả định mọi Map không chứa null.** `HashMap`/`LinkedHashMap` có thể chứa mapping null; đọc kiểu `V` phải hiểu contract của implementation và nguồn dữ liệu.
10. **Coi `Optional.ofNullable(map.get(k))` giữ được trạng thái khóa.** Nó gộp missing key với mapped null; không đủ nếu nghiệp vụ cần ba trạng thái.
11. **Dùng `containsKey` rồi `get` như một thao tác atomic khi Map đang thay đổi đồng thời.** Có race giữa hai lần đọc; dùng concurrency contract/snapshot.
12. **Thay đổi key sau khi đặt vào `HashMap` mà ảnh hưởng `equals/hashCode`.** Kết quả tra cứu có thể trông như khóa “biến mất” vì hash/equals không còn tương ứng; dùng khóa bất biến và triển khai `equals/hashCode` đúng hợp đồng.
13. **Nhầm chuỗi `"null"` in ra với giá trị null.** `System.out.println(map.get(key))` có thể in chữ `null` cho tham chiếu null. Nếu mapping thực sự chứa chuỗi `"null"`, output trông tương tự nhưng ý nghĩa khác.
14. **Cố truy cập `getOrDefault` trên biến Map bằng null.** `Map<String,String> map = null; map.getOrDefault(...)` ném NPE ngay khi gọi method, không phải quy tắc “không có mapping”.

## 14. Quy trình lựa chọn API đúng yêu cầu

| Mục tiêu | Nên dùng | Cần chú ý |
| --- | --- | --- |
| Muốn giá trị, hoặc default **khi khóa thiếu** | `getOrDefault(key, fallback)` | Mapping null vẫn trả null; không sửa Map |
| Phải biết khóa có tồn tại hay không | `containsKey(key)` | Hai lần tra cứu không atomic khi có concurrent writer |
| Muốn fallback **khi giá trị là null** | `Objects.requireNonNullElse(map.get(key), fallback)` (Java 9+) hoặc điều kiện null | Gộp mapping null và khóa thiếu |
| Muốn lưu giá trị mới khi khóa thiếu/**mapped null** | `computeIfAbsent(key, mappingFn)` | Có thể sửa Map, mapper có thể bị gọi, xem concurrency |
| Muốn đặt một value nếu không có value khác null | `putIfAbsent(key, value)` | Có thể thay mapping null, phụ thuộc khả năng sửa Map |
| Muốn cập nhật tích lũy theo khóa | `merge(key, nonNullValue, remappingFn)` | Có thể thêm, cập nhật hoặc xóa; không phải read-only |
| Muốn Map bất biến nhỏ không nhận null | `Map.of(...)` (Java 9+) | Không lưu key/value null và không hỗ trợ mutation |
| Muốn truy cập concurrent không lưu null | `ConcurrentHashMap` | Đảm bảo của từng operation khác với snapshot/transaction |
| Muốn giữ đủ ba trạng thái | `containsKey` + value hoặc kiểu LookupResult | Cần đồng bộ/snapshot khi có concurrent changes |

### Chọn theo ngữ nghĩa, không theo tên method

Đặt câu hỏi: “Ở đây **giá trị null** là một giá trị domain có chủ ý, dữ liệu bị thiếu, hay một lỗi?” Nếu nó mang ý nghĩa riêng, đừng thay bằng default mà không ghi nhận. Nếu nó không được phép tồn tại theo hợp đồng, có thể kiểm tra và báo lỗi sớm hoặc chuẩn hóa tại ranh giới dữ liệu. Nếu app chỉ cần một giá trị hiển thị, có thể dùng fallback có chủ ý nhưng hãy hiểu thông tin nào đã bị mất.

## 15. Kiểm thử các trường hợp biên

Một bộ test cho code đọc Map nên có các ca:

- **Có key, value hợp lệ**: `getOrDefault` trả đúng value; `containsKey` true.
- **Key vắng mặt**: `getOrDefault` trả default; `containsKey` false.
- **Key có mapping null** (với Map cho phép null): `getOrDefault` trả null, `containsKey` true.
- **Key có value 0/false/chuỗi rỗng**: vẫn là mapping hiện diện; không tự dùng default.
- **Default có side effect**: được tính trước trong `getOrDefault` khi truyền như expression.
- **Mặc định là null**: nếu `getOrDefault(k, null)` trả null thì không thể suy ra presence; dùng `containsKey`.
- **Unboxing `Integer null`**: nếu dùng kiểu `int`, cần test ngoại lệ/điều kiện bảo vệ.
- **Implementation cấm null**: test `ConcurrentHashMap`/`Map.of` theo hợp đồng; đừng đoán khả năng chấp nhận null.
- **Concurrent writer**: nếu quan trọng nhất quán, test trên cơ chế atomic/snapshot phù hợp chứ không chỉ kiểm thử một thao tác HashMap tuần tự.
- **Khóa domain**: `equals/hashCode` nhất quán và key bất biến trong thời gian lưu Map.

Không cần khẳng định mọi bài toán đều phải viết mười test; chọn những ca liên quan đến contract dữ liệu thật và nguy cơ lỗi của ứng dụng.

## 16. Bài tập tự kiểm tra

**Câu 1.** `map.put("a", null)` trên `HashMap` rồi `map.getOrDefault("a", "X")` trả gì?  
**Đáp án:** `null`. Có mapping cho khóa `"a"`, nên không dùng default.

**Câu 2.** `map` không có khóa `"b"`. `map.get("b")` và `map.getOrDefault("b", "X")` trả gì?  
**Đáp án:** `get` trả null; `getOrDefault` trả `"X"`.

**Câu 3.** `map.get("a") == null` có chứng minh `"a"` vắng mặt không?  
**Đáp án:** Không, nếu Map cho phép null value. Dùng `containsKey("a")` để xác định có mapping.

**Câu 4.** `map.put("a", 0)` thì `map.getOrDefault("a", 9)` trả gì?  
**Đáp án:** `0`; một giá trị bằng zero không phải khóa vắng mặt.

**Câu 5.** Vì sao `int total = map.getOrDefault("x", 0)` có thể ném `NullPointerException`?  
**Đáp án:** Nếu `"x"` được gắn với `Integer null`, method trả null; unboxing sang `int` ném NPE.

**Câu 6.** Có thể dùng `Map.of("x", null)` để minh họa mapping null không?  
**Đáp án:** Không. `Map.of` không cho phép null key/value và sẽ ném `NullPointerException` khi tạo.

**Câu 7.** `computeIfAbsent("x", f)` có giống `getOrDefault("x", fallback)` không?  
**Đáp án:** Không. `computeIfAbsent` có thể tính và **lưu** value, chạy cả khi khóa hiện có với value null; `getOrDefault` chỉ đọc và không sửa.

**Câu 8.** Trong môi trường nhiều thread, `containsKey` rồi `get` có bảo đảm thấy một trạng thái duy nhất không?  
**Đáp án:** Không. Có thể có cập nhật giữa hai lời gọi; cần concurrency contract/snapshot/lock thích hợp.

**Câu 9.** `map.getOrDefault("x", buildDefault())` có gọi `buildDefault()` nếu khóa đã có value không null không?  
**Đáp án:** Có; đối số method được Java đánh giá trước khi `getOrDefault` chạy.

**Câu 10.** `Optional.ofNullable(map.get("pending"))` có giúp phân biệt mapping null với khóa thiếu không?  
**Đáp án:** Không. Hai trường hợp cùng tạo `Optional.empty()`; cần kiểm tra presence riêng nếu sự khác biệt quan trọng.

## 17. Ghi nhớ

- **`Map.getOrDefault(k, d)` chỉ trả `d` khi **không có mapping** cho `k`; mapping `k → null` vẫn trả `null`.**
- `Map.get(k) == null` có thể nghĩa là **thiếu khóa** hoặc **khóa có value null**. Dùng `containsKey(k)` để phân biệt khi Map cho phép null.
- Giá trị `0`, `false`, chuỗi rỗng hay danh sách rỗng **không đồng nghĩa** với khóa thiếu.
- `getOrDefault` **không sửa Map**, và đối số default được đánh giá trước method call. `computeIfAbsent`/`putIfAbsent`/`merge` có semantics và tác động cập nhật khác.
- `HashMap`/`LinkedHashMap` cho phép mapping null; `ConcurrentHashMap`/`Map.of` không cho phép. Luôn biết implementation đang dùng.
- `containsKey` + `get` **không atomic** nếu có concurrent mutation. Chọn API/snapshot/transaction phù hợp khi cần tính nhất quán.
- Nếu domain cần ba trạng thái (absent / present-null / present-value), giữ chúng trong model thay vì biến tất cả thành một default.
