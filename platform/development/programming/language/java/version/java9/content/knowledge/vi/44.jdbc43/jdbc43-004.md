# ConnectionBuilder và cấu hình tạo kết nối — JDBC 4.3 (Java 9+, vẫn sử dụng hiện nay)

## 1. Vấn đề cần giải quyết

Trong ứng dụng Java, `Connection` đại diện cho một phiên làm việc với cơ sở dữ liệu. Trước khi chạy SQL, ứng dụng cần biết **kết nối tới đâu**, **xác thực bằng ai** và, trong một số hệ thống, **chọn shard nào**. JDBC 4.3 (xuất hiện cùng Java 9) bổ sung `java.sql.ConnectionBuilder` để cấu hình một yêu cầu tạo kết nối qua cách gọi chuỗi phương thức (*fluent API*):

```java
try (Connection connection = dataSource.createConnectionBuilder()
        .user(user)
        .password(password)
        .build()) {
    // Dùng connection để truy cập database.
}
```

`ConnectionBuilder` **vẫn tồn tại trong JDBC/JDK hiện hành**; kiến thức ở đây áp dụng cho Java 17+ và các JDK mới hơn. Tuy nhiên, **API tồn tại không đồng nghĩa mọi JDBC driver đều cài đặt nó**: phương thức mặc định `DataSource.createConnectionBuilder()` ném `SQLFeatureNotSupportedException` nếu nhà cung cấp không ghi đè để hỗ trợ. Vì thế, trước khi chọn builder cho sản phẩm, cần kiểm tra driver và phiên bản thực tế. Khi không cần tính năng builder, `DataSource.getConnection(...)` vẫn là cách chuẩn, hữu ích và được hỗ trợ.

### Ba tầng cấu hình cần tách bạch

| Tầng | Phụ trách | Ví dụ |
| --- | --- | --- |
| `DataSource` (do driver hoặc connection pool cung cấp) | Địa chỉ máy chủ, tên database, JDBC URL, TLS, thuộc tính driver, giới hạn kết nối/pool, login timeout theo API/driver | `setURL(...)` của Oracle `OracleDataSource`, `setLoginTimeout(10)` của `DataSource`. |
| `ConnectionBuilder` | Tùy chọn **cho lần yêu cầu kết nối này**: `user`, `password`, `shardingKey`, `superShardingKey` | `ds.createConnectionBuilder().user("app").password(secret).build()` |
| `Connection` đã tạo | Trạng thái phiên và transaction sau khi kết nối thành công | `setAutoCommit(false)`, `setReadOnly(true)`, `setTransactionIsolation(...)`, `commit()`, `rollback()`. |

Không có các phương thức chuẩn `ConnectionBuilder.url(...)`, `host(...)`, `port(...)`, `timeout(...)`, `autoCommit(...)` hay `poolSize(...)`. Những tùy chọn này thuộc `DataSource`, cấu hình riêng của driver/pool hoặc `Connection`. Không tự suy đoán API dựa theo builder của framework khác.

## 2. API chuẩn còn hiệu lực

`java.sql.ConnectionBuilder` thuộc module JDK `java.sql` và có năm phương thức chuẩn:

| Phương thức | Ý nghĩa |
| --- | --- |
| `ConnectionBuilder user(String username)` | Chọn tài khoản database cho lần tạo kết nối. |
| `ConnectionBuilder password(String password)` | Cung cấp mật khẩu tương ứng; theo Javadoc có thể truyền `null`, nhưng ý nghĩa thực tế phụ thuộc driver/cấu hình. |
| `ConnectionBuilder shardingKey(ShardingKey key)` | Chỉ định khóa chọn shard nếu driver và hệ thống database hỗ trợ sharding. |
| `ConnectionBuilder superShardingKey(ShardingKey key)` | Chỉ định khóa nhóm shard cao hơn trong mô hình sharding có hỗ trợ. |
| `Connection build() throws SQLException` | Thực sự yêu cầu tạo `Connection`; lỗi kết nối được báo qua `SQLException`. |

Các setter của builder trả lại chính builder để gọi liên tiếp. `DataSource` cung cấp cấu hình mặc định cho builder; các giá trị thiết lập trên builder được dùng cho lần `build()` tương ứng. Không suy ra rằng một builder có thể được tái sử dụng hoặc chia sẻ an toàn giữa các luồng nếu chưa kiểm tra tài liệu implementation.

**Chu trình tối thiểu:**

```text
Tạo / nhận DataSource đã cấu hình
            |
            v
dataSource.createConnectionBuilder()
            |
            +-- .user(username)
            +-- .password(secret)
            +-- .shardingKey(...)        [tùy chọn, nếu hỗ trợ]
            +-- .superShardingKey(...)   [tùy chọn, nếu hỗ trợ]
            |
            v
          .build()  ---> java.sql.Connection
                                |
                                v
                   chạy truy vấn/transaction
                                |
                                v
                     close() / trả về pool
```

`ConnectionBuilder` chỉ có nhiệm vụ **tạo** kết nối, không tự làm connection pool, không tự bắt đầu transaction, không tự chạy SQL. Khi `DataSource` là một pool, việc `Connection.close()` thường trả handle về pool theo contract của pool; khi là `DataSource` thường, `close()` đóng tài nguyên của kết nối. Dùng `try-with-resources` trong cả hai trường hợp.

### Điểm đặc biệt: hỗ trợ là tùy driver

`DataSource.createConnectionBuilder()` là **default method** kể từ Java 9. Theo Javadoc, implementation mặc định **ném `SQLFeatureNotSupportedException`**. Do đó:

- `javac` biên dịch thành công **chưa chứng minh** database driver chạy được builder.
- Một `DataSource` có thể hỗ trợ `getConnection()` nhưng không hỗ trợ `createConnectionBuilder()`.
- Một JDBC driver quảng bá hỗ trợ JDBC 4.3 cũng cần được kiểm tra **cụ thể từng tính năng**; có triển khai chỉ hỗ trợ một phần.
- Bắt `SQLFeatureNotSupportedException` đúng lúc **tạo builder** để có thể fallback sang `getConnection(user,password)` nếu nghiệp vụ cho phép; vẫn để các lỗi kết nối thật sự từ `build()` được báo rõ.

## 3. Mẫu mã ứng dụng dùng được với DataSource thật

Ví dụ dưới đây sử dụng **duy nhất API chuẩn của JDK**, không phụ thuộc tên lớp JDBC vendor. Ứng dụng/framework phải truyền vào `DataSource` đã cấu hình (Oracle, PostgreSQL, SQL Server, connection pool ...). Không cần tự cài đặt `ConnectionBuilder` trong lớp nghiệp vụ.

**`ConnectionFactory.java`**

```java
import java.sql.Connection;
import java.sql.ConnectionBuilder;
import java.sql.SQLException;
import java.sql.SQLFeatureNotSupportedException;
import java.util.Objects;
import javax.sql.DataSource;

public final class ConnectionFactory {
    private final DataSource dataSource;

    public ConnectionFactory(DataSource dataSource) {
        this.dataSource = Objects.requireNonNull(dataSource);
    }

    public Connection open(String user, String password) throws SQLException {
        Objects.requireNonNull(user, "user");

        ConnectionBuilder builder;
        try {
            builder = dataSource.createConnectionBuilder();
        } catch (SQLFeatureNotSupportedException unsupported) {
            // Driver không hỗ trợ builder: trở về API DataSource chuẩn.
            return dataSource.getConnection(user, password);
        }

        return builder.user(user)
                .password(password)
                .build();
    }
}
```

Biên dịch lớp độc lập với JDK 17+:

```bash
javac -encoding UTF-8 --release 17 ConnectionFactory.java
```

Đây là **lớp thư viện**, chưa phải chương trình `main`. Ứng dụng thật gọi `new ConnectionFactory(dataSource).open(user, password)` sau khi đã lấy được `DataSource` từ container, DI framework hoặc cấu hình driver. Ví dụ:

```java
// dataSource đã được khởi tạo và cấu hình ở lớp infrastructure.
ConnectionFactory factory = new ConnectionFactory(dataSource);
try (Connection connection = factory.open(user, password)) {
    System.out.println("Database: "
            + connection.getMetaData().getDatabaseProductName());
}
```

Đoạn trên là **mã tích hợp**, không phải file độc lập: `dataSource`, `user` và `password` là những biến do ứng dụng cung cấp. Kết quả in ra tùy database thực tế, nên không gán một stdout giả.

**Vì sao đặt `catch` quanh `createConnectionBuilder()`?** Nếu gói cả `build()` vào `catch (SQLFeatureNotSupportedException)`, lỗi từ một tùy chọn đặc thù hoặc từ quá trình tạo kết nối có thể bị che bởi việc thử lại bằng API khác. Fallback chỉ dành cho tình huống rõ ràng: **DataSource chưa cung cấp builder**, và đường `getConnection(user,password)` đáp ứng nghiệp vụ. Nếu chương trình **bắt buộc dùng sharding key**, không được silently fallback sang kết nối thiếu key.

## 4. Cấu hình DataSource thực tế: ví dụ Oracle JDBC còn được hỗ trợ

**`OracleDataSource` trong gói `oracle.jdbc.datasource.impl`** là lựa chọn được tài liệu Oracle Database 21c+ khuyến nghị cho `DataSource` trực tiếp. Đây là **API riêng của Oracle**, không thuộc JDK. Với driver `ojdbc11` phù hợp và database Oracle có thể truy cập, ví dụ sau tạo kết nối thật bằng JDBC builder.

**`OracleBuilderExample.java`**

```java
import java.sql.Connection;
import java.sql.SQLException;
import oracle.jdbc.datasource.impl.OracleDataSource;

public final class OracleBuilderExample {
    private static String required(String name) {
        String value = System.getenv(name);
        if (value == null || value.isBlank()) {
            throw new IllegalStateException("Missing environment variable: " + name);
        }
        return value;
    }

    public static void main(String[] args) throws SQLException {
        OracleDataSource ds = new OracleDataSource();
        ds.setURL(required("DB_URL"));
        ds.setLoginTimeout(10);

        try (Connection conn = ds.createConnectionBuilder()
                .user(required("DB_USER"))
                .password(required("DB_PASSWORD"))
                .build()) {
            System.out.println("Database: "
                    + conn.getMetaData().getDatabaseProductName());
        }
    }
}
```

Giả sử đã có driver `ojdbc11.jar` tương thích và database đang chạy:

```bash
# Linux/macOS; thay thông tin ví dụ bằng database thực tế.
export DB_URL='jdbc:oracle:thin:@//dbhost:1521/myservice'
export DB_USER='app_reader'
export DB_PASSWORD='value-from-secret-store'

javac -encoding UTF-8 --release 17 -cp ojdbc11.jar OracleBuilderExample.java
java -cp '.:ojdbc11.jar' OracleBuilderExample
```

Trong PowerShell, đặt biến bằng `$env:DB_URL`, `$env:DB_USER`, `$env:DB_PASSWORD`; khi chạy Windows, classpath dùng dấu `;`:

```powershell
javac -encoding UTF-8 --release 17 -cp ojdbc11.jar OracleBuilderExample.java
java -cp ".;ojdbc11.jar" OracleBuilderExample
```

Ví dụ yêu cầu **driver và database Oracle thực**. Nếu đúng cấu hình, chương trình in tên sản phẩm database mà JDBC metadata trả về, không có một stdout cố định cho mọi hệ thống. `setURL` là phương thức **OracleDataSource**, `setLoginTimeout` đến từ `DataSource`, còn `user/password/build` là **ConnectionBuilder** chuẩn.

Đừng đưa URL/mật khẩu thật vào tài liệu, source control hoặc log; thay bằng secret manager/cấu hình môi trường. Biến môi trường chỉ là ví dụ đơn giản; sản phẩm nên sử dụng cơ chế quản lý secret và cấp quyền tài khoản database ở mức tối thiểu.

## 5. Demo tự chạy bằng JDK 17: kiểm chứng chuỗi phương thức và close

Để thử **cú pháp và vòng đời builder mà không cần cài database**, chương trình sau tạo `DataSource` mô phỏng. `build()` trả về `Connection` mô phỏng qua `Proxy`, chỉ hỗ trợ `isClosed()/close()`. **Đây là bài thực hành API, tuyệt đối không kết nối hoặc chạy SQL thật**; mã nghiệp vụ thực tế nên dùng `DataSource` của driver/pool như mục 3–4.

**`BuilderDemo.java`**

```java
import java.io.PrintWriter;
import java.lang.reflect.Proxy;
import java.sql.*;
import java.util.concurrent.atomic.AtomicBoolean;
import java.util.logging.Logger;
import javax.sql.DataSource;

public class BuilderDemo {
    public static void main(String[] args) throws SQLException {
        DemoDataSource ds = new DemoDataSource();
        ds.setLoginTimeout(5);

        try (Connection con = ds.createConnectionBuilder()
                .user("app_reader")
                .password("demo-only")
                .build()) {
            System.out.println("Đang mở: " + !con.isClosed());
        }

        System.out.println("Đã đóng: " + ds.closed.get());
        System.out.println("Login timeout: " + ds.getLoginTimeout() + "s");
    }

    static final class DemoDataSource implements DataSource {
        final AtomicBoolean closed = new AtomicBoolean();
        private int timeout;

        @Override public ConnectionBuilder createConnectionBuilder() {
            return new DemoBuilder(closed);
        }
        @Override public Connection getConnection() throws SQLException {
            return createConnectionBuilder().user("guest").password("").build();
        }
        @Override public Connection getConnection(String user, String password)
                throws SQLException {
            return createConnectionBuilder().user(user).password(password).build();
        }
        @Override public int getLoginTimeout() { return timeout; }
        @Override public void setLoginTimeout(int seconds) { timeout = seconds; }
        @Override public PrintWriter getLogWriter() { return null; }
        @Override public void setLogWriter(PrintWriter writer) {}
        @Override public Logger getParentLogger() { return Logger.getGlobal(); }
        @Override public <T> T unwrap(Class<T> type) throws SQLException {
            throw new SQLException("No wrapper");
        }
        @Override public boolean isWrapperFor(Class<?> type) { return false; }
    }

    static final class DemoBuilder implements ConnectionBuilder {
        private final AtomicBoolean closed;
        private String user;
        private String password;

        DemoBuilder(AtomicBoolean closed) { this.closed = closed; }
        @Override public ConnectionBuilder user(String value) {
            user = value;
            return this;
        }
        @Override public ConnectionBuilder password(String value) {
            password = value;
            return this;
        }
        @Override public ConnectionBuilder shardingKey(ShardingKey value) {
            throw new UnsupportedOperationException("Demo does not support sharding");
        }
        @Override public ConnectionBuilder superShardingKey(ShardingKey value) {
            throw new UnsupportedOperationException("Demo does not support sharding");
        }
        @Override public Connection build() throws SQLException {
            if (user == null || password == null) {
                throw new SQLException("Credentials required");
            }
            closed.set(false);
            return (Connection) Proxy.newProxyInstance(
                    Connection.class.getClassLoader(),
                    new Class<?>[] {Connection.class},
                    (proxy, method, args) -> {
                        return switch (method.getName()) {
                            case "close" -> {
                                closed.set(true);
                                yield null;
                            }
                            case "isClosed" -> closed.get();
                            default -> throw new SQLFeatureNotSupportedException(
                                    "This demo only supports close and isClosed");
                        };
                    });
        }
    }
}
```

Biên dịch và chạy:

```bash
javac -encoding UTF-8 --release 17 BuilderDemo.java
java BuilderDemo
```

**Stdout chính xác (đã thử với OpenJDK 24.0.2, chế độ `--release 17`):**

```text
Đang mở: true
Đã đóng: true
Login timeout: 5s
```

Bài thực hành cho thấy: `user()`/`password()` trả builder để gọi nối tiếp, `build()` trả `Connection`, `try-with-resources` gọi `close()` tự động. Tham số `loginTimeout` nằm ở `DataSource`, không nằm trong các phương thức `ConnectionBuilder`. Vì đây là mock nên `setLoginTimeout(5)` chỉ lưu giá trị, không kiểm thử timeout mạng thật.

## 6. ShardingKey: mở rộng có điều kiện, không áp dụng đại trà

JDBC 4.3 bổ sung `ShardingKey`/`ShardingKeyBuilder` để driver có khả năng chọn shard khi tạo kết nối. **Chỉ dùng khi database và driver thật sự hỗ trợ sharding theo contract**; đây không phải cách thay thế cho thuật toán phân tuyến mọi ứng dụng.

**Mã minh họa (cần driver sharding tương thích, không chạy độc lập):**

```java
import java.sql.Connection;
import java.sql.JDBCType;
import java.sql.ShardingKey;
import javax.sql.DataSource;

// dataSource đã được cấu hình trên DB/driver hỗ trợ sharding.
ShardingKey region = dataSource.createShardingKeyBuilder()
        .subkey("EAST", JDBCType.VARCHAR)
        .build();

ShardingKey customer = dataSource.createShardingKeyBuilder()
        .subkey("customer-42", JDBCType.VARCHAR)
        .build();

try (Connection conn = dataSource.createConnectionBuilder()
        .user(user)
        .password(password)
        .superShardingKey(region)
        .shardingKey(customer)
        .build()) {
    // Thực hiện truy vấn trên kết nối đã chọn shard.
}
```

Trong mã đang chạy, có thể kiểm tra `connection.getMetaData().supportsSharding()` **sau khi lấy được Connection** để hỏi driver về hỗ trợ sharding; phương thức mặc định trả `false`. Với quá trình mở mới đã gắn shard, trước hết vẫn cần biết rõ năng lực driver từ tài liệu và thử nghiệm tích hợp. `createShardingKeyBuilder` hoặc `createConnectionBuilder` có thể ném `SQLFeatureNotSupportedException` ở driver không hỗ trợ.

Nếu không dùng sharding, **không cần gọi** `shardingKey`/`superShardingKey`. Tài khoản `user/password` không phải khóa sharding; routing shard là quyết định riêng do dữ liệu và kiến trúc database xác định.

### Liên hệ với những builder khác trong JDBC 4.3

| Nguồn | Phương thức | Kiểu builder và kết quả |
| --- | --- | --- |
| `DataSource` | `createConnectionBuilder()` | `java.sql.ConnectionBuilder` → `Connection`. |
| `ConnectionPoolDataSource` | `createPooledConnectionBuilder()` | `javax.sql.PooledConnectionBuilder` → `PooledConnection` dành cho pool manager, không phải handle `Connection` ứng dụng dùng trực tiếp. |
| `XADataSource` | `createXAConnectionBuilder()` | `javax.sql.XAConnectionBuilder` → `XAConnection` phục vụ transaction phân tán. |

Ba loại trên có mục đích khác nhau. Với ứng dụng dùng pool thông thường, hãy lấy `DataSource` do pool/framework quản lý và đóng `Connection` handle đúng thời điểm; không tự gọi `PooledConnectionBuilder` để chế pool thủ công.

## 7. Cấu hình kết nối an toàn, rõ ràng và dễ kiểm thử

### Trình tự khuyến nghị

1. **Chọn driver + phiên bản được hỗ trợ** bởi Java và database hiện tại. Kiểm tra `DataSource.createConnectionBuilder` của implementation cụ thể, không chỉ xem JDK có interface.
2. **Cấu hình `DataSource` một lần** ở tầng infrastructure: địa chỉ database hoặc JDBC URL, TLS, driver properties, connection pool và timeout nếu có. API setter cho URL/host là của từng driver, không phải của `ConnectionBuilder`.
3. **Lấy credentials từ nguồn bảo mật** (secret manager, cấu hình triển khai được bảo vệ). Không hardcode password trong chương trình hoặc stdout.
4. **Mỗi tác vụ mượn một connection, dùng trong phạm vi rõ ràng**: `try (Connection c = ...) { ... }`; trả đúng thời điểm. Nếu framework quản lý transaction, tuân theo vòng đời của framework thay vì đóng connection ngoài ý muốn.
5. **Cấu hình trạng thái kết nối sau `build()`** khi cần: `setReadOnly`, `setAutoCommit`, `setTransactionIsolation`, `setSchema`. Xác nhận driver hỗ trợ hành vi yêu cầu, và nếu dùng pool, lưu ý quy trình reset state khi trả connection.
6. **Kiểm thử tích hợp**: driver hỗ trợ builder, xác thực sai, database tạm ngắt, login timeout, kết nối pool bị cạn, failover và rollback. Test mock ở mục 5 chỉ xác nhận cú pháp/flow, không thay thế test với database thực.

Ví dụ một transaction không phụ thuộc vào `ConnectionBuilder` (đầu vào `Connection conn` đã lấy thành công; đoạn này chỉ minh họa vòng đời transaction):

```java
conn.setAutoCommit(false);
try {
    // Các lệnh INSERT/UPDATE dùng PreparedStatement...
    conn.commit();
} catch (java.sql.SQLException e) {
    try {
        conn.rollback();
    } catch (java.sql.SQLException rollbackError) {
        e.addSuppressed(rollbackError);
    }
    throw e;
}
```

Trong mã thực, luôn kết hợp với `try-with-resources` hoặc transaction manager để đóng connection đúng chỗ. Đừng thực hiện giao dịch nhiều câu SQL mà chỉ dựa vào `build()`; builder **không cấu hình transaction**.

### Timeout dễ nhầm

- `DataSource.setLoginTimeout(int seconds)` đặt khoảng thời gian chờ **khi thiết lập kết nối** theo contract của DataSource; driver/pool có thể có thêm timeout riêng.
- `Connection.setNetworkTimeout(Executor, milliseconds)` tác động lên **hoạt động mạng của Connection đã tạo**, nếu driver hỗ trợ. Nó **không** phải phương thức của ConnectionBuilder.
- `Statement.setQueryTimeout(int seconds)` giới hạn thời gian thực thi một statement theo khả năng JDBC driver.
- Connection pool thường có **acquisition timeout** riêng khi chờ được cấp một connection từ pool. Phải xem API/config của pool đã chọn.

| Hiện tượng | Kiểm tra |
| --- | --- |
| `SQLFeatureNotSupportedException` từ `ds.createConnectionBuilder()` | Driver/DataSource chưa cài đặt phương thức tùy chọn; dùng `ds.getConnection(...)` nếu không cần tính năng đặc biệt, hoặc chọn driver có hỗ trợ. |
| `SQLException` từ `build()` | URL/host, database, mạng/TLS, username/password, quyền tài khoản, giới hạn pool hoặc shard. Xem `getSQLState()`, `getErrorCode()` và cause; không in mật khẩu. |
| Gọi `builder.url(...)`/`builder.timeout(...)` bị lỗi biên dịch | Hai phương thức đó **không nằm trong `java.sql.ConnectionBuilder`**; cấu hình trên `DataSource` hoặc API của driver. |
| Builder hợp lệ nhưng `build()` không kết nối được | Có thể DataSource thiếu URL, cấu hình endpoint sai, credentials thiếu hoặc DB chưa sẵn sàng; builder không tự tìm database. |
| `No suitable driver` khi dùng `DriverManager` | Chưa khai báo driver JAR/module thích hợp hoặc JDBC URL không tương ứng; việc tồn tại `ConnectionBuilder` không cài driver. |
| Hết connection trong pool / chậm bất thường | Có thể quên `close()`, pool hết capacity hoặc timeout/transaction giữ kết nối lâu; xem metric của pool. |
| `superShardingKey`/`shardingKey` lỗi | Driver không hỗ trợ JDBC sharding, key sai loại/giá trị hoặc mô hình shard không tương ứng. |
| Transaction không lưu dữ liệu | Kiểm tra `autoCommit`, `commit()`/`rollback()`, lỗi từ statement và trạng thái kết nối khi trả pool. |

**Những hiểu nhầm cần tránh:**

- `ConnectionBuilder` **không phải** thay thế bắt buộc cho `DriverManager` hoặc `DataSource.getConnection`.
- Có `DataSource` trong JDK **không có nghĩa** JDK mang sẵn driver cho PostgreSQL/Oracle/SQL Server; vẫn cần JDBC driver tương thích.
- Gọi `build()` tạo kết nối theo `DataSource`, **không bảo đảm có pool** trừ khi implementation DataSource cung cấp pooling.
- Tồn tại `ShardingKey` trong API **không đồng nghĩa** database nào cũng hỗ trợ sharding.
- Không để một `Connection` dùng đồng thời tùy tiện giữa nhiều thread, không giữ connection qua request dài khi không cần; xem contract của driver/pool.

## 9. Ôn tập nhanh

1. **ConnectionBuilder do đâu tạo?** — Từ `DataSource.createConnectionBuilder()`.
2. **Tại sao Java 17 vẫn có thể ném `SQLFeatureNotSupportedException`?** — Đây là default method và nhà cung cấp DataSource có quyền không hỗ trợ builder; phiên bản JDK không quyết định khả năng của driver.
3. **Dùng builder để chỉnh host, port, URL, autocommit hoặc kích thước pool được không?** — Không theo API chuẩn; đặt ở tầng `DataSource`/driver/pool hoặc sau khi tạo `Connection`.
4. **Khi ứng dụng không dùng sharding và builder không được hỗ trợ, chọn gì?** — `DataSource.getConnection(user,password)` nếu đúng với chính sách ứng dụng.
5. **`build()` khác `commit()` như thế nào?** — `build()` tạo `Connection`; `commit()` xác nhận transaction đã chạy trên connection đó.
6. **Vì sao dùng `try-with-resources`?** — Đảm bảo `Connection.close()` được gọi cả khi code gặp ngoại lệ, tránh giữ tài nguyên/pool handle quá lâu.
