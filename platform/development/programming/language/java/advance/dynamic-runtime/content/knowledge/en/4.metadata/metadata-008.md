# 4.8 Exploring RecordComponent and Its Relationship with Record Accessors and Constructors

A `record` in Java describes data using a list of **record components** directly in the declaration: `record Point(int x, int y) {}`. When the system only knows `Class<?>` at runtime, Reflection can recover the component list and locate the exact **accessor** as well as the **canonical constructor**. This is the foundation for metadata readers, mappers, serializers, testing tools, plugins, and dependency injection that support records.

The key point: a record component is **a declared member in the record header**, not identical to a `Field`, a `Method`, or a constructor parameter. However, each component corresponds to a `private final` field, a parameterless accessor, and a parameter position in the canonical constructor. Java provides the `java.lang.reflect.RecordComponent` API to inspect that relationship directly.

**After this lesson**, you will be able to:

- Check `Class.isRecord()` and retrieve `RecordComponent` instances in exact declaration order.
- Distinguish between `getName()`, `getType()`, `getGenericType()`, `getAnnotatedType()`, and `getAccessor()`.
- Use `RecordComponent.getAccessor()` to read the value of a record instance under standard Reflection access rules.
- Identify the canonical constructor from **the exact list of component types in record header order**, including with compact constructors and generic records.
- Distinguish annotations on a component from annotations on the accessor, field, and constructor parameter.
- Design record inspection code that is safe enough when encountering non-record classes, empty records, array components, generics, overloads, and module access restrictions.

These APIs have been stable since **Java 16**; the examples below compile with **Java 17+**.

## 1. How Is a Record Structured?

Consider the declaration:

```java
public record Book(String title, int pages) {}
```

This is an illustrative declaration. Java associates the following concepts with a record:

| Component | Corresponding Example | Meaning |
| --- | --- | --- |
| Record header | `String title, int pages` | Two record components, ordered `title` before `pages` |
| Component field | `private final String title`, `private final int pages` | The actual field storing state; implicitly generated by the compiler |
| Accessor | `public String title()`, `public int pages()` | Returns the component value; can be compiler-generated or explicitly declared by the author |
| Canonical constructor | `Book(String title, int pages)` | Initializes all components according to the exact header list and order |
| Standard methods | `equals`, `hashCode`, `toString` | Have default implementations based on component fields, unless validly redeclared |

A record class extends `java.lang.Record` and cannot extend another application class; a record is implicitly `final`. The instance component fields are `private final` and are only initialized during record construction. **`final` here does not mean deep immutability**: if a component is a mutable `List` or array, the referenced object itself can still be modified unless designed defensively.

A record is allowed to declare additional secondary constructors, static fields, static methods, and instance methods, but **cannot declare additional instance fields**. Remember that `Book(String title, int pages)` is the canonical constructor, whereas `Book(String title)` (if present) is only a secondary constructor and must delegate to another constructor of the record using `this(...)`.

### 1.1. From the Record Header to the Reflection Model

```text
record Book(String title, int pages)
      |
      +-- Class<Book>.getRecordComponents()
      |     +-- RecordComponent "title" : String
      |     |       +-- getAccessor() -> Method title()
      |     +-- RecordComponent "pages" : int
      |             +-- getAccessor() -> Method pages()
      |
      +-- getDeclaredConstructor(String.class, int.class)
            -> canonical constructor in exact component order
```

`Class.getRecordComponents()` is designed for that exact purpose. Do not use `getDeclaredFields()` and assume it represents the record header: fields and components are two separate concepts, fields may include `static` fields, and the order returned by field-listing APIs is not a contract for inferring component order.

## 2. Essential RecordComponent APIs

| API | Returns | Usage |
| --- | --- | --- |
| `Class.isRecord()` | `boolean` | Branching when processing a `Class<?>` |
| `Class.getRecordComponents()` | `RecordComponent[]` or `null` | List of components in **declaration order**; `null` if not a record |
| `RecordComponent.getName()` | `String` | Exact name in the header, e.g., `title` |
| `getType()` | `Class<?>` | Runtime type with generics erased; used to find the constructor |
| `getGenericType()` | `Type` | Declared type carrying generic information, e.g., `List<String>` |
| `getGenericSignature()` | `String` or `null` | Generic signature in JVM format when present; usually using `Type` is more convenient |
| `getAnnotatedType()` | `AnnotatedType` | Annotation information at the **type-use position** of the component |
| `getAccessor()` | `Method` | Parameterless accessor with the same name as the component and a return type matching the component type |
| `getDeclaringRecord()` | `Class<?>` | The record that declares this component |
| `getAnnotation(A.class)` | `A` or `null` | Annotation directly readable on the **component**, according to `@Target` and `@Retention` |
| `getDeclaredAnnotations()` / `getAnnotations()` | `Annotation[]` | Inspect annotations directly on the component |

**Two special edge cases:**

- `String.class.isRecord()` is `false` and `String.class.getRecordComponents()` is **`null`**. Do not loop over it without checking first.
- For `record Empty() {}`, `isRecord()` is `true` and `getRecordComponents()` is a **0-length array**, not `null`. The canonical constructor in that case takes no parameters.

A record component does not have `getValue(record)`. `getAccessor()` returns a `Method` object; to read the value, we use `accessor.invoke(recordInstance)`, which must still obey Reflection access permissions and exceptions.

## 3. Relationship Between Component and Accessor

For `record Account(String id, int level) {}`, the accessor names are `id()` and `level()`, respectively. They **do not follow JavaBeans conventions** like `getId()` or `getLevel()`. The reliable approach is to retrieve `RecordComponent.getAccessor()` instead of guessing the name or looking for a getter starting with "get".

### 3.1. Implicitly Generated vs. Explicitly Declared Accessor

```java
record User(String username) {
    @Override
    public String username() {
        return username;
    }
}
```

This is an illustrative snippet: the accessor is explicitly declared with the same name and return type as the component. When calling `User.class.getRecordComponents()[0].getAccessor()`, Reflection still finds the exact `Method username()`. If no accessor is written, the compiler generates an equivalent accessor that returns the component field.

**You must not assume a custom accessor always returns the unmodified field in every program**, but it should be designed consistently with the record contract: creating a copy via the canonical constructor from the values returned by the accessors should preserve `equals` semantics. For example, if an accessor arbitrarily returns a value different from the state used by `equals`, the expected semantic invariant of the record may be broken. Normalizing data in the constructor and letting the accessor return the normalized state is usually easier to guarantee.

### 3.2. Reading Values with Reflection

```java
RecordComponent component = Account.class.getRecordComponents()[0];
Method accessor = component.getAccessor();
String id = (String) accessor.invoke(new Account("A01", 2));
```

This illustrative snippet requires importing `java.lang.reflect.RecordComponent` and `java.lang.reflect.Method`. `invoke` takes the record instance as the receiver and **no method arguments**, because an accessor accepts no parameters. The method returned by Reflection has a return type matching `component.getType()`; primitive types returned via `Method.invoke` are boxed—for example, an `int` value becomes an `Integer` in the `Object` result.

If an accessor throws an exception itself, `Method.invoke` wraps that exception in an `InvocationTargetException`. If the record is not accessible to the caller due to access scope or module boundaries, the call may encounter `IllegalAccessException` even after retrieving the metadata; you should not assume every `getAccessor()` can be invoked from every module.

## 4. Canonical Constructor: Identifying from Exact Component Types

The canonical constructor has a parameter list with the **same count, same types, and same order** as the record components. For `record Book(String title, int pages)`, the canonical signature is `(String, int)`; for `record Box<T>(T value)`, in Reflection after type erasure, the corresponding parameter is usually `Object` if `T` has no restrictive bound.

Because `getRecordComponents()` returns components in exact header order, we can write:

```java
RecordComponent[] components = recordClass.getRecordComponents();
Class<?>[] parameterTypes = Arrays.stream(components)
        .map(RecordComponent::getType)
        .toArray(Class<?>[]::new);
Constructor<?> canonical = recordClass.getDeclaredConstructor(parameterTypes);
```

This is an illustrative snippet assuming `recordClass` has been verified with `isRecord()==true` and appropriate imports (`Arrays`, `RecordComponent`, `Constructor`) are present. Use `getDeclaredConstructor` to look up by **exact signature**; do not pick the "first" constructor in the `getDeclaredConstructors()` array or assume the constructor with the fewest parameters is the canonical one.

| Constructor Kind | Example | Is It Canonical? |
| --- | --- | --- |
| Implicitly generated from header | `record Point(int x, int y) {}` | Yes: `Point(int, int)` |
| Explicit normal canonical | `public Point(int x, int y) { this.x=x; this.y=y; }` in record `Point` | Yes, if it satisfies the canonical constructor rules |
| Compact canonical | `public Point { if (x < 0) throw new IllegalArgumentException(); }` | Yes: the signature is still `Point(int, int)` |
| Secondary constructor | `public Point() { this(0, 0); }` | No: `Point()` only delegates to the canonical constructor |

### 4.1. Compact Constructors Do Not Change the Signature

```java
public record Product(String code, int quantity) {
    public Product {
        code = code.trim();
        if (quantity < 0) throw new IllegalArgumentException("quantity");
    }
}
```

In a compact canonical constructor, parameters are inferred from the record header; the body can validate and normalize the parameters. After the body executes, the fields are assigned from the (updated) parameter values. Reflection still finds it via `getDeclaredConstructor(String.class, int.class)`. Calling `canonical.newInstance("  P1  ", 2)` applies the same validation/normalization as calling `new Product("  P1  ", 2)` directly.

If the constructor throws `IllegalArgumentException` inside its body, `Constructor.newInstance` typically throws `InvocationTargetException` whose `getCause()` is that error. Distinguish this from an `IllegalArgumentException` thrown **before entering the constructor** due to an invalid argument count or type.

### 4.2. Do Not Confuse Secondary Constructors with the Canonical Constructor

```java
record Ticket(String code, int price) {
    Ticket(String code) { this(code, 0); }
}
```

The illustrative snippet above has a compiler-generated canonical constructor `Ticket(String, int)`, as well as a secondary constructor `Ticket(String)`. Both constructors can appear in `getDeclaredConstructors()`; array order must not be used to identify the canonical constructor.

**A record has only one canonical constructor**, even though you can write multiple secondary constructors. For a canonical constructor with restricted access, Reflection can still find it using `getDeclaredConstructor`, but `newInstance` must obey visibility and module rules; preserving the access policy is the safe choice for dynamic systems.

## 5. Runnable Java 17+ Example: Inspecting Components, Accessors, and Constructors

Create a file named **`RecordMetadataDemo.java`** containing the program below. It defines an `Article` record using a compact canonical constructor, a secondary constructor, an explicitly declared accessor, and an annotation applicable only to record components; it also includes a generic record `Box<T>` to observe type erasure.

```java
import java.lang.annotation.ElementType;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;
import java.lang.annotation.Target;
import java.lang.reflect.Constructor;
import java.lang.reflect.RecordComponent;
import java.util.Arrays;
import java.util.List;
import java.util.Objects;

public class RecordMetadataDemo {
    @Retention(RetentionPolicy.RUNTIME)
    @Target(ElementType.RECORD_COMPONENT)
    public @interface Caption { String value(); }

    public record Article(@Caption("primary title") String title,
                          List<String> tags, int pages) {
        public Article {
            title = Objects.requireNonNull(title).trim();
            tags = List.copyOf(tags);
            if (pages < 0) throw new IllegalArgumentException("pages");
        }

        public Article(String title) {
            this(title, List.of(), 0);
        }

        @Override
        public String title() { return title; }
    }

    public record Box<T>(T value, List<T> history) {}

    public static void main(String[] args) throws Exception {
        Class<Article> recordClass = Article.class;
        System.out.println("isRecord=" + recordClass.isRecord());
        System.out.println("ordinaryIsRecord=" + String.class.isRecord());
        System.out.println("ordinaryComponentsNull=" + (String.class.getRecordComponents() == null));

        RecordComponent[] components = recordClass.getRecordComponents();
        System.out.println("componentCount=" + components.length);
        for (RecordComponent rc : components) {
            System.out.println(rc.getName() + " | raw=" + rc.getType().getTypeName()
                    + " | generic=" + rc.getGenericType().getTypeName()
                    + " | accessor=" + rc.getAccessor().getName() + "()");
        }
        Class<?>[] types = Arrays.stream(components)
                .map(RecordComponent::getType)
                .toArray(Class<?>[]::new);
        Constructor<Article> canonical = recordClass.getDeclaredConstructor(types);
        System.out.println("canonicalParameterCount=" + canonical.getParameterCount());
        System.out.println("allConstructors=" + recordClass.getDeclaredConstructors().length);

        Article article = canonical.newInstance("  Java  ", List.of("reflection", "metadata"), 12);
        for (RecordComponent rc : components) {
            System.out.println("read " + rc.getName() + "=" + rc.getAccessor().invoke(article));
        }
        System.out.println("caption=" + components[0].getAnnotation(Caption.class).value());
        System.out.println("declaringRecord=" + components[0].getDeclaringRecord().getSimpleName());
        System.out.println("accessorCaption="
                + (components[0].getAccessor().getAnnotation(Caption.class) != null));

        RecordComponent generic = Box.class.getRecordComponents()[0];
        System.out.println("genericRaw=" + generic.getType().getTypeName());
        System.out.println("genericType=" + generic.getGenericType().getTypeName());
        System.out.println("genericSignature=" + generic.getGenericSignature());
    }
}
```

Compile/run:

```bash
javac --release 17 RecordMetadataDemo.java
java RecordMetadataDemo
```

`stdout` output on JDK 17+:

```text
isRecord=true
ordinaryIsRecord=false
ordinaryComponentsNull=true
componentCount=3
title | raw=java.lang.String | generic=java.lang.String | accessor=title()
tags | raw=java.util.List | generic=java.util.List<java.lang.String> | accessor=tags()
pages | raw=int | generic=int | accessor=pages()
canonicalParameterCount=3
allConstructors=2
read title=Java
read tags=[reflection, metadata]
read pages=12
caption=primary title
declaringRecord=Article
accessorCaption=false
genericRaw=java.lang.Object
genericType=T
genericSignature=TT;
```

**Results to understand:**

1. `Article` is a record; `String` is not. `getRecordComponents()` on `String` returns `null`, so you must check before iterating.
2. Component order is `title` → `tags` → `pages`, matching the header order. `getType()` of `tags` is `List.class`, while `getGenericType()` preserves the `List<String>` information.
3. The canonical constructor has exactly **3 parameters**, even though `Article` has **2 constructors in total** (the canonical constructor and a secondary constructor).
4. `Article` instantiated via Reflection still runs the compact constructor: `"  Java  "` is trimmed to `"Java"` and `tags` is copied into an unmodifiable list.
5. `rc.getAccessor().invoke(article)` reads each component using the exact accessor, including the explicitly declared `title()`.
6. `Caption` is only allowed on `RECORD_COMPONENT`, so `getAnnotation` on the component finds the annotation, whereas the accessor does not carry it.
7. For `Box<T>`, the runtime erased type of `T` is `Object`, but `getGenericType()` shows it is the type variable `T`; the raw generic signature is `TT;`.

This example declares the nested records as `public` and runs from the enclosing class itself, so there is no need to bypass access checks.

## 6. Inspecting Generics and Annotations in the Right Place

### 6.1. Raw Type vs. Generic Type

`RecordComponent.getType()` returns a `Class<?>` with type parameter information erased. `getGenericType()` returns a `Type`, which can be:

- `Class<?>` for `String`, `int`, or ordinary non-generic types.
- `ParameterizedType` for types like `List<String>`.
- `TypeVariable<?>` for `T` in `record Box<T>(T value)`.
- `GenericArrayType` when an array type has a type variable or generic component, depending on the declaration.

For detailed analysis, check `instanceof ParameterizedType` or `instanceof TypeVariable<?>`. `getGenericSignature()` returns the JVM signature string (if present); **you should not pass this string as a class name to `Class.forName` or treat it as a JVM field descriptor**.

Important: even though metadata retains `List<String>`, a `Constructor` looked up via Reflection still takes `List.class` as the parameter type for that position. For example:

```java
RecordComponent component = Article.class.getRecordComponents()[1];
System.out.println(component.getType() == List.class); // true
```

The snippet above references the `Article` class from the full program. When building a mapper, use the runtime type `getType()` to select the constructor, and `getGenericType()` to interpret or constrain element types for a serializer.

### 6.2. Annotations on a Component Differ from Annotations on an Accessor

`RecordComponent` implements `AnnotatedElement`. However, where an annotation appears is determined by `@Target`:

- `@Target(RECORD_COMPONENT)` allows it to appear directly on the record component.
- `@Target(METHOD)` applies to methods; an annotation in the record header can be **propagated** to the implicitly generated accessor if the annotation is valid for `METHOD`.
- `@Target(FIELD)` can cause the annotation to apply to the component field; `@Target(PARAMETER)` can affect the canonical constructor parameter according to implicit declaration rules.
- If the accessor or normal canonical constructor is **explicitly declared**, annotation propagation rules differ from generated members; you cannot assume an annotation will definitely appear in all locations.

Therefore, read annotations from **the exact Reflection object**: `rc.getAnnotation(...)` for the record component, `rc.getAccessor().getAnnotation(...)` for the accessor, `field.getAnnotation(...)` for the field, or `constructor.getParameters()[i].getAnnotation(...)` for the constructor parameter. Do not conflate these four metadata sources.

*Type-use* annotations are another matter. For example:

```java
@Target(ElementType.TYPE_USE)
@Retention(RetentionPolicy.RUNTIME)
@interface SensitiveType {}

record Catalog(java.util.List<@SensitiveType String> names) {}
```

This is an illustrative declaration with imports `ElementType`, `Target`, `Retention`, and `RetentionPolicy`. The annotation is attached to **the `String` type inside `List<...>`**. To inspect it, use `RecordComponent.getAnnotatedType()`, check for `AnnotatedParameterizedType`, and then inspect `getAnnotatedActualTypeArguments()`; merely calling `getAnnotations()` on `RecordComponent` itself may miss that *type-use* information.

### 6.3. Compile-Time Annotations May Not Be Visible at Runtime

Annotation retention is a different filter from target: only `@Retention(RUNTIME)` guarantees the corresponding annotation metadata can be read via Reflection at runtime. `SOURCE` annotations are discarded during compilation; `CLASS` annotations may exist in the class file but are not necessarily visible through standard Reflection APIs. For frameworks that read annotations, both `@Target` and `@Retention` must be checked.

## 7. Building a Record Metadata Analyzer in a Dynamic System

Suppose you are building a JSON/Map-to-record converter or a testing tool that only receives `Class<?>` at runtime. A reliable workflow:

1. **Identify the kind:** `if (!type.isRecord())`, reject it or branch to ordinary class handling. Do not infer a class is a record just because it has parameterless methods.
2. **Retrieve the component list:** `RecordComponent[] components = type.getRecordComponents()`. This is a list with a stable order matching the header; an empty record still yields a non-null array.
3. **Build the schema:** for each component, record `name`, `type`, `genericType`, necessary annotations, and `accessor`. Use `getDeclaringRecord()` to confirm the declaring record.
4. **Read an instance:** verify the instance has the expected record type; invoke each `getAccessor().invoke(instance)`. Avoid accessing private component fields when accessors suffice.
5. **Prepare values in the right order:** map input data by `component.getName()` but order the constructor argument list using **the order of the `components` array**. Do not rely on arbitrary `Map` key order or `getDeclaredFields` order.
6. **Find the canonical constructor:** build `Class<?>[]` from each `component.getType()`, then call `getDeclaredConstructor(types)`. Do not select by name, arbitrary parameter count, or index in `getDeclaredConstructors()`.
7. **Invoke the constructor:** build an `Object[] arguments` array with one element per component and call `canonical.newInstance(arguments)`. Check primitives, nulls, arrays, generics, access permissions, validation exceptions, and data trustworthiness before invoking.
8. **Report errors with context:** when a key is missing or a value is invalid, report the component name, declared type, and position; if `InvocationTargetException` occurs, inspect `getCause()` to distinguish errors inside the canonical constructor.

### 7.1. Why Not Instantiate with a No-Arg Constructor and Set Fields?

A record does not have a default no-arg constructor, unless the canonical constructor has **0 components** or the developer wrote a suitable secondary constructor. Component fields are `private final`, and mutating them reflectively after object construction is not the proper mechanism for constructing a record. A mapper should collect/validate all data and then **invoke the canonical constructor**. This preserves constraints in compact/normal canonical constructors and avoids relying on tricks to modify final fields.

### 7.2. Mapping Primitives, Arrays, and Varargs

| Header Component | `getType()` | Canonical Constructor Parameter |
| --- | --- | --- |
| `int count` | `int.class` | An `int`; Reflection can unbox a compatible wrapper value |
| `String name` | `String.class` | A `String` reference |
| `String[] labels` | `String[].class` | A `String[]` argument |
| `List<String> tags` | `List.class` | A `List` argument; generic info must be inspected separately |
| `String... labels` (last component) | `String[].class` | A `String[]` array argument; the canonical constructor has the varargs flag |

For `record Event(String name, String... labels) {}`, `getRecordComponents()` returns two components; the `labels` component has runtime type `String[]`. The canonical constructor is looked up with `getDeclaredConstructor(String.class, String[].class)` and `Constructor.isVarArgs()` returns `true`. **Reflection does not automatically flatten or pack varargs values for you**: prepare an `Object[]` containing a single `String[]` element at the last position. For example:

```java
Constructor<Event> ctor = Event.class.getDeclaredConstructor(
        String.class, String[].class);
Event event = ctor.newInstance(new Object[] {
        "created", new String[] {"audit", "async"}
});
```

This is an illustrative snippet, assuming record `Event` has been declared; `new Object[]{...}` is **the two-parameter argument list of the constructor**, in which the second element is **an array**. If you pass two strings instead of the array component, `newInstance` does not automatically pack them into a `String[]`.

## 8. Edge Cases and Common Pitfalls

| Symptom | Possible Cause | Resolution |
| --- | --- | --- |
| `getRecordComponents() == null` | `Class<?>` is not a record | Check `isRecord()` and branch accordingly |
| `getRecordComponents().length == 0` | Valid record with an empty header | Look up the parameterless canonical constructor |
| Constructor not found | Wrong component order/types, using `List<String>` as `Class<?>`, or taking only a subset of components | Use all `getType()` values in header order |
| Wrong secondary constructor picked | Selecting the first element of `getDeclaredConstructors()` | Use `getDeclaredConstructor(componentTypes)` |
| `IllegalArgumentException` at `newInstance` | Wrong argument count or type, e.g., passing `Object[]` instead of `String[]` for a component | Build `Object[]` matching the exact component count and actual values |
| `InvocationTargetException` at `newInstance` | Constructor actually ran and threw a validation or logic error | Read `getCause()` and handle according to business logic |
| `IllegalAccessException` / `InaccessibleObjectException` | Caller lacks access to the record/constructor/accessor; module restrictions | Fix API visibility or module exports/opens according to policy |
| Annotation readable on component but missing on getter | `@Target` or an explicit accessor changes where the annotation appears | Check the declaration location and the right `AnnotatedElement` |
| `getType()` is `Object` though declared as `T` | Type erasure | Use `getGenericType()` to get generic metadata |
| Serializer sees `List` without element type | Only using `getType()` | Inspect `ParameterizedType` or `AnnotatedType` when needed |
| Record data changes after initialization | Component references a mutable object, such as an array or mutable collection | Defensive copy and enforce the desired level of immutability |
| Accessor returns result inconsistent with `equals` | Custom accessor transforms the value compared to the stored field | Design constructor/accessor consistently with component values |

**Data scope and limitations:** Reflection inspects **the compiled structure**, and cannot retrieve every Java source expression. For generics, type variables, and type-use annotations, read information from `Type` and `AnnotatedType`; do not use string type names to guess all metadata. For records in another module, reading metadata does not automatically grant permission to invoke non-public constructors.

### 8.1. Differences Between Records and JavaBeans

| Criterion | Record | Ordinary JavaBeans Class |
| --- | --- | --- |
| State description | Header components are publicly exposed as metadata | Properties are typically inferred from getters/setters/fields by convention |
| Getter | `name()`, without a `get` prefix | Usually `getName()` / `isActive()` |
| Primary instantiation | Canonical constructor with all components | Can use a no-arg constructor and setters |
| Mutating state after creation | `private final` component fields, no default component setters | Design-dependent; may have setters or mutable fields |
| Useful Reflection | `Class.getRecordComponents()`, `RecordComponent.getAccessor()` | `java.beans.Introspector` (if using JavaBeans), `Method`, `Field` |

**Do not turn a record into a JavaBean by forcing it to have `getX()` or a no-arg constructor.** Frameworks should recognize records and invoke the appropriate canonical constructor instead of ignoring the header structure.

## 9. Self-Check Exercises

**Exercise 1.** Given `record Pair(String key, long value) {}`. What types must be passed to `Pair.class.getDeclaredConstructor(...)`?

**Answer:** `String.class, long.class` in exact order; `Long.class` cannot substitute for `long.class` when looking up a constructor signature.

**Exercise 2.** `record Empty() {}`. What does `Empty.class.getRecordComponents()` return?

**Answer:** A 0-length array; `Empty.class.getDeclaredConstructor()` finds the parameterless canonical constructor.

**Exercise 3.** `record Envelope<T>(T payload) {}`. For the `payload` component with no special bound, how do `getType()` and `getGenericType()` differ?

**Answer:** `getType() == Object.class`; `getGenericType()` returns a `TypeVariable` representing `T`. To find the canonical constructor on the runtime class, use `Object.class`.

**Exercise 4.** A record has a constructor `R(String name)` and a canonical constructor `R(String name, int version)`. Can you retrieve the canonical constructor with `getDeclaredConstructors()[0]`?

**Answer:** No; array order is not guaranteed. Use the list of `RecordComponent.getType()` to obtain `String.class, int.class` and call `getDeclaredConstructor`.

**Exercise 5.** `RecordComponent.getAnnotation(Tag.class)` returns a value, but `component.getAccessor().getAnnotation(Tag.class)` is `null`. Is there a contradiction?

**Answer:** No. Component, accessor, field, and constructor parameter have different annotation locations; check `@Target`, `@Retention`, and how the accessor is declared.
