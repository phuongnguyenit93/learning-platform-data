# 4.1 Reading Modifiers, `AccessFlag`, and Compiler-Generated `synthetic` Members

When inspecting a class at runtime, Reflection reveals what exists in the **compiled type**, not only what the author sees in the `.java` file. A method generated by `javac` to preserve polymorphism, a field holding a captured variable, or modifiers encoded in `.class` can appear in metadata results even if you did not declare them directly.

This lesson focuses on three related but distinct questions:

1. **Java language modifiers:** does the member have `public`, `private`, `static`, `final`, `abstract`, `volatile`… as expressed in the Java language?
2. **JVM access flags:** which bits does the class file mark the structure with, including `ACC_BRIDGE`, `ACC_SYNTHETIC`, or `ACC_MANDATED` that have no corresponding keywords in source code?
3. **Compiler-generated members:** which members are added by the compiler, why do they exist, and how should they be handled when using Reflection, analysis tools, or frameworks?

> **Version note:** `Modifier`, `getModifiers()`, `isSynthetic()`, and `Method.isBridge()` are already present in Java 17. `java.lang.reflect.AccessFlag` and the `accessFlags()` methods were added in **Java 20**. The main examples below compile with **Java 21+**; when running on Java 17, use the alternative APIs mentioned in the compatibility section.

## 1. Three-Layer Metadata Model

```text
Java source
  public class Child extends Base<String> {
      public String copy(String value) { ... }
  }
              |
              v  javac (compilation + type erasure + support code)
.class / class file
  flags: ACC_PUBLIC ...
  method copy(String): ACC_PUBLIC
  method copy(Object): ACC_PUBLIC, ACC_BRIDGE, ACC_SYNTHETIC
              |
              v  JVM loads class
Reflection
  getModifiers()  -> language-level modifiers
  accessFlags()   -> set of access flags appropriate for the class file location
  isSynthetic()   -> member marked as synthetic
  isBridge()      -> compiler-generated bridge method
```

There are two things to keep separate:

- A **modifier** is a Java language-level concept. Reflection represents this group with an `int` integer from `getModifiers()`, then uses `Modifier.isXxx(mask)` functions to decode it.
- An **access flag** is a bit according to the class file or module descriptor structure. `AccessFlag` models the bit and its **context**. Not every flag is a Java keyword, and not every Java feature has its own flag bit.

All compiler-generated members should be observed via actual metadata, not concluded solely from `$...` names, because auxiliary names may change between compiler versions.

## 2. Reading Modifiers with `getModifiers()` and `Modifier`

Basic Reflection classes:

| Target to read | API to find member | API to read modifier |
| --- | --- | --- |
| Class/interface/enum/record | `Class<?> type` | `type.getModifiers()` |
| Field | `type.getDeclaredField("name")` | `field.getModifiers()` |
| Method | `type.getDeclaredMethod("name", ParamType.class)` | `method.getModifiers()` |
| Constructor | `type.getDeclaredConstructor(ParamType.class)` | `constructor.getModifiers()` |
| Parameter | `method.getParameters()` | `parameter.getModifiers()` |

`getModifiers()` returns a **bitmask**, not an ordinal or an enum. Check using dedicated functions:

```java
int modifiers = field.getModifiers();

boolean isPublic = Modifier.isPublic(modifiers);
boolean isStatic = Modifier.isStatic(modifiers);
boolean isFinal = Modifier.isFinal(modifiers);
String readable = Modifier.toString(modifiers);
```

This is an **illustrative snippet**, assuming `field` is a `java.lang.reflect.Field` and `java.lang.reflect.Modifier` has been imported.

For example, with a `private static final` field, all three corresponding bits are present; checking `modifiers == Modifier.PRIVATE` will be **wrong** because the bitmask contains multiple flags. Use `Modifier.isPrivate(modifiers)` or controlled bit operations.

### 2.1. Member kind determines which modifiers are meaningful

| Kind | Common modifiers | How to read |
| --- | --- | --- |
| Class | `public`, `abstract`, `final`; member class can be `static` | `Modifier.isFinal(type.getModifiers())` |
| Method | `public`, `protected`, `private`, `static`, `final`, `abstract`, `synchronized`, `native` | `Modifier.isSynchronized(method.getModifiers())` |
| Field | `public`, `private`, `static`, `final`, `volatile`, `transient` | `Modifier.isVolatile(field.getModifiers())` |
| Constructor | access modifiers `public`/`protected`/`private` | `Modifier.isPublic(constructor.getModifiers())` |
| Parameter | certain parameter-related modifiers, e.g. `final` | `Modifier.isFinal(parameter.getModifiers())` |

Do not mechanically apply every `Modifier.isXxx` to every kind: `volatile` is meaningful for **field**; `synchronized` is meaningful for **method**; `transient` is not a modifier of a method.

### 2.2. Differences between `getDeclaredXxx` and `getXxx`

- `getDeclaredFields()`, `getDeclaredMethods()`, `getDeclaredConstructors()` return members **declared in the class file of that type itself**, including `private` and compiler-generated members if present. They do not automatically include inherited members from the superclass.
- `getFields()`, `getMethods()` focus on **public** members visible from the type, which may include inherited members. They are not an equivalent substitute when you want to inventory a class file.
- The API does not guarantee the order of arrays returned by `getDeclaredMethods()` or `getDeclaredFields()`. If a stable report is needed, **sort by an intentional key** before displaying.
- For overloaded methods, `getDeclaredMethod(name, parameterTypes...)` locates by name and **parameter types**, not parameter count or return type. With a bridge method, two methods can have the same name but different parameter types after type erasure.

## 3. `AccessFlag`: Viewing JVM-Level Metadata More Accurately

Since Java 20, `AccessFlag` represents class file and module flags; Reflection APIs return an unmodifiable `Set<AccessFlag>`.

| Reflection Source | API since Java 20 |
| --- | --- |
| `Class<?>` | `type.accessFlags()` |
| `Field` | `field.accessFlags()` |
| `Method` / `Constructor` | `method.accessFlags()` / `constructor.accessFlags()` |
| `Parameter` | `parameter.accessFlags()` |

Example:

```java
boolean isBridge = method.accessFlags().contains(AccessFlag.BRIDGE);
boolean isSynthetic = method.accessFlags().contains(AccessFlag.SYNTHETIC);
boolean isVolatile = field.accessFlags().contains(AccessFlag.VOLATILE);
```

This is an **illustrative snippet**, assuming `method`, `field` already exist and `java.lang.reflect.AccessFlag` has been imported.

### 3.1. Overlapping bits in different locations

Do not infer the meaning of a bit without knowing the **kind of structure** that owns it.

| Mask | In field | In method |
| --- | --- | --- |
| `0x0040` | `ACC_VOLATILE` | `ACC_BRIDGE` |
| `0x0080` | `ACC_TRANSIENT` | `ACC_VARARGS` |

In addition, bit `0x0020` means `ACC_SUPER` at the class location in a class file, but means `ACC_SYNCHRONIZED` for a method. `AccessFlag.Location` represents the location: `CLASS`, `INNER_CLASS`, `FIELD`, `METHOD`, `METHOD_PARAMETER`, and module-related locations.

When you have a mask and a valid location, you can use:

```java
Set<AccessFlag> fieldFlags =
        AccessFlag.maskToAccessFlags(0x0040, AccessFlag.Location.FIELD);
Set<AccessFlag> methodFlags =
        AccessFlag.maskToAccessFlags(0x0040, AccessFlag.Location.METHOD);
```

This is also an **illustrative snippet** (import `java.util.Set` and `AccessFlag`). `fieldFlags` contains `VOLATILE`; `methodFlags` contains `BRIDGE`. Use the right `Location` instead of trying to decode with a generic `Modifier` mask.

### 3.2. Language modifiers ≠ all flags in `.class`

Some flags map almost directly to source modifiers, such as `PUBLIC`, `FINAL`, `VOLATILE`, `SYNCHRONIZED`. Flags like `BRIDGE`, `SYNTHETIC`, `MANDATED` describe JVM artifacts and metadata, **not Java keywords**. The `flag.sourceModifier()` method indicates whether a flag has a direct corresponding source modifier; `flag.mask()` returns the corresponding bit position.

The reverse also has exceptions: `sealed` is described via permitted subclasses metadata, which can be queried using `Class.isSealed()` and `getPermittedSubclasses()`; a record has a `Record` attribute and `Class.isRecord()`. **There is no `AccessFlag.RECORD` or `AccessFlag.SEALED`** to replace those APIs.

`AccessFlag` is a more readable and semantically rich API when analyzing compiled structures, but it does not completely replace language-level queries or dedicated attributes such as `isRecord()`.

## 4. Practice 1 — Modifier and AccessFlag Inspecting the Same Field/Method

Create the file **`ModifierFlagsDemo.java`**:

```java
import java.lang.reflect.AccessFlag;
import java.lang.reflect.Field;
import java.lang.reflect.Method;
import java.lang.reflect.Modifier;

public class ModifierFlagsDemo {
    static final class Gadget {
        private volatile int state;
        public synchronized void refresh() {}
        public void send(String... messages) {}
    }

    public static void main(String[] args) throws Exception {
        Class<?> type = Gadget.class;
        Field state = type.getDeclaredField("state");
        Method refresh = type.getDeclaredMethod("refresh");
        Method send = type.getDeclaredMethod("send", String[].class);

        System.out.println("class final: " + Modifier.isFinal(type.getModifiers()));
        System.out.println("field volatile (Modifier): "
                + Modifier.isVolatile(state.getModifiers()));
        System.out.println("field VOLATILE (AccessFlag): "
                + state.accessFlags().contains(AccessFlag.VOLATILE));
        System.out.println("method synchronized (Modifier): "
                + Modifier.isSynchronized(refresh.getModifiers()));
        System.out.println("method SYNCHRONIZED (AccessFlag): "
                + refresh.accessFlags().contains(AccessFlag.SYNCHRONIZED));
        System.out.println("method varargs: " + send.isVarArgs());
        System.out.println("method VARARGS: "
                + send.accessFlags().contains(AccessFlag.VARARGS));
        System.out.println("0x40 as FIELD: "
                + AccessFlag.maskToAccessFlags(0x40,
                        AccessFlag.Location.FIELD).contains(AccessFlag.VOLATILE));
        System.out.println("0x40 as METHOD: "
                + AccessFlag.maskToAccessFlags(0x40,
                        AccessFlag.Location.METHOD).contains(AccessFlag.BRIDGE));
    }
}
```

Compile with JDK 21+:

```bash
javac ModifierFlagsDemo.java
java ModifierFlagsDemo
```

**Exact stdout:**

```text
class final: true
field volatile (Modifier): true
field VOLATILE (AccessFlag): true
method synchronized (Modifier): true
method SYNCHRONIZED (AccessFlag): true
method varargs: true
method VARARGS: true
0x40 as FIELD: true
0x40 as METHOD: true
```

Explanation:

1. `Modifier.isFinal(type.getModifiers())` reads the `final` modifier of the class.
2. `volatile` is a field modifier, so both `Modifier.isVolatile` and `AccessFlag.VOLATILE` can recognize it.
3. `synchronized` is a method modifier. `send(String...)` has the `VARARGS` flag; the runtime parameter is a `String[]`, even though the source syntax uses ellipsis.
4. Both decodings of `0x40` yield `true` but interpret **two different meanings** thanks to `Location.FIELD` and `Location.METHOD`.

> `Modifier.toString(mask)` is intended for displaying source modifiers; do not use it as a decoder for all JVM structural flags. When you need to detect bridge/synthetic, use the dedicated APIs or `accessFlags()`.

## 5. What Is `synthetic` and When Does the Compiler Generate Extra Members?

According to the class file format, `ACC_SYNTHETIC` or the `Synthetic` attribute marks a member generated by the compiler that does not correspond to a normal source declaration. APIs such as `Class.isSynthetic()`, `Field.isSynthetic()`, `Method.isSynthetic()`, and `Constructor.isSynthetic()` allow detection.

Common situations:

- **Bridge method for generics/type erasure**: the compiler adds a method to preserve proper overriding and polymorphism after generic type erasure, or similar covariance cases.
- **Field storing a captured value** of a local/anonymous class: so an object can reuse an outer variable after the method that created it has finished.
- **Certain internal support structures**: depending on the compiler and class file version. You should not assume the same name or the same number of helper fields/methods across all compilers.

### 5.1. Are `synthetic`, `bridge`, `mandated`, and `implicit` the same?

| Concept | What does it reflect? | How to query |
| --- | --- | --- |
| `synthetic` | The member is a compiler-generated artifact, marked synthetic | `member.isSynthetic()`; `AccessFlag.SYNTHETIC` |
| `bridge` | Bridge method to adapt signatures / preserve overriding in bytecode | `method.isBridge()`; `AccessFlag.BRIDGE` |
| `mandated` | Member/parameter present by language rules even though not explicitly written; at class file locations that support the flag | `AccessFlag.MANDATED` or `Parameter.isImplicit()` in the parameter case |
| `implicit` | Declaration implicitly mandated by the language, such as certain enum/record members | Do not assume `isSynthetic() == true` |

A bridge method **is usually both `isBridge()` and `isSynthetic()`** in bytecode generated by `javac`. However, you cannot conclude that every compiler-generated member is synthetic:

- Default constructors, class initializers, and implicitly declared members of enum/record have exceptions under the JVM Specification.
- Enum's `values()` and `valueOf(String)` methods, record's `x()` accessor, and record-generated `equals/hashCode/toString` are implicit members specified by the language. Do not filter them out just because they do not appear explicitly in source.
- `static`, a name containing `$`, or a "machine-generated" looking name **is not sufficient evidence** of being synthetic.
- Java 11+ supports nestmates, so the compiler does not necessarily generate `access$...` private access methods like older compilers. Lambdas often involve `invokedynamic` and runtime implementation; do not assume a single class/field shape for all JDKs.

## 6. Practice 2 — Bridge Method Due to Type Erasure

Create the file **`BridgeSyntheticDemo.java`**:

```java
import java.lang.reflect.AccessFlag;
import java.lang.reflect.Method;
import java.util.Locale;

public class BridgeSyntheticDemo {
    static class Base<T> {
        public T copy(T value) {
            return value;
        }
    }

    static final class StringBox extends Base<String> {
        @Override
        public String copy(String value) {
            return value.toUpperCase(Locale.ROOT);
        }
    }

    public static void main(String[] args) throws Exception {
        Method source = StringBox.class.getDeclaredMethod("copy", String.class);
        Method generated = StringBox.class.getDeclaredMethod("copy", Object.class);

        System.out.println("source: bridge=" + source.isBridge()
                + ", synthetic=" + source.isSynthetic());
        System.out.println("generated: bridge=" + generated.isBridge()
                + ", synthetic=" + generated.isSynthetic());
        System.out.println("generated BRIDGE flag: "
                + generated.accessFlags().contains(AccessFlag.BRIDGE));
        System.out.println("generated SYNTHETIC flag: "
                + generated.accessFlags().contains(AccessFlag.SYNTHETIC));
        System.out.println("bridge invoke: "
                + generated.invoke(new StringBox(), "java"));
    }
}
```

```bash
javac BridgeSyntheticDemo.java
java BridgeSyntheticDemo
```

**Exact stdout when compiled with `javac` JDK 21+:**

```text
source: bridge=false, synthetic=false
generated: bridge=true, synthetic=true
generated BRIDGE flag: true
generated SYNTHETIC flag: true
bridge invoke: JAVA
```

### 6.1. Why does the second method appear?

`Base<T>.copy(T)` after type erasure has a JVM-level signature taking `Object`. `StringBox.copy(String)` is the method the author actually declared, but the JVM must continue supporting polymorphic calls through the `Base<String>` type. `javac` generates a bridge roughly equivalent to:

```java
// CODE ILLUSTRATING THE MECHANISM, NOT a Java declaration that can be placed in the same class
public Object copy(Object value) {
    return copy((String) value);
}
```

The representative method in the class file has an `Object` parameter, calls the `copy(String)` version, and returns `String` as an `Object`. The bridge ensures that bytecode calling the erased signature still reaches the subclass's overridden behavior.

When reading `StringBox.class.getDeclaredMethods()`, Reflection sees both the source method and the bridge. If you are building a **human-facing API catalog**, you usually want to hide duplicate bridges; if you are building a bytecode analyzer or dispatch engine, **you must not remove or ignore the bridge's effect**. The filtering choice must depend on the purpose.

### 6.2. Verifying with `javap`

Use:

```bash
javap -p -v 'BridgeSyntheticDemo$StringBox'
```

Single quotes prevent the `$` character from being substituted by the shell. In the long output, find the `copy(java.lang.Object)` method. A typical flags line when compiling this example with `javac` is:

```text
flags: (0x1041) ACC_PUBLIC, ACC_BRIDGE, ACC_SYNTHETIC
```

`javap -v` displays the truth in the class file, while `Method.isBridge()` and `Method.isSynthetic()` are the corresponding ways to read it at runtime. Do not confuse a method with the `BRIDGE` flag with a "manual bridge method" written in source: the flag is set by the compiler/class-file-generating tool.

## 7. Practice 3 — Capture Field Is Generated, but Record Is Not Synthetic

Create the file **`SyntheticFieldDemo.java`**:

```java
import java.lang.reflect.Field;
import java.util.Arrays;

public class SyntheticFieldDemo {
    record Point(int x, int y) {}

    static Runnable capture(String message) {
        class LocalTask implements Runnable {
            @Override
            public void run() {
                System.out.println(message);
            }
        }
        return new LocalTask();
    }

    public static void main(String[] args) {
        Runnable task = capture("Hello");
        Field[] fields = task.getClass().getDeclaredFields();
        boolean hasSyntheticField = Arrays.stream(fields).anyMatch(Field::isSynthetic);

        System.out.println("captured synthetic field: " + hasSyntheticField);
        System.out.println("record class synthetic: " + Point.class.isSynthetic());
        System.out.println("record components: " + Point.class.getRecordComponents().length);
        task.run();
    }
}
```

```bash
javac SyntheticFieldDemo.java
java SyntheticFieldDemo
```

**Stdout with `javac` JDK 21+:**

```text
captured synthetic field: true
record class synthetic: false
record components: 2
Hello
```

`LocalTask` has a `run()` method accessing `message` from the enclosing scope; the compiler generates a field to store the captured value. The field name is a compiler **implementation detail** and applications must not rely on it. Checking `Field.isSynthetic()` is more reliable than guessing the name.

`Point` is a record in Java source, recognized via `isRecord()` and `getRecordComponents()`. The record class itself is not a synthetic class just because the compiler generates some of its members. The two record components `x` and `y` are members declared in source.

> With compilers other than `javac`, the way auxiliary fields are generated may differ. Therefore avoid enforcing checks like "every local class has exactly one synthetic field" or "every compiler chooses the same field name".

## 8. Parameter Metadata and `mandated`

`Parameter` has its own methods in addition to `getModifiers()`:

- `isNamePresent()`: whether the class file stores the parameter name via appropriate metadata. If not, `getName()` may return `arg0`, `arg1`... and **that is not a guaranteed source name**.
- `isSynthetic()`: the parameter is an artifact that was not explicitly/implicitly declared at the source level.
- `isImplicit()`: the parameter corresponds to a language-implicit declaration (often correlates with the `MANDATED` flag when recorded in `MethodParameters`).
- `accessFlags()`: since Java 20, views the flag set at the `METHOD_PARAMETER` location.

Example inspection snippet to include in a Reflection tool:

```java
// Fragment: executable is a Method or Constructor<?> obtained via Reflection
for (java.lang.reflect.Parameter parameter : executable.getParameters()) {
    System.out.println(parameter.getName()
            + " named=" + parameter.isNamePresent()
            + " synthetic=" + parameter.isSynthetic()
            + " implicit=" + parameter.isImplicit()
            + " flags=" + parameter.accessFlags());
}
```

To get stable source parameter names, you usually compile with `javac -parameters ...`; depending on the compiler, target, and parameter kind, `MethodParameters` may contain different information. Since JDK 21, `javac` also records metadata for many synthetic/mandated parameters where applicable. **Do not classify parameters solely by names like `arg0` or `this$0`**.

## 9. Designing a Metadata Reader for Tools/Frameworks

Typical reading steps:

1. Identify the right `Class<?>` and class loader; use `getDeclaredFields()`, `getDeclaredMethods()` if you want to inventory **this exact class file**.
2. Read source modifiers with `getModifiers()` + `Modifier`; for Java 20+, also read `accessFlags()`.
3. Record `isSynthetic()` and `isBridge()` for each method; for constructors/parameters/fields, use the appropriate synthetic APIs.
4. Choose a handling policy by purpose: **displaying API documentation** may hide bridges; **bytecode/dispatch analysis** should keep them to understand signatures and binary compatibility.
5. Sort results before displaying or serializing. Do not rely on Reflection array order and do not rely on compiler-generated names.

Separate illustrative example for listing methods, given a known `Class<?> type` input:

```java
// Java 21+ fragment: type already has a value.
java.lang.reflect.Method[] methods = type.getDeclaredMethods();
java.util.Arrays.sort(methods,
        java.util.Comparator.comparing(java.lang.reflect.Method::toGenericString));

for (java.lang.reflect.Method method : methods) {
    boolean compilerArtifact = method.isSynthetic() || method.isBridge();
    System.out.printf("%s | flags=%s | compilerArtifact=%s%n",
            method.toGenericString(), method.accessFlags(), compilerArtifact);
}
```

This is an **illustrative snippet for use in a tool**, not a standalone runnable program. `toGenericString()` is useful for describing and sorting, but do not design a long-term protocol based on Reflection's formatted string; if you need a stable identifier, encode the name, parameter types, return type, declaring class, and loader according to the tool's contract.

### 9.1. Access permission notes

`Modifier.isPublic(method.getModifiers())` only indicates a `public` **declaration**. It does not guarantee that calling code in every module is allowed to invoke it via reflection:

- The class containing the method may not be public, or its package may not be `exports`-ed by its module to the caller.
- `getDeclaredMethod` can read metadata of a private method, but **invoking/accessing** it is still subject to Java access control and the Java module system.
- `setAccessible(true)` or `trySetAccessible()` does not automatically cross every module boundary; `opens`/corresponding access permissions still play a role.
- Querying metadata does not mean being permitted to modify fields or invoke private constructors.

### 9.2. When should synthetic be filtered?

| Use case | Recommendation |
| --- | --- |
| Reader-facing API documentation page | Display source methods and avoid duplicate bridges when appropriate; still keep meaningful implicit members (record/enum). |
| Schema mapper/serializer | Clearly define field and property rules; do not automatically serialize every synthetic capture field. |
| Framework finding annotations/handlers | Understand the bridge–source method relationship; some frameworks must resolve the bridge to the right method. |
| Bytecode or binary compatibility tool | Keep all relevant members, including synthetic/bridge, as they may be required runtime link points. |
| Auditing, debugging class loader / reflection | Record flags, declaring class, and method information rather than inferring from names. |

## 10. Java 17 Compatibility and Inspection via Class File

If the environment is limited to **Java 17**, the `accessFlags()` methods and `AccessFlag` enum do not exist yet. You can still use:

```java
boolean publicMember =
        java.lang.reflect.Modifier.isPublic(method.getModifiers());
boolean bridge = method.isBridge();
boolean synthetic = method.isSynthetic();
```

This is a Java 17 fragment with the `method` variable already existing. If you need `ACC_*` bits that have no corresponding reflection API, use `javap -v -p <ClassName>` in the build environment or a reliable class file reader; do not try to force `Modifier` to be a full class file decoder.

When analyzing binaries, check the relevant sections in `javap`:

- `flags: (0x...) ACC_...` of class, field, method;
- `Signature` recording generic types that the JVM descriptor erased;
- `MethodParameters` containing parameter names and flags when present;
- `InnerClasses`, `Record`, `PermittedSubclasses`, and other attributes for properties that are not purely source modifiers.

Not every compiler necessarily writes the same set of auxiliary attributes. `javap` is a tool for inspecting bytecode on disk; Reflection observes the loaded runtime type, which can be affected by class loaders, modules, and bytecode-modifying tools.

## 11. Common Mistakes

1. **Using `getModifiers() == Modifier.PUBLIC`:** wrong when the member also has `static`, `final`...; decode with `Modifier.isPublic(...)`.
2. **Using `Modifier.toString()` to find bridge/synthetic:** it represents Java language modifiers, not a replacement for `Method.isBridge()`/`isSynthetic()`.
3. **Treating `0x40` as always volatile:** wrong at the method location, where that bit is `BRIDGE`.
4. **Assuming `getDeclaredMethods()` only returns methods written in source:** wrong; it can include bridge and compiler-generated methods.
5. **Filtering out all "not explicitly written" members as synthetic:** wrong for default constructors and valid implicit members of enum/record.
6. **Assuming every method with `$` is synthetic:** a name is not a flag; check the metadata property.
7. **Assuming Java 17 supports `AccessFlag`:** this API was introduced in Java 20; choose a Java 21+ toolchain when running this lesson's examples.
8. **Assuming `public` is always invokable across all modules:** access checks visibility, exports/opens, and caller context.
9. **Assuming the `getDeclaredMethods()` array has declaration order:** the API does not guarantee this; sort before reporting.
10. **Hiding bridges directly inside an execution engine/framework:** can lose polymorphic dispatch paths or mishandle metadata, especially when the runtime relies on erased method descriptors.

## 12. Self-Check Questions

**Question 1.** Why do we need to pass `AccessFlag.Location` when decoding a bitmask? What does `0x0080` mean in a field compared to a method?

**Question 2.** How many forms of `copy` in `StringBox` in Practice 2 can be accessed by `getDeclaredMethod`? Why is the method taking `Object` not written in source?

**Question 3.** A record has compiler-generated methods/members, so must `Point.class.isSynthetic()` return `true`?

**Question 4.** Should you use `getMethods()` or `getDeclaredMethods()` to inspect all members in a class file, including `private` and synthetic? When should you sort?

**Question 5.** On JDK 17, which API should you use to check if a method has the bridge flag? Can you use `AccessFlag.BRIDGE` directly?

**Question 6.** Why can a `public` method return `Modifier.isPublic(...) == true` yet still not be invokable from another module?

**Suggested answers:** (1) Because bits have meaning by location; `0x0080` is `TRANSIENT` in a field, `VARARGS` in a method. (2) `copy(String)` is the source method; `copy(Object)` is a synthetic bridge due to erasure to preserve overriding. (3) No; valid implicit members of a record do not make the class synthetic. (4) `getDeclaredMethods()`; sort whenever stable output is needed. (5) `Method.isBridge()`; `AccessFlag` does not exist on JDK 17. (6) Reflection permissions also depend on the enclosing class, Java module exports/opens, and caller context.

- [Java Language Specification 21 — `13.1 The Form of a Binary](https://docs.oracle.com/javase/specs/jls/se21/html/jls-13.html#jls-13.1): compiler-generated members and binary representation rules.

When reading metadata at runtime, ask **what kind of structure the target is**, **whether you are reading source modifiers or JVM access flags**, and **whether that member was added by the compiler**. These three questions help accurately interpret bridge, synthetic, and implicit members without missing structures required for a Java program to work properly.
