# Storing Multiple Class Files for Nested Classes and Generated Sources in In-Memory Java Compilation

When using `javax.tools.JavaCompiler` to compile Java sources directly in RAM, a common mistake is preparing a single `ByteArrayOutputStream` for the “main class” and treating that as the entire result. In reality, **one compilation unit can generate multiple `.class` files**: top-level classes, member classes, local classes, anonymous classes, and new types generated by annotation processors. A generated Java source can simultaneously exist as `.java` in `SOURCE_OUTPUT` and `.class` in `CLASS_OUTPUT`.

Therefore, the real problem is not “compile a string and return one byte array”, but **capture all file outputs by location, kind, and binary name**, preserve them until the compiler finishes, and supply all class bytes to the classloader.

## 1. Overall model

~~~text
JavaFileObjects of Kind.SOURCE (source code strings from RAM)
                             |
                    JavaCompiler.getTask
                             |
                     Annotation processor
                             |
               Filer.createSourceFile(...)
                             |
                SOURCE_OUTPUT + Kind.SOURCE
                    Generated.java (RAM)
                             |
                      Processing rounds
                             |
                         javac codegen
                             |
                CLASS_OUTPUT + Kind.CLASS
                  +----------+-----------+
                  |          |           |
             Main.class Outer.class  Outer$Nested.class
                  |          |           |
                  +----------+---- ... --+
                             |
                      Map<String, byte[]>
                             |
                      Custom ClassLoader
                             |
                        defineClass()
                             |
                     Execution in JVM
~~~

**Distinguish clearly:**

- **Input source:** `JavaFileObject` of kind `Kind.SOURCE` so the compiler reads virtual Java files provided by the application.
- **Generated source:** `JavaFileObject` of kind `Kind.SOURCE` created by `Filer`/processor at location `StandardLocation.SOURCE_OUTPUT`. The compiler can read that source in the next processing round.
- **Compiled binary:** `JavaFileObject` of kind `Kind.CLASS` at `StandardLocation.CLASS_OUTPUT`. One source input can trigger **multiple** calls to create outputs.
- **Runtime loading:** `ClassLoader` uses the binary name and class bytes. Putting bytes into a map does not automatically place the type on the application classpath.

The Java Compiler API belongs to the standard `java.compiler` module; the system compiler implementation requires a JDK with a compiler, typically the `jdk.compiler` module. `ToolProvider.getSystemJavaCompiler()` can return `null` in environments lacking a compiler.

## 2. Why are there more class files than source files?

Consider the following source (illustrative snippet, not standalone):

~~~java
package demo;

public class Outer {
    public static class Nested {}

    public void run() {
        class Local {}
        Runnable anonymous = new Runnable() {
            @Override public void run() {}
        };
        anonymous.run();
    }
}
~~~

With standard `javac`, besides `demo.Outer`, there are binary classes for `demo.Outer$Nested`, `Local`, and the anonymous class. Names of local/anonymous classes typically contain `$` and a sequence number, **but the numbering details are not a stable API across all compilers**. Do not guess file names yourself or filter only classes sharing the same simple name as the source.

| Cause | Example | Output to Store |
| --- | --- | --- |
| Top-level type | `class Outer` | `demo.Outer` |
| Static nested/member type | `static class Nested` | `demo.Outer$Nested` |
| Non-static inner member type | `class Inner` | Usually `demo.Outer$Inner` |
| Local class inside a method | `class Local` | Separate binary name, usually containing a numeric part |
| Anonymous class | `new Runnable() { ... }` | Separate binary name, usually containing `$N` |
| One compilation unit declaring multiple types | Package-private type in the same file | Each top-level type needs its own class output |
| Generated Java source | `Filer.createSourceFile("demo.Generated")` | Generated `.java` and, if compilation succeeds, `.class` |
| Processor creates binary directly | `Filer.createClassFile` | `.class` without necessarily having a generated `.java` |
| Records, enums, and synthetic constructs | `record Point(...)` | Corresponding `.class`; may have extra members/classes depending on the case |
| Lambda | `() -> doWork()` | **Does not necessarily create `Outer$N.class`**; modern `javac` typically uses `invokedynamic` |

**Storage principle:** the compiler is the authoritative source of truth on **which outputs are generated**. Do not compute the number of class files by counting occurrences of `class`, constructors, or lambdas in the source.

## 3. Most important callback: `getJavaFileForOutput`

Core interface of `JavaFileManager`:

~~~java
JavaFileObject getJavaFileForOutput(
    JavaFileManager.Location location,
    String className,
    JavaFileObject.Kind kind,
    FileObject sibling
) throws IOException;
~~~

This is an API signature, not a standalone runnable Java file.

- `location`: typically `StandardLocation.CLASS_OUTPUT` or `SOURCE_OUTPUT`. This is the **logical location** where the compiler wants to write.
- `className`: **binary name** provided by the compiler. For example `demo.Outer$Nested`, distinct from the source name `demo.Outer.Nested` and distinct from the file URI.
- `kind`: `JavaFileObject.Kind.CLASS` for compiled binaries, `Kind.SOURCE` for generated Java sources.
- `sibling`: related file object helping identify the output; should not be used alone as a unique key, because one source can emit multiple binary files.
- Return value: a `JavaFileObject` capable of receiving the content written by the compiler/processor.

In memory:

~~~text
CLASS_OUTPUT  + CLASS  + "demo.Outer$Nested" -> .class byte[]
SOURCE_OUTPUT + SOURCE + "demo.Generated"    -> .java bytes/text
CLASS_OUTPUT  + CLASS  + "demo.Generated"    -> .class byte[]
~~~

Because **`demo.Generated` can appear twice with different kinds**, separate `Map<String, Output> classFiles` and `Map<String, Output> generatedSources`, or use a composite key `(location, kind, name)`. Do not store both in a map keyed solely by `"Generated"`.

Each output object needs its own buffer; do not share the same `ByteArrayOutputStream` across class names. If multiple files write to one buffer, bytes get mixed or reset, causing the loader to fail with `ClassFormatError`, `NoClassDefFoundError`, or another linkage error.

## 4. Complete Java 17+ example: source in RAM, processor generating source, multiple class outputs

The example uses **a single file** on the host side: `MemoryCompilerDemo.java`. At runtime, the host creates three virtual sources `demo.Marker`, `demo.Outer`, and `demo.Main`. An annotation processor running in the same process generates `demo.Generated`. The compiler writes all class bytes into a map; a custom loader loads `demo.Main`, including dependencies located in the map.

### 4.1. Complete source code

~~~java
import java.io.ByteArrayInputStream;
import java.io.ByteArrayOutputStream;
import java.io.IOException;
import java.io.InputStream;
import java.io.OutputStream;
import java.io.OutputStreamWriter;
import java.io.Writer;
import java.net.URI;
import java.nio.charset.StandardCharsets;
import java.util.List;
import java.util.Locale;
import java.util.Map;
import java.util.Set;
import java.util.TreeMap;
import javax.annotation.processing.AbstractProcessor;
import javax.annotation.processing.RoundEnvironment;
import javax.annotation.processing.SupportedAnnotationTypes;
import javax.annotation.processing.SupportedSourceVersion;
import javax.lang.model.SourceVersion;
import javax.lang.model.element.TypeElement;
import javax.tools.Diagnostic;
import javax.tools.DiagnosticCollector;
import javax.tools.FileObject;
import javax.tools.ForwardingJavaFileManager;
import javax.tools.JavaCompiler;
import javax.tools.JavaFileManager;
import javax.tools.JavaFileObject;
import javax.tools.SimpleJavaFileObject;
import javax.tools.StandardJavaFileManager;
import javax.tools.StandardLocation;
import javax.tools.ToolProvider;

public final class MemoryCompilerDemo {
    // Pre-written Java source, supplied from a String.
    static final class Source extends SimpleJavaFileObject {
        private final String source;

        Source(String binaryName, String source) {
            super(URI.create("string:///" + binaryName.replace('.', '/')
                    + Kind.SOURCE.extension), Kind.SOURCE);
            this.source = source;
        }

        @Override
        public CharSequence getCharContent(boolean ignoreEncodingErrors) {
            return source;
        }
    }

    // Each output file has its own buffer, used for CLASS or SOURCE.
    static final class Output extends SimpleJavaFileObject {
        private final ByteArrayOutputStream buffer = new ByteArrayOutputStream();

        Output(String binaryName, Kind kind) {
            super(URI.create("mem:///" + binaryName.replace('.', '/')
                    + kind.extension), kind);
        }

        @Override
        public OutputStream openOutputStream() {
            buffer.reset();
            return buffer;
        }

        @Override
        public Writer openWriter() {
            return new OutputStreamWriter(openOutputStream(), StandardCharsets.UTF_8);
        }

        @Override
        public InputStream openInputStream() {
            return new ByteArrayInputStream(buffer.toByteArray());
        }

        @Override
        public CharSequence getCharContent(boolean ignoreEncodingErrors) {
            return new String(buffer.toByteArray(), StandardCharsets.UTF_8);
        }

        byte[] bytes() {
            return buffer.toByteArray();
        }
    }

    static final class MemoryFiles
            extends ForwardingJavaFileManager<StandardJavaFileManager> {
        final Map<String, Output> classFiles = new TreeMap<>();
        final Map<String, Output> generatedSources = new TreeMap<>();

        MemoryFiles(StandardJavaFileManager delegate) {
            super(delegate);
        }

        @Override
        public boolean hasLocation(Location location) {
            if (location == StandardLocation.CLASS_OUTPUT
                    || location == StandardLocation.SOURCE_OUTPUT) {
                return true;
            }
            return super.hasLocation(location);
        }

        @Override
        public JavaFileObject getJavaFileForOutput(Location location,
                String className, JavaFileObject.Kind kind, FileObject sibling)
                throws IOException {
            if (location == StandardLocation.CLASS_OUTPUT
                    && kind == JavaFileObject.Kind.CLASS) {
                Output file = new Output(className, kind);
                if (classFiles.putIfAbsent(className, file) != null) {
                    throw new IOException("Duplicate class output: " + className);
                }
                return file;
            }
            if (location == StandardLocation.SOURCE_OUTPUT
                    && kind == JavaFileObject.Kind.SOURCE) {
                Output file = new Output(className, kind);
                if (generatedSources.putIfAbsent(className, file) != null) {
                    throw new IOException("Duplicate source output: " + className);
                }
                return file;
            }
            return super.getJavaFileForOutput(location, className, kind, sibling);
        }
    }

    // Processor EXPLICITLY registered in CompilationTask.
    @SupportedAnnotationTypes("demo.Marker")
    @SupportedSourceVersion(SourceVersion.RELEASE_17)
    public static final class Generator extends AbstractProcessor {
        private boolean emitted;

        @Override
        public boolean process(Set<? extends TypeElement> annotations,
                RoundEnvironment round) {
            if (emitted || round.processingOver() || annotations.isEmpty()) {
                return true;
            }
            emitted = true;
            try (Writer writer = processingEnv.getFiler()
                    .createSourceFile("demo.Generated").openWriter()) {
                writer.write("package demo;\n"
                        + "public class Generated {\n"
                        + "  public static String message() { return \"generated\"; }\n"
                        + "}\n");
            } catch (IOException ex) {
                processingEnv.getMessager().printMessage(
                        Diagnostic.Kind.ERROR, ex.toString());
            }
            return true;
        }
    }

    static final class ByteLoader extends ClassLoader {
        private final Map<String, byte[]> classes;

        ByteLoader(ClassLoader parent, Map<String, byte[]> classes) {
            super(parent);
            this.classes = classes;
        }

        @Override
        protected Class<?> findClass(String name) throws ClassNotFoundException {
            byte[] data = classes.get(name);
            if (data == null) {
                throw new ClassNotFoundException(name);
            }
            return defineClass(name, data, 0, data.length);
        }
    }

    public static void main(String[] args) throws Exception {
        JavaCompiler compiler = ToolProvider.getSystemJavaCompiler();
        if (compiler == null) {
            throw new IllegalStateException("A full JDK is required");
        }

        List<JavaFileObject> inputs = List.of(
                new Source("demo.Marker", """
                        package demo;
                        public @interface Marker {}
                        """),
                new Source("demo.Outer", """
                        package demo;
                        @Marker
                        public class Outer {
                            public static class Nested {
                                public static String text() { return "nested"; }
                            }
                            public String local() {
                                class Local { String text() { return "local"; } }
                                return new Local().text();
                            }
                            public String anonymous() {
                                Runnable task = new Runnable() {
                                    @Override public void run() {}
                                };
                                task.run();
                                return "anonymous";
                            }
                        }
                        """),
                new Source("demo.Main", """
                        package demo;
                        public class Main {
                            public static void main(String[] args) {
                                System.out.println(Generated.message());
                                System.out.println(Outer.Nested.text());
                                System.out.println(new Outer().local());
                                System.out.println(new Outer().anonymous());
                            }
                        }
                        """));

        DiagnosticCollector<JavaFileObject> diagnostics = new DiagnosticCollector<>();
        try (StandardJavaFileManager standard = compiler.getStandardFileManager(
                diagnostics, Locale.ROOT, StandardCharsets.UTF_8)) {
            MemoryFiles files = new MemoryFiles(standard);
            JavaCompiler.CompilationTask task = compiler.getTask(
                    null, files, diagnostics, List.of("--release", "17"),
                    null, inputs);
            task.setProcessors(List.of(new Generator()));

            if (!Boolean.TRUE.equals(task.call())) {
                for (Diagnostic<? extends JavaFileObject> d :
                        diagnostics.getDiagnostics()) {
                    System.err.println(d);
                }
                throw new IllegalStateException("Compilation failed");
            }

            Map<String, byte[]> classBytes = new TreeMap<>();
            files.classFiles.forEach(
                    (name, file) -> classBytes.put(name, file.bytes()));

            System.out.println("generated-source="
                    + files.generatedSources.containsKey("demo.Generated"));
            System.out.println("generated-class="
                    + classBytes.containsKey("demo.Generated"));
            System.out.println("member-class="
                    + classBytes.containsKey("demo.Outer$Nested"));
            System.out.println("extra-classes="
                    + classBytes.keySet().stream()
                    .filter(n -> n.startsWith("demo.Outer$")
                            && !n.equals("demo.Outer$Nested"))
                    .count());

            ByteLoader loader = new ByteLoader(
                    MemoryCompilerDemo.class.getClassLoader(), classBytes);
            Class<?> main = Class.forName("demo.Main", true, loader);
            main.getMethod("main", String[].class)
                    .invoke(null, (Object) new String[0]);
        }
    }
}
~~~

### 4.2. Execution commands and output

Save the entire code above into `MemoryCompilerDemo.java`, using JDK 17 or higher:

~~~bash
javac --release 17 -encoding UTF-8 MemoryCompilerDemo.java
java MemoryCompilerDemo
~~~

**Stdout verified using OpenJDK 21 targeting Java 17:**

~~~text
generated-source=true
generated-class=true
member-class=true
extra-classes=2
generated
nested
local
anonymous
~~~

`generated-source=true` and `generated-class=true` confirm that **the same `demo.Generated` type** has both generated source and compiled binary. `member-class=true` confirms `demo.Outer$Nested` was not missed. `extra-classes=2` are two additional classes from local/anonymous constructs when using the tested JDK's `javac`, but **do not use their numbered names as fixed keys in application logic**.

Only the host Java code `MemoryCompilerDemo.java` is compiled directly by the external command; the `demo.*` types are compiled into RAM via `JavaCompiler`. Running `demo.Main` uses the byte map, without needing to write `demo.*` classes to disk.

## 5. Breaking down each important part

### 5.1. `Source`: Java source without a file on disk

`SimpleJavaFileObject` is created with a URI of the form `string:///demo/Outer.java` and `Kind.SOURCE`, and `getCharContent` returns the source string. One `CompilationTask` can accept multiple `JavaFileObject` instances corresponding to source units. The URI must be valid, carry the appropriate extension for the kind, and help provide clear file names in diagnostics.

The example has three input sources: `demo.Marker`, `demo.Outer`, and `demo.Main`. This number of source files does **not** put an upper bound on the number of `Kind.CLASS` outputs. If there are additional top-level types or generated sources, the compiler can still produce many other outputs.

### 5.2. `Output`: separate buffer and ability to read back generated sources

Class bytes are written by the compiler via `openOutputStream`. New sources created by `Filer.createSourceFile` can be written by the processor via `openWriter`; the compiler must read the generated source in a later round, so `getCharContent` and `openInputStream` must be supported appropriately.

In the example, `openWriter` uses UTF-8 and `getCharContent` decodes with the same encoding. This avoids losing Unicode characters when a processor generates sources containing Unicode strings. Each `Output` has a **separate** `ByteArrayOutputStream`, preventing bytes from mixing between `Outer.class`, `Outer$Nested.class`, and `Generated.class`.

### 5.3. `MemoryFiles`: classifying by location + kind

`ForwardingJavaFileManager<StandardJavaFileManager>` delegates looking up JDK classes, module/classpath inputs, and non-overridden operations to the standard manager. We only intercept two branches:

~~~java
// Illustrative code inside getJavaFileForOutput(...)
if (location == StandardLocation.CLASS_OUTPUT
        && kind == JavaFileObject.Kind.CLASS) {
    // Store into classFiles by className
}
if (location == StandardLocation.SOURCE_OUTPUT
        && kind == JavaFileObject.Kind.SOURCE) {
    // Store into generatedSources by className
}
~~~

This is an **illustrative snippet**, not a complete method. `hasLocation` informs the compiler that the file manager accepts the two output locations it handles.

If you want to support processors generating **resources**, you must add handling for `getFileForOutput(Location, packageName, relativeName, sibling)`. This method is different from `getJavaFileForOutput` and is not automatically intercepted by the example. Resources like `META-INF/services/...` need separate mapping by location/package/path. Therefore, the demo covers **generated Java sources and class outputs**, but does not claim to cover every file type an arbitrary processor might create.

### 5.4. `Generator`: new source generated during compilation

The processor is registered via:

~~~java
task.setProcessors(List.of(new Generator()));
~~~

This approach does not rely on service descriptors or auto-discovery. `Generator` is triggered when the compiler detects `@demo.Marker`, creates `demo.Generated` through `Filer`, and avoids emitting duplicates in subsequent rounds.

Understand the sequence:

1. `demo.Outer` is annotated with `@Marker`.
2. The compiler calls `Generator.process(...)`.
3. The processor creates `SOURCE_OUTPUT / demo.Generated.java`.
4. The compiler reads the generated source and resolves `Generated.message()` called by `demo.Main`.
5. The bytecode generator requests a class output for `demo.Generated`.
6. `MemoryFiles.classFiles` holds the corresponding bytes.

`@SupportedSourceVersion(SourceVersion.RELEASE_17)` describes the source level the processor supports; `--release 17` in compilation options is what selects the Java 17 target. One `CompilationTask` is single-use: a new task must be created for a new compilation.

### 5.5. `ByteLoader`: class name must be the binary name

`ClassLoader.findClass(String name)` receives a binary name such as `demo.Main` or `demo.Outer$Nested`. Using the exact `className` passed by the compiler into the manager as the map key allows `findClass` to look it up accurately.

`defineClass(name, bytes, 0, bytes.length)` creates a runtime class definition from the bytes. When `demo.Main` uses `Generated` or nested/local/anonymous types, the classloader must be able to find all those related classes.

`Class.forName("demo.Main", true, loader)` specifies the loader for the bytecode set. Casting `(Object) new String[0]` in the reflection call:

~~~java
main.getMethod("main", String[].class)
    .invoke(null, (Object) new String[0]);
~~~

ensures the `String[]` array is passed **as a single argument** to `main(String[])`, avoiding `Method.invoke`'s varargs expansion.

`ByteLoader` uses parent-first delegation by default: if the parent classloader already contains a class with **the same binary name**, the parent's class may take precedence. This is a loading-mechanism demo, **not a sandbox** or a full classloader isolation solution.

## 6. Source file, output file, and binary name are three different things

Example of type `demo.Outer$Nested`:

~~~text
Source compilation unit: demo.Outer  (string:///demo/Outer.java)
Java nested source name: demo.Outer.Nested
JVM binary name:          demo.Outer$Nested
Class output:             mem:///demo/Outer$Nested.class
Map key:                  "demo.Outer$Nested"
~~~

For local and anonymous classes, the compiler is allowed to use a naming scheme producing distinct binary names (usually with numbers), so **do not guess** the output name from the AST or source name. To store all class bytes, you do not need to know the list of names in advance: simply capture every `CLASS_OUTPUT + Kind.CLASS` callback.

`getJavaFileForOutput` has a `sibling` parameter, but you should not use the sibling source as the key, because multiple outputs can belong to **the same sibling**.

## 7. Distinguishing class files and generated sources from annotation processing

| Kind | Creation API | File Manager Location | Content |
| --- | --- | --- | --- |
| Java source generated by processor | `Filer.createSourceFile` | `SOURCE_OUTPUT` | Java text / `Kind.SOURCE` |
| Java class generated by compiler | `javac` code generation | `CLASS_OUTPUT` | JVM binary / `Kind.CLASS` |
| Java class generated directly by processor | `Filer.createClassFile` | `CLASS_OUTPUT` | JVM binary / `Kind.CLASS` |
| Resource generated by processor | `Filer.createResource` | `SOURCE_OUTPUT` or `CLASS_OUTPUT` | Depends on resource; may not be Java source |
| Hand-written input source | `new Source(...)` | Compilation units | Java text read by the compiler |
| Compiled dependency | Classpath/module path manager | `CLASS_PATH`/`MODULE_PATH` | Input bytecode, **not a new output** |

With `-proc:only`, annotation processing can generate `Generated.java` **without generating application class files**. If you want a two-step pipeline, the next compilation pass must take the generated source as input and create a new task (typically using `-proc:none` to avoid duplicate generation). In the main example, the pipeline performs processing **and** compilation in the same task.

If the generated source has syntax errors or unresolvable types, the compiler may have already created `Generated.java` while compilation fails and the class map is incomplete. Do not treat the map as a valid build if `task.call()` does not succeed.

## 8. Managing multiple compilation runs

Using the compiler to build an IDE tool, expression evaluator, or plugin server means compiling multiple times inside the same JVM. Several principles:

1. **Each compilation has its own output maps.** Do not let `classBytes` from an old run mix with a new run.
2. **Do not reuse a `CompilationTask`.** The task API is for one compilation; create a new task each time.
3. **Do not redefine the same binary name in the same classloader.** To load a new version, typically create a new classloader for the new run.
4. **Close standard resources.** `StandardJavaFileManager` implements `Closeable`; use try-with-resources as in the example. Output buffers can be snapshotted to byte arrays after a successful compile.
5. **Be careful sharing `byte[]`.** `Map.copyOf(...)` does not clone byte array elements; callers can mutate byte arrays if you return direct references. Copy each array when immutability is needed.
6. **Synchronize when needed.** Do not assume compiler tasks, maps, and shared buffers are thread-safe. If multiple requests run concurrently, each request should have its own manager/state.
7. **Cache with the right key.** The same source string with a different JDK version, `--release`, classpath, processor version, or compiler options can produce different output. Do not cache solely by main class name.
8. **Enforce resource limits.** Bytecode/output can be large; only compile and execute trusted code inside the application process, or apply real isolation for untrusted code.

## 9. Diagnostics and partial errors

`DiagnosticCollector<JavaFileObject>` stores compiler warnings/errors. If `task.call()` returns false, there may still be **some outputs generated before the error was detected**. Do not pass them to the runtime classloader and declare the build successful.

Illustrative error handling snippet:

~~~java
// Only use to replace the existing call() position; do not call task.call() a second time.
boolean success = Boolean.TRUE.equals(task.call());
if (!success) {
    for (Diagnostic<? extends JavaFileObject> diagnostic
            : diagnostics.getDiagnostics()) {
        System.err.println(diagnostic.getKind() + ": "
                + diagnostic.getMessage(Locale.ROOT));
    }
}
~~~

The code above is a snippet placed inside a method that has appropriate `task` and `diagnostics`. In real applications, include the source URI, line, and column to indicate whether the error originated from an input source or a generated source.

A compile result can be modeled as:

~~~java
// Illustrative record inside a project with appropriate imports
record CompileResult(
    boolean success,
    Map<String, byte[]> classBytes,
    Map<String, String> generatedSources,
    List<String> diagnostics
) {}
~~~

However, do not return class outputs when compilation fails as if it succeeded. You should create a *logically* immutable snapshot, clone bytes when passing data to another thread/plugin, and retain generated-source text only when needed for debugging/auditing.

## 10. Common errors

| Symptom | Possible Cause | How to Fix |
| --- | --- | --- |
| `ClassNotFoundException: demo.Outer$Nested` | Only storing the main class | Store **every** `getJavaFileForOutput(CLASS_OUTPUT, ...)` |
| `NoClassDefFoundError` when running a method | Missing auxiliary/local/anonymous class in the loader | Match the failing binary name against map keys |
| `ClassFormatError` | Reusing one buffer or wrong key-to-bytes mapping | One buffer per output, keyed by className from the compiler |
| `Generated.java` exists but `Generated.class` does not | `-proc:only` or compilation error | Check compile options, diagnostics, and class map |
| `Generated.class` exists without source | Processor emitted binary class directly, or source location wasn't intercepted | Check processor API and locations |
| `FilerException` | Trying to create the same file multiple times / colliding with input | Guard rounds, avoid duplicate names |
| `ToolProvider.getSystemJavaCompiler() == null` | Runtime lacks compiler | Run on a full JDK |
| `UnsupportedOperationException` when reading generated source | In-memory output only provides a write stream | Add `getCharContent`/`openInputStream` |
| `IllegalArgumentException` with URI | Invalid URI, incorrect source kind | Use a URI with proper scheme/path/extension |
| Compiled code runs an old version | Map or parent classloader retains another class with the same name | Fresh run state and loader isolation |
| Processor creates resources on disk | `getFileForOutput` not overridden | Add resource handling |
| App runs on build machine but fails on deploy | Not packaging all nested/generated classes | Export all required class bytes |
| Class-output map has entries yet compilation failed | Compiler wrote partial output before the error | Publish results only if the task succeeded |

### Debugging workflow

1. Verify `ToolProvider.getSystemJavaCompiler()` and JDK/target release.
2. Verify input `JavaFileObject` instances have valid kind/source text/URI.
3. Verify the processor is registered and generates sources via `Filer`.
4. Log each `location + kind + className` callback; **do not log only Main**.
5. Check that `generatedSources` has the right new source and the compiler can read it.
6. Check that `classFiles` has all outputs, valid byte lengths, and no overwrites.
7. Check diagnostics/success; do not use partial builds.
8. Create a new classloader and execute code to detect missing binary dependencies.
9. Test sources containing member, local, anonymous, and processor-generated types: this is a critical test suite for the file manager.

## 11. Self-check questions

**1.** Why can a single `Outer.java` source generate multiple `.class` files?  
Because outer contains member/local/anonymous types and the compiler can emit multiple outputs. The number of source files does not determine the number of class files.

**2.** What is the best map key for class output?  
Use the **verbatim binary name** the compiler passes into `getJavaFileForOutput`, such as `demo.Outer$Nested`, rather than the simple name or source filename.

**3.** How do `SOURCE_OUTPUT` and `CLASS_OUTPUT` differ?  
`SOURCE_OUTPUT` stores generated Java text/source files; `CLASS_OUTPUT` stores compiled JVM bytecode (and potentially resources).

**4.** Why can `demo.Generated` appear in both maps?  
One entry is the generated `Generated.java`; the other is the compiled `Generated.class`, sharing the type name but differing in kind/location.

**5.** Must a lambda create an additional class file like an anonymous class?  
No. Modern `javac` typically represents lambdas via `invokedynamic`; simply store whichever outputs the compiler actually produces.

**6.** When does `Generated.java` exist without `Generated.class`?  
With `-proc:only`, compilation failure in the generated source, or when the pipeline intentionally splits processing and compilation into two passes.

**7.** Is overriding only `openOutputStream` enough to support processors generating Java source in RAM?  
Not necessarily. The compiler may need to read the generated source using `getCharContent` or `openInputStream`; design the file object to support those operations.

**8.** Why does the example use `Class.forName("demo.Main", true, loader)`?  
The `demo.*` classes only reside in the in-memory map, not written to the application classpath. A loader reading the map must be used.

**9.** Can a single `ClassLoader` be reused to replace the bytes of an already-defined class?  
Not via the normal `defineClass` mechanism. Each version/run should use its own appropriate loader.

**10.** Can compiler + custom classloader be treated as a sandbox for running untrusted code?  
No. Executing bytecode can inherit process permissions; resource and permission isolation at the proper layer is required.

## 12. Implementation checklist

- [ ] Use `JavaFileObject.Kind.SOURCE` for input source strings.
- [ ] Create a **separate** output buffer for each class/source output.
- [ ] Capture **all** `CLASS_OUTPUT + Kind.CLASS` callbacks, without filtering for only the main class.
- [ ] Preserve binary names containing `$` for nested/local/anonymous classes.
- [ ] Capture `SOURCE_OUTPUT + Kind.SOURCE` when processors generate Java sources.
- [ ] Generated source objects support writing **and reading back** across processing rounds.
- [ ] Separate source maps and class maps; extend keys with location/kind/module/run if needed.
- [ ] If processors generate resources, also handle `getFileForOutput`.
- [ ] Load outputs only when `CompilationTask.call()` succeeds.
- [ ] Snapshot bytes/diagnostics and isolate each compilation run to avoid stale state.
- [ ] The classloader can resolve **all** generated dependent binary classes.
- [ ] Test member, local, anonymous, and processor-generated type cases.
- [ ] Do not rely on numbered local/anonymous names or class file counts for lambdas.
- [ ] Protect the system when compiling/loading untrusted code with real isolation.
