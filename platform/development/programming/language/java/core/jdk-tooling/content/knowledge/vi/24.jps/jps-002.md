# Liệt kê Java process bằng jps

**jps** (Java Virtual Machine Process Status Tool) là công cụ dòng lệnh đi kèm JDK để liệt kê các JVM đã được instrument trên máy đích và mà người dùng hiện tại có quyền truy cập. Nó giúp xác định nhanh Java application đang chạy, lấy local VM identifier, xem tên class/JAR khởi chạy và một số tham số của ứng dụng.

Lệnh cơ bản:

~~~bash
jps
~~~

Output thường có dạng:

~~~text
57916 ProcessProbe
58320 Jps
~~~

Cột đầu tiên là **local VM identifier (lvmid)**. Cột tiếp theo là tên ngắn của main class hoặc JAR. Dòng Jps có thể chính là tiến trình jps vừa chạy.

Khi cần biết đầy đủ tên class, tham số ứng dụng và tham số JVM:

~~~bash
jps -lmv
~~~

Ví dụ:

~~~text
57916 com.example.ProcessProbe alpha beta -Ddemo.mode=sample -Xms16m
~~~

Trong đó:

- 57916 là lvmid của JVM.
- com.example.ProcessProbe là tên đầy đủ của main class.
- alpha beta là các tham số truyền cho main method.
- -Ddemo.mode=sample và -Xms16m là tham số truyền cho JVM lúc khởi động.

Số lvmid thay đổi theo mỗi lần chạy. Nó thường trùng với PID của tiến trình hệ điều hành, nhưng không được bảo đảm luôn như vậy.

## 1. jps dùng để làm gì?

Trong môi trường phát triển và vận hành Java, một máy có thể chạy nhiều JVM cùng lúc:

- Ứng dụng backend.
- Application server.
- IDE.
- Build daemon.
- Java test runner.
- JShell.
- Monitoring hoặc diagnostic tool.
- Tiến trình Java được nhúng trong ứng dụng native.

Khi cần kiểm tra JVM nào đang chạy, jps cung cấp danh sách ngắn gọn mà không cần đọc toàn bộ process list của hệ điều hành.

Một số tình huống thực tế:

- Tìm JVM của service cần chẩn đoán.
- Phân biệt nhiều ứng dụng cùng có tên main class là Main.
- Xác định PID/lvmid trước khi dùng jcmd.
- Kiểm tra tham số JVM có được truyền khi khởi động hay không.
- Xác định ứng dụng được chạy từ class hay JAR.
- Kiểm tra một JVM còn tồn tại sau khi restart hoặc deploy hay không.

jps là công cụ khám phá và chẩn đoán nhanh. Nó không thay thế process manager, service supervisor, container orchestrator hoặc hệ thống monitoring production.

## 2. jps liệt kê loại process nào?

jps tìm các **instrumented Java HotSpot VM** trên máy đích. Nó chỉ hiển thị những JVM mà tài khoản hiện tại có quyền truy cập theo cơ chế bảo vệ của hệ điều hành và JVM.

Điều này có nghĩa:

- jps không phải danh sách mọi process của hệ điều hành.
- Một JVM do user khác chạy có thể không xuất hiện.
- Một JVM bị giới hạn attach hoặc không cung cấp metadata phù hợp có thể không được liệt kê.
- JVM chạy trong container hoặc process namespace khác có thể không hiển thị trong cùng phạm vi.
- JVM dùng custom launcher có thể hiện tên Unknown thay vì tên class/JAR.
- JVM có thể kết thúc ngay sau khi jps đọc danh sách, tạo ra tình huống race khi bạn dùng lvmid tiếp tục chẩn đoán.

Nếu jps không hiển thị một ứng dụng, chưa thể kết luận ứng dụng không chạy. Hãy kiểm tra thêm process list của hệ điều hành, service manager, container runtime và quyền truy cập.

### jps cũng có thể xuất hiện trong danh sách

Khi chạy jps, chính tiến trình jps có thể được liệt kê trong output:

~~~text
58320 Jps
~~~

Đây là hành vi bình thường. Không nhầm dòng Jps với ứng dụng cần tìm.

## 3. Cài đặt và kiểm tra lệnh jps

jps nằm trong thư mục bin của JDK. Hãy dùng JDK đã cài đặt và bảo đảm PATH trỏ tới đúng thư mục bin.

Kiểm tra trên Windows PowerShell:

~~~powershell
Get-Command jps
where.exe jps
~~~

Linux/macOS:

~~~bash
which jps
command -v jps
~~~

Xem cú pháp hỗ trợ:

~~~bash
jps --help
~~~

Kiểm tra phiên bản Java đang được gọi:

~~~bash
java -version
~~~

jps không phải lệnh của JRE runtime tối giản. Nếu hệ thống chỉ cài runtime image đã lược bỏ công cụ chẩn đoán, có thể không có executable jps.

Nên dùng jps từ JDK phù hợp với môi trường đang điều tra. Khi có nhiều JDK trên máy, kiểm tra đường dẫn thực tế của jps và java để tránh vô tình dùng công cụ từ một JDK khác.

## 4. Cấu trúc output

Output tổng quát của jps có dạng:

~~~text
lvmid [ [classname | JARfilename | "Unknown"] [arg*] [jvmarg*] ]
~~~

Các phần:

| Thành phần | Ý nghĩa |
|---|---|
| lvmid | Local VM identifier của JVM |
| classname | Main class được dùng để khởi chạy ứng dụng |
| JARfilename | JAR được dùng làm entry point |
| Unknown | Công cụ không xác định được class/JAR |
| arg | Tham số truyền cho main method |
| jvmarg | Tham số truyền cho JVM khi khởi động |

Các token trong output được phân tách bằng khoảng trắng. Nếu một tham số chứa khoảng trắng, việc ánh xạ token trở lại từng tham số có thể mơ hồ. Vì vậy tài liệu JDK khuyến cáo không viết script phụ thuộc vào việc parse output jps; định dạng có thể thay đổi giữa các phiên bản.

### lvmid và PID

lvmid thường trùng với PID của tiến trình hệ điều hành. Tuy nhiên, tên chính xác của cột này là local VM identifier và không nên giả định luôn có quan hệ một-một với PID trong mọi môi trường hoặc implementation.

Nếu cần thao tác hệ điều hành như dừng process, hãy xác minh PID bằng công cụ hệ điều hành trước khi thực hiện hành động. Đừng lấy một con số từ output rồi mặc định đó là PID hợp lệ trong mọi môi trường.

### Tên class và JAR

Nếu ứng dụng chạy bằng main class:

~~~text
57916 com.example.ProcessProbe
~~~

Nếu chạy bằng executable JAR, tên JAR có thể xuất hiện thay cho tên class.

Không có tùy chọn, jps thường hiển thị dạng ngắn, bỏ package hoặc đường dẫn JAR. Dùng -l để xem dạng đầy đủ hơn.

## 5. Các tùy chọn quan trọng

### Chỉ hiển thị local VM identifier: -q

~~~bash
jps -q
~~~

Tùy chọn -q ẩn tên class/JAR và các tham số main method, chỉ để lại danh sách local VM identifier.

Ví dụ:

~~~text
57916
58320
94336
~~~

Dùng khi chỉ cần danh sách ID hoặc muốn giảm lượng thông tin hiển thị.

### Hiển thị tên đầy đủ: -l

~~~bash
jps -l
~~~

-l hiển thị package đầy đủ của main class hoặc đường dẫn đầy đủ tới JAR khởi chạy.

Ví dụ:

~~~text
57916 com.example.ProcessProbe
58320 jdk.jcmd/sun.tools.jps.Jps
~~~

Với ứng dụng modular, output có thể thể hiện module/class theo cách công cụ trình bày. Với JAR, output có thể chứa đường dẫn đầy đủ.

Dùng -l khi nhiều ứng dụng có cùng tên ngắn như Main, Server hoặc Launcher.

### Hiển thị tham số main method: -m

~~~bash
jps -m
~~~

-m hiển thị các tham số được truyền cho main method.

Nếu khởi chạy:

~~~bash
java com.example.ProcessProbe alpha beta
~~~

output có thể có dạng:

~~~text
57916 ProcessProbe alpha beta
~~~

Đối với một số JVM được nhúng, giá trị tham số main có thể là null hoặc không có sẵn.

Tham số main không giống tham số JVM. Ví dụ alpha và beta thuộc ứng dụng; chúng không phải -Xmx hoặc -Dproperty.

### Hiển thị tham số JVM: -v

~~~bash
jps -v
~~~

-v hiển thị các tham số được truyền cho JVM khi khởi chạy.

Ví dụ:

~~~text
57916 ProcessProbe -Ddemo.mode=sample -Xms16m -Xmx512m
~~~

Một số nhóm tham số thường gặp:

- -Xms: kích thước heap ban đầu.
- -Xmx: kích thước heap tối đa.
- -Dname=value: system property.
- -XX:+UseG1GC: bật một JVM flag.
- -XX:MaxMetaspaceSize=...: giới hạn metaspace.

Output thực tế phụ thuộc cách JVM được khởi chạy và phiên bản JDK. Không phải mọi cấu hình đều xuất hiện như một tham số đơn giản; một số giá trị có thể đến từ environment, file cấu hình hoặc cơ chế launcher.

**Lưu ý bảo mật:** -v có thể hiển thị thông tin nhạy cảm nếu ứng dụng truyền password, token hoặc dữ liệu bí mật qua command line/system property. Không gửi output nguyên văn vào ticket, chat hoặc log công khai trước khi rà soát và che thông tin nhạy cảm.

### Kết hợp các tùy chọn

Có thể kết hợp -m, -l và -v:

~~~bash
jps -lmv
~~~

Đây là lệnh hữu ích khi cần nhận diện ứng dụng và hiểu cách JVM được khởi chạy.

Các tùy chọn này có thể kết hợp theo cú pháp jps. Hãy dùng đúng nhóm cần thiết để tránh output quá dài hoặc làm lộ command-line secrets.

## 6. Phân biệt main arguments và JVM arguments

Đây là điểm quan trọng khi đọc jps output.

Xét lệnh khởi chạy:

~~~bash
java -Ddemo.mode=sample -Xms16m \
    -cp build/classes \
    com.example.ProcessProbe alpha beta
~~~

Phân loại:

| Giá trị | Loại | jps hiển thị |
|---|---|---|
| -Ddemo.mode=sample | System property của JVM | -v |
| -Xms16m | JVM option | -v |
| -cp build/classes | Classpath option lúc khởi chạy | Tùy cách công cụ trình bày metadata |
| com.example.ProcessProbe | Main class | Mặc định hoặc -l |
| alpha beta | Main method arguments | -m |

Đừng nhầm -m với -v:

- -m trả lời ứng dụng nhận những tham số nào trong main.
- -v trả lời JVM nhận những tham số khởi động nào.

Nếu muốn xem cả hai, dùng -lmv.
## 7. Ví dụ Java 17+ hoàn chỉnh: tạo một process để jps tìm thấy

Ví dụ này tạo một Java process chạy trong hai phút. Trong thời gian đó, mở terminal thứ hai và dùng jps để liệt kê process.

Cấu trúc:

~~~text
jps-demo/
└── src/
    └── com/
        └── example/
            └── ProcessProbe.java
~~~

### ProcessProbe.java

~~~java
package com.example;

public final class ProcessProbe {
    private ProcessProbe() {
    }

    public static void main(String[] args) throws InterruptedException {
        System.out.println("ProcessProbe started");
        Thread.sleep(120_000);
    }
}
~~~

### Biên dịch bằng Java 17+

Từ thư mục gốc jps-demo:

Linux/macOS:

~~~bash
mkdir -p build/classes

javac --release 17 \
    -d build/classes \
    src/com/example/ProcessProbe.java
~~~

Windows PowerShell:

~~~powershell
New-Item -ItemType Directory -Force build/classes | Out-Null
javac --release 17 -d build/classes src/com/example/ProcessProbe.java
~~~

### Chạy process

~~~bash
java -Ddemo.mode=sample -Xms16m \
    -cp build/classes \
    com.example.ProcessProbe alpha beta
~~~

Output của chương trình:

~~~text
ProcessProbe started
~~~

Chương trình tiếp tục ngủ trong 120 giây. Để nguyên terminal này và mở terminal thứ hai.

### Liệt kê JVM

~~~bash
jps
~~~

Bạn sẽ thấy một dòng có tên ngắn ProcessProbe cùng lvmid. Các process Java khác đang chạy trên máy cũng có thể xuất hiện.

### Xem tên đầy đủ và tham số

~~~bash
jps -lmv
~~~

Output mẫu đã quan sát trên JDK 24.0.2:

~~~text
57916 com.example.ProcessProbe alpha beta -Ddemo.mode=sample -Xms16m
~~~

57916 chỉ là lvmid trong lần chạy kiểm thử; con số sẽ khác trên máy bạn.

### Xác nhận từng tùy chọn

~~~bash
jps -l
jps -m
jps -v
jps -q
~~~

Bạn có thể đối chiếu:

- -l hiển thị com.example.ProcessProbe.
- -m hiển thị alpha beta.
- -v hiển thị -Ddemo.mode=sample và -Xms16m.
- -q chỉ hiển thị lvmid.

Sau khi hết 120 giây, process kết thúc và không còn xuất hiện trong lần jps tiếp theo.

## 8. Liệt kê Java process từ xa bằng hostid

jps hỗ trợ chỉ định hostid để tìm JVM trên máy từ xa. Với dạng hostname, công cụ sử dụng RMI và giả định có jstatd đang chạy trên host đích.

Ví dụ:

~~~bash
jps -l app-server.example.com
~~~

Chỉ định cổng RMI registry:

~~~bash
jps -lm app-server.example.com:1099
~~~

Dạng hostid đầy đủ có thể gồm protocol, hostname, port và server name:

~~~text
[protocol:][[//]hostname][:port][/servername]
~~~

Khi hostname được chỉ định mà không ghi protocol, giao thức mặc định là rmi. Cổng RMI registry mặc định là 1099 nếu không chỉ định cổng.

Remote listing cần:

- jstatd chạy trên host đích.
- RMI registry hoạt động theo cấu hình.
- Firewall cho phép kết nối tới cổng cần thiết.
- Quyền truy cập và cấu hình bảo mật phù hợp.
- jps ở máy nguồn dùng hostid đúng.

Không bật jstatd trên mạng công cộng hoặc mở rộng quyền truy cập tùy tiện. Đây là công cụ chẩn đoán từ xa; hãy giới hạn mạng, danh tính và quyền theo chính sách vận hành.

Remote jps không phải cách thay thế monitoring agent hoặc service discovery. Nếu chỉ cần chẩn đoán một máy, ưu tiên chạy jps trực tiếp trên host đó.

## 9. Giới hạn và trạng thái hỗ trợ của jps

Tài liệu JDK mô tả jps là công cụ **experimental and unsupported**. Các tùy chọn và định dạng output có thể thay đổi hoặc bị loại bỏ trong các phiên bản tương lai.

Những giới hạn cần nhớ:

- Chỉ liệt kê JVM mà công cụ có quyền truy cập.
- Không bảo đảm hiển thị mọi Java process trên hệ điều hành.
- Không bảo đảm lvmid luôn là PID của hệ điều hành.
- Tên class/JAR có thể là Unknown nếu JVM dùng custom launcher.
- Tham số main có thể không có sẵn đối với JVM nhúng.
- Output phân tách bằng whitespace, có thể mơ hồ nếu argument chứa khoảng trắng.
- Process có thể kết thúc ngay sau khi được liệt kê.
- Container/process namespace và chính sách attach có thể ảnh hưởng khả năng nhìn thấy JVM.
- Không phải giao diện ổn định cho script production.

Vì vậy, dùng jps để khám phá và điều tra thủ công. Nếu cần automation ổn định, hãy dùng API quản lý process phù hợp, service manager, container orchestration, JMX/metrics hoặc công cụ giám sát được hỗ trợ.

## 10. Vì sao jps không tìm thấy ứng dụng?

### Chạy jps bằng user khác

jps bị giới hạn theo quyền truy cập của hệ điều hành. Nếu ứng dụng chạy dưới một user khác, jps hiện tại có thể không liệt kê được.

Hãy kiểm tra tài khoản chạy service và chạy công cụ bằng danh tính được phép truy cập. Không tăng quyền rộng hơn mức cần thiết chỉ để làm danh sách đầy đủ.

### Ứng dụng đã thoát

Nếu JVM kết thúc trước hoặc trong lúc jps truy vấn, nó sẽ không còn xuất hiện. Kiểm tra service status và chạy lại lệnh.

### JVM dùng custom launcher hoặc embedded mode

Nếu JVM được tạo bằng JNI Invocation API hoặc custom launcher, jps có thể không tìm được tên main class/JAR. Output có thể hiển thị Unknown hoặc thiếu main arguments.

Dùng OS process list, service metadata hoặc application log để xác định process.

### Attach bị giới hạn

Một số môi trường tắt hoặc giới hạn Attach API. Container, quyền filesystem, user namespace hoặc chính sách runtime có thể ảnh hưởng khả năng phát hiện.

Kiểm tra cấu hình JVM và quyền truy cập theo tài liệu của JDK đang dùng. Không bật attach cho mọi process nếu môi trường không yêu cầu.

### Dùng nhầm JDK

PATH có thể trỏ tới JDK khác với JDK chạy ứng dụng. Kiểm tra:

~~~powershell
Get-Command java
Get-Command jps
~~~

Hoặc trên Linux/macOS:

~~~bash
which java
which jps
java -version
~~~

### Ứng dụng chạy trong container khác

jps trên host không nhất thiết thấy JVM trong container có process namespace riêng. Chạy công cụ trong đúng container hoặc dùng công cụ quản lý container để lấy process.

### Tên hiển thị là Unknown

Tên class/JAR không có sẵn qua metadata launcher. Dùng lvmid kết hợp OS process inspection và log/service metadata để nhận diện.

## 11. Dùng lvmid với jcmd để chẩn đoán tiếp

Sau khi tìm được JVM cần kiểm tra, có thể dùng jcmd để yêu cầu diagnostic command.

Liệt kê JVM mà jcmd nhìn thấy:

~~~bash
jcmd -l
~~~

Xem các lệnh hỗ trợ bởi JVM mục tiêu:

~~~bash
jcmd <pid> help
~~~

Ví dụ xem command line của JVM:

~~~bash
jcmd <pid> VM.command_line
~~~

Xem JVM flags:

~~~bash
jcmd <pid> VM.flags
~~~

Xem thông tin phiên bản:

~~~bash
jcmd <pid> VM.version
~~~

Thay <pid> bằng process identifier phù hợp. Xác minh rằng lvmid thực tế dùng được như PID trên môi trường đó; nếu không, tìm PID bằng công cụ hệ điều hành.

jps chỉ giúp tìm JVM. jcmd cung cấp nhiều lệnh chẩn đoán sâu hơn, nhưng chỉ nên chạy lệnh phù hợp và có hiểu biết về tác động của nó.

## 12. So sánh jps với process list của hệ điều hành

| Công cụ | Phạm vi | Thông tin chính |
|---|---|---|
| jps | JVM instrumented mà người dùng có quyền truy cập | lvmid, main class/JAR, main args, JVM args |
| jcmd -l | JVM mà Attach API có thể liệt kê | PID và thông tin nhận diện JVM |
| ps | Process của hệ điều hành | PID, user, command line |
| Get-Process | Process Windows | PID, tên process và thông tin process |
| Get-CimInstance Win32_Process | Process Windows | PID, executable path, command line |
| Service manager | Service được quản lý | trạng thái, cấu hình và vòng đời service |

Linux/macOS:

~~~bash
ps -eo pid,user,args
~~~

Windows PowerShell:

~~~powershell
Get-CimInstance Win32_Process |
    Select-Object ProcessId, Name, ExecutablePath, CommandLine
~~~

OS process list có thể hiển thị nhiều process hơn jps nhưng không hiểu sâu về cấu trúc JVM. Ngược lại, jps tập trung vào JVM nhưng có giới hạn về quyền và instrumented process.

Command line của process có thể chứa password hoặc token. Rà soát và che dữ liệu nhạy cảm trước khi chia sẻ output.

## 13. Có nên parse output jps trong script không?

Không nên xây dựng automation phụ thuộc vào output dạng text của jps.

Lý do:

- jps được tài liệu JDK mô tả là experimental/unsupported.
- Output format có thể thay đổi giữa release.
- Token phân tách bằng whitespace, nên argument có khoảng trắng gây mơ hồ.
- Tên class có thể là Unknown.
- Danh sách phụ thuộc quyền truy cập và trạng thái process tại thời điểm quét.
- lvmid không được bảo đảm luôn là OS PID.

Nếu cần giám sát process, hãy dùng:

- ProcessHandle API nếu ứng dụng Java cần quan sát process của hệ điều hành.
- Service manager hoặc container orchestration cho vòng đời service.
- JMX hoặc metrics cho thông tin runtime.
- jcmd cho thao tác chẩn đoán có kiểm soát.
- OS process API cho script vận hành cần PID/command line.

Nếu vẫn phải parse jps trong một script nội bộ, coi đó là tích hợp dễ thay đổi, giới hạn phạm vi JDK, kiểm tra phiên bản, xử lý Unknown và whitespace, đồng thời có phương án fallback.

## 14. Quy trình sử dụng jps khi điều tra sự cố

1. Chạy jps để xem JVM đang hiển thị.
2. Dùng -l để xác định main class/JAR đầy đủ.
3. Dùng -m để phân biệt ứng dụng theo main arguments.
4. Dùng -v khi cần kiểm tra JVM arguments và system properties.
5. Ghi nhận lvmid và xác minh PID nếu cần thao tác OS.
6. Dùng jcmd -l để đối chiếu danh sách JVM có thể attach.
7. Chạy jcmd với lệnh diagnostic phù hợp.
8. Nếu process không xuất hiện, kiểm tra user, container, attach và service status.
9. Không chia sẻ output -m/-v trước khi loại bỏ secret.
10. Ghi nhận JDK version và thời điểm chạy vì process list thay đổi liên tục.

jps phù hợp cho bước đầu nhận diện JVM trong môi trường nhiều ứng dụng Java. Khi hiểu lvmid, phân biệt main arguments với JVM arguments, biết giới hạn quyền truy cập và kết hợp jcmd/OS tools, bạn có thể xác định đúng process để tiếp tục chẩn đoán.
