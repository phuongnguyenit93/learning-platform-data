# Đọc argument output bằng jps

`jps` (Java Virtual Machine Process Status Tool) là công cụ dòng lệnh đi kèm JDK để liệt kê các JVM HotSpot đã được instrument trên máy đích. Khi đọc output, cần phân biệt bốn thành phần: **LVMID**, tên main class hoặc JAR, **application arguments** truyền cho `main()` và **JVM arguments** truyền cho Java launcher.

Các tùy chọn thường dùng:

- `jps -m` hiển thị đối số ứng dụng.
- `jps -v` hiển thị đối số JVM.
- `jps -l` hiển thị tên class đầy đủ hoặc đường dẫn JAR.
- `jps -lmv` kết hợp cả ba nhóm thông tin.

Tài liệu Oracle JDK 21 đánh dấu `jps` là công cụ experimental và unsupported; định dạng output có thể thay đổi ở các bản phát hành sau. Dùng công cụ này để chẩn đoán tương tác, kiểm tra cú pháp bằng `jps -help` của JDK đang chạy và tránh xây dựng automation phụ thuộc vào cách tách cột của output.

## 1. Cấu trúc output của jps

Cú pháp output tổng quát:

```text
lvmid [ [ classname | JARfilename | "Unknown" ] [ arg* ] [ jvmarg* ] ]
```

| Thành phần | Ý nghĩa |
|---|---|
| `lvmid` | Local JVM identifier, định danh JVM mà `jps` tìm thấy |
| `classname` | Tên main class; dạng ngắn hoặc đầy đủ tùy tùy chọn |
| `JARfilename` | Tên hoặc đường dẫn file JAR dùng để khởi chạy |
| `arg*` | Các đối số truyền vào `main(String[] args)` |
| `jvmarg*` | Các đối số truyền cho JVM/Java launcher, ví dụ `-Xmx` hoặc `-Dname=value` |
| `Unknown` | Không xác định được class/JAR và application arguments, thường gặp với custom launcher |

`lvmid` thường trùng với process ID của hệ điều hành, nhưng không được bảo đảm luôn giống nhau. Khi cần truyền định danh cho công cụ khác, hãy xác minh PID bằng công cụ hệ điều hành hoặc công cụ quản trị phù hợp.

Các trường trong output được phân tách bằng khoảng trắng. Nếu một application argument chứa khoảng trắng, output văn bản có thể không thể hiện ranh giới argument rõ ràng. Vì vậy, không nên parse output `jps` như một định dạng máy đọc ổn định.

## 2. Liệt kê JVM với jps mặc định

Chạy:

```sh
jps
```

Ví dụ output minh họa:

```text
24680 ArgumentOutputDemo
25120 OrderService
25210 jps
```

Mỗi dòng thường gồm LVMID và tên rút gọn của main class hoặc JAR. Tên class rút gọn không chứa package; đường dẫn JAR cũng có thể được rút gọn.

Output có thể bao gồm chính process `jps` đang chạy, ngoài các ứng dụng Java khác mà tài khoản hiện tại được phép quan sát. PID trong ví dụ chỉ để minh họa; trên máy thật, giá trị thay đổi theo từng lần khởi chạy.

Nếu không thấy ứng dụng, điều đó không nhất thiết có nghĩa ứng dụng không chạy. `jps` chỉ báo các JVM instrumented mà người dùng hiện tại có quyền truy cập và công cụ có thể phát hiện.

## 3. Hiển thị application arguments bằng -m

Tùy chọn `-m` hiển thị các đối số truyền cho method `main()`:

```sh
jps -m
```

Ví dụ:

```text
24680 ArgumentOutputDemo --profile=staging --port=8080
25120 OrderService --spring.profiles.active=prod
25210 jps -m
```

Với ứng dụng được khởi chạy:

```sh
java com.example.ArgumentOutputDemo --profile=staging --port=8080
```

Hai giá trị `--profile=staging` và `--port=8080` là application arguments. Java launcher chuyển chúng vào mảng `String[] args` của method `main()`.

Một số JVM được nhúng hoặc khởi chạy qua cơ chế đặc biệt có thể hiển thị `null` thay cho application arguments. Nếu ứng dụng dùng custom launcher, `jps` có thể không xác định được các đối số này.

Không nhầm application arguments với system properties:

- `--profile=staging` sau tên main class là application argument.
- `-Dapp.mode=demo` trước tên main class là JVM/system property argument.
- `-Xmx128m` trước tên main class là JVM memory option.

## 4. Hiển thị tên class hoặc đường dẫn JAR đầy đủ bằng -l

Tùy chọn `-l` hiển thị tên package đầy đủ của main class hoặc đường dẫn đầy đủ đến JAR:

```sh
jps -l
```

Ví dụ:

```text
24680 com.example.tools.ArgumentOutputDemo
25120 /opt/services/order-service/order-service.jar
25210 jdk.jcmd/sun.tools.jps.Jps
```

Điều này hữu ích khi nhiều ứng dụng có cùng tên class rút gọn, chẳng hạn nhiều module đều có class `Main`. Tên package đầy đủ giúp phân biệt chúng.

Với ứng dụng chạy từ JAR, `-l` giúp xác định JAR được dùng để khởi chạy. Đường dẫn được hiển thị có thể phụ thuộc cách launcher và nền tảng cung cấp thông tin cho JVM.

## 5. Hiển thị JVM arguments bằng -v

Tùy chọn `-v` hiển thị các đối số được truyền cho JVM:

```sh
jps -v
```

Ví dụ:

```text
24680 ArgumentOutputDemo -Xms64m -Xmx128m -Dapp.mode=demo -Dregion=ap-southeast-1
25120 OrderService -Xms512m -Xmx2g -Dspring.profiles.active=prod
25210 jdk.jcmd/sun.tools.jps.Jps -Dapplication.home=/opt/jdk
```

Các đối số thường thấy:

| Argument | Ý nghĩa |
|---|---|
| `-Xms64m` | Heap ban đầu |
| `-Xmx128m` | Giới hạn heap tối đa |
| `-Dapp.mode=demo` | Đặt system property cho ứng dụng |
| `-Dregion=ap-southeast-1` | Ví dụ system property tùy chỉnh |
| `-ea` | Bật assertion theo phạm vi áp dụng |

`-v` hữu ích khi cần xác nhận JVM được khởi chạy với heap limit, system property hoặc cờ runtime mong muốn hay không.

Không phải mọi thông tin cấu hình đều xuất hiện trong `-v`. Một số giá trị có thể đến từ environment variable, file cấu hình, launcher riêng, container runtime hoặc được code thay đổi sau khi JVM khởi động.

## 6. Kết hợp -l, -m và -v

Có thể kết hợp các tùy chọn:

```sh
jps -l -m -v
```

Hoặc viết gọn:

```sh
jps -lmv
```

Ví dụ dòng output cho một ứng dụng:

```text
24680 com.example.tools.ArgumentOutputDemo --profile=staging --port=8080 -Xms64m -Xmx128m -Dapp.mode=demo
```

Cách đọc:

1. `24680` là LVMID.
2. `com.example.tools.ArgumentOutputDemo` là tên main class đầy đủ.
3. `--profile=staging --port=8080` là application arguments.
4. `-Xms64m -Xmx128m -Dapp.mode=demo` là JVM arguments.

Thứ tự trường là định danh, class/JAR, application arguments rồi JVM arguments. Tuy nhiên, vì các token được phân cách bằng whitespace và không có schema máy đọc ổn định, chỉ dùng cách đọc này cho chẩn đoán thủ công.

## 7. Chỉ hiển thị định danh bằng -q và -V

Tùy chọn `-q` ẩn tên class, tên JAR và application arguments, chỉ giữ lại local JVM identifier:

```sh
jps -q
```

Ví dụ:

```text
24680
25120
25210
```

Dùng `-q` khi chỉ cần danh sách định danh JVM. Không dùng output này để xác định ứng dụng nào cần xử lý vì tên class/JAR đã bị ẩn.

Theo tài liệu Oracle JDK 21, `-V` cũng suppress tên class, tên JAR và application arguments, để lại danh sách LVMID:

```sh
jps -V
```

Một số tài liệu JDK cũ mô tả `-V` khác với tài liệu JDK 21. Vì vậy, hãy kiểm tra `jps -help` và man page của đúng JDK đang sử dụng. Khi mục tiêu là xem JVM arguments, dùng chữ thường `-v`; đừng nhầm `-V` với `-v`.

## 8. Phân biệt application arguments và JVM arguments

Đây là khác biệt quan trọng nhất khi đọc argument output.

Ví dụ lệnh khởi chạy:

```sh
java -Xms64m -Xmx128m -Dapp.mode=demo -cp out com.example.ArgumentOutputDemo --profile=staging --port=8080
```

| Phần trong lệnh | Loại |
|---|---|
| `-Xms64m` | JVM argument |
| `-Xmx128m` | JVM argument |
| `-Dapp.mode=demo` | JVM/system property argument |
| `-cp out` | Java launcher option |
| `com.example.ArgumentOutputDemo` | Main class |
| `--profile=staging` | Application argument |
| `--port=8080` | Application argument |

`jps -m` tập trung vào đối số ứng dụng được truyền cho `main()`. `jps -v` tập trung vào đối số JVM. Nếu cần xem cả hai, dùng `jps -lmv`.

Không phải mọi token trong lệnh shell đều xuất hiện nguyên vẹn trong output `jps`. Shell có thể xử lý biến môi trường, dấu nháy hoặc wildcard trước khi gọi Java launcher. Output phản ánh thông tin mà JVM/tooling ghi nhận, không phải bản sao hoàn hảo của dòng lệnh shell ban đầu.

## 9. Ví dụ thực hành Java 17+: tạo JVM có argument dễ nhận diện

Tạo source file `src/com/example/ArgumentOutputDemo.java`:

```java
package com.example;

import java.util.Arrays;
import java.util.concurrent.CountDownLatch;

public class ArgumentOutputDemo {
    public static void main(String[] args) throws InterruptedException {
        System.out.println("PID=" + ProcessHandle.current().pid());
        System.out.println("APP_ARGS=" + Arrays.toString(args));

        // Giữ JVM chạy để có thể kiểm tra từ terminal khác.
        new CountDownLatch(1).await();
    }
}
```

Biên dịch:

```sh
mkdir -p out
javac -d out src/com/example/ArgumentOutputDemo.java
```

Chạy ứng dụng với cả JVM arguments và application arguments:

```sh
java -Xms64m -Xmx128m -Dapp.mode=demo -cp out com.example.ArgumentOutputDemo --profile=staging --port=8080
```

Output của chương trình:

```text
PID=24680
APP_ARGS=[--profile=staging, --port=8080]
```

`24680` là PID minh họa; giá trị thực tế được in bởi `ProcessHandle.current().pid()`. Chương trình chờ vô hạn để JVM vẫn tồn tại khi bạn mở terminal thứ hai.

Từ terminal thứ hai, chạy:

```sh
jps -lmv
```

Tìm dòng có class `com.example.ArgumentOutputDemo`. Dòng tương ứng có dạng:

```text
24680 com.example.ArgumentOutputDemo --profile=staging --port=8080 -Xms64m -Xmx128m -Dapp.mode=demo
```

Output còn có thể chứa JVM khác, bao gồm process `jps` vừa được khởi chạy. Sau khi thực hành, nhấn Ctrl+C ở terminal chạy chương trình để kết thúc process demo.

## 10. Trường hợp khởi chạy bằng JAR

Nếu ứng dụng được khởi chạy bằng executable JAR:

```sh
java -Xmx512m -Dapp.env=production -jar order-service.jar --port=8080 --region=vn
```

`jps -lmv` có thể hiển thị dạng:

```text
25120 /opt/services/order-service.jar --port=8080 --region=vn -Xmx512m -Dapp.env=production
```

Ở đây:

- Đường dẫn JAR là mục tiêu khởi chạy.
- `--port=8080` và `--region=vn` là đối số ứng dụng mà launcher chuyển cho `main()`.
- `-Xmx512m` và `-Dapp.env=production` là JVM arguments.

Dùng `-l` để xem đường dẫn JAR đầy đủ thay vì tên rút gọn. Nếu hệ thống triển khai tạo nhiều bản sao JAR cùng tên ở các thư mục khác nhau, đường dẫn đầy đủ giúp xác định đúng artifact đang chạy.

## 11. Khi jps hiển thị Unknown

`jps` sử dụng thông tin do Java launcher cung cấp để nhận diện tên class/JAR và application arguments. Nếu JVM được khởi chạy bằng custom launcher, các thông tin đó có thể không sẵn có.

Ví dụ:

```text
24680 Unknown
```

`Unknown` không tự động có nghĩa JVM bị lỗi. Nó có thể chỉ ra rằng launcher không cung cấp metadata mà `jps` cần để hiển thị tên ứng dụng và đối số main.

Khi gặp trường hợp này:

1. Dùng LVMID để tìm process tương ứng.
2. Kiểm tra command line bằng công cụ hệ điều hành.
3. Xem log khởi động hoặc service definition.
4. Dùng `jcmd -l` và diagnostic command nếu JVM hỗ trợ attach.
5. Kiểm tra cách custom launcher khởi tạo JVM.

Không giả định `jps -m` sẽ luôn khôi phục được application arguments khi launcher không cung cấp thông tin.

## 12. Phạm vi process mà jps có thể nhìn thấy

`jps` chỉ liệt kê JVM HotSpot instrumented mà công cụ có quyền truy cập. Danh sách có thể bị giới hạn bởi user/group của tài khoản chạy `jps`, quyền truy cập theo hệ điều hành, container/PID namespace, attach mechanism hoặc khác biệt JVM vendor.

Chạy `jps` dưới một tài khoản khác có thể cho danh sách khác. Không dùng việc thiếu một dòng trong output làm bằng chứng duy nhất rằng process không tồn tại.

Trong container, chạy `jps` bên trong đúng container hoặc PID namespace nếu cần quan sát JVM ở đó. PID nhìn từ host có thể khác PID trong container.

## 13. Xem JVM ở host từ xa

`jps` hỗ trợ host identifier (`hostid`) để truy vấn JVM trên máy khác theo giao thức và cấu hình được hỗ trợ. Với giao thức RMI mặc định khi chỉ định hostname, tài liệu yêu cầu có `jstatd` chạy trên host đích.

Cú pháp host identifier:

```text
[protocol:][[//]hostname][:port][/servername]
```

Ví dụ minh họa:

```sh
jps -l app-host.example.com:1099
```

Ví dụ này giả định remote `jstatd` và RMI registry đã được cấu hình trên port 1099, đồng thời máy hiện tại có quyền truy cập.

Remote monitoring không tự hoạt động chỉ bằng cách thêm hostname. Cần thiết lập `jstatd`, RMI và quyền mạng theo hướng dẫn của JDK. Chỉ bật dịch vụ này trong môi trường được kiểm soát; không phơi bày endpoint quản trị ra mạng không tin cậy.

## 14. Không parse jps output như giao thức ổn định

Oracle khuyến cáo không viết script phụ thuộc vào cấu trúc output `jps` vì format có thể thay đổi ở các release tương lai.

Nguyên nhân:

- Các trường được phân cách bằng whitespace.
- Application argument có thể chứa khoảng trắng.
- Class/JAR name và cách hiển thị có thể thay đổi theo launcher.
- JVM implementation và phiên bản có thể khác nhau.
- Công cụ được đánh dấu experimental và unsupported.

Nếu cần automation, ưu tiên Process API hoặc service manager để quản lý process do ứng dụng khởi chạy; dùng PID từ nguồn đáng tin cậy; dùng `jcmd` cho diagnostic command của JVM; dùng JMX hoặc hệ thống observability có schema rõ ràng khi cần dữ liệu lâu dài.

Không tách output theo vị trí cột cố định hoặc giả định mọi dòng đều có cùng số token.

## 15. Lưu ý bảo mật: arguments có thể làm lộ secret

`jps -m` và `jps -v` có thể hiển thị command-line arguments. Giá trị nhạy cảm có thể bị lộ nếu truyền qua application arguments như `--password=...`, JVM system properties như `-Dservice.token=...`, cờ launcher hoặc URL có embedded credentials.

Không truyền password, API token, private key hoặc secret trực tiếp trên command line. Các giá trị này có thể xuất hiện trong process listing, log chẩn đoán, công cụ giám sát hoặc dữ liệu hỗ trợ sự cố.

Dùng secret manager, file được bảo vệ với quyền truy cập hạn chế, credential provider hoặc cơ chế nhập secret phù hợp với runtime. Khi chia sẻ output `jps`, hãy rà soát và che thông tin nhạy cảm trước.

## 16. jps và các công cụ liên quan

| Công cụ | Mục đích |
|---|---|
| `jps` | Liệt kê JVM instrumented và hiển thị class/JAR/arguments |
| `jcmd -l` | Liệt kê JVM cục bộ có thể attach |
| `jcmd PID help` | Xem diagnostic command mà JVM cụ thể hỗ trợ |
| `jcmd PID VM.command_line` | Xem thông tin command line nếu JVM hỗ trợ command |
| `ps` / Task Manager | Xem process ở cấp hệ điều hành |
| `jstat` | Theo dõi một số thống kê JVM như GC |
| JMX | Giám sát và quản trị JVM qua MBean |

Vì `jps` được đánh dấu experimental và unsupported trong tài liệu Oracle JDK 21, hãy cân nhắc `jcmd -l` cho quy trình chẩn đoán dựa trên công cụ JDK hiện đại. Khả năng nhìn thấy process vẫn phụ thuộc quyền và môi trường attach.

Không phải mọi lệnh `jcmd` đều có trên mọi JVM hoặc mọi phiên bản. Hỏi target JVM bằng `jcmd PID help` trước khi gọi diagnostic command cụ thể.

## 17. Lỗi thường gặp và cách xử lý

| Hiện tượng | Nguyên nhân thường gặp | Cách xử lý |
|---|---|---|
| Không thấy ứng dụng trong `jps` | Khác user, container namespace hoặc JVM không instrument/không attach được | Chạy dưới đúng user/namespace và kiểm tra bằng process manager |
| Chỉ thấy số LVMID | Dùng `-q` hoặc `-V` | Chạy `jps -l` hoặc `jps -lmv` |
| Không thấy application arguments | Chưa dùng `-m` hoặc launcher không cung cấp metadata | Dùng `jps -m` và kiểm tra launcher |
| Không thấy JVM arguments | Chưa dùng `-v` | Chạy `jps -v` |
| Class name bị rút gọn | Dùng output mặc định | Dùng `jps -l` |
| Hiển thị `Unknown` | JVM chạy bằng custom launcher hoặc metadata không sẵn có | Kiểm tra command line, service definition và log |
| LVMID khác PID mong đợi | LVMID không được bảo đảm luôn là OS PID | Xác minh PID bằng công cụ hệ điều hành |
| Application arguments bị tách sai | Argument chứa whitespace làm output mơ hồ | Không parse output; kiểm tra cấu hình/launcher gốc |
| Output khác giữa hai JDK | Format/options có thể thay đổi theo release | Đọc `jps -help` và tài liệu đúng phiên bản |
| Remote host không trả kết quả | `jstatd`/RMI chưa cấu hình hoặc port bị chặn | Kiểm tra remote service, registry và network policy |
| Output chứa thông tin bí mật | Secret được truyền qua command line | Thay bằng secret manager/credential provider và che output |

## 18. Quy trình đọc argument output khi điều tra

Khi cần xác định một ứng dụng đang chạy với cấu hình nào:

1. Chạy `jps` để có danh sách JVM ban đầu.
2. Dùng `jps -l` để xác định class hoặc JAR đầy đủ.
3. Dùng `jps -m` để xem application arguments.
4. Dùng `jps -v` để xem JVM arguments.
5. Dùng `jps -lmv` nếu cần xem tất cả nhóm trong một lần.
6. Đối chiếu LVMID với PID của hệ điều hành.
7. Xác nhận giá trị quan trọng trong log/configuration của ứng dụng.
8. Che secret trước khi lưu hoặc chia sẻ output.
9. Nếu cần chẩn đoán sâu, dùng `jcmd` trên đúng JVM.
10. Ghi lại JDK version và command đã dùng để kết quả có thể tái lập.

Đối với sự cố heap, hãy kiểm tra `-Xms` và `-Xmx` trong JVM arguments. Đối với profile ứng dụng, xem application argument hoặc system property tương ứng. Đối với lỗi không thấy process, kiểm tra user, container và attach permissions trước khi kết luận JVM không chạy.

## 19. Checklist

- [ ] Đã chạy `jps` để liệt kê JVM có thể quan sát.
- [ ] Đã xác định LVMID và kiểm tra PID thực tế khi cần.
- [ ] Đã dùng `-l` để xem class/JAR đầy đủ.
- [ ] Đã dùng `-m` để xem application arguments.
- [ ] Đã dùng `-v` để xem JVM arguments.
- [ ] Đã hiểu `-q` và hành vi `-V` theo phiên bản JDK.
- [ ] Đã phân biệt `main()` arguments với `-D`/`-X` JVM arguments.
- [ ] Đã xem xét trường hợp custom launcher hiển thị `Unknown`.
- [ ] Đã kiểm tra quyền user và container namespace nếu thiếu process.
- [ ] Đã tránh parse output thành định dạng ổn định.
- [ ] Đã che secret trước khi lưu/chia sẻ output.
- [ ] Đã dùng `jcmd` hoặc công cụ observability phù hợp khi cần chẩn đoán sâu.

Dùng `-m` cho đối số `main()`, `-v` cho tùy chọn JVM, `-l` cho tên class/JAR đầy đủ; sau đó xác minh thông tin cần thiết bằng công cụ quản trị phù hợp.
