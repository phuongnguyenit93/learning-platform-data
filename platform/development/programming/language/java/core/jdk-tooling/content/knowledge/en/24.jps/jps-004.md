# Main Class Output in jps

**`jps`** is a JDK command-line tool that lists the running HotSpot JVMs that the current user account has permission to observe. Each line typically starts with a **local JVM identifier (lvmid)**, followed by the main class name or the JAR file name used to launch the application.

The class name in the output helps you quickly identify which Java application is running. When you need the exact package/class, arguments passed to `main()`, or JVM options, you can combine the `-l`, `-m`, and `-v` options.

## 1. What is the main class in jps output?

When running an application with the command:

```bash
java com.example.app.Main
```

The Java launcher loads the `com.example.app.Main` class and invokes the application's entry point method. This class is called the **main class**.

When running:

```bash
jps
```

The output typically looks like:

```text
18420 Main
29116 Main
32780 Jps
```

Each line consists of:

- **LVMID:** the local JVM identifier, usually matching the operating system process ID.
- **Main class or JAR:** the short name of the main class or the name of the JAR file used to launch the application.

In the example, `Main` is the short name of the main class; the package information has been omitted. `Jps` is the `jps` tool process itself running to list the JVMs.

The LVMID is usually the process PID, but the JDK documentation does not guarantee that the two values are always identical in all environments. Use the value returned by the tool when invoking other JVM tools, and verify the process if the environment uses a special launcher.

## 2. Distinguishing between main class, main method, and JAR

These three concepts are related but not identical:

| Concept | Meaning | Example |
| --- | --- | --- |
| Main class | The class selected by the launcher as the application's starting point | `com.example.app.Main` |
| Main method | The entry point method inside the class | `public static void main(String[] args)` |
| Executable JAR | An archive launched with `java -jar`; the manifest specifies the main class | `app.jar` |

If launched by class name:

```bash
java -cp app.jar com.example.app.Main
```

JPS typically displays the main class name.

If launched with an executable JAR:

```bash
java -jar app.jar
```

JPS may display the JAR name or path instead of the class name declared in the manifest. To view the JAR's main class, check the `Main-Class` attribute in `META-INF/MANIFEST.MF`.

If launched as a modular application:

```bash
java -m com.example.app/com.example.app.Main
```

The full output may show both the module and the class, for example:

```text
com.example.app/com.example.app.Main
```

JPS displays the launch target that the tool can identify; it does not print source code or stack traces of the main method.

## 3. Structure of a jps output line

The general output format described in the JDK documentation is:

```text
lvmid [ [classname | JARfilename | "Unknown"] [arg*] [jvmarg*] ]
```

Where:

- `lvmid`: local JVM identifier.
- `classname`: the main class name if the launcher provides this information.
- `JARfilename`: the name or path of the launched JAR.
- `Unknown`: a value that may appear when JPS cannot determine the class/JAR.
- `arg*`: arguments passed to the main method, if requested.
- `jvmarg*`: arguments passed to the JVM, if requested.

Example:

```text
18420 com.example.app.Main --profile=prod -Xms256m -Xmx2g
```

This can be read in order as:

1. `18420`: the JVM identifier.
2. `com.example.app.Main`: the main class.
3. `--profile=prod`: the application argument passed to `main(String[] args)`.
4. `-Xms256m -Xmx2g`: the JVM startup arguments.

This example illustrates how the fields are combined; to display all of this information, use the corresponding options.

## 4. Displaying the full class name with jps -l

Without options, `jps` typically displays only the short class name, omitting the package. If multiple applications share the class name `Main`, the results can be hard to tell apart.

Use `-l` to display the full package name of the main class or the full path of the JAR:

```bash
jps -l
```

Sample output:

```text
18420 com.example.billing.Main
29116 com.example.inventory.Main
32780 jdk.jcmd/sun.tools.jps.Jps
```

Both applications have a class named `Main`, but the package helps identify them accurately.

For applications running as modules, the output may have the form `module/class`. For example, a JDK tool JVM might display:

```text
jdk.jshell/jdk.internal.jshell.tool.JShellToolProvider
```

For applications launched with a JAR, `-l` displays the full path to the JAR as recognized by the launcher.

## 5. Displaying main method arguments with jps -m

The `-m` option displays the arguments passed to the main method.

Example run:

```bash
java -cp app.jar com.example.app.Main --profile=staging --port=8080
```

Then:

```bash
jps -m
```

Sample output:

```text
18420 Main --profile=staging --port=8080
```

The strings after the class name are application arguments, corresponding to the `args` array in:

```java
public static void main(String[] args) {
    // args[0] = "--profile=staging"
    // args[1] = "--port=8080"
}
```

If the JVM is embedded or launched through a custom launcher, main method argument information might be unavailable; the JDK documentation notes that the output may be `null` or `Unknown` depending on the case.

Do not confuse main method arguments with VM arguments. For example, `--profile=staging` above is an application argument, whereas `-Xmx2g` is a JVM option.

## 6. Displaying JVM arguments with jps -v

The `-v` option displays the arguments passed to the JVM at startup.

Example:

```bash
java -Xms256m -Xmx2g -Dapp.profile=production -jar app.jar
```

Run:

```bash
jps -v
```

Sample output:

```text
18420 app.jar -Xms256m -Xmx2g -Dapp.profile=production
```

Common arguments:

| Category | Example | Meaning |
| --- | --- | --- |
| Heap | `-Xms256m`, `-Xmx2g` | Initial and maximum heap size |
| System property | `-Dapp.profile=production` | System property value |
| GC | `-XX:+UseG1GC` | Garbage collector selection |
| Module | `--add-modules java.sql` | Add modules at startup |
| Debug | `-agentlib:jdwp=...` | Debugger agent configuration |

JVM arguments are useful when investigating runtime configuration, but they can contain sensitive information such as tokens, passwords, internal URLs, or file paths. Filter the output before sharing it in tickets, chats, or public logs.

## 7. Combining -l, -m, and -v

You can combine options to view complete information about a process:

```bash
jps -lmv
```

Meaning:

- `-l`: full main class name or JAR path.
- `-m`: arguments passed to the main method.
- `-v`: arguments passed to the JVM.

Example:

```text
18420 com.example.billing.Main --profile=prod -Dapp.profile=production -Xms256m -Xmx2g
29116 com.example.inventory.Main --port=8080 -Dapp.profile=staging -Xms128m -Xmx1g
```

When investigating an application with multiple instances, this combination helps compare classes, main arguments, and JVM arguments across processes.

You can write the options separately:

```bash
jps -l -m -v
```

or combined:

```bash
jps -lmv
```

Both forms request the corresponding fields. The order of parts in the output still follows the structure generated by JPS; do not assume every space-separated string is a single argument.

## 8. Displaying only PIDs with jps -q

If you only need a list of JVM identifiers to pass to another tool, use `-q`:

```bash
jps -q
```

Output:

```text
18420
29116
32780
```

This option omits the class/JAR name and main arguments, keeping only the local JVM identifiers.

Example using a discovered PID to view more details:

```bash
jcmd 18420 VM.uptime
jcmd 18420 VM.flags
```

In practice, verify that the PID still belongs to the intended application before sending a diagnostic command, because the process may have stopped or the PID may have been reused.

## 9. Java 17 hands-on example: observing main class output

This example creates an application with an explicit package, a main method argument, and some JVM arguments to observe the differences between `jps -l`, `-m`, and `-v`.

Create the directory structure:

```text
project/
  src/
    com/
      example/
        diagnostics/
          MainClassOutput.java
  out/
```

File **`src/com/example/diagnostics/MainClassOutput.java`**:

```java
package com.example.diagnostics;

public final class MainClassOutput {
    private MainClassOutput() {
    }

    public static void main(String[] args) throws InterruptedException {
        System.out.println("PID=" + ProcessHandle.current().pid());
        System.out.println("main args=" + String.join(",", args));

        Thread.sleep(120_000);
    }
}
```

The program prints its PID and main arguments, then sleeps for 120 seconds so the JVM stays alive until we inspect it with JPS.

Compile with Java 17:

```bash
javac --release 17 -d out src/com/example/diagnostics/MainClassOutput.java
```

Launch the application:

```bash
java -Dapp.profile=demo -Xms32m -cp out com.example.diagnostics.MainClassOutput --mode=demo
```

Open a second terminal and run:

```bash
jps -l
```

Sample output:

```text
82192 com.example.diagnostics.MainClassOutput
```

View main method arguments:

```bash
jps -m
```

Sample output:

```text
82192 MainClassOutput --mode=demo
```

View JVM arguments:

```bash
jps -v
```

Sample output:

```text
82192 MainClassOutput -Dapp.profile=demo -Xms32m
```

Combine all:

```bash
jps -lmv
```

Sample output:

```text
82192 com.example.diagnostics.MainClassOutput --mode=demo -Dapp.profile=demo -Xms32m
```

View only the PID:

```bash
jps -q
```

Output contains:

```text
82192
```

The PID `82192` is from a test run; when running on another machine, the PID will differ. The class name and remaining parameters are the values configured in the example.

Stop the program with Ctrl+C in the terminal running `MainClassOutput`.

## 10. Main class output when running via JAR

If the application is launched as:

```bash
java -jar app.jar
```

JPS may display the JAR name instead of the class name:

```text
18420 app.jar
```

Use:

```bash
jps -l
```

to view the full JAR path if the launcher provides that information.

To find the main class inside the JAR, read the manifest:

```bash
jar --list --file app.jar
```

Then extract the manifest into a temporary directory:

```bash
jar --extract --file app.jar META-INF/MANIFEST.MF
```

Open `META-INF/MANIFEST.MF` and look for:

```text
Main-Class: com.example.app.Main
```

The `Main-Class` attribute specifies the class that the Java launcher invokes when running the JAR with `-jar`. JPS displays the JAR launch target, so it does not always show the class name from the manifest directly.

## 11. Main class output when running via module

With JPMS, you can run an application using a module and main class:

```bash
java --module-path mods -m com.example.app/com.example.app.Main
```

When using `jps -l`, the output may display both the module name and class name:

```text
18420 com.example.app/com.example.app.Main
```

Where:

- `com.example.app` before the `/` is the module name.
- `com.example.app.Main` after the `/` is the main class.

The module name and package/class name may match in some projects, but they are two distinct identifiers. The module name is declared in `module-info.java`; the class name belongs to a Java package.

If the module is packaged in a runtime image or launched in a special way, the output format depends on the launcher information that JPS receives.

## 12. Why might jps show Unknown or miss the main class?

JPS relies on launcher information and the instrumented JVM mechanism to determine the class/JAR name and main arguments.

Some cases may not display as expected:

- The JVM was launched through a custom launcher instead of the standard Java launcher.
- The JVM is embedded in a native application via the JNI Invocation API.
- The process was launched by a framework or wrapper that makes main class information unavailable.
- The JVM is outside the scope that the current account has permission to observe.
- The JVM terminated before JPS collected the information.
- Containers or PID namespaces prevent the process from appearing in the scope where JPS is running.

In some cases, the class/JAR name or main arguments may be displayed as `Unknown`, or the main arguments may be `null`.

When you need to identify a process that JPS cannot recognize, inspect it further using OS tools such as Task Manager, `ps`, or `pgrep`, and match the PID against the application's launch configuration.

## 13. Limitations and notes when reading output

JPS only lists instrumented HotSpot JVMs that are accessible under the current account's permissions. It is not a tool for listing all OS processes and does not guarantee that every JVM in containers or under other users will appear.

Some important limitations:

- The LVMID is usually, but not necessarily, the OS PID.
- The default main class name is the short form, which can collide across multiple applications.
- `-m` may not display arguments if the launcher does not provide them.
- `-v` can expose sensitive configuration or data in VM arguments.
- Output separates tokens with whitespace; arguments containing spaces make manual parsing harder.
- Output format may change between JDK versions.

The JDK documentation advises against writing scripts that depend on parsing `jps` output, as the format may change in future releases. If you need stable automation, use an API/management interface or a monitoring mechanism designed for that purpose.

JPS is also described in the JDK 24 documentation as an experimental and unsupported tool. Check the documentation for the exact JDK version you are using and prepare alternatives if the tool is no longer provided in the future.

## 14. Common issues

| Symptom | Common Cause | Resolution |
| --- | --- | --- |
| Full main class not shown | Default command only displays the short name | Use `jps -l` |
| Multiple processes show `Main` | Applications in different packages share the same class name | Use `-l` to view the full package |
| Application arguments missing | Main arguments display is not enabled | Use `jps -m` |
| `-Xmx` or `-D...` not shown | JVM arguments display is not enabled | Use `jps -v` |
| Output shows JAR name instead of class | Application was launched with `java -jar` | Check `Main-Class` in the manifest |
| Output shows `Unknown` | Custom launcher or main class info unavailable | Inspect command line/process metadata with an appropriate tool |
| JVMs of other users not visible | OS permissions restrict visibility | Run under an authorized account or ask an administrator |
| JVMs in containers not visible | JPS is not in the same PID namespace or attach scope | Run the tool inside the container or check the PID from the host |
| Main args incomplete/hard to read | Arguments contain spaces or launcher omits metadata | Check the original launch command and application configuration |
| `jps` command not found | JDK not installed or `bin` directory missing from `PATH` | Check `JAVA_HOME` and `PATH` |

## 15. Workflow for identifying an application with jps

When you need to find the right running Java application:

1. Run `jps -l` to see the PID and full main class/JAR.
2. If multiple processes have the same name, use the package/module or JAR path to distinguish them.
3. Run `jps -m` to view application arguments.
4. Run `jps -v` to view JVM arguments.
5. Use the identified PID to send subsequent commands, such as `jcmd <pid> help`.
6. If the class/JAR displays `Unknown`, inspect the process with OS tools.
7. If the process is not visible, verify the user, access permissions, and PID namespace.
8. Filter sensitive data before sharing the output.

Example command sequence:

```bash
jps -l
jps -lmv
jcmd 18420 help
```

Do not reuse an old PID after an application restarts without re-verifying the process.

## 16. Key Takeaways

- The main class is the class selected by the launcher as the application's starting point; the main method is the entry point method inside that class.
- Default `jps` output consists of the LVMID and the short name of the main class or JAR.
- `jps -l` displays the full package name or JAR path.
- `jps -m` displays the arguments passed to the main method.
- `jps -v` displays JVM arguments such as `-Xmx`, `-Xms`, and `-D...`.
- `jps -lmv` combines class/JAR info, main args, and JVM args.
- `jps -q` displays only the local JVM identifiers.
- A JAR launch may display the JAR name instead of the `Main-Class` in the manifest.
- A module launch may display in `module/class` format.
- JPS may fail to recognize the main class with custom launchers, embedded JVMs, or insufficient permissions.
- Do not write scripts that parse JPS output as a stable format; verify PIDs and protect sensitive information.

Understanding the main class field in `jps` output helps you identify running Java applications, distinguish between multiple instances, determine launch parameters, and move from listing processes to diagnosing the JVM with tools like `jcmd`.
