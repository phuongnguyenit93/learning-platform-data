# PID process với jps

**PID (Process ID)** là mã số hệ điều hành gán cho một tiến trình đang chạy. Khi một ứng dụng Java khởi động bằng JVM, tiến trình JVM thường có một PID riêng. Công cụ **jps** của JDK giúp liệt kê các JVM HotSpot mà tài khoản hiện tại có quyền quan sát và hiển thị định danh JVM cùng tên class hoặc JAR khởi chạy.

PID hữu ích khi cần tìm đúng Java process để xem thông tin JVM, lấy thread dump, kiểm tra heap, điều tra sự cố hoặc dừng service theo quy trình vận hành. Tuy nhiên, PID chỉ là định danh trong một phạm vi hệ điều hành và trong vòng đời của một tiến trình; nó có thể được tái sử dụng sau khi process kết thúc.

Trong JDK 24, tài liệu Oracle đánh dấu jps là công cụ experimental và unsupported. Công cụ phù hợp cho kiểm tra vận hành thủ công, nhưng không nên coi output của nó là giao diện ổn định để xây dựng automation dài hạn.

## 1. Process, PID và JVM

Một **process** là một chương trình đang chạy được hệ điều hành quản lý. Process có không gian địa chỉ, tài nguyên và định danh riêng. PID là số do hệ điều hành gán cho process.

Khi chạy một ứng dụng Java thông thường, hệ điều hành nhìn thấy một process JVM. Bên trong process đó có thể có nhiều Java thread, class loader, heap, metaspace, compiler thread, garbage collector thread và các thành phần runtime khác.

Ví dụ:

~~~text
Operating System
│
├── PID 1200: java -jar api-server.jar
│   ├── Main thread
│   ├── HTTP worker threads
│   ├── GC threads
│   └── JIT compiler threads
│
├── PID 1250: java -jar batch-worker.jar
│   ├── Main thread
│   └── Worker threads
│
└── PID 1300: java -jar report-service.jar
    ├── Main thread
    └── Scheduler threads
~~~

Trong ví dụ này có ba JVM process, mỗi process có PID riêng. Một JVM có thể chứa hàng trăm hoặc hàng nghìn thread nhưng vẫn chỉ là một process ở cấp hệ điều hành.

### PID khác Thread ID

- **PID** nhận diện process ở cấp hệ điều hành.
- **Java thread ID** nhận diện thread trong JVM.
- **OS thread ID** nhận diện native thread do hệ điều hành quản lý.
- **Parent PID (PPID)** là PID của process cha đã tạo process hiện tại.

jps liệt kê JVM process; nó không liệt kê từng Java thread. Muốn xem thread đang chạy trong một JVM, dùng các công cụ như jcmd với lệnh Thread.print hoặc jstack.

### PID có phải định danh vĩnh viễn không?

Không. PID chỉ có ý nghĩa trong phạm vi hệ điều hành và thời gian process tồn tại. Khi process kết thúc, hệ điều hành có thể tái sử dụng PID đó cho một process khác.

Vì vậy, không lưu PID vào cấu hình như một định danh service cố định. Khi cần thao tác, hãy xác minh lại tên process, user, thời điểm khởi chạy và command line trước khi gửi lệnh chẩn đoán hoặc dừng process.

## 2. jps là gì?

jps là công cụ dòng lệnh đi kèm JDK, dùng để liệt kê các **instrumented Java HotSpot Virtual Machines** trên hệ thống đích.

Cú pháp tổng quát trong JDK 24:

~~~bash
jps [-q] [-mlvV] [hostid]
jps --help
~~~

Nếu không truyền hostid, jps tìm JVM trên máy cục bộ. Nếu truyền hostid, công cụ truy vấn JVM trên host được chỉ định theo giao thức và cổng tương ứng.

jps hiển thị local VM identifier (LVMID) cho mỗi JVM tìm thấy. LVMID thường là PID của process JVM ở máy cục bộ, nhưng tài liệu JDK nêu rõ nó không nhất thiết luôn trùng với PID hệ điều hành.

Mặc định, output có dạng:

~~~text
lvmid  short-class-name-or-jar
~~~

Ví dụ minh họa:

~~~text
31840 com.example.ApiServer
31912 Jps
32004 com.example.BatchWorker
~~~

- 31840 là LVMID của JVM chạy class com.example.ApiServer.
- 31912 là process jps đang chạy tại thời điểm liệt kê.
- 32004 là LVMID của JVM chạy class com.example.BatchWorker.

Các số trên chỉ minh họa. PID thực tế thay đổi theo hệ điều hành, lần khởi chạy và môi trường.

### jps không phải công cụ liệt kê mọi process

jps chỉ liệt kê JVM HotSpot được nhận diện và nằm trong phạm vi quyền truy cập của tài khoản hiện tại. Nó không thay thế ps, tasklist hoặc trình quản lý process của hệ điều hành.

Một số trường hợp có thể không xuất hiện hoặc không hiển thị đủ thông tin:

- JVM chạy dưới tài khoản khác mà người dùng hiện tại không có quyền quan sát.
- JVM chạy trong container hoặc process namespace khác.
- JVM được khởi chạy bằng custom launcher khiến tên class/JAR không xác định được.
- Process kết thúc trong lúc jps đang thu thập thông tin.
- JVM hoặc nền tảng không hỗ trợ cơ chế liệt kê mà jps sử dụng.

Nếu công cụ không nhận diện được launcher, tên class hoặc JAR có thể hiển thị là Unknown. Trong một số tình huống, output có thể báo process information unavailable.

## 3. Các tùy chọn của jps

JDK 24 hỗ trợ các tùy chọn sau.

| Tùy chọn | Ý nghĩa |
|---|---|
| -q | Chỉ hiển thị local VM identifier, không hiển thị class/JAR hoặc arguments |
| -m | Hiển thị arguments truyền cho phương thức main |
| -l | Hiển thị tên đầy đủ của main class hoặc đường dẫn đầy đủ của JAR |
| -v | Hiển thị arguments truyền cho JVM |
| -V | Chỉ hiển thị local VM identifier, tương tự chế độ rút gọn |
| --help | Hiển thị hướng dẫn sử dụng |

Có thể kết hợp các tùy chọn -m, -l và -v để xem nhiều thông tin hơn. Không nên bật các tùy chọn hiển thị command line nếu output có thể chứa bí mật.

### -q: chỉ lấy PID/LVMID

~~~bash
jps -q
~~~

Ví dụ output:

~~~text
31840
31912
32004
~~~

Dùng -q khi chỉ cần danh sách định danh để tra cứu tiếp. Tên class/JAR và arguments không được hiển thị.

### -l: tên class hoặc đường dẫn JAR đầy đủ

~~~bash
jps -l
~~~

Ví dụ output:

~~~text
31840 com.example.server.ApiServer
31912 jdk.jcmd/sun.tools.jps.Jps
32004 /opt/apps/batch-worker.jar
~~~

Tùy cách khởi chạy, jps hiển thị tên đầy đủ của main class hoặc đường dẫn JAR. Tùy chọn này hữu ích khi nhiều ứng dụng có tên class ngắn giống nhau.

### -m: arguments của main method

~~~bash
jps -m
~~~

Ví dụ ứng dụng được chạy bằng:

~~~bash
java com.example.BatchWorker nightly region-west
~~~

Output minh họa:

~~~text
32004 com.example.BatchWorker nightly region-west
~~~

Các giá trị sau tên class/JAR là arguments truyền vào main(String[] args). Với embedded JVM, phần này có thể không có giá trị.

### -v: JVM arguments

~~~bash
jps -v
~~~

Ví dụ:

~~~text
31840 com.example.server.ApiServer -Xms512m -Xmx2g -Dapp.profile=production
~~~

Các giá trị sau tên class/JAR là arguments được truyền cho JVM, ví dụ -Xms, -Xmx, -Dsystem.property hoặc các JVM flags khác.

**Cảnh báo bảo mật:** JVM arguments có thể chứa password, token, connection string hoặc thông tin nhạy cảm nếu ứng dụng được cấu hình không an toàn. Không đăng toàn bộ output -v vào ticket, log tập trung hoặc kênh chat. Hãy dùng -q nếu chỉ cần PID và che thông tin bí mật trước khi chia sẻ diagnostic output.

### -V: chỉ hiển thị định danh

Trong tài liệu Oracle JDK 24, -V cũng được mô tả là chỉ hiển thị local VM identifiers, tương tự output rút gọn. Không nhầm mô tả này với các tài liệu cũ của một số phiên bản JDK từng mô tả khác về tùy chọn -V. Hãy kiểm tra jps --help và tài liệu đúng phiên bản JDK đang sử dụng.

### Kết hợp tùy chọn

~~~bash
jps -lm
~~~

Lệnh trên hiển thị LVMID, tên đầy đủ class/JAR và arguments của main method.

~~~bash
jps -lv
~~~

Lệnh trên hiển thị tên đầy đủ class/JAR và JVM arguments.

~~~bash
jps -mlv
~~~

Lệnh trên hiển thị tên đầy đủ class/JAR, main arguments và JVM arguments. Output có thể dài và có nguy cơ lộ thông tin nhạy cảm.

## 4. Quy trình tìm PID của ứng dụng Java

Một quy trình thủ công thường dùng:

1. Chạy jps để liệt kê JVM.
2. Dùng -l để phân biệt class/JAR khi có nhiều ứng dụng.
3. Ghi lại LVMID của JVM cần điều tra.
4. Xác minh PID bằng công cụ hệ điều hành.
5. Dùng jcmd với PID đã xác nhận để xem thông tin JVM.
6. Chỉ thực hiện thao tác ảnh hưởng process sau khi xác minh đúng service và được phép.

Ví dụ:

~~~bash
jps -l
~~~

Output minh họa:

~~~text
31840 com.example.ApiServer
32004 com.example.BatchWorker
~~~

Giả sử cần kiểm tra ApiServer, lấy LVMID 31840 rồi xác minh process.

### Linux hoặc macOS

~~~bash
ps -p 31840 -o pid,ppid,user,etime,args
~~~

Các cột:

- pid: process ID.
- ppid: process cha.
- user: tài khoản sở hữu process.
- etime: thời gian process đã chạy.
- args: command line.

### Windows PowerShell

~~~powershell
Get-Process -Id 31840 |
    Select-Object Id, ProcessName, StartTime
~~~

Nếu cần thông tin command line và parent PID:

~~~powershell
Get-CimInstance Win32_Process -Filter "ProcessId = 31840" |
    Select-Object ProcessId, ParentProcessId, Name, CommandLine
~~~

Command line có thể chứa secret. Chỉ xem hoặc lưu các trường cần thiết, và redaction trước khi chia sẻ.

### Vì sao cần xác minh lại PID?

jps và công cụ OS thu thập thông tin tại những thời điểm khác nhau. Process có thể kết thúc giữa hai lệnh, hoặc hệ điều hành có thể tái sử dụng PID.

Trước khi gửi lệnh đến PID, hãy xác nhận:

- Process vẫn tồn tại.
- Tên executable hoặc main class đúng.
- User sở hữu process đúng.
- Command line và thư mục triển khai đúng.
- Thời điểm khởi chạy phù hợp.
- Process thuộc đúng máy hoặc container.

Không dùng một PID cũ được lưu từ lần kiểm tra trước để dừng hoặc thay đổi process mà không xác minh lại.

## 5. Dùng jcmd sau khi tìm được PID

jps trả lời câu hỏi JVM nào đang chạy. jcmd gửi diagnostic command đến một JVM cụ thể để lấy thông tin sâu hơn.

Liệt kê JVM mà jcmd có thể nhìn thấy:

~~~bash
jcmd -l
~~~

Xem version của JVM:

~~~bash
jcmd 31840 VM.version
~~~

Xem command line dùng để khởi chạy JVM:

~~~bash
jcmd 31840 VM.command_line
~~~

Xem JVM flags hiện tại:

~~~bash
jcmd 31840 VM.flags
~~~

Liệt kê các diagnostic command được JVM hỗ trợ:

~~~bash
jcmd 31840 help
~~~

Xem thread dump:

~~~bash
jcmd 31840 Thread.print
~~~

Lệnh Thread.print giúp điều tra thread đang chạy hoặc bị block. Nó không làm thay đổi PID; nó thu thập trạng thái thread trong JVM.

jcmd phải chạy trên cùng máy với JVM mục tiêu và thông thường cần cùng effective user/group ID đã khởi chạy JVM. Quyền truy cập phụ thuộc hệ điều hành và cấu hình runtime.

### jps, jcmd và ps khác nhau thế nào?

| Công cụ | Phạm vi | Mục đích |
|---|---|---|
| jps | JVM HotSpot có thể quan sát | Liệt kê JVM và LVMID |
| jcmd -l | JVM có thể attach, ngoài một số process/container riêng | Liệt kê JVM để chẩn đoán |
| jcmd PID command | Một JVM cụ thể | Gửi diagnostic command |
| ps / tasklist | Process hệ điều hành | Liệt kê và xác minh process |
| ProcessHandle | API Java | Lấy PID và thông tin process từ chương trình Java |

jcmd có nhiều lệnh với mức tác động khác nhau. Bắt đầu bằng các lệnh chỉ đọc như VM.version, VM.command_line, VM.flags và help. Các lệnh như GC.heap_dump, GC.run hoặc thao tác thay đổi logging có thể tạo tải, ghi file lớn hoặc ảnh hưởng hoạt động; hãy đọc help của command và đánh giá tác động trước khi chạy trên production.

## 6. PID trong container và môi trường nhiều namespace

Trong môi trường container, PID có thể khác nhau giữa host và container do PID namespace.

Ví dụ:

~~~text
Host PID namespace
└── Container process: host PID 42000
    └── Container PID namespace
        └── Java process: container PID 1
~~~

Bên trong container, Java process có thể mang PID 1. Trên host, cùng process đó có thể có PID 42000. Hai số này không mâu thuẫn; chúng được quan sát từ hai namespace khác nhau.

Tài liệu jcmd JDK 24 ghi rõ jcmd -l không liệt kê JVM chạy trong một Docker process riêng. Khi JVM chạy trong container, có thể cần dùng công cụ container hoặc hệ điều hành để tìm PID.

Ví dụ:

~~~bash
docker top my-java-container
~~~

Hoặc vào container để xem process:

~~~bash
docker exec my-java-container ps -ef
~~~

Nếu image không có ps, có thể dùng công cụ quản lý container hoặc kiểm tra /proc trong đúng PID namespace.

Khi thao tác với process trong Kubernetes, cần phân biệt PID trong container với PID trên node. Thực hiện diagnostic trong đúng pod/container và dùng công cụ quản trị cluster để xác định node, container và service tương ứng.

Không gửi kill hoặc jcmd đến một PID chỉ vì số đó giống PID quan sát ở host khác. Luôn xác minh đúng namespace và process.

## 7. Tìm JVM trên host từ xa

jps hỗ trợ host identifier (hostid) để truy vấn JVM trên host khác.

Cú pháp hostid theo tài liệu JDK:

~~~text
[protocol:][[//]hostname][:port][/servername]
~~~

Nếu chỉ truyền hostname, giao thức mặc định là RMI. jps giả định trên host đích có tiến trình jstatd đang chạy. Nếu không chỉ định port cho RMI, registry mặc định là 1099.

Ví dụ:

~~~bash
jps -l app-host.example:1099
~~~

Ví dụ này cần jstatd và RMI registry phù hợp trên máy đích, cùng quyền truy cập mạng và cấu hình bảo mật tương ứng. Đây không phải cách truy vấn mọi JVM từ xa mà không cần chuẩn bị.

### Lưu ý khi dùng jstatd

jstatd cung cấp dịch vụ giám sát JVM qua RMI. Việc mở RMI hoặc jstatd ra mạng có thể tạo bề mặt quản trị từ xa. Chỉ bật trong môi trường được phê duyệt, giới hạn network access, xác thực và cấu hình bảo mật theo tài liệu JDK.

LVMID nhận được từ host từ xa là định danh trong môi trường đích. Không dùng số đó với lệnh kill hoặc taskkill trên máy local.

Với hệ thống production, thường nên ưu tiên agent/monitoring đã được tổ chức phê duyệt, JMX được bảo vệ hoặc công cụ quản trị hạ tầng thay vì tự mở dịch vụ RMI chỉ để xem PID.

## 8. Lấy PID ngay trong chương trình Java bằng ProcessHandle

Từ Java 9, API ProcessHandle cung cấp cách lấy PID của process hiện tại và truy cập thông tin process ở cấp hệ điều hành.

Ví dụ Java 17+:

~~~java
public final class PidDemo {
    public static void main(String[] args) {
        long pid = ProcessHandle.current().pid();
        System.out.println("PID=" + pid);
    }
}
~~~

Lưu thành PidDemo.java.

Biên dịch:

~~~bash
javac --release 17 PidDemo.java
~~~

Chạy:

~~~bash
java PidDemo
~~~

Output có dạng:

~~~text
PID=31840
~~~

Số PID thay đổi theo process thực tế và có thể khác mỗi lần chạy. Trong ví dụ, 31840 chỉ là số minh họa.

### Lấy thông tin một process theo PID

ProcessHandle.of(long pid) trả về Optional<ProcessHandle>. Nếu process không tồn tại hoặc không thể được truy cập, Optional có thể rỗng.

Ví dụ:

~~~java
import java.util.Optional;

public final class ProcessLookup {
    public static void main(String[] args) {
        if (args.length != 1) {
            System.err.println("Usage: java ProcessLookup <pid>");
            System.exit(2);
        }

        long pid = Long.parseLong(args[0]);
        Optional<ProcessHandle> result = ProcessHandle.of(pid);

        if (result.isEmpty()) {
            System.out.println("Process not found: " + pid);
            return;
        }

        ProcessHandle process = result.get();
        ProcessHandle.Info info = process.info();

        System.out.println("PID=" + process.pid());
        System.out.println("Alive=" + process.isAlive());
        System.out.println("Command=" +
                info.command().orElse("unavailable"));
        System.out.println("Start=" +
                info.startInstant().map(Object::toString)
                        .orElse("unavailable"));
    }
}
~~~

Biên dịch:

~~~bash
javac --release 17 ProcessLookup.java
~~~

Chạy với PID đang tồn tại:

~~~bash
java ProcessLookup 31840
~~~

Output minh họa:

~~~text
PID=31840
Alive=true
Command=/path/to/java
Start=2026-11-10T10:00:00Z
~~~

Các giá trị Command và Start phụ thuộc hệ điều hành và quyền truy cập. Có thể không lấy được command hoặc thời điểm khởi chạy trong một số môi trường.

### Liệt kê process mà chương trình có thể nhìn thấy

ProcessHandle.allProcesses() trả về snapshot các process nhìn thấy được từ process hiện tại:

~~~java
ProcessHandle.allProcesses()
        .filter(process -> process.info().command()
                .map(command -> command.toLowerCase().contains("java"))
                .orElse(false))
        .forEach(process -> System.out.printf(
                "PID=%d COMMAND=%s%n",
                process.pid(),
                process.info().command().orElse("unavailable")
        ));
~~~

Đây là đoạn code minh họa cách lọc process; output phụ thuộc hệ điều hành và quyền truy cập. allProcesses() không đảm bảo mọi process còn sống tại thời điểm sử dụng, vì process có thể được tạo hoặc kết thúc bất đồng bộ.

### ProcessHandle không phải bản sao của jps

- ProcessHandle là API Java để nhận diện và tương tác với native process.
- jps là công cụ JDK chuyên liệt kê instrumented HotSpot JVM.
- ProcessHandle.allProcesses() có thể nhìn thấy cả process không phải Java nếu OS cho phép.
- jps có thể cung cấp tên main class/JAR theo cách phù hợp cho JVM.
- Cả hai đều bị giới hạn bởi quyền hệ điều hành và phạm vi process namespace.

Nếu chương trình chỉ cần PID của chính nó, dùng ProcessHandle.current().pid() là cách trực tiếp. Nếu cần quản trị process bên ngoài, hãy cân nhắc API hệ điều hành hoặc công cụ vận hành phù hợp.

## 9. Xử lý tình huống không tìm thấy PID hoặc JVM

### jps không hiển thị ứng dụng

Kiểm tra:

1. Ứng dụng còn chạy hay đã thoát.
2. Dùng đúng JDK và đúng host.
3. Tài khoản chạy jps có quyền quan sát JVM.
4. JVM có nằm trong container hoặc PID namespace khác không.
5. JVM có được khởi chạy bằng custom launcher không.
6. Công cụ có hỗ trợ loại JVM/runtime đang dùng không.
7. Thử công cụ hệ điều hành như ps, tasklist hoặc Get-Process.

### Tên class hiển thị là Unknown

jps lấy thông tin class/JAR từ cơ chế launcher. Nếu JVM khởi chạy bằng custom launcher hoặc thông tin không được cung cấp, jps có thể không xác định được tên class/JAR và arguments.

Khi đó, dùng OS process inspection hoặc jcmd nếu PID và quyền attach có sẵn.

### Process information unavailable

Thông báo có thể xuất hiện khi process kết thúc trong lúc thu thập hoặc quyền truy cập không đủ. Kiểm tra lại bằng OS tool, rồi chạy jps/jcmd một lần nữa khi process ổn định.

### jcmd báo không thể attach

Nguyên nhân thường gặp:

- jcmd không chạy trên cùng host.
- User/group không khớp với tài khoản khởi chạy JVM.
- PID không còn tồn tại hoặc đã được tái sử dụng.
- JVM nằm trong container/namespace khác.
- JVM không hỗ trợ Attach API hoặc attach bị vô hiệu hóa.
- Runtime và toolchain không tương thích.
- Chính sách hệ điều hành ngăn attach.

Không chạy công cụ bằng quyền cao hơn một cách tùy tiện để vượt qua lỗi. Xác nhận owner, môi trường và quy trình truy cập được phép trước.

### PID tồn tại nhưng đó là process khác

PID có thể được tái sử dụng. Nếu process Java ban đầu kết thúc, số PID cũ có thể thuộc về process mới. Xác minh process name, command line, user và start time trước mọi thao tác ảnh hưởng process.

## 10. Dùng PID để chẩn đoán an toàn

Sau khi xác định đúng JVM, dùng công cụ theo mức độ tác động tăng dần.

| Mục tiêu | Lệnh gợi ý | Tác động |
|---|---|---|
| Liệt kê JVM | jps -l | Chỉ đọc |
| Xem version | jcmd PID VM.version | Chỉ đọc |
| Xem flags | jcmd PID VM.flags | Chỉ đọc |
| Xem command line | jcmd PID VM.command_line | Chỉ đọc, có thể lộ secret |
| Xem thread | jcmd PID Thread.print | Thu thập diagnostic, có thể tạo tải |
| Xem heap | jcmd PID GC.heap_info | Thu thập diagnostic |
| Tạo heap dump | jcmd PID GC.heap_dump file.hprof | Tác động cao, ghi file lớn và có thể chứa dữ liệu nhạy cảm |
| Dừng process | Service manager hoặc OS process tool | Thay đổi trạng thái service |

Thay PID bằng số thực tế đã xác minh. Với command có tác động cao, đọc help trước và thực hiện theo runbook của service.

### Không dừng process chỉ dựa vào một con số

Trước khi dừng JVM:

1. Xác nhận đúng service và môi trường.
2. Xác nhận process owner và command line.
3. Kiểm tra có traffic, job hoặc transaction đang chạy không.
4. Ưu tiên graceful shutdown qua service manager, application endpoint hoặc orchestration platform.
5. Chỉ dùng OS termination theo quy trình khi graceful shutdown không khả thi.
6. Xác nhận service đã dừng và health check sau khi khởi động lại.

PID không cho biết process có quan trọng hay không. Việc dừng nhầm PID có thể làm gián đoạn service hoặc gây mất dữ liệu đang xử lý.

## 11. Bảo mật khi xem PID và command line

Thông tin process có thể tiết lộ cấu trúc nội bộ và dữ liệu nhạy cảm.

- jps -v có thể hiển thị system properties và JVM arguments.
- jps -m có thể hiển thị arguments chứa dữ liệu người dùng hoặc token.
- jps -l có thể tiết lộ tên package và đường dẫn cài đặt.
- jcmd VM.command_line có thể hiển thị toàn bộ command line.
- ProcessHandle.Info.commandLine() cũng có thể chứa thông tin nhạy cảm tùy ứng dụng.

Không truyền secret trực tiếp qua JVM arguments hoặc command line nếu có lựa chọn quản lý secret an toàn hơn. Khi audit, chỉ thu thập trường cần thiết, redaction trước khi lưu và giới hạn quyền truy cập vào log.

jps và jcmd cũng có thể giúp người vận hành quan sát process. Chỉ cấp quyền attach và diagnostic command cho tài khoản đáng tin cậy. Không mở jstatd/RMI hoặc management endpoint ra mạng công khai chỉ để tiện tra cứu PID.

## 12. jps có phù hợp cho script tự động không?

Oracle JDK 24 đánh dấu jps là experimental và unsupported. Tài liệu cũng cảnh báo output format có thể thay đổi và không khuyến nghị viết script parse output của jps.

Output được phân tách bằng whitespace; arguments có thể chứa khoảng trắng nên việc ánh xạ token về đúng tham số có thể mơ hồ.

Nếu cần automation:

- Dùng ProcessHandle API khi logic nằm trong chương trình Java.
- Dùng process API của hệ điều hành hoặc orchestration platform khi quản lý service.
- Dùng JMX/monitoring agent được phê duyệt khi cần quan sát JVM dài hạn.
- Dùng jcmd cho diagnostic command có kiểm soát.
- Không giả định PID là định danh cố định qua nhiều lần khởi chạy.
- Không parse output jps bằng cách tách chuỗi đơn giản rồi dùng kết quả để kill process.

### Lựa chọn công cụ theo nhu cầu

| Nhu cầu | Công cụ phù hợp |
|---|---|
| Tìm nhanh JVM trên máy local | jps |
| Chỉ cần danh sách LVMID | jps -q |
| Xem main class/JAR | jps -l |
| Xem JVM startup flags | jps -v hoặc jcmd PID VM.flags |
| Xem process OS đầy đủ | ps, tasklist, Get-Process, ProcessHandle |
| Chẩn đoán một JVM | jcmd PID command |
| Xem Java thread | jcmd PID Thread.print |
| Giám sát liên tục | JMX/agent/monitoring platform |
| Quản lý container process | Docker/Kubernetes và OS tools |

## 13. Checklist tìm và xác minh PID

- Xác định đúng host, container và PID namespace.
- Chạy jps trên đúng JDK/runtime environment.
- Dùng jps -l nếu cần phân biệt class/JAR.
- Dùng jps -q nếu chỉ cần danh sách LVMID.
- Hạn chế -m và -v vì có thể lộ command-line arguments.
- Ghi nhận LVMID và xác minh lại bằng OS process tool.
- Xác nhận process name, user, command line và start time.
- Nhớ rằng LVMID thường nhưng không nhất thiết là OS PID.
- Không coi PID là định danh vĩnh viễn; hệ điều hành có thể tái sử dụng PID.
- Dùng jcmd trên cùng host và với quyền phù hợp.
- Đọc help trước khi chạy diagnostic command có tác động cao.
- Dùng service manager hoặc orchestration platform để dừng service theo quy trình.
- Không parse jps output làm giao diện automation ổn định.
- Với container, tìm PID trong đúng namespace.
- Redact command line và diagnostic output trước khi chia sẻ.
- Lưu bằng chứng cùng thời điểm, host, runtime version và service identity.

## 14. Thuật ngữ cần nhớ

| Thuật ngữ | Ý nghĩa |
|---|---|
| Process | Một chương trình đang chạy do hệ điều hành quản lý |
| PID | Process ID do hệ điều hành gán |
| PPID | PID của process cha |
| LVMID | Local VM identifier do công cụ JVM hiển thị |
| JVM process | Process đang chạy một Java Virtual Machine |
| Java thread | Luồng thực thi bên trong JVM |
| OS thread ID | Định danh thread ở cấp hệ điều hành |
| jps | Công cụ JDK liệt kê instrumented HotSpot JVM |
| jcmd | Công cụ gửi diagnostic command đến JVM |
| jstatd | Dịch vụ cho phép công cụ jstat/jps truy cập thông tin JVM từ xa qua RMI |
| ProcessHandle | API Java nhận diện và tương tác với native process |
| PID namespace | Cơ chế cô lập không gian PID, thường gặp trong container |
| PID reuse | Hệ điều hành tái sử dụng PID sau khi process cũ kết thúc |
| Attach API | Cơ chế cho phép công cụ attach vào JVM đang chạy |
| Diagnostic command | Lệnh thu thập hoặc tác động đến trạng thái JVM |

jps là bước nhanh để tìm JVM và LVMID trên máy local. Hãy dùng PID như một định danh tạm thời, xác minh lại bằng công cụ hệ điều hành, rồi dùng jcmd hoặc ProcessHandle để lấy thông tin cần thiết. Trong container, môi trường từ xa và production, luôn xác định đúng host/namespace, quyền truy cập và mức độ tác động trước khi thao tác với process.
