# Packaging Icons with the jpackage Tool

## 1. What Is a Package Icon?

In the Java application packaging workflow, a package icon is the identifying icon attached to the application image, launcher, and installer package generated by `jpackage`. The icon helps users recognize the application in File Explorer, Finder, the application menu, desktop shortcuts, or the list of installed applications.

`jpackage` is the application packaging tool included with the JDK. The tool can create an application image containing the launcher and required runtime, or build an installer in the operating system's native format. The primary option for specifying an icon is `--icon`:

~~~bash
jpackage --type app-image --name IconDemo --icon path/to/icon-file
~~~

The icon path can be absolute or relative to the current working directory of the process running `jpackage`. When the path contains spaces, enclose the entire path in quotes.

It is important to distinguish between three types of icons:

- **Application/package icon:** the application icon configured during packaging via `--icon`.
- **Per-launcher icon:** each additional launcher can have its own icon via the `--add-launcher` configuration.
- **Application window icon:** set by Java UI code at runtime, such as a JavaFX `Stage`. The `--icon` option does not automatically replace the icon inside windows created by the application.

## 2. Icon Formats by Operating System

`jpackage` requires an icon file in the exact format of the target operating system. Do not simply rename a PNG image extension to ICO or ICNS; the file contents must actually be in the proper format.

| Operating System | Icon Format | Notes |
|---|---|---|
| Windows | `.ico` | Used for the launcher and package. It is best to create a multi-size ICO so Windows can pick the appropriate version. |
| macOS | `.icns` | Used for the application bundle and launcher icon on macOS. |
| Linux | `.png` | The icon is used in desktop integration; the desktop file may reference the icon. |

On Linux, the icon is typically referenced by a `.desktop` file rather than embedded into a native launcher as on Windows. Therefore, when verifying, check the application image, the desktop entry, and the icon path.

These formats apply to both the main icon and custom icons for additional launchers. Files used for file associations must also be in the format appropriate for the operating system.

## 3. Preparing Artwork Before Packaging

You should prepare a source design that can be exported to each platform format. A good icon needs to remain clear at small sizes, have sufficient contrast, and avoid relying on overly fine details.

Recommendations:

- Design with a square layout, placing the main shape within a safe zone to avoid clipping when the operating system applies masks or display effects.
- Use a transparent background if the artwork needs to blend into the desktop or dock.
- Create a multi-size ICO, such as 16, 32, 48, 64, 128, and 256 pixels, so Windows has suitable options.
- For ICNS, provide the necessary representations for macOS displays with different pixel densities.
- For PNG on Linux, export at high resolution, typically 256 or 512 pixels, so the desktop environment can scale it down.
- Test the icon on both light and dark backgrounds, in the taskbar/dock, and at small sizes.
- Keep icon files in an assets directory with clear platform-based naming.

Example structure:

~~~text
project/
├── src/
│   └── com/example/IconDemo.java
├── assets/
│   ├── windows/
│   │   └── icon-demo.ico
│   ├── macos/
│   │   └── icon-demo.icns
│   └── linux/
│       └── icon-demo.png
├── classes/
├── input/
└── dist/
~~~

You can use the same source artwork for all platforms, but it must be exported separately as ICO, ICNS, and PNG. Do not just rename the file extension.

## 4. Preparing a Sample Java Application

Create the file `src/com/example/IconDemo.java`:

~~~java
package com.example;

public class IconDemo {
    public static void main(String[] args) {
        System.out.println("Icon package ready");
    }
}
~~~

Compile with JDK 17 or later:

~~~bash
mkdir -p classes input dist
javac --release 17 -d classes src/com/example/IconDemo.java
~~~

Package the class into a JAR:

~~~bash
jar --create --file input/icon-demo.jar --main-class com.example.IconDemo -C classes .
~~~

The `input` directory contains the application's main JAR. `jpackage` uses `--input` to gather the files to package; `--main-jar` specifies the main JAR, and `--main-class` specifies the class with the `main` method.

Inspect the JAR before packaging:

~~~bash
jar --list --file input/icon-demo.jar
~~~

The output should contain the entries:

~~~text
META-INF/MANIFEST.MF
com/example/IconDemo.class
~~~

## 5. Attaching the Main Icon with `--icon`

### Windows

Use an ICO file:

~~~powershell
jpackage --type app-image --input input --name IconDemo --main-jar icon-demo.jar --main-class com.example.IconDemo --icon assets/windows/icon-demo.ico --win-console --dest dist --verbose
~~~

After creating the application image, the launcher is located in the output directory:

~~~powershell
.\dist\IconDemo\IconDemo.exe
~~~

Stdout:

~~~text
Icon package ready
~~~

`--win-console` creates a console launcher for applications that need terminal interaction or write to stdout/stderr. For desktop applications that do not need a console, this option can be omitted.

### macOS

Use an ICNS file:

~~~bash
jpackage --type app-image --input input --name IconDemo --main-jar icon-demo.jar --main-class com.example.IconDemo --icon assets/macos/icon-demo.icns --dest dist --verbose
~~~

The application image on macOS is typically an `IconDemo.app` bundle. Check the bundle's icon in Finder or the Dock after creation.

### Linux

Use a PNG file:

~~~bash
jpackage --type app-image --input input --name IconDemo --main-jar icon-demo.jar --main-class com.example.IconDemo --icon assets/linux/icon-demo.png --dest dist --verbose
~~~

The Linux application image contains the launcher and desktop resources. When verifying the icon, confirm that the PNG path used by the desktop entry exists in the application image or the corresponding installation location.

The commands above must be run on each target operating system. `jpackage` does not support creating native packages for another operating system from an arbitrary host.

## 6. Packaging a Modular Application

For JPMS applications, you can specify the module path and main module. `--module` replaces the `--main-jar`/`--main-class` pair.

Example:

~~~bash
jpackage --type app-image --name ModularIconDemo --module-path mods --module com.example.app/com.example.app.Main --icon assets/linux/modular-icon.png --dest dist
~~~

Replace the icon path with an ICO on Windows or an ICNS on macOS when building on those operating systems.

Do not pass `--module` and `--main-jar` at the same time. Choose the right mode based on how the application is compiled and packaged.

## 7. Custom Icons for Additional Launchers

An application can provide multiple launchers with different arguments or purposes. The `--add-launcher` option takes a launcher name and a properties file. In the properties file, the `icon` key specifies a dedicated icon for that launcher.

Example `admin-launcher.properties` file on Windows:

~~~properties
icon=C:/project/assets/windows/admin.ico
arguments=--mode=admin
~~~

Create an application image with the main launcher and an additional launcher:

~~~powershell
jpackage --type app-image --input input --name IconDemo --main-jar icon-demo.jar --main-class com.example.IconDemo --icon assets/windows/icon-demo.ico --add-launcher Admin=admin-launcher.properties --win-console --dest dist --verbose
~~~

The result includes the main launcher `IconDemo.exe` and the additional launcher `Admin.exe`. The additional launcher uses the icon declared in `admin-launcher.properties`.

On macOS, the `icon` value points to an `.icns` file; on Linux, it points to a `.png`. If no custom icon is specified for an additional launcher, the launcher may use the platform's default icon.

You can use the same launcher properties file to configure `main-class`, `main-jar` or `module`, `description`, `arguments`, `java-options`, and other supported launcher options.

## 8. Icons for File Associations

The application icon and the icon for file types opened by the application are two separate configuration items. If you want the operating system to display a dedicated icon for a file extension that your application registers to handle, use `--file-associations` with a properties file.

Example `demo-association.properties`:

~~~properties
extension=demo
mime-type=application/x-demo
description=Demo document
icon=assets/windows/demo-file.ico
~~~

The file association icon path must reside inside the application's input directory when packaging. For example, you can place the file as follows:

~~~text
input/
├── icon-demo.jar
└── assets/
    └── windows/
        └── demo-file.ico
~~~

Then create the installer:

~~~powershell
jpackage --type exe --input input --name IconDemo --main-jar icon-demo.jar --main-class com.example.IconDemo --icon assets/windows/icon-demo.ico --file-associations demo-association.properties --dest dist
~~~

In the file association properties file, the commonly used keys are:

- `extension`: the file extension, e.g., `demo`.
- `mime-type`: the MIME type, e.g., `application/x-demo`.
- `description`: a short description of the file type.
- `icon`: the icon dedicated to files belonging to that association.

Each association can use its own properties file and be passed with a `--file-associations` option. If no custom icon is declared, the operating system may fall back to the application's default icon. The icon format must match the platform: ICO, ICNS, or PNG.

## 9. Customizing Icons via `--resource-dir`

`--resource-dir` allows overriding the default resources and templates that `jpackage` uses when creating an application image or installer. For launcher icons, the filename in the resource directory depends on the operating system and the launcher name.

Examples:

| Operating System | Icon File in Resource Directory |
|---|---|
| Windows | `IconDemo.ico` |
| macOS | `IconDemo.icns` |
| Linux | `IconDemo.png` |

The filename must match the corresponding application or launcher name. For an additional launcher named `Admin`, you can provide `Admin.ico`, `Admin.icns`, or `Admin.png` depending on the platform.

Example:

~~~text
resource-dir/
├── IconDemo.ico
├── Admin.ico
└── IconDemo.properties
~~~

Invoke `jpackage`:

~~~powershell
jpackage --type app-image --input input --name IconDemo --main-jar icon-demo.jar --main-class com.example.IconDemo --resource-dir resource-dir --dest dist --verbose
~~~

If a dedicated command-line option like `--icon` is available, prefer using that option. `--resource-dir` is useful when you need to replace templates or other resources that do not have dedicated command-line options. Use `--verbose` to see which resources `jpackage` selected.

## 10. Application Image and Installer

Icons are processed during application image creation. You can start with `--type app-image` to verify the launcher, runtime, and icon before building an installer.

Common package formats by platform:

| Platform | Application Image | Installer |
|---|---|---|
| Windows | `app-image` | `exe`, `msi` |
| macOS | `app-image` | `pkg`, `dmg` |
| Linux | `app-image` | `deb`, `rpm` |

Supported package types depend on the operating system and JDK build. Build installers on the target operating system; `jpackage` does not cross-package between Windows, macOS, and Linux.

Recommended workflow:

1. Compile the application and prepare the input directory.
2. Choose an icon in the correct platform format.
3. Create the application image with `--type app-image` and `--icon`.
4. Open/run the launcher and verify the icon in the desktop environment.
5. Create the installer using the appropriate platform format.
6. Test-install the installer on a clean machine or virtual machine to verify shortcuts, menus, file associations, and icons after installation.

If you need to create an installer from an existing application image, use `--app-image` in `jpackage`'s package mode. When you need to change a launcher icon, regenerate the application image with the desired icon resource and then package that image.

## 11. JavaFX and Swing Window Icons

`jpackage --icon` sets the icon at the package/launcher level. It does not automatically set the icon inside every window created by application code.

For JavaFX, set the icon on the `Stage` in the `start` method:

~~~java
@Override
public void start(Stage stage) {
    Image icon = new Image(
            getClass().getResourceAsStream("/icons/app.png"));
    stage.getIcons().add(icon);

    stage.setTitle("Icon Demo");
    stage.show();
}
~~~

The `app.png` file must be packaged on the classpath or in module resources. If multiple sizes are needed, you can add multiple `Image` instances to `stage.getIcons()` so JavaFX can select the appropriate size.

For Swing, set the icon on a `JFrame` using `setIconImage`:

~~~java
Image icon = Toolkit.getDefaultToolkit().getImage(
        getClass().getResource("/icons/app.png"));
frame.setIconImage(icon);
~~~

Therefore, a desktop application may require two steps: setting the launcher/package icon with `jpackage` and setting the window icon in UI code.

## 12. Verifying the Icon After Packaging

Use `--verbose` when running `jpackage`. The log can show that the custom icon resource was loaded, for example:

~~~text
Using custom package resource [icon] (loaded from file .../icon-demo.ico).
Succeeded in building Windows Application Image package
~~~

The exact message may vary across JDK versions and operating systems. After packaging:

- Verify that the icon file exists and has the correct format before invoking `jpackage`.
- Check the verbose log to confirm that the expected icon path was used.
- Inspect the generated native launcher or application bundle.
- Run the launcher to verify the application works after packaging.
- Check the desktop shortcut, Start Menu, Dock, or application menu after installation.
- For file associations, install the application and try opening a file with the registered extension.
- On Linux, inspect the desktop entry and the icon path it references.
- On macOS, inspect the application bundle's icon in Finder/Dock.
- On Windows, inspect the icon of the launcher executable and shortcut.

A simple smoke test on Windows:

~~~powershell
.\dist\IconDemo\IconDemo.exe
~~~

Stdout when the launcher is built with `--win-console`:

~~~text
Icon package ready
~~~

You can further inspect the launcher's icon in File Explorer or Properties. Some desktop environments cache icons; after changing an icon, inspect the new application image or refresh the cache according to your operating system's procedure.

## 13. Common Issues and Troubleshooting

| Symptom | Common Cause | Resolution |
|---|---|---|
| Launcher still uses the default icon | Wrong path, invalid icon format, or unreadable file. | Check the path relative to the current working directory, the format, and `--verbose` logs. |
| Renamed PNG to ICO, but packaging fails | The extension changed, but the file contents are still PNG. | Export or convert to a true ICO using an icon creation tool. |
| Windows displays a blurry icon or lacks sizes | ICO only contains a single small size or unoptimized artwork. | Create a multi-size ICO and check the alpha channel. |
| macOS does not display the expected icon | Invalid ICNS file or the bundle was not rebuilt. | Create a valid ICNS, rebuild the application image, and inspect the bundle. |
| Linux shortcut does not show the icon | PNG is not at the path referenced by the desktop entry, or resource name is wrong. | Check the resource directory, desktop entry, and icon path. |
| Additional launcher uses the default icon | `icon` key not declared in `--add-launcher` properties, or resource name mismatch. | Set a custom icon in the launcher properties or provide a resource matching the launcher name. |
| Associated files still use the old icon | File association has no icon declared, or installer has not registered the new association. | Check `--file-associations`, place the icon in the input directory, and reinstall the package to test. |
| Launcher icon is right, but window icon is wrong | Only package icon was configured, not the JavaFX/Swing window icon. | Set the icon using `Stage.getIcons()` or `JFrame.setIconImage()`. |
| Building from an application image keeps the old icon | The input application image already contains the launcher with the old icon. | Regenerate the application image with the new icon and then package the installer from the new image. |
| Package builds on one OS, but fails for another OS | `jpackage` does not support cross-platform native packaging. | Run the build on a runner/agent for each target operating system. |

## 14. Pre-Release Checklist

- Identified the target operating system and its corresponding icon format.
- Icon is a valid file, not just a renamed extension.
- Artwork is clear at small sizes, with an appropriate safe zone and transparency.
- Prepared ICO, ICNS, or PNG per platform.
- Path passed to `--icon` exists and is resolved from the correct working directory.
- Application image built and verified with `--type app-image`.
- `--verbose` log confirms the icon resource was loaded.
- Main launcher and each additional launcher use the correct icon.
- File associations have custom icons if the product registers file types.
- JavaFX/Swing window icons are set in UI code if needed.
- Installer built on the target operating system and test-installed.
- Shortcuts, menus, Dock, desktop entries, and file associations display the correct icon.
- Final artifact rebuilt after any icon changes.
