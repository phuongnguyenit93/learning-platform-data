# Experimenting with JShell

## 1. What is JShell?

JShell (Java Shell) is a REPL tool included in the JDK since Java 9. REPL stands for Read–Eval–Print Loop: it reads a piece of code, compiles and executes it, and displays the result immediately within the same session.

Instead of creating a class with a `main` method, saving a file, running `javac`, and then running `java` for every small experiment, you can enter Java expressions, statements, and declarations directly into JShell.

JShell is useful when you need to:

- Try out an expression, operator, or Java API before adding it to an application.
- Quickly check how a collection, Stream, Date/Time API, or library behaves.
- Prototype a method, class, record, or lambda.
- Explore and test an unfamiliar API.
- Create short examples to learn or explain a Java feature.
- Quickly verify the result of a data transformation.
- Reload a group of snippets to continue experimenting.

JShell is suited for exploration and prototyping. It does not replace project structure, unit tests, integration tests, or the build process of a real application.

## 2. Checking the JDK and Starting JShell

JShell is a JDK tool. If the terminal does not recognize the `jshell` command, check your JDK installation and `PATH` variable.

Check the Java and JShell versions:

```bash
java --version
javac --version
jshell --version
```

Start an interactive session:

```bash
jshell
```

You can request more or less feedback right when launching:

```bash
jshell --feedback verbose
jshell --feedback normal
jshell --feedback concise
jshell --feedback silent
```

`verbose` is helpful when learning because JShell explains the snippet you just created or modified. `concise` is cleaner when running examples. `silent` suppresses success feedback, though errors are still displayed.

When launched, JShell displays the JDK version and suggests using `/help intro`. Enter:

```text
/help intro
```

To exit:

```text
/exit
```

You can use `/exit 0` to exit with a specific exit code. When working in a terminal, exit codes help external scripts determine the outcome of a JShell session.

## 3. Understanding Snippets and the REPL Loop

Each unit of code that JShell accepts is called a **snippet**. A snippet can be:

- An expression, such as `2 + 2`.
- A statement, such as `System.out.println("Hello")`.
- A variable declaration.
- A method declaration.
- A class, interface, enum, or record declaration.
- An import statement.

Each complete snippet is compiled and evaluated as soon as JShell receives the full input. When a multiline declaration is incomplete, the prompt changes to `...>` so you can continue typing.

Example:

```text
jshell> 2 + 2
$1 ==> 4

jshell> System.out.println("Hello, JShell!")
Hello, JShell!
```

For an expression without a variable name, JShell creates a scratch variable such as `$1`. This value can be reused within the session:

```text
jshell> $1 * 10
$2 ==> 40
```

Names like `$1` and `$2` are generated by JShell to reference temporary results. Do not use them as stable variable names in application code or assume the numbering will be identical across sessions.

JShell automatically appends a semicolon at the end of a complete snippet if you omit `;`. However, it is good practice to include semicolons in multi-statement examples so the code is easier to transfer into regular Java files.

## 4. Testing Expressions, Statements, and Variables

You can enter Java expressions directly:

```java
2 + 3
10 * 4
Math.sqrt(81)
"java".toUpperCase()
```

The corresponding results are `5`, `40`, `9.0`, and `"JAVA"`.

Declaring variables:

```java
int quantity = 3;
double price = 19.5;
double total = quantity * price;
total
```

JShell retains variables in the session for use in subsequent snippets:

```text
jshell> int quantity = 3
quantity ==> 3

jshell> double price = 19.5
price ==> 19.5

jshell> double total = quantity * price
total ==> 58.5

jshell> total
total ==> 58.5
```

You can use `var` for local variable type inference:

```java
var language = "Java";
var majorVersion = 17;
```

The type of `language` is `String`, and `majorVersion` is `int`. JShell still requires the variable's type to be inferable at declaration time; `var` does not mean a variable can change types arbitrarily.

Use `/vars` to list the currently active variables:

```text
/vars
```

## 5. Imports and Exploring Java APIs

JShell automatically imports `java.lang` and several commonly used packages via its default startup script, such as `java.util`, `java.io`, `java.math`, `java.nio.file`, and `java.util.stream`.

You can still add explicit imports:

```java
import java.time.LocalDate;
import java.util.ArrayList;
import java.util.List;
import java.util.stream.Collectors;
```

Example testing the Date/Time API:

```java
var today = LocalDate.now();
var nextWeek = today.plusDays(7);
nextWeek
```

Testing a collection:

```java
var names = new ArrayList<String>();
names.add("An");
names.add("Binh");
names.add("Chi");
names
```

View current imports:

```text
/imports
```

To explore methods of an API, use Tab completion and `/help`. For example, type `LocalDate.` and press Tab in an interactive session to see available methods. Inside a method's parameter position, Tab can also display overloads and parameter type hints.

## 6. Declaring and Calling Methods

JShell lets you declare a method without wrapping it inside a class you create yourself:

```java
int square(int value) {
    return value * value;
}
```

Call the method immediately after declaring it:

```java
square(7)
square(12)
```

Methods can call other methods:

```java
int cube(int value) {
    return value * square(value);
}
cube(3)
```

Result:

```text
$1 ==> 49
$2 ==> 144
$3 ==> 27
```

You can define a method that references an undeclared method or variable. JShell allows forward references during exploration, but you cannot invoke the method until all dependencies are validly declared.

Example:

```java
double volume(double radius) {
    return 4.0 / 3.0 * Math.PI * cubeDouble(radius);
}
double cubeDouble(double value) {
    return value * value * value;
}
volume(2.0)
```

If you change the signature or type of a declaration used by another method, dependent snippets may no longer compile. Re-run the related expressions and check for errors before relying on the results.

## 7. Testing Classes, Records, and Lambdas

You can create a class directly in JShell:

```java
class Counter {
    private int value;

    void increment() {
        value++;
    }

    int current() {
        return value;
    }
}
```

Instantiate the object and call its methods:

```java
var counter = new Counter();
counter.increment();
counter.increment();
counter.current()
```

Java 17 supports records, which are very convenient for testing data-only types:

```java
record Student(String name, int score) {}
var student = new Student("Lan", 92);
student.name()
student.score()
```

Testing lambdas and Streams:

```java
import java.util.List;
var scores = List.of(72, 85, 92, 68, 90);
var passed = scores.stream()
    .filter(score -> score >= 80)
    .toList();
passed
```

JShell is great for comparing Stream expressions, checking method references, or testing a small algorithm before writing formal tests.

Note: JShell is not a regular Java source file. Do not declare a `package` at the top of a session as you would in a `.java` file. If you need to test a class belonging to a real package, compile that class into a `.class` file or JAR and add it to JShell's classpath.


## 8. Editing and Replacing Snippets

While experimenting, you can redeclare a method or class to change its behavior. A new declaration with the same signature replaces the previous definition:

```java
String greet(String name) {
    return "Hello, " + name + "!";
}
greet("Java")
```

Modify the method:

```java
String greet(String name) {
    return "Welcome, " + name + "!";
}
greet("Java")
```

JShell notifies you that the method was modified, and subsequent calls use the new definition. When a change is incompatible—for example, changing the type or deleting a method used elsewhere—dependent snippets may enter an error state. Re-check them before saving or using the results.

Useful commands:

- `/list`: list active snippets.
- `/list -all`: list all snippets, including failed, replaced, dropped, and startup snippets.
- `/drop <id>`: remove a snippet from active state.
- `/edit <id>`: open a snippet in an editor to modify it.
- `/vars`, `/methods`, `/types`: view declared variables, methods, and types.

The snippet ID is the number shown in `/list`. Use the ID to target the exact piece of code you want to edit or remove.

## 9. Common JShell Commands

JShell commands start with `/`, distinguishing them from Java snippets. The following table lists the commands you should know when practicing:

| Command | Purpose |
|---|---|
| `/help` | Display the list of commands and help topics |
| `/help intro` | Introduction to using JShell |
| `/list` | List active snippets |
| `/list -all` | List all snippets, including inactive and startup snippets |
| `/vars` | View variables and their values |
| `/methods` | View methods and their signatures |
| `/types` | View classes, interfaces, enums, and records |
| `/imports` | View imports |
| `/history` | View input history |
| `/edit` | Open an editor to modify snippets |
| `/drop` | Drop a snippet |
| `/open` | Load snippets from a file or startup script |
| `/save` | Save snippets or history to a file |
| `/env` | View or change classpath/module options |
| `/reset` | Clear session state and restart |
| `/reload` | Restart and replay snippets from history |
| `/set feedback` | Change the feedback verbosity level |
| `/exit` | Exit JShell |

You can use `/help <command>` to view detailed syntax, for example:

```text
/help /save
/help /env
/help /edit
```

Commands and options support Tab completion. Commands can be abbreviated if the prefix is unique, though full command names are recommended in scripts for readability.

## 10. Editing, History, and State Management

JShell supports navigating input history with the up/down arrow keys and editing the current line. For long methods or classes, `/edit` opens an external editor, which is more convenient than editing line by line at the prompt.

You can configure the editor using:

```text
/set editor
```

JShell checks the `JSHELLEDITOR`, `VISUAL`, and `EDITOR` environment variables before falling back to the default editor. See `/help /set editor` for exact configuration syntax.

Session state can be cleared with:

```text
/reset
```

`/reset` reinitializes the execution state and reloads the configured startup script. Variables, methods, and classes created in the current session are lost if not saved.

Use `/history` to view what you have entered. History is useful for finding previous commands, though it may also contain failed commands or sensitive input you typed. Review the file before sharing it.

## 11. Saving Snippets and Creating JShell Scripts

You do not need to retype your experiments every time you open JShell. You can save active snippets:

```text
/save experiments.jsh
```

Save input history:

```text
/save -history experiments-history.jsh
```

Save startup definitions:

```text
/save -start my-startup.jsh
```

A JShell script is a file containing JShell snippets and commands. Each snippet or command is a unit in the file. You can run a script at startup:

```bash
jshell experiments.jsh
```

Or load it from an already open session:

```text
/open experiments.jsh
```

Example `math-lab.jsh` file:

```java
import java.util.List;

int square(int n) {
    return n * n;
}

var values = List.of(1, 2, 3, 4, 5);
var squared = values.stream().map(n -> square(n)).toList();
squared
```

Run it:

```bash
jshell --feedback concise math-lab.jsh
```

Scripts help reuse definitions during study or API exploration sessions. They are not project builds: scripts do not package JARs, manage dependencies like Gradle, or replace a test suite.

## 12. Startup Scripts and Built-in Scripts

JShell has a default startup script named `DEFAULT`, which contains commonly used imports. Startup scripts are loaded when starting a session or when the state is reset.

Built-in scripts include:

| Name | Contents |
|---|---|
| `DEFAULT` | Commonly used imports |
| `PRINTING` | Convenience methods `print`, `println`, `printf` |
| `TOOLING` | Access to JDK command-line tools such as `javac`, `javadoc`, `javap` |

Load the `PRINTING` script in a session:

```text
/open PRINTING
```

Afterward, you can call `println("Hello")` without writing `System.out.println`.

Load the `TOOLING` script:

```text
/open TOOLING
```

This script provides helper methods to invoke JDK tools via `ToolProvider`, for example:

```java
tools()
javac("--version")
```

You can specify a startup script at launch:

```bash
jshell --startup my-startup.jsh
```

Or skip the default startup script:

```bash
jshell --no-startup
```

Use a custom startup script when you have a set of imports or helper methods you use frequently. Avoid putting large application logic into a startup script, as it makes the initial state harder to understand and reproduce.

## 13. Choosing the Right Feedback Mode

The feedback mode determines how much information JShell displays when a snippet is entered.

| Mode | Behavior |
|---|---|
| `verbose` | Most detailed, including descriptions of declarations and updates |
| `normal` | Default feedback level |
| `concise` | Shows only essential results with minimal extra output |
| `silent` | No success feedback; errors are still displayed |

Change it during a session:

```text
/set feedback verbose
/set feedback concise
/set feedback silent
```

Or set it at startup:

```bash
jshell --feedback verbose
jshell --feedback concise
```

When learning a new API, `verbose` helps you see which snippet was just created or modified. When running scripts or short demos, `concise` keeps output readable. Avoid `silent` while debugging if you need to see step-by-step results.

## 14. Using External Classes via the Classpath

JShell can use compiled code in class directories or JARs. Those classes must belong to a named package; classes in the unnamed package cannot be imported in JShell.

For example, compile a library into `build/classes/java/main`, then launch JShell:

```bash
jshell --class-path build/classes/java/main
```

If you need multiple directories or JARs, separate them with `;` on Windows or `:` on Linux/macOS.

Windows:

```powershell
jshell --class-path "build/classes/java/main;lib/greeter.jar"
```

Linux/macOS:

```bash
jshell --class-path 'build/classes/java/main:lib/greeter.jar'
```

Inside JShell, import the package as usual:

```java
import com.example.greeter.Greeter;
Greeter.greet("Classpath")
```

If a session is already open, you can change the classpath:

```text
/env --class-path build/classes/java/main
```

`/env` updates the evaluation context and restores current snippets under the new environment options. When changing the classpath, JShell may reset the engine to reload state. If a snippet fails to recompile, update the dependencies or declarations accordingly.

## 15. Using the Module Path and Module Options

JShell also supports the module path. You can specify the module path and root modules to resolve at startup:

```bash
jshell --module-path mods --add-modules com.example.greeter
```

Where:

- `--module-path` points to the directory or JARs containing modules.
- `--add-modules` requests resolving the specified modules.
- `--add-exports` can open a specific package to a target module when intentional integration is needed.

Inside JShell, view and modify the evaluation context with `/env`:

```text
/env
/env --module-path mods --add-modules com.example.greeter
```

A module must export the package that a snippet wants to import. Code entered directly in JShell runs in the unnamed module, so packages exported only to specific named modules (qualified exports) may not be accessible from JShell.

JShell is well suited for testing a module's public API. To verify the full module graph, launch configuration, and application encapsulation, build and run the actual modular application with `java --module-path ... -m ...` or Gradle. Do not treat a snippet running in JShell as complete proof that the application's module path is configured correctly.


## 16. Passing Compiler and Runtime Options

JShell provides distinct option groups:

- `-C<flag>` passes a flag to the compiler used to compile snippets.
- `-R<flag>` passes a flag to the runtime when snippets are executed.
- `-J<flag>` passes a flag to the JVM running the JShell tool itself; this flag does not automatically apply to snippet execution.
- `--enable-preview` enables preview features of the current JDK when testing preview APIs or language features.

Example enabling compiler warnings:

```bash
jshell -C-Xlint
```

Passing a property to the snippet runtime:

```bash
jshell -R-Dapp.mode=demo
```

In the session, test:

```java
System.getProperty("app.mode")
```

To test a preview feature, use a JDK that supports that feature and enable preview mode when launching JShell. Preview APIs and language features are tied to a specific JDK version; do not copy preview examples to another JDK without re-checking.

## 17. Practical Example: Analyzing a Course List

This exercise uses JShell to declare a record, create a collection, filter data, and write a method to compute an average. It runs on Java 17+.

Start JShell:

```bash
jshell --feedback concise
```

Import `List`:

```java
import java.util.List;
```

Create the data type:

```java
record Course(String title, int hours) {}
```

Create sample data:

```java
var courses = List.of(
    new Course("Core Java", 24),
    new Course("Gradle", 12),
    new Course("Testing", 18)
);
```

Calculate total hours:

```java
int totalHours = courses.stream()
    .mapToInt(Course::hours)
    .sum();
totalHours
```

Filter courses with at least 18 hours:

```java
var intensive = courses.stream()
    .filter(course -> course.hours() >= 18)
    .map(Course::title)
    .toList();
intensive
```

Create a method to calculate average hours:

```java
double averageHours(List<Course> values) {
    return values.stream()
        .mapToInt(Course::hours)
        .average()
        .orElse(0.0);
}
```

Call the method:

```java
averageHours(courses)
```

Key output:

```text
totalHours ==> 54
intensive ==> [Core Java, Testing]
$... ==> 18.0
```

The exact scratch variable name in your output depends on how many snippets were run previously; the returned value is `18.0`.

You can inspect the state:

```text
/vars
/methods
/types
/list
```

Try modifying the data:

```java
var extendedCourses = List.of(
    new Course("Core Java", 24),
    new Course("Gradle", 12),
    new Course("Testing", 18),
    new Course("JVM", 30)
);
averageHours(extendedCourses)
```

The new result is `21.0`. Modifying data and re-invoking methods within the same session lets you quickly test logic before turning it into unit tests.

## 18. Common Errors and How to Fix Them

| Symptom | Common Cause | Resolution |
|---|---|---|
| `jshell` is not recognized | JDK not installed or `PATH` does not point to JDK | Check `java --version`, `javac --version`, `JAVA_HOME`, and `PATH` |
| `illegal start of expression` with `package` | JShell evaluates snippets in an environment without package declarations | Remove the `package` declaration; compile packaged classes and add to classpath |
| `cannot find symbol` | Missing import, declaration, or dependency | Check `/imports`, `/vars`, `/types`, and classpath |
| `package ... does not exist` | Missing JAR/class or package not exported | Check `--class-path` or module options |
| `ClassNotFoundException` | Class not on the runtime classpath | Add the appropriate directory/JAR to the classpath |
| `NoClassDefFoundError` | Runtime dependency is missing | Check runtime dependencies |
| `module not found` | Module path is missing the module or name is wrong | Check `--module-path` and `--add-modules` |
| `package ... is not visible` | Module does not export the package or snippet does not read the module | Check module descriptor and exports |
| `InaccessibleObjectException` | Framework needs deep reflection but package is not open | Check `opens` or `--add-opens` |
| Old method fails to run after editing | Dependent snippet entered an error state | Run `/list -all`, fix dependencies, and invoke again |
| Script fails to load | Wrong file path or invalid snippet syntax in file | Verify the path and test snippets individually |
| Different results across machines | Different JDK version, classpath, locale, or environment | Record the JDK version and launch options used |
| Javadoc/API not found | Import or module not resolved | Check imports and module path |

When an error occurs, read the first error message line and the snippet location. Use `/list` to find the ID, then `/edit <id>` to fix it. JShell generally lets you continue entering other snippets after a snippet fails, so you do not need to restart for every syntax error.

## 19. What JShell Is and Isn't Suited For

| Task | JShell | Better Tool |
|---|---|---|
| Testing a Java expression | Very well suited | — |
| Exploring an API | Very well suited | IDE/Javadoc when reading full documentation |
| Prototyping a short method or record | Well suited | Java files when packages or multiple classes are needed |
| Testing Streams/lambdas | Very well suited | Unit tests for long-term verification |
| Using compiled libraries | Well suited | Gradle/Maven for dependency management |
| Testing an application's packages/modules | Testing APIs piece by piece | `javac`, `java`, Gradle, and module tests |
| Regression testing | Not a test framework | JUnit or the project's test framework |
| Building and releasing JARs | Not suitable | Gradle/Maven |
| Reliable performance evaluation | Not suitable for formal benchmarking | JMH or a controlled benchmark harness |

JShell shortens the experimentation loop. Once the logic is solid, move it into source files in the proper package, write automated tests, and run them with the project's build tool.

## 20. Recommended Practice Workflow

1. Check `jshell --version` to verify the active JDK.
2. Start a session with `jshell --feedback verbose` when learning.
3. Test small expressions, variables, and imports.
4. Write methods or records to verify logic.
5. Use `/vars`, `/methods`, `/types`, and `/list` to inspect state.
6. Edit snippets and re-test multiple input cases.
7. If an external library is needed, compile it and add it via `--class-path`.
8. If modules are needed, configure `--module-path` and `--add-modules`.
9. Save useful snippets with `/save` or `/save -history`.
10. Move stabilized code into the real project and write unit tests.
11. Run builds/tests with Gradle or Maven before releasing.

## 21. Summary

JShell is the JDK's REPL for quickly experimenting with Java in an interactive session. You can enter expressions, statements, variables, methods, classes, records, imports, and lambdas; results appear immediately without creating a `main` class for each experiment.

Key takeaways:

- Use `jshell --version` to confirm your JDK includes JShell.
- Snippets are evaluated as soon as they are complete; expression results can be stored in scratch variables.
- Redeclare methods or classes to test new versions; use `/list` and `/drop` to manage snippets.
- Use `/vars`, `/methods`, `/types`, and `/imports` to inspect state.
- Use `/open` and `/save` to reuse scripts.
- Use `--class-path` for compiled classes/JARs and `--module-path` for modules.
- Use `/env` when you need to update the evaluation context mid-session.
- Choose a feedback mode suited for learning or running scripts.
- JShell supports exploration; unit tests and build tools remain the verification step for real projects.
