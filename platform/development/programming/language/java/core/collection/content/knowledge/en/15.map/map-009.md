# merge, replaceAll, and Data Update Patterns

## 1. Two Different Update Problems

One map tracks the number of occurrences of each word. Each newly read word needs to be added to the existing count; if it is not present yet, it starts at 1. Another map holds display labels; the application needs to normalize every existing label.

Those two needs lead to two tools:

- `merge`: combines an incoming value with the existing value of **a single key**.
- `replaceAll`: recomputes the value for **existing mappings**, using each key and its current value.

Both accept a function that computes a new value, but they differ in the function's parameters, the scope of effect, and the meaning of a null result.

This lesson moves from state tables to runnable examples, then explains patterns for counting, combining, normalizing, error handling, and concurrency boundaries. The examples use Java 17+ APIs and require no external libraries.

## 2. Quick Comparison Before Writing a Lambda

| Property | merge | replaceAll |
| --- | --- | --- |
| Scope | One specified key | Existing mappings |
| Input outside the map | One incoming value, must be non-null | No per-key incoming value |
| Function parameters | Old value, incoming value | Key, current value |
| When key is missing | Associates the incoming value directly | Does not create a new key |
| When old value is null | Associates the incoming value directly | Function may receive null if the map allows it |
| Function returns null | Removes the mapping being merged | Attempts to assign null as the replacement value |
| Method return value | New value, or null if no mapping remains | void |

Two abbreviated signatures:

```java
V merge(K key, V value,
        BiFunction<? super V, ? super V, ? extends V> remappingFunction);

void replaceAll(
        BiFunction<? super K, ? super V, ? extends V> function);
```

These are API signatures for reference, not standalone program code. `BiFunction` is a function that takes two inputs and returns one result.

The full contract is in [Map Java 17](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/Map.html).

## 3. merge: Three Branches You Must Understand

### 3.1. Missing Key or Existing Mapping to null

If key `k` is not present, `merge(k, incoming, f)` associates `incoming` directly with `k`. The function `f` is not used to produce the initial value.

If `k` currently maps to `null` in a map that permits null values, the behavior is also to associate `incoming` directly. The old `null` value is not passed to `f` as a normal old value.

With `incoming` equal to 3:

| Before the call | Is the merge function called? | Value after |
| --- | --- | --- |
| No `k` | No | `k → 3` |
| Has `k → null` | No | `k → 3` |
| Has `k → 2` | Yes, with `(2, 3)` | Determined by function result |

Therefore, a condition written only inside the lambda does not automatically apply to the initialization branch.

### 3.2. Non-null Old Value

In this case, the function receives:

```text
first argument:  old value
second argument: incoming value of the call
```

Example:

```java
// Illustrative snippet; counts is a mutable Map<String, Integer>.
counts.merge("java", 1, (oldCount, increment) -> oldCount + increment);
```

Both lambda arguments are numeric values, not `(key, value)`. Naming the variables `(k, v)` does not change this contract; it only misleads the reader.

If the merge needs to depend on the key, you can explicitly use the known key from the enclosing scope, or choose a key-based recomputation API with an appropriate contract. Do not assume `merge` passes the key to the remapping function.

### 3.3. A null Result Is a Removal Request

If `f` is called and returns a non-null value, the map stores that value. If `f` returns `null`, the mapping is removed.

```text
non-null old value
    ↓
call f(oldValue, incoming)
    ├─ non-null result → store result
    └─ null result     → remove mapping
```

`merge` returns the new value, or `null` when no mapping remains after the operation. It does not return the old value like `put`.

For example, if `old` is 5 and `incoming` is -5, the function can compute 0 and intentionally return `null` to drop a key whose total is 0. However, if the function actually returns the number 0, the map keeps the mapping to 0; Java does not treat 0 as a removal instruction.

## 4. Null Constraints of merge

### 4.1. The incoming Value Must Not Be null

Even though `HashMap` allows storing `null` in general, the `value` argument to `merge` must still be non-null:

```java
// Invalid example:
totals.merge("item", null, Integer::sum);
```

This throws a `NullPointerException`. Do not pass `null` in the `incoming` position to mean "remove the key." Removal via `merge` happens through the return value of the remapping function when that function is actually called.

`remappingFunction` must also be non-null, even if a call appears likely to take the missing-key branch and not need to execute the function.

### 4.2. A Function That Always Returns null Does Not Remove in All Cases

Consider:

```java
// Illustrative snippet:
totals.merge("item", 5, (oldValue, incoming) -> null);
```

If `item` currently has a non-null value, the function runs and removes `item`.

If `item` is absent or currently maps to `null`, the function does not run; `merge` stores 5. This is why you should not use this pattern in place of `remove` when the intent is to delete regardless of state.

### 4.3. Null Keys Are a Separate Policy

`merge` does not automatically allow every map type to accept null keys. `HashMap` can accept a null key; `ConcurrentHashMap` cannot. A map's key policy is separate from the requirement that `incoming` must be non-null.

Consult [HashMap Java 17](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/HashMap.html) when applying examples with null mappings.

## 5. Runnable Program: Observing Each Branch of merge

Save as **MergeStateDemo.java**:

```java
import java.util.LinkedHashMap;
import java.util.Map;

public class MergeStateDemo {
    private static int sumCalls;

    private static Integer add(Integer oldValue, Integer incoming) {
        sumCalls++;
        return Math.addExact(oldValue, incoming);
    }

    public static void main(String[] args) {
        Map<String, Integer> totals = new LinkedHashMap<>();
        totals.put("existing", 2);
        totals.put("null-slot", null);

        System.out.println("existing result: " + totals.merge("existing", 3, MergeStateDemo::add));
        System.out.println("missing result: " + totals.merge("missing", 4, MergeStateDemo::add));
        System.out.println("null-slot result: " + totals.merge("null-slot", 7, MergeStateDemo::add));
        System.out.println("sum callback calls: " + sumCalls);
        System.out.println("after initial merges: " + totals);

        Integer removed = totals.merge("existing", -5, (oldValue, incoming) -> {
            int next = Math.addExact(oldValue, incoming);
            return next == 0 ? null : next;
        });
        System.out.println("zero-result merge return: " + removed);
        System.out.println("existing remains: " + totals.containsKey("existing"));

        System.out.println("missing with null-returning callback: "
                + totals.merge("fresh", 5, (oldValue, incoming) -> null));
        System.out.println("fresh current: " + totals.get("fresh"));

        try {
            totals.merge("bad-value", null, Integer::sum);
        } catch (NullPointerException ex) {
            System.out.println("null incoming value: " + ex.getClass().getSimpleName());
        }
        try {
            totals.merge("bad-function", 1, null);
        } catch (NullPointerException ex) {
            System.out.println("null remapping function: " + ex.getClass().getSimpleName());
        }

        totals.put("fail", 9);
        try {
            totals.merge("fail", 1, (oldValue, incoming) -> {
                throw new IllegalStateException("cannot combine");
            });
        } catch (IllegalStateException ex) {
            System.out.println("callback failure: " + ex.getClass().getSimpleName());
        }
        System.out.println("fail value after exception: " + totals.get("fail"));
        System.out.println("final mappings: " + totals);
    }
}
```

Compile and run:

```shell
javac --release 17 -encoding UTF-8 MergeStateDemo.java
java MergeStateDemo
```

Exact stdout:

```text
existing result: 5
missing result: 4
null-slot result: 7
sum callback calls: 1
after initial merges: {existing=5, null-slot=7, missing=4}
zero-result merge return: null
existing remains: false
missing with null-returning callback: 5
fresh current: 5
null incoming value: NullPointerException
null remapping function: NullPointerException
callback failure: IllegalStateException
fail value after exception: 9
final mappings: {null-slot=7, missing=4, fresh=5, fail=9}
```

The `add` method is called only once in the first three calls, because only `existing` had a non-null old value. `missing` and `null-slot` directly receive the incoming value.

The merge on `existing` with -5 intentionally returns `null` when the sum is 0; the `existing` key is removed. Conversely, `fresh` is absent, so the always-null function is not called; `fresh` is created with 5.

The `fail` case has value 9. The remapping function throws an exception before returning a new value, so that mapping remains 9. This does not mean any side effects placed inside the function by the author are rolled back; the example uses a function that only computes a result or throws an error.

The program uses a default `LinkedHashMap` so that the printed mapping order is easy to verify. Do not treat this print order as a guarantee for every `Map` implementation. See [LinkedHashMap Java 17](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/LinkedHashMap.html).

The programs in this lesson were compiled with `--release 17` and run on OpenJDK 24.0.2. That flag checks against the Java 17 target language/API and emits corresponding bytecode; the JVM used to run them is the version noted above.

## 6. replaceAll: Recomputing Values for Each Existing Key

### 6.1. Function Receives Key and Value

Example:

```java
// Illustrative snippet; scores is a mutable Map<String, Integer>.
scores.replaceAll((name, score) -> score + name.length());
```

Unlike `merge`, the first argument here is the key. The function is used to produce the replacement value for the corresponding mapping. The `function` argument must be non-null, even when the map is empty. The map must also support replacing values; an unmodifiable map may throw `UnsupportedOperationException`.

The method returns `void`. It does not return a new map, does not return the count of modified elements, and does not require reassignment:

```java
// Correct usage in context:
scores.replaceAll((name, score) -> score * 2);

// Incorrect example, does not compile:
// Map<String, Integer> updated = scores.replaceAll((name, score) -> score * 2);
```

### 6.2. Does Not Create New Keys

If the map currently has A, B, C, `replaceAll` processes the values associated with those keys. It does not add a nonexistent key D on its own.

During a normal run with no external structural modification and no exceptions, the key set is preserved; each mapping's value is recomputed. The number of mappings does not grow simply because a new value differs from the old value.

Do not confuse the name `replaceAll` with "replace every entry with a new key–value pair." The function returns `V`, not an `Entry` with a new key.

### 6.3. Existing null Values Still Need Handling

If the map permits nulls, the function can be called with a `null` `oldValue`. The snippet:

```java
labels.replaceAll((key, value) -> value.strip());
```

can fail if a `value` is `null`. The normalization policy should be written explicitly:

```java
labels.replaceAll((key, value) ->
        value == null ? "unknown" : value.strip());
```

These are illustrative statements for a mutable `Map<String, String>`. An empty string after `strip` is still a value; it is not automatically removed.

## 7. Null from replaceAll Does Not Mean the Same Thing as in merge

With a `HashMap` that permits nulls:

```java
// Illustrative snippet:
labels.replaceAll((key, value) -> null);
```

attempts to assign `null` as the value of each mapping. The keys still remain after a successful pass.

| Situation | merge | replaceAll |
| --- | --- | --- |
| Function is called and returns null | Removes the mapping being merged | Assigns null if the map supports it |
| Want to remove all entries | Not a whole-map tool | Returning null is not a substitute for clear |
| Map implementation forbids storing null | Null from the remapping function can still request removal | A null result can throw an error when replacing the value |

`ConcurrentHashMap` does not store null values. With it, having `replaceAll` produce a null result is not a way to remove an entry; it can throw a `NullPointerException`.

If you want to filter out entries based on a condition, choose an appropriate removal/filtering operation. Do not reuse one API's meaning of `null` for another API just because both accept a lambda.

## 8. Runnable Program: Counting, Bulk Transformation, and Mid-Operation Failure

Save as **BulkValueUpdatesDemo.java**:

```java
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

public class BulkValueUpdatesDemo {
    public static void main(String[] args) {
        Map<String, Integer> frequencies = new LinkedHashMap<>();
        for (String word : List.of("java", "map", "java", "api", "map", "java")) {
            frequencies.merge(word, 1, Math::addExact);
        }
        System.out.println("frequencies: " + frequencies);
        frequencies.replaceAll((word, count) -> count * word.length());
        System.out.println("weighted values: " + frequencies);

        Map<String, String> labels = new LinkedHashMap<>();
        labels.put("A", " raw ");
        labels.put("B", null);
        labels.put("C", "");
        labels.replaceAll((key, value) -> value == null ? "unknown" : value.strip());
        System.out.println("normalized labels: " + labels);
        labels.replaceAll((key, value) -> key.equals("B") ? null : value);
        System.out.println("B after null result: " + labels.get("B"));
        System.out.println("B key remains: " + labels.containsKey("B"));
        System.out.println("label count: " + labels.size());

        Map<Integer, Integer> partial = new LinkedHashMap<>();
        partial.put(1, 10);
        partial.put(2, 20);
        partial.put(3, 30);
        try {
            partial.replaceAll((key, value) -> {
                if (key == 2) {
                    throw new IllegalArgumentException("stop at key 2");
                }
                return value + 1;
            });
        } catch (IllegalArgumentException ex) {
            System.out.println("replaceAll failure: " + ex.getClass().getSimpleName());
        }
        System.out.println("observed partial update: " + partial);
    }
}
```

Run commands:

```shell
javac --release 17 -encoding UTF-8 BulkValueUpdatesDemo.java
java BulkValueUpdatesDemo
```

Stdout in the test environment:

```text
frequencies: {java=3, map=2, api=1}
weighted values: {java=12, map=6, api=3}
normalized labels: {A=raw, B=unknown, C=}
B after null result: null
B key remains: true
label count: 3
replaceAll failure: IllegalArgumentException
observed partial update: {1=11, 2=20, 3=30}
```

The `merge` loop counts `java` three times, `map` two times, and `api` once. `Math.addExact` is used so that addition can report overflow instead of silently wrapping around. The sample data is small, so no error occurs.

The subsequent `replaceAll` receives both the key and the value: the count is multiplied by the word length. It mutates the existing map rather than creating a separate result map.

The `labels` section shows an existing `null` value being replaced with `unknown`; a later `replaceAll` returns `null` for `B`, yet `B` still remains and `size` is still 3.

The `observed partial update` line illustrates the state observed after an exception: key 1 was already changed to 11, key 2 caused the error, and key 3 was not yet processed. Do not treat that specific key sequence as an ordering contract for all `Map` types or implementations. The takeaway is that **`replaceAll` does not promise to roll back completed changes when a later computation throws an exception**.

## 9. Common Data Update Patterns

### 9.1. Frequency Counting

Starting from an empty map:

```java
// Illustrative snippet; counts is a Map<String, Integer>.
for (String word : words) {
    counts.merge(word, 1, Math::addExact);
}
```

A word appearing for the first time receives 1. Subsequent occurrences combine `oldCount` with 1.

If the map currently has `word → null`, `merge` also sets it to 1 without calling the sum function. This differs from an expression that auto-unboxes `null` and then adds.

You need to decide on the numeric type size. `Integer` has a limit; `Long` also has a limit. Using `Math.addExact` helps detect overflow, though how to handle the error or whether to choose a larger type remains part of application design.

### 9.2. Combining Two Total Maps by Key

An illustrative utility method, placed inside a class and requiring `Map` to be imported:

```java
static void addTotals(
        Map<String, Integer> target,
        Map<String, Integer> incoming) {
    for (Map.Entry<String, Integer> entry : incoming.entrySet()) {
        target.merge(entry.getKey(), entry.getValue(), Math::addExact);
    }
}
```

The method assumes the incoming values are non-null. Each entry updates one key in `target`; it may add a new key or add to an existing key.

It does not promise that the whole batch is a single transaction. If a later entry fails, earlier entries may already be updated. Nor should this loop be used to mutate a source structure concurrently in a way the map does not support; the simple assumption for the example is that source and target are clearly controlled.

### 9.3. Concatenating Content by Key

```java
// Illustrative snippet; messages is a Map<String, String>.
messages.merge("topic", "first", (oldText, newText) -> oldText + ", " + newText);
messages.merge("topic", "second", (oldText, newText) -> oldText + ", " + newText);
```

If `topic` is initially missing, the result after both statements is `first, second`. The first call does not invoke the lambda, so there is no leading comma.

Repeated string concatenation can create many intermediate objects. If the data is large or each item needs to be stored separately for further processing, using a collection as the value may be more suitable. `merge` does not make every accumulation style have the same cost.

### 9.4. Removing a Key When the Total Reaches 0

A merge function can compute the sum and return `null` when the sum is 0, as in the first program.

However, do not put all input validation inside the merge function. For a missing key, `incoming` is used directly:

```java
// Illustrates a logic pitfall; balances does not yet contain new-key:
balances.merge("new-key", -1,
        (oldValue, delta) -> oldValue + delta <= 0 ? null : oldValue + delta);
```

The function does not run for `new-key`, so the map can store `-1`. If the domain forbids negative values, you must validate the input or choose an update workflow that handles the initialization branch as well, rather than assuming the `merge` lambda is always called.

### 9.5. Normalizing or Applying a Rule to All Values

`replaceAll` fits when every existing mapping needs a computation of the same form: trimming whitespace, changing labels, normalizing nulls, or computing a value from the key and old data.

If you only need to update one key, an operation targeting that key is usually easier to read. If you need to change the keys themselves, you must design building a new map and handling new key collisions; `replaceAll` only transforms `V`.

## 10. Errors Do Not Automatically Become an "All-or-Nothing" Update

### 10.1. A Single merge and a replaceAll Batch Have Different Boundaries

If a `merge` remapping function throws an exception, the exception is propagated to the caller and the mapping being computed does not receive a new result. That assumes the function does not itself mutate the map or a shared payload.

`replaceAll` may have already updated many entries before encountering an error. An exception does not automatically restore old values.

An `addTotals` loop consisting of multiple `merge` calls is also multiple operations. A key that fails later does not automatically undo keys merged earlier.

### 10.2. Compute on a New Copy If the Source Must Stay Intact on Failure

An illustrative method:

```java
static <K, V> Map<K, V> transformedCopy(
        Map<K, V> source,
        BiFunction<? super K, ? super V, ? extends V> transform) {
    Map<K, V> result = new LinkedHashMap<>();
    for (Map.Entry<K, V> entry : source.entrySet()) {
        result.put(entry.getKey(),
                transform.apply(entry.getKey(), entry.getValue()));
    }
    return result;
}
```

Placed in a class, this requires importing `Map`, `LinkedHashMap`, and `BiFunction`. The method returns the result copy only after all computations succeed. If `transform` only computes data and does not itself mutate the source or payloads, a mid-loop failure prevents `source`'s structure from being updated by the method.

This is a way to separate the computation step from the application step, not an atomic transaction across all threads. Publishing or swapping the shared data instance still requires an appropriate application policy.

A structural copy also does not automatically deep-copy every key/value object. If `transform` directly mutates an old object still held by the source, the source can still observe that change.

## 11. Keep Computation Functions Short, Clear, and Free of Map Self-Mutation

Inside a `merge` or `replaceAll` function, compute the return value instead of calling `put`/`remove`/`clear` on the very map being processed.

An example to avoid:

```java
// Example of flawed merge function design:
totals.merge("A", 1, (oldValue, incoming) -> {
    totals.remove("B");
    return oldValue + incoming;
});
```

Mutating the source while the map is computing or updating may be detected with an exception or cause behavior not permitted by the contract. Do not use a single run without an exception as proof that this style is valid.

Do not assume every invalid modification is detected at the same point. Detection mechanisms vary across classes and may only be best-effort.

Actions such as sending network requests, logging notifications, or mutating data outside the map also create side effects that are hard to roll back and hard to retry safely. Keeping the function focused on computing a result makes error handling and concurrent access easier to reason about.

The `sumCalls` counter in the first program is only for observation in a single-threaded example. Do not use incrementing an external variable inside a lambda as a concurrent counter or assume the callback always runs exactly once across every `Map` type.

## 12. Concurrency: Per-Key Atomicity Differs from Whole-Map Updates

### 12.1. Do Not Infer Atomicity from Default Map Methods

Default methods on `Map` do not inherently provide synchronization or atomicity guarantees. `HashMap` does not become thread-safe simply because you call `merge` instead of `get` followed by `put`.

When multiple threads perform updates, you must choose an implementation class or synchronization mechanism with the appropriate contract.

### 12.2. ConcurrentHashMap.merge Has an Atomic Contract

`ConcurrentHashMap` performs a single `merge` call atomically according to its contract. This is well suited for adding a value to the same key when multiple threads update concurrently.

The computation function should be short and simple because other updates may have to wait during computation. Do not use it to update other mappings on the same map.

A `null` return from the remapping function can remove a mapping in `ConcurrentHashMap` even though the class does not store null values. It acts as a control signal for the `merge` operation, not as storing a null payload.

See [ConcurrentHashMap Java 17](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/concurrent/ConcurrentHashMap.html#merge(K,V,java.util.function.BiFunction)).

### 12.3. replaceAll Is Not a Single Atomic Whole-Map Swap

Do not assume all values change simultaneously at a single instant just because the name contains `All`. With a concurrent map, another thread may observe or update data during processing according to the data structure's contract.

The default `ConcurrentMap.replaceAll` implementation may retry under contention, including calling the function multiple times for a single key. Therefore, do not place a side effect that is only allowed to happen once inside the function under the assumption that there will be no retries.

Consult [ConcurrentMap.replaceAll Java 17](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/concurrent/ConcurrentMap.html#replaceAll(java.util.function.BiFunction)).

An atomic `merge` call for one key, a `replaceAll` pass, and a multi-key business batch are three different scopes. Good design chooses the scope that needs to be guaranteed first.

## 13. Common Mistakes and How to Choose the Right Operation

| Symptom | Cause | Fix |
| --- | --- | --- |
| `merge` lambda does not run for a new key | Missing/null branch uses `incoming` directly | Handle initialization checks in the right place |
| Passing `null` to `merge` fails on `HashMap` | `merge`'s `incoming` must be non-null | Distinguish input `null` from a function's `null` result |
| Returning `null` in `replaceAll` leaves the key intact | `null` is a replacement value | Use a remove/filter operation if the entry must be dropped |
| Assuming the first argument of `merge` is the key | Confused with `replaceAll`/`compute` | Name parameters `oldValue` and `incoming` |
| Assigning `replaceAll`'s result to a `Map` | `replaceAll` returns `void` | Call it directly or build a result map yourself |
| An existing `null` value breaks the normalization function | `replaceAll` can pass `null` to the function | Write an explicit null policy |
| Data is partially changed after an error | No whole-batch rollback | Separate computation or design an appropriate transaction |
| Merge function mutates another key | Mutating the map while computing | Return a result; do not mutate the source in the callback |
| Parallel counting is wrong on `HashMap` | No concurrency guarantees | Choose `ConcurrentHashMap` or appropriate synchronization |
| Notifications sent repeatedly in concurrent `replaceAll` | Function may be retried | Separate side effects from computation |
| Negative value slips through despite lambda check | New keys bypass the `merge` lambda | Validate `incoming` or use a workflow covering all branches |

## 14. Self-Check Exercises with Solutions

### Exercise 1: Is the Function Called?

A map has `A → 2`, `B → null`, and no `C`. Merge each key with `incoming` 3 and an addition function. What is the result, and how many times does the addition function run?

**Solution:** `A → 5`, `B → 3`, `C → 3`. The function runs only for `A`, once in total under the single-threaded conditions of the exercise.

### Exercise 2: Function Always Returns null

A map has `A → 2` and no `B`. Call `merge(A, 5, function returning null)` and then `merge(B, 5, same function)`. What remains afterward?

**Solution:** `A` is removed because the function is called and returns `null`. `B` is created with 5 because the missing-key branch does not call the function.

### Exercise 3: Null in replaceAll

A `HashMap` has `A → 1` and `B → 2`. `replaceAll` returns `null` for every entry. Does `size` become 0?

**Solution:** No. If the pass succeeds, there are still two keys, each mapped to `null`. Removing all mappings requires a different operation such as `clear` matching that intent.

### Exercise 4: Lambda Parameters

In `merge`, what are the two parameters? In `replaceAll`, what are the two parameters?

**Solution:** `merge` receives the old value and the incoming value; `replaceAll` receives the key and the current value. Lambda variable names do not change the contract.

### Exercise 5: Error on the Second Entry

A `replaceAll` pass has already replaced the first entry, then the function throws an error on the next entry. Can you assume the first entry automatically reverts to its old value?

**Solution:** No. The method does not promise whole-batch rollback. You need a pre-computation design or a separate transaction if the business logic forbids partial updates.

### Exercise 6: Checking for Negatives Only in the Merge Function

The map is empty. Merge key `K` with `incoming` -1; the lambda will return `null` if the sum is non-positive. Is it guaranteed that `K` will not appear?

**Solution:** No. The lambda does not run when `K` is missing, so `incoming` -1 is associated directly. Validity conditions must also be handled for the initialization branch.

### Exercise 7: One Key vs. the Whole Map

`ConcurrentHashMap.merge` is an atomic operation. Does that imply `replaceAll` on that map is an atomic transaction across all keys?

**Solution:** No. The guarantee for a merge operation on one key does not automatically extend to replacing the entire map at a single point in time.

### Exercise 8: Return Values

`A` currently has 2. Does `merge(A, 3, addition function)` return 2 or 5? Does `replaceAll` return a new map or the number of changes?

**Solution:** `merge` returns 5, the post-merge value. `replaceAll` returns `void`, neither a new map nor an entry count.

- [ConcurrentHashMap Java 17](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/concurrent/ConcurrentHashMap.html): concurrent per-key updates.
- [ConcurrentMap Java 17](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/concurrent/ConcurrentMap.html): bulk value replacement mechanics and retry behavior.

Choose `merge` when you need to fold additional data into a single key; choose `replaceAll` when you need to transform the values of existing mappings. Always determine three things separately: when the function is called, what `null` in the result means, and what scope of changes an error or contention can leave behind.
