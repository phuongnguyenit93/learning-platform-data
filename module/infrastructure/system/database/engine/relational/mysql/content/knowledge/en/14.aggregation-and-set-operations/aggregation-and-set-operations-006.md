# WITH ROLLUP, GROUPING, and Distinguishing Summary Rows from NULL Data

When building reports, in addition to detail rows for each group, you often need subtotals at each hierarchy level and a grand total. MySQL supports `GROUP BY ... WITH ROLLUP` to generate these summary rows in a single query. However, generated summary rows use `NULL` as a placeholder for rolled-up grouping levels. If the source data also contains `NULL`, looking only at the grouping columns cannot tell whether a `NULL` is real data or was generated by ROLLUP.

The `GROUPING()` function resolves this ambiguity: it indicates whether a `NULL` value in a result row is a placeholder produced by aggregation. This lesson covers how to use `WITH ROLLUP`, read summary level order correctly, distinguish data NULLs from aggregated NULLs, format and filter summary rows, and handle MySQL version differences.

In the `DATABASE_MYSQL` module, these techniques support reports for revenue, order counts, inventory, and metrics aggregated across multiple dimensions. Results must preserve business semantics: detail rows with NULL data must remain distinct from subtotal or grand total rows.

## 1. What Is Multi-Level Aggregation?

Suppose a business wants a revenue report by region and product category. A useful report typically needs three levels:

1. **Detail rows:** revenue for each region and category pair.
2. **Region subtotals:** total revenue across all categories within a region.
3. **Grand total:** total revenue across the entire selected dataset.

If you only use `GROUP BY region, category`, the query returns only the detail level. You could write separate queries for subtotals and the grand total and combine them with `UNION ALL`, but `WITH ROLLUP` generates the summary levels along the grouping hierarchy in one aggregation.

Conceptual illustration:

```text
Region       Category          Revenue     Row Type
North        Hardware          100         Detail
North        Software          150         Detail
North        NULL              250         North Subtotal
South        Hardware          200         Detail
South        NULL               75         Detail with NULL category
South        NULL              275         South Subtotal
NULL         Hardware           50         Detail with NULL region
NULL         NULL               50         NULL region Subtotal
NULL         NULL              575         Grand Total
```

Rows with the same `NULL` value in grouping columns can have completely different meanings. Therefore, reports need an additional flag to identify the summary level.

## 2. Preparing Practice Data

Create a test table with data containing real `NULL` values in both grouping columns:

```sql
CREATE TABLE sales_rollup_demo (
    id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    region VARCHAR(40) NULL,
    category VARCHAR(40) NULL,
    amount DECIMAL(12,2) NOT NULL,
    PRIMARY KEY (id),
    KEY idx_sales_rollup_region_category (region, category)
) ENGINE=InnoDB;

INSERT INTO sales_rollup_demo (region, category, amount)
VALUES
    ('North', 'Hardware', 100.00),
    ('North', 'Software', 150.00),
    ('South', 'Hardware', 200.00),
    (NULL,    'Hardware',  50.00),
    ('South', NULL,        75.00);
```

In this fixture:

- `region IS NULL` in the fourth row means the source data has no region assigned.
- `category IS NULL` in the fifth row means the source data has no category assigned.
- `amount` always has a value so total revenue is not made ambiguous by NULL.

Verify the source data:

```sql
SELECT id, region, category, amount
FROM sales_rollup_demo
ORDER BY id;
```

## 3. Syntax of `GROUP BY ... WITH ROLLUP`

Basic syntax:

```sql
SELECT group_column_1,
       group_column_2,
       aggregate_function(...)
FROM table_name
GROUP BY group_column_1, group_column_2 WITH ROLLUP;
```

`WITH ROLLUP` instructs MySQL to generate extra summary rows from right to left along the `GROUP BY` expression list.

With:

```sql
GROUP BY region, category WITH ROLLUP
```

MySQL produces these levels:

| Level | `region` | `category` | Meaning |
|---|---|---|---|
| Detail | Group value | Group value | Total for each region/category pair. |
| Subtotal | Region value | `NULL` | Total across all categories in that region. |
| Grand total | `NULL` | `NULL` | Total across all groups. |

Run the first query:

```sql
SELECT
    region,
    category,
    SUM(amount) AS revenue
FROM sales_rollup_demo
GROUP BY region, category WITH ROLLUP;
```

The output contains detail rows, regional subtotals, and the grand total. Some rows have `NULL` in `region` or `category` from the source data; summary rows also use `NULL` to represent rolled-up levels. This is why `GROUPING()` is needed.

## 4. Column Order in GROUP BY Determines Subtotal Order

ROLLUP is a hierarchical aggregation. With `GROUP BY region, category WITH ROLLUP`, `category` is rolled up first to produce regional subtotals, and then `region` is rolled up to produce the grand total.

If you swap the order:

```sql
SELECT
    category,
    region,
    SUM(amount) AS revenue
FROM sales_rollup_demo
GROUP BY category, region WITH ROLLUP;
```

The levels become:

- Detail by category and region.
- Subtotal by category (region rolled up to NULL).
- Grand total.

The order of expressions in `GROUP BY` is therefore part of report design, not just presentation. If you need both subtotals by region and subtotals by category in the same report, a single ROLLUP does not produce arbitrary combinations of groupings.

MySQL supports `WITH ROLLUP`; do not assume `GROUPING SETS` or `CUBE` syntax from other database engines works as-is in MySQL. For subtotal combinations that do not follow a single hierarchy tree, combine separate queries using `UNION ALL`.

## 5. Why Do Data NULLs and Aggregated NULLs Look Identical?

In the query:

```sql
SELECT region, category, SUM(amount) AS revenue
FROM sales_rollup_demo
GROUP BY region, category WITH ROLLUP;
```

A row with `region = NULL, category = 'Hardware'` can be a detail group containing source data with an unspecified region. A row with `region = 'North', category = NULL` could be the North subtotal, or it could be a detail group whose source data has `category IS NULL`.

Even the `(NULL, NULL)` pair can appear multiple times with different meanings:

- A detail row for the data group with `region IS NULL` and `category IS NULL`, if the source data contains that pair.
- The subtotal for the NULL region group, when category is rolled up.
- The grand total, when both region and category are rolled up.

You cannot classify reliably using only:

```sql
CASE WHEN region IS NULL THEN 'Grand Total' ... END
```

That condition would mislabel source data rows that have a NULL region. You need a signal that explicitly states which column was rolled up by ROLLUP.

## 6. `GROUPING()` Identifies ROLLUP-Generated NULLs

`GROUPING(expr)` returns:

- `1` if the expression's `NULL` in the result row was produced by ROLLUP rolling up that grouping level.
- `0` if the expression is still part of the current grouping level, even when the actual source data value is NULL.

The expression passed to `GROUPING()` must correspond to an expression in `GROUP BY`. In our current example:

```sql
SELECT
    region,
    category,
    SUM(amount) AS revenue,
    GROUPING(region) AS region_rolled_up,
    GROUPING(category) AS category_rolled_up
FROM sales_rollup_demo
GROUP BY region, category WITH ROLLUP;
```

The two flag columns indicate which level was rolled up:

| Row | `GROUPING(region)` | `GROUPING(category)` | Meaning |
|---|---:|---:|---|
| Detail, both values present | 0 | 0 | Detail group. |
| Detail with NULL region in source data | 0 | 0 | Still a detail group. |
| Detail with NULL category in source data | 0 | 0 | Still a detail group. |
| Subtotal by region | 0 | 1 | Category was rolled up. |
| Grand total | 1 | 1 | Both region and category were rolled up. |

Key point: `GROUPING(region) = 0` does not mean `region` is non-NULL; it means `region` has not been rolled up. If the source value of `region` is NULL, the column remains NULL while the GROUPING flag is 0.

### Example Distinguishing Accurately in the Fixture

```sql
SELECT
    region,
    category,
    SUM(amount) AS revenue,
    GROUPING(region) AS g_region,
    GROUPING(category) AS g_category
FROM sales_rollup_demo
GROUP BY region, category WITH ROLLUP;
```

For the source row `('South', NULL, 75.00)`, the detail result has `g_region = 0` and `g_category = 0`. The South subtotal row has the same `region = 'South'` and `category = NULL`, but has `g_region = 0`, `g_category = 1`. Two rows have identical displayed values in the grouping columns yet are distinguished by the flags.

For the source group with `region IS NULL`, its subtotal has `g_region = 0`, `g_category = 1`; the grand total has `g_region = 1`, `g_category = 1`. Thus, even when both columns display NULL, we still identify the exact row type.

## 7. Formatting Labels for Detail, Subtotal, and Grand Total Rows

Once you have `GROUPING()` flags, use `CASE` to display meaningful labels. Do not naively use `COALESCE(region, 'Grand Total')`, because it confuses source NULLs with ROLLUP-generated NULLs.

```sql
SELECT
    CASE
        WHEN GROUPING(region) = 1 THEN 'All regions'
        WHEN region IS NULL THEN '(Unspecified region)'
        ELSE region
    END AS region_label,
    CASE
        WHEN GROUPING(category) = 1 THEN 'All categories'
        WHEN category IS NULL THEN '(Uncategorized)'
        ELSE category
    END AS category_label,
    SUM(amount) AS revenue,
    GROUPING(region) AS g_region,
    GROUPING(category) AS g_category
FROM sales_rollup_demo
GROUP BY region, category WITH ROLLUP;
```

Display rules:

1. Check `GROUPING()` first to identify summary levels.
2. If it is not a summary row and the source value is NULL, show a label such as "Unspecified".
3. If a value is present, display the original value.

The order of `CASE` branches is critical. Checking `region IS NULL` before `GROUPING(region) = 1` would label the grand total row as "(Unspecified region)" instead of "All regions".

In APIs or exported reports, also return the `g_region` and `g_category` flags or an explicitly computed `row_type`. Do not force the UI layer to infer row types from text labels.

## 8. Classifying Rows with `row_type`

A report often needs a simple field so clients can distinguish detail, subtotal, and grand total rows:

```sql
SELECT
    region,
    category,
    SUM(amount) AS revenue,
    GROUPING(region) AS g_region,
    GROUPING(category) AS g_category,
    CASE
        WHEN GROUPING(region) = 1 THEN 'GRAND_TOTAL'
        WHEN GROUPING(category) = 1 THEN 'REGION_SUBTOTAL'
        ELSE 'DETAIL'
    END AS row_type
FROM sales_rollup_demo
GROUP BY region, category WITH ROLLUP;
```

Because a regional subtotal has `GROUPING(category) = 1` while the grand total has `GROUPING(region) = 1`, the grand total branch must be checked first. Reversing those two conditions would classify the grand total as a subtotal.

If you need to distinguish the subtotal of the NULL region group from the subtotal of a named region, `g_region` is 0 in both cases; the value of `region` shows whether the source group is NULL or named. `row_type` tells you the summary level, while the original grouping column tells you the group value.

## 9. Filtering Source Data with WHERE and Summary Results with HAVING

`WHERE` filters source rows before grouping and generating ROLLUP. `HAVING` filters groups after aggregation, including subtotal and grand total rows. If you use HAVING without considering `GROUPING()`, you can accidentally filter out summary rows.

Example: calculate revenue only from rows matching a condition:

```sql
SELECT
    region,
    category,
    SUM(amount) AS revenue,
    GROUPING(region) AS g_region,
    GROUPING(category) AS g_category
FROM sales_rollup_demo
WHERE amount > 0
GROUP BY region, category WITH ROLLUP;
```

The `WHERE amount > 0` condition excludes source rows before computing any summary level.

Example: keep subtotals/grand total and only detail groups meeting a threshold:

```sql
SELECT
    region,
    category,
    SUM(amount) AS revenue,
    GROUPING(region) AS g_region,
    GROUPING(category) AS g_category
FROM sales_rollup_demo
GROUP BY region, category WITH ROLLUP
HAVING GROUPING(region) = 1
    OR GROUPING(category) = 1
    OR SUM(amount) >= 100;
```

This condition keeps all summary rows and only detail rows with revenue of at least 100. Writing only `HAVING SUM(amount) >= 100` could drop subtotals or the grand total if they fail the threshold. Clarify whether the threshold applies to detail rows, subtotals, or both.

## 10. Counting Rows and Handling NULL in ROLLUP Aggregations

Aggregate functions have their own NULL rules:

- `COUNT(*)` counts every row in the group.
- `COUNT(expr)` counts only rows where `expr` is non-NULL.
- `SUM(expr)`, `AVG(expr)`, `MIN(expr)`, and `MAX(expr)` ignore NULL arguments.
- If there are no non-NULL values for an aggregate, the result can be NULL.

Example:

```sql
SELECT
    region,
    category,
    COUNT(*) AS source_rows,
    COUNT(category) AS rows_with_category,
    SUM(amount) AS revenue,
    GROUPING(region) AS g_region,
    GROUPING(category) AS g_category
FROM sales_rollup_demo
GROUP BY region, category WITH ROLLUP;
```

`COUNT(category)` does not count source rows with NULL category, and still evaluates on subtotal/grand total groups by the same rule. `COUNT(*)` counts all source rows contributing to each group. Do not mistake `COUNT(category) = 0` for a subtotal row; combine it with GROUPING flags to understand the summary level.

If you want to display revenue as 0 instead of NULL when there is no data, you can use `COALESCE(SUM(amount), 0)`. Only do this when 0 is genuinely the appropriate representation for the report; NULL can carry a different meaning from a zero sum.

## 11. Sorting ROLLUP Results

ROLLUP result ordering reflects the aggregation hierarchy, but if a report needs a custom order, sort explicitly using grouping flags. A controllable approach is wrapping the ROLLUP query in a derived table and applying `ORDER BY` in the outer query:

```sql
SELECT
    region,
    category,
    revenue,
    g_region,
    g_category,
    row_type
FROM (
    SELECT
        region,
        category,
        SUM(amount) AS revenue,
        GROUPING(region) AS g_region,
        GROUPING(category) AS g_category,
        CASE
            WHEN GROUPING(region) = 1 THEN 'GRAND_TOTAL'
            WHEN GROUPING(category) = 1 THEN 'REGION_SUBTOTAL'
            ELSE 'DETAIL'
        END AS row_type
    FROM sales_rollup_demo
    GROUP BY region, category WITH ROLLUP
) AS rollup_rows
ORDER BY
    g_region,
    region,
    g_category,
    category;
```

In this example, the grand total row has `g_region = 1`, so it is placed after region groups where `g_region = 0`. Subtotals and details are distinguished by `g_category`. If you want subtotals to appear after all details within each region, adjust the sort expressions using `g_category` and the grouping columns.

Do not rely solely on `region IS NULL` or `category IS NULL` to sort summary rows, because NULL source data would sort into the same region. Use GROUPING flags instead.

## 12. Multi-Level ROLLUP and Flag Meanings

With three columns:

```sql
GROUP BY year, region, category WITH ROLLUP
```

MySQL generates levels in order:

1. Detail by year, region, category.
2. Subtotal by year and region (category rolled up).
3. Subtotal by year (region and category rolled up).
4. Grand total (all three columns rolled up).

Query:

```sql
SELECT
    sales_year,
    region,
    category,
    SUM(amount) AS revenue,
    GROUPING(sales_year) AS g_year,
    GROUPING(region) AS g_region,
    GROUPING(category) AS g_category
FROM yearly_sales
GROUP BY sales_year, region, category WITH ROLLUP;
```

Flags provide accurate classification:

| Level | `g_year` | `g_region` | `g_category` |
|---|---:|---:|---:|
| Detail | 0 | 0 | 0 |
| Year/region subtotal | 0 | 0 | 1 |
| Year subtotal | 0 | 1 | 1 |
| Grand total | 1 | 1 | 1 |

At each level, columns from the right side of the GROUP BY list are rolled up progressively. This is the core hierarchical rule of ROLLUP.

## 13. Version Limitations and `GROUPING()`

`WITH ROLLUP` has existed in MySQL for many versions, but the `GROUPING()` function is a MySQL 8.0 feature. On MySQL 5.7, there is no equivalent `GROUPING()` function to directly distinguish aggregated NULLs from source NULLs in ROLLUP output. Check the server version before relying on it:

```sql
SELECT VERSION();
```

On MySQL 8.0 and later, you can use `GROUPING(region)` and `GROUPING(category)` in ROLLUP queries. On older versions without the function, avoid guessing from NULL; consider manually building report levels with `UNION ALL` to attach explicit labels.

Additionally, syntax and restrictions around `WITH ROLLUP` can differ across MySQL versions. If you need custom `ORDER BY` or combinations with other features, consult the documentation for your exact version; wrapping the ROLLUP result in a derived table and sorting in the outer query separates aggregation from presentation.

## 14. Alternative with UNION ALL When Per-Level Control Is Needed

When running on a version without `GROUPING()`, or when you need subtotals that do not fit a single ROLLUP tree, you can build each level with `UNION ALL`. Each branch adds an explicit row type or flag column.

Example on MySQL 8.0 using a CTE to avoid repeating filter conditions:

```sql
WITH filtered_sales AS (
    SELECT region, category, amount
    FROM sales_rollup_demo
    WHERE amount > 0
)
SELECT
    region,
    category,
    SUM(amount) AS revenue,
    0 AS g_region,
    0 AS g_category,
    'DETAIL' AS row_type
FROM filtered_sales
GROUP BY region, category

UNION ALL

SELECT
    region,
    NULL AS category,
    SUM(amount) AS revenue,
    0 AS g_region,
    1 AS g_category,
    'REGION_SUBTOTAL' AS row_type
FROM filtered_sales
GROUP BY region

UNION ALL

SELECT
    NULL AS region,
    NULL AS category,
    SUM(amount) AS revenue,
    1 AS g_region,
    1 AS g_category,
    'GRAND_TOTAL' AS row_type
FROM filtered_sales;
```

Here, NULLs in the detail branch are source data NULLs; `g_region` and `g_category` are both 0. NULLs in subtotals or the grand total are explicitly flagged. `UNION ALL` keeps all rows, even when grouping column values coincide between a detail row and a subtotal row. Using `UNION` would eliminate identical rows and could drop a valid summary row.

If using MySQL 5.7, replace the CTE with repeated derived tables or a session-scoped temporary table. The key is that every branch must apply the same filter conditions, the same aggregate definitions, and compatible column data types in corresponding SELECT positions.

## 15. Performance and Checking Execution Plans

ROLLUP still has to read and group the source data. Cost depends on input row count, group count, grouping key size, indexes, memory, and how the optimizer executes the query.

Guidelines:

- Filter source data with `WHERE` before grouping whenever the condition can be applied without changing report semantics.
- Create appropriate indexes for filtering and grouping columns when the workload demonstrates a benefit; an index does not guarantee every ROLLUP avoids sorting or temporary tables.
- Avoid selecting unnecessary columns in aggregate queries.
- Use appropriate numeric types: `DECIMAL` for monetary values and `BIGINT` for large counts; avoid summing money with `FLOAT` when decimal precision is required.
- Use `EXPLAIN` to inspect access paths, keys, estimated rows, and grouping/sorting steps.
- Measure on representative data; small tables may cause the optimizer to choose a table scan even when an index exists.

Example:

```sql
EXPLAIN
SELECT
    region,
    category,
    SUM(amount) AS revenue,
    GROUPING(region) AS g_region,
    GROUPING(category) AS g_category
FROM sales_rollup_demo
WHERE amount >= 0
GROUP BY region, category WITH ROLLUP;
```

`EXPLAIN ANALYZE` can execute the query to provide actual runtime statistics on supported versions. Run it only when the execution cost on that environment is acceptable; for heavy reporting queries, prefer testing on staging or a data replica.

Do not add `GROUPING()` to every query just to have extra columns. Use it when you need to distinguish summary levels or when output is consumed by downstream systems requiring row metadata.

## 16. Common Pitfalls

| Mistake | Consequence | Solution |
|---|---|---|
| Assuming every NULL in ROLLUP results is a summary row | Source NULL data is mislabeled | Use `GROUPING()` to distinguish. |
| Checking `region IS NULL` before `GROUPING(region)` | Grand total is labeled as an unspecified group | Check GROUPING flags first, then check data NULLs. |
| Reordering columns in GROUP BY without considering hierarchy | Subtotals appear along a different dimension | Decide the subtotal dimension before ordering grouping columns. |
| Using `HAVING` on SUM alone while forgetting summary rows | Subtotals/grand total may be filtered out | Combine predicates with `GROUPING()`. |
| Using `UNION` instead of `UNION ALL` when building summary levels manually | Detail and summary rows with matching values may be dropped | Use `UNION ALL` and `row_type`/flag columns. |
| Assuming MySQL supports `GROUPING SETS` or `CUBE` | Incompatible SQL syntax | Use hierarchical ROLLUP or UNION ALL. |
| Using GROUPING() on an unsupported version | Non-existent function error | Check `VERSION()` and use an alternative approach. |
| Sorting only by nullable grouping columns | Summary rows mix with source NULLs | Sort by GROUPING flags in an outer query. |
| Using `COUNT(column)` to count all rows | Skips rows where the column is NULL | Use `COUNT(*)` when counting rows. |

## 18. Key Principles to Remember

- `GROUP BY ... WITH ROLLUP` generates subtotals and a grand total following the hierarchical order of grouping expressions.
- With `GROUP BY region, category WITH ROLLUP`, MySQL produces detail rows, region subtotals, and then the grand total.
- NULL in summary rows can look identical to real NULL values in source data.
- `GROUPING(expr) = 1` identifies a column rolled up by ROLLUP; `0` means the column remains at the current grouping level, even if the source value is NULL.
- Inside `CASE`, check GROUPING before checking `IS NULL` when formatting labels.
- Include GROUPING flags or `row_type` when returning report results to applications.
- `WHERE` filters source rows before aggregation; `HAVING` filters groups and can drop subtotals/grand total if GROUPING is not checked.
- MySQL 8.0 supports `GROUPING()`; on older versions without it, build levels manually with `UNION ALL` and explicit flags.
- `UNION ALL` keeps summary rows with duplicate column values; `UNION` can drop them.
- Use `EXPLAIN` and representative data to evaluate performance instead of guessing based on index existence.

By combining `WITH ROLLUP` and `GROUPING()`, you can produce multi-level reports while preserving the true meaning of NULL in source data. This provides the foundation for displaying accurate subtotals and grand totals, filtering reports safely, and delivering clearly structured results to applications.
