# Runtime Native Image

**GraalVM Native Image** biên dịch ứng dụng Java trước thời điểm chạy (*ahead-of-time compilation*) thành executable riêng cho nền tảng đích. Cách triển khai này có thể giảm thời gian khởi động và mức dùng bộ nhớ so với JVM trong những workload phù hợp, nhưng đòi hỏi phân tích tĩnh theo mô hình **closed-world**: phần lớn mã và tài nguyên cần thiết phải được nhận diện lúc build. Những truy cập động như reflection, JNI, resource loading, serialization hoặc proxy có thể cần **reachability metadata**; vì vậy một ứng dụng chạy đúng trên JVM chưa chắc chạy đúng sau khi biên dịch native. Module dành cho người đã biết Java, Maven/Gradle và Spring Boot cơ bản, muốn đánh giá và triển khai ứng dụng dưới dạng native executable.

Lộ trình bắt đầu từ nguyên lý Native Image và các đánh đổi với JVM, sau đó chuẩn bị GraalVM JDK cùng Native Build Tools cho Maven hoặc Gradle. Với Spring Boot, người học thực hiện **Spring AOT**, kiểm tra ứng dụng đã xử lý AOT trên JVM và tìm hiểu các hint được sinh ra. Các mốc tiếp theo tập trung vào reachability metadata cho reflection, resource, proxy, serialization và JNI; dùng tracing agent cùng metadata của thư viện để phát hiện thiếu đăng ký; rồi kiểm soát **class initialization** ở build time hoặc runtime. Cuối cùng là build/package bằng native plugin hoặc Cloud Native Buildpacks, kiểm thử AOT/native có chọn lọc và đo startup, memory, throughput cùng chi phí build.

Sau khi hoàn thành, bạn có thể tạo native executable cho một ứng dụng Java/Spring Boot thử nghiệm, chẩn đoán lỗi thiếu metadata, lựa chọn cách đóng gói và so sánh số đo với JVM trên cùng workload. Không nên mặc định native image luôn nhanh hơn hoặc nhỏ hơn trong mọi tình huống: hãy benchmark trên môi trường và dữ liệu đại diện, kiểm tra tính tương thích dependency, đồng thời giữ phần lớn unit/integration test trên JVM và bổ sung native tests cho những khu vực chịu ảnh hưởng bởi AOT hoặc truy cập động.
