# Tham số đặt tên, tham số danh sách và xử lý giá trị null trong HQL

## 1. Mục tiêu của parameter binding

HQL truy vấn theo entity và thuộc tính Java thay vì tên bảng/cột SQL. Query thường nhận giá trị như SKU, trạng thái hoặc danh sách ID.

Cách an toàn là viết query với placeholder rồi bind giá trị:

```java
List<InventoryItem> items = session.createQuery(
        "from InventoryItem i where i.sku = :sku",
        InventoryItem.class
    )
    .setParameter("sku", requestedSku)
    .getResultList();
```

`:sku` là named parameter; tên truyền vào `setParameter` là `"sku"`, không có dấu hai chấm. `requestedSku` được bind riêng, không nối vào chuỗi HQL.

Parameter binding tách dữ liệu khỏi cú pháp query, giảm nguy cơ injection do nối chuỗi, cho Hibernate biết kiểu dữ liệu và giữ cấu trúc query ổn định giữa nhiều lần thực thi.

## 2. Named parameters

### 2.1. Cú pháp cơ bản

Named parameter bắt đầu bằng dấu hai chấm:

```hql
from InventoryItem i
where i.sku = :sku
```

Bind bằng tên tương ứng:

```java
Query<InventoryItem> query = session.createQuery(
        """
        from InventoryItem i
        where i.sku = :sku
        """,
        InventoryItem.class
    );

query.setParameter("sku", "KB-101");

List<InventoryItem> result = query.getResultList();
```

Tên tham số trong HQL và tên truyền vào API phải khớp. Khi gọi `setParameter`, bỏ dấu `:`.

Có thể đặt nhiều named parameters trong cùng query:

```hql
from InventoryItem i
where i.sku = :sku
  and i.quantity >= :minimumQuantity
  and i.active = :active
```

```java
List<InventoryItem> result = session.createQuery(
        """
        from InventoryItem i
        where i.sku = :sku
          and i.quantity >= :minimumQuantity
          and i.active = :active
        """,
        InventoryItem.class
    )
    .setParameter("sku", "KB-101")
    .setParameter("minimumQuantity", 5)
    .setParameter("active", true)
    .getResultList();
```

Một named parameter có thể xuất hiện nhiều lần:

```hql
from PurchaseOrder o
where o.createdAt >= :fromTime
  and o.updatedAt >= :fromTime
```

```java
query.setParameter("fromTime", fromTime);
```

Cùng một giá trị được dùng ở cả hai vị trí. Named parameters thường dễ đọc và bảo trì hơn positional parameters khi query có nhiều điều kiện.

### 2.2. Tham số vị trí

HQL hỗ trợ positional parameters theo cú pháp ordinal như `?1`:

```hql
from InventoryItem i
where i.sku = ?1
  and i.quantity >= ?2
```

```java
List<InventoryItem> result = session.createQuery(
        """
        from InventoryItem i
        where i.sku = ?1
          and i.quantity >= ?2
        """,
        InventoryItem.class
    )
    .setParameter(1, "KB-101")
    .setParameter(2, 5)
    .getResultList();
```

Trong HQL/JPA hiện đại, ordinal parameter bắt đầu từ 1. Cú pháp JDBC dấu hỏi không đánh số `?` không phải cách viết positional parameter chuẩn cho HQL.

## 3. Bind giá trị, không nối chuỗi

Không nên tạo HQL bằng cách nối dữ liệu đầu vào:

```java
String hql =
        "from InventoryItem i where i.sku = '"
        + requestedSku
        + "'";

List<InventoryItem> items = session
        .createQuery(hql, InventoryItem.class)
        .getResultList();
```

Nếu `requestedSku` chứa dấu nháy hoặc nội dung được thiết kế để thay đổi cấu trúc query, câu HQL có thể bị phá vỡ hoặc dẫn đến injection.

Cách đúng:

```java
List<InventoryItem> items = session.createQuery(
        "from InventoryItem i where i.sku = :sku",
        InventoryItem.class
    )
    .setParameter("sku", requestedSku)
    .getResultList();
```

### 3.1. Parameter không thay thế tên entity, property hoặc keyword

Tham số dùng cho **giá trị**, không dùng để thay cấu trúc query:

```java
// Không dùng parameter như tên property.
String hql = "from InventoryItem i order by :sortProperty";
```

`:sortProperty` là một giá trị bind, không biến thành tên thuộc tính cần sắp xếp. Nếu cần sort động, chọn property từ danh sách cho phép rồi xây dựng phần cấu trúc HQL từ lựa chọn đã kiểm soát:

```java
String orderBy = switch (sortKey) {
    case "sku" -> "i.sku";
    case "quantity" -> "i.quantity";
    case "createdAt" -> "i.createdAt";
    default -> "i.id";
};

String hql = "from InventoryItem i order by " + orderBy;
```

`orderBy` phải đến từ whitelist cố định của ứng dụng, không phải chuỗi người dùng nhập. Hướng `ASC`/`DESC` cũng cần được kiểm soát bằng enum hoặc whitelist.

Binding không thay thế authorization. Các điều kiện tenant, ownership, soft delete và quyền truy cập vẫn phải được kiểm tra riêng.

## 4. Bind kiểu dữ liệu

Hibernate thường suy luận kiểu tham số từ thuộc tính được so sánh:

```hql
from InventoryItem i
where i.quantity >= :minimum
```

Vì `i.quantity` là kiểu số, Hibernate biết kiểu phù hợp khi bind `minimum`:

```java
query.setParameter("minimum", 10);
```

### 4.1. Enum và ngày giờ

Nếu entity có:

```java
@Enumerated(EnumType.STRING)
private OrderStatus status;
```

HQL và binding:

```java
List<PurchaseOrder> approved = session.createQuery(
        "from PurchaseOrder o where o.status = :status",
        PurchaseOrder.class
    )
    .setParameter("status", OrderStatus.APPROVED)
    .getResultList();
```

Nên bind enum object theo mapping thay vì tự chuyển sang chuỗi.

Với thời gian:

```hql
from PurchaseOrder o
where o.createdAt >= :fromTime
  and o.createdAt < :toTime
```

```java
query.setParameter("fromTime", fromTime);
query.setParameter("toTime", toTime);
```

Khoảng nửa mở `[fromTime, toTime)` thường giúp tránh lỗi biên khi timestamp có precision khác nhau. Kiểu Java, JDBC và database column phải được mapping phù hợp.

### 4.2. Bind type tường minh khi cần

Trong một số query, đặc biệt khi tham số null hoặc biểu thức không cung cấp đủ thông tin suy luận, có thể cần chỉ định kiểu. Hibernate cung cấp overload nhận Hibernate type:

```java
query.setParameter(
        "sku",
        requestedSku,
        StandardBasicTypes.STRING
);
```

API/type cụ thể thay đổi giữa các thế hệ Hibernate. Trong Hibernate 6, các type Hibernate nằm trong package `org.hibernate.type`; với JPA API portable, có overload dùng `Class` hoặc `TemporalType` cho trường hợp phù hợp.

Không thêm type tường minh máy móc nếu Hibernate đã suy luận chính xác từ thuộc tính HQL.

## 5. Tham số danh sách trong IN

### 5.1. Collection parameter

Một bộ lọc có thể nhận nhiều ID:

```java
List<Long> ids = List.of(10L, 20L, 30L);
```

Dùng collection-valued parameter trong mệnh đề `IN`:

```hql
from InventoryItem i
where i.id in :ids
```

Bind collection:

```java
List<InventoryItem> result = session.createQuery(
        """
        from InventoryItem i
        where i.id in :ids
        """,
        InventoryItem.class
    )
    .setParameter("ids", ids)
    .getResultList();
```

Collection-valued parameter được dùng ở vị trí phù hợp như mệnh đề `IN`. Với JPA `Query`, collection parameter cũng được hỗ trợ cho biểu thức IN theo đặc tả.

### 5.2. SQL được mở rộng

Với danh sách ba ID, SQL có thể được mở rộng thành:

```sql
SELECT i.id, i.sku, i.quantity
FROM inventory_items i
WHERE i.id IN (?, ?, ?);
```

Hibernate bind từng phần tử thành JDBC parameter. Danh sách được mở rộng thành số placeholder tương ứng; ứng dụng không cần tự tạo chuỗi dấu phẩy.

### 5.3. Kết hợp list parameter với scalar parameters

```hql
from InventoryItem i
where i.id in :ids
  and i.active = :active
  and i.quantity >= :minimumQuantity
```

```java
List<InventoryItem> result = session.createQuery(
        """
        from InventoryItem i
        where i.id in :ids
          and i.active = :active
          and i.quantity >= :minimumQuantity
        """,
        InventoryItem.class
    )
    .setParameter("ids", ids)
    .setParameter("active", true)
    .setParameter("minimumQuantity", 5)
    .getResultList();
```

Một query có thể kết hợp scalar parameters và collection parameters. Mỗi tham số vẫn cần bind đúng tên và kiểu.

### 5.4. `setParameterList` trong Hibernate API

Hibernate native query API còn có phương thức `setParameterList`:

```java
org.hibernate.query.Query<InventoryItem> query =
        session.createQuery(
            "from InventoryItem i where i.id in :ids",
            InventoryItem.class
        );

query.setParameterList("ids", ids);
```

Đây là API Hibernate-specific. Khi code chỉ dùng Jakarta Persistence `Query`, có thể dùng `setParameter("ids", collection)` cho collection-valued parameter trong `IN`:

```java
TypedQuery<InventoryItem> query = em.createQuery(
        "select i from InventoryItem i where i.id in :ids",
        InventoryItem.class
);

query.setParameter("ids", ids);
```

Chọn API theo abstraction của dự án. Không cần ép toàn bộ code dùng `Session` nếu ứng dụng đã chuẩn hóa trên `EntityManager`.

## 6. Danh sách rỗng và danh sách lớn

Một collection parameter có thể rỗng. SQL không có cú pháp portable cho `IN ()`; cách provider xử lý list rỗng có thể khác theo Hibernate version và dialect. Nên xử lý ở tầng ứng dụng:

```java
if (ids.isEmpty()) {
    return List.of();
}
```

Phân biệt `null` list (không cung cấp hoặc input không hợp lệ), empty list (không chọn phần tử nào) và list có phần tử. Không dùng cùng một trạng thái cho cả “bỏ filter” và “không có kết quả”.

Danh sách rất lớn có thể vượt giới hạn bind parameters của database/driver. Có thể chia batch, dùng staging table hoặc cơ chế array/table-valued parameter nếu dialect hỗ trợ. `IN` không bảo đảm giữ thứ tự danh sách đầu vào.

## 7. NULL trong SQL/HQL

Phép so sánh `= NULL` không trả TRUE; kết quả là UNKNOWN theo logic ba giá trị. Để tìm cột null, dùng:

```hql
from InventoryItem i where i.description is null
```

Để loại hàng null:

```hql
from InventoryItem i where i.description is not null
```

| Biểu thức | Kết quả |
|---|---|
| `'A' = 'A'` | TRUE |
| `'A' = 'B'` | FALSE |
| `NULL = 'A'` | UNKNOWN |
| `NULL = NULL` | UNKNOWN |
| `NULL IS NULL` | TRUE |

Trong WHERE, chỉ hàng có predicate TRUE được giữ. FALSE và UNKNOWN đều bị loại. Bind null vào `field = :p` không tương đương `field IS NULL`.

## 8. Null là bỏ filter hay tìm hàng null?

Một bộ lọc tùy chọn có thể viết:

```hql
from InventoryItem i
where (:description is null or i.description = :description)
```

Khi parameter null, vế đầu TRUE nên điều kiện được bỏ qua. Khi parameter có giá trị, vế so sánh quyết định kết quả.

Điều này khác với yêu cầu chỉ lấy hàng có cột null:

```hql
where i.description is null
```

Nếu API cần ba trạng thái (bỏ filter, so sánh giá trị, tìm null), dùng mode/enum riêng thay vì cố biểu diễn cả ba bằng một String nullable.

## 9. NULL trong IN và NOT IN

Nếu collection có phần tử null, biểu thức `IN` có thể trả UNKNOWN cho những hàng không khớp các giá trị non-null. NULL trong list không phải cách kiểm tra cột null. Lọc null khỏi collection; chỉ thêm `OR field IS NULL` khi business rule yêu cầu.

```sql
SELECT *
FROM inventory_items
WHERE sku NOT IN ('A', NULL);
```

`NOT IN` có thể trở thành UNKNOWN cho nhiều hàng khi list/subquery chứa NULL. Với ý nghĩa “không tồn tại bản ghi liên quan”, `NOT EXISTS` thường dễ diễn đạt hơn:

```hql
from InventoryItem i
where not exists (
    select h.id
    from InventoryHistory h
    where h.inventoryItem = i
)
```

## 10. Tham số null và suy luận kiểu

Khi parameter chỉ xuất hiện trong `:value is null` mà không có thuộc tính giúp suy luận type, Hibernate có thể cần kiểu tường minh. Có thể dùng overload nhận `Class` hoặc Hibernate type phù hợp với phiên bản.

Không chuyển null thành chuỗi `"null"`. Null Java và chuỗi ký tự n-u-l-l là hai giá trị khác nhau.

## 11. Tìm kiếm theo pattern với named parameter

HQL hỗ trợ `LIKE`:

```hql
from InventoryItem i
where i.sku like :pattern
```

Bind pattern bằng `setParameter`. Nếu input chứa wildcard `%` hoặc `_` mà yêu cầu là tìm literal, escape chúng và khai báo escape character:

```hql
from InventoryItem i
where i.description like :pattern escape '!'
```

```java
static String escapeLike(String input) {
    return input
        .replace("!", "!!")
        .replace("%", "!%")
        .replace("_", "!_");
}
```

Binding ngăn injection nhưng không tự biến wildcard thành ký tự literal.

## 12. Criteria API cho filter động

Khi có nhiều predicate tùy chọn, Criteria API giúp chỉ thêm điều kiện thực sự được cung cấp:

```java
CriteriaBuilder cb = em.getCriteriaBuilder();
CriteriaQuery<InventoryItem> cq =
        cb.createQuery(InventoryItem.class);
Root<InventoryItem> root = cq.from(InventoryItem.class);

List<Predicate> predicates = new ArrayList<>();

if (filter.sku() != null && !filter.sku().isBlank()) {
    predicates.add(cb.like(root.get("sku"), filter.sku() + "%"));
}

if (filter.active() != null) {
    predicates.add(cb.equal(root.get("active"), filter.active()));
}

if (filter.categoryIds() != null) {
    if (filter.categoryIds().isEmpty()) {
        return List.of();
    }
    predicates.add(root.get("category").get("id").in(filter.categoryIds()));
}

cq.select(root).where(predicates.toArray(Predicate[]::new));
return em.createQuery(cq).getResultList();
```

Criteria API hữu ích khi filter có nhiều tổ hợp. Giá trị vẫn được bind do provider quản lý.

## 13. Query plan và list parameters

Named parameter giữ cấu trúc HQL ổn định giữa các giá trị khác nhau. Collection parameter có kích thước khác nhau có thể tạo SQL có số placeholder khác nhau. Vì vậy query plan cache, JDBC statement cache và database plan cache là các lớp khác nhau; không giả định một HQL string giống nhau luôn tạo một execution plan duy nhất.

## 14. Các lỗi thường gặp

| Lỗi | Nguyên nhân | Cách xử lý |
|---|---|---|
| Không tìm thấy parameter | Tên bind không khớp HQL | So lại tên, bỏ dấu hai chấm khi gọi API |
| Sort bằng parameter không hoạt động | Parameter chỉ bind value | Whitelist tên property/order direction |
| IN với list rỗng lỗi hoặc có semantics không rõ | SQL không có IN () portable | Short-circuit ở ứng dụng |
| List lớn gây lỗi DB | Vượt giới hạn bind parameters | Chia batch/staging |
| Bind null vào field = :p không tìm được hàng null | SQL three-valued logic | Dùng IS NULL |
| Null filter vô tình bỏ hết kết quả | Chưa định nghĩa null là bỏ filter hay tìm null | Optional predicate hoặc mode riêng |
| NOT IN bị ảnh hưởng bởi NULL | Predicate có thể thành UNKNOWN | Lọc null hoặc NOT EXISTS |
| LIKE không tìm wildcard literal | % và _ là wildcard | Escape pattern |
| Query nhiều OR chậm | Optimizer khó chọn plan | Criteria động hoặc biến thể query |

## 15. Quy trình xây dựng query an toàn

1. Xác định null, rỗng và không cung cấp có nghĩa gì.
2. Dùng named scalar parameter cho giá trị đơn và collection parameter cho IN.
3. Validate kiểu, miền giá trị và kích thước danh sách.
4. Bind mọi giá trị; không nối input vào HQL.
5. Xử lý list rỗng và null element trước khi chạy query.
6. Phân biệt IS NULL với optional filter.
7. Kiểm tra SQL, bind count và execution plan trên database thực tế.
8. Test null, rỗng, list một phần tử, list nhiều phần tử, list có null và ký tự wildcard.

## 16. Bài tập thực hành

- Viết query tìm InventoryItem theo SKU bằng named parameter.
- Kết hợp scalar parameter và list parameter trong cùng query.
- So sánh list có 1, 3 và 100 ID qua SQL log.
- Truyền list rỗng và short-circuit ở repository.
- So sánh field = :p khi bind null với field IS NULL.
- Viết optional filter và chạy với null, true, false.
- Thử NOT IN với list chứa null rồi thay bằng NOT EXISTS.
- Escape % và _ trong LIKE.
- Tạo filter động bằng Criteria API.
- Đo query plan và giới hạn bind parameters với list lớn.

## 17. Câu hỏi tự kiểm tra

**1. Named parameter viết thế nào?**

Dùng `:parameterName` và bind bằng `setParameter("parameterName", value)`.

**2. Có cần truyền dấu hai chấm vào setParameter không?**

Không. Truyền tên không có dấu hai chấm.

**3. Parameter có thể thay tên property không?**

Không. Nó chỉ thay giá trị; cấu trúc query phải được kiểm soát riêng.

**4. Collection parameter dùng ở đâu?**

Trong vị trí collection-valued phù hợp, thường là IN.

**5. Có nên chạy query với list rỗng?**

Nên short-circuit để semantics không phụ thuộc provider/dialect.

**6. Field = :p với p null có tìm field null không?**

Không. Dùng IS NULL.

**7. Null filter nghĩa là bỏ điều kiện thế nào?**

Dùng optional predicate hoặc chỉ thêm predicate khi input có giá trị.

**8. NOT IN với NULL có thể gây gì?**

Predicate có thể thành UNKNOWN và loại hàng ngoài ý muốn.

**9. Binding có thay thế authorization không?**

Không. Tenant, ownership và quyền truy cập vẫn cần được kiểm tra.

**10. Vì sao list lớn cần chia batch?**

Mỗi phần tử tạo bind placeholder và có thể vượt giới hạn database/driver.

## 18. Ghi nhớ

- Named parameter viết bằng `:name`; bind bằng `setParameter("name", value)`.
- Parameter chỉ thay giá trị, không thay tên entity/property hoặc cấu trúc ORDER BY.
- Collection parameter dùng trong `IN`; Hibernate mở rộng thành JDBC placeholders.
- Xử lý list rỗng trước khi chạy query; phân biệt null list, empty list và list có phần tử.
- Danh sách lớn có thể vượt giới hạn bind parameters; cân nhắc batch hoặc staging table.
- `column = NULL` không đúng; dùng `IS NULL`/`IS NOT NULL`.
- “Null nghĩa bỏ filter” khác “tìm hàng có cột null”.
- `NOT IN` nhạy với NULL; lọc null hoặc cân nhắc `NOT EXISTS`.
- Khi type inference không đủ, bind type tường minh theo API đang dùng.
- Binding không escape wildcard LIKE, không whitelist sort field và không thay thế authorization.
