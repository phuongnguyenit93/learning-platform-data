# Chọn thực thể, giá trị vô hướng và kiểu kết quả mong đợi trong HQL

Trong HQL, phần SELECT quyết định **mỗi dòng kết quả đại diện cho điều gì**: một entity được Hibernate quản lý, một giá trị đơn như tên hoặc giá, một kết quả tổng hợp như COUNT, hay một cấu trúc gồm nhiều giá trị. Kiểu dữ liệu mà ứng dụng khai báo khi tạo query phải phù hợp với biểu thức được chọn; nếu không, lỗi có thể xuất hiện khi tạo query, khi đọc kết quả hoặc dưới dạng ép kiểu sai trong code.

HQL truy vấn **mô hình entity và thuộc tính Java**, không truy vấn trực tiếp tên bảng/cột như SQL. Vì vậy SELECT b, SELECT b.title và SELECT count(b) đều có thể đọc từ cùng entity Book, nhưng ba query trả về ba loại kết quả khác nhau:

- **Book:** entity, có thể được quản lý trong persistence context.
- **String:** giá trị vô hướng lấy từ thuộc tính.
- **Long:** giá trị tổng hợp do count trả về.

Bài này trình bày HQL trong Hibernate ORM 6.x và đối chiếu các cách tạo query bằng Jakarta Persistence. Trọng tâm là **chọn đúng loại kết quả và khai báo kiểu mong đợi**, để code đọc rõ ràng, tránh Object[] khó bảo trì và không nhầm DTO projection với entity managed.

## 1. Mô hình ví dụ

Giả sử ứng dụng quản lý sách:

~~~java
import jakarta.persistence.*;
import java.math.BigDecimal;

@Entity
@Table(name = "books")
public class Book {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false, length = 200)
    private String title;

    @Column(nullable = false, precision = 12, scale = 2)
    private BigDecimal price;

    @Enumerated(EnumType.STRING)
    @Column(nullable = false, length = 20)
    private BookStatus status;

    protected Book() {}

    public Long getId() { return id; }
    public String getTitle() { return title; }
    public BigDecimal getPrice() { return price; }
    public BookStatus getStatus() { return status; }
}

public enum BookStatus {
    DRAFT, PUBLISHED, ARCHIVED
}
~~~

Giả sử Book còn có quan hệ tới Author:

~~~java
@ManyToOne(fetch = FetchType.LAZY)
@JoinColumn(name = "author_id")
private Author author;
~~~

Các ví dụ giả định EntityManager hoặc Session đã được cấu hình. Getter, constructor và field phụ không liên quan được lược bỏ để tập trung vào query result.

## 2. Chọn entity: trả về đối tượng được ánh xạ

### 2.1. Chọn toàn bộ entity

~~~java
List<Book> books = entityManager.createQuery(
        "select b from Book b",
        Book.class
    )
    .getResultList();
~~~

Book là tên **entity name** trong persistence model, thường mặc định là tên lớp. b là identification variable (alias) đại diện cho mỗi entity trong query. SELECT b yêu cầu kết quả là chính các entity Book.

Có thể viết HQL ngắn hơn:

~~~sql
from Book b
~~~

Khi bỏ SELECT, HQL mặc định chọn root entity trong FROM theo quy tắc của HQL. Trong tài liệu và code cần minh bạch kiểu kết quả, viết SELECT b FROM Book b thường dễ đọc hơn.

### 2.2. Entity được query trả về có managed không?

Nếu query chạy trong persistence context đang mở, entity được chọn thường là **managed entity**:

~~~java
Book book = entityManager.createQuery(
        "select b from Book b where b.id = :id",
        Book.class
    )
    .setParameter("id", 10L)
    .getSingleResult();

boolean managed = entityManager.contains(book);
~~~

contains(book) có thể trả true vì entity thuộc persistence context hiện tại. Nếu entity cùng identity đã được tải trước đó trong context, Hibernate dùng instance managed tương ứng thay vì tạo một bản sao managed độc lập.

Điều này có nghĩa:

- Thay đổi field trên entity managed có thể được dirty checking ghi xuống database khi flush.
- Lazy association vẫn có thể chưa được khởi tạo; chọn entity không đồng nghĩa toàn bộ graph đã loaded.
- Nếu entity bị detach hoặc persistence context đóng, object Java vẫn tồn tại nhưng không còn được theo dõi.
- Kết quả entity chịu ảnh hưởng của inheritance mapping và tính đa hình; query trên entity cha có thể trả về các subclass phù hợp.

### 2.3. Chọn một association cũng có thể trả entity

~~~java
List<Author> authors = entityManager.createQuery(
        "select distinct b.author " +
        "from Book b " +
        "where b.status = :status and b.author is not null",
        Author.class
    )
    .setParameter("status", BookStatus.PUBLISHED)
    .getResultList();
~~~

b.author là association-valued path, nên kết quả là entity Author, không phải chuỗi tên tác giả. Nếu chỉ cần tên, chọn b.author.name:

~~~java
List<String> authorNames = entityManager.createQuery(
        "select b.author.name " +
        "from Book b " +
        "where b.status = :status and b.author is not null",
        String.class
    )
    .setParameter("status", BookStatus.PUBLISHED)
    .getResultList();
~~~

Sự khác biệt nằm ở **biểu thức được chọn**: entity path trả entity; basic-valued path trả giá trị của thuộc tính.

## 3. Chọn giá trị vô hướng (scalar value)

Scalar selection trả về một giá trị Java tương ứng với biểu thức trong SELECT, ví dụ:

~~~java
List<String> titles = entityManager.createQuery(
        "select b.title from Book b order by b.title",
        String.class
    )
    .getResultList();
~~~

Một số ví dụ khác:

~~~java
List<Long> ids = entityManager.createQuery(
        "select b.id from Book b",
        Long.class
    )
    .getResultList();

List<BigDecimal> prices = entityManager.createQuery(
        "select b.price from Book b",
        BigDecimal.class
    )
    .getResultList();

List<BookStatus> statuses = entityManager.createQuery(
        "select b.status from Book b",
        BookStatus.class
    )
    .getResultList();
~~~

Scalar projection phù hợp khi caller chỉ cần một field hoặc một expression. Hibernate không cần trả một Book managed đầy đủ chỉ để ứng dụng đọc title.

### 3.1. Scalar không phải entity managed

~~~java
String title = entityManager.createQuery(
        "select b.title from Book b where b.id = :id",
        String.class
    )
    .setParameter("id", 10L)
    .getSingleResult();
~~~

title là một giá trị Java. Nó không phải entity, không có identity trong persistence context và không được dirty checking như Book. Sửa một biến chuỗi cục bộ không làm thay đổi entity trong database.

Tương tự, b.id trả identifier value; nó không trả một entity Book. Nếu cần entity để thay đổi trạng thái, chọn b hoặc tải entity theo ID.

### 3.2. Biểu thức scalar

HQL có thể chọn biểu thức, không chỉ field:

~~~java
List<String> normalizedTitles = entityManager.createQuery(
        "select lower(b.title) from Book b",
        String.class
    )
    .getResultList();
~~~

Ví dụ với CASE:

~~~java
List<String> labels = entityManager.createQuery(
        "select case " +
        "when b.status = :published then 'Public' " +
        "else 'Internal' end " +
        "from Book b",
        String.class
    )
    .setParameter("published", BookStatus.PUBLISHED)
    .getResultList();
~~~

Kiểu kết quả của expression được suy ra từ các nhánh và kiểu toán hạng. Khi dùng CASE, phép toán số học, hàm chuỗi, hàm ngày giờ hoặc COALESCE, hãy bảo đảm các nhánh có kiểu tương thích và result class phản ánh đúng kiểu Java mong đợi.

### 3.3. Null trong scalar result

Một thuộc tính nullable có thể trả null trong danh sách kết quả:

~~~java
List<String> subtitles = entityManager.createQuery(
        "select b.subtitle from Book b",
        String.class
    )
    .getResultList();
~~~

Nếu subtitle nullable, một phần tử trong subtitles có thể null. Không dùng primitive result type như int.class cho biểu thức có thể null; dùng wrapper hoặc kiểu tham chiếu phù hợp.

NOT NULL ở schema/entity mapping là một quy tắc dữ liệu khác. Kiểu query không tự làm một giá trị nullable trở thành non-null.

## 4. Chọn kết quả tổng hợp

Các hàm aggregate thường trả về scalar:

~~~java
Long totalBooks = entityManager.createQuery(
        "select count(b) from Book b",
        Long.class
    )
    .getSingleResult();
~~~

Các kiểu kết quả quan trọng theo semantics JPQL/HQL:

| Biểu thức | Kiểu kết quả Java thông thường |
| --- | --- |
| count(...) | Long |
| avg(...) | Double |
| min(x), max(x) | Kiểu của biểu thức x |
| sum() trên kiểu số nguyên thông thường | Long |
| sum() trên BigInteger | BigInteger |
| sum() trên BigDecimal | BigDecimal |
| sum() trên kiểu dấu phẩy động | Double |

Cần xem đúng kiểu thuộc tính và quy tắc của Jakarta Persistence/Hibernate cho biểu thức số. Đừng mặc định count trả Integer chỉ vì số lượng nhỏ.

### 4.1. Count, sum và average

~~~java
Long publishedCount = entityManager.createQuery(
        "select count(b) from Book b " +
        "where b.status = :status",
        Long.class
    )
    .setParameter("status", BookStatus.PUBLISHED)
    .getSingleResult();

BigDecimal totalPrice = entityManager.createQuery(
        "select sum(b.price) from Book b",
        BigDecimal.class
    )
    .getSingleResult();

Double averagePrice = entityManager.createQuery(
        "select avg(b.price) from Book b",
        Double.class
    )
    .getSingleResult();
~~~

count trả 0 khi không có dòng phù hợp. Với sum, avg, min và max không có giá trị đầu vào phù hợp, kết quả thường là null theo semantics aggregate. Vì vậy totalPrice và averagePrice có thể null nếu bảng rỗng hoặc không có giá trị phù hợp; code cần xử lý trường hợp này.

### 4.2. Aggregate kết hợp GROUP BY

~~~java
List<Object[]> rows = entityManager.createQuery(
        "select b.status, count(b) " +
        "from Book b " +
        "group by b.status",
        Object[].class
    )
    .getResultList();

for (Object[] row : rows) {
    BookStatus status = (BookStatus) row[0];
    Long count = (Long) row[1];
}
~~~

Mỗi result row có hai phần tử theo đúng thứ tự trong SELECT: BookStatus, rồi Long. Đây là multiselect; kiểu result không còn là một scalar đơn.

Có thể dùng DTO projection để tránh index-based access, được trình bày ở phần sau.

## 5. Chọn nhiều biểu thức: multiselect và Object[]

Khi SELECT có nhiều biểu thức, dạng kết quả phổ biến trong query không khai báo DTO là Object[]:

~~~java
List<Object[]> rows = entityManager.createQuery(
        "select b.title, b.price from Book b",
        Object[].class
    )
    .getResultList();

for (Object[] row : rows) {
    String title = (String) row[0];
    BigDecimal price = (BigDecimal) row[1];
}
~~~

Thứ tự các phần tử phụ thuộc thứ tự biểu thức:

~~~text
select b.title, b.price, b.status
       row[0]    row[1]   row[2]
       String    BigDecimal BookStatus
~~~

Object[] hữu ích cho truy vấn nhanh hoặc dữ liệu động, nhưng có một số nhược điểm:

- Code phải nhớ index và cast.
- Đổi thứ tự select list có thể làm sai logic ở caller mà compiler không phát hiện.
- Tên field/ý nghĩa không được thể hiện rõ trong kiểu kết quả.
- Null và kiểu runtime chỉ được kiểm tra khi đọc phần tử.

Với projection được dùng lâu dài trong service/API, DTO constructor projection thường dễ bảo trì hơn.

### 5.1. Nhiều entity hoặc entity kết hợp scalar

~~~java
List<Object[]> rows = entityManager.createQuery(
        "select b, b.title from Book b",
        Object[].class
    )
    .getResultList();

for (Object[] row : rows) {
    Book book = (Book) row[0];
    String title = (String) row[1];
}
~~~

row[0] là entity Book và có thể managed trong context; row[1] là scalar String. Việc một row chứa entity không biến toàn bộ Object[] thành entity. Hãy xác định riêng kiểu và lifecycle của từng selection.

## 6. DTO constructor projection: kiểu kết quả có tên và có cấu trúc

Nếu caller cần vài trường nhưng không cần entity managed, dùng DTO.

### 6.1. Khai báo DTO

~~~java
package com.example.book;

import java.math.BigDecimal;

public record BookSummary(
        Long id,
        String title,
        BigDecimal price
) {}
~~~

Record có canonical constructor khớp ba kiểu tham số. Có thể dùng class thông thường với constructor tương ứng.

### 6.2. JPQL/HQL constructor expression

~~~java
List<BookSummary> summaries = entityManager.createQuery(
        "select new com.example.book.BookSummary(" +
        "b.id, b.title, b.price) " +
        "from Book b " +
        "where b.status = :status",
        BookSummary.class
    )
    .setParameter("status", BookStatus.PUBLISHED)
    .getResultList();
~~~

select new yêu cầu tên lớp đầy đủ (fully qualified class name) trong constructor expression theo JPQL. Thứ tự và kiểu của các biểu thức phải khớp constructor. DTO không phải entity chỉ vì query của nó đọc từ bảng entity; nó không được quản lý trong persistence context.

Ưu điểm:

- Caller nhận kiểu rõ ràng, không cần cast Object[].
- Chỉ lấy các cột cần thiết.
- Không tạo entity managed chỉ để đọc.
- Có thể định nghĩa projection phù hợp với API/report.
- Không kéo theo lifecycle và lazy associations của entity gốc.

### 6.3. DTO constructor với aggregate

~~~java
public record StatusCount(
        BookStatus status,
        Long total
) {}
~~~

~~~java
List<StatusCount> counts = entityManager.createQuery(
        "select new com.example.book.StatusCount(" +
        "b.status, count(b)) " +
        "from Book b " +
        "group by b.status",
        StatusCount.class
    )
    .getResultList();
~~~

Kiểu tham số thứ hai phải tương ứng Long, vì count trả Long. Nếu khai báo constructor nhận Integer, query có thể không tìm được constructor phù hợp hoặc lỗi khi khởi tạo kết quả.

### 6.4. DTO và entity có lifecycle khác nhau

| Đặc điểm | Entity selection | DTO constructor projection |
| --- | --- | --- |
| Ví dụ | select b from Book b | select new BookSummary(...) |
| Kết quả | Book entity | BookSummary |
| Managed trong persistence context | Có thể có, nếu query trong context | Không |
| Dirty checking | Có với entity managed | Không |
| Lazy association | Có thể có proxy/collection lazy | Chỉ chứa dữ liệu constructor đã chọn |
| Mục đích phù hợp | Đọc/chỉnh sửa aggregate/entity | Read model, API response, báo cáo |
| Dữ liệu được chọn | Entity state theo mapping/fetch plan | Những expression được liệt kê |

Không dùng DTO projection nếu nghiệp vụ cần thay đổi entity managed rồi dựa vào dirty checking. Ngược lại, không tải entity graph lớn chỉ để hiển thị ba cột.

## 7. Hibernate 6 và typed result packaging

Ngoài constructor expression select new, Hibernate HQL 6 hỗ trợ cách khai báo result type khi tạo query để đóng gói nhiều selection vào lớp kết quả phù hợp constructor:

~~~java
List<BookSummary> summaries = entityManager.createQuery(
        "select b.id, b.title, b.price from Book b",
        BookSummary.class
    )
    .getResultList();
~~~

Đây là **khả năng đóng gói kết quả của Hibernate HQL**, không nên mặc định là cách viết portable cho mọi JPA provider và mọi JPQL version. Với code cần tương thích JPA, dùng constructor expression select new com.example.book.BookSummary(...).

Hibernate cần tìm constructor phù hợp với các biểu thức selection theo thứ tự. Nếu lớp không có constructor khớp kiểu hoặc số lượng tham số, query có thể thất bại khi khởi tạo/kiểm tra result packaging. Hãy kiểm tra tài liệu đúng Hibernate version trước khi chọn cách viết ngắn này.

### 7.1. Khi nào nên dùng cách nào?

- **Portable JPA:** constructor expression select new.
- **Hibernate HQL 6 và muốn typed result packaging:** có thể truyền result class tương ứng khi tạo query.
- **Dữ liệu động, số selection thay đổi:** Object[] hoặc cấu trúc result phù hợp.
- **Cần tên alias và truy cập theo tên:** cân nhắc Tuple trong Criteria API hoặc API Hibernate phù hợp.

Không trộn cú pháp portable và extension Hibernate mà không ghi rõ yêu cầu provider; điều này đặc biệt quan trọng trong thư viện dùng chung hoặc ứng dụng có kế hoạch đổi JPA provider.

## 8. Tuple và alias: truy cập kết quả nhiều cột có tên

JPA Criteria API hỗ trợ Tuple cho projection nhiều selection có alias:

~~~java
import jakarta.persistence.Tuple;
import jakarta.persistence.criteria.*;

CriteriaBuilder cb = entityManager.getCriteriaBuilder();
CriteriaQuery<Tuple> cq = cb.createTupleQuery();
Root<Book> book = cq.from(Book.class);

cq.multiselect(
    book.get("title").alias("title"),
    book.get("price").alias("price")
);

List<Tuple> rows = entityManager.createQuery(cq).getResultList();

for (Tuple row : rows) {
    String title = row.get("title", String.class);
    BigDecimal price = row.get("price", BigDecimal.class);
}
~~~

Tuple cho phép truy cập theo alias thay vì index. Alias phải duy nhất trong tuple result và tên truyền vào row.get("title", String.class) phải khớp alias.

HQL cũng hỗ trợ alias cho selection:

~~~sql
select b.title as title, b.price as price
from Book b
~~~

Cách tiêu thụ tuple/alias phụ thuộc API query được sử dụng. Nếu dùng JPA Criteria Tuple, đoạn trên cho thấy cách portable. Nếu dùng Hibernate-specific HQL result packaging hoặc tuple API, đối chiếu đúng Hibernate version. Không giả định mọi createQuery(String, Tuple.class) có semantics giống CriteriaQuery<Tuple> trên mọi provider.

## 9. Chọn entity, scalar, DTO hay Tuple?

| Nhu cầu | Kiểu kết quả nên cân nhắc | Vì sao |
| --- | --- | --- |
| Sửa trạng thái một Book | Book | Cần entity managed và dirty checking |
| Lấy danh sách title | String | Chỉ cần một scalar |
| Lấy ID và price cho export | DTO hoặc Object[] | Nhiều cột nhưng không cần entity |
| Đếm số sách | Long | Aggregate count trả Long |
| Báo cáo theo status | DTO hoặc Tuple | Nhiều giá trị có ý nghĩa rõ |
| Chọn author để dùng trong domain logic | Author | Association path trả entity |
| Chỉ hiển thị author name | String hoặc DTO | Không cần entity Author |
| Dữ liệu động nhiều selection | Object[]/Tuple phù hợp | Cấu trúc có thể thay đổi |
| API read-only cần ít field | DTO projection | Tránh hydrate entity graph |
| Cần thay đổi một phần aggregate | Entity selection | Giữ persistence context quản lý state |

Một nguyên tắc thực dụng: **chọn loại kết quả nhỏ nhất vẫn đáp ứng mục đích của use case**. Nếu chỉ cần giá trị, không cần hydrate entity. Nếu cần hành vi domain và cập nhật, hãy chọn entity.

## 10. DISTINCT: loại trùng trong kết quả selection

Khi join một quan hệ to-many, một entity root có thể xuất hiện trên nhiều dòng SQL:

~~~java
List<Book> books = entityManager.createQuery(
        "select distinct b " +
        "from Book b join b.tags t " +
        "where t.name in :names",
        Book.class
    )
    .setParameter("names", tagNames)
    .getResultList();
~~~

distinct diễn đạt rằng kết quả selection cần loại trùng. Với scalar:

~~~java
List<String> categories = entityManager.createQuery(
        "select distinct b.category from Book b",
        String.class
    )
    .getResultList();
~~~

Với DTO projection, nếu muốn loại những DTO có giá trị selection trùng nhau, cần xem các expression trong select list và semantics của distinct. distinct trên entity selection không đồng nghĩa database chỉ đọc một hàng; SQL join và số dòng trung gian vẫn có chi phí.

Hibernate 6 có xử lý loại duplicate root entity trong một số trường hợp fetch join. Tuy nhiên, khi query dùng join thông thường và selection có thể trùng, hãy diễn đạt rõ bằng distinct nếu kết quả nghiệp vụ yêu cầu duy nhất. Không dùng distinct để che một query join sai hoặc để tránh hiểu cardinality.

## 11. Kiểu kết quả và số lượng kết quả là hai vấn đề riêng

Typed query trả lời câu hỏi **mỗi kết quả có kiểu gì**. getSingleResult() hay getResultList() trả lời **có bao nhiêu kết quả**.

~~~java
Book book = entityManager.createQuery(
        "select b from Book b where b.id = :id",
        Book.class
    )
    .setParameter("id", 10L)
    .getSingleResult();
~~~

Nếu không có hàng phù hợp, getSingleResult() ném NoResultException. Nếu có nhiều hơn một kết quả, nó ném NonUniqueResultException. Kiểu Book.class không tự bảo đảm điều kiện lọc là duy nhất.

Nếu query có thể trả 0 hoặc nhiều hàng, dùng getResultList():

~~~java
List<Book> books = entityManager.createQuery(
        "select b from Book b where b.status = :status",
        Book.class
    )
    .setParameter("status", BookStatus.PUBLISHED)
    .getResultList();
~~~

Danh sách có thể rỗng; không có exception chỉ vì không có row.

### 11.1. Một aggregate query thường trả một row

~~~java
Long count = entityManager.createQuery(
        "select count(b) from Book b where b.status = :status",
        Long.class
    )
    .setParameter("status", BookStatus.PUBLISHED)
    .getSingleResult();
~~~

count không có GROUP BY trả một giá trị tổng hợp, kể cả khi không có sách nào phù hợp; giá trị lúc đó là 0. Nhưng sum hoặc avg trên tập rỗng có thể trả null. Kiểu kết quả và nullability vẫn phải được xử lý riêng.

### 11.2. GROUP BY có thể trả nhiều dòng

~~~java
List<Object[]> counts = entityManager.createQuery(
        "select b.status, count(b) " +
        "from Book b group by b.status",
        Object[].class
    )
    .getResultList();
~~~

Query này có thể trả nhiều dòng, một dòng cho mỗi status xuất hiện. Gọi getSingleResult() là sai nếu nghiệp vụ không bảo đảm chỉ có một group.

## 12. TypedQuery, Query và kiểu mong đợi

### 12.1. Dùng typed query

~~~java
TypedQuery<Book> query = entityManager.createQuery(
        "select b from Book b",
        Book.class
);

List<Book> books = query.getResultList();
~~~

Kiểu generic giúp compiler kiểm tra phần lớn việc sử dụng kết quả. Tương tự:

~~~java
TypedQuery<String> query = entityManager.createQuery(
        "select b.title from Book b",
        String.class
);
~~~

Đây là cách nên ưu tiên trong code ứng dụng vì thể hiện rõ contract.

### 12.2. Query không kiểu và cast thủ công

~~~java
Query query = entityManager.createQuery(
        "select b.title from Book b"
);

List<?> values = query.getResultList();
~~~

Không nên tùy tiện cast:

~~~java
// Rủi ro: code giả định result là Book nhưng HQL chọn String.
List<Book> books = (List<Book>) query.getResultList();
~~~

Query không giúp compiler biết kiểu thực tế. Nếu select list thay đổi, lỗi có thể chỉ xuất hiện khi caller cast hoặc đọc phần tử. Dùng typed query với result class khớp selection.

### 12.3. Typed result class không thay thế việc hiểu select list

~~~java
// Đúng: entity selection và Book.class
entityManager.createQuery(
    "select b from Book b",
    Book.class
);

// Đúng: scalar String selection và String.class
entityManager.createQuery(
    "select b.title from Book b",
    String.class
);
~~~

Không khai báo Book.class khi query chỉ chọn b.title, cũng không khai báo String.class khi query chọn entity b. Nếu nhiều selection, chọn Object[].class, DTO class theo constructor packaging được hỗ trợ, hoặc API Tuple phù hợp.

## 13. Kiểu của biểu thức trong HQL

Kiểu kết quả không chỉ đến từ field mà còn từ toán tử và hàm:

| HQL expression | Kết quả thường gặp |
| --- | --- |
| b.title | String |
| b.id | Kiểu identifier được mapping |
| b.price | BigDecimal trong ví dụ |
| b.status | BookStatus |
| lower(b.title) | String |
| count(b) | Long |
| avg(b.price) | Double |
| min(b.price), max(b.price) | Kiểu của price |
| CASE với các nhánh chuỗi | String nếu các nhánh tương thích |
| coalesce(b.subtitle, 'N/A') | Kiểu tương thích của các đối số |

Với function do DBMS cung cấp, native function hoặc function được đăng ký qua Hibernate, kiểu kết quả có thể phụ thuộc function descriptor và dialect. Nếu query báo type mismatch, kiểm tra **kiểu Java của path/expression**, không chỉ kiểu cột SQL.

### 13.1. Toán tử số học

~~~java
List<BigDecimal> adjusted = entityManager.createQuery(
        "select b.price * 1.1 from Book b",
        BigDecimal.class
    )
    .getResultList();
~~~

Biểu thức số học chịu quy tắc promotion/type inference. Với BigDecimal và literal số, cần kiểm tra kiểu mà provider suy ra trong phiên bản đang dùng; khi query phức tạp hoặc dùng function đặc thù, có thể phải cast theo HQL/DBMS phù hợp. Không ép kiểu Java sau khi query nếu SQL expression thực tế có kiểu khác.

### 13.2. Enum và temporal expressions

Nếu status là enum, SELECT b.status trả enum Java chứ không phải chuỗi PUBLISHED, dù DB đang lưu bằng Enumerated(EnumType.STRING). Mapping enum quyết định chuyển đổi giữa Java enum và giá trị DB; selection vẫn theo kiểu Java.

Tương tự, chọn temporal path trả kiểu Java được mapping (LocalDate, Instant, LocalDateTime, v.v.), không nhất thiết là kiểu timestamp SQL. Khai báo result class theo Java attribute type.

## 14. Chọn embedded/value object

Một path tới embeddable có thể trả về value object được ánh xạ, không phải entity root độc lập:

~~~java
@Embeddable
public class Address {
    private String city;
    private String postalCode;
}

@Entity
public class Publisher {
    @Id
    private Long id;

    @Embedded
    private Address address;
}
~~~

Query:

~~~java
List<Address> addresses = entityManager.createQuery(
        "select p.address from Publisher p",
        Address.class
    )
    .getResultList();
~~~

Address là embeddable/value object, không có identity và lifecycle độc lập như entity Publisher. Khi cần một số field trong address, có thể scalar-select hoặc DTO projection. Đừng nhầm “đối tượng Java được trả về” với “entity managed”.

## 15. Lỗi thường gặp khi chọn kiểu kết quả

| Hiện tượng | Nguyên nhân | Cách xử lý |
| --- | --- | --- |
| ClassCastException khi đọc kết quả | Query chọn scalar/array nhưng code cast thành entity | Đối chiếu select list với result type |
| Query type mismatch | Result class không khớp expression hoặc DTO constructor | Dùng typed query đúng kiểu, kiểm tra constructor |
| Object[] bị đọc sai index | Thay thứ tự select list nhưng caller không đổi | DTO hoặc Tuple với alias |
| getSingleResult() ném NoResultException | Không có row phù hợp | Dùng list hoặc xử lý no-result rõ ràng |
| getSingleResult() ném NonUniqueResultException | Query trả nhiều row | Thêm điều kiện unique/aggregate hoặc dùng list |
| count bị cast sang Integer | count trả Long | Dùng Long |
| sum/avg trả null | Tập dữ liệu rỗng hoặc không có giá trị | Xử lý null theo nghiệp vụ |
| Entity selection gây tải nhiều dữ liệu | Caller chỉ cần vài field nhưng query hydrate entity | Scalar/DTO projection |
| DTO bị coi là managed entity | Nhầm constructor projection với entity selection | DTO không nằm trong persistence context |
| Query trả entity trùng lặp | Join tạo nhiều row cho cùng root | Xem join semantics và dùng distinct khi phù hợp |
| Lazy exception sau query | Entity trả về nhưng association chưa loaded | Fetch join/EntityGraph hoặc map DTO trong transaction |
| Alias không tìm thấy trong Tuple | Alias thiếu hoặc khác tên truy cập | Đặt alias duy nhất và dùng đúng tên |

### 15.1. Đừng giải quyết type mismatch bằng cast

Nếu HQL là:

~~~sql
select b.title from Book b
~~~

thì result là String. Không có cast nào biến scalar string thành Book entity. Muốn có entity, phải chọn b:

~~~sql
select b from Book b
~~~

Tương tự, SELECT b.id, b.title không phải một entity Book; đó là một multiselect. Hãy chọn DTO hoặc Object[] đúng mục đích.

## 16. Một ví dụ service với ba loại query

~~~java
public class BookQueryService {
    private final EntityManager em;

    public BookQueryService(EntityManager em) {
        this.em = em;
    }

    // 1. Entity query: caller có thể tiếp tục làm việc với managed entity.
    public Book findForUpdate(long id) {
        return em.createQuery(
                "select b from Book b where b.id = :id",
                Book.class
            )
            .setParameter("id", id)
            .getSingleResult();
    }

    // 2. Scalar query: chỉ trả title.
    public List<String> findTitles(BookStatus status) {
        return em.createQuery(
                "select b.title from Book b " +
                "where b.status = :status order by b.title",
                String.class
            )
            .setParameter("status", status)
            .getResultList();
    }

    // 3. DTO query: read model cho API.
    public List<BookSummary> findSummaries(BookStatus status) {
        return em.createQuery(
                "select new com.example.book.BookSummary(" +
                "b.id, b.title, b.price) " +
                "from Book b where b.status = :status",
                BookSummary.class
            )
            .setParameter("status", status)
            .getResultList();
    }
}
~~~

Service này minh họa ba contract kết quả. Trong ứng dụng thật, EntityManager thường được inject qua PersistenceContext hoặc constructor của repository/infrastructure phù hợp; transaction boundary phải được đặt ở service/use case. Phương thức findForUpdate chỉ trả entity managed trong persistence context hiện tại; nó không tự tạo khóa database nếu không chỉ định lock mode.

## 17. Chọn kiểu kết quả trong từng tình huống

### Tình huống A — Cập nhật trạng thái sách

Chọn entity:

~~~java
Book book = em.find(Book.class, bookId);
book.publish();
~~~

Caller cần hành vi domain và dirty checking. Scalar title không đủ để thực hiện cập nhật aggregate.

### Tình huống B — Dropdown chỉ hiển thị tên sách

Chọn scalar:

~~~java
List<String> titles = em.createQuery(
        "select b.title from Book b order by b.title",
        String.class
    ).getResultList();
~~~

Không cần tạo entity managed cho hàng nghìn sách nếu chỉ dùng tên.

### Tình huống C — Trang báo cáo hiển thị ID, title, price

Chọn DTO projection:

~~~java
List<BookSummary> result = em.createQuery(
        "select new com.example.book.BookSummary(" +
        "b.id, b.title, b.price) from Book b",
        BookSummary.class
    ).getResultList();
~~~

Caller có kiểu dữ liệu rõ, không phải nhớ row[0], row[1], row[2].

### Tình huống D — Đếm sách đã xuất bản

Chọn aggregate scalar:

~~~java
Long count = em.createQuery(
        "select count(b) from Book b where b.status = :status",
        Long.class
    ).setParameter("status", BookStatus.PUBLISHED)
     .getSingleResult();
~~~

Kết quả là Long, kể cả khi số lượng nhỏ.

### Tình huống E — Báo cáo nhóm theo trạng thái

Chọn DTO:

~~~java
List<StatusCount> rows = em.createQuery(
        "select new com.example.book.StatusCount(" +
        "b.status, count(b)) from Book b group by b.status",
        StatusCount.class
    ).getResultList();
~~~

Mỗi dòng là một group, nên dùng list chứ không dùng single result.

## 18. Quy trình thiết kế HQL result type

1. **Viết rõ caller cần gì.** Entity để thay đổi, scalar để đọc một giá trị, hay DTO cho một read model?
2. **Xem từng biểu thức trong select list.** Path là entity, basic value, embeddable hay aggregate?
3. **Xác định Java type.** Đối chiếu identifier type, enum, numeric promotion, function và aggregate result type.
4. **Chọn result class tương ứng.** Book.class, String.class, Long.class, Object[].class hoặc DTO class.
5. **Với nhiều giá trị, ưu tiên DTO có constructor rõ.** Dùng Object[] khi dữ liệu thực sự động; Tuple khi cần alias.
6. **Phân biệt JPA portable với Hibernate-specific.** select new là cách portable; typed result packaging cho nhiều selection là extension Hibernate.
7. **Xác định cardinality.** Dùng list nếu 0..N; dùng single result khi điều kiện/aggregate bảo đảm đúng một kết quả.
8. **Xử lý null và empty input.** Đặc biệt với scalar nullable và aggregate ngoài count.
9. **Kiểm tra lifecycle.** Entity selection có thể managed; DTO/scalar không được dirty checking.
10. **Quan sát SQL và tải dữ liệu.** Projection có thể giảm cột/hydration nhưng query plan và joins vẫn cần được đo.

## 19. Bài tập tự kiểm tra

1. Query SELECT b FROM Book b khác SELECT b.title FROM Book b ở kiểu kết quả và lifecycle như thế nào?
2. Vì sao SELECT b.author trả Author, còn SELECT b.author.name trả scalar?
3. Kiểu Java của count(b) là gì? Vì sao không nên khai báo Integer.class?
4. Khi select hai expression, dạng Object[] sắp xếp phần tử theo quy tắc nào?
5. DTO constructor projection khác entity selection ở persistence context ra sao?
6. Vì sao SELECT NEW com.example.BookSummary(...) cần constructor khớp số lượng và kiểu tham số?
7. getSingleResult() xử lý thế nào khi query không có row hoặc có nhiều row?
8. Vì sao sum() có thể trả null trong khi count() trả 0 trên tập rỗng?
9. Khi nào nên dùng DTO projection thay vì chọn entity rồi chỉ đọc ba field?
