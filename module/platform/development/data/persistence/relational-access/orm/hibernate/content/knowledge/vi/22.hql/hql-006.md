# Điều kiện lọc, so sánh, biểu thức điều kiện và thứ tự kết quả

HQL (Hibernate Query Language) cho phép truy vấn trên **entity, thuộc tính và quan hệ của mô hình object**, sau đó Hibernate chuyển truy vấn thành SQL phù hợp với database dialect. Một câu HQL thường dùng `where` để lọc, các toán tử so sánh và biểu thức boolean để diễn tả điều kiện, rồi `order by` để sắp xếp kết quả.

~~~java
List<Book> books = entityManager.createQuery(
    """
    select b
    from Book b
    where b.published = true
      and b.price >= :minimumPrice
    order by b.publishedAt desc, b.title asc
    """,
    Book.class
)
.setParameter("minimumPrice", new BigDecimal("100000"))
.getResultList();
~~~

Câu truy vấn đọc entity `Book`, lọc các sách đã xuất bản có giá từ ngưỡng trở lên, sau đó sắp xếp theo ngày xuất bản giảm dần và tiêu đề tăng dần. `b.price` và `b.publishedAt` là tên thuộc tính Java được ánh xạ, không nhất thiết trùng tên cột SQL.

Để viết điều kiện đúng, cần hiểu cú pháp HQL, kiểu dữ liệu, giá trị NULL, logic ba trạng thái của SQL, cách kết hợp điều kiện và quy tắc sắp xếp. Một truy vấn có thể chạy không lỗi nhưng vẫn trả sai tập kết quả nếu biểu thức boolean hoặc null semantics không đúng với ý định nghiệp vụ.

> **Phạm vi:** Ví dụ dùng Hibernate ORM 6.x và Jakarta Persistence (`jakarta.persistence`). Phần lớn cú pháp minh họa thuộc tập con JPQL portable; các tính năng được đánh dấu Hibernate-specific là mở rộng HQL và có thể phụ thuộc phiên bản/dialect. Hibernate 5 thường dùng `javax.persistence`. SQL đầu ra thay đổi theo database, mapping và dialect.

## 1. HQL truy vấn mô hình entity, không truy vấn trực tiếp tên cột

Giả sử entity:

~~~java
@Entity
@Table(name = "book")
public class Book {
    @Id
    private Long id;

    @Column(name = "book_title")
    private String title;

    @Column(name = "unit_price")
    private BigDecimal price;

    @Column(name = "is_published")
    private boolean published;

    @Column(name = "published_at")
    private LocalDateTime publishedAt;
}
~~~

HQL:

~~~sql
select b
from Book b
where b.title like :pattern
  and b.price >= :minimum
~~~

HQL dùng `b.title` và `b.price` theo tên thuộc tính entity. SQL Hibernate sinh ra có thể dùng `book_title` và `unit_price`:

~~~sql
SELECT b.id, b.book_title, b.unit_price, ...
FROM book b
WHERE b.book_title LIKE ?
  AND b.unit_price >= ?
~~~

Không viết tên cột vật lý trong HQL trừ khi tên đó tình cờ cũng là tên thuộc tính. Nếu cần viết SQL trực tiếp, dùng native query; native SQL và HQL là hai ngôn ngữ khác nhau.

## 2. Cấu trúc cơ bản của câu HQL

~~~sql
select b
from Book b
where b.published = true
order by b.title asc
~~~

| Thành phần | Vai trò |
|---|---|
| `select b` | Chọn giá trị/entity trả về. |
| `from Book b` | Chọn entity root và khai báo alias. |
| `where ...` | Lọc các entity thỏa điều kiện. |
| `order by ...` | Xác định thứ tự kết quả. |

Trong HQL, `from Book b` không có `select` tường minh cũng có thể trả về entity:

~~~sql
from Book b
where b.published = true
~~~

Dùng `select` rõ ràng giúp người đọc nhận biết kiểu kết quả, nhất là khi query trả về scalar, DTO hoặc nhiều biểu thức.

### Alias và path expression

~~~sql
select b
from Book b
join b.author a
where a.country = :country
  and b.title = :title
~~~

`b` và `a` là alias của các entity trong query. Path `b.author.name` đi qua association `author` để đọc thuộc tính `name` của Author. Hibernate có thể tạo SQL join tương ứng. Không nên giả định path navigation luôn miễn phí; join có thể ảnh hưởng số rows, index và query plan.

## 3. WHERE: lọc theo điều kiện

`where` nhận một biểu thức điều kiện. Chỉ những dòng mà điều kiện được đánh giá là TRUE mới được chọn; FALSE và UNKNOWN không được chọn.

~~~sql
select b
from Book b
where b.published = true
  and b.price >= :minimumPrice
  and b.category.code = :categoryCode
~~~

Đặt điều kiện càng rõ càng tốt: dùng tên thuộc tính entity đúng mapping, dùng parameter cho giá trị thay đổi, dùng ngoặc khi kết hợp nhiều nhóm điều kiện và kiểm tra null semantics thay vì suy luận như Java boolean thuần.

## 4. Toán tử so sánh cơ bản

| Toán tử | Ý nghĩa | Ví dụ |
|---|---|---|
| `=` | Bằng | `b.status = :status` |
| `<>` | Khác | `b.status <> :status` |
| `<` | Nhỏ hơn | `b.price < :maximum` |
| `<=` | Nhỏ hơn hoặc bằng | `b.price <= :maximum` |
| `>` | Lớn hơn | `b.stock > 0` |
| `>=` | Lớn hơn hoặc bằng | `b.publishedAt >= :from` |

~~~java
List<Book> books = entityManager.createQuery(
    """
    select b
    from Book b
    where b.price >= :minimum
      and b.price < :maximum
    """,
    Book.class
)
.setParameter("minimum", new BigDecimal("50000"))
.setParameter("maximum", new BigDecimal("200000"))
.getResultList();
~~~

Với kiểu số, ngày giờ và các kiểu comparable, toán tử phải phù hợp với kiểu thuộc tính. Không so sánh chuỗi ngày tháng theo cách tùy tiện nếu entity đã có kiểu date/time.

## 5. So sánh String, enum và entity

So sánh chuỗi dùng collation của database/column:

~~~sql
where b.title = :title
~~~

Tính phân biệt chữ hoa/chữ thường và thứ tự từ điển phụ thuộc collation. Muốn tìm không phân biệt hoa thường theo cách tương đối portable:

~~~sql
where lower(b.title) = lower(:title)
~~~

Gọi hàm trên cột có thể làm DB khó sử dụng index thông thường. Với bảng lớn, cân nhắc functional index/generated normalized column hoặc collation phù hợp.

Với enum, bind giá trị Java có kiểu:

~~~java
@Enumerated(EnumType.STRING)
private BookStatus status;

query.setParameter("status", BookStatus.PUBLISHED);
~~~

Không nên tự nối chuỗi enum vào HQL hoặc giả định cột DB luôn lưu tên enum. Mapping ORDINAL có thể lưu số thứ tự, còn STRING lưu tên; thay đổi thứ tự enum khi dùng ORDINAL có thể làm dữ liệu cũ bị diễn giải sai.

HQL cũng có thể so sánh entity reference theo định danh:

~~~sql
select b
from Book b
where b.author = :author
~~~

~~~java
Author author = entityManager.find(Author.class, authorId);
query.setParameter("author", author);
~~~

Nếu chỉ có ID và không muốn load entity để bind, có thể dùng `b.author.id = :authorId`. Kiểu parameter phải khớp biểu thức.

## 6. So sánh ngày giờ và khoảng thời gian

~~~sql
select b
from Book b
where b.publishedOn >= :startDate
  and b.publishedOn < :endDate
order by b.publishedOn desc
~~~

~~~java
query.setParameter("startDate", LocalDate.of(2026, 1, 1));
query.setParameter("endDate", LocalDate.of(2027, 1, 1));
~~~

Khoảng `[startDate, endDate)` thường hữu ích khi lọc theo tháng/năm vì ngày bắt đầu được tính, ngày đầu kỳ kế tiếp không được tính. Nó tránh phải tạo mốc cuối ngày kiểu 23:59:59.999999 tùy precision database.

Với timestamp có timezone, thống nhất kiểu Java, mapping, database column và quy ước UTC/zone nghiệp vụ. Không biến ngày giờ thành chuỗi để so sánh.

## 7. Biểu thức boolean và thứ tự ưu tiên

Điều kiện boolean có thể kết hợp bằng `and`, `or` và `not`. Thứ tự ưu tiên thông dụng là ngoặc, NOT, AND rồi OR.

~~~sql
where b.published = true
  and b.featured = true
  or b.price < :discountPrice
~~~

được hiểu tương đương:

~~~sql
where (b.published = true and b.featured = true)
   or b.price < :discountPrice
~~~

Nếu ý định là “đã xuất bản và (nổi bật hoặc giá thấp)” thì phải viết:

~~~sql
where b.published = true
  and (
      b.featured = true
      or b.price < :discountPrice
  )
~~~

Hai biểu thức không tương đương. Khi có nhiều AND/OR, hãy đặt ngoặc theo cấu trúc nghiệp vụ, kể cả khi có thể bỏ ngoặc theo precedence.

## 8. NULL và logic ba trạng thái của SQL

Trong SQL/HQL, biểu thức điều kiện có thể cho ba kết quả: TRUE, FALSE và UNKNOWN. UNKNOWN thường xuất hiện khi so sánh với NULL.

`b.subtitle = null` không phải cách kiểm tra đúng. So sánh `= NULL` tạo UNKNOWN, không phải TRUE. Dùng:

~~~sql
where b.subtitle is null
~~~

Hoặc:

~~~sql
where b.subtitle is not null
~~~

| A | B | A AND B | A OR B |
|---|---|---|---|
| TRUE | UNKNOWN | UNKNOWN | TRUE |
| FALSE | UNKNOWN | FALSE | UNKNOWN |
| UNKNOWN | UNKNOWN | UNKNOWN | UNKNOWN |

Trong `where`, chỉ TRUE được chọn. UNKNOWN cũng bị loại như FALSE, nhưng khác về logic và có thể tạo bug khi dùng NOT/IN.

### NOT không biến NULL thành giá trị bình thường

Giả sử `b.subtitle` là NULL:

~~~sql
where not (b.subtitle = :value)
~~~

Nếu `:value` không null, biểu thức so sánh là UNKNOWN; phủ định UNKNOWN vẫn là UNKNOWN. Row đó không được chọn.

Nếu yêu cầu là “subtitle khác giá trị truyền vào hoặc subtitle đang null”, viết rõ:

~~~sql
where b.subtitle <> :value
   or b.subtitle is null
~~~

Nếu parameter cũng có thể null, cần định nghĩa riêng semantics mong muốn và xây điều kiện tương ứng. Không dựa vào `<>` để tự bao gồm NULL.

### IS DISTINCT FROM

HQL hiện đại hỗ trợ predicate:

~~~sql
where b.subtitle is distinct from :subtitle
~~~

Predicate này so sánh null-safe: hai giá trị NULL được xem là không khác nhau; một giá trị NULL và một giá trị khác NULL được xem là khác nhau. Mức độ portable phụ thuộc phiên bản HQL/JPQL và database. Nếu cần JPQL portable rộng, viết nhánh NULL rõ ràng bằng `is null`/`is not null` và `or`.

## 9. LIKE: tìm kiếm theo mẫu chuỗi

`LIKE` dùng hai wildcard phổ biến:

| Ký tự | Ý nghĩa |
|---|---|
| `%` | Khớp với không hoặc nhiều ký tự. |
| `_` | Khớp đúng một ký tự. |

~~~sql
where b.title like 'Hibernate%'
~~~

Khớp tiêu đề bắt đầu bằng Hibernate.

~~~sql
where b.title like '%Persistence%'
~~~

Khớp tiêu đề có chứa Persistence.

~~~sql
where b.title like 'Java_'
~~~

Khớp chuỗi bắt đầu bằng Java và có thêm đúng một ký tự.

### LIKE với parameter

Nên bind pattern thay vì nối chuỗi vào HQL:

~~~java
String pattern = "%" + keyword + "%";

List<Book> books = entityManager.createQuery(
    """
    select b
    from Book b
    where b.title like :pattern
    """,
    Book.class
)
.setParameter("pattern", pattern)
.getResultList();
~~~

Parameter binding tránh HQL injection và xử lý kiểu dữ liệu đúng. Nhưng wildcard `%`/`_` bên trong keyword vẫn có ý nghĩa tìm kiếm. Nếu muốn coi input người dùng là văn bản literal, cần escape wildcard.

### LIKE với ESCAPE

~~~sql
where b.title like :pattern escape '!'
~~~

Application phải escape ký tự escape trước, rồi wildcard:

~~~java
static String literalContainsPattern(String input) {
    String escaped = input
        .replace("!", "!!")
        .replace("%", "!%")
        .replace("_", "!_");
    return "%" + escaped + "%";
}
~~~

~~~java
query.setParameter("pattern", literalContainsPattern(userInput));
~~~

Ký tự `!` trong ví dụ được chọn làm escape character. Phải giữ cho ký tự trong `ESCAPE` và logic escape phía Java khớp nhau.

### ILIKE

Hibernate HQL cung cấp mở rộng `ilike` ở những phiên bản hỗ trợ:

~~~sql
where b.title ilike :pattern
~~~

Đây không phải cú pháp JPQL portable. Lựa chọn portable hơn là:

~~~sql
where lower(b.title) like lower(:pattern)
~~~

Khi cần tìm kiếm accent-insensitive hoặc Unicode normalization, `lower()` có thể chưa đủ. Collation, locale và full-text search là các vấn đề riêng; kiểm thử dữ liệu tiếng Việt thực tế.

## 10. IN, NOT IN và BETWEEN

`IN` kiểm tra biểu thức có bằng một phần tử trong tập hay không:

~~~sql
select b
from Book b
where b.status in :statuses
~~~

~~~java
query.setParameter(
    "statuses",
    List.of(BookStatus.PUBLISHED, BookStatus.REVIEW)
);
~~~

Trong JPQL/HQL, collection-valued parameter được hỗ trợ cho predicate IN. Với Hibernate native Query API có thể có `setParameterList()` tùy loại query/API.

### IN với subquery

~~~sql
where b.author.id in (
    select a.id
    from Author a
    where a.country = :country
)
~~~

Subquery trả tập giá trị phù hợp với kiểu biểu thức bên ngoài. Nếu ý định là kiểm tra sự tồn tại thay vì lấy danh sách ID, cân nhắc EXISTS.

### NOT IN và NULL

Nếu danh sách hoặc subquery chứa NULL, kết quả NOT IN có thể trở thành UNKNOWN cho những giá trị không khớp, khiến query loại nhiều rows hơn dự kiến. Nếu mục tiêu là “không tồn tại bản ghi liên quan”, `not exists` thường diễn tả ý định rõ hơn và tránh bẫy NULL.

Một danh sách parameter rỗng có thể được provider xử lý khác nhau hoặc sinh SQL không phù hợp với DB. Hãy quyết định semantics ở application: empty list có nghĩa “không có ID nào được chọn” hay “không lọc theo ID”.

### BETWEEN

~~~sql
where b.price between :minimum and :maximum
~~~

`BETWEEN` bao gồm cả hai đầu mút, tương đương:

~~~sql
where b.price >= :minimum
  and b.price <= :maximum
~~~

Nếu nghiệp vụ muốn khoảng nửa mở `[from, to)`, dùng `>=` và `<` thay vì BETWEEN. Với ngày giờ, đây thường là cách thuận tiện để truy vấn theo ngày/tháng mà không phụ thuộc timestamp precision.

## 11. EXISTS, ANY, SOME và ALL

Giả sử Book có nhiều Review. Muốn lấy sách có ít nhất một review được duyệt:

~~~sql
select b
from Book b
where exists (
    select r.id
    from Review r
    where r.book = b
      and r.approved = true
)
~~~

Subquery là correlated subquery vì dùng alias `b` của query ngoài. `EXISTS` chỉ quan tâm subquery có trả ít nhất một row, không cần lấy toàn bộ review lên application.

### NOT EXISTS

~~~sql
select b
from Book b
where not exists (
    select r.id
    from Review r
    where r.book = b
)
~~~

`NOT EXISTS` thường là cách rõ ràng để biểu diễn “không có bản ghi liên quan”, nhất là khi so với NOT IN có thể bị ảnh hưởng bởi NULL.

### ANY, SOME và ALL

~~~sql
where b.price > all (
    select x.price
    from Book x
    where x.category = b.category
)
~~~

Ý nghĩa: giá của sách b lớn hơn tất cả giá trong tập con trả về.

~~~sql
where b.price > any (
    select x.price
    from Book x
    where x.category = b.category
)
~~~

Ý nghĩa: giá lớn hơn ít nhất một giá trong tập. `SOME` thường đồng nghĩa với `ANY`. Khi tập subquery rỗng, semantics của ALL/ANY tuân theo logic lượng từ SQL; NULL trong tập cũng có thể tạo UNKNOWN.

## 12. Predicate trên collection

Với association collection:

~~~java
@OneToMany(mappedBy = "book")
private List<Review> reviews = new ArrayList<>();
~~~

Lấy sách chưa có review:

~~~sql
select b
from Book b
where b.reviews is empty
~~~

Lấy sách có review:

~~~sql
where b.reviews is not empty
~~~

`IS EMPTY` diễn tả trực tiếp điều kiện collection rỗng. Hibernate có thể chuyển thành SQL EXISTS/NOT EXISTS hoặc dạng tương đương theo dialect.

`MEMBER OF` kiểm tra một entity có phải phần tử của collection hay không:

~~~sql
select a
from Author a
where :book member of a.books
~~~

Có thể dùng `not member of`. Đảm bảo parameter là entity reference đúng kiểu association. Với collection chứa basic values hoặc embedded values, cú pháp/khả năng hỗ trợ phụ thuộc mapping và JPA/HQL version.

### SIZE

~~~sql
select b
from Book b
where size(b.reviews) >= 5
~~~

`size()` trả số phần tử collection theo semantics query. Đây không có nghĩa Hibernate tải toàn bộ collection vào Java; SQL có thể dùng correlated subquery/count.

- Chỉ cần biết có phần tử: `is not empty`/`exists`.
- Cần so sánh số lượng: `size()` hoặc subquery count.
- Cần lấy dữ liệu chi tiết: join/fetch theo nhu cầu.

Đừng load collection vào memory chỉ để gọi size trong vòng lặp; query có thể tạo N+1 hoặc tải nhiều dữ liệu không cần thiết.

## 13. JOIN, LEFT JOIN, ON và WITH

~~~sql
select b
from Book b
join b.author a
where a.country = :country
  and a.active = true
~~~

`join` mặc định là inner join: chỉ các sách có author phù hợp mới được chọn. Nếu quan hệ có thể null, inner join sẽ loại những sách không có author.

### LEFT JOIN

~~~sql
select b
from Book b
left join b.author a
where a.country = :country
~~~

Mặc dù là LEFT JOIN, điều kiện `a.country = :country` trong WHERE loại các dòng có a là NULL. Kết quả thực tế có thể giống inner join đối với điều kiện này.

Nếu muốn giữ tất cả sách và chỉ giới hạn author được nối theo điều kiện, đặt predicate trong ON:

~~~sql
select b
from Book b
left join b.author a on a.active = true
where b.published = true
~~~

Predicate ON điều khiển cách ghép hàng; predicate WHERE lọc kết quả sau phép join.

JPQL hiện đại hỗ trợ ON cho association joins. Hibernate HQL cũng có cú pháp `with` như một mở rộng lịch sử:

~~~sql
select b
from Book b
left join b.reviews r with r.approved = true
where b.published = true
~~~

`ON` portable hơn trong JPQL hiện đại; `WITH` là cú pháp Hibernate-specific. Không đưa predicate vào WHERE nếu mục tiêu là giữ root rows dù association không khớp.

## 14. CASE, COALESCE và NULLIF

`CASE` tính một giá trị dựa trên điều kiện:

~~~sql
select
    b.title,
    case
        when b.price >= 500000 then 'PREMIUM'
        when b.price >= 200000 then 'STANDARD'
        else 'BUDGET'
    end
from Book b
~~~

Có thể dùng CASE trong ORDER BY để ưu tiên nghiệp vụ, hoặc trong WHERE. Tuy nhiên, điều kiện boolean trực tiếp thường dễ đọc hơn nếu chỉ cần kiểm tra một thuộc tính.

`coalesce()` trả về đối số đầu tiên không null:

~~~sql
select coalesce(b.subtitle, b.title)
from Book b
~~~

`nullif(x, y)` trả NULL khi hai đối số bằng nhau:

~~~sql
select nullif(b.discountCode, '')
from Book b
~~~

COALESCE/NULLIF hữu ích để xử lý giá trị nullable trong projection/biểu thức, nhưng không nên dùng để che giấu chất lượng dữ liệu hoặc thay thế constraint phù hợp. Nếu giá trị mặc định có thể trùng dữ liệu thật, semantics so sánh có thể không còn đúng.

## 15. Hàm chuỗi, số học và ngày giờ

Một số hàm chuỗi phổ biến:

| Hàm | Ý nghĩa | Ví dụ |
|---|---|---|
| `lower(x)` | Chuyển chữ thường. | `lower(b.title) = :title` |
| `upper(x)` | Chuyển chữ hoa. | `upper(b.code) = :code` |
| `length(x)` | Độ dài chuỗi. | `length(b.title) > 10` |
| `trim(x)` | Loại khoảng trắng đầu/cuối. | `trim(b.isbn) <> ''` |
| `substring(x, start, length)` | Lấy đoạn chuỗi. | `substring(b.isbn, 1, 3) = '978'` |
| `concat(x, y)` | Nối chuỗi. | `concat(b.firstName, b.lastName)` |

Hàm số học:
 
~~~sql
where abs(b.balance) > :limit
~~~

~~~sql
where mod(b.stock, 2) = 0
~~~

HQL hỗ trợ nhiều hàm số học, nhưng một số hàm được dịch sang hàm riêng của DB. Cần bảo đảm kiểu số, precision/scale và overflow phù hợp. Với tiền tệ, dùng BigDecimal và kiểu decimal thích hợp thay vì floating point không chính xác.

HQL hỗ trợ các biểu thức ngày giờ như `current_date`, `current_time`, `current_timestamp` theo grammar/provider version:

~~~sql
select b
from Book b
where b.publishedAt < current_timestamp
~~~

Nếu cần thời điểm được kiểm soát bởi application/test, truyền parameter thay vì phụ thuộc clock của DB.

## 16. TYPE và TREAT cho inheritance

~~~java
@Entity
@Inheritance(strategy = InheritanceType.SINGLE_TABLE)
abstract class Publication {
    @Id
    Long id;
    String title;
}

@Entity
class PrintedBook extends Publication {
    String isbn;
}

@Entity
class Magazine extends Publication {
    Integer issueNumber;
}
~~~

Có thể lọc theo subtype bằng TYPE:

~~~sql
select p
from Publication p
where type(p) = PrintedBook
~~~

TREAT cho phép xem path như subtype để truy cập thuộc tính riêng:

~~~sql
select p
from Publication p
where treat(p as PrintedBook).isbn = :isbn
~~~

Syntax entity type literal và hỗ trợ TREAT có thể khác giữa HQL/JPQL version; kiểm tra entity name và provider. Không dùng tên bảng subtype thay entity type.

## 17. ORDER BY: sắp xếp kết quả

Không có `order by`, database **không bảo đảm thứ tự kết quả**. Dù query thường trả cùng thứ tự trên môi trường dev, execution plan, index, dữ liệu và version DB có thể làm thứ tự thay đổi.

~~~sql
select b
from Book b
order by b.title asc
~~~

`asc` là tăng dần; đây thường là mặc định nếu bỏ direction. `desc` là giảm dần:

~~~sql
select b
from Book b
order by b.publishedAt desc
~~~

Khi thứ tự có ý nghĩa với API, báo cáo hoặc pagination, luôn chỉ định ORDER BY rõ ràng.

### Sắp xếp nhiều tiêu chí

~~~sql
select b
from Book b
order by b.publishedAt desc,
         b.title asc,
         b.id asc
~~~

Database áp dụng tiêu chí theo thứ tự: ngày xuất bản mới nhất trước; nếu cùng ngày, title tăng dần; nếu vẫn bằng nhau, ID tăng dần. Nên thêm khóa duy nhất làm tie-breaker nếu cần thứ tự ổn định.

### Sắp xếp theo biểu thức

~~~sql
select b
from Book b
order by
    case
        when b.featured = true then 0
        else 1
    end,
    b.title asc
~~~

CASE đưa sách featured lên trước rồi sắp xếp theo title. Biểu thức phức tạp có thể ảnh hưởng index và sort cost. Chỉ dùng khi quy tắc nghiệp vụ yêu cầu.

## 18. Thứ tự NULL: NULLS FIRST và NULLS LAST

~~~sql
select b
from Book b
order by b.publishedAt desc nulls last
~~~

Ngày mới nhất đứng đầu; sách chưa có ngày xuất bản đứng cuối.

~~~sql
order by b.publishedAt asc nulls first
~~~

Quy tắc NULL mặc định khác nhau giữa database và hướng sort. HQL 6 hỗ trợ cú pháp null precedence cho ORDER BY; khả năng dịch thành SQL phụ thuộc dialect. Nếu cần tương thích provider cũ, có thể dùng CASE:

~~~sql
order by
    case when b.publishedAt is null then 1 else 0 end,
    b.publishedAt desc
~~~

CASE tạo tiêu chí xếp nhóm null/non-null rồi mới sắp xếp ngày.

## 19. Collation và thứ tự chuỗi

~~~sql
order by b.title asc
~~~

Thứ tự phụ thuộc collation của cột/database. Với tiếng Việt, dấu, chữ hoa/chữ thường và locale có thể làm kết quả khác với thứ tự Unicode code point đơn giản.

Nếu sản phẩm cần quy tắc sort ngôn ngữ cụ thể, xác định collation/locale ở DB hoặc cột; kiểm tra dữ liệu có dấu, chữ hoa, ký tự tổ hợp; thêm tie-breaker ổn định như ID. `lower()` không giải quyết đầy đủ accent/collation.

## 20. ORDER BY với DISTINCT và JOIN

Join một collection có thể làm một entity root xuất hiện nhiều lần ở mức SQL:

~~~sql
select b
from Book b
join b.reviews r
where r.approved = true
order by b.title
~~~

Một book có ba reviews approved có thể tạo ba joined rows. Nếu mục tiêu chỉ là “sách có ít nhất một review approved”, EXISTS thường diễn tả chính xác hơn:

~~~sql
select b
from Book b
where exists (
    select r.id
    from Review r
    where r.book = b
      and r.approved = true
)
order by b.title
~~~

Nếu thật sự cần join, cân nhắc `select distinct b`, nhưng DISTINCT có thể làm SQL sort/hash tốn thêm chi phí và tương tác với ORDER BY theo quy tắc DB. Không thêm DISTINCT như cách che giấu join cardinality mà chưa hiểu query.

## 21. ORDER BY và pagination

Trong JPA, có thể giới hạn kết quả bằng API:

~~~java
List<Book> page = entityManager.createQuery(
    """
    select b
    from Book b
    where b.published = true
    order by b.publishedAt desc, b.id desc
    """,
    Book.class
)
.setFirstResult(0)
.setMaxResults(20)
.getResultList();
~~~

- `setFirstResult(0)`: offset bắt đầu.
- `setMaxResults(20)`: số kết quả tối đa.

Hibernate chuyển thành cú pháp pagination của DB dialect như LIMIT/OFFSET, OFFSET/FETCH hoặc dạng tương ứng.

### Pagination cần thứ tự ổn định

Không nên phân trang bằng ORDER BY chỉ một cột không duy nhất. Nếu nhiều books cùng timestamp, thứ tự giữa chúng không được xác định. Thêm ID:

~~~sql
order by b.publishedAt desc, b.id desc
~~~

Ngay cả ORDER BY ổn định, nếu rows được insert/delete giữa hai requests, trang offset sau có thể dịch chuyển: một row xuất hiện ở trang trước rồi lặp lại hoặc bị bỏ qua. Với dữ liệu lớn và thay đổi liên tục, cân nhắc keyset/seek pagination.

### Keyset pagination

Giả sử sắp xếp mới nhất trước:

~~~sql
order by b.publishedAt desc, b.id desc
~~~

Trang tiếp theo sau cursor `(lastPublishedAt, lastId)`:

~~~sql
where b.publishedAt < :lastPublishedAt
   or (
       b.publishedAt = :lastPublishedAt
       and b.id < :lastId
   )
order by b.publishedAt desc, b.id desc
~~~

Cách này phù hợp khi sort keys không null và có tie-breaker duy nhất. Nếu publishedAt nullable, cần thiết kế cursor và predicate riêng theo quy tắc null ordering. Keyset pagination tránh chi phí offset sâu nhưng không hỗ trợ nhảy tùy ý đến trang số N dễ dàng.

## 22. Tham số động: không nối input vào HQL

Không an toàn:

~~~java
String hql =
    "from Book b where b.title = '" + userInput + "'";
~~~

Input có thể thay đổi cú pháp query, gây HQL injection và lỗi escaping.

An toàn hơn:

~~~java
List<Book> result = entityManager.createQuery(
    "select b from Book b where b.title = :title",
    Book.class
)
.setParameter("title", userInput)
.getResultList();
~~~

Bind parameter dành cho **giá trị**, không phải tên thuộc tính, keyword hoặc hướng sort. Không thể viết `order by :column` để truyền tên cột rồi mong database sắp xếp theo identifier đó.

### Dynamic ORDER BY cần allowlist

~~~java
String orderBy = switch (sortField) {
    case "title" -> "b.title";
    case "price" -> "b.price";
    case "publishedAt" -> "b.publishedAt";
    default -> "b.id";
};

String direction = descending ? "desc" : "asc";

String hql = """
    select b
    from Book b
    where b.published = true
    order by %s %s, b.id asc
    """.formatted(orderBy, direction);
~~~

Đoạn này chỉ an toàn khi orderBy được lấy từ allowlist cố định và direction được chuyển từ boolean/enum do application kiểm soát. Không nối raw client input vào identifier hoặc asc/desc.

## 23. Parameter binding và kiểu dữ liệu

~~~java
TypedQuery<Book> query = entityManager.createQuery(
    """
    select b
    from Book b
    where b.price >= :minimum
      and b.status = :status
      and b.publishedAt < :cutoff
    """,
    Book.class
);

query.setParameter("minimum", new BigDecimal("99000"));
query.setParameter("status", BookStatus.PUBLISHED);
query.setParameter(
    "cutoff",
    LocalDateTime.of(2026, 12, 1, 0, 0)
);
~~~

Hibernate suy luận/bind kiểu theo metadata và kiểu parameter. Tránh truyền chuỗi cho cột số/ngày giờ rồi dựa vào implicit conversion của DB; conversion có thể khác dialect và làm index khó được sử dụng.

JPQL/JPA hỗ trợ positional parameters dạng `?1`, `?2`:

~~~sql
where b.price >= ?1
  and b.status = ?2
~~~

~~~java
query.setParameter(1, minimumPrice);
query.setParameter(2, BookStatus.PUBLISHED);
~~~

Named parameters thường dễ đọc và ít nhầm thứ tự hơn khi query dài.

## 24. Kết hợp filter tùy chọn

Một API tìm sách có thể nhận title, status, minimumPrice. Có thể viết:

~~~sql
select b
from Book b
where (:title is null or lower(b.title) like lower(:title))
  and (:status is null or b.status = :status)
  and (:minimumPrice is null or b.price >= :minimumPrice)
order by b.title asc, b.id asc
~~~

Application truyền null cho filter không dùng. Cách này tiện, nhưng OR với parameter nullable có thể làm optimizer khó chọn index plan; kiểu parameter null có thể khó suy luận trong biểu thức phức tạp; một query có nhiều filter optional có thể tạo execution plan kém cho một số tổ hợp.

Với truy vấn quan trọng hoặc nhiều filter, xây dựng predicate động bằng Criteria API/specification có thể tạo query chỉ chứa điều kiện được dùng. Luôn bind values, không nối raw input.

## 25. WHERE và HAVING không cùng vai trò

WHERE lọc rows trước khi grouping/aggregation; HAVING lọc các nhóm sau khi aggregate.

~~~sql
select b.category, count(b)
from Book b
where b.published = true
group by b.category
having count(b) >= :minimumBooks
order by count(b) desc
~~~

WHERE bỏ các sách chưa xuất bản trước khi nhóm; GROUP BY tạo nhóm theo category; HAVING giữ các category có đủ số sách đã xuất bản; ORDER BY sắp xếp nhóm theo số lượng.

Không dùng HAVING thay WHERE cho predicate thông thường nếu không cần aggregate; điều đó có thể làm query khó đọc và kém hiệu quả.

## 26. Phân biệt WHERE filter và JOIN FETCH

~~~sql
select b
from Book b
left join fetch b.author
where b.published = true
order by b.title
~~~

WHERE lọc root entities. JOIN FETCH thay đổi fetch plan, yêu cầu nạp association trong cùng query. Fetch join không phải một loại filter.

Với collection fetch join và pagination, số SQL rows có thể lớn hơn số root entities; Hibernate có thể phải xử lý pagination ở memory hoặc cảnh báo tùy version/configuration. Đối với trang dữ liệu lớn, thường nên page IDs/root entities trước rồi fetch association cần thiết bằng query thứ hai, hoặc dùng DTO projection phù hợp.

## 27. Điều kiện lọc và index database

Predicate có thể đúng về logic nhưng không hiệu quả:

~~~sql
where lower(b.title) = lower(:title)
~~~

Nếu index chỉ có trên title, DB có thể không dùng index thông thường cho biểu thức lower(title). Tương tự:

~~~sql
where year(b.publishedAt) = :year
~~~

có thể khiến DB phải áp dụng hàm trên nhiều rows.

Khi hiệu năng quan trọng:
- Ưu tiên predicate range trên cột gốc nếu có thể.
- Tạo functional index/generated column khi DB hỗ trợ và workload chứng minh cần.
- Đảm bảo cột join/filter có index phù hợp.
- Kiểm tra cardinality và execution plan.
- Tránh query lấy toàn bộ entity nếu chỉ cần vài scalar values.

Ví dụ lọc cả năm theo range:

~~~sql
where b.publishedAt >= :yearStart
  and b.publishedAt < :nextYearStart
~~~

thường thân thiện với index range hơn gọi hàm year() trên từng row, tùy mapping/dialect.

## 28. HQL mở rộng và JPQL portable

HQL của Hibernate có nhiều khả năng vượt quá tập con JPQL:

| Cú pháp/khả năng | Ghi chú |
|---|---|
| `ilike` | Hibernate HQL extension; không portable JPQL rộng. |
| `with` trong association join | Cú pháp Hibernate-specific; JPQL hiện đại có `on`. |
| `is distinct from` | Được HQL hỗ trợ trong các phiên bản hiện đại; kiểm tra JPQL/provider portability. |
| Hàm HQL bổ sung | Phụ thuộc grammar Hibernate và khả năng dịch của dialect. |
| CTE/derived roots/window functions ở HQL hiện đại | Khả năng nâng cao, phụ thuộc Hibernate version và database. |

Nếu ứng dụng chỉ dùng Hibernate, extension HQL có thể hữu ích. Nếu cần portability giữa JPA providers, giữ query trong tập JPQL chuẩn và kiểm thử provider mục tiêu.

## 29. HQL version và cú pháp hàm

Hibernate 6 cải tiến grammar HQL và hỗ trợ nhiều biểu thức hơn các phiên bản trước. Tuy vậy:
- HQL grammar có thể thay đổi theo major version.
- Một hàm HQL có thể được dịch sang hàm DB khác nhau.
- DB dialect có thể không hỗ trợ một chức năng.
- Một truy vấn hợp lệ ở Hibernate 6 không nhất thiết chạy nguyên văn trên Hibernate 5.

Khi nâng cấp Hibernate, hãy chạy integration tests cho query có nulls first/last, ilike, is distinct from, treat, subquery, functions và pagination. Không coi một câu HQL extension là cú pháp SQL portable.

## 30. Ví dụ tổng hợp: tìm kiếm sách

Yêu cầu: chỉ lấy sách đã xuất bản; có thể lọc theo keyword, category, mức giá và thời gian; loại trừ một số trạng thái; sắp xếp sách mới nhất trước, title tăng dần và ID làm tie-breaker.

~~~java
public List<Book> searchBooks(
        String keyword,
        String categoryCode,
        BigDecimal minPrice,
        BigDecimal maxPrice,
        LocalDateTime publishedFrom,
        List<BookStatus> excludedStatuses,
        int offset,
        int pageSize) {

    StringBuilder hql = new StringBuilder("""
        select b
        from Book b
        join b.category c
        where b.published = true
        """);

    if (keyword != null && !keyword.isBlank()) {
        hql.append(" and lower(b.title) like lower(:keyword) ");
    }
    if (categoryCode != null) {
        hql.append(" and c.code = :categoryCode ");
    }
    if (minPrice != null) {
        hql.append(" and b.price >= :minPrice ");
    }
    if (maxPrice != null) {
        hql.append(" and b.price <= :maxPrice ");
    }
    if (publishedFrom != null) {
        hql.append(" and b.publishedAt >= :publishedFrom ");
    }
    if (excludedStatuses != null && !excludedStatuses.isEmpty()) {
        hql.append(" and b.status not in :excludedStatuses ");
    }

    hql.append("""
        order by b.publishedAt desc nulls last,
                 b.title asc,
                 b.id asc
        """);

    TypedQuery<Book> query = entityManager.createQuery(
        hql.toString(),
        Book.class
    );

    if (keyword != null && !keyword.isBlank()) {
        query.setParameter("keyword", "%" + keyword + "%");
    }
    if (categoryCode != null) {
        query.setParameter("categoryCode", categoryCode);
    }
    if (minPrice != null) {
        query.setParameter("minPrice", minPrice);
    }
    if (maxPrice != null) {
        query.setParameter("maxPrice", maxPrice);
    }
    if (publishedFrom != null) {
        query.setParameter("publishedFrom", publishedFrom);
    }
    if (excludedStatuses != null && !excludedStatuses.isEmpty()) {
        query.setParameter("excludedStatuses", excludedStatuses);
    }

    return query
        .setFirstResult(offset)
        .setMaxResults(pageSize)
        .getResultList();
}
~~~

Ví dụ minh họa cách dựng predicate động với allowlist cố định trong source code. Trong production cần validate offset/pageSize, xử lý keyword literal nếu wildcard phải được escape, quyết định semantics khi danh sách excluded rỗng, và kiểm tra dialect có hỗ trợ nulls last. Nếu cần portability cao hơn, thay null ordering bằng CASE hoặc dùng cú pháp được provider mục tiêu hỗ trợ.

## 31. Ví dụ tổng hợp: điều kiện boolean phức tạp

Yêu cầu: lấy sách đã xuất bản, có giá trong khoảng, và (được đánh dấu nổi bật hoặc có ít nhất một review tốt).

~~~sql
select b
from Book b
where b.published = true
  and b.price between :minimum and :maximum
  and (
      b.featured = true
      or exists (
          select r.id
          from Review r
          where r.book = b
            and r.rating >= :minimumRating
      )
  )
order by b.price asc, b.id asc
~~~

Điều kiện trong ngoặc rất quan trọng. Nếu bỏ ngoặc, OR EXISTS có thể khiến một sách chưa xuất bản vẫn được chọn chỉ vì có review tốt, tùy precedence của AND/OR.

## 32. Ví dụ tổng hợp: sắp xếp ưu tiên nghiệp vụ

Giả sử muốn ưu tiên featured trước, còn hàng trước, giá thấp trước, rồi ID tăng dần:

~~~sql
select b
from Book b
where b.published = true
order by
    case when b.featured = true then 0 else 1 end asc,
    case when b.stock > 0 then 0 else 1 end asc,
    b.price asc,
    b.id asc
~~~

CASE biến điều kiện boolean thành sort key số. Đây là cách hữu ích khi thứ tự không chỉ là tăng/giảm một thuộc tính mà còn chứa ưu tiên nghiệp vụ.

## 33. Debug một truy vấn trả sai kết quả

Khi query không trả đúng rows, kiểm tra:
1. **Entity mapping:** thuộc tính có đúng kiểu, nullable và association không?
2. **Path/alias:** có đang dùng tên Java property thay vì cột SQL?
3. **Parameter:** giá trị, kiểu, timezone và collection binding có đúng không?
4. **NULL:** điều kiện có thể trả UNKNOWN không?
5. **Precedence:** AND/OR/NOT có ngoặc đúng không?
6. **Join:** INNER JOIN hoặc predicate WHERE có vô tình loại root rows không?
7. **Collection:** join có nhân bản rows không; có nên dùng EXISTS?
8. **Order:** có ORDER BY và tie-breaker chưa?
9. **Pagination:** offset/limit có làm kết quả thay đổi giữa requests không?
10. **SQL thật:** Hibernate dịch predicate và bind values như thế nào?

Bật SQL logging trong môi trường phù hợp:

~~~properties
logging.level.org.hibernate.SQL=DEBUG
logging.level.org.hibernate.orm.jdbc.bind=TRACE
~~~

Tên logger tùy Hibernate version. Bind logging có thể làm lộ thông tin nhạy cảm, nên chỉ bật có kiểm soát trong môi trường phát triển/kiểm thử.

## 34. Bài tập thực hành

Giả sử có entity Book, Author, Category, Review với các thuộc tính được dùng trong bài. Hãy viết HQL cho các yêu cầu:

1. Lấy sách có giá từ 100.000 đến dưới 300.000.
2. Lấy sách đã xuất bản và có publishedAt khác NULL.
3. Lấy sách có tiêu đề bắt đầu bằng Hibernate.
4. Lấy sách có tiêu đề chứa keyword nhưng tìm không phân biệt hoa thường.
5. Lấy sách có trạng thái thuộc tập PUBLISHED, REVIEW.
6. Lấy sách không có review nào bằng NOT EXISTS.
7. Lấy tác giả có ít nhất một cuốn sách đã xuất bản.
8. Lấy sách thuộc category có code được truyền vào, nhưng vẫn giữ sách không có category nếu điều kiện join cho phép.
9. Sắp xếp featured trước, giá tăng dần, ID tăng dần.
10. Sắp xếp ngày mới nhất trước, giá trị NULL cuối cùng.
11. Lấy trang tiếp theo sau cursor (publishedAt, id) bằng keyset pagination.
12. Lọc các sách có giá cao hơn mọi sách trong cùng category.

### Gợi ý một số đáp án

Giá trong khoảng nửa mở:

~~~sql
where b.price >= :minimum
  and b.price < :maximum
~~~

Không có review:

~~~sql
where not exists (
    select r.id from Review r where r.book = b
)
~~~

Featured trước:

~~~sql
order by
    case when b.featured = true then 0 else 1 end,
    b.price asc,
    b.id asc
~~~

Ngày NULL cuối:

~~~sql
order by b.publishedAt desc nulls last, b.id asc
~~~

Giá cao hơn tất cả sách cùng category:

~~~sql
where b.price > all (
    select other.price
    from Book other
    where other.category = b.category
      and other.id <> b.id
)
~~~

Với bài cuối, hãy suy nghĩ trường hợp category không có sách khác và trường hợp có giá NULL; semantics của ALL và NULL có thể ảnh hưởng kết quả. Nếu nghiệp vụ yêu cầu một cách xử lý cụ thể, bổ sung điều kiện rõ ràng.

## 35. Quy tắc thực hành khi viết HQL

- Dùng entity name, alias và property paths đúng mapping.
- Dùng named parameters cho giá trị; không nối raw user input vào HQL.
- Dùng IS NULL/IS NOT NULL, không dùng = NULL.
- Dùng ngoặc cho các nhóm AND/OR phức tạp.
- Hiểu NOT IN có thể bị ảnh hưởng bởi NULL.
- Dùng EXISTS khi ý định là kiểm tra sự tồn tại.
- Chọn JOIN/LEFT JOIN và vị trí ON/WHERE theo đúng semantics.
- Luôn chỉ định ORDER BY khi thứ tự có ý nghĩa.
- Thêm unique tie-breaker khi phân trang hoặc cần kết quả ổn định.
- Kiểm tra null ordering và collation trên DB mục tiêu.
- Dùng kiểu parameter phù hợp với thuộc tính.
- Kiểm tra SQL, bind values và execution plan khi query quan trọng.
- Đánh dấu HQL extension và kiểm tra khả năng tương thích theo Hibernate version.

## 36. Sơ đồ tổng hợp

~~~mermaid
flowchart TD
    A["HQL query"] --> B["FROM entity + alias"]
    B --> C["WHERE predicates"]
    C --> D["Comparisons: =, <>, <, <=, >, >="]
    C --> E["Boolean: NOT, AND, OR"]
    C --> F["NULL: IS NULL / IS NOT NULL"]
    C --> G["Patterns and sets: LIKE, IN, BETWEEN"]
    C --> H["Subqueries: EXISTS, ALL, ANY"]
    C --> I["Collections: IS EMPTY, MEMBER OF, SIZE"]
    C --> J["Expressions: CASE, COALESCE, functions"]
    D --> K["ORDER BY"]
    E --> K
    F --> K
    G --> K
    H --> K
    I --> K
    J --> K
    K --> L["ASC/DESC + null precedence + tie-breaker"]
    L --> M["Pagination / result list"]
~~~

Điều kiện lọc quyết định **entity nào được chọn**; biểu thức so sánh, boolean và NULL semantics quyết định cách điều kiện được đánh giá; `ORDER BY` quyết định **thứ tự của những kết quả được chọn**. Khi viết HQL, hãy mô tả điều kiện theo mô hình entity, bind parameter đúng kiểu, xử lý NULL có chủ đích và chỉ định thứ tự ổn định. Cuối cùng, xác nhận SQL Hibernate sinh ra trên database thực tế, vì query language có tính portable không đồng nghĩa mọi dialect có cùng execution plan hoặc cùng hiệu năng.
