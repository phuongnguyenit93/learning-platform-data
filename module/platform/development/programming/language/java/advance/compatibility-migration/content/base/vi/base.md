# Java Advance Compatibility Migration

**Java Compatibility & Migration** là quá trình đánh giá và xử lý những khác biệt khi nâng cấp JDK, cập nhật thư viện hoặc cần duy trì ứng dụng chạy trên nhiều phiên bản Java. Một chương trình có thể biên dịch thành công nhưng vẫn gặp lỗi khi liên kết bytecode hoặc thay đổi hành vi tại runtime. Vì vậy cần phân biệt **source compatibility**, **binary compatibility** và **behavioral compatibility**, đồng thời xác định rõ phiên bản Java nguồn, đích và các môi trường cần tiếp tục hỗ trợ.

Module dành cho người đã biết Java, JVM, Maven hoặc Gradle và cách chạy kiểm thử tự động. Bạn sẽ bắt đầu từ xác định mục tiêu di trú, kiểm kê framework, dependency và công cụ build; dùng `jdeps` cùng `jdeprscan` để phát hiện API nội bộ hoặc bị đánh dấu loại bỏ; sau đó cấu hình `javac --release` để tạo artifact tương thích với Java mục tiêu. Các mốc tiếp theo xử lý Java Platform Module System (JPMS), strong encapsulation, các API đã bị loại bỏ và thay đổi mặc định liên quan đến charset, locale, TLS hay JVM flags. Cuối cùng, bạn thực hiện ma trận kiểm thử trên các JDK có liên quan và lập kế hoạch rollout, quan sát và rollback.

Sau tám mốc, bạn có thể lập một kế hoạch nâng cấp Java có bằng chứng: biết thành phần nào cần thay đổi, phân biệt lỗi từ source với lỗi từ runtime và kiểm tra hệ thống trước khi phát hành. **`--release` giúp giới hạn API và bytecode theo bản Java đích nhưng không thay thế việc chạy thử trên JDK đó**; tương tự, `--add-opens` có thể giúp chuyển tiếp khi gặp thư viện reflection cũ, nhưng không nên coi đó là giải pháp lâu dài thay cho API được hỗ trợ.
