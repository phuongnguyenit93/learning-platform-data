# 2.3 Binary name, canonical name, and descriptor: choosing the right name form for each API

In Java, the same type can have multiple **name representations** depending on the language layer, Reflection, class loader, or bytecode format. For `java.util.Map.Entry`, the canonical name is `java.util.Map.Entry`, the binary name is `java.util.Map$Entry`, and the JVM descriptor is `Ljava/util/Map$Entry;`. Passing the right type with the wrong **name form** can cause `ClassNotFoundException`, an invalid descriptor, or errors during dynamic linking.

**After this lesson, you can:** distinguish canonical name, binary name, internal name, and JVM descriptor; choose the right input for `Class.forName`, `ClassLoader`, `ClassDesc`, `MethodType`, and bytecode reading tools; properly handle nested classes, arrays, primitive types, local/anonymous classes, and generics.

## 1. Four representations to keep separate

| Form | Where it is used | Example for `java.util.Map.Entry` |
| --- | --- | --- |
| Canonical name (*canonical name*) | How a type with a canonical name is referred to in the Java language; display, documentation | `java.util.Map.Entry` |
| Binary name (*binary name*) | Identifier of a compiled class/interface; loading a class by name | `java.util.Map$Entry` |
| JVM internal name (*internal name*) | Representation of a class name in many class file structures | `java/util/Map$Entry` |
| Reference type descriptor (*field/type descriptor*) | Fields, parameters, return values, type description according to the JVM | `Ljava/util/Map$Entry;` |

**Rule of thumb:** dot `.` separates packages in a binary name; dollar sign `$` separates a member class/interface name (*member class/interface*) from its enclosing class; forward slash `/` separates packages in an internal name; a reference descriptor adds `L` at the beginning and `;` at the end. String-based transformations are only safe when the original name and type structure are known with certainty.

### 1.1. Canonical name

`Class.getCanonicalName()` returns the canonical name when the type has a canonical name, or `null` if it does not. For a member class, the canonical name uses dots:

- `String.class.getCanonicalName()` → `java.lang.String`.
- `java.util.Map.Entry.class.getCanonicalName()` → `java.util.Map.Entry`.
- `String[][].class.getCanonicalName()` → `java.lang.String[][]`.
- Local classes declared inside a method and anonymous classes **do not have a canonical name**; the result is `null`.

Canonical names are usually suitable for presentation in documentation, human-readable logs, or source code, but **must not be assumed to be strings accepted by a class loader**. Even though a canonical name looks like the full name of a class, a nested member still has a different binary name.

### 1.2. Binary name

According to Java's binary naming rules, a top-level class usually has the form `package.ClassName`; a member class has the form `package.Outer$Inner`. Java allows `$` in identifiers, so **seeing `$` cannot be used to reliably deduce a nested class boundary**.

For a normal class or interface (not an array and not a *hidden class*), `Class.getName()` returns the binary name. `Class.forName("java.util.Map$Entry")` and `ClassLoader.loadClass("java.util.Map$Entry")` use this name form. Conversely, `Class.forName("java.util.Map.Entry")` will look for a different binary name and usually throws `ClassNotFoundException`.

**Note:** binary names generated by the compiler for local/anonymous classes may contain `$` and sequential numbers; do not hard-code that generated structure/name as a stable contract.

### 1.3. Internal name

In appropriate places in a class file, a binary name is encoded into internal form by replacing **package-separating dots** with `/`, keeping `$` inside member names. For example: `java/lang/String`, `java/util/Map$Entry`.

An internal name is not yet the descriptor of a reference type: `java/lang/String` is missing `L...;`. APIs or tools that manipulate class files may require an internal name, whereas `Class.forName` does not use the `/` form. For arrays, many places in a class file use an **array descriptor** (for example `[Ljava/lang/String;`), so do not try to construct an "internal name of an array" with a generic dot-replacement operation.

### 1.4. JVM descriptor

A descriptor is a structured syntax describing a **type** or a **method's type signature**. It serves class files, JVM linkage, `MethodType`, and constant description APIs. It is not a class name to pass directly into `Class.forName`.

A reference type descriptor is `L` + internal name + `;`: `Ljava/lang/String;`. Arrays place one `[` for each dimension: `[I` is `int[]`; `[[Ljava/lang/String;` is `String[][]`. A method descriptor has the form `(param_1param_2...)return_type`: `(Ljava/lang/String;I)V` is a method taking (`String`, `int`) and returning `void`.

## 2. Comparison on easily confused types

| Java type | Canonical name | `Class.getName()` | JVM type descriptor |
| --- | --- | --- | --- |
| `java.lang.String` | `java.lang.String` | `java.lang.String` | `Ljava/lang/String;` |
| `java.util.Map.Entry` | `java.util.Map.Entry` | `java.util.Map$Entry` | `Ljava/util/Map$Entry;` |
| `int` | `int` | `int` | `I` |
| `int[]` | `int[]` | `[I` | `[I` |
| `String[]` | `java.lang.String[]` | `[Ljava.lang.String;` | `[Ljava/lang/String;` |
| `String[][]` | `java.lang.String[][]` | `[[Ljava.lang.String;` | `[[Ljava/lang/String;` |
| `Map.Entry[]` | `java.util.Map.Entry[]` | `[Ljava.util.Map$Entry;` | `[Ljava/util/Map$Entry;` |

In the table above, `Class.getName()` of a **reference array** looks like a descriptor, but **the element name part still has package dots** (`[Ljava.lang.String;`). A true JVM descriptor uses `/` (`[Ljava/lang/String;`). This small difference is very important when working with `Class.forName` and `ClassDesc.ofDescriptor`.

### 2.1. Primitive type code table

| Descriptor character | Type | Descriptor character | Type |
| --- | --- | --- | --- |
| `B` | `byte` | `C` | `char` |
| `D` | `double` | `F` | `float` |
| `I` | `int` | `J` | `long` |
| `S` | `short` | `Z` | `boolean` |

`V` denotes `void` **in the return type position of a method**; do not use `V` as the descriptor of a field or parameter. The API `void.class.descriptorString()` still returns `"V"` to describe the `void` type.

### 2.2. Method descriptor: reading from left to right

| Java declaration (illustrative) | JVM method descriptor | Meaning |
| --- | --- | --- |
| `void log()` | `()V` | No parameters, no return value |
| `int twice(int n)` | `(I)I` | One `int` in, one `int` out |
| `String label(String key, int count)` | `(Ljava/lang/String;I)Ljava/lang/String;` | `String` then `int`, returns `String` |
| `void accept(String[] values)` | `([Ljava/lang/String;)V` | One `String[]` parameter, returns `void` |

**There are no commas or spaces** between parameters in a descriptor. Parentheses `()` enclose the parameter list; the part after `)` is the return type. The method name (e.g. `label`) and modifiers like `static` are not part of the method descriptor itself. Do not include variable names, generic arguments, or `throws` in a descriptor.

## 3. Which API accepts which form?

| Situation / API | Correct value and reason |
| --- | --- |
| Writing a type name in source code | `java.util.Map.Entry`, `String[]`; language-level type syntax |
| Displaying a human-readable name | `clazz.getCanonicalName()` (check for `null`), or `clazz.getTypeName()` if you want a friendly name for arrays |
| Getting a name to load a normal class | `clazz.getName()` when `clazz` is a normal class/interface; `Class.forName("java.util.Map$Entry")` |
| Loading a class with `ClassLoader` | `loader.loadClass("java.util.Map$Entry")`, using the binary name of the class/interface; do not pass a descriptor |
| Loading an **array class** via `Class.forName` | `Class.forName("[Ljava.lang.String;")` or `Class.forName("[I")`; the array name form returned by `Class.getName()` |
| Getting a type descriptor from `Class<?>` | `clazz.descriptorString()`; e.g. `String[].class.descriptorString()` → `[Ljava/lang/String;` |
| Working with `java.lang.constant.ClassDesc` | `ClassDesc.of("java.util.Map$Entry")` with a binary name; `ClassDesc.ofDescriptor("Ljava/util/Map$Entry;")` with a descriptor |
| Creating a method descriptor | `MethodType.methodType(void.class, String.class, int.class).toMethodDescriptorString()` → `(Ljava/lang/String;I)V` |
| Parsing a method descriptor | `MethodType.fromMethodDescriptorString("(Ljava/lang/String;I)V", loader)` → `MethodType` |
| Finding a method via Reflection | `clazz.getDeclaredMethod("name", String.class, int.class)`: method name + parameter `Class<?>` objects, **not** a descriptor string |
| Looking up a `MethodHandle` with `Lookup.findVirtual` | Requires receiver `Class<?>`, method name, and `MethodType`, without manually concatenating binary names into a descriptor |
| Reading bytecode with `javap -s` | The tool prints JVM descriptors of fields/methods |
| Reading a resource with `ClassLoader.getResource` | A resource path like `demo/Message.class` (without `L...;`); this is a *resource path*, not a type name |

Do not infer from a method name containing "name" that it always needs a canonical name. Check the parameter contract: **binary name**, **descriptor**, **internal name**, **Class object**, **MethodType**, or **resource path** are different things.

## 4. Runnable Java 17+ example

Create a single file `NameFormsDemo.java` with the following content:

```java
import java.lang.constant.ClassDesc;
import java.lang.invoke.MethodType;
import java.util.Map;

public class NameFormsDemo {
    public static void main(String[] args) throws Exception {
        Class<?> nested = Map.Entry.class;
        System.out.println("canonical = " + nested.getCanonicalName());
        System.out.println("binary    = " + nested.getName());
        System.out.println("descriptor= " + nested.descriptorString());
        System.out.println("array name= " + String[].class.getName());
        System.out.println("array desc= " + String[].class.descriptorString());
        System.out.println("array canonical = " + String[].class.getCanonicalName());
        System.out.println("int array name= " + int[].class.getName());
        System.out.println("loaded    = " + Class.forName("java.util.Map$Entry").getSimpleName());

        MethodType mt = MethodType.methodType(void.class, String.class, int.class);
        System.out.println("method    = " + mt.toMethodDescriptorString());
        System.out.println("parsed    = " + MethodType.fromMethodDescriptorString(
                "(Ljava/lang/String;I)V", NameFormsDemo.class.getClassLoader()));
        System.out.println("classDesc = "
                + ClassDesc.ofDescriptor("Ljava/util/Map$Entry;").descriptorString());

        class Local {}
        Runnable anonymous = new Runnable() { public void run() {} };
        System.out.println("local canonical = " + Local.class.getCanonicalName());
        System.out.println("anonymous canonical = "
                + anonymous.getClass().getCanonicalName());
    }
}
```

Compile and run with JDK 17 or later (for example Java 17 or Java 21):

```bash
javac --release 17 NameFormsDemo.java
java NameFormsDemo
```

Exact `stdout`:

```text
canonical = java.util.Map.Entry
binary    = java.util.Map$Entry
descriptor= Ljava/util/Map$Entry;
array name= [Ljava.lang.String;
array desc= [Ljava/lang/String;
array canonical = java.lang.String[]
int array name= [I
loaded    = Entry
method    = (Ljava/lang/String;I)V
parsed    = (String,int)void
classDesc = Ljava/util/Map$Entry;
local canonical = null
anonymous canonical = null
```

Explanation: `getCanonicalName()` and `getName()` produce two different ways of referring to `Map.Entry`; `descriptorString()` produces the JVM code with `L...;`. Arrays use an encoding starting with `[`; `Class.forName` successfully loads the member class using the **binary name**. `MethodType` creates/parses method descriptors without manual string concatenation. The two local/anonymous types are direct examples of the case with **no canonical name**.

Also run `javap` on the compiled class:

```bash
javap -s -p NameFormsDemo
```

In the output, the `main(String[])` method has descriptor `([Ljava/lang/String;)V`; `([Ljava/lang/String;)V` consists of one `String[]` array parameter and returns `void`. `javap -s` is the way to cross-check descriptors written into the class file by the compiler.

## 5. Converting and handling arrays properly

When you already have a `Class<?>` object, **query the API according to your goal** instead of manually concatenating/formatting names:

```java
Class<?> type = java.util.Map.Entry[].class;

String canonical = type.getCanonicalName();  // java.util.Map.Entry[]
String runtimeName = type.getName();          // [Ljava.util.Map$Entry;
String descriptor = type.descriptorString();  // [Ljava/util/Map$Entry;
```

This is an **illustrative snippet** (not a standalone program). Array classes are not loaded with `Class.forName("java.util.Map.Entry[]")` or `Class.forName("[Ljava/util/Map$Entry;")`. When you need to load via `Class.forName`, use the exact **array class name in `Class.getName()` form**, for example `Class.forName("[Ljava.util.Map$Entry;")`. When you need a JVM descriptor, use `[Ljava/util/Map$Entry;`.

For primitives, `Class.forName("int")` is not the way to look up `int.class`; use `int.class` directly or map explicitly to `int.class`. `Class.forName("[I")` can obtain the `int[]` array class, because array class names follow different rules from single primitive names.

**Do not write generic converters** like `canonical.replace('.', '$')` or `binary.replace('.', '/')` and assume they are correct. There can be multiple package dots and member classes, class names containing valid `$`, as well as local, anonymous, and hidden classes. If the only input is a source string `a.b.Outer.Inner`, you need to know the actual package/class boundary before building a binary name. It is best to keep `Class<?>`, `ClassDesc`, or `MethodType` as long as possible.

## 6. Special cases in dynamic runtime

### 6.1. Local, anonymous, and hidden classes

- Local/anonymous classes return `null` from `getCanonicalName()` but still have a `Class<?>`; compiler-generated names are not suitable for fixed configuration or guessing.
- For a *hidden class* (for example created via `MethodHandles.Lookup.defineHiddenClass`), `Class.getName()` **is not a normal binary name**; the name has an internal suffix. `descriptorString()` of a hidden class is also not a nominal descriptor that can be passed arbitrarily into `ClassDesc.ofDescriptor`. Work with `Class<?>` and a valid lookup instead of trying to load a hidden class by a string name.
- `getSimpleName()` only gets the short name, e.g. `Entry`; it has no package and does not guarantee unique identification. `getTypeName()` is useful for display (especially for arrays), not a general contract for `Class.forName`.

### 6.2. The right name is not enough to identify a class at runtime

In plugin/hot-reload/multiple-class-loader systems, two classes can have the **same binary name and same descriptor** yet be defined by two different class loaders. They are still two distinct runtime types. Therefore, when handling `ClassNotFoundException`, `ClassCastException`, or `LinkageError`, check the **class loader, module, and visibility** along with the name form; do not conclude that every error comes from replacing `.` with `$`.

`Class.forName(name)` can trigger class initialization; when you need to avoid initialization during lookup, use the overload `Class.forName(name, false, loader)` with the appropriate loader. `Class.forName` does not automatically turn a member class's canonical string into a binary name.

### 6.3. Generic signature differs from JVM descriptor

Suppose a Java field is declared `List<String> names;`. Because of *type erasure*, the **field descriptor** is `Ljava/util/List;`, without `String`. Type argument information, if retained, may reside in the `Signature` attribute, for example `Ljava/util/List<Ljava/lang/String;>;` — this is a **generic signature**, not a valid field descriptor.

Similarly, `String`, `String[]`, and `List<String>` are different representations: the descriptor only records the erased runtime type if generics are present. To read generic types, use APIs like `Field.getGenericType()` or `Method.getGenericReturnType()` and inspect `Type` / `ParameterizedType`; do not expect `Class.descriptorString()` to preserve `<String>`.

## 7. Workflow for choosing a name form when integrating APIs

1. **Identify the target receiver.** Does the API require `Class<?>`, binary name, JVM descriptor, internal name, or resource path? Read the signature and Javadoc of the exact API.
2. **If you have `Class<?>`**, prefer `getName()` for normal classes / array names used with `Class.forName`, `getCanonicalName()` for display with a `null` check, and `descriptorString()` for JVM syntax.
3. **If you have a method**, prefer `MethodType` to build/parse method descriptors. When selecting a Reflection overload, use `Class<?>[]` parameters in the exact order and exact types (primitive `int` differs from boxed `Integer`).
4. **If you must accept a string from configuration**, state the expected format clearly and validate at the boundary: for example "binary name: `java.util.Map$Entry`", or "JVM descriptor: `Ljava/util/Map$Entry;`". Do not accept an ambiguous "className" field and guess how to convert it.
5. **When an error occurs**, log the input value and the API called, the class loader involved, and then re-check the name form. For a binary name, you can try `Class.forName(name, false, loader)` in the appropriate loader context; for a descriptor, try parser APIs like `MethodType.fromMethodDescriptorString` or `ClassDesc.ofDescriptor` and handle format errors.

### Common mistakes

| Wrong or easily confused | Contextually correct |
| --- | --- |
| `Class.forName("java.util.Map.Entry")` | `Class.forName("java.util.Map$Entry")` |
| `Class.forName("java.lang.String[]")` | `Class.forName("[Ljava.lang.String;")` or `String[].class` |
| `Class.forName("Ljava/lang.String;")` | `Class.forName("java.lang.String")` if you want to load the class; use the descriptor with `ClassDesc.ofDescriptor` |
| `ClassDesc.ofDescriptor("Ljava.lang.String;")` | `ClassDesc.ofDescriptor("Ljava/lang/String;")` |
| `MethodType.fromMethodDescriptorString("(String,int)void", loader)` | `MethodType.fromMethodDescriptorString("(Ljava/lang/String;I)V", loader)` |
| Treating `Ljava/util/List<Ljava/lang/String;>;` as a field descriptor | Understand that it is a generic signature; the erased descriptor is `Ljava/util/List;` |
| Assuming `getCanonicalName()` always returns a string | Check for `null` on local/anonymous classes and types without a canonical name |

## 8. Quick self-check

**Scenario A:** a plugin receives the member class name string `com.acme.Outer.Inner` but calling `Class.forName` fails to find it. Verify the declaration and package, and use the binary name `com.acme.Outer$Inner` if it is indeed a member class. Also check the plugin's loader.

**Scenario B:** bytecode needs to describe the method `boolean check(String[] names, long timeout)`. The correct descriptor is `([Ljava/lang/String;J)Z`: `[Ljava/lang/String;` for `String[]`, `J` for `long`, `Z` for `boolean`.

**Scenario C:** a log prints `[Ljava.lang.String;`, while a bytecode library requires a descriptor. Do not pass that log string directly into the library; get `String[].class.descriptorString()` to obtain `[Ljava/lang/String;`.

**Scenario D:** `getCanonicalName()` returns `null`. This may be a type without a canonical name, such as local/anonymous; do not infer that the class is "not loaded" from this result.
