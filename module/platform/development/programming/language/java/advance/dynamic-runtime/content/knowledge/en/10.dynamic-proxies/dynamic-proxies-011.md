# 10.11. Package, Dynamic Module of a Proxy Class, and Identifying Proxies via API

> **Context:** Knowledge lesson in **10. Dynamic Proxies** of the **Java Advance – dynamic-runtime** module. In Java 21, `java.lang.reflect.Proxy` generates **a class at runtime** to implement interfaces, but **the package and module of the generated class are not arbitrarily fixed**. They follow the accessibility of those interfaces, may reside in a **dynamic module**, and must be inspected using the official APIs. This lesson focuses on the package/module selection rules, JPMS constraints, and how to identify a real proxy without relying on the `$Proxy...` name.

## 1. Objectives and Prerequisites

After this lesson, you must be able to explain and practice:

1. Distinguishing **proxy class**, **proxy instance**, **proxy interface**, and **InvocationHandler**.
2. Correctly applying the Java 21 matrix on **public / non-public interfaces** and **exported/open / non-exported-and-non-open packages** to deduce the location and accessibility of the proxy class.
3. Explaining that a **dynamic module** is a named module generated at runtime, in which case a public proxy is placed in an encapsulated package of that module, and why its constructor cannot be called directly from outside.
4. Reading `Class.getPackageName()`, `Class.getModule()`, `Class.getClassLoader()`, `Modifier.isPublic` along with `Module.isExported/isOpen/canRead` to diagnose.
5. Using `Proxy.isProxyClass(Class<?>)` and `Proxy.getInvocationHandler(Object)` to identify proxies via API; knowing why comparing class names or `Proxy.class.isAssignableFrom` is not equivalent.
6. Reading `IllegalArgumentException` errors when an interface is sealed/not an interface, duplicated, not visible to the loader, or non-public interfaces do not share the same package/module.
7. Writing and running pure JDK Java 21 examples for a public proxy, a package-private interface, a public interface in a non-exported named module, and invalid proxy creation cases.

**Prerequisites:** interfaces, packages and access modifiers, `ClassLoader`, Reflection (`Class<?>`), JPMS concepts (`module-info.java`, `exports`, `opens`), `javac`/`java` terminal. Do not use CGLIB, Byte Buddy, Spring AOP, or other libraries: those tools may generate subclass proxies with different rules.

## 2. What is a Dynamic Proxy Class?

Basic example:

```java
// Illustrative snippet, run inside a class that imports java.lang.reflect.*;
interface Greeting {
    String say(String who);
}

InvocationHandler handler = (proxy, method, args) -> "Hello " + args[0];
Greeting greeting = (Greeting) Proxy.newProxyInstance(
        Greeting.class.getClassLoader(),
        new Class<?>[]{Greeting.class},
        handler);
```

Here `Proxy.newProxyInstance` creates **an object** of a class generated by the JVM/JDK at runtime. That class implements the requested interfaces; calls from the interface to the object are dispatched through `InvocationHandler.invoke`. `handler` is not the proxy class, and `Greeting.class` is not the proxy class.

Properties guaranteed by the `Proxy` Javadoc:

- The generated class is **final**, **non-abstract**, and has `java.lang.reflect.Proxy` as its **direct superclass**.
- It implements **the exact list of requested interfaces, in the exact order**. `proxyClass.getInterfaces()` returns the list in this order.
- The **simple** name and package/module names of the proxy class are not considered a fixed contract; do not rely on naming conventions like `$Proxy0` or `jdk.proxy1`.
- The generated instance is an instance of each corresponding interface, so `proxy instanceof Interface` and casting to the interface are valid.
- Each proxy instance is associated with an `InvocationHandler`, retrieved using `Proxy.getInvocationHandler`.
- Interface methods (and certain `Object` methods such as `equals`, `hashCode`, `toString`) are forwarded to the handler.
- `Proxy.isProxyClass` is the reliable API to determine **a class generated by the proxy mechanism**, not merely a class whose name or superclass looks similar.

`Proxy` is an **interface-based proxy**: it does not create an arbitrary subclass of a concrete class. `Proxy.newProxyInstance` does not accept a `Class<?>` that is a concrete class in place of an interface, and in Java 21 it does not directly create a proxy for a sealed interface.

### 2.1. Distinguishing Identity and Appearance

```text
Interface A + Interface B + a ClassLoader
                |
                v
       Proxy.newProxyInstance(...)
                |
                +--> generated proxy Class<?>
                |     superclass = Proxy
                |     implements = [A, B] in exact order
                |     package/module depends on interface accessibility
                |
                +--> proxy instance
                      |
                      +--> InvocationHandler

Class<?> name contains "$Proxy"   : NOT sufficient for identification
extends java.lang.reflect.Proxy   : NOT sufficient for identification
Proxy.isProxyClass(clazz)         : Official identification API
```

A user can manually write a class that extends `Proxy` and call its protected constructor; that class is **not necessarily** a *generated proxy class*. This is the reason to use `isProxyClass` rather than just checking inheritance.

## 3. JPMS Concepts to Distinguish

A **Package** is a namespace containing types. A **Module** is the encapsulation boundary of the Java Platform Module System (JPMS). A **Class loader** is the context for loading/defining classes. These three things are related but **not synonymous**.

### 3.1. `exports` vs `opens`

- `exports p;`: allows other modules to access **public types and public members** of package `p` according to normal Java/JVM access checks.
- `opens p;`: allows **deep reflection** to accessible members when code has appropriate permissions, but does not make every type public for normal compile-time access.
- `exports p to x;` and `opens p to x;` are **qualified exports/opens**: granting access only to the listed module.
- A package that is **non-exported and non-open** from an unqualified perspective is an encapsulated package; a public class inside it can still be inaccessible to another module.
- `Module.isExported("p")`/`isOpen("p")` checks the **unconditional** status; `isExported("p", targetModule)`/`isOpen("p", targetModule)` checks permission for a **specific target**. Do not confuse the results of these two overloads.

In the `Proxy` rules, the Javadoc calls a “non-exported package” a package **not exported to all modules** (even if it is qualifiedly exported); “non-open package” is understood similarly for opens. Therefore, a package with only `exports ... to x` is still **not exported unconditionally**.

### 3.2. Named, Unnamed, and Dynamic Modules

- Classes on the regular classpath belong to the **unnamed module** of the corresponding class loader; packages in an unnamed module are generally exported/open according to the JPMS rules for unnamed modules.
- Classes in a module with `module-info.java` belong to a **named module**. That module may not `exports` a package, even if the interface inside is public.
- A **Dynamic module** here is a **named module created by the JDK when generating a proxy**, not an “unnamed module” or an “automatic module”. It has an unspecified package/module name per the API contract and may be completely encapsulated.

A class having a valid name and being visible to a loader **does not mean** its package/module is exported/open to the current code. That is why checking `Modifier.isPublic` alone is not enough to conclude that a constructor can be called via Reflection from an external module.

## 4. Package/Module Matrix of a Generated Proxy Class in Java 21

The `Proxy` Javadoc classifies by **publicity of the interfaces** and **exported/open status of the packages containing the interfaces**.

| Set of proxied interfaces | Are all interface packages exported or open? | Where is the generated proxy class? | Accessibility |
| --- | --- | --- | --- |
| **All public** | **Yes** | An **unconditionally exported but non-open** package, package/module name **unspecified** | **public** proxy class |
| **At least one non-public** | **Yes** | **Same package and same module** as the non-public interfaces | **non-public** proxy class |
| **All public** | **No**: at least one interface in a non-exported and non-open package | A **non-exported, non-open** package of a **dynamic module** | **public** proxy class, but the package is encapsulated |
| **At least one non-public** | **No** | **Same package and same module** as the non-public interfaces | **non-public** proxy class |

**Mandatory constraint:** if there are multiple **non-public** interfaces, they **must be in the same package and module** (and satisfy the class loader requirements of `Proxy.newProxyInstance`). Otherwise, the corresponding proxy class cannot be created: an `IllegalArgumentException` is typically thrown.

### 4.1. Two Things Not to Misread from the Table

1. **A public proxy class does not mean every module can access it.** In the non-exported/non-open dynamic module branch, `Modifier.isPublic(proxyClass.getModifiers())` can be `true`, yet code in another module still cannot access the class through Java access checks and cannot use `Constructor.newInstance` from outside.
2. **A public interface does not mean the proxy class is placed next to the interface.** When the interface is in a named module whose package is not exported/open, the public proxy class is generated in a **separate dynamic module**, whereas a non-public interface forces the proxy class into **the exact package/module of the non-public interface**.

The rules specify **accessibility**, without guaranteeing sequence numbers, simple names, or specific module/package names. A JDK version may place a public proxy class in a module named like `jdk.proxy1`; that name is not a stable API for writing business logic.

### 4.2. Quick Classification Examples

- A `public` interface in an exported or open module/unnamed package: **row 1**.
- A top-level `package-private` interface in a package: **row 2** or **row 4** depending on exports/opens, but the proxy remains **non-public in the same package/module**.
- A `public` interface of module `inventory.core` whose package `internal.spi` is neither exported nor opened: **row 3**, public proxy in an encapsulated dynamic module.
- Multiple non-public interfaces from **two different packages**: **invalid**, regardless of whether each interface can be seen via Reflection.

Remember: **the least accessible proxy interface governs proxy accessibility**. This is especially important when mixing public and non-public interfaces.

## 5. Lab 1 — Public Proxy and API Identification

Create the file **`PublicProxyLab.java`**:

```java
import java.lang.reflect.InvocationHandler;
import java.lang.reflect.Modifier;
import java.lang.reflect.Proxy;

public class PublicProxyLab {
    public interface Hello {
        String say(String value);
    }

    static final class ManualProxy extends Proxy implements Hello {
        private static final long serialVersionUID = 1L;

        ManualProxy(InvocationHandler h) {
            super(h);
        }

        public String say(String value) {
            return value;
        }
    }

    public static void main(String[] args) {
        InvocationHandler handler = (proxy, method, arguments) -> {
            if (method.getName().equals("say")) {
                return "Hi " + arguments[0];
            }
            if (method.getName().equals("toString")) {
                return "public-proxy";
            }
            throw new UnsupportedOperationException(method.getName());
        };

        Hello proxy = (Hello) Proxy.newProxyInstance(
                Hello.class.getClassLoader(),
                new Class<?>[] { Hello.class },
                handler);

        Class<?> pc = proxy.getClass();
        Module module = pc.getModule();
        String pkg = pc.getPackageName();

        System.out.println("result=" + proxy.say("Java"));
        System.out.println("isProxy=" + Proxy.isProxyClass(pc));
        System.out.println("sameHandler=" + (Proxy.getInvocationHandler(proxy) == handler));
        System.out.println("implementsHello=" + Hello.class.isAssignableFrom(pc));
        System.out.println("directSuperclass=" + (pc.getSuperclass() == Proxy.class));
        System.out.println("publicFinal=" + (Modifier.isPublic(pc.getModifiers())
                && Modifier.isFinal(pc.getModifiers())));
        System.out.println("exportedUnconditionally=" + module.isExported(pkg));
        System.out.println("openUnconditionally=" + module.isOpen(pkg));

        System.out.println("manualIsProxy=" + Proxy.isProxyClass(ManualProxy.class));
        System.out.println("manualSuperclass=" +
                (ManualProxy.class.getSuperclass() == Proxy.class));

        try {
            Proxy.getInvocationHandler(new ManualProxy(handler));
            System.out.println("manualHandler=unexpected");
        } catch (IllegalArgumentException expected) {
            System.out.println("manualHandler=IllegalArgumentException");
        }
    }
}
```

Compile/run from the directory containing the file using Java 21:

```sh
javac --release 21 -Xlint:all PublicProxyLab.java
java PublicProxyLab
```

**Stdout:**

```text
result=Hi Java
isProxy=true
sameHandler=true
implementsHello=true
directSuperclass=true
publicFinal=true
exportedUnconditionally=true
openUnconditionally=false
manualIsProxy=false
manualSuperclass=true
manualHandler=IllegalArgumentException
```

### 5.1. Output Explanation

- `Hello` is a **public member interface**. The JDK can generate a **public final** proxy class in a package that is **exported unconditionally but non-open**; hence the two exported/open values above.
- `Proxy.isProxyClass(pc)` is `true`, and `Proxy.getInvocationHandler(proxy) == handler` is `true`: the retrieved handler is the same registered object.
- `Hello.class.isAssignableFrom(pc)` confirms the generated class implements the interface, while the direct superclass is `Proxy.class`.
- `ManualProxy` also has `Proxy.class` as its direct superclass, but it was **written manually** rather than generated through the proxy factory. `Proxy.isProxyClass(ManualProxy.class)` returns `false`; calling `Proxy.getInvocationHandler` on this instance is rejected with `IllegalArgumentException`.
- The code **does not print `pc.getName()` or `module.getName()`** because those names must not be used as fixed results across JDKs.

**Example scope:** the handler only handles `say` and `toString`; if a real application calls `equals`/`hashCode`, an appropriate policy must be implemented to avoid returning the wrong type. In a general handler, exceptions and intentional calls to default methods must also be handled.

## 6. APIs Used to Identify and Inspect Proxies

| API | Correct Meaning | Limitations |
| --- | --- | --- |
| `Proxy.isProxyClass(clazz)` | `true` if `clazz` is a valid generated proxy class | Does not rely solely on name or `extends Proxy`; `clazz=null` throws `NullPointerException`. |
| `Proxy.getInvocationHandler(proxy)` | Returns the handler attached to a **proxy instance** | Non-proxy object: `IllegalArgumentException`; `null`: `NullPointerException`. |
| `obj.getClass()` | Concrete runtime class of the object | Does not by itself prove this is a real proxy. |
| `clazz.getSuperclass()` | A generated proxy has direct superclass `Proxy.class` | A class manually extending `Proxy` can also satisfy this; `isProxyClass` is needed. |
| `clazz.getInterfaces()` | List of proxy interfaces in **requested order** | Cannot replace checking generated proxy identity. |
| `clazz.getPackageName()` | Runtime package name | Do not hard-code JDK-generated package names. |
| `clazz.getModule()` | Actual `Module` containing the class | A named module does not by itself prove the package is exported/open. |
| `clazz.getClassLoader()` | Loader of the class | Same class name is not enough to infer class identity when loaders differ. |
| `Modifier.isPublic(clazz.getModifiers())` | Has the `public` flag on the class | A public class in a non-exported package is still not easily accessible outside the module. |
| `module.isExported(pkg)` | Package exported **to all modules** | Differs from `isExported(pkg, target)` when qualified exports exist. |
| `module.isOpen(pkg)` | Package open **to all modules** | Differs from `isOpen(pkg, target)`. |
| `module.canRead(otherModule)` | Module readability | Having a read edge is not enough to access members in a non-exported package. |

**How to identify a proxy object via API:**

```java
// Illustrative helper, placed inside a class that imports java.lang.reflect.Proxy.
static boolean isGeneratedProxy(Object value) {
    return value != null && Proxy.isProxyClass(value.getClass());
}
```

If you need to get the handler, check `isGeneratedProxy(value)` first, or let `Proxy.getInvocationHandler` throw the appropriate error. `Proxy.isProxyClass` is a check for **a class generated by the proxy mechanism**, **not** a security proof that the handler is trustworthy, the object is authorized, or the input is valid.

## 7. Lab 2 — Non-public Interface and Proxy in the Same Package/Module

Create the exact file path **`src/edu/packageprivate/PackagePrivateProxyLab.java`**:

```java
package edu.packageprivate;

import java.lang.reflect.InvocationHandler;
import java.lang.reflect.Modifier;
import java.lang.reflect.Proxy;

interface HiddenTask {
    String run();
}

public class PackagePrivateProxyLab {
    public static void main(String[] args) {
        InvocationHandler handler = (proxy, method, values) -> "done";
        HiddenTask task = (HiddenTask) Proxy.newProxyInstance(
                HiddenTask.class.getClassLoader(),
                new Class<?>[] { HiddenTask.class },
                handler);

        Class<?> pc = task.getClass();
        System.out.println("result=" + task.run());
        System.out.println("isProxy=" + Proxy.isProxyClass(pc));
        System.out.println("public=" + Modifier.isPublic(pc.getModifiers()));
        System.out.println("samePackage=" +
                pc.getPackageName().equals(HiddenTask.class.getPackageName()));
        System.out.println("sameModule=" + (pc.getModule() == HiddenTask.class.getModule()));
        System.out.println("sameLoader=" +
                (pc.getClassLoader() == HiddenTask.class.getClassLoader()));
        System.out.println("moduleNamed=" + pc.getModule().isNamed());
    }
}
```

In the project directory containing `src`:

```sh
javac --release 21 -Xlint:all -d out src/edu/packageprivate/PackagePrivateProxyLab.java
java -cp out edu.packageprivate.PackagePrivateProxyLab
```

**Stdout when running on this classpath:**

```text
result=done
isProxy=true
public=false
samePackage=true
sameModule=true
sameLoader=true
moduleNamed=false
```

### 7.1. Why Package/Module Differs from Lab 1

`HiddenTask` is a top-level **package-private interface** (no `public`). By specification, the proxy class must be **non-public and in the same package/module** as this interface. All non-public proxy interfaces (if multiple) must reside in the **same package and module**, not just share a simple name.

`moduleNamed=false` in the lab because the classes are running from the **classpath/unnamed module**. If the exercise is moved into a **named module**, this result can change, but the **sameModule=true** requirement for non-public interfaces still holds. Do not confuse a “non-public proxy class” with a “public proxy class in a non-exported dynamic module”: they are two different cases.

**Access note:** a class outside package `edu.packageprivate` cannot arbitrarily cast to `HiddenTask` from Java source; even if it obtains the proxy's `Class<?>`, public Reflection APIs must still obey access permissions to the actual class/member/package/module. Use a factory/contract from the proper module rather than trying to bypass access.

## 8. When Do Dynamic Modules Appear?

If **all proxy interfaces are public**, but **at least one interface** is in a package that is **non-exported and non-open**, the proxy class is generated as **public in a non-exported, non-open package of a dynamic module**.

Example:

```java
// module-info.java of a module that has a public interface in a hidden package.
module demo.hidden {
    // Intentionally does NOT exports/opens hidden.api.
}
```

This interface is `public`, but external modules cannot normally use that type name in Java source if the package is not exported. Nevertheless, code can obtain the `Class<?>` via class loading/Reflection and ask the JDK to create a proxy under valid conditions.

### 8.1. How Does a Dynamic Module Differ from the Interface's Declaring Module?

- `proxyClass.getModule()` is a module created by the JDK at runtime, **different** from the module containing the non-exported interface.
- The proxy's module can **read** the modules of its superinterfaces and the modules of reference types appearing in public method signatures.
- When a package containing a required interface/reference type is not exported, the JDK may update the module containing that type to **export the package specifically to the dynamic proxy module**. This **does not make the package exported unconditionally**, nor does it make it open to all code.
- The proxy package in the dynamic module is **non-exported/non-open**, so callers from other modules cannot access the generated proxy class via reflection like an ordinary public class.
- The proxy class **still has the `public` modifier**, because Java visibility flags and JPMS export/open are **two different permission layers**.

**Important consequence of the Java 21 Javadoc:** calling `Constructor.newInstance(...)` on a proxy class residing in a dynamic module from code outside that module throws `IllegalAccessException`. Use **`Proxy.newProxyInstance(...)`**, do not attempt to instantiate the generated class's constructor yourself.

This lab requires **three files**: a `module-info.java`, a public interface in a hidden package, and a classpath program to observe the proxy. Set up the exact structure:

│       └── hidden/api/SecretService.java

**`srcmods/demo.hidden/module-info.java`:**

**`srcmods/demo.hidden/hidden/api/SecretService.java`:**

package hidden.api;

public interface SecretService {

**`DynamicModuleProxyLab.java`:**

```java
import java.lang.reflect.Constructor;
import java.lang.reflect.InvocationHandler;
import java.lang.reflect.Modifier;
import java.lang.reflect.Proxy;

public class DynamicModuleProxyLab {
    public static void main(String[] args) throws Exception {
        Class<?> api = Class.forName("hidden.api.SecretService");
        Module apiModule = api.getModule();
        InvocationHandler handler = (proxy, method, values) -> "handled";

        Object proxy = Proxy.newProxyInstance(
                api.getClassLoader(), new Class<?>[] { api }, handler);
        Class<?> pc = proxy.getClass();
        Module pm = pc.getModule();
        String proxyPkg = pc.getPackageName();
        String apiPkg = api.getPackageName();

        System.out.println("apiNamed=" + apiModule.isNamed());
        System.out.println("apiExportedToAll=" + apiModule.isExported(apiPkg));
        System.out.println("apiOpenToAll=" + apiModule.isOpen(apiPkg));
        System.out.println("isProxy=" + Proxy.isProxyClass(pc));
        System.out.println("proxyPublic=" + Modifier.isPublic(pc.getModifiers()));
        System.out.println("proxyNamed=" + pm.isNamed());
        System.out.println("differentModule=" + (pm != apiModule));
        System.out.println("proxyExportedToAll=" + pm.isExported(proxyPkg));
        System.out.println("proxyOpenToAll=" + pm.isOpen(proxyPkg));
        System.out.println("canReadApi=" + pm.canRead(apiModule));
        System.out.println("apiExportedToProxy=" + apiModule.isExported(apiPkg, pm));
        System.out.println("sameHandler=" + (Proxy.getInvocationHandler(proxy) == handler));

        Constructor<?> ctor = pc.getConstructor(InvocationHandler.class);
        try {
            ctor.newInstance(handler);
            System.out.println("ctorAccess=unexpected");
        } catch (IllegalAccessException expected) {
            System.out.println("ctorAccess=IllegalAccessException");
        }
    }
}
```

If the module is not resolved, `Class.forName` will not have class `hidden.api.SecretService` available in this run mode. apiOpenToAll=false

### 9.2. Key Interpretations

1. **`apiNamed=true`**: the interface belongs to the named module `demo.hidden` declared by `module-info.java`.
2. **`apiExportedToAll=false`, `apiOpenToAll=false`**: package `hidden.api` is not publicly exported or opened.
3. **`isProxy=true`**: the object was genuinely generated by the `Proxy` factory, not a hand-written class.
4. **`proxyPublic=true`**: the access flag on the generated class is `public`.
5. **`proxyNamed=true` and `differentModule=true`**: the generated class resides in a **dynamic named module different** from the module containing the interface.
6. **`proxyExportedToAll=false` / `proxyOpenToAll=false`**: the generated class's package is encapsulated, even though the class has the public flag.
7. **`canReadApi=true`**: the dynamic proxy module has a read edge to the module containing the interface.
8. **`apiExportedToProxy=true`**: the JDK opens a **targeted export** from the package containing the interface to the dynamic module, allowing the generated class to implement the interface. The package is still **not exported to all modules**.
9. **`sameHandler=true`**: the handler is still accessible via `Proxy.getInvocationHandler` from outside the dynamic module.
10. **`ctorAccess=IllegalAccessException`**: even though the public `Constructor<?>` is retrieved, `Constructor.newInstance` from an external caller lacks permission because the proxy package is not exported. The correct way to create an instance is `Proxy.newProxyInstance`.

The lab output intentionally prints only **boolean properties**, not the generated module name or proxy package name. The JDK may use different internal names; application logic must not rely on them.

### 9.3. Do Not Equate Exported with Open

`apiModule.isExported(apiPkg,pm) == true` **does not mean** `apiModule.isOpen(apiPkg) == true` or `pm.isOpen(proxyPkg) == true`. **Exports** serve Java access checks for public types; **opens** serve deep reflection. Dynamic modules are designed to support proxy operation while maintaining encapsulation against unauthorized modules.

## 10. Identifying and Retrieving the Handler Properly

### 10.1. A Concise Inspection Flow

When given an object `candidate`:

```text
candidate == null ?
   |
   +--> yes: not a proxy instance
   |
   +--> no:
          |
          +--> Class<?> clazz = candidate.getClass()
          |
          +--> Proxy.isProxyClass(clazz) ?
                   |
                   +--> false: not a generated proxy
                   |
                   +--> true:
                          |
                          +--> Proxy.getInvocationHandler(candidate)
                          |
                          +--> clazz.getInterfaces()
                          +--> clazz.getModule()
                          +--> clazz.getPackageName()
```

Do not call `getInvocationHandler` with a non-proxy object to avoid `IllegalArgumentException`, or catch the error according to your API's responsibility. Do not unconditionally use `candidate.toString()` for identification logging: if the candidate is a proxy, `toString()` **may invoke the handler** and produce side effects.

### 10.2. A Handler Does Not Prove Trust

`Proxy.isProxyClass` serves to **identify a generated proxy class**. It does not prove that the invocation handler is trustworthy, does not guarantee that interface methods obey business logic, nor does it authenticate the caller's permissions. `getInvocationHandler` shows you the **handler object** attached to the instance, but inspecting the handler class may have permission/package/module restrictions.

If a plugin system uses dynamic proxies to wrap services, check the **interface contract** and **proxy creation source** per your system's design; do not allow any proxy instance to become a trusted capability just because `isProxyClass` returns true.

### 10.3. Interface Names and Order

`getInterfaces()` of the generated class preserves the exact order of interfaces passed to the factory. For interfaces with methods sharing the same name and parameter signature, **interface order** can also affect which `Method` the handler receives. Therefore, do not arbitrarily collapse the interface list into a `Set` and lose the order before creating the proxy.

`Proxy.newProxyInstance(loader, [A.class,B.class], h)` and `Proxy.newProxyInstance(loader, [B.class,A.class], h)` can create **two different proxy classes** per the specification. Do not rely on class names for caching; understand the **ordered** list together with the loader/context.

## 11. Input Constraints of `Proxy.newProxyInstance`

The Java 21 Javadoc specifies several fundamental conditions:

| Condition | Valid? | Common Issue |
| --- | --- | --- |
| Each `Class<?>` element is an **interface**, not a class/primitive | Mandatory | Passing `String.class` or `int.class`. |
| Interface is **not hidden and not sealed** | Mandatory | A sealed interface cannot be implemented by a generated proxy class not in the `permits` list. |
| No two interface elements are the **same Class object** | Mandatory | Passing `A.class` twice. |
| Interface is visible to the requested class loader | Mandatory | `Class.forName(i.getName(),false,loader) != i`. |
| Types in **public method signatures** are visible to the loader | Mandatory | The loader sees the interface but cannot see the method's parameter/return types. |
| All non-public interfaces must be in the **same package/module** and defined by the appropriate loader | Mandatory | Mixing two package-private interfaces in two different packages. |
| For methods with the same signature across multiple interfaces, return types are compatible | Mandatory | Two different primitive return types cannot be merged. |
| Does not exceed classfile/JVM limits | Mandatory | Too many interfaces or metadata. |

Violating these constraints leads to `IllegalArgumentException` per the contract of `newProxyInstance` (alongside other errors such as `NullPointerException` for null arguments). It cannot be fixed by naming the generated class, because the factory already chooses the package/module according to the rules.

**Class loader boundary:** the check `Class.forName(i.getName(), false, loader) == i` emphasizes **class identity**. Two interfaces with the same binary name defined by two different loaders can be two different `Class<?>` objects. Seeing the name in logs is not enough to guarantee the proxy factory can use that interface.

## 12. Lab 4 — Interface Order and Cases Where Proxy Creation Fails

This lab uses one main class and two package-private interfaces located in **two different packages**, to observe the package/module scope error firsthand.

Create the exact three files:

```text
project/
├── InvalidProxyLab.java
└── src/
    ├── edu/one/HiddenOne.java
    └── edu/two/HiddenTwo.java
```

**`src/edu/one/HiddenOne.java`:**

```java
package edu.one;
interface HiddenOne { void run(); }
```

**`src/edu/two/HiddenTwo.java`:**

```java
package edu.two;
interface HiddenTwo { void run(); }
```

**`InvalidProxyLab.java`:**

```java
import java.lang.reflect.InvocationHandler;
import java.lang.reflect.Proxy;

public class InvalidProxyLab {
    public sealed interface SealedTask permits ApprovedTask {
        void run();
    }

    public static final class ApprovedTask implements SealedTask {
        public void run() {}
    }

    public interface First { void f(); }
    public interface Second { void g(); }

    public static void main(String[] args) throws ClassNotFoundException {
        InvocationHandler handler = (proxy, method, values) -> null;
        ClassLoader loader = InvalidProxyLab.class.getClassLoader();

        Object first = Proxy.newProxyInstance(
                loader, new Class<?>[]{First.class, Second.class}, handler);
        Object reverse = Proxy.newProxyInstance(
                loader, new Class<?>[]{Second.class, First.class}, handler);
        System.out.println("orderChangesProxyClass=" +
                (first.getClass() != reverse.getClass()));
        System.out.println("firstInterface=" +
                first.getClass().getInterfaces()[0].getSimpleName());

        try {
            Proxy.newProxyInstance(loader, new Class<?>[]{SealedTask.class}, handler);
            System.out.println("sealed=unexpected");
        } catch (IllegalArgumentException expected) {
            System.out.println("sealed=IllegalArgumentException");
        }

        try {
            Proxy.newProxyInstance(loader, new Class<?>[]{String.class}, handler);
            System.out.println("class=unexpected");
        } catch (IllegalArgumentException expected) {
            System.out.println("class=IllegalArgumentException");
        }

        Class<?> one = Class.forName("edu.one.HiddenOne");
        Class<?> two = Class.forName("edu.two.HiddenTwo");
        try {
            Proxy.newProxyInstance(loader, new Class<?>[]{one, two}, handler);
            System.out.println("nonPublicMixed=unexpected");
        } catch (IllegalArgumentException expected) {
            System.out.println("nonPublicMixed=IllegalArgumentException");
        }

        try {
            Proxy.newProxyInstance(loader, new Class<?>[]{First.class, First.class}, handler);
            System.out.println("duplicate=unexpected");
        } catch (IllegalArgumentException expected) {
            System.out.println("duplicate=IllegalArgumentException");
        }
    }
}
```

**Compile and run commands:**

```sh
javac --release 21 -Xlint:all -d out InvalidProxyLab.java src/edu/one/HiddenOne.java src/edu/two/HiddenTwo.java
java -cp out InvalidProxyLab
```

**Stdout:**

```text
orderChangesProxyClass=true
firstInterface=First
sealed=IllegalArgumentException
class=IllegalArgumentException
nonPublicMixed=IllegalArgumentException
duplicate=IllegalArgumentException
```

**Explanation:**

- Interface order is part of the input to proxy class creation, not just a set of names.
- `SealedTask` is rejected because the JDK proxy factory does not accept sealed interfaces.
- `String.class` is a concrete class, not an interface.
- `edu.one.HiddenOne` and `edu.two.HiddenTwo` are both non-public interfaces but in different packages; a single non-public generated class cannot be placed in two packages at once.
- Passing the same `First.class` twice violates the requirement of no duplicate `Class<?>` in the interfaces array.

Other cases to check separately when building a real plugin: hidden interfaces, incompatible return types with matching signatures, class loaders that cannot see interface types, and corresponding module access.

## 13. Why Should You Not Create Objects Yourself via the Generated Constructor?

`Proxy.getProxyClass(loader, interfaces...)` still exists but has been **deprecated** since Java 9. A major reason is that a proxy class generated in a **named/dynamic module** may be encapsulated: obtaining `Class<?>` does not guarantee you are allowed to call its constructor.

**Not recommended:**

```java
// Illustrative anti-pattern snippet: reflecting on the generated proxy's constructor.
Class<?> proxyClass = proxy.getClass();
var constructor = proxyClass.getConstructor(java.lang.reflect.InvocationHandler.class);
Object another = constructor.newInstance(handler); // May throw IllegalAccessException!
```

**Recommended:**

```java
// Place inside a class that imports java.lang.reflect.Proxy.
// Both loader and apiInterface must refer to the exact runtime Class<?> identity.
Object another = Proxy.newProxyInstance(
        apiInterface.getClassLoader(),
        new Class<?>[]{apiInterface},
        handler);
```

For a non-exported/non-open dynamic module, `Constructor.newInstance` is rejected from callers outside the module. Trying `setAccessible(true)` is not a general solution: JPMS can block deep reflection with `InaccessibleObjectException` because the package is not open to the caller. Do not add `--add-opens` or break module boundaries just to avoid using the factory designed for this purpose.

**Design perspective:** `Proxy.newProxyInstance` is responsible for generating the class and returning the appropriate instance. Client code should operate through the **public interface contract**, rather than depending on the package/module structure of the generated class.

## 14. InvocationHandler and Methods Dispatched by the Proxy

The proxy class is the *runtime shape*, and the handler is the *behavior*. An interface method invocation on the proxy is encoded as a call to `InvocationHandler.invoke(proxy, method, args)`.

- The received `Method` describes the invoked method according to the proxy's dispatch rules; for methods colliding across interfaces, **interface order** affects `Method.getDeclaringClass()`.
- For `equals`, `hashCode`, and `toString` handled by the proxy from `Object`, the handler receives a `Method` whose declaring class is `Object.class`. Writing the handler must satisfy the return type (`boolean`/`int`/`String`) and the desired identity or value semantics.
- `args` can be `null` when the method takes no parameters. Do not always access `args[0]` without knowing which method was called.
- A default method on a proxy interface can be invoked via `InvocationHandler.invokeDefault` if the application wants to use the default implementation, instead of naively calling `method.invoke(proxy, args)` again which easily leads to recursion.
- The handler must adhere to the checked exception types declared by the interface; checked exceptions outside the contract may be wrapped in `UndeclaredThrowableException`.

**Module connection:** if the generated proxy class resides in an encapsulated dynamic module, you can still invoke it through an **accessible interface** or use the appropriate factory/handler APIs. This **does not automatically grant permission** for code in other modules to call every public method on the generated class via Reflection.

### 14.1. Do Not Log `proxy.toString()` “Just to Be Sure”

With a dynamic proxy, `toString()` can be dispatched to the handler. An accidental log statement can invoke business code or throw an exception. If you only want to inspect the type, obtain `proxy.getClass()`, `Proxy.isProxyClass`, `getModule()`, and metadata APIs; avoid invoking methods with side effects.

## 15. Common Errors and Diagnostic Workflow

| Symptom | Possible Cause | Fix / Verification |
| --- | --- | --- |
| `isProxyClass=false` even though the class extends `Proxy` | The class is a hand-written subclass, not a generated proxy | Use `Proxy.newProxyInstance` and `Proxy.isProxyClass`. |
| `isProxyClass=false` even though the name contains `$Proxy` | Class name is not proof of a proxy | Do not guess from the name; use the API. |
| `IllegalArgumentException` when creating a proxy | Invalid, duplicate, or sealed interface, different package/module, not visible, or conflicting return types | Check factory inputs against the Java 21 Javadoc. |
| `IllegalAccessException` when calling the generated constructor | Public proxy class but its package is in a non-exported dynamic module | Use `Proxy.newProxyInstance`. |
| `InaccessibleObjectException` after `setAccessible(true)` | Package is non-open to the caller | Do not bypass JPMS; switch to creating/accessing via factory/interface. |
| `ClassCastException` between two interfaces with the same name | Two types have the same binary name but different class loader identities | Compare `Class<?>` and loader, use a shared API module/loader. |
| `getInvocationHandler` throws `IllegalArgumentException` | Object is not a factory-generated proxy instance | Check `isProxyClass` first. |
| `getInvocationHandler(null)` fails | `null` is not an instance | Check for null explicitly. |
| `Modifier.isPublic=true` but Reflection cannot access it | JPMS package is not exported to the caller | Check `clazz.getModule().isExported(pkg, callerModule)`. |
| `Module.isExported(pkg) == false` yet the generated class can use the interface | Package has a **qualified export** to the dynamic proxy module | Check the overload `isExported(pkg, proxyModule)`. |
| Different proxy class when reversing interface order | Interface list order is a meaningful input | Preserve order when caching/initializing. |
| Proxy has strange package/module names | Generated package/module names are not guaranteed to be fixed | Read via `getPackageName()`, `getModule()`; do not hard-code. |
| Handler loops infinitely or throws on `toString`/`equals` | Dispatch through handler does not handle `Object` methods | Handle according to the method contract, do not naively re-invoke the proxy method. |

**Ordered debugging workflow:**

```text
[1] Identify the interface list (order, public/non-public, sealed, duplicates)
   |
[2] Inspect each interface: ClassLoader, Module, is package exported/open?
   |
[3] Confirm Class.forName(name,false,loader) == interfaceClass
   |
[4] Proxy.newProxyInstance(...) and classify proxy creation errors
   |
[5] For an instance: Proxy.isProxyClass(proxy.getClass())
   |
[6] Inspect proxyClass.getPackageName(), getModule(), flags
   |
[7] Distinguish isExported(pkg) from isExported(pkg, callerModule)
   |
[8] Proxy.getInvocationHandler(proxy), verify handler contract
   |
[9] Invoke through the authorized interface contract, avoid generated constructor
```

Do not turn a class loading or module visibility error into a decision to “try every package/module” in an uncontrolled manner; class identity and access policies must be clearly designed.
