# 4.5. Handling WildcardType, GenericArrayType, and the limits of type erasure

> **Context:** In the *Java Advance – dynamic-runtime* module, group **4. Metadata**, this lesson focuses on how to read and interpret generic signatures using Reflection in Java 21. The two cases that need careful handling are **`WildcardType`** and **`GenericArrayType`**. We also need to understand precisely which information remains in a declaration's metadata and which information is removed by **type erasure** at runtime. The examples run with JDK 21, without external libraries.

## 1. Objectives and prerequisites

After this lesson, you should be able to do the following:

1. Correctly identify the five common forms of `java.lang.reflect.Type`: `Class<?>`, `ParameterizedType`, `TypeVariable<?>`, `WildcardType`, and `GenericArrayType`.
2. Read the upper bounds (`getUpperBounds()`) and lower bounds (`getLowerBounds()`) of a wildcard, including the case of `?` without declared bounds.
3. Extract the component of a generic array via `GenericArrayType.getGenericComponentType()` and distinguish it from an array type represented by `Class<?>`.
4. Explain type erasure according to JLS rules, determining why `getGenericType()` can provide the generic signature of a *declaration* while `getType()` only provides the post-erasure type.
5. Write Reflection code that checks `instanceof` before casting `Type`, traverses nested generic structures, and does not assume a type parameter can be traced back from an object alone.
6. Point out how a subclass/type reference preserves a generic declaration, its limitations, and bridge methods generated by the compiler.

**Prerequisites:** Java generics (`List<T>`, `? extends T`, `? super T`), arrays, basic Reflection (`Class`, `Field`, `Method`), generic methods, and how to run programs with `javac`/`java`.

## 2. The `Type` model: viewing metadata as a tree

`Type` is an interface in `java.lang.reflect`. Results from Reflection are not necessarily a `Class<?>`. The foundational model:

```text
java.lang.reflect.Type
  ├── Class<?>             : String, int, String[], List (raw)
  ├── ParameterizedType    : List<String>, Map<String, Integer>
  ├── TypeVariable<?>      : T in class/method <T extends Number>
  ├── WildcardType         : ?, ? extends Number, ? super Integer
  └── GenericArrayType    : T[], List<String>[]
```

A multi-level declaration example:

```java
// Illustrative declaration; place inside a class that imports java.util.Map and List.
Map<String, List<? extends Number>[]> payload;
```

When accessing `Field.getGenericType()`, Reflection sees an equivalent structure:

```text
ParameterizedType: Map<..., ...>
  ├── Class: String
  └── GenericArrayType: List<? extends Number>[]
      └── ParameterizedType: List<...>
          └── WildcardType: ? extends Number
              └── upper bound: Class Number
```

**Key lesson:** Do not directly call `(Class<?>) field.getGenericType()`. Depending on the declaration, the cast can cause a `ClassCastException`. Branch by the actual kind and then traverse into children.

| Where to read | API | Result to understand |
| --- | --- | --- |
| Field | `Field.getType()` | `Class<?>` of the post-erasure type: `List<String>` → `List.class`, `T[]` → array of the erased bound. |
| Field | `Field.getGenericType()` | A `Type`, which may be `ParameterizedType`, `GenericArrayType`, `TypeVariable`, `Class<?>`. |
| Method | `Method.getReturnType()` / `getGenericReturnType()` | Erased return type versus generic declaration. |
| Method | `Method.getParameterTypes()` / `getGenericParameterTypes()` | Array of erased `Class<?>` versus array of generic `Type`. |
| Class | `getSuperclass()` / `getGenericSuperclass()` | Erased superclass versus generic declaration of the superclass. |
| Class | `getInterfaces()` / `getGenericInterfaces()` | Erased interfaces versus generic declarations. |
| Generic declaration | `Class.getTypeParameters()` or `Method.getTypeParameters()` | `TypeVariable<?>[]` describing the **definition** of the type parameter, not the type bound by an instance. |

`Type.getTypeName()` is useful for logging. For array classes, `Class.getName()` may return a JVM format like `[Ljava.lang.String;`, whereas `getTypeName()` is suitable for displaying in the form `java.lang.String[]`. When using `ParameterizedType`, `getRawType()` is usually `Class<?>`; `getActualTypeArguments()` returns a `Type[]` array where each element may itself be another generic type. `getOwnerType()` is worth noting when encountering nested/member classes.

## 3. `WildcardType`: handling `?`, `extends`, and `super`

A wildcard expresses an **unspecified concrete type** in a type argument position. It differs from a `TypeVariable` that is **declared with a name** like `T` in `class Box<T>`.

| Declaration | Runtime node of argument | `getUpperBounds()` | `getLowerBounds()` |
| --- | --- | --- | --- |
| `List<?>` | `WildcardType` | `[Object]` | `[]` |
| `List<? extends Number>` | `WildcardType` | `[Number]` | `[]` |
| `List<? super Integer>` | `WildcardType` | `[Object]` | `[Integer]` |
| `List<String>` | `Class<?>` argument `String.class` | Not `WildcardType` | Not `WildcardType` |
| `List<T>` | `TypeVariable<?>` argument `T` | Use `getBounds()` of `TypeVariable` | Not a lower-bound wildcard |

How to read bounds:

- **`? extends Number`:** the unknown type is some subtype of `Number`. Use `getUpperBounds()`; lower bounds are empty.
- **`? super Integer`:** the unknown type is `Integer` or one of its supertypes. Use `getLowerBounds()`; the default upper bound is `Object`.
- **`?`:** no upper/lower bound declared, so the default upper bound is `Object` and the lower bound array is **empty**.
- **`T extends Number & Comparable<T>`:** this is a `TypeVariable`, and `getBounds()` can contain **multiple** upper bounds, one of which is a `ParameterizedType`; do not confuse it with a wildcard.

The API returns a **`Type[]` array**, not directly a `Class<?>` or a string. Do not write `wildcard.getLowerBounds()[0]` before checking the length. Under current Java syntax, a wildcard typically has at most one bound on each side, but process all elements returned by the API to avoid hardcoded assumptions.

### 3.1. PECS and read/write behavior

PECS (*Producer Extends, Consumer Super*) explains why this wildcard is useful in source code:

- `List<? extends Number>`: elements can be read as `Number`; an arbitrary `Integer`/`Double` cannot be added because the actual element type may be another subtype (adding `null` is a special case that is allowed).
- `List<? super Integer>`: `Integer` can be added; reading back in a generally type-safe manner yields `Object`.
- `List<?>`: read as `Object`; arbitrary non-null elements cannot be added.

These are **compile-time type checking rules**. Reflection returns metadata describing those rules, but does not turn a generic element type into an automatic runtime check for each element.

## 4. `GenericArrayType`: when the component is not yet a fully reifiable type

An array whose component is a **parameterized type** or **type variable** in a generic declaration is typically represented by `GenericArrayType`:

| Field declaration | `getGenericType()` is | Component read via |
| --- | --- | --- |
| `String[] texts;` | `Class<?>` (array class) | `((Class<?>) type).getComponentType()` |
| `int[][] matrix;` | `Class<?>` (array class) | Loop `Class.getComponentType()` to the final element |
| `T[] values;` | `GenericArrayType` | `getGenericComponentType()` → `TypeVariable<?>` |
| `List<String>[] groups;` | `GenericArrayType` | `getGenericComponentType()` → `ParameterizedType` of `List<String>` |
| `List<?>[] groups;` | `GenericArrayType` in the field's declaration metadata | `getGenericComponentType()` → `ParameterizedType` with wildcard argument |

Clearly distinguish between **declaring a variable with a generic array type** and **creating an array**:

- `List<String>[] groups;` is a **valid** field/variable declaration.
- `new List<String>[3]` is a **compile error** (*generic array creation*): the component `List<String>` is not reifiable.
- `new T[3]` is also not allowed when `T` is a regular type variable.
- `List<?>[] slots = new List<?>[3];` is allowed, because `List<?>` is a reifiable form according to the JLS.
- `String[] strings = new String[3];` works because `String` is reifiable and the runtime array knows the component is `String.class`.

**Why?** Arrays carry a runtime component type and perform checks when assigning elements; regular generic type arguments are erased. If `new List<String>[n]` were allowed while array covariance still operated, it would easily break the type-checking assumptions of generic elements. `GenericArrayType` is only a **type description in metadata**, not an actual array object for allocation.

`java.lang.reflect.Array.newInstance(Class<?> component, int length)` only accepts a runtime `Class<?>` for the component. It cannot create a `List<String>[]` with runtime enforcement for the `String` parameter from a `ParameterizedType` alone. If using an unchecked cast for a generic array, you must clearly understand and limit the trust boundary of the data.

**Multi-dimensional arrays:** for `T[][]`, `GenericArrayType.getGenericComponentType()` may continue to be another `GenericArrayType`; you need to recurse until reaching `TypeVariable`. For `String[][]`, the outer type is still `Class<?>` and `getComponentType()` can be used multiple times.

## 5. Lab 1: reading bounds and generic arrays with Reflection

Create the file **`TypeInspectionLab.java`**:

```java
import java.lang.reflect.GenericArrayType;
import java.lang.reflect.ParameterizedType;
import java.lang.reflect.Type;
import java.lang.reflect.TypeVariable;
import java.lang.reflect.WildcardType;
import java.util.Arrays;
import java.util.List;
import java.util.stream.Collectors;

public final class TypeInspectionLab<T extends Number & Comparable<T>> {
    private List<? extends Number> source;
    private List<? super Integer> target;
    private List<?> unknown;
    private List<String>[] listArray;
    private T[] genericArray;
    private String[] ordinaryArray;

    private static String names(Type[] bounds) {
        return Arrays.stream(bounds)
                .map(Type::getTypeName)
                .collect(Collectors.joining(", ", "[", "]"));
    }

    private static void inspect(String name) throws NoSuchFieldException {
        Type type = TypeInspectionLab.class.getDeclaredField(name).getGenericType();
        if (type instanceof ParameterizedType parameterized) {
            Type[] arguments = parameterized.getActualTypeArguments();
            if (arguments.length == 1 && arguments[0] instanceof WildcardType wildcard) {
                System.out.println(name + ": upper=" + names(wildcard.getUpperBounds())
                        + ", lower=" + names(wildcard.getLowerBounds()));
            }
        } else if (type instanceof GenericArrayType array) {
            System.out.println(name + ": generic array of "
                    + array.getGenericComponentType().getTypeName());
        } else if (type instanceof Class<?> arrayClass && arrayClass.isArray()) {
            System.out.println(name + ": ordinary array of "
                    + arrayClass.getComponentType().getTypeName());
        }
    }

    public static void main(String[] args) throws NoSuchFieldException {
        inspect("source");
        inspect("target");
        inspect("unknown");
        inspect("listArray");
        inspect("genericArray");
        inspect("ordinaryArray");
        TypeVariable<?> variable = TypeInspectionLab.class.getTypeParameters()[0];
        System.out.println("T bounds=" + names(variable.getBounds()));
    }
}
```

Compile/run in the directory containing the file, using **JDK 21**:

```sh
javac --release 21 -Xlint:all TypeInspectionLab.java
java TypeInspectionLab
```

**Exact stdout:**

```text
source: upper=[java.lang.Number], lower=[]
target: upper=[java.lang.Object], lower=[java.lang.Integer]
unknown: upper=[java.lang.Object], lower=[]
listArray: generic array of java.util.List<java.lang.String>
genericArray: generic array of T
ordinaryArray: ordinary array of java.lang.String
T bounds=[java.lang.Number, java.lang.Comparable<T>]
```

### 5.1. Explaining the output

1. `getDeclaredField(name).getGenericType()` reads the field signature from the **declaration** in the class file. There is no need to create an instance of `TypeInspectionLab` or initialize field values.
2. `List<? extends Number>` is a `ParameterizedType` with raw type `List` and argument being a `WildcardType` with upper bound `Number`.
3. `List<? super Integer>` has lower bound `Integer`, default upper bound `Object`. `List<?>` has default upper bound `Object` and an empty lower array.
4. `List<String>[]` has a component that is `ParameterizedType`; `T[]` has a component that is `TypeVariable<?>`. Neither of those two forms may be cast to `Class<?>`.
5. `String[]` is a reifiable array class, so the `Class<?> && isArray()` branch uses `getComponentType()`.
6. `T extends Number & Comparable<T>` keeps **two bounds in the generic declaration**. These are not two bounds of a wildcard; that is information belonging to `TypeVariable`.

**An intentional limitation of the lab:** the `inspect` method only prints the field forms known in the lesson. In general metadata-processing code, you need to recursively traverse generic arguments and array components, without assuming a field has exactly one type argument.

## 6. Lab 2: wildcards used in code vs. wildcard metadata

Create **`WildcardUseLab.java`**:

```java
import java.util.ArrayList;
import java.util.List;

public final class WildcardUseLab {
    static void addScores(List<? super Integer> destination) {
        destination.add(7);
        destination.add(5);
    }

    static int sum(List<? extends Number> source) {
        int total = 0;
        for (Number n : source) {
            total += n.intValue();
        }
        return total;
    }

    public static void main(String[] args) {
        List<Number> scores = new ArrayList<>();
        addScores(scores);
        System.out.println("sum=" + sum(scores));
    }
}
```

```sh
javac --release 21 -Xlint:all WildcardUseLab.java
java WildcardUseLab
```

**Stdout:**

```text
sum=12
```

`? super Integer` allows `addScores` to accept `List<Integer>` or `List<Number>` and write `Integer` into it. `? extends Number` allows `sum` to read elements as `Number`. Even though `List<Number>` can be passed to both, **`List<Integer>` is not a subtype of `List<Number>`**: Java's generic types are fundamentally *invariant*, and wildcards create use-site variance bounds.

Using Reflection, `Method.getGenericParameterTypes()` can read the signatures `List<? super Integer>` and `List<? extends Number>` respectively from the declaration. Conversely, `Method.getParameterTypes()` will return the post-erasure parameter type `List.class` for each method (each method here has a different name so they do not conflict).

## 7. Type erasure: what data remains, what data is lost?

Java generics have **type erasure**: most type arguments are used for type checking at **compile time**, after which many places in bytecode use the erased type. According to JLS `4.6:

| Type in source code | Erasure |
| --- | --- |
| `List<String>` | `List` |
| `Map<String, List<Integer>>` | `Map` |
| `T` when `<T>` is unbounded | `Object` |
| `T` when `<T extends Number>` | `Number` |
| `T` when `<T extends Number & Comparable<T>>` | `Number` (leftmost bound) |
| `T[]` | Array of the erased type of `T`, e.g. `Number[]` |
| `List<String>[]` | `List[]` (runtime component does not carry the `String` argument) |

Erasure **does not mean** Java deletes every trace of generics in the class file. The compiler typically stores **generic signatures of declarations** (fields, methods, superclass/interfaces, type parameters), and Reflection has `getGeneric...` APIs to read that metadata back. However, the object `new ArrayList<String>()` itself **does not carry** a separate runtime class for `ArrayList<String>`. Nor can you infer `String` solely via `list.getClass()`.

Two statements must both be true:

- `getGenericType()` of a field declared as `List<String>` can return a `ParameterizedType` describing `List<String>`, because that is **information at the declaration site**.
- `getClass()` of an instance of `ArrayList<String>` and `ArrayList<Integer>` returns the same runtime class `ArrayList` (in the example using the same concrete class), because type arguments are not reified into two different classes.

**Operations invalid at compile time:**

- `List<String>.class` (there is no class literal for a concrete generic instantiation).
- `value instanceof List<String>` (the `String` argument cannot be checked at runtime; `instanceof List<?>` is allowed).
- `new List<String>[2]` (generic array creation is invalid).
- Declaring two overloads differing only in `List<String>` vs. `List<Integer>` at the same parameter position, because after erasure they have the same method signature.

### 7.1. Heap pollution risk

`List<String>` does not automatically check that every element contains `String` at runtime. If a raw/unchecked path inserts an `Integer` into a structure that a client assumes is `List<String>`, a `ClassCastException` error may appear **later when reading the element and the compiler-inserted cast executes**. Generics also do not allow you to use `getClass()` to enforce a full validator based on nested type arguments.

Arrays are different: the runtime still knows the component class of `String[]`, so a wrongly typed write through an `Object[]` alias can throw `ArrayStoreException`. The difference between **array covariance + runtime component check** and **generic invariance + erasure** explains many hard-to-remember rules about generic arrays and unchecked conversions.

When handling external data (JSON, plugin payload, RPC), generic metadata is a **schema/hint**, not proof that the current object actually contains elements of the right type. If correctness is required, validate the data structure and values at the trust boundary.

## 8. Lab 3: contrasting generic declarations and runtime classes

Create **`ErasureLab.java`**:

```java
import java.lang.reflect.Field;
import java.lang.reflect.ParameterizedType;
import java.lang.reflect.Type;
import java.util.ArrayList;
import java.util.List;

public final class ErasureLab {
    static class Holder<T extends Number> {
        T item;
        List<String> names;
    }

    static final class IntegerHolder extends Holder<Integer> { }

    static abstract class TypeRef<T> {
        private final Type type;

        protected TypeRef() {
            Type parent = getClass().getGenericSuperclass();
            if (!(parent instanceof ParameterizedType parameterized)) {
                throw new IllegalStateException("Missing type argument");
            }
            type = parameterized.getActualTypeArguments()[0];
        }

        Type type() {
            return type;
        }
    }

    public static void main(String[] args) throws NoSuchFieldException {
        Class<?> stringListClass = new ArrayList<String>().getClass();
        Class<?> integerListClass = new ArrayList<Integer>().getClass();
        System.out.println("same runtime class: " + (stringListClass == integerListClass));

        Field item = Holder.class.getDeclaredField("item");
        Field names = Holder.class.getDeclaredField("names");
        System.out.println("item generic: " + item.getGenericType().getTypeName());
        System.out.println("item runtime: " + item.getType().getTypeName());
        System.out.println("names generic: " + names.getGenericType().getTypeName());
        System.out.println("names runtime: " + names.getType().getTypeName());

        ParameterizedType parent =
                (ParameterizedType) IntegerHolder.class.getGenericSuperclass();
        System.out.println("subclass argument: "
                + parent.getActualTypeArguments()[0].getTypeName());

        Type captured = new TypeRef<List<String>>() { }.type();
        System.out.println("captured: " + captured.getTypeName());
    }
}
```

```sh
javac --release 21 -Xlint:all ErasureLab.java
java ErasureLab
```

**Exact stdout:**

```text
same runtime class: true
item generic: T
item runtime: java.lang.Number
names generic: java.util.List<java.lang.String>
names runtime: java.util.List
subclass argument: java.lang.Integer
captured: java.util.List<java.lang.String>
```

### 8.1. Analyzing what is preserved

- The two `ArrayList` instances have the same `Class<?>`; there is no separate `Class<List<String>>` to look up from an instance.
- `Holder.item` is declared as `T extends Number`: `Field.getGenericType()` gives `T`, while `Field.getType()` gives `Number.class` because the erasure of `T` is its first bound.
- `Holder.names` is declared concretely as `List<String>`: the generic signature can read the `String` parameter, while the runtime field type is only `List`.
- `IntegerHolder extends Holder<Integer>` puts the **concrete `Integer` into the supertype declaration**, so `getGenericSuperclass()` sees that argument.
- `new TypeRef<List<String>>() { }` creates an **anonymous subclass** whose generic superclass contains `List<String>` in its metadata. `TypeRef` reads the signature of the **subclass**, rather than inferring the type from an `ArrayList` inside the object.

This is the underlying mechanism of many *type token/type reference* patterns in libraries. It works when the programmer **deliberately writes a generic type into an inheritance declaration**. If there is only an object that does not store a generic argument in any reliable signature, the standard Reflection API **cannot recover** the argument lost due to erasure.

**Additional limitation:** a `List<T>` field in a generic base class still describes the letter `T` when calling `getGenericType()` directly on that field. If a subclass binds `T = Integer`, a metadata processor needs to build a `TypeVariable → Type` mapping along the inheritance path, rather than assuming `Field.getGenericType()` will automatically substitute `T` with `Integer` in all contexts.

## 9. Bridge methods: a consequence of overriding generics

Type erasure sometimes causes the compiler to generate an additional **bridge method** to preserve proper polymorphism at the bytecode level. When using Reflection to iterate over methods, do not assume every method you see is a method written directly in source.

Create **`BridgeLab.java`**:

```java
import java.lang.reflect.Method;
import java.util.Arrays;
import java.util.Comparator;

public final class BridgeLab {
    static class Parent<T> {
        T get() { return null; }
    }

    static final class Child extends Parent<String> {
        @Override String get() { return "ok"; }
    }

    public static void main(String[] args) {
        Arrays.stream(Child.class.getDeclaredMethods())
                .filter(m -> m.getName().equals("get"))
                .sorted(Comparator.comparing(Method::isBridge))
                .forEach(m -> System.out.println(m.getReturnType().getSimpleName()
                        + " bridge=" + m.isBridge()));
    }
}
```

```sh
javac --release 21 -Xlint:all BridgeLab.java
java BridgeLab
```

**Exact stdout on JDK 21 with `javac`:**

```text
String bridge=false
Object bridge=true
```

`Parent<T>.get()` is erased to a method returning `Object`. `Child.get()` returns `String`, so the compiler emits a bridge method returning `Object` that forwards to the `String`-returning implementation. `Method.isBridge()` helps detect it; `isSynthetic()` is also useful when filtering compiler-generated methods. Sorting by `isBridge` in the lab gives the output a deterministic order, because the raw order of `getDeclaredMethods()` is not guaranteed.

A framework that auto-discovers handlers or mapping methods needs to decide whether to skip the bridge or merge it with the target, avoiding registering the same behavior twice. Observe further with:

```sh
javap -v 'BridgeLab$Child'
```

On Windows PowerShell or Linux/macOS you can use single quotes as above; on Windows CMD, use double quotes to avoid shell syntax dependencies. Pay attention to the `ACC_BRIDGE` and `ACC_SYNTHETIC` flags in the class file.

## 10. Generally processing a `Type` tree

In a mapper, validator, or plugin registry library, a function that only handles `ParameterizedType` and casts every argument to `Class<?>` will break when encountering `List<? extends T[]>`. The processing mindset must be **recursive by node kind**, not splitting strings from `getTypeName()` with regex.

### 10.1. Traversal rules and actions

| Node | What to read | Next step |
| --- | --- | --- |
| `Class<?>` | `isArray()`, `getComponentType()`, class identity | If it is an array, traverse the component; otherwise, it is a leaf type (or inspect class metadata when needed). |
| `ParameterizedType` | `getRawType()`, `getOwnerType()`, `getActualTypeArguments()` | Traverse each argument and owner type if present, preserving the relationship with the raw type. |
| `WildcardType` | **Both** `getUpperBounds()` and `getLowerBounds()` | Traverse all bounds; distinguish default `Object` from explicit constraints. |
| `GenericArrayType` | `getGenericComponentType()` | Traverse the component; it may be a `ParameterizedType`, `TypeVariable`, or another generic array. |
| `TypeVariable<?>` | `getName()`, `getGenericDeclaration()`, `getBounds()` | Keep the declaration scope; if resolution is needed, use a mapping from the superclass/interface/method context. |

Core pattern for processing a node (illustrative helper snippet, placed in a class that already imports `java.lang.reflect.*` and `java.util.Set`):

```java
static void walk(Type type, Set<Type> active) {
    if (!active.add(type)) {
        return; // avoid infinite recursion, e.g. T extends Comparable<T>
    }
    try {
        if (type instanceof Class<?> cls) {
            if (cls.isArray()) walk(cls.getComponentType(), active);
        } else if (type instanceof ParameterizedType p) {
            walk(p.getRawType(), active);
            if (p.getOwnerType() != null) walk(p.getOwnerType(), active);
            for (Type t : p.getActualTypeArguments()) walk(t, active);
        } else if (type instanceof WildcardType w) {
            for (Type b : w.getUpperBounds()) walk(b, active);
            for (Type b : w.getLowerBounds()) walk(b, active);
        } else if (type instanceof GenericArrayType a) {
            walk(a.getGenericComponentType(), active);
        } else if (type instanceof TypeVariable<?> v) {
            for (Type b : v.getBounds()) walk(b, active);
        }
    } finally {
        active.remove(type);
    }
}
```

The function above illustrates the **traversal structure**, so it does not log or produce AST output yet; in an application, add callbacks for each node/edge and retain both path and scope. `active` is the **set of nodes currently on the recursion branch**, not a global “seen” list: the same `Type` can legitimately appear on multiple branches. A `TypeVariable` self-referencing through `Comparable<T>` puts naive recursion without a cycle guard at risk of running infinitely. Use `Set<Type>` based on `equals`, avoiding relying on object identity (`==`) for all Reflection objects.

**Additional points to check in production code:**

- A `TypeVariable` with the same name `T` in two different generic declarations is **not equivalent**. Do not use the name string alone as a key; keep `getGenericDeclaration()`.
- When encountering `ParameterizedType`, `getOwnerType()` may carry type arguments of the outer class; ignoring the owner can cause incorrect resolution of nested generic classes.
- Parsing data from non-standard bytecode may encounter `GenericSignatureFormatError`, `TypeNotPresentException`, or `MalformedParameterizedTypeException`. Handle errors at the plugin/module boundary and report sufficient diagnostic context.
- If you need to inspect annotations directly at a type use/bound, the `AnnotatedType` API and `TypeVariable.getAnnotatedBounds()` can provide metadata beyond the standard `Type` tree.
- When looking up a method via Reflection by name and `Class<?>...` parameters, pass the corresponding **erased types**; `Method.getGenericParameterTypes()` only reads back the generic signature after the method has been found.

### 10.2. Why not write a type-string parser?

`getTypeName()` is suitable for printing, but it is not an AST/parser contract for a generic resolver system. Splitting `Map<String, List<? extends T[]>[]>` by commas or `<` will fail with multiple levels of nesting. Use the `Type` interfaces themselves to preserve order, generic argument boundaries, arrays, wildcard bounds, and owner declarations.

## 11. Common errors and false assumptions

| Symptom | Cause | Fix |
| --- | --- | --- |
| `ClassCastException` when casting `Type` to `Class<?>` | Actual type is `ParameterizedType`, `WildcardType`, or `GenericArrayType` | Branch with `instanceof` first; traverse recursively. |
| `ArrayIndexOutOfBoundsException` with `getLowerBounds()[0]` | `?` or `? extends ...` has empty lower bounds | Check the array, iterate over all bounds. |
| Thinking `? super Integer` has upper bound `Integer` | Misunderstanding the meaning of “super” | Default upper is `Object`; lower contains `Integer`. |
| `getGenericType()` gives `T` instead of `String` | Field is declared in a generic base class, inheritance context not yet resolved | Build a type variable mapping from generic superclass/interfaces. |
| `getClass()` only gives `ArrayList` | Type erasure on runtime instances | Obtain the type from a contract/declaration or a pre-declared type reference; do not infer it from the instance. |
| `ClassCastException` or corrupt data after unchecked cast | Heap pollution, type arguments are not checked in collections | Eliminate raw types, minimize unchecked conversions, validate elements at the boundary. |
| `GenericSignatureFormatError` / `TypeNotPresentException` | Corrupted bytecode signature or missing referenced type | Check classpath/module path, build tool/bytecode source, and clearly report the type/field. |
| Losing generic array info when using `getType()` | Only retrieves the erased class of the array | Use `getGenericType()` and check `GenericArrayType`. |
| Method processed twice | Bridge/synthetic methods exist | Check `Method.isBridge()`, `isSynthetic()`, and map to the real method. |
| Infinite recursion on `T extends Comparable<T>` | Traversing self-referential bounds without a guard | Use a set of active types on the current branch, preserving declaration scope. |

**Checklist when writing a runtime metadata library:**

1. Use the generic Reflection API at the right declaration site; preserve `Type` objects when passing them between layers.
2. Branch across all `Type` forms, without indexing bounds or casting arbitrarily.
3. Be clear whether you are reading **generic signature metadata** or checking **runtime object values**; the two do not substitute for each other.
4. Resolve generic inheritance based on context-aware declaration mappings; manage cycles in the type graph.
5. For external data, create validation at the boundary; avoid using generic metadata as proof of runtime type safety.
6. Re-run labs with `javac --release 21 -Xlint:all`, check warnings, and inspect bytecode/bridges when needed.

## 13. Java 21 official documentation

- [`WildcardType` — Java SE 21](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/reflect/WildcardType.html): `getUpperBounds()`, `getLowerBounds()`.
- [`GenericArrayType` — Java SE 21](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/reflect/GenericArrayType.html): `getGenericComponentType()`.
- [`ParameterizedType` — Java SE 21](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/reflect/ParameterizedType.html): raw type, type arguments, owner type.
- [`TypeVariable` — Java SE 21](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/reflect/TypeVariable.html): bounds and generic declaration.
- [`Field` — Java SE 21](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/reflect/Field.html): `getType()`, `getGenericType()`.
- [Java Language Specification 21, chapter 4](https://docs.oracle.com/javase/specs/jls/se21/html/jls-4.html): `4.5.1` (wildcards), `4.6` (type erasure), `4.7` (reifiable types).
- [Java Language Specification 21, chapter 10](https://docs.oracle.com/javase/specs/jls/se21/html/jls-10.html): array types, generic array creation, and store checks.

**Technical takeaway:** `WildcardType` and `GenericArrayType` help accurately read the **generic shape of a declaration**. Type erasure still limits what the runtime knows about **an instance's type arguments**. A good metadata processor must respect both of these facts.
