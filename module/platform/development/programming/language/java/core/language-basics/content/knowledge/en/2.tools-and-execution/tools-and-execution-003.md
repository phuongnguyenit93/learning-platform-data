# Running a Class with java and Distinguishing Class Names from File Names

## 1. What you need to understand before typing commands

In the traditional Java workflow, you **write source code in a `.java` file**, use **`javac`** to compile the source code into one or more **`.class` files**, and then use the **`java`** command to launch a class that has a program entry point.

~~~mermaid
flowchart LR
    A["Welcome.java<br/>Source file name"] -->|"javac"| B["Welcome.class<br/>Bytecode"]
    B -->|"java Welcome<br/>Class name"| C["JVM loads class<br/>and calls main"]
    C --> D["Program runs"]
~~~

**Core rule:** in **compiled class execution** mode, the main argument to `java` is the **class name**, usually including the package name if one exists. You do **not** pass the `.class` file path as if it were an executable program.

For example, the three commands below do not have the same meaning:

| Command | Meaning |
|---|---|
| `javac Welcome.java` | Compiles the source file `Welcome.java` |
| `java Welcome` | Runs the class named `Welcome` that the JVM finds on the classpath |
| `java Welcome.java` | Runs the **source file** using source-file mode (available since Java 11), not running the already compiled `Welcome` class as in the line above |

The examples use **JDK 17 or higher**. Open the terminal in the exact directory shown in the example or adjust paths to match your machine.

## 2. Running a simple class without a package

Create the file **`Welcome.java`** with the following content:

~~~java
public class Welcome {
    public static void main(String[] args) {
        String person = args.length > 0 ? args[0] : "Java";
        System.out.println("Xin chao, " + person + "!");
    }
}
~~~

Open a terminal in the directory containing `Welcome.java`. Confirm that the JDK tools are available:

~~~bash
java -version
javac -version
~~~

Compile and run:

~~~bash
javac --release 17 -encoding UTF-8 Welcome.java
java -cp . Welcome
java -cp . Welcome Lan
~~~

Output of the two `java` commands, in order:

~~~text
Xin chao, Java!
Xin chao, Lan!
~~~

Explanation of each part:

- `javac` reads **`Welcome.java`** and, if compilation succeeds, creates **`Welcome.class`** in the current directory.
- `--release 17` targets Java 17-compatible syntax/APIs/class-file format; the compiler in use must support this release level.
- `-encoding UTF-8` specifies how to read source code; it does not guarantee the terminal displays all Unicode characters identically.
- `java` is the runtime launcher program; it starts the JVM to find and execute the class.
- `-cp .` sets the classpath to the current directory; the dot `.` is a directory path, **not a file extension**.
- `Welcome` is the **class name**, not `Welcome.java` or `Welcome.class`.
- `Lan` is an application argument; for this program it becomes `args[0]`.

Thanks to the condition `args.length > 0`, running without arguments does not cause an `ArrayIndexOutOfBoundsException`.

### Equivalent commands in Bash and PowerShell

The `javac` and `java` syntax above **works in both Bash and PowerShell**. For example, to list the input file and generated bytecode:

**Bash (Linux/macOS/Git Bash):**

~~~bash
ls Welcome.java
javac --release 17 -encoding UTF-8 Welcome.java
ls Welcome.class
java -cp . Welcome
~~~

**PowerShell (Windows):**

~~~powershell
Get-Item .\Welcome.java
javac --release 17 -encoding UTF-8 .\Welcome.java
Get-Item .\Welcome.class
java -cp . Welcome
~~~

The path `.\Welcome.java` used when invoking `javac` is **the path to the source file**. When invoking `java` to run the class, you still write **`Welcome`** because that is the class name the JVM needs to locate.

## 3. Three commonly confused names

| Concept | Example | Where is it used? |
|---|---|---|
| **Source file name** | `Welcome.java` | Argument to `javac`; opened/edited in an editor |
| **Declared class name** | `Welcome` in `class Welcome` | Identifier name of the class |
| **Bytecode file name** | `Welcome.class` | File produced by `javac` for the JVM to load |
| **Fully qualified class name** | `demo.Welcome` | Name when the class belongs to package `demo` |
| **Source path** | `src/demo/Welcome.java` | File location on disk |
| **Classpath root** | `out` | Directory or entry set where the runtime searches for classes |

Do not infer the class name solely from the file name. **Read the `class` and `package` declarations**, then identify the classpath root containing the bytecode.

In `public class Welcome` in the main example, Java requires the public source file name to be `Welcome.java`. On case-sensitive systems, `welcome.java` and `Welcome.java` are different names.

## 4. When the source file name is not the runnable class name

A `.java` file can contain multiple top-level classes (*top-level class*) as long as it follows the rule for `public` classes. Create the file **`Examples.java`**:

~~~java
class Helper {
    static String message() {
        return "Hello from Helper";
    }
}

class Runner {
    public static void main(String[] args) {
        System.out.println(Helper.message());
    }
}
~~~

Run:

~~~bash
javac --release 17 Examples.java
java -cp . Runner
~~~

Output:

~~~text
Hello from Helper
~~~

`javac` can generate **`Helper.class`** and **`Runner.class`**, even though the source file is named **`Examples.java`**. Reason: no top-level class is declared `public`, so the source file name does not have to match `Runner`.

**The command `java -cp . Examples` will not run this example**, because there is no class named `Examples`. Try `java -cp . Runner` instead.

Conversely, if you declare `public class Runner`, the file containing it must be named **`Runner.java`**. This is a compilation rule, not a rule forcing every source name to always match the runnable class name.

## 5. Packages change the name used with the java command

Consider the project structure:

~~~text
project/
└── src/
    └── demo/
        └── Welcome.java
~~~

File `src/demo/Welcome.java`:

~~~java
package demo;

public class Welcome {
    public static void main(String[] args) {
        String who = args.length > 0 ? args[0] : "Java";
        System.out.println("Xin chao tu demo, " + who + "!");
    }
}
~~~

The `package demo;` part means the class has a **fully qualified class name** of `demo.Welcome`, no longer just `Welcome` in the default package.

From the `project` directory, create the output directory before compiling.

**Bash:**

~~~bash
mkdir -p out
javac --release 17 -encoding UTF-8 -d out src/demo/Welcome.java
java -cp out demo.Welcome Lan
~~~

**PowerShell:**

~~~powershell
New-Item -ItemType Directory -Force out | Out-Null
javac --release 17 -encoding UTF-8 -d out src/demo/Welcome.java
java -cp out demo.Welcome Lan
~~~

Output:

~~~text
Xin chao tu demo, Lan!
~~~

After compilation, the important structure will be:

~~~text
project/
├── src/
│   └── demo/
│       └── Welcome.java
└── out/
    └── demo/
        └── Welcome.class
~~~

Analyzing the run command **`java -cp out demo.Welcome Lan`**:

- `-cp out`: where the JVM starts searching for classes.
- `demo.Welcome`: the class to run, consisting of **package + class name**.
- `Lan`: argument passed to the program, not part of the class name.

**The classpath must point to `out`, not `out/demo`**, because the JVM uses the `demo` package to look up the corresponding path beneath the classpath root.

~~~mermaid
flowchart TD
    CP["Classpath root: out/"] --> PK["Package: demo/"]
    PK --> BC["Welcome.class"]
    CMD["java -cp out demo.Welcome"] --> CP
~~~

When in the `project` directory, the following invocations are **different**:

| Command | Evaluation |
|---|---|
| `java -cp out demo.Welcome` | Correct |
| `java -cp out Welcome` | Wrong full class name |
| `java -cp out/demo demo.Welcome` | Wrong classpath root |
| `java -cp out/demo Welcome` | May cause an error where the internal class name does not match the path/package; not the proper way to run |
| `java -cp out demo/Welcome.class` | Wrong: passing a file path instead of a class name |

## 6. Program entry point: the class must have an appropriate main

In Java 17, to use standard class execution examples as above, the target class needs the method:

~~~java
public static void main(String[] args) {
    // Execution starts here
}
~~~

An equivalent variant can use `String... args`. However, the methods below are **not standard Java 17 entry points**:

~~~java
// Wrong return type:
public static int main(String[] args) { return 0; }

// Wrong because static is missing:
public void main(String[] args) { }

// Wrong parameter type:
public static void main(int[] args) { }
~~~

The classes can still **compile successfully** if those methods are valid as ordinary methods; the error appears when you try to launch them as a main class without a supported entry point.

**Do not mix Java 17 rules with newer `main` forms from other Java versions.** This lesson uses JDK 17 so syntax and commands can be compared consistently.

### Main class vs. helper class

A program may use dozens of classes, but the `java` command needs to know **which class is the entry point**. For example, `Runner` calls `Helper.message()`; `Helper` not having `main` does not prevent `Runner` from running. However, running `java Helper` as the main class will lack a suitable entry point.

## 7. Distinguishing class mode from running source directly

Since Java 11, the launcher also has **source-file mode**, allowing a simple source file to be run directly:

~~~bash
java Welcome.java
~~~

Comparing the approaches:

| Approach | Command | Meaning |
|---|---|---|
| **Class mode** | `javac Welcome.java` then `java Welcome` | You compile first; the launcher locates a class already on the classpath |
| **Source-file mode** | `java Welcome.java` | The launcher processes the source code for execution on that invocation; does not require you to produce a `.class` saved on disk |
| **JAR mode** | `java -jar program.jar` | The launcher uses entry-point metadata of an executable JAR and corresponding classpath rules |

The two commands `java Welcome` and `java Welcome.java` differ due to **launcher mode**, not merely how the extension is written. In class mode, do not write `.java` or `.class` after the class name.

Source-file mode has its own compilation and organization rules; it is handy for quickly testing small examples. When you need to inspect bytecode, control the classpath, or simulate a build workflow, practice `javac` followed by `java` first.

**Do not confuse `java -jar app.jar` with `java -cp app.jar demo.Welcome`:** `-jar` mode relies on entry-point configuration such as `Main-Class` in the JAR's manifest; using `-cp` requires you to specify the class to run. Not every JAR file can be run directly with `-jar`.

## 8. Classpath is not a path to a single .class file

The classpath is a set of **locations to search for classes and libraries**. An entry can be a directory containing a package tree or a JAR file.

For example, with application classes in `out/` and a library in `lib/example.jar`:

**Bash (Linux/macOS):**

~~~bash
java -cp "out:lib/example.jar" demo.Welcome
~~~

**PowerShell (Windows):**

~~~powershell
java -cp "out;lib/example.jar" demo.Welcome
~~~

The separator between classpath entries is **`:` on Linux/macOS** and **`;` on Windows**; using Bash or PowerShell does not itself decide the separator—the **operating system running the JVM** is the determining factor. With Git Bash running Windows Java, `;` is normally still used.

Note: the `demo.Welcome` example above does not need `example.jar`; the snippet only illustrates multiple classpath entry syntax, so only use it when that JAR actually exists. The minimal command to run the demo is `java -cp out demo.Welcome`.

When there is only one entry such as `out` or `.`, no separator is needed.

## 9. Errors when typing java and how to diagnose them

| Message / symptom | Possible cause | How to check |
|---|---|---|
| `Could not find or load main class Welcome` | Wrong class name, wrong classpath, or not yet compiled | Check where `.class` is, verify the `class` name and `-cp` |
| `ClassNotFoundException: demo.Welcome` | Class loader could not find the class name to load | Check whether `out/demo/Welcome.class` and `-cp out` are present |
| `NoClassDefFoundError` with `wrong name` | Package name in bytecode does not match location/invocation | Check `package` declaration, classpath root, and fully qualified name |
| `Main method not found` | Class exists but has no suitable entry point | Check the `public static void main(String[] args)` signature |
| `UnsupportedClassVersionError` | JVM is too old to read the compiled class file | Compare `java -version`, `--release` level, and compiling JDK |
| Running produces old output even after editing `.java` | Running a stale `.class` | Save source, re-run `javac`, check output directory |
| `javac` reports public class name does not match file name | Wrong source file name | Rename to `Welcome.java` for `public class Welcome` |
| `java` is not recognized | JDK/runtime or `PATH` is not configured properly | Check JDK installation, `PATH` configuration, open a new terminal |

**Quick checklist when class mode fails to run:**

1. Which directory are you currently in? Bash: `pwd`; PowerShell: `Get-Location`.
2. Did `javac` run successfully? If compilation failed, an old `.class` file may still remain.
3. Which `package` and `class` does the file actually declare?
4. Under which classpath directory does the `.class` file reside?
5. Did you invoke **`java -cp <root> package.ClassName`**?
6. If the class exists but cannot launch, check the `main` signature and `java -version`.

Avoid randomly changing file names, packages, and classpaths all at once; verify each condition individually to find the real cause.

## 10. Using javap to confirm a class has been compiled

The JDK includes `javap` to inspect class file information without running the program. For the `demo` package example:

~~~bash
javap -classpath out demo.Welcome
~~~

You will see information about `demo.Welcome`, including the method `public static void main(java.lang.String[])`. To view bytecode:

~~~bash
javap -classpath out -c demo.Welcome
~~~

`javap` helps answer “which class name can the JVM find, and which methods were compiled?” but **does not replace execution or testing**. Exact output varies by compiler/JDK.

You can also compare after editing source code: if `javac` has not been re-run, `javap` continues describing the old `.class` on that classpath.

## 11. Edge cases to remember

**File name and public class name differ.** `public class SalesApp` in `Program.java` causes a compile error. Meanwhile, `Program.java` containing only a non-public `class SalesApp` can compile into `SalesApp.class`; at runtime use `java SalesApp`.

**Package differs from current directory.** With `demo.Welcome`, the class name must be written in full when launching, even if you are near the `Welcome.class` file. Changing the current directory does not turn the class's full name into `Welcome`.

**Multiple classes in a single source file.** There is no rule that “one source file always produces one class file.” Nested classes also have their own bytecode naming conventions; let the compiler and launcher handle them instead of manually renaming `.class` files.

**Application arguments follow the class name.** `java -cp out demo.Welcome Lan` passes `Lan` into `args`; options like `-cp out` belong to the launcher. Misplacing them can cause strings to be interpreted as arguments or class names.

**JVM differs from compiling JDK.** If a machine has multiple Java versions, `javac -version` and `java -version` may differ. Even with the right class name, the wrong runtime version can still trigger `UnsupportedClassVersionError`.

**Paths containing spaces.** Quote file/directory paths appropriately for your shell:

~~~bash
javac -d "build output" "src/demo/Welcome.java"
java -cp "build output" demo.Welcome
~~~

Before using `-d`, create the output directory appropriately for your environment. Quotes protect paths; **they do not turn a class name into a path**.

**Only changing source contents.** In class mode, the JVM does not automatically recompile modified source files. To run updated source, run `javac` again first; source-file mode is a different mode.

## 12. Self-check exercises with answers

### Exercise A — choose the right run command

Given `Hello.java`:

~~~java
public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello");
    }
}
~~~

You ran `javac Hello.java` successfully in the current directory. Which command runs the **compiled class**?

A. `java Hello.java`  
B. `java Hello`  
C. `java Hello.class`

**Answer:** B. A invokes source-file mode on a supporting runtime; C uses the wrong file extension in class mode.

### Exercise B — predict javac outputs

Source file named `Tools.java`:

~~~java
class Util {
    static int twice(int x) { return x * 2; }
}
class Program {
    public static void main(String[] args) {
        System.out.println(Util.twice(4));
    }
}
~~~

**Question:** which class files are generated and how do you run it?

**Answer:** when compiled successfully, `Util.class` and `Program.class` are generated; run `java -cp . Program`, output is `8`. `Tools.java` does not create a `Tools` class because there is no `class Tools` declaration.

### Exercise C — spot the wrong classpath root

Compiled `package school;` and `public class Main` into `out/school/Main.class`. Which command is correct?

~~~bash
java -cp out school.Main
~~~

**Answer:** that exact command above. Do not use `-cp out/school` or `java -cp out Main`.

### Exercise D — pass an argument in the right position

From the `Welcome` program, you want `args[0]` to be `Binh`. Write the command.

**Answer:** `java -cp . Welcome Binh` with the class in the default package and `Welcome.class` in the current directory.

### Exercise E — source edited but output unchanged

You changed `System.out.println("A");` to `System.out.println("B");` in `Welcome.java`, then re-ran `java Welcome` and still saw `A`.

**Answer:** you are very likely running an old `Welcome.class` or another class with the same name on another classpath. Save the source, re-run `javac Welcome.java`, use an explicit classpath, and verify the output file.

### Exercise F — diagnose “Main method not found”

File `MathTool.java` contains:

~~~java
public class MathTool {
    public static int square(int n) {
        return n * n;
    }
}
~~~

**Question:** why does `javac MathTool.java` succeed while `java MathTool` fails?

**Answer:** the class declaration and `square` method are valid, but the class lacks a `main` entry point compatible with Java 17 launch mode. Add `public static void main(String[] args)` to call `square` or write a `Runner` class with `main` and call `MathTool.square(3)`.

When running a compiled class, use `java -cp <classpath-root> package.ClassName` (or just `ClassName` if there is no package). **The `.java` file name is the input to the compiler; the class name is the target the launcher needs to find to execute.**
