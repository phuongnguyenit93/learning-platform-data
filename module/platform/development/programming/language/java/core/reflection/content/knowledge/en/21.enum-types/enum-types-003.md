# Field.isEnumConstant: identifying fields that represent enum constants

## 1. An enum has multiple kinds of fields

An enum class does not only contain the constants listed at the beginning of its declaration. It can also have instance fields for each object, static fields added by the author, and helper fields generated by the compiler.

Therefore, when iterating over `getDeclaredFields()`, the question "does this field belong to an enum?" is not enough. Documentation generators or metadata inspection tools often need a more precise question: **does this field represent a declared enum constant?**

`Field.isEnumConstant()` answers that question:

~~~java
// Method of java.lang.reflect.Field:
public boolean isEnumConstant();
~~~

- Returns `true` if the field represents an enum constant.
- Returns `false` for other fields.
- The result is a `boolean`, not an enum object and not the value currently stored in the field.

The API definition is in the [Field.isEnumConstant](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/reflect/Field.html#isEnumConstant()) documentation.

A key distinction to keep clear from the start: this is a classification of the **field declaration**, not a check of "whether the field's value is an enum object".

## 2. Why are enum constants seen as Fields?

Consider the declaration:

~~~java
enum Priority {
    LOW, HIGH;

    static final Priority DEFAULT = LOW;
}
~~~

`LOW` and `HIGH` are enum constants. Java has corresponding fields named `LOW` and `HIGH`, with declared type `Priority`, with `public static final` attributes implicitly declared.

`DEFAULT` is also a field of type `Priority`, but declared by the author after the semicolon. It holds a reference to `LOW`; it does not add another constant to the set `LOW, HIGH`.

You can visualize this as:

~~~text
Constant declaration LOW
    -> field LOW represents an enum constant
    -> isEnumConstant() = true

Field declaration DEFAULT = LOW
    -> regular field referencing an existing constant
    -> isEnumConstant() = false
~~~

The rules for implicit fields corresponding to enum constants are described in [JLS §8.9.3](https://docs.oracle.com/javase/specs/jls/se21/html/jls-8.html#jls-8.9.3).

Do not equate "enum constant" with the term **constant variable** in Java's constant expression rules. In that sense, a constant variable is a `final` variable of primitive type or `String` initialized with a constant expression. An enum-typed field does not belong to that group; looking at `final` alone does not identify it as an enum constant.

## 3. Complete example: enum constants, aliases, and regular data

Create the file `EnumConstantFieldDemo.java`:

~~~java
import java.lang.reflect.Field;
import java.util.Arrays;

public class EnumConstantFieldDemo {
    public enum Status {
        NEW(10),
        DONE(20) {
            @Override
            public String toString() {
                return "finished";
            }
        };

        public static final Status DEFAULT = NEW;
        public static final String LABEL = "status";
        private final int code;

        Status(int code) {
            this.code = code;
        }
    }

    static void inspect(String name) throws NoSuchFieldException {
        Field field = Status.class.getDeclaredField(name);
        System.out.println(name
                + " -> enumConstant=" + field.isEnumConstant()
                + ", synthetic=" + field.isSynthetic()
                + ", type=" + field.getType().getSimpleName());
    }

    public static void main(String[] args)
            throws ReflectiveOperationException {
        inspect("NEW");
        inspect("DONE");
        inspect("DEFAULT");
        inspect("LABEL");
        inspect("code");

        System.out.println("constant fields (name order): "
                + Arrays.stream(Status.class.getDeclaredFields())
                        .filter(Field::isEnumConstant)
                        .map(Field::getName)
                        .sorted()
                        .toList());

        System.out.println("constants (declaration order): "
                + Arrays.stream(Status.class.getEnumConstants())
                        .map(Status::name)
                        .toList());

        Field newField = Status.class.getDeclaredField("NEW");
        Field aliasField = Status.class.getDeclaredField("DEFAULT");
        System.out.println("NEW and DEFAULT same object: "
                + (newField.get(null) == aliasField.get(null)));

        Status done = Status.DONE;
        System.out.println("DONE runtime class is enum: "
                + done.getClass().isEnum());
        System.out.println("DONE declaring enum: "
                + (done.getDeclaringClass() == Status.class));
        System.out.println("DONE name: " + done.name());
        System.out.println("DONE display: " + done);
    }
}
~~~

The program uses Java 17 or later. Compile and run:

~~~bash
javac --release 17 -encoding UTF-8 EnumConstantFieldDemo.java
java EnumConstantFieldDemo
~~~

Exact output:

~~~text
NEW -> enumConstant=true, synthetic=false, type=Status
DONE -> enumConstant=true, synthetic=false, type=Status
DEFAULT -> enumConstant=false, synthetic=false, type=Status
LABEL -> enumConstant=false, synthetic=false, type=String
code -> enumConstant=false, synthetic=false, type=int
constant fields (name order): [DONE, NEW]
constants (declaration order): [NEW, DONE]
NEW and DEFAULT same object: true
DONE runtime class is enum: false
DONE declaring enum: true
DONE name: DONE
DONE display: finished
~~~

The field names in `inspect(...)` are specified explicitly so the output does not depend on the order returned by `getDeclaredFields()`. When printing the list of constant fields, the program deliberately sorts by name.

### 3.1. NEW and DONE are enum constants

The two constants are declared before the semicolon in `Status`. Therefore, both corresponding fields have `isEnumConstant() == true`.

`DONE` has a constant-specific body to override `toString()`. That does not remove the enum constant role of the `Status.DONE` field.

### 3.2. DEFAULT is a reference alias

`DEFAULT` is declared as follows:

~~~java
public static final Status DEFAULT = NEW;
~~~

It has the same declared type as the `NEW` field, and its value is the same object as `Status.NEW`. However:

- The `NEW` field represents the enum constant `NEW`.
- The `DEFAULT` field is a regular static field referencing that object.
- `DEFAULT` does not increase the number of enum constants and does not appear in `Status.values()`.

This is why the line `NEW and DEFAULT same object: true` can appear alongside `DEFAULT -> enumConstant=false`. The two results describe different aspects and do not contradict each other.

### 3.3. Neither LABEL nor code is an enum constant

`LABEL` is a static field holding a string. `code` is an instance data field belonging to each `Status` object. Both are declared inside the enum, yet both have `isEnumConstant() == false`.

Saying "every field of an enum is an enum constant" would cause a tool to mistake both data fields and configuration fields for options in the list.

## 4. Do not replace the API with guesses

| Check method | Why is it insufficient? |
| --- | --- |
| Uppercase field name | Only a naming convention; `DEFAULT` and `LABEL` are also uppercase |
| Field has `static final` | Regular fields can also have both modifiers |
| Field is `public static final` | The `DEFAULT` alias in the example satisfies this yet is not an enum constant |
| `field.getType().isEnum()` | The `DEFAULT` field has type `Status` and still returns `false` for `isEnumConstant()` |
| `field.getDeclaringClass().isEnum()` | Both `code` and `LABEL` are declared in `Status` |
| Read value is `instanceof Enum<?>` | The alias's value is also an enum object; and it requires reading the value |
| `!field.isSynthetic()` | Many author-declared fields are non-synthetic yet are not enum constants |

At the class file level, a field representing an enum constant carries the `ACC_ENUM` flag. This is standardized classification metadata; using `isEnumConstant()` makes the code express its intent without hand-writing bit checks. Field flags are described in [JVMS §4.5](https://docs.oracle.com/javase/specs/jvms/se21/html/jvms-4.html#jvms-4.5).

### isSynthetic is not the negation of isEnumConstant

In the sample program, all five printed fields have `isSynthetic() == false`, yet only `NEW` and `DONE` are enum constants.

The compiler can also generate helper fields, such as an internal array serving `values()`. That helper field is not an enum constant. Do not look it up by a fixed name like `$VALUES`, because implementation names and details are not an interface for applications to depend on.

The fact that constant fields are implicitly declared by Java does not mean they must be marked synthetic. They represent constants present in the language declaration; query each property using its corresponding API.

## 5. Distinguishing Field.isEnumConstant from Class.isEnum

The two methods differ in their receiver object and meaning:

- `field.isEnumConstant()`: does this field represent an enum constant?
- `type.isEnum()`: does this class token represent the enum declaration class itself?

In the program, `DONE` has its own body:

~~~java
DONE(20) {
    @Override
    public String toString() {
        return "finished";
    }
}
~~~

This is an excerpt from the enum declaration, not a standalone Java program.

The constant-specific body creates an anonymous subclass for that constant. Consequently:

| Expression | Result in the example |
| --- | --- |
| `Status.class.isEnum()` | `true` |
| `Status.class.getDeclaredField("DONE").isEnumConstant()` | `true` |
| `Status.class.getDeclaredField("DONE").getType() == Status.class` | `true` |
| `Status.DONE.getClass().isEnum()` | `false` |
| `Status.DONE.getDeclaringClass() == Status.class` | `true` |

`getType()` on a field reads the **declared type of the field**. `getClass()` on an object reads the **runtime class of the object**. These two classes can differ when an enum constant has a constant-specific body.

If you already hold an `Enum<?>` object and want to find its declaring enum class, use `enumValue.getDeclaringClass()`. Do not assume `enumValue.getClass()` is always the appropriate token for enumerating constants.

Also do not confuse two methods with the same name:

- `Field.getDeclaringClass()` returns the class declaring the field.
- `Enum.getDeclaringClass()` returns the enum class declaring the constant represented by the object.

In the example, both can return `Status.class`, but they originate from two different kinds of objects.

## 6. Metadata differs from values: when is the enum initialized?

You can check whether a field is an enum constant without reading the object stored in the field:

~~~java
// Illustrative snippet in the context of the sample program.
Field field = Status.class.getDeclaredField("NEW");
boolean constant = field.isEnumConstant();
~~~

Neither `field.get(...)` nor `setAccessible(true)` is needed for this classification.

If you need to read the value of a static field, you can use `field.get(null)`. For a static field, the receiver object argument is ignored; passing `null` makes the intent clear. Reading is still subject to access control. A field being `public` does not mean every declaring class and module boundary is automatically accessible from everywhere.

More importantly, reading a static field via Reflection can initialize the declaring class if the class has not yet been initialized. The following experiment demonstrates the difference.

Create the file `EnumMetadataInitializationDemo.java`:

~~~java
import java.lang.reflect.Field;

public class EnumMetadataInitializationDemo {
    public enum Mode {
        ON;

        static {
            System.out.println("Mode initialized");
        }
    }

    public static void main(String[] args)
            throws ReflectiveOperationException {
        Field field = Mode.class.getDeclaredField("ON");
        System.out.println("metadata: " + field.isEnumConstant());
        System.out.println("before reading value");
        System.out.println("value: " + field.get(null));
    }
}
~~~

Compile and run in a new Java process:

~~~bash
javac --release 17 -encoding UTF-8 EnumMetadataInitializationDemo.java
java EnumMetadataInitializationDemo
~~~

Output:

~~~text
metadata: true
before reading value
Mode initialized
value: ON
~~~

The first two lines appear before `Mode initialized`. Obtaining the `Mode.class` token, finding the field metadata, and calling `isEnumConstant()` did not trigger the static block in this experiment. Only at `field.get(null)` was the enum class initialized and the `Mode.ON` value read.

This is a useful distinction for inspection tools: if you only need to classify fields, do not read values unnecessarily. Class initialization can execute application-defined code. If initialization fails, the read operation can fail according to class initialization rules, rather than remaining a simple metadata flag query.

The example does not modify enum constants. `isEnumConstant()` does not grant permission to change field values, and finding a `Field` is no reason to attempt writing to `final` constant fields.

## 7. Choosing an enumeration approach by goal

| Goal | Suitable approach |
| --- | --- |
| Already have a `Field`, need to classify it | `field.isEnumConstant()` |
| Need constant fields to read names or annotations | Iterate `getDeclaredFields()`, filter with `Field::isEnumConstant` |
| Know the enum at compile time, need the values | Call `Status.values()` |
| Only know the class token at runtime, need the values | Call `enumType.getEnumConstants()` |
| Need metadata of a constant whose name is known | `enumType.getDeclaredField(name)`, then verify with `isEnumConstant()` |

`getDeclaredFields()` does not guarantee declaration order. In the example, we sorted fields by name to obtain a stable result `[DONE, NEW]`.

By contrast, `values()` and `Class.getEnumConstants()` return constants in declaration order, so the result is `[NEW, DONE]`. If the token does not represent an enum class, `getEnumConstants()` returns `null`; for an enum without constants, it returns an empty array. Those two situations are different.

If you need both **declaration order** and field metadata, go from the enum values to their declared names. Place the following example in `main()` of the first program:

~~~java
for (Status value : Status.class.getEnumConstants()) {
    Field field = Status.class.getDeclaredField(value.name());
    System.out.println(field.getName() + ": " + field.isEnumConstant());
}
~~~

Output for this added snippet alone:

~~~text
NEW: true
DONE: true
~~~

Use `name()` to look up the field, not `toString()`. In the example:

- The declared name of the constant is `DONE`.
- The display string of the object is `finished`, because `toString()` was overridden.
- There is no constant field named `finished`.

Going through the values can initialize the enum class. Choose this approach when declaration order is needed and retrieving the values is acceptable; if only metadata classification is needed, filtering fields suffices.

`getFields()` only considers `public` fields and may include inherited fields. `getDeclaredFields()` focuses on fields declared directly in the class, including other access levels and helper fields. For the task of identifying constants of the enum under inspection itself, starting from `getDeclaredFields()` and using a clear predicate is usually easier to control.

## 8. Applied example: retrieving constant metadata for a tool

A documentation generator might need the `Field` objects to read annotations attached to each constant, rather than only retrieving the enum objects.

The following method accepts the **declaring enum class token** and returns the constant fields sorted by name. This is a helper method, not a standalone Java file. Add imports for `java.lang.reflect.Field`, `java.util.Arrays`, `java.util.Comparator`, `java.util.List`, and `java.util.Objects` to the enclosing class.

~~~java
static List<Field> enumConstantFields(Class<?> enumType) {
    Objects.requireNonNull(enumType, "enumType");

    if (!enumType.isEnum()) {
        throw new IllegalArgumentException(
                "Expected an enum declaration class: " + enumType.getName());
    }

    return Arrays.stream(enumType.getDeclaredFields())
            .filter(Field::isEnumConstant)
            .sorted(Comparator.comparing(Field::getName))
            .toList();
}
~~~

Example call in the context of the sample program:

~~~java
List<Field> fields = enumConstantFields(Status.class);
for (Field field : fields) {
    System.out.println(field.getName());
}
~~~

Output of the call snippet:

~~~text
DONE
NEW
~~~

If the input is `Status.DONE.getClass()`, the helper method rejects it because that is the constant's own subclass, not the declaring enum class. When starting from an enum object, pass `value.getDeclaringClass()` if the goal is to inspect the enum containing that constant.

Filtering with `isEnumConstant()` prevents `DEFAULT`, `LABEL`, `code`, and helper fields from entering the constant list. The tool can proceed to read annotations on each `Field` using the corresponding annotation APIs; whether annotations can be read at runtime also depends on the annotation's retention policy.

## 9. Mistakes to avoid

1. **Using a field's type to conclude it is an enum constant.** `DEFAULT` has an enum type yet is only an alias.
2. **Reading the value and checking the object to classify the field.** That confuses the value with the declaration role and can trigger unnecessary class initialization.
3. **Filtering all non-synthetic fields.** Regular data fields are also typically non-synthetic.
4. **Trusting that the array from getDeclaredFields is in declaration order.** Sort if you want a stable order; use the value APIs and map back by name if you want enum constant order.
5. **Using toString as the field name.** Display strings can be overridden or localized; `name()` is the declared name required to look up a constant field.
6. **Taking getClass of a constant with its own body to scan the enum.** Distinguish a constant's subclass from the declaring enum class.
7. **Assuming identifying a constant means it can be modified.** This API only answers a classification question.

## 10. Self-check

With the `Status` enum in the sample program:

1. Why can `NEW` and `DEFAULT` hold the same object yet return different `isEnumConstant()` results?
2. `code` is declared inside the enum; does that make it an enum constant?
3. Does `Status.DONE.getClass().isEnum()` returning `false` cause the `DONE` field to lose its enum constant role?
4. Why does the name-sorted field list start with `DONE`, while the declaration-order value list starts with `NEW`?
5. To look up the field metadata of `Status.DONE`, should you use `done.name()` or `done.toString()`?
6. If you only need to know whether a field is an enum constant, do you need to call `field.get(null)`?
7. If `enumType.getEnumConstants()` returns `null`, should that be interpreted as an enum with no constants?

Answers:

1. `NEW` is the field representing a constant declared in the constant list; `DEFAULT` is a regular field referencing an existing constant. The predicate checks the role of the field.
2. No. It is data belonging to each enum object.
3. No. The object's runtime subclass is distinct from the field's declared role.
4. The two lists use different ordering rules; `getDeclaredFields()` itself does not guarantee declaration order.
5. Use `name()`, which gives the string `DONE`. `toString()` in the example gives `finished`.
6. No. `isEnumConstant()` reads field classification metadata; reading the value is a separate operation.
7. No. `null` indicates the token is not an enum class; an enum with no constants returns an empty array.
