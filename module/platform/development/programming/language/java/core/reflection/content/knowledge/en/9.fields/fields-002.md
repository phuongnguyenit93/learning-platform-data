# How getFields() differs from getDeclaredFields() with inheritance — Java Reflection

When reading a class's structure with Reflection, both `Class.getFields()` and `Class.getDeclaredFields()` return a `Field[]` array, but they answer **two different questions**:

- **`getFields()`:** "Which `public` fields are within the public member lookup scope of this class/interface, including fields in superclasses and superinterfaces?"
- **`getDeclaredFields()`:** "Which fields does the class/interface under inspection **directly declare**, regardless of `public`, `protected`, package-private, or `private`?"

Therefore, `getDeclaredFields()` is **not** a "more complete" version of `getFields()` regarding inheritance. It retrieves non-public fields *in the class itself*, but **does not automatically traverse parent class fields**. To analyze the entire inheritance chain, a program usually must combine `getDeclaredFields()` with `getSuperclass()`.

## 1. Lookup scope comparison table

| Scenario | `SomeClass.class.getFields()` | `SomeClass.class.getDeclaredFields()` |
| --- | --- | --- |
| `public` field declared directly in `SomeClass` | Yes | Yes |
| `private`, `protected`, package-private field declared directly in `SomeClass` | No | Yes |
| `public` field in a superclass | Yes | No |
| `private`, `protected`, package-private field in a superclass | No | No |
| `public static final` constant declared in an interface that the class implements/extends | Yes within the relevant interface scope | No if the interface is the declaring type |
| `static` field | Yes if `public` within lookup scope | Yes if directly declared, regardless of access level |
| Synthetic field generated by the compiler | May appear if it meets `public`/scope conditions | May appear if declared in the bytecode of the class itself |
| Element order in the array | Not guaranteed | Not guaranteed |

**Key point:** "Declared" refers to **where it is declared**, not "only accessible fields", and "Fields" does not mean "all fields". Even if a subclass has no `public` fields, `getFields()` can still return `public` fields from a parent class or interface.

Java 17 standard documentation:
- `Class.getFields()`: https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/lang/Class.html#getFields()
- `Class.getDeclaredFields()`: https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/lang/Class.html#getDeclaredFields()

## 2. Mechanism when a subclass inherits from a superclass

Consider the relationship:

```text
                 interface Labeled
                 + CATEGORY: String (public static final)
                         ^
                         | implements
class Base              |
+ name: String (public) |
+ version: int (public static)
+ level: int (protected)
+ token: long (private)
       ^                 |
       | extends         |
       +------ class Child
               + name: String (public, hides Base.name)
               + active: boolean (public)
               + note: String (private)
```

With `Child.class`:

- `getFields()` finds the `public` fields of `Child`, the `public` fields from `Base`, and the public field of `Labeled`. It does not retrieve `Base.level`, `Base.token`, or `Child.note`.
- `getDeclaredFields()` only retrieves the three fields declared by `Child`: `name`, `active`, `note`. It does not retrieve `Base.name`, `Base.version`, or `Labeled.CATEGORY`.
- `Base.class.getDeclaredFields()` returns the four own fields of `Base` at all access levels; it is unaffected by whether `Child` hides a field name.

Here there is **field hiding**: `Child` also declares `name`, so that field name hides `Base.name` when referenced using normal syntax. In Reflection, each `Field` object remains tied to its **actual declaring class** (via `getDeclaringClass()`). Consequently, a `getFields()` list can contain **multiple `Field`s with the same name** if they belong to different classes.

## 3. Standalone runnable Java 17+ example and exact output

Save the following snippet to the file `FieldInheritanceDemo.java`. The auxiliary classes are top-level types in the same package, allowing the example to illustrate inheritance relationships without depending on fields of an enclosing class.

```java
import java.lang.reflect.Field;
import java.util.Arrays;
import java.util.stream.Collectors;

public class FieldInheritanceDemo {
    private static String names(Field[] fields) {
        return Arrays.stream(fields)
                .map(f -> f.getDeclaringClass().getSimpleName()
                        + "." + f.getName())
                .sorted()
                .collect(Collectors.joining(", "));
    }

    public static void main(String[] args) throws Exception {
        Class<Child> type = Child.class;

        System.out.println("getFields=" + names(type.getFields()));
        System.out.println(
                "getDeclaredFields=" + names(type.getDeclaredFields()));
        System.out.println(
                "baseDeclared=" + names(Base.class.getDeclaredFields()));

        Field selectedName = type.getField("name");
        System.out.println("selectedName.owner="
                + selectedName.getDeclaringClass().getSimpleName());

        Field parentName = Base.class.getDeclaredField("name");
        Child child = new Child();
        System.out.println("parentName.value=" + parentName.get(child));
        System.out.println("childName.value=" + selectedName.get(child));

        long publicNameCount = Arrays.stream(type.getFields())
                .filter(f -> f.getName().equals("name"))
                .count();
        System.out.println("publicNameCount=" + publicNameCount);

        Field category = type.getField("CATEGORY");
        System.out.println("interfaceField.owner="
                + category.getDeclaringClass().getSimpleName());
        System.out.println("interfaceField.value=" + category.get(null));

        try {
            type.getDeclaredField("level");
        } catch (NoSuchFieldException e) {
            System.out.println("childDeclaredLevel=NoSuchFieldException");
        }

        System.out.println("parentProtected.exists="
                + Arrays.stream(type.getFields())
                        .anyMatch(f -> f.getName().equals("level")));
    }
}

interface Labeled {
    String CATEGORY = "tagged";
}

class Base {
    public String name = "base";
    public static int version = 1;
    protected int level = 2;
    private long token = 3;
}

class Child extends Base implements Labeled {
    public String name = "child";
    public boolean active = true;
    private String note = "private";
}
```

Compile/run commands:

```bash
javac FieldInheritanceDemo.java
java FieldInheritanceDemo
```

Output (deliberately sorted the `Field[]` results with `sorted()` so as not to rely on the order returned by Reflection):

```text
getFields=Base.name, Base.version, Child.active, Child.name, Labeled.CATEGORY
getDeclaredFields=Child.active, Child.name, Child.note
baseDeclared=Base.level, Base.name, Base.token, Base.version
selectedName.owner=Child
parentName.value=base
childName.value=child
publicNameCount=2
interfaceField.owner=Labeled
interfaceField.value=tagged
childDeclaredLevel=NoSuchFieldException
parentProtected.exists=false
```

Explanation of easy-to-miss points:

1. `getFields()` includes two `public` fields with the same name `name`: `Base.name` and `Child.name`. Therefore, **you should not build a map keyed only by name** if you need to preserve all fields in the inheritance tree.
2. `getField("name")` returns the `Child.name` field declared `public` by the inspected class itself. In this example, `getDeclaringClass()` is `Child.class`.
3. `Base.name` can still be retrieved separately using `Base.class.getDeclaredField("name")`. When reading it from a `Child` object, the value is `"base"`; `Child`'s field has its own value `"child"`. Field hiding **does not overwrite the same memory slot** via method polymorphism.
4. `Labeled.CATEGORY` is an interface field. In Java, a field declared in an interface is implicitly `public static final`, and `getField("CATEGORY")` can find it from `Child.class`. Since it is `static`, calling `Field.get(null)` reads the field's value.
5. `Base.level` is `protected` and `Base.token` is `private`, so they do not appear in `Child.class.getFields()`; neither belongs to `Child.class.getDeclaredFields()`, because they are declared in `Base`.

## 4. How do getField(name) and getDeclaredField(name) relate?

The two singular APIs have similar scopes:

| API | Condition to find | Not found |
| --- | --- | --- |
| `getField(String name)` | A `public` field with a matching name, searched according to class/superinterface/superclass rules | `NoSuchFieldException` |
| `getDeclaredField(String name)` | A field **directly declared** on the current `Class`, regardless of access modifier | `NoSuchFieldException` |

Example:

```java
Child.class.getField("active");           // Child.active, public
Child.class.getField("version");          // Base.version, public
Child.class.getField("CATEGORY");         // Labeled.CATEGORY, public
Child.class.getDeclaredField("note");     // Child.note, private
Base.class.getDeclaredField("level");     // Base.level, protected
Base.class.getDeclaredField("token");     // Base.token, private

// The two calls below throw NoSuchFieldException:
Child.class.getDeclaredField("version");  // Declared in Base
Child.class.getField("level");            // Not public
```

This is an **illustrative snippet placed in the context of the classes declared above**, not a standalone runnable program; the singular methods may also require handling `NoSuchFieldException`.

### When multiple public fields share the same name

`getField(name)` **does not** return all fields with the same name. The lookup algorithm prioritizes a `public` field declared directly in the class/interface under inspection; if not found, it searches superinterfaces in declaration order and then searches the superclass. The result is **a single `Field`** according to the JDK's algorithm, not a complete list. Therefore:

- Need to look up a public member the way Java defines it → use `getField("name")`.
- Need to see **every** public field in the inheritance tree, including hidden ones → iterate over `getFields()` and inspect `getDeclaringClass()`.
- Need a specific field declared in a superclass → call `SuperClass.class.getDeclaredField("name")` (or traverse the hierarchy), independent of whether a subclass also has a field with the same name.

Do not take the first element from the `getFields()` array and assume it is the subclass's field. **Element order is not guaranteed**; use `getField` with its explicit lookup algorithm or select manually using `getDeclaringClass()`.

## 5. How to collect all declared fields in the superclass chain

There is no single `getDeclaredFields()` call that automatically finds all non-public fields across all parent classes. For cases requiring full state inspection (e.g., serializers or debugging tools), you can traverse `getSuperclass()`:

```java
import java.lang.reflect.Field;
import java.util.ArrayList;
import java.util.List;

public class HierarchyFieldsExample {
    static List<Field> declaredFieldsInClassHierarchy(Class<?> type) {
        List<Field> result = new ArrayList<>();
        for (Class<?> current = type;
             current != null;
             current = current.getSuperclass()) {
            for (Field field : current.getDeclaredFields()) {
                result.add(field);
            }
        }
        return result;
    }
}
```

This is **illustrative helper code**, without a `main` method to run on its own. With `Child.class` in the previous example, the logic above collects fields declared by `Child`, then `Base`, and then `Object`; `Object` has no instance fields declared for the example. This approach preserves duplicate-named fields because each `Field` carries its own declaring class.

**Limitations to remember:**

- `getSuperclass()` only traverses the **superclass chain**, not superinterfaces. If interface fields are also needed, you must traverse `getInterfaces()` and superinterfaces separately while preventing duplicates by identity when walking the interface graph.
- Results may include `static`, `final`, and compiler-generated/synthetic fields. Filter as needed rather than assuming every field is instance state.
- The order of each `getDeclaredFields()` array is not guaranteed. If reproducible output is needed, sort by an explicit key, usually consisting of declaring class and name; when finer distinction is required, add descriptor/type.
- `getDeclaredFields()` only returns metadata. Reading/writing values of non-public fields is still subject to access rules, module restrictions, and `AccessibleObject`.

### Example of filtering instance or synthetic fields

```java
for (Field field : declaredFieldsInClassHierarchy(Child.class)) {
    boolean isInstanceField = !java.lang.reflect.Modifier.isStatic(
            field.getModifiers());
    if (isInstanceField && !field.isSynthetic()) {
        // Process metadata: name, type, declaring class...
    }
}
```

This is an illustrative snippet placed alongside the `declaredFieldsInClassHierarchy` helper, not a standalone runnable program. The filter above does not by itself decide whether a field is suitable for serialization; in practice you must also check `transient`, annotations, visibility, business rules, and access state.

## 6. Interface fields, field hiding, and inherited fields

### Interface fields can appear even when the subclass does not declare them

Every field declared in an interface is `public static final`. If `Child implements Labeled`, `Child.class.getFields()` includes `Labeled.CATEGORY` within the public member scope. However, `Child.class.getDeclaredFields()` **does not** include that field. Only `Labeled.class.getDeclaredFields()` returns this field with `getDeclaringClass() == Labeled.class`.

If multiple interfaces declare fields with the same name, `getField(name)` lookup follows the superinterface order of the API algorithm; do not treat that as a "no-conflict" check across the entire interface tree. When auditing is needed, iterate over `getFields()` along with declaring class.

### Field hiding differs from method overriding

Fields in Java **do not override** via dynamic dispatch like instance methods. If `Base` and `Child` both declare `public String name`, they are **two separate fields**. `Field.get(child)` reads the field that the `Field` object itself represents, even if the actual receiver is an instance of `Child`. Thus, a `Field` pointing to `Base.name` reads the value of `Base.name`.

To distinguish fields with the same name, use `field.getDeclaringClass()`, `field.getType()`, and `field.getModifiers()`. A name alone is not enough to identify a field when hiding occurs.

### "Inherited" and Reflection scope

In the Java Language Specification, whether a field is hidden or how it is inherited is a language-semantics concept. `Class.getFields()` describes the scope of **public fields of the class, superclasses, and superinterfaces** and can even reveal hidden fields. Therefore, do not infer that "only being able to call `obj.name` in a simple way" means "Reflection only finds one Field named `name`".

## 7. Value access and Java module restrictions

Finding a `Field` does not mean you can read or modify its value. For example, `Base.class.getDeclaredField("token")` returns metadata of the `private` field, but `field.get(object)` still checks access permissions and can throw `IllegalAccessException`. When deep reflection is needed, `trySetAccessible()` or `setAccessible(true)` can only enable bypassing access checks if access rules and modules allow it. Unopened packages of a named module can block the operation with `InaccessibleObjectException` or cause `trySetAccessible()` to return `false`.

For `final` fields, do not assume enabling the accessible flag makes them writable or that writing is always safe. Some final fields such as `static final`, record final fields, or hidden class final fields cannot be written via Reflection; modifying other final fields also has limitations regarding consistency and optimizations.

Tools that need to traverse fields should clearly separate two phases: **collecting metadata** with `getFields`/`getDeclaredFields` first, and then **determining actual access permissions** if reading/writing is needed.

## 8. Common mistakes and how to choose the API

| Misconception | Correct understanding |
| --- | --- |
| `getDeclaredFields()` gets all fields including those in superclasses | Only gets fields declared by the class/interface itself |
| `getFields()` gets all fields in the inheritance tree | Only gets `public` fields within class/superclass/superinterface scope |
| `getFields()` does not return hidden fields | Can return multiple `Field`s with the same name but different declaring classes |
| `getFields()[0]` is always a subclass field | Element order is not guaranteed |
| `getField("name")` and `getDeclaredField("name")` are equivalent | One API looks up a public member, the other looks up a direct declaration regardless of visibility |
| Calling `getDeclaredField` on a subclass finds a parent's private field | Must get the parent `Class` or traverse superclasses |
| Having a `Field` means having `get`/`set` permission | Metadata and access permissions are two separate steps |
| Every interface field is copied as a declared field of the implementing class | Interface fields keep the interface as their declaring class |

**Quick selection rule:** if you need the set of **public fields of the class along with inheritance/interfaces**, use `getFields()`; if you need the set of fields **declared directly in a class regardless of access level**, use `getDeclaredFields()`; if you also need `private` or `protected` fields in superclasses, **manually traverse the hierarchy and call `getDeclaredFields()` on each class**. When there are duplicate names, always pair the field with `getDeclaringClass()` to avoid confusion.
