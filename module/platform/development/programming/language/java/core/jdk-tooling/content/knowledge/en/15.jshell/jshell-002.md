# Starting JShell

**JShell** is the REPL (Read-Eval-Print Loop) tool included with the JDK, allowing you to enter and directly execute Java expressions, statements, variable declarations, methods, and classes without creating a project or writing a `main` method first. Introduced in JDK 9, JShell is well suited for learning Java, trying out APIs, testing small code snippets, and rapid prototyping.

Starting JShell is straightforward: open a terminal, run the `jshell` command, and then enter Java snippets at the prompt. JShell compiles and executes a snippet as soon as it receives a complete syntactic unit, then displays the result or an error message.

## 1. Prerequisites Before Starting

JShell is distributed with the JDK, not as a standalone application that needs to be downloaded separately. You need JDK 9 or later installed; for modern projects, use a JDK version supported by your development team, such as JDK 17 or JDK 21.

Verify the Java runtime, compiler, and JShell:

~~~bash
java -version
javac -version
jshell --version
~~~

The `java`, `javac`, and `jshell` commands should point to the same JDK installation to avoid situations where the compiler and the interactive tool use different versions. If multiple JDKs are installed on your machine, check the actual path of each command.

Windows PowerShell:

~~~powershell
Get-Command java
Get-Command javac
Get-Command jshell
~~~

Linux/macOS:

~~~bash
which java
which javac
which jshell
~~~

If the terminal reports that `jshell` is not found:

1. Confirm that JDK 9 or later is installed, not just an older JRE.
2. Check that the `JAVA_HOME` variable points to the JDK root directory.
3. Add the JDK `bin` directory to `PATH`.
4. Open a new terminal and check `jshell --version` again.
5. If multiple JDKs are installed, configure `PATH` for the JDK you want to use and re-check the locations of `java`, `javac`, and `jshell`.

Common path examples:

- Windows: C:\Program Files\Java\jdk-21\bin
- Linux: /usr/lib/jvm/jdk-21/bin
- macOS: /Library/Java/JavaVirtualMachines/jdk-21.jdk/Contents/Home/bin

Actual directory names and installation locations depend on how the JDK was installed. Do not copy these example paths verbatim if they do not exist on your machine.

## 2. Starting an Interactive JShell Session

Open Command Prompt, PowerShell, Terminal, or your corresponding shell, then type:

~~~bash
jshell
~~~

JShell displays a welcome message, the version, and a prompt for entering snippets. The exact welcome text varies by JDK version.

Example session:

~~~text
$ jshell
|  Welcome to JShell -- Version 21
|  For an introduction type: /help intro

jshell>
~~~

The `jshell>` prompt indicates that JShell is waiting for a command or Java snippet. Enter an expression:

~~~java
2 + 3
~~~

JShell evaluates the expression and displays the result. Depending on the feedback mode, it may display:

~~~text
jshell> 2 + 3
$1 ==> 5
~~~

Temporary variable names like `$1` are automatically generated by JShell to store the result of an expression that has not been assigned to a variable. The ID number depends on the snippets entered in the session; do not rely on a fixed ID number in documentation or scripts.

To print a message:

~~~java
System.out.println("Hello, JShell!");
~~~

Output printed by the program:

~~~text
Hello, JShell!
~~~

There is no need to declare a class or a `main` method for simple tests like this.

## 3. Entering Your First Snippets

JShell accepts many kinds of Java language snippets:

- Expressions, such as `10 * 5`.
- Statements, such as `System.out.println("Hello")`.
- Variable declarations, such as `int count = 3`.
- Method declarations.
- Class, interface, enum, or record declarations.
- `import` statements.

Example of a short session:

~~~text
jshell> int quantity = 4
quantity ==> 4

jshell> int price = 25000
price ==> 25000

jshell> int total = quantity * price
total ==> 100000

jshell> System.out.println("Total = " + total)
Total = 100000
~~~

Once declared, variables persist in the session state. You can reuse them in subsequent snippets:

~~~java
total + 5000
~~~

The result is `105000`. JShell retains state across inputs until the session is reset or exited.

### Semicolons

For a complete snippet, JShell can automatically insert a semicolon if you omit it. However, it is good practice to write semicolons according to Java conventions so the code is easy to move into a `.java` file and to avoid confusion when entering multiple statements.

Example:

~~~java
int a = 10;
int b = 20;
System.out.println(a + b);
~~~

A snippet containing multiple statements can be entered across multiple lines; JShell continues waiting until the syntax is complete.

## 4. Declaring Methods and Classes Directly in a Session

You do not need to create a separate file to test a method. Example:

~~~java
int square(int value) {
    return value * value;
}
~~~

After JShell confirms the method has been created, call it:

~~~java
square(6)
~~~

Result:

~~~text
$2 ==> 36
~~~

The result ID may vary by session. The method can be called from subsequent snippets without recompiling an entire project.

You can declare a class:

~~~java
class Product {
    String name;
    int price;

    Product(String name, int price) {
        this.name = name;
        this.price = price;
    }

    int priceWithTax(int tax) {
        return price + tax;
    }
}
~~~

Create an object and call a method:

~~~java
Product item = new Product("Notebook", 30000);
item.priceWithTax(3000)
~~~

The result of the last expression is `33000`. JShell is useful for quickly testing class structure, constructors, and methods before putting code into a project.

## 5. Multiline Input and Completing Snippets

When you enter an incomplete declaration, JShell switches to a continuation prompt, typically displayed as `...>`.

Example:

~~~text
jshell> int add(int a, int b) {
   ...>     return a + b;
   ...> }
|  created method add(int,int)

jshell> add(7, 8)
$1 ==> 15
~~~

The continuation prompt indicates that JShell is waiting for the rest of the snippet, such as a closing brace or the next statement. Once the syntax is complete, JShell processes the entire declaration.

If there is a mistake, JShell displays diagnostics from the compiler. Read the location and error message, fix the snippet, and re-enter it. For an already declared method or class, you can re-enter its definition to replace the active version.

## 6. Distinguishing Java Snippets and JShell Commands

In JShell, there are two types of input:

| Type | How to Identify | Example | Purpose |
|---|---|---|---|
| Java snippet | Standard Java syntax | int x = 10; | Compile and execute code |
| JShell command | Starts with `/` | /help | Control the session and manage snippets |

Some useful commands right when starting out:

| Command | Purpose |
|---|---|
| /help | List commands and help topics |
| /help intro | Introduction to using JShell |
| /list | List active snippets |
| /vars | View declared variables |
| /methods | View declared methods |
| /types | View declared classes/interfaces/enums |
| /imports | View current imports |
| /history | View input history in the session |
| /reset | Clear snippet state and restart the environment |
| /exit | Exit JShell |

Example:

~~~text
jshell> /help intro
~~~

To see the imports loaded automatically at startup:

~~~text
jshell> /list -start
~~~

JShell has a default startup script containing commonly used imports such as `java.util` and `java.io`. The `java.lang` package is automatically imported by Java, so it does not need to be declared again.

The leading `/` on a command lets JShell distinguish control commands from Java source. When you want to write an expression or statement, enter standard Java syntax.

## 7. Adjusting the Feedback Level at Startup

Feedback determines how much information JShell displays after you enter a snippet. You can select it directly from the command line using `--feedback`:

~~~bash
jshell --feedback verbose
~~~

Main modes:

| Mode | Behavior |
|---|---|
| verbose | Displays detailed information about the snippet and the action taken |
| normal | Moderate level of information; this is the default |
| concise | Minimal feedback |
| silent | Suppresses normal feedback; error diagnostics are still displayed |

Shorthand flags are also available:

~~~bash
jshell -v
jshell -q
jshell -s
~~~

Corresponding to:

- `-v` selects `verbose`.
- `-q` selects `concise`.
- `-s` selects `silent`.

You can change the mode after entering a session:

~~~text
jshell> /set feedback verbose
~~~

When learning or debugging, `verbose` is helpful because it shows how snippets are created, modified, or evaluated. When running scripts or wanting cleaner output, `concise` or `silent` may be more suitable.

## 8. Starting JShell with a Classpath

If you need to use classes located in a compiled directory or an external JAR, specify the classpath at startup.

Example:

~~~bash
jshell --class-path lib/example.jar
~~~

The `--class-path` option specifies the directories and archives searched for loading class files. It overrides the `CLASSPATH` environment variable. If `CLASSPATH` is not set and this option is not passed, the current directory is searched.

If there are multiple dependencies:

Linux/macOS:

~~~bash
jshell --class-path "lib/a.jar:lib/b.jar:build/classes"
~~~

Windows:

~~~powershell
jshell --class-path "lib\a.jar;lib\b.jar;build\classes"
~~~

The separator is a colon on Linux/macOS and a semicolon on Windows. Enclose the entire classpath in quotes so the shell does not interpret special characters.

If a class is not found, check:

1. Does the JAR contain the exact class and package path?
2. Does the classpath point to the right JAR or the package root directory?
3. Does the class name in the `import` have the correct package?
4. Are transitive dependencies provided?
5. Is the JAR compatible with the running Java version?

## 9. Starting with a Module Path

If you need to use named modules, specify the module path:

~~~bash
jshell --module-path mods
~~~

You can request additional modules to be resolved:

~~~bash
jshell --module-path mods --add-modules com.acme.library
~~~

The module path is used to locate application modules. It differs from the classpath: the classpath typically holds classes/JARs belonging to the unnamed module, whereas the module path holds named modules or automatic modules.

If JShell cannot find a module, check:

- The module name in `module-info.java`.
- Whether the module has been compiled and is in the right directory.
- Whether the `mods` path contains the required module directory or modular JAR.
- Whether module dependencies are resolved.
- Whether the required package is exported by the module.

You can use the `/env` command to view or change environment settings during a session. When you change the classpath or module path via `/env`, JShell restarts the execution state and reloads startup scripts.

## 10. Starting with a Startup Script

JShell has a default startup script named `DEFAULT`, containing commonly used imports. You can replace the startup script using the `--startup` option:

~~~bash
jshell --startup my-startup.jsh
~~~

Predefined startup scripts:

| Script | Contents |
|---|---|
| DEFAULT | Commonly used imports; used by default |
| JAVASE | Imports Java SE packages; may increase startup time |
| PRINTING | Defines `print`, `println`, and `printf` methods for direct calling |
| TOOLING | Defines helper methods to invoke certain JDK tools such as `javac`, `jar`, and `javap` |

You can load multiple startup scripts by repeating `--startup`:

~~~bash
jshell --startup DEFAULT --startup PRINTING
~~~

Scripts are executed in the order declared. If you use `--no-startup`, JShell does not run the default startup script; do not combine `--no-startup` with `--startup`.

### Creating a Custom Startup Script

Create the file `my-startup.jsh`:

~~~java
import java.time.LocalDate;
import java.util.List;

String greeting(String name) {
    return "Xin chào, " + name + "!";
}
~~~

Start JShell:

~~~bash
jshell --startup my-startup.jsh
~~~

Once in the session, you can call the `greeting` method immediately:

~~~java
greeting("Java")
~~~

Result:

~~~text
$1 ==> "Xin chào, Java!"
~~~

Startup scripts are loaded when JShell starts and when the session is reset/reloaded according to the tool's rules. If you modify the file contents after configuring it with `/set start`, JShell stores the script contents as of the time it was configured; you must re-run the configuration command to update the contents used.

You can save the current startup setting with:

~~~text
jshell> /set start -retain
~~~

This preserves the startup configuration for your future JShell sessions.

## 11. Running a Script Immediately at Startup

In addition to startup scripts, JShell lets you pass script files at the end of the command line:

~~~bash
jshell first-session.jsh
~~~

A script is a sequence of Java snippets and JShell commands. Each snippet or command is written on one or multiple lines depending on its syntax.

Example `first-session.jsh` file:

~~~java
String greeting = "Xin chào JShell!";
System.out.println(greeting);

int total = 10 + 20;
System.out.println("Total = " + total);
~~~

Run with `silent` feedback for clean program output:

~~~bash
jshell --feedback silent first-session.jsh
~~~

Stdout from the `print` statements:

~~~text
Xin chào JShell!
Total = 30
~~~

Files passed at the end of the command line are executed when the tool starts. You can pass multiple script files; they are processed in order. To load a script after already entering a session, use:

~~~text
jshell> /open first-session.jsh
~~~

Comparison:

- `--startup` specifies environment initialization scripts that are reloaded when the session resets/reloads.
- Script files passed at the end of the command line execute snippets/commands when the tool starts.
- `/open` loads a file into the currently running session.

## 12. Other Useful Startup Options

| Option | Purpose |
|---|---|
| --version | Print version and exit |
| --show-version | Print version and continue into JShell |
| --help | Display option help |
| --help-extra | Display non-standard options, subject to change |
| --enable-preview | Allow snippets to use preview features of the matching JDK release |
| -C flag | Pass an option to the Java compiler inside JShell |
| -R flag | Pass an option to the runtime when executing snippets |
| --class-path | Set the classpath |
| --module-path | Set the module path |
| --startup | Specify a startup script |
| --no-startup | Do not run a startup script |

Example enabling preview features on the matching JDK release:

~~~bash
jshell --enable-preview
~~~

Only use this when the running JDK supports the preview feature you want to test. Preview features are tied to their corresponding release; do not assume preview code will run on every Java version.

Passing a compiler option:

~~~bash
jshell -C-Xlint
~~~

Passing a system property to the snippet execution runtime:

~~~bash
jshell -R-Dapp.mode=dev
~~~

In JShell, try reading the property:

~~~java
System.getProperty("app.mode")
~~~

The result is the string `dev`. `-C` affects the compiler inside JShell; `-R` affects the runtime executing snippets. `-J` passes a flag to the tool's own runtime and does not replace `-R` for the default execution engine.

## 13. Exiting and Restarting a Session

To end a session, enter:

~~~text
jshell> /exit
|  Goodbye
~~~

You can press `Ctrl+D` in terminals that support sending end-of-file to terminate input. The most common and explicit method remains `/exit`.

The reset/reload commands differ in how they handle state:

| Command | Behavior |
|---|---|
| /reset | Discards all current snippets, restarts state, and runs startup scripts; does not replay history |
| /reload | Restarts state, runs startup scripts, and then replays valid history |
| /env | Views or changes the environment; when changes are made, the session is restarted and valid history is replayed |
| /exit | Exits the tool |

If you want to keep your snippets for later use, save them before exiting:

~~~text
jshell> /save session.jsh
~~~

To save the full history, including commands:

~~~text
jshell> /save -history session-history.txt
~~~

Saved files can be reloaded by passing them at startup or using `/open`. Review file contents before sharing, as history may contain data entered during the session.

## 14. Troubleshooting JShell Startup

| Symptom | Possible Cause | Resolution |
|---|---|---|
| `jshell` is not recognized | JDK not installed, JDK too old, or `PATH` missing `bin` directory | Check JDK 9+, `JAVA_HOME`, and `PATH` |
| `java` runs but `jshell` does not | `PATH` points to a JRE or another JDK without JShell | Check `Get-Command`/`which` and use the right JDK `bin` |
| JShell opens with an unexpected version | Multiple JDKs installed and `PATH` prioritizes another version | Check `jshell` location and reorder `PATH` |
| Importing a class fails | Missing classpath or wrong package | Use `--class-path` and verify JAR contents |
| Module not found | Wrong module path or incorrect module name | Use `--module-path`, check module descriptor |
| Script does not run | Wrong path or file is not a valid JShell script | Check working directory, file path, and contents |
| Startup script does not take effect immediately | Script settings apply on the next startup/reset | Use `--startup` when opening a new session or `/reset` after configuring |
| No feedback shown after snippet | Using `concise`/`silent` mode | Check `--feedback` or `/set feedback` |
| Multiline snippet has not executed | Syntax is still incomplete | Continue entering the rest; check braces and semicolons |
| Code using preview features errors out | Preview not enabled or wrong JDK release | Start with `--enable-preview` on the appropriate JDK |

When encountering an error, read the full message before changing settings. Snippet syntax errors are distinct from class/module-not-found errors and from tool startup failures.

## 15. Workflow for Starting an Effective Session

1. Open a terminal in your working directory.
2. Run `java -version` and `jshell --version` to verify the JDK.
3. Run `jshell` to open the REPL.
4. Enter `/help intro` to read the introductory guide.
5. Try a simple expression such as `2 + 3`.
6. Declare a variable or method to confirm session state is preserved.
7. Use `/vars`, `/methods`, `/types`, and `/list` to inspect snippets.
8. If external libraries are needed, start with `--class-path` or `--module-path`.
9. If you have reusable declarations, create a startup script or load a file with `/open`.
10. Save snippets you want to keep with `/save` and exit with `/exit`.

For a quick test, starting JShell with defaults is enough. For tests requiring dependencies or multiple reusable declarations, configure the classpath/module path and startup script upfront so snippets run in the same environment.

## 16. Key Takeaways

- JShell is Java's REPL, distributed with the JDK since JDK 9.
- Run the `jshell` command in a terminal to open an interactive session.
- JShell accepts expressions, statements, variables, methods, classes, and imports as snippets.
- Snippets are evaluated once complete; the `...>` prompt indicates JShell is waiting for the rest.
- JShell commands start with `/`, such as `/help`, `/list`, `/vars`, and `/exit`.
- The default startup script is `DEFAULT`; you can use `--startup`, `--no-startup`, or built-in scripts like `PRINTING`.
- Files passed at the end of the command line or the `/open` command load snippets from a file.
- `--class-path` and `--module-path` allow JShell to access dependencies.
- `--feedback` controls the amount of output displayed; the default is `normal`.
- `/save` saves snippets for reuse; `/exit` ends the session.
