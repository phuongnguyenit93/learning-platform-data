# Declaring Methods in JShell

**JShell** is an interactive environment (REPL) included with the JDK that allows you to enter and execute Java expressions, statements, variable declarations, classes, and methods directly within a session. When declaring a method in JShell, you can define a named operation, pass parameters, return a result, and invoke it repeatedly without needing to create a complete application class.

Methods are entered at the top level of JShell and stored as snippets in the current session state. Once declared successfully, a method can be called from expressions, statements, or other methods within the same session.

## 1. Starting JShell

JShell is available starting from JDK 9 and later. Open Terminal or PowerShell and check:

```sh
jshell --version
```

Start JShell:

```sh
jshell
```

When entering an interactive session, JShell displays the prompt:

```text
jshell>
```

Enter a Java expression to try it out quickly:

```java
jshell> 2 + 3
$1 ==> 5
```

Temporary variable names like `$1` are automatically generated by JShell for expression results; the sequence number changes according to the session history. When you declare a method, JShell stores that declaration so it can be called again at subsequent prompts.

Exit the session:

```text
jshell> /exit
```

## 2. Method Declaration Syntax

General syntax of a Java method:

```java
[modifiers] returnType methodName(parameterList) {
    // method body
}
```

Components:

- **Modifiers:** optional modifier keywords if needed, such as `public`, `private`, `static`.
- **Return type:** the data type returned by the method, such as `int`, `String`, `boolean`, or `void` if no value is returned.
- **Method name:** the name of the method following Java identifier rules.
- **Parameter list:** the list of parameters, each with a type and a name.
- **Method body:** the statements executed when the method is called.

In JShell, enter the method declaration directly at the prompt without placing it inside a user-defined class.

Example:

```java
jshell> int add(int a, int b) {
   ...>     return a + b;
   ...> }
```

The `...>` prompt indicates that JShell is waiting for the rest of a multi-line declaration. When the closing brace is entered and the declaration is complete, JShell compiles the snippet. If there are no errors, the method is ready to use.

Calling the method:

```java
jshell> add(4, 6)
$1 ==> 10
```

The `add` method takes two `int` parameters, adds them together, and returns an `int` result.

## 3. Declaring Methods That Return a Value

If a method needs to produce a result for the caller to use, declare an appropriate return type and use `return`.

Example of a method that computes the square of a number:

```java
jshell> int square(int number) {
   ...>     return number * number;
   ...> }
```

Calling the method:

```java
jshell> square(7)
$1 ==> 49
```

You can use the result directly in another expression:

```java
jshell> square(3) + square(4)
$2 ==> 25
```

For a method with a non-`void` return type, every normal execution path must return a value compatible with the declared type.

Example of a method that checks whether a number is even:

```java
jshell> boolean isEven(int number) {
   ...>     return number % 2 == 0;
   ...> }
```

```java
jshell> isEven(12)
$3 ==> true

jshell> isEven(9)
$4 ==> false
```

You cannot arbitrarily change the return type when calling a method. The returned value must match the type specified by the method declaration.

## 4. Declaring `void` Methods

Use `void` when a method performs an action without returning a value.

Example:

```java
jshell> void greet(String name) {
   ...>     System.out.println("Xin chao, " + name + "!");
   ...> }
```

Calling the method:

```java
jshell> greet("Lan")
Xin chao, Lan!
```

The `greet` method takes a `String` parameter, prints a greeting, and finishes. Because the return type is `void`, no `return` statement with a value is required. You can use `return;` to exit a `void` method early when needed.

Input validation example:

```java
jshell> void printName(String name) {
   ...>     if (name == null || name.isBlank()) {
   ...>         System.out.println("Ten khong hop le");
   ...>         return;
   ...>     }
   ...>     System.out.println("Ten: " + name);
   ...> }
```

```java
jshell> printName("An")
Ten: An

jshell> printName(" ")
Ten khong hop le
```

Distinguish between value-returning methods and `void` methods by their intended purpose:

| Method type | Declaration | Result |
|---|---|---|
| Returns data | `int calculate(...)` | Caller receives a value for further processing |
| Performs an action | `void print(...)` | Performs a side effect, returns no value |

## 5. Parameters and Arguments

A **parameter** is a variable declared in the method's parameter list. An **argument** is the actual value passed in when calling the method.

Example:

```java
jshell> double calculateTotal(double price, int quantity) {
   ...>     return price * quantity;
   ...> }
```

When calling:

```java
jshell> calculateTotal(19.5, 3)
$1 ==> 58.5
```

In the declaration, `price` and `quantity` are parameters. In the call, `19.5` and `3` are arguments.

Java checks the number and types of arguments:

- The number of arguments must match the parameter list.
- Argument types must be compatible with parameter types according to Java's conversion rules.
- The order of arguments must match the order of parameters.
- Parameters are scoped only within that method.

Example of a method with two parameters:

```java
jshell> int subtract(int first, int second) {
   ...>     return first - second;
   ...> }
```

```java
jshell> subtract(10, 4)
$2 ==> 6
```

Calling `subtract(10)` causes an error because an argument is missing; calling `subtract(10, 4, 2)` is also invalid because too many arguments are passed.

Java passes arguments by value (pass-by-value). For reference types, the value copied is the reference value; the method can modify the state of the referenced object, but reassigning the parameter variable does not make the caller's variable point to a different object.

## 6. Declaring Multi-Line and Multi-Statement Methods

A method can contain multiple statements, local variables, conditionals, and loops. Use curly braces to enclose the entire method body.

Example of summing numbers from 1 to `n`:

```java
jshell> int sumTo(int n) {
   ...>     if (n < 0) {
   ...>         throw new IllegalArgumentException("n must be non-negative");
   ...>     }
   ...>     int sum = 0;
   ...>     for (int i = 1; i <= n; i++) {
   ...>         sum += i;
   ...>     }
   ...>     return sum;
   ...> }
```

Calling the method:

```java
jshell> sumTo(5)
$1 ==> 15

jshell> sumTo(0)
$2 ==> 0
```

The method uses local variables `sum` and `i`. These variables exist only within the execution scope of the method and cannot be accessed directly after the method finishes.

When entering multiple lines, ensure every opening brace has a matching closing brace. If JShell keeps displaying `...>`, the snippet may be incomplete or missing a closing delimiter.

## 7. Methods Calling Other Methods

Methods declared in JShell can be called from other methods. This is a way to break a large task into smaller, clearly named steps.

Example:

```java
jshell> int square(int n) {
   ...>     return n * n;
   ...> }
```

Declare a method that computes the sum of squares:

```java
jshell> int sumOfSquares(int a, int b) {
   ...>     return square(a) + square(b);
   ...> }
```

Call:

```java
jshell> sumOfSquares(3, 4)
$1 ==> 25
```

The `sumOfSquares` method reuses `square`, avoiding repeated multiplication expressions and making the purpose of each step clearer.

If the called method does not exist yet or does not have a matching signature, JShell reports a compilation error. Declare dependencies first, or check the name and parameter types of the called method.

## 8. Overloading: Multiple Methods with the Same Name

Java allows declaring multiple methods with the same name as long as their parameter lists differ. This mechanism is called **method overloading**.

Example:

```java
jshell> String describe(int value) {
   ...>     return "So nguyen: " + value;
   ...> }
```

```java
jshell> String describe(String value) {
   ...>     return "Van ban: " + value;
   ...> }
```

Calling by argument type:

```java
jshell> describe(42)
$1 ==> "So nguyen: 42"

jshell> describe("Java")
$2 ==> "Van ban: Java"
```

The compiler selects the appropriate overload based on the method name, the number and types of arguments, and Java's overload resolution rules.

**Changing only the return type does not create an overload.** Two methods with the same name and parameter type list but different return types are conflicting declarations.

Valid example:

```java
int convert(int value) { return value; }
String convert(String value) { return value; }
```

Invalid example if both are declared:

```java
int calculate(int value) { return value; }
double calculate(int value) { return value; }
```

The two methods above have the same name and the same parameter types; a difference in return type is not enough to distinguish their signatures.

When there are multiple overloads, choose clear parameter types. A call such as `process(null)` can be ambiguous if multiple overloads accept reference types without a clear specificity relationship.

## 9. Varargs and Array Parameters

A method can accept a variable number of arguments using varargs syntax `...`. The varargs parameter must be the last parameter in the parameter list.

Example:

```java
jshell> int sum(int... values) {
   ...>     int result = 0;
   ...>     for (int value : values) {
   ...>         result += value;
   ...>     }
   ...>     return result;
   ...> }
```

Calling with multiple arguments:

```java
jshell> sum(1, 2, 3, 4)
$1 ==> 10
```

You can also pass an `int[]` array directly:

```java
jshell> sum(new int[] { 5, 6 })
$2 ==> 11
```

Inside the method, the varargs parameter is handled as an array. Varargs is convenient for APIs with a variable number of arguments, but should not be overused when the input is actually a collection or an existing array.

## 10. Generic Methods

A method can declare type parameters to work with multiple data types while preserving compile-time type checking.

Example:

```java
jshell> <T> T identity(T value) {
   ...>     return value;
   ...> }
```

Calling with different types:

```java
jshell> identity("Java")
$1 ==> "Java"

jshell> identity(100)
$2 ==> 100
```

`T` is a type parameter declared before the return type. The compiler infers the type from the argument when the method is called. Generic methods are useful when an algorithm does not depend on a specific type, yet you still want to preserve the type relationship between input and output.

Example using a type bound:

```java
jshell> <T extends Number> double toDouble(T value) {
   ...>     return value.doubleValue();
   ...> }
```

This method only accepts `Number` or its subtypes. Passing an object outside that bound will fail to compile.

## 11. Recursion in Methods

A method can call itself. This is **recursion**. Every recursive method needs a base case to prevent infinite calls.

Example of computing factorial:

```java
jshell> long factorial(int n) {
   ...>     if (n < 0) {
   ...>         throw new IllegalArgumentException("n must be non-negative");
   ...>     }
   ...>     if (n <= 1) {
   ...>         return 1L;
   ...>     }
   ...>     return n * factorial(n - 1);
   ...> }
```

Call:

```java
jshell> factorial(5)
$1 ==> 120
```

The condition `n <= 1` is the base case. For `n > 1`, the method decrements the argument until it reaches the base case.

Recursion can make code easier to understand for certain problems, but each call creates a frame on the call stack. Overly large inputs can cause a `StackOverflowError`; with loops, some algorithms can use less memory.

## 12. Scope, State, and Method Lifecycle in JShell

A method declaration is a snippet stored in the JShell session state. The method can be called again after the prompt returns to `jshell>`.

Example:

```java
jshell> int triple(int value) {
   ...>     return value * 3;
   ...> }

jshell> triple(8)
$1 ==> 24
```

The method remains usable within the same session until the snippet is dropped or the JShell state is reset. When you exit and start a new session, previous declarations are not automatically preserved unless you save and reload them.

Useful commands:

| JShell Command | Purpose |
|---|---|
| `/methods` | List methods currently available in the session |
| `/list` | List entered snippets |
| `/list -all` | View both inactive and current snippets |
| `/vars` | List declared variables |
| `/types` | List declared types |
| `/drop <id>` | Drop a snippet by ID |
| `/reset` | Reset the JShell session state |
| `/help` | View command help |
| `/exit` | Exit JShell |

Example of inspecting methods:

```text
jshell> /methods
```

JShell displays the active method declarations along with their signatures. Use `/list` to view snippet contents and their corresponding IDs.

If you want to remove a method, find its snippet ID with `/list`, then run:

```text
jshell> /drop <id>
```

Replace `<id>` with the actual ID shown in the session. If other methods depend on the dropped snippet, those related snippets may become invalid; check JShell's messages and redeclare any required dependencies.

`/reset` clears the session state, including declared methods, variables, classes, and imports. Use it only when you truly want to start over.

## 13. Updating a Declared Method

During experimentation, you can redeclare a method with the same name and parameter type list to change its body.

Initial declaration example:

```java
jshell> int applyDiscount(int price) {
   ...>     return price - 10;
   ...> }
```

```java
jshell> applyDiscount(100)
$1 ==> 90
```

Redeclare with the same signature and a new rule:

```java
jshell> int applyDiscount(int price) {
   ...>     return price - 20;
   ...> }
```

Call again:

```java
jshell> applyDiscount(100)
$2 ==> 80
```

JShell supports replacing method declarations during an interactive session. Use `/methods` to view active methods and `/list` to track snippet history. When a method has multiple overloads, pay attention to which exact parameter list is being updated.

## 14. Common Errors When Declaring Methods

| Symptom | Cause | How to Fix |
|---|---|---|
| `';' expected` or syntax error | Missing semicolon in method body, missing brace/parenthesis, or invalid syntax | Check each statement and matching braces/parentheses |
| JShell keeps showing `...>` | Incomplete multi-line declaration, usually a missing `}` | Complete the method body and close all braces |
| `missing return statement` | Method has a return type, but a branch can finish without returning a value | Add `return` for every normal execution path |
| `incompatible types` | Returned value is incompatible with the declared return type | Change the return type or convert the data properly |
| `cannot find symbol` | Calling an undeclared method, misspelled name, or wrong signature | Check the name, parameters, and declare dependencies first |
| `method ... cannot be applied to given types` | Wrong number or types of arguments | Pass the correct number and types of arguments |
| `reference to ... is ambiguous` | Multiple overloads match the call equally | Clarify argument types or redesign the overloads |
| `method is already defined` or conflicting declaration | Two declarations have the same signature and cannot be distinguished in the current state | Check `/methods`, `/list`, and update the right snippet |
| `non-static ... cannot be referenced from a static context` | Method context requires a static member, but an instance member is referenced | Review modifiers and how state/objects are organized |
| `StackOverflowError` | Recursion lacks a base case or recursion depth is too large | Fix the base case or switch to a loop |

When an error occurs, read the message directly at the prompt. JShell compiles the method declaration before activating the snippet; compilation errors must be fixed in the declaration and re-entered. Do not continue calling a method that has not been declared successfully.

## 15. Integrated Practice

In a new JShell session, enter the following methods in order.

Method to calculate the price after discount:

```java
double finalPrice(double price, double discountRate) {
    if (price < 0 || discountRate < 0 || discountRate > 1) {
        throw new IllegalArgumentException("Invalid price or discount");
    }
    return price * (1 - discountRate);
}
```

Method to format the result:

```java
String formatPrice(double price) {
    return String.format("%.2f", price);
}
```

Method combining the two steps:

```java
String checkout(double price, double discountRate) {
    double result = finalPrice(price, discountRate);
    return "Total: " + formatPrice(result);
}
```

Call the method:

```java
checkout(200.0, 0.10)
```

Result:

```text
$1 ==> "Total: 180.00"
```

The methods are declared separately but can call each other. `checkout` coordinates the workflow, `finalPrice` performs the calculation, and `formatPrice` handles formatting. This separation gives each method a specific responsibility, making it easier to test and modify.

You can try additional cases:

- `checkout(0.0, 0.0)` to test boundary values.
- `checkout(200.0, 1.0)` to test a 100% discount.
- `checkout(-1.0, 0.1)` to test exception handling.
- `checkout(200.0, 1.5)` to test an invalid discount rate.

For the last two cases, the method throws an `IllegalArgumentException`; JShell displays a stack trace instead of a normal return value.

## 16. Saving and Reusing Declarations

A JShell session is a temporary interactive environment by default. To keep snippets and reload them in a later session, you can use commands to save and open files:

```text
jshell> /save methods.jsh
```

In a new session:

```text
jshell> /open methods.jsh
```

The saved file may contain snippets other than methods, depending on the session state and save options. Review the file contents before sharing or reusing it in another environment.

If you need to use external libraries when starting JShell, you can pass the classpath:

```sh
jshell --class-path "lib/*"
```

Then declare imports and methods that use types from those libraries. The dependencies must exist at the specified location and be compatible with the JDK running JShell.

## 17. Principles for Writing Clear Methods

- Name methods with verbs or verb phrases that express the action, such as `calculateTotal`, `findUser`, `printReport`.
- Each method should have one primary responsibility.
- Choose a return type that accurately reflects the result; use `void` when only performing an action.
- Give parameters meaningful names and use appropriate data types.
- Validate inputs where necessary, especially for `null` values, negative numbers, and domain bounds.
- Avoid overly long methods or too many nested branches.
- Use overloading when operations share the same meaning but accept different input types.
- Avoid ambiguous overloading, especially with reference types and `null` values.
- For recursion, always define a base case and a reasonable depth limit.
- Use JShell to quickly test behavior, then move stable methods into structured classes and projects when developing real applications.
