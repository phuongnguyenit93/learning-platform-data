# Main class output trong jps

**`jps`** là công cụ dòng lệnh của JDK dùng để liệt kê các JVM HotSpot đang chạy mà tài khoản hiện tại có quyền quan sát. Mỗi dòng thường bắt đầu bằng một **local JVM identifier (lvmid)**, tiếp theo là tên main class hoặc tên tệp JAR đã khởi chạy ứng dụng.

Phần tên lớp trong output giúp nhận diện nhanh ứng dụng Java nào đang chạy. Khi cần biết chính xác package/class, tham số truyền vào `main()` hoặc tùy chọn JVM, có thể kết hợp các tùy chọn `-l`, `-m` và `-v`.

## 1. Main class trong output jps là gì?

Khi chạy ứng dụng bằng lệnh:

```bash
java com.example.app.Main
```

Java launcher nạp lớp `com.example.app.Main` và gọi phương thức entry point của ứng dụng. Lớp này được gọi là **main class**.

Khi chạy:

```bash
jps
```

Output thường có dạng:

```text
18420 Main
29116 Main
32780 Jps
```

Mỗi dòng gồm:

- **LVMID:** định danh JVM cục bộ, thường trùng với process ID của hệ điều hành.
- **Main class hoặc JAR:** tên ngắn của lớp main hoặc tên tệp JAR dùng để khởi chạy ứng dụng.

Trong ví dụ, `Main` là tên ngắn của main class; thông tin package đã được lược bỏ. `Jps` là chính tiến trình công cụ `jps` đang chạy để liệt kê JVM.

LVMID thường là PID của process, nhưng tài liệu JDK không bảo đảm hai giá trị luôn giống nhau trong mọi môi trường. Hãy dùng giá trị mà công cụ trả về khi gọi các công cụ JVM khác và kiểm tra lại process nếu môi trường có launcher đặc biệt.

## 2. Phân biệt main class, main method và JAR

Ba khái niệm này liên quan nhưng không giống nhau:

| Khái niệm | Ý nghĩa | Ví dụ |
| --- | --- | --- |
| Main class | Lớp được launcher chọn làm điểm bắt đầu ứng dụng | `com.example.app.Main` |
| Main method | Phương thức entry point trong lớp | `public static void main(String[] args)` |
| Executable JAR | Archive được khởi chạy bằng `java -jar`; manifest xác định lớp main | `app.jar` |

Nếu khởi chạy theo tên lớp:

```bash
java -cp app.jar com.example.app.Main
```

JPS thường hiển thị tên main class.

Nếu khởi chạy bằng executable JAR:

```bash
java -jar app.jar
```

JPS có thể hiển thị tên hoặc đường dẫn JAR thay vì tên lớp được khai báo trong manifest. Để xem main class của JAR, kiểm tra thuộc tính `Main-Class` trong `META-INF/MANIFEST.MF`.

Nếu khởi chạy ứng dụng modular:

```bash
java -m com.example.app/com.example.app.Main
```

Output dạng đầy đủ có thể thể hiện module và class, ví dụ:

```text
com.example.app/com.example.app.Main
```

JPS hiển thị launch target mà công cụ có thể nhận diện; nó không in nội dung mã nguồn hoặc stack trace của main method.

## 3. Cấu trúc một dòng jps

Dạng output tổng quát được tài liệu JDK mô tả:

```text
lvmid [ [classname | JARfilename | "Unknown"] [arg*] [jvmarg*] ]
```

Trong đó:

- `lvmid`: local JVM identifier.
- `classname`: tên main class nếu launcher cung cấp được thông tin.
- `JARfilename`: tên hoặc đường dẫn JAR được khởi chạy.
- `Unknown`: giá trị có thể xuất hiện khi JPS không xác định được class/JAR.
- `arg*`: các đối số truyền vào main method, nếu yêu cầu hiển thị.
- `jvmarg*`: các đối số truyền cho JVM, nếu yêu cầu hiển thị.

Ví dụ:

```text
18420 com.example.app.Main --profile=prod -Xms256m -Xmx2g
```

Có thể đọc theo thứ tự:

1. `18420`: định danh JVM.
2. `com.example.app.Main`: main class.
3. `--profile=prod`: đối số ứng dụng truyền vào `main(String[] args)`.
4. `-Xms256m -Xmx2g`: đối số khởi động JVM.

Đây là ví dụ minh họa cách kết hợp các trường; để hiển thị đủ thông tin, dùng các tùy chọn tương ứng.

## 4. Hiển thị tên lớp đầy đủ bằng jps -l

Không có tùy chọn, `jps` thường chỉ hiển thị tên lớp dạng ngắn, bỏ package. Nếu nhiều ứng dụng cùng có tên lớp `Main`, kết quả có thể khó phân biệt.

Dùng `-l` để hiển thị tên package đầy đủ của main class hoặc đường dẫn đầy đủ của JAR:

```bash
jps -l
```

Output minh họa:

```text
18420 com.example.billing.Main
29116 com.example.inventory.Main
32780 jdk.jcmd/sun.tools.jps.Jps
```

Hai ứng dụng đều có class tên `Main`, nhưng package giúp nhận diện chính xác hơn.

Với ứng dụng chạy bằng module, output có thể có dạng `module/class`. Ví dụ JVM công cụ trong JDK có thể hiển thị:

```text
jdk.jshell/jdk.internal.jshell.tool.JShellToolProvider
```

Với ứng dụng khởi chạy bằng JAR, `-l` hiển thị đường dẫn đầy đủ đến JAR theo khả năng nhận diện của launcher.

## 5. Hiển thị tham số của main method bằng jps -m

Tùy chọn `-m` hiển thị các đối số truyền cho main method.

Ví dụ chạy:

```bash
java -cp app.jar com.example.app.Main --profile=staging --port=8080
```

Sau đó:

```bash
jps -m
```

Output minh họa:

```text
18420 Main --profile=staging --port=8080
```

Các chuỗi sau tên class là đối số ứng dụng, tương ứng với mảng `args` trong:

```java
public static void main(String[] args) {
    // args[0] = "--profile=staging"
    // args[1] = "--port=8080"
}
```

Nếu JVM được nhúng (embedded JVM) hoặc khởi chạy qua custom launcher, thông tin đối số main method có thể không có; tài liệu JDK cho biết output có thể là `null` hoặc `Unknown` tùy trường hợp.

Không nhầm đối số main method với VM arguments. Ví dụ `--profile=staging` ở trên là đối số ứng dụng, còn `-Xmx2g` là tùy chọn JVM.

## 6. Hiển thị JVM arguments bằng jps -v

Tùy chọn `-v` hiển thị các đối số đã truyền cho JVM khi khởi động.

Ví dụ:

```bash
java -Xms256m -Xmx2g -Dapp.profile=production -jar app.jar
```

Chạy:

```bash
jps -v
```

Output minh họa:

```text
18420 app.jar -Xms256m -Xmx2g -Dapp.profile=production
```

Các đối số thường gặp:

| Nhóm | Ví dụ | Ý nghĩa |
| --- | --- | --- |
| Heap | `-Xms256m`, `-Xmx2g` | Heap ban đầu và tối đa |
| System property | `-Dapp.profile=production` | Giá trị system property |
| GC | `-XX:+UseG1GC` | Chọn garbage collector |
| Module | `--add-modules java.sql` | Thêm module khi khởi chạy |
| Debug | `-agentlib:jdwp=...` | Cấu hình debugger agent |

JVM arguments hữu ích khi điều tra cấu hình runtime, nhưng có thể chứa thông tin nhạy cảm như token, mật khẩu, URL nội bộ hoặc đường dẫn. Hãy lọc output trước khi chia sẻ trong ticket, chat hoặc log công khai.

## 7. Kết hợp -l, -m và -v

Có thể kết hợp các tùy chọn để xem đầy đủ thông tin về một tiến trình:

```bash
jps -lmv
```

Ý nghĩa:

- `-l`: tên main class đầy đủ hoặc đường dẫn JAR.
- `-m`: đối số truyền cho main method.
- `-v`: đối số truyền cho JVM.

Ví dụ:

```text
18420 com.example.billing.Main --profile=prod -Dapp.profile=production -Xms256m -Xmx2g
29116 com.example.inventory.Main --port=8080 -Dapp.profile=staging -Xms128m -Xmx1g
```

Khi cần điều tra một ứng dụng có nhiều instance, tổ hợp này giúp so sánh class, main arguments và JVM arguments giữa các process.

Có thể viết các tùy chọn riêng:

```bash
jps -l -m -v
```

hoặc gộp:

```bash
jps -lmv
```

Cả hai cách đều yêu cầu các trường tương ứng. Thứ tự các phần trong output vẫn theo cấu trúc mà JPS tạo ra; không nên tự giả định mọi chuỗi có dấu cách là một đối số đơn.

## 8. Chỉ hiển thị PID bằng jps -q

Nếu chỉ cần danh sách định danh JVM để truyền cho công cụ khác, dùng `-q`:

```bash
jps -q
```

Output:

```text
18420
29116
32780
```

Tùy chọn này bỏ tên class/JAR và các đối số main, chỉ giữ local JVM identifiers.

Ví dụ dùng PID tìm được để xem thêm thông tin:

```bash
jcmd 18420 VM.uptime
jcmd 18420 VM.flags
```

Trong thực tế, hãy xác nhận PID vẫn thuộc ứng dụng mong muốn trước khi gửi diagnostic command, vì process có thể đã dừng hoặc PID được tái sử dụng.

## 9. Ví dụ thực hành Java 17: quan sát main class output

Ví dụ này tạo một ứng dụng có package rõ ràng, một đối số main method và một số JVM arguments để quan sát sự khác nhau giữa `jps -l`, `-m` và `-v`.

Tạo cấu trúc:

```text
project/
  src/
    com/
      example/
        diagnostics/
          MainClassOutput.java
  out/
```

Tệp **`src/com/example/diagnostics/MainClassOutput.java`**:

```java
package com.example.diagnostics;

public final class MainClassOutput {
    private MainClassOutput() {
    }

    public static void main(String[] args) throws InterruptedException {
        System.out.println("PID=" + ProcessHandle.current().pid());
        System.out.println("main args=" + String.join(",", args));

        Thread.sleep(120_000);
    }
}
```

Chương trình in PID và đối số main, sau đó ngủ 120 giây để JVM tiếp tục tồn tại cho tới khi ta kiểm tra bằng JPS.

Biên dịch bằng Java 17:

```bash
javac --release 17 -d out src/com/example/diagnostics/MainClassOutput.java
```

Khởi chạy ứng dụng:

```bash
java -Dapp.profile=demo -Xms32m -cp out com.example.diagnostics.MainClassOutput --mode=demo
```

Mở terminal thứ hai và chạy:

```bash
jps -l
```

Output mẫu:

```text
82192 com.example.diagnostics.MainClassOutput
```

Xem đối số main method:

```bash
jps -m
```

Output mẫu:

```text
82192 MainClassOutput --mode=demo
```

Xem JVM arguments:

```bash
jps -v
```

Output mẫu:

```text
82192 MainClassOutput -Dapp.profile=demo -Xms32m
```

Kết hợp tất cả:

```bash
jps -lmv
```

Output mẫu:

```text
82192 com.example.diagnostics.MainClassOutput --mode=demo -Dapp.profile=demo -Xms32m
```

Chỉ xem PID:

```bash
jps -q
```

Output có chứa:

```text
82192
```

PID `82192` là giá trị từ một lần chạy kiểm thử; khi chạy lại trên máy khác, PID sẽ thay đổi. Tên class và các tham số còn lại là những giá trị được thiết lập trong ví dụ.

Dừng chương trình bằng Ctrl+C ở terminal đang chạy `MainClassOutput`.

## 10. Main class output khi chạy bằng JAR

Nếu ứng dụng được khởi chạy theo dạng:

```bash
java -jar app.jar
```

JPS có thể hiển thị tên JAR thay vì tên class:

```text
18420 app.jar
```

Dùng:

```bash
jps -l
```

để xem đường dẫn JAR đầy đủ nếu launcher cung cấp thông tin đó.

Muốn tìm main class bên trong JAR, đọc manifest:

```bash
jar --list --file app.jar
```

Sau đó trích xuất manifest vào thư mục tạm:

```bash
jar --extract --file app.jar META-INF/MANIFEST.MF
```

Mở tệp `META-INF/MANIFEST.MF` và tìm:

```text
Main-Class: com.example.app.Main
```

Thuộc tính `Main-Class` cho biết class mà Java launcher gọi khi chạy JAR bằng `-jar`. JPS hiển thị launch target dạng JAR, nên không phải lúc nào nó cũng hiện trực tiếp tên lớp trong manifest.

## 11. Main class output khi chạy bằng module

Với JPMS, có thể chạy ứng dụng bằng module và main class:

```bash
java --module-path mods -m com.example.app/com.example.app.Main
```

Khi dùng `jps -l`, output có thể hiển thị module name và class name:

```text
18420 com.example.app/com.example.app.Main
```

Trong đó:

- `com.example.app` trước dấu `/` là tên module.
- `com.example.app.Main` sau dấu `/` là main class.

Module name và package/class name có thể trùng nhau trong một số dự án, nhưng chúng là hai định danh khác nhau. Tên module được khai báo trong `module-info.java`; tên class thuộc package Java.

Nếu module được đóng gói trong runtime image hoặc được khởi chạy theo cách đặc biệt, định dạng output phụ thuộc thông tin launcher mà JPS nhận được.

## 12. Vì sao jps có thể hiển thị Unknown hoặc thiếu main class?

JPS dựa vào thông tin launcher và cơ chế instrumented JVM để xác định tên class/JAR và đối số main.

Một số trường hợp có thể không hiển thị như mong đợi:

- JVM được khởi chạy qua custom launcher thay vì Java launcher thông thường.
- JVM được nhúng trong ứng dụng native qua JNI Invocation API.
- Tiến trình được khởi chạy bằng framework hoặc wrapper khiến thông tin main class không có sẵn.
- JVM không nằm trong phạm vi mà tài khoản hiện tại có quyền quan sát.
- JVM đã kết thúc trước khi JPS thu thập thông tin.
- Container hoặc PID namespace khiến process không xuất hiện trong phạm vi JPS đang chạy.

Trong một số trường hợp, tên lớp/JAR hoặc main arguments có thể được hiển thị là `Unknown`, hoặc đối số main có thể là `null`.

Khi cần xác định process mà JPS không nhận diện được, kiểm tra thêm bằng công cụ hệ điều hành như Task Manager, `ps` hoặc `pgrep`, rồi đối chiếu PID với cấu hình chạy ứng dụng.

## 13. Giới hạn và lưu ý khi đọc output

JPS chỉ liệt kê các JVM HotSpot được instrument và có thể truy cập theo quyền của tài khoản hiện tại. Nó không phải công cụ liệt kê mọi tiến trình hệ điều hành và không bảo đảm mọi JVM trong container hoặc user khác đều xuất hiện.

Một số giới hạn quan trọng:

- LVMID thường nhưng không nhất thiết là PID của hệ điều hành.
- Tên main class mặc định là dạng ngắn, có thể trùng giữa nhiều ứng dụng.
- `-m` có thể không hiển thị đối số nếu launcher không cung cấp.
- `-v` có thể để lộ cấu hình hoặc dữ liệu nhạy cảm trong VM arguments.
- Output phân tách token bằng khoảng trắng; đối số chứa khoảng trắng làm việc phân tích thủ công khó hơn.
- Định dạng output có thể thay đổi giữa các phiên bản JDK.

Tài liệu JDK khuyến cáo không viết script phụ thuộc vào việc parse output `jps`, vì định dạng có thể thay đổi trong các bản phát hành tương lai. Nếu cần automation ổn định, dùng API/management interface hoặc cơ chế giám sát được thiết kế cho mục tiêu đó.

JPS cũng được tài liệu JDK 24 mô tả là công cụ experimental và unsupported. Hãy kiểm tra tài liệu của đúng phiên bản JDK đang sử dụng và chuẩn bị phương án thay thế nếu công cụ không còn được cung cấp trong tương lai.

## 14. Lỗi thường gặp

| Hiện tượng | Nguyên nhân thường gặp | Cách xử lý |
| --- | --- | --- |
| Không thấy main class đầy đủ | Dùng lệnh mặc định chỉ hiển thị tên ngắn | Dùng `jps -l` |
| Nhiều process cùng hiển thị `Main` | Các ứng dụng khác package nhưng cùng tên class | Dùng `-l` để xem package đầy đủ |
| Không thấy tham số ứng dụng | Chưa bật hiển thị main arguments | Dùng `jps -m` |
| Không thấy `-Xmx` hoặc `-D...` | Chưa bật hiển thị JVM arguments | Dùng `jps -v` |
| Output có tên JAR thay vì class | Ứng dụng được chạy bằng `java -jar` | Kiểm tra `Main-Class` trong manifest |
| Output hiển thị `Unknown` | Custom launcher hoặc thông tin main class không có sẵn | Kiểm tra command line/process metadata bằng công cụ phù hợp |
| Không thấy JVM của user khác | Quyền hệ điều hành giới hạn khả năng quan sát | Chạy dưới tài khoản được phép hoặc nhờ admin |
| Không thấy JVM trong container | JPS không ở cùng PID namespace hoặc attach scope | Chạy công cụ trong container hoặc kiểm tra PID từ host |
| Main args hiển thị thiếu/khó đọc | Đối số chứa khoảng trắng hoặc launcher không cung cấp metadata | Kiểm tra lệnh khởi chạy gốc và cấu hình ứng dụng |
| Không tìm thấy lệnh jps | Chưa cài JDK hoặc PATH không có thư mục bin | Kiểm tra `JAVA_HOME` và `PATH` |

## 15. Quy trình nhận diện ứng dụng bằng jps

Khi cần tìm đúng ứng dụng Java đang chạy:

1. Chạy `jps -l` để xem PID và main class/JAR đầy đủ.
2. Nếu nhiều process trùng tên, dùng package/module hoặc đường dẫn JAR để phân biệt.
3. Chạy `jps -m` để xem tham số ứng dụng.
4. Chạy `jps -v` để xem JVM arguments.
5. Dùng PID xác định để gửi lệnh tiếp theo, chẳng hạn `jcmd <pid> help`.
6. Nếu class/JAR hiển thị `Unknown`, kiểm tra process bằng công cụ hệ điều hành.
7. Nếu không thấy process, xác nhận user, quyền truy cập và PID namespace.
8. Lọc dữ liệu nhạy cảm trước khi chia sẻ output.

Ví dụ chuỗi lệnh:

```bash
jps -l
jps -lmv
jcmd 18420 help
```

Không dùng PID cũ sau khi ứng dụng restart mà chưa xác nhận lại process.

## 16. Ghi nhớ

- Main class là lớp được launcher chọn làm điểm bắt đầu ứng dụng; main method là phương thức entry point bên trong lớp.
- Output mặc định của `jps` gồm LVMID và tên ngắn của main class hoặc JAR.
- `jps -l` hiển thị tên package đầy đủ hoặc đường dẫn JAR.
- `jps -m` hiển thị đối số truyền vào main method.
- `jps -v` hiển thị JVM arguments như `-Xmx`, `-Xms` và `-D...`.
- `jps -lmv` kết hợp thông tin class/JAR, main args và JVM args.
- `jps -q` chỉ hiển thị local JVM identifiers.
- JAR launch có thể hiển thị tên JAR thay vì Main-Class trong manifest.
- Module launch có thể hiển thị dạng `module/class`.
- JPS có thể không nhận diện main class với custom launcher, embedded JVM hoặc khi thiếu quyền truy cập.
- Không nên viết script parse output JPS như một định dạng ổn định; kiểm tra PID và bảo vệ thông tin nhạy cảm.

Hiểu trường main class trong output `jps` giúp bạn nhận diện ứng dụng Java đang chạy, phân biệt nhiều instance, xác định tham số khởi chạy và chuyển từ bước liệt kê process sang chẩn đoán JVM bằng các công cụ như `jcmd`.
