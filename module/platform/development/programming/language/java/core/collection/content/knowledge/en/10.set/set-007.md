# Choosing Between HashSet, LinkedHashSet, TreeSet, or EnumSet

## 1. Choose Based on Data Requirements Before Picking a Class Name

All four options are `Set` implementations: their shared goal is to represent unique values without duplicates. However, they address different requirements regarding ordering, lookup behavior, and element domain.

A requirement like “store unique codes” is not specific enough to make a choice. You need to ask further:

1. Do we need to preserve the order of first appearance?
2. Do the values need to remain sorted at all times?
3. Do we need to find the nearest value or retrieve an ordered range?
4. Do all elements belong to the same enum type?
5. Is `null` allowed?
6. Is the main cost in membership checks, iteration, updates, or set operations?

Four general roles:

| Option | Primary Role |
| --- | --- |
| HashSet | General-purpose hash-based set with no guaranteed iteration order |
| LinkedHashSet | Hash-based set that also preserves insertion order |
| TreeSet | Ordered set based on `Comparable` or `Comparator`, supporting order-based queries |
| EnumSet | Specialized set for constants of a single enum type |

There is no single “best” class independent of requirements. Choosing the wrong ordering semantics can be a correctness bug, not merely a speed difference.

This article uses Java 17 or later. The programs run standalone in a single thread, with elements whose identity-defining data is not mutated while in the set.

## 2. Baseline Comparison Table

| Criterion | HashSet | LinkedHashSet | TreeSet | EnumSet |
| --- | --- | --- | --- | --- |
| Element domain | Any reference type suitable for `Set` | Same as `HashSet` | Elements comparable under the chosen rule | Constants belonging to the same enum type |
| Membership rule | `equals`/`hashCode` | `equals`/`hashCode` | `compareTo` or `Comparator`; must be consistent with `equals` to uphold the general `Set` contract | Identity of constants of that enum type |
| Iteration order | Not guaranteed | Insertion order | Comparison order | Enum constant declaration order |
| Basic add/remove/contains | Constant time when hash distribution is good; not a time guarantee for all inputs | Similar, with additional order-maintenance overhead | O(log n), plus the cost of one comparison | Constant-time basic operations for the defined enum domain per class documentation |
| Nearest/range order queries | No dedicated API | No dedicated API | Yes, via `SortedSet`/`NavigableSet` | Does not implement `SortedSet`/`NavigableSet` |
| `null` | Allows at most one `null` | Allows at most one `null` | Natural ordering rejects `null`; a custom comparator must explicitly support it if desired | `null` cannot be added |
| Primary structure | Hash table | Hash table with order-preserving links | Ordered structure backed by `TreeMap` | Bit vector |
| Built-in synchronization for concurrent writes | No | No | No | No |

“Constant” and “logarithmic” are work-scaling models relative to size. Do not convert them into a fixed nanosecond ratio between classes.

Null handling is a policy to decide, not the sole reason to choose a data structure. A program can actively forbid `null` even if the chosen class supports it.

## 3. A Practical Decision Path

### 3.1. Is it a set of constants from the same enum?

If yes, `EnumSet` is a strong candidate when declaration order is sufficient and you do not need to preserve insertion history or use a custom comparator.

However, do not stop at “it has an enum”:

- Need the order in which the user selected the constants: `LinkedHashSet<EnumType>` may be more appropriate.
- Need a custom priority order or neighbor queries under a specific ordering: consider `TreeSet` with the right comparison rule.
- Only need flags or groups of constants within an enum domain: `EnumSet` usually expresses intent clearly and has a compact representation.

### 3.2. Does comparison order need to be maintained continuously?

If you need to find elements before/after a threshold, retrieve a range, or keep values sorted across updates, `TreeSet` provides those capabilities.

If you only need to print a sorted report at the end, using `TreeSet` throughout the entire process is not mandatory. You can use a suitable `Set` during collection, then create a list and sort it when presenting. Account for update frequency versus how often sorted data is needed.

### 3.3. Is insertion order needed?

If you need to deduplicate while preserving first-appearance order, `LinkedHashSet` expresses that requirement.

Insertion order is different from alphabetical order, numerical order, priority level, or most-recent access. Do not lump all of these requirements together as “ordered”.

### 3.4. None of the above ordering guarantees needed?

`HashSet` is a sensible general-purpose choice for membership checks or collecting distinct values when no guaranteed iteration order is needed and elements have proper `equals`/`hashCode`.

The fact that one run happens to print a `HashSet` in a neat-looking order does not establish a new ordering contract.

## 4. HashSet: Suitable When You Need a General Set Without Relying on Order

### 4.1. Hashing for membership lookup

`HashSet` uses a hash table to store elements. For a custom class:

- Objects that are `equals` must have the same `hashCode`.
- Having the same `hashCode` does not guarantee equality.
- Data participating in `equals`/`hashCode` must remain stable while the element is in the set.

If you break the element contract, switching from `HashSet` to `LinkedHashSet` will not fix it, because both are hash-based.

According to [Java 17 HashSet](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/HashSet.html), basic operations have constant-time performance assuming the hash function disperses elements properly. That condition matters; do not claim “`HashSet` is always O(1)” for every key type and every measurement.

### 4.2. No guaranteed iteration order

`HashSet` does not preserve insertion order and does not sort itself. The order can be affected by hash contents, capacity, and mutations to the set.

Therefore, do not rely on `HashSet` iteration order for:

- Output formatting that must stay stable in insertion order.
- A “first element encountered” rule.
- Picking the smallest value by calling `iterator.next`.
- Data that must follow a fixed priority order.

Those requirements call for a different organization.

### 4.3. Iteration cost also depends on capacity

The `HashSet` documentation notes that iteration depends on both the number of elements and the capacity of the backing hash table. Allocating an overly large capacity can make iteration do extra work, even when the current element count is small.

This differs from the oversimplified maxim “iterating a `Set` always depends only on `size`”. You need to consider the implementation and allocation strategy.

You do not need to tune capacity manually in every program. First determine data size and usage patterns; only optimize parameters when there is a specific reason.

## 5. LinkedHashSet: Preserving Insertion Order While Using Hash Rules

### 5.1. First appearance determines position

Given the input:

```text
gamma, alpha, beta, alpha
```
A `LinkedHashSet` keeps the values in the order:

```text
gamma, alpha, beta
```
The second addition of `alpha` does not create a duplicate and does not move `alpha` to the end.

If you remove `alpha` and then add it back, that is a fresh insertion after `alpha` is no longer in the set, so it can appear at the end of the current insertion order.

This is the difference between:

- Attempting to re-add an element that is already present.
- Removing and then re-adding an element.

### 5.2. Benefits and costs

[Java 17 LinkedHashSet](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/LinkedHashSet.html) maintains ordering links across the hash table entries.

Basic operations remain hash-based. In return, the structure needs extra state and work to maintain the order. Do not treat that guarantee as free in terms of memory.

Iterating a `LinkedHashSet` takes time proportional to the number of elements, independent of capacity in the way `HashSet` table scanning is. Therefore, do not conclude that `LinkedHashSet` is always slower for every kind of workload just because it manages extra links.

### 5.3. Not a sorted set or access-order mechanism

`LinkedHashSet` does not automatically place `alpha` before `beta` alphabetically. Nor does it change order on each `contains` check or each time an element is read.

If you need a most-recently-accessed policy, do not infer it from the word “Linked”. The class contract in Java 17 is insertion order.

Copying an ordered collection into a `LinkedHashSet` can preserve the order encountered during insertion. However, copying a `HashSet` will not recover an insertion history that `HashSet` never provided.

## 6. Runnable Example: Distinguishing Unordered, Insertion Order, and Sorted Order

Save as `SetOrderChoiceDemo.java`:

```java
import java.util.HashSet;
import java.util.LinkedHashSet;
import java.util.List;
import java.util.Set;
import java.util.TreeSet;

public class SetOrderChoiceDemo {
    public static void main(String[] args) {
        List<String> input = List.of("gamma", "alpha", "beta", "alpha");
        Set<String> hash = new HashSet<>(input);
        LinkedHashSet<String> linked = new LinkedHashSet<>(input);
        TreeSet<String> sorted = new TreeSet<>(input);

        System.out.println("HashSet size = " + hash.size());
        System.out.println("HashSet contains alpha = " + hash.contains("alpha"));
        System.out.println("HashSet members sorted for display = "
                + new TreeSet<>(hash));
        System.out.println("LinkedHashSet = " + linked);
        System.out.println("TreeSet = " + sorted);
        System.out.println("hash equals linked = " + hash.equals(linked));

        System.out.println("add existing alpha = " + linked.add("alpha"));
        System.out.println("order after existing add = " + linked);

        linked.remove("alpha");
        linked.add("alpha");
        System.out.println("order after remove and add = " + linked);

        System.out.println("HashSet add first null = " + hash.add(null));
        System.out.println("HashSet add second null = " + hash.add(null));
    }
}
```
Compile and run:

```shell
javac --release 17 SetOrderChoiceDemo.java
java SetOrderChoiceDemo
```
Output:

```text
HashSet size = 3
HashSet contains alpha = true
HashSet members sorted for display = [alpha, beta, gamma]
LinkedHashSet = [gamma, alpha, beta]
TreeSet = [alpha, beta, gamma]
hash equals linked = true
add existing alpha = false
order after existing add = [gamma, alpha, beta]
order after remove and add = [gamma, beta, alpha]
HashSet add first null = true
HashSet add second null = false
```
The program intentionally does not print the `HashSet` order directly as a fixed output.

The `HashSet members sorted for display` line creates **another TreeSet** to present the contents sorted. It does not prove that the original `HashSet` was ordered.

Verified points:

- All three implementations retain three distinct values.
- `LinkedHashSet` preserves `gamma, alpha, beta` by first appearance.
- `TreeSet` uses `String` natural ordering, printing `alpha, beta, gamma`.
- `HashSet` and `LinkedHashSet` still satisfy `Set.equals` when they have the same members.
- Re-adding an existing `alpha` does not change the order.
- Removing and then adding `alpha` yields `gamma, beta, alpha`.
- `HashSet` accepts one `null` without creating a second entry.

This program does not measure speed or memory of the three classes. The ordering output is not a benchmark.

## 7. TreeSet: Choose When Ordering Is a Capability to Maintain

### 7.1. Natural ordering or Comparator

`TreeSet` uses the element's `Comparable` implementation or a supplied `Comparator`. Elements are kept in that order, not by insertion time.

Examples:

- Integers in ascending order.
- `String` codes in `String` comparison order.
- A custom order described by a `Comparator`, if it fits the element model.

According to [Java 17 TreeSet](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/TreeSet.html), `add`, `remove`, and `contains` have O(log n) cost for basic operations, with the comparison cost factored in appropriately. A `Comparator` that reads long strings or complex data does not automatically have constant cost.

Do not pick `TreeSet` just because the class name suggests “a tree searches faster than hashing”. The primary reason is that the set maintains order and provides order-based queries.

### 7.2. Comparison returning 0 determines membership

Two values considered equal (returning 0) by the comparator or `compareTo` are treated by `TreeSet` as the same element.

If a comparator only compares `String` length, two different strings of the same length will cause the second addition to return `false`. If the business logic wants to keep both strings, that comparator is missing a tie-breaking criterion.

To uphold the general `Set` contract, the ordering should be consistent with `equals`. For `String`, you can sort by length and then by content:

```java
// Illustrative snippet: requires importing java.util.Comparator and java.util.TreeSet.
Comparator<String> order = Comparator
        .comparingInt(String::length)
        .thenComparing(Comparator.naturalOrder());

TreeSet<String> values = new TreeSet<>(order);
```
The secondary rule here keeps strings with different contents distinct when they have the same length. Do not add a tie-breaker that makes two `equals` objects compare as non-zero.

Also, do not mutate data participating in the comparator while the element is in the tree. Its position in the structure may become invalid after such a change.

### 7.3. Nearest-match and range queries

With `NavigableSet`:

| Method | Queried Value |
| --- | --- |
| `lower(x)` | Greatest value strictly less than `x` |
| `floor(x)` | Greatest value less than or equal to `x` |
| `ceiling(x)` | Least value greater than or equal to `x` |
| `higher(x)` | Least value strictly greater than `x` |
| `subSet(from, fromInclusive, to, toInclusive)` | Range of values between two bounds per boundary rules |
| `first()`, `last()` | The two extremes under the current ordering |

`lower`/`floor`/`ceiling`/`higher` return `null` if no matching value is found. `first`/`last` throw `NoSuchElementException` when the set is empty. These are different contracts.

The comparator's order is what defines “before”, “after”, or “range”; with a reversed comparator, do not keep reading the results as ascending numerical order.

### 7.4. A view is not a copy

`subSet` returns a view backed by the original set. Additions or removals through the view can modify the original set; matching changes on the original are also visible through the view.

Adding a value outside the view's bounds is rejected. If you need an independent result set, copy it intentionally and preserve the required comparison rule.

## 8. Runnable Example: TreeSet for Queries That HashSet Cannot Provide

Save as `TreeSetRangeChoiceDemo.java`:

```java
import java.util.List;
import java.util.NavigableSet;
import java.util.TreeSet;

public class TreeSetRangeChoiceDemo {
    public static void main(String[] args) {
        NavigableSet<Integer> values = new TreeSet<>(
                List.of(40, 10, 30, 20));

        System.out.println("sorted values = " + values);
        System.out.println("first = " + values.first());
        System.out.println("last = " + values.last());
        System.out.println("lower than 20 = " + values.lower(20));
        System.out.println("floor of 20 = " + values.floor(20));
        System.out.println("ceiling of 25 = " + values.ceiling(25));
        System.out.println("higher than 30 = " + values.higher(30));

        NavigableSet<Integer> middle = values.subSet(20, true, 40, false);
        System.out.println("range [20, 40) = " + middle);

        middle.remove(30);
        System.out.println("original after range removal = " + values);

        try {
            middle.add(50);
        } catch (IllegalArgumentException ex) {
            System.out.println("add outside range = "
                    + ex.getClass().getSimpleName());
        }

        try {
            values.add(null);
        } catch (NullPointerException ex) {
            System.out.println("natural-order TreeSet null = "
                    + ex.getClass().getSimpleName());
        }
    }
}
```
Compile and run:

```shell
javac --release 17 TreeSetRangeChoiceDemo.java
java TreeSetRangeChoiceDemo
```
Output:

```text
sorted values = [10, 20, 30, 40]
first = 10
last = 40
lower than 20 = 10
floor of 20 = 20
ceiling of 25 = 30
higher than 30 = 40
range [20, 40) = [20, 30]
original after range removal = [10, 20, 40]
add outside range = IllegalArgumentException
natural-order TreeSet null = NullPointerException
```
Explanation:

- Data is added in the order 40, 10, 30, 20, yet iterates in ascending order.
- `lower(20)` excludes 20 itself, whereas `floor(20)` can return 20.
- `ceiling(25)` finds 30 without requiring 25 to be present.
- `subSet` selects from 20 inclusive up to 40 exclusive, so initially it contains 20 and 30.
- Removing 30 through `middle` also removes 30 from the original set.
- Adding 50 through `middle` violates the bounds, throwing `IllegalArgumentException`.
- The natural-order `TreeSet` in this example rejects `null`.

If you only need to ask whether 25 is present, `HashSet` also has `contains`. When you need “the smallest value not less than 25”, that is an order-based requirement that `TreeSet` answers directly.

A `TreeSet` with a null-handling comparator may have a different policy than this example. Do not turn a custom comparator case into an assumption that every `TreeSet` accepts `null`.

## 9. EnumSet: Leveraging a Domain That Is Already an Enum

### 9.1. Closed domain and bit representation

`EnumSet` is designed for constants of the same enum type. It knows the domain of possible values and uses a bit vector to represent membership.

For example, a selected group of `Phase` values can be represented without a separate general-purpose hash entry for each present value. According to [Java 17 EnumSet](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/EnumSet.html), this is a compact representation and basic operations take constant time; bulk operations can also be optimized when the argument is an `EnumSet`.

Do not infer from “bit” that users should manually bit-shift by `ordinal` or maintain a separate `int` bitmask. `EnumSet` provides a safer data type for working with enum constants.

`EnumSet` is also not limited to enums with at most 64 constants. [OpenJDK 17 EnumSet source](https://github.com/openjdk/jdk17u/blob/master/src/java.base/share/classes/java/util/EnumSet.java) selects an internal implementation based on domain size. Those internal implementation class names are not an API that application code should depend on.

### 9.2. Declaration order, not insertion order

If an enum declares `NEW` before `RUNNING` before `FAILED`, `EnumSet` iterates in that order even if `FAILED` is added first.

This is neither alphabetical order nor user selection history. If the requirement is “display in the order the user selected the states”, `EnumSet` alone does not satisfy that guarantee; `LinkedHashSet<Phase>` may be suitable.

If you need a custom order or comparator-based queries, `EnumSet` does not turn into a `TreeSet`. It does not implement `SortedSet`/`NavigableSet` just because it has an iteration order.

### 9.3. Factory methods to recognize

| Factory | Meaning |
| --- | --- |
| `EnumSet.noneOf(Phase.class)` | Empty set that still knows the enum type |
| `EnumSet.of(a, b, ...)` | Set containing the specified constants |
| `EnumSet.allOf(Phase.class)` | Set containing all constants of that type |
| `EnumSet.copyOf(existingEnumSet)` | Copy of a set with the same enum type |
| `EnumSet.range(from, to)` | Constants from `from` through `to`, inclusive, in declaration order |
| `EnumSet.complementOf(selected)` | Constants of the same type not in `selected` |

`EnumSet` is an abstract class, so it cannot be instantiated with `new EnumSet<>()`. Use the appropriate factory method to supply the domain type.

### 9.4. Two pitfalls with range and copyOf

**`range` is not a `subSet` of an existing set.** `EnumSet.range` creates the constants in the declared slice of the enum domain, even if they were never added to any `selected` set. `TreeSet.subSet`, by contrast, selects a range from values currently present in the backing set and returns a view.

**`copyOf` from an empty ordinary collection cannot infer the enum type.** If the runtime argument is not an `EnumSet` and has no elements, `EnumSet.copyOf(Collection)` throws `IllegalArgumentException`. When the target type is known, `noneOf(Type.class)` followed by `addAll` expresses the intent clearly.

An empty `EnumSet` still retains its type information, so it can be copied. This is not merely a compile-time variable type issue: the `Collection` overload also checks whether the runtime argument is an `EnumSet` per the factory method's contract.

### 9.5. allOf and complementOf must be read in terms of the domain

If a new constant is added to the enum type in a later version, the “all constants” set and the domain complement will include that new constant. Make sure the business intent truly is to select over the entire domain.

Enum declaration order is not a state machine either. `EnumSet.range` between two `Phase` values only reflects declaration positions; it does not prove that every state transition in between is valid in business logic.

Do not use the current `ordinal` as a stable business identifier just because the internal representation relates to constant position. Separate identifier storage/transport from collection optimization details.

## 10. Runnable Example: EnumSet, Domain Order, and Empty Sets

Save as `EnumSetChoiceDemo.java`:

```java
import java.util.EnumSet;
import java.util.List;

public class EnumSetChoiceDemo {
    enum Phase {
        NEW, VALIDATED, RUNNING, COMPLETED, FAILED
    }

    public static void main(String[] args) {
        EnumSet<Phase> selected = EnumSet.of(
                Phase.FAILED, Phase.NEW, Phase.RUNNING);
        System.out.println("selected in declaration order = " + selected);
        System.out.println("none = " + EnumSet.noneOf(Phase.class));
        System.out.println("all = " + EnumSet.allOf(Phase.class));
        System.out.println("range VALIDATED through COMPLETED = "
                + EnumSet.range(Phase.VALIDATED, Phase.COMPLETED));
        System.out.println("complement = " + EnumSet.complementOf(selected));

        EnumSet<Phase> copy = EnumSet.copyOf(selected);
        copy.remove(Phase.FAILED);
        System.out.println("copy after removal = " + copy);
        System.out.println("selected remains = " + selected);

        EnumSet<Phase> empty = EnumSet.noneOf(Phase.class);
        System.out.println("copy empty EnumSet = " + EnumSet.copyOf(empty));

        try {
            EnumSet.copyOf(List.<Phase>of());
        } catch (IllegalArgumentException ex) {
            System.out.println("copy empty ordinary collection = "
                    + ex.getClass().getSimpleName());
        }

        try {
            selected.add(null);
        } catch (NullPointerException ex) {
            System.out.println("EnumSet add null = "
                    + ex.getClass().getSimpleName());
        }
    }
}
```
Compile and run:

```shell
javac --release 17 EnumSetChoiceDemo.java
java EnumSetChoiceDemo
```
Output:

```text
selected in declaration order = [NEW, RUNNING, FAILED]
none = []
all = [NEW, VALIDATED, RUNNING, COMPLETED, FAILED]
range VALIDATED through COMPLETED = [VALIDATED, RUNNING, COMPLETED]
complement = [VALIDATED, COMPLETED]
copy after removal = [NEW, RUNNING]
selected remains = [NEW, RUNNING, FAILED]
copy empty EnumSet = []
copy empty ordinary collection = IllegalArgumentException
EnumSet add null = NullPointerException
```
Verified points:

1. `FAILED` is passed to `of` first, but is iterated after `NEW` and `RUNNING` due to declaration order.
2. `noneOf` creates a typed empty set.
3. `allOf` selects all five constants.
4. `range` is inclusive of both `VALIDATED` and `COMPLETED`, so it includes `RUNNING` in between.
5. `complementOf` selects the constants in the domain not present in `selected`.
6. Modifying `copy` does not remove `FAILED` from `selected`.
7. Copying an empty `EnumSet` is valid.
8. Copying an ordinary empty `List` has no data from which to infer the enum type.
9. Adding `null` is rejected with `NullPointerException`.

The copy here is an independent set structure. The enum constants themselves remain constants of the same type; no new constants are cloned.

This example does not measure memory or speed, so do not derive a speedup ratio over `HashSet`. The rationale for choosing `EnumSet` comes from a fitting domain type and specialized representation.

## 11. Choosing the Declared Type to Express the Required Capability

### 11.1. Only need membership: Set is usually enough

```java
// Illustrative snippet.
Set<String> visitedIds = new HashSet<>();
Set<String> orderedTags = new LinkedHashSet<>();
```
Callers can use `add`, `contains`, `remove`, or iterate over the `Set`. The implementation preserves the chosen characteristics internally.

However, if ordering is part of the contract that callers depend on, you must document that guarantee clearly. Looking at the `Set` type alone does not tell whether the result preserves insertion order, sorted order, or has no guaranteed order.

### 11.2. Need order queries: declare the matching capability

```java
// Illustrative snippet.
NavigableSet<Integer> thresholds = new TreeSet<>();
Integer next = thresholds.ceiling(25);
```
If the variable only has type `Set`, `ceiling` cannot be called directly. `NavigableSet` makes it clear that the code needs order-based neighbor capabilities, not just membership checks.

Do not cast an arbitrary `Set` to `TreeSet` just to access these methods. The declared type and input contract should align from the design stage.

### 11.3. Enum domain: keep EnumSet where specialized operations are needed

```java
// Illustrative snippet; Phase is a defined enum type.
EnumSet<Phase> selected = EnumSet.noneOf(Phase.class);
selected.add(Phase.RUNNING);
```
If a method only needs membership checks, it can accept `Set<Phase>`. If it needs domain-based `copyOf`/`complementOf` or wants to guarantee the specialized representation, a more specific contract may be needed.

Do not mix different enum types through raw types to bypass type constraints. Each `EnumSet` is bound to a single enum domain.

## 12. Changing the Implementation Can Change Guarantees, Not Just Speed

### 12.1. Copying to another type

| Conversion | What to Check |
| --- | --- |
| `HashSet` → `LinkedHashSet` | Preserves the order encountered when iterating the source, does not recover insertion history |
| `LinkedHashSet` → `HashSet` | May lose presentation-order guarantees |
| `Set` → `TreeSet` | Needs a comparable type or suitable comparator; comparison returning 0 affects membership |
| `EnumSet` → `HashSet` | Still holds the constants, but loses `EnumSet`'s declaration-order guarantee |
| Empty ordinary `Set` → `EnumSet.copyOf` | No domain type to infer if the source is not an `EnumSet` |
| Set with comparator → new result set | Must preserve the comparator if ordering requirements depend on it |

When copying a `TreeSet`, do not just look at the elements and forget the comparison rule. Constructing the new set must account for the comparator to preserve.

### 12.2. Unmodifiability is a separate requirement

All four types in this article are ordinary mutable structures. Returning a `Set` that prevents callers from adding/removing requires a separate policy.

Do not assume `Set.copyOf(enumSet)` remains an `EnumSet` or preserves declaration order. `Set.copyOf` follows the `Set` factory contract, not a promise to preserve all characteristics of the source class.

Wrapping or copying also does not create deep immutability for element objects. When elements have mutable fields, you must keep identity-defining data stable and define mutation permissions at the model level.

### 12.3. Switching TreeSet to HashSet can expose different equality criteria

If a `TreeSet` used a comparator inconsistent with `equals`, it may have already merged values that `HashSet` considers distinct. Switching to `HashSet` cannot restore elements that were never retained.

Therefore, check equality criteria before switching classes. A collection conversion cannot recreate data that was already discarded earlier.

## 13. Cost, Memory, and Concurrency Model

### 13.1. Look at the full operation pattern

If the workload is mostly `contains` and does not need ordering, hashing is a natural direction. If you must always return an ordered range after every update, the maintenance cost of `TreeSet` directly serves that requirement.

If you only iterate once at the end, compare the cost of collecting first and sorting a presentation copy. If the domain is an enum, consider the benefits of `EnumSet`'s specialized representation and set operations.

Do not choose based on a single measurement on a few elements or an `O(...)` table that omits conditions on the hash function or comparator.

### 13.2. No fixed memory ratio

`HashSet` has a hash table and management entries. `LinkedHashSet` adds order-linking state. `TreeSet` has an order-maintaining tree structure. `EnumSet` uses bits for the enum domain along with associated domain metadata.

Actual byte counts depend on the JVM, set size, domain type, capacity, and element object graph. Do not claim a class always consumes exactly X bytes per element across all environments.

`EnumSet` being compact does not mean you can use it for dynamically generated `String` codes. It only fits when the domain is genuinely an enum.

### 13.3. The four classes do not handle concurrent access by themselves

`HashSet`, `LinkedHashSet`, `TreeSet`, and `EnumSet` are not synchronized for concurrent modifications across multiple threads. The choice in this article is based on domain and ordering; concurrency is a separate dimension.

The fail-fast iterators of some classes help detect certain invalid modifications on a best-effort basis. `EnumSet`'s iterator is weakly consistent per the documentation, but that does not make `EnumSet` a thread-safe collection for arbitrary concurrent access.

If the program requires concurrent writes or a consistent snapshot, you must choose a mechanism or data structure suited to that requirement. Do not pick a class just because one test run did not happen to throw `ConcurrentModificationException`.

## 14. Concrete Selection Scenarios

| Scenario | Well-Founded Initial Choice | Reason and Conditions |
| --- | --- | --- |
| Collect unique codes to check if seen before, no ordered output needed | `HashSet` | No need to pay the cost of maintaining an unused order |
| Deduplicate tags while preserving first user-entered order | `LinkedHashSet` | Insertion order is a requirement |
| Track numeric thresholds and frequently query the smallest threshold ≥ x | `TreeSet` via `NavigableSet` | Provides `ceiling` and order-based capabilities |
| Maintain active values and retrieve range `[a, b)` | `TreeSet` | Needs ordered range; mind the backed view |
| Group values of the same enum, declaration order is sufficient | `EnumSet` | Fixed domain type and specialized representation |
| Enum constants, but must preserve user selection order | `LinkedHashSet<EnumType>` | `EnumSet` uses declaration order, not selection history |
| Only need one sorted output after collection finishes | Appropriate `Set` to collect, then sort a presentation copy when needed | No need to maintain a tree throughout the entire process |
| Strings that may collide under a custom business key | Choose the key model first, then choose the `Set` type | The collection class does not infer key criteria on its own |

A well-founded initial choice does not replace benchmarking real workloads when data or load is large. However, correctness of ordering and membership must be clear before optimizing time.

## 15. Common Misconceptions That Lead to Wrong Choices

| Misconception | What to Distinguish |
| --- | --- |
| “`HashSet` is currently printing in ascending order so I can rely on it” | Observed order is not an API guarantee |
| “`LinkedHashSet` sorts by value” | It preserves insertion order |
| “Re-adding an existing element moves it to the end” | Java 17 `LinkedHashSet` does not change position on a duplicate `add` |
| “`TreeSet` only changes print order” | Comparison returning 0 also decides whether an element is kept |
| “`Comparator` doesn't need to care about `equals`” | Upholding the general `Set` contract requires consistency with `equals` |
| “If there's an enum, always choose `EnumSet`” | Check insertion order, custom order, and query capabilities |
| “`EnumSet` iterates in the order `add` was called” | It iterates in declaration order |
| “`EnumSet` is just a `Set.of` for enums” | A normal `EnumSet` is mutable; `Set.of` creates an unmodifiable set |
| “`EnumSet.range` filters the current `selected` set” | It produces the slice of constants in the enum domain |
| “`copyOf` from any empty collection knows the enum type” | A non-`EnumSet` empty source cannot provide the type to infer |
| “An ordered `Set` is a `SortedSet`” | `LinkedHashSet` and `EnumSet` have iteration order but do not provide `SortedSet`/`NavigableSet` APIs |
| “Same `O(1)` means every class runs the same” | Hashing assumptions, constants, memory, and workload still differ |
| “An unmodifiable `Set` is a deeply immutable snapshot” | Distinguish set structure from element lifecycle |

## 16. Practice: Choosing by Contract

### Exercise 1: Keep the first line encountered

The source has codes `C, A, B, A`. You want to deduplicate while outputting `C, A, B`.

`LinkedHashSet` is the direct choice by insertion order. `TreeSet` would sort into a different order; `HashSet` does not guarantee the requirement; `EnumSet` is only usable if the domain is modeled as an enum and declaration order may not match the requirement.

### Exercise 2: Query the nearest threshold

You have thresholds `10, 20, 30, 40`; you need the smallest threshold not less than `25`.

`TreeSet` via `NavigableSet` gives `ceiling(25)` equal to `30`. Calling `contains(25)` on a hash set only answers whether the exact value `25` is present, not the same kind of result.

### Exercise 3: Enum constants added in reverse declaration order

If an enum declares `A, B, C` and you call `EnumSet.of(C, A)`, iteration yields `A` then `C`. If you need `C` then `A` in selection order, use a structure with an insertion-order guarantee or store the selection history separately.

### Exercise 4: Do we need TreeSet just for neat printing?

If the application only needs uniqueness during collection and outputs a sorted report once, you can collect in a `HashSet` and sort a result list. If you need frequent order queries during updates, `TreeSet` has a stronger rationale.

### Exercise 5: Comparator comparing only one attribute

Two distinct records have the same priority. A comparator that only compares priority can return `0`, causing `TreeSet` not to keep both. You need to define the proper membership criterion and a consistent ordering rule; do not treat this as a random tree bug.

### Exercise 6: Initializing an empty enum group

You know the `Phase` type but have not selected any values yet. Use `EnumSet.noneOf(Phase.class)`, rather than trying to infer the type from an ordinary empty `List`.

### Exercise 7: Mutating through a range

A variable receives the result of `TreeSet.subSet` and calls `remove`. If you need to preserve the source set, remember that it is a view, not an independent copy. Copy intentionally before mutating if the requirement is to compute a separate result.

### Exercise 8: Re-evaluating the choice after requirements change

Initially no ordering was needed, so `HashSet` was used. Later, the output must preserve user insertion order. This is a data-contract change; switching to `LinkedHashSet` is more appropriate than relying on an incidental `HashSet` order.

A good decision states **the element domain, duplicate criterion, required order, query types, mutability, and operation pattern**. From those requirements, choose `HashSet`, `LinkedHashSet`, `TreeSet`, or `EnumSet`, and verify the key guarantees with appropriate examples.
