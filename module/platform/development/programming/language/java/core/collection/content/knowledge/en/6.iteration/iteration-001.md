# Index-based Loops, Enhanced for, and Iterable

**Element traversal** (or iteration) is the process of retrieving elements one by one from a data source for processing. In Java, two familiar approaches are the index-based loop and the for-each loop, also known as the **enhanced for** loop.

They differ by more than just syntax:

- An index-based loop relies on the ability to access a specific position.
- An enhanced for loop expresses processing each element without requiring the author to manage positions manually.
- `Iterable<T>` is the contract that allows an object to provide a way to traverse its elements.

Understanding this relationship helps you choose the right traversal method, avoid inefficient access patterns, and avoid confusing reassigning a loop variable with modifying data inside a collection.

This lesson uses Java 17. Three complete programs have been compiled with `--release 17` and executed to verify stdout. The remaining short snippets only illustrate a single operation or part of a method, not standalone runnable files.

After this lesson, you should be able to:

- Write loops with proper bounds for arrays or lists.
- Explain which data sources can be used with the enhanced for loop.
- Describe the distinct roles of `Iterable` and `Iterator`.
- Choose a traversal approach based on the need for indices, element replacement, and the underlying data structure.
- Build a small custom `Iterable` with independent traversal passes.

## 1. Start from the Requirement, Not from the Syntax

Suppose we have the following processing steps:

```text
read
write
run
```

Different requirements lead to different ways of writing the traversal:

| Requirement | Information Needed |
| --- | --- |
| Print the name of each step | Only the element is needed |
| Print the position and name of each step | Both the index and the element are needed |
| Replace the second element | A position-based operation is needed |
| Traverse a set that has no indices | A mechanism to fetch the next element is needed |
| Traverse a sequence of numbers generated by the program | A source capable of supplying elements sequentially is needed |

Not all data has positions accessible via `get(index)`. If only the elements are needed, forcing the data source to provide an index can create unnecessary dependencies.

## 2. Index-based Loops

### With Arrays

An illustrative snippet inside a method:

```java
String[] steps = {"read", "write", "run"};

for (int index = 0; index < steps.length; index++) {
    String step = steps[index];
    System.out.println(index + " -> " + step);
}
```

The three parts of the loop:

1. `int index = 0`: start at the first position.
2. `index < steps.length`: only use valid positions.
3. `index++`: advance to the next position after each iteration.

An array of length `n` uses indices from `0` to `n - 1`. If the condition were `index <= steps.length`, the loop would attempt to access position `n`, which is outside the array.

An empty array has `length == 0`; the condition is false from the very beginning, so the loop body does not execute.

### With List

```java
List<String> steps = new ArrayList<>(List.of("read", "write", "run"));

for (int index = 0; index < steps.size(); index++) {
    String step = steps.get(index);
    System.out.println(index + " -> " + step);
}
```

This snippet requires importing `List` and `ArrayList` from `java.util`.

Key distinctions:

- Arrays use the `length` field and `array[index]` syntax.
- Lists use the `size()` and `get(index)` methods.
- The `List` interface provides index-based access operations.
- The general `Collection` interface does not declare `get(index)`; a `Set` is not an indexed list.

### When the Index Has Pedagogical or Business Value

An index-based loop is appropriate when you need to:

- Print the position of an element.
- Access neighboring positions, after checking bounds.
- Assign to an array slot or replace a list element.
- Traverse a subrange, traverse in reverse, or step across multiple positions.
- Coordinate multiple sources by the same index when they genuinely share a positional relationship.

Example of traversing a list in reverse:

```java
for (int index = steps.size() - 1; index >= 0; index--) {
    System.out.println(steps.get(index));
}
```

When the list is empty, the starting value is `-1`, and the condition is false immediately. No `get(-1)` access occurs in this snippet.

Controlling the index gives you flexibility, but it also makes the author responsible for bounds, step increments, and any positional shifts during traversal.

## 3. Enhanced for: Expressing the Intent to Process Each Element

Syntax:

```java
for (String step : steps) {
    System.out.println(step);
}
```

Read this as: for each element taken from `steps`, assign that value to the variable `step` for the current iteration and then execute the loop body.

This syntax works with:

1. Arrays, including primitive arrays such as `int[]`.
2. Objects whose type is compatible with `Iterable`.

It does not provide a built-in index variable. If you genuinely need an index for positional access, consider an index-based loop. If you only want a sequence number for display, you can count iterations, but that counter does not grant index-based access capabilities to the underlying source.

### Guarantees to Read Accurately

The enhanced for loop:

- Retrieves elements according to the source's traversal mechanism.
- Does not sort automatically.
- Does not deduplicate automatically.
- Does not automatically create an independent copy of the entire dataset.
- Does not automatically make operations thread-safe under concurrent use.
- Does not automatically turn an arbitrary object into an iterable source.

Lists are typically traversed in list order. For a set, the order depends on the specific contract of that set; the for-each syntax adds no new ordering guarantees.

### Break and Continue

Standard control statements can still be used:

- `break`: exits the loop according to the statement's scope.
- `continue`: skips the remainder of the current iteration and moves to the next iteration.

Example of stopping when the target step is encountered:

```java
for (String step : steps) {
    if (step.equals("write")) {
        break;
    }
    System.out.println(step);
}
```

This illustrative snippet assumes `step` is not `null`. The stopping condition is a decision made by the loop body, not a removal of the element from the source.

## 4. Direct Comparison of the Two Traversal Styles

Create the file **`TraversalStylesDemo.java`**:

```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

public class TraversalStylesDemo {
    public static void main(String[] args) {
        List<String> steps = new ArrayList<>(List.of("read", "write", "run"));

        System.out.println("indexed:");
        for (int index = 0; index < steps.size(); index++) {
            System.out.println(index + " -> " + steps.get(index));
        }

        System.out.println("enhanced:");
        for (String step : steps) {
            System.out.println(step);
        }

        int[] numbers = {2, 4, 6};

        for (int number : numbers) {
            number *= 10;
        }
        System.out.println("after local assignment = " + Arrays.toString(numbers));

        for (int index = 0; index < numbers.length; index++) {
            numbers[index] *= 10;
        }
        System.out.println("after indexed assignment = " + Arrays.toString(numbers));

        for (int index = steps.size() - 1; index >= 0; index--) {
            System.out.println("reverse " + index + " -> " + steps.get(index));
        }
    }
}
```

Compile and run:

```text
javac -encoding UTF-8 --release 17 TraversalStylesDemo.java
java -Dfile.encoding=UTF-8 TraversalStylesDemo
```

Stdout:

```text
indexed:
0 -> read
1 -> write
2 -> run
enhanced:
read
write
run
after local assignment = [2, 4, 6]
after indexed assignment = [20, 40, 60]
reverse 2 -> run
reverse 1 -> write
reverse 0 -> read
```

### Reading the Program

- The index-based loop prints both the position and the step name.
- The enhanced for loop retrieves each string without writing `get(index)`.
- The loop over the number array uses the variable `number`, which receives the **value** of the element on each iteration.
- Assigning `number *= 10` only modifies the local variable, so the array remains `[2, 4, 6]`.
- Assigning `numbers[index] *= 10` updates the exact slot in the array, so the result is `[20, 40, 60]`.
- The final loop traverses the list in reverse using an index.

Both approaches express traversal, but they do not provide the same access to the positions of the source.

## 5. The Loop Variable Is Not a Slot in the Collection

This point is especially easy to misunderstand when the elements are objects.

### With Primitive Values

In:

```java
for (int number : numbers) {
    number = 100;
}
```

`number` is a local variable. It is not an alias that can be assigned to in place of `numbers[index]`.

### With Objects

In:

```java
for (Counter counter : counters) {
    counter.value += 10;
}
```

the variable `counter` receives a copy of the **reference** to the object. That reference still points to the exact same object held by the collection, so mutating the object's state can be observed through the collection.

However:

```java
for (Counter counter : counters) {
    counter = new Counter(99);
}
```

only changes the reference held by the local variable. The element in the list is not replaced with the new object.

You must distinguish three actions:

| Action | Does it replace the element stored at the list position? |
| --- | --- |
| Reassigning the local variable in a for-each loop | No |
| Mutating the state of the referenced object | Keeps the reference unchanged, though the object itself may change |
| Calling `list.set(index, other)` on a list that supports replacement | Yes |

### Complete Program

Create the file **`ElementReferenceDemo.java`**:

```java
import java.util.ArrayList;
import java.util.List;

public class ElementReferenceDemo {
    private static final class Counter {
        private int value;

        private Counter(int value) {
            this.value = value;
        }

        @Override
        public String toString() {
            return Integer.toString(value);
        }
    }

    public static void main(String[] args) {
        List<Counter> counters = new ArrayList<>(
                List.of(new Counter(1), new Counter(2)));

        for (Counter counter : counters) {
            counter.value += 10;
        }
        System.out.println("after object mutation = " + counters);

        for (Counter counter : counters) {
            counter = new Counter(99);
        }
        System.out.println("after local reassignment = " + counters);

        for (int index = 0; index < counters.size(); index++) {
            counters.set(index, new Counter(20 + index));
        }
        System.out.println("after list replacement = " + counters);
    }
}
```

Compile and run:

```text
javac -encoding UTF-8 --release 17 ElementReferenceDemo.java
java -Dfile.encoding=UTF-8 ElementReferenceDemo
```

Stdout:

```text
after object mutation = [11, 12]
after local reassignment = [11, 12]
after list replacement = [20, 21]
```

The results show:

1. Modifying the field of the two objects changes the data to `[11, 12]`.
2. Reassigning `counter` to a new object does not change the list.
3. Calling `set` by index actually replaces the list elements with two new objects.

For immutable types like `String`, there is no operation that directly mutates the contents of a string object. For example, receiving a new string from a method and simply assigning it to the for-each variable will not update the list of strings either.

## 6. Iterable and Iterator Hold Two Different Roles

### Iterable<T>: A Source Capable of Providing a Traversal Pass

The core signature, in simplified form:

```java
public interface Iterable<T> {
    Iterator<T> iterator();
}
```

This is a signature excerpt to explain the contract, not an interface you need to redefine yourself.

`iterator()` returns an object capable of supplying elements one after another. The source does not need to reveal whether it stores elements in an array, a linked list, or generates values on demand.

`Iterable` does not require having:

- `size()`.
- `get(index)`.
- `add` or `remove`.
- All data preloaded in memory.
- A finite number of elements.
- A fixed snapshot for every traversal pass.

### Iterator<T>: The State of a Single Traversal Pass

Two essential operations:

| Operation | Meaning |
| --- | --- |
| `hasNext()` | Indicates whether there are more elements to retrieve |
| `next()` | Returns the next element and advances the traversal state |

When no elements remain, `next()` must throw `NoSuchElementException`. `null` is not used as a general end-of-traversal signal because a source may legitimately contain `null` elements.

`hasNext()` is not responsible for advancing to the next element. If you omit `next()` in a manual loop, the program may fail to make progress.

An `Iterator` is typically used as the cursor for a single advancing traversal pass. The `Iterator` type itself is not an `Iterable` by default; you cannot assume that having an iterator lets you place it directly on the right-hand side of `:` in an enhanced for loop.

### Relationship with Collection

```text
Collection<E> extends Iterable<E>

Iterable<E> source
    -> iterator()
    -> an Iterator<E> holding the traversal position
    -> next() supplies each element
```

`List`, `Set`, and many other collection types can therefore be used with the enhanced for loop through this inherited contract.

Avoid confusing "the source" with "where the cursor currently is within the source". Two variables pointing to the same iterator instance will share the traversal state of that exact iterator.

## 7. How Does Enhanced for Work?

### On an Iterable

The loop:

```java
for (String step : steps) {
    System.out.println(step);
}
```

can be understood as closely equivalent to the explicit operation:

```java
Iterator<String> cursor = steps.iterator();

while (cursor.hasNext()) {
    String step = cursor.next();
    System.out.println(step);
}
```

This shortened snippet requires `import java.util.Iterator;` and a `steps` source of a compatible type. It illustrates the conceptual traversal mechanism without attempting to list every compiler type-conversion detail.

Important points:

- One iterator is obtained for this execution of the loop.
- `hasNext()` determines whether to continue.
- `next()` provides the element on each iteration.
- The variable `step` belongs to the loop body; it is not a slot that writes back into the source.
- A subsequent for-each loop will request a new iterator via another call to `iterator()`.

### On an Array

Arrays work with the enhanced for loop thanks to a dedicated rule in the Java language; arrays **do not implement `Iterable`**.

Conceptually, the compiler holds a reference to the array being traversed and steps through its indices. It does not need to create a Java Collections Framework `Iterator` for the array.

Consequences:

- `int[]` can be used in `for (int value : array)`.
- You still cannot pass an `int[]` to a method that expects `Iterable<Integer>`.
- Reassigning the original array variable elsewhere does not cause an already-started for-each loop to switch to a different array.
- Do not assume a deep snapshot exists: values at unread positions still belong to the array currently being traversed.

The two kinds of sources share the same syntax, but they do not use the same underlying mechanism.

## 8. Defining a Simple Custom Iterable

Let us create an integer range:

```text
[startInclusive, endExclusive)
```

For example, `[3, 6)` yields `3`, `4`, `5`. The range does not need to pre-allocate a collection holding three numbers; it can generate each value from the cursor state.

This design requires:

1. The source holds two immutable bounds.
2. Each call to `iterator()` creates a new iterator.
3. Each iterator has its own `current` field.
4. `hasNext()` checks the upper bound.
5. `next()` rejects calls when exhausted; otherwise, it returns the current value and advances the cursor.

### Complete Program

Create the file **`IterableRangeDemo.java`**:

```java
import java.util.Iterator;
import java.util.List;
import java.util.NoSuchElementException;
import java.util.StringJoiner;

public class IterableRangeDemo {
    public record IntRange(int startInclusive, int endExclusive)
            implements Iterable<Integer> {
        public IntRange {
            if (endExclusive < startInclusive) {
                throw new IllegalArgumentException("Invalid range");
            }
        }

        @Override
        public Iterator<Integer> iterator() {
            return new Iterator<>() {
                private int current = startInclusive;

                @Override
                public boolean hasNext() {
                    return current < endExclusive;
                }

                @Override
                public Integer next() {
                    if (!hasNext()) {
                        throw new NoSuchElementException();
                    }
                    return current++;
                }
            };
        }
    }

    public static void main(String[] args) {
        IntRange range = new IntRange(3, 6);

        System.out.println("range pass 1 = " + join(range));
        System.out.println("range pass 2 = " + join(range));
        System.out.println("list = " + join(List.of(8, 9)));

        Iterator<Integer> first = range.iterator();
        Iterator<Integer> second = range.iterator();

        System.out.println("first iterator = " + first.next() + ", " + first.next());
        System.out.println("second iterator = " + second.next());

        Iterator<Integer> empty = new IntRange(5, 5).iterator();
        System.out.println("empty hasNext = " + empty.hasNext());

        try {
            empty.next();
        } catch (NoSuchElementException exception) {
            System.out.println("empty next = "
                    + exception.getClass().getSimpleName());
        }
    }

    private static String join(Iterable<Integer> source) {
        StringJoiner result = new StringJoiner(", ", "[", "]");
        for (int number : source) {
            result.add(Integer.toString(number));
        }
        return result.toString();
    }
}
```

Compile and run:

```text
javac -encoding UTF-8 --release 17 IterableRangeDemo.java
java -Dfile.encoding=UTF-8 IterableRangeDemo
```

Stdout:

```text
range pass 1 = [3, 4, 5]
range pass 2 = [3, 4, 5]
list = [8, 9]
first iterator = 3, 4
second iterator = 3
empty hasNext = false
empty next = NoSuchElementException
```

### Why Does This Example Fulfill the Roles Properly?

- `IntRange` implements `Iterable<Integer>` without being a `Collection`.
- The range does not expose add/remove operations or index-based access.
- The constructor rejects an upper bound smaller than the lower bound.
- A range with equal bounds is empty.
- `iterator()` creates a fresh iterator object, so both `join(range)` passes start at `3`.
- Two explicit iterators also maintain independent state: the first iterator has already consumed `3` and `4`, while the second iterator still starts at `3`.
- Calling `next()` on an empty range properly throws `NoSuchElementException`.
- The `join` method only requires `Iterable<Integer>`, so it works with both our custom range and a `List<Integer>`.

Because the upper bound is exclusive, the last returned element is strictly less than `endExclusive`. Within valid `int` ranges in this design, incrementing after the last element never overflows `Integer.MAX_VALUE`.

This example does not support removing elements via the iterator. The source is a range of values defined by bounds, not a mutable collection from which elements can be removed.

### Do Not Generalize Repeatability to Every Iterable

In `IntRange`, iterators are independent and repeatable because we designed it that way. Seeing the `Iterable` type alone is not enough to conclude that every source:

- Can be traversed repeatedly any number of times with identical data.
- Reads data at zero cost.
- Produces independent iterators under all conditions.
- Has no dependency on external resources or the timing of reads.

When designing an API, document these conditions clearly. Furthermore, if a source holds resources that must be closed, `Iterable` alone carries no contract to automatically close resources on behalf of the caller.

## 9. Choosing a Traversal Approach by Structure and Requirement

| Requirement | Recommended Direction |
| --- | --- |
| Read all elements sequentially | Enhanced for usually expresses the intent clearly |
| Modify an array position | Index-based loop |
| Replace an element in a `List` | Index with `set`, or an appropriate list mechanism |
| Traverse a source that only implements `Iterable` | Enhanced for or an explicit iterator |
| Control the cursor manually, such as removing via a supported iterator | Explicit iterator |
| Traverse a source in reverse | A reverse mechanism supported by the source; do not assume every source has indices |
| Display a sequence number | Count iterations; do not treat the counter as an access index into the source |

### The Efficiency of get(index) Depends on the Implementation Class

With `ArrayList`, accessing an index has a cost that does not grow with the number of elements under normal usage models. Sequential traversal via `get(index)` is a reasonable choice when an index is needed.

With `LinkedList`, retrieving an element by index requires walking the linked chain to reach that position. If you repeatedly call `get(0)`, `get(1)`, ..., `get(n - 1)`, the total work can grow quadratically with the number of elements.

Traversing a `LinkedList` sequentially through its iterator avoids restarting from the head or tail for each index and achieves linear cost for the entire pass.

Therefore, if a method accepts an arbitrary `List` and only needs to read elements sequentially, an enhanced for loop generally avoids unnecessary assumptions about random-access performance.

Do not conclude that every enhanced for loop is always faster than every index-based loop. Data types, the work inside the loop body, and runtime optimizations all play a role. First and foremost, choose the approach that matches the contract and avoids access patterns with unsuitable costs.

### Caching size Before the Loop Is Not a Cure-All

Writing `int count = list.size()` before a loop only means you are using a saved bound. It does not turn `get(index)` on a linked list into fast random access.

If the list changes size during traversal, the saved bound may also become out of sync with the current size. Only use this pattern when the data conditions and intent are clear.

## 10. Sources That Cannot Be Used Directly with Enhanced for

### Map Does Not Implement Iterable

You cannot directly traverse a `Map` with:

```text
for (entry : map)
```

based on guesswork. Instead, `Map` provides views:

| View | Content |
| --- | --- |
| `keySet()` | The keys |
| `values()` | The values |
| `entrySet()` | The key–value pairs |

If you need both keys and values, an illustrative pattern is:

```java
for (Map.Entry<String, Integer> entry : counts.entrySet()) {
    System.out.println(entry.getKey() + " = " + entry.getValue());
}
```

This snippet requires `import java.util.Map;` and a `counts` variable of an appropriate map type. The traversal order still depends on the contract of the map implementation and its view, not on the enhanced for loop.

### String Is Not an Iterable<Character>

A `String` object cannot be placed directly into an enhanced for loop under the assumption that it will supply characters one by one.

You can choose a traversal method suited to characters, code units, or code points, depending on your exact requirement. Do not assume that a visible character always corresponds to a single `char`.

### Iterator Is Not Automatically an Iterable Source

If you already hold an iterator, drive it using `hasNext()` and `next()`, or whichever dedicated mechanism that API provides.

`Iterable` is responsible for supplying a way to traverse; a specific iterator is the advancing state of a pass. The two roles cannot be swapped simply by renaming a variable.

## 11. Null, Element Types, and Changing Data

### A null Source Differs from an Empty Source

- Empty source: zero element-processing iterations occur.
- `null` source: there is no array or `Iterable` object to traverse; an enhanced for loop will throw `NullPointerException`.

Be consistent in your APIs about whether to return an empty source or allow `null`. Do not treat the two states as interchangeable.

### A null Element Can Cause Errors Inside the Loop Body

When a source can contain `null`, the enhanced for loop can still receive that element. An error may arise when calling a method on the loop variable or during unboxing.

Illustrative example:

```java
for (int number : values) {
    System.out.println(number);
}
```

If `values` is an `Iterable<Integer>` containing `null`, converting `Integer` to `int` on that iteration requires unboxing and throws `NullPointerException`.

The enhanced for loop does not automatically validate or skip missing data.

### Adding or Removing During Traversal Requires a Supported Mechanism

Do not directly add or remove elements structurally on a collection inside a for-each loop and expect the cursor to always update itself cleanly.

Some iterators employ modification-detection mechanisms and may throw `ConcurrentModificationException`, even in a single-threaded program. This is not a guarantee that every invalid modification will be detected.

Approaches depending on your goal:

- Remove via an explicit iterator when the source supports that operation.
- Use `removeIf` on a collection that supports removal.
- Collect changes and apply them after the traversal pass completes.
- Choose a collection type whose traversal contract matches your concurrency requirements.

Do not simply switch to an index-based loop to "dodge the exception". Removing an element shifts the indices of subsequent elements; if you increment the index as usual, you may skip elements or access out-of-bounds positions.

Mutating the internal state of an element object, replacing an element in a list, and structurally adding or removing elements are distinct kinds of changes. How you handle them must rely on the source's contract and your specific goal.

## 12. Enhanced for Differs from the forEach Method

The syntax:

```java
for (String step : steps) {
    System.out.println(step);
}
```

is different from the method call:

```java
steps.forEach(step -> System.out.println(step));
```

The second pattern passes a function to an API; it does not turn the lambda body into an enhanced for loop body.

| Characteristic | Enhanced for | `forEach` Accepting a Consumer Function |
| --- | --- | --- |
| Form | Language control structure | Method invocation |
| Stopping via loop `break` | Yes | No enclosing loop to `break` out of inside the lambda |
| Skipping the rest of an iteration via `continue` | Yes | Cannot use `continue` as a loop-body statement |
| Built-in index provided | No | Also does not automatically provide an index |
| Execution context mental model | The loop body being written directly | A handler function invoked by the API |

There is no need to switch to a lambda just to make the code look shorter. Choose the form that clearly expresses the control flow you need, especially when early exit or multi-branch logic is involved.

## 13. Common Mistakes

### Using <= Instead of < with length or size

The last valid index is the element count minus one. Check the condition before accessing, including when the group is empty.

### Reassigning the for-each Variable to Replace an Element

Assigning `element = other` only modifies the local variable. For arrays or lists that require element replacement, use a supported positional assignment mechanism.

### Assuming an Unmodifiable Collection Makes Its Contained Objects Immutable

Preventing additions, removals, or positional replacements does not mean mutable objects inside the collection cannot have their internal state modified. Distinguish the collection's contract from the element's contract.

### Calling get(index) on Every Collection Type

`Collection` does not define that operation. Only require `List` when you genuinely need list capabilities; if you only read sequentially, `Iterable` may already be sufficient.

### Sharing a Single Iterator Instance Across All Calls to iterator()

If a source intends to provide independent traversal passes but always returns the exact same advancing iterator, subsequent passes may start mid-way or find the iterator already exhausted. Nested loops over the same source can also interfere with each other's state.

Design and document your iterator policy intentionally. For instance, `IntRange` creates a new iterator on each call to support repeated traversal.

### Returning null When an Iterator Is Exhausted

`null` can be a valid element. When exhausted, `hasNext()` must reflect that state and `next()` must throw `NoSuchElementException`.

### Calling hasNext Without Consuming the Element

`hasNext()` is not an advancing operation. In a manual iterator loop, every execution path that intends to move forward must appropriately call `next()`.

### Assuming for-each Is a Safe Snapshot by Default

The enhanced for loop does not copy data automatically. Ordering, consistency under modification, and multi-threaded safety must all be determined from the underlying source.
