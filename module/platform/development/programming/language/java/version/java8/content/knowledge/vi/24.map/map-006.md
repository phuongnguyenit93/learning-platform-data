# Map.computeIfPresent và cập nhật giá trị đang tồn tại

**Chủ đề:** Java 8 → Map → computeIfPresent và cập nhật giá trị đang tồn tại.

Khi làm việc với **Map<K, V>**, một nghiệp vụ phổ biến là **chỉ cập nhật một giá trị nếu khóa đã có giá trị hợp lệ**, chẳng hạn tăng số lượt sử dụng, chỉnh trạng thái tồn kho, giảm hạn mức hoặc thay một đối tượng đang lưu trong bảng tra cứu. Java cung cấp **Map.computeIfPresent(...)** để mô tả điều kiện và phép cập nhật trong cùng một lời gọi.

Điểm then chốt: **"present" trong tên phương thức không đơn giản đồng nghĩa với containsKey(key) == true**. Phương thức chỉ áp dụng hàm cập nhật khi **map.get(key) khác null**. Nếu khóa vắng mặt hoặc đang ánh xạ tới giá trị **null**, hàm cập nhật **không được gọi**. Khi hàm cập nhật trả **null**, mục nhập sẽ bị **xóa**, không phải được lưu với giá trị null.

**Map.computeIfPresent** được giới thiệu trong Java 8 và vẫn được hỗ trợ trong Java hiện đại. Ví dụ hoàn chỉnh dưới đây dùng **Java 17+** để có thể dùng **record** và **List.of** cho dữ liệu đơn giản; chính phương thức Map này không yêu cầu các cú pháp mới.

## 1. Mục tiêu bài học

Sau bài học, bạn có thể:

1. Hiểu chữ ký **computeIfPresent(K, BiFunction<K,V,V>)** và đọc được vai trò của khóa, giá trị hiện tại, giá trị thay thế.
2. Phân biệt ba trạng thái: **khóa không có**, **khóa có nhưng value là null**, **khóa có value khác null**.
3. Biết khi nào hàm remapping được gọi, khi nào Map cập nhật giá trị, khi nào xóa mục nhập và ý nghĩa giá trị trả về.
4. Dùng **lambda** hoặc **method reference** cho các thao tác cập nhật an toàn, dễ kiểm thử.
5. So sánh **computeIfPresent**, **computeIfAbsent**, **compute**, **merge**, **replace**, **putIfAbsent** và **replaceAll**.
6. Tránh các lỗi về **null**, thao tác sửa Map ngay trong callback, thay đổi đối tượng mutable, **overflow**, Map unmodifiable và xử lý đồng thời.
7. Biết khi nào có thể dùng **ConcurrentHashMap.computeIfPresent(...)** để cập nhật nguyên tử theo khóa và vì sao **HashMap** không có bảo đảm tương đương.

## 2. Chữ ký và ý nghĩa

Phương thức trên **java.util.Map<K,V>**:

~~~java
default V computeIfPresent(
        K key,
        BiFunction<? super K, ? super V, ? extends V> remappingFunction)
~~~

Đây là **chữ ký API minh họa**, không phải phương thức cần tự định nghĩa lại trong chương trình.

- **key (K):** khóa mà bạn muốn cập nhật.
- **remappingFunction:** hàm nhận **khóa** và **giá trị hiện tại**, rồi tạo ra **giá trị mới**.
- **Giá trị trả về (V):** giá trị mới gắn với khóa sau cập nhật, hoặc **null** nếu không còn giá trị được ánh xạ.
- **BiFunction<K,V,V>:** về mặt ý tưởng nhận **hai đối số** (key và oldValue) rồi trả **một newValue**. Chữ ký có wildcard generic để linh hoạt kiểu tham số và kiểu kết quả.
- **Optional operation:** một số Map không cho sửa dữ liệu; lời gọi có thể ném **UnsupportedOperationException**.

Cú pháp sử dụng:

~~~java
V newValue = map.computeIfPresent(
        key,
        (k, oldValue) -> /* tính giá trị thay thế */
);
~~~

Đây là **mẫu minh họa**, không biên dịch độc lập vì **V**, **map**, **key** và phần expression chưa được xác định.

Ví dụ có thể áp dụng ngay:

~~~java
Map<String, Integer> counts = new HashMap<>();
counts.put("java", 4);

Integer updated = counts.computeIfPresent(
        "java",
        (key, current) -> current + 1
);

// updated == 5
// counts.get("java") == 5
~~~

Với đoạn này, Java đọc giá trị hiện tại tại khóa **"java"** (là 4), gọi lambda để tạo 5, rồi gắn 5 vào khóa ấy. Không có thao tác thêm khóa mới vì khóa đã mang một giá trị khác null.

## 3. Bảng quy tắc chính xác

Giả sử Map **hỗ trợ cập nhật**, việc tra cứu diễn ra không có thay đổi đồng thời và callback không tự sửa Map:

| Trạng thái trước khi gọi | Có gọi remappingFunction? | Nếu callback trả giá trị mới khác null | Nếu callback trả null |
|---|---|---|---|
| Khóa **không có** | **Không** | Không áp dụng; callback không chạy | Không áp dụng; Map giữ nguyên |
| Khóa **có**, value **null** | **Không** | Không áp dụng; callback không chạy | Không áp dụng; ánh xạ null được giữ nguyên |
| Khóa **có**, value **khác null** | **Có** | Thay value bằng kết quả mới | **Xóa mapping của khóa** |

**Giá trị trả về:**

- Callback chạy và trả **newValue != null** → **computeIfPresent** trả **newValue**.
- Callback chạy và trả **null** → mục nhập bị xóa; phương thức trả **null**.
- Callback không chạy do **get(key) == null** → phương thức trả **null**.
- Callback ném **unchecked exception** → exception được chuyển ra ngoài; giá trị đang gắn với khóa được để nguyên theo hợp đồng Map (không tự hoàn tác tác dụng phụ đã xảy ra trong đối tượng mutable hoặc ngoài Map).

**Một số ngộ nhận cần tránh:**

1. **Giá trị 0 không phải null.** Nếu số đếm là 0, callback **vẫn chạy**.
2. **Map chứa key ánh xạ null không giống Map thiếu key**, dù **get(key)** trả null ở cả hai trường hợp.
3. **Callback trả null không có nghĩa giữ giá trị cũ**. Nó ra lệnh **xóa mapping** khi đã có value khác null.
4. **Callback không được gọi** với **oldValue == null** theo hợp đồng computeIfPresent; nếu muốn tính cho trường hợp null/không có, cần API khác.

### 3.1. Mô hình tương đương của default implementation

Ở mức ý niệm, cài đặt mặc định của Map tương đương:

~~~java
V oldValue = map.get(key);

if (oldValue != null) {
    V newValue = remappingFunction.apply(key, oldValue);

    if (newValue != null) {
        map.put(key, newValue);
    } else {
        map.remove(key);
    }
}
~~~

Đây là **mã giả** dùng V/map/key từ ngữ cảnh. Tài liệu API mô tả default implementation tương đương các bước **get → tính → put/remove**.

**Không suy ra từ mã giả rằng toàn bộ thao tác được khóa/atomic**. **Map** mặc định không cam kết đồng bộ hóa hoặc atomicity. Những triển khai như **ConcurrentHashMap** có thể override để cung cấp ngữ nghĩa concurrency mạnh hơn. Cũng không được dựa vào số lần gọi **get(...)** hoặc callback của mọi implementation là giống nhau: phải dựa vào hợp đồng từng lớp.

## 4. Ví dụ hoàn chỉnh: cập nhật, bỏ qua và xóa

Lưu thành **ComputeIfPresentDemo.java**:

~~~java
import java.util.LinkedHashMap;
import java.util.Map;

public class ComputeIfPresentDemo {
    public static void main(String[] args) {
        Map<String, Integer> counts = new LinkedHashMap<>();
        counts.put("java", 3);
        counts.put("python", 5);
        counts.put("empty", null);

        Integer updated = counts.computeIfPresent(
                "java",
                (key, current) -> current + 2
        );

        Integer missing = counts.computeIfPresent(
                "missing",
                (key, current) -> 100
        );

        Integer nullMapped = counts.computeIfPresent(
                "empty",
                (key, current) -> 99
        );

        System.out.println("updated=" + updated);
        System.out.println("missing=" + missing);
        System.out.println("nullMapped=" + nullMapped);
        System.out.println("counts=" + counts);
        System.out.println("emptyKeyPresent="
                + counts.containsKey("empty"));

        Integer removed = counts.computeIfPresent(
                "python",
                (key, current) -> null
        );

        System.out.println("removed=" + removed);
        System.out.println("hasPython="
                + counts.containsKey("python"));
        System.out.println("afterRemoval=" + counts);
    }
}
~~~

~~~bash
javac -encoding UTF-8 ComputeIfPresentDemo.java
java ComputeIfPresentDemo
~~~

**Stdout:**

~~~text
updated=5
missing=null
nullMapped=null
counts={java=5, python=5, empty=null}
emptyKeyPresent=true
removed=null
hasPython=false
afterRemoval={java=5, empty=null}
~~~

**Giải thích:**

- **"java"** có value 3 → callback được gọi với **("java", 3)** → kết quả 5 được lưu lại.
- **"missing"** không có trong Map → callback không chạy → phương thức trả null, không có key mới.
- **"empty"** đã được đặt bằng null → callback **không chạy**, mặc dù **containsKey("empty")==true**. Mapping **empty=null** còn nguyên.
- **"python"** có value 5 → callback chạy, trả null → mapping bị **xóa**.
- **LinkedHashMap** dùng trong ví dụ để thứ tự khi in được dự đoán: thứ tự chèn ban đầu là java, python, empty; cập nhật value không tự di chuyển key của một insertion-order LinkedHashMap. Không dùng output của HashMap để suy ra thứ tự key ổn định.

**Không viết println trực tiếp trong callback nếu cần test số lần gọi**. Đây là ví dụ an toàn với lambda tính toán thuần. Đối với ConcurrentMap khác nhau, số lần callback có thể phụ thuộc hợp đồng concurrency riêng.

## 5. Phân biệt khóa vắng mặt và khóa có value null

Có hai cách tra cứu khác nhau:

~~~java
boolean exists = map.containsKey(key);
V value = map.get(key);
~~~

- **containsKey(key)** hỏi Map có mapping cho key hay không.
- **get(key)** hỏi giá trị đang được ánh xạ; có thể trả **null** khi vắng key **hoặc** khi Map cho phép lưu null và key đang ánh xạ null.

Với **HashMap**, **LinkedHashMap** (cho phép null value), **computeIfPresent** không gọi callback ở cả hai trường hợp **get(key)==null**. Nếu nghiệp vụ muốn **khôi phục giá trị cho key đang ánh xạ null**, dùng **computeIfAbsent** hoặc **compute** tùy yêu cầu; đừng dùng computeIfPresent.

### 5.1. Ví dụ điều kiện callback chạy

~~~java
Map<String, Integer> map = new HashMap<>();
map.put("zero", 0);
map.put("empty", null);

Integer a = map.computeIfPresent("zero", (k, v) -> v + 1);
Integer b = map.computeIfPresent("empty", (k, v) -> 100);
Integer c = map.computeIfPresent("absent", (k, v) -> 100);

// a == 1
// b == null và map.containsKey("empty") == true
// c == null và map.containsKey("absent") == false
~~~

Đây là **đoạn minh họa**; cần import **Map** và **HashMap**. Nó cho thấy **0 là một giá trị hợp lệ khác null**, không phải "không tồn tại".

### 5.2. Nếu muốn luôn tính giá trị mới, kể cả khi vắng key

~~~java
map.compute("item", (key, oldValue) ->
        oldValue == null ? 1 : oldValue + 1);
~~~

**Map.compute(...)** có thể gọi callback với **oldValue == null** khi key không có hoặc đang ánh xạ null; bạn phải định nghĩa rõ cách tạo giá trị khởi đầu. **computeIfPresent** không phục vụ mục tiêu khởi tạo key mới.

## 6. BiFunction: dùng cả key và oldValue

Callback nhận **hai tham số**:

~~~java
(key, currentValue) -> newValue
~~~

Thông thường chỉ cần currentValue:

~~~java
counts.computeIfPresent(
        "java",
        (key, current) -> current + 1
);
~~~

Nhưng đối số **key** hữu ích nếu quy tắc phụ thuộc vào khóa:

~~~java
Map<String, Integer> limits = new HashMap<>();
limits.put("premium", 15);
limits.put("standard", 10);

limits.computeIfPresent(
        "premium",
        (tier, oldLimit) ->
                tier.equals("premium") ? oldLimit + 5 : oldLimit
);

// limits.get("premium") == 20
~~~

Đoạn trên là ví dụ ngắn; cần import **Map** và **HashMap**.

**Không nên đặt logic nghiệp vụ vào key string mơ hồ khi hệ thống lớn.** Trong ứng dụng thực tế, dùng enum hoặc loại khóa có ý nghĩa để tránh lỗi chính tả và quy định phép cập nhật một cách rõ ràng.

### 6.1. Method reference khi hàm phù hợp

Một **BiFunction<K,V,V>** có thể là một method reference nếu có chữ ký tương thích:

~~~java
static Integer raise(String key, Integer value) {
    return Math.addExact(value, 1);
}
~~~

~~~java
// Đoạn minh họa khi raise(...) là static method cùng scope:
counts.computeIfPresent("java", MyClass::raise);
~~~

Không thể dùng method reference có chữ ký không tương thích một cách tùy ý. Nếu chỉ muốn cộng số, lambda **(k, v) -> v + 1** thường dễ hiểu nhất.

**Cảnh báo phạm vi:** Nếu giá trị là **Integer**, phép cộng **v + 1** có thể tràn int. Khi đó **Math.addExact(v, 1)** phát hiện overflow qua **ArithmeticException**, hoặc chọn **Long/BigInteger** nếu miền số yêu cầu.

## 7. Giá trị trả null: lệnh xóa có chủ ý

Điểm khác biệt quan trọng của **computeIfPresent** là callback không chỉ cập nhật mà còn **có thể xóa**:

~~~java
Map<String, Integer> stock = new HashMap<>();
stock.put("A", 3);

Integer after = stock.computeIfPresent(
        "A",
        (sku, remaining) ->
                remaining > 1 ? remaining - 1 : null
);

// after == 2, stock.get("A") == 2
~~~

Nếu ban đầu còn **1**, cùng phép tính sẽ trả **null** và xóa **"A"** khỏi Map. Đây là quyết định nghiệp vụ: một số hệ thống muốn **giữ khóa với value 0**, số khác muốn **xóa key khi số lượng bằng 0**. Cần thống nhất điều đó trước khi viết callback.

**Không dùng null làm giá trị trả về cho trường hợp "cập nhật không hợp lệ nhưng vẫn muốn giữ nguyên".** Callback trả null theo hợp đồng là xóa mapping. Nếu cần từ chối cập nhật, có thể:

- Ném exception có ý nghĩa khi dữ liệu mới vi phạm điều kiện.
- Hoặc trả về **oldValue** nếu chính sách yêu cầu giữ nguyên.
- Hoặc xác thực điều kiện trước lời gọi, nếu có thể làm an toàn theo mô hình concurrency.

### 7.1. Xóa khi điều kiện hết hiệu lực

~~~java
Map<String, String> sessions = new HashMap<>();
sessions.put("token-1", "ACTIVE");

sessions.computeIfPresent(
        "token-1",
        (token, status) ->
                status.equals("ACTIVE") ? null : status
);

// sessions.containsKey("token-1") == false
~~~

Đây chỉ là **minh họa API**, không phải cơ chế quản lý session bảo mật hoàn chỉnh. Ứng dụng thực tế cần kiểm tra điều kiện hết hạn, xác thực, concurrency, cache và lưu trữ bền vững phù hợp.

## 8. Ví dụ nghiệp vụ: cập nhật hoặc xóa tồn kho bằng record

Giả sử Map lưu đối tượng bất biến mô tả hàng hóa. Một đơn hàng nhập thêm **3 sản phẩm A**, còn sản phẩm **B** cần xóa mapping khi số lượng không đủ cho yêu cầu xuất.

Lưu thành **StockUpdateDemo.java**:

~~~java
import java.util.LinkedHashMap;
import java.util.Map;

public class StockUpdateDemo {
    record Stock(
            String sku,
            long available,
            long unitPriceCents) {}

    public static void main(String[] args) {
        Map<String, Stock> stock = new LinkedHashMap<>();
        stock.put("A", new Stock("A", 5, 1200));
        stock.put("B", new Stock("B", 2, 2500));

        Stock updated = stock.computeIfPresent(
                "A",
                (sku, current) ->
                        new Stock(
                                current.sku(),
                                Math.addExact(current.available(), 3L),
                                current.unitPriceCents()
                        )
        );

        Stock removed = stock.computeIfPresent(
                "B",
                (sku, current) ->
                        current.available() >= 3
                                ? new Stock(
                                    current.sku(),
                                    current.available() - 3,
                                    current.unitPriceCents())
                                : null
        );

        System.out.println("updated=" + updated);
        System.out.println("removed=" + removed);
        System.out.println("stock=" + stock);
    }
}
~~~

~~~bash
javac -encoding UTF-8 StockUpdateDemo.java
java StockUpdateDemo
~~~

**Stdout:**

~~~text
updated=Stock[sku=A, available=8, unitPriceCents=1200]
removed=null
stock={A=Stock[sku=A, available=8, unitPriceCents=1200]}
~~~

**Giải thích:**

1. Với key **"A"**, callback nhận một **Stock** đang có; phép **Math.addExact** tạo số lượng 8 (phát hiện tràn nếu có) và constructor tạo một record mới. Map được cập nhật bằng record mới.
2. Với key **"B"**, số lượng 2 không đủ cho yêu cầu 3; callback trả null → mapping **B bị xóa**.
3. **Record** làm rõ rằng bản cập nhật là **thay giá trị gắn với key**, không trực tiếp sửa nội dung của record cũ.
4. **Đây không phải quy tắc nghiệp vụ tồn kho mặc định.** Thông thường, số lượng không đủ nên **từ chối xuất hàng** thay vì xóa sản phẩm. Ví dụ chỉ cố ý biểu diễn nhánh **null → xóa**, cần thay bằng chính sách thực tế của hệ thống. Nếu muốn giữ B và báo lỗi, hãy ném exception (với giới hạn riêng của Map) hoặc quản lý trạng thái lỗi ngoài callback theo thiết kế của ứng dụng.
5. **computeIfPresent** trên LinkedHashMap trong ví dụ **không tạo thao tác transaction** trên database hay giữa các dịch vụ. Nó cập nhật đối tượng Map trong bộ nhớ.

### 8.1. Cách cập nhật mà không xóa khi không đủ số lượng

~~~java
stock.computeIfPresent("B", (sku, current) -> {
    if (current.available() < 3) {
        throw new IllegalStateException("Insufficient stock");
    }
    return new Stock(
            current.sku(),
            current.available() - 3,
            current.unitPriceCents()
    );
});
~~~

Đây là đoạn minh họa phụ thuộc record **Stock** và biến **stock** ở chương trình trên. Nếu thiếu hàng, exception được ném và mapping đang gắn tại **B** được giữ nguyên theo hợp đồng Map (miễn callback không có side effect thay đổi dữ liệu khác).

## 9. So sánh với các API khác trên Map

Các phương thức có tên gần nhau, nhưng khác nhau ở điều kiện gọi callback và ý nghĩa return **null**.

| Phương thức | Trạng thái đầu vào quyết định điều gì? | Khi nào phù hợp? |
|---|---|---|
| **computeIfPresent(key, remap)** | Chỉ chạy remap khi **get(key) != null** | Cập nhật/xóa giá trị **đã có khác null** |
| **computeIfAbsent(key, mapper)** | Chỉ chạy mapper khi **get(key) == null** | Tạo giá trị khi thiếu hoặc đang map tới null |
| **compute(key, remap)** | Tính lại mapping bất kể trạng thái hiện tại | Tạo/cập nhật/xóa theo cả key và oldValue, kể cả oldValue null |
| **merge(key, value, remap)** | Nếu oldValue null/không có → dùng value mới không-null; nếu có → kết hợp old và value | Tăng/tích lũy theo giá trị bổ sung |
| **replace(key, newValue)** | Điều kiện là **containsKey(key)**, không nhất thiết oldValue khác null | Thay value đã có mapping theo hợp đồng Map |
| **replace(key, old, new)** | Chỉ thay khi key đang map tới **old** theo so sánh phù hợp | Cập nhật có điều kiện kiểu compare-and-set |
| **putIfAbsent(key, value)** | Đặt value khi thiếu hoặc đang map null | Đặt giá trị mặc định nếu chưa có |
| **replaceAll((key, value) -> newValue)** | Áp dụng cho **mọi entry** | Biến đổi hàng loạt các value |
| **put(key, value)** | Ghi đè hoặc tạo mới **không phụ thuộc trạng thái cũ** | Biết rõ giá trị cần ghi |
| **remove(key)** | Xóa mapping theo key | Xóa trực tiếp, không cần callback |

**Chú ý:** tính **atomicity**, hỗ trợ null và khả năng sửa của các phương thức khác nhau phụ thuộc implementation Map. Không suy ra **computeIfPresent** trên HashMap an toàn cho concurrent updates chỉ vì một số phương thức của ConcurrentHashMap có hợp đồng atomic.

### 9.1. computeIfAbsent: bổ sung khi chưa có giá trị

~~~java
Map<String, Integer> visits = new HashMap<>();

visits.computeIfAbsent("java", key -> 1);
// visits.get("java") == 1

visits.computeIfPresent("java", (key, n) -> n + 1);
// visits.get("java") == 2
~~~

Đây là **đoạn minh họa** yêu cầu import **Map**, **HashMap**. Đầu tiên tạo giá trị 1, sau đó chỉ cập nhật khi đã có giá trị.

Nếu yêu cầu chính là **tăng bộ đếm dù chưa có key**, có thể đơn giản hơn bằng **merge**.

### 9.2. merge: cộng giá trị mới hoặc khởi tạo

~~~java
Map<String, Integer> counts = new HashMap<>();

counts.merge("java", 1, Integer::sum); // java=1
counts.merge("java", 1, Integer::sum); // java=2
~~~

**merge(key, 1, Integer::sum)** dùng giá trị bổ sung **1** nếu chưa có key/value; khi đã có, kết hợp oldValue và 1. Khác với **computeIfPresent** (bỏ qua key chưa có).

**merge** có quy tắc khác về **tham số value**: value truyền vào phải **khác null**, và **remappingFunction** nhận **hai value**, không nhận key. Đừng tráo **Integer::sum** của merge với lambda **(key, oldValue)** của computeIfPresent.

### 9.3. compute: muốn luôn tính từ trạng thái hiện tại

~~~java
Map<String, Integer> counts = new HashMap<>();

counts.compute(
        "java",
        (key, oldValue) ->
                oldValue == null ? 1 : oldValue + 1
);
// counts.get("java") == 1
~~~

**compute** có thể gọi remap ngay cả khi giá trị chưa có, vì thế callback phải xử lý **oldValue == null**. Nếu remap trả null, mapping bị xóa hoặc giữ vắng mặt.

### 9.4. replace: trường hợp chỉ cần thay bằng một giá trị đã biết

~~~java
Map<String, String> status = new HashMap<>();
status.put("A", "OLD");

String previous = status.replace("A", "NEW");

// previous == "OLD"; status.get("A").equals("NEW")
~~~

Nếu **newValue** đã biết và không cần đọc oldValue để tính, **replace(key, value)** có thể diễn đạt rõ hơn **computeIfPresent(key, (k, old) -> value)**. Chú ý khác biệt ở ánh xạ null: Map.replace dựa trên **containsKey**, nên các triển khai cho phép null có thể thay mapping null, còn computeIfPresent sẽ bỏ qua.

### 9.5. Map.replaceAll khác computeIfPresent

~~~java
Map<String, Integer> counts = new LinkedHashMap<>();
counts.put("A", 1);
counts.put("B", 2);

counts.replaceAll((key, value) -> value * 10);

// counts == {A=10, B=20}
~~~

**replaceAll** duyệt mọi entry, không yêu cầu bạn chỉ rõ một key, còn **computeIfPresent** nhắm một key cụ thể. **replaceAll** có thể gọi callback với **value null** đối với Map cho phép null; computeIfPresent không làm vậy.

## 10. Khi callback ném exception

Theo hợp đồng **Map.computeIfPresent**: nếu **remappingFunction** ném unchecked exception, exception được truyền ra ngoài, và **mapping hiện tại của key không bị thay thế bởi kết quả tính dở**.

Lưu thành **ComputeIfPresentErrorDemo.java**:

~~~java
import java.util.HashMap;
import java.util.Map;

public class ComputeIfPresentErrorDemo {
    public static void main(String[] args) {
        Map<String, Integer> limits = new HashMap<>();
        limits.put("quota", 7);

        try {
            limits.computeIfPresent("quota", (key, current) -> {
                if (current < 10) {
                    throw new IllegalArgumentException(
                            "Cannot update quota");
                }
                return current + 1;
            });
        } catch (IllegalArgumentException ex) {
            System.out.println("error=" + ex.getMessage());
        }

        System.out.println("unchanged=" + limits.get("quota"));
    }
}
~~~

~~~bash
javac -encoding UTF-8 ComputeIfPresentErrorDemo.java
java ComputeIfPresentErrorDemo
~~~

**Stdout:**

~~~text
error=Cannot update quota
unchanged=7
~~~

**Ranh giới của bảo đảm:** Map không ghi một **replacement value** mới khi callback ném exception. Điều đó **không có nghĩa toàn bộ tác dụng phụ trong callback được rollback**. Nếu callback sửa một object mutable mà oldValue đang trỏ tới, gọi API bên ngoài, thay biến global hoặc chỉnh dữ liệu trong database, những thay đổi đó có thể đã xảy ra trước khi exception xuất hiện.

Do đó, khi cần cập nhật an toàn, thường nên **tạo giá trị mới độc lập** thay vì sửa trực tiếp oldValue mutable. Ví dụ:

~~~java
// Ưu tiên tạo record bất biến thay vì sửa bên trong old object:
map.computeIfPresent(key, (k, old) -> old.withNewValue(...));
~~~

Đây chỉ là **pseudocode**: kiểu old phải có phương thức withNewValue trong ứng dụng thực tế; không có phương thức Java chung tên như vậy.

## 11. Không sửa chính Map từ bên trong remappingFunction

Theo tài liệu **Map**, remappingFunction **không nên sửa chính Map đó trong khi tính**. Ví dụ sau là sai:

~~~java
// SAI: can thiệp cấu trúc Map đang được compute.
counts.computeIfPresent("A", (key, value) -> {
    counts.put("B", 100);
    return value + 1;
});
~~~

Đây là **đoạn minh họa lỗi**, biến counts được giả sử có sẵn.

Lý do:

- Trên một số Map không đồng thời, sự thay đổi cấu trúc trong callback có thể bị phát hiện và ném **ConcurrentModificationException**.
- Trên các ConcurrentMap, việc đệ quy hoặc cập nhật Map trong callback có thể dẫn đến **IllegalStateException**, khóa chéo hoặc các trường hợp ngoài hợp đồng.
- Không được dựa vào việc một lần chạy tình cờ thành công để cho rằng thao tác nested put/remove trong callback là hợp lệ.
- Nếu cần cập nhật **hai key** phụ thuộc lẫn nhau, **computeIfPresent** không tự trở thành transaction nhiều key; cần thiết kế đồng bộ hóa hoặc mô hình cập nhật phù hợp.

**Đúng:** callback chủ yếu đọc **key** và **oldValue**, tính **newValue** và trả về. Nếu cần phát sinh tác vụ khác (ghi audit, gửi event), hãy xây dựng ranh giới giao dịch và thứ tự thực hiện riêng, không nhồi các side effect khó hoàn tác vào callback.

### 11.1. Tránh callback sửa oldValue mutable rồi trả chính nó

~~~java
// RỦI RO nếu value là List mutable dùng chung:
map.computeIfPresent(key, (k, list) -> {
    list.add(item);
    return list;
});
~~~

Có thể thấy mapping không đổi **tham chiếu** nhưng object trong Map đã bị sửa. Với HashMap và một thread, mã có thể chạy; tuy nhiên nó gây side effect khó rollback và không tự đảm bảo an toàn khi được dùng đồng thời. Nếu map value là list dùng chung, quyết định rõ chính sách thread-safety, copy-on-write hoặc đồng bộ.

Một cách dùng mẫu với thiết kế mới bất biến:

~~~java
// Minh họa khi value kiểu List<String> không chứa null
Map<String, List<String>> map = new HashMap<>();
map.put("tags", List.of("java"));

map.computeIfPresent("tags", (key, oldTags) -> {
    List<String> copy = new ArrayList<>(oldTags);
    copy.add("stream");
    return List.copyOf(copy);
});

// map.get("tags") == [java, stream]
~~~

**List.copyOf** (Java 10+) tạo List không cho phép sửa; nó không cho null. Ở đây giá trị mới được tạo rồi công bố qua Map, tránh sửa oldTags vốn có thể còn được tham chiếu ở nơi khác.

## 12. ConcurrentHashMap: cập nhật nguyên tử theo khóa

Một điểm không thể bỏ qua: **Map** mặc định **không bảo đảm atomicity** cho computeIfPresent. Nếu nhiều thread cùng dùng một **HashMap** để cập nhật, cần cơ chế đồng bộ riêng; HashMap không an toàn cho truy cập ghi đồng thời.

**ConcurrentHashMap<K,V>** có override với hợp đồng mạnh hơn:

- Nếu key có giá trị, toàn bộ lời gọi **computeIfPresent** được thực hiện **nguyên tử** đối với việc cập nhật mapping của key đó.
- Callback của **ConcurrentHashMap.computeIfPresent** được gọi **đúng một lần cho mỗi lần gọi phương thức khi key có mapping**, hoặc không gọi nếu key vắng mặt.
- Một số thao tác cập nhật khác có thể phải chờ trong khi phép tính đang chạy. Vì vậy callback nên **ngắn, đơn giản, không blocking**.
- Không sửa Map từ bên trong callback; các cập nhật đệ quy có thể bị từ chối và ném **IllegalStateException**.
- **ConcurrentHashMap không cho null key hoặc null value**. Do đó không có trạng thái "key tồn tại nhưng value null" trên ConcurrentHashMap.
- Nguyên tử ở đây là **cập nhật mapping Map**, không phải transaction xuyên database, message broker hoặc hệ thống bên ngoài.

### 12.1. Ví dụ chạy đầy đủ: nhiều thread tăng cùng bộ đếm

Lưu thành **ConcurrentComputeDemo.java**:

~~~java
import java.util.concurrent.ConcurrentHashMap;
import java.util.stream.IntStream;

public class ConcurrentComputeDemo {
    public static void main(String[] args) {
        ConcurrentHashMap<String, Integer> counters =
                new ConcurrentHashMap<>();

        counters.put("java", 0);

        IntStream.range(0, 10_000)
                .parallel()
                .forEach(i -> counters.computeIfPresent(
                        "java",
                        (key, current) -> current + 1
                ));

        System.out.println("java=" + counters.get("java"));

        Integer absent = counters.computeIfPresent(
                "missing",
                (key, current) -> 1
        );

        System.out.println("missingResult=" + absent);
        System.out.println("missingKey="
                + counters.containsKey("missing"));
    }
}
~~~

~~~bash
javac -encoding UTF-8 ConcurrentComputeDemo.java
java ConcurrentComputeDemo
~~~

**Stdout:**

~~~text
java=10000
missingResult=null
missingKey=false
~~~

**Vì sao kết quả xác định?** Với ConcurrentHashMap, mỗi lời gọi computeIfPresent cập nhật mapping hiện tại theo hợp đồng nguyên tử, nên 10.000 lần tăng đơn vị không bị lost update (các phép cộng trong ví dụ nằm trong phạm vi int). Nhiều thread có thể chờ nhau vì chúng cùng cập nhật **một key**; ví dụ minh họa tính đúng đắn, **không khẳng định cách này nhanh hơn vòng lặp tuần tự**.

Nếu muốn đếm lưu lượng lớn với mức cạnh tranh cao, cân nhắc cấu trúc/chiến lược thống kê phù hợp (ví dụ **LongAdder** theo key khi bài toán cho phép semantics đó). Không nên cho rằng mọi lần cập nhật ConcurrentHashMap đều hiệu quả nhất chỉ vì được thực hiện trong parallel stream.

### 12.2. ConcurrentMap không phải tất cả đều giống nhau

Một số **ConcurrentMap** có default implementation với vòng lặp thử **replace/remove**; callback có thể được gọi lại khi có tranh chấp. **Đọc hợp đồng cụ thể của implementation**, không suy rộng quy tắc "chạy đúng một lần" của ConcurrentHashMap cho mọi ConcurrentMap.

Vì vậy, ngay cả với Map đồng thời, callback nên **thuần, không có tác dụng phụ ngoài Map, dễ tính lại**. Tính toán không phụ thuộc trạng thái bất định bên ngoài.

## 13. Map mutable, Map unmodifiable và chính sách null

| Triển khai | Có hỗ trợ thay mapping thông thường? | Null key/value | Cần lưu ý |
|---|---|---|---|
| **HashMap** | Có | Cho phép một null key và null values | Không thread-safe; không cam kết thứ tự duyệt |
| **LinkedHashMap** | Có | Hỗ trợ null theo hợp đồng | Có thứ tự duyệt theo configuration; callback không nên sửa cấu trúc Map |
| **TreeMap** | Có | Phụ thuộc comparator/key; null value có thể được hỗ trợ | Các key phải tuân thứ tự so sánh; không dùng key không tương thích |
| **ConcurrentHashMap** | Có | **Không hỗ trợ null key/value** | computeIfPresent atomic; callback ngắn và không sửa Map |
| **Map.of(...)** | **Không** | Không cho null key/value | Map unmodifiable; update có thể ném UnsupportedOperationException |
| **Map.copyOf(...)** | **Không** | Không cho null key/value | Kết quả unmodifiable |
| **Collections.unmodifiableMap(...)** | Không qua wrapper | Phụ thuộc backing Map | Wrapper chặn các lời gọi cập nhật qua nó |

**Điểm quan trọng:** Khai báo biến theo **Map<K,V>** không chứng minh rằng mọi implementation hỗ trợ phép cập nhật. **computeIfPresent là optional operation**, nên với Map unmodifiable có thể ném **UnsupportedOperationException**; không dựa vào việc key vắng mặt để khẳng định lời gọi sẽ luôn trả null mà không ném.

### 13.1. Nếu muốn sửa Map.of

~~~java
Map<String, Integer> source = Map.of(
        "A", 2,
        "B", 3
);

Map<String, Integer> editable = new HashMap<>(source);

editable.computeIfPresent(
        "A",
        (key, current) -> current + 10
);

// editable.get("A") == 12
// source.get("A") == 2
~~~

Đoạn minh họa có import **Map**, **HashMap**. Đây là bản sao **Map** mới, không phải thay đổi Map nguồn. Nếu các value là đối tượng mutable, việc copy Map thông thường chỉ sao chép **tham chiếu value**, không phải deep copy.

### 13.2. Null key khác null value

**HashMap** cho phép key null:

~~~java
Map<String, Integer> map = new HashMap<>();
map.put(null, 10);

Integer value = map.computeIfPresent(
        null,
        (key, current) -> current + 1
);

// value == 11
// map.get(null) == 11
~~~

**ConcurrentHashMap** cấm null key; vì vậy cùng lời gọi key null sẽ ném **NullPointerException**. Không phụ thuộc vào null key khi dữ liệu cần chuyển giữa nhiều loại Map hoặc khi muốn tránh ý nghĩa khóa mơ hồ.

**remappingFunction == null** cũng không hợp lệ và ném **NullPointerException** khi cần thực hiện API theo hợp đồng.

## 14. Overflow, kiểm tra giá trị và đặc tả nghiệp vụ

**computeIfPresent** chỉ quyết định khi nào cập nhật value; nó không tự kiểm tra giới hạn số, quy tắc đơn vị hoặc tính hợp lệ của dữ liệu mới.

Ví dụ tăng bộ đếm:

~~~java
map.computeIfPresent(
        "count",
        (key, count) -> Math.addExact(count, 1)
);
~~~

Nếu count là **Integer.MAX_VALUE**, **Math.addExact** sẽ ném **ArithmeticException** thay vì tạo số âm do overflow. Mapping của key không bị ghi đè bằng kết quả sai trong trường hợp callback ném exception. Nhưng mọi side effect khác từ callback (nếu có) không tự rollback.

Với số tiền hoặc số lượng lớn, dùng **Long** hoặc **BigInteger** theo miền giá trị. Nếu cần decimal chính xác, dùng **BigDecimal** thay vì cộng **double** rồi kỳ vọng không có sai số. Phép cộng đúng phụ thuộc **kiểu value**, không được computeIfPresent tự động nâng cấp.

### 14.1. Dữ liệu cần validation trước khi ghi

~~~java
map.computeIfPresent("quota", (key, oldQuota) -> {
    int candidate = Math.addExact(oldQuota, requestedIncrease);

    if (candidate < 0 || candidate > maximumQuota) {
        throw new IllegalArgumentException("Quota outside range");
    }

    return candidate;
});
~~~

Đây là **đoạn minh họa**: biến **map**, **requestedIncrease**, **maximumQuota** cần được khai báo trước; **oldQuota** kiểu Integer. Việc tính candidate rồi kiểm tra trước khi trả giá trị giúp ngăn một giá trị sai đi vào Map.

Nếu **maximumQuota** hoặc **requestedIncrease** có thể thay đổi đồng thời từ thread khác, cần thiết kế concurrency và đồng bộ riêng; callback đọc các biến ngoài không tự biến cả hệ thống thành một transaction nhất quán.

### 14.2. Đối tượng value mutable và hiệu ứng phụ

Giả sử Map có value là **OrderState** mutable, callback gọi **oldState.setStatus(...)** rồi ném exception ở bước sau. Mapping vẫn trỏ đến cùng đối tượng, nhưng object đó đã bị đổi trạng thái. Không coi câu "mapping unchanged when callback throws" là bảo đảm các object nằm trong Map đều được hoàn nguyên.

Cách thiết kế dễ kiểm soát hơn: lấy oldValue, **tạo value mới độc lập**, validate và **return**. Với record hoặc class immutable, ranh giới cập nhật thường rõ ràng hơn.

## 15. Hiệu năng và lựa chọn phương thức

**computeIfPresent** phù hợp để gói quy tắc "nếu có value thì tính lại" thành một thao tác dễ đọc. So với tự viết:

~~~java
V current = map.get(key);
if (current != null) {
    map.put(key, update(current));
}
~~~

Nó giảm sự lặp lại và cho implementation của Map cơ hội cung cấp semantics concurrency phù hợp (như ConcurrentHashMap). Tuy nhiên:

- **Không phải lời hứa tối ưu tốc độ** so với get/put trong mọi Map và mọi tình huống.
- Với ConcurrentHashMap, callback quá nặng có thể khiến các cập nhật khác bị chờ.
- Với HashMap, **không có atomicity mặc định**; get/put gói trong computeIfPresent không tự làm chương trình nhiều thread trở nên an toàn.
- Callback cần trả **giá trị mới hoặc null**; nếu chỉ muốn ghi một constant value cho key hiện có, **replace(key, value)** có thể ngắn và rõ hơn.
- Với thống kê thường xuyên trên nhiều key có contention lớn, cần benchmark và chọn cấu trúc dữ liệu phù hợp.

Nếu mục tiêu nghiệp vụ là cập nhật database, Map trong bộ nhớ không thay thế **transaction**, **locking** hoặc **compare-and-swap** của lớp lưu trữ.

## 16. Các lỗi thường gặp

### Lỗi 1 — cho rằng chỉ cần containsKey là callback chạy

~~~java
Map<String, Integer> map = new HashMap<>();
map.put("A", null);

map.computeIfPresent("A", (k, v) -> 10);
// callback không chạy vì map.get("A") == null
~~~

Dù **containsKey("A")==true**, không có cập nhật. Nếu muốn khởi tạo giá trị null, cân nhắc **computeIfAbsent**.

### Lỗi 2 — dùng computeIfPresent để tạo key mới

~~~java
Map<String, Integer> map = new HashMap<>();
map.computeIfPresent("new", (k, old) -> 1);

// map vẫn không có key "new"
~~~

Với yêu cầu tạo/cộng, dùng **compute** hoặc **merge** theo semantics phù hợp.

### Lỗi 3 — tưởng callback trả null sẽ lưu null

~~~java
Map<String, String> map = new HashMap<>();
map.put("A", "ACTIVE");
map.computeIfPresent("A", (k, v) -> null);

// !map.containsKey("A")
~~~

Callback trả null là **xóa mapping** nếu oldValue khác null.

### Lỗi 4 — sửa Map ngay bên trong callback

~~~java
// SAI:
map.computeIfPresent("A", (k, v) -> {
    map.remove("B");
    return v;
});
~~~

Vi phạm khuyến nghị trong API, có nguy cơ ngoại lệ hoặc tình huống concurrency khó xử lý.

### Lỗi 5 — coi HashMap.computeIfPresent là atomic

~~~java
// Hai thread cập nhật cùng một HashMap không có đồng bộ:
map.computeIfPresent("count", (k, n) -> n + 1);
~~~

**HashMap** không thread-safe; việc có một lời gọi API không đảm bảo tránh lost update hoặc data race. Dùng **ConcurrentHashMap** hoặc cơ chế đồng bộ phù hợp với hệ thống.

### Lỗi 6 — chèn I/O hoặc side effect vào callback

~~~java
// Không nên gửi email, gọi HTTP hoặc ghi DB
// bên trong remappingFunction như một bước phụ tùy tiện.
~~~

Callback có thể không được gọi nếu value vắng/null; một số ConcurrentMap có thể gọi lại khi tranh chấp; exception không tự hoàn tác side effect. Tách logic ngoại vi theo thiết kế có kiểm soát.

### Lỗi 7 — sửa object mutable mà không tạo value mới

Nếu callback cập nhật trực tiếp value mutable rồi trả nó, người dùng khác đang giữ tham chiếu có thể quan sát thay đổi. Nếu callback thất bại, side effect có thể vẫn xảy ra. Với trường hợp phù hợp, dùng record/immutable value và trả bản sao mới.

### Lỗi 8 — không xét UnsupportedOperationException

**Map.of**, **Map.copyOf** hoặc unmodifiable wrapper không cho cập nhật. Nếu cần tính lại một giá trị, tạo mutable copy hoặc tạo Map kết quả mới theo yêu cầu.

### Lỗi 9 — bỏ qua overflow

~~~java
map.computeIfPresent("count", (k, v) -> v + 1);
~~~

Có thể tràn **int**. Dùng **Math.addExact** hoặc đổi kiểu giá trị khi giới hạn lớn hơn.

### Lỗi 10 — nhầm các callback signatures

- **computeIfPresent:** **(key, oldValue) -> newValue**.
- **computeIfAbsent:** **key -> value**.
- **merge:** **(oldValue, suppliedValue) -> result**, không có key trong callback.
- **replaceAll:** **(key, value) -> newValue** cho mỗi entry.

Các lambda có hai tham số **không có nghĩa các tham số có cùng ý nghĩa**.

### Lỗi 11 — dùng getOrDefault như phép kiểm tra tồn tại

**getOrDefault(key, fallback)** trả null nếu key thực sự ánh xạ tới null trong Map cho phép null, vì đó là một mapping có thật. Đừng suy ra value null tương đương thiếu key. Khi cần phân biệt, dùng **containsKey(key)**.

### Lỗi 12 — dùng computeIfPresent cho cập nhật nhiều key nguyên tử

Lời gọi nhắm **một key**. Nếu nghiệp vụ chuyển tiền giữa hai ví, thay nhiều mapping phụ thuộc lẫn nhau hoặc cập nhật dữ liệu bền vững, cần cơ chế transaction hoặc khóa có phạm vi phù hợp. Không dùng nhiều lời gọi computeIfPresent riêng lẻ rồi mặc định chúng là một transaction.

## 17. Checklist kiểm thử

Để đảm bảo logic cập nhật đúng, nên kiểm thử tối thiểu:

1. **Khóa vắng mặt:** callback không chạy, phương thức trả null, Map không thêm key.
2. **Khóa có value null** trên Map cho phép null: callback không chạy và null mapping được giữ nguyên.
3. **Value bằng 0 hoặc chuỗi rỗng:** vẫn được coi là **khác null**, callback phải chạy.
4. **Callback trả value mới:** mapping thay đúng giá trị mới, phương thức trả value ấy.
5. **Callback trả null:** mapping bị xóa nếu trước đó có value khác null.
6. **Callback ném exception:** mapping giữ nguyên; kiểm thử riêng đối với side effect lên object mutable.
7. **Overflow** hoặc giá trị vượt quy tắc: xử lý exception/validation đúng.
8. **Unmodifiable Map:** ứng dụng dự kiến rõ UnsupportedOperationException hoặc tạo mutable copy.
9. **Null key/value** nếu ứng dụng có thể dùng nhiều Map implementation khác nhau.
10. **ConcurrentHashMap**: nhiều thread cập nhật cùng key cho kết quả phù hợp; không dùng callback lâu hoặc callback sửa Map.
11. **Thay đổi value là object:** người dùng không vô tình giữ tham chiếu mutable rồi thấy dữ liệu đổi ngoài dự kiến.
12. **Vòng đời dữ liệu:** nếu Map chỉ là cache, đảm bảo tác vụ cập nhật database/transaction không bị nhầm với Map update.

Với phép tăng số đơn giản, test cả trường hợp key mới xuất hiện giữa các thread. **computeIfPresent không tạo key mới**, do đó nếu key không tồn tại tại thời điểm lời gọi, nó không thể tự biến thành phép tăng đầu tiên.

## 18. Bài tập tự kiểm tra

Cho Map:

~~~java
Map<String, Integer> scores = new HashMap<>();
scores.put("A", 3);
scores.put("B", 0);
scores.put("C", null);
~~~

Giả sử đã import **java.util.Map** và **java.util.HashMap**.

**Câu 1.** Kết quả và nội dung Map sau **scores.computeIfPresent("A", (k, v) -> v * 2)** là gì?

**Câu 2.** **scores.computeIfPresent("B", (k, v) -> v + 5)** có chạy callback không? Vì sao?

**Câu 3.** **scores.computeIfPresent("C", (k, v) -> 100)** có làm C trở thành 100 không?

**Câu 4.** **scores.computeIfPresent("D", (k, v) -> 100)** có tạo key D không?

**Câu 5.** Nếu **scores.computeIfPresent("A", (k, v) -> null)**, key A còn không? Phương thức trả gì?

**Câu 6.** Nên dùng **compute**, **computeIfAbsent**, **computeIfPresent** hay **merge** để tạo số đếm bằng 1 nếu thiếu key, còn nếu đã có thì tăng thêm 1 theo cách ngắn gọn?

**Câu 7.** Vì sao **Map.computeIfPresent** trên HashMap không đủ bảo đảm atomic khi có nhiều thread?

**Câu 8.** Với **ConcurrentHashMap**, callback có được sửa một key khác trong cùng Map không?

**Câu 9.** Nếu callback của computeIfPresent ném exception sau khi đã sửa một object mutable, toàn bộ object có được tự rollback không?

**Câu 10.** Khi value là null, **replace(key, value)** và **computeIfPresent(key, fn)** có cùng điều kiện hoạt động không?

**Đáp án:**

1. Trả **6**, mapping **A=6**.
2. **Có.** Giá trị **0** khác null, nên callback chạy và **B=5**.
3. **Không.** Key C có mapping null; callback của computeIfPresent không chạy.
4. **Không.** Key D vắng mặt, nên callback không chạy và Map giữ nguyên.
5. Key **A bị xóa**; phương thức trả **null**.
6. Với giá trị bổ sung 1, **scores.merge(key, 1, Integer::sum)** là một lựa chọn ngắn gọn (cần kiểm tra overflow trong ứng dụng có số lớn).
7. **Map default không cam kết đồng bộ hoặc atomicity; HashMap không thread-safe**, nên các cập nhật có thể tranh chấp.
8. **Không nên và không được theo hợp đồng của ConcurrentHashMap**: remappingFunction không được sửa Map trong lúc tính.
9. **Không.** Hợp đồng giữ mapping chưa bị thay bởi giá trị mới, không hoàn tác mọi side effect lên object hoặc dịch vụ ngoài.
10. **Không.** **replace(key,newValue)** dùng điều kiện key có mapping; **computeIfPresent** đòi **oldValue != null**. Trên Map cho phép null, replace có thể cập nhật mapping null, còn computeIfPresent bỏ qua.

## 19. Tổng kết

**computeIfPresent(key, remappingFunction)** là API dành cho quy tắc **"chỉ cập nhật khi khóa đang gắn với một giá trị khác null"**:

- Value khác null → gọi callback với **(key, oldValue)**.
- Callback trả value khác null → **cập nhật mapping** và trả value mới.
- Callback trả null → **xóa mapping** và trả null.
- Key vắng mặt hoặc đang map tới null → **không gọi callback**, không tự khởi tạo key.
- Callback ném unchecked exception → mapping không bị thay bởi kết quả tính mới; **side effect bên ngoài không được rollback**.
- **Map mặc định không bảo đảm atomicity**; **ConcurrentHashMap** cung cấp override atomic theo key với callback ngắn và không sửa Map.
- Nếu muốn khởi tạo value khi thiếu, xem **computeIfAbsent**, **compute** hoặc **merge**; nếu chỉ muốn gán giá trị có sẵn, xem **replace**.
- Giữ callback **thuần, dễ dự đoán**, kiểm tra overflow và hiểu chính sách null/mutability của Map implementation.
