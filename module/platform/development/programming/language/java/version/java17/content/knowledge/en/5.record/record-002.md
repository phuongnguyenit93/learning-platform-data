# Record Components, `private final` Fields, and Accessors in Java 17

A `record` in Java 17 provides a concise way to declare a data type with a **fixed structure**. The list at the head of a `record` declaration is called the **record components**. Each component corresponds directly to a **`private final` instance field**, a **public accessor**, and a **parameter of the canonical constructor**.

Example:

```java
record Person(String name, int age) {}
```

From this single line, the Java 17 compiler automatically generates the essential members to store and access the two values `name` and `age`. Understanding this mechanism helps you use `record` properly and avoid confusing it with public fields, JavaBeans getters, or deep data immutability.

> **Version:** Records have been a standard feature since Java 16 (JEP 395); in **Java 17**, `--enable-preview` is not required. The examples in this lesson use syntax officially supported by Java 17.

## 1. What Is a Record Component?

A **record component** is a **data type and name** entry declared in the header of a `record`:

```java
record Book(String title, String author, int pages) {}
//          ^^^^^^^^^^^^  ^^^^^^^^^^^^^  ^^^^^^^^^
//           component 1   component 2     component 3
```

Here there are three components:

| Component | Declared Type | Name | Corresponding Accessor |
|---|---|---|---|
| `String title` | `String` | `title` | `title()` |
| `String author` | `String` | `author` | `author()` |
| `int pages` | `int` | `pages` | `pages()` |

The component list describes the **core state** of each `Book` object. The position of each component also matters: the order in the header is the parameter order of the **canonical constructor**.

To create and use an object:

```java
Book book = new Book("Effective Java", "Joshua Bloch", 416);

System.out.println(book.title());
System.out.println(book.author());
System.out.println(book.pages());
```

Output:

```text
Effective Java
Joshua Bloch
416
```

Calls to `title()`, `author()`, and `pages()` are valid even though you **never wrote those three methods**. The compiler generates the accessor corresponding to each component.

### 1.1. A Component Is Not a "Public Variable"

A component in the header does not declare a public field. Java stores state inside the object via fields with `private` visibility and the `final` modifier.

The following code is **invalid** if written outside `Book`:

```java
// Invalid: title is a private field.
// System.out.println(book.title);

// Invalid: cannot assign directly to the field.
// book.pages = 500;

// Valid: call the public accessor.
System.out.println(book.title());
```

The term *record component* describes the **member declaration** in the header. The corresponding field and accessor are separate members generated from that declaration.

### 1.2. Component Data Types

Components can use primitive types, reference types, generic types, and arrays:

```java
import java.math.BigDecimal;
import java.time.LocalDate;
import java.util.List;

record Invoice(
        long id,
        BigDecimal amount,
        LocalDate issuedAt,
        List<String> tags,
        byte[] signature
) {}
```

The components here have different types, yet all follow the rule **`private final` field + same-named accessor**. For reference or array types, `final` only fixes **the reference held in the field**; it does not automatically make the object's contents immutable. Section 6 analyzes this in detail.

## 2. How Does Java Generate Fields, Constructors, and Accessors?

Consider the declaration:

```java
record Point(int x, int y) {}
```

Conceptually, the main members are roughly equivalent to:

```java
// The following code only illustrates the core members,
// NOT the exact source code generated by javac.
final class PointLike {
    private final int x;
    private final int y;

    public PointLike(int x, int y) {
        this.x = x;
        this.y = y;
    }

    public int x() {
        return x;
    }

    public int y() {
        return y;
    }
}
```

Correspondence table:

| Written in the header | Derived field | Derived accessor | Constructor parameter |
|---|---|---|---|
| `int x` | `private final int x` | `public int x()` | `int x` |
| `int y` | `private final int y` | `public int y()` | `int y` |

In addition to those members, a record also gets appropriate implementations of `equals(Object)`, `hashCode()`, and `toString()`, which use the state of the components.

A record is a special class that directly extends `java.lang.Record` and is implicitly **`final`** (cannot be subclassed by another class). Therefore:

```java
record Point(int x, int y) {}

// Invalid: Point is final.
// class ColorPoint extends Point {}
```

**Important to remember:** the compiler does not "translate a record into a regular class with identical source code" in a literal source-transformation sense; the table and `PointLike` class merely illustrate the members a programmer can observe and use.

### 2.1. Inspecting Members with `javap`

If you create a file `Point.java`:

```java
public record Point(int x, int y) {}
```

In a terminal using JDK 17:

```bash
javac --release 17 Point.java
javap -p Point
```

`javap -p` shows `private` members as well, letting you see the data types, fields, and methods generated by the compiler. The output contains lines equivalent to:

```text
public final class Point extends java.lang.Record {
  private final int x;
  private final int y;
  public Point(int, int);
  public final java.lang.String toString();
  public final int hashCode();
  public final boolean equals(java.lang.Object);
  public int x();
  public int y();
}
```

This is **illustrative output**; the display order of members may vary by compiler or tool. What to observe is that the fields carry `private final` and the accessors return the exact component types.

## 3. The `private final` Fields of a Record

Given:

```java
record User(long id, String email) {}
```

Java establishes the storage fields:

```java
// Conceptual representation; do not write these lines inside User:
private final long id;
private final String email;
```

### 3.1. Why `private`?

`private` blocks direct access from other classes. Information is read through the public interface—the accessors:

```java
User user = new User(101L, "a@example.com");

System.out.println(user.id());    // 101
System.out.println(user.email()); // a@example.com
```

This allows a record to **explicitly control how values are read** when needed, such as returning a copy of mutable data in an explicit accessor.

### 3.2. Why `final`?

`final` enforces that the field is assigned during object construction and cannot be reassigned afterward.

```java
record User(long id, String email) {
    void changeEmail(String newEmail) {
        // Invalid: the field is final.
        // this.email = newEmail;
    }
}
```

From outside, you also cannot:

```java
User user = new User(101L, "a@example.com");

// Invalid: no auto-generated setter exists.
// user.setEmail("b@example.com");

// Invalid: private final field.
// user.email = "b@example.com";
```

When a different value is needed, the natural approach is to **create a new record**:

```java
User updated = new User(user.id(), "b@example.com");
```

The two objects have independent state: `user` still has the original email, while `updated` holds the new email.

### 3.3. Do Not Redeclare Component Instance Fields

You must not and cannot add an instance field to the record body to "redefine" a component:

```java
// Invalid: records do not allow declaring instance fields manually.
// record User(long id) {
//     private final long id;
// }
```

A record also does not allow declaring additional instance fields beyond those derived from record components:

```java
// Invalid: extra is an additionally declared instance field.
// record User(long id) {
//     private int extra;
// }
```

However, a record **can have static fields**, member methods, valid constructors, and can implement interfaces:

```java
record Product(String name, long price) {
    static final String CURRENCY = "VND";

    String label() {
        return name() + ": " + price() + " " + CURRENCY;
    }
}
```

Using `name()` and `price()` inside methods you write is clear and consistent with the record's API.

## 4. Record Accessors: `name()` Instead of `getName()`

For a component `String name`, the default accessor is **`public String name()`**.

```java
record Employee(String name, int level) {}

Employee e = new Employee("Mai", 3);

String n = e.name();
int l = e.level();
```

No JavaBeans getters `getName()` or `getLevel()` are generated automatically.

| Component | Correct Record Syntax | Not Auto-Generated |
|---|---|---|
| Component `name` | `employee.name()` | `employee.getName()` |
| Component `level` | `employee.level()` | `employee.getLevel()` |
| `boolean` component `active` | `employee.active()` | `employee.isActive()` |

Example:

```java
record Feature(String name, boolean active) {}

Feature f = new Feature("Export", true);

System.out.println(f.name());
System.out.println(f.active());
```

Even when the component type is `boolean`, the default accessor is still **`active()`**.

### 4.1. Do Accessors Take Parameters?

A component accessor **takes no parameters**:

```java
record Size(int width, int height) {}

Size size = new Size(800, 600);

System.out.println(size.width());  // 800
System.out.println(size.height()); // 600

// Invalid: width() takes no parameters.
// size.width(1024);
```

The accessor has the **exact same return type as the declared component**: `width()` returns `int`, `name()` returns `String`, and `tags()` returns `List<String>` if the component is `List<String> tags`.

### 4.2. Generated Accessors Have `public` Visibility

Even when a record lacks the `public` keyword (package-private record), its generated accessors still carry the `public` modifier. Whether the record is accessible from another package is still governed by **the visibility of the record type itself**.

If you want to use a record type from another package, declare a `public` top-level record in a file with the matching name:

```java
// File: com/example/model/Employee.java
package com.example.model;

public record Employee(String name, int level) {}
```

Clients can then access `Employee` and `Employee.name()`/`Employee.level()` if they have the appropriate package/module access.

### 4.3. Can You Write an Accessor Yourself?

Yes. This is called an **explicit accessor**. It must match the component's contract: a `public` instance method with no parameters, returning the exact component type, and declaring no type parameters or `throws` clause.

Example:

```java
record Title(String text) {
    public String text() {
        return text;
    }
}
```

The `return text;` line inside the record body accesses the `private final` field generated by Java. Because a valid explicit accessor is present, Java **does not generate another** `text()` accessor.

This is a public method written by the programmer:

```java
Title title = new Title("Java 17");
System.out.println(title.text());
```

**Design note:** a record is intended as a *transparent carrier* of its component values. A custom accessor should preserve the semantic meaning of the component's data. For example, having an accessor `price()` return a different price than the actual field value can surprise readers because the default `equals`/`hashCode` are based on component state, not on arbitrary transformations performed by an accessor. If you want to normalize a value, prefer doing so **in the constructor**.

## 5. Components and the Canonical Constructor

Every record has a **canonical constructor** with a parameter list matching the components in **the same order and types**.

```java
record Person(String name, int age) {}

Person p = new Person("An", 20);
```

Here the constructor has two parameters `(String name, int age)`. The following call does not match the order or types:

```java
// Invalid: the first parameter must be String.
// Person wrong = new Person(20, "An");
```

### 5.1. Compact Canonical Constructor

To validate and normalize input, you can write a **compact constructor** using the syntax `public Person { ... }`. In a compact constructor, Java automatically assigns the component fields from the corresponding parameters **after the body completes normally**:

```java
import java.util.Objects;

public record Person(String name, int age) {
    public Person {
        name = Objects.requireNonNull(name, "name").strip();

        if (name.isEmpty()) {
            throw new IllegalArgumentException("name must not be blank");
        }
        if (age < 0) {
            throw new IllegalArgumentException("age must be non-negative");
        }
    }
}
```

When called:

```java
Person p = new Person("  An  ", 20);
System.out.println(p.name()); // "An"
System.out.println(p.age());  // 20
```

The line `name = ...` in the compact constructor reassigns the **input parameter**, not a `private final` field. Java uses the normalized parameter value when performing the implicit field assignment at the end of the constructor.

In a compact constructor, **do not manually assign** `this.name = ...` or `this.age = ...`; Java handles field assignment.

### 5.2. Explicit Canonical Constructor

If you need to write the full canonical constructor, declare the parameter list matching the header and manually assign **all** component fields:

```java
import java.util.Objects;

record PointLabel(int x, int y, String label) {
    public PointLabel(int x, int y, String label) {
        this.x = x;
        this.y = y;
        this.label = Objects.requireNonNull(label).strip();
    }
}
```

Unlike a compact constructor, an explicit canonical constructor is **responsible for initializing** all final fields itself.

For ordinary data records, a compact constructor is usually easier to write and reduces the risk of missing a field.

### 5.3. Additional Constructors Must Delegate to the Canonical Constructor

A record can provide convenience constructors, but any non-canonical constructor must call another constructor via `this(...)`:

```java
record Range(int start, int end) {
    Range(int end) {
        this(0, end);
    }

    Range {
        if (start > end) {
            throw new IllegalArgumentException("start > end");
        }
    }
}
```

`new Range(10)` delegates to the canonical constructor `Range(int start, int end)`, where all components are validated and initialized.

## 6. `private final` Only Guarantees Shallow Immutability

This is the most common mistake when working with records: **a `final` field does not guarantee that the referenced object is also immutable**.

### 6.1. Example with an Array Component

```java
record Scores(int[] values) {}

int[] input = {10, 20};
Scores scores = new Scores(input);

input[0] = 99; // Directly mutates the contents of the passed-in array.

System.out.println(scores.values()[0]); // 99
```

Why:

- The `values` field in `Scores` is `private final int[] values`.
- `final` only prevents reassigning the field to **another array**.
- It does not prevent modifying elements of **the current array**.
- The auto-generated accessor `values()` returns **the exact array reference** stored in the record.

Callers can also mutate through the accessor:

```java
scores.values()[1] = 77;
System.out.println(input[1]); // 77
```

Therefore, you cannot assume every record has deeply immutable state.

### 6.2. Copying Arrays on Input and Output

If you need to protect an array from external mutation, copy on both input and output:

```java
import java.util.Arrays;
import java.util.Objects;

record SafeScores(int[] values) {
    public SafeScores {
        values = Objects.requireNonNull(values, "values").clone();
    }

    public int[] values() {
        return values.clone();
    }

    public int sum() {
        return Arrays.stream(values).sum();
    }
}
```

Usage:

```java
int[] input = {10, 20};
SafeScores scores = new SafeScores(input);

input[0] = 99;            // Does not affect the internal array.
scores.values()[1] = 77;  // Only modifies the returned copy.

System.out.println(scores.sum()); // 30
```

In the compact constructor, `values = values.clone()` replaces the **parameter**, and then Java assigns that copy to the field at the end of the constructor. The explicit accessor `values()` also copies when returning.

**Advanced point to know:** a record with an array component still gets default `equals`/`hashCode` based on the comparison semantics of its components; for arrays, default comparison is based on **reference**, not element-by-element comparison. Two array copies with identical elements do not necessarily make two records equal. If content-based value equality is needed, you must explicitly design `equals`/`hashCode` consistently or use a more suitable immutable structure.

### 6.3. Taking a Safer Snapshot with `List.copyOf`

A common choice in Java 17 is converting an input `List` into an unmodifiable list:

```java
import java.util.List;
import java.util.Objects;

record Course(String title, List<String> lessons) {
    public Course {
        title = Objects.requireNonNull(title, "title").strip();
        lessons = List.copyOf(lessons);
    }
}
```

Example:

```java
import java.util.ArrayList;
import java.util.List;

List<String> source = new ArrayList<>(List.of("Introduction", "Records"));
Course course = new Course("Java 17", source);

source.add("Sealed classes");

System.out.println(course.lessons());
// [Introduction, Records]
```

With the `Course` record:

- `List.copyOf` creates a snapshot of the list at construction time and returns an **unmodifiable** list.
- `course.lessons().add("Extra")` will throw `UnsupportedOperationException`.
- Structural modifications to `source` after record creation do not change the stored list.

**Limitation:** If each element in the list is a mutable object, `List.copyOf` does not deep-copy those objects. With `List<String>`, `String` elements are immutable, so this simple example is appropriate. `List.copyOf` also does not accept `null` elements.

## 7. Does Writing a Custom Accessor Change `equals` or `hashCode`?

Do not assume that overriding an accessor automatically redefines how a record compares instances. Consider:

```java
record MaskedSecret(String value) {
    public String value() {
        return "***";
    }
}
```

`MaskedSecret` still stores the `value` field internally. The accessor returns a masked string, but the default `equals` and `hashCode` rely on **the stored component state**, not by calling the custom accessor to retrieve `"***"` by default.

Example:

```java
MaskedSecret first = new MaskedSecret("alpha");
MaskedSecret second = new MaskedSecret("beta");

System.out.println(first.value());           // ***
System.out.println(second.value());          // ***
System.out.println(first.equals(second));    // false
```

This illustrates why an accessor behaving very differently from the underlying data can cause surprises. Additionally, the default `toString()` may display stored components, so **never rely on a masking accessor alone to protect secrets**; for sensitive data, consider storage, logging, `toString`, and the type's API carefully.

If you only want to normalize casing, whitespace, or validate value ranges, the constructor is usually the right place:

```java
import java.util.Locale;
import java.util.Objects;

record CountryCode(String value) {
    CountryCode {
        value = Objects.requireNonNull(value).strip().toUpperCase(Locale.ROOT);
    }
}
```

Now `new CountryCode(" vn ").value()` returns `"VN"`, and the normalized value is also the stored state.

## 8. Components and Interfaces: Accessors Can Satisfy Existing Contracts

A record can `implements` interfaces. If a method's name and signature match a component accessor, the generated accessor suffices to implement the interface method.

```java
interface Named {
    String name();
}

record Customer(String name, long id) implements Named {}

class Demo {
    public static void main(String[] args) {
        Named n = new Customer("An", 101L);
        System.out.println(n.name()); // An
    }
}
```

There is no need to write an extra `public String name()` method in `Customer`.

Conversely, if an interface requires `getName()`:

```java
interface BeanNamed {
    String getName();
}
```

a record with component `name` **does not automatically implement** `getName()`. You can write a forwarding method when interoperating with such an API:

```java
record Customer(String name) implements BeanNamed {
    public String getName() {
        return name();
    }
}
```

This is a method added manually by the developer. The compiler still generates the `name()` accessor from the component.

This matters when integrating frameworks or libraries that expect traditional getters: check whether the library supports Java records and which method conventions its API expects.

## 9. How Do Record Components Differ from Fields and Methods in Reflection?

Java 17 has dedicated reflection APIs for records:

- `Class.isRecord()`: checks whether a class is a record.
- `Class.getRecordComponents()`: retrieves the `RecordComponent` array declared in the header.
- `RecordComponent.getName()`, `getType()`, `getAccessor()`: inspects the name, type, and accessor method.

Example:

```java
import java.lang.reflect.RecordComponent;

record Address(String city, int zipCode) {}

class ReflectRecord {
    public static void main(String[] args) {
        Class<Address> type = Address.class;

        System.out.println(type.isRecord()); // true

        for (RecordComponent c : type.getRecordComponents()) {
            System.out.printf(
                    "component=%s, type=%s, accessor=%s%n",
                    c.getName(),
                    c.getType().getSimpleName(),
                    c.getAccessor().getName()
            );
        }
    }
}
```

Output:

```text
true
component=city, type=String, accessor=city
component=zipCode, type=int, accessor=zipCode
```

**Distinguishing the three reflection objects:**

| API | Represents | Example |
|---|---|---|
| `RecordComponent` | Component declared in the record header | `String city` |
| `Field` | Field storing data in the class | `private final String city` |
| `Method` | Method, including accessors | `public String city()` |

A `RecordComponent` is neither a `Field` nor a `Method`. They are related via the record declaration, but have distinct reflection APIs.

If `Class.getRecordComponents()` is called on a non-record class, it returns `null`; use `isRecord()` when handling arbitrary classes. For a record with no components, it returns an empty array.

### 9.1. Annotations on Record Components

In Java, annotations can specifically target `RECORD_COMPONENT` or fields, methods, and parameters. Depending on `@Target`, an annotation written on a component may appear on the corresponding generated elements according to Java 17 annotation propagation rules.

Example of an annotation targeting only the component:

```java
import java.lang.annotation.ElementType;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;
import java.lang.annotation.Target;

@Target(ElementType.RECORD_COMPONENT)
@Retention(RetentionPolicy.RUNTIME)
@interface Label {
    String value();
}

record Customer(@Label("Customer ID") String id) {}
```

You can query `Label` via `Customer.class.getRecordComponents()[0]`. Because the annotation above targets only `RECORD_COMPONENT`, do not assume it automatically appears on `Field` or `Method`; that depends on `@Target` and the applicable rules.

This is why libraries working with records can inspect component metadata instead of only searching for field names or getters.

## 10. What Records Auto-Generate vs. What They Do Not

| Member | Auto-Generated from Component? | Notes |
|---|---|---|
| `private final` instance field | Yes | One field per component |
| `componentName()` accessor | Yes | `public`, returns the component type |
| Canonical constructor | Yes if not declared manually | Parameters in component order |
| `equals(Object)` | Yes if not declared manually | Based on component state |
| `hashCode()` | Yes if not declared manually | Consistent with `equals` |
| `toString()` | Yes if not declared manually | Shows record name and components |
| JavaBeans `getName()`/`isActive()` | **No** | Must be written manually if truly needed |
| Setter `setName(...)` | **No** | Component fields are `final` |
| Defensive copy for mutable arrays/lists | **No** | Must be designed in constructor/accessor |
| `null` and range validation | **No** | Validate manually in constructor if needed |
| Additional instance field | **Cannot be added manually** | Records only hold instance fields from components |

The table above reflects the rules in Java 17. Additional libraries or framework mechanisms may introduce their own behavior, but they do not alter the core record API.

## 11. Common Mistakes

### 11.1. Using Field-Access Syntax Instead of the Accessor

```java
record Point(int x, int y) {}

class Demo {
    public static void main(String[] args) {
        Point p = new Point(1, 2);

        // Invalid: x is a private field of Point.
        // System.out.println(p.x);

        System.out.println(p.x()); // Valid
    }
}
```

### 11.2. Assuming Records Have JavaBeans Getters

```java
record Person(String name) {}

class Demo {
    public static void main(String[] args) {
        Person p = new Person("Lan");

        // Invalid: getName is not auto-generated by a record.
        // System.out.println(p.getName());

        System.out.println(p.name()); // Valid
    }
}
```

### 11.3. Trying to Reassign a `final` Field

```java
record Counter(int value) {
    void increase() {
        // Invalid: cannot reassign the field.
        // this.value++;
    }

    Counter increased() {
        return new Counter(value() + 1);
    }
}
```

Instead of mutating in place, the `increased()` method creates a new record.

### 11.4. Explicit Accessor with the Wrong Signature

```java
// Invalid: accessor must have the same return type as the component.
// record Price(long cents) {
//     public int cents() {
//         return 0;
//     }
// }
```

Correct:

```java
record Price(long cents) {
    public long cents() {
        return cents;
    }
}
```

You cannot use the default `cents()` accessor to change the public API type from `long` to `int`; if conversion is needed, write **a differently named method**, such as `intValueExact()` with proper overflow handling.

### 11.5. Missing `public` on an Explicit Accessor

```java
// Invalid: explicit accessors must be public.
// record Person(String name) {
//     String name() {
//         return name;
//     }
// }
```

Correct:

```java
record Person(String name) {
    public String name() {
        return name;
    }
}
```

### 11.6. Holding a Mutable Reference While Thinking Data Is Locked

```java
record Holder(StringBuilder data) {}

StringBuilder buffer = new StringBuilder("A");
Holder holder = new Holder(buffer);

buffer.append("B");

System.out.println(holder.data()); // AB
```

The `data` field still points to the same `StringBuilder`. `final` does not prevent `append`. If immutable string state is desired, a `String` component is usually better, converting data to `String` at record creation.

### 11.7. Changing Components but Forgetting Canonical Constructor Order

```java
record Position(int row, int column) {}

Position p = new Position(2, 5);
```

Both parameters are `int`, so swapping `(5, 2)` by mistake **still compiles**, but the data meaning is wrong. When components share the same type, use clear variable names or factory methods if the API is complex.

## 12. Complete Example: Java 17 Learner Record

Create `RecordDemo.java`:

```java
import java.util.List;
import java.util.Objects;

record Student(String id, String fullName, List<String> courses) {
    Student {
        id = Objects.requireNonNull(id, "id").strip();
        fullName = Objects.requireNonNull(fullName, "fullName").strip();
        courses = List.copyOf(courses);

        if (id.isBlank()) {
            throw new IllegalArgumentException("id must not be blank");
        }
        if (fullName.isBlank()) {
            throw new IllegalArgumentException("fullName must not be blank");
        }
    }

    int numberOfCourses() {
        return courses().size();
    }

    Student withFullName(String newFullName) {
        return new Student(id(), newFullName, courses());
    }
}

public class RecordDemo {
    public static void main(String[] args) {
        Student a = new Student(
                "  S001  ",
                "  Minh  ",
                List.of("Java 17", "SQL")
        );

        System.out.println(a.id());
        System.out.println(a.fullName());
        System.out.println(a.courses());
        System.out.println(a.numberOfCourses());

        Student b = a.withFullName("Minh Anh");

        System.out.println(a.fullName());
        System.out.println(b.fullName());
        System.out.println(a.equals(b));
        System.out.println(a);
    }
}
```

Compile and run with JDK 17:

```bash
javac --release 17 RecordDemo.java
java RecordDemo
```

Output:

```text
S001
Minh
[Java 17, SQL]
2
Minh
Minh Anh
false
Student[id=S001, fullName=Minh, courses=[Java 17, SQL]]
```

Key takeaways from the example:

1. `Student`'s header declares three components: `id`, `fullName`, and `courses`.
2. The compiler generates the corresponding `private final` fields and accessors `id()`, `fullName()`, `courses()`.
3. The compact constructor validates inputs, normalizes strings, and snapshots the list with `List.copyOf`.
4. The `numberOfCourses()` method adds behavior without changing the number of components.
5. `withFullName(...)` returns a **new record**, leaving `a` unchanged.
6. The default `equals` and `toString` rely on the component values after constructor normalization.

## 13. Self-Practice Exercises

### Exercise 1 — Identify Accessors and Fields

Given:

```java
record Ticket(long number, String owner, boolean used) {}
```

State:

- How many components are there?
- What are the names and types of the three compiler-generated fields?
- Which method must be called to read the `used` state?
- Is `ticket.isUsed()` generated automatically?

**Answer:** three components; the fields are `private final long number`, `private final String owner`, and `private final boolean used`; access via `ticket.used()`; `isUsed()` is not generated by default.

### Exercise 2 — Choose the Right Update Approach

Given:

```java
record Temperature(double celsius) {}

Temperature t1 = new Temperature(24.5);
```

To create a new temperature equal to 25 degrees Celsius, write:

```java
Temperature t2 = new Temperature(25.0);
```

Do not mutate `t1`'s field. If a convenience method is needed, you can add:

```java
record Temperature(double celsius) {
    Temperature withCelsius(double value) {
        return new Temperature(value);
    }
}
```

### Exercise 3 — Why Can `final` Still Allow Data Changes?

Given:

```java
record Tags(String[] values) {}

String[] data = {"a", "b"};
Tags tags = new Tags(data);
data[0] = "x";
```

**Answer:** the record holds a `final` reference to the `data` array but does not copy the array and does not prevent element mutation. `tags.values()[0]` will be `"x"`. To prevent external modification, copy the data in the constructor and in the accessor, or use an appropriate immutable list type.

### Exercise 4 — Write a Compact Constructor

Goal: record `Age(int years)` rejects negative values.

```java
record Age(int years) {
    Age {
        if (years < 0) {
            throw new IllegalArgumentException("years < 0");
        }
    }
}
```

You do not need to write `this.years = years`. Assignment to the `private final` field happens implicitly after the compact constructor body completes normally.

## 14. How to Remember

When reading `record R(Type component)`, associate it with three core parts:

```text
record R(Type component) {}
        │
        ├── component in the record header
        │
        ├── private final Type component;   (storage field)
        │
        ├── public Type component();        (read accessor)
        │
        └── R(Type component)               (canonical constructor)
```

- **Component** is the data structure declaration.
- **`private final` field** holds state once upon initialization and disallows reassigning the reference/value.
- **Accessor `component()`** is the public method to retrieve the value; there are no default JavaBeans getters.
- **`final` does not mean deep immutability**. For arrays, lists, or mutable objects, explicitly decide whether defensive copying is required.
- **Constructor** is the appropriate place to validate and normalize data before it is stored.
