# Kiểm tra khả năng hỗ trợ của JDBC driver và DatabaseMetaData (JDBC 4.3, Java 9+)

## 1. Mục tiêu và cách hiểu đúng

Một ứng dụng Java có thể chạy trên JDK mới nhưng **driver JDBC** mà ứng dụng nạp và **hệ quản trị cơ sở dữ liệu (DBMS)** đang kết nối không hỗ trợ mọi tính năng JDBC. Vì vậy, khi muốn sử dụng batch update, transaction, savepoint, result set có thể cuộn/cập nhật, REF CURSOR hoặc sharding, cần kiểm tra đúng cặp **driver + phiên bản DBMS + cấu hình kết nối** đang chạy.

`DatabaseMetaData` là giao diện thuộc `java.sql`, lấy từ một `Connection`:

```java
DatabaseMetaData meta = connection.getMetaData();
```

Nó cung cấp thông tin về sản phẩm database, phiên bản driver, phiên bản JDBC driver công bố, bảng/cột/schema, kiểu dữ liệu, và các câu trả lời `supports...()` cho khả năng SQL/JDBC. Kết quả phản ánh **khả năng phối hợp giữa driver và DBMS**, không chỉ khả năng của JDK.

**JDBC 4.3** được thêm vào Java 9 và tiếp tục dùng trên các JDK hiện đại. Kiến thức ở đây áp dụng cho Java 17+ và các JDBC driver hiện hành. Một số tính năng của 4.3 là **tùy chọn**, đặc biệt là sharding; không nên suy ra “JDBC 4.3 = mọi tính năng đều được hỗ trợ”.

### Quy trình kiểm tra ba tầng

```text
Driver JAR có trong runtime/classpath?
            |
 DriverManager nhận diện JDBC URL?
            |
 Kết nối thật tới DBMS thành công?
            |
 Connection.getMetaData()
            |
 Đọc product/version và supports...()
            |
 Với tính năng quan trọng:
 thử nghiệm thao tác thật trên DB thử nghiệm
```

- **Tầng 1 — driver có sẵn:** kiểm tra dependency và driver được phát hiện cho JDBC URL. Không có driver phù hợp thường dẫn đến `SQLException` như “No suitable driver”.
- **Tầng 2 — kết nối thật:** chứng minh mạng, xác thực, cấu hình TLS, DBMS và driver làm việc cùng nhau. `Connection.isValid(timeout)` có thể giúp kiểm tra kết nối còn sử dụng được, nhưng không chứng minh tính năng SQL cụ thể.
- **Tầng 3 — năng lực:** dùng `DatabaseMetaData` để quyết định nhánh xử lý phù hợp, sau đó thử một tình huống đại diện trong integration test nếu nghiệp vụ phụ thuộc tính năng đó.

Không nhầm `supports...()==true` với cam kết rằng **mọi câu lệnh** sẽ chạy thành công: cú pháp SQL, quyền tài khoản, cấu hình server và hành vi theo phiên bản vẫn có thể làm thao tác thất bại.

## 2. Phân biệt thông tin phiên bản của driver, JDBC API và database

| API | Cho biết điều gì? | Cách dùng |
| --- | --- | --- |
| `DatabaseMetaData.getDriverName()` / `getDriverVersion()` | Tên và phiên bản driver đang phục vụ `Connection` | Ghi nhận để tái hiện lỗi, đối chiếu tài liệu vendor |
| `getJDBCMajorVersion()` / `getJDBCMinorVersion()` | Phiên bản JDBC API driver báo cáo | Biết mức API mà driver tự công bố; **không thay cho kiểm tra tính năng** |
| `getDatabaseProductName()` / `getDatabaseProductVersion()` | Tên và phiên bản DBMS đang kết nối | Xác định môi trường cơ sở dữ liệu thật |
| `getDatabaseMajorVersion()` / `getDatabaseMinorVersion()` | Số phiên bản major/minor của DBMS | Hữu ích cho compatibility matrix |
| `Driver.getMajorVersion()` / `getMinorVersion()` | Số phiên bản do `Driver` công bố | **Không phải** `getJDBCMajorVersion()` |
| `DriverManager.getDriver(jdbcUrl)` | Một driver đã đăng ký nhận diện JDBC URL này | Chỉ là phát hiện ứng viên; chưa chứng minh có thể đăng nhập thành công |

Ví dụ driver công bố JDBC `4.3` nhưng `supportsSharding()` trả về `false` là điều hoàn toàn có thể xảy ra. Driver có thể hỗ trợ request boundary, statement quoting nhưng không triển khai JDBC sharding; hoặc DBMS không có tính năng tương ứng.

### Driver có được tự động phát hiện không?

Với các driver JDBC hiện đại có khai báo Java Service Provider, `DriverManager` có thể tìm driver qua cơ chế service loading; thông thường không cần tự `Class.forName("...Driver")`. Hãy đảm bảo driver JAR thực sự có mặt trong **runtime classpath/module path**, không chỉ trong compile classpath.

Từ Java 9 có thể xem danh sách các driver ứng dụng hiện tại truy cập được:

```java
DriverManager.drivers().forEach(driver ->
    System.out.println(driver.getClass().getName()));
```

Đây là đoạn mã minh họa đặt trong chương trình đã import `java.sql.DriverManager`; kết quả phụ thuộc các JAR đã tải và class loader. **Danh sách trống hoặc thiếu tên mong đợi** cần kiểm tra dependency, module/class loader và cấu hình đóng gói trước khi truy vấn database. Trong ứng dụng web hoặc app server, class loader của từng module có thể cho ra tập driver khác nhau.

## 3. Những năng lực cần kiểm tra bằng DatabaseMetaData

| Nhu cầu của ứng dụng | Phương thức kiểm tra | Điều cần hiểu |
| --- | --- | --- |
| Giao dịch | `supportsTransactions()` | Không đồng nghĩa DDL luôn rollback được |
| Mức cô lập cụ thể | `supportsTransactionIsolationLevel(Connection.TRANSACTION_REPEATABLE_READ)` | Kiểm tra từng isolation level cần dùng |
| Savepoint | `supportsSavepoints()` | Dùng cùng transaction; hành vi còn phụ thuộc DBMS |
| Batch update | `supportsBatchUpdates()` | Hãy kiểm tra thêm hành vi lỗi và số dòng cập nhật trong integration test |
| Nhận khóa sinh tự động | `supportsGetGeneratedKeys()` | Việc sinh khóa còn tùy schema/câu lệnh |
| `ResultSet` cuộn | `supportsResultSetType(ResultSet.TYPE_SCROLL_INSENSITIVE)` | Kiểm tra theo type; loại `TYPE_FORWARD_ONLY` phổ biến hơn |
| `ResultSet` cập nhật | `supportsResultSetConcurrency(type, ResultSet.CONCUR_UPDATABLE)` | Cần kết hợp đúng `type` và `concurrency`; SQL cụ thể vẫn có giới hạn |
| Giữ cursor sau commit | `supportsResultSetHoldability(ResultSet.HOLD_CURSORS_OVER_COMMIT)` | Tùy driver và giao dịch |
| Stored procedure | `supportsStoredProcedures()` | Còn tùy DBMS và quyền thực thi |
| REF CURSOR | `supportsRefCursors()` | API JDBC 4.2, có thể trả về `false` |
| Sharding JDBC 4.3 | `supportsSharding()` | API từ Java 9; mặc định trả `false` nếu driver không override |
| Kiểu dữ liệu DBMS | `getTypeInfo()` | Trả `ResultSet` mô tả các SQL type |
| Danh mục bảng/cột | `getTables(...)` / `getColumns(...)` | Trả `ResultSet`; kết quả phụ thuộc schema, quyền và pattern |

Nếu ứng dụng cần nhiều tính năng, nên tạo **capability matrix** từ kết quả trên ở môi trường thực tế, chẳng hạn theo driver version, database server version, connection URL options. Trong code runtime, ưu tiên kiểm tra **tính năng mà use case thực sự cần**, thay vì giả định chỉ dựa vào một chuỗi phiên bản.

## 4. Điểm mới có liên quan trực tiếp đến JDBC 4.3

JDBC 4.3 bổ sung các khả năng sau, vẫn có ý nghĩa khi phát triển ứng dụng Java ngày nay:

1. **`DatabaseMetaData.supportsSharding()`**: trả `true` nếu driver và database hỗ trợ sharding thông qua JDBC; implementation mặc định trả `false`. Đây là phép hỏi phù hợp trước khi cân nhắc `ShardingKey` và các API liên quan. Việc database tự chia shard theo cơ chế vendor không nhất thiết đồng nghĩa các **JDBC sharding API** được hỗ trợ.
2. **`Connection.beginRequest()` / `endRequest()`**: đánh dấu ranh giới một đơn vị xử lý; hữu ích chủ yếu cho driver/pool quản lý trạng thái connection. **Implementation mặc định là no-op**; gọi không ném lỗi **không chứng minh** driver có hành vi tối ưu hóa request boundary. Theo Javadoc, API này mang tính gợi ý, không yêu cầu ứng dụng tự bọc mọi câu lệnh. Nếu kết nối được quản lý bởi pool/framework, tuân theo vòng đời mà framework đó quy định.
3. **Connection builder và sharding builder:** các giao diện như `ConnectionBuilder`, `ShardingKey` và `ShardingKeyBuilder` hỗ trợ tạo kết nối theo thông số và khóa sharding khi vendor triển khai. Không phải driver 4.3 nào cũng hỗ trợ các API này; các lời gọi không hỗ trợ có thể ném `SQLFeatureNotSupportedException`.
4. **`DriverManager.drivers()`:** trả về `Stream<Driver>` cho các driver hiện có mà caller truy cập được; tiện kiểm tra nạp driver trong ứng dụng.
5. **Các hàm quote trên `Statement`:** ví dụ `enquoteIdentifier(name, true)`, `enquoteLiteral(value)`; dùng theo hợp đồng API/provider khi cần biểu diễn identifier/literal. **PreparedStatement với tham số** vẫn là lựa chọn chuẩn cho dữ liệu người dùng; các hàm quote không thay thế parameter binding.

Không có một “cờ JDBC 4.3” nào bảo đảm tất cả các phương thức trên đều có hành vi thực sự. `DatabaseMetaData` là điểm khởi đầu và tài liệu/kiểm thử của driver là nguồn xác nhận cuối cùng.

## 5. Ví dụ Java 17+: kiểm tra driver và metadata trên kết nối thật

Chương trình sau:

- Nhận **một JDBC URL** từ dòng lệnh và lấy tài khoản/mật khẩu từ biến môi trường, không ghi mật khẩu ra console.
- Kiểm tra driver ứng viên qua `DriverManager.getDriver(url)`, rồi kết nối thật bằng `DriverManager.getConnection(...)`.
- In tên/phiên bản driver, database và phiên bản JDBC được công bố.
- Dùng `DatabaseMetaData` để kiểm tra transaction, savepoint, batch, generated keys, result set, isolation, REF CURSOR và sharding.
- Phân biệt `YES`, `NO`, `UNKNOWN (unsupported API)` và `UNKNOWN (SQLState=...)`. Một phương thức `supports...()` ném exception không được tùy tiện quy thành `false`.
- Đóng connection bằng `try-with-resources`.

Lưu thành file **`JdbcCapabilityCheck.java`**:

```java
import java.sql.Connection;
import java.sql.DatabaseMetaData;
import java.sql.Driver;
import java.sql.DriverManager;
import java.sql.ResultSet;
import java.sql.SQLException;
import java.sql.SQLFeatureNotSupportedException;
import java.util.Properties;

public class JdbcCapabilityCheck {
    @FunctionalInterface
    interface SqlProbe {
        boolean check() throws SQLException;
    }

    private static void probe(String label, SqlProbe action) {
        try {
            System.out.printf("%-28s %s%n", label, action.check() ? "YES" : "NO");
        } catch (SQLFeatureNotSupportedException ex) {
            System.out.printf("%-28s UNKNOWN (unsupported API)%n", label);
        } catch (SQLException ex) {
            System.out.printf("%-28s UNKNOWN (SQLState=%s)%n",
                    label, ex.getSQLState());
        }
    }

    public static void main(String[] args) {
        if (args.length != 1) {
            System.out.println("Usage: java JdbcCapabilityCheck <jdbc-url>");
            return;
        }

        String url = args[0];
        Properties options = new Properties();
        if (System.getenv("JDBC_USER") != null) {
            options.setProperty("user", System.getenv("JDBC_USER"));
        }
        if (System.getenv("JDBC_PASSWORD") != null) {
            options.setProperty("password", System.getenv("JDBC_PASSWORD"));
        }

        DriverManager.setLoginTimeout(10); // Driver-dependent; not a hard timeout.
        try {
            Driver candidate = DriverManager.getDriver(url);
            System.out.println("Candidate driver class: "
                    + candidate.getClass().getName());

            try (Connection connection = DriverManager.getConnection(url, options)) {
                DatabaseMetaData md = connection.getMetaData();
                System.out.println("Driver: " + md.getDriverName()
                        + " | " + md.getDriverVersion());
                System.out.println("Database: " + md.getDatabaseProductName()
                        + " | " + md.getDatabaseProductVersion());
                System.out.println("Advertised JDBC: "
                        + md.getJDBCMajorVersion() + "."
                        + md.getJDBCMinorVersion());

                probe("Connection valid (2 s)", () -> connection.isValid(2));
                probe("Transactions", md::supportsTransactions);
                probe("Savepoints", md::supportsSavepoints);
                probe("Batch updates", md::supportsBatchUpdates);
                probe("Generated keys", md::supportsGetGeneratedKeys);
                probe("Scroll-insensitive ResultSet", () ->
                        md.supportsResultSetType(ResultSet.TYPE_SCROLL_INSENSITIVE));
                probe("Scrollable + updatable", () ->
                        md.supportsResultSetConcurrency(
                            ResultSet.TYPE_SCROLL_INSENSITIVE,
                            ResultSet.CONCUR_UPDATABLE));
                probe("Repeatable-read isolation", () ->
                        md.supportsTransactionIsolationLevel(
                            Connection.TRANSACTION_REPEATABLE_READ));
                probe("REF CURSOR", md::supportsRefCursors);
                probe("Sharding (JDBC 4.3)", md::supportsSharding);
            }
        } catch (SQLException ex) {
            System.err.println("Cannot inspect JDBC connection: SQLState="
                    + ex.getSQLState() + ", vendorCode=" + ex.getErrorCode());
            System.exit(1);
        }
    }
}
```

### Biên dịch và chạy

Cần **JDK 17+**, JAR của JDBC driver tương thích Java bạn dùng, một database chạy thật và tài khoản có quyền đăng nhập. Java SE có API JDBC nhưng **không kèm driver cho PostgreSQL/MySQL/SQL Server...**; phải thêm driver do nhà cung cấp tương ứng phân phối. Dùng driver được hỗ trợ ở phiên bản Java/DBMS hiện tại; tránh giữ bản driver cũ chỉ vì ứng dụng đã từng kết nối được.

Biên dịch (không cần driver JAR nếu chỉ dùng các API chuẩn trong mã trên):

```bash
javac -encoding UTF-8 JdbcCapabilityCheck.java
java JdbcCapabilityCheck
```

Khi không truyền URL, stdout **chính xác** là:

```text
Usage: java JdbcCapabilityCheck <jdbc-url>
```

Với driver JAR được lưu trong thư mục `lib` và PostgreSQL làm **ví dụ URL** (đổi thành URL/database và driver của bạn):

```bash
# Linux/macOS: dấu : ngăn cách các mục classpath
export JDBC_USER=app_reader
# Đặt JDBC_PASSWORD qua secret manager hoặc môi trường chạy.
java -cp ".:lib/*" JdbcCapabilityCheck "jdbc:postgresql://localhost:5432/appdb"
```

Với Windows, classpath dùng dấu `;`:

```powershell
$env:JDBC_USER = "app_reader"
# Đặt JDBC_PASSWORD trong môi trường an toàn của phiên chạy.
java -cp ".;lib/*" JdbcCapabilityCheck "jdbc:postgresql://localhost:5432/appdb"
```

**Kết quả khi kết nối thật không có stdout cố định**: tên driver, phiên bản database và các giá trị `YES`/`NO` phụ thuộc vendor, phiên bản driver/server và cấu hình. Không được lấy một ví dụ kết quả giả định để kết luận khả năng của hệ thống đang triển khai.

### Cách đọc kết quả

- **`YES`**: metadata báo tính năng được hỗ trợ trong tổ hợp đang kết nối. Kiểm tra behavior thật nếu tính năng mang tính quyết định.
- **`NO`**: metadata báo không hỗ trợ; với default method như `supportsSharding()`, đây cũng có thể là giá trị mặc định mà driver chưa override. Không tự thử các API sharding rồi coi chúng chắc chắn khả dụng.
- **`UNKNOWN (unsupported API)`**: driver ném `SQLFeatureNotSupportedException` khi được hỏi; không có cơ sở kết luận có hỗ trợ.
- **`UNKNOWN (SQLState=...)`**: truy vấn metadata thất bại do một lỗi SQL khác. Xem `SQLState`, vendor code, log ở môi trường an toàn và tài liệu nhà cung cấp, rồi kiểm tra lại.
- **`Connection valid (2 s)`**: trạng thái kết nối; đây **không phải** kiểm tra tính năng của JDBC 4.3.

`DriverManager.getDriver(url)` chỉ tìm driver **ứng viên** nhận diện URL. Driver mà `getConnection` thực sự sử dụng nên được nhận diện qua `DatabaseMetaData.getDriverName()`, vì driver có thể thay đổi theo cấu hình runtime hoặc cơ chế pool/proxy.

Trong ứng dụng có connection pool, ưu tiên lấy `Connection` từ `DataSource` mà ứng dụng thực sự dùng rồi gọi `getMetaData()` tại đó. Demo chọn `DriverManager` để không phụ thuộc framework. Timeout thiết lập qua `setLoginTimeout` là giới hạn **phụ thuộc mức hỗ trợ của driver**, không phải bảo đảm cắt mọi thao tác mạng sau 10 giây.

## 6. Đọc schema, bảng, cột và kiểu dữ liệu bằng DatabaseMetaData

Ngoài kiểm tra khả năng, `DatabaseMetaData` giúp ứng dụng nhiều database tự khám phá cấu trúc khi thật sự cần:

- `getCatalogs()`, `getSchemas()`: liệt kê catalog/schema.
- `getTables(catalog, schemaPattern, tableNamePattern, types)`: lấy bảng/view phù hợp.
- `getColumns(catalog, schemaPattern, tableNamePattern, columnNamePattern)`: tên cột, `DATA_TYPE` (mã `java.sql.Types`), `TYPE_NAME`, kích thước/nullable.
- `getPrimaryKeys(...)`, `getImportedKeys(...)`, `getIndexInfo(...)`: khóa chính, khóa ngoại, chỉ mục.
- `getTypeInfo()`: các loại SQL type mà database/driver cung cấp metadata.

Ví dụ mã **minh họa, đặt bên trong scope đã có `Connection connection` và `DatabaseMetaData md`**:

```java
try (ResultSet rs = md.getTables(
        connection.getCatalog(), null, "orders", new String[] {"TABLE"})) {
    while (rs.next()) {
        System.out.println(rs.getString("TABLE_SCHEM")
                + "." + rs.getString("TABLE_NAME"));
    }
}

try (ResultSet rs = md.getColumns(
        connection.getCatalog(), null, "orders", "%")) {
    while (rs.next()) {
        System.out.printf("%s -> SQL type=%d, DB type=%s%n",
                rs.getString("COLUMN_NAME"),
                rs.getInt("DATA_TYPE"),
                rs.getString("TYPE_NAME"));
    }
}
```

Đoạn này chỉ trả kết quả nếu database hiện tại có bảng khớp pattern `orders` và tài khoản đủ quyền xem metadata; không tạo hay sửa bảng. Tên bảng là ví dụ, cần thay bằng bảng thực tế. Cần lưu ý:

1. Tham số có chữ `Pattern` dùng quy tắc JDBC `%` = nhiều ký tự và `_` = đúng một ký tự; `null` ở pattern thường có nghĩa không giới hạn theo tiêu chí đó. Khi muốn tìm tên chứa ký tự `%`/`_` thật, dùng ký tự escape mà `md.getSearchStringEscape()` trả về.
2. Một số DBMS tự đổi tên identifier thành chữ hoa/chữ thường hoặc phân biệt chữ hoa với dấu quote. Kiểm tra `storesUpperCaseIdentifiers()`, `storesLowerCaseIdentifiers()` và chính sách schema/database trước khi cho rằng bảng không tồn tại.
3. `getTables`/`getColumns` trả `ResultSet`. Luôn dùng `try-with-resources` để đóng, kiểm tra các nhãn cột theo chuẩn JDBC; driver có thể bổ sung cột riêng. Metadata không tìm được có thể là `ResultSet` rỗng, không phải lúc nào cũng là lỗi.
4. Trên database lớn, truy vấn metadata có thể tốn thời gian và chịu giới hạn quyền; lọc schema/table pattern cụ thể, cache kết quả khi hợp lý, làm mới khi có thay đổi schema.

**Phân biệt ba loại metadata:** `DatabaseMetaData` mô tả database/driver và schema; `ResultSetMetaData` mô tả các cột của **một kết quả query cụ thể**; `ParameterMetaData` mô tả tham số của một `PreparedStatement` và có thể thiếu chi tiết tùy driver. Không dùng `ResultSetMetaData` thay cho phép thử `supportsBatchUpdates()` hoặc `supportsSharding()`.

## 7. Quyết định sử dụng tính năng và kiểm thử hành vi thật

### Chọn đường xử lý từ metadata

Ví dụ muốn gộp nhiều câu lệnh ghi: trước hết đọc `supportsBatchUpdates()`. Nếu trả `true` thì code có thể dùng `PreparedStatement.addBatch()` và `executeBatch()`; nếu `false`, chọn giải pháp tương thích là thực thi từng lệnh (cân nhắc transaction). Nhưng vẫn phải thiết kế xử lý `BatchUpdateException` và quan sát `updateCounts`, vì batch có thể thất bại một phần, phụ thuộc driver/server.

Khi cần `ResultSet` cập nhật, không chỉ hỏi `supportsResultSetType(type)` mà còn hỏi `supportsResultSetConcurrency(type, CONCUR_UPDATABLE)` **trên cùng type**. Ngay cả khi cả hai trả `true`, một truy vấn join phức tạp vẫn có thể tạo result set chỉ đọc. Hãy dùng `ResultSet.getConcurrency()` của đối tượng thực tế hoặc integration test phù hợp.

Khi cần transaction có isolation đặc biệt, hỏi `supportsTransactions()` và `supportsTransactionIsolationLevel(level)` trước khi gọi `setTransactionIsolation(level)`. Lưu ý DDL và isolation semantics khác nhau giữa các DBMS; thử trên môi trường kiểm thử thay vì giả định tất cả lệnh đều rollback được.

### Kiểm thử tính năng tùy chọn của JDBC 4.3

- Với **sharding**, dùng `md.supportsSharding()` trước. Nếu `true`, kiểm tra tiếp tài liệu driver/provider về cách tạo `ShardingKeyBuilder`, phân vùng, topology và yêu cầu server. Không gọi `Connection.setShardingKey(...)` tùy tiện giữa transaction hoặc trên connection đang có state.
- Với **request boundary**, lời gọi `beginRequest()/endRequest()` thành công chưa chứng minh có tối ưu hóa; default implementation là no-op. Nếu pool/framework đã quản lý ranh giới request, tránh gọi chồng chéo.
- Với **connection builder**, gọi API tương ứng trên `DataSource` trong kiểm thử tích hợp, bắt `SQLFeatureNotSupportedException` nếu driver không triển khai. Không thể dùng một boolean `supportsConnectionBuilder()` trên `DatabaseMetaData` vì API này **không tồn tại**.
- Với **identifier quoting**, có thể tận dụng `Statement.enquoteIdentifier(...)` tùy provider; luôn dùng `PreparedStatement` cho giá trị do người dùng nhập.

Một **smoke test** đáng tin cần chỉ rõ: driver artifact/version, JDK, DBMS/version, JDBC URL options, quyền tài khoản, giá trị metadata trả về, và thao tác/SQL cụ thể đã chạy. Tách riêng “metadata báo YES” với “integration test PASS” trong báo cáo.

## 8. Lỗi phổ biến và cách xử lý

| Hiện tượng | Giải thích khả dĩ | Cách kiểm tra |
| --- | --- | --- |
| `No suitable driver` | Thiếu driver JAR runtime, sai JDBC URL prefix hoặc driver không được class loader nạp | Kiểm tra dependency runtime, `DriverManager.drivers()` và URL vendor |
| Driver có mặt nhưng không kết nối được | Cấu hình mạng, TLS, tài khoản, quyền hoặc DBMS không sẵn sàng | Xem `SQLState`/vendor code; thử kết nối qua cấu hình triển khai thật |
| Driver báo JDBC `4.3` nhưng sharding là `false` | Hỗ trợ API version không đồng nghĩa hỗ trợ sharding; `supportsSharding()` có default false | Kiểm tra tài liệu tính năng của **đúng phiên bản driver và DBMS** |
| Gọi `beginRequest()` thành công nhưng không thấy hiệu ứng | Default no-op hoặc driver/pool không có logic bổ sung | Xem mô tả vendor; không dùng lời gọi này như phép kiểm tra support |
| `supportsBatchUpdates()=true` nhưng batch lỗi | SQL, transaction, quyền, giới hạn hoặc dữ liệu thực tế gây lỗi | Kiểm thử batch thật; xử lý `BatchUpdateException`/`updateCounts` |
| `getTables(...)` không thấy bảng | Sai catalog/schema, case, pattern hoặc quyền metadata | Dò schema phù hợp; điều chỉnh pattern, quyền, identifier case |
| Metadata method ném `SQLFeatureNotSupportedException` | Driver không triển khai lời gọi đó | Trả trạng thái UNKNOWN, dùng fallback và xem tài liệu vendor |
| Môi trường dev OK, production lỗi | Khác driver JAR, phiên bản server, classpath, connection URL options hoặc quyền | Ghi lại capability matrix trên môi trường production tương đương |
| Dùng `getDriverVersion()` thay cho `getJDBCMinorVersion()` | Nhầm phiên bản driver vendor với chuẩn JDBC | In riêng cả hai trường như chương trình mẫu |

## 9. Checklist triển khai

1. Đặt đúng driver artifact được nhà cung cấp hỗ trợ trong runtime; dùng URL phù hợp và không đưa mật khẩu vào log.
2. Thử kết nối **qua cùng `DataSource`/pool** mà ứng dụng chạy thật sẽ sử dụng; đối chiếu product/driver/JDBC version.
3. Đối với **mỗi yêu cầu nghiệp vụ** (batch, transaction, savepoint, sharding...), chọn đúng phương thức `DatabaseMetaData` và xử lý cả `SQLException`/`SQLFeatureNotSupportedException`.
4. Ghi kết quả capability matrix; có fallback được kiểm thử nếu `false` hoặc `UNKNOWN`.
5. Làm integration test đối với hành vi quan trọng bằng schema/test data và quyền tương đương production; chạy lại khi nâng driver/JDK/DBMS.
6. Xem các đặc điểm tùy chọn của JDBC 4.3 như **sharding/request boundary** theo tài liệu vendor; không dựa vào mỗi phiên bản API.
7. Đóng `Connection`/`ResultSet` đúng cách; giới hạn phạm vi truy vấn metadata trên DBMS lớn.

## 10. Tài liệu chuẩn còn áp dụng

- Oracle Java SE: [`DatabaseMetaData` (Java 26)](https://docs.oracle.com/en/java/javase/26/docs/api/java.sql/java/sql/DatabaseMetaData.html), giải thích kết quả là khả năng của driver kết hợp với DBMS và các `supports...()`.
- Oracle Java SE: [`java.sql` (Java 25)](https://docs.oracle.com/en/java/javase/25/docs/api/java.sql/java/sql/package-summary.html), liệt kê phần bổ sung của JDBC 4.3 trong Java 9.
- Oracle Java SE: [`DriverManager` (Java 25)](https://docs.oracle.com/en/java/javase/25/docs/api/java.sql/java/sql/DriverManager.html), service loading, `getDriver`, `getConnection` và `drivers()`.
- Oracle Java SE: [`Connection` (Java 24)](https://docs.oracle.com/en/java/javase/24/docs/api/java.sql/java/sql/Connection.html), hành vi của `beginRequest`/`endRequest` và sharding methods.
- Nếu dùng một DBMS/driver cụ thể, đối chiếu **bảng tương thích cập nhật của vendor** trước khi bật tính năng tùy chọn, ví dụ [Microsoft JDBC Driver for SQL Server](https://learn.microsoft.com/en-us/sql/connect/jdbc/microsoft-jdbc-driver-for-sql-server) hoặc [Oracle JDBC Standards Support](https://docs.oracle.com/en/database/oracle/oracle-database/26/jjdbc/JDBC-standards-support.html).
