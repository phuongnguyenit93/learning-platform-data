# Kiểm thử driver, metadata, giao dịch và giải phóng tài nguyên

Một ứng dụng JDBC chạy đúng trên máy phát triển chưa chứng minh rằng nó tương thích với driver và database production. Driver có thể hỗ trợ một phần JDBC API, database có thể khác về SQL grammar hoặc isolation level, và một số tính năng chỉ được hỗ trợ tùy cấu hình. Vì vậy, cần kiểm tra phiên bản driver, metadata, khả năng thực tế, ranh giới giao dịch và vòng đời tài nguyên.

Java SE 26 đưa JDBC lên **JDBC 4.5**. Phiên bản này bổ sung các khả năng hữu ích cho việc quản lý tài nguyên và làm việc với kiểu dữ liệu SQL mới: Array, Blob, Clob, NClob và SQLXML triển khai AutoCloseable; JDBCType và Types có thêm JSON và DECFLOAT; Connection có các phương thức quote literal và identifier. Đây là API chính thức của Java SE 26, không phải preview hay incubator. Tuy vậy, việc API tồn tại trong JDK không có nghĩa mọi driver/database đều hỗ trợ mọi tính năng.

## 1. Phân biệt phiên bản JDK, JDBC API, driver và database

Có bốn phiên bản cần theo dõi riêng:

| Thành phần | Cách nhận biết | Ý nghĩa |
|---|---|---|
| JDK | Runtime.version() hoặc java -version | API Java mà ứng dụng có thể biên dịch và chạy |
| JDBC API | JDBC version trong Java SE và DatabaseMetaData.getJDBCMajorVersion()/getJDBCMinorVersion() | Hợp đồng API JDBC mà driver khai báo hỗ trợ |
| JDBC driver | Tên và version từ DatabaseMetaData.getDriverName()/getDriverVersion() | Implementation kết nối đến database |
| Database server | Tên và version từ getDatabaseProductName()/getDatabaseProductVersion() | SQL grammar, kiểu dữ liệu, isolation và tính năng thực tế của server |

JDBC 4.5 được tích hợp trong Java SE 26. JDBC 4.4 thuộc Java SE 24; JDBC 4.3 thuộc Java SE 9. Một ứng dụng chạy trên JDK 26 vẫn có thể nạp một driver cũ hơn và driver đó có thể không hỗ trợ một số API hoặc SQL type mới. Ngược lại, driver có version mới không làm database server tự có thêm kiểu dữ liệu hoặc tính năng SQL.

Không nên suy luận khả năng từ tên JAR hoặc số version của JDK. Hãy đọc metadata lúc khởi tạo kết nối, ghi nhận trong diagnostics và kiểm tra các tính năng ứng dụng thật sự sử dụng.

## 2. Lấy metadata của driver và database

DatabaseMetaData mô tả khả năng của một cặp driver/database cụ thể. Nó hữu ích cho logging, compatibility check, migration và công cụ cần làm việc với nhiều DBMS.

```java
import java.sql.Connection;
import java.sql.DatabaseMetaData;
import java.sql.SQLException;

static void printJdbcEnvironment(Connection connection)
        throws SQLException {
    DatabaseMetaData md = connection.getMetaData();

    System.out.printf(
            "JDBC=%d.%d, driver=%s %s, database=%s %s%n",
            md.getJDBCMajorVersion(),
            md.getJDBCMinorVersion(),
            md.getDriverName(),
            md.getDriverVersion(),
            md.getDatabaseProductName(),
            md.getDatabaseProductVersion());

    System.out.printf(
            "transactions=%s, savepoints=%s, batch=%s%n",
            md.supportsTransactions(),
            md.supportsSavepoints(),
            md.supportsBatchUpdates());

    System.out.printf(
            "READ_COMMITTED=%s, SERIALIZABLE=%s%n",
            md.supportsTransactionIsolationLevel(
                    Connection.TRANSACTION_READ_COMMITTED),
            md.supportsTransactionIsolationLevel(
                    Connection.TRANSACTION_SERIALIZABLE));
}
```

Nên lưu những thông tin này cùng phiên bản ứng dụng, cấu hình kết nối và môi trường triển khai. Không ghi URL kết nối có password, access token hoặc thông tin xác thực vào log.

Các phương thức metadata hữu ích khác:

- supportsResultSetType(...) và supportsResultSetConcurrency(...): kiểm tra loại/concurrency của ResultSet.
- supportsResultSetHoldability(...): kiểm tra cursor có thể giữ qua commit hay phải đóng.
- supportsGetGeneratedKeys(): kiểm tra khả năng lấy generated keys.
- supportsBatchUpdates(): kiểm tra batch update.
- supportsSavepoints(): kiểm tra savepoint.
- supportsTransactionIsolationLevel(level): kiểm tra isolation level.
- getIdentifierQuoteString(): lấy delimiter quote identifier theo database.
- getSQLStateType(): xác định kiểu SQLState driver trả về.

Metadata là tín hiệu để chọn đường xử lý, không phải bằng chứng tuyệt đối rằng mọi trường hợp sử dụng đều chạy đúng. Một driver có thể khai báo hỗ trợ nhưng có giới hạn theo loại cột, phiên bản server, cấu hình hoặc transaction mode. Hãy kiểm thử integration trên đúng driver và database version production.

## 3. Kiểm tra kết nối và lỗi JDBC

Connection.isClosed() chỉ cho biết đối tượng connection đã được đóng theo vòng đời JDBC hay chưa; nó không phải phép thử đáng tin cậy để xác định database còn truy cập được. Dùng Connection.isValid(timeoutSeconds) để yêu cầu driver xác minh kết nối:

```java
static boolean isConnectionUsable(Connection connection)
        throws SQLException {
    return !connection.isClosed() && connection.isValid(3);
}
```

Driver có thể thực hiện thao tác kiểm tra phù hợp với database. Timeout của isValid được tính bằng giây. Không gọi kiểm tra quá thường xuyên trên mỗi câu query nếu connection pool đã có validation policy; điều đó có thể tạo thêm round trip không cần thiết.

Khi xử lý lỗi, kiểm tra cả loại exception, SQLState, vendor error code và chuỗi exception tiếp theo:

```java
import java.sql.SQLException;

static void logSqlFailure(SQLException exception) {
    for (SQLException current = exception;
         current != null;
         current = current.getNextException()) {

        System.err.printf(
                "type=%s, SQLState=%s, vendorCode=%d, message=%s%n",
                current.getClass().getSimpleName(),
                current.getSQLState(),
                current.getErrorCode(),
                current.getMessage());
    }
}
```

Các nhóm exception thường gặp:

| Exception | Ý nghĩa thường gặp | Cách xử lý |
|---|---|---|
| SQLTransientException | Lỗi có thể tạm thời | Chỉ retry khi transaction và thao tác có thể retry an toàn |
| SQLNonTransientException | Retry cùng thao tác thường không giải quyết được nguyên nhân | Sửa SQL, quyền, schema, kiểu dữ liệu hoặc cấu hình |
| SQLRecoverableException | Có thể phục hồi bằng cách thiết lập lại kết nối/thực hiện lại toàn bộ transaction | Hủy connection lỗi, lấy connection mới và áp dụng chính sách idempotency |
| SQLIntegrityConstraintViolationException | Vi phạm constraint | Xử lý xung đột nghiệp vụ; không retry vô hạn |
| SQLTimeoutException | Timeout ở login, query hoặc thao tác liên quan | Kiểm tra trạng thái statement/transaction và hủy hoặc rollback theo chính sách |
| SQLFeatureNotSupportedException | Driver/database không hỗ trợ tính năng được gọi | Chọn fallback đã kiểm thử hoặc từ chối tính năng rõ ràng |

Không retry mù quáng một lệnh ghi khi client mất kết nối trong lúc commit(): server có thể đã commit nhưng phản hồi không đến được client. Khi kết quả commit không xác định, cần thiết kế idempotency key, truy vấn xác minh trạng thái hoặc quy trình reconciliation phù hợp.

## 4. Kiểm tra khả năng thực tế thay vì chỉ đọc version

Trước khi bật một tính năng mới, hãy xác minh theo ba lớp:

1. **API có trong JDK:** mã biên dịch với JDK mục tiêu và method/type có trong Java SE API.
2. **Driver khai báo hỗ trợ:** metadata, tài liệu phát hành và cấu hình driver cho biết khả năng tương ứng.
3. **Database thực thi đúng:** integration test chạy thao tác thật, xác nhận dữ liệu round-trip, lỗi, transaction và hiệu năng ở mức cần thiết.

Với tính năng tùy chọn, xử lý SQLFeatureNotSupportedException ở ranh giới adapter/driver. Không nuốt exception rồi giả định dữ liệu đã được lưu. Nếu tính năng là bắt buộc đối với nghiệp vụ, fail fast trong quá trình khởi động hoặc deployment validation.

Một kiểm tra smoke test có thể xác nhận thông tin môi trường, mở transaction, thực hiện thao tác ghi/đọc thử trong bảng test riêng, rollback và kiểm tra connection có thể tiếp tục sử dụng. Không dùng bảng nghiệp vụ thật hoặc transaction chứa side effect bên ngoài để chạy smoke test.

## 5. Giao dịch: auto-commit, commit và rollback

Mặc định, connection JDBC mới ở chế độ auto-commit. Mỗi statement được thực thi như một transaction riêng. Để nhóm nhiều thao tác thành một đơn vị nguyên tử, tắt auto-commit, thực hiện các thao tác, rồi commit hoặc rollback:

```java
import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.SQLException;
import javax.sql.DataSource;

static void transfer(
        DataSource dataSource,
        long fromAccount,
        long toAccount,
        long amount) throws SQLException {

    try (Connection connection = dataSource.getConnection()) {
        connection.setAutoCommit(false);
        try {
            try (PreparedStatement debit = connection.prepareStatement(
                    "UPDATE account SET balance = balance - ? WHERE id = ?");
                 PreparedStatement credit = connection.prepareStatement(
                    "UPDATE account SET balance = balance + ? WHERE id = ?")) {

                debit.setLong(1, amount);
                debit.setLong(2, fromAccount);
                if (debit.executeUpdate() != 1) {
                    throw new SQLException("Source account was not updated");
                }

                credit.setLong(1, amount);
                credit.setLong(2, toAccount);
                if (credit.executeUpdate() != 1) {
                    throw new SQLException("Destination account was not updated");
                }
            }

            connection.commit();
        } catch (SQLException | RuntimeException failure) {
            try {
                connection.rollback();
            } catch (SQLException rollbackFailure) {
                failure.addSuppressed(rollbackFailure);
            }
            throw failure;
        }
    }
}
```

Ví dụ minh họa cấu trúc transaction; hệ thống thật còn phải kiểm tra số dư không âm, khóa hàng, chống chuyển trùng, currency, authorization và chính sách retry. Các ràng buộc nghiệp vụ nên được bảo vệ trong database bằng constraint hoặc câu lệnh cập nhật có điều kiện khi phù hợp.

Một số điểm quan trọng:

- commit() chỉ dùng khi auto-commit đang tắt.
- rollback() hoàn tác các thay đổi kể từ commit/rollback trước đó.
- close() connection khi transaction vẫn hoạt động có kết quả implementation-defined. Hãy commit hoặc rollback tường minh trước khi trả connection.
- Đổi setAutoCommit(false) thành true trong lúc transaction đang hoạt động có thể commit transaction hiện tại. Không bật lại auto-commit trước khi đã quyết định commit/rollback.
- Không thay đổi isolation level giữa một transaction đang hoạt động; kết quả khi gọi setTransactionIsolation trong transaction là implementation-defined.

Nếu connection được quản lý bởi JTA hoặc transaction manager, để transaction manager quản lý commit/rollback. Không gọi commit(), rollback() hoặc đổi auto-commit trực tiếp trên connection tham gia distributed transaction.

## 6. Kiểm thử rollback, savepoint và isolation

Một integration test transaction nên xác nhận trạng thái dữ liệu sau cả commit lẫn rollback:

| Ca kiểm thử | Thao tác | Kết quả mong đợi |
|---|---|---|
| Commit | Tắt auto-commit, ghi dữ liệu, commit | Connection khác nhìn thấy dữ liệu đã commit theo isolation |
| Rollback | Tắt auto-commit, ghi dữ liệu, rollback | Dữ liệu thay đổi trong transaction không còn |
| Constraint failure | Gây lỗi có kiểm soát giữa transaction | Ứng dụng rollback và không để lại trạng thái một phần |
| Savepoint | Tạo savepoint, thực hiện bước phụ, rollback về savepoint | Thay đổi trước savepoint còn; thay đổi sau savepoint bị hoàn tác |
| Isolation | Dùng hai connection thực hiện lịch đọc/ghi đồng thời | Hành vi phù hợp isolation level và database đã cấu hình |

Savepoint là tính năng tùy chọn; kiểm tra supportsSavepoints() trước khi phụ thuộc vào nó:

```java
import java.sql.Connection;
import java.sql.DatabaseMetaData;
import java.sql.Savepoint;
import java.sql.SQLException;
import java.sql.SQLFeatureNotSupportedException;
import javax.sql.DataSource;

try (Connection connection = dataSource.getConnection()) {
    DatabaseMetaData metadata = connection.getMetaData();
    if (!metadata.supportsSavepoints()) {
        throw new SQLFeatureNotSupportedException(
                "This workflow requires savepoints");
    }

    connection.setAutoCommit(false);
    try {
        performRequiredChanges(connection);

        Savepoint optionalStep = connection.setSavepoint("optional_step");
        try {
            performOptionalChanges(connection);
        } catch (SQLException optionalFailure) {
            connection.rollback(optionalStep);
            // Ghi nhận lỗi tùy chọn; transaction chính vẫn có thể tiếp tục.
        } finally {
            connection.releaseSavepoint(optionalStep);
        }

        connection.commit();
    } catch (SQLException | RuntimeException failure) {
        try {
            connection.rollback();
        } catch (SQLException rollbackFailure) {
            failure.addSuppressed(rollbackFailure);
        }
        throw failure;
    }
}
```

Không giả định mọi DBMS triển khai isolation level với cùng hiệu năng hoặc cùng chi tiết locking. supportsTransactionIsolationLevel() cho biết driver/database khai báo hỗ trợ mức đó; integration test với hai connection mới kiểm chứng được hành vi trong workload của ứng dụng.

## 7. Kiểm tra batch update và generated keys

supportsBatchUpdates() và supportsGetGeneratedKeys() giúp xác định khả năng được driver công bố. Nhưng cần kiểm thử thêm trường hợp batch lỗi ở giữa:

- executeBatch() có thể ném BatchUpdateException; getUpdateCounts() cho biết kết quả từng phần tử theo hợp đồng driver.
- Không giả định batch luôn atomic. Nếu cần all-or-nothing, chạy batch trong transaction và rollback khi có lỗi.
- Kiểm tra generated key được trả về với đúng số lượng và đúng thứ tự theo driver/database; không suy đoán key từ số dòng đã cập nhật.
- Kiểm tra giới hạn batch size, parameter count, timeout và memory khi chạy dữ liệu lớn.

Batch giúp giảm round trip, nhưng không phải lúc nào cũng nhanh hơn. Đo với dữ liệu, kích thước batch và database gần production.

## 8. JDBC 4.5: kiểu JSON và DECFLOAT

Java SE 26 bổ sung JDBCType.JSON, JDBCType.DECFLOAT và các hằng Types.JSON, Types.DECFLOAT. Chúng giúp biểu diễn hai kiểu SQL tổng quát trong API JDBC:

```java
import java.sql.JDBCType;
import java.sql.PreparedStatement;
import java.sql.ResultSet;

String json = """
        {"orderId":"A-1042","state":"PAID"}
        """;

try (PreparedStatement statement = connection.prepareStatement(
        "INSERT INTO event_log(payload) VALUES (?)")) {
    statement.setObject(1, json, JDBCType.JSON);
    statement.executeUpdate();
}

try (PreparedStatement statement = connection.prepareStatement(
        "SELECT payload FROM event_log WHERE event_id = ?")) {
    statement.setLong(1, eventId);
    try (ResultSet result = statement.executeQuery()) {
        if (result.next()) {
            Object payload = result.getObject("payload");
            // Kiểu Java cụ thể phụ thuộc mapping của driver.
        }
    }
}
```

Đoạn mã chỉ chạy khi database có cột JSON và driver hỗ trợ mapping JSON tương ứng. Không phải mọi database đều có kiểu JSON native; một số hệ thống lưu JSON dưới dạng text, binary hoặc kiểu riêng của vendor. Hãy kiểm tra kiểu cột, binding, truy vấn, index và round-trip trên driver thực tế.

DECFLOAT là kiểu số thập phân dấu phẩy động được database hỗ trợ. Không giả định nó tương đương DOUBLE, FLOAT hay DECIMAL; cách làm tròn, precision, scale, special values và Java mapping phụ thuộc driver/database. Chọn Java type theo tài liệu driver, sau đó test các giá trị biên và round-trip.

Việc JDBCType.JSON và DECFLOAT có trong JDK 26 chỉ có nghĩa JDBC API nhận diện được type code. Nó không cài đặt JSON engine hoặc DECFLOAT vào database và cũng không buộc mọi driver phải hỗ trợ chúng.

## 9. JDBC 4.5: quote identifier và literal bằng Connection

JDK 26 bổ sung các phương thức trên Connection để quote identifier và literal theo quy tắc driver/database:

- isSimpleIdentifier(String): kiểm tra tên có phải simple SQL identifier hay không.
- enquoteIdentifier(String, boolean): trả về identifier hợp lệ hoặc identifier đã được delimiter.
- enquoteLiteral(String): quote string literal và escape dấu nháy đơn.
- enquoteNCharLiteral(String): quote national character literal với tiền tố N.

Ví dụ:

```java
String identifier = connection.enquoteIdentifier("order detail", true);
String literal = connection.enquoteLiteral("O'Reilly");
String nationalLiteral = connection.enquoteNCharLiteral("Đặng");
```

Kết quả quote identifier/literal phụ thuộc quy tắc của database và driver. enquoteIdentifier có thể ném SQLFeatureNotSupportedException nếu database không hỗ trợ delimited identifier hoặc SQLException nếu tên không hợp lệ. isSimpleIdentifier kiểm tra cú pháp đơn giản, không kiểm tra quyền truy cập hay tên đó có tồn tại.

Đây là tiện ích cho trường hợp phải tạo SQL động theo dialect. Với giá trị dữ liệu trong câu query thông thường, vẫn ưu tiên PreparedStatement binding. Không thay parameter binding bằng cách tự ghép kết quả enquoteLiteral vào hàng loạt câu SQL.

Quote identifier cũng không thay thế allowlist và authorization. Một identifier được quote đúng cú pháp vẫn có thể trỏ đến bảng hoặc cột mà user không được phép truy cập. Hãy chọn identifier từ danh sách do ứng dụng quản lý, kiểm tra quyền, sau đó mới dùng API quote nếu cần.

## 10. JDBC 4.5: giải phóng LOB và SQL object bằng try-with-resources

Từ JDBC 4.5 trong Java SE 26, Array, Blob, Clob, NClob và SQLXML triển khai AutoCloseable và có close() mặc định. Điều này cho phép dùng try-with-resources trực tiếp thay vì chỉ gọi free() trong finally.

Ví dụ đọc BLOB theo dạng streaming:

```java
import java.io.InputStream;
import java.nio.file.Files;
import java.nio.file.Path;
import java.sql.Blob;
import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.ResultSet;

static void downloadDocument(
        Connection connection,
        long documentId,
        Path destination) throws Exception {

    try (PreparedStatement statement = connection.prepareStatement(
            "SELECT content FROM document_store WHERE document_id = ?")) {
        statement.setLong(1, documentId);

        try (ResultSet result = statement.executeQuery()) {
            if (!result.next()) {
                throw new IllegalArgumentException("Document not found");
            }

            try (Blob blob = result.getBlob("content");
                 InputStream input = blob.getBinaryStream()) {
                try (var output = Files.newOutputStream(destination)) {
                    input.transferTo(output);
                }
            }
        }
    }
}
```

Đóng stream trước, sau đó đóng Blob, ResultSet, Statement và cuối cùng connection. Blob.close() có implementation mặc định gọi free(). Các LOB locator thường chỉ hợp lệ trong transaction đã tạo hoặc lấy chúng; hãy đọc/ghi và giải phóng trong đúng phạm vi connection/transaction.

Với Clob, NClob, SQLXML và Array, nguyên tắc tương tự: đóng stream/reader/writer được lấy ra từ object trước, sau đó đóng object JDBC. Không giữ LOB locator qua commit, rollback hoặc sau khi connection đã được trả về pool.

close() của các interface LOB có thể ném SQLFeatureNotSupportedException tùy driver. Với driver cũ hoặc khi biên dịch trên JDK trước 26, dùng API free() theo hợp đồng của phiên bản đó. Không gọi cả close() và free() như hai bước bắt buộc trên cùng một object; close() mặc định đã gọi free().

## 11. Quản lý Connection, Statement và ResultSet

Các resource JDBC nên có phạm vi sống ngắn và được đóng theo thứ tự ngược với thứ tự tạo:

```java
try (Connection connection = dataSource.getConnection();
     PreparedStatement statement = connection.prepareStatement(
             "SELECT id, name FROM customer WHERE active = ?")) {
    statement.setBoolean(1, true);

    try (ResultSet result = statement.executeQuery()) {
        while (result.next()) {
            long id = result.getLong("id");
            String name = result.getString("name");
            // Chuyển dữ liệu sang object độc lập với ResultSet.
        }
    }
}
```

Quy tắc:

- ResultSet phụ thuộc vào Statement; đóng statement sẽ đóng result set liên quan. Vẫn nên quản lý result set tường minh để ranh giới tài nguyên rõ ràng.
- Không trả ResultSet, Blob, Clob, Array, SQLXML hoặc stream gắn với chúng ra khỏi tầng repository nếu connection/transaction đã kết thúc.
- Đọc và chuyển dữ liệu cần thiết thành DTO/value object trước khi đóng JDBC resources.
- Dùng DataSource và connection pool trong ứng dụng server; gọi Connection.close() thường trả logical connection về pool, không nhất thiết đóng physical connection tới database.
- Không giữ connection trong field dùng chung, không chia sẻ một connection cho nhiều request đồng thời, và không giữ connection trong lúc chờ user hoặc gọi dịch vụ bên ngoài.
- Không dựa vào garbage collector để đóng resource; luôn dùng try-with-resources hoặc quản lý vòng đời tường minh.

## 12. Kiểm tra connection pool và request boundary

Trong ứng dụng dùng pool, DataSource.getConnection() cấp một logical connection. Khi gọi close(), pool thường reset trạng thái và đưa connection về pool. Kiểm tra pool có khôi phục các trạng thái như auto-commit, isolation level, read-only, schema/catalog, warnings và network timeout sau khi connection được trả lại hay không.

JDBC 4.3 đã có Connection.beginRequest() và endRequest() như hint cho driver về ranh giới một request độc lập; đây không phải transaction boundary. Chúng không thay thế commit()/rollback() và không đảm bảo driver sẽ reset mọi session state. Dùng theo hướng dẫn của pool/driver nếu có lợi ích; không gọi lồng nhau như transaction.

Kiểm tra các tình huống:

- Connection trả về pool sau commit.
- Connection trả về pool sau rollback.
- Query timeout hoặc network failure.
- Connection bị hủy bằng abort(Executor) hoặc bị database đóng.
- Request kết thúc khi có ResultSet/LOB còn mở.
- Nhiều request liên tiếp nhận cùng physical connection nhưng không bị rò rỉ session state.

Connection.close() khi transaction còn hoạt động có kết quả implementation-defined. Trước khi trả connection về pool, hãy bảo đảm transaction đã được commit hoặc rollback và mọi statement/result set/LOB đã đóng.

## 13. SQLPermission và SecurityManager

java.sql.SQLPermission bị deprecated for removal từ JDK 26. Class này chỉ hữu ích khi kết hợp với SecurityManager, vốn không còn được hỗ trợ. Nó không còn là cơ chế kiểm soát quyền truy cập tài nguyên và không có API thay thế trực tiếp.

Không thêm SQLPermission vào code mới, policy file hoặc hệ thống authorization. Dùng các cơ chế bảo mật đang được hỗ trợ: database users/roles, quyền tối thiểu, secret manager, TLS, network policy, application authorization và audit log. Đây là thay đổi cần lưu ý khi nâng cấp, không phải lý do để tiếp tục dùng SecurityManager hoặc permission checks cũ.

## 14. Bộ kiểm thử tích hợp nên có

Một bộ kiểm thử driver/database hữu ích nên chạy trong CI với phiên bản database và driver gần production:

| Nhóm | Kiểm tra |
|---|---|
| Driver identity | JDBC major/minor, driver name/version, database product/version |
| Connectivity | Login, isValid, network timeout, connection loss |
| Metadata | Schema/table/column, identifier quote, transaction và isolation support |
| SQL execution | Prepared statement, generated keys, batch, pagination và type mapping |
| Transactions | Commit, rollback, savepoint, constraint failure, concurrent isolation |
| JDBC 4.5 | JSON, DECFLOAT, Connection.enquote..., LOB close() |
| Resource lifecycle | ResultSet/Statement/Connection/LOB/stream đóng đúng thứ tự |
| Pool | Reset session state, connection reuse, leak detection và timeout |
| Failure behavior | SQLState, vendor code, exception chain, retry và rollback |

Test nên tạo schema riêng hoặc dùng database container cô lập. Không chạy destructive migration hoặc test transaction trên database production. Nếu ứng dụng hỗ trợ nhiều DBMS, chạy cùng contract test trên từng driver/database pair thay vì chỉ mock Connection.

## 15. Phiên bản JDBC và tính ổn định

| JDBC API | Java SE | Nội dung tiêu biểu |
|---|---|---|
| JDBC 4.3 | JDK 9 | Sharding, request boundary, DriverManager.drivers() và các khả năng metadata liên quan |
| JDBC 4.4 | JDK 24 | Cập nhật mô tả và hợp đồng liên quan SecurityManager đã không còn được hỗ trợ |
| JDBC 4.5 | JDK 26 | LOB/Array/SQLXML AutoCloseable, JSON, DECFLOAT, Connection enquote và SQLPermission deprecated for removal |

Các tính năng JDBC 4.5 trong bài là API chính thức, không cần --enable-preview. Nhưng nhiều tính năng JDBC là optional theo driver/database; luôn xác nhận driver version, metadata và integration test. Không dùng API deprecated như SQLPermission chỉ vì nó vẫn còn hiện diện trong JDK.

## 16. Những điểm cần nhớ

- Phân biệt JDK version, JDBC API version, driver version và database version.
- Dùng DatabaseMetaData để nhận diện môi trường và dò khả năng; xác nhận lại bằng integration test thật.
- isClosed() không chứng minh database còn kết nối; dùng isValid(timeout) khi cần kiểm tra.
- Tắt auto-commit cho transaction nhiều bước; commit/rollback tường minh trước khi đóng connection.
- Không đổi auto-commit hoặc isolation level trong transaction đang chạy.
- Savepoint, batch, generated keys và isolation level cần được kiểm tra theo driver/database.
- JDBC 4.5 bổ sung JDBCType.JSON, JDBCType.DECFLOAT và các hằng Types tương ứng; driver/server phải hỗ trợ mới dùng được.
- JDBC 4.5 cho phép dùng Array, Blob, Clob, NClob, SQLXML với try-with-resources; đóng stream con trước object LOB.
- Dùng Connection.enquote... khi thực sự cần quote theo dialect; parameter binding vẫn là lựa chọn chính cho giá trị.
- SQLPermission deprecated for removal vì SecurityManager không còn được hỗ trợ; dùng database roles và cơ chế authorization hiện hành.
- Dùng DataSource, connection pool và try-with-resources; không giữ JDBC resource sau transaction hoặc trả chúng ra khỏi repository.
