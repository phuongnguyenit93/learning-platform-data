# Truyền, nhận kiểu dữ liệu với cơ sở dữ liệu hỗ trợ

JDBC 4.5 được đưa vào Java SE 26. Một thay đổi quan trọng là JDBC bổ sung hai kiểu SQL tổng quát `JSON` và `DECFLOAT`, cùng các ánh xạ chuẩn để truyền và đọc chúng từ Java. Ứng dụng có thể dùng `JDBCType.JSON`, `JDBCType.DECFLOAT`, `Types.JSON` và `Types.DECFLOAT` thay vì tự đoán kiểu dữ liệu qua chuỗi hoặc số.

Hai kiểu này có ánh xạ Java khác nhau:

- SQL `JSON` được biểu diễn bằng `String` trong Java.
- SQL `DECFLOAT` được biểu diễn bằng `java.math.BigDecimal`.

JDBC 4.5 là API chuẩn, không phải preview hay incubator. Tuy nhiên, có hằng số trong JDK 26 không đồng nghĩa mọi database hoặc JDBC driver đều đã hỗ trợ kiểu SQL tương ứng. Cần xác minh cả driver lẫn database server trước khi triển khai.

## 1. Hai kiểu SQL mới trong JDBC 4.5

JDK 26 bổ sung hai hằng số vào `java.sql.JDBCType` và `java.sql.Types`:

| Kiểu SQL | `JDBCType` | `Types` | Mã JDBC |
|---|---|---|---:|
| JSON | `JDBCType.JSON` | `Types.JSON` | 2016 |
| DECFLOAT | `JDBCType.DECFLOAT` | `Types.DECFLOAT` | 2015 |

Các hằng số này có từ Java SE 26. Trong code nên dùng tên biểu tượng `JDBCType.JSON`, `Types.JSON` thay vì ghi trực tiếp số `2016`; tương tự với `DECFLOAT`. Tên hằng số giúp code dễ đọc và tránh phụ thuộc vào số mã được định nghĩa trong đặc tả.

### 1.1. JSON

`JSON` là kiểu SQL dành cho dữ liệu có cấu trúc JSON. Database có thể cung cấp khả năng kiểm tra cú pháp, truy vấn thuộc tính, lập chỉ mục hoặc thao tác JSON theo cách riêng của sản phẩm. JDBC 4.5 chuẩn hóa mã kiểu và ánh xạ Java, nhưng không định nghĩa một object model JSON trong JDK.

Ánh xạ JDBC chuẩn dùng `String`:

| Chiều dữ liệu | Java | SQL/JDBC |
|---|---|---|
| Gửi vào database | `String` chứa JSON text | `JSON` |
| Đọc từ database | `String` | `JSON` |

Nếu ứng dụng đang có `Map`, record hoặc DTO, hãy dùng thư viện JSON của dự án để serialize thành JSON text trước khi bind. Khi đọc, lấy JSON text thành `String` rồi parse bằng thư viện tương ứng. JDBC 4.5 không tự chuyển JSON text thành `Map` hoặc record Java.

### 1.2. DECFLOAT

`DECFLOAT` là kiểu số dấu phẩy động thập phân. Khác với `FLOAT`/`DOUBLE` nhị phân, kiểu thập phân phù hợp với phép tính cần giữ biểu diễn thập phân và độ chính xác tài chính. Một số hệ quản trị cung cấp các mức precision như `DECFLOAT(16)` hoặc `DECFLOAT(34)`; cú pháp và giới hạn cụ thể phụ thuộc database.

Ánh xạ JDBC chuẩn dùng `BigDecimal`:

| Chiều dữ liệu | Java | SQL/JDBC |
|---|---|---|
| Gửi vào database | `java.math.BigDecimal` | `DECFLOAT` |
| Đọc từ database | `java.math.BigDecimal` | `DECFLOAT` |

`BigDecimal` biểu diễn giá trị thập phân hữu hạn chính xác. Không tạo giá trị bằng `new BigDecimal(double)` nếu cần giữ nguyên số thập phân, vì giá trị `double` đã có thể bị làm tròn theo biểu diễn nhị phân. Dùng constructor nhận chuỗi hoặc `BigDecimal.valueOf(...)` khi đầu vào ban đầu là một số `double` đã được chấp nhận.

```java
BigDecimal amount = new BigDecimal("12345678901234567890.125");
```

Không nên đổi `DECFLOAT` sang `double` chỉ để tiện tính toán. Việc chuyển sang `double` có thể làm tròn và mất độ chính xác thập phân. Một số database còn hỗ trợ giá trị đặc biệt như `NaN`, `Infinity` và `-Infinity`; `BigDecimal` không biểu diễn được các giá trị này, nên cách đọc/ghi chúng phụ thuộc driver và database. Nếu nghiệp vụ cần các giá trị đặc biệt, phải kiểm tra tài liệu driver cụ thể và định nghĩa cách xử lý riêng.

## 2. Gửi JSON bằng PreparedStatement

Để gửi một chuỗi JSON như một tham số SQL có kiểu `JSON`, chỉ định kiểu đích tường minh bằng `JDBCType.JSON`:

```java
import java.sql.Connection;
import java.sql.JDBCType;
import java.sql.PreparedStatement;
import java.sql.SQLException;

static void insertEvent(Connection connection, String jsonText)
        throws SQLException {
    String sql = "INSERT INTO event_store (payload) VALUES (?)";

    try (PreparedStatement statement = connection.prepareStatement(sql)) {
        statement.setObject(1, jsonText, JDBCType.JSON);
        statement.executeUpdate();
    }
}
```

Tên bảng `event_store` và cột `payload` là ví dụ; kiểu khai báo cột JSON trong DDL phải theo cú pháp database đang dùng. `setObject(index, value, JDBCType.JSON)` yêu cầu driver gửi giá trị theo kiểu SQL `JSON`, thay vì để driver suy đoán từ `String`.

Không dùng nối chuỗi JSON vào câu SQL. `PreparedStatement` giữ dữ liệu tách khỏi câu lệnh, giúp xử lý dấu nháy, ký tự đặc biệt và chống SQL injection. `JDBCType.JSON` không tự xác thực JSON trong Java; nội dung phải là JSON hợp lệ và database/driver có thể từ chối chuỗi sai cú pháp khi thực thi.

### 2.1. Serialize object Java trước khi bind

JDBC chỉ chuẩn hóa ánh xạ `String` ↔ `JSON`. Nếu dữ liệu nghiệp vụ đang là record, hãy serialize bằng thư viện JSON đang dùng:

```java
record OrderEvent(String orderId, BigDecimal total) {}

OrderEvent event = new OrderEvent(
        "order-42",
        new BigDecimal("1250.75"));

// jsonMapper là mapper của thư viện JSON trong ứng dụng.
String jsonText = jsonMapper.writeValueAsString(event);

try (PreparedStatement statement = connection.prepareStatement(
        "INSERT INTO event_store (payload) VALUES (?)")) {
    statement.setObject(1, jsonText, JDBCType.JSON);
    statement.executeUpdate();
}
```

`jsonMapper` chỉ là tên minh họa cho mapper của thư viện ứng dụng; JDBC không cung cấp biến này hoặc API serialize JSON. Nên kiểm tra schema JSON ở tầng ứng dụng hoặc database nếu dữ liệu có hợp đồng cấu trúc bắt buộc.

## 3. Gửi DECFLOAT bằng BigDecimal

Khi tham số SQL được khai báo là `DECFLOAT`, chỉ định kiểu đích tường minh:

```java
import java.math.BigDecimal;
import java.sql.Connection;
import java.sql.JDBCType;
import java.sql.PreparedStatement;
import java.sql.SQLException;

static void insertMeasurement(Connection connection, BigDecimal value)
        throws SQLException {
    String sql = "INSERT INTO measurement (decimal_value) VALUES (?)";

    try (PreparedStatement statement = connection.prepareStatement(sql)) {
        statement.setObject(1, value, JDBCType.DECFLOAT);
        statement.executeUpdate();
    }
}
```

Không nên chỉ gọi `setBigDecimal()` nếu mục tiêu là buộc tham số dùng SQL `DECFLOAT`. Theo bảng ánh xạ JDBC, `BigDecimal` có thể tương ứng với `DECIMAL`, `NUMERIC` hoặc `DECFLOAT`; setter `setBigDecimal()` thông thường được mô tả là gửi giá trị `NUMERIC`. `setObject(..., JDBCType.DECFLOAT)` nêu rõ kiểu đích cần dùng.

### 3.1. Chọn precision và kiểm tra miền giá trị

`BigDecimal` có thể chứa precision và scale lớn hơn giới hạn của cột database. Khi bind, driver/database có thể làm tròn, báo lỗi hoặc áp dụng quy tắc chuyển đổi riêng nếu giá trị vượt precision hoặc exponent cho phép. Vì vậy:

- Chọn kiểu cột `DECFLOAT` theo precision database hỗ trợ.
- Kiểm tra precision và exponent trước khi ghi nếu dữ liệu đến từ người dùng hoặc hệ thống ngoài.
- Không tự gọi `setScale()` để ép số về một scale cố định nếu nghiệp vụ cần giữ exponent/scale gốc.
- Kiểm tra kết quả round-trip bằng dữ liệu biên: số rất lớn, rất nhỏ, nhiều chữ số thập phân và giá trị gần giới hạn.
- Dùng `BigDecimal` trong toàn bộ luồng tính toán nếu cần giữ độ chính xác thập phân; tránh chuyển qua `float`/`double` ở giữa.

`DECFLOAT` là số dấu phẩy động thập phân, không giống hoàn toàn `DECIMAL(p,s)` với precision và scale cố định. Quy tắc làm tròn, exponent và hỗ trợ giá trị đặc biệt cần được kiểm tra trong tài liệu SQL của database đích.

## 4. Gửi SQL NULL có kiểu

Khi tham số có thể là `null`, hãy gửi SQL `NULL` với đúng mã kiểu:

```java
import java.sql.Types;

if (jsonText == null) {
    statement.setNull(1, Types.JSON);
} else {
    statement.setObject(1, jsonText, JDBCType.JSON);
}

if (amount == null) {
    statement.setNull(2, Types.DECFLOAT);
} else {
    statement.setObject(2, amount, JDBCType.DECFLOAT);
}
```

`PreparedStatement.setNull()` yêu cầu khai báo SQL type. Không dựa vào `setObject(index, null)` không có kiểu vì không phải database nào cũng chấp nhận tham số NULL không có type. `Types.JSON` và `Types.DECFLOAT` có từ JDK 26.

## 5. Đọc JSON và DECFLOAT từ ResultSet

JDBC 4.5 xác định kiểu Java mặc định cho `ResultSet.getObject()`:

| Kiểu SQL | `getObject()` trả về | Getter phù hợp |
|---|---|---|
| `JSON` | `String` | `getString()` |
| `DECFLOAT` | `BigDecimal` | `getBigDecimal()` |

Ví dụ:

```java
import java.math.BigDecimal;
import java.sql.PreparedStatement;
import java.sql.ResultSet;

String sql = "SELECT payload, decimal_value FROM event_store WHERE event_id = ?";

try (PreparedStatement statement = connection.prepareStatement(sql)) {
    statement.setLong(1, eventId);

    try (ResultSet result = statement.executeQuery()) {
        if (result.next()) {
            String jsonText = result.getString("payload");
            BigDecimal amount = result.getBigDecimal("decimal_value");

            // Parse JSON bằng mapper của ứng dụng nếu cần object Java.
            // Dùng BigDecimal để giữ độ chính xác thập phân.
        }
    }
}
```

Có thể dùng `getObject(columnLabel, String.class)` cho JSON và `getObject(columnLabel, BigDecimal.class)` cho DECFLOAT nếu driver hỗ trợ các phép chuyển đổi đó. `getObject(columnLabel)` dùng ánh xạ mặc định của JDBC 4.5: JSON thành `String`, DECFLOAT thành `BigDecimal`.

Nếu SQL value là `NULL`, getter tham chiếu trả `null`. Với getter primitive như `getDouble()` hoặc `getLong()`, kết quả có thể là `0` khi SQL NULL; phải gọi `wasNull()` ngay sau getter nếu cần phân biệt NULL với số 0. Với JSON và DECFLOAT, ưu tiên getter tham chiếu `String`/`BigDecimal` để giữ được trạng thái null.

## 6. Phân biệt ánh xạ mặc định và chỉ định kiểu đích

JDBC 4.5 cập nhật các bảng chuyển đổi trong Appendix B. Các ánh xạ chính:

| Java object | Kiểu JDBC có thể ánh xạ |
|---|---|
| `String` | `CHAR`, `VARCHAR`, `LONGVARCHAR`, `NCHAR`, `NVARCHAR`, `LONGNVARCHAR`, `JSON` |
| `BigDecimal` | `DECIMAL`, `NUMERIC`, `DECFLOAT` |

Vì một Java type có thể tương ứng với nhiều JDBC type, gọi `setObject(index, value)` không phải lúc nào cũng diễn đạt rõ kiểu SQL mong muốn. Với cột JSON, chỉ định `JDBCType.JSON`; với cột DECFLOAT, chỉ định `JDBCType.DECFLOAT`. Điều này giúp driver biết kiểu đích cần truyền.

JDBC 4.5 cũng cập nhật các chuyển đổi đọc:

- `getString()` và `getNString()` hỗ trợ đọc JDBC `JSON` và `DECFLOAT` dưới dạng văn bản.
- `getBigDecimal()` hỗ trợ đọc JDBC `DECFLOAT`.
- `getObject()` ánh xạ `JSON` thành `String`, `DECFLOAT` thành `BigDecimal`.

Không suy luận rằng mọi chuyển đổi đều không mất dữ liệu. Ví dụ, đọc DECFLOAT bằng `getDouble()` có thể làm tròn theo độ chính xác nhị phân. Dùng kiểu Java theo ánh xạ chuẩn nếu cần bảo toàn dữ liệu.

## 7. Kiểm tra database và JDBC driver có hỗ trợ hay không

Việc ứng dụng biên dịch trên JDK 26 chỉ chứng minh API có trong JDK. Muốn truyền/nhận thành công cần đồng thời có:

1. Database server hỗ trợ kiểu SQL tương ứng hoặc kiểu tương thích theo tài liệu sản phẩm.
2. JDBC driver có triển khai hỗ trợ mã kiểu `JSON`/`DECFLOAT` và các phương thức bind/read cần dùng.
3. Cột, tham số stored procedure hoặc biểu thức SQL thực tế có kiểu phù hợp.
4. Driver và database có cùng quy tắc chuyển đổi, precision, null và xử lý giá trị đặc biệt.

Có thể bắt đầu bằng metadata:

```java
import java.sql.DatabaseMetaData;
import java.sql.ResultSet;
import java.sql.Types;

DatabaseMetaData metadata = connection.getMetaData();
System.out.println("Database: " + metadata.getDatabaseProductName()
        + " " + metadata.getDatabaseProductVersion());
System.out.println("Driver: " + metadata.getDriverName()
        + " " + metadata.getDriverVersion());
System.out.println("JDBC: " + metadata.getJDBCMajorVersion()
        + "." + metadata.getJDBCMinorVersion());

try (ResultSet typeInfo = metadata.getTypeInfo()) {
    while (typeInfo.next()) {
        int dataType = typeInfo.getInt("DATA_TYPE");
        if (dataType == Types.JSON || dataType == Types.DECFLOAT) {
            System.out.println(typeInfo.getString("TYPE_NAME")
                    + " -> " + dataType
                    + ", precision=" + typeInfo.getInt("PRECISION"));
        }
    }
}
```

`DatabaseMetaData.getTypeInfo()` trả về danh sách kiểu dữ liệu mà database khai báo hỗ trợ, gồm tên kiểu, mã `DATA_TYPE` và precision. Metadata hữu ích để khám phá, nhưng có driver báo thiếu hoặc ánh xạ kiểu vendor-specific khác với mã tổng quát. Hãy đối chiếu tài liệu driver và kiểm thử thật bằng câu lệnh `INSERT`/`SELECT` trên đúng phiên bản database.

`DatabaseMetaData.getJDBCMajorVersion()` và `getJDBCMinorVersion()` cho biết mức JDBC mà driver báo hỗ trợ. Nếu driver báo phiên bản cũ hơn 4.5, không nên giả định nó biết các type code mới của JDK 26. Cập nhật driver lên bản hỗ trợ JDBC 4.5 trước khi dùng các kiểu mới.

`DatabaseMetaData.supportsConvert()` kiểm tra hỗ trợ hàm SQL `CONVERT` giữa các JDBC type; nó không phải phép kiểm tra đầy đủ cho khả năng `PreparedStatement.setObject()` hoặc `ResultSet.getObject()`. Không dùng riêng phương thức này để kết luận driver có thể bind JSON/DECFLOAT.

## 8. Xử lý khi driver chưa hỗ trợ

Khi driver không hỗ trợ target SQL type, phương thức bind có thể ném `SQLFeatureNotSupportedException`; lỗi chuyển đổi, precision hoặc cú pháp SQL có thể xuất hiện dưới dạng `SQLException` hoặc lớp con khác. Không nên bắt mọi `SQLException` rồi âm thầm gửi dữ liệu dưới một kiểu khác vì có thể làm thay đổi semantics.

Hướng xử lý theo thứ tự:

- Nâng cấp JDBC driver lên bản có hỗ trợ JDBC 4.5 và các kiểu mới.
- Kiểm tra phiên bản database server và bật/khai báo native type theo tài liệu vendor.
- Nếu database không có native JSON, dùng kiểu văn bản/LOB theo chính sách ứng dụng và ghi rõ đó là JSON text được lưu như text, không phải SQL `JSON`.
- Nếu database không hỗ trợ DECFLOAT, chỉ chuyển sang `DECIMAL`/`NUMERIC` sau khi xác định precision, scale và miền giá trị nghiệp vụ vẫn được bảo toàn.
- Không chuyển DECFLOAT sang `DOUBLE` chỉ để tránh lỗi driver nếu yêu cầu nghiệp vụ cần độ chính xác thập phân.

SQL type name trong DDL không hoàn toàn giống nhau giữa các database. Hãy dùng cú pháp của database mục tiêu; `JDBCType.JSON` và `JDBCType.DECFLOAT` là mã kiểu JDBC, không phải chỉ thị rằng mọi database phải dùng đúng từ khóa DDL đó.

## 9. Lưu ý tương thích khi nâng lên JDK 26

- `JDBCType.JSON`, `JDBCType.DECFLOAT`, `Types.JSON` và `Types.DECFLOAT` có từ Java SE 26. Source code tham chiếu các hằng số này cần compile với JDK 26 trở lên.
- JDBC 4.5 là API final trong Java SE 26; không cần `--enable-preview`, `--add-modules` hoặc incubator module.
- JDK 26 không tự nâng cấp JDBC driver đi kèm ứng dụng. Cần kiểm tra driver độc lập với phiên bản JDK.
- Nếu thư viện dùng `setObject(int, Object, SQLType)`, lưu ý đây là default method trên `PreparedStatement`; default implementation ném `SQLFeatureNotSupportedException`. Driver cần triển khai overload này để hỗ trợ. Có thể dùng overload nhận `int` (`Types.JSON`, `Types.DECFLOAT`) nếu driver hỗ trợ, nhưng điều đó không thay thế yêu cầu driver/database phải hỗ trợ kiểu đích.
- Kiểm thử integration trên đúng database, driver, schema và JDK sẽ triển khai; unit test chỉ mock `PreparedStatement` không chứng minh việc chuyển đổi ở wire protocol hoạt động.

## 10. Checklist truyền và nhận JSON/DECFLOAT

- [ ] Xác nhận database server có kiểu JSON/DECFLOAT hoặc phương án lưu trữ thay thế được nghiệp vụ chấp nhận.
- [ ] Dùng JDBC driver có hỗ trợ JDBC 4.5 và target type cần dùng.
- [ ] Dùng `JDBCType.JSON` khi bind JSON text; serialize object Java thành JSON bằng thư viện của ứng dụng.
- [ ] Dùng `JDBCType.DECFLOAT` khi bind `BigDecimal` vào tham số DECFLOAT.
- [ ] Tạo `BigDecimal` từ chuỗi thập phân, không qua `double` nếu cần chính xác.
- [ ] Dùng `Types.JSON`/`Types.DECFLOAT` khi gửi SQL NULL có kiểu.
- [ ] Dùng `getString()` cho JSON và `getBigDecimal()` cho DECFLOAT.
- [ ] Kiểm thử dữ liệu null, JSON sai cú pháp, số vượt precision/exponent và các giá trị đặc biệt nếu database hỗ trợ.
- [ ] Kiểm tra metadata `getTypeInfo()` và xác nhận bằng round-trip thực tế.
- [ ] Không âm thầm fallback JSON sang text hoặc DECFLOAT sang DOUBLE nếu semantics bị thay đổi.
