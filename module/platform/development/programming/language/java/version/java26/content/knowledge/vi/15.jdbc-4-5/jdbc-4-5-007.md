# `Connection.enquoteIdentifier` và `isSimpleIdentifier`

JDBC 4.5, được tích hợp trong Java 26, bổ sung các phương thức xử lý SQL identifier trực tiếp trên `java.sql.Connection`. Hai phương thức trọng tâm là `isSimpleIdentifier(String)` để nhận biết một tên có thể dùng như regular identifier và `enquoteIdentifier(String, boolean)` để tạo tên đã được delimiter theo quy tắc của database. Chúng giúp ứng dụng xây dựng câu SQL có tên bảng, cột hoặc view động mà không phải tự ghép dấu quote theo một dialect cố định.

Đây là API Java SE/JDBC ổn định, không phải preview hoặc incubator. Cả hai phương thức là `default` methods và có `Since: 26`. JDBC 4.5 vẫn giữ các phương thức tương ứng trên `Statement` được bổ sung từ Java 9; API trên `Connection` cung cấp cách gọi ở cấp connection. [Java 26 `Connection`](https://docs.oracle.com/en/java/javase/26/docs/api/java.sql/java/sql/Connection.html) · [JDBC 4.5 Maintenance Release](https://www.jcp.org/aboutJava/communityprocess/maintenance/jsr221/JDBC_Change_Log_March_02_2026.pdf) · [JDK 26 Release Notes](https://www.oracle.com/java/technologies/javase/26-relnote-issues.html).

## 1. SQL identifier là gì?

SQL identifier là tên của một đối tượng trong database, chẳng hạn:

- Tên bảng: `orders`, `customer`.
- Tên cột: `customer_id`, `created_at`.
- Tên schema: `sales`, `reporting`.
- Tên view, sequence hoặc đối tượng khác tùy hệ quản trị cơ sở dữ liệu.

SQL phân biệt identifier với literal/value. Identifier xuất hiện ở vị trí cú pháp xác định bảng hoặc cột; literal biểu diễn dữ liệu như chuỗi, số, ngày tháng. Hai loại này cần cách xử lý khác nhau:

```sql
SELECT order_id, total
FROM orders
WHERE customer_id = 42;
```

Trong ví dụ, `orders`, `order_id`, `total` và `customer_id` là identifier. Giá trị `42` là dữ liệu. Khi tạo SQL động:

- Identifier cần được kiểm soát nguồn và delimiter đúng dialect.
- Giá trị dữ liệu nên được truyền qua `PreparedStatement` parameter marker `?`.

Không dùng `enquoteIdentifier` để quote giá trị dữ liệu. Cũng không nối dữ liệu người dùng trực tiếp vào SQL rồi hy vọng việc quote identifier sẽ ngăn SQL injection.

## 2. Identifier đơn giản và identifier có delimiter

SQL phân biệt regular/simple identifier với delimited identifier.

| Loại | Ví dụ | Đặc điểm |
|---|---|---|
| Simple/regular identifier | `orders`, `customer_id` | Tuân theo quy tắc tên thông thường của SQL và database; thường không cần dấu delimiter. |
| Delimited identifier | `"Order Details"`, `"select"` | Tên được bao bởi delimiter do database hỗ trợ, thường là dấu nháy kép theo SQL standard. Có thể chứa dấu cách hoặc trùng từ khóa nếu database cho phép. |

Ví dụ SQL dùng delimited identifiers:

```sql
SELECT "Order ID", "Total"
FROM "Order Details"
WHERE "Customer ID" = ?;
```

Delimiter thường là dấu `"` theo SQL standard, nhưng database khác nhau có thể dùng quy tắc riêng. Một số hệ quản trị dùng backtick hoặc dấu ngoặc vuông; driver JDBC cần xử lý dialect của datasource. Ứng dụng không nên tự giả định rằng mọi database đều dùng cùng một ký tự quote.

Một identifier đã được delimiter vẫn là **một tên đối tượng**. Ví dụ `"sales.orders"` là một identifier có dấu chấm nằm bên trong tên; nó không tương đương với tên schema `sales` cộng với tên bảng `orders`. Khi tạo tên đầy đủ, phải quote từng thành phần rồi nối bằng dấu chấm.

## 3. `Connection.isSimpleIdentifier(String)`

Chữ ký Java 26:

```java
default boolean isSimpleIdentifier(String identifier) throws SQLException
```

Phương thức trả về `true` nếu tên truyền vào là simple SQL identifier theo quy tắc của datasource; trả về `false` nếu tên không thỏa điều kiện. Theo SQL standard, regular identifier có các đặc điểm chính:

1. Ký tự đầu tiên là chữ cái.
2. Các ký tự tiếp theo là chữ cái, chữ số hoặc dấu gạch dưới `_`.
3. Tên không phải SQL reserved word.

Datasource có thể áp dụng thêm quy tắc, ví dụ chấp nhận ký tự bổ sung theo locale hoặc giới hạn độ dài khác.

### Quy tắc của default implementation trong JDK 26

Nếu driver không override phương thức, implementation mặc định sử dụng các tiêu chí:

- Identifier không được bao sẵn trong dấu nháy kép.
- Ký tự đầu là chữ ASCII `A-Z` hoặc `a-z`.
- Các ký tự còn lại chỉ là chữ ASCII, chữ số `0-9` hoặc `_`.
- Identifier không phải SQL standard reserved word.
- Độ dài từ 1 đến 128 ký tự, tính cả hai đầu.

Ví dụ theo Javadoc:

| Input | `isSimpleIdentifier` | Lý do |
|---|---:|---|
| `Hello` | `true` | Bắt đầu bằng chữ, phần còn lại hợp lệ. |
| `customer_id` | `true` | Chỉ có chữ và `_`. |
| `G'Day` | `false` | Có dấu nháy đơn. |
| `Bruce Wayne` | `false` | Có dấu cách. |
| `GoodDay$` | `false` | Có ký tự `$`. |
| `select` | `false` | Là SQL standard reserved word. |
| `from` | `false` | Là SQL standard reserved word. |
| `"Bruce Wayne"` | `false` | Chuỗi đã có delimiter không phải simple identifier. |

Điểm quan trọng: từ khóa như `select` có thể vẫn là một tên đối tượng hợp lệ nếu được delimiter đúng cách. `isSimpleIdentifier("select")` trả `false` để báo rằng không nên đưa từ đó vào SQL dưới dạng regular identifier không quote; kết quả `false` không có nghĩa database chắc chắn không cho tạo đối tượng tên `select`.

### Dùng để kiểm tra, không dùng để quyết định quyền truy cập

```java
boolean simple = connection.isSimpleIdentifier("customer_id");

if (simple) {
    System.out.println("Tên có thể dùng như regular identifier");
} else {
    System.out.println("Tên cần được xử lý như delimited identifier hoặc bị từ chối theo chính sách");
}
```

`isSimpleIdentifier` không kiểm tra bảng/cột có thực sự tồn tại hay không, không xác nhận quyền đọc/ghi của user database, không xác thực tên có thuộc allow-list của ứng dụng và không thay thế authorization. Đây là phép kiểm tra hình dạng identifier theo quy tắc SQL/datasource.

### Ngoại lệ

- `NullPointerException`: `identifier` là `null`.
- `SQLException`: có lỗi khi datasource/driver thực hiện kiểm tra.

Không nên bắt mọi `SQLException` rồi mặc định identifier hợp lệ. Nếu kiểm tra thất bại do database hoặc driver, cần báo lỗi hoặc áp dụng chính sách fallback được thiết kế rõ ràng.

## 4. `Connection.enquoteIdentifier(String, boolean)`

Chữ ký Java 26:

```java
default String enquoteIdentifier(String identifier, boolean alwaysDelimit)
        throws SQLException
```

Phương thức trả về identifier ở dạng simple hoặc delimited tùy quy tắc của datasource và giá trị `alwaysDelimit`.

| Trường hợp | `alwaysDelimit` | Hành vi |
|---|---:|---|
| Identifier là simple | `false` | Trả nguyên chuỗi, không thêm delimiter. |
| Identifier là simple | `true` | Thêm delimiter và trả về delimited identifier. |
| Identifier không simple | `false` hoặc `true` | Phải delimiter identifier bằng ký tự mà datasource cung cấp. |

Do đó, `alwaysDelimit=false` không có nghĩa là “không bao giờ quote”. Tên không phải simple identifier vẫn được delimiter nếu hợp lệ. Cờ này chỉ quyết định có quote thêm các tên vốn đã simple hay không.

Ví dụ theo Javadoc:

| Identifier | `alwaysDelimit` | Kết quả minh họa của default implementation |
|---|---:|---|
| `Hello` | `false` | `Hello` |
| `Hello` | `true` | `"Hello"` |
| `G'Day` | `false` | `"G'Day"` |
| `Bruce Wayne` | `false` | `"Bruce Wayne"` |
| `select` | `false` | `"select"` |
| `GoodDay$` | `false` | `"GoodDay$"` |
| `Hello"World` | `false` | `SQLException` theo default implementation |

Kết quả thực tế phụ thuộc driver và database. Ví dụ trong bảng minh họa default implementation của JDK dùng dấu nháy kép; driver có thể override để đáp ứng quy tắc của datasource.

### Default implementation kiểm tra những gì?

Theo Javadoc Java 26, default implementation:

- Dùng `DatabaseMetaData.getIdentifierQuoteString()` để lấy delimiter của datasource.
- Ném `SQLException` nếu quote string không phải dấu nháy kép `"`.
- Ném `SQLException` nếu identifier có ký tự NUL hoặc dấu nháy kép.
- Ném `SQLException` nếu độ dài nhỏ hơn 1 hoặc lớn hơn 128 ký tự.
- Ném `SQLFeatureNotSupportedException` nếu datasource không hỗ trợ delimited identifiers.
- Ném `NullPointerException` nếu identifier là `null`.

Driver có thể override phương thức để hỗ trợ đúng dialect, ký tự quote, giới hạn độ dài và các quy tắc hợp lệ của database. Đây là lý do phải thử nghiệm trên JDBC driver thực tế thay vì chỉ dựa vào default implementation.

### Không truyền identifier đã quote sẵn

Hãy truyền tên thô, không tự thêm delimiter trước khi gọi API:

```java
// Đúng: đưa tên thô vào API
String table = connection.enquoteIdentifier("Order Details", false);

// Sai cách dùng: tự quote trước rồi lại đưa vào API
String table = connection.enquoteIdentifier("\"Order Details\"", false);
```

Default implementation từ chối identifier có dấu nháy kép bên trong. Nếu tự quote trước, bạn có thể nhận `SQLException` hoặc kết quả không đúng theo driver. Hãy để driver tạo delimiter.

## 5. Tạo SQL động an toàn với allow-list và PreparedStatement

`PreparedStatement` parameter marker `?` đại diện cho **giá trị dữ liệu**, không đại diện cho tên bảng, cột, schema hoặc keyword SQL. Vì vậy, khi ứng dụng cần chọn bảng động, hãy:

1. Chuyển lựa chọn từ request sang một tên bảng cố định trong allow-list do ứng dụng kiểm soát.
2. Gọi `Connection.enquoteIdentifier` với tên thô để tạo identifier phù hợp database.
3. Dùng `PreparedStatement` cho mọi giá trị dữ liệu.

Ví dụ:

```java
import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.sql.SQLException;
import java.util.Map;

public final class OrderRepository {
    // Giá trị phía phải là identifier cố định do ứng dụng kiểm soát.
    private static final Map<String, String> TABLES = Map.of(
            "current", "orders",
            "archive", "orders_archive"
    );

    public void printOrders(Connection connection,
                            String requestedView,
                            long customerId) throws SQLException {

        String rawTableName = TABLES.get(requestedView);
        if (rawTableName == null) {
            throw new IllegalArgumentException("Unsupported order view");
        }

        String table = connection.enquoteIdentifier(rawTableName, false);
        String customerColumn = connection.enquoteIdentifier("customer_id", false);

        String sql = "SELECT order_id, total FROM " + table
                + " WHERE " + customerColumn + " = ?";

        try (PreparedStatement statement = connection.prepareStatement(sql)) {
            statement.setLong(1, customerId);

            try (ResultSet resultSet = statement.executeQuery()) {
                while (resultSet.next()) {
                    System.out.printf("order=%s, total=%s%n",
                            resultSet.getString("order_id"),
                            resultSet.getBigDecimal("total"));
                }
            }
        }
    }
}
```

Ở đây, `requestedView` có thể đến từ request, nhưng nó chỉ dùng để chọn một entry trong allow-list. Chuỗi SQL được tạo từ identifier cố định và đã được delimiter. `customerId` luôn được truyền bằng `setLong`, không được nối trực tiếp vào SQL.

Nếu `requestedView` là `"orders; DROP TABLE users"`, map không tìm thấy key và ứng dụng từ chối yêu cầu. `enquoteIdentifier` không thay thế allow-list; quote một chuỗi không đáng tin cậy không có nghĩa là ứng dụng đã cho phép đối tượng đó được truy cập.

## 6. Quote tên schema và table theo từng thành phần

Tên đủ điều kiện thường gồm nhiều thành phần, ví dụ `schema.table` hoặc `catalog.schema.table`. Mỗi thành phần là một identifier riêng; dấu chấm là ký tự phân tách cú pháp SQL.

```java
String schema = connection.enquoteIdentifier("reporting", false);
String table = connection.enquoteIdentifier("monthly_sales", false);
String qualifiedTable = schema + "." + table;

String sql = "SELECT * FROM " + qualifiedTable;
```

Không gọi `enquoteIdentifier("reporting.monthly_sales", false)` nếu ý định là schema cộng table. Khi đó, chuỗi có thể bị hiểu là một identifier duy nhất và được quote thành một tên có dấu chấm nằm bên trong.

Nếu tên có ba thành phần, quote từng phần rồi nối:

```java
String catalog = connection.enquoteIdentifier(catalogName, false);
String schema = connection.enquoteIdentifier(schemaName, false);
String table = connection.enquoteIdentifier(tableName, false);

String qualifiedName = catalog + "." + schema + "." + table;
```

Việc catalog/schema có xuất hiện trong cú pháp tên đầy đủ hay không còn phụ thuộc database. Hãy kiểm tra metadata và cú pháp của datasource đích.

## 7. `alwaysDelimit` và vấn đề chữ hoa/chữ thường

Quote một identifier có thể thay đổi cách database so sánh tên. Nhiều hệ quản trị chuẩn hóa tên không quote về chữ hoa hoặc chữ thường; delimited identifiers thường giữ nguyên chính xác chữ hoa/chữ thường đã viết. Vì vậy:

- `alwaysDelimit=false` giữ simple identifier ở dạng không quote, giúp database áp dụng quy tắc chuẩn hóa thông thường.
- `alwaysDelimit=true` luôn quote cả tên đơn giản. Điều này có thể thay đổi cách tìm đối tượng nếu database phân biệt tên quote và không quote.
- Identifier không simple vẫn cần delimiter dù `alwaysDelimit=false`.

Ví dụ, nếu bảng được tạo dưới dạng không quote `Orders`, database có thể lưu tên theo dạng chuẩn hóa riêng. Quote chuỗi `Orders` thành `"Orders"` có thể tìm một tên khác với `orders` tùy database. Không bật `alwaysDelimit=true` hàng loạt mà không kiểm tra quy tắc tạo và tra cứu identifier của hệ quản trị cơ sở dữ liệu.

Khi cần tính portable, dùng tên được lấy từ metadata hoặc allow-list đã được kiểm thử với database cụ thể; chọn `alwaysDelimit` theo naming convention của schema. Đừng dựa vào việc một chuỗi có vẻ hợp lệ trong Java để suy ra database sẽ resolve nó tới cùng một đối tượng ở mọi dialect.

## 8. Khác biệt giữa `isSimpleIdentifier` và `enquoteIdentifier`

Hai phương thức liên quan nhưng không thay thế nhau:

| Câu hỏi | Phương thức phù hợp | Kết quả |
|---|---|---|
| Tên có phải regular/simple identifier không? | `isSimpleIdentifier(name)` | Boolean. |
| Cần tạo chuỗi SQL identifier có delimiter đúng datasource không? | `enquoteIdentifier(name, alwaysDelimit)` | Chuỗi SQL đã được định dạng hoặc exception. |
| Tên bảng có tồn tại trong schema không? | `DatabaseMetaData` hoặc truy vấn metadata phù hợp | Kiểm tra metadata thực tế. |
| Người dùng hiện tại có quyền truy cập bảng không? | Quyền database và thao tác thực tế | Được database kiểm tra khi thực thi. |
| Giá trị chuỗi/số/ngày an toàn trong SQL như thế nào? | `PreparedStatement` parameters | Driver truyền giá trị theo kiểu dữ liệu. |

Ví dụ dùng cả hai phương thức:

```java
String rawName = "select";

boolean simple = connection.isSimpleIdentifier(rawName); // false: reserved word
String sqlIdentifier = connection.enquoteIdentifier(rawName, false);
// Default implementation tạo identifier có delimiter: "select"
```

Không cần gọi `isSimpleIdentifier` trước mỗi lần `enquoteIdentifier`. `enquoteIdentifier` đã thực hiện lựa chọn cần thiết theo quy tắc simple/delimited. Dùng `isSimpleIdentifier` khi ứng dụng cần hiển thị thông tin, áp dụng policy riêng hoặc giải thích vì sao tên phải được delimiter.

## 9. Tại sao không tự ghép dấu quote?

Các cách sau dễ sai:

```java
String sql = "SELECT * FROM \"" + tableName + "\"";
```

Vấn đề:

- Database có thể không dùng dấu nháy kép làm identifier delimiter.
- Cách escape delimiter nằm bên trong tên khác nhau giữa các hệ quản trị.
- Quy tắc ký tự hợp lệ và giới hạn độ dài không giống nhau.
- Tên có dấu quote, ký tự NUL hoặc chuỗi đặc biệt có thể làm SQL sai cú pháp.
- Một cách quote tự viết có thể tạo cảm giác an toàn giả trong khi không xác thực nguồn identifier.

`Connection.enquoteIdentifier` giao việc tạo delimiter cho driver/database. Tuy nhiên, nó không thay thế việc kiểm soát nguồn identifier. Kết hợp API với allow-list hoặc mapping từ tên logic sang identifier đã cấu hình.

## 10. Driver JDBC và khả năng tương thích

`Connection.enquoteIdentifier` và `Connection.isSimpleIdentifier` là default methods được thêm vào `Connection` trong JDBC 4.5, có từ Java 26. Default method giúp các implementation hiện có có hành vi mặc định mà không bắt buộc mọi driver phải bổ sung method ngay lập tức.

Tuy nhiên, driver có thể cần override để phù hợp datasource:

- Database dùng delimiter khác dấu nháy kép.
- Database cho phép ký tự Unicode hoặc ký tự bổ sung trong identifier.
- Giới hạn độ dài identifier khác 128 ký tự.
- Danh sách reserved words và quy tắc tên khác SQL standard.
- Cách xử lý delimiter hoặc tên đã được quote có quy tắc riêng.

JDK 26 Release Notes cảnh báo về tương thích của một số implementation:

1. Nếu class driver có method nội bộ `private` hoặc `protected` trùng chữ ký với default method mới, method đó cần được đổi tên hoặc đưa về `public` phù hợp với hợp đồng interface.
2. Một class không thể kế thừa hai default methods khác nhau cùng chữ ký từ nhiều interface mà không giải quyết xung đột; implementation cần override để chọn hành vi.

Đây là vấn đề cần chú ý với tác giả JDBC driver, wrapper và class tự implement nhiều interface. Ứng dụng sử dụng driver nên kiểm tra phiên bản driver được nhà cung cấp hỗ trợ với Java 26, đặc biệt nếu database không tuân theo delimiter mặc định của SQL standard.

### Kiểm tra metadata của datasource

```java
DatabaseMetaData metadata = connection.getMetaData();

System.out.println("Driver: " + metadata.getDriverName());
System.out.println("Driver version: " + metadata.getDriverVersion());
System.out.println("Identifier quote: ["
        + metadata.getIdentifierQuoteString() + "]");
```

`getIdentifierQuoteString()` cho biết delimiter mà datasource sử dụng. Một số datasource không hỗ trợ delimited identifiers có thể trả về chuỗi biểu thị không có delimiter theo hợp đồng của `DatabaseMetaData`. Default implementation Java 26 yêu cầu dấu nháy kép; nếu metadata khác giá trị đó, driver cần override để cung cấp cách xử lý phù hợp hoặc thao tác có thể ném `SQLException`/`SQLFeatureNotSupportedException`.

Không nên chỉ kiểm tra metadata một lần rồi tự ghép delimiter bằng tay. Hãy gọi phương thức trên `Connection` đang sử dụng và xác minh hành vi với driver/version thực tế.

## 11. Ngoại lệ cần xử lý

| Phương thức | Ngoại lệ | Trường hợp |
|---|---|---|
| `isSimpleIdentifier` | `NullPointerException` | `identifier` là `null`. |
| `isSimpleIdentifier` | `SQLException` | Lỗi khi datasource/driver kiểm tra identifier. |
| `enquoteIdentifier` | `NullPointerException` | `identifier` là `null`. |
| `enquoteIdentifier` | `SQLException` | Identifier không hợp lệ, chứa ký tự bị cấm hoặc vượt giới hạn độ dài; default implementation còn ném lỗi nếu quote string không phải dấu nháy kép. |
| `enquoteIdentifier` | `SQLFeatureNotSupportedException` | Datasource không hỗ trợ delimited identifiers. |

Ví dụ xử lý:

```java
try {
    String identifier = connection.enquoteIdentifier(rawName, false);
    executeUsingIdentifier(identifier);
} catch (SQLFeatureNotSupportedException unsupported) {
    // Datasource không hỗ trợ delimiter; không tự ghép quote theo phỏng đoán.
    throw new IllegalStateException(
            "Database does not support delimited identifiers", unsupported);
} catch (SQLException invalidOrDatabaseError) {
    throw new IllegalArgumentException(
            "Identifier is invalid for the configured database", invalidOrDatabaseError);
}
```

Trong ứng dụng thật, cần phân biệt lỗi identifier không hợp lệ với lỗi kết nối hoặc lỗi truy cập metadata nếu driver cung cấp SQLState/vendor code phù hợp. Không biến mọi `SQLException` thành thông báo “tên không hợp lệ” nếu nguyên nhân có thể là lỗi database.

## 12. Những nhầm lẫn thường gặp

| Nhầm lẫn | Cách hiểu đúng |
|---|---|
| `isSimpleIdentifier` trả `false` nghĩa là tên không tồn tại. | Nó chỉ nói tên không phải regular identifier; tên đó vẫn có thể hợp lệ khi được delimiter. |
| `isSimpleIdentifier` trả `true` nghĩa là có thể truy cập bảng. | Không kiểm tra sự tồn tại, schema hay quyền database. |
| `alwaysDelimit=false` có nghĩa là kết quả không bao giờ có quote. | Identifier không simple vẫn phải được delimiter. |
| `alwaysDelimit=true` luôn an toàn và portable hơn. | Quote luôn có thể thay đổi quy tắc case folding và cách database resolve tên. |
| Có thể truyền `schema.table` như một identifier duy nhất. | Phải quote schema và table riêng rồi nối bằng dấu chấm. |
| `enquoteIdentifier` thay thế `PreparedStatement`. | Không. Identifier là cú pháp; dữ liệu vẫn cần parameter binding. |
| Quote một chuỗi tùy ý là đủ chống SQL injection. | Cần allow-list/mapping cho identifier và bind giá trị bằng `PreparedStatement`. |
| Mọi database đều dùng dấu nháy kép. | Driver có thể phải override để đáp ứng delimiter của datasource. |
| Có thể tự quote chuỗi rồi đưa vào `enquoteIdentifier`. | Truyền tên thô; default implementation có thể từ chối dấu quote trong input. |
| API mới là preview của Java 26. | Đây là Java SE/JDBC stable API, `Since: 26`. |

## 13. Kiểm thử trên JDK và driver thực tế

Trước khi đưa SQL động vào production, hãy kiểm tra tối thiểu:

1. Một simple identifier bình thường, ví dụ `customer_id`.
2. Một reserved word, ví dụ `select`.
3. Một identifier có dấu cách, ví dụ `Order Details`.
4. Một identifier có ký tự punctuation mà database có thể hoặc không thể hỗ trợ.
5. Identifier rỗng, quá dài, `null` và có ký tự NUL.
6. Datasource dùng delimiter khác dấu nháy kép.
7. Tên có chữ hoa/chữ thường để xác minh hành vi khi `alwaysDelimit` là `true` và `false`.
8. Schema/table qualified name với từng thành phần được quote riêng.
9. Giá trị dữ liệu vẫn được truyền qua `PreparedStatement`, không nối vào SQL.
10. Phiên bản JDBC driver đang được nhà cung cấp xác nhận hỗ trợ Java 26.

Kiểm tra hành vi qua `Connection` lấy từ `DataSource` hoặc `DriverManager` trong môi trường giống production. Không chỉ test một mock `Connection`, vì mock thường không phản ánh metadata, delimiter và override của driver thực tế.

### Biên dịch và chạy

Hai phương thức thuộc `java.sql` trong module `java.sql`; không cần `--enable-preview` hay `--add-modules`. Dùng JDK 26 để biên dịch:

```bash
javac --release 26 -cp "jdbc-driver.jar" -d out src/IdentifierExample.java
java -cp "out;jdbc-driver.jar" com.example.IdentifierExample
```

Trên Linux/macOS, classpath dùng dấu `:` thay cho `;`:

```bash
java -cp "out:jdbc-driver.jar" com.example.IdentifierExample
```

Nếu ứng dụng phải chạy trên Java 25 trở xuống, các phương thức mới trên `Connection` không có trong API baseline đó. Khi đó cần biên dịch theo release thấp nhất được hỗ trợ và dùng một abstraction/driver API phù hợp; không gọi method Java 26 rồi kỳ vọng runtime cũ tự cung cấp.

## 14. Checklist triển khai

- [ ] Đã phân biệt SQL identifier với literal/value.
- [ ] Đã hiểu `isSimpleIdentifier` kiểm tra regular identifier, gồm cả reserved word.
- [ ] Đã hiểu `false` không đồng nghĩa identifier không hợp lệ hoặc không tồn tại.
- [ ] Đã dùng `enquoteIdentifier` với tên thô, chưa tự thêm delimiter.
- [ ] Đã chọn `alwaysDelimit` theo naming convention và case-folding của database.
- [ ] Đã quote từng thành phần của tên đầy đủ như schema và table.
- [ ] Đã dùng allow-list hoặc mapping cố định cho identifier lấy từ request/configuration không tin cậy.
- [ ] Đã dùng `PreparedStatement` cho mọi giá trị dữ liệu.
- [ ] Đã kiểm tra `DatabaseMetaData.getIdentifierQuoteString()` và hành vi override của driver.
- [ ] Đã xử lý `SQLException`, `SQLFeatureNotSupportedException` và `NullPointerException` phù hợp.
- [ ] Đã kiểm thử trên đúng JDK 26 và JDBC driver/version triển khai.
- [ ] Đã xác nhận ứng dụng không dựa vào preview/incubator hoặc API legacy.
