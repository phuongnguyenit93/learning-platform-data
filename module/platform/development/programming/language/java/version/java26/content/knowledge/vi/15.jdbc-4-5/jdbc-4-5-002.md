# JDBCType.JSON, JDBCType.DECFLOAT và khả năng của driver

## Mục tiêu

Sau bài học này, bạn có thể:

- Xác định vị trí của `JDBCType.JSON` và `JDBCType.DECFLOAT` trong JDBC 4.5 của Java 26.
- Phân biệt mã kiểu JDBC chuẩn với kiểu dữ liệu và cú pháp SQL riêng của từng hệ quản trị cơ sở dữ liệu.
- Gửi giá trị JSON và DECFLOAT qua `PreparedStatement` bằng `SQLType`.
- Đọc kết quả mà không giả định mọi driver ánh xạ kiểu SQL sang cùng một lớp Java.
- Dùng `DatabaseMetaData.getTypeInfo()` và metadata của `ResultSet` để khảo sát khả năng của driver kết hợp với DBMS.
- Xử lý driver không hỗ trợ kiểu, mapping hoặc overload cần dùng.
- Thiết kế kiểm thử tích hợp để xác nhận bind, đọc, null, precision và semantics trên đúng driver/database triển khai.

## 1. JDBC 4.5 trong Java 26 bổ sung điều gì?

JDBC 4.5 là phiên bản JDBC được tích hợp trong Java SE 26. API gồm các package `java.sql` và `javax.sql`; các thành phần mới được đánh dấu `Since: 26` trong Javadoc.

Trong phạm vi kiểu dữ liệu, Java 26 bổ sung hai mã kiểu SQL tổng quát:

- `JDBCType.JSON` và `Types.JSON`: định danh kiểu SQL JSON.
- `JDBCType.DECFLOAT` và `Types.DECFLOAT`: định danh kiểu SQL decimal floating-point.

Hai enum constant mới nằm trong `java.sql.JDBCType`, implement `SQLType`, còn hai hằng `int` nằm trong `java.sql.Types`. Chúng thuộc Java SE, không phải preview hoặc incubator; không cần `--enable-preview`.

~~~java
import java.sql.JDBCType;
import java.sql.Types;

System.out.println(JDBCType.JSON.getName());       // JSON
System.out.println(JDBCType.DECFLOAT.getName());   // DECFLOAT

int jsonCode = Types.JSON;
int decfloatCode = Types.DECFLOAT;

System.out.println(JDBCType.valueOf(jsonCode));     // JSON
System.out.println(JDBCType.valueOf(decfloatCode)); // DECFLOAT
~~~

Các hằng này chuẩn hóa cách ứng dụng chỉ định loại SQL cho JDBC driver. Chúng không tự thêm kiểu dữ liệu vào database, không thay đổi schema và không buộc mọi driver phải hỗ trợ JSON hoặc DECFLOAT.

JDBC 4.5 có những tính năng tùy chọn. Mức hỗ trợ có thể khác nhau giữa các driver, phiên bản driver, DBMS và phiên bản server. Vì vậy, khả năng biên dịch code với JDK 26 chỉ xác nhận API có mặt trong Java; ứng dụng vẫn phải xác minh khả năng của tổ hợp driver/database thực tế.

## 2. Phân biệt ba lớp: Java API, JDBC type và kiểu SQL của DBMS

Khi làm việc với JSON hoặc DECFLOAT, cần tách ba lớp:

1. **Java API:** `JDBCType.JSON`, `JDBCType.DECFLOAT`, `Types.JSON` và `Types.DECFLOAT` là các định danh trong Java.
2. **JDBC driver:** chuyển giá trị Java và mã kiểu JDBC thành giao thức, tham số và kiểu dữ liệu mà database hiểu; đồng thời chuyển dữ liệu kết quả về Java.
3. **DBMS:** quyết định kiểu SQL thực tế có tồn tại, cách lưu trữ, độ chính xác, phép toán, validation, index và cú pháp DDL.

Ví dụ, database có thể cung cấp kiểu JSON native, kiểu JSON nhị phân, kiểu JSONB của nhà cung cấp hoặc chỉ lưu văn bản. Tên kiểu SQL, cú pháp tạo cột, toán tử truy vấn và cách tạo index phụ thuộc DBMS.

Tương tự, database quyết định độ chính xác và miền exponent của DECFLOAT mà nó hỗ trợ. JDBC type code chỉ giúp ứng dụng và driver nhận diện kiểu tổng quát; nó không áp đặt một precision hoặc storage format giống nhau trên mọi sản phẩm.

Không nên hiểu `JDBCType.JSON` là một JSON parser trong Java, hoặc `JDBCType.DECFLOAT` là một lớp số Java mới. Chúng là mã định danh SQL type để sử dụng qua các API JDBC.

## 3. JSON và DECFLOAT giải quyết hai nhu cầu khác nhau

| Kiểu SQL | Ý nghĩa | Cần quan tâm |
|---|---|---|
| `JSON` | Lưu dữ liệu có cấu trúc JSON như object, array, string, number, boolean và null | Validation, encoding, kích thước, toán tử JSON, index và Java mapping |
| `DECFLOAT` | Lưu số dấu phẩy động thập phân với precision và exponent | Precision, exponent range, rounding, special values và chuyển đổi Java |
| `DECIMAL` / `NUMERIC` | Số thập phân có precision và scale được khai báo | Số chữ số và số chữ số sau dấu thập phân |
| `REAL` / `FLOAT` / `DOUBLE` | Kiểu dấu phẩy động nhị phân | Sai số biểu diễn nhị phân và độ chính xác |

### JSON

JSON phù hợp khi dữ liệu có cấu trúc thay đổi hoặc chứa các trường lồng nhau. Kiểu native có thể giúp database kiểm tra JSON và cung cấp toán tử truy vấn theo đường dẫn. Tuy nhiên, các tính năng này phụ thuộc database.

Một cột JSON không tự bảo đảm mọi truy vấn đều nhanh. Cần kiểm tra cách database lưu dữ liệu, hỗ trợ index và tối ưu truy vấn JSON.

### DECFLOAT

DECFLOAT là số dấu phẩy động theo cơ số 10. Nó khác `DECIMAL`/`NUMERIC` có scale cố định và khác `FLOAT`/`DOUBLE` dùng biểu diễn nhị phân.

Một số DBMS cung cấp DECFLOAT với nhiều mức precision và hỗ trợ giá trị đặc biệt như NaN hoặc infinity. Miền giá trị và quy tắc chính xác do DBMS quy định. Không giả định mọi database có cùng precision hoặc cùng tập special values chỉ vì driver dùng `JDBCType.DECFLOAT`.

Với dữ liệu tiền tệ cần scale cố định và quy tắc làm tròn rõ ràng, `DECIMAL` hoặc `NUMERIC` thường phù hợp hơn. DECFLOAT hữu ích khi nghiệp vụ cần số học dấu phẩy động thập phân với exponent linh hoạt.

## 4. Gửi JSON bằng PreparedStatement

Khi driver hỗ trợ JSON và mapping từ `String` sang kiểu SQL JSON, có thể chỉ định kiểu đích bằng `JDBCType.JSON`:

~~~java
import java.sql.Connection;
import java.sql.JDBCType;
import java.sql.PreparedStatement;
import java.sql.SQLException;

static void insertDocument(Connection connection, String json)
        throws SQLException {

    String sql = "INSERT INTO documents (document_id, payload) VALUES (?, ?)";

    try (PreparedStatement statement = connection.prepareStatement(sql)) {
        statement.setLong(1, 1001L);
        statement.setObject(2, json, JDBCType.JSON);
        statement.executeUpdate();
    }
}
~~~

Trong ví dụ:

- SQL DDL giả định bảng `documents` có cột JSON native tương thích với driver.
- `json` là văn bản JSON đã được ứng dụng tạo hoặc kiểm tra.
- `setObject(2, json, JDBCType.JSON)` yêu cầu driver gửi tham số theo kiểu SQL JSON.
- `PreparedStatement` giữ giá trị dữ liệu tách khỏi câu lệnh SQL.

Tên bảng, cột và DDL cần được điều chỉnh theo DBMS. Việc gọi `setObject` không bảo đảm server chấp nhận dữ liệu. Database có thể từ chối JSON sai cú pháp, kích thước quá lớn hoặc giá trị không phù hợp với schema/ràng buộc.

Không nối chuỗi JSON trực tiếp vào SQL. Hãy bind bằng placeholder để tránh lỗi escaping và SQL injection.

### Nếu driver không hỗ trợ overload SQLType

`PreparedStatement.setObject(int, Object, SQLType)` là overload nhận kiểu SQL tổng quát. Implementation mặc định của interface ném `SQLFeatureNotSupportedException` nếu driver không hỗ trợ overload này.

Nếu driver có hỗ trợ mã kiểu mới nhưng chỉ triển khai overload nhận `int`, có thể thử:

~~~java
statement.setObject(2, json, Types.JSON);
~~~

Cách này vẫn cần driver và DBMS hiểu `Types.JSON`. Nó không phải fallback phổ quát cho database không có kiểu JSON.

Nếu driver yêu cầu kiểu Java hoặc API riêng của nhà cung cấp, hãy dùng mapping được tài liệu driver công bố. Nếu DBMS chỉ hỗ trợ JSON thông qua cột văn bản và phép chuyển đổi SQL, có thể bind `VARCHAR` rồi dùng cú pháp cast do DBMS hỗ trợ. Cú pháp cast và validation không giống nhau giữa các sản phẩm; không đưa một cú pháp vendor-specific vào code dùng chung mà không có dialect/adapter.

## 5. Đọc JSON từ ResultSet

Cách driver trả JSON về Java phụ thuộc mapping được hỗ trợ. Một số driver có thể trả `String`; driver khác có thể trả object riêng của nhà cung cấp hoặc kiểu biểu diễn khác.

Có thể kiểm tra metadata cột trước khi quyết định cách đọc:

~~~java
try (PreparedStatement statement =
         connection.prepareStatement(
             "SELECT payload FROM documents WHERE document_id = ?")) {

    statement.setLong(1, 1001L);

    try (var result = statement.executeQuery()) {
        var metadata = result.getMetaData();

        if (result.next()) {
            int jdbcType = metadata.getColumnType(1);
            String databaseTypeName = metadata.getColumnTypeName(1);
            String javaClassName = metadata.getColumnClassName(1);

            System.out.println("JDBC type code: " + jdbcType);
            System.out.println("Database type: " + databaseTypeName);
            System.out.println("Java class: " + javaClassName);

            Object value = result.getObject(1);
            System.out.println(value == null ? "SQL NULL" : value.getClass());
        }
    }
}
~~~

Các method metadata giúp chẩn đoán:

- `getColumnType()` trả mã JDBC type.
- `getColumnTypeName()` trả tên kiểu do driver/database báo cáo.
- `getColumnClassName()` cho biết class mà driver dự kiến dùng cho `getObject()`.
- `getObject()` trả object theo mapping của driver.

Nếu tài liệu driver xác nhận JSON được ánh xạ sang `String`, có thể dùng `getString()`. Nếu driver trả kiểu riêng, dùng API chuyển đổi được nhà cung cấp hỗ trợ. Không ép mọi kết quả thành `String` hoặc tự parse class vendor-specific mà chưa kiểm tra hợp đồng.

## 6. Gửi DECFLOAT và bảo toàn semantics số

`JDBCType.DECFLOAT` cho phép chỉ định SQL type đích khi bind:

~~~java
import java.math.BigDecimal;
import java.sql.JDBCType;
import java.sql.PreparedStatement;

BigDecimal measurement = new BigDecimal("123456789.0123456789");

try (PreparedStatement statement =
         connection.prepareStatement(
             "INSERT INTO measurements (measurement) VALUES (?)")) {

    // Chỉ dùng mapping BigDecimal -> DECFLOAT nếu driver công bố hỗ trợ.
    statement.setObject(1, measurement, JDBCType.DECFLOAT);
    statement.executeUpdate();
}
~~~

Ví dụ dùng `BigDecimal` cho giá trị thập phân hữu hạn và giả định driver hỗ trợ chuyển đổi này. JDBC 4.5 không định nghĩa một lớp Java mới dành riêng cho DECFLOAT và không buộc mọi driver ánh xạ DECFLOAT sang `BigDecimal`.

Trước khi dùng ví dụ trong ứng dụng thật, kiểm tra tài liệu driver về:

- Java class được chấp nhận khi bind DECFLOAT.
- Java class trả về bởi `ResultSet.getObject()`.
- Precision và exponent range của database.
- Quy tắc làm tròn hoặc chuyển đổi.
- Cách biểu diễn special values nếu database hỗ trợ.
- Khả năng giữ nguyên giá trị qua vòng bind → lưu → đọc.

### Vì sao không nên tự động dùng double?

`double` dùng biểu diễn nhị phân nên nhiều số thập phân không biểu diễn chính xác. Chuyển một `double` sang DECFLOAT không khôi phục được chữ số đã mất trước đó.

Nếu dữ liệu bắt đầu từ chuỗi thập phân, hãy giữ dạng thập phân khi tạo giá trị:

~~~java
BigDecimal exactDecimal = new BigDecimal("0.1");
double approximateBinary = 0.1d;
~~~

`BigDecimal("0.1")` giữ giá trị thập phân được chỉ định. `double` chứa giá trị nhị phân gần đúng. Việc driver có thể bind `BigDecimal` sang DECFLOAT hay không vẫn cần xác nhận.

### Đọc DECFLOAT

Có thể lấy object và kiểm tra class runtime:

~~~java
Object value = resultSet.getObject("measurement");

if (value == null) {
    // SQL NULL
} else if (value instanceof BigDecimal decimal) {
    // Mapping do driver cung cấp; chỉ áp dụng nếu driver tài liệu hóa.
    processFiniteDecimal(decimal);
} else {
    // Xử lý theo kiểu cụ thể được driver công bố.
    processDriverSpecificValue(value);
}
~~~

Các hàm `processFiniteDecimal` và `processDriverSpecificValue` là logic ứng dụng. Không giả định `getBigDecimal()` có thể biểu diễn mọi giá trị DECFLOAT. Nếu DBMS hỗ trợ NaN hoặc infinity, `BigDecimal` không thể biểu diễn các giá trị đó; cần dùng mapping khác do driver công bố hoặc xử lý qua biểu diễn văn bản/kiểu riêng.

## 7. Phân biệt JDBCType với Types

Cả hai cách đều chỉ cùng một nhóm mã SQL, nhưng phục vụ các overload khác nhau:

| API | Kiểu Java | Cách sử dụng |
|---|---|---|
| `JDBCType.JSON` | `SQLType` | `setObject(index, value, JDBCType.JSON)` |
| `JDBCType.DECFLOAT` | `SQLType` | `setObject(index, value, JDBCType.DECFLOAT)` |
| `Types.JSON` | `int` | `setObject(index, value, Types.JSON)` |
| `Types.DECFLOAT` | `int` | `setObject(index, value, Types.DECFLOAT)` |

Ưu tiên `JDBCType` trong code mới vì tên enum dễ đọc và type-safe hơn. Dùng `Types` khi cần gọi overload nhận mã `int`, hoặc khi tích hợp với API cũ của driver.

Không tự tạo số nguyên type code hoặc hard-code mã vendor. Hãy dùng hằng chuẩn hoặc `SQLType` do driver công bố.

## 8. Kiểm tra driver và database có hỗ trợ kiểu hay không

`DatabaseMetaData` mô tả khả năng của tổ hợp driver và DBMS đang kết nối. Phương thức `getTypeInfo()` trả về các kiểu dữ liệu database hỗ trợ, gồm các cột như:

- `TYPE_NAME`: tên kiểu.
- `DATA_TYPE`: mã SQL type theo `java.sql.Types`.
- `PRECISION`: precision tối đa.
- `CREATE_PARAMS`: tham số dùng khi tạo kiểu.
- `NULLABLE`: khả năng chấp nhận SQL NULL.
- `SEARCHABLE`: khả năng dùng kiểu trong điều kiện WHERE.

Ví dụ kiểm tra database có công bố các mã kiểu JDBC tương ứng:

~~~java
import java.sql.Connection;
import java.sql.DatabaseMetaData;
import java.sql.ResultSet;
import java.sql.SQLException;
import java.sql.Types;

static boolean advertisesType(DatabaseMetaData metadata, int jdbcType)
        throws SQLException {

    try (ResultSet types = metadata.getTypeInfo()) {
        while (types.next()) {
            if (types.getInt("DATA_TYPE") == jdbcType) {
                return true;
            }
        }
    }

    return false;
}

static void inspectTypes(Connection connection) throws SQLException {
    DatabaseMetaData metadata = connection.getMetaData();

    System.out.println("Driver: " + metadata.getDriverName());
    System.out.println("Driver version: " + metadata.getDriverVersion());
    System.out.println("JDBC version: "
        + metadata.getJDBCMajorVersion() + "."
        + metadata.getJDBCMinorVersion());

    System.out.println("Database: " + metadata.getDatabaseProductName());
    System.out.println("Database version: " + metadata.getDatabaseProductVersion());

    System.out.println("Advertises JSON: "
        + advertisesType(metadata, Types.JSON));

    System.out.println("Advertises DECFLOAT: "
        + advertisesType(metadata, Types.DECFLOAT));
}
~~~

Đây là bước khảo sát hữu ích nhưng không phải phép chứng minh đầy đủ rằng mọi thao tác đều hoạt động:

- `getTypeInfo()` liệt kê các kiểu được driver/database công bố, không kiểm tra toàn bộ khả năng bind và đọc của từng overload.
- Một DBMS có kiểu vendor-specific như JSONB có thể được báo dưới mã khác thay vì `Types.JSON`.
- Metadata có thể không đầy đủ hoặc khác nhau theo driver.
- Việc hỗ trợ tạo cột không nhất thiết đồng nghĩa hỗ trợ mọi phép chuyển đổi Java, stored procedure hoặc toán tử.
- `getJDBCMajorVersion()` và `getJDBCMinorVersion()` chỉ cho biết mức JDBC driver công bố; không chứng minh riêng driver đã hỗ trợ JSON hoặc DECFLOAT.

Do đó, kết hợp metadata với tài liệu driver, phiên bản DBMS và integration test trên đúng môi trường triển khai.

## 9. Kiểm thử khả năng thật bằng integration test

Một kiểm thử tối thiểu nên thực hiện trên database và driver thực tế:

1. Tạo bảng thử nghiệm có cột JSON và DECFLOAT bằng DDL của DBMS.
2. Bind giá trị JSON hợp lệ bằng `JDBCType.JSON`.
3. Thử JSON sai cú pháp và xác nhận hành vi validation của database.
4. Đọc lại JSON và xác nhận mapping Java.
5. Bind DECFLOAT với giá trị thập phân có nhiều chữ số.
6. Đọc lại và so sánh theo precision/exponent mà DBMS công bố.
7. Kiểm tra SQL NULL bằng `setNull()`, `getObject()` và `wasNull()` khi phù hợp.
8. Thử các giá trị biên, giá trị lớn/nhỏ và special values nếu DBMS hỗ trợ.
9. Chạy lại test sau mỗi lần nâng driver hoặc database.

Không chỉ test trên H2 hoặc một database nhúng rồi suy ra khả năng của PostgreSQL, Oracle Database, Db2 hay sản phẩm khác. Mỗi driver có thể có mapping và tính năng riêng. Dùng Testcontainers hoặc môi trường tích hợp tương đương để kiểm tra đúng phiên bản DBMS mà ứng dụng triển khai.

## 10. Xử lý lỗi khi driver không hỗ trợ

Các lỗi thường gặp:

| Lỗi hoặc tình huống | Ý nghĩa | Cách xử lý |
|---|---|---|
| `SQLFeatureNotSupportedException` từ overload `setObject(..., SQLType)` | Driver không triển khai overload hoặc tính năng được yêu cầu | Kiểm tra phiên bản driver; thử overload `Types` nếu driver hỗ trợ; nâng cấp hoặc dùng mapping vendor được tài liệu hóa |
| `SQLFeatureNotSupportedException` khi bind type | Driver không hỗ trợ kiểu đích | Kiểm tra type support, driver docs và DBMS version |
| `SQLException` khi execute | Server từ chối kiểu, conversion hoặc giá trị | Kiểm tra SQL type, DDL, precision và thông báo database |
| `ClassCastException` trong ứng dụng | Code giả định mapping Java không đúng | Dùng metadata và mapping chính thức của driver |
| JSON parse/validation error | Nội dung JSON hoặc quy tắc DBMS không hợp lệ | Kiểm tra JSON, encoding và constraint |
| Mất chữ số DECFLOAT | Giá trị đã bị chuyển qua kiểu Java có precision không phù hợp hoặc bị làm tròn | Kiểm tra mapping, precision và đường chuyển đổi end-to-end |

Đừng bắt mọi `SQLException` rồi chuyển sang `VARCHAR` một cách âm thầm. Việc fallback có thể thay đổi semantics, bỏ mất validation JSON native hoặc làm tròn số DECFLOAT. Chỉ fallback khi hợp đồng lưu trữ và truy vấn cho phép, và phải kiểm thử rõ ràng.

## 11. Thiết kế adapter khi hỗ trợ nhiều DBMS

Nếu ứng dụng kết nối nhiều loại database, tránh rải điều kiện vendor khắp code nghiệp vụ. Tách phần binding và đọc giá trị theo một abstraction:

~~~java
interface JsonJdbcMapping {
    void bind(PreparedStatement statement, int index, String json)
        throws SQLException;

    String read(ResultSet resultSet, String column)
        throws SQLException;
}
~~~

Mỗi DBMS/driver có thể cung cấp implementation phù hợp:

- Driver hỗ trợ `JDBCType.JSON`: dùng overload `SQLType`.
- Driver chỉ hỗ trợ vendor type: dùng API hoặc mapping được nhà cung cấp công bố.
- Database chỉ lưu văn bản: dùng `VARCHAR` và quy tắc validation/cast do ứng dụng xác định.

Tương tự, DECFLOAT có thể cần adapter riêng cho Java class, special values và precision. Không ép mọi driver trả `BigDecimal` nếu hợp đồng driver không cam kết điều đó.

Adapter cần được chọn dựa trên metadata và cấu hình deployment đã xác nhận. Không nên suy ra vendor chỉ từ chuỗi JDBC URL tùy tiện nếu driver cung cấp metadata chính thức.

## 12. Tương thích JDK và trạng thái API

`JDBCType.JSON`, `JDBCType.DECFLOAT`, `Types.JSON` và `Types.DECFLOAT` được thêm trong JDBC 4.5, thuộc Java SE 26. Chúng là API ổn định, không phải preview feature; không cần cờ JVM đặc biệt.

Ứng dụng biên dịch và chạy bằng JDK 26 có thể tham chiếu trực tiếp các constant này. Nếu phải chạy cùng binary trên JDK trước 26, không thể giả định các field mới tồn tại ở runtime đó; việc liên kết có thể thất bại. Hãy đặt baseline runtime là JDK 26 hoặc tách phần tích hợp theo phiên bản runtime trong kiến trúc cần hỗ trợ nhiều JDK.

Việc dùng JDK 26 cũng không tự nâng cấp JDBC driver. Hãy chọn phiên bản driver tương thích với JDK và DBMS, kiểm tra release notes, mapping type và hỗ trợ từng overload trước khi triển khai.

## 13. Checklist trước khi đưa JSON/DECFLOAT vào production

- [ ] JDK build và runtime là Java 26 trở lên nếu code tham chiếu trực tiếp các constant mới.
- [ ] Phiên bản JDBC driver và DBMS được ghi nhận.
- [ ] Tài liệu driver xác nhận hỗ trợ kiểu SQL và Java mapping cần dùng.
- [ ] `DatabaseMetaData.getTypeInfo()` đã được kiểm tra và kết quả được hiểu đúng.
- [ ] DDL của JSON/DECFLOAT đã được kiểm thử trên DBMS mục tiêu.
- [ ] `PreparedStatement` bind theo `JDBCType` hoặc `Types` mà driver hỗ trợ.
- [ ] Mapping khi đọc đã được xác nhận qua `ResultSetMetaData` và tài liệu driver.
- [ ] JSON sai cú pháp, SQL NULL và payload lớn đã được kiểm thử.
- [ ] DECFLOAT đã được kiểm thử precision, exponent, rounding và special values nếu có.
- [ ] Không chuyển DECFLOAT qua `double` nếu cần giữ chính xác thập phân.
- [ ] Không fallback sang `VARCHAR` hoặc kiểu vendor khác mà không đánh giá semantics.
- [ ] Integration test chạy trên đúng driver và phiên bản database production.

## Kết luận

JDBC 4.5 trong Java 26 bổ sung `JDBCType.JSON`, `JDBCType.DECFLOAT` cùng các mã `Types.JSON` và `Types.DECFLOAT`. Đây là các định danh SQL type chuẩn trong Java; chúng giúp ứng dụng chỉ định rõ kiểu đích khi bind và nhận diện kiểu trong metadata. Khả năng lưu, bind, đọc, validation, precision và mapping Java vẫn phụ thuộc driver kết hợp với DBMS. Hãy khảo sát `DatabaseMetaData.getTypeInfo()`, xem tài liệu của driver, kiểm tra metadata cột và chạy integration test với đúng phiên bản triển khai. Với DECFLOAT, giữ semantics số thập phân và tránh chuyển qua `double` khi cần bảo toàn precision; với JSON, dùng parameter binding và xác nhận validation cũng như mapping do driver hỗ trợ.
