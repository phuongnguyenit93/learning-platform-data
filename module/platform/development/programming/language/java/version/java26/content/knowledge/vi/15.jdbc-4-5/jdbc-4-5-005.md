# Quan hệ close, free và vòng đời tài nguyên JDBC

> **Mốc cập nhật: 27-11-2026.** JDBC 4.5 Maintenance Release được tích hợp trong Java SE 26. Điểm thay đổi trọng tâm của bài này là `Array`, `Blob`, `Clob`, `NClob` và `SQLXML` trở thành `AutoCloseable`; mỗi interface có `close()` mặc định gọi `free()`. Vì vậy, từ JDK 26 có thể quản lý trực tiếp các resource này bằng try-with-resources. `Connection`, `Statement` và `ResultSet` vốn đã hỗ trợ `AutoCloseable` từ các phiên bản JDBC trước.

## 1. Mục tiêu

Một thao tác JDBC thường mở nhiều loại resource cùng lúc:

- `Connection` đại diện cho session làm việc với database.
- `Statement` hoặc `PreparedStatement` đại diện cho câu lệnh được thực thi.
- `ResultSet` đại diện cho cursor kết quả.
- `Blob`, `Clob`, `NClob`, `SQLXML` và `Array` đại diện cho dữ liệu hoặc locator có thể giữ tài nguyên phía driver/database.
- `InputStream`, `Reader`, `OutputStream` và `Writer` dùng để đọc hoặc ghi nội dung LOB/XML.

Nếu chỉ đóng `ResultSet` và `Statement`, một số resource lấy từ kết quả vẫn có thể còn sống. Ngược lại, nếu giải phóng LOB quá sớm, code đang đọc stream hoặc xử lý nội dung có thể gặp `SQLException`.

Sau bài này, bạn có thể:

- Phân biệt `close()` và `free()` trong JDBC 4.5.
- Biết interface nào được bổ sung `AutoCloseable` từ JDK 26.
- Hiểu quan hệ vòng đời giữa Connection, Statement, ResultSet và LOB.
- Dùng try-with-resources đúng thứ tự và đúng ownership.
- Đóng stream/reader riêng với object JDBC cung cấp stream.
- Xử lý transaction trước khi đóng Connection.
- Nhận biết resource gắn với transaction và các giới hạn phụ thuộc JDBC driver.

## 2. JDBC 4.5 thay đổi điều gì?

JDBC 4.5 Maintenance Release bổ sung hỗ trợ quản lý tài nguyên nhất quán hơn cho các kiểu dữ liệu lớn và object đại diện dữ liệu SQL.

Năm interface sau mở rộng `AutoCloseable`:

| Interface | Ánh xạ SQL | API mới trong JDK 26 |
|---|---|---|
| `Array` | `ARRAY` | `close()` mặc định gọi `free()` |
| `Blob` | `BLOB` | `close()` mặc định gọi `free()` |
| `Clob` | `CLOB` | `close()` mặc định gọi `free()` |
| `NClob` | `NCLOB` | Kế thừa `AutoCloseable` và `close()` từ `Clob` |
| `SQLXML` | `SQLXML` | `close()` mặc định gọi `free()` |

Các API này thuộc package `java.sql` và `javax.sql` của Java SE. Javadoc đánh dấu các phương thức `close()` mới bằng `Since: 26`.

### 2.1. Connection, Statement và ResultSet đã có từ trước

Không phải toàn bộ JDBC resource chỉ từ JDBC 4.5 mới dùng được try-with-resources.

| Resource | Hỗ trợ AutoCloseable | Mốc API |
|---|---|---|
| `Connection` | Có | JDBC 4.1 / Java 7 |
| `Statement` và `PreparedStatement` | Có | JDBC 4.1 / Java 7 |
| `ResultSet` | Có | JDBC 4.1 / Java 7 |
| `Array`, `Blob`, `Clob`, `NClob`, `SQLXML` | Có từ JDBC 4.5 MR | Java 26 |

Điểm mới của JDBC 4.5 là đưa các object dữ liệu lớn/locator vào cùng mô hình đóng tài nguyên tự động. Nhờ đó code không còn phải tự viết khối finally chỉ để gọi `free()` cho các interface này.

### 2.2. close() và free() có quan hệ gì?

`free()` là API đã tồn tại từ trước để giải phóng tài nguyên do `Array`, `Blob`, `Clob`, `NClob` hoặc `SQLXML` nắm giữ.

JDBC 4.5 bổ sung `close()` để tích hợp với `AutoCloseable`. Implementation mặc định của `close()` gọi `free()`:

~~~java
default void close() throws SQLException {
    free();
}
~~~

Đoạn trên mô tả hợp đồng mặc định của API. Driver có thể cung cấp implementation riêng theo hợp đồng interface.

| Phương thức | Ý nghĩa | Cách dùng |
|---|---|---|
| `free()` | Đóng và giải phóng tài nguyên của object. | Vẫn là API hợp lệ; có thể gọi trực tiếp khi cần. |
| `close()` | Đóng object theo hợp đồng `AutoCloseable`; mặc định gọi `free()`. | Cách dùng ưu tiên khi quản lý bằng try-with-resources. |

Cả hai phương thức đều không làm gì nếu object đã được đóng. Sau khi object đã đóng, gọi các phương thức khác ngoài `free()` hoặc `close()` thường dẫn đến `SQLException` theo hợp đồng API.

**Không cần gọi cả `close()` lẫn `free()` cho cùng một object.** Khi dùng try-with-resources, JVM gọi `close()` tự động; implementation mặc định đã chuyển tiếp sang `free()`.

## 3. Vòng đời của các resource JDBC

Một câu truy vấn thường có cấu trúc sở hữu như sau:

~~~mermaid
flowchart TD
    C["Connection"] --> S["Statement / PreparedStatement"]
    S --> R["ResultSet"]
    R --> L["Blob / Clob / NClob / SQLXML / Array"]
    L --> IO["InputStream / Reader / Writer"]
    IO --> X["Đóng stream"]
    X --> Y["Đóng LOB bằng close()"]
    Y --> Z["Đóng ResultSet"]
    Z --> Q["Đóng Statement"]
    Q --> P["Đóng Connection"]
~~~

Sơ đồ thể hiện thứ tự đóng an toàn cho các resource được mở lồng nhau. Quan hệ thực tế giữa từng object còn phụ thuộc loại resource và JDBC driver.

### 3.1. Connection

`Connection` đại diện cho một session database. Khi đóng Connection:

- Các tài nguyên JDBC/database thuộc connection được giải phóng.
- Các statement đang gắn với connection không còn dùng được.
- Connection không còn hợp lệ cho các thao tác JDBC tiếp theo.
- Nếu connection do pool cung cấp, `close()` trên logical connection thường trả handle về pool để tái sử dụng; pool quản lý physical connection.

`Connection.close()` không thay thế `commit()` hoặc `rollback()`. Nếu transaction vẫn đang hoạt động, kết quả khi đóng Connection là implementation-defined. Ứng dụng cần commit hoặc rollback rõ ràng trước khi Connection đóng.

### 3.2. Statement và PreparedStatement

`Statement.close()` giải phóng tài nguyên của statement. Nếu statement có current ResultSet, ResultSet đó cũng được đóng.

Một ResultSet cũng tự đóng khi statement tạo ra nó bị:

- Đóng.
- Thực thi lại.
- Dùng để lấy result tiếp theo trong chuỗi nhiều kết quả.

Vì vậy, không giữ ResultSet để dùng sau khi Statement tương ứng đã đóng.

### 3.3. ResultSet

`ResultSet.close()` giải phóng cursor và tài nguyên của result set. Gọi close lần nữa không gây lỗi.

Một chi tiết quan trọng: đóng ResultSet **không đóng các Blob, Clob hoặc NClob được tạo ra từ ResultSet đó**. Các object này còn hiệu lực ít nhất trong thời gian transaction tạo ra chúng, trừ khi ứng dụng gọi `free()` hoặc `close()`.

Do đó, khi lấy LOB từ ResultSet, hãy quản lý vòng đời LOB riêng. Đừng dựa vào việc đóng ResultSet để giải phóng LOB.

Ngoài ra, nếu một InputStream được mở trực tiếp cho dòng hiện tại của ResultSet, gọi `next()` có thể tự động đóng stream đó. Hãy đọc xong stream của dòng hiện tại trước khi chuyển sang dòng tiếp theo.

### 3.4. Blob, Clob, NClob, SQLXML và Array

Các object này có thể là locator tới dữ liệu do database quản lý, thay vì chứa toàn bộ nội dung trong heap Java.

Ví dụ:

- `Blob` có thể giữ locator tới dữ liệu nhị phân lớn.
- `Clob` và `NClob` có thể giữ locator tới dữ liệu ký tự lớn.
- `SQLXML` có thể giữ locator tới dữ liệu XML.
- `Array` có thể giữ locator tới giá trị SQL ARRAY.

Một số object có hiệu lực gắn với transaction tạo ra chúng. Vì vậy, không nên giữ locator qua thời điểm transaction hoặc connection kết thúc nếu driver/database không bảo đảm điều đó.

### 3.5. Stream và Reader/Writer

Stream lấy từ LOB/XML là resource riêng:

- `Blob.getBinaryStream()` trả `InputStream`.
- `Clob.getCharacterStream()` trả `Reader`.
- `SQLXML.getBinaryStream()` trả `InputStream`.
- `SQLXML.setCharacterStream()` trả `Writer`.

Đóng LOB không nên được dùng thay cho việc đóng stream. Hãy đóng stream/reader/writer trước, sau đó đóng LOB/XML object. Cách viết lồng try-with-resources giúp thứ tự này được bảo đảm.

## 4. Dùng try-with-resources cho truy vấn JDBC

Với JDK 26 trở lên, có thể khai báo toàn bộ resource trong cùng một try-with-resources:

~~~java
import javax.sql.DataSource;
import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.ResultSet;

public final class CustomerRepository {
    private final DataSource dataSource;

    public CustomerRepository(DataSource dataSource) {
        this.dataSource = dataSource;
    }

    public void printCustomers() throws Exception {
        String sql = "SELECT id, name FROM customer";

        try (Connection connection = dataSource.getConnection();
             PreparedStatement statement =
                     connection.prepareStatement(sql);
             ResultSet resultSet = statement.executeQuery()) {

            while (resultSet.next()) {
                long id = resultSet.getLong("id");
                String name = resultSet.getString("name");

                System.out.println(id + " - " + name);
            }
        }
    }
}
~~~

Các resource được đóng theo thứ tự ngược với thứ tự khai báo:

1. `ResultSet.close()`.
2. `PreparedStatement.close()`.
3. `Connection.close()`.

Thứ tự này phù hợp với quan hệ sử dụng: ResultSet được tạo từ Statement, Statement được tạo từ Connection.

Nếu thân try ném exception và thao tác close cũng ném exception, exception từ close được lưu trong danh sách suppressed exceptions của exception chính. Cách này giữ lại lỗi xử lý nghiệp vụ lẫn lỗi giải phóng tài nguyên.

## 5. Dùng Blob với close() và free()

Ví dụ đọc dữ liệu nhị phân từ cột BLOB:

~~~java
import java.io.InputStream;
import java.sql.Blob;
import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import javax.sql.DataSource;
import java.io.OutputStream;

static void copyDocument(
        DataSource dataSource,
        long documentId,
        OutputStream destination) throws Exception {

    String sql = "SELECT payload FROM document WHERE id = ?";

    try (Connection connection = dataSource.getConnection();
         PreparedStatement statement =
                 connection.prepareStatement(sql)) {

        statement.setLong(1, documentId);

        try (ResultSet resultSet = statement.executeQuery()) {
            if (!resultSet.next()) {
                return;
            }

            try (Blob blob = resultSet.getBlob("payload")) {
                if (blob == null) {
                    return;
                }

                try (InputStream input = blob.getBinaryStream()) {
                    input.transferTo(destination);
                }
            }
        }
    }
}
~~~

Thứ tự đóng trong ví dụ:

1. Đóng InputStream sau khi copy xong.
2. Đóng Blob; default close gọi free.
3. Đóng ResultSet.
4. Đóng PreparedStatement.
5. Đóng Connection.

Nếu cột SQL là NULL, driver có thể trả về null. Try-with-resources bỏ qua bước close đối với resource null, nhưng code vẫn phải kiểm tra null trước khi gọi phương thức trên object.

Không giữ Blob sau khi Connection/transaction kết thúc để dùng ở một luồng xử lý khác. Nếu cần dùng dữ liệu lâu hơn, hãy materialize nội dung thành byte array/file hoặc chuyển sang abstraction lưu trữ độc lập với JDBC locator.

## 6. Dùng Clob và NClob

`Clob` và `NClob` có cùng mô hình vòng đời với Blob. Khác biệt chính nằm ở nội dung ký tự và cách đọc:

~~~java
import java.io.Reader;
import java.sql.Clob;
import java.sql.PreparedStatement;
import java.sql.ResultSet;

static String readDescription(
        java.sql.Connection connection,
        long documentId) throws Exception {

    String sql = "SELECT description FROM document WHERE id = ?";

    try (PreparedStatement statement =
                 connection.prepareStatement(sql)) {

        statement.setLong(1, documentId);

        try (ResultSet resultSet = statement.executeQuery()) {
            if (!resultSet.next()) {
                return null;
            }

            try (Clob clob = resultSet.getClob("description")) {
                if (clob == null) {
                    return null;
                }

                try (Reader reader = clob.getCharacterStream()) {
                    StringBuilder text = new StringBuilder();
                    char[] buffer = new char[4096];

                    int count;
                    while ((count = reader.read(buffer)) != -1) {
                        text.append(buffer, 0, count);
                    }

                    return text.toString();
                }
            }
        }
    }
}
~~~

`NClob` mở rộng `Clob` và đại diện cho SQL NCLOB dùng national character set. Vì NClob kế thừa close/free từ Clob, nó cũng dùng được trong try-with-resources từ JDK 26.

Không cần gọi `clob.free()` sau khối try. `close()` đã được gọi tự động và implementation mặc định gọi `free()`.

## 7. Dùng Array và ResultSet con

`Array` biểu diễn SQL ARRAY. Nó có thể trả nội dung thành Java array hoặc tạo ResultSet chứa từng phần tử.

Khi dùng `Array.getResultSet()`, có hai resource cần đóng: ResultSet con và Array. Khai báo lồng nhau để ResultSet con đóng trước:

~~~java
import java.sql.Array;
import java.sql.ResultSet;

static void printTags(java.sql.Connection connection)
        throws Exception {

    String sql = "SELECT tags FROM article WHERE id = ?";

    try (var statement = connection.prepareStatement(sql)) {
        statement.setLong(1, 100L);

        try (var rows = statement.executeQuery()) {
            if (!rows.next()) {
                return;
            }

            try (Array tags = rows.getArray("tags")) {
                if (tags == null) {
                    return;
                }

                try (ResultSet elements = tags.getResultSet()) {
                    while (elements.next()) {
                        Object value = elements.getObject(2);
                        System.out.println(value);
                    }
                }
            }
        }
    }
}
~~~

`Array` có thể dùng SQL locator và có hiệu lực theo transaction. Hãy đọc hết dữ liệu cần thiết và đóng ResultSet con/Array trong phạm vi transaction.

## 8. Dùng SQLXML và đóng stream đúng thời điểm

`SQLXML` có trạng thái đọc/ghi. Theo hợp đồng API, dữ liệu XML chỉ có thể được đọc hoặc ghi tối đa một lần theo các trạng thái tương ứng:

- Sau khi gọi API đọc như `getString()`, `getBinaryStream()`, `getCharacterStream()` hoặc `getSource()`, object chuyển sang trạng thái không đọc được.
- Sau khi gọi API ghi như `setString()`, `setBinaryStream()`, `setCharacterStream()` hoặc `setResult()`, object chuyển sang trạng thái không ghi được.
- `close()` hoặc `free()` cũng kết thúc khả năng đọc/ghi.
- Tất cả stream phải được đóng trước khi gọi execute; nếu không, thao tác có thể ném `SQLException`.

Ví dụ tạo SQLXML và ghi bằng Writer:

~~~java
import java.io.Writer;
import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.SQLXML;

static void insertXml(Connection connection) throws Exception {
    String sql = "INSERT INTO document_xml(payload) VALUES (?)";

    try (SQLXML xml = connection.createSQLXML()) {
        try (Writer writer = xml.setCharacterStream()) {
            writer.write("<document><status>ready</status></document>");
        }

        try (PreparedStatement statement =
                     connection.prepareStatement(sql)) {
            statement.setSQLXML(1, xml);
            statement.executeUpdate();
        }
    }
}
~~~

Writer được đóng trước khi execute. SQLXML được đóng sau khi câu lệnh hoàn tất. Khi đọc XML, hãy đóng Reader/InputStream trước khi đóng SQLXML.

Nếu cần xử lý XML nhiều lần, hãy đọc nội dung vào một biểu diễn độc lập như String, byte array hoặc object XML đã parse. Không gọi nhiều API đọc trên cùng SQLXML locator với giả định dữ liệu có thể đọc lại.

## 9. free() vẫn là API hợp lệ

JDBC 4.5 bổ sung close để dùng với AutoCloseable, nhưng không loại bỏ free.

| Tình huống | Cách dùng |
|---|---|
| Code mới trên JDK 26+ | Dùng try-with-resources và close tự động. |
| Có resource cần đóng trong một scope rõ ràng | Dùng try-with-resources. |
| API cũ hoặc code cần gọi giải phóng ngay tại một điểm cụ thể | Có thể gọi free trực tiếp. |
| Object đã được đóng trước đó | Gọi close/free lần nữa không làm gì. |

Không gọi cả hai phương thức liên tiếp chỉ để “chắc chắn”. Nếu đã dùng try-with-resources, không cần gọi free thủ công ở finally.

Việc bổ sung default method giúp các implementation hiện có có thể kế thừa hành vi close từ interface mà không buộc ứng dụng phải tự quản lý thêm một loại resource khác.

## 10. Transaction và thứ tự đóng Connection

Đóng Connection là giải phóng session/resource, không phải cách xác định kết quả transaction.

Nếu auto-commit đang bật, mỗi statement hoàn tất sẽ tự commit theo cấu hình JDBC. Nếu đã gọi `setAutoCommit(false)`, ứng dụng phải gọi `commit()` để lưu thay đổi hoặc `rollback()` để hủy thay đổi.

Javadoc quy định nếu Connection.close() được gọi trong khi transaction còn hoạt động, kết quả là implementation-defined. Vì vậy, không dựa vào việc driver tự rollback hoặc tự commit khi Connection đóng.

Ví dụ quản lý transaction rõ ràng:

~~~java
import java.sql.Connection;
import java.sql.PreparedStatement;
import java.sql.SQLException;
import javax.sql.DataSource;

static void updateStatus(DataSource dataSource, long id)
        throws SQLException {

    try (Connection connection = dataSource.getConnection()) {
        connection.setAutoCommit(false);

        try (PreparedStatement statement =
                     connection.prepareStatement(
                             "UPDATE job SET status = ? WHERE id = ?")) {

            statement.setString(1, "DONE");
            statement.setLong(2, id);
            statement.executeUpdate();

            connection.commit();

        } catch (SQLException | RuntimeException failure) {
            try {
                connection.rollback();
            } catch (SQLException rollbackFailure) {
                failure.addSuppressed(rollbackFailure);
            }

            throw failure;
        }
    }
}
~~~

Các resource statement được đóng trước Connection. Nếu xử lý lỗi, rollback được thực hiện trước khi Connection đóng. Nếu rollback cũng lỗi, exception rollback được thêm vào suppressed exceptions để không làm mất lỗi ban đầu.

Trong ứng dụng dùng connection pool, gọi close trên logical Connection khi kết thúc unit of work để trả connection về pool. Không giữ Connection hoặc LOB locator qua nhiều request.

## 11. Những lỗi vòng đời thường gặp

| Lỗi | Hệ quả | Cách xử lý |
|---|---|---|
| Chỉ đóng ResultSet, bỏ quên Blob/Clob | Locator hoặc tài nguyên LOB còn được giữ. | Đóng LOB bằng try-with-resources hoặc free. |
| Nghĩ Statement.close tự giải phóng mọi LOB lấy từ ResultSet | Có thể rò rỉ tài nguyên LOB; ResultSet.close không đóng Blob/Clob/NClob. | Quản lý từng LOB riêng. |
| Đóng Blob trước InputStream | Stream đang đọc có thể không còn sử dụng được. | Đóng stream/reader trước rồi đóng Blob/Clob. |
| Dùng Blob sau khi transaction kết thúc | Locator có thể không còn hợp lệ. | Materialize dữ liệu trước khi kết thúc transaction nếu cần giữ lâu hơn. |
| Gọi free rồi tiếp tục đọc object | Thường nhận SQLException. | Dừng sử dụng object sau close/free. |
| Đọc SQLXML nhiều lần | API có thể ném SQLException do trạng thái không còn readable. | Đọc một lần, lưu kết quả nếu cần dùng lại. |
| Gọi execute khi stream ghi SQLXML chưa đóng | Có thể ném SQLException. | Đóng Writer/OutputStream trước execute. |
| Đóng Connection khi transaction còn mở | Kết quả transaction phụ thuộc implementation. | Commit hoặc rollback rõ ràng trước close. |
| Dùng close() mới nhưng target JDK thấp hơn 26 | Code có thể không compile vì LOB interface chưa AutoCloseable. | Đặt baseline compile/runtime phù hợp với JDBC 4.5. |
| Giả định mọi driver hỗ trợ mọi kiểu LOB/ARRAY/XML | Driver có thể ném SQLFeatureNotSupportedException. | Kiểm tra tài liệu và khả năng hỗ trợ của driver/database. |

## 12. Hỗ trợ từ JDBC driver

JDK 26 cung cấp API JDBC 4.5, nhưng việc sử dụng một kiểu dữ liệu vẫn phụ thuộc vào database và driver.

Cần kiểm tra:

- Database có hỗ trợ SQL type tương ứng không.
- JDBC driver có triển khai type đó không.
- Các thao tác stream/locator có được driver hỗ trợ không.
- Driver có hành vi đóng resource phù hợp với ứng dụng không.
- Các thao tác không hỗ trợ có ném `SQLFeatureNotSupportedException` hay không.

Javadoc của các interface yêu cầu driver triển khai đầy đủ các method nếu driver hỗ trợ kiểu dữ liệu tương ứng. Không suy luận rằng mọi database đều hỗ trợ SQL ARRAY, NCLOB hoặc SQLXML chỉ vì JDK có interface.

Nếu nâng JDK lên 26 để dùng try-with-resources cho LOB, vẫn nên kiểm tra phiên bản driver đang dùng và chạy integration test trên đúng database production.

## 13. Bài tập thực hành

1. Viết truy vấn dùng Connection, PreparedStatement và ResultSet trong một try-with-resources; xác nhận thứ tự đóng ngược.
2. Lấy một Blob từ ResultSet, đọc bằng InputStream và đóng cả hai resource.
3. Lấy Clob và NClob; đọc bằng Reader, sau đó kiểm tra object không còn dùng được sau close.
4. Lấy Array, gọi getResultSet và đóng ResultSet con trước Array.
5. Tạo SQLXML, ghi dữ liệu bằng Writer, đóng Writer rồi mới execute câu lệnh.
6. Thử đọc SQLXML hai lần qua hai API đọc khác nhau; ghi nhận trạng thái và SQLException theo hợp đồng.
7. Gọi free() rồi gọi close() lần nữa; xác nhận thao tác đóng lặp không làm gì.
8. Đóng ResultSet nhưng vẫn giữ Blob trong cùng transaction; kiểm tra khác biệt giữa vòng đời ResultSet và Blob.
9. Tắt auto-commit, thực hiện cập nhật rồi commit; lặp lại với rollback khi có lỗi.
10. Chạy thử với driver không hỗ trợ một kiểu dữ liệu; xác định exception được trả về và cách ứng dụng xử lý.
11. So sánh thời gian compile target JDK 25 và JDK 26 đối với code khai báo Blob trong try-with-resources.

Bảng ghi nhận:

| Resource | Mở bằng | Đóng bằng | Thời điểm cần đóng |
|---|---|---|---|
| Connection | DataSource / DriverManager | close() | Khi unit of work kết thúc, sau commit/rollback. |
| Statement | Connection.prepareStatement/createStatement | close() | Sau khi thực thi và dùng hết kết quả. |
| ResultSet | Statement.executeQuery/getResultSet | close() | Sau khi đọc hết cursor. |
| Blob/Clob/NClob | ResultSet getter hoặc Connection factory | close() hoặc free() | Khi đọc/ghi LOB xong, trong transaction phù hợp. |
| SQLXML | ResultSet getter hoặc Connection.createSQLXML | close() hoặc free() | Sau khi đọc/ghi và execute xong. |
| Array | ResultSet getter hoặc Connection.createArrayOf | close() hoặc free() | Sau khi đọc hết dữ liệu/ResultSet con. |
| InputStream/Reader/Writer | LOB/XML getter/setter | close() | Trước khi đóng LOB/XML và trước khi execute theo yêu cầu API. |

## 14. Checklist trước khi phát hành

- [ ] Dùng JDK 26+ nếu muốn khai báo Blob/Clob/NClob/SQLXML/Array trực tiếp trong try-with-resources.
- [ ] Hiểu close() mới mặc định gọi free().
- [ ] Không gọi close() và free() liên tiếp cho cùng một object.
- [ ] Quản lý Blob/Clob/NClob riêng vì ResultSet.close() không đóng chúng.
- [ ] Đóng stream/reader/writer trước object LOB/XML sở hữu dữ liệu.
- [ ] Không giữ locator quá transaction lifetime.
- [ ] Đóng Statement/ResultSet trước Connection.
- [ ] Commit hoặc rollback transaction trước Connection.close().
- [ ] Không dựa vào Connection.close() để quyết định transaction outcome.
- [ ] Kiểm tra driver/database hỗ trợ các SQL type cần dùng.
- [ ] Kiểm tra exception từ close và suppressed exceptions khi cleanup lỗi.
- [ ] Dùng integration test để xác minh hành vi driver trong môi trường triển khai.
