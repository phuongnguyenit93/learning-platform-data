# Phân biệt không hỗ trợ giao thức, lỗi TLS và lỗi kết nối

Khi dùng HTTP/3 với Java 26, một request thất bại có thể xuất phát từ ba nhóm nguyên nhân khác nhau: implementation không thể sử dụng HTTP/3, quá trình bảo mật TLS 1.3 trong QUIC gặp lỗi, hoặc kết nối mạng không được thiết lập/duy trì thành công. Phân loại đúng giúp chọn cách khắc phục phù hợp và tránh thay đổi cấu hình bảo mật chỉ để làm request chạy được.

HTTP/3 là phần mở rộng chính thức của HTTP Client API trong module **java.net.http** từ Java 26. API không ở trạng thái preview hoặc incubator. Tuy nhiên, việc API tồn tại không bảo đảm mọi client, server, SSL provider và mạng đều có thể sử dụng HTTP/3. Nội dung bài tập trung vào cách đọc lỗi trong đúng bối cảnh JDK 26, đặc biệt với **HttpClient.Version.HTTP_3** và **HttpOption.H3_DISCOVERY**.

## 1. Nhìn lỗi theo từng giai đoạn

Một request HTTP/3 trải qua các bước: tạo HttpClient, chọn cách khám phá endpoint, phân giải tên miền, mở đường truyền QUIC qua UDP, thực hiện bắt tay TLS 1.3 trong QUIC, trao đổi HTTP/3 và nhận response. Lỗi ở mỗi giai đoạn có dấu hiệu khác nhau.

| Nhóm lỗi | Dấu hiệu thường gặp | Điều cần xác minh trước |
|---|---|---|
| Không hỗ trợ giao thức hoặc cấu hình | **UnsupportedProtocolVersionException**, đôi khi nằm trong **UncheckedIOException** lúc build client | JDK và implementation có hỗ trợ HTTP/3 không; SSLContext/SSLParameters có tương thích không; chế độ discovery có yêu cầu HTTP/3 trực tiếp không |
| Lỗi TLS hoặc xác minh danh tính | **SSLHandshakeException**, **SSLPeerUnverifiedException**, **SSLException** hoặc một lỗi bảo mật nằm trong cause chain | Chứng thư, hostname, truststore, TLS 1.3 và SSLContext tùy chỉnh |
| Lỗi kết nối hoặc timeout | **UnknownHostException**, **HttpConnectTimeoutException**, **HttpTimeoutException**, hoặc **IOException** khác | DNS, UDP/QUIC, firewall, NAT, endpoint, proxy và thời gian chờ |
| Server trả lỗi HTTP | Có response với status **4xx** hoặc **5xx** | HTTP exchange đã nhận được response; kiểm tra status, header và body theo nghiệp vụ |

Mã trạng thái HTTP 4xx/5xx không tự động có nghĩa là lỗi TLS hay lỗi kết nối. Nếu đã nhận được HttpResponse, kết nối và trao đổi HTTP đủ thành công để server trả lời. Ứng dụng cần xử lý status code và nội dung response theo hợp đồng API.

Cũng cần phân biệt phiên bản được yêu cầu với phiên bản thực tế. Đặt HTTP/3 làm phiên bản ưu tiên không chứng minh request đã chạy qua QUIC. Hãy kiểm tra **HttpResponse.version()** sau khi nhận response.

## 2. Không hỗ trợ HTTP/3: hiểu đúng UnsupportedProtocolVersionException

**UnsupportedProtocolVersionException** là exception thuộc **java.net.http**, kế thừa IOException và có từ Java 26. Nó biểu thị HTTP client không hỗ trợ phiên bản giao thức được yêu cầu.

Tài liệu Java SE 26 nêu một trường hợp điển hình: ứng dụng cấu hình HttpClient dùng HTTP/3 nhưng SSLContext bên dưới không đáp ứng yêu cầu của implementation QUIC mà client sử dụng. Lỗi này có thể xuất hiện khi xây dựng client với HTTP/3 là phiên bản ưu tiên, hoặc khi gửi request yêu cầu HTTP/3 trực tiếp bằng chế độ **HTTP_3_URI_ONLY**.

Ví dụ cấu hình:

    HttpClient client = HttpClient.newBuilder()
            .version(HttpClient.Version.HTTP_3)
            .build();

Nếu cấu hình không được implementation chấp nhận, lời gọi build có thể ném **UncheckedIOException** vì chữ ký của Builder.build() sử dụng exception không kiểm tra cho lỗi tài nguyên hoặc cấu hình không hợp lệ. Cause bên trong có thể chứa UnsupportedProtocolVersionException. Khi gửi request, UnsupportedProtocolVersionException cũng được mô tả trong API của HttpClient cho trường hợp client cụ thể không hỗ trợ HTTP/3.

Không nên hiểu exception này đơn giản là “server không mở cổng HTTP/3”. Có ba tình huống cần tách biệt:

- **Implementation không thể dùng HTTP/3:** kiểm tra JDK, provider SSLContext, SSLParameters và khả năng của HttpClient đang được tạo. Đây là trường hợp phù hợp với UnsupportedProtocolVersionException.
- **Server không quảng bá hoặc không cung cấp HTTP/3:** hành vi phụ thuộc chế độ discovery. Với **ALT_SVC**, client có thể tiếp tục dùng HTTP/1.1 hoặc HTTP/2 cho đến khi server quảng bá endpoint h3. Với **ANY**, implementation có thể thử QUIC và kết nối TLS/TCP, rồi dùng kết nối thành công trước.
- **Ứng dụng bắt buộc HTTP/3 trực tiếp:** **HTTP_3_URI_ONLY** chỉ thử QUIC tại host và port của URI, không dùng Alternative Services. Nếu endpoint không nhận HTTP/3, request sẽ không có đường fallback sang HTTP/2 hoặc HTTP/1.1.

JDK 26 tích hợp HTTP/3 không sử dụng proxy. Nếu proxy được chọn, chế độ ANY hoặc ALT_SVC có thể bị hạ xuống HTTP/2 hoặc HTTP/1.1 và tùy chọn discovery bị bỏ qua; với HTTP_3_URI_ONLY, request sẽ thất bại. Một response HTTP/2 trong trường hợp này là dấu hiệu cần xem lại proxy và chế độ discovery, không phải bằng chứng API HTTP/3 chưa được hỗ trợ.

Nếu dự án chạy trên JDK 25 hoặc cũ hơn, API **HttpClient.Version.HTTP_3** chưa có trong Java SE của release đó. Mã nguồn tham chiếu enum constant này sẽ không biên dịch với API release 25. Hãy dùng JDK 26 trở lên để biên dịch và chạy mã HTTP/3.

## 3. Lỗi TLS: phân biệt handshake và xác minh chứng thư

HTTP/3 dùng QUIC trên UDP. TLS 1.3 được tích hợp vào QUIC để xác thực peer và thiết lập khóa mã hóa; không có quy trình TLS-over-TCP giống HTTP/2 qua HTTPS. Dù vậy, các vấn đề về chứng thư, danh tính server, thuật toán mật mã và cấu hình SSL vẫn có thể khiến quá trình thiết lập HTTP/3 thất bại.

Một số loại exception thuộc JSSE có ý nghĩa sau:

| Exception | Ý nghĩa | Hướng kiểm tra |
|---|---|---|
| **SSLHandshakeException** | Client và server không thương lượng được mức bảo mật mong muốn | Phiên bản TLS, bộ thuật toán mật mã, chứng thư server và cấu hình handshake |
| **SSLPeerUnverifiedException** | Danh tính của peer chưa được xác minh | Hostname của URI, chứng thư và cơ chế xác minh danh tính |
| **SSLException** | Lỗi chung phát sinh từ subsystem SSL | Đọc message và cause để tìm lỗi cụ thể |
| **UnsupportedProtocolVersionException** | Client không thể sử dụng phiên bản HTTP được yêu cầu; có thể do SSLContext không đáp ứng yêu cầu QUIC | Khả năng tương thích của provider và cấu hình client |

**SSLHandshakeException** nói về việc thương lượng bảo mật thất bại. **SSLPeerUnverifiedException** nói về việc không xác minh được danh tính peer. Hai lỗi này có liên quan nhưng không đồng nghĩa. Chứng thư hết hạn, thiếu CA tin cậy hoặc hostname không khớp thường dẫn đến lỗi xác minh trong quá trình bảo mật; cần xem thông báo và cause cụ thể để xác định nguyên nhân.

Không phải mọi lỗi liên quan TLS của HTTP/3 đều nhất thiết được biểu diễn bằng cùng một lớp exception. Lỗi không tương thích của SSLContext có thể được báo dưới dạng UnsupportedProtocolVersionException; lỗi xảy ra trong lúc bắt tay hoặc xác minh có thể xuất hiện qua SSLException hoặc lớp con, tùy implementation và giai đoạn thất bại. Vì vậy, hãy đọc toàn bộ cause chain thay vì chỉ nhìn tên exception ngoài cùng.

### Kiểm tra SSLContext và SSLParameters

Nếu ứng dụng dùng SSLContext mặc định của JDK, hãy thử cấu hình mặc định trước để xác định lỗi có đến từ cấu hình tùy chỉnh hay không. Nếu phải dùng SSLContext riêng, xác nhận provider đó tương thích với yêu cầu QUIC của HTTP Client JDK 26.

Không tùy tiện tự đặt các SSLParameters liên quan đến giao thức ứng dụng. Tài liệu Builder lưu ý một số tham số mà HTTP Client sử dụng nội bộ, chẳng hạn danh sách application protocol, có thể bị bỏ qua hoặc do implementation quản lý. Khi chuyển từ HTTP/2 sang HTTP/3, cấu hình SSLParameters được sao chép và vẫn phải tương thích với client.

Ví dụ kiểm tra với cấu hình mặc định:

    HttpClient client = HttpClient.newBuilder()
            .version(HttpClient.Version.HTTP_3)
            .connectTimeout(Duration.ofSeconds(10))
            .build();

Nếu ví dụ tối giản dùng SSLContext mặc định hoạt động nhưng client production thất bại, so sánh lần lượt SSLContext, SSLParameters, truststore và proxy selector của hai cấu hình. Thay từng yếu tố một để xác định thay đổi gây lỗi.

Không tắt hostname verification, không cài trust manager chấp nhận mọi chứng thư và không hạ mức bảo mật TLS để “sửa” lỗi. Cách đúng là cài CA hoặc chứng thư hợp lệ vào truststore phù hợp, dùng hostname khớp với chứng thư, và cấu hình provider SSL tương thích.

## 4. Lỗi kết nối: DNS, QUIC/UDP và timeout

HTTP/3 dùng QUIC trên UDP. Vì vậy, các giả định chỉ dựa trên TCP không đủ để chẩn đoán. Một firewall có thể chặn UDP hoặc mạng có thể làm mất gói QUIC; trong trường hợp đó, client có thể chờ timeout thay vì nhận được một thông báo từ chối kết nối giống kiểu TCP.

Các exception thường gặp trong quá trình gửi request:

- **UnknownHostException:** hệ thống không phân giải được địa chỉ IP của hostname. Kiểm tra tên miền, DNS resolver, VPN và DNS nội bộ.
- **HttpConnectTimeoutException:** kết nối dùng cho request không được thiết lập trong thời gian connect timeout. Với implementation tích hợp của JDK, giai đoạn này bao gồm cả TLS handshake.
- **HttpTimeoutException:** response không được nhận trong thời gian timeout đặt ở request. Đây là thời gian của request, không chỉ riêng bước kết nối.
- **IOException:** lỗi I/O khi gửi hoặc nhận. Đây là lớp tổng quát; phải xem cause và log để phân biệt lỗi mạng, giao thức hay bảo mật.

Với HTTP/3, không nên kết luận rằng UDP bị chặn chắc chắn sẽ sinh **ConnectException**. QUIC chạy trên UDP và có thể không nhận được phản hồi khi packet bị lọc hoặc thất lạc; tùy tình huống, lỗi quan sát được có thể là timeout hoặc IOException. JDK không cam kết ánh xạ mọi lỗi đường truyền QUIC thành một exception chuyên biệt duy nhất.

### Đặt timeout đúng mục đích

**HttpClient.Builder.connectTimeout(...)** đặt thời gian cho giai đoạn thiết lập kết nối mới. Nếu không tạo kết nối mới vì client tái sử dụng kết nối sẵn có, connect timeout không có tác dụng cho request đó. Implementation tích hợp của JDK áp dụng connect timeout cho toàn bộ giai đoạn kết nối, bao gồm TLS handshake.

**HttpRequest.Builder.timeout(...)** đặt giới hạn cho thời gian thực hiện request. API quy định timeout áp dụng từ khi bắt đầu thực hiện request đến ít nhất khi HttpResponse được tạo; implementation JDK tích hợp duy trì timeout cho đến khi body subscriber hoàn tất nếu có body.

Ví dụ:

    HttpClient client = HttpClient.newBuilder()
            .version(HttpClient.Version.HTTP_3)
            .connectTimeout(Duration.ofSeconds(8))
            .build();

    HttpRequest request = HttpRequest.newBuilder()
            .uri(URI.create("https://h3.example.test/"))
            .version(HttpClient.Version.HTTP_3)
            .timeout(Duration.ofSeconds(20))
            .GET()
            .build();

Nếu connect timeout xảy ra, kiểm tra DNS, UDP/QUIC, firewall, NAT, endpoint và TLS handshake. Nếu request timeout xảy ra sau khi kết nối đã thiết lập, kiểm tra tốc độ phản hồi server, tải hệ thống, thời gian xử lý và việc tiêu thụ response body.

## 5. Dùng discovery mode để khoanh vùng nguyên nhân

Java 26 cung cấp **HttpOption.H3_DISCOVERY** với ba chế độ. Chọn đúng chế độ giúp phân biệt server chưa quảng bá HTTP/3 với endpoint QUIC trực tiếp không thể kết nối.

| Chế độ | Hành vi | Ý nghĩa khi chẩn đoán |
|---|---|---|
| **ANY** | Implementation tự tìm hoặc thiết lập kết nối; có thể thử HTTP/3 qua QUIC và HTTP qua TLS/TCP | Phù hợp kiểm tra hoạt động thực tế có fallback; response có thể là HTTP/3, HTTP/2 hoặc HTTP/1.1 |
| **ALT_SVC** | Chỉ khám phá HTTP/3 qua thông tin Alternative Services do origin server quảng bá | Nếu chưa có endpoint h3 được quảng bá, request có thể tiếp tục qua HTTP/1.1 hoặc HTTP/2 |
| **HTTP_3_URI_ONLY** | Chỉ thử HTTP/3 trực tiếp tại host và port của URI; không dùng Alt-Svc | Dùng để xác nhận endpoint QUIC trực tiếp; thất bại không tự fallback sang phiên bản khác |

Đoạn mã dưới đây yêu cầu HTTP/3 trực tiếp để kiểm tra endpoint. Thay hostname mẫu bằng máy chủ kiểm thử đã cấu hình HTTP/3:

    HttpRequest request = HttpRequest.newBuilder()
            .uri(URI.create("https://h3.example.test/"))
            .version(HttpClient.Version.HTTP_3)
            .setOption(
                    HttpOption.H3_DISCOVERY,
                    HttpOption.Http3DiscoveryMode.HTTP_3_URI_ONLY
            )
            .timeout(Duration.ofSeconds(20))
            .GET()
            .build();

    HttpClient client = HttpClient.newBuilder()
            .version(HttpClient.Version.HTTP_3)
            .connectTimeout(Duration.ofSeconds(8))
            .build();

Nếu chế độ ANY trả response HTTP/2 nhưng HTTP_3_URI_ONLY thất bại, có thể suy ra đường fallback TCP/TLS đang hoạt động trong khi đường QUIC trực tiếp chưa thành công. Tiếp tục kiểm tra UDP, port, server listener, SSLContext và log QUIC. Kết quả này tự nó chưa chứng minh firewall là nguyên nhân duy nhất.

Nếu ALT_SVC trả HTTP/2, kiểm tra response đầu tiên có header **Alt-Svc** quảng bá giao thức h3 hay chưa, thời hạn của bản ghi và endpoint được quảng bá. Không cần tự đặt header Alt-Svc trong request để ép server dùng HTTP/3; đây là thông tin do server gửi trong response.

## 6. Đọc exception và cause chain trong Java

Các phương thức **HttpClient.send(...)** khai báo IOException và InterruptedException. Các lỗi chuyên biệt như UnsupportedProtocolVersionException, SSLException, HttpConnectTimeoutException, HttpTimeoutException và UnknownHostException đều thuộc nhánh IOException. Khi gọi **sendAsync(...)**, future hoàn tất bất thường với IOException; nếu gọi join(), lỗi thường được bọc trong CompletionException.

Ví dụ dưới đây giữ nguyên phân loại exception và in cause chain để tránh bỏ sót lỗi gốc:

    import java.io.IOException;
    import java.io.UncheckedIOException;
    import java.net.URI;
    import java.net.UnknownHostException;
    import java.net.http.HttpClient;
    import java.net.http.HttpOption;
    import java.net.http.HttpRequest;
    import java.net.http.HttpResponse;
    import java.net.http.HttpConnectTimeoutException;
    import java.net.http.HttpTimeoutException;
    import java.net.http.UnsupportedProtocolVersionException;
    import java.time.Duration;
    import javax.net.ssl.SSLException;

    public class Http3Diagnostics {
        static void printCauses(Throwable error) {
            for (Throwable current = error;
                    current != null;
                    current = current.getCause()) {
                System.err.println(
                        current.getClass().getName() + ": "
                                + current.getMessage()
                );
            }
        }

        public static void main(String[] args) {
            HttpClient client;

            try {
                client = HttpClient.newBuilder()
                        .version(HttpClient.Version.HTTP_3)
                        .connectTimeout(Duration.ofSeconds(8))
                        .build();
            } catch (UncheckedIOException e) {
                System.err.println("Không tạo được HttpClient với cấu hình này.");
                printCauses(e);
                return;
            }

            try (client) {
                HttpRequest request = HttpRequest.newBuilder()
                        .uri(URI.create("https://h3.example.test/"))
                        .version(HttpClient.Version.HTTP_3)
                        .setOption(
                                HttpOption.H3_DISCOVERY,
                                HttpOption.Http3DiscoveryMode.HTTP_3_URI_ONLY
                        )
                        .timeout(Duration.ofSeconds(20))
                        .GET()
                        .build();

                HttpResponse<String> response = client.send(
                        request,
                        HttpResponse.BodyHandlers.ofString()
                );

                System.out.println("HTTP version: " + response.version());
                System.out.println("Status: " + response.statusCode());

            } catch (UnsupportedProtocolVersionException e) {
                System.err.println("Client không hỗ trợ HTTP/3 trong cấu hình này.");
                printCauses(e);
            } catch (SSLException e) {
                System.err.println("Lỗi TLS hoặc xác minh danh tính peer.");
                printCauses(e);
            } catch (HttpConnectTimeoutException e) {
                System.err.println("Hết thời gian thiết lập kết nối.");
                printCauses(e);
            } catch (HttpTimeoutException e) {
                System.err.println("Request không nhận response đúng hạn.");
                printCauses(e);
            } catch (UnknownHostException e) {
                System.err.println("Không phân giải được hostname.");
                printCauses(e);
            } catch (IOException e) {
                System.err.println("Lỗi I/O khi gửi hoặc nhận HTTP request.");
                printCauses(e);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
                System.err.println("Request bị thread interrupt.");
            }
        }
    }

Các catch block được đặt theo thứ tự từ exception chuyên biệt đến lớp cha. **HttpConnectTimeoutException** là lớp con của HttpTimeoutException nên phải được bắt trước. UnsupportedProtocolVersionException và SSLException là các nhánh IOException riêng, cũng cần bắt trước IOException tổng quát.

Ví dụ dùng HTTP_3_URI_ONLY để kiểm tra kết nối trực tiếp. Khi chuyển sang ANY hoặc ALT_SVC, response có thể là HTTP/2 hoặc HTTP/1.1 mà không phát sinh exception; hãy xem giá trị response.version() và log để hiểu quyết định của client.

Không nên chỉ ghi lại getMessage() của exception ngoài cùng. Cause chain thường chứa thông tin quan trọng hơn, nhất là khi lỗi cấu hình bị bọc trong UncheckedIOException hoặc lỗi bất đồng bộ được bọc trong CompletionException.

## 7. Bật log HTTP/3 và QUIC khi cần

JDK 26 tích hợp thuộc tính **jdk.httpclient.HttpClient.log** cho Platform Logging API. Các nhóm có thể bật gồm **errors**, **requests**, **headers**, **ssl**, **http3** và **quic**. Với QUIC, có thể chọn nhóm chi tiết như **control**, **retransmit**, **crypto** hoặc **all**.

Ví dụ chạy chương trình với log phục vụ chẩn đoán:

    java -Djdk.httpclient.HttpClient.log=errors,requests,ssl,http3,quic:control:retransmit -cp out Http3Diagnostics

Bắt đầu với **errors**, **requests**, **ssl**, **http3** và **quic:control:retransmit**. Nếu cần thêm chi tiết, mở rộng nhóm log theo từng vấn đề:

- Không thấy request dùng HTTP/3: kiểm tra nhóm **http3** và lựa chọn discovery.
- QUIC liên tục truyền lại packet: kiểm tra **quic:retransmit**, firewall, NAT, mất gói và chất lượng đường truyền.
- Lỗi bảo mật: bật **ssl** và xem exception/cause về handshake hoặc xác minh peer.
- Lỗi ở tầng điều khiển stream: bổ sung **quic:control**.

Log có thể chứa URL, header, thông tin endpoint và chi tiết trao đổi. Chỉ bật ở môi trường phù hợp, giới hạn quyền truy cập và thời gian lưu log; không chia sẻ dữ liệu xác thực hoặc thông tin nhạy cảm trong log hỗ trợ.

## 8. Quy trình chẩn đoán thực tế

Thực hiện theo thứ tự để không nhầm một lỗi cấu hình với lỗi mạng:

1. **Xác nhận phiên bản JDK:** chạy java --version và javac --version; cả compiler và runtime phải hỗ trợ API HTTP/3 từ Java 26.
2. **Xác nhận URI:** dùng scheme https. URI http không được gửi bằng HTTP/3 trong implementation JDK.
3. **Kiểm tra proxy:** JDK HTTP Client tích hợp không dùng HTTP/3 khi request đi qua proxy. Kiểm tra ProxySelector mặc định và cấu hình proxy của môi trường.
4. **Kiểm tra chế độ discovery:** ANY cho phép fallback; ALT_SVC cần thông tin h3 được quảng bá; HTTP_3_URI_ONLY yêu cầu QUIC trực tiếp.
5. **Đọc exception và cause chain:** phân biệt UnsupportedProtocolVersionException, SSLException, UnknownHostException và timeout.
6. **Kiểm tra mạng:** xác nhận DNS, UDP, firewall, NAT và port QUIC được phép đến đúng endpoint.
7. **Kiểm tra TLS:** dùng truststore và chứng thư hợp lệ; so sánh SSLContext/SSLParameters với cấu hình mặc định nếu nghi ngờ provider.
8. **Đọc response.version():** nếu nhận được response, xác định phiên bản HTTP thực tế và kiểm tra status code.
9. **Bật log có mục tiêu:** dùng errors, ssl, http3 và quic khi cần bằng chứng sâu hơn.

| Kết quả quan sát | Diễn giải hợp lý | Bước tiếp theo |
|---|---|---|
| Client build thất bại với UncheckedIOException, cause là UnsupportedProtocolVersionException | Cấu hình hoặc implementation không đáp ứng yêu cầu HTTP/3 | Kiểm tra SSLContext, SSLParameters và provider |
| HTTP_3_URI_ONLY thất bại, ANY trả HTTP/2 | Đường QUIC trực tiếp chưa thành công nhưng đường TLS/TCP hoạt động | Kiểm tra UDP, listener HTTP/3, Alt-Svc và log QUIC |
| SSLHandshakeException hoặc SSLPeerUnverifiedException | Lỗi trong quá trình thương lượng hoặc xác minh danh tính | Kiểm tra TLS, truststore, hostname và chứng thư |
| UnknownHostException | DNS không phân giải hostname | Kiểm tra DNS, VPN và tên endpoint |
| HttpConnectTimeoutException | Giai đoạn thiết lập kết nối vượt thời hạn | Kiểm tra QUIC/UDP, TLS handshake và đường truyền |
| HttpTimeoutException | Request không hoàn tất trong thời hạn | Kiểm tra thời gian xử lý server, body và timeout |
| Response HTTP/2 khi đã ưu tiên HTTP/3 | Client đã dùng fallback hoặc có ràng buộc khiến H3 không được chọn | Kiểm tra response.version(), discovery mode và proxy |

## 9. Những cách xử lý nên tránh

- Không vô hiệu hóa xác minh hostname hoặc cài trust manager chấp nhận mọi chứng thư.
- Không tắt TLS 1.3 hoặc hạ cipher suite chỉ để né lỗi mà chưa xác định nguyên nhân.
- Không tự đặt các header nội bộ của giao thức như **Alt-Svc**, **Host**, **Connection** hoặc **Upgrade** để ép lựa chọn phiên bản.
- Không xem HTTP/2 fallback là bằng chứng HTTP/3 đã chạy thành công.
- Không retry liên tục mọi IOException. Với request có side effect như POST hoặc thanh toán, phải xác định request đã được gửi đến server hay chưa và chỉ retry theo chính sách idempotency phù hợp.
- Không ghi log token, cookie, Authorization header hoặc dữ liệu cá nhân khi bật log chi tiết.

Nếu mục tiêu là xác nhận server có thể nhận HTTP/3, hãy dùng endpoint kiểm thử được quản lý, cấu hình HTTP_3_URI_ONLY và ghi nhận response hoặc cause chain. Nếu mục tiêu là đảm bảo ứng dụng hoạt động trên nhiều mạng khác nhau, ANY hoặc ALT_SVC phù hợp hơn vì có thể dùng HTTP/2 hoặc HTTP/1.1 khi QUIC không sẵn sàng.

## Tài liệu chính thức

- [Java SE 26 API — HttpClient](https://docs.oracle.com/en/java/javase/26/docs/api/java.net.http/java/net/http/HttpClient.html): điều kiện lựa chọn HTTP/3, URI HTTPS, proxy và UnsupportedProtocolVersionException.
- [Java SE 26 API — UnsupportedProtocolVersionException](https://docs.oracle.com/en/java/javase/26/docs/api/java.net.http/java/net/http/UnsupportedProtocolVersionException.html): exception khi client không hỗ trợ phiên bản HTTP được yêu cầu và lưu ý về SSLContext/QUIC.
- [Java SE 26 API — HttpOption.Http3DiscoveryMode](https://docs.oracle.com/en/java/javase/26/docs/api/java.net.http/java/net/http/HttpOption.Http3DiscoveryMode.html): hành vi ANY, ALT_SVC và HTTP_3_URI_ONLY.
- [Java SE 26 API — HttpClient.Builder](https://docs.oracle.com/en/java/javase/26/docs/api/java.net.http/java/net/http/HttpClient.Builder.html): connect timeout, SSLContext, SSLParameters và lỗi khi build client.
- [Java SE 26 API — HttpRequest.Builder](https://docs.oracle.com/en/java/javase/26/docs/api/java.net.http/java/net/http/HttpRequest.Builder.html): timeout của request và phiên bản giao thức ưu tiên.
- [Java SE 26 API — HttpConnectTimeoutException](https://docs.oracle.com/en/java/javase/26/docs/api/java.net.http/java/net/http/HttpConnectTimeoutException.html): timeout khi thiết lập kết nối.
- [Java SE 26 API — HttpTimeoutException](https://docs.oracle.com/en/java/javase/26/docs/api/java.net.http/java/net/http/HttpTimeoutException.html): timeout khi không nhận response đúng hạn.
- [Java SE 26 API — SSLHandshakeException](https://docs.oracle.com/en/java/javase/26/docs/api/java.base/javax/net/ssl/SSLHandshakeException.html): lỗi thương lượng mức bảo mật giữa client và server.
- [Java SE 26 API — SSLPeerUnverifiedException](https://docs.oracle.com/en/java/javase/26/docs/api/java.base/javax/net/ssl/SSLPeerUnverifiedException.html): lỗi xác minh danh tính peer.
- [Java SE 26 API — java.net.http module](https://docs.oracle.com/en/java/javase/26/docs/api/java.net.http/module-summary.html): các thuộc tính logging HTTP Client, HTTP/3 và QUIC của implementation JDK.
- [Oracle Java Security Developer's Guide — Troubleshooting JSSE](https://docs.oracle.com/en/java/javase/26/security/security-developer-guide.pdf): chẩn đoán lỗi handshake, chứng thư và cấu hình TLS.

Các phân loại và giới hạn trong bài được đối chiếu với Java SE 26 API Specification và tài liệu bảo mật Oracle JDK 26 hiện hành tại ngày 27-11-2026. Exception cụ thể có thể phụ thuộc implementation và nguyên nhân ở tầng hệ điều hành/mạng; luôn xem cause chain cùng log trước khi chọn cách khắc phục.
