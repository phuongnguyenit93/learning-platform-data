# HttpOption.H3_DISCOVERY và HttpRequest.Builder.setOption

Từ JDK 26, `java.net.http.HttpClient` có thể gửi request bằng HTTP/3. API này được giới thiệu qua **JEP 517 — HTTP/3 for the HTTP Client API** và là tính năng đã được đưa vào bản phát hành Java 26. `HttpClient.Version.HTTP_3`, `HttpOption.H3_DISCOVERY` và `HttpRequest.Builder.setOption` đều có từ Java 26; chúng không phải preview API hay incubator API.

HTTP/3 sử dụng QUIC làm transport. Với Java, bạn không phải tự tạo socket QUIC hoặc tự viết quá trình thương lượng giao thức: built-in `HttpClient` xử lý kết nối. Ứng dụng chọn HTTP/3 làm phiên bản ưu tiên, sau đó có thể dùng `H3_DISCOVERY` để gợi ý cách tìm hoặc thiết lập kết nối HTTP/3.

## 1. Vì sao cần `H3_DISCOVERY`?

HTTP/3 không được bật mặc định. `HttpClient.newHttpClient()` và builder không chỉ định phiên bản có mặc định ưu tiên HTTP/2. Vì vậy, chỉ gọi `setOption(HttpOption.H3_DISCOVERY, ...)` mà không chọn HTTP/3 thì option không có tác dụng.

Cần cấu hình ít nhất một trong hai vị trí:

- `HttpClient.Builder.version(HttpClient.Version.HTTP_3)`: đặt HTTP/3 làm phiên bản ưu tiên ở cấp client, áp dụng mặc định cho các request gửi qua client đó.
- `HttpRequest.Builder.version(HttpClient.Version.HTTP_3)`: đặt HTTP/3 làm phiên bản ưu tiên cho riêng request; có thể dùng client vẫn ưu tiên HTTP/2 cho phần còn lại của ứng dụng.

`HttpOption.H3_DISCOVERY` là option ở cấp request, truyền vào `HttpRequest.Builder.setOption`. Nó nhận giá trị thuộc enum `HttpOption.Http3DiscoveryMode` và cho built-in `HttpClient` biết nên tìm endpoint HTTP/3 theo chiến lược nào.

Chữ ký API chính:

```java
HttpRequest.Builder setOption(
        HttpOption<T> option,
        T value
)
```

Với HTTP/3, kiểu dữ liệu cụ thể là:

```java
HttpOption<HttpOption.Http3DiscoveryMode> option = HttpOption.H3_DISCOVERY;
```

Lưu ý: `setOption` cung cấp một *hint* cho implementation. Hợp đồng API cho phép một implementation bỏ qua option mà nó không hiểu hoặc từ chối request. Built-in `HttpClient` của JDK hiểu `H3_DISCOVERY`; không nên mặc định mọi HTTP client của bên thứ ba đều hỗ trợ option này.

## 2. Ba chế độ khám phá HTTP/3

`HttpOption.Http3DiscoveryMode` có ba giá trị. Chúng chỉ có ý nghĩa khi HTTP/3 đã được chọn làm phiên bản ưu tiên ở cấp client hoặc request.

| Chế độ | Cách hoạt động | Hành vi fallback | Trường hợp phù hợp |
| --- | --- | --- | --- |
| `ANY` | Để implementation tự chọn cách tìm kết nối. Thông thường client có thể thử kết nối QUIC/HTTP/3 và TLS/TCP/HTTP cùng lúc, rồi dùng kết nối thành công trước | Có thể dùng HTTP/3, HTTP/2 hoặc HTTP/1.1 tùy kết nối thành công | Muốn client tự tối ưu khả năng kết nối và độ trễ |
| `ALT_SVC` | Chỉ dùng thông tin HTTP Alternative Services để tìm endpoint HTTP/3 | Ban đầu request đi bằng HTTP/1.1 hoặc HTTP/2; sau khi origin quảng bá endpoint `h3`, request tiếp theo có thể dùng HTTP/3 | Muốn discovery theo cơ chế Alt-Svc chuẩn, triển khai thận trọng |
| `HTTP_3_URI_ONLY` | Chỉ kết nối HTTP/3 tới đúng host và port trong URI, qua QUIC; không dùng Alternative Services | Không fallback sang HTTP/2 hoặc HTTP/1.1; request thất bại nếu endpoint không nhận HTTP/3 tại authority đó | Kiểm thử hoặc yêu cầu bắt buộc phải dùng HTTP/3 |

### `ANY`: ưu tiên khả năng kết nối

Đây là chế độ mặc định của built-in `HttpClient` khi HTTP/3 đã được chọn mà request không chỉ định `H3_DISCOVERY`. Implementation có thể thử HTTP/3 và một kết nối HTTP qua TLS/TCP; kết nối thành công trước sẽ được sử dụng. Nếu request ưu tiên HTTP/3, client có thể ưu tiên thử QUIC trước.

Vì đây là chiến lược linh hoạt, việc đặt HTTP/3 làm phiên bản ưu tiên không đảm bảo response thực tế sẽ dùng HTTP/3. Client có thể nhận response qua HTTP/2 hoặc HTTP/1.1 nếu đường HTTP/3 không thiết lập được.

### `ALT_SVC`: khám phá qua HTTP Alternative Services

`ALT_SVC` yêu cầu client dùng thông tin HTTP Alternative Services để tìm endpoint HTTP/3. Server thường quảng bá dịch vụ thay thế bằng response header `Alt-Svc` có protocol identifier `h3`.

Nếu client chưa có thông tin Alt-Svc cho origin, request đầu tiên thường vẫn đi qua HTTP/1.1 hoặc HTTP/2. Sau khi server quảng bá endpoint HTTP/3, client có thể dùng endpoint đó cho những request tiếp theo. Hãy tái sử dụng cùng một `HttpClient` cho các request tới origin để tận dụng trạng thái và connection pool mà client quản lý.

Chế độ này không ép request đầu tiên phải dùng HTTP/3. Nếu ứng dụng cần xác minh phiên bản thực tế, hãy đọc `HttpResponse.version()` thay vì suy luận từ cấu hình request.

### `HTTP_3_URI_ONLY`: chỉ cho phép HTTP/3

Chế độ này bỏ qua Alt-Svc và chỉ thử HTTP/3 qua QUIC tới đúng authority trong URI. Ví dụ URI `https://api.example.com:443/items` yêu cầu server nhận HTTP/3 ở host `api.example.com`, port `443`.

Nếu server chỉ hỗ trợ HTTP/2/HTTP/1.1, hoặc không thể thiết lập HTTP/3, request sẽ thất bại thay vì tự chuyển xuống phiên bản thấp hơn. Đây là lựa chọn hữu ích cho kiểm thử khả năng HTTP/3 thực sự của endpoint, nhưng không phù hợp làm mặc định cho mọi endpoint chưa được xác nhận hỗ trợ.

## 3. Ví dụ: đặt HTTP/3 cho một request

Ví dụ sau dùng client mặc định ưu tiên HTTP/2, nhưng đặt HTTP/3 làm phiên bản ưu tiên cho một request cụ thể. Chế độ `ANY` cho phép implementation tìm kết nối phù hợp và fallback nếu cần.

```java
import java.net.URI;
import java.net.http.HttpClient;
import java.net.http.HttpOption;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;
import java.time.Duration;

public class Http3RequestExample {
    public static void main(String[] args) throws Exception {
        HttpClient client = HttpClient.newBuilder()
                .connectTimeout(Duration.ofSeconds(10))
                .build(); // Mặc định ưu tiên HTTP/2

        HttpRequest request = HttpRequest.newBuilder()
                .uri(URI.create("https://example.com/"))
                .version(HttpClient.Version.HTTP_3)
                .setOption(
                        HttpOption.H3_DISCOVERY,
                        HttpOption.Http3DiscoveryMode.ANY
                )
                .timeout(Duration.ofSeconds(20))
                .GET()
                .build();

        HttpResponse<String> response = client.send(
                request,
                HttpResponse.BodyHandlers.ofString()
        );

        System.out.println("Status: " + response.statusCode());
        System.out.println("Protocol used: " + response.version());
        System.out.println(response.body());
    }
}
```

Biên dịch và chạy bằng JDK 26 trở lên:

```bash
javac Http3RequestExample.java
java Http3RequestExample
```

Không cần `--enable-preview` cho HTTP/3. Đây là API Java SE đã được phát hành từ Java 26. Địa chỉ `example.com` trong ví dụ chỉ là URI minh họa; khi thực hành, hãy thay bằng endpoint HTTPS mà bạn kiểm soát hoặc biết chắc có thể truy cập.

`response.version()` trả về phiên bản giao thức thực tế của response. Kết quả có thể là `HTTP_3`, `HTTP_2` hoặc `HTTP_1_1`, tùy khả năng của server và điều kiện kết nối. `request.version()` chỉ đặt phiên bản ưu tiên, không phải cam kết phiên bản cuối cùng.

## 4. Chọn chiến lược Alt-Svc hoặc HTTP/3 bắt buộc

Để dùng Alt-Svc, thay `ANY` trong ví dụ bằng:

```java
.setOption(
        HttpOption.H3_DISCOVERY,
        HttpOption.Http3DiscoveryMode.ALT_SVC
)
```

Giữ nguyên `.version(HttpClient.Version.HTTP_3)`. Gửi request tới cùng origin bằng cùng client; server có thể trả `Alt-Svc: h3=...` để quảng bá endpoint thay thế. Request sau có thể sử dụng HTTP/3 nếu endpoint đó truy cập được. Nếu server không quảng bá HTTP/3, request vẫn có thể hoàn tất qua HTTP/1.1 hoặc HTTP/2.

Nếu muốn xác nhận endpoint hỗ trợ HTTP/3 tại chính host/port của URI, dùng:

```java
.setOption(
        HttpOption.H3_DISCOVERY,
        HttpOption.Http3DiscoveryMode.HTTP_3_URI_ONLY
)
```

Khi đó request không dùng Alt-Svc và không fallback. Hãy xử lý lỗi I/O hoặc `UnsupportedProtocolVersionException` phù hợp với yêu cầu ứng dụng. `UnsupportedProtocolVersionException` có thể xuất hiện nếu implementation không thể hỗ trợ HTTP/3, ví dụ `SSLContext` hoặc `SSLParameters` được cấu hình không tương thích với QUIC transport của implementation.

## 5. Chọn phiên bản ở cấp client hay request

| Cấu hình | Phạm vi | Ý nghĩa |
| --- | --- | --- |
| `HttpClient.newBuilder().version(HTTP_3)` | Toàn client | Các request không ghi phiên bản riêng sẽ ưu tiên HTTP/3 |
| `HttpRequest.newBuilder().version(HTTP_3)` | Một request | Chỉ request này ưu tiên HTTP/3; các request khác theo cấu hình client |
| `HttpRequest.Builder.setOption(H3_DISCOVERY, mode)` | Một request | Chọn chiến lược discovery cho HTTP/3 của request này |

Ví dụ khi một ứng dụng có phần lớn API vẫn ưu tiên HTTP/2, nhưng một endpoint cụ thể muốn thử HTTP/3:

```java
HttpClient client = HttpClient.newBuilder()
        .version(HttpClient.Version.HTTP_2)
        .build();

HttpRequest h3Request = HttpRequest.newBuilder()
        .uri(URI.create("https://api.example.com/catalog"))
        .version(HttpClient.Version.HTTP_3)
        .setOption(
                HttpOption.H3_DISCOVERY,
                HttpOption.Http3DiscoveryMode.ALT_SVC
        )
        .GET()
        .build();

HttpResponse<String> response = client.send(
        h3Request,
        HttpResponse.BodyHandlers.ofString()
);

System.out.println(response.version());
```

Request-level version là lựa chọn phù hợp khi rollout HTTP/3 theo từng endpoint. Với client ưu tiên HTTP/3 ở cấp client, mọi request không ghi phiên bản riêng đều chịu ảnh hưởng của cấu hình đó.

## 6. Điều kiện và giới hạn của built-in HttpClient

HTTP/3 không thể sử dụng trong mọi môi trường mạng. Cần kiểm tra các điều kiện sau:

1. **JDK:** API `HttpClient.Version.HTTP_3`, `HttpOption.H3_DISCOVERY` và `HttpRequest.Builder.setOption` yêu cầu JDK 26 trở lên. Dự án compile bằng `--release 25` hoặc JDK 25 không thể sử dụng các API này.
2. **HTTPS:** request có URI scheme khác `https` sẽ không được gửi qua HTTP/3.
3. **Proxy:** built-in `HttpClient` của JDK hiện không hỗ trợ HTTP/3 qua proxy. Nếu proxy được chọn, chế độ thông thường có thể hạ xuống HTTP/2 hoặc HTTP/1.1 và bỏ qua hint `H3_DISCOVERY`; với `HTTP_3_URI_ONLY`, request sẽ thất bại.
4. **QUIC và mạng:** HTTP/3 chạy trên QUIC, thường cần đường UDP tới endpoint. Firewall, NAT hoặc chính sách mạng chặn UDP có thể khiến kết nối HTTP/3 không thiết lập được; `ANY` có thể sử dụng đường HTTP qua TCP nếu đường đó thành công.
5. **TLS:** `SSLContext` và `SSLParameters` tùy chỉnh phải tương thích với HTTP/3/QUIC của implementation. Cấu hình TLS đặc thù có thể khiến client không hỗ trợ HTTP/3 và ném `UnsupportedProtocolVersionException`.
6. **Server:** endpoint phải hỗ trợ HTTP/3 trực tiếp hoặc quảng bá một endpoint HTTP/3 qua Alt-Svc, tùy discovery mode được chọn.
7. **Implementation:** `setOption` là request hint. Built-in JDK HttpClient hiểu `H3_DISCOVERY`; implementation khác có thể bỏ qua hoặc từ chối option.

Không tắt xác thực chứng chỉ hoặc hostname verification để khắc phục lỗi kết nối HTTP/3. Hãy kiểm tra chứng chỉ, cấu hình TLS, khả năng QUIC và chính sách mạng theo cách triển khai bảo mật thông thường.

## 7. Kiểm tra giao thức thực tế và triển khai an toàn

Khi kiểm thử, ghi nhận phiên bản response thay vì chỉ ghi lại phiên bản ưu tiên:

```java
System.out.printf(
        "requested=%s, actual=%s, status=%d%n",
        request.version().orElse(client.version()),
        response.version(),
        response.statusCode()
);
```

Biểu thức trên giả định `request` và `client` là các biến đã tạo như ví dụ trước. `HttpRequest.version()` trả về `Optional` vì request có thể không đặt phiên bản riêng; khi đó phiên bản ưu tiên đến từ client.

Khi đưa HTTP/3 vào production:

- Bắt đầu với `ANY` nếu cần khả năng kết nối linh hoạt, hoặc `ALT_SVC` nếu muốn server quảng bá endpoint HTTP/3 trước khi client chuyển sang dùng nó.
- Dùng `HTTP_3_URI_ONLY` cho kiểm thử hoặc các trường hợp nghiệp vụ thực sự yêu cầu HTTP/3; chuẩn bị xử lý lỗi thay vì chờ fallback.
- Đo latency, tỷ lệ lỗi, protocol thực tế và hiệu quả trên mạng/thiết bị đích. HTTP/3 không tự động nhanh hơn trong mọi tình huống.
- Tái sử dụng `HttpClient` để tận dụng connection pooling và trạng thái Alt-Svc; tránh tạo client mới cho từng request.
- Giữ HTTP/2 hoặc HTTP/1.1 làm đường tương thích nếu ứng dụng cần phục vụ server hay mạng chưa hỗ trợ HTTP/3.
- Khi nâng JDK, đọc API Specification và Release Notes của phiên bản đích; biên dịch và kiểm thử lại các tùy chọn HTTP/3, nhất là khi dùng proxy hoặc TLS tùy chỉnh.

## 8. Ghi nhớ

- HTTP/3 trong `java.net.http.HttpClient` được bổ sung từ Java 26 qua JEP 517; đây là API đã phát hành, không cần `--enable-preview`.
- HTTP/3 không được chọn mặc định. Phải đặt `HttpClient.Version.HTTP_3` ở cấp client hoặc request.
- `HttpOption.H3_DISCOVERY` chỉ có tác dụng khi HTTP/3 đã được chọn; giá trị của nó là `ANY`, `ALT_SVC` hoặc `HTTP_3_URI_ONLY`.
- `ANY` ưu tiên khả năng kết nối; `ALT_SVC` chờ quảng bá dịch vụ thay thế; `HTTP_3_URI_ONLY` chỉ dùng HTTP/3 và không fallback.
- Dùng `HttpResponse.version()` để xác minh giao thức thực tế.
- Built-in JDK HttpClient yêu cầu HTTPS cho HTTP/3 và hiện không dùng HTTP/3 khi request đi qua proxy.
