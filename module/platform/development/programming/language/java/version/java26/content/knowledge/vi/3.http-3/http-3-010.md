# Kiểm tra giao thức thực tế bằng `HttpResponse.version`

Khi gửi yêu cầu bằng Java HTTP Client, việc đặt phiên bản HTTP mong muốn không bảo đảm kết nối sẽ sử dụng đúng phiên bản đó. Máy chủ, cấu hình TLS, proxy, khả năng kết nối QUIC và cơ chế khám phá HTTP/3 đều có thể ảnh hưởng đến giao thức được chọn. Vì vậy, sau khi nhận phản hồi, hãy đọc `HttpResponse.version()` để biết giao thức thực tế đã được dùng.

Java 26 bổ sung HTTP/3 cho `java.net.http.HttpClient` thông qua JEP 517. Đây là tính năng thư viện chính thức, không phải preview hoặc incubator. Phương thức `HttpResponse.version()` đã có từ JDK 11; điểm mới trong Java 26 là giá trị `HttpClient.Version.HTTP_3` và khả năng HTTP Client của JDK gửi nhận HTTP/3.

## Mục tiêu học tập

Sau bài này, bạn có thể:

- Phân biệt phiên bản HTTP được yêu cầu với giao thức thực tế của một phản hồi.
- Đọc `HttpResponse.version()` và diễn giải các giá trị `HTTP_1_1`, `HTTP_2`, `HTTP_3`.
- Bật ưu tiên HTTP/3 ở cấp `HttpClient` hoặc `HttpRequest` và hiểu cơ chế fallback.
- Chọn chế độ khám phá HTTP/3 phù hợp bằng `HttpOption.H3_DISCOVERY`.
- Xác định điều kiện mạng, HTTPS, QUIC, proxy và TLS cần có khi kiểm chứng HTTP/3.

## 1. Phiên bản được yêu cầu và phiên bản thực tế

HTTP Client có nhiều nơi thể hiện phiên bản giao thức, nhưng chúng mang ý nghĩa khác nhau:

| API | Ý nghĩa |
|---|---|
| `HttpClient.version()` | Phiên bản HTTP mặc định mà client ưu tiên cho request |
| `HttpRequest.version()` | `Optional` chứa phiên bản ưu tiên riêng của request, nếu được đặt |
| `HttpResponse.version()` | Phiên bản HTTP thực tế đã được dùng cho phản hồi đó |

Ví dụ, `client.version()` có thể trả về `HTTP_3` vì ứng dụng đã yêu cầu ưu tiên HTTP/3. Tuy nhiên, nếu điều kiện kết nối không đáp ứng, JDK có thể dùng HTTP/2 hoặc HTTP/1.1. Khi đó, `response.version()` phản ánh giao thức đã thực sự được dùng.

Đừng kết luận giao thức từ cấu hình client, từ URL, hoặc chỉ từ một header như `Alt-Svc` hay `Server`. Header `Alt-Svc` có thể quảng bá một dịch vụ thay thế hỗ trợ HTTP/3; nó không chứng minh rằng chính phản hồi hiện tại đã đi qua HTTP/3. `HttpResponse.version()` là API cần kiểm tra cho phản hồi mà bạn vừa nhận.

## 2. Kiểm tra phiên bản thực tế bằng Java HTTP Client

Ví dụ dưới đây ưu tiên HTTP/3 nhưng vẫn cho phép JDK lựa chọn giao thức phù hợp nếu HTTP/3 không khả dụng:

```java
import java.io.IOException;
import java.net.URI;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;
import java.nio.charset.StandardCharsets;
import java.time.Duration;

public class CheckHttpVersion {
    public static void main(String[] args)
            throws IOException, InterruptedException {
        if (args.length != 1) {
            throw new IllegalArgumentException(
                    "Usage: CheckHttpVersion <https-url>");
        }

        URI uri = URI.create(args[0]);
        if (!"https".equalsIgnoreCase(uri.getScheme())) {
            throw new IllegalArgumentException(
                    "HTTP/3 requires an HTTPS URI");
        }

        try (HttpClient client = HttpClient.newBuilder()
                .version(HttpClient.Version.HTTP_3)
                .connectTimeout(Duration.ofSeconds(10))
                .build()) {

            HttpRequest request = HttpRequest.newBuilder(uri)
                    .timeout(Duration.ofSeconds(20))
                    .GET()
                    .build();

            HttpResponse<String> response = client.send(
                    request,
                    HttpResponse.BodyHandlers.ofString(StandardCharsets.UTF_8));

            System.out.println("Client preference: " + client.version());
            System.out.println("HTTP status: " + response.statusCode());
            System.out.println("Actual protocol: " + response.version());
            System.out.println("Response URI: " + response.uri());

            if (response.version() == HttpClient.Version.HTTP_3) {
                System.out.println("The response used HTTP/3.");
            } else {
                System.out.println(
                        "HTTP/3 was preferred, but another version was used.");
            }
        }
    }
}
```

Chạy bằng JDK 26 với một HTTPS endpoint mà bạn muốn kiểm tra:

```bash
javac --release 26 CheckHttpVersion.java
java CheckHttpVersion https://your-http-endpoint.example/
```

Thay URL minh họa bằng endpoint thực tế. Để quan sát HTTP/3, endpoint phải hỗ trợ QUIC/HTTP/3 và mạng từ máy chạy chương trình phải kết nối được tới endpoint đó. Không cần `--enable-preview`, vì HTTP/3 trong JEP 517 là tính năng chính thức của Java 26.

Kết quả có thể có dạng:

```text
Client preference: HTTP_3
HTTP status: 200
Actual protocol: HTTP_2
Response URI: https://your-http-endpoint.example/
HTTP/3 was preferred, but another version was used.
```

Đây là kết quả hợp lệ: chương trình đã yêu cầu ưu tiên HTTP/3 nhưng phản hồi cụ thể được truyền bằng HTTP/2. Nếu `Actual protocol` là `HTTP_3`, phản hồi đó đã sử dụng HTTP/3. Mã trạng thái HTTP và phiên bản giao thức là hai thông tin độc lập; một phản hồi lỗi như 404 vẫn có thể được truyền qua HTTP/3.

## 3. HTTP/3 trong Java 26 là tính năng chính thức

JEP 517 bổ sung hỗ trợ HTTP/3 cho HTTP Client API. Các hằng số phiên bản được cung cấp là:

| Hằng số | Giao thức | Có từ |
|---|---|---:|
| `HttpClient.Version.HTTP_1_1` | HTTP/1.1 | JDK 11 |
| `HttpClient.Version.HTTP_2` | HTTP/2 | JDK 11 |
| `HttpClient.Version.HTTP_3` | HTTP/3 | JDK 26 |

`HttpResponse.version()` không phải API mới của Java 26; nó đã trả về giao thức thực tế của phản hồi từ JDK 11. Java 26 bổ sung giá trị `HTTP_3`, nên mã nguồn muốn tham chiếu hằng số này cần biên dịch và chạy với JDK 26 trở lên.

HTTP/1.1 và HTTP/2 thường chạy trên TCP. HTTP/3 chạy trên QUIC, sử dụng UDP và tích hợp TLS 1.3 trong quá trình thiết lập kết nối. Khác biệt này khiến việc kiểm chứng HTTP/3 phải xét đến khả năng QUIC của máy chủ, đường mạng và cấu hình bảo mật; chỉ kiểm tra rằng website mở được bằng trình duyệt hoặc HTTP/2 chưa đủ để kết luận UDP/QUIC hoạt động.

## 4. Ưu tiên HTTP/3 ở cấp client hoặc request

Có thể đặt phiên bản ưu tiên khi tạo client:

```java
HttpClient client = HttpClient.newBuilder()
        .version(HttpClient.Version.HTTP_3)
        .build();
```

Mọi request không chỉ định phiên bản riêng sẽ dùng ưu tiên của client. Nếu chỉ một request cần HTTP/3, đặt ưu tiên trên request:

```java
HttpRequest request = HttpRequest.newBuilder()
        .uri(URI.create("https://your-http-endpoint.example/"))
        .version(HttpClient.Version.HTTP_3)
        .GET()
        .build();
```

Phiên bản đặt trên request ghi đè lựa chọn mặc định của client cho request đó. Dù đặt ở cấp nào, đây vẫn là phiên bản ưu tiên; hãy đọc `response.version()` sau khi gửi để xác nhận kết quả.

Nếu không gọi `version(...)`, HTTP Client mặc định ưu tiên HTTP/2. Java 26 có hỗ trợ HTTP/3 không đồng nghĩa mọi request tự động chuyển sang HTTP/3. Ứng dụng phải chủ động chọn `HTTP_3` khi muốn sử dụng giao thức này.

## 5. Hiểu cơ chế khám phá và fallback HTTP/3

Với JDK HTTP Client mặc định, khi HTTP/3 được chọn, cơ chế khám phá mặc định tương ứng với `HttpOption.Http3DiscoveryMode.ANY`. Client có thể thử thiết lập kết nối QUIC cho HTTP/3 và kết nối TLS trên TCP cho HTTP/1.1 hoặc HTTP/2; giao thức được dùng phụ thuộc vào kết quả khám phá và kết nối. Client cũng có thể dùng thông tin HTTP Alternative Services (`Alt-Svc`) đã nhận từ máy chủ để tìm endpoint HTTP/3.

Java 26 cung cấp `HttpOption.H3_DISCOVERY` để điều chỉnh cách khám phá cho từng request:

| Chế độ | Cách hoạt động | Trường hợp sử dụng |
|---|---|---|
| `ANY` | Để implementation chọn cách khám phá; có thể thử QUIC và TCP, dùng kết nối thành công trước hoặc thông tin Alt-Svc đã biết | Muốn ưu tiên HTTP/3 nhưng vẫn cho phép fallback |
| `ALT_SVC` | Chỉ dùng thông tin HTTP Alternative Services để tìm endpoint HTTP/3; request ban đầu có thể vẫn chạy bằng HTTP/1.1 hoặc HTTP/2 cho đến khi server quảng bá `h3` | Muốn chỉ dùng endpoint HTTP/3 được máy chủ công bố qua Alt-Svc |
| `HTTP_3_URI_ONLY` | Chỉ thử HTTP/3 trực tiếp tại host và port của URI; không dùng Alt-Svc và không fallback sang HTTP/1.1 hoặc HTTP/2 | Muốn kiểm tra nghiêm ngặt server có nhận QUIC tại đúng authority của URI |

Đặt chế độ khám phá trên request như sau:

```java
HttpRequest request = HttpRequest.newBuilder()
        .uri(URI.create("https://your-http3-endpoint.example/"))
        .version(HttpClient.Version.HTTP_3)
        .setOption(
                HttpOption.H3_DISCOVERY,
                HttpOption.Http3DiscoveryMode.ALT_SVC)
        .GET()
        .build();
```

`H3_DISCOVERY` là gợi ý cấu hình ở cấp request. Nếu phiên bản ưu tiên của client và request đều không phải HTTP/3, tùy chọn này không có tác dụng. Implementation có thể bỏ qua gợi ý không hỗ trợ; các chế độ và hành vi trong bảng mô tả implementation HTTP Client tích hợp của JDK 26.

Để kiểm tra HTTP/3 trực tiếp và không cho phép fallback, dùng `HTTP_3_URI_ONLY`:

```java
import java.io.IOException;
import java.net.URI;
import java.net.http.HttpClient;
import java.net.http.HttpOption;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;

public class RequireHttp3 {
    public static void main(String[] args)
            throws IOException, InterruptedException {
        if (args.length != 1) {
            throw new IllegalArgumentException(
                    "Usage: RequireHttp3 <https-url>");
        }

        URI uri = URI.create(args[0]);
        if (!"https".equalsIgnoreCase(uri.getScheme())) {
            throw new IllegalArgumentException(
                    "HTTP/3 requires an HTTPS URI");
        }

        try (HttpClient client = HttpClient.newBuilder()
                .version(HttpClient.Version.HTTP_3)
                .proxy(HttpClient.Builder.NO_PROXY)
                .build()) {

            HttpRequest request = HttpRequest.newBuilder(uri)
                    .version(HttpClient.Version.HTTP_3)
                    .setOption(
                            HttpOption.H3_DISCOVERY,
                            HttpOption.Http3DiscoveryMode.HTTP_3_URI_ONLY)
                    .GET()
                    .build();

            HttpResponse<Void> response = client.send(
                    request, HttpResponse.BodyHandlers.discarding());

            if (response.version() != HttpClient.Version.HTTP_3) {
                throw new IllegalStateException(
                        "Expected HTTP/3 but received " + response.version());
            }

            System.out.println("Confirmed protocol: " + response.version());
            System.out.println("HTTP status: " + response.statusCode());
        }
    }
}
```

Chế độ `HTTP_3_URI_ONLY` chỉ thành công nếu máy chủ nhận HTTP/3 qua QUIC tại đúng host và port trong URI. Ví dụ này cố định kết nối trực tiếp bằng `HttpClient.Builder.NO_PROXY`, bởi HTTP/3 của implementation JDK 26 hiện không được sử dụng khi request đi qua proxy. Nếu môi trường bắt buộc dùng proxy, hãy kiểm thử đường HTTP/1.1 hoặc HTTP/2 phù hợp với môi trường đó.

## 6. Điều kiện để HTTP/3 được sử dụng

Trước khi kết luận ứng dụng có lỗi, hãy kiểm tra các điều kiện sau:

1. **JDK:** dùng JDK 26 trở lên. `HttpClient.Version.HTTP_3` và `HttpOption.H3_DISCOVERY` được bổ sung từ JDK 26.
2. **URI:** request phải dùng scheme `https`. Request có scheme `http` sẽ không được gửi bằng HTTP/3 trong implementation JDK này.
3. **Máy chủ:** endpoint phải hỗ trợ HTTP/3 qua QUIC. Nếu chỉ hỗ trợ HTTP/1.1 hoặc HTTP/2, request ưu tiên HTTP/3 có thể được xử lý bằng giao thức khác khi dùng chế độ cho phép fallback.
4. **Mạng:** đường truyền phải cho phép QUIC/UDP tới endpoint. Firewall, NAT hoặc chính sách mạng có thể chặn UDP dù TCP vẫn hoạt động.
5. **Proxy:** implementation HTTP Client tích hợp của JDK 26 không sử dụng HTTP/3 khi một proxy được chọn. Dùng kết nối trực tiếp cho bài kiểm tra HTTP/3.
6. **TLS:** HTTP/3 yêu cầu TLS 1.3. `SSLContext` hoặc `SSLParameters` tùy chỉnh phải tương thích với QUIC và cấu hình TLS cần thiết; cấu hình không phù hợp có thể khiến client không hỗ trợ HTTP/3.
7. **Discovery:** chọn `ANY`, `ALT_SVC` hoặc `HTTP_3_URI_ONLY` theo mục tiêu kiểm thử. Chế độ nghiêm ngặt không có fallback.

Không cần bật preview bằng `--enable-preview`. HTTP/3 là tính năng thư viện chính thức trong Java 26. Nếu build project với `--release`, mã nguồn sử dụng `HTTP_3` hoặc `HttpOption.H3_DISCOVERY` phải đặt release từ 26 trở lên; không thể biên dịch các tham chiếu này cho release 25 bằng JDK 26.

## 7. Đọc kết quả đúng cách

| Giá trị `response.version()` | Diễn giải |
|---|---|
| `HTTP_1_1` | Phản hồi này được truyền qua HTTP/1.1 |
| `HTTP_2` | Phản hồi này được truyền qua HTTP/2 |
| `HTTP_3` | Phản hồi này được truyền qua HTTP/3 trên QUIC |

Một số lưu ý khi phân tích kết quả:

- `response.version()` mô tả phản hồi hiện tại, không phải danh sách giao thức mà server hỗ trợ.
- Nếu bật tự động redirect, `response` cuối cùng mô tả phản hồi cuối cùng. Có thể lần theo `response.previousResponse()` để xem các phản hồi trung gian và phiên bản giao thức của từng phản hồi.
- Một client có thể tái sử dụng kết nối. Các request tới cùng origin không nhất thiết thực hiện lại toàn bộ quá trình khám phá giao thức.
- `response.version()` không đo độ trễ, thông lượng, thời gian bắt tay hoặc mức mất gói. Muốn so sánh hiệu năng cần thiết kế phép đo riêng với cùng endpoint, payload, số lần lặp và điều kiện mạng.
- Không dùng `response.statusCode()` để suy ra giao thức; status code cho biết kết quả xử lý HTTP, còn `version()` cho biết phiên bản giao thức.

## 8. Lỗi thường gặp khi kiểm chứng HTTP/3

| Hiện tượng | Nguyên nhân có thể | Cách kiểm tra |
|---|---|---|
| Compiler không tìm thấy `HTTP_3` | Đang biên dịch bằng JDK trước 26 hoặc release đích thấp hơn 26 | Kiểm tra `javac --version`; dùng JDK 26 và release 26 trở lên |
| Client ưu tiên HTTP/3 nhưng `response.version()` là `HTTP_2` | Server chưa hỗ trợ HTTP/3, QUIC không kết nối được, UDP bị chặn hoặc discovery chọn kết nối TCP | Kiểm tra endpoint, UDP, Alt-Svc và kết quả giao thức thực tế |
| Client ưu tiên HTTP/3 nhưng phản hồi là `HTTP_1_1` | HTTP/2 không khả dụng hoặc có ràng buộc kết nối khiến client dùng HTTP/1.1 | Kiểm tra proxy, server và cấu hình TLS; đọc `response.version()` |
| Request HTTP/3 không hoạt động với URI `http://` | HTTP/3 trong implementation này chỉ dùng với HTTPS | Dùng endpoint HTTPS có hỗ trợ QUIC |
| Chế độ `HTTP_3_URI_ONLY` thất bại | Server không nhận QUIC tại đúng host/port, proxy được chọn, UDP bị chặn hoặc cấu hình TLS không tương thích | Kiểm tra URI authority, proxy, UDP và `SSLContext`/`SSLParameters` |
| Client không được tạo với ưu tiên HTTP/3 | Implementation không hỗ trợ cấu hình HTTP/3, ví dụ SSLContext/SSLParameters không tương thích QUIC | Xem nguyên nhân của `UncheckedIOException` hoặc lỗi giao thức phát sinh khi build |

Khi chỉ cần ứng dụng hoạt động ổn định, hãy cho phép fallback và ghi nhận `response.version()` để quan sát giao thức. Khi viết bài kiểm thử tích hợp cho hạ tầng HTTP/3, hãy dùng một endpoint được kiểm soát và chế độ `HTTP_3_URI_ONLY` để test thất bại rõ ràng nếu HTTP/3 không được thiết lập.

## 9. Bài tập thực hành

Viết chương trình gửi GET request đến một HTTPS endpoint. Chương trình cần ưu tiên HTTP/3, in mã trạng thái, URI cuối cùng và phiên bản giao thức thực tế.

**Yêu cầu:**

1. Dùng JDK 26 và `HttpClient.newBuilder().version(HttpClient.Version.HTTP_3)`.
2. Gửi request bằng `client.send(...)` và lấy phản hồi qua `HttpResponse`.
3. In cả `client.version()` và `response.version()`; giải thích vì sao hai giá trị có thể khác nhau.
4. Chạy thử với endpoint hỗ trợ HTTP/3 và một endpoint chỉ hỗ trợ HTTP/2 hoặc HTTP/1.1 nếu có môi trường kiểm thử phù hợp.
5. Thử `HttpOption.Http3DiscoveryMode.HTTP_3_URI_ONLY` và mô tả sự khác biệt khi endpoint không có HTTP/3.
6. Giải thích vì sao không cần `--enable-preview` và vì sao mã nguồn tham chiếu `HTTP_3` yêu cầu release 26 trở lên.

**Kết quả mong đợi:**

- Người học chỉ ra được `client.version()` là phiên bản ưu tiên, còn `response.version()` là giao thức thực tế của phản hồi.
- Khi server và mạng hỗ trợ HTTP/3, kết quả có thể là `HTTP_3`.
- Khi dùng chế độ `ANY` và HTTP/3 không khả dụng, client có thể trả về phản hồi qua HTTP/2 hoặc HTTP/1.1.
- Khi dùng `HTTP_3_URI_ONLY`, request thất bại nếu không thiết lập được HTTP/3 trực tiếp tới đúng authority.
- Người học phân biệt được HTTP/3 là tính năng chính thức Java 26 với các tính năng preview/incubator khác trong cùng JDK.

- [HttpOption — Java SE 26 API](https://docs.oracle.com/en/java/javase/26/docs/api/java.net.http/java/net/http/HttpOption.html) và [Http3DiscoveryMode — Java SE 26 API](https://docs.oracle.com/en/java/javase/26/docs/api/java.net.http/java/net/http/HttpOption.Http3DiscoveryMode.html): cấu hình khám phá HTTP/3.
- [HttpClient.Builder — Java SE 26 API](https://docs.oracle.com/en/java/javase/26/docs/api/java.net.http/java/net/http/HttpClient.Builder.html): cấu hình phiên bản ưu tiên và proxy.
- [JDK 26 Release Notes](https://www.oracle.com/java/technologies/javase/26all-relnotes.html): xác nhận HTTP/3 for the HTTP Client API trong nhóm tính năng thư viện của Java 26.
- [HTTP Client Updates in Java 26 — Inside.java](https://inside.java/2026/03/04/jdk-26-http-client/): giải thích cách sử dụng HTTP/3 và việc HTTP/2 vẫn là phiên bản mặc định.
