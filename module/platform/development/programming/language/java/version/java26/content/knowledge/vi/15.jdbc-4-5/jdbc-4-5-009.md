# Tương thích default method với các driver hiện có

## 1. Bối cảnh JDBC 4.5

JDK 26 tích hợp JDBC 4.5 Maintenance Release. Các thay đổi liên quan trực tiếp đến default method gồm:

- `Array`, `Blob`, `Clob`, `NClob` và `SQLXML` mở rộng `AutoCloseable` và có default method `close()` gọi `free()`.
- `Connection` bổ sung bốn default method `enquoteIdentifier`, `enquoteLiteral`, `enquoteNCharLiteral` và `isSimpleIdentifier`. Các phương thức tương ứng đã có trên `Statement` từ Java 9.
- Các API này là API JDBC tiêu chuẩn thuộc Java SE, không phải preview hoặc incubator. JDK 27 tiếp tục giữ các phương thức này.

Default method giúp mở rộng interface mà không buộc mọi driver cũ phải bổ sung ngay phần triển khai. Tuy nhiên, driver có thể gặp va chạm chữ ký hoặc cần ghi đè default implementation để tuân theo cú pháp riêng của DBMS.

Bài học tập trung vào cách nhận diện và xử lý các rủi ro đó khi biên dịch, nâng cấp driver hoặc chạy driver cũ trên JDK 26/27.

## 2. Những default method mới

### 2.1. close() trên Array, Blob, Clob, NClob và SQLXML

Trước JDBC 4.5, các interface này có phương thức `free()` để giải phóng tài nguyên. Từ JDK 26, chúng còn là `AutoCloseable` và có default implementation:

~~~java
default void close() throws SQLException {
    free();
}
~~~

Điều này cho phép dùng trực tiếp trong try-with-resources:

~~~java
try (Blob blob = resultSet.getBlob("payload");
     InputStream input = blob.getBinaryStream()) {
    input.transferTo(outputStream);
}
~~~

Khi thoát khối, `InputStream.close()` chạy trước, sau đó `Blob.close()` gọi `Blob.free()`. Driver vốn đã triển khai `free()` có thể dùng lại logic giải phóng hiện tại.

Hành vi cần lưu ý:

- `close()` giải phóng tài nguyên và không làm gì nếu đối tượng đã đóng.
- Sau khi đóng, các thao tác khác ngoài `close()` và `free()` có thể ném `SQLException`.
- `free()` vẫn là phương thức mà driver phải triển khai khi hỗ trợ kiểu dữ liệu tương ứng.
- Nếu `free()` ném `SQLException` hoặc `SQLFeatureNotSupportedException`, default `close()` truyền lỗi đó cho caller.

`NClob` mở rộng `Clob`, vì vậy nó kế thừa default `close()` từ `Clob`. Không cần coi đây là một default method độc lập thứ hai.

### 2.2. Các phương thức enquote trên Connection

JDK 26 thêm các phương thức sau vào `Connection`:

| Phương thức | Ý nghĩa |
|---|---|
| `enquoteIdentifier(String, boolean)` | Kiểm tra và tạo identifier đơn giản hoặc identifier có delimiter |
| `enquoteLiteral(String)` | Bao chuỗi bằng dấu nháy đơn và nhân đôi dấu nháy đơn bên trong |
| `enquoteNCharLiteral(String)` | Tạo national character literal với tiền tố `N` |
| `isSimpleIdentifier(String)` | Kiểm tra identifier có phải dạng đơn giản theo quy tắc SQL hay không |

Ví dụ:

~~~java
String literal = connection.enquoteLiteral("O'Reilly");
// 'O''Reilly'

String nationalLiteral = connection.enquoteNCharLiteral("O'Reilly");
// N'O''Reilly'

boolean simple = connection.isSimpleIdentifier("customer");
// true theo quy tắc mặc định

String identifier = connection.enquoteIdentifier("Order Details", false);
// "Order Details" nếu datasource hỗ trợ dấu nháy kép
~~~

Các default implementation dùng quy tắc SQL phổ thông. Chúng không thể biết hết quy tắc định danh, ký tự escape, giới hạn độ dài và reserved word riêng của từng DBMS.

Ví dụ, default `enquoteIdentifier` của JDK 26 yêu cầu `DatabaseMetaData.getIdentifierQuoteString()` trả về dấu nháy kép. Nếu datasource dùng delimiter khác, default có thể ném `SQLException`. Driver cần override để dùng đúng cú pháp của database.

## 3. Default method giúp driver cũ như thế nào?

Nếu JDK thêm một phương thức abstract vào interface `Connection`, mọi class triển khai interface đó phải cung cấp phương thức mới. Driver cũ có thể gặp `AbstractMethodError` khi runtime gọi phương thức chưa được triển khai.

Default method cung cấp phần thân mặc định ngay trong interface. Vì thế:

- Driver cũ không có phương thức mới vẫn có thể kế thừa default implementation.
- Với LOB, default `close()` tận dụng `free()` mà driver đã có.
- Với `Connection`, driver có thể dùng cách quote mặc định nếu phù hợp hoặc override theo cú pháp của DBMS.
- Driver không cần bật preview hoặc thêm module để sử dụng các API này trên JDK 26/27.

Đây là khả năng tương thích ở cấp interface. Nó không đảm bảo mọi driver cũ đều hoạt động đúng với mọi default method mới: chữ ký trùng với helper nội bộ, nhiều default method cùng được kế thừa và khác biệt cú pháp SQL vẫn cần được xử lý.

## 4. Rủi ro 1: helper private/protected trùng chữ ký

JDK 26 Release Notes cảnh báo driver có thể có phương thức nội bộ `private` hoặc `protected` trùng chữ ký với default method mới.

Trước JDK 26, đoạn code sau có thể hợp lệ vì interface `Connection` chưa khai báo `enquoteLiteral(String)`:

~~~java
class VendorConnection implements Connection {
    private String enquoteLiteral(String value) {
        return "'" + value.replace("'", "''") + "'";
    }

    // Các phương thức Connection còn lại
}
~~~

Khi biên dịch lại với JDK 26, phương thức interface mới là public. Phương thức private trong class không thể triển khai một phương thức public với cùng chữ ký; compiler có thể báo lỗi về quyền truy cập yếu hơn. Trường hợp `protected` cũng cần xử lý.

Có hai hướng sửa:

**Đổi tên helper nội bộ** nếu nó chỉ là chi tiết triển khai:

~~~java
class VendorConnection implements Connection {
    private String quoteLiteralInternal(String value) {
        return "'" + value.replace("'", "''") + "'";
    }

    // Các phương thức Connection còn lại
}
~~~

**Hoặc cung cấp public override** nếu driver muốn triển khai API JDBC:

~~~java
class VendorConnection implements Connection {
    private String quoteLiteralInternal(String value) {
        // Áp dụng quy tắc literal của DBMS
        return vendorQuoteLiteral(value);
    }

    @Override
    public String enquoteLiteral(String value) throws SQLException {
        return quoteLiteralInternal(value);
    }

    // Các phương thức Connection còn lại
}
~~~

Áp dụng cùng cách kiểm tra cho `enquoteIdentifier`, `enquoteNCharLiteral` và `isSimpleIdentifier`. Với LOB implementation, kiểm tra cả helper `close()` có access modifier yếu hơn public hay không.

Nếu driver đã có public method đúng chữ ký, phương thức đó trở thành implementation override của default method. Hãy kiểm tra lại logic và thêm annotation `@Override` khi source được biên dịch bằng JDK mới.

## 5. Rủi ro 2: nhiều interface cung cấp default method trùng nhau

Java không tự hợp nhất hai default method chỉ vì tên và phần thân của chúng giống nhau. Khi một class kế thừa các default method cùng chữ ký từ các interface không có quan hệ kế thừa, class phải tự giải quyết xung đột.

### 5.1. Connection và Statement

`Statement` đã có các phương thức `enquote*` từ Java 9. JDK 26 thêm các phương thức cùng chữ ký vào `Connection`.

Một lớp wrapper đặc biệt triển khai đồng thời `Connection` và `Statement` có thể gặp xung đột ở bốn phương thức này:

~~~java
class CombinedJdbcFacade implements Connection, Statement {
    @Override
    public String enquoteLiteral(String value) throws SQLException {
        return quoteLiteralForDatabase(value);
    }

    @Override
    public String enquoteIdentifier(
            String identifier,
            boolean alwaysDelimit
    ) throws SQLException {
        return quoteIdentifierForDatabase(identifier, alwaysDelimit);
    }

    @Override
    public String enquoteNCharLiteral(String value) throws SQLException {
        return quoteNationalLiteralForDatabase(value);
    }

    @Override
    public boolean isSimpleIdentifier(String identifier)
            throws SQLException {
        return isSimpleIdentifierForDatabase(identifier);
    }

    // Các phương thức JDBC còn lại
}
~~~

Trong trường hợp class triển khai trực tiếp cả hai interface, cũng có thể gọi tường minh một default implementation bằng cú pháp `Statement.super.method(...)` nếu implementation đó phù hợp. Với driver đa DBMS, override theo quy tắc database thường rõ ràng hơn.

### 5.2. Array, Blob, Clob và SQLXML

Các interface `Array`, `Blob`, `Clob` và `SQLXML` đều có default `close()`. Một implementation đặc biệt triển khai đồng thời hai interface độc lập như `Array` và `Blob` cần tự override `close()`:

~~~java
class CombinedSqlValue implements Array, Blob {
    @Override
    public void close() throws SQLException {
        free(); // Một implementation free() chịu trách nhiệm giải phóng resource
    }

    @Override
    public void free() throws SQLException {
        releaseUnderlyingResource();
    }

    // Các phương thức Array và Blob còn lại
}
~~~

Nếu wrapper quản lý hai resource riêng biệt, `close()` phải giải phóng cả hai và giữ lại các lỗi phát sinh, chẳng hạn ném lỗi đầu tiên rồi gắn lỗi tiếp theo bằng `addSuppressed()`.

`NClob` kế thừa `Clob`; riêng cặp này không tạo hai khai báo default độc lập cho `close()`.

### 5.3. Ảnh hưởng đến binary compatibility

Theo Java Language Specification `13.5.7, việc thêm default method nhìn chung không phá binary compatibility của class file đã biên dịch. Tuy nhiên, binary cũ có thể gặp `IncompatibleClassChangeError` khi gọi phương thức nếu interface dùng để gọi kế thừa hai default method cùng chữ ký từ các interface không có quan hệ cha-con.

Vì vậy cần phân biệt:

- **Source compatibility:** source driver có thể không biên dịch lại được do helper private/protected hoặc default method conflict.
- **Binary compatibility:** class file cũ thường vẫn link được sau khi interface thêm default method, nhưng có ngoại lệ xung đột default method khi gọi.
- **Behavioral compatibility:** phương thức default có thể chạy được nhưng không phù hợp cú pháp SQL hoặc cách giải phóng resource của driver.

Không chỉ kiểm tra driver có tải được class. Cần thực thi các phương thức mới trên đúng database và đúng driver version.

## 6. Default quoting có luôn đúng với database không?

Không. Default method cung cấp quy tắc chung và Javadoc của `Connection` cho phép driver override khi cần.

### 6.1. Identifier và delimiter

Default `isSimpleIdentifier` sử dụng bộ quy tắc đơn giản: bắt đầu bằng chữ cái ASCII, tiếp theo là chữ cái/số/underscore, không phải SQL reserved word và có độ dài trong giới hạn mặc định. Database có thể cho phép thêm ký tự theo locale hoặc có giới hạn độ dài khác.

Default `enquoteIdentifier` dùng delimiter SQL tiêu chuẩn là dấu nháy kép. Nếu database dùng dấu khác, chẳng hạn backtick, driver nên override thay vì dựa vào default.

Ví dụ MySQL Connector/J có worklog riêng để triển khai `enquote*` theo quy tắc MySQL, trong đó identifier quote character là backtick. Đây là ví dụ thực tế cho lý do driver cần override các default method.

### 6.2. Literal và national character literal

Default `enquoteLiteral` đổi một dấu nháy đơn thành hai dấu nháy đơn và bao chuỗi bằng dấu nháy đơn. Default `enquoteNCharLiteral` thêm tiền tố `N`.

Một số DBMS có quy tắc escape hoặc cách biểu diễn national character literal khác. Driver cần kiểm tra SQL dialect và override nếu default không đáp ứng.

### 6.3. Không dùng enquoteLiteral thay cho bind parameter

Với dữ liệu người dùng, ưu tiên `PreparedStatement` và parameter marker:

~~~java
try (PreparedStatement ps =
         connection.prepareStatement(
             "SELECT id FROM customer WHERE display_name = ?")) {
    ps.setString(1, userInput);
    try (ResultSet rs = ps.executeQuery()) {
        // Xử lý kết quả
    }
}
~~~

`enquoteLiteral` là tiện ích tạo literal SQL trong những trường hợp cần thiết; nó không thay thế prepared statement cho dữ liệu đầu vào.

Identifier như tên bảng hoặc tên cột thường không thể truyền bằng parameter marker. Với identifier động, hãy kiểm tra bằng allow-list của ứng dụng và dùng `enquoteIdentifier` của driver đã được xác nhận phù hợp với DBMS.

## 7. Kiểm tra driver cũ khi nâng lên JDK 26/27

### 7.1. Xác định chính xác driver đang chạy

Lấy metadata từ connection:

~~~java
DatabaseMetaData metadata = connection.getMetaData();

System.out.println(metadata.getDriverName());
System.out.println(metadata.getDriverVersion());
System.out.println(metadata.getDatabaseProductName());
System.out.println(metadata.getDatabaseProductVersion());
System.out.println(metadata.getIdentifierQuoteString());
~~~

Đối chiếu driver name/version với ma trận hỗ trợ JDK và database của nhà cung cấp. Không suy ra driver hỗ trợ đầy đủ JDBC 4.5 chỉ vì ứng dụng chạy trên JDK 26.

JDBC có những tính năng tùy chọn và mức hỗ trợ khác nhau giữa các driver. Tài liệu driver của nhà cung cấp và integration test với DBMS thực tế mới là căn cứ để bật tính năng trong production.

### 7.2. Kiểm tra source driver

Nếu tổ chức tự phát triển hoặc fork driver:

1. Biên dịch source bằng JDK 26 và JDK 27.
2. Tìm các phương thức private/protected có chữ ký trùng bốn phương thức mới của `Connection`.
3. Tìm các implementation `Array`, `Blob`, `Clob`, `NClob` và `SQLXML` có helper `close()` không public.
4. Kiểm tra class triển khai nhiều interface có default method cùng chữ ký.
5. Thêm `@Override` cho những method thực sự triển khai JDBC API.
6. Override các method quoting nếu quy tắc DBMS khác default.

### 7.3. Kiểm tra binary driver đã biên dịch trước đó

Nếu driver được cung cấp dưới dạng JAR và không thể sửa source, chạy integration test bằng chính JAR đó trên JDK 26/27:

- Mở connection, tạo statement, truy vấn và đóng connection.
- Lấy `Blob`, `Clob`, `NClob`, `Array` hoặc `SQLXML` nếu database hỗ trợ.
- Gọi `close()` và xác nhận tài nguyên được giải phóng.
- Gọi `free()` hai lần để xác nhận hành vi idempotent theo hợp đồng driver.
- Gọi `Connection.enquote*` với identifier đơn giản, reserved word, ký tự đặc biệt, literal có dấu nháy đơn và chuỗi Unicode.
- Kiểm tra lỗi `SQLException`, `SQLFeatureNotSupportedException` và các lỗi linkage như `IncompatibleClassChangeError`.

### 7.4. Ma trận kiểm thử đề xuất

| Nhóm | Ca kiểm thử | Kết quả mong đợi |
|---|---|---|
| LOB lifecycle | Đóng Blob/Clob/SQLXML bằng try-with-resources | Tài nguyên được giải phóng |
| LOB idempotence | Gọi close/free nhiều lần | Không giải phóng lặp gây lỗi ngoài hợp đồng |
| Identifier | Tên bảng đơn giản | Giữ nguyên khi không yêu cầu delimiter |
| Identifier | Reserved word hoặc tên có khoảng trắng | Được quote đúng theo DBMS |
| Identifier | DBMS dùng delimiter khác dấu nháy kép | Driver override xử lý đúng |
| Literal | Chuỗi có dấu nháy đơn | Escape đúng theo SQL dialect |
| NChar literal | Chuỗi Unicode | Tạo literal phù hợp với DBMS |
| Compatibility | Driver JAR cũ trên JDK 26/27 | Không lỗi source/binary/linkage khi chạy |
| Conflict | Driver wrapper triển khai nhiều interface có default method | Có override giải quyết xung đột |
| Unsupported | Driver không hỗ trợ loại SQL tương ứng | Báo lỗi JDBC phù hợp, không che giấu lỗi |

Nên chạy cả test với driver version cũ đang triển khai và version mới nhất được nhà cung cấp hỗ trợ. Test trên database thật hoặc container database cùng phiên bản; mock không thể xác minh chính xác identifier delimiter và SQL literal rules của DBMS.

## 8. Checklist nâng cấp dành cho nhà phát triển driver

- [ ] Đã đọc JDBC 4.5 Maintenance Release và JDK 26 Release Notes.
- [ ] Đã tìm private/protected helper trùng chữ ký `Connection.enquote*`.
- [ ] Đã kiểm tra helper `close()` trong các LOB implementation.
- [ ] Đã xử lý class triển khai nhiều interface có default method cùng chữ ký.
- [ ] Đã giữ `free()` giải phóng resource đúng và có thể gọi lặp theo hợp đồng.
- [ ] Đã override quoting methods khi default không phù hợp SQL dialect.
- [ ] Đã xác minh reserved word, identifier delimiter, độ dài và ký tự đặc biệt.
- [ ] Đã chạy compile test trên JDK 26/27 nếu có source.
- [ ] Đã chạy binary integration test với JAR driver cũ.
- [ ] Đã kiểm tra wrapper/proxy và connection pool nếu driver sử dụng các lớp này.
- [ ] Đã đối chiếu driver version với ma trận hỗ trợ chính thức của nhà cung cấp.

## 9. Checklist dành cho ứng dụng nâng cấp JDK

- [ ] Xác nhận driver version hỗ trợ JDK 26/27.
- [ ] Kiểm tra `DatabaseMetaData` để nhận diện driver và database thực tế.
- [ ] Thử `Blob`, `Clob`, `Array` và `SQLXML` bằng try-with-resources nếu DBMS hỗ trợ.
- [ ] Kiểm tra các phương thức `Connection.enquote*` trên database thật.
- [ ] Tiếp tục dùng PreparedStatement cho giá trị đầu vào.
- [ ] Không giả định mọi driver cũ đều có cùng hành vi default.
- [ ] Theo dõi lỗi SQL và linkage sau khi nâng runtime.
- [ ] Chỉ bật đường code phụ thuộc default method sau khi integration test pass.

## 10. Kết luận

JDBC 4.5 dùng default method để bổ sung khả năng đóng tài nguyên LOB và quoting trên `Connection` mà không buộc mọi driver cũ viết lại toàn bộ implementation.

Các điểm cần nhớ:

- `Array`, `Blob`, `Clob`, `NClob` và `SQLXML` có `close()` mặc định gọi `free()`.
- `Connection` có bốn default method quoting/kiểm tra identifier từ JDK 26; `Statement` đã có các phương thức tương ứng từ Java 9.
- Driver source có helper private/protected trùng chữ ký cần đổi tên hoặc đưa thành public override.
- Class triển khai nhiều interface có default method trùng nhau phải override để chọn hành vi.
- Default quoting không nhất thiết phù hợp mọi SQL dialect; driver có thể cần triển khai riêng.
- Thêm default method thường binary-compatible nhưng xung đột có thể gây lỗi khi compile hoặc lúc gọi.
- Cần kiểm thử cả source driver lẫn binary driver cũ trên JDK 26/27 và database thật.

JDBC 4.5 API là API tiêu chuẩn, nhưng khả năng tương thích thực tế vẫn phụ thuộc implementation của từng driver và DBMS. Hãy nâng cấp driver cùng runtime theo ma trận hỗ trợ của nhà cung cấp và xác minh các default method bằng integration test.
