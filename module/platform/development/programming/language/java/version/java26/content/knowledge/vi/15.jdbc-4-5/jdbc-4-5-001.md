# Phạm vi cập nhật JDBC 4.5 trong Java 26

Java 26 tích hợp **JDBC 4.5 Maintenance Release 5 (MR5)** trong Java SE. Bản cập nhật này mở rộng API JDBC chuẩn cho kiểu SQL JSON và DECFLOAT, quản lý vòng đời các đối tượng LOB/Array, tạo literal và identifier theo quy tắc của database, đồng thời đánh dấu SQLPermission để loại bỏ trong tương lai.

JDBC 4.5 là API chuẩn của Java SE 26, không phải preview hoặc incubator. Các API mới có nhãn **Since: 26** và nằm trong module **java.sql**. Vì vậy, mã sử dụng chúng cần JDK 26 trở lên để biên dịch và chạy; không cần bật --enable-preview.

JDBC 4.5 không có nghĩa mọi database đều hỗ trợ mọi kiểu dữ liệu mới. JDBC driver và database server phải cùng hỗ trợ tính năng tương ứng. Tài liệu Java SE 27 hiện vẫn giữ API JDBC 4.5, nên các cập nhật này tiếp tục áp dụng khi ứng dụng chạy trên JDK 27.

## 1. Tổng quan các cập nhật

| Khu vực | Cập nhật trong JDBC 4.5 | Lợi ích |
|---|---|---|
| SQL data types | Thêm JSON và DECFLOAT vào JDBCType và Types | Nhận diện kiểu SQL chuẩn và truyền dữ liệu qua JDBC |
| Resource lifecycle | Array, Blob, Clob, NClob và SQLXML mở rộng AutoCloseable | Có thể giải phóng tài nguyên bằng try-with-resources |
| SQL identifier/literal | Connection có các phương thức enquoteIdentifier, enquoteLiteral, enquoteNCharLiteral và isSimpleIdentifier | Xử lý tên bảng/cột và literal theo quy tắc của driver |
| SQL escape processing | Bổ sung vùng SQL string có thể tắt xử lý JDBC escape và parameter marker cục bộ | Cho phép viết cú pháp SQL có ký tự ? mà JDBC thường nhận là placeholder |
| Security API | SQLPermission deprecated for removal | Loại bỏ dần API chỉ hữu ích khi có SecurityManager |
| Tương thích driver | Thêm default methods vào Connection và các kiểu dữ liệu mới | Cần kiểm tra driver cũ và khả năng hỗ trợ của database |

JDBC 4.5 tiếp tục bao gồm các API của các phiên bản JDBC trước. Các phương thức enquote trên Statement đã có từ Java 9; cập nhật của Java 26 bổ sung các phương thức tương ứng vào Connection với default implementation.

## 2. Kiểu SQL JSON và DECFLOAT

Java 26 thêm hai hằng kiểu dữ liệu vào **java.sql.JDBCType** và **java.sql.Types**:

| JDBC type | Type code | Kiểu Java chuẩn | Công dụng |
|---|---:|---|---|
| JDBCType.JSON / Types.JSON | 2016 | String | Lưu và trao đổi giá trị JSON |
| JDBCType.DECFLOAT / Types.DECFLOAT | 2015 | BigDecimal | Số dấu phẩy động thập phân có độ chính xác cao |

Hai hằng này giúp ứng dụng và driver trao đổi loại SQL rõ ràng thay vì phải dựa vào mã kiểu riêng của từng nhà cung cấp.

### JSON

JDBC 4.5 ánh xạ JSON sang String. Khi ghi dữ liệu, có thể dùng PreparedStatement.setObject với JDBCType.JSON:

    String json = """
            {
              "orderId": "ORD-2026-001",
              "status": "paid",
              "items": [
                {"sku": "KB-01", "quantity": 2}
              ]
            }
            """;

    String sql = """
            INSERT INTO order_payload (order_id, payload)
            VALUES (?, ?)
            """;

    try (PreparedStatement ps = connection.prepareStatement(sql)) {
        ps.setString(1, "ORD-2026-001");
        ps.setObject(2, json, JDBCType.JSON);
        ps.executeUpdate();
    }

Khi đọc, có thể nhận JSON dưới dạng String:

    try (PreparedStatement ps = connection.prepareStatement(
            "SELECT payload FROM order_payload WHERE order_id = ?")) {

        ps.setString(1, "ORD-2026-001");

        try (ResultSet rs = ps.executeQuery()) {
            if (rs.next()) {
                String payload = rs.getString("payload");
                System.out.println(payload);
            }
        }
    }

Driver có thể cung cấp mapping riêng cho kiểu JSON, nhưng mapping chuẩn trong JDBC 4.5 là String. JDBC không tự cung cấp một JSON object model hay parser JSON; ứng dụng dùng thư viện JSON phù hợp để parse và validate nội dung.

### DECFLOAT

DECFLOAT là kiểu số dấu phẩy động thập phân. JDBC 4.5 ánh xạ kiểu này sang **java.math.BigDecimal**, đồng thời cho phép truyền BigDecimal làm giá trị DECFLOAT.

    BigDecimal amount = new BigDecimal("12345678901234567890.123456789");

    String sql = """
            INSERT INTO invoice_total (invoice_id, amount)
            VALUES (?, ?)
            """;

    try (PreparedStatement ps = connection.prepareStatement(sql)) {
        ps.setString(1, "INV-2026-001");
        ps.setObject(2, amount, JDBCType.DECFLOAT);
        ps.executeUpdate();
    }

Đọc giá trị DECFLOAT bằng getBigDecimal:

    try (PreparedStatement ps = connection.prepareStatement(
            "SELECT amount FROM invoice_total WHERE invoice_id = ?")) {

        ps.setString(1, "INV-2026-001");

        try (ResultSet rs = ps.executeQuery()) {
            if (rs.next()) {
                BigDecimal amountFromDb = rs.getBigDecimal("amount");
            }
        }
    }

Không chuyển DECFLOAT sang double chỉ để thuận tiện tính toán nếu nghiệp vụ cần giữ độ chính xác thập phân. BigDecimal là mapping JDBC chuẩn cho DECFLOAT; hãy kiểm tra giới hạn precision, scale và các giá trị đặc biệt theo tài liệu database/driver cụ thể.

### Kiểm tra khả năng hỗ trợ kiểu dữ liệu

Việc JDK có JDBCType.JSON hoặc JDBCType.DECFLOAT không bảo đảm database đang kết nối hỗ trợ các kiểu này. Trước khi triển khai, kiểm tra:

- Tài liệu phiên bản JDBC driver và database server.
- Kiểu dữ liệu mà database hỗ trợ, ví dụ qua DatabaseMetaData.getTypeInfo().
- JDBC major/minor version mà driver công bố.
- Cách driver ánh xạ JSON/DECFLOAT và các giới hạn precision.
- Khả năng tạo schema, bind parameter, đọc lại và xử lý NULL.

Có thể ghi lại thông tin driver và xem các kiểu mà database công bố:

    DatabaseMetaData metadata = connection.getMetaData();

    System.out.println(metadata.getDriverName());
    System.out.println(metadata.getDriverVersion());
    System.out.println(
            "JDBC " + metadata.getJDBCMajorVersion()
                    + "." + metadata.getJDBCMinorVersion()
    );

    try (ResultSet types = metadata.getTypeInfo()) {
        while (types.next()) {
            String typeName = types.getString("TYPE_NAME");
            int dataType = types.getInt("DATA_TYPE");

            if (dataType == Types.JSON || dataType == Types.DECFLOAT) {
                System.out.println(typeName + " -> " + dataType);
            }
        }
    }

Metadata là một tín hiệu để kiểm tra, không thay thế tài liệu driver hoặc phép thử thực tế. Tên kiểu SQL và câu lệnh tạo cột JSON/DECFLOAT vẫn phụ thuộc database; JDBC không làm cho cú pháp DDL giữa các nhà cung cấp trở nên giống nhau.

## 3. Array, Blob, Clob, NClob và SQLXML hỗ trợ AutoCloseable

Trong JDBC 4.5, năm interface sau mở rộng **java.lang.AutoCloseable**:

- java.sql.Array
- java.sql.Blob
- java.sql.Clob
- java.sql.NClob
- java.sql.SQLXML

Mỗi interface có một default method close() gọi đến free(). Nhờ đó, ứng dụng có thể quản lý các tài nguyên này bằng try-with-resources thay vì phải tự gọi free() trong khối finally.

Ví dụ đọc Blob:

    try (Blob blob = resultSet.getBlob("document_data");
         InputStream input = blob.getBinaryStream()) {

        byte[] buffer = new byte[8192];

        while (input.read(buffer) != -1) {
            // Xử lý từng phần dữ liệu.
        }
    }

Khi khối try kết thúc, InputStream được đóng và Blob.close() giải phóng tài nguyên Blob bằng cách gọi free().

Ví dụ với SQL Array:

    try (Array tags = resultSet.getArray("tags")) {
        Object values = tags.getArray();

        if (values instanceof Object[] elements) {
            for (Object element : elements) {
                System.out.println(element);
            }
        }
    }

Tương tự, có thể dùng try-with-resources với Clob, NClob và SQLXML:

    try (Clob description = resultSet.getClob("description")) {
        String text = description.getSubString(
                1,
                Math.toIntExact(description.length())
        );
    }

    try (SQLXML xml = resultSet.getSQLXML("document_xml")) {
        String xmlText = xml.getString();
    }

Sau khi đóng, chỉ được gọi lại close() hoặc free(); các phương thức khác có thể ném SQLException. close() mặc định gọi free(), nên không cần gọi cả hai lần. free() vẫn tồn tại để tương thích với mã JDBC cũ.

Một số driver triển khai Blob/Clob/Array bằng locator tham chiếu đến dữ liệu trong database. Đối tượng có thể chỉ hợp lệ trong thời gian transaction hoặc connection tương ứng. Hãy đọc và giải phóng tài nguyên đúng vòng đời; không giữ locator sau khi transaction hoặc connection kết thúc nếu driver không bảo đảm điều đó.

Các interface chỉ được driver hỗ trợ đầy đủ khi database/driver hỗ trợ kiểu dữ liệu tương ứng. Việc interface có AutoCloseable không có nghĩa mọi database đều phải hỗ trợ BLOB, CLOB, ARRAY hoặc SQLXML.

## 4. Các phương thức enquote mới trên Connection

Java 26 bổ sung các default method sau vào java.sql.Connection:

| Phương thức | Công dụng |
|---|---|
| isSimpleIdentifier(String) | Kiểm tra tên có phải simple SQL identifier hay không |
| enquoteIdentifier(String, boolean) | Trả về identifier đơn giản hoặc identifier đã được delimit/quote |
| enquoteLiteral(String) | Tạo SQL character literal với dấu nháy đơn được escape |
| enquoteNCharLiteral(String) | Tạo national character literal có tiền tố N |

Các phương thức tương ứng trên Statement đã có từ Java 9. Điểm mới trong Java 26 là Connection cũng cung cấp chúng, nhờ đó ứng dụng có thể thực hiện quote theo metadata và quy tắc của kết nối hiện tại mà không cần tạo Statement chỉ để gọi phương thức hỗ trợ.

### isSimpleIdentifier

Một simple SQL identifier thường là tên bảng, cột hoặc view tuân theo quy tắc identifier thông thường của SQL.

Default implementation trong Java 26 kiểm tra:

- Ký tự đầu là chữ cái ASCII A-Z hoặc a-z.
- Các ký tự tiếp theo chỉ gồm chữ cái ASCII, chữ số hoặc dấu gạch dưới.
- Tên không phải SQL reserved word.
- Độ dài từ 1 đến 128 ký tự.
- Tên không được đặt sẵn trong dấu ngoặc kép.

Driver có thể override phương thức để áp dụng quy tắc riêng của database, ví dụ giới hạn độ dài khác hoặc tập ký tự mở rộng theo locale.

    boolean simple = connection.isSimpleIdentifier("customer_name");
    boolean reserved = connection.isSimpleIdentifier("select");

Tên select là từ khóa SQL nên default implementation trả về false. Không tự viết một regex riêng rồi xem nó là quy tắc chính thức cho mọi database; dùng method của Connection để driver áp dụng ngữ nghĩa phù hợp.

### enquoteIdentifier

Phương thức enquoteIdentifier(identifier, alwaysDelimit) xử lý tên database object:

- Nếu identifier đơn giản và alwaysDelimit là false, trả về tên gốc.
- Nếu identifier đơn giản và alwaysDelimit là true, trả về dạng đã quote.
- Nếu identifier không đơn giản, phương thức tạo delimited identifier theo delimiter của database.
- Nếu identifier có ký tự không hợp lệ hoặc độ dài không hợp lệ, phương thức ném SQLException.
- Nếu database không hỗ trợ delimited identifier, có thể ném SQLFeatureNotSupportedException.

Ví dụ:

    String column = connection.enquoteIdentifier(
            "order",
            false
    );

    String quotedColumn = connection.enquoteIdentifier(
            "customer name",
            false
    );

Default implementation của Java 26 sử dụng dấu ngoặc kép theo SQL standard. Nếu DatabaseMetaData.getIdentifierQuoteString() không trả về dấu ngoặc kép, default implementation có thể ném SQLException. Driver có thể override để xử lý quy tắc quote riêng của database.

Với tên bảng hoặc cột lấy từ request, vẫn cần allowlist tên hợp lệ trước khi đưa vào SQL. Quoting chỉ tạo cú pháp identifier đúng; nó không xác định người dùng có quyền truy cập bảng/cột đó hay không.

### enquoteLiteral

enquoteLiteral(value) tạo character literal đặt trong dấu nháy đơn và thay mỗi dấu nháy đơn bên trong bằng hai dấu nháy đơn.

Ví dụ:

| Giá trị đầu vào | Kết quả |
|---|---|
| Hello | 'Hello' |
| G'Day | 'G''Day' |
| 'G''Day' | '''G''''Day''' |

    String literal = connection.enquoteLiteral("G'Day");
    System.out.println(literal);

Default implementation tạo kết quả bằng cách thêm dấu nháy đơn ở hai đầu và thay dấu nháy đơn trong chuỗi thành hai dấu nháy đơn. Driver có thể override để đáp ứng quy tắc literal của database.

### enquoteNCharLiteral

enquoteNCharLiteral(value) tạo national character literal với tiền tố N:

| Giá trị đầu vào | Kết quả |
|---|---|
| Hello | N'Hello' |
| G'Day | N'G''Day' |
| N'Hello' | N'N''Hello''' |

    String nationalLiteral =
            connection.enquoteNCharLiteral("G'Day");

Phương thức này hữu ích khi SQL dialect phân biệt national character set literal. Driver có thể chấp nhận tập ký tự khác với enquoteLiteral.

### Không thay PreparedStatement bằng nối chuỗi

Các phương thức enquote giúp xử lý literal/identifier khi cần tạo SQL động. Với dữ liệu giá trị như tên người dùng, email, mã đơn hàng hoặc số tiền, vẫn ưu tiên PreparedStatement và parameter binding:

    String sql = """
            SELECT id, total
            FROM invoice
            WHERE customer_name = ?
            """;

    try (PreparedStatement ps = connection.prepareStatement(sql)) {
        ps.setString(1, customerName);

        try (ResultSet rs = ps.executeQuery()) {
            while (rs.next()) {
                // Xử lý kết quả.
            }
        }
    }

Không dùng enquoteLiteral để thay thế parameter binding trong truy vấn nghiệp vụ thông thường. PreparedStatement tách dữ liệu khỏi cấu trúc SQL, giúp tránh lỗi quoting và giảm nguy cơ SQL injection.

PreparedStatement không thể bind tên bảng hoặc tên cột bằng dấu ?. Với identifier động, xác thực bằng allowlist, sau đó dùng enquoteIdentifier:

    String sortColumn = switch (requestedSort) {
        case "created_at" -> "created_at";
        case "total" -> "total";
        default -> throw new IllegalArgumentException(
                "Unsupported sort column"
        );
    };

    String quotedColumn =
            connection.enquoteIdentifier(sortColumn, false);

    String sql = "SELECT id, total FROM invoice ORDER BY "
            + quotedColumn;

Allowlist xác định tên nào được phép dùng; enquoteIdentifier xử lý cú pháp quote theo database. Cần cả hai lớp kiểm soát.

## 5. Tắt xử lý JDBC escape và parameter marker trong một vùng SQL

JDBC thường xử lý cú pháp escape như {d '2026-01-01'}, {fn ...} hoặc outer join escape trước khi gửi SQL đến database. Ký tự ? trong SQL string cũng thường được nhận diện là parameter marker của PreparedStatement.

Với các cú pháp SQL mới như MATCH_RECOGNIZE, dấu ? có thể là một toán tử hoặc quantifier của pattern, ví dụ A? hoặc X*?. Nếu JDBC driver coi mọi dấu ? là parameter marker, nó có thể phân tích sai SQL.

JDBC 4.5 MR5 định nghĩa một vùng có thể tắt xử lý JDBC escape và parameter marker cục bộ. Vùng này bắt đầu bằng hai ký tự mở { và backslash, kết thúc bằng backslash và }:

    {\ ... \}

Trong Java source, phải escape dấu backslash thành hai dấu backslash. Ví dụ dùng text block:

    String sql = """
            SELECT T.firstW, T.lastZ, ?
            FROM transaction_log
            MATCH_RECOGNIZE (
                MEASURES A.customer_id AS firstW,
                         LAST(Z.customer_id) AS lastZ
                ALL MATCHES
                {\ PATTERN (A? X*? Y+? Z??)\}
                DEFINE
                    X AS X.amount > PREV(X.amount),
                    Y AS Y.amount < PREV(Y.amount),
                    Z AS Z.amount > PREV(Z.amount)
            ) AS T
            """;

Trong vùng được đánh dấu, driver không diễn giải dấu ? thành parameter marker và không xử lý JDBC escape syntax. Dấu ? ở ngoài vùng vẫn có thể là placeholder của PreparedStatement.

Đây là thay đổi ở đặc tả xử lý SQL string và phụ thuộc driver triển khai JDBC 4.5 MR5. Nó không phải một phương thức Java mới. Trước khi sử dụng, kiểm tra release notes của driver và chạy thử truy vấn trên đúng database. Nếu driver chưa hỗ trợ, câu lệnh có thể bị phân tích sai hoặc gửi nguyên phần delimiter đến server.

## 6. SQLPermission được deprecated for removal

JDBC 4.5 đánh dấu **java.sql.SQLPermission** là deprecated for removal từ Java 26.

Lớp này từng được dùng kết hợp với SecurityManager để kiểm soát một số thao tác nhạy cảm trong JDBC. SecurityManager hiện không còn được hỗ trợ để làm cơ chế bảo vệ ứng dụng, vì vậy SQLPermission không còn vai trò bảo mật thực tế như thiết kế ban đầu.

Đặc điểm cần nhớ:

- SQLPermission vẫn tồn tại trong JDK 26 để duy trì tương thích.
- Annotation deprecated có since="26" và forRemoval=true.
- API không có lớp thay thế.
- Không tiếp tục dựa vào policy file hoặc SQLPermission để bảo vệ database resource.
- Dùng cơ chế bảo vệ ở các lớp phù hợp: database user/grant, secret management, network isolation, xác thực ứng dụng và phân quyền nghiệp vụ.

Ví dụ, nếu mã cũ còn tạo SQLPermission hoặc kiểm tra quyền này với SecurityManager, hãy rà soát và loại bỏ đường xử lý đó. Không thay nó bằng một permission class khác của Java rồi kỳ vọng SecurityManager hoạt động trở lại.

## 7. Kiểm tra tương thích của JDBC driver

JDK 26 cung cấp API JDBC 4.5 nhưng driver là thành phần độc lập. Một driver cũ có thể chưa hỗ trợ JSON, DECFLOAT, default methods mới hoặc escape syntax MR5.

JDK 26 release notes lưu ý hai tình huống có thể ảnh hưởng đến tương thích driver:

1. Nếu implementation driver có phương thức cùng chữ ký với default method mới nhưng để private hoặc protected, implementation cần được đổi tên hoặc chuyển thành public.
2. Nếu một lớp triển khai nhiều interface cung cấp default method khác nhau với cùng chữ ký, lớp đó cần override phương thức để giải quyết xung đột.

Trước khi nâng JDK, cần:

- Nâng JDBC driver lên phiên bản được nhà cung cấp xác nhận hỗ trợ Java 26/JDBC 4.5.
- Kiểm tra driver name/version và JDBC major/minor version.
- Kiểm tra JSON/DECFLOAT trong DatabaseMetaData.getTypeInfo().
- Thử đọc/ghi các kiểu mới trên database thật.
- Kiểm tra Blob/Clob/Array/SQLXML có giải phóng tài nguyên đúng khi close().
- Kiểm thử các phương thức Connection.enquote... với identifier/literal đặc thù của database.
- Kiểm tra các câu SQL có MATCH_RECOGNIZE hoặc cú pháp chứa dấu ? trong vùng escape mới.

Không suy ra database hỗ trợ JSON hoặc DECFLOAT chỉ vì code biên dịch thành công. Java API và driver có thể nhận biết type code trong khi server chưa hỗ trợ kiểu dữ liệu tương ứng.

## 8. Kiểm thử JDBC 4.5 theo từng nhóm tính năng

Một kế hoạch kiểm thử nên tách riêng từng cập nhật để dễ tìm lỗi:

| Nhóm | Phép thử | Kết quả cần xác nhận |
|---|---|---|
| JSON | Ghi String bằng JDBCType.JSON, đọc lại bằng getString/getObject | Giá trị JSON không bị đổi ngoài quy tắc của database |
| DECFLOAT | Ghi BigDecimal bằng JDBCType.DECFLOAT, đọc bằng getBigDecimal | Độ chính xác và scale đáp ứng yêu cầu nghiệp vụ |
| LOB/Array | Dùng try-with-resources với Array, Blob, Clob, NClob và SQLXML | close() giải phóng tài nguyên và không dùng object sau khi đóng |
| Identifier | Kiểm tra identifier đơn giản, reserved word, tên có dấu cách và ký tự không hợp lệ | Quote đúng theo database hoặc báo lỗi phù hợp |
| Literal | Kiểm tra chuỗi có dấu nháy đơn và national character | Literal được quote theo quy tắc của driver |
| SQL escape region | Thực thi SQL có dấu ? trong MATCH_RECOGNIZE | Driver không nhầm quantifier với placeholder trong vùng escape |
| SQLPermission | Build và chạy với code không còn phụ thuộc permission cũ | Không còn kiểm soát bảo mật dựa vào SecurityManager |

Với JSON và DECFLOAT, cần test cả NULL, giá trị lớn, precision cao và lỗi dữ liệu. Với LOB/Array, cần test cả trường hợp xử lý thành công, exception giữa chừng và đóng connection. Với identifier/literal, cần test các tên reserved word và tên do người dùng gửi lên.

## 9. Biên dịch và chạy trên JDK 26

JDBC 4.5 là API Java SE ổn định. Ứng dụng không cần preview flag:

    javac --release 26 -cp "lib/database-driver.jar" -d out src/Jdbc45Demo.java

    java -cp "lib/database-driver.jar;out" Jdbc45Demo

Nếu ứng dụng dùng Java Platform Module System, khai báo:

    module application.jdbc {
        requires java.sql;
    }

Driver vẫn phải được thêm vào runtime theo cách phân phối của driver, ví dụ module path, class path hoặc cơ chế service provider.

Nếu biên dịch với --release 25, các thành viên JDBC mới có nhãn Since: 26 sẽ không có trong API release 25. Hãy dùng compiler JDK 26 trở lên và nhắm đúng release đích. Khi chạy JDK 27, JDBC 4.5 API tiếp tục có mặt; không cần bật preview.

Không cần thêm --add-modules cho java.sql trong ứng dụng Java SE thông thường. Nếu dùng jlink để tạo runtime image tối giản, đảm bảo image chứa module java.sql và module driver cần thiết.

## 10. Lộ trình nâng cấp từ driver/JDK cũ

Khi nâng ứng dụng lên JDK 26, nên làm theo trình tự:

1. Ghi nhận database engine, version, JDBC driver và version driver hiện tại.
2. Kiểm tra release notes của driver về JDK 26 và JDBC 4.5 MR5.
3. Nâng driver trước hoặc cùng đợt nâng JDK theo ma trận hỗ trợ của nhà cung cấp.
4. Biên dịch bằng --release 26 để phát hiện mã tham chiếu API mới.
5. Chạy integration test với database thực, đặc biệt JSON, DECFLOAT và LOB lifecycle.
6. Tìm code dùng SQLPermission và loại bỏ phụ thuộc SecurityManager.
7. Kiểm tra các driver wrapper, proxy và pool có xung đột default method hay không.
8. Đưa các thay đổi vào staging, theo dõi SQL exception, lỗi type conversion, lỗi đóng tài nguyên và latency trước khi phát hành.

Nếu driver chưa hỗ trợ một tính năng, có thể tiếp tục dùng kiểu dữ liệu hoặc phương pháp tương thích mà database/driver đã hỗ trợ. Ví dụ, JSON có thể được lưu dưới dạng VARCHAR/CLOB nếu schema hiện tại yêu cầu, nhưng ứng dụng phải hiểu đây là phương án theo khả năng database chứ không phải JDBCType.JSON đang được hỗ trợ.

## 11. Những hiểu lầm thường gặp

- **JDBC 4.5 là preview API:** không đúng. Đây là API chuẩn Java SE 26.
- **JDK 26 có JDBCType.JSON nghĩa là mọi database đều có JSON type:** không đúng. Driver và database phải hỗ trợ.
- **Array/Blob/Clob có close() thì không cần quan tâm transaction:** không đúng. Locator có thể chỉ hợp lệ trong transaction hoặc connection.
- **enquoteLiteral thay thế PreparedStatement:** không nên. Dữ liệu giá trị vẫn nên truyền bằng parameter binding.
- **enquoteIdentifier cho phép mọi tên bảng:** không đúng. Cần allowlist và quy tắc quyền truy cập.
- **SQLPermission có API thay thế:** không có. Lớp này chỉ được giữ lại để tương thích trong thời gian chuyển tiếp.
- **Driver cũ chắc chắn hoạt động vì các method mới đều là default:** không hoàn toàn đúng. Default method có thể phát sinh xung đột hoặc va chạm với implementation nội bộ của driver.
- **Mã Java 26 tự bật tính năng JDBC 4.5 ở server:** không đúng. JDBC driver thực hiện giao tiếp và database quyết định hỗ trợ SQL type/feature nào.

## 12. Checklist triển khai

1. Dùng JDK 26+ và API java.sql chuẩn, không bật preview.
2. Xác nhận JDBC driver tương thích JDBC 4.5 MR5.
3. Xác nhận database hỗ trợ JSON và DECFLOAT trước khi dùng hai type mới.
4. Dùng String cho JSON và BigDecimal cho DECFLOAT theo mapping chuẩn.
5. Dùng try-with-resources cho Array, Blob, Clob, NClob và SQLXML.
6. Dùng Connection.enquoteIdentifier cho identifier động sau khi xác thực allowlist.
7. Dùng PreparedStatement cho các giá trị dữ liệu.
8. Chỉ dùng vùng tắt JDBC escape/parameter marker khi driver hỗ trợ MR5.
9. Loại bỏ SQLPermission và mọi giả định về SecurityManager.
10. Kiểm thử lại driver wrapper, connection pool và default method.
11. Đo và theo dõi lỗi SQL, type conversion, tài nguyên LOB và transaction trong staging.
12. Khi nâng lên JDK 27, xác nhận driver vẫn hỗ trợ API JDBC 4.5 và các tính năng MR5 cần dùng.
