# Chuẩn bị PostgreSQL hoặc MySQL và dữ liệu mẫu

Để thực hành **Spring Data Relational JDBC** (Spring Data JDBC), trước hết cần một cơ sở dữ liệu quan hệ chạy ổn định, tài khoản có quyền truy cập, một lược đồ có bảng và khóa liên kết, cùng dữ liệu có thể kiểm tra bằng SQL. Bài này hướng dẫn chuẩn bị môi trường với **PostgreSQL hoặc MySQL** và nối môi trường đó với ứng dụng Spring Boot.

Bạn chỉ cần **chọn một hệ quản trị** để học. Hai hướng dẫn dùng chung cấu trúc dữ liệu mẫu để các bài Spring Data JDBC phía sau có thể tập trung vào entity, aggregate và repository thay vì phải đổi dữ liệu mỗi lần.

## 1. Kết quả mong đợi và các thành phần

Sau khi thực hiện, bạn sẽ có:

- Một PostgreSQL hoặc MySQL đang chạy trên máy phát triển.
- Database `jdbc_lab` và tài khoản `jdbc_user` dùng để kết nối ứng dụng.
- Hai bảng `authors` và `books`, có khóa chính, khóa ngoại và dữ liệu mẫu.
- Lệnh SQL xác minh số hàng, phép nối bảng và dữ liệu thực sự đã được nạp.
- Cấu hình `spring.datasource.*` để Spring Data JDBC truy cập đúng database.

~~~mermaid
flowchart LR
    App["Spring Boot<br/>Spring Data JDBC"] -->|"JDBC URL + user/password"| Driver["JDBC Driver"]
    Driver -->|"SQL qua TCP"| DB[("PostgreSQL<br/>hoặc MySQL")]
    DB --> Author["authors"]
    DB --> Book["books"]
    Book -->|"author_id (FK)"| Author
    Script["schema + seed SQL"] --> DB
~~~

**Yêu cầu tối thiểu:** Docker Engine hoặc Docker Desktop đang hoạt động, Docker Compose v2 (lệnh `docker compose`), một terminal và Java/JDK phù hợp với dự án Spring Boot. Nếu đã cài PostgreSQL/MySQL trực tiếp, bạn có thể bỏ phần Docker và dùng các file SQL ở phần dưới.

Các tên, tài khoản và mật khẩu `localdev` trong bài là **dữ liệu giả để học trên máy cá nhân**. Với môi trường dùng chung hoặc production, quản lý mật khẩu bằng cấu hình bí mật, giới hạn quyền và không công bố cổng database ra Internet.

## 2. Chọn PostgreSQL hay MySQL?

| Nội dung | PostgreSQL | MySQL |
|---|---|---|
| Driver JDBC | `org.postgresql:postgresql` | `com.mysql:mysql-connector-j` |
| JDBC URL trên máy local | `jdbc:postgresql://localhost:5432/jdbc_lab` | `jdbc:mysql://localhost:3306/jdbc_lab` |
| Cổng mặc định | `5432` | `3306` |
| Cột khóa chính tự tăng trong ví dụ | `GENERATED BY DEFAULT AS IDENTITY` | `AUTO_INCREMENT` |
| Ứng dụng đọc/ghi qua | JDBC / Spring Data JDBC | JDBC / Spring Data JDBC |

Spring Data JDBC làm việc với **cả hai** qua driver và dialect tương ứng. Một số câu SQL DDL khác nhau giữa hai hệ quản trị, vì vậy bài có **hai file schema riêng** và **một file data chung**.

## 3. Cấu trúc thư mục thực hành

Tạo một thư mục thực hành; các đường dẫn sau là cấu trúc **được đề xuất**, chưa phải file có sẵn trong dự án:

~~~text
jdbc-lab/
├── compose.yaml
└── db/
    ├── schema-postgresql.sql
    ├── schema-mysql.sql
    └── data.sql
~~~

Chạy các lệnh Docker Compose từ thư mục `jdbc-lab`, nơi đặt `compose.yaml`. Cả hai dịch vụ dùng thư mục `db` ở chế độ chỉ đọc (`/scripts`) để có thể chạy các script bên trong container.

## 4. Khởi động PostgreSQL hoặc MySQL bằng Docker Compose

Tạo file `compose.yaml`:

~~~yaml
services:
  postgres:
    profiles: ["postgres"]
    image: postgres:16
    environment:
      POSTGRES_DB: jdbc_lab
      POSTGRES_USER: jdbc_user
      POSTGRES_PASSWORD: localdev
    ports:
      - "127.0.0.1:5432:5432"
    volumes:
      - pg_data:/var/lib/postgresql/data
      - ./db:/scripts:ro
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U $$POSTGRES_USER -d $$POSTGRES_DB"]
      interval: 5s
      timeout: 3s
      retries: 20

  mysql:
    profiles: ["mysql"]
    image: mysql:8.4
    environment:
      MYSQL_DATABASE: jdbc_lab
      MYSQL_USER: jdbc_user
      MYSQL_PASSWORD: localdev
      MYSQL_ROOT_PASSWORD: localroot
    ports:
      - "127.0.0.1:3306:3306"
    volumes:
      - mysql_data:/var/lib/mysql
      - ./db:/scripts:ro
    healthcheck:
      test: ["CMD-SHELL", "mysql -h 127.0.0.1 -u$$MYSQL_USER -p$$MYSQL_PASSWORD $$MYSQL_DATABASE -e 'SELECT 1' >/dev/null 2>&1"]
      interval: 5s
      timeout: 3s
      retries: 30

volumes:
  pg_data:
  mysql_data:
~~~

Ý nghĩa các thiết lập:

- `profiles` giúp chỉ chạy hệ quản trị bạn chọn.
- `POSTGRES_DB` hoặc `MYSQL_DATABASE` yêu cầu image khởi tạo database `jdbc_lab`; biến `USER` và `PASSWORD` tương ứng khởi tạo tài khoản thực hành ở lần đầu tạo volume.
- `127.0.0.1:5432:5432` và `127.0.0.1:3306:3306` chỉ mở cổng trên loopback của máy host để ứng dụng chạy ngoài Docker kết nối được.
- `pg_data` và `mysql_data` giữ dữ liệu khi container dừng/xóa rồi tạo lại. **Đổi biến môi trường không tự thay đổi user/password của database đã khởi tạo trong volume cũ.**
- `healthcheck` kiểm tra dịch vụ sẵn sàng nhận kết nối; ký hiệu `$$` yêu cầu Docker Compose chuyển nguyên ký tự `$` để shell trong container đọc biến môi trường.

### Phương án A: PostgreSQL

~~~powershell
docker compose --profile postgres up -d --wait
docker compose --profile postgres ps
docker compose exec postgres pg_isready -U jdbc_user -d jdbc_lab
~~~

Đầu ra `pg_isready` kỳ vọng là `accepting connections`. Nếu Compose cũ không hỗ trợ `--wait`, dùng `docker compose --profile postgres up -d`, rồi theo dõi `docker compose ps` và kiểm tra `pg_isready` khi database khởi tạo xong.

### Phương án B: MySQL

~~~powershell
docker compose --profile mysql up -d --wait
docker compose --profile mysql ps
docker compose exec mysql mysql -ujdbc_user -plocaldev -D jdbc_lab -e "SELECT 1;"
~~~

Lệnh truy vấn trả về một ô có giá trị `1` nghĩa là kết nối hoạt động. CLI MySQL có thể cảnh báo khi mật khẩu được đưa trực tiếp trên command line; cách viết này chỉ phục vụ môi trường local minh họa, không dùng cho môi trường chứa dữ liệu thật.

**Chỉ chạy một phương án** cho một buổi thực hành. Nếu cổng `5432` hoặc `3306` đã bị chương trình khác sử dụng, thay **cổng bên trái** của ánh xạ (ví dụ `127.0.0.1:15432:5432`), rồi đổi cổng trong JDBC URL thành `15432`. Cổng **bên phải** vẫn là cổng bên trong container.

## 5. Thiết kế dữ liệu mẫu: tác giả và sách

Lược đồ gồm hai bảng:

~~~mermaid
erDiagram
    AUTHORS ||--o{ BOOKS : "author_id"
    AUTHORS {
        BIGINT id PK
        VARCHAR code UK
        VARCHAR full_name
    }
    BOOKS {
        BIGINT id PK
        BIGINT author_id FK
        VARCHAR book_code UK
        VARCHAR title
        DATE published_on
        BIGINT price_vnd
        INTEGER stock_quantity
    }
~~~

- `authors.id` và `books.id` là **khóa chính** (primary key, PK), do database tự sinh khi thêm bản ghi.
- `books.author_id` là **khóa ngoại** (foreign key, FK) tham chiếu `authors.id`.
- `authors.code` và `books.book_code` là mã nghiệp vụ duy nhất, giúp đọc dữ liệu mẫu mà không phải giả định ID tự tăng luôn bằng `1`, `2`, `3`.
- `price_vnd` lưu số nguyên VND, tránh dùng kiểu dấu phẩy động cho giá tiền; `stock_quantity` là số lượng tồn kho không âm.
- Dữ liệu ví dụ có ba sách từ hai tác giả, bao gồm một cuốn hết hàng để thử truy vấn lọc.

Hai bảng này phục vụ việc luyện SQL và Spring Data JDBC. **Quan hệ FK trong schema không tự xác định ranh giới aggregate** của domain model; khi xây dựng entity/repository, hãy quyết định quyền sở hữu dựa trên quy tắc nghiệp vụ.

## 6. Tạo schema PostgreSQL

Ghi file `db/schema-postgresql.sql`:

~~~sql
-- CHỈ CHO DATABASE THỰC HÀNH:
-- Xóa bảng cũ để mỗi lần chạy schema có cùng dữ liệu ban đầu.
DROP TABLE IF EXISTS books;
DROP TABLE IF EXISTS authors;

CREATE TABLE authors (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    code VARCHAR(20) NOT NULL UNIQUE,
    full_name VARCHAR(120) NOT NULL
);

CREATE TABLE books (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    author_id BIGINT NOT NULL REFERENCES authors(id),
    book_code VARCHAR(30) NOT NULL UNIQUE,
    title VARCHAR(200) NOT NULL,
    published_on DATE,
    price_vnd BIGINT NOT NULL CHECK (price_vnd >= 0),
    stock_quantity INTEGER NOT NULL DEFAULT 0
        CHECK (stock_quantity >= 0)
);

CREATE INDEX idx_books_author_id ON books(author_id);
~~~

**Lưu ý về `DROP TABLE`:** file cố tình xóa dữ liệu cũ để thực hành từ đầu. Chỉ chạy trong `jdbc_lab` thử nghiệm. Không dùng cách này cho database cần giữ dữ liệu.

Chạy schema sau khi container PostgreSQL khỏe:

~~~powershell
docker compose exec -T postgres psql -v ON_ERROR_STOP=1 -U jdbc_user -d jdbc_lab -f /scripts/schema-postgresql.sql
~~~

Với `psql`, tùy chọn `-v ON_ERROR_STOP=1` khiến phiên thực thi dừng khi SQL lỗi. Sau lệnh thành công, có hai bảng trống với ràng buộc khóa chính, khóa ngoại và các cột cần thiết.

## 7. Tạo schema MySQL

Ghi file `db/schema-mysql.sql`:

~~~sql
-- CHỈ CHO DATABASE THỰC HÀNH.
DROP TABLE IF EXISTS books;
DROP TABLE IF EXISTS authors;

CREATE TABLE authors (
    id BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY,
    code VARCHAR(20) NOT NULL UNIQUE,
    full_name VARCHAR(120) NOT NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE books (
    id BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY,
    author_id BIGINT NOT NULL,
    book_code VARCHAR(30) NOT NULL UNIQUE,
    title VARCHAR(200) NOT NULL,
    published_on DATE,
    price_vnd BIGINT NOT NULL CHECK (price_vnd >= 0),
    stock_quantity INT NOT NULL DEFAULT 0
        CHECK (stock_quantity >= 0),
    CONSTRAINT fk_books_author
        FOREIGN KEY (author_id) REFERENCES authors(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE INDEX idx_books_author_id ON books(author_id);
~~~

MySQL dùng `AUTO_INCREMENT` để sinh khóa chính. `InnoDB` hỗ trợ khóa ngoại và transaction; `utf8mb4` cho phép lưu tên sách và tác giả có dấu tiếng Việt. Các ràng buộc `CHECK` trong ví dụ được thực thi trên MySQL 8.4 đã chọn.

Sau khi container MySQL sẵn sàng, chạy schema qua MySQL client trong container:

~~~powershell
docker compose exec -T mysql mysql -ujdbc_user -plocaldev -D jdbc_lab -e "SOURCE /scripts/schema-mysql.sql"
~~~

Lệnh `SOURCE` yêu cầu MySQL client đọc file đã được mount vào `/scripts`. Phần lớn lệnh SQL trong schema PostgreSQL và MySQL giống nhau, nhưng cú pháp định nghĩa cột tự tăng, một số kiểu dữ liệu và chi tiết DDL khác nhau. Vì vậy **không chạy nhầm file schema** của hệ quản trị kia.

## 8. Nạp dữ liệu mẫu chung cho cả hai hệ quản trị

Ghi `db/data.sql`. File không cung cấp ID tự tăng; nó dùng mã nghiệp vụ `code` để tìm tác giả:

~~~sql
INSERT INTO authors (code, full_name) VALUES
    ('AU-01', 'Nguyễn Minh An'),
    ('AU-02', 'Lê Thu Hà');

INSERT INTO books (
    author_id, book_code, title, published_on, price_vnd, stock_quantity
) VALUES
    (
        (SELECT id FROM authors WHERE code = 'AU-01'),
        'BK-001', 'Nhập môn SQL', '2024-01-15', 129000, 20
    ),
    (
        (SELECT id FROM authors WHERE code = 'AU-01'),
        'BK-002', 'Thiết kế dữ liệu quan hệ', '2024-06-10', 169000, 8
    ),
    (
        (SELECT id FROM authors WHERE code = 'AU-02'),
        'BK-003', 'Spring JDBC thực hành', '2025-02-05', 219000, 0
    );
~~~

Chạy **một trong hai lệnh**, tương ứng database đã khởi động và schema đã tạo:

**PostgreSQL:**

~~~powershell
docker compose exec -T postgres psql -v ON_ERROR_STOP=1 -U jdbc_user -d jdbc_lab -f /scripts/data.sql
~~~

**MySQL:**

~~~powershell
docker compose exec -T mysql mysql -ujdbc_user -plocaldev -D jdbc_lab -e "SOURCE /scripts/data.sql"
~~~

Sau lần nạp đầu, bảng `authors` có **2 hàng** và bảng `books` có **3 hàng**. File seed không được thiết kế để chạy hai lần liên tiếp trên cùng dữ liệu: mã `code` hoặc `book_code` sẽ bị trùng và gặp ràng buộc `UNIQUE`. Để đặt lại bài lab, chạy lại **schema đúng hệ quản trị trước**, rồi chạy lại `data.sql`.

## 9. Xác minh dữ liệu bằng SQL

Trước khi khởi chạy Spring Boot, nên xác minh dữ liệu bằng cách **truy vấn database trực tiếp**. Dùng chung các câu SQL sau cho PostgreSQL và MySQL:

~~~sql
SELECT COUNT(*) AS author_count FROM authors;
SELECT COUNT(*) AS book_count FROM books;

SELECT
    b.book_code,
    b.title,
    a.full_name AS author_name,
    b.price_vnd,
    b.stock_quantity
FROM books b
JOIN authors a ON a.id = b.author_id
ORDER BY b.book_code;

SELECT book_code, title
FROM books
WHERE stock_quantity = 0
ORDER BY book_code;
~~~

Truy vấn đếm phải trả về `author_count = 2` và `book_count = 3`. Kết quả phép nối cho thấy:

| book_code | title | author_name | price_vnd | stock_quantity |
|---|---|---|---:|---:|
| BK-001 | Nhập môn SQL | Nguyễn Minh An | 129000 | 20 |
| BK-002 | Thiết kế dữ liệu quan hệ | Nguyễn Minh An | 169000 | 8 |
| BK-003 | Spring JDBC thực hành | Lê Thu Hà | 219000 | 0 |

Truy vấn cuối trả về `BK-003` vì tồn kho bằng 0. Nếu trả về thiếu hàng, sai tác giả hoặc có mã trùng, hãy kiểm tra xem bạn đã tạo schema đúng hệ quản trị và chỉ nạp seed một lần hay chưa.

Có thể chạy nhanh truy vấn đếm từ terminal:

~~~powershell
# PostgreSQL
docker compose exec -T postgres psql -U jdbc_user -d jdbc_lab -c "SELECT COUNT(*) FROM books;"

# MySQL
docker compose exec -T mysql mysql -ujdbc_user -plocaldev -D jdbc_lab -e "SELECT COUNT(*) FROM books;"
~~~

Hai câu lệnh là hai lựa chọn độc lập; dùng lệnh phù hợp với database đang chạy.

## 10. Kết nối ứng dụng Spring Boot / Spring Data JDBC

Khi kết nối qua JDBC, Spring Boot cần driver tương ứng trên classpath, địa chỉ database, username và password. Ví dụ `build.gradle` cho ứng dụng Spring Boot dùng Gradle:

~~~groovy
dependencies {
    implementation 'org.springframework.boot:spring-boot-starter-data-jdbc'

    // Giữ driver của database đang sử dụng; có thể giữ cả hai
    // nếu cùng một ứng dụng cần chuyển qua lại giữa hai profile.
    runtimeOnly 'org.postgresql:postgresql'
    runtimeOnly 'com.mysql:mysql-connector-j'
}
~~~

Nếu sử dụng Maven, các artifact tương ứng là `spring-boot-starter-data-jdbc`, `postgresql` và `mysql-connector-j` với phiên bản được quản lý bởi Spring Boot BOM.

Tạo cấu hình cho **hai Spring profile** độc lập để dễ chuyển đổi database. Các ví dụ bên dưới đặt trong `src/main/resources/` của dự án Spring Boot.

**`application.yml`** — cấu hình chung:

~~~yaml
spring:
  application:
    name: jdbc-lab
  sql:
    init:
      mode: never
~~~

`spring.sql.init.mode: never` nghĩa là ứng dụng **không tự chạy lại schema/seed SQL khi khởi động**; trong bài này ta đã chạy file qua database client. Tránh vô tình reset dữ liệu khi chạy ứng dụng lần thứ hai.

**`application-postgres.yml`:**

~~~yaml
spring:
  datasource:
    url: jdbc:postgresql://localhost:5432/jdbc_lab
    username: jdbc_user
    password: ${JDBC_DB_PASSWORD:localdev}
~~~

**`application-mysql.yml`:**

~~~yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/jdbc_lab
    username: jdbc_user
    password: ${JDBC_DB_PASSWORD:localdev}
~~~

Biểu thức `${JDBC_DB_PASSWORD:localdev}` dùng biến môi trường `JDBC_DB_PASSWORD` nếu có; nếu không có thì nhận mật khẩu demo `localdev`. Giá trị dự phòng này chỉ thích hợp với bài lab cục bộ.

Kích hoạt profile đúng với database. Ví dụ trong dự án Spring Boot có Gradle wrapper:

~~~powershell
# Windows PowerShell: PostgreSQL
.\gradlew.bat bootRun --args="--spring.profiles.active=postgres"

# Windows PowerShell: MySQL
.\gradlew.bat bootRun --args="--spring.profiles.active=mysql"
~~~

Trên Linux/macOS, lệnh tương ứng là `./gradlew bootRun --args='--spring.profiles.active=postgres'` (hoặc `mysql`). Chạy một profile tại một thời điểm. Nếu ứng dụng chạy **trong một container khác cùng Compose network** thay vì trên máy host, hostname JDBC phải đổi thành tên service `postgres`/`mysql` và giữ cổng container `5432`/`3306`, vì `localhost` khi đó chỉ chính container ứng dụng.

### Thử truy cập bằng repository

Sau khi cấu hình Spring Data JDBC, có thể định nghĩa một aggregate root tối giản cho bảng `books`:

~~~java
import java.time.LocalDate;
import org.springframework.data.annotation.Id;
import org.springframework.data.relational.core.mapping.Table;
import org.springframework.data.repository.CrudRepository;

@Table("books")
public record Book(
    @Id Long id,
    Long authorId,
    String bookCode,
    String title,
    LocalDate publishedOn,
    long priceVnd,
    int stockQuantity
) {}

public interface BookRepository extends CrudRepository<Book, Long> {}
~~~

Trong dự án thật, đặt `Book` và `BookRepository` ở **hai file Java riêng**, thuộc package mà ứng dụng Spring Boot quét được. Với chiến lược đặt tên mặc định, `bookCode` ánh xạ tới `book_code`, `authorId` tới `author_id`, `priceVnd` tới `price_vnd`. Ở mô hình minh họa này, tác giả được tham chiếu bằng `authorId`; không cần ánh xạ thành một object graph lớn.

Một lời gọi `bookRepository.count()` trong service hoặc runner sẽ trả về **3** nếu JDBC URL, tài khoản, driver và schema đều đúng. Dùng `findAll()` để đọc các bản ghi mẫu. Với bài này, kiểm tra bằng SQL ở phần trước vẫn là cách cô lập lỗi database khỏi lỗi mapping Java.

## 11. Kiểm tra lần lượt khi ứng dụng không kết nối được

| Hiện tượng | Nguyên nhân có thể | Cách kiểm tra hoặc sửa |
|---|---|---|
| `Connection refused` / timeout | Database chưa khởi động hoặc sai host/cổng | Kiểm tra `docker compose ps`, healthcheck và cổng ở JDBC URL |
| `password authentication failed` / `Access denied` | Sai tài khoản, mật khẩu hoặc volume cũ đã khởi tạo credential khác | Đối chiếu biến môi trường và tài khoản thực tế trong database; đổi credential bằng SQL quản trị khi cần |
| `database "jdbc_lab" does not exist` / `Unknown database` | Chưa tạo database hoặc kết nối sai tên | Xem database hiện có và chọn đúng tên trong URL |
| `relation "books" does not exist` / `Table 'jdbc_lab.books' doesn't exist` | Chưa chạy schema hoặc kết nối nhầm DB/schema | Chạy file schema tương ứng, kiểm tra database hiện hành |
| `Table ... already exists` hoặc lỗi khóa duy nhất khi seed | Chạy script sai thứ tự hoặc nạp data nhiều lần | Reset schema **chỉ trong database lab** rồi nạp data một lần |
| `No suitable driver` / thiếu JDBC driver | Thiếu dependency JDBC cho database đang dùng | Thêm `postgresql` hoặc `mysql-connector-j` vào runtime classpath |
| Không đọc được tên có dấu | Encoding file/script hoặc kết nối không phù hợp | Lưu SQL UTF-8; với MySQL dùng `utf8mb4` như schema mẫu |
| Lỗi khóa ngoại khi thêm sách | `author_id` không tồn tại | Thêm tác giả trước, tra ID qua mã `code` |
| Kết nối được từ host nhưng không được từ ứng dụng trong Docker | Sử dụng nhầm `localhost` | Dùng tên Compose service làm hostname trong network chung |

Một trình tự gỡ lỗi dễ kiểm chứng là **container sẵn sàng → CLI login thành công → bảng tồn tại → seed đúng số hàng → Spring Boot kết nối → repository trả kết quả**. Nếu lỗi xảy ra ở bước nào, xử lý bước đó trước khi sửa code domain.

## 12. Giữ dữ liệu hoặc bắt đầu lại

Chạy lại container thường **không xóa dữ liệu** vì đã sử dụng named volume:

~~~powershell
docker compose --profile postgres down
docker compose --profile postgres up -d --wait
~~~

Hoặc thay `postgres` bằng `mysql` nếu chọn MySQL. Sau khi lên lại, dữ liệu cũ vẫn còn trong volume. Nếu chỉ muốn đưa **dữ liệu mẫu** về trạng thái ban đầu, chạy lại file `schema-<database>.sql` đúng hệ quản trị rồi chạy `data.sql`; thao tác đó chủ động xóa các bảng lab cũ.

Lệnh `docker compose down -v` **xóa volume do Compose quản lý**, tức là xóa toàn bộ database của môi trường thực hành này. Chỉ dùng khi bạn thực sự muốn bỏ mọi dữ liệu thử nghiệm; không dùng để khắc phục lỗi kết nối khi chưa xác định nguyên nhân.

Với hệ thống thực tế, thay cơ chế reset schema và dữ liệu demo bằng **migration có phiên bản** (như Flyway hoặc Liquibase) và seed có kiểm soát. Không chạy script `DROP TABLE` tự động khi ứng dụng production khởi động.

## 13. Tự luyện tập

Sau khi nạp dữ liệu:

1. Truy vấn tên các sách có `stock_quantity > 0` theo giá tăng dần.
2. Đếm số sách của từng tác giả bằng `JOIN` và `GROUP BY`; kỳ vọng tác giả `AU-01` có 2 sách, `AU-02` có 1 sách.
3. Thêm một dòng sách hợp lệ cho `AU-02` mà không tự điền `books.id`.
4. Thử thêm một sách có `author_id` không tồn tại; quan sát ràng buộc FK ngăn dữ liệu mồ côi.
5. Đổi giá trị cổng host, cập nhật JDBC URL và xác minh ứng dụng vẫn truy cập được.

Ví dụ lời giải cho câu 2:

~~~sql
SELECT a.code, a.full_name, COUNT(b.id) AS book_count
FROM authors a
LEFT JOIN books b ON b.author_id = a.id
GROUP BY a.id, a.code, a.full_name
ORDER BY a.code;
~~~

Khi có database chạy được, dữ liệu mẫu nhất quán và kết nối JDBC đã xác minh, bạn đã có nền tảng để tiếp tục xây dựng **entity, aggregate root, repository và truy vấn Spring Data JDBC** dựa trên những bảng thật.
