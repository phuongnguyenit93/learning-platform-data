# OrderBy, First, Top, and Limiting Results by Version

In **Spring Data Relational JDBC**, derived queries let you describe query conditions directly in repository method names. Beyond conditions like `findByStatus("ACTIVE")`, a method name can also specify ordering and result counts. Three commonly used constructs are:

- **`OrderBy`**: declares sort order in the method name.
- **`First`** and **`Top`**: limit the maximum number of results; the two keywords are equivalent in query derivation.
- **`Limit`**: a dynamic limit parameter available in newer Spring Data versions.

Combining these constructs properly lets the repository retrieve only the needed subset of data instead of loading an entire table into Java before sorting or slicing. Method syntax, return types, and Spring Data version support must be understood accurately.

## 1. What Are Derived Queries?

Spring Data parses repository method names by convention. The part before `By` describes the query type; the part after `By` describes filter conditions. Keywords such as `OrderBy`, `First`, and `Top` add sorting and result limiting.

Example:

```java
List<Customer> findByStatus(String status);
List<Customer> findByStatusOrderByCreatedAtDesc(String status);
Optional<Customer> findFirstByEmail(String email);
List<Customer> findTop10ByStatusOrderByCreatedAtDesc(String status);
```

Spring Data reads the method name, resolves properties in the entity, and generates a query tailored to the database dialect.

Suppose the entity is:

```java
import java.time.Instant;
import org.springframework.data.annotation.Id;
import org.springframework.data.relational.core.mapping.Column;
import org.springframework.data.relational.core.mapping.Table;

@Table("customer")
public record Customer(
        @Id Long id,
        String fullName,
        String email,
        String status,
        @Column("created_at") Instant createdAt
) {}
```

Illustrative PostgreSQL schema:

```sql
CREATE TABLE customer (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    full_name VARCHAR(120) NOT NULL,
    email VARCHAR(255) NOT NULL UNIQUE,
    status VARCHAR(30) NOT NULL,
    created_at TIMESTAMP NOT NULL
);
```

Repository:

```java
import java.util.List;
import java.util.Optional;
import org.springframework.data.repository.CrudRepository;

public interface CustomerRepository
        extends CrudRepository<Customer, Long> {

    List<Customer> findByStatus(String status);

    List<Customer> findByStatusOrderByCreatedAtDesc(String status);

    Optional<Customer> findFirstByEmail(String email);

    List<Customer> findTop10ByStatusOrderByCreatedAtDescIdAsc(
            String status);
}
```

In the method name, `CreatedAt` is the entity's Java property. It maps to the SQL column `created_at` via the annotation/naming strategy. Derived queries always use domain model property names, not physical column names in place of properties.

## 2. OrderBy: Declaring Ordering in the Method Name

`OrderBy` is placed after the condition section and before the property used for sorting:

```java
List<Customer> findByStatusOrderByCreatedAtDesc(String status);
List<Customer> findByStatusOrderByFullNameAsc(String status);
```

- `Asc`: ascending order.
- `Desc`: descending order.
- If no direction is specified, the default order is ascending.

You can sort by multiple properties:

```java
List<Customer> findByStatusOrderByCreatedAtDescIdAsc(String status);
```

This method filters customers by `status`, sorts by `createdAt` descending, and then by `id` ascending.

### 2.1. Why should there be a secondary sort criterion?

If multiple rows share the same `createdAt`, the database does not guarantee their relative order unless the query specifies an additional criterion. When using `Top` limits, nondeterministic ordering can cause the records returned in the result set to vary across runs.

Illustrative PostgreSQL SQL:

```sql
SELECT id, full_name, created_at
FROM customer
WHERE status = 'ACTIVE'
ORDER BY created_at DESC, id ASC
LIMIT 10;
```

The primary key `id` acts as a tie-breaker. This keeps the ordering stable when multiple customers have identical timestamps. Still, if data changes between two requests, the returned results can naturally change.

### 2.2. OrderBy uses Java property names

If the entity declares `@Column("created_at") Instant createdAt`, the method uses `OrderByCreatedAtDesc`. Do not write `OrderByCreated_At` just because the physical column contains an underscore. The framework maps Java properties to SQL identifiers via metadata.

## 3. First and Top: Static Result Limiting

`First` and `Top` are two equivalent keywords:

```java
Optional<Customer> findFirstByStatusOrderByCreatedAtDescIdAsc(
        String status);

List<Customer> findTop5ByStatusOrderByCreatedAtDescIdAsc(
        String status);

List<Customer> findFirst10ByStatusOrderByCreatedAtDescIdAsc(
        String status);
```

Rules:

- `First` or `Top` without a number limits results to at most **one** record.
- You can append a number immediately after the keyword, such as `Top5` or `First10`.
- `First` and `Top` are semantically equivalent; pick one naming style consistently.
- The limit is applied inside the database query, not after loading the full list into memory.

Example fetching the newest customer:

```java
Optional<Customer> latest = repository
        .findFirstByStatusOrderByCreatedAtDescIdAsc("ACTIVE");
```

Example fetching the 5 newest customers:

```java
List<Customer> latestFive =
        repository.findTop5ByStatusOrderByCreatedAtDescIdAsc("ACTIVE");
```

### 3.1. Choosing the right return type

| Return type | Suitable when | When no results exist |
| --- | --- | --- |
| `Optional<T>` | At most one result, and absence should be modeled explicitly | `Optional.empty()` |
| `T` | At most one result, accepting the API's null/exception contract | Typically null if absent |
| `List<T>` | Multiple results are possible | Empty list |
| `Collection<T>` / `Iterable<T>` | A general result collection is sufficient | Empty collection |

Do not declare `Optional<Customer>` for a `Top10` method because it can return multiple rows. Conversely, when only one result is expected, `Optional` lets calling code handle missing records clearly.

### 3.2. First/Top does not replace a unique constraint

`findFirstByEmail(email)` returns at most one row, but it does not prove that emails are unique. If business logic requires uniqueness, enforce a unique constraint in the database along with proper validation. Limiting to one row merely picks one of the matching rows; it does not fix duplicate data and does not guarantee a meaningful selection without `OrderBy`.

## 4. Combining First/Top with Filter Conditions

Filter conditions are placed before `OrderBy`:

```java
List<Customer> findTop20ByStatusAndFullNameContainingIgnoreCaseOrderByCreatedAtDescIdAsc(
        String status,
        String keyword
);
```

This method filters by `status`, searches `fullName` for `keyword` case-insensitively according to query derivation/database capabilities, sorts by timestamp descending then ID ascending, and returns at most 20 rows.

Do not cram too much logic into a method name. When names become overly long or queries grow complex, consider `@Query` with clear SQL or a dedicated query service; verify dialect behavior and result mapping.

## 5. What SQL Is Generated?

Given the method:

```java
List<Customer> findTop10ByStatusOrderByCreatedAtDescIdAsc(String status);
```

Semantically equivalent PostgreSQL SQL:

```sql
SELECT id, full_name, email, status, created_at
FROM customer
WHERE status = ?
ORDER BY created_at DESC, id ASC
LIMIT 10;
```

This is illustrative SQL; actual SQL generated by Spring Data JDBC and the dialect may differ in quoting, column lists, or limit syntax. The driver receives the `status` value via a bind parameter.

Logical evaluation order is filtering with `WHERE`, sorting with `ORDER BY`, and then limiting using the database's syntax. Databases other than PostgreSQL may use `FETCH FIRST ... ROWS ONLY`, `TOP (...)`, or vendor-specific syntax. Spring Data uses the dialect to produce the appropriate SQL.

## 6. Dynamic Limiting with Sort and Limit

Static limits work well when a method always uses the same limit. If the count or sort order varies per call, use dynamic parameters when supported by your version.

### 6.1. Dynamic Sort

A repository method can accept `Sort`:

```java
import org.springframework.data.domain.Sort;

List<Customer> findTop10ByStatus(String status, Sort sort);
```

Invocation:

```java
List<Customer> customers = repository.findTop10ByStatus(
        "ACTIVE",
        Sort.by(
                Sort.Order.desc("createdAt"),
                Sort.Order.asc("id")
        )
);
```

`Top10` keeps the maximum limit at 10; `Sort` changes the sort order per invocation. Sort properties are Java persistent property names, such as `createdAt`, not physical column names like `created_at`.

### 6.2. Dynamic Limit since Spring Data Commons 3.2

Starting in **Spring Data Commons 3.2**, you can use the `Limit` type as a repository parameter to pass dynamic limits:

```java
import org.springframework.data.domain.Limit;

List<Customer> findByStatusOrderByCreatedAtDescIdAsc(
        String status,
        Limit limit
);
```

Invocation:

```java
List<Customer> latestFive = repository
        .findByStatusOrderByCreatedAtDescIdAsc(
                "ACTIVE",
                Limit.of(5)
        );

List<Customer> allMatching = repository
        .findByStatusOrderByCreatedAtDescIdAsc(
                "ACTIVE",
                Limit.unlimited()
        );
```

`Limit.of(5)` caps results at five rows; `Limit.unlimited()` applies no limit from this parameter. Combining `Limit` with other parameters depends on the module version and query type; confirm that the method signature is supported in your project.

**Version constraint:** `Limit` is a newer API than the `First`/`Top` keywords. In Spring Data Commons prior to 3.2, this class is unavailable; use `FirstN`/`TopN` for fixed limits or `Pageable` for pagination. Do not upgrade Spring Data Commons independently just to obtain the new class if doing so conflicts with the version set managed by Spring Boot.

### 6.3. Choosing between First/Top, Limit, and Pageable

| Requirement | Declaration style |
| --- | --- |
| Always fetch at most one row | `findFirstBy...` or `findTopBy...` |
| Always fetch at most 10 rows | `findTop10By...` |
| Limit varies per call, Spring Data 3.2+ | `Limit` parameter |
| Row count varies and page/offset is needed | `Pageable` |
| Fixed row count with varying sort order | `TopN` with `Sort` parameter |

Do not use `Limit` as a substitute for `Pageable` when the UI needs page numbers, offsets, or page metadata. `Limit` only expresses a maximum row count.

## 7. Combining with Pageable and Page

`Pageable` specifies page number, page size, and sort order. `Page<T>` includes metadata such as total elements and total pages in addition to content.

```java
import org.springframework.data.domain.Page;
import org.springframework.data.domain.Pageable;

Page<Customer> findByStatus(String status, Pageable pageable);
```

Invocation:

```java
Pageable pageable = PageRequest.of(
        0,
        20,
        Sort.by(Sort.Order.desc("createdAt"), Sort.Order.asc("id"))
);
Page<Customer> page = repository.findByStatus("ACTIVE", pageable);
```

Differences:

- `Top10` caps the total maximum number of results returned by the method.
- `PageRequest.of(0, 10)` requests the first page with size 10.
- `Page<T>` includes total element/page metadata; the framework may need a count query to supply the total count.
- `Slice<T>` focuses on content and whether a next page exists, without requiring a total page count like `Page<T>`.

Some query derivations allow combining a limiting keyword with `Pageable`; in that case, pagination applies within the query's limit. Because the semantics can be confusing, only combine them if verified in the documentation for your version. For standard pagination, use a query method accepting `Pageable` without adding `TopN`.

## 8. Versions and Dependencies

Actual capabilities depend on the Spring Data Commons and Spring Data JDBC versions on the classpath:

| Capability | Notes |
| --- | --- |
| `First` / `Top` in derived queries | Available since earlier Spring Data generations; broadly compatible |
| `OrderBy` and `Asc`/`Desc` directions | Core derived query syntax |
| `Limit` as a dynamic parameter | Available since Spring Data Commons 3.2 |
| `Pageable` / `Sort` | Core Spring Data Commons APIs; exact support depends on repository module/query type |

Spring Boot manages Spring Data versions through dependency management. Declare the appropriate starter and let the BOM select compatible versions. You can inspect the resolved classpath dependency with:

```bash
./gradlew dependencyInsight --dependency spring-data-commons --configuration runtimeClasspath
```

The output confirms the classpath version. Do not rely solely on the Spring Boot version in the build file if a dependency is overridden by another BOM, version catalog, or constraint.

If `Limit` fails to compile:

1. Check whether `org.springframework.data.domain.Limit` exists on the classpath.
2. Check the `spring-data-commons` version on the compile classpath.
3. If older than 3.2, use `findTop5By...`/`findFirstBy...` for fixed limits.
4. If the limit must vary, consider `Pageable` and cap page size in the service layer.
5. Upgrade Spring Boot/Spring Data only as an intentional dependency change.

## 9. Semantics and Performance Notes

### 9.1. Do not load a large list and slice in memory

Avoid:

```java
List<Customer> all = repository.findByStatus("ACTIVE");
List<Customer> firstTen = all.stream().limit(10).toList();
```

This loads all ACTIVE customers into the application before slicing. If there are hundreds of thousands of rows, the application still receives and instantiates objects for the entire dataset.

Prefer:

```java
List<Customer> firstTen =
        repository.findTop10ByStatusOrderByCreatedAtDescIdAsc("ACTIVE");
```

The database filters, sorts, and limits directly in the query.

### 9.2. Index matching filter conditions and sort order

For a query filtering on `status` and sorting by timestamp:

```sql
SELECT id, full_name, created_at
FROM customer
WHERE status = ?
ORDER BY created_at DESC, id ASC
LIMIT 10;
```

A composite index can help on PostgreSQL:

```sql
CREATE INDEX idx_customer_status_created_id
ON customer (status, created_at DESC, id ASC);
```

This is only one candidate to measure with an execution plan. Effectiveness depends on data distribution, status selectivity, table size, and write workload. Do not add indexes for every property combination without measuring.

### 9.3. Limit does not replace validation

If an API lets clients pass a row count:

- Reject negative numbers or 0 if the contract requires positive counts.
- Enforce a reasonable maximum cap.
- Prevent clients from requesting huge result counts.
- Allowlist permitted sort properties.
- If "latest" is requested, explicitly define the ordering and tie-breaker.

`Limit.of(n)` passes the limit to the repository; it does not enforce system-wide maximums on its own.

## 10. Common Mistakes

| Symptom | Possible cause | How to fix |
| --- | --- | --- |
| Method name fails to parse | Invalid `OrderBy`/property/direction syntax or nonexistent property | Check property names and derived query grammar |
| Incorrect sort | Using SQL column name instead of Java property | Use persistent property name and `Asc`/`Desc` |
| Top 10 shifts between calls | Nondeterministic ordering when sort values tie | Add a unique key as a tie-breaker |
| Using `Optional<T>` when query can return multiple rows | Method lacks a single-row limit | Use `List<T>` or limit to at most one result |
| `Limit` does not compile | Spring Data Commons older than 3.2 or version mismatch | Check classpath; use `TopN`/`Pageable` |
| Using `Top` yet still loading lots of data | Calling a different method, custom query missing limit, or slicing in Java | Inspect the actual SQL |
| Query is slow even when fetching only 10 rows | Missing index or expensive sort | Check execution plan and indexes |
| Confusing page size with total limit | Mixing up pagination and limiting | Pick `TopN`/`Limit` or `Pageable` appropriately |
| Column name with underscore not recognized | Using SQL column name in derived method | Use the Java property name |

## 11. Combined Repository Example

```java
import java.util.List;
import java.util.Optional;
import org.springframework.data.domain.Limit;
import org.springframework.data.domain.Sort;
import org.springframework.data.repository.CrudRepository;

public interface CustomerRepository
        extends CrudRepository<Customer, Long> {

    Optional<Customer> findFirstByEmail(String email);

    List<Customer> findTop5ByStatusOrderByCreatedAtDescIdAsc(
            String status);

    List<Customer> findTop10ByStatus(String status, Sort sort);

    // Requires Spring Data Commons 3.2+.
    List<Customer> findByStatusOrderByCreatedAtDescIdAsc(
            String status, Limit limit);
}
```

Service:

```java
import java.util.List;
import org.springframework.data.domain.Limit;
import org.springframework.data.domain.Sort;
import org.springframework.stereotype.Service;

@Service
public class CustomerQueryService {

    private final CustomerRepository repository;

    public CustomerQueryService(CustomerRepository repository) {
        this.repository = repository;
    }

    public List<Customer> latestActiveCustomers() {
        return repository.findTop5ByStatusOrderByCreatedAtDescIdAsc(
                "ACTIVE");
    }

    public List<Customer> latestCustomers(int requestedSize) {
        int size = Math.max(1, Math.min(requestedSize, 50));
        return repository.findByStatusOrderByCreatedAtDescIdAsc(
                "ACTIVE", Limit.of(size));
    }

    public List<Customer> activeCustomersByName() {
        return repository.findTop10ByStatus(
                "ACTIVE",
                Sort.by(Sort.Order.asc("fullName"), Sort.Order.asc("id")));
    }
}
```

`Math.max/Math.min` in the example clamps the requested count to 1..50. This is an illustrative policy; a real application may return a validation error instead of silently clamping. If the project uses Spring Data prior to 3.2, remove the method taking `Limit` and use a fixed `TopN` or `Pageable`.

**Exercise 2 — First and Top.** Write `findFirstByStatusOrderByCreatedAtDescIdAsc` and `findTop5ByStatusOrderByCreatedAtDescIdAsc`. Compare `Optional` and `List` when no matching data exists.

**Exercise 3 — Limiting SQL.** Enable SQL logging in development and confirm the Top 5 query is limited in the database rather than fetching all results and slicing in Java.

**Exercise 4 — Dynamic Sort.** Add a `Sort` parameter to `findTop10ByStatus`. Create an allowlist of valid sort properties and reject disallowed property names.

**Exercise 5 — Limit by version.** Check your `spring-data-commons` version. If 3.2 or newer, try `Limit.of(3)` and `Limit.unlimited()`; if older, substitute `Top3` or an appropriate `Pageable`.
