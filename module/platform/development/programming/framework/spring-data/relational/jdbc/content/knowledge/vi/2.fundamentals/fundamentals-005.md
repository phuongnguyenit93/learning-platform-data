# Vai trò của JdbcTemplate và NamedParameterJdbcTemplate trong Spring Data Relational JDBC

## 1. Vì sao cần hai lớp này?

Khi làm việc với cơ sở dữ liệu quan hệ từ Java, JDBC cung cấp các thành phần nền tảng như `Connection`, `PreparedStatement` và `ResultSet`. Chúng cho phép chạy SQL trực tiếp, nhưng mã ứng dụng phải tự quản lý việc lấy/giải phóng kết nối, gán tham số, duyệt kết quả và xử lý lỗi.

**`JdbcTemplate`** và **`NamedParameterJdbcTemplate`** thuộc **Spring JDBC**. Chúng giải quyết phần thao tác lặp lại của JDBC, để lập trình viên tập trung vào câu SQL, dữ liệu đầu vào và cách ánh xạ kết quả. Trong một ứng dụng sử dụng **Spring Data JDBC**, hai lớp này vẫn hữu ích khi cần truy vấn hoặc cập nhật trực tiếp bằng SQL.

~~~mermaid
flowchart TD
    A["Service / business logic"] --> B["Spring Data JDBC Repository"]
    A --> C["JdbcTemplate"]
    A --> D["NamedParameterJdbcTemplate"]
    B --> E["Spring JDBC infrastructure"]
    C --> E
    D --> E
    E --> F["DataSource / JDBC Driver"]
    F --> G[("Relational Database")]
~~~

Cần phân biệt ba tầng:

- **JDBC chuẩn:** API của Java để gửi SQL tới database thông qua JDBC driver.
- **Spring JDBC:** cung cấp `JdbcTemplate`, `NamedParameterJdbcTemplate`, xử lý tài nguyên, ngoại lệ và tích hợp giao dịch.
- **Spring Data JDBC:** tầng trừu tượng cao hơn cho việc lưu, tải và quản lý *aggregate* thông qua repository và ánh xạ đối tượng. Spring Data JDBC sử dụng hạ tầng Spring JDBC, nhưng không thay thế mọi nhu cầu viết SQL thủ công.

`JdbcTemplate` và `NamedParameterJdbcTemplate` **không phải ORM như JPA/Hibernate**: chúng không theo dõi đối tượng đang được quản lý (*persistence context*), không tự phát hiện thay đổi thuộc tính để ghi xuống database và không cung cấp cơ chế lazy loading quan hệ đối tượng.

## 2. JdbcTemplate làm những gì?

`JdbcTemplate` là lớp trung tâm của Spring JDBC, nhận một `DataSource` và thực hiện quy trình JDBC thay cho ứng dụng:

1. Lấy một `Connection` thích hợp từ `DataSource`, tham gia giao dịch Spring đang hoạt động nếu có.
2. Chuẩn bị và thực thi câu SQL; truyền tham số cho `PreparedStatement`.
3. Giao `ResultSet` cho `RowMapper` hoặc callback để chuyển hàng dữ liệu thành đối tượng Java.
4. Giải phóng tài nguyên JDBC theo đúng ngữ cảnh; kết nối thuộc giao dịch sẽ được quản lý theo vòng đời giao dịch.
5. Chuyển `SQLException` thành hệ thống ngoại lệ `DataAccessException` của Spring.

Nhờ vậy, lập trình viên thường chỉ viết **SQL + tham số + cách đọc dữ liệu**, không cần tự viết `try/finally` để đóng `ResultSet` và `Statement` cho mỗi truy vấn.

### Những thao tác thường dùng

| Nhu cầu | API tiêu biểu | Kết quả |
|---|---|---|
| Truy vấn nhiều hàng | `query(sql, rowMapper, args...)` | `List<T>` |
| Truy vấn một giá trị | `queryForObject(sql, Long.class, args...)` | Một giá trị, hoặc ngoại lệ khi số hàng không đúng |
| Thực hiện INSERT/UPDATE/DELETE | `update(sql, args...)` | Số hàng bị tác động |
| Cập nhật hàng loạt | `batchUpdate(...)` | Kết quả cập nhật theo từng lệnh/batch |
| Thực hiện SQL hay JDBC callback đặc biệt | `execute(...)` | Phụ thuộc loại callback |

`JdbcTemplate` hỗ trợ **tham số vị trí** với ký tự `?`. Mỗi giá trị phải được truyền đúng thứ tự dấu `?` trong SQL.

## 3. Ví dụ: đọc và cập nhật bảng books bằng JdbcTemplate

Giả sử ứng dụng có bảng:

~~~sql
CREATE TABLE books (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    title VARCHAR(200) NOT NULL,
    author VARCHAR(120) NOT NULL,
    price DECIMAL(12, 2) NOT NULL
);
~~~

Ví dụ sử dụng Spring Boot và Spring Data JDBC với cấu hình Gradle:

~~~groovy
dependencies {
    implementation("org.springframework.boot:spring-boot-starter-data-jdbc")
    runtimeOnly("com.h2database:h2") // Chỉ dùng H2 cho ví dụ chạy cục bộ
}
~~~

Trong Spring Boot, khi có `DataSource` và các dependency tương ứng, Boot có thể cấu hình sẵn bean `JdbcTemplate` để tiêm qua constructor. Trong ứng dụng thực tế, driver và thông tin kết nối phụ thuộc hệ quản trị cơ sở dữ liệu đang dùng.

Định nghĩa đối tượng kết quả:

~~~java
import java.math.BigDecimal;

public record Book(
        long id,
        String title,
        String author,
        BigDecimal price
) {}
~~~

Tạo lớp truy cập dữ liệu:

~~~java
import java.math.BigDecimal;
import java.util.List;
import java.util.Optional;

import org.springframework.jdbc.core.JdbcTemplate;
import org.springframework.jdbc.core.RowMapper;
import org.springframework.stereotype.Repository;

@Repository
public class BookJdbcDao {

    private static final RowMapper<Book> BOOK_MAPPER = (rs, rowNum) ->
            new Book(
                    rs.getLong("id"),
                    rs.getString("title"),
                    rs.getString("author"),
                    rs.getBigDecimal("price")
            );

    private final JdbcTemplate jdbc;

    public BookJdbcDao(JdbcTemplate jdbc) {
        this.jdbc = jdbc;
    }

    public List<Book> findByAuthor(String author) {
        String sql = """
                SELECT id, title, author, price
                FROM books
                WHERE author = ?
                ORDER BY id
                """;
        return jdbc.query(sql, BOOK_MAPPER, author);
    }

    public Optional<Book> findById(long id) {
        String sql = """
                SELECT id, title, author, price
                FROM books
                WHERE id = ?
                """;
        return jdbc.query(sql, BOOK_MAPPER, id).stream().findFirst();
    }

    public long countBooks() {
        Long count = jdbc.queryForObject(
                "SELECT COUNT(*) FROM books", Long.class);
        return count.longValue();
    }

    public int changePrice(long id, BigDecimal newPrice) {
        return jdbc.update(
                "UPDATE books SET price = ? WHERE id = ?",
                newPrice, id
        );
    }

    public int deleteById(long id) {
        return jdbc.update("DELETE FROM books WHERE id = ?", id);
    }
}
~~~

**Điểm cần hiểu trong ví dụ:**

- `BOOK_MAPPER` nhận từng hàng `ResultSet` và tạo một `Book`; đây là ánh xạ thủ công, tường minh, không tự động tải toàn bộ quan hệ đối tượng.
- Trong `findByAuthor`, chỉ có một dấu `?` nên tham số `author` nằm ở vị trí đầu tiên.
- Trong `changePrice`, dấu `?` đầu tiên ứng với `newPrice`; dấu thứ hai ứng với `id`. Đảo thứ tự có thể dẫn đến lỗi dữ liệu hoặc lỗi kiểu.
- `update(...)` trả về **số hàng được tác động**. Với khóa chính, kết quả `0` thường nghĩa là không tìm thấy bản ghi; `1` nghĩa là một hàng đã cập nhật.
- `query(...)` trả về danh sách rỗng nếu không có hàng phù hợp. Cách xây dựng `Optional` ở trên dựa vào tính duy nhất của `id` được đảm bảo bởi khóa chính.
- `queryForObject(...)` yêu cầu số hàng kết quả phù hợp với truy vấn đơn giá trị/một hàng. Với truy vấn không có hàng hoặc có nhiều hàng khi chỉ mong đợi một hàng, Spring có thể ném `IncorrectResultSizeDataAccessException` (trường hợp rỗng thường là `EmptyResultDataAccessException`). Không nên tự động coi mọi `DataAccessException` là “không tìm thấy”.

### RowMapper, ResultSetExtractor và RowCallbackHandler

`RowMapper<T>` phù hợp nhất khi **mỗi hàng ánh xạ thành một đối tượng**. Với kết quả cần tổng hợp từ nhiều hàng (ví dụ một hóa đơn có nhiều dòng hàng), có thể sử dụng `ResultSetExtractor<T>` để chủ động duyệt toàn bộ `ResultSet`. `RowCallbackHandler` phù hợp khi cần xử lý lần lượt từng hàng mà không xây dựng một `List` kết quả.

Trong truy vấn có `JOIN` làm lặp dữ liệu của thực thể cha, đừng mặc định một `RowMapper` đơn giản có thể khôi phục đúng quan hệ một-nhiều; phải thiết kế cách nhóm dữ liệu hoặc để Spring Data JDBC quản lý aggregate phù hợp.

## 4. NamedParameterJdbcTemplate khác gì?

`NamedParameterJdbcTemplate` cung cấp **tham số có tên** theo cú pháp `:tenThamSo`, thay cho việc buộc người đọc đếm dấu `?`. Nó dùng hạ tầng `JdbcTemplate` phía dưới: Spring phân tích cú pháp SQL có tên, chuyển thành tham số JDBC theo vị trí và bind các giá trị tương ứng.

Ví dụ cùng một điều kiện:

~~~sql
-- JdbcTemplate: tham số theo vị trí
SELECT id, title, author, price
FROM books
WHERE author = ? AND price >= ?;

-- NamedParameterJdbcTemplate: tham số có tên
SELECT id, title, author, price
FROM books
WHERE author = :author AND price >= :minPrice;
~~~

Với câu SQL nhiều điều kiện, cùng một giá trị dùng ở nhiều vị trí hoặc được chỉnh sửa thường xuyên, tên tham số giúp giảm nhầm lẫn về thứ tự.

### Truy vấn thực tế với MapSqlParameterSource

~~~java
import java.math.BigDecimal;
import java.util.List;

import org.springframework.jdbc.core.RowMapper;
import org.springframework.jdbc.core.namedparam.MapSqlParameterSource;
import org.springframework.jdbc.core.namedparam.NamedParameterJdbcTemplate;
import org.springframework.stereotype.Repository;

@Repository
public class NamedBookJdbcDao {

    private static final RowMapper<Book> BOOK_MAPPER = (rs, rowNum) ->
            new Book(
                    rs.getLong("id"),
                    rs.getString("title"),
                    rs.getString("author"),
                    rs.getBigDecimal("price")
            );

    private final NamedParameterJdbcTemplate namedJdbc;

    public NamedBookJdbcDao(NamedParameterJdbcTemplate namedJdbc) {
        this.namedJdbc = namedJdbc;
    }

    public List<Book> findByAuthorAndMinPrice(
            String author, BigDecimal minPrice) {

        String sql = """
                SELECT id, title, author, price
                FROM books
                WHERE author = :author AND price >= :minPrice
                ORDER BY id
                """;

        var params = new MapSqlParameterSource()
                .addValue("author", author)
                .addValue("minPrice", minPrice);

        return namedJdbc.query(sql, params, BOOK_MAPPER);
    }

    public List<Book> findByIds(List<Long> ids) {
        if (ids.isEmpty()) {
            return List.of();
        }

        String sql = """
                SELECT id, title, author, price
                FROM books
                WHERE id IN (:ids)
                ORDER BY id
                """;

        return namedJdbc.query(
                sql,
                new MapSqlParameterSource("ids", ids),
                BOOK_MAPPER
        );
    }
}
~~~

Ở ví dụ `findByIds`, Spring mở rộng collection `ids` thành số lượng dấu `?` tương ứng và bind từng giá trị. **Danh sách rỗng phải được xử lý trước**, bởi SQL kiểu `IN ()` không có cú pháp hoặc ý nghĩa nhất quán giữa các database. Với danh sách rất lớn, cần cân nhắc giới hạn số tham số của driver/database, chia batch hoặc sử dụng chiến lược truy vấn phù hợp.

### Những cách truyền tham số có tên

- `Map<String, ?>`: ngắn gọn cho số lượng tham số nhỏ.
- `MapSqlParameterSource`: dễ thêm tham số, chỉ định `SQL type` khi cần, đặc biệt với giá trị `null`.
- `BeanPropertySqlParameterSource`: đọc các JavaBean property từ đối tượng; phù hợp khi tên property khớp tên tham số SQL.

Ví dụ khi driver cần biết kiểu của giá trị `null`:

~~~java
import java.sql.Types;
import org.springframework.jdbc.core.namedparam.MapSqlParameterSource;

var params = new MapSqlParameterSource()
        .addValue("author", null, Types.VARCHAR)
        .addValue("minPrice", new BigDecimal("100.00"));
~~~

Điểm đáng chú ý: `:author` **chỉ thay thế một giá trị dữ liệu**. Nó không thể là tên bảng, tên cột hay cú pháp SQL tùy ý.

## 5. INSERT lấy khóa sinh tự động và batch update

Với bảng sử dụng cột `id` kiểu identity, có thể lấy khóa do database tạo thông qua `KeyHolder`. Đoạn sau là một phương thức có thể thêm vào `NamedBookJdbcDao` ở mục trước:

~~~java
import org.springframework.jdbc.support.GeneratedKeyHolder;
import org.springframework.jdbc.support.KeyHolder;

public long insert(String title, String author, BigDecimal price) {
    String sql = """
            INSERT INTO books (title, author, price)
            VALUES (:title, :author, :price)
            """;

    var params = new MapSqlParameterSource()
            .addValue("title", title)
            .addValue("author", author)
            .addValue("price", price);

    KeyHolder keys = new GeneratedKeyHolder();
    int rows = namedJdbc.update(sql, params, keys, new String[] {"id"});

    Number key = keys.getKey();
    if (rows != 1 || key == null) {
        throw new IllegalStateException("Insert không trả về khóa id");
    }
    return key.longValue();
}
~~~

Độ hỗ trợ generated keys phụ thuộc JDBC driver và database. Mảng `new String[] {"id"}` chỉ rõ cột cần trả về. Với một số database hoặc cấu hình, có thể cần cú pháp SQL riêng hoặc cách lấy khóa khác.

Khi phải cập nhật nhiều bản ghi cùng kiểu, `batchUpdate` thường tránh chi phí gửi từng lệnh rời rạc:

~~~java
import org.springframework.jdbc.core.namedparam.SqlParameterSource;

public record PriceChange(long id, BigDecimal price) {}

public int[] updatePrices(List<PriceChange> changes) {
    SqlParameterSource[] batch = changes.stream()
            .map(change -> new MapSqlParameterSource()
                    .addValue("id", change.id())
                    .addValue("price", change.price()))
            .toArray(SqlParameterSource[]::new);

    return namedJdbc.batchUpdate(
            "UPDATE books SET price = :price WHERE id = :id",
            batch
    );
}
~~~

`batchUpdate` trả kết quả cập nhật theo từng phần tử; cách driver báo số hàng có thể bao gồm các mã trạng thái JDBC đặc biệt. **Batch không mặc nhiên bảo đảm tính nguyên tử**: khi cần tất cả cùng thành công hoặc rollback, hãy đặt thao tác trong giao dịch phù hợp.

## 6. Giao dịch: Template thực thi SQL, Spring quản lý ranh giới transaction

`JdbcTemplate` và `NamedParameterJdbcTemplate` có thể tham gia một giao dịch được mở bằng `@Transactional`. Thực tế, transaction manager lấy/bind kết nối theo thread trong ngữ cảnh Spring; các template dùng `DataSource` phù hợp sẽ tham gia giao dịch đó.

Ví dụ cập nhật giá của hai cuốn sách như một thao tác nghiệp vụ:

~~~java
import java.math.BigDecimal;

import org.springframework.jdbc.core.JdbcTemplate;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

@Service
public class BookPricingService {

    private final JdbcTemplate jdbc;

    public BookPricingService(JdbcTemplate jdbc) {
        this.jdbc = jdbc;
    }

    @Transactional
    public void setPairPrice(
            long firstBookId, long secondBookId, BigDecimal price) {

        int first = jdbc.update(
                "UPDATE books SET price = ? WHERE id = ?",
                price, firstBookId
        );
        if (first != 1) {
            throw new IllegalArgumentException("Không tìm thấy sách thứ nhất");
        }

        int second = jdbc.update(
                "UPDATE books SET price = ? WHERE id = ?",
                price, secondBookId
        );
        if (second != 1) {
            throw new IllegalArgumentException("Không tìm thấy sách thứ hai");
        }
    }
}
~~~

Khi transaction manager được cấu hình đúng và phương thức được gọi qua Spring proxy, nếu cập nhật thứ hai thất bại và ngoại lệ runtime được ném ra, cập nhật thứ nhất sẽ được rollback cùng giao dịch. Mặc định, Spring rollback với `RuntimeException` và `Error`; ngoại lệ checked cần cấu hình `rollbackFor` nếu nghiệp vụ yêu cầu.

Những điều cần nhớ:

- Nên đặt ranh giới `@Transactional` ở **service/use case**, nơi biết một tác vụ nghiệp vụ gồm bao nhiêu thao tác SQL.
- Chỉ sử dụng chung một connection transaction khi template và transaction manager phối hợp trên `DataSource` phù hợp.
- Tự gọi một phương thức `@Transactional` từ phương thức khác trong cùng đối tượng thường không đi qua proxy; đừng coi annotation đó luôn mở transaction.
- Transaction đảm bảo tính nhất quán của nhiều lệnh, nhưng vẫn phải xét isolation, lock và xung đột cập nhật theo đặc tính database.

## 7. SQL injection và sự an toàn của tham số

**Cả hai template đều hỗ trợ binding giá trị qua prepared statements.** Không ghép trực tiếp dữ liệu người dùng vào SQL:

~~~java
// Không an toàn: dữ liệu từ người dùng trở thành một phần cú pháp SQL.
String unsafeSql =
        "SELECT * FROM books WHERE author = '" + authorInput + "'";

// An toàn: driver bind authorInput như một giá trị.
jdbc.query(
        "SELECT id, title, author, price FROM books WHERE author = ?",
        BOOK_MAPPER,
        authorInput
);

// Cách tương đương với tên tham số:
namedJdbc.query(
        "SELECT id, title, author, price FROM books WHERE author = :author",
        new MapSqlParameterSource("author", authorInput),
        BOOK_MAPPER
);
~~~

Prepared parameters **không thể thay thế định danh SQL** như tên cột trong `ORDER BY`. Nếu người dùng được chọn tiêu chí sắp xếp, chỉ lấy tên cột từ một danh sách cố định do ứng dụng kiểm soát:

~~~java
String orderBy = switch (sortKey) {
    case "title" -> "title";
    case "price" -> "price";
    default -> "id";
};

String sql = """
        SELECT id, title, author, price
        FROM books
        ORDER BY %s
        """.formatted(orderBy);
~~~

Ở đây `orderBy` luôn là một chuỗi từ allowlist, không chứa trực tiếp nội dung tùy ý từ request. Có thể thêm `ASC`/`DESC` bằng cách tương tự.

## 8. Đọc lỗi và quan sát hiệu năng

Spring chuyển phần lớn `SQLException` thành các loại `DataAccessException` để tầng trên không phải xử lý riêng từng mã lỗi JDBC. Một số loại thường gặp:

| Ngoại lệ | Tình huống tiêu biểu |
|---|---|
| `EmptyResultDataAccessException` | API mong một hàng nhưng truy vấn không trả hàng nào |
| `DuplicateKeyException` | INSERT/UPDATE vi phạm ràng buộc unique hoặc primary key |
| `DataIntegrityViolationException` | Vi phạm ràng buộc dữ liệu, ví dụ foreign key hoặc NOT NULL |
| `BadSqlGrammarException` | Câu SQL không hợp lệ với database |
| `CannotGetJdbcConnectionException` | Không lấy được kết nối JDBC |

Tên ngoại lệ cụ thể phụ thuộc lỗi do driver trả về và bộ phân loại của Spring. Không nên dựa vào việc “lỗi SQL nào cũng là duplicate key”, cũng không dùng `catch (Exception)` để mặc định trả danh sách rỗng. Với lỗi kỹ thuật, cần để ngoại lệ được xử lý và ghi log ở tầng thích hợp.

Về hiệu năng:

- Chỉ SELECT các cột cần dùng, sử dụng index cho điều kiện tìm kiếm thường gặp và phân trang khi kết quả lớn.
- `RowMapper` tạo đối tượng cho từng hàng; trả về một danh sách khổng lồ có thể tốn bộ nhớ. Với luồng lớn, cân nhắc callback hoặc cơ chế xử lý từng phần thích hợp.
- `batchUpdate` giúp giảm số vòng trao đổi với database nhưng cần kiểm soát số lượng mỗi batch và transaction.
- `JdbcTemplate` có thể dùng như bean singleton khi cấu hình xong; tài nguyên JDBC của từng lần gọi được xử lý trong phạm vi thực thi. Không lưu `ResultSet` hoặc `Connection` dùng chung giữa các request.
- `DataSource` thường sử dụng connection pool trong ứng dụng thực tế. Pool và timeout cần được cấu hình theo tải, thay vì tạo kết nối mới cho từng câu lệnh.
- Không nhầm khả năng SQL của template với việc SQL được tối ưu: hiệu năng vẫn phụ thuộc index, query plan, isolation và cấu trúc schema.

## 9. Chọn JdbcTemplate, NamedParameterJdbcTemplate hay Spring Data JDBC Repository?

| Tiêu chí | `JdbcTemplate` | `NamedParameterJdbcTemplate` | Spring Data JDBC Repository |
|---|---|---|---|
| Cách làm việc | Viết SQL trực tiếp | Viết SQL trực tiếp | Thao tác với aggregate/repository |
| Binding | `?` theo vị trí | `:name` có tên | Framework xử lý nhiều thao tác chuẩn |
| Mức kiểm soát SQL | Rất cao | Rất cao | Dùng repository cho CRUD chuẩn; có thể có query tùy biến |
| Ánh xạ kết quả | Tự cung cấp `RowMapper`/callback | Tự cung cấp `RowMapper`/callback | Ánh xạ aggregate theo metadata và quy ước |
| Trường hợp phù hợp | SQL ít tham số, câu lệnh ngắn, thao tác đặc biệt | SQL nhiều bộ lọc, nhiều tham số, `IN` list, batch | Lưu/tải aggregate theo mô hình Spring Data JDBC |

**Khi dùng từng cách:**

1. Chọn `JdbcTemplate` khi SQL đơn giản, số tham số ít, thứ tự dễ kiểm soát hoặc cần dùng callback JDBC trực tiếp.
2. Chọn `NamedParameterJdbcTemplate` khi SQL phức tạp hơn, có nhiều điều kiện, lặp tham số hoặc truy vấn nhận tập ID.
3. Chọn repository của Spring Data JDBC khi muốn biểu diễn thao tác lưu/tải aggregate theo mô hình domain và dùng các quy tắc lifecycle của Spring Data JDBC.

Chúng có thể **cùng tồn tại trong một ứng dụng**. Ví dụ, repository lo thao tác lưu aggregate `Order`, còn `NamedParameterJdbcTemplate` thực hiện một truy vấn báo cáo cần `JOIN`, tổng hợp và projection riêng.

### Lưu ý khi phối hợp Spring Data JDBC và SQL trực tiếp

SQL viết bằng template cập nhật database ngay theo câu lệnh đã gửi và **không tự chạy các bước lifecycle của repository** như callback của aggregate hoặc kiểm tra optimistic locking theo `@Version`. Nếu thay đổi cùng một aggregate bằng cả repository và SQL trực tiếp, cần chủ động bảo vệ invariant và quy tắc đồng bộ dữ liệu.

Ví dụ, nếu repository đang dùng cột `version` để phát hiện cập nhật đồng thời, câu lệnh SQL trực tiếp phải tự thiết kế điều kiện `WHERE id = :id AND version = :expectedVersion` và cập nhật `version` phù hợp nếu muốn duy trì cùng bảo đảm chống ghi đè. Chỉ chạy `UPDATE ... WHERE id = :id` sẽ bỏ qua kiểm tra đó.

## 10. Sai lầm phổ biến và cách tránh

| Sai lầm | Hướng xử lý |
|---|---|
| Ghép biến người dùng thành chuỗi SQL | Dùng `?` hoặc `:name` để bind giá trị |
| Đảo thứ tự nhiều dấu `?` | Dùng tham số có tên cho SQL khó đọc |
| Dùng `queryForObject` rồi giả định không có dữ liệu sẽ trả `null` | Xử lý đúng ngoại lệ “không có hàng”, hoặc dùng `query(...).stream().findFirst()` với truy vấn bảo đảm duy nhất |
| Dùng `IN (:ids)` với danh sách trống | Xác định nghiệp vụ và xử lý danh sách trống trước |
| Dùng tên tham số cho tên bảng/cột | Dùng allowlist định danh SQL |
| Coi `batchUpdate` tự động là giao dịch nguyên tử | Dùng `@Transactional` cho nghiệp vụ nhiều cập nhật |
| Dùng `RowMapper` một-hàng-một-đối-tượng cho mọi `JOIN` một-nhiều | Chủ động nhóm kết quả hoặc dùng aggregate mapping thích hợp |
| Cập nhật thẳng aggregate nhưng kỳ vọng callback/`@Version` của repository | Kiểm soát invariant, version và lifecycle một cách tường minh |

## 11. Bài tập thực hành

Với bảng `books` ở trên, hãy thử:

1. Viết truy vấn tìm sách có `author` bằng tham số và `price` trong một khoảng bằng `JdbcTemplate`. Quan sát thứ tự của ba dấu `?`.
2. Chuyển truy vấn đó sang `NamedParameterJdbcTemplate` với `:author`, `:minPrice`, `:maxPrice`, rồi thêm một điều kiện dùng lại `:author`.
3. Viết `findByIds(List<Long> ids)`, kiểm tra hai trường hợp danh sách có phần tử và danh sách rỗng.
4. Viết một service cập nhật giá hai sách trong `@Transactional`; cố ý dùng ID không tồn tại ở cập nhật thứ hai và quan sát giá trị đầu tiên có được rollback hay không.
5. Thử truy vấn một sách không tồn tại bằng `queryForObject`, đối chiếu với cách trả `Optional<Book>` và phân biệt “không có hàng” với lỗi kết nối.

**Ghi nhớ:** `JdbcTemplate` giúp viết JDBC ít mã lặp với tham số **theo vị trí**; `NamedParameterJdbcTemplate` giữ các lợi ích đó và cho SQL dễ đọc hơn bằng tham số **có tên**. Spring Data JDBC repository bổ sung tầng thao tác với **aggregate**. Hiểu trách nhiệm từng tầng giúp chọn đúng công cụ và giữ giao dịch, dữ liệu và SQL trong tầm kiểm soát.
