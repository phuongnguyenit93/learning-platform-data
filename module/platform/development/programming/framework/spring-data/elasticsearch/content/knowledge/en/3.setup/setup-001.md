# Creating a Spring Boot Application with Spring Data Elasticsearch

Spring Data Elasticsearch helps Spring Boot applications store and query data on Elasticsearch through familiar Spring Data abstractions. Instead of manually creating an HTTP request for each operation, the application can declare entities using annotations, define repositories, and use methods such as `save`, `findById`, `findAll`, or query methods.

In this lesson, we build a simple product management application. The application connects to an Elasticsearch node, stores product information, searches for products by category, and exposes REST endpoints for testing. Through this example, you will see the components needed in a Spring Boot application using Spring Data Elasticsearch and how they work together.

## 1. Application Architecture

The sample application consists of the following components:

| Component | Role |
|---|---|
| Spring Boot | Starts the application, manages configuration, and auto-configures integration components |
| Spring Data Elasticsearch | Provides mapping, repositories, and APIs for interacting with Elasticsearch |
| Elasticsearch | Stores, indexes, and searches documents |
| Product | Entity representing a product stored in the `products` index |
| ProductRepository | Repository providing read and write operations for products |
| ProductController | REST API that receives requests and calls the repository |

Processing flow when creating a product:

```text
HTTP request
     |
     v
ProductController
     |
     v
ProductRepository
     |
     v
Spring Data Elasticsearch
     |
     v
Elasticsearch Java Client
     |
     v
Elasticsearch cluster
     |
     v
Index: products
```

Spring Data Elasticsearch uses the Elasticsearch Java Client to communicate with the cluster. The repository hides most of the details of sending requests, converting entities, and mapping returned results.

## 2. Preparing the Environment

You will need:

- A JDK compatible with the chosen Spring Boot version. For Spring Boot 3.x projects, Java 17 or higher is the baseline choice.
- Maven or Gradle, or the Maven/Gradle Wrapper generated with the project.
- Docker Desktop or Docker Engine to run Elasticsearch locally; alternatively, an Elasticsearch cluster to which you have been granted access.
- A Java-capable IDE such as IntelliJ IDEA, Eclipse, or Visual Studio Code.

Spring Boot and Spring Data Elasticsearch have corresponding version lines. Let Spring Boot manage dependency versions through its dependency management/BOM. Avoid arbitrarily overriding the `spring-data-elasticsearch` or Elasticsearch Java Client version with one different from the dependency train in use. When choosing an Elasticsearch server version, check the compatibility matrix of Spring Data Elasticsearch and the client.

The code examples in this lesson use common APIs from Spring Boot 3.x and Spring Data Elasticsearch 5.x. If the project uses a different major version, consult the documentation for that exact version before applying specific configurations or APIs.

## 3. Creating a Spring Boot Project

Open Spring Initializr at `https://start.spring.io/` and create a project with the following basic options:

| Property | Suggested Value |
|---|---|
| Project | Maven or Gradle |
| Language | Java |
| Spring Boot | A currently supported version |
| Group | `com.example` |
| Artifact | `catalog` |
| Name | `catalog` |
| Packaging | Jar |
| Java | Version compatible with the selected Spring Boot |

Add two dependencies:

- **Spring Web**: creates REST controllers and handles HTTP requests.
- **Spring Data Elasticsearch**: connects to Elasticsearch, maps entities, and provides repositories.

Download the project, extract it, and open the project directory in your IDE. Spring Initializr generates the application class, build configuration, and Maven/Gradle Wrapper.

### 3.1. Dependencies with Maven

If you created the project with Spring Initializr, the corresponding two dependencies will be in `pom.xml`. The declarations go inside the `dependencies` element:

```xml
<dependencies>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
    </dependency>

    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-data-elasticsearch</artifactId>
    </dependency>

    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-test</artifactId>
        <scope>test</scope>
    </dependency>
</dependencies>
```

Starter dependencies have their versions managed by the Spring Boot parent or BOM. If creating `pom.xml` manually, declare the parent/BOM and Spring Boot Maven Plugin as generated by Initializr; do not copy only the `dependencies` block into a project without dependency management and expect Maven to automatically pick compatible versions.

### 3.2. Dependencies with Gradle

With Gradle, the corresponding dependencies block looks like:

```groovy
dependencies {
    implementation 'org.springframework.boot:spring-boot-starter-web'
    implementation 'org.springframework.boot:spring-boot-starter-data-elasticsearch'
    testImplementation 'org.springframework.boot:spring-boot-starter-test'
}
```

A project generated by Initializr already includes the Spring Boot plugin and appropriate dependency management mechanism. Keep that configuration intact when adding starters.

## 4. Starting Elasticsearch for Development

The Spring Boot application needs a running Elasticsearch endpoint. If you do not already have a cluster, you can run a local single node using Docker Compose.

Create a `compose.yaml` file in the project root directory:

```yaml
services:
  elasticsearch:
    image: docker.elastic.co/elasticsearch/elasticsearch:8.15.0
    container_name: catalog-elasticsearch
    environment:
      - discovery.type=single-node
      - xpack.security.enabled=false
      - ES_JAVA_OPTS=-Xms1g -Xmx1g
    ports:
      - "9200:9200"
    volumes:
      - elasticsearch-data:/usr/share/elasticsearch/data

volumes:
  elasticsearch-data:
```

> **Note:** The configuration above is intended for a local development machine. It disables security and exposes the Elasticsearch port on the host machine to simplify the hands-on exercise. Do not use this configuration for production environments or networks accessible by others. When using a real cluster, enable authentication and TLS, manage credentials via secrets/environment variables, and verify the server certificate.

Start the container:

```bash
docker compose up -d
```

Verify the node is ready by sending a request to `http://localhost:9200`:

```bash
curl http://localhost:9200
```

If the node is running, Elasticsearch returns JSON containing the node name, cluster name, version, and tagline. If the request does not succeed immediately after running Compose, check the container status and logs because Elasticsearch needs time to start up.

The image name and server version in Compose are fixed examples for reproducing the exercise. When changing the Spring Boot/Spring Data Elasticsearch version, choose a compatible Elasticsearch version according to the documentation for the release train in use.

## 5. Configuring the Connection in Spring Boot

Create or update `src/main/resources/application.yml`:

```yaml
spring:
  application:
    name: catalog
  elasticsearch:
    uris: ${ELASTICSEARCH_URIS:http://localhost:9200}
```

The `spring.elasticsearch.uris` property specifies the Elasticsearch address that the application connects to. The syntax `${ELASTICSEARCH_URIS:http://localhost:9200}` means Spring Boot reads the `ELASTICSEARCH_URIS` environment variable; if this variable is not set, it falls back to the default address after the `:` sign.

When running the application on the host machine alongside the Docker Compose setup above, `localhost:9200` is the appropriate address. If the application also runs inside Docker Compose, `localhost` inside the application container points to the application container itself. In that case, use the service name `elasticsearch` as the hostname, for example `http://elasticsearch:9200`, and place both services on the same Docker network.

For secured clusters, configure username/password and TLS according to the Spring Boot version in use. For example, credentials can be supplied via environment variables:

```yaml
spring:
  elasticsearch:
    uris: ${ELASTICSEARCH_URIS}
    username: ${ELASTICSEARCH_USERNAME}
    password: ${ELASTICSEARCH_PASSWORD}
```

This only declares the credentials; an HTTPS endpoint must also be configured to trust the cluster's CA/certificate using the SSL mechanism supported by your Spring Boot version. Do not commit real passwords to source control and do not disable TLS verification to bypass certificate errors.

## 6. Application Entry Point Class

Spring Initializr generates a main class annotated with `@SpringBootApplication`. For example:

```java
package com.example.catalog;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class CatalogApplication {

    public static void main(String[] args) {
        SpringApplication.run(CatalogApplication.class, args);
    }
}
```

`@SpringBootApplication` combines configuration, auto-configuration, and component scanning. Spring Boot detects the Elasticsearch starter on the classpath, reads the `spring.elasticsearch.*` properties, and automatically configures the necessary client components.

Place the `domain`, `repository`, and `controller` packages under `com.example.catalog` so that default component scanning and repository scanning discover them. You only need `@EnableElasticsearchRepositories` when you want to explicitly configure the packages containing repositories or when repositories reside outside the default scan scope.

## 7. Creating the Product Entity

An entity is a Java class representing a document stored in Elasticsearch. Create `src/main/java/com/example/catalog/domain/Product.java`:

```java
package com.example.catalog.domain;

import org.springframework.data.annotation.Id;
import org.springframework.data.elasticsearch.annotations.Document;
import org.springframework.data.elasticsearch.annotations.Field;
import org.springframework.data.elasticsearch.annotations.FieldType;

@Document(indexName = "products", createIndex = true)
public class Product {

    @Id
    private String id;

    @Field(type = FieldType.Text, analyzer = "standard")
    private String name;

    @Field(type = FieldType.Keyword)
    private String category;

    @Field(type = FieldType.Long)
    private Long priceInCents;

    public Product() {
    }

    public Product(String id, String name, String category, Long priceInCents) {
        this.id = id;
        this.name = name;
        this.category = category;
        this.priceInCents = priceInCents;
    }

    public String getId() {
        return id;
    }

    public void setId(String id) {
        this.id = id;
    }

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }

    public String getCategory() {
        return category;
    }

    public void setCategory(String category) {
        this.category = category;
    }

    public Long getPriceInCents() {
        return priceInCents;
    }

    public void setPriceInCents(Long priceInCents) {
        this.priceInCents = priceInCents;
    }
}
```

Key annotations:

- `@Document(indexName = "products")` binds the entity to the `products` index.
- `createIndex = true` instructs Spring Data to create the index and mapping when the index does not yet exist according to the repository initialization mechanism.
- `@Id` marks the property used as the document ID in Elasticsearch.
- `@Field(type = FieldType.Text)` declares a text field analyzed into tokens.
- `@Field(type = FieldType.Keyword)` declares a string field stored as a single value for filtering or exact matching.
- `@Field(type = FieldType.Long)` maps a long integer value.

In this example, the product price is stored as an integer `priceInCents` to avoid binary rounding errors common when using floating-point types for monetary calculations. The application can format the amount at the API or UI layer.

When the `products` index does not exist yet, Spring Data Elasticsearch can create the index and mapping based on the entity metadata. If the index already exists, annotations do not automatically overwrite the existing mapping. When changing a field type or analyzer, plan to create a new index and reindex data rather than just editing annotations and restarting the application.

## 8. Creating ProductRepository

Create `src/main/java/com/example/catalog/repository/ProductRepository.java`:

```java
package com.example.catalog.repository;

import java.util.List;

import org.springframework.data.elasticsearch.repository.ElasticsearchRepository;
import com.example.catalog.domain.Product;

public interface ProductRepository
        extends ElasticsearchRepository<Product, String> {

    List<Product> findByCategory(String category);
}
```

`ElasticsearchRepository<Product, String>` is a repository for the `Product` entity with a `String` ID type. Spring Data provides basic operations such as:

| Method | Purpose |
|---|---|
| `save(product)` | Inserts or updates a document by ID |
| `findById(id)` | Finds a document by ID |
| `findAll()` | Retrieves documents |
| `existsById(id)` | Checks whether a document with the ID exists |
| `deleteById(id)` | Deletes a document by ID |
| `count()` | Counts documents via the repository |

The `findByCategory` method is a query method derived from the method name. Because `category` is mapped as `keyword`, matching by category value fits this data type. If you need full-text search on product names, choose a query such as `match` on the `name` field instead of assuming any string search method performs full-text search.

The repository is automatically discovered by Spring Data through package scanning. There is no need to write an implementation class for standard repository methods.

## 9. Creating the REST Controller

Create `src/main/java/com/example/catalog/controller/ProductController.java`:

```java
package com.example.catalog.controller;

import java.util.List;

import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.DeleteMapping;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

import com.example.catalog.domain.Product;
import com.example.catalog.repository.ProductRepository;

@RestController
@RequestMapping("/products")
public class ProductController {

    private final ProductRepository productRepository;

    public ProductController(ProductRepository productRepository) {
        this.productRepository = productRepository;
    }

    @PostMapping
    public Product create(@RequestBody Product product) {
        return productRepository.save(product);
    }

    @GetMapping("/{id}")
    public ResponseEntity<Product> findById(@PathVariable String id) {
        return ResponseEntity.of(productRepository.findById(id));
    }

    @GetMapping
    public Iterable<Product> findAll() {
        return productRepository.findAll();
    }

    @GetMapping("/by-category/{category}")
    public List<Product> findByCategory(@PathVariable String category) {
        return productRepository.findByCategory(category);
    }

    @DeleteMapping("/{id}")
    public ResponseEntity<Void> deleteById(@PathVariable String id) {
        if (!productRepository.existsById(id)) {
            return ResponseEntity.notFound().build();
        }

        productRepository.deleteById(id);
        return ResponseEntity.noContent().build();
    }
}
```

Constructor injection provides the controller with the Spring-managed repository. The controller only handles HTTP requests and delegates operations to the repository; Spring Data handles converting the entity to a document and sending operations to Elasticsearch.

This is a demonstration controller for verifying integration. In a real application, you should add DTOs for requests/responses, input validation, centralized error handling, and pagination for listing endpoints. Do not return internal entities directly if the API requires a stable data contract.

## 11. Running and Testing the Application

First, start Elasticsearch:

```bash
docker compose up -d
```

Confirm that `http://localhost:9200` returns node information. Then, in the project directory, run Spring Boot.

With Maven on macOS/Linux:

```bash
./mvnw spring-boot:run
```

With Maven on Windows:

```powershell
.\mvnw.cmd spring-boot:run
```

With Gradle, use `./gradlew bootRun` on macOS/Linux or `.\gradlew.bat bootRun` on Windows.

Once the application starts successfully, Spring Boot listens for HTTP on the default port `8080`. Spring Data Elasticsearch connects to the endpoint declared in `application.yml`.

### 11.1. Creating a Product

Send the following request using Postman, curl, or an HTTP request file in your IDE:

```http
POST http://localhost:8080/products
Content-Type: application/json

{
  "id": "p-100",
  "name": "Mechanical Keyboard",
  "category": "keyboard",
  "priceInCents": 1299000
}
```

The controller receives the JSON, converts it to a `Product`, and calls `productRepository.save(product)`. Spring Data converts the entity into a document and writes it to the `products` index.

### 11.2. Reading a Product by ID

```http
GET http://localhost:8080/products/p-100
```

The repository calls Elasticsearch to look up the document by ID. If found, the API returns the product; otherwise, the controller returns HTTP `404 Not Found`.

### 11.3. Listing Products

```http
GET http://localhost:8080/products
```

This endpoint demonstrates `findAll()`. In a real environment, you should use `Pageable` and limit page size to avoid loading too many documents at once.

### 11.4. Searching by Category

```http
GET http://localhost:8080/products/by-category/keyboard
```

Spring Data executes the `findByCategory` query method on the `category` field. Because the field is declared as `keyword`, the value `keyboard` is matched as a category value.

### 11.5. Deleting a Product

```http
DELETE http://localhost:8080/products/p-100
```

If the document exists, the repository deletes the document by ID and the controller returns HTTP `204 No Content`. If the ID does not exist, the controller returns `404 Not Found`.

Elasticsearch is a near-real-time search system. After writing or deleting a document, changes may not appear immediately in search results until the next refresh. Therefore, when testing a write followed immediately by a search, account for the refresh delay rather than immediately concluding that the repository write failed.

## 12. What Does Spring Boot Auto-Configure?

When `spring-boot-starter-data-elasticsearch` is on the classpath and a valid connection configuration is present, Spring Boot can auto-configure the components needed for Spring Data to work with Elasticsearch. Depending on the version, common components include:

- An Elasticsearch Java Client configured from connection properties.
- `ElasticsearchOperations` for high-level entity and query operations.
- Repository infrastructure to create beans for interfaces extending `ElasticsearchRepository`.
- Conversion between Java objects and Elasticsearch documents based on mapping metadata.

Thanks to auto-configuration, a basic application does not need to manually instantiate HTTP clients or write repository implementation classes. When deeper customization is needed, you can declare client configuration beans or use `ElasticsearchOperations` according to the API of your version. Only replace auto-configured beans when there is a specific requirement and you understand the impact on dependent components.

## 13. When Should You Use ElasticsearchOperations?

Repositories are suitable for CRUD operations and common query methods. For more complex queries—such as combining multiple conditions, sorting, aggregations, highlighting, or specialized query configurations—you can use `ElasticsearchOperations` alongside Spring Data Elasticsearch's query APIs.

The example below illustrates only how to inject the abstraction:

```java
import org.springframework.data.elasticsearch.core.ElasticsearchOperations;
import org.springframework.stereotype.Service;

@Service
public class ProductSearchService {

    private final ElasticsearchOperations operations;

    public ProductSearchService(ElasticsearchOperations operations) {
        this.operations = operations;
    }
}
```

From `ElasticsearchOperations`, a service can use APIs such as `save`, `get`, `search`, and `indexOps`. When building queries, specific APIs may vary across release trains; use `NativeQuery` or the query abstractions recommended in the documentation for your version of Spring Data Elasticsearch. Query selection should be based on Elasticsearch semantics, such as `match` for full-text search and `term` for exact values.

## 14. Inspecting Index and Mapping in Elasticsearch

After the application initializes the entity/repository, inspect the indices:

```http
GET http://localhost:9200/_cat/indices?v
```

Inspect the mapping of `products`:

```http
GET http://localhost:9200/products/_mapping
```

The expected mapping shows `name` as `text`, `category` as `keyword`, and `priceInCents` as `long`. Actual mappings also depend on the Spring Data version, entity metadata, and existing index configurations.

Inspect written documents:

```http
GET http://localhost:9200/products/_search
```

These requests help distinguish application-layer errors from index-layer errors. For example, if the API saves successfully but the document does not appear immediately in `_search`, check the refresh and index status. If the mapping differs from expectations, check whether the index already existed beforehand.

## 15. Common Integration Issues

### Cannot Connect to Elasticsearch

Common causes include Elasticsearch not running, an incorrect URI, a wrong port, or an application running inside a container while configured with `localhost` as the hostname. Check the container, logs, and call the Elasticsearch endpoint directly from the application's actual network environment.

### Authentication or TLS Errors

A secured cluster may require username/password and an HTTPS connection with a trusted CA. Invalid credentials cause authentication errors; a missing CA or hostname mismatch with the certificate causes TLS errors. Check the cluster's security configuration and how your Spring Boot version loads SSL trust material.

### Repository Not Found

Ensure the repository interface extends `ElasticsearchRepository` and lies within the package scan scope of the `@SpringBootApplication` class. If the package lies outside that scope, configure `@EnableElasticsearchRepositories` with the appropriate `basePackages`.

### Index or Mapping Not as Expected

`@Document` and `@Field` describe the mapping for an entity, but an existing index is not automatically overwritten every time the application starts. Inspect `_mapping`, determine whether existing data needs to be preserved, and use a migration/reindex process when changing field structures.

### Document Not Found Immediately After Save

Elasticsearch search is near real-time. A successful write does not guarantee the document appears immediately in search results. Check the write operation response, index status, and refresh cycle.

### Mismatched Query Type vs. Field Type

`text` fields are analyzed into tokens, whereas `keyword` fields preserve values as a single term. Use a query appropriate to the mapping. If you need both full-text search and exact filtering/sorting, consider multi-fields instead of forcing a single field to serve every purpose.

## 16. Production Readiness Considerations

The sample application focuses on the basic integration flow. When evolving into a real system, several design decisions need to be added:

- **Connection security:** use HTTPS, authentication, least-privilege permissions, and externalized secrets outside source code.
- **Index management:** create mappings deliberately, version indices, and establish reindex/alias workflows when changing schemas.
- **Error handling:** distinguish validation errors, business errors, network errors, and Elasticsearch errors; return appropriate HTTP statuses.
- **Pagination:** avoid returning an entire index through an unbounded `findAll()` endpoint.
- **Testing:** use a real Elasticsearch instance in integration tests, such as via Testcontainers, to verify mappings and queries rather than only mocking repositories.
- **Observability:** log with context, monitor response times, connection errors, index size, and cluster health.
- **Consistency:** design appropriate retry and idempotency handling when the application encounters timeouts or resends write operations.

Do not treat Elasticsearch as a direct replacement for a relational database. Determine which data needs to be searchable, how data is updated and deleted, and latency and consistency requirements before deciding whether to use Elasticsearch as primary storage or as a search index synchronized from another system.

## 17. End-to-End Implementation Workflow

When creating a Spring Boot application using Spring Data Elasticsearch, the basic implementation sequence is:

1. Create a Spring Boot project with Spring Web and Spring Data Elasticsearch.
2. Choose compatible versions of Spring Boot, Spring Data Elasticsearch, and Elasticsearch server.
3. Start or provision an Elasticsearch cluster.
4. Configure the endpoint and authentication details via externalized configuration.
5. Create an entity with `@Document`, `@Id`, and `@Field` to describe the mapping.
6. Create a repository extending `ElasticsearchRepository`.
7. Create a service/controller to expose save and search operations through the application API.
8. Run the application and verify the connection, index, mapping, and actual documents.
9. Add validation, pagination, security, integration tests, and migration processes before deploying to production.

With this structure, most standard data operations are handled through the repository. When search requirements become more complex, the application can extend with `ElasticsearchOperations` and Query DSL while retaining Spring Boot's dependency management, configuration, and application lifecycle mechanisms.
