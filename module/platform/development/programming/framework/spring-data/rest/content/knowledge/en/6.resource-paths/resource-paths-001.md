# Configuring the Base Path and Distinguishing It from the Servlet Context Path in Spring Data REST

## Objectives

After this lesson, you can configure a common URL prefix for REST resources generated by Spring Data REST; distinguish that prefix from the context path of the entire web application; combine the path segments to determine the actual URL; and handle common issues such as calling an endpoint with a missing or duplicated prefix.

## 1. Two Types of Paths Serving Two Different Purposes

Spring Data REST and the servlet container can both add a path segment to the URL, but each belongs to a different layer:

- **Spring Data REST base path** is a prefix dedicated to the API managed by Spring Data REST. It groups the API root, repository resources, and Spring Data REST endpoints under a common branch.
- **Servlet context path** is the root path of the entire web application in the servlet container. It applies to all requests belonging to the application, including Spring MVC controllers, Spring Data REST, static resources, and other servlets in the same context.

For example, suppose an application has a servlet context path of `/shop` and a Spring Data REST base path of `/api`. The `CustomerRepository` repository has a resource path of `customers`. The full collection URL will be:

```text
http://localhost:8080/shop/api/customers
```

In the URL above:

- `/shop` locates the web application in the servlet container.
- `/api` is the prefix specific to Spring Data REST.
- `/customers` is the resource path of the repository.

If the context path is omitted, the Spring Data REST request takes the form `http://localhost:8080/api/customers`. If the base path is omitted, the repository resource is located at `http://localhost:8080/shop/customers`.

## 2. Configuring the Spring Data REST Base Path with Spring Boot

In a Spring Boot application, use the `spring.data.rest.base-path` property in `application.properties`:

```properties
spring.data.rest.base-path=/api
```

After configuration, Spring Data REST places the API root and repository resources under `/api`. For example:

```java
@RepositoryRestResource(path = "customers")
public interface CustomerRepository
        extends CrudRepository<Customer, Long> {
}
```

The collection resource of this repository is accessed via `/api/customers` when the application runs at the default context root.

You can use a multi-segment prefix, for example:

```properties
spring.data.rest.base-path=/internal/data
```

In that case, the collection resource has the path `/internal/data/customers`. The base path is a global configuration for Spring Data REST; `@RepositoryRestResource(path = "customers")` still specifies the repository's own path segment.

If no base path is configured, Spring Data REST uses its default root path. In that case, repository resources are typically accessed directly by the repository's path, for example `/customers`.

## 3. Configuring the Base Path in Java

If you need to configure it in Java, implement `RepositoryRestConfigurer` and call `setBasePath` on `RepositoryRestConfiguration`:

```java
import org.springframework.context.annotation.Configuration;
import org.springframework.data.rest.core.config.RepositoryRestConfiguration;
import org.springframework.data.rest.webmvc.config.RepositoryRestConfigurer;
import org.springframework.web.servlet.config.annotation.CorsRegistry;

@Configuration
public class SpringDataRestConfig implements RepositoryRestConfigurer {

    @Override
    public void configureRepositoryRestConfiguration(
            RepositoryRestConfiguration config,
            CorsRegistry cors) {

        config.setBasePath("/api");
    }
}
```

The configuration above sets the Spring Data REST base path to `/api`. It serves the same purpose as the Spring Boot property `spring.data.rest.base-path=/api`.

In a Spring Boot application, choose the configuration approach that fits your project's conventions and avoid declaring different base path values in multiple places. If the application has multiple `RepositoryRestConfigurer` implementations, check their order and configuration contents to determine the final applied value.

## 4. Configuring the Servlet Context Path

The servlet context path sets the root path for the entire web application. For Spring Boot running an embedded servlet container, configure it with `server.servlet.context-path`:

```properties
server.servlet.context-path=/shop
```

This property affects every endpoint belonging to the application, not just Spring Data REST. For example, if the application has a Spring MVC controller:

```java
@RestController
class HealthController {

    @GetMapping("/health")
    String health() {
        return "ok";
    }
}
```

then the controller endpoint has the URL `/shop/health` when the context path is `/shop`.

If both are configured simultaneously:

```properties
server.servlet.context-path=/shop
spring.data.rest.base-path=/api
```

then typical URLs are:

| Endpoint | URL path |
| --- | --- |
| Spring Data REST API root | `/shop/api` |
| Customer collection resource | `/shop/api/customers` |
| Spring MVC `/health` controller | `/shop/health` |

This table assumes the servlet is mapped at the default `/` path and the repository has the resource path `customers`.

When deploying the application to an external servlet container, the context root is sometimes determined by the container's deployment configuration or the deployed application name. In that case, you need to check the actual context root of the runtime environment; the Spring Boot property `server.servlet.context-path` is typically used when the application runs standalone with an embedded server.

## 5. Combining Components into the Actual URL

For an application running on the default servlet mapping, you can think of the URL of a Spring Data REST repository resource in the following order:

```text
scheme://host:port
    + servlet context path
    + Spring Data REST base path
    + repository resource path
```

Configuration example:

```properties
server.port=8080
server.servlet.context-path=/shop
spring.data.rest.base-path=/api
```

and repository:

```java
@RepositoryRestResource(path = "orders")
public interface OrderRepository
        extends CrudRepository<Order, Long> {
}
```

The collection resource URL is:

```text
http://localhost:8080/shop/api/orders
```

If you only change `spring.data.rest.base-path` to `/data`, the new URL is `http://localhost:8080/shop/data/orders`. Regular controllers such as `/health` remain under the `/shop` context path and do not automatically move to `/data`.

If the application also configures a separate servlet mapping path—for example, `DispatcherServlet` mapped under a different prefix—that prefix may also appear in the URL. Therefore, when debugging an actual URL, check both the context path and servlet mapping of the running environment in addition to the Spring Data REST base path.

## 6. Distinguishing Base Path from Repository Resource Path

The following three configurations are not interchangeable:

- `spring.data.rest.base-path=/api`: sets the common prefix for Spring Data REST endpoints.
- `@RepositoryRestResource(path = "customers")`: sets the path of a specific repository.
- `server.servlet.context-path=/shop`: sets the context root for the entire web application.

For example, with all three configured, the collection resource is `/shop/api/customers`.

Do not repeat the base path in the repository annotation. If the base path is already set to `/api` and you also declare `@RepositoryRestResource(path = "api/customers")`, the result can become a duplicated path such as `/api/api/customers` (plus the context path if present). Keep the shared prefix in the base path and the repository-specific segment in the repository path.

## 7. How to Verify After Configuration

After changing the configuration, verify using the following steps:

1. Restart the application so the new configuration is loaded.
2. Identify the host, port, and servlet context path of the running environment.
3. Send a request to the API root according to the context path and Spring Data REST base path. In the example above, that is `GET /shop/api`.
4. Read the HAL links in the response to confirm the collection resources published by Spring Data REST.
5. Call the collection resource, for example `GET /shop/api/customers`.
6. Call a controller outside Spring Data REST, for example `GET /shop/health`, to confirm the context path applies to the whole application while the base path affects only the Spring Data REST API.

The HAL API root is helpful because the links in the response show the paths the server is publishing. When a proxy or gateway sits in front of the application, check both the external URL and the URL forwarded to the application.

## 8. Common Issues and How to Handle Them

**Calling the API without the context path**

If `server.servlet.context-path=/shop`, calling `/api/customers` directly on the application typically results in a 404. Call `/shop/api/customers` instead.

**Calling the API without the Spring Data REST base path**

If the base path is `/api`, calling `/shop/customers` will not match the configured Spring Data REST endpoint. Add `/api` after the context path.

**Duplicating the prefix in the repository path**

If the base path is already `/api`, do not add `api` again in `@RepositoryRestResource(path = ...)`. Declare only the repository-specific segment, such as `customers`.

**Confusing base path with context path**

If Spring MVC controllers also need to reside under a prefix, change the context path. If you only want to group Spring Data REST endpoints under a prefix, change the base path. Choosing the wrong property can unexpectedly change the URLs of other controllers.

**External path differs from internal path behind a reverse proxy**

A proxy or API gateway may add, strip, or rewrite prefixes before forwarding requests to the application. Cross-check the proxy's rewrite rules, forwarded headers, and the actual URL received by the application. Do not add a prefix a second time if the proxy already adds that prefix.

## Summary

- `spring.data.rest.base-path` sets the common prefix for the Spring Data REST API.
- `server.servlet.context-path` sets the context root for the entire web application.
- `@RepositoryRestResource(path = "...")` sets only the path of a single repository.
- When the context path is `/shop`, the base path is `/api`, and the repository path is `customers`, the collection URL is `/shop/api/customers`.
- Inspect the HAL API root and a regular controller's URL to verify which prefixes are currently applied.
