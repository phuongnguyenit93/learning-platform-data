# Hiding an Entire Repository with `exported = false`

## Objective

Spring Data REST can automatically generate REST resources for Spring Data repositories detected in an application. When a repository is strictly for internal processing, set `exported = false` on the repository interface itself so Spring Data REST does not expose its endpoints.

The annotation to use is `@RepositoryRestResource` in the `org.springframework.data.rest.core.annotation` package.

## Configuration

Example with Spring Data JPA:

    import org.springframework.data.jpa.repository.JpaRepository;
    import org.springframework.data.rest.core.annotation.RepositoryRestResource;

    @RepositoryRestResource(exported = false)
    public interface AuditRecordRepository
            extends JpaRepository<AuditRecord, Long> {
    }

Place the annotation on the repository interface detected by Spring Data REST. If the application uses MongoDB, JDBC, Redis, or another Spring Data module, the approach is the same: keep the corresponding repository type and add `@RepositoryRestResource(exported = false)`.

`exported` defaults to `true` when a repository is exposed by Spring Data REST. Setting it to `false` disables exporting that repository. If you need to hide multiple repositories, add this annotation to each interface you want to hide.

## What Changes

When a repository is marked `exported = false`, Spring Data REST does not create REST resources based on that repository. Specifically:

- No collection endpoint for the repository.
- No item endpoint by ID through that repository.
- The repository's query methods are not exposed as REST search resources.
- The repository does not appear as a link in the Spring Data REST API root.

For example, if the repository was previously accessed via `/api/audit-records`, after disabling export, requests to that path will no longer be served by Spring Data REST. The `/api/` API root will also no longer include a link to this repository. Actual paths depend on `spring.data.rest.base-path` and the repository's `path` setting.

Disabling export only affects REST endpoints generated by Spring Data REST. The repository remains a Spring bean, and the application can still inject it into services or components to read and write data:

    @Service
    public class AuditRecordService {
        private final AuditRecordRepository repository;

        public AuditRecordService(AuditRecordRepository repository) {
            this.repository = repository;
        }

        public List<AuditRecord> findAll() {
            return repository.findAll();
        }
    }

Database data is not deleted, and repository operations in Java code continue to work normally.

## Distinguishing Hiding a Repository from Hiding a Method

- Hide the entire repository: use `@RepositoryRestResource(exported = false)` on the interface. This is the approach for this section.
- Hide only a single query method in an otherwise exported repository: use `@RestResource(exported = false)` on that method.

Example hiding only a method that finds a user by email:

    import org.springframework.data.rest.core.annotation.RestResource;

    @RestResource(exported = false)
    Optional<User> findByEmail(String email);

Do not use method-level hiding if the requirement is to stop exposing the entire repository; place `exported = false` at the interface level.

## Verifying Results

After restarting the application, check the API root and the repository's endpoint. For example, if the base path is `/api` and the repository has path `audit-records`:

    GET /api/
    GET /api/audit-records

The API root should no longer contain a link to the hidden repository. Requests to the repository's collection endpoint should return a resource-not-found status (typically `404 Not Found`). Use your application's actual path and link relation when writing integration tests.

## Security Notes

`exported = false` controls Spring Data REST's automatic repository exposure; it is not an authorization mechanism. If a custom `@RestController`, GraphQL endpoint, or other custom API still calls the repository and returns data externally, that endpoint remains accessible. Configure Spring Security and enforce access checks on the corresponding endpoints or services whenever data protection is needed.

## When the Configuration Does Not Take Effect

1. Verify the import is `org.springframework.data.rest.core.annotation.RepositoryRestResource`.
2. Ensure the annotation is placed on the actual repository interface detected by Spring Data REST, not solely on a parent interface that is not registered as a repository.
3. Check `spring.data.rest.base-path` and `path` so you call the right URL during verification.
4. Check whether any custom controller or endpoint is exposing the same data; `exported = false` only disables endpoints generated by Spring Data REST from the repository.
