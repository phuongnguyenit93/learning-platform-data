# Creating a Sample Application with Spring Data JPA, H2, and Seed Data

This hands-on tutorial creates a small Spring Boot application for managing products. Spring Data JPA maps Java objects to database tables and provides repositories; H2 is a lightweight in-memory relational database; sample data is automatically loaded on application startup. Since this module focuses on Spring Data REST, the repository is also exposed as a REST API without manually writing a CRUD controller.

After this lesson, you will be able to create an entity, declare a repository, configure H2, load initial seed data, verify data with tests, and call the REST endpoints generated by Spring Data REST.

## 1. Prerequisites

- JDK 17 or later.
- Maven 3.6.3 or later, or the Maven Wrapper generated by Spring Initializr.
- A Java-capable IDE such as IntelliJ IDEA, Eclipse, or VS Code.
- Basic knowledge of Java, annotations, and HTTP.

The example uses Spring Boot 3.5.0 and Java 17. When creating a new project, you can pick the latest patch release in the Spring Boot 3.5.x line compatible with your environment. Spring Boot 3 uses the Jakarta namespace, so JPA imports in the example start with `jakarta.persistence`.

### 3.1. Application Entry Point

Create `DemoApplication.java`:

~~~java
package com.example.demo;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class DemoApplication {

    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}
~~~

`@SpringBootApplication` combines configuration, auto-configuration, and component scanning. Because the remaining classes are inside `com.example.demo` or subpackages, Spring Boot can discover them automatically.

### 3.2. Creating the `Product` Entity

An entity is a Java class representing an item persisted in the database. Create `Product.java`:

~~~java
package com.example.demo;

import jakarta.persistence.Column;
import jakarta.persistence.Entity;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;
import jakarta.persistence.Table;

import java.math.BigDecimal;

@Entity
@Table(name = "products")
public class Product {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false, length = 120)
    private String name;

    @Column(nullable = false, precision = 12, scale = 2)
    private BigDecimal price;

    @Column(nullable = false)
    private boolean active;

    protected Product() {
        // JPA requires a no-arg constructor.
    }

    public Product(String name, BigDecimal price, boolean active) {
        this.name = name;
        this.price = price;
        this.active = active;
    }

    public Long getId() {
        return id;
    }

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }

    public BigDecimal getPrice() {
        return price;
    }

    public void setPrice(BigDecimal price) {
        this.price = price;
    }

    public boolean isActive() {
        return active;
    }

    public void setActive(boolean active) {
        this.active = active;
    }
}
~~~

Explanation of annotations:

- `@Entity` marks `Product` as a JPA-managed entity.
- `@Table(name = "products")` specifies the table name. If omitted, Hibernate derives the table name from the entity using its naming strategy.
- `@Id` designates the primary key.
- `@GeneratedValue(strategy = GenerationType.IDENTITY)` delegates primary key generation to the database's identity mechanism.
- `@Column` declares column constraints. For `price`, `precision` is the total number of digits and `scale` is the number of digits after the decimal point.

Use `BigDecimal` for monetary values instead of `float` or `double` to avoid floating-point rounding errors. A no-arg constructor is required for JPA; `protected` visibility is sufficient in this case.

### 3.3. Creating the Repository

The repository is the data-access layer. Create `ProductRepository.java`:

~~~java
package com.example.demo;

import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.data.repository.query.Param;
import org.springframework.data.rest.core.annotation.RepositoryRestResource;
import org.springframework.data.rest.core.annotation.RestResource;

import java.util.List;
import java.util.Optional;

@RepositoryRestResource(path = "products")
public interface ProductRepository extends JpaRepository<Product, Long> {

    @RestResource(path = "active", rel = "active")
    List<Product> findByActiveTrue();

    @RestResource(path = "by-name", rel = "by-name")
    Optional<Product> findByNameIgnoreCase(@Param("name") String name);
}
~~~

`JpaRepository<Product, Long>` provides built-in operations such as `save`, `saveAll`, `findById`, `findAll`, `count`, and `deleteById`. The first type argument is the entity type; the second is the primary key type.

Spring Data JPA generates the repository implementation at runtime. Query methods can be derived from method names: `findByActiveTrue` finds products where `active` is `true`; `findByNameIgnoreCase` searches by name case-insensitively.

`@RepositoryRestResource` sets the collection path to `products`. `@RestResource` sets the path and link relation name for the two custom queries. `@Param` specifies the parameter name that appears in the URL. With Spring Data REST on the classpath, public repositories are automatically exported as endpoints; you do not need to write a controller just for basic CRUD.

### 3.4. Configuring H2 and JPA

Create `src/main/resources/application.properties`:

~~~properties
spring.application.name=spring-data-jpa-h2-demo

spring.datasource.url=jdbc:h2:mem:catalogdb
spring.datasource.driver-class-name=org.h2.Driver
spring.datasource.username=sa
spring.datasource.password=

spring.jpa.hibernate.ddl-auto=create-drop
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true
spring.jpa.open-in-view=false

spring.h2.console.enabled=true
spring.h2.console.path=/h2-console

spring.data.rest.base-path=/api
~~~

Configuration details:

- `jdbc:h2:mem:catalogdb` creates an in-memory database named `catalogdb`. The database lives for the lifecycle of the application.
- Username `sa` and an empty password are the default credentials for this H2 example.
- `ddl-auto=create-drop` tells Hibernate to create the schema on startup and drop it when the context closes. This is suitable for demos, not for persisting long-term data.
- `show-sql` and `format_sql` help inspect the SQL statements Hibernate executes.
- `open-in-view=false` disables Open Session in View to avoid accidentally triggering lazy-loading queries while rendering responses.
- `spring.h2.console.enabled` enables the H2 web admin UI; `path` sets its URL.
- `spring.data.rest.base-path=/api` sets the prefix for Spring Data REST endpoints.

Because it uses in-memory H2, data is lost when the application stops and recreated on the next run. If you need data to persist across restarts, switch to a durable database and configure proper migrations.

### 3.5. Loading Initial Seed Data

There are several ways to seed sample data. This lesson uses `CommandLineRunner` to invoke the repository after Spring initializes the context and Hibernate creates the schema. This avoids execution-order issues between Hibernate-generated schemas and a `data.sql` script.

Create `ProductDataInitializer.java`:

~~~java
package com.example.demo;

import org.springframework.boot.CommandLineRunner;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

import java.math.BigDecimal;
import java.util.List;

@Configuration
public class ProductDataInitializer {

    @Bean
    CommandLineRunner seedProducts(ProductRepository repository) {
        return args -> {
            if (repository.count() == 0) {
                repository.saveAll(List.of(
                    new Product("Mechanical Keyboard", new BigDecimal("1290000.00"), true),
                    new Product("Wireless Mouse", new BigDecimal("450000.00"), true),
                    new Product("24-inch Monitor", new BigDecimal("3290000.00"), true)
                ));
            }
        };
    }
}
~~~

Spring Boot invokes `CommandLineRunner` beans after the `ApplicationContext` is initialized and before application startup completes. When the runner executes, the repository is ready to save data.

The `repository.count() == 0` check prevents re-inserting all sample data if the database already contains records. With in-memory H2 and `create-drop`, the database is typically empty on each fresh startup, so the three sample products are inserted again. With a persistent database, this check is only a simple mechanism for demo data; complex seed data should use migrations or controlled seeding.

You do not need to create the table manually with SQL in this example. Hibernate reads the mapping from `Product` and creates the `products` table according to `ddl-auto`.

## 4. Testing the Seed Data

Create `ProductDataInitializerTest.java` under `src/test/java/com/example/demo`:

~~~java
package com.example.demo;

import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.context.SpringBootTest;

import static org.assertj.core.api.Assertions.assertThat;

@SpringBootTest
class ProductDataInitializerTest {

    @Autowired
    private ProductRepository repository;

    @Test
    void seededProductsAreAvailableAfterStartup() {
        assertThat(repository.findAll()).hasSizeGreaterThanOrEqualTo(3);
        assertThat(repository.findByNameIgnoreCase("Wireless Mouse")).isPresent();
    }
}
~~~

`@SpringBootTest` initializes the Spring `ApplicationContext` for the test. Since `CommandLineRunner` executes during context startup, the test can verify that the seed data was loaded. AssertJ provides readable assertions: checking that at least three records exist and that a product named `Wireless Mouse` is present.

Run the test with the Maven Wrapper:

~~~bash
./mvnw test
~~~

On Windows PowerShell, run:

~~~powershell
.\mvnw.cmd test
~~~

The test passes when Maven finishes with `BUILD SUCCESS` and zero test failures. Across test runs, the in-memory H2 database for the context is recreated for each test lifecycle; the runner seeds data for that context.

## 5. Running the Application and Calling the REST API

Start the application:

~~~bash
./mvnw spring-boot:run
~~~

On Windows PowerShell:

~~~powershell
.\mvnw.cmd spring-boot:run
~~~

Once the application starts, Spring Data REST provides the following endpoints:

| HTTP method | Endpoint | Meaning |
|---|---|---|
| `GET` | `/api/products` | Retrieve the list of products |
| `GET` | `/api/products/{id}` | Retrieve a single product by ID |
| `POST` | `/api/products` | Create a product |
| `PUT` | `/api/products/{id}` | Replace product information |
| `PATCH` | `/api/products/{id}` | Partially update a product |
| `DELETE` | `/api/products/{id}` | Delete a product |
| `GET` | `/api/products/search/active` | Find active products |
| `GET` | `/api/products/search/by-name?name=Wireless%20Mouse` | Find by name, case-insensitively |

Try fetching the list:

~~~bash
curl -i http://localhost:8080/api/products
~~~

Spring Data REST returns HAL JSON by default. The response typically includes `_embedded` containing the list of resources, `_links` containing navigation links, and `page` containing pagination info. The collection key inside `_embedded` is based on the resource name derived by Spring Data REST.

Try the endpoint for finding active products:

~~~bash
curl -i http://localhost:8080/api/products/search/active
~~~

Try searching by name:

~~~bash
curl -i "http://localhost:8080/api/products/search/by-name?name=Wireless%20Mouse"
~~~

Create a new product:

~~~bash
curl -i -X POST http://localhost:8080/api/products   -H "Content-Type: application/json"   -d '{"name":"Headphones","price":850000,"active":true}'
~~~

If running in Windows PowerShell, call `curl.exe` to avoid PowerShell's `Invoke-WebRequest` alias. You can also use Postman or an IDE REST client with the same URL, method, and JSON body.

Spring Data REST converts the JSON into an entity and invokes the corresponding repository method. When POST succeeds, the server typically returns HTTP `201 Created` and a `Location` header pointing to the newly created resource. The actual ID is generated by H2, so do not assume a fixed value.

The H2 Console should only be enabled in learning or development environments. Never expose the console publicly in production.

## 7. Application Runtime Flow

When running the application, the components coordinate in the following general order:

1. Spring Boot reads `application.properties` and configures the H2 datasource.
2. Hibernate scans the `Product` entity and creates the `products` table according to `ddl-auto`.
3. Spring Data JPA generates the implementation for `ProductRepository`.
4. Spring Data REST detects the exported repository and registers endpoints under `/api`.
5. Spring initializes the `ApplicationContext` and runs `ProductDataInitializer`.
6. The `CommandLineRunner` checks the record count; if the database is empty, `saveAll` persists the three sample products.
7. The application is ready to accept HTTP requests. Spring Data REST forwards requests to the repository and returns results as HAL JSON.

The key takeaway is that the repository serves as the central hub: the data initializer uses it to persist records, and Spring Data REST uses the same repository to serve HTTP traffic. There is no need to create a separate DAO layer or write manual CRUD SQL statements.

## 8. Common Errors and Troubleshooting

**`ProductRepository` not found or repository bean could not be created**

Verify that the repository extends `JpaRepository<Product, Long>`, has the `spring-boot-starter-data-jpa` dependency, and resides in a package covered by Spring Boot component scanning. The package of `DemoApplication` should be the root package containing the remaining classes.

**Error `Not a managed type: Product`**

Verify that `Product` has the `@Entity` annotation, imports `jakarta.persistence.Entity`, and sits within the scanned package scope. Do not use `javax.persistence` with Spring Boot 3.

**Cannot connect to H2 or driver not found**

Check the `com.h2database:h2` dependency, the `jdbc:h2:mem:catalogdb` URL, and the username configuration. Ensure the application is running with the correct `application.properties`.

**Table `products` does not exist when loading seed data**

This example uses `CommandLineRunner`, so data is saved after Hibernate creates the schema. If switching to `data.sql`, watch out for initialization ordering; with Spring Boot you can set `spring.jpa.defer-datasource-initialization=true` to defer SQL script execution until after Hibernate creates the schema.

**Endpoints return 404**

Verify that `spring-boot-starter-data-rest` is added, the repository is exported, the base path is `/api`, and the collection path is `/products`. The full collection URL in this example is `/api/products`.

**Data disappears after restart**

This is expected behavior with `jdbc:h2:mem` and `ddl-auto=create-drop`. Use a persistent database if data must survive restarts.

**Port 8080 is already in use**

Stop the process occupying the port or set `server.port` to another port in `application.properties`, such as `server.port=8081`. When changing the port, update your API and H2 Console URLs accordingly.

## 9. Considerations for Production Projects

The configuration in this lesson prioritizes simplicity for learning and experimentation. For real deployments:

- Do not use `create-drop` if data must be preserved. Use Flyway or Liquibase for versioned schema migrations.
- Do not use in-memory H2 as production storage. Choose a suitable database such as PostgreSQL or MySQL and supply connection details via environment variables or a secret manager.
- Never enable the H2 Console in production.
- Add Spring Security, authorization, and authentication before exposing write endpoints.
- Add validation for input data, such as non-empty names and non-negative prices.
- Consider DTOs, projections, or repository exposure settings to control what data is exposed via the API. Extending `JpaRepository` does not mean every method or field should be public to end users.
- For seed data with complex relationships or strict ordering requirements, manage it via migrations rather than just checking `count` and calling `saveAll`.

## 10. Summary

The sample application combines three core pieces: Spring Data JPA manages entities and repositories, H2 provides a lightweight database for development, and `CommandLineRunner` loads initial data once the schema is ready. Spring Data REST exposes the repository as a REST API, allowing you to test CRUD and queries without writing manual controllers.

Once running successfully, you can open `/api/products` to inspect the data, test the `search` endpoints for queries, POST a new product, and open the H2 Console to view the `PRODUCTS` table. This forms the foundation for learning entity relationships, pagination, sorting, validation, security, and schema management with migrations.
