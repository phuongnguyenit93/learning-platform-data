# Ánh xạ kết quả native query về Entity

JPA thường dùng JPQL để truy vấn theo entity và thuộc tính Java. Tuy nhiên, có những tình huống cần viết SQL trực tiếp: dùng cú pháp riêng của database, CTE, window function, hint, truy vấn tối ưu đã được kiểm chứng hoặc tận dụng một view có sẵn. Khi đó, JPA cho phép thực thi native SQL và ánh xạ kết quả về entity.

Ánh xạ native query về entity có nghĩa mỗi dòng kết quả SQL được chuyển thành một instance của entity theo metadata JPA. Nếu truy vấn được thực hiện trong persistence context đang hoạt động, entity trả về được quản lý theo quy tắc identity của JPA. Vì vậy, native query trả entity có thể tham gia dirty checking và các thao tác persistence tiếp theo.

Điều kiện quan trọng là result set phải cung cấp đủ cột để provider dựng trạng thái entity theo mapping. Nếu chỉ SELECT một vài cột rồi cố ánh xạ thành entity đầy đủ, kết quả có thể sai hoặc không xác định theo đặc tả. Với dữ liệu một phần, hãy dùng DTO hoặc projection.

**Điều kiện của ví dụ:** các đoạn mã dùng Spring Boot 3.x, Java 17 trở lên, Jakarta Persistence và Spring Data JPA. Ứng dụng cần dependency **spring-boot-starter-data-jpa**, JDBC driver, DataSource và schema phù hợp. Các đoạn mã là những phần của ứng dụng Spring Boot, không phải chương trình độc lập có thể chạy chỉ bằng **javac**.

## 1. Native SQL và JPQL khác nhau ở đâu?

| Đặc điểm | JPQL | Native SQL |
|---|---|---|
| Đối tượng truy vấn | Entity và thuộc tính Java | Bảng, cột, view và cú pháp SQL |
| Tính portable | Tương đối cao giữa các JPA provider/database | Phụ thuộc database và dialect nhiều hơn |
| Mapping kết quả | Entity, scalar hoặc DTO theo JPQL | Entity, scalar, DTO hoặc result-set mapping |
| Tên dùng trong truy vấn | Entity name, field/property | Tên bảng/cột vật lý |
| Tính năng database riêng | Hạn chế theo ngôn ngữ JPQL/provider extension | Có thể dùng CTE, window function, hint và cú pháp riêng |

Ví dụ JPQL:

~~~java
select b
from Book b
where b.status = :status
~~~

Ví dụ native SQL:

~~~sql
SELECT b.id, b.title, b.status
FROM books b
WHERE b.status = ?;
~~~

JPQL dùng entity Book và thuộc tính status. Native SQL dùng bảng books và cột vật lý tương ứng.

Chọn native query khi lợi ích của SQL trực tiếp là rõ ràng. Nếu JPQL diễn đạt được truy vấn và hiệu năng đã đáp ứng, JPQL thường dễ bảo trì và ít phụ thuộc database hơn.

## 2. Entity mẫu để ánh xạ kết quả

Ta dùng entity Book đơn giản:

~~~java
package com.example.catalog.domain;

import jakarta.persistence.Column;
import jakarta.persistence.Entity;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;
import jakarta.persistence.Table;
import jakarta.persistence.Version;

import java.math.BigDecimal;

@Entity
@Table(name = "books")
public class Book {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(name = "title", nullable = false, length = 150)
    private String title;

    @Column(name = "isbn", nullable = false, length = 20)
    private String isbn;

    @Column(name = "price", nullable = false, precision = 12, scale = 2)
    private BigDecimal price;

    @Version
    @Column(name = "version")
    private Long version;

    protected Book() {
    }

    public Long getId() {
        return id;
    }

    public String getTitle() {
        return title;
    }

    public String getIsbn() {
        return isbn;
    }

    public BigDecimal getPrice() {
        return price;
    }

    public Long getVersion() {
        return version;
    }
}
~~~

Giả sử database có bảng:

~~~sql
CREATE TABLE books (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    title VARCHAR(150) NOT NULL,
    isbn VARCHAR(20) NOT NULL,
    price NUMERIC(12, 2) NOT NULL,
    version BIGINT
);
~~~

Tên bảng và cột trong native SQL phải khớp schema thực tế. Nếu mapping dùng **@Column(name = "book_title")**, câu SQL cần trả về cột hoặc alias tương ứng với mapping đó.

## 3. Cách 1: EntityManager.createNativeQuery(sql, Entity.class)

Jakarta Persistence cho phép truyền entity class làm kiểu kết quả:

~~~java
List<Book> books = entityManager
    .createNativeQuery(
        "SELECT id, title, isbn, price, version FROM books WHERE price >= ?",
        Book.class
    )
    .setParameter(1, minimumPrice)
    .getResultList();
~~~

Tham số thứ hai là Book.class, nên JPA provider ánh xạ từng dòng result set thành entity Book.

Có thể lấy một kết quả:

~~~java
Book book = (Book) entityManager
    .createNativeQuery(
        "SELECT id, title, isbn, price, version FROM books WHERE id = ?",
        Book.class
    )
    .setParameter(1, id)
    .getSingleResult();
~~~

Nếu không có dòng phù hợp, getSingleResult ném **NoResultException**. Nếu có nhiều hơn một dòng, nó ném **NonUniqueResultException**. Nếu muốn xử lý không có kết quả theo kiểu collection, dùng getResultList và kiểm tra danh sách rỗng.

### Điều kiện của result set

Với entity mapping, truy vấn cần trả về đủ các cột được ánh xạ cho entity, bao gồm khóa chính và các cột cần thiết cho trạng thái entity. Nếu entity có quan hệ, provider có thể cần cả cột khóa ngoại tương ứng. Với entity dùng secondary table, inheritance hoặc mapping phức tạp, yêu cầu result set còn phụ thuộc mapping đó.

Đặc tả JPA cảnh báo rằng hành vi không được xác định nếu native query không trả về đủ dữ liệu cột cần thiết cho entity mapping. Không nên chỉ SELECT id và title rồi yêu cầu provider dựng một Book đầy đủ nếu entity còn isbn, price và version.

Nếu chỉ cần một vài cột, hãy dùng scalar hoặc DTO projection ở phần sau.

## 4. Cách 2: Spring Data JPA repository trả về Entity

Với Spring Data JPA, có thể khai báo native query ngay trên repository bằng **@Query(nativeQuery = true)**:

~~~java
package com.example.catalog.repository;

import com.example.catalog.domain.Book;
import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.data.jpa.repository.Query;
import org.springframework.data.repository.query.Param;

import java.math.BigDecimal;
import java.util.List;
import java.util.Optional;

public interface BookRepository extends JpaRepository<Book, Long> {

    @Query(
        value = """
            SELECT b.id, b.title, b.isbn, b.price, b.version
            FROM books b
            WHERE b.price >= ?1
            ORDER BY b.price DESC
            """,
        nativeQuery = true
    )
    List<Book> findBooksWithMinimumPrice(BigDecimal minimumPrice);

    @Query(
        value = """
            SELECT b.id, b.title, b.isbn, b.price, b.version
            FROM books b
            WHERE b.isbn = :isbn
            """,
        nativeQuery = true
    )
    Optional<Book> findNativeByIsbn(@Param("isbn") String isbn);
}
~~~

Khi method khai báo kiểu trả về Book hoặc List<Book>, Spring Data JPA yêu cầu provider ánh xạ result set thành entity Book.

Lưu ý:

- **nativeQuery = true** báo cho Spring Data đây là SQL thay vì JPQL.
- SQL phải dùng đúng tên bảng/cột của database.
- Có thể dùng tham số vị trí như **?1** hoặc named parameter với **@Param**, tùy hỗ trợ của Spring Data/provider và phiên bản đang dùng.
- Kết quả entity cần đủ cột theo mapping.
- Truy vấn native không tự trở thành read-only chỉ vì nó là SELECT; transaction và flush mode vẫn cần được cân nhắc.

## 5. Tên cột, alias và quy tắc ánh xạ

Cách ánh xạ đơn giản nhất là trả về các cột có tên tương ứng với tên cột vật lý trong entity mapping:

~~~sql
SELECT
    b.id,
    b.title,
    b.isbn,
    b.price,
    b.version
FROM books b
~~~

Khi câu SQL có alias, phép ánh xạ có thể cần cấu hình rõ. Ví dụ:

~~~sql
SELECT
    b.id AS book_id,
    b.title AS book_title,
    b.isbn AS book_isbn,
    b.price AS book_price,
    b.version AS book_version
FROM books b
~~~

Các alias book_id, book_title không tự động tương đương với id, title trong mọi mapping entity. Với alias tùy chỉnh, nên khai báo **@SqlResultSetMapping** và **@FieldResult** để chỉ rõ cột kết quả ứng với thuộc tính entity nào.

Một số database tự chuyển chữ hoa/thường của alias không được quote. Nếu mapping phụ thuộc alias có chữ hoa hoặc ký tự đặc biệt, hãy dùng alias đơn giản, ổn định và kiểm thử trên database đích. Tránh alias trùng nhau khi join nhiều bảng.

## 6. Cách 3: @SqlResultSetMapping và @EntityResult

**@SqlResultSetMapping** là cơ chế chuẩn của JPA để mô tả cách ánh xạ result set. **@EntityResult** chỉ định entity đích; **@FieldResult** nối tên cột trả về với thuộc tính entity.

Ví dụ khai báo mapping trên Book:

~~~java
@Entity
@Table(name = "books")
@SqlResultSetMapping(
    name = "BookEntityMapping",
    entities = @EntityResult(
        entityClass = Book.class,
        fields = {
            @FieldResult(name = "id", column = "book_id"),
            @FieldResult(name = "title", column = "book_title"),
            @FieldResult(name = "isbn", column = "book_isbn"),
            @FieldResult(name = "price", column = "book_price"),
            @FieldResult(name = "version", column = "book_version")
        }
    )
)
public class Book {
    // Các field và mapping JPA như ví dụ ở trên.
}
~~~

Thực thi:

~~~java
List<Book> books = entityManager
    .createNativeQuery(
        """
        SELECT
            b.id AS book_id,
            b.title AS book_title,
            b.isbn AS book_isbn,
            b.price AS book_price,
            b.version AS book_version
        FROM books b
        WHERE b.price >= ?
        """,
        "BookEntityMapping"
    )
    .setParameter(1, minimumPrice)
    .getResultList();
~~~

Trong **@FieldResult**:

- **name** là tên thuộc tính persistent của entity.
- **column** là tên cột hoặc alias trong result set.

Cách này hữu ích khi SQL join nhiều bảng, có alias riêng hoặc tên cột trả về không giống tên mapping mặc định.

Nếu entity có quan hệ, mapping cần cung cấp dữ liệu cần thiết cho association theo quy tắc JPA. Với mapping phức tạp như embedded ID, inheritance, secondary table hoặc association nhiều tầng, hãy kiểm tra đặc tả và khả năng provider; không giả định chỉ thêm một alias là đủ.

## 7. Native query trả về Entity có phải entity managed không?

Khi native query dùng entity result mapping trong một persistence context đang hoạt động, kết quả được xử lý như entity theo quy tắc quản lý và identity của JPA. Nếu entity được tìm thấy trong persistence context hiện tại, JPA duy trì identity nhất quán thay vì tạo hai managed instance khác nhau cho cùng một entity key.

Ví dụ:

~~~java
@Transactional(readOnly = true)
public Book findBook(Long id) {
    return bookRepository.findNativeById(id).orElseThrow();
}
~~~

Nếu entity được trả về và đang managed trong transaction, nó có thể được dirty checking theo dõi khi thay đổi trong transaction ghi phù hợp.

Tuy nhiên, đừng xem native SELECT như lệnh refresh. Nếu cùng entity đã được managed trong persistence context, không nên giả định query sẽ ghi đè mọi field trong object hiện có bằng giá trị mới nhất từ database. Nếu cần nạp lại trạng thái, dùng refresh phù hợp hoặc tạo persistence context mới theo yêu cầu.

Native SELECT cũng không tự động gọi persist hay merge. Nó chỉ truy vấn và ánh xạ kết quả.

## 8. Khi nào không nên ánh xạ native query về Entity?

Không nên ánh xạ về entity khi result set chỉ chứa một phần dữ liệu hoặc kết quả là phép tổng hợp.

Ví dụ:

~~~sql
SELECT status, COUNT(*) AS order_count
FROM purchase_orders
GROUP BY status
~~~

Kết quả này không phải một PurchaseOrder đầy đủ. Không nên khai báo method trả về **PurchaseOrder**. Hãy dùng DTO, scalar mapping hoặc interface projection.

Các trường hợp phù hợp với DTO:

- Báo cáo tổng hợp.
- Kết quả join nhiều bảng nhưng chỉ cần một số cột.
- Màn hình danh sách cần ID, tên và trạng thái.
- Truy vấn dùng CTE/window function trả về cấu trúc không tương ứng entity.
- Kết quả có cột tính toán hoặc alias tùy chỉnh.

Entity biểu diễn trạng thái persistent; DTO biểu diễn dữ liệu phục vụ một use case. Phân biệt hai loại giúp tránh entity giả hoặc object thiếu field nhưng bị hiểu là trạng thái đầy đủ.

## 9. Ánh xạ scalar bằng @ColumnResult

Nếu native query trả về một số cột đơn giản, JPA có thể ánh xạ scalar bằng **@ColumnResult**.

Ví dụ:

~~~java
@SqlResultSetMapping(
    name = "BookPriceMapping",
    columns = {
        @ColumnResult(name = "book_id", type = Long.class),
        @ColumnResult(name = "book_price", type = BigDecimal.class)
    }
)
~~~

Thực thi:

~~~java
List<Object[]> rows = entityManager
    .createNativeQuery(
        """
        SELECT id AS book_id, price AS book_price
        FROM books
        WHERE price >= ?
        """,
        "BookPriceMapping"
    )
    .setParameter(1, minimumPrice)
    .getResultList();
~~~

Mỗi dòng chứa các giá trị scalar theo thứ tự khai báo trong mapping. Với nhiều cột, cần ép kiểu cẩn thận. Nếu muốn kết quả có tên field rõ ràng, DTO constructor mapping thường dễ bảo trì hơn.

## 10. Ánh xạ native query về DTO bằng @ConstructorResult

JPA hỗ trợ **@ConstructorResult** để gọi constructor của DTO với các cột trong result set.

DTO:

~~~java
package com.example.catalog.dto;

import java.math.BigDecimal;

public record BookPriceView(
    Long id,
    String title,
    BigDecimal price
) {
}
~~~

Mapping:

~~~java
@SqlResultSetMapping(
    name = "BookPriceViewMapping",
    classes = @ConstructorResult(
        targetClass = BookPriceView.class,
        columns = {
            @ColumnResult(name = "book_id", type = Long.class),
            @ColumnResult(name = "book_title", type = String.class),
            @ColumnResult(name = "book_price", type = BigDecimal.class)
        }
    )
)
~~~

Thực thi:

~~~java
List<BookPriceView> views = entityManager
    .createNativeQuery(
        """
        SELECT
            id AS book_id,
            title AS book_title,
            price AS book_price
        FROM books
        WHERE price >= ?
        ORDER BY price DESC
        """,
        "BookPriceViewMapping"
    )
    .setParameter(1, minimumPrice)
    .getResultList();
~~~

Các cột trong **@ConstructorResult** được truyền vào constructor theo đúng thứ tự khai báo. Kiểu dữ liệu phải tương thích với kiểu tham số của constructor. Dùng record giúp DTO bất biến và giảm boilerplate.

Với Spring Data JPA, native query có thể trả về interface projection hoặc DTO theo khả năng của phiên bản và cách khai báo. Khi cần mapping phức tạp, **@SqlResultSetMapping** là lựa chọn chuẩn, tường minh và ít phụ thuộc cơ chế suy luận của framework.

## 11. Native query có JOIN nhiều bảng nhưng chỉ trả về một Entity

Có thể join bảng khác để lọc hoặc sắp xếp, nhưng vẫn chỉ ánh xạ cột entity chính:

~~~sql
SELECT
    b.id,
    b.title,
    b.isbn,
    b.price,
    b.version
FROM books b
JOIN authors a ON a.id = b.author_id
WHERE a.name = ?
~~~

Kết quả chỉ chứa các cột của Book. JOIN authors được dùng để lọc theo tên tác giả; nó không có nghĩa entity Author cũng được ánh xạ hoặc association author đã được tải.

Nếu cần trả về cả Book và Author, hãy dùng result set mapping nhiều entity bằng **@SqlResultSetMapping** với nhiều **@EntityResult**, hoặc trả DTO chứa các field cần thiết. Khi mapping nhiều entity, cần alias cột riêng biệt để tránh trùng tên id, name hoặc các cột chung.

Nếu Book có association Author và bạn chỉ map Book, việc truy cập **book.getAuthor()** sau đó vẫn tuân theo fetch strategy của association. Native SQL JOIN trong câu query không tự động biến association thành đã được fetch trong mọi provider/mapping.

## 12. Phân trang native query

Spring Data JPA có thể phân trang native query bằng **Pageable**. Với truy vấn phức tạp, nên khai báo count query riêng:

~~~java
@Query(
    value = """
        SELECT b.id, b.title, b.isbn, b.price, b.version
        FROM books b
        WHERE b.price >= ?1
        ORDER BY b.price DESC
        """,
    countQuery = """
        SELECT COUNT(*)
        FROM books b
        WHERE b.price >= ?1
        """,
    nativeQuery = true
)
Page<Book> findPageByMinimumPrice(
    BigDecimal minimumPrice,
    Pageable pageable
);
~~~

Count query phải đếm đúng số dòng logic mà truy vấn nội dung trả về. Nếu truy vấn JOIN tạo nhiều dòng cho một Book, có thể cần **COUNT(DISTINCT b.id)**. Nếu truy vấn có GROUP BY, count query cần đếm số nhóm chứ không phải tổng số hàng nguồn.

Việc phân trang SQL có thể phụ thuộc dialect và phiên bản Spring Data JPA. Kiểm thử cả câu query nội dung lẫn count query trên database thực tế.

## 13. Tham số, transaction và flush khi dùng native SQL

Dùng parameter binding thay vì nối chuỗi:

~~~java
@Query(
    value = "SELECT id, title, isbn, price, version FROM books WHERE isbn = ?1",
    nativeQuery = true
)
Optional<Book> findByIsbnNative(String isbn);
~~~

Không làm:

~~~java
String sql = "SELECT * FROM books WHERE isbn = '" + isbn + "'";
~~~

Nối chuỗi input vào SQL có nguy cơ SQL injection và lỗi escaping. Parameter binding dành cho giá trị; tên bảng, tên cột hoặc hướng sort thường không thể bind như giá trị. Nếu cần SQL động cho identifier, dùng allowlist các lựa chọn được kiểm soát.

Với native SELECT, hãy chọn transaction boundary phù hợp và cân nhắc **@Transactional(readOnly = true)** cho use case đọc. Với native UPDATE/DELETE, cần **@Modifying** trong Spring Data repository và transaction ghi:

~~~java
@Modifying
@Transactional
@Query(
    value = "UPDATE books SET price = ?1 WHERE id = ?2",
    nativeQuery = true
)
int updatePrice(BigDecimal price, Long id);
~~~

Native UPDATE/DELETE chạy trực tiếp trên database và không đi qua entity lifecycle thông thường. Chúng không gọi entity callback, cascade JPA hoặc dirty checking cho từng entity. Persistence context có thể giữ entity cũ; cân nhắc flush trước và clear/refresh sau khi thực thi.

Đặc biệt, flush mode và cách provider đồng bộ thay đổi trước native query có thể khác nhau theo provider và cấu hình. Nếu truy vấn phụ thuộc vào thay đổi đang chờ trong persistence context, hãy flush một cách tường minh khi cần và kiểm thử.

## 14. Những lỗi thường gặp

| Triệu chứng | Nguyên nhân | Cách xử lý |
|---|---|---|
| Entity trả về thiếu field hoặc lỗi mapping | Native SELECT không cung cấp đủ cột entity | Chọn đầy đủ cột persistent cần thiết |
| Alias không được ánh xạ đúng | Tên alias khác tên cột mapping | Dùng alias ổn định và **@SqlResultSetMapping/@FieldResult** |
| Native query dùng tên entity nhưng database báo lỗi | Viết JPQL syntax trong native SQL | Dùng tên bảng/cột vật lý |
| Kết quả join có nhiều entity trùng | Join tạo nhiều dòng cho một entity | Xác định cardinality và dùng DISTINCT khi đúng ngữ nghĩa |
| Entity association chưa được tải | JOIN SQL chỉ dùng để lọc, không phải entity fetch mapping | Dùng EntityGraph/fetch query hoặc DTO |
| DTO constructor lỗi | Sai thứ tự hoặc kiểu cột | Kiểm tra **@ColumnResult** và constructor |
| Page tổng số phần tử sai | Count query không phản ánh số dòng/nhóm | Khai báo countQuery phù hợp |
| Object managed cũ sau native UPDATE | Native DML bỏ qua persistence context | Flush và clear/refresh theo use case |
| SQL injection | Nối chuỗi input vào SQL | Dùng parameter binding |
| Truy vấn chạy trên một DB nhưng hỏng ở DB khác | Cú pháp native phụ thuộc dialect | Kiểm thử và quản lý SQL theo database đích |

## 15. Checklist ánh xạ native query về Entity

- [ ] Xác định truy vấn thực sự cần native SQL hay JPQL đã đủ.
- [ ] Dùng đúng tên bảng và cột vật lý của database.
- [ ] Khi trả về entity, SELECT đủ các cột cần thiết theo mapping.
- [ ] Bao gồm khóa chính và các cột version/foreign key cần thiết.
- [ ] Dùng alias ổn định nếu tên cột kết quả khác mapping.
- [ ] Dùng **@SqlResultSetMapping** và **@EntityResult** khi cần mapping entity tường minh.
- [ ] Không ánh xạ result set một phần hoặc kết quả aggregate thành entity đầy đủ.
- [ ] Dùng DTO hoặc scalar mapping cho dữ liệu báo cáo.
- [ ] Dùng parameter binding, không nối chuỗi input vào SQL.
- [ ] Khai báo countQuery đúng khi phân trang native query.
- [ ] Quản lý persistence context sau native UPDATE/DELETE.
- [ ] Kiểm thử trên database và dialect thực tế.

## 16. Kết luận

Native query cho phép tận dụng SQL trực tiếp trong ứng dụng JPA. Khi kết quả là entity đầy đủ, có thể dùng **EntityManager.createNativeQuery(sql, Entity.class)** hoặc Spring Data **@Query(nativeQuery = true)**. Khi tên cột/alias tùy chỉnh, dùng **@SqlResultSetMapping** với **@EntityResult** và **@FieldResult** để ánh xạ rõ ràng.

Chỉ ánh xạ về entity khi result set cung cấp đủ dữ liệu theo mapping. Với báo cáo, aggregate hoặc dữ liệu một phần, dùng DTO/scalar projection. Luôn kiểm tra alias, kiểu dữ liệu, count query, transaction và trạng thái persistence context để native SQL hoạt động đúng trong ứng dụng.
