# Thay quan hệ nhiều-nhiều bằng Entity liên kết có thuộc tính riêng

Trong mô hình quan hệ, quan hệ nhiều-nhiều thường được lưu bằng một bảng nối chứa khóa ngoại đến hai bảng chính. Khi bảng nối chỉ có hai khóa ngoại, JPA có thể biểu diễn bằng @ManyToMany. Nhưng khi mỗi lần liên kết có thêm dữ liệu nghiệp vụ như ngày đăng ký, trạng thái, điểm số, vai trò, số lượng hoặc ghi chú, bản thân liên kết đã trở thành một đối tượng có ý nghĩa. Lúc này nên mô hình hóa bảng nối thành một entity riêng, thường gọi là **association entity** hoặc **association object**.

Bài học dùng ví dụ sinh viên đăng ký khóa học. Một sinh viên có thể đăng ký nhiều khóa học, một khóa học có nhiều sinh viên, và mỗi lần đăng ký có ngày đăng ký, trạng thái, điểm cùng ghi chú. Ta thay quan hệ Student–Course trực tiếp bằng entity Enrollment. Cách này giúp lưu thuộc tính của liên kết, quản lý vòng đời, truy vấn, kiểm soát ràng buộc và mở rộng nghiệp vụ rõ ràng hơn.

## 1. Vì sao @ManyToMany không còn phù hợp?

Giả sử có hai entity:

- Student: sinh viên.
- Course: khóa học.

Một sinh viên có thể tham gia nhiều khóa học; một khóa học có nhiều sinh viên. Nếu liên kết chỉ cần hai khóa ngoại, bảng nối có thể có dạng:

~~~sql
CREATE TABLE student_courses (
    student_id BIGINT NOT NULL,
    course_id BIGINT NOT NULL,
    PRIMARY KEY (student_id, course_id),
    FOREIGN KEY (student_id) REFERENCES students(id),
    FOREIGN KEY (course_id) REFERENCES courses(id)
);
~~~

Trong JPA, có thể ánh xạ bằng @ManyToMany và @JoinTable. Tuy nhiên, khi nghiệp vụ cần thêm thông tin:

- Thời điểm đăng ký.
- Trạng thái đăng ký: ACTIVE, COMPLETED, CANCELLED.
- Điểm cuối khóa.
- Vai trò của thành viên trong nhóm.
- Giá trị thanh toán, số lượng, ghi chú hoặc người phê duyệt.

thì bảng nối không còn chỉ là chi tiết kỹ thuật. Mỗi hàng biểu diễn một lần đăng ký có vòng đời và quy tắc riêng. @ManyToMany không cung cấp một entity độc lập để đặt các thuộc tính và hành vi đó.

Mô hình phù hợp hơn là:

~~~text
Student 1 -------- * Enrollment * -------- 1 Course
                      |
                      +-- enrolledAt
                      +-- status
                      +-- score
                      +-- note
~~~

Quan hệ nhiều-nhiều ban đầu được tách thành hai quan hệ một-nhiều và nhiều-một:

- Một Student có nhiều Enrollment.
- Mỗi Enrollment thuộc về một Student.
- Một Course có nhiều Enrollment.
- Mỗi Enrollment thuộc về một Course.

Enrollment là entity đại diện cho chính liên kết Student–Course.

## 2. Thiết kế bảng dữ liệu

Mô hình gồm ba bảng:

| Bảng | Vai trò | Dữ liệu chính |
|---|---|---|
| students | Lưu sinh viên | id, name |
| courses | Lưu khóa học | id, code, title |
| enrollments | Lưu lần đăng ký | id, student_id, course_id, enrolled_at, status, score, note |

Ví dụ DDL:

~~~sql
CREATE TABLE students (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name VARCHAR(120) NOT NULL
);

CREATE TABLE courses (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    code VARCHAR(40) NOT NULL UNIQUE,
    title VARCHAR(200) NOT NULL
);

CREATE TABLE enrollments (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    student_id BIGINT NOT NULL,
    course_id BIGINT NOT NULL,
    enrolled_at TIMESTAMP WITH TIME ZONE NOT NULL,
    status VARCHAR(20) NOT NULL,
    score DECIMAL(5, 2),
    note VARCHAR(500),
    version BIGINT NOT NULL DEFAULT 0,

    CONSTRAINT fk_enrollment_student
        FOREIGN KEY (student_id) REFERENCES students(id),

    CONSTRAINT fk_enrollment_course
        FOREIGN KEY (course_id) REFERENCES courses(id),

    CONSTRAINT uk_enrollment_student_course
        UNIQUE (student_id, course_id),

    CONSTRAINT chk_enrollment_status
        CHECK (status IN ('ACTIVE', 'COMPLETED', 'CANCELLED')),

    CONSTRAINT chk_enrollment_score
        CHECK (score IS NULL OR (score >= 0 AND score <= 100))
);

CREATE INDEX idx_enrollment_course_status
    ON enrollments(course_id, status);
~~~

DDL trên dùng cú pháp identity và timestamp có múi giờ theo kiểu SQL phổ biến ở PostgreSQL/H2; cú pháp chi tiết có thể cần điều chỉnh theo hệ quản trị. Các ràng buộc cần giữ lại dù mapping JPA có khai báo tương ứng, vì database phải bảo vệ dữ liệu trước mọi nguồn ghi.

Ở ví dụ này, một sinh viên chỉ được đăng ký một lần vào một khóa học. Vì vậy có UNIQUE(student_id, course_id). Nếu nghiệp vụ cho phép đăng ký lại theo từng học kỳ, cần thêm term_id hoặc cohort_id và đổi khóa duy nhất thành UNIQUE(student_id, course_id, term_id). Hãy xác định quy tắc nghiệp vụ trước khi chọn khóa.

## 3. Ánh xạ entity Enrollment

Enrollment là entity độc lập có khóa chính riêng. Nó chứa hai quan hệ @ManyToOne đến Student và Course, cùng các thuộc tính của lần đăng ký.

~~~java
package example.domain;

import jakarta.persistence.*;
import java.math.BigDecimal;
import java.time.Instant;
import java.util.Objects;

@Entity
@Table(
    name = "enrollments",
    uniqueConstraints = {
        @UniqueConstraint(
            name = "uk_enrollment_student_course",
            columnNames = {"student_id", "course_id"}
        )
    },
    indexes = {
        @Index(
            name = "idx_enrollment_course_status",
            columnList = "course_id,status"
        )
    }
)
public class Enrollment {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @ManyToOne(fetch = FetchType.LAZY, optional = false)
    @JoinColumn(name = "student_id", nullable = false)
    private Student student;

    @ManyToOne(fetch = FetchType.LAZY, optional = false)
    @JoinColumn(name = "course_id", nullable = false)
    private Course course;

    @Column(name = "enrolled_at", nullable = false, updatable = false)
    private Instant enrolledAt;

    @Enumerated(EnumType.STRING)
    @Column(nullable = false, length = 20)
    private EnrollmentStatus status;

    @Column(precision = 5, scale = 2)
    private BigDecimal score;

    @Column(length = 500)
    private String note;

    @Version
    private long version;

    protected Enrollment() {
        // Constructor dành cho JPA.
    }

    public Enrollment(Instant enrolledAt) {
        this.enrolledAt = Objects.requireNonNull(enrolledAt);
        this.status = EnrollmentStatus.ACTIVE;
    }

    void assignStudent(Student student) {
        this.student = Objects.requireNonNull(student);
    }

    void assignCourse(Course course) {
        this.course = Objects.requireNonNull(course);
    }

    public void complete(BigDecimal score) {
        if (score == null
                || score.compareTo(BigDecimal.ZERO) < 0
                || score.compareTo(new BigDecimal("100")) > 0) {
            throw new IllegalArgumentException(
                "Score must be between 0 and 100"
            );
        }

        if (status == EnrollmentStatus.CANCELLED) {
            throw new IllegalStateException(
                "A cancelled enrollment cannot be completed"
            );
        }

        this.score = score;
        this.status = EnrollmentStatus.COMPLETED;
    }

    public void cancel() {
        if (status == EnrollmentStatus.COMPLETED) {
            throw new IllegalStateException(
                "A completed enrollment cannot be cancelled"
            );
        }

        this.status = EnrollmentStatus.CANCELLED;
    }

    public Long getId() {
        return id;
    }

    public Student getStudent() {
        return student;
    }

    public Course getCourse() {
        return course;
    }

    public Instant getEnrolledAt() {
        return enrolledAt;
    }

    public EnrollmentStatus getStatus() {
        return status;
    }

    public BigDecimal getScore() {
        return score;
    }

    public String getNote() {
        return note;
    }

    public long getVersion() {
        return version;
    }

    public void changeNote(String note) {
        this.note = note;
    }
}
~~~

Enum trạng thái:

~~~java
package example.domain;

public enum EnrollmentStatus {
    ACTIVE,
    COMPLETED,
    CANCELLED
}
~~~

Một số điểm cần chú ý:

- Enrollment có @Id riêng nên có thể được repository quản lý, tìm kiếm, cập nhật và xóa độc lập.
- Hai field student và course dùng @ManyToOne vì nhiều lần đăng ký có thể cùng tham chiếu một sinh viên hoặc một khóa học.
- @JoinColumn xác định khóa ngoại nằm ở bảng enrollments.
- FetchType.LAZY trì hoãn việc tải Student và Course đến khi cần; khi truy cập phải nằm trong phạm vi persistence context phù hợp.
- @Enumerated(EnumType.STRING) lưu tên trạng thái. Nếu cần mã lưu trữ riêng, có thể dùng AttributeConverter theo bài học chuyển đổi dữ liệu.
- @Version hỗ trợ optimistic locking để phát hiện cập nhật đồng thời.
- complete() và cancel() đặt quy tắc chuyển trạng thái ở đúng entity có ý nghĩa nghiệp vụ.

Không thêm cascade REMOVE từ Enrollment sang Student hoặc Course. Xóa một lần đăng ký không được xóa sinh viên hoặc khóa học đang được nhiều lần đăng ký khác tham chiếu.

## 4. Ánh xạ hai phía Student và Course

Nếu cần điều hướng từ Student đến danh sách Enrollment và từ Course đến danh sách Enrollment, có thể dùng quan hệ hai chiều.

Student:

~~~java
package example.domain;

import jakarta.persistence.*;
import java.util.ArrayList;
import java.util.Collections;
import java.util.List;

@Entity
@Table(name = "students")
public class Student {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false, length = 120)
    private String name;

    @OneToMany(mappedBy = "student", fetch = FetchType.LAZY)
    private List<Enrollment> enrollments = new ArrayList<>();

    protected Student() {
    }

    public Student(String name) {
        this.name = name;
    }

    public void addEnrollment(Enrollment enrollment) {
        if (enrollment.getStudent() != null
                && enrollment.getStudent() != this) {
            throw new IllegalArgumentException(
                "Enrollment already belongs to another student"
            );
        }

        if (!enrollments.contains(enrollment)) {
            enrollments.add(enrollment);
        }

        enrollment.assignStudent(this);
    }

    public List<Enrollment> getEnrollments() {
        return Collections.unmodifiableList(enrollments);
    }

    public Long getId() {
        return id;
    }

    public String getName() {
        return name;
    }
}
~~~

Course:

~~~java
package example.domain;

import jakarta.persistence.*;
import java.util.ArrayList;
import java.util.Collections;
import java.util.List;

@Entity
@Table(name = "courses")
public class Course {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false, unique = true, length = 40)
    private String code;

    @Column(nullable = false, length = 200)
    private String title;

    @OneToMany(mappedBy = "course", fetch = FetchType.LAZY)
    private List<Enrollment> enrollments = new ArrayList<>();

    protected Course() {
    }

    public Course(String code, String title) {
        this.code = code;
        this.title = title;
    }

    public void addEnrollment(Enrollment enrollment) {
        if (enrollment.getCourse() != null
                && enrollment.getCourse() != this) {
            throw new IllegalArgumentException(
                "Enrollment already belongs to another course"
            );
        }

        if (!enrollments.contains(enrollment)) {
            enrollments.add(enrollment);
        }

        enrollment.assignCourse(this);
    }

    public List<Enrollment> getEnrollments() {
        return Collections.unmodifiableList(enrollments);
    }

    public Long getId() {
        return id;
    }

    public String getCode() {
        return code;
    }

    public String getTitle() {
        return title;
    }
}
~~~

Trong hai class này:

- @OneToMany(mappedBy = "student") trỏ đến field student trong Enrollment.
- @OneToMany(mappedBy = "course") trỏ đến field course trong Enrollment.
- mappedBy cho biết hai collection là phía inverse; chúng không sở hữu khóa ngoại.
- Enrollment là owning side vì các field @ManyToOne của nó khai báo @JoinColumn.

JPA ghi khóa ngoại dựa trên owning side. Nếu chỉ thêm Enrollment vào collection của Student mà không gán student trên Enrollment, thay đổi quan hệ có thể không được ghi như mong muốn. Các phương thức addEnrollment() cập nhật cả hai phía để object graph nhất quán trong bộ nhớ.

Nếu ứng dụng không cần điều hướng Student → Enrollment hoặc Course → Enrollment, có thể bỏ hai collection @OneToMany và chỉ giữ hai @ManyToOne trong Enrollment. Đây thường là mô hình đơn giản hơn và tránh tải collection ngoài ý muốn.

## 5. Tạo Enrollment thay cho thao tác add trực tiếp vào @ManyToMany

Với @ManyToMany cũ, code thường có dạng:

~~~java
student.getCourses().add(course);
~~~

Cách này chỉ thể hiện hai object được liên kết. Không có chỗ rõ ràng để đặt enrolledAt, status hoặc score.

Với association entity, quy trình trở thành:

1. Tìm Student đã tồn tại.
2. Tìm Course đã tồn tại.
3. Kiểm tra quy tắc đăng ký.
4. Tạo Enrollment.
5. Gán cả Student và Course.
6. Lưu Enrollment.

Ví dụ service:

~~~java
package example.service;

import example.domain.Course;
import example.domain.Enrollment;
import example.domain.Student;
import example.repository.CourseRepository;
import example.repository.EnrollmentRepository;
import example.repository.StudentRepository;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.time.Instant;

@Service
public class EnrollmentService {

    private final StudentRepository studentRepository;
    private final CourseRepository courseRepository;
    private final EnrollmentRepository enrollmentRepository;

    public EnrollmentService(
            StudentRepository studentRepository,
            CourseRepository courseRepository,
            EnrollmentRepository enrollmentRepository) {
        this.studentRepository = studentRepository;
        this.courseRepository = courseRepository;
        this.enrollmentRepository = enrollmentRepository;
    }

    @Transactional
    public Enrollment enroll(Long studentId, Long courseId) {
        Student student = studentRepository.findById(studentId)
            .orElseThrow(() ->
                new IllegalArgumentException("Student not found"));

        Course course = courseRepository.findById(courseId)
            .orElseThrow(() ->
                new IllegalArgumentException("Course not found"));

        if (enrollmentRepository
                .existsByStudent_IdAndCourse_Id(studentId, courseId)) {
            throw new IllegalStateException(
                "Student is already enrolled in this course"
            );
        }

        Enrollment enrollment = new Enrollment(Instant.now());

        student.addEnrollment(enrollment);
        course.addEnrollment(enrollment);

        return enrollmentRepository.save(enrollment);
    }

    @Transactional
    public void complete(Long enrollmentId,
                         java.math.BigDecimal score) {
        Enrollment enrollment = enrollmentRepository.findById(enrollmentId)
            .orElseThrow(() ->
                new IllegalArgumentException("Enrollment not found"));

        enrollment.complete(score);
    }

    @Transactional
    public void cancel(Long enrollmentId) {
        Enrollment enrollment = enrollmentRepository.findById(enrollmentId)
            .orElseThrow(() ->
                new IllegalArgumentException("Enrollment not found"));

        enrollment.cancel();
    }
}
~~~

Student và Course đã được tải trong transaction nên là managed entity. Khi lưu Enrollment, JPA ghi hai khóa ngoại student_id và course_id cùng các thuộc tính còn lại.

Không cần cascade PERSIST từ Enrollment đến Student và Course trong trường hợp này vì cả hai đã tồn tại. Nếu cascade sai, thao tác lưu một lần đăng ký có thể cố tạo lại hoặc tác động ngoài ý muốn đến entity liên quan.

Phương thức complete() và cancel() không gọi repository.save() lần nữa. Entity đã được quản lý trong transaction; dirty checking phát hiện thay đổi và provider đồng bộ khi flush hoặc commit.

## 6. Repository cho association entity

Mỗi entity có thể có repository riêng:

~~~java
package example.repository;

import example.domain.Student;
import org.springframework.data.jpa.repository.JpaRepository;

public interface StudentRepository
        extends JpaRepository<Student, Long> {
}
~~~

~~~java
package example.repository;

import example.domain.Course;
import org.springframework.data.jpa.repository.JpaRepository;

public interface CourseRepository
        extends JpaRepository<Course, Long> {
}
~~~

~~~java
package example.repository;

import example.domain.Enrollment;
import example.domain.EnrollmentStatus;
import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.data.jpa.repository.Query;
import org.springframework.data.repository.query.Param;

import java.util.List;
import java.util.Optional;

public interface EnrollmentRepository
        extends JpaRepository<Enrollment, Long> {

    boolean existsByStudent_IdAndCourse_Id(
        Long studentId,
        Long courseId
    );

    Optional<Enrollment> findByStudent_IdAndCourse_Id(
        Long studentId,
        Long courseId
    );

    List<Enrollment> findAllByStudent_IdOrderByEnrolledAtDesc(
        Long studentId
    );

    @Query("""
        select e
        from Enrollment e
        join fetch e.course
        where e.student.id = :studentId
          and e.status = :status
        """)
    List<Enrollment> findWithCourseByStudentAndStatus(
        @Param("studentId") Long studentId,
        @Param("status") EnrollmentStatus status
    );
}
~~~

Các method derived query dùng đường dẫn thuộc tính:

- Student_Id đi qua quan hệ student rồi lấy id.
- Course_Id đi qua quan hệ course rồi lấy id.
- existsByStudent_IdAndCourse_Id kiểm tra một cặp liên kết đã tồn tại hay chưa.
- findByStudent_IdAndCourse_Id lấy entity liên kết theo hai đầu mối.

Dấu gạch dưới giúp Spring Data hiểu ranh giới giữa tên quan hệ và thuộc tính id. Nếu tên property phức tạp hoặc dễ mơ hồ, có thể dùng @Query để diễn đạt rõ hơn.

## 7. Truy vấn dữ liệu theo thuộc tính của liên kết

Sau khi có Enrollment, có thể truy vấn theo trạng thái, thời gian, điểm số hoặc dữ liệu của Student/Course.

Ví dụ tìm các đăng ký đang hoạt động của một khóa học:

~~~java
@Query("""
    select e
    from Enrollment e
    where e.course.id = :courseId
      and e.status = :status
    order by e.enrolledAt desc
    """)
List<Enrollment> findByCourseAndStatus(
    @Param("courseId") Long courseId,
    @Param("status") EnrollmentStatus status
);
~~~

Tìm sinh viên đã hoàn thành khóa học với điểm từ 80 trở lên:

~~~java
@Query("""
    select e
    from Enrollment e
    where e.course.id = :courseId
      and e.status = example.domain.EnrollmentStatus.COMPLETED
      and e.score >= :minimumScore
    """)
List<Enrollment> findHighScoringEnrollments(
    @Param("courseId") Long courseId,
    @Param("minimumScore") BigDecimal minimumScore
);
~~~

Trong JPQL, có thể dùng tham số cho enum để dễ tái sử dụng:

~~~java
@Query("""
    select e
    from Enrollment e
    where e.course.id = :courseId
      and e.status = :status
      and e.score >= :minimumScore
    """)
List<Enrollment> findByCourseStatusAndMinimumScore(
    @Param("courseId") Long courseId,
    @Param("status") EnrollmentStatus status,
    @Param("minimumScore") BigDecimal minimumScore
);
~~~

Association entity cho phép truy vấn trực tiếp dữ liệu của lần liên kết mà không cần tải toàn bộ Student hoặc Course rồi lọc trong Java.

## 8. Phân trang và DTO

Một khóa học có thể có hàng nghìn đăng ký. Không nên tải toàn bộ danh sách vào bộ nhớ khi chỉ cần hiển thị từng trang.

Repository có thể trả Page:

~~~java
Page<Enrollment> findAllByCourse_Id(
    Long courseId,
    Pageable pageable
);
~~~

Service nhận Pageable và trả kết quả phù hợp. Với API, nên chuyển entity thành DTO trong transaction hoặc dùng projection để chỉ lấy các cột cần thiết.

Ví dụ DTO record:

~~~java
package example.dto;

import example.domain.EnrollmentStatus;
import java.math.BigDecimal;
import java.time.Instant;

public record EnrollmentSummary(
    Long enrollmentId,
    String studentName,
    String courseCode,
    String courseTitle,
    EnrollmentStatus status,
    BigDecimal score,
    Instant enrolledAt
) {
}
~~~

JPQL projection:

~~~java
@Query(
    value = """
        select new example.dto.EnrollmentSummary(
            e.id,
            e.student.name,
            e.course.code,
            e.course.title,
            e.status,
            e.score,
            e.enrolledAt
        )
        from Enrollment e
        where e.course.id = :courseId
        """,
    countQuery = """
        select count(e)
        from Enrollment e
        where e.course.id = :courseId
        """
)
Page<EnrollmentSummary> findSummariesByCourseId(
    @Param("courseId") Long courseId,
    Pageable pageable
);
~~~

Projection giúp tránh trả entity ra ngoài API và hạn chế lazy loading sau khi transaction kết thúc. Nó cũng giảm lượng dữ liệu được tải nếu giao diện chỉ cần một số trường.

## 9. Chọn khóa chính cho Enrollment

Có hai cách thiết kế phổ biến.

### 9.1. Khóa chính thay thế (surrogate key)

Ví dụ chính dùng:

~~~java
@Id
@GeneratedValue(strategy = GenerationType.IDENTITY)
private Long id;
~~~

Bảng enrollments có id riêng, còn cặp student_id/course_id được bảo vệ bằng UNIQUE constraint.

Ưu điểm:

- Repository thao tác bằng một ID đơn giản.
- DTO và URL có thể tham chiếu một enrollment cụ thể.
- Dễ thêm các thuộc tính nghiệp vụ khác.
- Ít phức tạp hơn khi ánh xạ JPA.

Nhược điểm là bảng có thêm một cột khóa chính. Nếu cặp student/course đã là định danh tự nhiên duy nhất, cần giữ unique constraint để tránh dữ liệu trùng.

### 9.2. Khóa chính ghép

Nếu bản thân cặp Student–Course là định danh ổn định của liên kết, có thể dùng @EmbeddedId và @MapsId:

~~~java
@Embeddable
public class EnrollmentId implements Serializable {

    private Long studentId;
    private Long courseId;

    protected EnrollmentId() {
    }

    public EnrollmentId(Long studentId, Long courseId) {
        this.studentId = studentId;
        this.courseId = courseId;
    }

    // Cần triển khai equals() và hashCode() dựa trên cả hai ID.
}
~~~

~~~java
@Entity
@Table(name = "enrollments")
public class Enrollment {

    @EmbeddedId
    private EnrollmentId id;

    @MapsId("studentId")
    @ManyToOne(fetch = FetchType.LAZY, optional = false)
    @JoinColumn(name = "student_id")
    private Student student;

    @MapsId("courseId")
    @ManyToOne(fetch = FetchType.LAZY, optional = false)
    @JoinColumn(name = "course_id")
    private Course course;

    // Các thuộc tính như enrolledAt, status, score...
}
~~~

Đây là dạng minh họa; constructor, equals/hashCode và cách khởi tạo khóa cần được hoàn thiện theo ứng dụng. @MapsId đồng bộ phần khóa của embedded ID với ID của entity liên quan.

Khóa ghép có thể phù hợp khi liên kết chỉ tồn tại duy nhất cho một cặp. Nếu cho phép đăng ký lại theo kỳ, phải đưa kỳ học vào khóa hoặc dùng surrogate key cùng unique constraint nghiệp vụ. Không nên chọn khóa ghép chỉ vì muốn tiết kiệm một cột nếu nó làm các thao tác repository và API phức tạp hơn.

## 10. Cascade, orphan removal và vòng đời

Association entity có vòng đời riêng. Hãy xác định rõ ai sở hữu dữ liệu và điều gì xảy ra khi Student hoặc Course bị xóa.

- Không cascade REMOVE từ Enrollment đến Student hoặc Course.
- Nếu Enrollment là lịch sử nghiệp vụ, thường giữ bản ghi và đổi status sang CANCELLED thay vì xóa vật lý.
- Nếu một liên kết chỉ là dữ liệu phụ thuộc hoàn toàn vào aggregate cha, có thể cân nhắc cascade PERSIST hoặc orphanRemoval ở phía OneToMany.
- orphanRemoval=true có nghĩa xóa entity liên kết khỏi collection có thể dẫn đến xóa hàng tương ứng khi flush. Chỉ bật khi quy tắc nghiệp vụ thật sự yêu cầu.
- Nếu Enrollment có thanh toán, phê duyệt, lịch sử hoặc audit, xóa vật lý có thể làm mất bằng chứng nghiệp vụ; cần cân nhắc soft delete hoặc trạng thái kết thúc.

Trong ví dụ này, Student và Course không cascade sang Enrollment. Service lưu Enrollment tường minh qua EnrollmentRepository. Cách này làm ranh giới thao tác dễ đọc và tránh việc lưu Student bất ngờ kéo theo nhiều đăng ký.

## 11. Đồng bộ hai phía và owning side

Trong quan hệ hai chiều, Enrollment là owning side vì nó chứa @JoinColumn. Student.enrollments và Course.enrollments là inverse side vì chúng dùng mappedBy.

Nếu chỉ cập nhật inverse collection, JPA không có thông tin owning side mới để ghi khóa ngoại. Vì vậy, nên cung cấp phương thức helper ở entity để cập nhật hai phía cùng lúc.

Quy tắc:

1. Thay đổi quan hệ trên Enrollment phải cập nhật field student/course.
2. Nếu có collection inverse đã được tải, cập nhật collection để object graph nhất quán.
3. Không gán null cho quan hệ NOT NULL trong khi entity vẫn được giữ lại.
4. Không dùng equals/hashCode dựa trên toàn bộ collection quan hệ; có thể gây vòng lặp, tải lazy ngoài ý muốn hoặc làm thay đổi hash khi trạng thái entity đổi.

Nếu không cần điều hướng từ Student/Course, bỏ collection inverse và giữ một chiều từ Enrollment đến hai entity. Điều đó giảm số helper cần duy trì.

## 12. Hiệu năng và truy vấn N+1

Khi tải danh sách Enrollment rồi truy cập từng Course, nếu quan hệ ManyToOne là LAZY, provider có thể phát sinh một truy vấn lấy enrollment và thêm nhiều truy vấn lấy course. Đây là tình huống N+1.

Có thể xử lý theo nhu cầu:

- Dùng JOIN FETCH khi cần tải Course cùng Enrollment trong một truy vấn.
- Dùng @EntityGraph(attributePaths = "course") cho một repository method.
- Dùng DTO projection để chỉ lấy trường cần hiển thị.
- Phân trang ở database khi danh sách lớn.
- Tạo index phù hợp với các điều kiện thường dùng như course_id, student_id, status.
- Kiểm tra execution plan và SQL thực tế khi hiệu năng không đạt yêu cầu.

Ví dụ JOIN FETCH ở phần repository tải Course cho một danh sách Enrollment. Vì Course là quan hệ ManyToOne, mỗi Enrollment chỉ tham chiếu một Course. Với collection fetch join và phân trang, cần đặc biệt cẩn thận vì số hàng SQL có thể nhân lên và kết quả phân trang không còn đơn giản.

Không chuyển toàn bộ danh sách Enrollment về Java rồi lọc bằng Stream nếu database có thể thực hiện WHERE, ORDER BY và LIMIT hiệu quả hơn.

## 13. Transaction và cập nhật đồng thời

Tạo, hoàn tất hoặc hủy Enrollment là thao tác nghiệp vụ nên được đặt trong transaction.

Ví dụ, kiểm tra cặp Student–Course đã tồn tại rồi tạo Enrollment. Nếu hai request đồng thời cùng đăng ký một cặp, cả hai có thể cùng vượt qua bước existsBy... trước khi một request ghi dữ liệu.

Vì vậy, kiểm tra ở service giúp phản hồi sớm, còn UNIQUE(student_id, course_id) ở database mới là hàng rào cuối cùng bảo vệ dữ liệu. Ứng dụng cần xử lý lỗi vi phạm unique constraint và chuyển thành phản hồi nghiệp vụ phù hợp.

@Version trên Enrollment giúp phát hiện hai transaction cùng sửa một bản ghi. Nếu một transaction ghi trước, transaction còn lại có thể nhận optimistic locking exception khi flush/commit do version đã thay đổi. Ứng dụng có thể yêu cầu tải lại và thử lại theo quy tắc nghiệp vụ.

Không phải mọi lỗi đồng thời đều nên tự động retry. Hãy phân biệt lỗi tạm thời có thể thử lại với xung đột cần người dùng hoặc nghiệp vụ quyết định.

## 14. Chuyển từ bảng nối @ManyToMany hiện có

Nếu hệ thống đã dùng bảng student_courses, việc chuyển đổi cần bảo toàn dữ liệu.

Một quy trình migration có thể gồm:

1. Kiểm kê các cột, khóa chính, khóa ngoại, unique constraint và index hiện có.
2. Thêm cột id cho bảng nối nếu chuyển sang surrogate key.
3. Thêm các cột nghiệp vụ mới như enrolled_at, status, score và note.
4. Backfill giá trị cho bản ghi cũ. Ví dụ, đặt trạng thái ACTIVE và dùng thời điểm migration hoặc dữ liệu lịch sử phù hợp cho enrolled_at.
5. Tạo khóa chính mới và giữ unique constraint trên cặp student_id/course_id nếu nghiệp vụ vẫn yêu cầu.
6. Cập nhật entity mapping để ánh xạ bảng nối thành Enrollment.
7. Cập nhật repository, service, DTO và truy vấn JPQL/native SQL đang dùng quan hệ ManyToMany.
8. Chạy integration test trên bản sao dữ liệu hoặc môi trường migration thử nghiệm.
9. Triển khai theo trình tự tương thích với các phiên bản ứng dụng đang chạy.
10. Chỉ loại bỏ mapping và code cũ sau khi xác nhận mọi luồng đã chuyển sang Enrollment.

Không nên thêm các cột NOT NULL mới mà không có default hoặc backfill cho bản ghi cũ. Cũng không nên đổi mapping trước khi schema production đã sẵn sàng.

Nếu có nhiều ứng dụng cùng đọc bảng nối, cần phối hợp thời điểm triển khai và bảo đảm phiên bản cũ vẫn đọc được dữ liệu trong giai đoạn chuyển tiếp.

## 15. Khi nào association entity là lựa chọn phù hợp?

| Tình huống | Cách mô hình hóa |
|---|---|
| Liên kết chỉ có hai khóa ngoại, không có dữ liệu riêng | @ManyToMany có thể đủ |
| Liên kết có ngày tạo, trạng thái, điểm, vai trò hoặc số lượng | Entity liên kết |
| Liên kết có workflow, phê duyệt hoặc lịch sử | Entity liên kết |
| Cần repository, API hoặc quyền thao tác riêng cho liên kết | Entity liên kết |
| Liên kết cần được tìm kiếm, phân trang hoặc báo cáo độc lập | Entity liên kết |
| Một cặp có thể xuất hiện nhiều lần theo thời gian | Entity liên kết với khóa/unique constraint có thêm ngữ cảnh |

Đừng tạo association entity chỉ vì muốn có thêm một class. Hãy tạo khi liên kết thực sự mang dữ liệu hoặc hành vi nghiệp vụ, hoặc khi cần quản lý nó độc lập.

## 16. Những lỗi thường gặp

**1. Giữ @ManyToMany và thêm field nghiệp vụ vào bảng nối**

JPA không cung cấp entity riêng để ánh xạ các thuộc tính của join table trong mô hình @ManyToMany thông thường. Hãy thay bằng entity liên kết có hai @ManyToOne.

**2. Chỉ cập nhật collection inverse**

Nếu chỉ thêm Enrollment vào Student.enrollments mà không gán Enrollment.student, owning side chưa được cập nhật. Dùng helper method đồng bộ hai phía.

**3. Cascade REMOVE làm mất entity chính**

Xóa một Enrollment không được xóa Student hoặc Course. Không đặt CascadeType.REMOVE từ ManyToOne association sang hai entity chính.

**4. Quên unique constraint**

Kiểm tra exists trong Java không đủ để chống hai request đồng thời. Database phải có unique constraint cho khóa nghiệp vụ.

**5. Dùng khóa ghép nhưng không triển khai equals/hashCode**

Embedded ID cần equality dựa trên các thành phần khóa. Thiếu hoặc triển khai sai có thể làm hành vi persistence và collection không đúng.

**6. Trả entity trực tiếp ra REST API**

Entity có thể chứa quan hệ lazy và vòng tham chiếu hai chiều. Dùng DTO hoặc projection để kiểm soát dữ liệu trả về.

**7. Tải collection lớn cùng lúc**

Truy cập tất cả Enrollment của một Student hoặc Course có thể tốn bộ nhớ và gây nhiều truy vấn. Dùng repository query có phân trang.

**8. Thay đổi converter hoặc enum mà quên dữ liệu cũ**

Nếu status được lưu bằng chuỗi enum, đổi tên hằng số có thể khiến bản ghi cũ không đọc được. Dùng mã ổn định hoặc migration tương thích.

**9. Dùng orphanRemoval theo thói quen**

Nếu Enrollment là lịch sử nghiệp vụ, tự động xóa khi bị loại khỏi collection có thể làm mất dữ liệu. Chọn chính sách vòng đời theo yêu cầu thực tế.

## 19. Câu hỏi ôn tập

**1. Khi nào cần thay @ManyToMany bằng entity liên kết?**

Khi mỗi hàng liên kết có thuộc tính hoặc hành vi riêng như thời gian, trạng thái, điểm, vai trò, số lượng, phê duyệt hoặc lịch sử.

**2. Trong mô hình Student–Enrollment–Course, entity nào sở hữu khóa ngoại?**

Enrollment sở hữu hai khóa ngoại vì các field @ManyToOne của nó khai báo @JoinColumn. Các collection @OneToMany trong Student và Course là phía inverse.

**3. Vì sao cần unique constraint khi service đã kiểm tra exists?**

Vì hai transaction đồng thời có thể cùng thấy chưa tồn tại rồi cùng insert. Database constraint bảo vệ tính duy nhất một cách nguyên tử.

**4. Có nên cascade REMOVE từ Enrollment đến Student và Course không?**

Không, vì Student và Course là entity độc lập có thể được nhiều Enrollment tham chiếu. Xóa một liên kết không được xóa hai đối tượng chính.

**5. Nên chọn surrogate key hay composite key?**

Surrogate key thường đơn giản hơn cho repository và API; composite key phù hợp khi cặp khóa tự nhiên thực sự là định danh ổn định. Quyết định phụ thuộc quy tắc nghiệp vụ và khả năng xuất hiện nhiều lần theo thời gian.

**6. Làm sao tránh N+1 khi hiển thị danh sách đăng ký cùng tên khóa học?**

Dùng fetch join hoặc EntityGraph cho quan hệ cần tải, hoặc dùng DTO projection để lấy đúng trường cần hiển thị. Kết hợp phân trang và kiểm tra SQL thực tế.

Khi mô hình hóa liên kết thành một entity riêng, Enrollment có thể mang dữ liệu, quy tắc và vòng đời của chính nó. Đây là cách thiết kế phù hợp khi quan hệ nhiều-nhiều đã trở thành một khái niệm nghiệp vụ trong hệ thống.
