# Tải người dùng từ cơ sở dữ liệu reactive với R2DBC trong Spring Security WebFlux

## Mục tiêu học tập

Sau bài này, bạn có thể:

1. Giải thích cách **R2DBC**, `ConnectionFactory`, `DatabaseClient` và Spring Data R2DBC kết nối cơ sở dữ liệu quan hệ trong ứng dụng WebFlux.
2. Xây dựng `ReactiveUserDetailsService.findByUsername(String)` trả `Mono<UserDetails>` từ account và danh sách authorities trong database.
3. Hiểu cách `UserDetailsRepositoryReactiveAuthenticationManager` xác minh mật khẩu đã băm, trạng thái tài khoản, rồi đưa danh tính vào chuỗi bảo mật WebFlux.
4. Viết truy vấn có tham số, tránh blocking và SQL injection; phân biệt `Mono.empty()`, lỗi xác thực và lỗi database.
5. Kiểm thử 200/401/403, username không tồn tại, mật khẩu sai, tài khoản disabled và role bằng H2 R2DBC + `WebTestClient`.
6. Biết những điểm cần thay đổi khi chuyển từ H2 demo sang PostgreSQL production: migration, connection pooling, secret, indexes, transaction và kiểm soát quyền.

> Bài tập hướng tới Java 17+, Spring Boot 3.x và Spring Security WebFlux/reactive. Ở Servlet/MVC, `UserDetailsService` và JDBC/JPA đồng bộ là một thiết kế khác; không đem các lời gọi blocking đó đặt trực tiếp vào event loop WebFlux.

## 1. Vì sao tải người dùng bằng R2DBC?

Trong Spring Security WebFlux, mỗi HTTP request được xử lý qua `SecurityWebFilterChain` và các publisher của Project Reactor. Khi Basic Auth gửi username/password, bộ xác thực cần đọc account, password hash và quyền rồi kiểm tra credential. Nếu dùng JDBC/JPA blocking trên Reactor Netty event loop, các thread xử lý nhiều request sẽ bị giữ lại trong lúc chờ I/O.

**R2DBC (Reactive Relational Database Connectivity)** định nghĩa truy cập cơ sở dữ liệu quan hệ bằng Reactive Streams, với driver hỗ trợ I/O reactive. Nó không tự giải quyết password hashing, role, transaction hoặc phân quyền; các trách nhiệm đó vẫn cần Spring Security và thiết kế nghiệp vụ.

| Thành phần | Vai trò | Kết quả điển hình |
| --- | --- | --- |
| `ConnectionFactory` | Quản lý cách tạo kết nối R2DBC thay cho JDBC `DataSource` | Hạ tầng connection |
| `DatabaseClient` | Thực hiện SQL, bind parameter, ánh xạ hàng kết quả | `Mono<AccountRow>`, `Flux<GrantedAuthority>` |
| `ReactiveCrudRepository` | API repository cấp cao của Spring Data R2DBC | `Mono<Account>` |
| `ReactiveUserDetailsService` | Hợp đồng tra account theo username cho Spring Security | `Mono<UserDetails>` |
| `UserDetailsRepositoryReactiveAuthenticationManager` | Dùng service để tải user, đối chiếu hash và trạng thái | `Mono<Authentication>` |
| `SecurityWebFilterChain` | Quy tắc HTTP authentication/authorization | Cho phép hoặc từ chối request |

Sơ đồ luồng xác thực HTTP Basic:

```text
GET /admin/report + HTTP Basic credentials
            |
            v
SecurityWebFilterChain
            |
            v
ReactiveAuthenticationManager
            |
            +--> ReactiveUserDetailsService.findByUsername(username)
            |                |
            |                v
            |          DatabaseClient + R2DBC
            |                |
            |                +--> SELECT account       -> Mono<AccountRow>
            |                +--> SELECT authorities   -> Flux<GrantedAuthority>
            |                +--> map/flatMap          -> Mono<UserDetails>
            |
            +--> PasswordEncoder.matches(rawPassword, storedHash)
            +--> Kiểm tra enabled / trạng thái tài khoản
            |
            v
Authentication + Reactor SecurityContext
            |
            v
Authorization: /admin/** yêu cầu ROLE_ADMIN
            |
            +--> Đủ quyền: controller
            +--> Chưa xác thực: 401 (HTTP Basic)
            +--> Có danh tính, thiếu role: 403
```

Đây là mô hình khái niệm. Request không có credential, endpoint `permitAll()` hoặc cơ chế token khác không nhất thiết phải đi qua toàn bộ bước truy vấn account này.

## 2. Thiết kế bảng account và authorities

Ví dụ dùng hai bảng để tách user khỏi quyền:

**`src/main/resources/schema.sql`** — dành cho H2 trong bài thực hành:

```sql
CREATE TABLE IF NOT EXISTS app_users (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    username VARCHAR(120) NOT NULL UNIQUE,
    password_hash VARCHAR(150) NOT NULL,
    enabled BOOLEAN NOT NULL DEFAULT TRUE
);

CREATE TABLE IF NOT EXISTS app_user_authorities (
    user_id BIGINT NOT NULL,
    authority VARCHAR(100) NOT NULL,
    PRIMARY KEY (user_id, authority),
    CONSTRAINT fk_user_authority
        FOREIGN KEY (user_id) REFERENCES app_users(id)
        ON DELETE CASCADE
);
```

**Ý nghĩa của schema:**

- `username UNIQUE` bảo đảm tra đúng tối đa một account. Ở hệ thống thật cần thống nhất cách chuẩn hóa Unicode và phân biệt chữ hoa/chữ thường giữa logic đăng ký, truy vấn và collation database.
- `password_hash` giữ chuỗi do `PasswordEncoder` tạo, ví dụ `{bcrypt}$2a$...`. Dấu ba chấm chỉ minh họa dạng; đó không phải hash hợp lệ để sử dụng. Không lưu plaintext hoặc SHA-256 một vòng rồi coi là password hashing an toàn.
- `enabled=false` làm account bị từ chối đăng nhập khi manager kiểm tra trạng thái.
- `authority` lưu tên đầy đủ như `ROLE_ADMIN` hoặc `ROLE_READER`. `hasRole("ADMIN")` yêu cầu authority `ROLE_ADMIN`; đừng vô tình lưu `ADMIN` mà không ánh xạ prefix.
- Primary key ghép ngăn quyền trùng; foreign key tránh quyền mồ côi. Chỉ quy trình có quyền quản trị mới được thay đổi bảng cấp role.
- Một user có thể có nhiều authorities, vì vậy account lookup dùng `Mono` còn authority lookup dùng `Flux`.

Đây là schema demo. PostgreSQL production cần migration có version, quyền DB tối thiểu và kiểm soát audit; không bật tạo bảng demo tự động trên database đang có dữ liệu thật.


## 4. Truy vấn account và role bằng DatabaseClient

Spring Boot tự cấu hình `ConnectionFactory` và `DatabaseClient` khi dependency và URL phù hợp. Ta viết repository SQL trực tiếp để quan sát cơ chế `Mono`/`Flux`. Một dự án khác có thể dùng `ReactiveCrudRepository` nếu mapping entity phù hợp.

**`src/main/java/example/r2dbcauth/SqlAccountRepository.java`**:

```java
package example.r2dbcauth;

import org.springframework.r2dbc.core.DatabaseClient;
import org.springframework.security.core.GrantedAuthority;
import org.springframework.security.core.authority.SimpleGrantedAuthority;
import org.springframework.stereotype.Repository;
import reactor.core.publisher.Flux;
import reactor.core.publisher.Mono;

@Repository
public class SqlAccountRepository {

    private final DatabaseClient database;

    public SqlAccountRepository(DatabaseClient database) {
        this.database = database;
    }

    public Mono<AccountRow> findByUsername(String username) {
        return database.sql("""
                    SELECT id, username, password_hash, enabled
                      FROM app_users
                     WHERE username = :username
                    """)
                .bind("username", username)
                .map((row, metadata) -> new AccountRow(
                        row.get("id", Long.class),
                        row.get("username", String.class),
                        row.get("password_hash", String.class),
                        Boolean.TRUE.equals(row.get("enabled", Boolean.class))
                ))
                .one();
    }

    public Flux<GrantedAuthority> findAuthorities(long userId) {
        return database.sql("""
                    SELECT authority
                      FROM app_user_authorities
                     WHERE user_id = :userId
                     ORDER BY authority
                    """)
                .bind("userId", userId)
                .map((row, metadata) ->
                        (GrantedAuthority) new SimpleGrantedAuthority(
                                row.get("authority", String.class)))
                .all();
    }

    public record AccountRow(
            long id,
            String username,
            String passwordHash,
            boolean enabled
    ) {}
}
```

**Phân tích:**

1. `sql(...).bind("username", username)` sử dụng **bind parameter**; không nối username vào chuỗi SQL. Cách này ngăn SQL injection qua giá trị đầu vào.
2. `.map((row, metadata) -> ...)` chuyển từng hàng thành record Java. Cột quan trọng có ràng buộc `NOT NULL` trong schema.
3. `.one()` đại diện tối đa một account. Nếu không tìm thấy hàng, hoàn tất `Mono.empty()`; nếu SQL lỗi, trả tín hiệu `onError`.
4. `.all()` trả `Flux<GrantedAuthority>`, có thể rỗng hoặc chứa nhiều quyền.
5. Không có `block()` hoặc `subscribe()`. Những thao tác được gọi sau này trong một subscription do framework điều khiển.

Để dễ học, repository dùng hai SQL query thay vì JOIN; khi hệ thống có tải lớn, đo độ trễ rồi có thể tối ưu thành JOIN, giữ đúng trường hợp account không có role và tránh trùng quyền. Trong thời gian hai query chạy, bảng role có thể thay đổi; nếu yêu cầu snapshot nhất quán, cân nhắc reactive transaction hoặc cơ chế version phù hợp.

## 5. Triển khai ReactiveUserDetailsService từ database

Spring Security WebFlux dùng giao diện:

```java
Mono<UserDetails> findByUsername(String username);
```

**`src/main/java/example/r2dbcauth/DatabaseReactiveUserDetailsService.java`**:

```java
package example.r2dbcauth;

import org.springframework.security.core.userdetails.ReactiveUserDetailsService;
import org.springframework.security.core.userdetails.User;
import org.springframework.security.core.userdetails.UserDetails;
import org.springframework.stereotype.Service;
import reactor.core.publisher.Mono;

@Service
public class DatabaseReactiveUserDetailsService
        implements ReactiveUserDetailsService {

    private final SqlAccountRepository repository;

    public DatabaseReactiveUserDetailsService(
            SqlAccountRepository repository) {
        this.repository = repository;
    }

    @Override
    public Mono<UserDetails> findByUsername(String username) {
        return repository.findByUsername(username)
                .flatMap(account ->
                        repository.findAuthorities(account.id())
                                .collectList()
                                .map(authorities -> User
                                        .withUsername(account.username())
                                        .password(account.passwordHash())
                                        .disabled(!account.enabled())
                                        .authorities(authorities)
                                        .build()));
    }
}
```

Vì `findByUsername` có thể không tìm thấy account, ta giữ `Mono.empty()`: `flatMap` không chạy, manager xử lý xác thực thất bại theo hợp đồng. Nếu tìm thấy account, `flatMap` nối truy vấn quyền có đầu vào `account.id()`. `collectList()` biến `Flux<GrantedAuthority>` thành danh sách authority; số role một account thông thường có giới hạn, nên thao tác gom này phù hợp.

`User.withUsername(...).password(...).disabled(...).authorities(...).build()` tạo `UserDetails` với hash và trạng thái. Không tự so sánh raw password ở đây. Mọi lỗi R2DBC từ repository được giữ thành lỗi của publisher; **không dùng `onErrorResume(e -> Mono.empty())` bừa bãi**, vì như thế sẽ biến sự cố database thành "không có user".

Tài khoản có zero role vẫn có thể được xác thực nếu password/trạng thái hợp lệ; nó sẽ không vượt qua `hasRole("ADMIN")`. Nếu policy đòi account luôn có ít nhất một role, cần kiểm tra yêu cầu đó ở nghiệp vụ/provisioning, không tự cấp role ADMIN để "vá" dữ liệu.

### Phân biệt ba tín hiệu từ service

| Tình huống | Publisher | Ý nghĩa |
| --- | --- | --- |
| Account tồn tại | `Mono.just(UserDetails)` sau khi truy vấn hoàn tất | Manager có dữ liệu để kiểm tra credential |
| Account không tồn tại | `Mono.empty()` | Không có user tương ứng |
| SQL timeout/connection error | `Mono.error(...)` | Hạ tầng dữ liệu bị lỗi, cần xử lý/giám sát khác |

`ReactiveUserDetailsService` là **bộ tải dữ liệu**, không phải authentication manager. Dù SQL trả một user, raw password có thể sai, account có thể disabled hoặc role không đủ.

## 6. Nối vào SecurityWebFilterChain và controller

**`src/main/java/example/r2dbcauth/SecurityConfiguration.java`**:

```java
package example.r2dbcauth;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.http.HttpMethod;
import org.springframework.security.authentication.ReactiveAuthenticationManager;
import org.springframework.security.authentication.UserDetailsRepositoryReactiveAuthenticationManager;
import org.springframework.security.config.annotation.web.reactive.EnableWebFluxSecurity;
import org.springframework.security.config.web.server.ServerHttpSecurity;
import org.springframework.security.core.userdetails.ReactiveUserDetailsService;
import org.springframework.security.crypto.factory.PasswordEncoderFactories;
import org.springframework.security.crypto.password.PasswordEncoder;
import org.springframework.security.web.server.SecurityWebFilterChain;

@Configuration(proxyBeanMethods = false)
@EnableWebFluxSecurity
public class SecurityConfiguration {

    @Bean
    PasswordEncoder passwordEncoder() {
        return PasswordEncoderFactories.createDelegatingPasswordEncoder();
    }

    @Bean
    ReactiveAuthenticationManager authenticationManager(
            ReactiveUserDetailsService userService,
            PasswordEncoder encoder) {
        var manager =
                new UserDetailsRepositoryReactiveAuthenticationManager(
                        userService);
        manager.setPasswordEncoder(encoder);
        return manager;
    }

    @Bean
    SecurityWebFilterChain securityWebFilterChain(
            ServerHttpSecurity http,
            ReactiveAuthenticationManager manager) {
        return http
                .authorizeExchange(exchanges -> exchanges
                        .pathMatchers(HttpMethod.GET, "/public/ping")
                            .permitAll()
                        .pathMatchers("/admin/**")
                            .hasRole("ADMIN")
                        .anyExchange().authenticated())
                .httpBasic(basic ->
                        basic.authenticationManager(manager))
                .formLogin(form -> form.disable())
                .build();
    }
}
```

**`src/main/java/example/r2dbcauth/DemoController.java`**:

```java
package example.r2dbcauth;

import org.springframework.security.core.context.ReactiveSecurityContextHolder;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;
import reactor.core.publisher.Mono;

@RestController
public class DemoController {

    @GetMapping("/public/ping")
    public Mono<String> ping() {
        return Mono.just("pong");
    }

    @GetMapping("/me")
    public Mono<String> me() {
        return ReactiveSecurityContextHolder.getContext()
                .map(ctx ->
                        "hello " + ctx.getAuthentication().getName());
    }

    @GetMapping("/admin/report")
    public Mono<String> report() {
        return Mono.just("admin report");
    }
}
```

**Tại sao cấu hình như vậy?**

- `UserDetailsRepositoryReactiveAuthenticationManager` dùng `ReactiveUserDetailsService` vừa tạo để tra user. Nó nhận `PasswordEncoder` để kiểm tra raw password với hash đã lưu; việc mã hóa password không nằm trong controller.
- `PasswordEncoderFactories.createDelegatingPasswordEncoder()` tạo encoder với id thuật toán. Hash sinh ra cho ví dụ test thường bắt đầu bằng `{bcrypt}`.
- HTTP Basic được bật rõ ràng, form login bị tắt vì demo không có giao diện đăng nhập web. **CSRF mặc định không bị tắt**; controller chỉ dùng GET. API thực tế có POST/PUT/DELETE phải đánh giá CSRF theo cơ chế credential.
- `/public/ping` cho anonymous GET; `/admin/**` cần `ROLE_ADMIN` thông qua `hasRole("ADMIN")`; request khác yêu cầu authenticated.
- `ReactiveSecurityContextHolder` đọc context theo subscription reactive, không giả định thông tin xác thực nằm cố định trong thread-local của Servlet.
- HTTP Basic mang raw username/password trong mỗi request dưới dạng Base64; production phải có HTTPS, kiểm soát brute force và audit phù hợp. Base64 **không mã hóa bảo mật**.

### 401 và 403 biểu thị các lỗi khác nhau

| Request hoặc dữ liệu | Kết quả thường thấy trong demo | Nguyên nhân |
| --- | --- | --- |
| Anonymous vào `/me` | 401 | Chưa xác thực |
| Username không tồn tại | 401 | Lookup không tìm được user |
| Password sai | 401 | Encoder không khớp |
| `enabled=false` dù password đúng | 401 | Tài khoản bị từ chối |
| User `ROLE_READER` gọi `/admin/report` | 403 | Đã xác thực, thiếu role |
| User `ROLE_ADMIN` gọi `/admin/report` | 200 | Đủ quyền |
| R2DBC database bị lỗi | Lỗi server/handler tương ứng | **Lỗi hạ tầng**, không tự coi là sai mật khẩu |

Không lộ thông tin nhạy cảm qua lỗi client, như "account tồn tại nhưng nhập sai mật khẩu", vì có thể giúp dò username. Log nội bộ nên ghi loại lỗi/correlation ID, tránh ghi Authorization header, password hoặc hash.

## 7. Kiểm thử tích hợp với H2 R2DBC và WebTestClient

Test tạo hash bằng `PasswordEncoder`, thêm account/role qua `DatabaseClient`, rồi gửi HTTP request. Không cần đưa password băm có thật vào repository. Chỉ dùng fixture cục bộ; không tái sử dụng credential test trong môi trường thật.

**`src/test/java/example/r2dbcauth/R2dbcSecurityHttpTest.java`**:

```java
package example.r2dbcauth;

import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.autoconfigure.web.reactive.AutoConfigureWebTestClient;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.r2dbc.core.DatabaseClient;
import org.springframework.security.core.userdetails.ReactiveUserDetailsService;
import org.springframework.security.crypto.password.PasswordEncoder;
import org.springframework.test.web.reactive.server.WebTestClient;
import reactor.core.publisher.Mono;
import reactor.test.StepVerifier;

@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT)
@AutoConfigureWebTestClient
class R2dbcSecurityHttpTest {

    @Autowired DatabaseClient database;
    @Autowired PasswordEncoder encoder;
    @Autowired ReactiveUserDetailsService userService;
    @Autowired WebTestClient client;

    @BeforeEach
    void seedUsers() {
        Mono<Void> seed = database.sql("DELETE FROM app_user_authorities")
                .then()
                .then(database.sql("DELETE FROM app_users").then())
                .then(insertUser("admin", "admin-test-pass", true))
                .then(insertUser("reader", "reader-test-pass", true))
                .then(insertUser("disabled", "disabled-test-pass", false))
                .then(insertAuthority("admin", "ROLE_ADMIN"))
                .then(insertAuthority("reader", "ROLE_READER"));

        StepVerifier.create(seed).verifyComplete();
    }

    private Mono<Void> insertUser(
            String username, String password, boolean enabled) {
        return database.sql("""
                    INSERT INTO app_users
                        (username, password_hash, enabled)
                    VALUES (:username, :hash, :enabled)
                    """)
                .bind("username", username)
                .bind("hash", encoder.encode(password))
                .bind("enabled", enabled)
                .fetch()
                .rowsUpdated()
                .then();
    }

    private Mono<Void> insertAuthority(String username, String authority) {
        return database.sql("""
                    INSERT INTO app_user_authorities (user_id, authority)
                    SELECT id, :authority
                      FROM app_users
                     WHERE username = :username
                    """)
                .bind("authority", authority)
                .bind("username", username)
                .fetch()
                .rowsUpdated()
                .then();
    }

    @Test
    void unknownUsernameProducesEmptyMono() {
        StepVerifier.create(userService.findByUsername("nobody"))
                .verifyComplete();
    }

    @Test
    void publicEndpointIsAccessible() {
        client.get().uri("/public/ping").exchange()
                .expectStatus().isOk()
                .expectBody(String.class).isEqualTo("pong");
    }

    @Test
    void anonymousCannotAccessProtectedEndpoint() {
        client.get().uri("/me").exchange()
                .expectStatus().isUnauthorized();
    }

    @Test
    void wrongPasswordReturnsUnauthorized() {
        client.get().uri("/me")
                .headers(h -> h.setBasicAuth("admin", "wrong"))
                .exchange()
                .expectStatus().isUnauthorized();
    }

    @Test
    void readerCanReadPrincipal() {
        client.get().uri("/me")
                .headers(h -> h.setBasicAuth("reader", "reader-test-pass"))
                .exchange()
                .expectStatus().isOk()
                .expectBody(String.class).isEqualTo("hello reader");
    }

    @Test
    void readerCannotReadAdminReport() {
        client.get().uri("/admin/report")
                .headers(h -> h.setBasicAuth("reader", "reader-test-pass"))
                .exchange()
                .expectStatus().isForbidden();
    }

    @Test
    void adminCanReadAdminReport() {
        client.get().uri("/admin/report")
                .headers(h -> h.setBasicAuth("admin", "admin-test-pass"))
                .exchange()
                .expectStatus().isOk()
                .expectBody(String.class).isEqualTo("admin report");
    }

    @Test
    void disabledAccountCannotAuthenticate() {
        client.get().uri("/me")
                .headers(h -> h.setBasicAuth("disabled", "disabled-test-pass"))
                .exchange()
                .expectStatus().isUnauthorized();
    }
```

## 8. Từ H2 demo sang PostgreSQL production

Thêm PostgreSQL driver R2DBC qua dependency của dự án Boot:

```groovy
runtimeOnly 'org.postgresql:r2dbc-postgresql'
```

**`src/main/resources/application-prod.yml`** (placeholder, không có secret thật):

```yaml
spring:
  r2dbc:
    url: "${DB_R2DBC_URL}"
    username: "${DB_USERNAME}"
    password: "${DB_PASSWORD}"
  sql:
    init:
      mode: never
```

Biến `DB_R2DBC_URL` phải có định dạng như `r2dbc:postgresql://db-host:5432/appdb` và được cung cấp từ deployment/secret manager. Không dùng JDBC URL để cấu hình `ConnectionFactory` R2DBC. Khác biệt giữa H2 và PostgreSQL gồm cú pháp DDL, collation, behavior của generated keys và kiểu cột; schema phải được di trú có kiểm soát.

Các việc cần thiết khi lên production:

1. **Migrations:** chạy Flyway/Liquibase hoặc quy trình schema có version qua môi trường được quản lý; không bật `spring.sql.init.mode=always` trên dữ liệu thật.
2. **Least privilege:** user database dùng để đọc thông tin đăng nhập nên có quyền tối thiểu. Tạo user, đổi password, cấp/thu hồi role thuộc service/quy trình được ủy quyền riêng.
3. **Indexes:** `username UNIQUE` cung cấp index tra account; xem xét thêm index theo `user_id` ở authorities dựa vào query plan và tải.
4. **Pool và timeout:** WebFlux non-blocking vẫn có thể quá tải DB. Giới hạn connection pool, request timeout, concurrency và quan sát p95/p99 login latency.
5. **TLS và secret:** cấu hình TLS phù hợp tới database, giới hạn network, không in password hash/raw password. Quản lý rotation và audit.
6. **Lỗi database:** SQL timeout/connection failure không thể trở thành user-not-found; giữ tín hiệu lỗi cho telemetry/handler phù hợp.
7. **Tính nhất quán:** tạo user + roles trong một transaction reactive khi cần atomic, dùng `R2dbcTransactionManager`/`TransactionalOperator` hoặc `@Transactional` trên phương thức reactive Spring proxy. Không dùng `JpaTransactionManager` cho luồng R2DBC.
8. **Normalization:** kiểm tra username case sensitivity/Unicode và unique constraint trên database thật, không giả định H2/PostgreSQL có collation giống nhau.

## 9. Các lỗi và bẫy bảo mật thường gặp

| Sai lầm | Hậu quả | Cách sửa |
| --- | --- | --- |
| Dùng JDBC blocking trong filter/controller reactive | Chặn event loop, giảm thông lượng | Sử dụng driver R2DBC hoặc cô lập blocking có đánh giá tải |
| Gọi `findByUsername(...).block()` trong request | Có thể bị Reactor cấm trên non-blocking thread | Trả publisher, nối `flatMap`/`map` |
| Tự gọi `subscribe()` trong service | Tách khỏi vòng đời request, mất quản lý lỗi/context | Để Spring Security subscribe |
| Nối username trực tiếp vào SQL | SQL injection | Dùng `bind("username", username)` |
| Dùng `map` khi hàm trả `Mono` | Tạo `Mono<Mono<T>>` | Dùng `flatMap` |
| Nuốt lỗi database thành `Mono.empty()` | DB lỗi bị hiểu nhầm là sai username | Giữ lỗi hạ tầng, phân loại/log/monitor an toàn |
| Lưu password thô hoặc hash SHA nhanh | Dễ lộ/đoán password | Dùng password encoder thích hợp và work factor |
| Hash thiếu prefix `{bcrypt}` với delegating encoder | Không xác thực theo thuật toán dự kiến | Migrate hash rõ ràng, không mở `{noop}` tùy tiện |
| DB lưu `ADMIN` nhưng policy cần `ROLE_ADMIN` | User login được nhưng luôn bị 403 | Thống nhất format authorities |
| Không ánh xạ `enabled` | Account vô hiệu hóa vẫn có thể đăng nhập | Tạo `UserDetails.disabled(...)` và test |
| Dùng `SELECT *`/log toàn bộ account | Tăng phạm vi dữ liệu nhạy cảm | Chỉ SELECT cột cần, che log |
| Cache UserDetails mà không invalidation | Role/password/disabled state cũ sau thay đổi | TTL/invalidation/revalidation theo rủi ro |
| Retry query vô hạn khi DB lỗi | Khuếch đại sự cố pool/DB | Retry có giới hạn với lỗi transient phù hợp |
| Mở endpoint cấp ADMIN để seed dữ liệu | Tạo đường leo thang quyền | Provision ngoài API công khai, có audit và quyền |

### Password verification và hiệu năng

Password encoder như BCrypt cần chi phí CPU đáng kể theo thiết kế. `UserDetailsRepositoryReactiveAuthenticationManager` hỗ trợ scheduler cho công việc kiểm tra password; cần đo tải và work factor phù hợp, không tự đặt phép băm CPU nặng trên Reactor Netty event loop. `DelegatingPasswordEncoder` có thể giúp nâng cấp thuật toán/hash theo chính sách. Mật khẩu sai, tài khoản disabled và username không tồn tại có thể cùng trả 401 ở HTTP Basic, nhưng nên được phân loại đúng cho logic kiểm soát và vận hành, tránh làm lộ khả năng dò tài khoản.

### Role và permission động

Đối tượng `UserDetails` được tạo từ snapshot dữ liệu lúc lookup. Khi role bị thu hồi sau đó, authentication đã cấp trước đây không tự động bị hủy ở mọi cơ chế session/token/cache. Thiết kế TTL, invalidation hoặc đánh giá quyền trực tiếp từ nguồn tin cậy theo yêu cầu nghiệp vụ. `hasRole("ADMIN")` chỉ kiểm tra role của route, không thay thế điều kiện truy vấn theo chủ sở hữu đối với từng bản ghi.

## 10. Bài tập mở rộng

1. Bổ sung `account_locked` trong bảng và ánh xạ vào `UserDetails.accountNonLocked`; viết test password đúng nhưng account bị khóa vẫn nhận 401.
2. Dùng `ReactiveCrudRepository` thay `DatabaseClient` để tra `Mono<Account>`; so sánh độ minh bạch SQL, mapping và số query đọc authority.
3. Tạo user không có authority và chứng minh `/me` có thể trả 200 nhưng `/admin/report` trả 403.
4. Mô phỏng DB unavailable: xác nhận repository phát lỗi thay vì trả `Mono.empty()`; xây dựng metric không chứa password/hash.
5. Tạo account + authorities trong transaction reactive. Cố tình tạo duplicate username và kiểm tra rollback.
6. Chuyển demo sang PostgreSQL R2DBC, chạy migration, đo thời gian xử lý login khi đồng thời nhiều request.
7. Kiểm thử thu hồi role ADMIN sau khi user đã đăng nhập theo HTTP Basic, session và cache; xác định điểm phải làm mới quyền.

**Ghi nhớ:** R2DBC tải dữ liệu người dùng/quyền bằng publisher; `ReactiveUserDetailsService` chuyển chúng thành `Mono<UserDetails>`; `ReactiveAuthenticationManager` mới xác minh password và trạng thái; `SecurityWebFilterChain` kiểm tra quyền. Bảo toàn tính reactive, sử dụng SQL parameter binding, password hashing mạnh và test phân biệt 401/403 là nền tảng cho xác thực từ database đúng và an toàn.
