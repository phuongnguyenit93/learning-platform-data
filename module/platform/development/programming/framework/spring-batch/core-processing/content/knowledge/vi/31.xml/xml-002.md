# JAXB hoặc marshaller trong XML processing

Trong Spring Batch, XML input/output thường được xử lý bằng các thành phần StAX kết hợp với cơ chế object-to-XML mapping. **JAXB** là một công nghệ binding phổ biến: nó chuyển XML thành Java object khi đọc và chuyển Java object thành XML khi ghi. Spring cung cấp abstraction `Marshaller` và `Unmarshaller` trong Spring OXM để Spring Batch có thể dùng JAXB hoặc một công nghệ mapping khác.

Với file XML lớn, mô hình thường dùng là `StaxEventItemReader` để đọc từng fragment XML và `StaxEventItemWriter` để ghi từng item thành fragment. `Jaxb2Marshaller` đảm nhiệm việc ánh xạ fragment với Java class. Cách tách này giúp xử lý dữ liệu theo chunk, quản lý transaction/checkpoint và tránh phải nạp toàn bộ tài liệu XML vào bộ nhớ.

## 1. JAXB, Marshaller và Unmarshaller là gì?

JAXB (Jakarta XML Binding trong các phiên bản mới) là cơ chế ánh xạ giữa XML và Java object dựa trên metadata như annotation hoặc binding configuration.

Hai thao tác chính:

- **Unmarshal:** đọc XML và tạo Java object.
- **Marshal:** chuyển Java object thành XML.

Ví dụ XML:

```xml
<customer>
    <id>C001</id>
    <name>Nguyen An</name>
    <email>an@example.com</email>
</customer>
```

Java object tương ứng có thể được mô tả bằng JAXB annotations. Khi unmarshal, XML được chuyển thành một `CustomerXml`. Khi marshal, object được chuyển ngược thành phần tử XML theo mapping.

Trong Spring OXM:

| Thành phần | Trách nhiệm |
|---|---|
| `Marshaller` | Chuyển object Java thành XML. |
| `Unmarshaller` | Chuyển XML thành object Java. |
| `Jaxb2Marshaller` | Adapter của Spring OXM sử dụng JAXB để thực hiện cả marshal và unmarshal. |
| `StaxEventItemReader` | Đọc XML theo từng fragment và gọi `Unmarshaller` để tạo item. |
| `StaxEventItemWriter` | Gọi `Marshaller` để ghi item thành fragment XML. |

`Marshaller` và `Unmarshaller` là abstraction của Spring OXM. Nhờ vậy, reader/writer của Spring Batch không phải phụ thuộc trực tiếp vào API JAXB trong phần điều phối file.

## 2. JAXB model và annotation

JAXB cần biết cách ánh xạ element/attribute XML sang property của Java class. Có thể dùng annotation như `@XmlRootElement`, `@XmlAccessorType`, `@XmlElement`, `@XmlAttribute` và `@XmlType`.

Ví dụ model:

```java
import jakarta.xml.bind.annotation.XmlAccessType;
import jakarta.xml.bind.annotation.XmlAccessorType;
import jakarta.xml.bind.annotation.XmlElement;
import jakarta.xml.bind.annotation.XmlRootElement;
import jakarta.xml.bind.annotation.XmlType;

@XmlRootElement(name = "customer")
@XmlAccessorType(XmlAccessType.FIELD)
@XmlType(propOrder = {"id", "name", "email"})
public class CustomerXml {

    @XmlElement(required = true)
    private String id;

    private String name;

    private String email;

    public CustomerXml() {
    }

    public CustomerXml(String id, String name, String email) {
        this.id = id;
        this.name = name;
        this.email = email;
    }

    public String getId() {
        return id;
    }

    public String getName() {
        return name;
    }

    public String getEmail() {
        return email;
    }
}
```

Một số annotation thường dùng:

| Annotation | Ý nghĩa |
|---|---|
| `@XmlRootElement` | Khai báo tên root element đại diện cho class. |
| `@XmlAccessorType` | Quy định JAXB truy cập field hay property. |
| `@XmlElement` | Ánh xạ field/property thành XML element. |
| `@XmlAttribute` | Ánh xạ field/property thành XML attribute. |
| `@XmlType` | Điều khiển thứ tự element và tên XML type. |
| `@XmlTransient` | Loại field/property khỏi quá trình binding. |
| `@XmlElementWrapper` | Tạo element wrapper cho collection. |

Trong ví dụ, `@XmlAccessorType(XmlAccessType.FIELD)` yêu cầu JAXB bind trực tiếp các field. Constructor không tham số giúp JAXB tạo object theo cách thông dụng. Nếu dùng property access hoặc adapter tùy chỉnh, cần cấu hình theo model tương ứng.

## 3. Khác biệt javax.xml.bind và jakarta.xml.bind

Đây là điểm quan trọng khi nâng cấp Spring Batch hoặc Spring Framework:

- Các ứng dụng Java EE/JAXB đời cũ thường dùng package `javax.xml.bind.*`.
- Spring Framework 6 và Spring Batch 5 thuộc hệ sinh thái Jakarta, dùng `jakarta.xml.bind.*`.
- Spring Batch 4/Spring Framework 5 thường gặp API `javax`.

Không trộn hai họ package trong cùng một model binding. Class có annotation `javax.xml.bind.annotation.XmlRootElement` không tương đương với annotation `jakarta.xml.bind.annotation.XmlRootElement` đối với JAXB runtime Jakarta.

Trên Java 11 trở lên, JAXB không còn được cung cấp sẵn trong JDK như các phiên bản Java cũ. Ứng dụng cần khai báo API và runtime phù hợp thông qua dependency management. Với Spring Boot, nên để BOM của Boot quản lý phiên bản tương thích.

## 4. Cấu hình Jaxb2Marshaller

`Jaxb2Marshaller` là implementation của Spring OXM cho JAXB. Có thể cấu hình danh sách class được binding:

```java
@Bean
Jaxb2Marshaller customerMarshaller() {
    Jaxb2Marshaller marshaller = new Jaxb2Marshaller();
    marshaller.setClassesToBeBound(CustomerXml.class);
    return marshaller;
}
```

Hoặc quét package chứa JAXB model:

```java
@Bean
Jaxb2Marshaller customerMarshaller() {
    Jaxb2Marshaller marshaller = new Jaxb2Marshaller();
    marshaller.setPackagesToScan("com.example.batch.xml.model");
    return marshaller;
}
```

Chọn một cách cấu hình rõ ràng. `setClassesToBeBound` phù hợp khi số class ít và muốn kiểm soát chính xác type được hỗ trợ. `setPackagesToScan` thuận tiện khi package có nhiều JAXB model.

Có thể cấu hình property cho marshal:

```java
@Bean
Jaxb2Marshaller customerMarshaller() {
    Jaxb2Marshaller marshaller = new Jaxb2Marshaller();
    marshaller.setClassesToBeBound(CustomerXml.class);
    marshaller.setMarshallerProperties(Map.of(
            jakarta.xml.bind.Marshaller.JAXB_FORMATTED_OUTPUT, true));
    return marshaller;
}
```

`JAXB_FORMATTED_OUTPUT` yêu cầu XML được format dễ đọc hơn. Trong production, format đẹp có thể làm file lớn hơn; nếu output chỉ dành cho máy đọc, có thể chọn cấu hình compact phù hợp.

## 5. Đọc XML bằng StaxEventItemReader và JAXB

`StaxEventItemReader<T>` dùng StAX để duyệt XML stream và tách các fragment có root element được chỉ định. Mỗi fragment được chuyển cho `Unmarshaller` để tạo một item kiểu `T`.

Ví dụ file input chứa nhiều customer:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<customers>
    <customer>
        <id>C001</id>
        <name>Nguyen An</name>
        <email>an@example.com</email>
    </customer>
    <customer>
        <id>C002</id>
        <name>Tran Binh</name>
        <email>binh@example.com</email>
    </customer>
</customers>
```

Reader có thể cấu hình như sau:

```java
@Bean
@StepScope
StaxEventItemReader<CustomerXml> customerReader(
        @Value("#{jobParameters['inputFile']}") String inputFile,
        Jaxb2Marshaller customerMarshaller) {

    StaxEventItemReader<CustomerXml> reader = new StaxEventItemReader<>();
    reader.setName("customerReader");
    reader.setResource(new FileSystemResource(inputFile));
    reader.setFragmentRootElementName("customer");
    reader.setUnmarshaller(customerMarshaller);
    reader.setSaveState(true);
    return reader;
}
```

Reader không cần unmarshal toàn bộ `<customers>` thành một collection. Nó đọc từng fragment `<customer>` và trả về một `CustomerXml` cho mỗi lần gọi `read()`.

`setFragmentRootElementName` xác định element được xem là một item. Nếu file có nhiều cấp lồng nhau, cần chọn đúng element để tránh đọc nhầm fragment. Với XML có namespace, phải kiểm thử cách reader nhận diện fragment theo local name/namespace trong phiên bản đang dùng và cấu hình XML phù hợp.

## 6. XML fragment và root document

Một tài liệu XML hoàn chỉnh có đúng một root element. Nhưng mỗi item của Spring Batch thường chỉ là một fragment con trong tài liệu đó.

Ví dụ:

```xml
<orders>
    <order>...</order>
    <order>...</order>
    <order>...</order>
</orders>
```

Trong cấu hình reader:

- `<orders>` là root của toàn bộ document.
- `<order>` là fragment root cho mỗi item.
- JAXB model `OrderXml` mô tả một `<order>`.

Nếu chọn fragment root là `orders`, reader có thể coi cả collection là một item, không phải từng order. Nếu chọn sai tên element, reader có thể không trả item hoặc trả cấu trúc không đúng mong muốn.

Khi XML chứa nhiều loại record, ví dụ `<customer>` và `<address>`, cần quyết định step đọc loại nào. Có thể cấu hình fragment root phù hợp hoặc thiết kế model/writer riêng theo từng loại record. Không nên cố unmarshal mọi element khác nhau thành một class không tương thích.

## 7. Ghi XML bằng StaxEventItemWriter và JAXB

`StaxEventItemWriter<T>` ghi mỗi item thành một XML fragment bằng `Marshaller`. Writer thường tạo một root tag bao quanh các fragment để kết quả là một XML document hợp lệ.

Ví dụ:

```java
@Bean
@StepScope
StaxEventItemWriter<CustomerXml> customerWriter(
        @Value("#{jobParameters['outputFile']}") String outputFile,
        Jaxb2Marshaller customerMarshaller) {

    StaxEventItemWriter<CustomerXml> writer = new StaxEventItemWriter<>();
    writer.setName("customerWriter");
    writer.setResource(new FileSystemResource(outputFile));
    writer.setMarshaller(customerMarshaller);
    writer.setRootTagName("customers");
    writer.setOverwriteOutput(true);
    writer.setSaveState(true);
    return writer;
}
```

Với hai item, output có dạng:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<customers>
    <customer>
        <id>C001</id>
        <name>Nguyen An</name>
        <email>an@example.com</email>
    </customer>
    <customer>
        <id>C002</id>
        <name>Tran Binh</name>
        <email>binh@example.com</email>
    </customer>
</customers>
```

`rootTagName` là root của toàn bộ output; `@XmlRootElement(name = "customer")` xác định tên fragment do JAXB marshal. Hai cấu hình này có vai trò khác nhau.

`setOverwriteOutput(true)` cho phép writer ghi output mới lên resource hiện có trong một lần chạy mới theo chính sách của writer. Với job cần restart, phải giữ state và resource ổn định; không được xem overwrite như một chỉ thị xóa file ở mọi lần mở, kể cả restart. Hãy kiểm thử lifecycle của writer với JobRepository và checkpoint.

## 8. Kết hợp reader, processor và writer trong chunk step

Reader và writer XML được sử dụng như các thành phần item thông thường trong chunk-oriented step.

```java
@Bean
Step transformCustomersStep(
        JobRepository jobRepository,
        PlatformTransactionManager transactionManager,
        StaxEventItemReader<CustomerXml> customerReader,
        ItemProcessor<CustomerXml, CustomerXml> customerProcessor,
        StaxEventItemWriter<CustomerXml> customerWriter) {

    return new StepBuilder("transformCustomersStep", jobRepository)
            .<CustomerXml, CustomerXml>chunk(100, transactionManager)
            .reader(customerReader)
            .processor(customerProcessor)
            .writer(customerWriter)
            .build();
}
```

Với chunk size 100, step đọc và xử lý tối đa 100 item cho một chunk rồi gọi writer. Transaction boundary được quản lý bởi step và transaction manager. Reader/writer XML quản lý stream và state theo hợp đồng `ItemStream`.

Processor có thể chuyển `CustomerXml` sang domain model hoặc validate dữ liệu. Nên tách XML transport model khỏi domain model khi cấu trúc XML của đối tác khác với cấu trúc dữ liệu nội bộ.

## 9. Phân biệt XML DTO và domain object

Không nhất thiết phải dùng JAXB annotation trực tiếp trên entity hoặc domain model. Một mô hình rõ ràng thường có hai lớp:

```text
XML document
     |
     v
JAXB model / transport DTO
     |
     v
ItemProcessor mapping + validation
     |
     v
Domain model
     |
     v
Writer / database / downstream system
```

Ví dụ:

```java
public record Customer(
        String customerId,
        String displayName,
        String emailAddress) {
}

@Bean
ItemProcessor<CustomerXml, Customer> customerProcessor() {
    return xml -> {
        if (xml.getId() == null || xml.getId().isBlank()) {
            throw new InvalidCustomerException("Customer id is required");
        }

        return new Customer(
                xml.getId().trim(),
                xml.getName() == null ? "" : xml.getName().trim(),
                xml.getEmail());
    };
}
```

Lợi ích của việc tách DTO:

- XML schema có thể thay đổi mà không buộc domain model thay đổi theo.
- JAXB annotation không lan vào entity hoặc service nghiệp vụ.
- Dễ kiểm thử mapping và validation riêng.
- Có thể hỗ trợ nhiều phiên bản XML đầu vào bằng các DTO/adapters khác nhau.
- Domain model không phải tuân theo constructor/no-arg hoặc property access mà JAXB yêu cầu.

Với batch đơn giản, dùng trực tiếp JAXB model làm item có thể đủ. Với tích hợp lâu dài hoặc nhiều đối tác, tách lớp thường giúp kiểm soát thay đổi tốt hơn.

## 10. XML attribute, element và collection

JAXB hỗ trợ ánh xạ XML attribute và element.

Ví dụ XML:

```xml
<order id="O-100" status="NEW">
    <customerId>C001</customerId>
    <lines>
        <line>
            <sku>SKU-01</sku>
            <quantity>2</quantity>
        </line>
        <line>
            <sku>SKU-02</sku>
            <quantity>1</quantity>
        </line>
    </lines>
</order>
```

Model JAXB có thể khai báo:

```java
@XmlRootElement(name = "order")
@XmlAccessorType(XmlAccessType.FIELD)
public class OrderXml {

    @XmlAttribute(name = "id")
    private String id;

    @XmlAttribute(name = "status")
    private String status;

    @XmlElement(name = "customerId")
    private String customerId;

    @XmlElementWrapper(name = "lines")
    @XmlElement(name = "line")
    private List<OrderLineXml> lines = new ArrayList<>();

    public OrderXml() {
    }
}
```

Model `OrderLineXml` tiếp tục khai báo `sku` và `quantity`. `@XmlElementWrapper` ánh xạ container `<lines>`, còn `@XmlElement` ánh xạ từng `<line>`.

Khi collection lớn nằm trong một fragment rất lớn, unmarshal fragment đó vẫn có thể tiêu thụ nhiều bộ nhớ. StAX reader chia theo fragment root, không tự chia nhỏ mọi collection lồng bên trong. Hãy chọn fragment root phù hợp với đơn vị xử lý nghiệp vụ.

## 11. Namespace trong JAXB

XML tích hợp giữa các hệ thống thường có namespace:

```xml
<customers xmlns="urn:example:customer:v1">
    <customer>
        <id>C001</id>
        <name>Nguyen An</name>
    </customer>
</customers>
```

JAXB model cần khai báo namespace tương ứng:

```java
@XmlRootElement(name = "customer", namespace = "urn:example:customer:v1")
@XmlAccessorType(XmlAccessType.FIELD)
public class CustomerXml {

    @XmlElement(namespace = "urn:example:customer:v1")
    private String id;

    @XmlElement(namespace = "urn:example:customer:v1")
    private String name;

    public CustomerXml() {
    }
}
```

Có thể dùng `package-info.java` với `@XmlSchema` để đặt namespace mặc định cho package model. Cách này tránh lặp namespace ở mọi field.

Khi đọc XML có namespace, cần kiểm tra fragment selection của `StaxEventItemReader` có khớp với tên element và namespace trong tài liệu hay không. Chỉ đặt `fragmentRootElementName("customer")` mà chưa kiểm tra namespace có thể không đủ cho mọi định dạng/version. Dùng fixture XML thật có namespace trong integration test.

Khi ghi, namespace và prefix có thể ảnh hưởng tới khả năng tương thích của consumer. Prefix thường không mang ý nghĩa khác nhau nếu URI namespace giống nhau, nhưng một số hệ thống cũ lại có giả định riêng. Hãy kiểm tra output theo XSD và hợp đồng tích hợp.

## 12. XML schema validation

JAXB binding xác định cách chuyển element sang field, nhưng không tự đảm bảo mọi quy tắc XSD của đối tác đều được thỏa mãn nếu không cấu hình validation.

`Jaxb2Marshaller` có thể được cấu hình với schema resource để validate XML trong quá trình marshal/unmarshal:

```java
@Bean
Jaxb2Marshaller customerMarshaller() {
    Jaxb2Marshaller marshaller = new Jaxb2Marshaller();
    marshaller.setClassesToBeBound(CustomerXml.class);
    marshaller.setSchemas(
            new ClassPathResource("xsd/customer-v1.xsd"));
    return marshaller;
}
```

Khi bật schema validation, XML không phù hợp schema có thể gây lỗi unmarshal. Output được marshal cũng có thể bị từ chối nếu không thỏa schema. Cần kiểm thử cả tài liệu hợp lệ và không hợp lệ.

Schema validation có thể tốn CPU. Với file lớn, hãy đo hiệu năng và chọn vị trí validate phù hợp. Nếu cần báo lỗi theo item, đọc theo fragment và xác định exception ở từng fragment; nếu lỗi schema áp dụng cho cấu trúc toàn document, có thể cần bước validate file hoàn chỉnh trước khi xử lý.

## 13. Validation nghiệp vụ sau khi unmarshal

Schema validation và validation nghiệp vụ là hai tầng khác nhau:

- XSD kiểm tra cấu trúc XML, element, attribute, kiểu dữ liệu và cardinality theo schema.
- Validation nghiệp vụ kiểm tra quy tắc như customer ID có tồn tại, amount phải dương, trạng thái order có hợp lệ hay không.

Ví dụ, XSD có thể xác nhận `<amount>` là decimal. Nhưng chỉ processor hoặc validator nghiệp vụ mới biết đơn hàng có được phép có amount bằng 0 hay không.

Nên phân loại lỗi rõ:

- XML sai cú pháp hoặc fragment không thể unmarshal: lỗi parsing/mapping.
- XML hợp lệ theo XSD nhưng vi phạm quy tắc nghiệp vụ: lỗi validation nghiệp vụ.
- Database hoặc API không khả dụng: lỗi hạ tầng.

Skip policy có thể cho phép bỏ qua một số lỗi item cụ thể, nhưng không nên skip mọi exception từ JAXB hoặc StAX. Nếu toàn file sai namespace/schema, tiếp tục bỏ qua từng fragment có thể làm mất phần lớn dữ liệu.

## 14. Encoding và XML declaration

Encoding phải nhất quán giữa file, XML declaration và resource reader/writer.

Ví dụ XML declaration:

```xml
<?xml version="1.0" encoding="UTF-8"?>
```

Với writer, có thể cấu hình encoding:

```java
writer.setEncoding("UTF-8");
```

Với reader, StAX parser đọc XML theo encoding khai báo trong XML declaration hoặc encoding được xác định từ resource/parser configuration. Không nên chuyển file sang String bằng charset mặc định của máy rồi mới đưa vào parser.

Các điểm cần xác nhận:

- File nguồn thực sự dùng UTF-8, UTF-16 hay charset legacy khác.
- XML declaration có khớp encoding thực tế không.
- Ký tự có dấu tiếng Việt và ký tự ngoài ASCII được đọc/ghi đúng.
- Consumer có yêu cầu XML declaration, BOM hoặc encoding cụ thể không.
- Không có bước trung gian làm thay đổi charset hoặc line ending ngoài ý muốn.

## 15. XML parser security

XML có thể chứa DTD hoặc external entity. Nếu parser cho phép resolve external entity, tài liệu không tin cậy có thể khiến ứng dụng đọc file cục bộ hoặc gọi tài nguyên mạng ngoài dự kiến (XXE).

Với StAX, nên cấu hình `XMLInputFactory` để tắt DTD và external entities nếu ứng dụng không cần các tính năng đó:

```java
XMLInputFactory inputFactory = XMLInputFactory.newFactory();
inputFactory.setProperty(XMLInputFactory.SUPPORT_DTD, false);
inputFactory.setProperty(
        "javax.xml.stream.isSupportingExternalEntities", false);

StaxEventItemReader<CustomerXml> reader = new StaxEventItemReader<>();
reader.setName("customerReader");
reader.setResource(resource);
reader.setFragmentRootElementName("customer");
reader.setUnmarshaller(customerMarshaller);
reader.setXmlInputFactory(inputFactory);
```

Property hỗ trợ có thể phụ thuộc StAX provider. Cần kiểm thử cấu hình trên provider thực tế và xác nhận parser từ chối hoặc không resolve external entity như mong đợi. Không dựa vào default của môi trường production.

Nếu XSD import/include tài nguyên ngoài, hãy quản lý schema resource bằng cấu hình tin cậy hoặc resolver phù hợp; không mở quyền truy cập mạng tùy tiện chỉ để validation hoạt động.

## 16. Xử lý lỗi marshal/unmarshal

Lỗi XML có thể phát sinh ở nhiều giai đoạn:

| Giai đoạn | Ví dụ lỗi |
|---|---|
| StAX parse | XML sai cú pháp, tag không đóng, encoding lỗi. |
| Fragment selection | Không tìm thấy element cần đọc hoặc chọn sai root. |
| JAXB unmarshal | Element/attribute không ánh xạ được, conversion lỗi, schema violation. |
| Processor | XML đã parse nhưng vi phạm nghiệp vụ. |
| JAXB marshal | Object thiếu dữ liệu bắt buộc hoặc mapping không hợp lệ. |
| File output | Không có quyền ghi, hết dung lượng, lỗi I/O. |

Không nên cấu hình skip cho tất cả `Exception`. XML sai cú pháp ở đầu tài liệu có thể khiến parser không thể tiếp tục tìm fragment phía sau. Lỗi I/O hoặc lỗi cấu hình marshaller thường là lỗi step cần dừng.

Nếu chỉ một fragment không hợp lệ và parser có thể tiếp tục an toàn, có thể thiết kế cơ chế ghi nhận lỗi theo item. Tuy nhiên, không phải mọi lỗi StAX/JAXB đều cho phép reader khôi phục vị trí và tiếp tục. Hãy kiểm thử bằng file lỗi thực tế và xác định rõ reader có thể tiếp tục sau exception hay không.

## 17. Dependency cho JAXB và Spring OXM

Trong ứng dụng dùng Spring Batch 5/Spring Framework 6, có thể khai báo Spring OXM và JAXB runtime phù hợp:

```groovy
dependencies {
    implementation("org.springframework:spring-oxm")
    runtimeOnly("org.glassfish.jaxb:jaxb-runtime")
}
```

Trong nhiều dự án Spring Boot, dependency management quản lý version cho Spring Framework và JAXB runtime. Nếu không dùng BOM, cần chọn version tương thích với Jakarta JAXB API được Spring OXM yêu cầu.

`spring-batch-infrastructure` cung cấp các reader/writer XML của Spring Batch; `spring-oxm` cung cấp abstraction và `Jaxb2Marshaller`. Hãy xác nhận các module cần thiết đã có trong dependency graph của ứng dụng.

## 18. Kiểm thử Jaxb2Marshaller độc lập

Có thể kiểm tra JAXB binding mà không cần khởi chạy job. Test marshal object thành XML và unmarshal lại để xác nhận mapping.

```java
class CustomerMarshallerTest {

    private final Jaxb2Marshaller marshaller = new Jaxb2Marshaller();

    @BeforeEach
    void setUp() throws Exception {
        marshaller.setClassesToBeBound(CustomerXml.class);
        marshaller.afterPropertiesSet();
    }

    @Test
    void marshalsAndUnmarshalsCustomer() throws Exception {
        CustomerXml customer = new CustomerXml(
                "C001", "Nguyen An", "an@example.com");

        StringWriter output = new StringWriter();
        marshaller.marshal(customer, new StreamResult(output));

        String xml = output.toString();
        assertThat(xml).contains("<customer>");
        assertThat(xml).contains("<id>C001</id>");

        CustomerXml restored = (CustomerXml) marshaller.unmarshal(
                new StreamSource(new StringReader(xml)));

        assertThat(restored.getId()).isEqualTo("C001");
        assertThat(restored.getName()).isEqualTo("Nguyen An");
    }
}
```

Test này chỉ xác nhận JAXB mapping và không kiểm tra StAX reader/writer của Spring Batch. Nếu class dùng namespace, adapter hoặc schema validation, hãy thêm fixture XML thể hiện đúng các trường hợp đó.

## 19. Kiểm thử StaxEventItemReader

Reader test cần xác nhận việc tìm fragment và unmarshal từng item. Dùng XML fixture có nhiều record và một số trường hợp biên:

```java
@Test
void readsEachCustomerFragment() throws Exception {
    StaxEventItemReader<CustomerXml> reader = new StaxEventItemReader<>();
    reader.setName("customerReader");
    reader.setResource(new ClassPathResource("customers.xml"));
    reader.setFragmentRootElementName("customer");
    reader.setUnmarshaller(customerMarshaller);

    reader.afterPropertiesSet();
    reader.open(new ExecutionContext());
    try {
        CustomerXml first = reader.read();
        CustomerXml second = reader.read();
        CustomerXml end = reader.read();

        assertThat(first.getId()).isEqualTo("C001");
        assertThat(second.getId()).isEqualTo("C002");
        assertThat(end).isNull();
    } finally {
        reader.close();
    }
}
```

Test nên bao gồm:

- Document có nhiều fragment.
- Document không có fragment cần đọc.
- Fragment lồng nhau hoặc có element cùng tên ở nhiều cấp.
- Namespace mặc định và namespace có prefix.
- XML sai cú pháp.
- Encoding và ký tự Unicode.
- Schema validation nếu được bật.

## 20. Kiểm thử StaxEventItemWriter

Writer test có thể mở writer, ghi một số item và kiểm tra XML output.

```java
@Test
void writesCustomerFragmentsInsideRootElement() throws Exception {
    Path output = tempDir.resolve("customers.xml");

    StaxEventItemWriter<CustomerXml> writer = new StaxEventItemWriter<>();
    writer.setName("customerWriter");
    writer.setResource(new FileSystemResource(output));
    writer.setMarshaller(customerMarshaller);
    writer.setRootTagName("customers");
    writer.setOverwriteOutput(true);

    writer.afterPropertiesSet();
    writer.open(new ExecutionContext());
    try {
        writer.write(Chunk.of(
                new CustomerXml("C001", "Nguyen An", "an@example.com"),
                new CustomerXml("C002", "Tran Binh", "binh@example.com")));
    } finally {
        writer.close();
    }

    String xml = Files.readString(output);
    assertThat(xml).contains("<customers");
    assertThat(xml).contains("<customer>");
    assertThat(xml).contains("<id>C001</id>");
    assertThat(xml).contains("<id>C002</id>");
}
```

Trong test thực tế, nên parse file output bằng XML parser và kiểm tra cấu trúc/namespace thay vì chỉ so sánh chuỗi, vì XML có thể thay đổi whitespace hoặc namespace prefix mà vẫn tương đương về cấu trúc.

## 21. Kiểm thử tích hợp XML chunk step

Unit test cho marshaller, reader và writer chưa xác nhận transaction, checkpoint và JobRepository. Với job quan trọng, hãy thêm integration test:

1. Chuẩn bị XML input fixture.
2. Khởi chạy job bằng JobLauncherTestUtils với JobParameters chỉ định input/output.
3. Xác nhận JobExecution và StepExecution hoàn tất.
4. Parse output XML và kiểm tra số item cùng giá trị.
5. Mô phỏng lỗi ở một chunk rồi restart cùng JobInstance.
6. Xác nhận writer không tạo fragment trùng hoặc thiếu.
7. Kiểm tra metadata và ExecutionContext nếu reader/writer cần restart.

Nếu job dùng schema validation, namespace hoặc XSD import, test nên chạy bằng schema resource thực tế. Một unit test dùng XML tối giản không đủ xác nhận hợp đồng XML với hệ thống đối tác.

## 22. Khi nào dùng JAXB, khi nào dùng marshaller khác?

JAXB phù hợp khi:

- XML có schema hoặc cấu trúc tương đối ổn định.
- Muốn khai báo mapping bằng annotation hoặc binding configuration.
- Cần chuyển XML thành Java DTO có kiểu dữ liệu rõ ràng.
- Cần schema validation và kiểm soát namespace/element.

Spring OXM abstraction cho phép dùng các marshaller/unmarshaller khác nếu dự án có yêu cầu đặc biệt. Chọn công nghệ theo định dạng, schema, hiệu năng và khả năng bảo trì. Không nên chọn JAXB chỉ vì nó phổ biến nếu dữ liệu thực tế là XML fragment rất linh hoạt hoặc cần xử lý streaming ở cấp node thay vì tạo object lớn.

Với XML rất lớn, cần tránh unmarshal một root collection khổng lồ thành một object chứa toàn bộ dữ liệu. Hãy chọn fragment root sao cho mỗi item có kích thước bộ nhớ hợp lý. Nếu một fragment vẫn chứa hàng triệu phần tử lồng nhau, cần chia nhỏ định dạng hoặc dùng StAX cursor/event processing chuyên biệt.

## 23. Những lỗi thường gặp khi dùng JAXB hoặc marshaller

| Triệu chứng | Nguyên nhân thường gặp | Hướng xử lý |
|---|---|---|
| JAXB không nhận diện class | Chưa cấu hình class/package trong `Jaxb2Marshaller`. | Dùng `setClassesToBeBound` hoặc `setPackagesToScan`. |
| `javax` và `jakarta` không tương thích | Model và runtime dùng hai hệ package khác nhau. | Đồng bộ theo Spring Batch/Spring Framework version. |
| Reader không trả item | Chọn sai fragment root hoặc XML có namespace chưa được xử lý đúng. | Kiểm tra XML fixture và fragment selection. |
| Cả collection bị đọc thành một item | Chọn root document thay vì element của từng record. | Chọn fragment root như `customer` hoặc `order`. |
| JAXB báo thiếu constructor | Model không đáp ứng cách tạo object của JAXB. | Cung cấp constructor phù hợp hoặc cấu hình binding tương ứng. |
| Field luôn null | Sai tên element, namespace hoặc annotation access strategy. | Kiểm tra `@XmlElement`, `@XmlAccessorType` và namespace URI. |
| Output sai root | `rootTagName` và `@XmlRootElement` bị nhầm vai trò. | Root writer bao toàn document; JAXB root xác định fragment. |
| XML không đúng schema | Mapping hoặc dữ liệu không phù hợp XSD. | Bật schema validation và test với schema chính thức. |
| Ký tự tiếng Việt bị lỗi | Encoding không nhất quán. | Cấu hình UTF-8/charset đúng và test dữ liệu Unicode. |
| Parser truy cập tài nguyên ngoài | DTD/external entity được cho phép. | Tắt DTD/external entities và kiểm thử StAX provider. |
| Job tốn bộ nhớ | Unmarshal fragment quá lớn hoặc giữ collection trong RAM. | Chọn fragment nhỏ hơn và xử lý theo chunk. |
| Restart tạo XML fragment trùng | Writer state không được lưu/khôi phục hoặc resource thay đổi. | Giữ `saveState`, writer name và output path ổn định. |
| Skip hàng loạt record | Lỗi toàn file bị coi là lỗi từng item. | Dừng job và kiểm tra schema, namespace, encoding, fragment root. |

## 24. Quy trình triển khai XML processing với JAXB

Khi tích hợp một XML file mới vào Spring Batch, có thể đi theo trình tự:

1. **Đọc XML mẫu và XSD:** xác định root document, fragment root, namespace, encoding và cardinality.
2. **Tạo JAXB model:** khai báo element, attribute, collection và thứ tự theo schema.
3. **Cấu hình `Jaxb2Marshaller`:** đăng ký class/package, schema và property cần thiết.
4. **Cấu hình StAX reader:** chọn resource, fragment root, unmarshaller, encoding và checkpoint.
5. **Tạo processor:** chuyển XML DTO sang domain model và validate nghiệp vụ.
6. **Cấu hình StAX writer nếu cần:** marshaller, root tag, resource, encoding và save state.
7. **Thiết kế fault tolerance:** phân loại lỗi XML, dữ liệu và hạ tầng; chỉ skip lỗi item có thể phục hồi theo nghiệp vụ.
8. **Bảo vệ parser:** tắt DTD/external entities nếu không cần và kiểm tra schema resource tin cậy.
9. **Kiểm thử riêng:** marshal/unmarshal, fragment reader, writer, namespace và schema validation.
10. **Kiểm thử tích hợp:** chạy chunk step, transaction, restart và kiểm tra output XML cuối cùng.

Giữ lại XML fixture từ hệ thống nguồn đã được xác nhận. Test trên fixture thật thường phát hiện lỗi namespace, padding, thứ tự element và encoding mà XML tự tạo đơn giản không thể hiện.

## 25. Những điểm cần ghi nhớ

- JAXB chuyển đổi XML và Java object; marshal là object sang XML, unmarshal là XML sang object.
- Spring OXM định nghĩa abstraction `Marshaller` và `Unmarshaller`; `Jaxb2Marshaller` triển khai cả hai bằng JAXB.
- Spring Batch dùng `StaxEventItemReader` để đọc fragment XML và `StaxEventItemWriter` để ghi fragment theo chunk.
- `fragmentRootElementName` chọn element đại diện cho một item; `rootTagName` của writer bao các fragment thành document.
- JAXB annotations như `@XmlRootElement`, `@XmlElement`, `@XmlAttribute`, `@XmlAccessorType` và `@XmlType` mô tả mapping.
- Spring Framework 6/Spring Batch 5 dùng Jakarta package `jakarta.xml.bind`; hệ cũ có thể dùng `javax.xml.bind`. Không trộn hai loại.
- `Jaxb2Marshaller` cần đăng ký class/package được binding và có thể cấu hình schema/property.
- XML schema validation khác validation nghiệp vụ; processor vẫn cần kiểm tra quy tắc domain.
- Encoding, namespace và fragment selection phải khớp với hợp đồng XML của nguồn/đích.
- Với XML không tin cậy, cần tắt DTD/external entities và xác minh StAX provider.
- Chọn fragment root có kích thước hợp lý để giữ lợi ích streaming và chunk processing.
- Reader/writer cần lưu state và resource ổn định nếu job phải restart.
- Kiểm thử marshaller, reader, writer và integration step riêng biệt; parse output XML thay vì chỉ so sánh chuỗi khi có thể.

JAXB hoặc một marshaller khác đảm nhiệm việc ánh xạ XML với Java object, còn Spring Batch quản lý cách các item được đọc, xử lý, ghi theo chunk và khôi phục khi restart. Kết hợp `Jaxb2Marshaller` với StAX reader/writer giúp xử lý XML theo fragment mà không cần nạp toàn bộ tài liệu vào bộ nhớ. Để kết quả đáng tin cậy, cần định nghĩa đúng JAXB model, namespace, schema, encoding, fragment root và chính sách lỗi theo hợp đồng dữ liệu thực tế.
