# HAL collection

Trong HAL, **collection** là một tài nguyên biểu diễn một tập hợp tài nguyên cùng loại hoặc cùng một tiêu chí truy vấn. Response collection thường cung cấp self link đến chính collection, nhúng các phần tử dưới thuộc tính _embedded và công bố những link điều hướng như next, prev, first hoặc last khi có phân trang.

Spring HATEOAS dùng CollectionModel để biểu diễn collection có hypermedia links. Mỗi phần tử có thể là EntityModel hoặc một model tùy chỉnh kế thừa RepresentationModel, nhờ đó item có dữ liệu và link riêng. Khi serialize bằng HAL, collection model được chuyển thành cấu trúc HAL JSON với _embedded và _links.

Collection resource là một tài nguyên ở cấp tập hợp, có URI và semantics riêng. Nó không chỉ là một Java List được serialize thành JSON array. Client nên khám phá collection qua relation link từ tài nguyên cha hoặc entry point, sau đó theo các link được server cung cấp để duyệt collection và từng item.

Sau bài học, bạn có thể:

- Giải thích cấu trúc HAL collection và vai trò của _embedded, _links.
- Phân biệt collection resource với JSON array hoặc danh sách JPA.
- Tạo collection response bằng CollectionModel và assembler.
- Tạo self link cho collection và item links cho từng phần tử.
- Đặt tên embedded relation bằng @Relation và hiểu vai trò của LinkRelationProvider.
- Xử lý collection rỗng, phân trang, lọc và sắp xếp.
- Thương lượng media type HAL và kiểm thử hợp đồng collection.

## HAL collection là gì?

HAL (Hypertext Application Language) là một định dạng biểu diễn hypermedia cho JSON. HAL xác định cách thể hiện link bằng _links và tài nguyên được nhúng bằng _embedded. Một collection HAL thường có các phần:

- _links ở cấp ngoài chứa link đến collection và các đích điều hướng khác.
- _embedded chứa các representation của từng item, được nhóm theo relation.
- Mỗi embedded item có thể có dữ liệu và _links riêng.
- Metadata bổ sung có thể mô tả trạng thái collection hoặc phân trang, tùy hợp đồng API.

Ví dụ collection đơn hàng:

~~~json
{
  "_embedded": {
    "orders": [
      {
        "id": 42,
        "orderNumber": "ORD-0042",
        "status": "PAID",
        "_links": {
          "self": {
            "href": "https://api.example.com/orders/42"
          }
        }
      },
      {
        "id": 43,
        "orderNumber": "ORD-0043",
        "status": "PENDING_PAYMENT",
        "_links": {
          "self": {
            "href": "https://api.example.com/orders/43"
          }
        }
      }
    ]
  },
  "_links": {
    "self": {
      "href": "https://api.example.com/orders"
    }
  }
}
~~~

Trong response:

- _embedded.orders là tập hợp representation của các đơn hàng.
- _links.self ở cấp ngoài trỏ đến collection.
- _links.self trong từng item trỏ đến tài nguyên đơn hàng tương ứng.

Collection và item là hai cấp tài nguyên khác nhau. Self link của collection không thay thế self link của từng item.

## Collection resource khác JSON array

Một controller trả List<OrderResponse> có thể tạo JSON array thuần:

~~~json
[
  {
    "id": 42,
    "orderNumber": "ORD-0042"
  },
  {
    "id": 43,
    "orderNumber": "ORD-0043"
  }
]
~~~

JSON array cho biết có các phần tử, nhưng không tự cung cấp:

- URI của collection hiện tại.
- Link đến item độc lập.
- Link đến trang tiếp theo hoặc trước đó.
- Relation để khám phá các thao tác liên quan.
- Metadata hypermedia cho client.

HAL collection có thể công bố những thông tin đó:

~~~json
{
  "_embedded": {
    "orders": [
      {
        "id": 42,
        "orderNumber": "ORD-0042",
        "_links": {
          "self": { "href": "/orders/42" }
        }
      }
    ]
  },
  "_links": {
    "self": { "href": "/orders" },
    "create": { "href": "/orders" }
  }
}
~~~

Link create trong ví dụ chỉ là relation do API thiết kế; nếu client cần biết method và request fields, hãy công bố affordance bằng media type hỗ trợ mô tả thao tác. HAL link cơ bản chỉ cung cấp relation và URI.

Không nên mặc định mọi Java collection sẽ tự được bọc thành HAL collection. Để có cấu trúc HAL và links ở cấp collection, hãy trả model hypermedia như CollectionModel hoặc PagedModel.

## _embedded và _links trong collection

Hai thuộc tính này có vai trò khác nhau:

| Thuộc tính | Nội dung | Ví dụ |
| --- | --- | --- |
| _embedded | Representation của tài nguyên được nhúng | _embedded.orders |
| _links | Link điều hướng đến collection, item hoặc tài nguyên liên quan | _links.self, _links.next |

Collection có thể chứa embedded item và đồng thời cung cấp link đến cùng item. Embedded item mang dữ liệu hiện tại; link cho phép client truy cập tài nguyên độc lập hoặc tải biểu diễn mới hơn.

Một embedded item có thể có:

- Thuộc tính nghiệp vụ như ID, trạng thái, tên hoặc thời điểm tạo.
- Self link đến chính item.
- Link đến tài nguyên liên quan như customer, invoice hoặc product.
- Affordance mô tả thao tác, nếu media type được chọn hỗ trợ.

Relation trong _embedded xác định loại item được nhóm. Client nên truy cập theo relation thay vì phụ thuộc vào thứ tự thuộc tính hoặc tên Java class.

## CollectionModel trong Spring HATEOAS

CollectionModel<T> là kiểu wrapper biểu diễn một collection cùng links ở cấp collection. Nó cho phép controller trả dữ liệu tập hợp dưới dạng hypermedia thay vì một danh sách thuần.

Ví dụ tạo collection đơn giản:

~~~java
import java.util.List;

import org.springframework.hateoas.CollectionModel;
import org.springframework.hateoas.EntityModel;
import org.springframework.hateoas.Link;

List<EntityModel<OrderResponse>> orders = List.of(
    EntityModel.of(new OrderResponse(42L, "ORD-0042", "PAID")),
    EntityModel.of(new OrderResponse(43L, "ORD-0043", "DRAFT"))
);

CollectionModel<EntityModel<OrderResponse>> collection =
    CollectionModel.of(orders, Link.of("/orders").withSelfRel());
~~~

Ví dụ trên tạo collection model với self link. Trong API thực tế, mỗi item thường cần self link riêng; phần tiếp theo trình bày cách thực hiện bằng assembler.

### Các model thường gặp

| Kiểu | Ý nghĩa |
| --- | --- |
| RepresentationModel<T> | Base class cho model tùy chỉnh có links |
| EntityModel<T> | Bọc một object cùng links |
| CollectionModel<T> | Bọc nhiều phần tử cùng links ở cấp collection |
| PagedModel<T> | Biểu diễn collection phân trang và metadata page |

CollectionModel có thể chứa DTO thuần, EntityModel hoặc representation model tùy chỉnh. Nếu muốn mỗi item có link riêng, hãy dùng EntityModel hoặc một kiểu model có links.

## Xây dựng HAL collection bằng assembler

Giả sử ứng dụng có domain object và DTO:

~~~java
public record Order(
    Long id,
    String orderNumber,
    String status
) {}

public record OrderResponse(
    Long id,
    String orderNumber,
    String status
) {}
~~~

Assembler chuyển domain object thành item representation:

~~~java
import org.springframework.hateoas.server.RepresentationModelAssembler;
import org.springframework.stereotype.Component;

import static org.springframework.hateoas.server.mvc.WebMvcLinkBuilder.linkTo;
import static org.springframework.hateoas.server.mvc.WebMvcLinkBuilder.methodOn;

@Component
class OrderModelAssembler
        implements RepresentationModelAssembler<Order, OrderModel> {

    @Override
    public OrderModel toModel(Order order) {
        OrderModel model = new OrderModel(
            order.id(), order.orderNumber(), order.status());

        model.add(linkTo(methodOn(OrderController.class)
            .one(order.id())).withSelfRel());
        return model;
    }
}
~~~

Assembler tạo self link cho từng item từ mapping controller. Nếu mapping đổi, link builder sẽ lấy URI theo mapping mới.

Controller tạo collection:

~~~java
import java.util.List;

import org.springframework.hateoas.CollectionModel;
import org.springframework.hateoas.MediaTypes;
import org.springframework.http.HttpStatus;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;
import org.springframework.web.server.ResponseStatusException;

import static org.springframework.hateoas.server.mvc.WebMvcLinkBuilder.linkTo;
import static org.springframework.hateoas.server.mvc.WebMvcLinkBuilder.methodOn;

@RestController
@RequestMapping("/orders")
class OrderController {

    private final OrderService orderService;
    private final OrderModelAssembler assembler;

    OrderController(OrderService orderService, OrderModelAssembler assembler) {
        this.orderService = orderService;
        this.assembler = assembler;
    }

    @GetMapping(produces = MediaTypes.HAL_JSON_VALUE)
    CollectionModel<OrderModel> all() {
        List<OrderModel> content =
            orderService.findAll().stream()
                .map(assembler::toModel)
                .toList();

        return CollectionModel.of(content,
            linkTo(methodOn(OrderController.class).all()).withSelfRel());
    }

    @GetMapping("/{id}")
    OrderModel one(@PathVariable Long id) {
        Order order = orderService.findById(id)
            .orElseThrow(() -> new ResponseStatusException(HttpStatus.NOT_FOUND));
        return assembler.toModel(order);
    }
}
~~~

Ví dụ giả định OrderService.findAll() trả về List<Order>, findById() trả về Optional<Order>, và OrderModel được khai báo với @Relation như phần tiếp theo. Khi client gửi Accept: application/hal+json, Spring HATEOAS serialize collection model thành HAL JSON.

Response có cấu trúc khái quát:

~~~json
{
  "_embedded": {
    "orders": [
      {
        "id": 42,
        "orderNumber": "ORD-0042",
        "status": "PAID",
        "_links": {
          "self": { "href": "/orders/42" }
        }
      }
    ]
  },
  "_links": {
    "self": { "href": "/orders" }
  }
}
~~~

Trong ví dụ này, OrderModel khai báo @Relation với collectionRelation là orders, nên relation nhúng được xác định rõ. Nếu dùng EntityModel<OrderResponse> mà không có metadata relation tương ứng, LinkRelationProvider sẽ suy ra relation từ kiểu content và cấu hình hiện hành; hãy kiểm tra JSON thực tế hoặc cấu hình tên rõ ràng nếu relation là một phần quan trọng của hợp đồng API.

## Tùy chỉnh collection relation bằng @Relation

Spring HATEOAS dùng LinkRelationProvider để xác định relation của representation. Với model tùy chỉnh, có thể dùng annotation @Relation để đặt tên item relation và collection relation:

~~~java
import org.springframework.hateoas.RepresentationModel;
import org.springframework.hateoas.server.core.Relation;

@Relation(value = "order", collectionRelation = "orders")
public class OrderModel extends RepresentationModel<OrderModel> {

    private final Long id;
    private final String orderNumber;
    private final String status;

    public OrderModel(Long id, String orderNumber, String status) {
        this.id = id;
        this.orderNumber = orderNumber;
        this.status = status;
    }

    public Long getId() {
        return id;
    }

    public String getOrderNumber() {
        return orderNumber;
    }

    public String getStatus() {
        return status;
    }
}
~~~

Trong annotation:

- value là relation của một item.
- collectionRelation là relation dùng khi một collection các model được nhúng.

Khi trả CollectionModel<OrderModel>, collection relation được cấu hình là orders. Điều này tránh phụ thuộc vào tên class hoặc quy tắc pluralization mặc định.

Assembler ở phần trước đã trả về OrderModel và thêm self link cho mỗi item. Vì OrderModel khai báo collectionRelation là orders, serializer dùng relation đó khi nhúng collection.

Nếu muốn dùng phương thức toCollectionModel thay cho việc stream và gọi toModel thủ công, controller có thể viết:

~~~java
@GetMapping(produces = MediaTypes.HAL_JSON_VALUE)
CollectionModel<OrderModel> all() {
    return assembler.toCollectionModel(orderService.findAll())
        .add(linkTo(methodOn(OrderController.class).all()).withSelfRel());
}
~~~

RepresentationModelAssembler cung cấp phương thức chuyển collection bằng cách gọi toModel cho từng phần tử rồi bọc kết quả trong CollectionModel. Self link cấp collection được thêm riêng.

### Collection rỗng và fallback type

Collection rỗng vẫn là một tài nguyên hợp lệ. Tuy nhiên, khi không có phần tử, serializer không thể suy luận relation từ instance item. Có thể cung cấp fallback type:

~~~java
CollectionModel<OrderModel> empty =
    CollectionModel.<OrderModel>empty()
        .withFallbackType(OrderModel.class)
        .add(linkTo(methodOn(OrderController.class).all()).withSelfRel());
~~~

Fallback type cho biết kiểu representation dự kiến ngay cả khi collection không có phần tử. Điều này giúp relation được xác định ổn định trong response rỗng. Hãy kiểm tra cấu trúc thực tế với phiên bản Spring HATEOAS của ứng dụng.

## Collection có relation và link điều hướng

Collection thường cung cấp nhiều link ngoài self:

| Relation | Ý nghĩa |
| --- | --- |
| self | Collection hiện tại |
| next | Trang kế tiếp |
| prev | Trang trước |
| first | Trang đầu |
| last | Trang cuối |
| search | Điểm khám phá hoặc template tìm kiếm |
| profile | Mô tả profile của representation |

Không phải collection nào cũng cần mọi relation. Chỉ công bố link có ý nghĩa trong ngữ cảnh hiện tại. Ví dụ, trang đầu không có prev; trang cuối không có next.

Link relation là phần hợp đồng công khai. Giữ semantics của relation ổn định để client có thể điều hướng mà không phải dựa vào URI path cụ thể.

### Collection link và item link

Collection link trỏ đến tập hợp; item link trỏ đến một tài nguyên cụ thể. Không dùng một link self ở cấp collection để thay cho link self của từng item.

Ví dụ:

~~~json
{
  "_embedded": {
    "orders": [
      {
        "id": 42,
        "_links": {
          "self": { "href": "/orders/42" },
          "invoice": { "href": "/orders/42/invoice" }
        }
      }
    ]
  },
  "_links": {
    "self": { "href": "/orders" },
    "next": { "href": "/orders?page=1&size=20" }
  }
}
~~~

Client theo next để tiếp tục collection và theo self bên trong item để tải lại đơn hàng. Relation invoice là link đến tài nguyên liên quan của item đó.

## Phân trang HAL collection

Khi collection có nhiều phần tử, API nên phân trang để giới hạn payload và chi phí xử lý. Spring HATEOAS tích hợp với Spring Data thông qua PagedResourcesAssembler, chuyển Page<T> thành PagedModel<D>.

Ví dụ:

~~~java
import org.springframework.data.domain.Page;
import org.springframework.data.domain.Pageable;
import org.springframework.data.web.PagedResourcesAssembler;
import org.springframework.hateoas.PagedModel;

@GetMapping(produces = MediaTypes.HAL_JSON_VALUE)
PagedModel<OrderModel> all(
        Pageable pageable,
        PagedResourcesAssembler<Order> pagedAssembler) {

    Page<Order> page = orderService.findAll(pageable);
    return pagedAssembler.toModel(page, assembler);
}
~~~

Ví dụ giả định assembler triển khai RepresentationModelAssembler<Order, OrderModel> và service trả Page<Order>. Trong controller thực tế, dùng một method collection có phân trang thay cho method collection không tham số cùng mapping, hoặc thiết kế mapping riêng để tránh xung đột.

HAL response có thể chứa metadata page:

~~~json
{
  "_embedded": {
    "orders": [
      {
        "id": 42,
        "orderNumber": "ORD-0042",
        "_links": {
          "self": { "href": "/orders/42" }
        }
      }
    ]
  },
  "_links": {
    "self": { "href": "/orders?page=0&size=20" },
    "first": { "href": "/orders?page=0&size=20" },
    "next": { "href": "/orders?page=1&size=20" },
    "last": { "href": "/orders?page=4&size=20" }
  },
  "page": {
    "size": 20,
    "totalElements": 85,
    "totalPages": 5,
    "number": 0
  }
}
~~~

Tên thuộc tính metadata và các relation phụ thuộc cấu hình paginator và phiên bản. Client nên theo link do server trả về thay vì tự tính URI trang tiếp theo. Nếu API dùng Slice hoặc cursor pagination, metadata và relation có thể khác; hãy công bố hợp đồng nhất quán.

### Giữ query parameters của collection

Collection có thể được lọc, sắp xếp hoặc phân trang:

~~~http
GET /orders?status=PAID&sort=createdAt,desc&page=0&size=20
~~~

Self link nên đại diện cho truy vấn hiện tại. Link next/prev cần giữ các filter và sort có ý nghĩa, chỉ thay đổi phần điều hướng trang. Khi dùng Spring Data và PagedResourcesAssembler, kiểm tra URI được tạo trong response để bảo đảm các tham số của ứng dụng được giữ đúng.

Không tự loại bỏ query parameter chỉ vì nó xuất hiện trong URL. Filter và sort có thể làm thay đổi tập hợp; tracking parameter không ảnh hưởng dữ liệu có thể được xử lý theo chính sách riêng.

## Collection rỗng và trạng thái HTTP

Nếu collection tồn tại nhưng chưa có phần tử, response thường là 200 OK cùng collection rỗng và self link:

~~~json
{
  "_links": {
    "self": { "href": "/orders" }
  }
}
~~~

Collection rỗng không đồng nghĩa với tài nguyên không tồn tại. Cần phân biệt:

- Collection tồn tại và có 0 item: trả collection rỗng.
- Collection thuộc tài nguyên cha không tồn tại vì cha không tồn tại: có thể trả 404 Not Found.
- Client không có quyền truy cập collection: trả status phù hợp với chính sách bảo mật.
- Request không hợp lệ, chẳng hạn page size ngoài giới hạn: trả lỗi validation phù hợp.

Không nên trả 404 chỉ vì repository trả danh sách rỗng. Collection resource vẫn có thể tồn tại với tập phần tử hiện tại bằng rỗng.

## Content negotiation cho HAL

HAL JSON dùng media type application/hal+json. Client có thể yêu cầu representation:

~~~http
GET /orders HTTP/1.1
Accept: application/hal+json
~~~

Trong Spring HATEOAS, dùng hằng số MediaTypes.HAL_JSON hoặc MediaTypes.HAL_JSON_VALUE để tránh gõ sai media type:

~~~java
@GetMapping(produces = MediaTypes.HAL_JSON_VALUE)
CollectionModel<OrderModel> all() {
    // ...
}
~~~

Ứng dụng Spring Boot có thể tự cấu hình các thành phần hypermedia khi dùng starter phù hợp. Với cấu hình Spring MVC tùy chỉnh, bật hỗ trợ hypermedia HAL theo cấu hình Spring HATEOAS tương ứng, ví dụ @EnableHypermediaSupport(type = HypermediaType.HAL).

Nếu endpoint hỗ trợ nhiều media type, hãy kiểm tra cả request Accept và response Content-Type. Không nên giả định mọi client muốn JSON thuần đều hiểu cấu trúc HAL.

## HAL collection và khả năng tiến hóa hợp đồng

Collection là một entry point quan trọng cho client. Khi client tìm thấy relation orders, nó có thể theo link collection, đọc các embedded item và dùng link của từng item. Khi URI collection thay đổi, server có thể cập nhật href mà client không cần tự ghép path.

Để hợp đồng ổn định:

- Giữ relation collection có semantics rõ ràng.
- Không đổi tên relation chỉ vì đổi tên Java class.
- Giữ self link của collection và item nhất quán.
- Khi thêm filter hoặc pagination, duy trì các relation đã có.
- Chỉ thêm embedded fields hoặc links theo cách tương thích với client hiện tại.
- Không dựa vào thứ tự item hoặc thứ tự thuộc tính JSON.
- Dùng profile hoặc tài liệu API khi client cần hiểu schema chi tiết.

Nếu đổi relation orders thành purchases, đó là thay đổi hợp đồng có thể ảnh hưởng client. Cần có kế hoạch chuyển tiếp hoặc công bố cả relation cũ và mới trong thời gian tương thích nếu semantics cho phép.

## Kiểm thử HAL collection

Kiểm thử nên xác minh media type, relation, embedded item và link điều hướng. Không chỉ kiểm tra HTTP status hoặc số lượng phần tử.

Ví dụ với Spring MVC Test:

~~~java
import static org.hamcrest.Matchers.endsWith;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.get;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.content;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.jsonPath;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.status;

import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.autoconfigure.web.servlet.AutoConfigureMockMvc;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.hateoas.MediaTypes;
import org.springframework.test.web.servlet.MockMvc;

@SpringBootTest
@AutoConfigureMockMvc
class OrderHalCollectionTest {

    @Autowired
    MockMvc mockMvc;

    @Test
    void returnsHalCollectionWithEmbeddedOrders() throws Exception {
        mockMvc.perform(get("/orders").accept(MediaTypes.HAL_JSON))
            .andExpect(status().isOk())
            .andExpect(content().contentTypeCompatibleWith(MediaTypes.HAL_JSON))
            .andExpect(jsonPath("$._links.self.href")
                .value(endsWith("/orders")))
            .andExpect(jsonPath("$._embedded.orders").isArray())
            .andExpect(jsonPath("$._embedded.orders[0].id").exists())
            .andExpect(jsonPath("$._embedded.orders[0]._links.self.href").exists());
    }
}
~~~

Test giả định dữ liệu kiểm thử có ít nhất một đơn hàng và relation collection được cấu hình là orders. Nếu dùng relation mặc định hoặc tên tùy chỉnh khác, cập nhật JSONPath theo hợp đồng thực tế.

Các trường hợp nên kiểm thử:

1. Request HAL trả đúng Content-Type.
2. Collection có self link đến đúng URI.
3. Embedded relation có tên ổn định.
4. Mỗi item có dữ liệu và self link phù hợp.
5. Collection rỗng vẫn có response hợp lệ.
6. Trang đầu, trang giữa và trang cuối có các relation điều hướng phù hợp.
7. Query filter và sort được giữ trong các link pagination.
8. Client yêu cầu media type không được hỗ trợ nhận lỗi negotiation phù hợp.
9. Item không bị lộ các trường ngoài DTO công khai.
10. Link trong response vẫn đúng khi base path hoặc context path thay đổi.

## Những sai lầm thường gặp

**Trả List và mong Spring tự tạo HAL collection.** List thuần có thể serialize thành JSON array. Dùng CollectionModel hoặc PagedModel để tạo representation collection có hypermedia.

**Chỉ tạo self link ở cấp collection.** Mỗi item có URI riêng cần self link riêng nếu client có thể truy cập item độc lập.

**Nhầm _embedded với _links.** _embedded chứa representation; _links chứa link điều hướng. Hai phần có thể cùng xuất hiện trong một response.

**Không kiểm soát collection relation.** Relation suy ra từ kiểu Java có thể không phù hợp với hợp đồng. Dùng @Relation hoặc relation provider để đặt tên rõ.

**Bỏ qua collection rỗng.** Không có item vẫn có thể là collection resource hợp lệ. Dùng fallback type khi serializer cần biết kiểu item để xác định relation.

**Tải collection không giới hạn.** Collection lớn làm tăng payload, bộ nhớ và thời gian xử lý. Dùng phân trang, giới hạn page size hoặc cursor.

**Tự tạo URL trang tiếp theo.** Client nên theo relation next/prev do server cung cấp để tránh phụ thuộc query parameters và cấu trúc URI.

**Coi embedded item là dữ liệu luôn mới.** Embedded representation phản ánh thời điểm response được tạo và có thể cũ khi item thay đổi. Theo self link để tải lại khi cần.

**Không kiểm tra media type.** Client cần yêu cầu application/hal+json và server cần trả content type tương ứng.

## Kết luận

HAL collection biểu diễn một tập hợp tài nguyên bằng _embedded và _links. Collection có self link ở cấp ngoài, relation xác định nhóm item được nhúng và mỗi item có thể mang links riêng. Trong Spring HATEOAS, CollectionModel là wrapper cho collection; assembler chuyển từng domain object thành representation có link, còn PagedModel và PagedResourcesAssembler hỗ trợ collection phân trang.

Hãy xác định relation collection ổn định, dùng fallback type khi collection rỗng cần suy luận item relation, giữ filter và pagination trong các link điều hướng, và thương lượng application/hal+json. Kiểm thử cả cấu trúc _embedded, links của collection và item, collection rỗng cùng các trang phân trang để client có thể khám phá tập hợp mà không phụ thuộc vào URL tự ghép.

Tài liệu tham khảo: Spring HATEOAS Reference — HAL support (https://docs.spring.io/spring-hateoas/docs/current/reference/html/#mediatypes.hal).
