# HAL self link

Trong HAL (Hypertext Application Language), **self link** là link relation có tên **self**, dùng để nhận diện tài nguyên hoặc collection đang được biểu diễn. HAL JSON đặt link này dưới khóa **_links.self**. Client có thể đọc href để truy cập lại resource hiện tại mà không cần tự ghép URL từ ID hoặc ghi nhớ route của server.

Spring HATEOAS cho phép tạo self link bằng **withSelfRel()**, **IanaLinkRelations.SELF** hoặc các builder dựa trên mapping controller. Representation model không tự suy ra self link chỉ từ trường ID; assembler hoặc controller cần chủ động thêm link vào model trước khi serialize.

## HAL resource và self relation

HAL biểu diễn một resource bằng dữ liệu, các link và có thể có các resource nhúng. Trong HAL JSON, hai vùng chính là:

- **_links** chứa link relation và URI đích.
- **_embedded** chứa representation của resource liên quan được nhúng.

Ví dụ một đơn hàng:

~~~json
{
  "id": "a7c1f4d2-55a1-4e51-93a2-88a12d1e1001",
  "status": "PENDING",
  "total": 125000,
  "_links": {
    "self": {
      "href": "https://api.example.com/orders/a7c1f4d2-55a1-4e51-93a2-88a12d1e1001"
    },
    "customer": {
      "href": "https://api.example.com/customers/6d2b8e4a-2a10-4d10-a5d3-9b9f5e3a2002"
    }
  }
}
~~~

Ở đây, self chỉ chính đơn hàng; customer chỉ tài nguyên khách hàng liên quan. Relation mô tả ý nghĩa của link, còn href chỉ URI đích. Client nên tìm relation self thay vì suy luận rằng trường id luôn tương ứng với đường dẫn /orders/{id}.

Self là một link relation chuẩn trong IANA Link Relation Registry. Trong Spring HATEOAS, có thể dùng hằng **IanaLinkRelations.SELF** để tránh viết chuỗi relation thủ công. Với HAL, relation này được serialize thành khóa self bên trong _links.

## Self link không phải dữ liệu ID

ID là dữ liệu của representation và thường là định danh nội bộ hoặc định danh nghiệp vụ. Self link là URI điều hướng được server công bố cho client. Hai giá trị có thể liên hệ nhưng không đồng nhất:

| Thành phần | Mục đích | Ví dụ |
| --- | --- | --- |
| id | Nhận diện đối tượng trong dữ liệu | a7c1... |
| _links.self.href | URI truy cập resource qua API | /orders/a7c1... |
| _links.customer.href | URI của resource liên quan | /customers/6d2b... |

Server có thể thay đổi route từ /orders/{id} sang /sales-orders/{id} mà không cần đổi ID của đơn hàng. Nếu client dựa vào self link, nó tiếp tục điều hướng theo URI mới mà server trả về.

Self link cũng không phải cơ chế phân quyền. Có link trong response không có nghĩa mọi caller đều được phép truy cập URI đó. Endpoint vẫn phải xác thực danh tính, kiểm tra quyền và xác nhận caller được phép xem resource.

## Tạo self link bằng WebMvcLinkBuilder

Với Spring MVC, cách thông dụng là dùng **WebMvcLinkBuilder.linkTo(...)** kết hợp **methodOn(...)**. Lời gọi methodOn là lời gọi mô phỏng để Spring HATEOAS đọc mapping controller và đối số; nó không thực thi logic nghiệp vụ của phương thức.

Giả sử controller expose resource đơn hàng:

~~~java
import java.math.BigDecimal;
import java.util.UUID;

public record OrderRepresentation(
    UUID id,
    String status,
    BigDecimal total
) {}
~~~

Controller expose resource đơn hàng và trả về representation model:

~~~java
import java.util.UUID;

import org.springframework.hateoas.EntityModel;
import org.springframework.hateoas.MediaTypes;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequestMapping("/orders")
class OrderController {

    private final OrderService orderService;
    private final OrderModelAssembler assembler;

    OrderController(OrderService orderService, OrderModelAssembler assembler) {
        this.orderService = orderService;
        this.assembler = assembler;
    }

    @GetMapping(value = "/{id}", produces = MediaTypes.HAL_JSON_VALUE)
    EntityModel<OrderRepresentation> one(@PathVariable UUID id) {
        Order order = orderService.findById(id);
        return assembler.toModel(order);
    }
}
~~~

Assembler ánh xạ domain object thành representation và gắn self link:

~~~java
import static org.springframework.hateoas.server.mvc.WebMvcLinkBuilder.linkTo;
import static org.springframework.hateoas.server.mvc.WebMvcLinkBuilder.methodOn;

import org.springframework.hateoas.EntityModel;
import org.springframework.hateoas.server.RepresentationModelAssembler;
import org.springframework.stereotype.Component;

@Component
class OrderModelAssembler implements
        RepresentationModelAssembler<Order, EntityModel<OrderRepresentation>> {

    @Override
    public EntityModel<OrderRepresentation> toModel(Order order) {
        OrderRepresentation body = new OrderRepresentation(
            order.getId(),
            order.getStatus(),
            order.getTotal()
        );

        return EntityModel.of(body,
            linkTo(methodOn(OrderController.class).one(order.getId()))
                .withSelfRel());
    }
}
~~~

Phương thức one được dùng để suy ra route item. Khi mapping đổi, builder dựa trên mapping mới thay vì một chuỗi URL được ghép thủ công trong assembler. Nếu cần thêm link customer, cancel hoặc collection, assembler có thể thêm các relation đó riêng.

## Tạo Link trực tiếp bằng IanaLinkRelations.SELF

Khi đã có URI, có thể tạo Link trực tiếp:

~~~java
import org.springframework.hateoas.IanaLinkRelations;
import org.springframework.hateoas.Link;

Link self = Link.of(
    "https://api.example.com/orders/42",
    IanaLinkRelations.SELF
);
~~~

Hoặc gắn relation sau khi tạo link:

~~~java
Link self = Link.of("https://api.example.com/orders/42").withSelfRel();
~~~

Hai cách đều tạo link relation self. Dùng builder theo controller khi muốn URI bám sát mapping; dùng Link.of khi URI đã được xác định bởi một nguồn khác, chẳng hạn một gateway hoặc một link factory riêng.

Không nên tạo self link từ chuỗi ghép thủ công nếu controller mapping đã có sẵn. Nối chuỗi có thể bỏ sót context path, API version, host công khai hoặc encoding của path variable.

## Self link cho collection

Collection cũng là một resource. Representation của collection nên có self link trỏ tới chính collection hoặc view hiện tại của collection.

~~~java
import static org.springframework.hateoas.server.mvc.WebMvcLinkBuilder.linkTo;
import static org.springframework.hateoas.server.mvc.WebMvcLinkBuilder.methodOn;

import java.util.List;

import org.springframework.hateoas.CollectionModel;
import org.springframework.hateoas.EntityModel;

CollectionModel<EntityModel<OrderRepresentation>> toCollectionModel(
        List<EntityModel<OrderRepresentation>> items) {

    return CollectionModel.of(items,
        linkTo(methodOn(OrderController.class).all()).withSelfRel());
}
~~~

Ví dụ giả định controller có phương thức GET all() trả collection. Khi serialize HAL, self link của collection nằm ở _links.self ngoài cùng. Self link của từng đơn hàng vẫn nằm trong _links.self của phần tử tương ứng bên trong _embedded.

~~~json
{
  "_embedded": {
    "orders": [
      {
        "id": "a7c1",
        "_links": {
          "self": {
            "href": "https://api.example.com/orders/a7c1"
          }
        }
      }
    ]
  },
  "_links": {
    "self": {
      "href": "https://api.example.com/orders"
    }
  }
}
~~~

Client cần phân biệt hai cấp self. Link ngoài cùng nhận diện collection; link bên trong nhận diện từng item. Không dùng self của collection thay cho self của một phần tử.

## Self link cho collection có filter và phân trang

Một collection có thể được truy cập bằng nhiều view khác nhau. Ví dụ:

- /orders?status=PENDING
- /orders?status=PAID
- /orders?status=PENDING&page=1&size=20

Nếu query parameter làm thay đổi tập kết quả hoặc trang hiện tại, self link nên giữ các tham số đó để client có thể truy cập lại đúng view. Những tham số chỉ phục vụ tracking hoặc không ảnh hưởng representation thường không cần được đưa vào self link.

Với Spring Data, **PagedResourcesAssembler** có thể chuyển Page thành PagedModel và tạo các link điều hướng:

~~~java
import org.springframework.data.domain.Page;
import org.springframework.data.domain.Pageable;
import org.springframework.data.web.PagedResourcesAssembler;
import org.springframework.hateoas.EntityModel;
import org.springframework.hateoas.PagedModel;
import org.springframework.web.bind.annotation.GetMapping;

@GetMapping
PagedModel<EntityModel<OrderRepresentation>> all(
        Pageable pageable,
        PagedResourcesAssembler<Order> pagedAssembler) {

    Page<Order> page = orderRepository.findAll(pageable);
    return pagedAssembler.toModel(page, orderModelAssembler);
}
~~~

PagedResourcesAssembler tạo PagedModel cùng metadata và các link phân trang phù hợp với request, thường gồm first, prev, self, next và last khi tương ứng. Tránh thêm một self link khác nếu assembler phân trang đã tạo link này. Với filter tùy chỉnh, bảo đảm query và cơ chế tạo link giữ lại các tham số có ảnh hưởng đến kết quả.

Ví dụ giả định controller đã inject orderRepository và orderModelAssembler, đồng thời cấu hình query để áp dụng các filter nếu endpoint hỗ trợ lọc.

## Lấy URI từ request hiện tại

Trong một số endpoint, self link cần giữ nguyên query string hiện tại. Với Spring MVC, **ServletUriComponentsBuilder.fromCurrentRequest()** có thể tạo URI từ request đang được xử lý:

~~~java
import org.springframework.hateoas.IanaLinkRelations;
import org.springframework.hateoas.Link;
import org.springframework.web.servlet.support.ServletUriComponentsBuilder;

String currentUri = ServletUriComponentsBuilder
    .fromCurrentRequest()
    .build()
    .toUriString();

Link self = Link.of(currentUri, IanaLinkRelations.SELF);
~~~

Cách này bao gồm query string của request hiện tại. Nó hữu ích khi các query parameter định nghĩa view collection. Tuy nhiên, không nên giữ mọi query parameter một cách máy móc: tham số tracking, tham số tạm thời hoặc tham số không ảnh hưởng representation có thể làm self URI thiếu ổn định.

Với item resource, URI ổn định được suy ra từ controller mapping thường phù hợp hơn việc lấy toàn bộ request URI. Với collection đã lọc hoặc phân trang, URI hiện tại có thể là self link chính xác nếu các query parameter là một phần của view.

## Host, context path và reverse proxy

Trong môi trường triển khai, ứng dụng có thể chạy sau ingress, load balancer hoặc reverse proxy. URI nội bộ mà servlet container nhìn thấy có thể khác URI công khai mà client sử dụng. Nếu self link được tạo từ request nhưng proxy không chuyển tiếp hoặc ứng dụng không xử lý đúng forwarded headers, link có thể chứa host, scheme hoặc port nội bộ.

Hãy cấu hình proxy gửi các header forwarded phù hợp và cấu hình Spring xử lý chúng theo cách triển khai của ứng dụng. Không lấy host từ một header tùy ý mà không có proxy tin cậy, vì điều đó có thể tạo ra link với host do client kiểm soát. Integration test nên chạy với cấu hình forwarded header hoặc URI base tương ứng môi trường triển khai.

Context path và API version cũng là một phần của URI công khai. Dùng controller mapping và link builder giúp giảm nguy cơ quên prefix; với link được tạo thủ công, cần bảo đảm base URI và path đúng với public route.

## Self link và content negotiation

Self link nhận diện resource hoặc collection view. Nó không nhất thiết nhận diện một định dạng representation duy nhất. Cùng một URI có thể trả HAL JSON hoặc media type khác tùy header Accept mà client gửi.

Ví dụ:

~~~http
GET /orders/42 HTTP/1.1
Accept: application/hal+json
~~~

Server có thể trả representation HAL JSON với Content-Type tương thích application/hal+json. Nếu client yêu cầu media type khác mà server hỗ trợ, cùng URI self có thể trả một biểu diễn khác. Nếu query parameter hoặc API version làm thay đổi resource/view, các giá trị đó có thể thuộc URI; nếu chỉ Accept thay đổi định dạng, thường không cần thêm media type vào href của self.

## Phân biệt HAL self link, HTTP Location và Link header

Các cơ chế sau có thể cùng chứa URI nhưng có vai trò khác nhau:

| Cơ chế | Vị trí | Mục đích |
| --- | --- | --- |
| HAL self link | Body JSON tại _links.self | Điều hướng trong representation hypermedia |
| Location | HTTP response header | Chỉ URI của resource được tạo hoặc URI đích trong một số response chuyển hướng |
| Link header | HTTP response header | Công bố link theo định dạng Web Linking ở header |

Khi POST tạo đơn hàng mới, server có thể trả 201 Created cùng Location trỏ tới đơn hàng mới, đồng thời body HAL chứa _links.self trỏ tới cùng resource. Location không thay thế self link trong body; client dùng chúng theo ngữ cảnh của HTTP response và representation.

## Cấu hình HAL JSON trong Spring

Trong ứng dụng Spring Boot, dependency **spring-boot-starter-hateoas** cung cấp tích hợp Spring HATEOAS và cấu hình serialization hypermedia phù hợp. Endpoint có thể khai báo media type:

~~~java
import java.util.UUID;

import org.springframework.hateoas.EntityModel;
import org.springframework.hateoas.MediaTypes;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;

@GetMapping(value = "/{id}", produces = MediaTypes.HAL_JSON_VALUE)
EntityModel<OrderRepresentation> one(@PathVariable UUID id) {
    return orderService.findModel(id);
}
~~~

Client gửi Accept: application/hal+json. Spring MVC content negotiation chọn representation và HAL message converter serialize các link dưới _links. Khi không dùng Spring Boot, ứng dụng cần cấu hình hỗ trợ hypermedia HAL tương ứng, ví dụ bằng @EnableHypermediaSupport với HypermediaType.HAL.

~~~java
import org.springframework.context.annotation.Configuration;
import org.springframework.hateoas.config.EnableHypermediaSupport;

@Configuration
@EnableHypermediaSupport(type = EnableHypermediaSupport.HypermediaType.HAL)
class HalConfiguration {
}
~~~

Không tự dựng JSON bằng cách nối chuỗi hoặc serialize một DTO thường rồi thêm _links bằng tay. Hãy trả về RepresentationModel, EntityModel, CollectionModel hoặc PagedModel để Spring HATEOAS quản lý cấu trúc hypermedia.

## Kiểm thử self link bằng MockMvc

Kiểm thử qua HTTP xác nhận assembler, controller, content negotiation và HAL serializer cùng hoạt động. Ví dụ:

~~~java
import static org.hamcrest.Matchers.endsWith;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.get;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.content;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.jsonPath;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.status;

import org.springframework.hateoas.MediaTypes;

mockMvc.perform(get("/orders/{id}", orderId)
        .accept(MediaTypes.HAL_JSON))
    .andExpect(status().isOk())
    .andExpect(content().contentTypeCompatibleWith(MediaTypes.HAL_JSON))
    .andExpect(jsonPath("$._links.self.href")
        .value(endsWith("/orders/" + orderId)));
~~~

Test có thể xác nhận thêm ID trong body khớp ID trong URI, relation customer trỏ đúng khách hàng và không có link trùng self. Với collection, kiểm tra self ngoài cùng và self của từng phần tử nhúng. Với trang phân trang, kiểm tra self giữ page, size, sort và filter đang áp dụng.

Ví dụ test giả định test class đã cấu hình MockMvc và orderId là ID của fixture tồn tại.

Một số trường hợp nên có trong bộ test:

- Item resource tồn tại: self href trỏ tới đúng item URI.
- Item không tồn tại: server trả 404 theo hợp đồng, không tạo representation giả.
- Collection có filter: self giữ query parameter ảnh hưởng đến kết quả.
- Collection phân trang: self chỉ trang hiện tại; next và prev trỏ tới trang liền kề khi có.
- Reverse proxy/context path: self dùng public base URI đã cấu hình.
- Content negotiation: HAL JSON được trả khi client yêu cầu media type tương ứng.

Không phụ thuộc vào host cụ thể trong test nếu môi trường test có thể thay đổi host. Có thể kiểm tra path suffix hoặc dùng cấu hình base URI cố định cho test. Nếu host là một phần quan trọng của hợp đồng, hãy kiểm tra chính xác host trong integration test chuyên biệt.

## Những lỗi thường gặp

- **Không thêm self link:** representation có ID nhưng client không có URI điều hướng được công bố.
- **Self trỏ nhầm collection:** item representation dùng URI collection thay vì URI item.
- **Ghép URL thủ công:** link sai khi route, context path hoặc API version thay đổi.
- **Mất query parameter:** self của collection không tái tạo được filter hoặc trang hiện tại.
- **Tạo nhiều self link:** assembler và processor cùng thêm relation self mà không kiểm tra link đã có.
- **Nhầm self với Location:** Location là response header; self là link trong representation HAL.
- **Nhầm self với phân quyền:** client thấy link không có nghĩa request sẽ được phép.
- **Sai public host sau proxy:** href chứa host nội bộ hoặc scheme không đúng do forwarded headers chưa được cấu hình.

HAL self link cung cấp URI của resource hoặc collection view ngay trong representation. Khi tạo link bằng Spring HATEOAS, phân biệt self ở cấp item và collection, giữ query parameter có ý nghĩa, cấu hình đúng public URI và kiểm thử response HAL thực tế, client có thể điều hướng theo hợp đồng ổn định mà không phụ thuộc vào cách server tổ chức route nội bộ.
