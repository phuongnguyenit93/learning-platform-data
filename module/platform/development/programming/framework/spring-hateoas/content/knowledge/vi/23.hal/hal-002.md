# Media type application/hal+json

`application/hal+json` là media type dùng để biểu diễn tài nguyên theo định dạng HAL (Hypertext Application Language) trên nền JSON. Nó cho client biết response không chỉ là một object JSON thông thường mà còn tuân theo quy ước hypermedia của HAL: link được đặt trong `_links`, tài nguyên liên quan được nhúng trong `_embedded`, và mỗi link có relation mô tả ý nghĩa điều hướng.

Trong Spring HATEOAS, media type này được biểu diễn bằng hằng `MediaTypes.HAL_JSON` hoặc chuỗi `MediaTypes.HAL_JSON_VALUE`. Controller có thể khai báo `produces = MediaTypes.HAL_JSON_VALUE`; client gửi `Accept: application/hal+json`; server trả response với `Content-Type: application/hal+json`. Ba phần này phối hợp để content negotiation chọn đúng định dạng.

## Media type mô tả điều gì?

HTTP media type cho biết cách diễn giải representation trong message body. `application/json` nói rằng body là JSON. `application/hal+json` nói rằng body sử dụng cú pháp JSON và tuân theo cấu trúc hypermedia HAL.

| Media type | Ý nghĩa |
| --- | --- |
| `application/json` | JSON tổng quát; không tự quy định vị trí của link hoặc embedded resource. |
| `application/hal+json` | JSON theo quy ước HAL, có các vùng hypermedia như `_links` và `_embedded`. |
| `application/xml` | XML tổng quát; không mặc định là một định dạng hypermedia cụ thể. |

Phần hậu tố `+json` cho biết representation sử dụng cú pháp JSON. Phần `hal` xác định quy ước nội dung mà client cần hiểu. Vì vậy, một response có body JSON hợp lệ vẫn có thể không phải HAL nếu không tuân theo cấu trúc HAL.

Không nên trả `application/json` cho một HAL document chỉ vì dữ liệu bên trong có cú pháp JSON. Client dựa vào media type để chọn cách parse và diễn giải response. Nếu media type và cấu trúc body không thống nhất, client có thể bỏ qua link hoặc không nhận diện được embedded resource.

## Cấu trúc HAL cơ bản

HAL bổ sung các vùng hypermedia vào representation JSON. `_links` chứa các link theo relation; `_embedded` chứa representation của tài nguyên liên quan được nhúng.

Ví dụ response chi tiết đơn hàng:

```json
{
  "id": "o-42",
  "status": "PAID",
  "totalAmount": 125000,
  "_links": {
    "self": {
      "href": "https://shop.example/api/orders/o-42"
    },
    "customer": {
      "href": "https://shop.example/api/customers/c-17"
    },
    "items": {
      "href": "https://shop.example/api/orders/o-42/items"
    }
  }
}
```

Trong đó:

- `id`, `status` và `totalAmount` là dữ liệu của đơn hàng.
- `_links.self` xác định URI của chính đơn hàng.
- `_links.customer` cho biết URI của khách hàng liên quan.
- `_links.items` dẫn đến collection dòng hàng.

Client có thể tìm relation `customer` hoặc `items` thay vì tự ghép URL từ ID và quy ước route. Server có thể thay đổi đường dẫn mà vẫn giữ relation cùng ý nghĩa.

Collection HAL có thể nhúng các item dưới `_embedded`:

```json
{
  "_embedded": {
    "orders": [
      {
        "id": "o-42",
        "status": "PAID",
        "_links": {
          "self": {
            "href": "https://shop.example/api/orders/o-42"
          }
        }
      },
      {
        "id": "o-43",
        "status": "PENDING",
        "_links": {
          "self": {
            "href": "https://shop.example/api/orders/o-43"
          }
        }
      }
    ]
  },
  "_links": {
    "self": {
      "href": "https://shop.example/api/orders"
    },
    "next": {
      "href": "https://shop.example/api/orders?page=1"
    }
  }
}
```

`orders` là relation của collection item; `self` và `next` là link relation. Relation tên item/collection có thể được kiểm soát bằng `@Relation` trên resource model. `_embedded` không bắt buộc phải có trong mọi response: một resource chỉ có dữ liệu và `_links` vẫn là HAL representation hợp lệ.

## Phân biệt Accept và Content-Type

Content negotiation thường dùng hai HTTP header:

| Header | Hướng | Vai trò | Ví dụ |
| --- | --- | --- | --- |
| `Accept` | Request | Client cho biết media type response mà nó có thể xử lý. | `Accept: application/hal+json` |
| `Content-Type` | Request hoặc response | Mô tả media type của body đang được gửi. | `Content-Type: application/hal+json` |

Khi client đọc đơn hàng, request có thể là:

```http
GET /api/orders/o-42 HTTP/1.1
Host: shop.example
Accept: application/hal+json
```

Server trả:

```http
HTTP/1.1 200 OK
Content-Type: application/hal+json

{
  "id": "o-42",
  "status": "PAID",
  "_links": {
    "self": {
      "href": "https://shop.example/api/orders/o-42"
    }
  }
}
```

`Accept` không mô tả body của request; nó là lựa chọn representation mong muốn cho response. `Content-Type` của response xác nhận định dạng thực tế server gửi. Nếu request có body, `Content-Type` của request mô tả định dạng body đó và `Accept` vẫn mô tả định dạng response mà client mong muốn.

Ví dụ client gửi dữ liệu JSON thông thường để tạo đơn hàng nhưng muốn nhận response HAL:

```http
POST /api/orders HTTP/1.1
Content-Type: application/json
Accept: application/hal+json

{
  "customerId": "c-17",
  "items": [
    { "productId": "p-1", "quantity": 2 }
  ]
}
```

Request body là JSON theo hợp đồng tạo đơn hàng; response có thể là HAL. Hai media type có thể khác nhau vì chúng mô tả hai message body khác nhau.

## Khai báo media type trong Spring HATEOAS

Spring HATEOAS cung cấp các hằng trong `org.springframework.hateoas.MediaTypes`:

```java
import org.springframework.hateoas.MediaTypes;
import org.springframework.http.MediaType;

MediaType hal = MediaTypes.HAL_JSON;
String halValue = MediaTypes.HAL_JSON_VALUE;
```

Trong annotation mapping, dùng chuỗi `HAL_JSON_VALUE`:

```java
import java.util.UUID;

import org.springframework.hateoas.EntityModel;
import org.springframework.hateoas.MediaTypes;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequestMapping("/api/orders")
class OrderController {

    private final OrderService service;
    private final OrderAssembler assembler;

    OrderController(OrderService service, OrderAssembler assembler) {
        this.service = service;
        this.assembler = assembler;
    }

    @GetMapping(value = "/{id}", produces = MediaTypes.HAL_JSON_VALUE)
    EntityModel<OrderDto> one(@PathVariable UUID id) {
        return assembler.toModel(service.findById(id));
    }
}
```

Khai báo `produces` giúp Spring chọn handler phù hợp với `Accept` và đặt media type cho response. `EntityModel<OrderDto>` được Spring HATEOAS chuyển thành HAL representation khi hypermedia message converter/codec phù hợp được cấu hình.

Với endpoint nhận request body, khai báo `consumes` theo định dạng đầu vào và `produces` theo định dạng đầu ra:

```java
import org.springframework.hateoas.EntityModel;
import org.springframework.hateoas.MediaTypes;
import org.springframework.http.MediaType;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;

@PostMapping(
        consumes = MediaType.APPLICATION_JSON_VALUE,
        produces = MediaTypes.HAL_JSON_VALUE)
ResponseEntity<EntityModel<OrderDto>> create(@RequestBody CreateOrderRequest request) {
    Order created = service.create(request);
    EntityModel<OrderDto> model = assembler.toModel(created);

    return ResponseEntity
            .created(model.getRequiredLink("self").toUri())
            .body(model);
}
```

`consumes` và `produces` không thay thế nhau. `consumes` giới hạn media type của request body; `produces` công bố media type response. Nếu request không có body, không cần khai báo `consumes` chỉ để chọn HAL response.

## Cấu hình HAL trong ứng dụng

Với Spring Boot, dependency thường dùng là starter HATEOAS cùng web starter phù hợp:

```kotlin
dependencies {
    implementation("org.springframework.boot:spring-boot-starter-web")
    implementation("org.springframework.boot:spring-boot-starter-hateoas")
}
```

Spring Boot có thể tự cấu hình các thành phần hypermedia khi starter HATEOAS có trên classpath. Với ứng dụng không dùng auto-configuration hoặc cần khai báo cấu hình tường minh, có thể bật HAL:

```java
import org.springframework.context.annotation.Configuration;
import org.springframework.hateoas.config.EnableHypermediaSupport;
import org.springframework.hateoas.config.EnableHypermediaSupport.HypermediaType;

@Configuration
@EnableHypermediaSupport(type = HypermediaType.HAL)
class HypermediaConfiguration {
}
```

Chỉ thêm cấu hình thủ công khi cần. Trong ứng dụng Spring Boot đã có auto-configuration, hãy kiểm tra cấu hình hiện tại trước khi đăng ký thêm các bean hypermedia. Nếu ứng dụng chạy WebFlux, dùng `spring-boot-starter-webflux` và kiểm tra WebFlux hypermedia codec thay vì đưa nhầm Spring MVC starter vào cùng ứng dụng.

## Serialize EntityModel và CollectionModel thành HAL

Spring HATEOAS model độc lập với định dạng serialize. `EntityModel<T>` bọc một payload và các link; `CollectionModel<T>` bọc một tập hợp model cùng các link của collection. Khi response được serialize với HAL converter/codec, chúng được biểu diễn theo `_links` và `_embedded`.

```java
import static org.springframework.hateoas.server.mvc.WebMvcLinkBuilder.linkTo;
import static org.springframework.hateoas.server.mvc.WebMvcLinkBuilder.methodOn;

import org.springframework.hateoas.EntityModel;
import org.springframework.stereotype.Component;

@Component
class OrderAssembler {

    EntityModel<OrderDto> toModel(Order order) {
        OrderDto dto = new OrderDto(order.getId(), order.getStatus().name());

        return EntityModel.of(dto,
                linkTo(methodOn(OrderController.class)
                        .one(order.getId())).withSelfRel());
    }
}
```

Controller chỉ trả model và khai báo media type:

```java
@GetMapping(produces = MediaTypes.HAL_JSON_VALUE)
CollectionModel<EntityModel<OrderDto>> all() {
    List<EntityModel<OrderDto>> orders = service.findAll().stream()
            .map(assembler::toModel)
            .toList();

    return CollectionModel.of(orders,
            linkTo(methodOn(OrderController.class).all()).withSelfRel());
}
```

Khi serialize HAL, collection có self link ở cấp ngoài và các item được nhúng dưới relation collection. Tên relation có thể khai báo trên kiểu resource bằng `@Relation(itemRelation = "order", collectionRelation = "orders")`; nếu không, `LinkRelationProvider` áp dụng quy tắc đã cấu hình.

## HAL không đồng nghĩa với HAL-FORMS

`application/hal+json` là định dạng HAL. Nó dùng `_links` và `_embedded` để biểu diễn điều hướng và tài nguyên nhúng. HAL không quy định cấu trúc form tương tác hoặc template nhập liệu.

HAL-FORMS là một định dạng liên quan, có media type riêng và bổ sung metadata về các template/hành động có input. Không nên đưa `_templates` vào một response rồi vẫn khai báo `application/hal+json` nếu thực tế response được xây theo HAL-FORMS. Hãy chọn media type tương ứng với cấu trúc được serialize và kiểm tra client hỗ trợ định dạng đó.

## Content negotiation và các lỗi thường gặp

Khi client yêu cầu media type mà endpoint không hỗ trợ, Spring có thể trả `406 Not Acceptable`. Khi client gửi request body với `Content-Type` mà endpoint không nhận, server có thể trả `415 Unsupported Media Type`.

| Tình huống | Kết quả thường gặp | Cách kiểm tra |
| --- | --- | --- |
| Client gửi `Accept: application/hal+json`, endpoint hỗ trợ HAL | Response HAL và `Content-Type: application/hal+json`. | Kiểm tra response header và `_links`. |
| Client chỉ chấp nhận media type không được endpoint hỗ trợ | `406 Not Acceptable`. | Kiểm tra `produces` và `Accept`. |
| Client gửi body `Content-Type` không nằm trong `consumes` | `415 Unsupported Media Type`. | Kiểm tra `consumes` và `Content-Type` request. |
| Controller trả DTO thường nhưng client kỳ vọng HAL | Có thể nhận JSON không có `_links`, hoặc không có converter phù hợp. | Trả `EntityModel`/`RepresentationModel` và kiểm tra cấu hình HAL. |
| HAL body nhưng header là `application/json` | Client không nhận được metadata định dạng chính xác. | Khai báo media type HAL trong mapping và kiểm thử header. |

Không phải mọi cấu hình đều trả chính xác cùng status code nếu có exception handler tùy chỉnh hoặc fallback converter. Hãy kiểm thử hành vi thực tế của ứng dụng thay vì dựa vào giả định chung.

## Kiểm thử media type bằng MockMvc

Kiểm thử cần xác nhận cả content negotiation và cấu trúc HAL. Ví dụ:

```java
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.get;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.content;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.jsonPath;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.status;

import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.autoconfigure.web.servlet.AutoConfigureMockMvc;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.hateoas.MediaTypes;
import org.springframework.test.web.servlet.MockMvc;

@SpringBootTest
@AutoConfigureMockMvc
class HalMediaTypeTest {

    @Autowired
    MockMvc mockMvc;

    @Test
    void acceptsHalAndReturnsHalRepresentation() throws Exception {
        mockMvc.perform(get("/api/orders/{id}", "o-42")
                        .accept(MediaTypes.HAL_JSON))
                .andExpect(status().isOk())
                .andExpect(content().contentTypeCompatibleWith(MediaTypes.HAL_JSON))
                .andExpect(jsonPath("$._links.self.href").exists());
    }

    @Test
    void rejectsUnsupportedResponseMediaType() throws Exception {
        mockMvc.perform(get("/api/orders/{id}", "o-42")
                        .accept("application/xml"))
                .andExpect(status().isNotAcceptable());
    }
}
```

Fixture cần có đơn hàng `o-42`. Test 406 giả định endpoint chỉ khai báo HAL và ứng dụng không có converter XML hoặc handler khác đáp ứng `application/xml`. Nếu ứng dụng hỗ trợ thêm media type, hãy chọn một media type chắc chắn không được hỗ trợ trong cấu hình kiểm thử.

Với WebFlux, có thể dùng `WebTestClient` để gửi `Accept: application/hal+json` và kiểm tra `Content-Type` cùng JSONPath tương tự. Không dùng MockMvc để kiểm tra một ứng dụng chỉ chạy WebFlux.

## Checklist khi công bố HAL

- Controller khai báo `produces = MediaTypes.HAL_JSON_VALUE` cho endpoint HAL.
- Client gửi `Accept: application/hal+json` khi cần HAL cụ thể.
- Response trả `Content-Type` tương thích với `application/hal+json`.
- Resource model chứa link trong `_links` với relation có ý nghĩa.
- Embedded resource, nếu có, được đặt dưới `_embedded` và relation ổn định.
- Collection có self link và item có self link riêng khi hợp đồng yêu cầu.
- `consumes` mô tả request body; `produces` mô tả response body.
- Test kiểm tra cả header và cấu trúc HAL thực tế.

## Nguyên tắc thiết kế

- Dùng `application/hal+json` khi body tuân theo cấu trúc hypermedia HAL.
- Phân biệt rõ media type này với `application/json` tổng quát.
- Dùng `Accept` để client chọn representation và `Content-Type` để mô tả body thực tế.
- Dùng `MediaTypes.HAL_JSON`/`HAL_JSON_VALUE` thay vì tự gõ chuỗi ở nhiều nơi.
- Trả `EntityModel`, `CollectionModel` hoặc `RepresentationModel` khi cần link và embedded resource.
- Cấu hình HAL converter/codec phù hợp với Spring MVC hoặc WebFlux stack.
- Phân biệt HAL với HAL-FORMS và khai báo đúng media type cho định dạng được serialize.
- Kiểm thử content negotiation, response header, `_links` và `_embedded`.

Khi server và client thống nhất `application/hal+json`, media type trở thành tín hiệu rõ ràng về cách diễn giải response. Spring HATEOAS đảm nhiệm việc chuyển các model cùng link thành HAL representation; controller công bố media type, client yêu cầu nó qua `Accept`, và kiểm thử hợp đồng xác nhận header cùng cấu trúc hypermedia luôn đi cùng nhau.
