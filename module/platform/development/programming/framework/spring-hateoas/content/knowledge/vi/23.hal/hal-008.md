# HAL relation

## Mục tiêu

Trong HAL, relation (rel) cho biết một link hoặc tài nguyên nhúng có quan hệ ngữ nghĩa gì với representation hiện tại. Client dùng relation để hiểu mục đích của liên kết, ví dụ self, next, collection, payment hoặc cancel, thay vì phải suy luận từ URL hay vị trí của trường JSON.

Spring HATEOAS biểu diễn relation bằng kiểu LinkRelation, cung cấp các relation chuẩn IANA qua IanaLinkRelations và hỗ trợ LinkRelationProvider để suy ra tên relation cho kiểu tài nguyên. Với HAL, relation còn quyết định key trong _links và _embedded; CURIE có thể rút gọn các relation URI dài thành dạng compact.

Sau bài học, bạn có thể:

- Giải thích ý nghĩa relation trong HAL.
- Phân biệt relation chuẩn IANA với extension relation.
- Tạo link bằng IanaLinkRelations và LinkRelation.
- Kiểm soát relation cho item và collection bằng @Relation.
- Hiểu vai trò của LinkRelationProvider.
- Đọc representation có nhiều link cùng relation.
- Dùng CURIE để rút gọn extension relation URI.
- Kiểm thử relation như một phần của hợp đồng hypermedia.

## Relation trong HAL là gì?

HAL là một định dạng hypermedia cho JSON. Representation có thể chứa dữ liệu tài nguyên, các link trong _links và tài nguyên liên quan được nhúng trong _embedded.

Tên relation là key mô tả ngữ nghĩa của link hoặc embedded resource:

~~~json
{
  "id": "order-42",
  "status": "PAID",
  "_links": {
    "self": {
      "href": "/api/orders/order-42"
    },
    "collection": {
      "href": "/api/orders"
    },
    "customer": {
      "href": "/api/customers/customer-7"
    },
    "next": {
      "href": "/api/orders/order-42/events?page=1"
    }
  },
  "_embedded": {
    "orderLines": [
      {
        "sku": "BOOK-01",
        "quantity": 2
      }
    ]
  }
}
~~~

Trong ví dụ:

- self xác định URI của representation hiện tại.
- collection trỏ tới collection resource chứa các đơn hàng.
- customer trỏ tới tài nguyên khách hàng có liên quan.
- next biểu thị liên kết điều hướng tới phần tiếp theo trong một chuỗi.
- orderLines là relation của collection dòng hàng được nhúng trong document.

Relation mô tả mối quan hệ giữa context hiện tại và target. Nó không phải tên method Java, tên controller, tên bảng cơ sở dữ liệu hay một phần bắt buộc của URL. Client nên dùng relation để tìm link phù hợp, sau đó theo href mà server cung cấp.

Ví dụ, client cần collection đơn hàng nên tìm relation collection. Nếu server đổi URI từ /api/orders sang /api/v2/orders, client vẫn có thể hoạt động nếu relation giữ nguyên và client không tự ghép URL.

## Hai nhóm relation: IANA và extension

RFC Web Linking phân biệt registered relation types và extension relation types:

| Nhóm | Đặc điểm | Ví dụ |
|---|---|---|
| Registered relation | Tên đã được đăng ký trong IANA Link Relation Registry, có ngữ nghĩa dùng chung. | self, next, prev, first, last, collection, item, related |
| Extension relation | URI do ứng dụng hoặc tổ chức định nghĩa để mô tả quan hệ riêng. | https://api.example.com/rels/cancel |

Nên ưu tiên relation IANA khi ngữ nghĩa của link đã có định nghĩa chuẩn. Điều này giúp client tổng quát hiểu relation mà không cần tài liệu riêng cho từng API.

Khi nghiệp vụ cần quan hệ riêng, dùng một URI ổn định làm extension relation. URI đó định danh ngữ nghĩa của quan hệ; nó không nhất thiết là URI của tài nguyên mà link trỏ tới. Ví dụ, relation URI https://api.example.com/rels/cancel mô tả ý nghĩa thao tác hủy, còn href của link có thể là /api/orders/order-42/cancellation.

Một số ứng dụng dùng token ngắn như cancel hoặc orders trong HAL vì thuận tiện. Spring HATEOAS cho phép tạo LinkRelation từ chuỗi, nhưng khi cần tuân thủ quy ước extension relation của Web Linking và khả năng liên thông rộng, nên dùng URI relation hoặc đăng ký relation phù hợp.

## Dùng IanaLinkRelations

Spring HATEOAS cung cấp IanaLinkRelations để tham chiếu các relation chuẩn mà không phải tự gõ chuỗi:

~~~java
import org.springframework.hateoas.IanaLinkRelations;
import org.springframework.hateoas.Link;

Link self = Link.of(
        "/api/orders/order-42",
        IanaLinkRelations.SELF);

Link collection = Link.of(
        "/api/orders",
        IanaLinkRelations.COLLECTION);

Link next = Link.of(
        "/api/orders?page=1",
        IanaLinkRelations.NEXT);
~~~

Một số relation IANA thường gặp:

| Relation | Ý nghĩa |
|---|---|
| SELF | Định danh representation hiện tại. |
| COLLECTION | Target là collection resource liên quan tới context. |
| ITEM | Target là một item trong collection. |
| FIRST | Target là phần tử hoặc trang đầu của một chuỗi. |
| PREV | Target là phần tử hoặc trang ngay trước. |
| NEXT | Target là phần tử hoặc trang kế tiếp. |
| LAST | Target là phần tử hoặc trang cuối. |
| RELATED | Target là một tài nguyên có liên quan. |
| EDIT | Target có thể được dùng để chỉnh sửa context. |
| PROFILE | Mô tả profile mà representation tuân theo. |

IanaLinkRelations là tập hằng số có kiểu LinkRelation. Khi cần relation chuẩn khác, tra cứu registry IANA và kiểm tra hằng số có trong phiên bản Spring HATEOAS của ứng dụng. Không tự gán một từ thông dụng thành relation IANA nếu từ đó chưa được đăng ký.

## LinkRelation cho relation tùy chỉnh

Spring HATEOAS dùng LinkRelation làm kiểu giá trị cho relation thay vì yêu cầu mọi API truyền String. Có thể tạo relation tùy chỉnh bằng LinkRelation.of(...):

~~~java
import org.springframework.hateoas.Link;
import org.springframework.hateoas.LinkRelation;

Link cancel = Link.of(
        "/api/orders/order-42/cancellation",
        LinkRelation.of("https://api.example.com/rels/cancel"));
~~~

Relation có thể được lưu thành hằng số để tránh gõ sai hoặc tạo nhiều biến thể:

~~~java
import org.springframework.hateoas.LinkRelation;

final class OrderRelations {

    static final LinkRelation CANCEL =
            LinkRelation.of("https://api.example.com/rels/cancel");

    static final LinkRelation INVOICE =
            LinkRelation.of("https://api.example.com/rels/invoice");

    private OrderRelations() {
    }
}
~~~

Sau đó assembler có thể dùng các relation đã định nghĩa:

~~~java
model.add(Link.of(
        "/api/orders/" + order.getId() + "/cancellation",
        OrderRelations.CANCEL));
~~~

LinkRelation giúp API làm việc nhất quán với relation ở nhiều vị trí như Link, Links, HAL builder và relation provider. Nó không xác minh URI relation có tồn tại hoặc tài liệu mô tả relation đã được publish hay chưa; trách nhiệm duy trì định danh và ngữ nghĩa vẫn thuộc về API.

## Relation cho item và collection

Trong representation model, relation thường được suy ra từ kiểu dữ liệu. Ví dụ, một OrderModel có relation cho một item và một collection các OrderModel có relation cho collection.

Spring HATEOAS cung cấp annotation @Relation để khai báo tường minh hai tên này:

~~~java
import org.springframework.hateoas.RepresentationModel;
import org.springframework.hateoas.server.core.Relation;

@Relation(
        itemRelation = "order",
        collectionRelation = "orders")
public class OrderModel extends RepresentationModel<OrderModel> {

    private String id;
    private String status;

    public OrderModel(String id, String status) {
        this.id = id;
        this.status = status;
    }

    public String getId() {
        return id;
    }

    public String getStatus() {
        return status;
    }
}
~~~

Khi serialize collection model trong HAL, collection relation được dùng làm key trong _embedded:

~~~java
import org.springframework.hateoas.CollectionModel;

CollectionModel<OrderModel> model =
        CollectionModel.of(orderModels);
~~~

Kết quả minh họa:

~~~json
{
  "_embedded": {
    "orders": [
      {
        "id": "order-42",
        "status": "PAID"
      },
      {
        "id": "order-43",
        "status": "PENDING"
      }
    ]
  }
}
~~~

itemRelation mô tả một item của loại tài nguyên đó; collectionRelation mô tả tập hợp các item. Trong ví dụ, order là relation của item và orders là relation của collection.

Nếu không khai báo @Relation, Spring HATEOAS dùng LinkRelationProvider để xác định relation. Quy tắc mặc định là tên class đã viết thường chữ đầu cho item và thêm hậu tố List cho collection. Nếu thư viện EVO inflector có trong classpath, collection relation có thể được tạo bằng dạng số nhiều tự nhiên của item relation. Vì pluralization có thể phụ thuộc dependency, nên dùng @Relation khi tên relation là hợp đồng công khai cần ổn định.

## LinkRelationProvider

LinkRelationProvider là abstraction xác định relation cho item resource và collection resource dựa trên kiểu Java. Spring HATEOAS dùng provider khi tạo embedded resources và khi cần suy ra relation từ representation type.

Các phương thức thường dùng:

~~~java
import org.springframework.hateoas.LinkRelation;
import org.springframework.hateoas.server.LinkRelationProvider;

class RelationInspector {

    private final LinkRelationProvider relationProvider;

    RelationInspector(LinkRelationProvider relationProvider) {
        this.relationProvider = relationProvider;
    }

    LinkRelation itemRelation() {
        return relationProvider.getItemResourceRelFor(OrderModel.class);
    }

    LinkRelation collectionRelation() {
        return relationProvider.getCollectionResourceRelFor(OrderModel.class);
    }
}
~~~

Khi bật hypermedia support bằng @EnableHypermediaSupport, Spring HATEOAS tự đăng ký LinkRelationProvider như một Spring bean. Có thể inject provider vào assembler hoặc thành phần tạo representation khi cần xác định relation theo kiểu.

Thuật toán mặc định được áp dụng theo thứ tự:

1. Nếu kiểu có @Relation, dùng itemRelation và collectionRelation đã khai báo.
2. Nếu không, dùng tên class viết thường chữ đầu cho item và hậu tố List cho collection.
3. Nếu EVO inflector có trong classpath, dùng dạng số nhiều do pluralization algorithm tạo ra.
4. Với controller được đánh dấu @ExposesResourceFor, provider có thể suy relation từ kiểu resource mà controller expose.

Nếu quy tắc mặc định không phù hợp với ngôn ngữ hoặc quy ước API, có thể triển khai LinkRelationProvider tùy chỉnh và đăng ký thành Spring bean. Hãy bảo đảm provider trả về relation ổn định và nhất quán giữa item, collection, link và embedded resource.

## Relation trong _links: một link hay nhiều link

Trong HAL, _links là một object. Mỗi key là một relation; value có thể là một link object hoặc một mảng link object.

Khi một relation có đúng một link, Spring HATEOAS mặc định serialize thành object:

~~~json
{
  "_links": {
    "self": {
      "href": "/api/orders/order-42"
    }
  }
}
~~~

Khi một relation có nhiều link, HAL serialize thành array:

~~~json
{
  "_links": {
    "item": [
      {
        "href": "/api/orders/order-42"
      },
      {
        "href": "/api/orders/order-43"
      }
    ]
  }
}
~~~

HAL cho phép cấu hình cách biểu diễn một link đơn thành object hay mảng một phần tử. Nếu client muốn xử lý một kiểu cấu trúc thống nhất, có thể cấu hình HalConfiguration:

~~~java
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.hateoas.mediatype.hal.HalConfiguration;

import static org.springframework.hateoas.mediatype.hal.HalConfiguration.RenderSingleLinks.AS_ARRAY;

@Configuration
class HalRenderingConfiguration {

    @Bean
    HalConfiguration halConfiguration() {
        return new HalConfiguration()
                .withRenderSingleLinks(AS_ARRAY);
    }
}
~~~

Ví dụ trên buộc tất cả relation có một link được serialize thành mảng. Nếu chỉ muốn áp dụng cho một relation, dùng withRenderSingleLinksFor(relation, policy) để cấu hình theo relation cụ thể.

Client nên xử lý được cả object và array nếu API không cam kết một chính sách duy nhất. Không dùng vị trí phần tử trong mảng làm định danh; hãy chọn link dựa trên relation và metadata của link.

## CURIE cho extension relation URI

Extension relation thường là URI đầy đủ để định danh ngữ nghĩa riêng. Nếu API có nhiều relation URI, các key trong HAL có thể dài và khó đọc. HAL hỗ trợ CURIE (Compact URI) để rút gọn relation URI bằng một prefix.

Ví dụ, relation đầy đủ:

~~~text
https://api.example.com/rels/orders
~~~

có thể được viết gọn thành:

~~~text
ex:orders
~~~

với prefix ex được định nghĩa bởi URI template:

~~~text
https://api.example.com/rels/{rel}
~~~

Spring HATEOAS cung cấp CurieProvider và DefaultCurieProvider:

~~~java
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.hateoas.UriTemplate;
import org.springframework.hateoas.mediatype.hal.CurieProvider;
import org.springframework.hateoas.mediatype.hal.DefaultCurieProvider;

@Configuration
class CurieConfiguration {

    @Bean
    CurieProvider curieProvider() {
        return new DefaultCurieProvider(
                "ex",
                UriTemplate.of("https://api.example.com/rels/{rel}"));
    }
}
~~~

Khi có CurieProvider, Spring HATEOAS tự thêm relation curies vào _links và dùng prefix ex cho các extension relation. Representation có thể có dạng:

~~~json
{
  "_links": {
    "self": {
      "href": "/api/orders/order-42"
    },
    "curies": {
      "name": "ex",
      "href": "https://api.example.com/rels/{rel}",
      "templated": true
    },
    "ex:cancel": {
      "href": "/api/orders/order-42/cancellation"
    }
  }
}
~~~

Client đọc curies để biết prefix ex được mở rộng theo URI template nào. Vì vậy, ex:cancel có thể được giải thành https://api.example.com/rels/cancel. CURIE chỉ rút gọn relation identifier; nó không thay đổi href của link target.

Một application scope chỉ nên khai báo một CurieProvider. Khi đổi prefix hoặc URI template, cần xem đó là thay đổi hợp đồng hypermedia vì client có thể dùng CURIE để nhận diện quan hệ.

## Thiết kế relation ổn định

Relation là một phần của hợp đồng API. Client có thể dựa vào relation để quyết định hiển thị nút, tải tài nguyên liên quan hoặc chuyển sang trang tiếp theo. Vì vậy:

- Chọn relation IANA nếu đã có quan hệ chuẩn phù hợp.
- Dùng extension relation URI cho ngữ nghĩa riêng của ứng dụng.
- Đặt tên relation ngắn gọn, nhất quán và không phụ thuộc tên class Java.
- Dùng @Relation khi muốn cố định item và collection relation cho một representation type.
- Dùng LinkRelationProvider tùy chỉnh khi nhiều loại model cần chung một quy tắc đặt tên.
- Chỉ thay relation khi có kế hoạch tương thích với client hiện tại.
- Không dùng cùng một relation cho các ý nghĩa không liên quan.

Relation nên biểu đạt ngữ nghĩa của target, không chỉ mô tả chi tiết triển khai. Ví dụ, relation cancel cho biết target phục vụ hành động hủy; nó bền vững hơn một relation có tên cancelOrderControllerMethod.

Nếu client cần phân biệt nhiều biến thể link cùng relation, có thể dùng thuộc tính link như name, title hoặc type để bổ sung thông tin. Không tạo relation mới chỉ để mã hóa định dạng file nếu ý nghĩa chung vẫn là download; khi đó relation download có thể kết hợp name hoặc type để phân biệt PDF và XML.

## Kiểm thử HAL relation

MockMvc có thể xác minh relation của link và embedded collection trong response HAL:

~~~java
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.get;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.jsonPath;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.status;

import org.springframework.hateoas.MediaTypes;

mockMvc.perform(get("/api/orders")
                .accept(MediaTypes.HAL_JSON))
        .andExpect(status().isOk())
        .andExpect(jsonPath("$._links.self.href").exists())
        .andExpect(jsonPath("$._links.collection.href").exists())
        .andExpect(jsonPath("$._embedded.orders").isArray());
~~~

Nếu có nhiều link cùng relation, kiểm thử số lượng và nội dung các link:

~~~java
mockMvc.perform(get("/api/orders/related")
                .accept(MediaTypes.HAL_JSON))
        .andExpect(status().isOk())
        .andExpect(jsonPath("$._links.item").isArray())
        .andExpect(jsonPath("$._links.item.length()").value(2));
~~~

Với relation extension có CURIE, kiểm tra cả khai báo prefix và relation compact:

~~~java
mockMvc.perform(get("/api/orders/order-42")
                .accept(MediaTypes.HAL_JSON))
        .andExpect(status().isOk())
        .andExpect(jsonPath("$._links.curies.name").value("ex"))
        .andExpect(jsonPath("$._links['ex:cancel'].href").exists());
~~~

Các kiểm thử nên bao gồm:

- Relation chuẩn dùng đúng IANA token.
- Item relation và collection relation đúng với @Relation.
- Collection rỗng vẫn giữ relation nếu hợp đồng yêu cầu key rỗng.
- Nhiều link cùng relation được serialize thành array.
- Chính sách render single link nhất quán với HalConfiguration.
- CURIE có prefix và URI template đúng.
- Client có thể tìm link bằng relation mà không cần ghép URL thủ công.

## Những lỗi thường gặp

- **Nhầm relation với href:** relation mô tả ngữ nghĩa; href là URI của target.
- **Dùng token tự đặt như relation chuẩn:** relation IANA phải thuộc registry. Với quan hệ riêng, dùng extension URI hoặc quy ước CURIE được công bố.
- **Đặt relation theo tên controller/method:** client không nên phụ thuộc chi tiết triển khai Java.
- **Không khai báo @Relation khi cần tên ổn định:** tên mặc định có thể phụ thuộc class name hoặc pluralization dependency.
- **Giả định một relation luôn có object:** khi có nhiều link, HAL dùng array; client phải xử lý cả hai dạng.
- **Dùng CURIE để rút gọn href:** CURIE áp dụng cho relation identifier trong key của _links, không rút gọn URL target.
- **Đổi prefix CURIE mà không xem xét client:** prefix và URI template là một phần hợp đồng relation.
- **Dùng cùng relation cho nhiều ý nghĩa:** client sẽ không thể xác định chính xác hành động hoặc tài nguyên đích.
- **Chỉ kiểm thử href:** relation sai có thể khiến client không khám phá được link dù URI vẫn hợp lệ.

## Quy trình thiết kế HAL relation

1. Xác định ngữ nghĩa của từng link và từng embedded resource.
2. Chọn relation IANA nếu có; nếu là quan hệ riêng, định danh bằng extension URI.
3. Dùng IanaLinkRelations hoặc LinkRelation để tạo relation trong code.
4. Khai báo @Relation cho item/collection model hoặc cấu hình LinkRelationProvider khi cần quy tắc chung.
5. Dùng CurieProvider để rút gọn extension relation URI nếu document có nhiều relation dài.
6. Kiểm tra cách HAL serialize relation đơn, relation nhiều link và collection embedded.
7. Viết test bảo vệ relation, CURIE, embedded key và cấu trúc object/array như một phần của API contract.

Relation là lớp ngữ nghĩa giúp client hiểu các liên kết và tài nguyên nhúng trong HAL. Khi dùng relation chuẩn đúng chỗ, định danh extension ổn định, cấu hình item/collection rõ ràng và kiểm thử hợp đồng, API Spring HATEOAS có thể thay đổi URI và cấu trúc triển khai mà vẫn giữ khả năng điều hướng cho client.
