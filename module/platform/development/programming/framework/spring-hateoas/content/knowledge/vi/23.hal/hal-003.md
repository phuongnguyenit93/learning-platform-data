# _links

Trong HAL (Hypertext Application Language), phần `_links` chứa các liên kết hypermedia của một resource. Mỗi liên kết được đặt dưới một **relation** (`rel`) mô tả ý nghĩa của đích đến, chẳng hạn `self`, `next`, `customer` hoặc `cancel`. Giá trị liên kết cung cấp `href` để client theo tới tài nguyên hoặc hành động liên quan.

Spring HATEOAS biểu diễn các liên kết bằng `Link` và quản lý chúng trong `RepresentationModel`, `EntityModel`, `CollectionModel` hoặc `PagedModel`. Khi response được tuần tự hóa bằng HAL, các link đó xuất hiện trong `_links`. Nhờ vậy, client có thể khám phá API theo quan hệ mà server công bố thay vì tự ghép URL từ ID hoặc tên endpoint.

Bài học này thuộc chương **HAL** trong module **SPRING_HATEOAS**, tập trung vào cấu trúc `_links`, relation key, các thuộc tính của link object, nhiều link cùng relation, URI template, CURIE và cách tạo/kiểm thử liên kết bằng Spring HATEOAS.

Sau bài học, bạn có thể:

- Giải thích vai trò của `_links` trong một HAL representation.
- Phân biệt relation (`rel`) với URI đích (`href`).
- Đọc cấu trúc link object và các thuộc tính metadata chuẩn của HAL.
- Xử lý nhiều link cùng relation và quan hệ mở rộng bằng CURIE.
- Nhận diện URI template qua thuộc tính `templated`.
- Tạo link trong Spring HATEOAS và tuần tự hóa thành HAL JSON.
- Kiểm thử relation, `href`, metadata và media type của response.

## 1. Vai trò của _links trong HAL

HAL là một định dạng biểu diễn hypermedia dựa trên JSON. Một HAL resource có thể chứa dữ liệu thông thường, liên kết và tài nguyên nhúng. Hai vùng cấu trúc quan trọng là:

- `_links`: các liên kết tới resource hiện tại, resource liên quan hoặc bước điều hướng tiếp theo.
- `_embedded`: các resource khác được nhúng trực tiếp trong representation.

Ví dụ một đơn hàng:

```json
{
  "id": 42,
  "status": "PENDING",
  "total": 125000,
  "_links": {
    "self": {
      "href": "https://api.example.com/orders/42"
    },
    "orders": {
      "href": "https://api.example.com/orders"
    },
    "customer": {
      "href": "https://api.example.com/customers/7"
    },
    "cancel": {
      "href": "https://api.example.com/orders/42/cancellation"
    }
  }
}
```

Các key `self`, `orders`, `customer` và `cancel` là relation. Mỗi relation giúp client hiểu liên kết có ý nghĩa gì đối với đơn hàng hiện tại. `href` là URI đích mà client có thể truy cập.

`_links` không phải nơi chứa dữ liệu nghiệp vụ như `id`, `status` hay `total`. Nó mô tả cách client tiếp tục điều hướng từ resource hiện tại. Client nên đọc relation và theo `href` được trả về, thay vì tự xây dựng đường dẫn `/orders/42/cancellation`.

## 2. Relation key và link object

Trong HAL, `_links` là một object JSON. Mỗi thuộc tính của object đại diện cho một relation; giá trị của thuộc tính là một link object hoặc một mảng link object.

Cấu trúc cơ bản:

```json
{
  "_links": {
    "self": {
      "href": "https://api.example.com/orders/42"
    }
  }
}
```

Trong đó:

| Thành phần | Ý nghĩa |
|---|---|
| `_links` | Vùng chứa tất cả liên kết của resource. |
| `self` | Relation key mô tả quan hệ của link. |
| `href` | URI reference của đích liên kết. |

Một link object HAL bắt buộc có `href`. Các thuộc tính khác là metadata tùy chọn. Tên relation có thể là relation đã đăng ký, ví dụ `self`, `next`, `first`, hoặc một extension relation được định danh bằng URI. HAL cũng hỗ trợ CURIE để rút gọn URI relation thành tên có prefix.

Relation và href trả lời hai câu hỏi khác nhau: relation cho biết **đích có ý nghĩa gì**, còn href cho biết **đi tới đâu**. Nếu URL đổi nhưng ý nghĩa quan hệ không đổi, server có thể cập nhật href trong khi client vẫn tìm cùng relation.

## 3. Các thuộc tính của link object

HAL định nghĩa một số thuộc tính có thể xuất hiện trong link object:

| Thuộc tính | Kiểu | Ý nghĩa |
|---|---|---|
| `href` | String | URI reference của resource đích; là thuộc tính bắt buộc. |
| `templated` | Boolean | Cho biết `href` là URI template có biến cần client mở rộng. |
| `type` | String | Gợi ý media type của resource đích, ví dụ `application/pdf`. |
| `deprecation` | String | URI dẫn tới tài liệu giải thích việc relation hoặc link bị deprecated. |
| `name` | String | Tên phụ để phân biệt các link có cùng relation. |
| `profile` | String | URI xác định profile mô tả resource đích. |
| `title` | String | Nhãn dễ đọc dành cho người dùng hoặc giao diện. |
| `hreflang` | String | Ngôn ngữ của resource đích, ví dụ `vi` hoặc `en`. |

Ví dụ link có metadata:

```json
{
  "_links": {
    "help": {
      "href": "https://docs.example.com/orders",
      "type": "text/html",
      "title": "Hướng dẫn quản lý đơn hàng",
      "hreflang": "vi"
    }
  }
}
```

Client có thể dùng `type` để biết định dạng mong đợi, `hreflang` để chọn ngôn ngữ và `title` để hiển thị nhãn. Metadata là gợi ý giúp client hiểu link; nó không thay thế content negotiation hoặc kiểm tra response thực tế.

`deprecation` không phải boolean. Nó chứa URI tài liệu mô tả trạng thái deprecated của link hoặc relation. Khi một API muốn thông báo link cũ đang được thay thế, có thể cung cấp URI tài liệu để client hoặc người tích hợp tìm hiểu lộ trình chuyển đổi.

`profile` cũng là URI, dùng để tham chiếu một profile mô tả thêm semantics của resource. Client không nên mặc định profile là schema JSON hoặc tự tải profile nếu hợp đồng không yêu cầu.

## 4. Một relation có thể chứa nhiều link

HAL cho phép giá trị của relation là một link object hoặc một mảng link object. Khi có nhiều link cùng relation, serializer biểu diễn chúng thành array:

```json
{
  "_links": {
    "alternate": [
      {
        "href": "https://api.example.com/orders/42",
        "type": "application/hal+json",
        "title": "Đơn hàng dạng HAL"
      },
      {
        "href": "https://api.example.com/orders/42.pdf",
        "type": "application/pdf",
        "title": "Đơn hàng dạng PDF"
      }
    ]
  }
}
```

Ở đây relation `alternate` có hai đích thay thế, khác media type. Client có thể chọn link dựa trên `type` hoặc nhu cầu hiển thị.

Không nên giả định mọi relation luôn có đúng một link. Client tổng quát cần xử lý cả object và array. HAL cho phép cả object lẫn array một phần tử khi relation chỉ có một link; Spring HATEOAS mặc định chọn cách gọn hơn và tuần tự hóa một link thành object. Khi có từ hai link cùng relation, giá trị được biểu diễn thành array.

Trong Spring HATEOAS, một representation model có thể chứa nhiều `Link` mang cùng relation:

```java
import org.springframework.hateoas.EntityModel;
import org.springframework.hateoas.Link;

EntityModel<OrderResponse> model = EntityModel.of(orderResponse);

model.add(Link.of("/orders/42", "alternate")
        .withType("application/hal+json")
        .withTitle("Đơn hàng dạng HAL"));

model.add(Link.of("/orders/42.pdf", "alternate")
        .withType("application/pdf")
        .withTitle("Đơn hàng dạng PDF"));
```

Khi tuần tự hóa thành HAL, hai link cùng relation có thể được nhóm thành một mảng. Hãy kiểm tra output thực tế bằng integration test nếu client phụ thuộc vào việc chọn link theo `type` hoặc `name`.

## 5. Relation chuẩn và relation mở rộng

Relation key trong `_links` thường thuộc một trong hai nhóm:

- **Registered relation:** relation đã được đăng ký trong IANA, ví dụ `self`, `next`, `prev`, `first`, `last`, `collection`, `item` hoặc `help`.
- **Extension relation:** relation do API định nghĩa để diễn đạt nghiệp vụ riêng, thường được định danh bằng URI tuyệt đối.

Ưu tiên relation chuẩn khi semantics phù hợp. Spring HATEOAS cung cấp `IanaLinkRelations` để tránh viết chuỗi relation chuẩn rải rác:

```java
import org.springframework.hateoas.IanaLinkRelations;
import org.springframework.hateoas.Link;

Link self = Link.of("/orders/42", IanaLinkRelations.SELF);
Link next = Link.of("/orders?page=1", IanaLinkRelations.NEXT);
```

Với relation tùy chỉnh, có thể tạo `LinkRelation` từ URI:

```java
import org.springframework.hateoas.Link;
import org.springframework.hateoas.LinkRelation;

Link cancel = Link.of("/orders/42/cancellation")
        .withRel(LinkRelation.of("https://api.example.com/rels/cancel"));
```

Một relation ổn định giúp client hiểu ý nghĩa link qua nhiều phiên bản API. Không nên dùng relation chuẩn sai nghĩa hoặc đổi relation chỉ vì tên controller hay path nội bộ thay đổi.

## 6. CURIE cho extension relation

URI relation tùy chỉnh có thể dài. HAL hỗ trợ CURIE (*Compact URI*) để công bố một prefix và rút gọn URI relation. Một entry `curies` khai báo prefix cùng URI template dùng để mở rộng tên rút gọn:

```json
{
  "_links": {
    "curies": [
      {
        "name": "acme",
        "href": "https://api.example.com/rels/{rel}",
        "templated": true
      }
    ],
    "acme:cancel": {
      "href": "https://api.example.com/orders/42/cancellation"
    }
  }
}
```

`acme:cancel` là tên rút gọn của relation URI theo template đã công bố. Client có thể đọc `curies` để hiểu prefix `acme` được mở rộng thành URI nào. Relation `curies` là relation dành riêng cho việc khai báo CURIE trong HAL.

Spring HATEOAS hỗ trợ CURIE trong HAL thông qua `CurieProvider`. Ví dụ cấu hình:

```java
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.hateoas.UriTemplate;
import org.springframework.hateoas.mediatype.hal.CurieProvider;
import org.springframework.hateoas.mediatype.hal.DefaultCurieProvider;

@Configuration
class HalConfiguration {

    @Bean
    CurieProvider curieProvider() {
        return new DefaultCurieProvider(
                "acme",
                new UriTemplate("https://api.example.com/rels/{rel}")
        );
    }
}
```

Khi có `CurieProvider`, Spring HATEOAS có thể công bố link `curies` và rút gọn extension relation tương ứng khi tạo HAL output. CURIE là quy ước của HAL; không nên giả định mọi media type hypermedia khác đều hiểu prefix này.

## 7. URI template và thuộc tính templated

Một link có thể trỏ tới URI cụ thể hoặc cung cấp URI template để client điền biến. Ví dụ, server muốn công bố điểm tìm kiếm đơn hàng với các tham số `status` và `page`:

```json
{
  "_links": {
    "search": {
      "href": "https://api.example.com/orders{?status,page}",
      "templated": true
    }
  }
}
```

`templated: true` cho client biết `href` chứa biến URI template. Client có thể mở rộng template với giá trị cần tìm, ví dụ `status=PAID` và `page=0`. Nếu `templated` không có hoặc là `false`, `href` được xem là URI reference thông thường.

Trong Spring HATEOAS, có thể tạo link từ URI template:

```java
import org.springframework.hateoas.Link;

Link search = Link.of("/orders{?status,page}")
        .withRel("search");
```

Khi được tuần tự hóa thành HAL, link template được biểu diễn cùng cờ `templated`. Nếu endpoint có mapping Spring MVC tương ứng, có thể tạo link bằng `WebMvcLinkBuilder` và URI template builder thay vì viết path thủ công.

URI template không đồng nghĩa với query string đã có giá trị. Client cần mở rộng các biến theo cú pháp URI Template trước khi gửi request. Server vẫn phải validate các tham số được mở rộng; template không phải schema xác thực đầu vào.

## 8. Tạo _links bằng Spring HATEOAS

Trong Spring HATEOAS, `RepresentationModel` là nơi quản lý các `Link`. `EntityModel<T>` bọc một content object; `CollectionModel<T>` và `PagedModel<T>` biểu diễn tập hợp hoặc trang dữ liệu. Khi trả các kiểu này từ controller với HAL converter, các link được tuần tự hóa vào `_links`.

Ví dụ tạo representation cho một đơn hàng:

Giả sử `orderResponse` là DTO đã được service hoặc mapper tạo, còn `OrderController` khai báo các mapping `one(Long)` và `all()`.

```java
import org.springframework.hateoas.CollectionModel;
import org.springframework.hateoas.EntityModel;
import org.springframework.hateoas.Link;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

import static org.springframework.hateoas.server.mvc.WebMvcLinkBuilder.linkTo;
import static org.springframework.hateoas.server.mvc.WebMvcLinkBuilder.methodOn;

Long orderId = 42L;

Link self = linkTo(methodOn(OrderController.class).one(orderId))
        .withSelfRel();

Link orders = linkTo(methodOn(OrderController.class).all())
        .withRel("orders");

EntityModel<OrderResponse> model = EntityModel.of(orderResponse, self, orders);
```

`withSelfRel()` gắn relation chuẩn `self`; `withRel("orders")` gắn relation tùy theo hợp đồng API. `linkTo(methodOn(...))` tạo URI dựa trên mapping controller và tham số, giảm việc hard-code URL.

Nếu cần thêm link sau khi tạo model:

```java
model.add(Link.of("/customers/7").withRel("customer"));

if (orderResponse.status().equals("PENDING")) {
    model.add(Link.of("/orders/42/cancellation").withRel("cancel"));
}
```

Trong ứng dụng thực tế, nên tạo link nội bộ từ mapping controller hoặc `EntityLinks`; ví dụ URI cố định ở trên chỉ nhằm minh họa thao tác `add`. Việc có link `cancel` không thay thế xác thực, phân quyền hoặc kiểm tra trạng thái tại endpoint.

## 9. Thêm metadata vào Link

Spring HATEOAS cho phép thêm metadata cho link bằng API fluent. Ví dụ:

```java
import org.springframework.hateoas.Link;
import org.springframework.hateoas.LinkRelation;

Link help = Link.of("https://docs.example.com/orders")
        .withRel(LinkRelation.of("help"))
        .withTitle("Hướng dẫn đơn hàng")
        .withType("text/html")
        .withHreflang("vi");

Link deprecated = Link.of("/legacy/orders/42")
        .withRel("legacy-order")
        .withDeprecation("https://docs.example.com/deprecations/legacy-orders")
        .withName("legacy");
```

Các phương thức `withTitle`, `withType`, `withHreflang`, `withDeprecation` và `withName` tạo link mới với metadata tương ứng. `Link` là immutable; các thao tác fluent không sửa link gốc.

Chỉ thêm metadata khi client có thể sử dụng nó. `title` phù hợp làm nhãn hiển thị; `type` giúp nhận biết media type; `hreflang` chỉ ngôn ngữ đích; `deprecation` dẫn tới tài liệu về link cũ. Đừng dùng metadata để truyền thông tin bí mật hoặc thay thế tài liệu hợp đồng.

## 10. _links và _embedded khác nhau

`_links` chứa URI để client điều hướng; `_embedded` chứa representation của resource được nhúng. Ví dụ một đơn hàng có thể cung cấp link tới khách hàng và đồng thời nhúng thông tin khách hàng rút gọn:

```json
{
  "id": 42,
  "_links": {
    "self": {
      "href": "https://api.example.com/orders/42"
    },
    "customer": {
      "href": "https://api.example.com/customers/7"
    }
  },
  "_embedded": {
    "customer": {
      "id": 7,
      "name": "Nguyen Van A",
      "_links": {
        "self": {
          "href": "https://api.example.com/customers/7"
        }
      }
    }
  }
}
```

Trong trường hợp này:

- `_links.customer` cho biết URI để truy cập tài nguyên khách hàng.
- `_embedded.customer` cung cấp representation khách hàng ngay trong response hiện tại.

Không phải link nào cũng cần embedded resource. Nhúng dữ liệu có thể giảm số request nhưng làm response lớn hơn và có nguy cơ trả dữ liệu không cần thiết. Chọn giữa link-only và embedded resource theo nhu cầu client, kích thước payload và chính sách công bố dữ liệu.

## 11. Cấu hình HAL và content negotiation

Trong Spring Boot, dependency `spring-boot-starter-hateoas` cung cấp tích hợp Spring HATEOAS và cấu hình hypermedia message converter. Client yêu cầu HAL JSON bằng media type:

```http
Accept: application/hal+json
```

Controller có thể trả `EntityModel` trực tiếp:

```java
import org.springframework.hateoas.CollectionModel;
import org.springframework.hateoas.EntityModel;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

import static org.springframework.hateoas.server.mvc.WebMvcLinkBuilder.linkTo;
import static org.springframework.hateoas.server.mvc.WebMvcLinkBuilder.methodOn;

@RestController
@RequestMapping("/orders")
class OrderController {

    private final OrderService orderService;

    OrderController(OrderService orderService) {
        this.orderService = orderService;
    }

    @GetMapping("/{id}")
    EntityModel<OrderResponse> one(@PathVariable Long id) {
        OrderResponse response = orderService.findResponseById(id);

        return EntityModel.of(
                response,
                linkTo(methodOn(OrderController.class).one(id)).withSelfRel(),
                linkTo(methodOn(OrderController.class).all()).withRel("orders")
        );
    }

    @GetMapping
    CollectionModel<EntityModel<OrderResponse>> all() {
        return CollectionModel.empty();
    }
}
```

Ví dụ giả định `OrderService.findResponseById` trả về `OrderResponse`; phương thức `all()` được rút gọn bằng collection rỗng để minh họa mapping đích cho link. Trong ứng dụng thực tế, thay bằng collection do service/assembler tạo ra.

Nếu ứng dụng không dùng auto-configuration của Spring Boot, có thể bật hỗ trợ HAL bằng `@EnableHypermediaSupport(type = HypermediaType.HAL)` và cấu hình converter tương ứng. Không nên đăng ký lặp cấu hình thủ công nếu starter đã tự cấu hình cùng hạ tầng.

`_links` là cấu trúc của HAL. Nếu client yêu cầu JSON thông thường hoặc media type khác, response có thể được tuần tự hóa theo định dạng khác và không nhất thiết có `_links`. Hãy kiểm tra `Content-Type` và cấu hình content negotiation thay vì giả định mọi JSON response đều là HAL.

## 12. Đọc _links ở phía client

Client nên truy cập link bằng relation key và sử dụng `href` do server trả về. Ví dụ pseudocode JavaScript:

```javascript
const selfHref = document._links.self.href;
const customerHref = document._links.customer.href;

const customerResponse = await fetch(customerHref, {
  headers: { Accept: "application/hal+json" }
});
```

Nếu relation có thể chứa nhiều link, client cần xử lý cả object và array. Ví dụ với relation `alternate`:

```javascript
const alternate = document._links.alternate;
const alternatives = Array.isArray(alternate) ? alternate : [alternate];

const pdf = alternatives.find(link => link.type === "application/pdf");
```

Với URI template, client phải mở rộng template theo cú pháp URI Template trước khi gửi request. Với CURIE, client cần đọc khai báo `curies` để giải nghĩa relation có prefix.

Client không nên:

- Tự ghép URI từ ID hoặc tên property.
- Giả định `href` luôn ở cùng host hoặc có path cố định.
- Giả định mọi relation chỉ có một link.
- Coi link `cancel` là bằng chứng người dùng chắc chắn có quyền hủy.
- Giả định `_links` tồn tại khi response không phải HAL.

## 13. Kiểm thử _links bằng MockMvc và JSONPath

Integration test cần kiểm tra media type, relation và URI đích. Ví dụ:

```java
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.autoconfigure.web.servlet.AutoConfigureMockMvc;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.hateoas.MediaTypes;
import org.springframework.test.web.servlet.MockMvc;

import static org.hamcrest.Matchers.containsString;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.get;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.content;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.jsonPath;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.status;

@SpringBootTest
@AutoConfigureMockMvc
class OrderHalLinksTest {

    @Autowired
    MockMvc mockMvc;

    @Test
    void orderResponseContainsExpectedRelations() throws Exception {
        mockMvc.perform(get("/orders/42").accept(MediaTypes.HAL_JSON))
                .andExpect(status().isOk())
                .andExpect(content().contentTypeCompatibleWith(MediaTypes.HAL_JSON))
                .andExpect(jsonPath("$.id").value(42))
                .andExpect(jsonPath("$._links.self.href", containsString("/orders/42")))
                .andExpect(jsonPath("$._links.orders.href").exists())
                .andExpect(jsonPath("$._links.customer.href").exists());
    }
}
```

Ví dụ giả định fixture đã tạo đơn hàng `42` và khách hàng liên quan. Kiểm tra một phần URI thay vì host/port tuyệt đối giúp test ít phụ thuộc môi trường triển khai.

Đặt các assertion sau trong một phương thức test khác của `OrderHalLinksTest` ở trên:


Với nhiều link cùng relation, hãy xác nhận serializer trả array và từng phần tử có đúng `type`, `title` hoặc `href`. Với CURIE, kiểm tra link `curies`, prefix và relation rút gọn. Các assertion phải khớp đúng response của media type HAL mà ứng dụng thực sự cung cấp.

## 14. Lỗi thường gặp

| Lỗi | Hệ quả | Cách xử lý |
|---|---|---|
| Nhầm relation với href | Client dùng URL như tên quan hệ hoặc ngược lại. | Relation mô tả ý nghĩa; href là URI đích. |
| Bỏ `_links` khỏi response HAL | Client không thể khám phá liên kết. | Trả representation model có link và dùng HAL converter. |
| Dùng relation chuẩn sai nghĩa | Client tổng quát có thể xử lý link sai. | Chọn relation IANA đúng nghĩa hoặc extension relation ổn định. |
| Giả định relation chỉ có một link | Client lỗi khi server trả array. | Hỗ trợ object và array cho một relation. |
| Bỏ `templated: true` cho URI template | Client không biết cần mở rộng biến trong href. | Công bố link template với cờ templated đúng. |
| Dùng extension relation khó định danh | Client không thể hiểu relation một cách ổn định. | Dùng URI relation hoặc CURIE cho HAL. |
| Cho rằng link mô tả HTTP method | Client không biết thao tác cần dùng method/payload nào. | Dùng affordance hoặc media type hỗ trợ mô tả form. |
| Coi link là cơ chế phân quyền | Request trực tiếp vẫn có thể gọi endpoint. | Xác thực và phân quyền tại server. |
| Chỉ kiểm tra JSON mà bỏ qua Content-Type | Test không phát hiện response không phải HAL. | Kiểm tra `application/hal+json`. |

## 15. Quy trình thiết kế _links

Khi thiết kế `_links` cho một resource, hãy thực hiện theo trình tự:

1. Xác định resource hiện tại và các resource hoặc hành động mà client cần khám phá.
2. Chọn relation chuẩn IANA nếu có semantics phù hợp; nếu không, định nghĩa extension relation ổn định.
3. Tạo link với URI đích chính xác và không phụ thuộc vào URL hard-code rải rác.
4. Thêm metadata như `type`, `title`, `hreflang`, `name` hoặc `deprecation` khi client thực sự cần.
5. Dùng mảng link khi một relation có nhiều đích hợp lệ.
6. Công bố URI template với `templated: true` và CURIE khi cần rút gọn extension relation trong HAL.
7. Phân biệt link điều hướng trong `_links` với resource nhúng trong `_embedded`.
8. Kiểm thử relation, href, metadata, array/template và media type qua HTTP.
9. Bảo đảm endpoint đích tự thực hiện xác thực, phân quyền và kiểm tra nghiệp vụ.

`_links` là phần điều hướng của HAL representation. Khi relation mô tả đúng ngữ nghĩa, href trỏ tới địa chỉ client truy cập được và metadata được dùng có chủ đích, client có thể khám phá API mà không bị ràng buộc vào cấu trúc URL nội bộ của server.
