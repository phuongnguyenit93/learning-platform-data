# Mapping Requests from Application Models

## 1. Why Map Application Models to Protobuf Requests?

In **Spring gRPC**, a unary method accepts **one protobuf request** and returns **one protobuf response** on success. However, the data used by business logic typically lives in an **application model**: Java objects carrying types and rules tailored to the application, such as `UUID`, `Currency`, `Instant`, internal enums, or a pre-validated group of fields.

Generated protobuf messages, on the other hand, are the **over-the-wire contract**: numbered fields and Protocol Buffers types encoded so clients and servers in different languages can interoperate. Because the two models serve different responsibilities, a mapping step is needed at the **gRPC client boundary**.

Example: business logic wants to request a product price quote.

```text
HTTP/CLI/job input
       │  parse and validate input
       ▼
PriceQuoteQuery                ← application model
       │
       │ PriceQuoteRequestMapper.toProto(...)
       ▼
PriceQuoteRequest              ← protobuf request
       │
       │ PricingServiceGrpc stub (unary RPC)
       ▼
Spring gRPC server
       │
       ▼
PriceQuoteResponse or error gRPC status
```

A mapper helps:

- **Keep domain types explicit:** `productId` in the application is a `UUID`, while in protobuf it can be a `string` so other platforms can handle it conveniently.
- **Centralize conversion rules:** enums, currencies, timestamps, lists, optional fields, and data bounds are handled in one place.
- **Reduce coupling:** business services do not have to call `PriceQuoteRequest.newBuilder()` everywhere.
- **Test in isolation:** conversion rules can be verified without starting a gRPC server or opening a network port.
- **Support contract evolution:** when the schema changes, the mapper serves as the compatibility checkpoint between the application model and the wire contract.

**Lesson scope:** mapping **requests** for unary RPCs in the `SPRING_GRPC` module. Clients still need deadlines, metadata, interceptors, TLS, and gRPC status handling when making calls; a mapper does not replace those mechanisms.

## 2. Example Unary Contract in a .proto File

Suppose a quoting service takes a product ID, quantity, currency, sales channel, list of promotion codes, an optional customer note, and a pricing timestamp. File `src/main/proto/pricing.proto`:

```proto
syntax = "proto3";

package pricing.v1;

option java_package = "com.example.pricing.grpc";
option java_multiple_files = true;

import "google/protobuf/timestamp.proto";

service PricingService {
  rpc GetQuote (PriceQuoteRequest) returns (PriceQuoteResponse);
}

enum SalesChannelProto {
  SALES_CHANNEL_UNSPECIFIED = 0;
  SALES_CHANNEL_WEB = 1;
  SALES_CHANNEL_STORE = 2;
}

message PriceQuoteRequest {
  string product_id = 1;
  int32 quantity = 2;
  string currency_code = 3;
  SalesChannelProto sales_channel = 4;
  repeated string promotion_codes = 5;
  optional string customer_note = 6;
  google.protobuf.Timestamp price_at = 7;
}

message PriceQuoteResponse {
  int64 total_minor_units = 1;
  string currency_code = 2;
}
```

This is a **unary RPC** because `GetQuote` does not declare `stream` on the request or response. The classes `PriceQuoteRequest`, `PriceQuoteResponse`, `SalesChannelProto`, and `PricingServiceGrpc` are generated by `protoc` and the gRPC Java plugin configured in the project.

Important details about the request:

| Field in .proto | Typical generated Java API | Meaning during mapping |
| --- | --- | --- |
| `string product_id` | `setProductId(String)` | Convert from `UUID` to a string using a stable format. |
| `int32 quantity` | `setQuantity(int)` | Check `quantity > 0` and business limits before sending. |
| `string currency_code` | `setCurrencyCode(String)` | Convert `Currency` to an ISO code like `USD` or `VND`. |
| `SalesChannelProto sales_channel` | `setSalesChannel(SalesChannelProto)` | Map internal enum to the generated enum. |
| `repeated string promotion_codes` | `addAllPromotionCodes(Iterable<String>)` | Transfer list in order and validate size/contents. |
| `optional string customer_note` | `setCustomerNote(String)`, `hasCustomerNote()` | Distinguish **not provided** from **provided as empty**. |
| `google.protobuf.Timestamp price_at` | `setPriceAt(Timestamp)`, `hasPriceAt()` | Convert `Instant` to seconds and nanos; do not serialize time as an arbitrary string. |

In `proto3`, plain scalars like `int32` or `string` return default values (`0` or `""`) when unset, without indicating whether the sender explicitly set them. `optional string customer_note` enables field **presence** so `hasCustomerNote()` can be used. Message fields like `price_at` also have presence. A `repeated` field with no elements reads as an empty list.

Numbers in declarations such as `= 4` are **wire field numbers**, not default values. Do not arbitrarily change or reuse field numbers when evolving a contract already used by clients.

## 3. Defining an Application Model Independent of Protobuf

In the application layer, a quote request can be more strongly typed:

```java
// SalesChannel.java
package com.example.pricing.application;

public enum SalesChannel {
    WEB,
    STORE
}
```

```java
// PriceQuoteQuery.java
package com.example.pricing.application;

import java.time.Instant;
import java.util.Currency;
import java.util.List;
import java.util.UUID;

public record PriceQuoteQuery(
        UUID productId,
        int quantity,
        Currency currency,
        SalesChannel channel,
        List<String> promotionCodes,
        String customerNote,
        Instant priceAt
) {
    public PriceQuoteQuery {
        // null from form/API means no promotion codes.
        // Copy to prevent list mutation after creating the query.
        promotionCodes = promotionCodes == null
                ? List.of()
                : List.copyOf(promotionCodes);
    }
}
```

`PriceQuoteQuery` is an **internal model**. It does not import `PriceQuoteRequest`, `Timestamp`, or `SalesChannelProto`. When an HTTP controller reads JSON, the controller or input adapter parses strings into `UUID`, `Currency`, `Instant`, and internal enums to construct `PriceQuoteQuery`. If the application triggers quotes from a scheduler or message consumer, the exact same model applies.

Example application data:

```java
PriceQuoteQuery query = new PriceQuoteQuery(
        UUID.fromString("a14b04af-13b1-40a8-a76d-4c171e481b76"),
        3,
        Currency.getInstance("USD"),
        SalesChannel.WEB,
        List.of("SAVE10", "MEMBER"),
        null,
        Instant.parse("2026-11-19T02:15:30.123456789Z")
);
```

In this example `customerNote == null` means the **field is absent** in the request; if `customerNote.equals("")`, the field is present with an empty value. Agree on these semantics in the API contract before implementation.

**Avoid using generated protobuf classes directly as parameters across all application services.** Doing so couples business logic to the wire schema and forces multiple layers to remember quirks like `UNSPECIFIED` enum values or `optional` presence. A mapper isolates this responsibility.

## 4. Writing a Mapper from Application Model to Protobuf Request

A mapper can be a stateless Spring `@Component` for easy reuse and unit testing. It performs two jobs:

1. **Enforce appropriate invariants at the client boundary**: ID, quantity, currency, channel, string lengths, and list limits.
2. **Perform intentional type conversions**: UUID → string; Currency → ISO 4217 code; application enum → proto enum; list → repeated; nullable string → optional; Instant → Timestamp.

```java
package com.example.pricing.client;

import com.example.pricing.application.PriceQuoteQuery;
import com.example.pricing.application.SalesChannel;
import com.example.pricing.grpc.PriceQuoteRequest;
import com.example.pricing.grpc.SalesChannelProto;
import com.google.protobuf.Timestamp;
import com.google.protobuf.util.Timestamps;
import org.springframework.stereotype.Component;

import java.util.List;
import java.util.Objects;
import java.util.regex.Pattern;

@Component
public class PriceQuoteRequestMapper {

    private static final int MAX_QUANTITY = 1_000;
    private static final int MAX_PROMOTIONS = 10;
    private static final Pattern PROMO_CODE =
            Pattern.compile("[A-Z0-9_-]{1,32}");

    public PriceQuoteRequest toProto(PriceQuoteQuery query) {
        Objects.requireNonNull(query, "query");

        if (query.productId() == null) {
            throw new IllegalArgumentException("productId is required");
        }
        if (query.quantity() < 1 || query.quantity() > MAX_QUANTITY) {
            throw new IllegalArgumentException(
                    "quantity must be between 1 and 1000");
        }
        if (query.currency() == null) {
            throw new IllegalArgumentException("currency is required");
        }
        if (query.channel() == null) {
            throw new IllegalArgumentException("channel is required");
        }

        List<String> codes = query.promotionCodes();
        if (codes.size() > MAX_PROMOTIONS) {
            throw new IllegalArgumentException("Too many promotion codes");
        }
        for (String code : codes) {
            if (!PROMO_CODE.matcher(code).matches()) {
                throw new IllegalArgumentException(
                        "Invalid promotion code: " + code);
            }
        }

        PriceQuoteRequest.Builder builder = PriceQuoteRequest.newBuilder()
                .setProductId(query.productId().toString())
                .setQuantity(query.quantity())
                .setCurrencyCode(query.currency().getCurrencyCode())
                .setSalesChannel(toProtoChannel(query.channel()))
                .addAllPromotionCodes(codes);

        if (query.customerNote() != null) {
            if (query.customerNote().length() > 200) {
                throw new IllegalArgumentException(
                        "customerNote exceeds 200 UTF-16 characters");
            }
            builder.setCustomerNote(query.customerNote());
        }

        if (query.priceAt() != null) {
            Timestamp timestamp = Timestamp.newBuilder()
                    .setSeconds(query.priceAt().getEpochSecond())
                    .setNanos(query.priceAt().getNano())
                    .build();

            // Validate the protobuf Timestamp range.
            Timestamps.checkValid(timestamp);
            builder.setPriceAt(timestamp);
        }

        return builder.build();
    }

    private static SalesChannelProto toProtoChannel(
            SalesChannel channel) {
        return switch (channel) {
            case WEB -> SalesChannelProto.SALES_CHANNEL_WEB;
            case STORE -> SalesChannelProto.SALES_CHANNEL_STORE;
        };
    }
}
```

This snippet uses `com.google.protobuf.util.Timestamps` from **protobuf-java-util**; you need a dependency version compatible with the project's protobuf version. Without that utility library, you must still check timestamp range and formatting before sending because Java's `Instant` spans a wider range than standard `google.protobuf.Timestamp`.

Notable design choices:

- **The mapper makes no network calls.** `toProto` only accepts an application model and returns an immutable message; never create channels or stubs inside a mapper.
- **Stable IDs.** `UUID#toString()` produces a canonical string representation. The server must parse and validate using the same contract; never call an arbitrary `toString()` on an ID object lacking a stable format.
- **Explicit enum mapping.** If the application adds `PARTNER`, a `switch` without `default` catches missing mappings at compile time. Never concatenate `enum.name()` with magic prefixes or rely on ordinals.
- **Promotion codes are not silently reordered.** `repeated` fields in protobuf are ordered; if duplicates should be deduplicated or rejected, state that rule explicitly in the business requirements and enforce it in validation.
- **Notes preserve presence.** `null` skips the setter, whereas `""` sets an empty string and makes `hasCustomerNote()` return `true`.
- **Timestamps preserve nanosecond precision.** Using `getEpochSecond()` and `getNano()` avoids losing sub-millisecond precision.
- **Data bounds are illustrative.** `MAX_QUANTITY`, `MAX_PROMOTIONS`, and promo-code patterns must reflect the real business contract and be enforced consistently on the server.

Because `PriceQuoteQuery` uses `List.copyOf`, the list cannot contain `null` elements; passing a `null` element fails when constructing the application model, before reaching the mapper. That is intentional. If you need per-element validation errors, check and report them in the input-parsing layer before invoking this constructor.

### Data flow diagram before and after mapping

```mermaid
flowchart LR
    A["PriceQuoteQuery<br/>UUID, Currency, enum, List,<br/>String?, Instant?"] -->|"validate + convert"| B["PriceQuoteRequest.Builder"]
    B --> C["PriceQuoteRequest<br/>string, int32, enum,<br/>repeated, optional, Timestamp"]
    C --> D["PricingServiceGrpc stub"]
    D --> E["Unary GetQuote"]
```

A good mapper is typically a simple, **deterministic** function given the same inputs and rules, allowing unit tests to assert field equality without worrying about execution order or networking.

## 5. Calling a Unary RPC from Spring with the Mapped Request

Once mapping succeeds, the client passes the request to the generated stub. With Spring gRPC, configure a channel named `pricing` and register a blocking stub:

```properties
# application.properties; local address for illustration only.
spring.grpc.client.channels.pricing.address=static://localhost:9090
```

```java
package com.example.pricing.client;

import com.example.pricing.grpc.PricingServiceGrpc;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.grpc.client.GrpcChannelFactory;

@Configuration
public class PricingGrpcClientConfiguration {

    @Bean
    PricingServiceGrpc.PricingServiceBlockingStub pricingBlockingStub(
            GrpcChannelFactory factory) {
        return PricingServiceGrpc.newBlockingStub(
                factory.createChannel("pricing"));
    }
}
```

The client sits the mapper between the application model and the stub:

```java
package com.example.pricing.client;

import com.example.pricing.application.PriceQuoteQuery;
import com.example.pricing.grpc.PriceQuoteRequest;
import com.example.pricing.grpc.PriceQuoteResponse;
import com.example.pricing.grpc.PricingServiceGrpc;
import org.springframework.stereotype.Service;

import java.util.concurrent.TimeUnit;

@Service
public class PricingGrpcClient {

    private final PriceQuoteRequestMapper mapper;
    private final PricingServiceGrpc.PricingServiceBlockingStub stub;

    public PricingGrpcClient(
            PriceQuoteRequestMapper mapper,
            PricingServiceGrpc.PricingServiceBlockingStub stub) {
        this.mapper = mapper;
        this.stub = stub;
    }

    public PriceQuoteResponse getQuote(PriceQuoteQuery query) {
        // Mapping errors occur before initiating the RPC call.
        PriceQuoteRequest request = mapper.toProto(query);

        // withDeadlineAfter returns a derived stub for the current RPC.
        return stub.withDeadlineAfter(1200, TimeUnit.MILLISECONDS)
                .getQuote(request);
    }
}
```

`getQuote(query)` has two distinct error layers:

| Error location | Examples | Error type |
| --- | --- | --- |
| In application input/mapper, before network | `quantity == 0`, missing `Currency`, out-of-range Timestamp | Typically `IllegalArgumentException` or application validation error; **no RPC sent**. |
| After stub calls server | `INVALID_ARGUMENT`, `NOT_FOUND`, `UNAVAILABLE`, `DEADLINE_EXCEEDED` | `StatusRuntimeException` with a gRPC status; must decide handling at the call boundary. |
| Server succeeds | Payload and status `OK` | One `PriceQuoteResponse` in the unary call. |

A blocking stub was chosen because this example is synchronous. If the application uses a future stub, **the mapper stays identical**:

```java
// Example inside a client class with PricingServiceFutureStub injected.
PriceQuoteRequest request = mapper.toProto(query);
ListenableFuture<PriceQuoteResponse> pending =
        futureStub.withDeadlineAfter(1200, TimeUnit.MILLISECONDS)
                .getQuote(request);
```

The future stub type is `PricingServiceGrpc.PricingServiceFutureStub`, and `ListenableFuture` comes from Guava. With an async stub, call `getQuote(request, responseObserver)`. All three send the exact same protobuf message under the unary contract.

**Deadlines** must be set close to when each RPC is issued. Calling `withDeadlineAfter` when creating a singleton bean can cause the deadline to expire before a request is sent. Transport, TLS, and connection/channel configuration belong to client infrastructure; the mapper's sole job remains data conversion.

## 6. Presence, Default Values, and Missing Data

Mapping bugs rarely come from `Builder` syntax—they usually stem from **mismatched absence semantics** between the two models.

Consider three cases for `customerNote`:

| Value in application model | Mapping | Observed on server |
| --- | --- | --- |
| `null` | Do not call `setCustomerNote` | `hasCustomerNote() == false`; `getCustomerNote()` still returns `""`. |
| `""` | Call `setCustomerNote("")` | `hasCustomerNote() == true`, empty string value. |
| `"Deliver after 18:00"` | Call setter with content | `hasCustomerNote() == true` with content. |

**Do not silently convert `null` to `""`** if the contract distinguishes between a user providing no note and explicitly submitting an empty string. Conversely, if business logic treats both as "no note", normalize at one consistent boundary and document the rule.

For `quantity` and `sales_channel`:

- `int32 quantity` without `optional` reads as `0` when omitted. The server **must independently validate** quantity even if the Spring client already validates it.
- `SalesChannelProto` defaults to `SALES_CHANNEL_UNSPECIFIED` (`0`). Never treat this value as a valid sales channel.
- When receiving a new enum value from a newer server/client version, generated Java enums can return `UNRECOGNIZED`; reverse-mapping code must handle that branch rather than assuming only currently known application values can arrive.
- `repeated promotion_codes` reads as an empty list when omitted; an absent list and an empty list are normally indistinguishable. If they must be distinguished, model presence explicitly in the contract.
- `google.protobuf.Timestamp price_at` is a message field with `hasPriceAt()`. When no timestamp is supplied by the client, the server must define and apply a default policy, such as using the processing time from a trusted clock.

### Adding a `oneof` field when a request has multiple ways to identify an entity

When a request allows **only one of two lookup keys**, you can design another contract using `oneof`:

```proto
message LookupProductRequest {
  oneof identifier {
    string product_id = 1;
    string sku = 2;
  }
}
```

The generated builder provides `setProductId(...)` or `setSku(...)`; on the server you can inspect `getIdentifierCase()`. If the application model holds two nullable fields, the mapper must **verify that exactly one field is non-null** before choosing a setter. This snippet illustrates an extended design and does not change the `PriceQuoteRequest` contract used in this lesson.

## 7. Converting Time, Enums, and Numeric Types Without Losing Semantics

### Timestamp: Instant → protobuf Timestamp

`Instant` and `google.protobuf.Timestamp` both represent instants on the UTC timeline, but they do not share the exact same valid range. Mapper:

```java
Timestamp timestamp = Timestamp.newBuilder()
        .setSeconds(priceAt.getEpochSecond())
        .setNanos(priceAt.getNano())
        .build();

Timestamps.checkValid(timestamp);
```

The seconds/nanos pair preserves nanosecond precision. Avoid machine-timezone date/time strings, `LocalDateTime.toString()`, or round-tripping through `Date` when the contract requires an absolute instant. If the business operation only needs a **local calendar date** (such as a delivery date), consider a calendar type like `google.type.Date` with an explicit timezone policy instead of coercing a date into an arbitrary instant.

**Security/business note:** `price_at` sent by a client is request input, not automatically trusted as an audit or approval timestamp. The server should enforce rules governing historical quotes and record its own processing timestamp separately.

### Application enum → protobuf enum

Use explicit conversion and define an `UNSPECIFIED = 0` value in the proto enum. Avoid relying on declaration order:

```java
private static SalesChannelProto toProtoChannel(SalesChannel value) {
    return switch (value) {
        case WEB -> SalesChannelProto.SALES_CHANNEL_WEB;
        case STORE -> SalesChannelProto.SALES_CHANNEL_STORE;
    };
}
```

If a `PARTNER` channel is later added to the app, an explicit `switch` surfaces the missing mapping at compile time. When designing a server receiving messages from older or newer clients, treat unsupported enum values as `INVALID_ARGUMENT` errors or apply a clearly defined fallback policy; never silently treat unknown values as `WEB`.

### Currency and monetary amounts

The request uses `Currency#getCurrencyCode()` to transmit the currency code. Never convert money to `double` for calculations or protobuf transport: when transmitting monetary amounts, typically use **minor units as `int64`** paired with a currency code, or an agreed decimal schema.

In the example, `PriceQuoteResponse.total_minor_units` returns an integer. If the application needs to display `USD 12.34`, the response handler must know the currency's decimal precision; never assume every currency has two decimal places.

## 8. Where Should Validation Live and Who Is Responsible?

A request can cross multiple boundaries:

1. **Input adapter** (REST controller, CLI, message consumer): parses JSON/strings into `UUID`, `Currency`, and `Instant`; handles syntax errors and missing fields.
2. **Application model and business validation**: enforces valid quantity, product rules, pricing policies, and allowed currencies/channels.
3. **gRPC request mapper**: ensures every field has a valid protobuf representation, proper presence, and conforms to wire limits.
4. **gRPC server**: re-validates all inputs because requests can originate from other clients without going through our Spring mapper.

Never rely on client-side validation to protect the server. Any client can craft a syntactically valid protobuf message that is invalid semantically, such as quantity `0` or an `UNSPECIFIED` enum.

### Distinguishing mapping errors from server errors

For example, in Spring MVC you might map application validation failures to HTTP `400 Bad Request` (depending on API conventions). For errors from the gRPC server, inspect `StatusRuntimeException#getStatus().getCode()` to translate accurately into business errors or external statuses.

```java
try {
    PriceQuoteResponse response = pricingGrpcClient.getQuote(query);
    // Process response when gRPC status is OK.
} catch (IllegalArgumentException validationError) {
    // Invalid input/application model/mapper: RPC not sent yet.
    throw validationError;
} catch (io.grpc.StatusRuntimeException rpcError) {
    switch (rpcError.getStatus().getCode()) {
        case INVALID_ARGUMENT -> {
            // Server rejected the request after it was sent.
            throw new IllegalArgumentException(
                    "Server rejected quote request", rpcError);
        }
        case DEADLINE_EXCEEDED, UNAVAILABLE -> {
            // Let the upper layer decide on safe fallback/retry.
            throw new IllegalStateException(
                    "Pricing service is unavailable", rpcError);
        }
        default -> throw rpcError;
    }
}
```

This snippet only illustrates error classification; real systems typically define custom exceptions and structured error-mapping rules. Never parse `Status.getDescription()` strings for business branching or return raw stack traces and server internals to clients.

## 9. Metadata, Authorization, and Data That Does Not Belong in the Request

The mapper converts **business payload data**. Authentication tokens, trace contexts, and request correlation IDs normally belong in **gRPC metadata, interceptors, or `CallCredentials`**, not in `customer_note` or user-supplied token fields.

In multi-tenant systems, `tenantId` in the application context can be obtained from the authenticated principal. If the contract requires a tenant field, the client should pull it from a **trusted context** and the server must verify access rights to that tenant; never blindly copy an arbitrary tenant string from an HTTP body and trust it.

Responsibilities can be divided as follows:

| Information type | Typical transport location | Principle |
| --- | --- | --- |
| Product ID, quantity, currency | Protobuf request | Validate and normalize per contract. |
| Authentication token | Metadata/`CallCredentials` over TLS | Never place tokens in logs, business messages, or metric labels. |
| Correlation ID / trace context | Metadata/interceptor/tracing instrumentation | Used to correlate logs/traces, with size limits and input validation. |
| RPC deadline | Stub call options | Set per call; avoid embedding transport timeouts inside protobuf payloads. |
| Authorized tenant | Security context and server authorization policy | Never trust a tenant solely because the client sent it in the payload. |

TLS must be configured on the channel to match the server; the mapper does not control plaintext vs. TLS. When monitoring reliability, time mapping separately if needed, while core RPC metrics generally track latency, status, deadlines, and in-flight calls. Avoid using product IDs or tokens as high-cardinality metric labels.

## 10. Isolated Mapper Tests and Integration Tests

Because the mapper has no network dependencies, a **JUnit 5 unit test** can thoroughly verify field conversions and presence. Example:

```java
package com.example.pricing.client;

import com.example.pricing.application.PriceQuoteQuery;
import com.example.pricing.application.SalesChannel;
import com.example.pricing.grpc.PriceQuoteRequest;
import com.example.pricing.grpc.SalesChannelProto;
import org.junit.jupiter.api.Test;

import java.time.Instant;
import java.util.Currency;
import java.util.List;
import java.util.UUID;

import static org.junit.jupiter.api.Assertions.*;

class PriceQuoteRequestMapperTest {

    private final PriceQuoteRequestMapper mapper =
            new PriceQuoteRequestMapper();

    private static PriceQuoteQuery sample(String note) {
        return new PriceQuoteQuery(
                UUID.fromString("a14b04af-13b1-40a8-a76d-4c171e481b76"),
                3,
                Currency.getInstance("USD"),
                SalesChannel.WEB,
                List.of("SAVE10", "MEMBER"),
                note,
                Instant.parse("2026-11-19T02:15:30.123456789Z"));
    }

    @Test
    void mapsAllFieldsAndPreservesNanoseconds() {
        PriceQuoteRequest proto = mapper.toProto(sample(null));

        assertEquals(
                "a14b04af-13b1-40a8-a76d-4c171e481b76",
                proto.getProductId());
        assertEquals(3, proto.getQuantity());
        assertEquals("USD", proto.getCurrencyCode());
        assertEquals(SalesChannelProto.SALES_CHANNEL_WEB,
                proto.getSalesChannel());
        assertEquals(List.of("SAVE10", "MEMBER"),
                proto.getPromotionCodesList());

        assertFalse(proto.hasCustomerNote());
        assertTrue(proto.hasPriceAt());
        assertEquals(123_456_789, proto.getPriceAt().getNanos());
        assertEquals(
                Instant.parse("2026-11-19T02:15:30.123456789Z")
                        .getEpochSecond(),
                proto.getPriceAt().getSeconds());
    }

    @Test
    void distinguishesAbsentNoteFromExplicitEmptyNote() {
        PriceQuoteRequest absent = mapper.toProto(sample(null));
        PriceQuoteRequest empty = mapper.toProto(sample(""));

        assertFalse(absent.hasCustomerNote());
        assertTrue(empty.hasCustomerNote());
        assertEquals("", empty.getCustomerNote());
    }

    @Test
    void rejectsQuantityBeforeCreatingRpcRequest() {
        PriceQuoteQuery invalid = new PriceQuoteQuery(
                UUID.randomUUID(),
                0,
                Currency.getInstance("USD"),
                SalesChannel.STORE,
                List.of(),
                null,
                null);

        assertThrows(IllegalArgumentException.class,
                () -> mapper.toProto(invalid));
    }
}
```

These tests verify the output **before sending over the channel**. Additional tests can verify invalid promotion code patterns, too many codes, overly long notes, missing currency/channel, and out-of-range Timestamps.

### Integration testing at the gRPC boundary

An integration test should invoke `PricingGrpcClient` or the generated stub against a test server and check:

| Case | Expectation |
| --- | --- |
| Successful mapping, server accepts request | Server receives the exact product ID, quantity, currency, enum, list, optional presence, and Timestamp; unary returns one `OK` response. |
| Invalid quantity input | Client rejects before RPC; confirm the server receives no call. |
| Server directly receives protobuf missing business-required fields | Server returns `INVALID_ARGUMENT` rather than trusting client validation. |
| Server slower than deadline | Client receives `DEADLINE_EXCEEDED`; verify cancellation and remaining active resources. |
| Connection lost | Client handles `UNAVAILABLE`/deadline appropriately; avoid retrying non-idempotent writes. |
| TLS and authentication enabled | Only valid channel/certificates connect; server verifies metadata and permissions. |

gRPC Java's `InProcessServerBuilder` and `InProcessChannelBuilder` work well for lightweight protocol/mapping tests, though they do not exercise TLS or real TCP/HTTP/2. To verify Spring configuration, interceptors, and security, write integration tests running the application over real transport with matching configuration.

### Schema compatibility testing

When adding a new enum value or optional field, write tests for how older versions handle absent data, unknown enum values, and defaults. When removing a deployed field, mark its field number and name as `reserved` instead of reusing them for another meaning. The mapper evolves with the contract, while the application model does not necessarily need to change if new wire values can be safely derived.

## 11. Common Mapping Mistakes

1. **Letting application services construct builders everywhere.** Leads to inconsistent conversion and validation rules. Centralize mapping at the gRPC boundary.
2. **Mapping enums by ordinal or arbitrary strings.** Reordering an enum once can make the server misinterpret the sales channel. Use an explicit `switch`.
3. **Turning every `null` into a default value.** Erases presence semantics on `optional` and message fields.
4. **Sending timestamps via `LocalDateTime.toString()`.** Risks losing timezones or misinterpreting instants; use `Timestamp` with seconds/nanos for absolute points in time.
5. **Using `double` to represent money.** Introduces binary floating-point rounding errors; use integer minor units or an agreed decimal contract.
6. **Assuming client validation protects the server.** Any client can send arbitrary messages; the server must always validate and authorize.
7. **Making network calls inside a mapper.** Makes testing harder, hides deadlines, and mixes error layers. A mapper should only transform data.
8. **Reusing deleted protobuf field numbers.** Can cause old payloads to be misinterpreted. Keep field numbers stable and mark removed fields `reserved`.
9. **Putting tokens, arbitrary tenant IDs, and unvalidated trace contexts into business payloads.** Risks leaks and privilege escalation; use proper metadata/security contexts and server-side authorization.
10. **Leaving lists or string lengths unbounded.** Oversized messages increase memory allocation, serialization cost, and server load; enforce limits per contract and operational constraints.
