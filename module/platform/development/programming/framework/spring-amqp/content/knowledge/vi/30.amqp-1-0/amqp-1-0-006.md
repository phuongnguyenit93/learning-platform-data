# Qpid ProtonJ2, AmqpConnectionFactory và SingleAmqpConnectionFactory

## 1. Bài toán: dùng Spring AMQP nhưng giao tiếp bằng AMQP 1.0

Trong module **Spring AMQP**, chúng ta thường học RabbitMQ thông qua `RabbitTemplate`, `@RabbitListener`, exchange, queue và binding, sau đó mở rộng sang xác nhận giao nhận, retry, dead-letter, giao dịch và quan sát hệ thống. Những thành phần quen thuộc này chủ yếu đi cùng **AMQP 0-9-1**, giao thức RabbitMQ đã hỗ trợ từ lâu.

Tuy nhiên, các hệ thống tích hợp có thể cần **AMQP 1.0** để làm việc với những broker hoặc dịch vụ hỗ trợ chuẩn này, như RabbitMQ phiên bản phù hợp, Apache ActiveMQ Artemis hoặc dịch vụ messaging hỗ trợ AMQP 1.0. Dù cùng mang tên AMQP, **AMQP 1.0 không phải phiên bản nâng cấp tương thích trực tiếp của AMQP 0-9-1**: mô hình wire protocol, connection/session/link, settlement và cách định địa chỉ khác nhau.

Kể từ **Spring AMQP 4.1**, module `spring-amqp-client` cung cấp hỗ trợ **AMQP 1.0 tổng quát** dựa trên **Apache Qpid ProtonJ2 Client Library**. Ba thành phần trung tâm là:

- **Qpid ProtonJ2** (`org.apache.qpid.protonj2.client`): client triển khai AMQP 1.0, quản lý kết nối, session, sender/receiver links và trao đổi message.
- **AmqpConnectionFactory** (`org.springframework.amqp.client.AmqpConnectionFactory`): abstraction Spring để cung cấp kết nối ProtonJ2 cho các thành phần AMQP 1.0.
- **SingleAmqpConnectionFactory** (`org.springframework.amqp.client.SingleAmqpConnectionFactory`): implementation quản lý **một kết nối ProtonJ2 dùng chung**, có cấu hình host, port, credentials và reconnect.

Với các thành phần này, ứng dụng có thể dùng **`AmqpClient`** để gửi/nhận bất đồng bộ bằng `CompletableFuture`, hoặc dùng **`@AmqpListener`** để nhận message theo mô hình listener của Spring.

**Sau bài học**, bạn sẽ biết khi nào chọn ProtonJ2, dựng factory đúng package, giải thích vòng đời kết nối và khả năng reconnect, gửi/nhận qua AMQP 1.0, định tuyến tới RabbitMQ bằng address phù hợp, đồng thời xử lý lỗi giao nhận đáng tin cậy.

> **Giới hạn phiên bản:** các API tổng quát `org.springframework.amqp.client.*` trong bài yêu cầu **Spring AMQP 4.1 trở lên**. Ví dụ ưu tiên các API được tài liệu Spring AMQP **4.2.x** ghi nhận. Dự án Spring Boot 3.x/Spring AMQP 3.x không thể chỉ copy import mới và kỳ vọng tương thích.

## 2. Tránh nhầm ba họ client của Spring AMQP

Spring AMQP hiện có nhiều lựa chọn. Cùng tên gần giống nhau nhưng **khác package, giao thức và dependency**:

| Mục đích | Dependency Spring | Kiểu factory | Client gửi/nhận |
| --- | --- | --- | --- |
| RabbitMQ **AMQP 0-9-1** truyền thống | `spring-rabbit` (Boot 4: `spring-boot-starter-rabbitmq`) | `org.springframework.amqp.rabbit.connection.ConnectionFactory`; thường dùng `CachingConnectionFactory` | `RabbitTemplate`, `@RabbitListener` |
| **AMQP 1.0 tổng quát**, dựa trên Qpid ProtonJ2 | **`spring-amqp-client`** (Boot 4: `spring-boot-starter-amqp`) | **`org.springframework.amqp.client.AmqpConnectionFactory`**, `SingleAmqpConnectionFactory` | **`AmqpClient`**, **`@AmqpListener`** |
| **AMQP 1.0 chuyên cho RabbitMQ**, dùng RabbitMQ native AMQP client | `spring-rabbitmq-client` (Boot 4: `spring-boot-starter-amqp-rabbitmq`) | `org.springframework.amqp.rabbitmq.client.AmqpConnectionFactory`, implementation cùng tên `SingleAmqpConnectionFactory` nhưng **package khác** | `RabbitAmqpTemplate`, RabbitMQ AMQP listener |

**Đừng import nhầm:**

~~~java
// ĐÚNG cho bài này: AMQP 1.0 tổng quát / Qpid ProtonJ2.
import org.springframework.amqp.client.AmqpConnectionFactory;
import org.springframework.amqp.client.SingleAmqpConnectionFactory;
import org.springframework.amqp.client.AmqpClient;
import org.springframework.amqp.client.annotation.AmqpListener;

// KHÁC: org.springframework.amqp.rabbit.connection.ConnectionFactory
// KHÁC: org.springframework.amqp.rabbitmq.client.AmqpConnectionFactory
~~~

**Tính tương thích của giao thức** khác với tính tương thích của API Java. Một broker hỗ trợ hai protocol có thể cho cả hai kiểu client truy cập cùng các queue theo điều kiện broker cung cấp, nhưng tính năng, metadata, settlement, topology và đường định tuyến cần kiểm thử. Đặc biệt, **`@AmqpListener`** không phải bí danh của **`@RabbitListener`**.

### 2.1. AMQP 1.0 có những tầng nào?

~~~text
Spring Boot Service
    |
    +--- AmqpClient / @AmqpListener -----------------------------+
    |                                                            |
    +--- org.springframework.amqp.client.AmqpConnectionFactory   |
                     |                                          |
             SingleAmqpConnectionFactory                        |
                     |                                          |
         Qpid ProtonJ2 Client (shared connection)               |
                     |                                          |
                     +------ AMQP 1.0 Connection ---------------+
                                |
                        AMQP 1.0 Sessions
                                |
                   Sender/Receiver Links (multiplexing)
                                |
                     RabbitMQ hoặc AMQP 1.0 peer
                                |
                    Address -> destination của broker
~~~

**Connection** là kết nối giao thức từ client đến peer. **Session** là ngữ cảnh giao tiếp có flow control. **Link** là đường gửi hoặc nhận message trong AMQP 1.0; một connection có thể chia sẻ giữa nhiều producer và consumer nhờ multiplexing. Việc tạo `SingleAmqpConnectionFactory` không có nghĩa mọi producer/consumer chỉ được dùng một link, và cũng không có nghĩa tạo một TCP connection cho mỗi message.

## 3. Cài thư viện và kiểm tra broker

### 3.1. Dùng dependency phù hợp

Với dự án Spring Boot 4.x có hỗ trợ AMQP 1.0 generic auto-configuration, chọn:

~~~xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-amqp</artifactId>
</dependency>
~~~

Nếu tự quản lý dependency Spring AMQP, dùng module chứa API generic:

~~~xml
<dependency>
    <groupId>org.springframework.amqp</groupId>
    <artifactId>spring-amqp-client</artifactId>
    <!-- Đồng bộ version theo Spring BOM; ví dụ 4.2.x. -->
</dependency>
~~~

`spring-amqp-client` dựa vào thư viện **`org.apache.qpid:protonj2-client`**. Khi dùng dependency quản lý đúng phiên bản, không nên tùy ý ép các phiên bản Qpid khác nhau mà chưa kiểm chứng tương thích.

**Chú ý về lịch sử Spring Boot:** tên starter có thể khác nghĩa giữa các thế hệ Boot. Trong tài liệu **Spring Boot 4.2**, `spring-boot-starter-amqp` dành cho AMQP 1.0 tổng quát, còn `spring-boot-starter-rabbitmq` dành cho RabbitMQ AMQP 0-9-1. Không suy ra rằng ứng dụng cũ sẽ chuyển sang AMQP 1.0 chỉ bằng cách nâng một con số version.

### 3.2. Chuẩn bị broker

**RabbitMQ 4.0 trở lên** hỗ trợ AMQP 1.0 native theo tài liệu RabbitMQ; một endpoint mặc định có thể chấp nhận cả AMQP 1.0 và AMQP 0-9-1 trên cổng **5672** dựa vào protocol header. Các broker khác có thể dùng cổng/TLS/address syntax riêng.

Trước khi chạy code:

1. Kiểm tra **broker và phiên bản** thực sự hỗ trợ AMQP 1.0.
2. Chuẩn bị user, password/TLS, quyền truy cập destination và virtual host theo broker.
3. Với RabbitMQ, provision queue, exchange và binding tương ứng trong vhost trước khi gửi/nhận; dùng Management UI, CLI hoặc công cụ quản lý topology thích hợp.
4. Xác minh address format theo broker. AMQP 1.0 **không quy định một chuỗi address duy nhất** mà mọi broker đều hiểu giống nhau.
5. Không sử dụng credential `guest/guest` qua mạng ngoài như cấu hình production.

### 3.3. Address AMQP 1.0 đối với RabbitMQ

RabbitMQ 4.0 giới thiệu **address format v2**, nên ưu tiên:

| Mục đích | Address trên RabbitMQ | Điều kiện |
| --- | --- | --- |
| Gửi trực tiếp vào queue | `/queues/orders.inbox.q` | Queue phải tồn tại; user có quyền phù hợp. |
| Gửi qua direct/topic exchange | `/exchanges/orders.events.x/order.created` | Exchange tồn tại; routing key được dùng để tìm binding. |
| Gửi qua fanout exchange | `/exchanges/orders.broadcast.x` | Routing key rỗng; exchange/binding phải tồn tại. |
| Nhận từ queue | `/queues/orders.inbox.q` | Source address phải trỏ tới queue đã tồn tại. |

Ví dụ hướng dẫn dưới dùng exchange `orders.events.x`, routing key `order.created` và queue `orders.inbox.q`. RabbitMQ sẽ xử lý destination `/exchanges/orders.events.x/order.created` dựa vào topology thực tế. Nếu gửi trực tiếp `/queues/orders.inbox.q`, message đi qua cơ chế định tuyến tới queue tương ứng theo quy ước RabbitMQ, không cần ghi exchange name trong address.

**Đừng dùng cú pháp v1** như `/exchange/orders.events.x/order.created` hay `/amq/queue/orders.inbox.q` trong ứng dụng mới. RabbitMQ coi v1 đã deprecated. Những tên chứa ký tự đặc biệt như dấu `/` trong routing key cần **percent-encode theo RFC 3986**; ví dụ key `my-routing/123` thành `my-routing%2F123`.

### 3.4. Provision topology minh họa

RabbitMQ vẫn có mô hình exchange/queue/binding quen thuộc:

~~~text
Spring AMQP 1.0 AmqpClient
    |
    | to("/exchanges/orders.events.x/order.created")
    v
RabbitMQ exchange: orders.events.x (direct)
    |
    | binding key = order.created
    v
RabbitMQ queue: orders.inbox.q
    |
    | source address: "/queues/orders.inbox.q"
    v
Spring AMQP 1.0 @AmqpListener
~~~

Không nên giả định việc tạo `SingleAmqpConnectionFactory` tự khai báo exchange/queue/binding. Nếu chọn AMQP 1.0 tổng quát để giữ tính portable, hạ tầng topology thường được provision **theo broker**; RabbitMQ-specific APIs không tự trở thành API chung cho Artemis/Azure Service Bus.

## 4. AmqpConnectionFactory là gì?

Abstraction cần học:

~~~java
package org.springframework.amqp.client;

// Minh họa chữ ký, không phải mã nguồn đầy đủ:
public interface AmqpConnectionFactory {
    org.apache.qpid.protonj2.client.Connection getConnection();
}
~~~

`getConnection()` trả về **Qpid ProtonJ2 Connection**; các thành phần Spring như `AmqpClient` và listener container nhận factory để lấy và tái sử dụng connection. Ứng dụng nghiệp vụ thông thường nên tiêm **abstraction** `AmqpConnectionFactory` thay vì tự gọi `Client.connect()` ở từng service.

Những trách nhiệm cần phân biệt:

| Lớp | Vai trò |
| --- | --- |
| `org.apache.qpid.protonj2.client.Client` | Entrypoint tạo kết nối AMQP 1.0. |
| `org.apache.qpid.protonj2.client.ConnectionOptions` | Cấu hình authentication, virtual host, TLS/transport, reconnect và các lựa chọn giao thức. |
| `org.springframework.amqp.client.AmqpConnectionFactory` | Cung cấp connection cho Spring components. |
| `SingleAmqpConnectionFactory` | Giữ một shared connection, quản lý lựa chọn kết nối và lifecycle. |
| `AmqpClient` | API fluent gửi/nhận, chuyển đổi message và trả `CompletableFuture`. |
| `AmqpMessageListenerContainer` / `@AmqpListener` | Nhận và xử lý message qua AMQP 1.0 Receiver links. |

## 5. Cấu hình SingleAmqpConnectionFactory

### 5.1. Cấu hình tối thiểu

Spring AMQP 4.1+ hỗ trợ:

~~~java
import org.springframework.amqp.client.AmqpConnectionFactory;
import org.springframework.amqp.client.SingleAmqpConnectionFactory;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class GenericAmqp10Config {
    @Bean
    AmqpConnectionFactory amqpConnectionFactory() {
        return new SingleAmqpConnectionFactory();
    }
}
~~~

Trong ví dụ mặc định được tài liệu Spring AMQP mô tả, factory kết nối `localhost:5672` và có cơ chế thử reconnect. Điều này phù hợp thử nghiệm cục bộ, **không tự phù hợp production** vì thiếu credentials/TLS, kiểm soát timeout và chính sách retry phù hợp.

### 5.2. Chỉ định host, port và credentials

~~~java
import org.springframework.amqp.client.AmqpConnectionFactory;
import org.springframework.amqp.client.SingleAmqpConnectionFactory;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class ProtonConnectionConfig {

    @Bean
    AmqpConnectionFactory amqpConnectionFactory(
            @Value("${app.amqp10.host:localhost}") String host,
            @Value("${app.amqp10.port:5672}") int port,
            @Value("${app.amqp10.username}") String username,
            @Value("${app.amqp10.password}") String password) {

        return new SingleAmqpConnectionFactory()
                .setHost(host)
                .setPort(port)
                .setUsername(username)
                .setPassword(password);
    }
}
~~~

~~~yaml
app:
  amqp10:
    host: localhost
    port: 5672
    username: app-user
    password: ${AMQP10_PASSWORD}
~~~

`app.amqp10.*` là namespace tự đặt và chỉ có tác dụng vì `@Value` ở Java đang đọc nó. Với Spring Boot 4.2 auto-configuration, bạn có thể dùng **`spring.amqp.*`** thay cho factory tự viết, được trình bày ở mục 9. Không dùng cùng lúc hai cách mà không xác định bean nào thực sự được tiêm.

Đặt mật khẩu qua secret/environment; không commit credential thực vào Git. Với TLS, cấu hình `ConnectionOptions` và trust material phù hợp endpoint, không chỉ đổi số port rồi mặc định an toàn.

### 5.3. Tùy chọn nâng cao bằng ConnectionOptions

`SingleAmqpConnectionFactory` có `setConnectionOptions(...)` và `setReconnectOptions(...)`. Khi cần tùy biến sâu, Qpid ProtonJ2 cung cấp `ConnectionOptions`:

~~~java
import org.apache.qpid.protonj2.client.ConnectionOptions;
import org.springframework.amqp.client.AmqpConnectionFactory;
import org.springframework.amqp.client.SingleAmqpConnectionFactory;
import org.springframework.context.annotation.Bean;

@Bean
AmqpConnectionFactory configuredProtonFactory() {
    ConnectionOptions options = new ConnectionOptions()
            .user("app-user")
            .password(System.getenv("AMQP10_PASSWORD"))
            .reconnectEnabled(true);

    options.reconnectOptions()
            .reconnectDelay(1_000)
            .maxReconnectDelay(30_000)
            .useReconnectBackOff(true);

    return new SingleAmqpConnectionFactory()
            .setHost("localhost")
            .setPort(5672)
            .setConnectionOptions(options);
}
~~~

**Quan trọng về thứ tự cấu hình:** theo Javadoc Spring AMQP 4.2, `setConnectionOptions(...)` và hai setter tiện ích `setUsername(...)`, `setPassword(...)` **loại trừ nhau**. Nếu đã cung cấp `ConnectionOptions`, đặt user/password trong chính `ConnectionOptions` như ví dụ; không gọi thêm `setUsername`/`setPassword` rồi kỳ vọng một tập hợp kết quả rõ ràng.

Đoạn mã `System.getenv(...)` chỉ để minh họa môi trường thử nghiệm. Production nên dùng property binding/secret manager, kiểm tra không rỗng và không log password. Khi dùng Qpid TLS, host verification, trust store, credential rotation và SASL phải phù hợp với broker. Nếu dùng vhost RabbitMQ khác `/`, phải cấu hình hostname/vhost theo quy ước AMQP 1.0 của RabbitMQ, trong đó hostname gửi trong `Open` frame có tiền tố `vhost:`; đừng nhầm với khai báo vhost của AMQP 0-9-1.

### 5.4. Có nên tự khai báo Client của ProtonJ2?

Có thể tái sử dụng `Client` nếu nhiều factory cùng ứng dụng:

~~~java
import org.apache.qpid.protonj2.client.Client;
import org.springframework.amqp.client.AmqpConnectionFactory;
import org.springframework.amqp.client.SingleAmqpConnectionFactory;
import org.springframework.context.annotation.Bean;

@Bean
Client protonClient() {
    return Client.create();
}

@Bean
AmqpConnectionFactory primaryAmqpConnectionFactory(Client protonClient) {
    return new SingleAmqpConnectionFactory(protonClient)
            .setHost("localhost")
            .setPort(5672);
}
~~~

Một `Client` có thể được dùng để tạo kết nối tới nhiều broker; **thông số từng broker thuộc factory/connection**, không đồng nghĩa một connection chia sẻ giữa hai broker. Nếu chỉ có một destination, **không cần bean Client riêng**: `new SingleAmqpConnectionFactory()` tự tạo ProtonJ2 client mặc định.

Khi tự quản lý `Client` bean, kiểm tra shutdown/lifecycle của nó và tránh đóng một client dùng chung khi factory khác còn hoạt động. Bean factory của Spring được quản lý theo vòng đời context và implement `DisposableBean` để giải phóng tài nguyên của nó.

## 6. Dùng AmqpClient để gửi message qua ProtonJ2

`AmqpClient` là API fluent cấp cao của Spring AMQP 1.0; nó nhận `AmqpConnectionFactory` rồi chuyển đổi `org.springframework.amqp.core.Message` sang message ProtonJ2 khi gửi. Không cần ứng dụng tự mở sender link cho mỗi lời gọi.

~~~java
import org.springframework.amqp.client.AmqpClient;
import org.springframework.amqp.client.AmqpConnectionFactory;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class AmqpClientConfig {
    @Bean
    AmqpClient amqpClient(AmqpConnectionFactory connectionFactory) {
        return AmqpClient.builder(connectionFactory)
                .defaultToAddress("/queues/orders.inbox.q")
                .build();
    }
}
~~~

Trong ví dụ này, `defaultToAddress` dành cho trường hợp muốn dùng một destination mặc định. Nếu gửi tới exchange hoặc queue khác, dùng `client.to(address)` trong từng request:

~~~java
import java.util.concurrent.CompletableFuture;
import org.springframework.amqp.client.AmqpClient;
import org.springframework.stereotype.Service;

@Service
public class OrderAmqp10Publisher {
    private final AmqpClient amqpClient;

    public OrderAmqp10Publisher(AmqpClient amqpClient) {
        this.amqpClient = amqpClient;
    }

    public CompletableFuture<Boolean> publishOrderCreated(
            String eventId, String orderId) {

        String address = "/exchanges/orders.events.x/order.created";
        return amqpClient
                .to(address)
                .body(orderId)
                .messageId(eventId)
                .header("eventType", "order.created")
                .send();
    }
}
~~~

Ví dụ `body(orderId)` dùng payload String. API cũng cho phép gửi message Spring AMQP hoặc ProtonJ2 native, và sử dụng `MessageConverter` để chuyển đổi object. Nếu gửi DTO JSON cần thống nhất converter/schema với consumer; không coi payload String đơn giản là hợp đồng production.

**Kết quả gửi là `CompletableFuture<Boolean>`.** Theo API này, tương lai hoàn tất dựa vào **AMQP 1.0 settlement** của phía peer; Boolean phản ánh kết quả API được trả về. Đây **không phải** kết quả xử lý nghiệp vụ từ consumer. Không biến `send()` trả về future thành bằng chứng message đã được giao; phải quan sát future hoàn tất.

### 6.1. Xử lý thành công, từ chối và exception

~~~java
publisher.publishOrderCreated("event-100", "ORDER-100")
        .whenComplete((accepted, error) -> {
            if (error != null) {
                System.err.println("AMQP 1.0 send failed: " + error);
                // Ghi lại trong outbox để đối soát/retry có kiểm soát.
            }
            else if (!Boolean.TRUE.equals(accepted)) {
                System.err.println("Message was not accepted by peer");
            }
            else {
                System.out.println("Peer accepted the delivery");
                // Chưa chứng minh @AmqpListener đã commit nghiệp vụ.
            }
        });
~~~

**Không gọi `get()` hoặc `join()` trong luồng request nếu mục tiêu là không chặn.** Các callback như `whenComplete`, `thenApply` hoặc `handle` giúp xử lý kết quả. Công việc nặng và truy vấn DB chậm nên chạy trên executor do ứng dụng quản lý; callback có thể thực thi trên thread hoàn thành future.

Giới hạn thời gian chờ có thể được đặt ở tầng client/caller, nhưng **timeout không hủy chắc chắn message** đã đến broker. Khi kết quả không xác định, retry cùng **business event ID** và thiết kế consumer idempotent. Không tạo eventId mới mỗi lần reconnect.

### 6.2. Gửi Spring Message hoặc ProtonJ2 native

`AmqpClient` có thể nhận Spring `Message`:

~~~java
import java.nio.charset.StandardCharsets;
import org.springframework.amqp.core.Message;

Message springMessage =
        new Message("ORDER-101".getBytes(StandardCharsets.UTF_8));

CompletableFuture<Boolean> future =
        amqpClient.to("/queues/orders.inbox.q")
                  .message(springMessage)
                  .send();
~~~

Hoặc dùng ProtonJ2 client trực tiếp khi cần kiểm soát các phần của AMQP 1.0 `Message` ở tầng thấp. Chỉ chọn đường native khi có yêu cầu cụ thể như message sections, delivery settlement hay link credit; nếu yêu cầu thông thường là gửi/nhận nội dung nghiệp vụ và quan sát, API Spring `AmqpClient` giúp nhất quán với Spring context/converter.

## 7. Nhận message: @AmqpListener của generic AMQP 1.0

Không dùng `@RabbitListener` cho đường generic ProtonJ2. Spring AMQP 4.1+ cung cấp **`org.springframework.amqp.client.annotation.AmqpListener`**:

~~~java
import org.springframework.amqp.client.annotation.AmqpListener;
import org.springframework.stereotype.Component;

@Component
public class OrderAmqp10Consumer {

    @AmqpListener(addresses = "/queues/orders.inbox.q")
    public void onOrderCreated(String orderId) {
        // Nghiệp vụ thật nên kiểm tra eventId, schema và idempotency.
        System.out.println("AMQP 1.0 order event: " + orderId);
    }
}
~~~

**`addresses`** ở đây là address AMQP 1.0. Với RabbitMQ v2, nguồn nhận thông thường có dạng `/queues/<queue>` và queue phải tồn tại. Với broker khác, xem convention tương ứng; không mang nguyên cú pháp RabbitMQ sang Artemis/Azure Service Bus mà không kiểm tra.

Trong Spring Boot có auto-configuration generic AMQP 1.0, default listener factory có thể được tạo tự động. Khi cấu hình thủ công không dùng auto-configuration này, bật hạ tầng annotation bằng `@EnableAmqp` và cung cấp listener container factory đúng kiểu/bean name:

~~~java
import org.springframework.amqp.client.AmqpConnectionFactory;
import org.springframework.amqp.client.annotation.EnableAmqp;
import org.springframework.amqp.client.config.MethodAmqpMessageListenerContainerFactory;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
@EnableAmqp
public class ProtonListenerConfiguration {

    @Bean("amqpListenerContainerFactory")
    MethodAmqpMessageListenerContainerFactory amqpListenerContainerFactory(
            AmqpConnectionFactory connectionFactory) {
        return new MethodAmqpMessageListenerContainerFactory(connectionFactory);
    }
}
~~~

**Lưu ý bean name:** đây là tên mặc định thường dùng cho generic `@AmqpListener` infrastructure của Spring; khi tự cấu hình phiên bản cụ thể, tham khảo hằng `AmqpDefaultConfiguration.DEFAULT_AMQP_LISTENER_CONTAINER_FACTORY_BEAN_NAME` và các mặc định của Boot. Có thể tránh phụ thuộc tên mặc định bằng cách chỉ định `containerFactory` tường minh ngay trong annotation khi dùng nhiều factory.

### 7.1. Một factory riêng cho listener đặc biệt

~~~java
import org.springframework.amqp.client.AmqpConnectionFactory;
import org.springframework.amqp.client.config.MethodAmqpMessageListenerContainerFactory;
import org.springframework.context.annotation.Bean;

@Bean("orderAmqp10ListenerFactory")
MethodAmqpMessageListenerContainerFactory orderAmqp10ListenerFactory(
        AmqpConnectionFactory connectionFactory) {

    MethodAmqpMessageListenerContainerFactory factory =
            new MethodAmqpMessageListenerContainerFactory(connectionFactory);
    factory.setConcurrency(3);
    factory.setAutoAccept(true);
    return factory;
}
~~~

~~~java
@AmqpListener(
    addresses = "/queues/orders.inbox.q",
    containerFactory = "orderAmqp10ListenerFactory"
)
public void receive(String orderId) {
    // Chỉ minh họa. Khi chạy demo, không bật đồng thời
    // nhiều listener cạnh tranh trên cùng một queue.
}
~~~

**Lưu ý về cú pháp:** ví dụ trên là phần method/bean đặt trong một `@Configuration` / `@Component` phù hợp, không phải một file Java hoàn chỉnh. Spring AMQP 4.1+ còn cho phép đặt concurrency, initial credits, receive timeout và các thuộc tính khác của AMQP 1.0 listener container. Chỉ điều chỉnh khi hiểu cơ chế flow control/settlement của AMQP 1.0.

### 7.2. Settlement, link credit và xử lý lỗi

Trong AMQP 1.0, consumer nhận delivery qua **receiver link**. Link credit kiểm soát số delivery broker có thể gửi. Spring generic listener container sử dụng cơ chế credit này để giới hạn luồng dữ liệu:

| Khái niệm | Ý nghĩa |
| --- | --- |
| `initialCredits` | Số credit ban đầu của receiver link; tác động số delivery được phép nhận trước khi bổ sung credit. |
| `autoAccept=true` | Container tự xử lý accept/settlement phù hợp sau khi gọi listener; cần hiểu error handling theo version. |
| `autoAccept=false` | Cho phép logic ứng dụng kiểm soát settlement thông qua `AmqpAcknowledgment` hoặc native delivery khi cấu hình phù hợp. |
| `consumersPerQueue` / concurrency | Số receiver/consumer chạy song song cho một address. |
| `recoveryBackOff` | Khoảng chờ/giới hạn để tái tạo receiver link khi receive bị lỗi. |

AMQP 1.0 dùng **delivery outcome** như `Accepted`, `Released` và `Rejected`, không phải đúng bộ frame `basic.ack`/`basic.nack` của AMQP 0-9-1. Với RabbitMQ, những outcome đó có ánh xạ sang hành vi broker, nhưng **không được sao chép y nguyên logic requeue/DLX từ một `SimpleRabbitListenerContainerFactory` 0-9-1** rồi nghĩ rằng luôn tương đương.

Khi listener thất bại, hãy kiểm tra chính sách autoAccept, error handler, retry và broker-specific dead-letter. Để tránh poison message quay vòng, đặt số lần thử có giới hạn và một nơi lưu thông tin lỗi (DLQ hoặc persistent failure store) theo broker.

## 8. Sự khác biệt với @RabbitListener và RabbitTemplate

| Nhu cầu | AMQP 0-9-1 của RabbitMQ | Generic AMQP 1.0 / ProtonJ2 |
| --- | --- | --- |
| Gửi message | `RabbitTemplate.convertAndSend(exchange, routingKey, ...)` | `AmqpClient.to(address).body(...).send()` |
| Nhận message | `@RabbitListener(queues="...")` | `@AmqpListener(addresses="...")` |
| Nơi quản lý connection | `CachingConnectionFactory` (`spring-rabbit`) | `SingleAmqpConnectionFactory` (`spring-amqp-client`) |
| Routing | API tách exchange và routing key | **Address** do broker định nghĩa; RabbitMQ v2 có `/exchanges/x/key` |
| Confirm/giao nhận | Publisher confirm và consumer ACK trên 0-9-1 | `CompletableFuture` kết quả send và AMQP 1.0 delivery settlement |
| Nhận song song | Prefetch/concurrency trên listener container 0-9-1 | Receiver link credit/concurrency trên container AMQP 1.0 |
| Khôi phục | Connection/channel/container recovery theo `spring-rabbit` | ProtonJ2 reconnect + receiver-link recovery của generic listener container |

Nếu dự án đang dùng nhiều tính năng RabbitMQ 0-9-1 như topology binding tùy biến, RabbitTemplate transaction hay retry advice đã được thử kỹ, **đừng thay cả ứng dụng sang AMQP 1.0 chỉ vì tên protocol có số 1.0**. Việc chuyển cần đánh giá từng capability, format message, settlement và broker-version.

## 9. Auto-configuration trong Spring Boot 4.x

Spring Boot 4.2 có hỗ trợ auto-configuration cho generic AMQP 1.0 với key **`spring.amqp.*`**:

~~~yaml
spring:
  amqp:
    host: localhost
    port: 5672
    username: app-user
    password: ${AMQP10_PASSWORD}
    client:
      default-to-address: "/queues/orders.inbox.q"
      completion-timeout: 5s
~~~

Khi dùng `spring-boot-starter-amqp` đúng thế hệ, Spring Boot có thể cung cấp bean `AmqpConnectionFactory`, `AmqpClient` và listener factory mặc định. Ứng dụng chỉ cần:

~~~java
import org.springframework.amqp.client.AmqpClient;
import org.springframework.stereotype.Component;

@Component
public class OrdersBootPublisher {
    private final AmqpClient client;

    public OrdersBootPublisher(AmqpClient client) {
        this.client = client;
    }

    public void submit(String orderId) {
        client.to("/queues/orders.inbox.q")
              .body(orderId)
              .send()
              .whenComplete((accepted, error) -> {
                  // Ghi kết quả / metric / outbox theo chính sách ứng dụng.
              });
    }
}
~~~

Với auto-config, có thể đăng ký **`ConnectionOptionsCustomizer`** để tùy chỉnh ProtonJ2 connection options và **`AmqpClientCustomizer`** cho fluent client, theo API của Spring Boot tương ứng. Khi bạn đã tạo một bean `AmqpConnectionFactory` thủ công, phải kiểm tra điều kiện auto-configuration để tránh hai bean xung đột hoặc application tự lấy bean không mong muốn.

Ba nhóm key Spring Boot 4.2 cần phân biệt:

| Thư viện/hướng sử dụng | Namespace config trong Boot 4.2 |
| --- | --- |
| Generic AMQP 1.0 / Qpid ProtonJ2 | `spring.amqp.*` |
| RabbitMQ-specific AMQP 1.0 / native Java client | `spring.amqp.rabbitmq.*` |
| RabbitMQ AMQP 0-9-1 truyền thống | `spring.rabbitmq.*` |

Nếu chỉ nhìn key `spring.rabbitmq.host` nhưng đang dùng generic `spring-amqp-client`, ứng dụng có thể không kết nối đến endpoint bạn tưởng. Kiểm tra **effective config**, bean factory và địa chỉ broker trước khi thử publish.

## 10. Khôi phục connection và receiver link

### 10.1. Reconnect không đồng nghĩa phục hồi toàn bộ công việc

`SingleAmqpConnectionFactory` có thể cấu hình reconnect của ProtonJ2 bằng `ReconnectOptions`. Kết nối sau sự cố mạng có thể được thiết lập lại, nhưng các publish có kết quả chưa rõ có thể đã đến broker hoặc chưa. Đồng thời, **receiver link** có thể gặp lỗi độc lập với connection.

~~~text
AmqpClient.send()
       |
       v
Connection / Session / Sender link
       |
       +--> mạng chập chờn, reconnect
       |            |
       |            +--> link hoặc operation cần phục hồi
       |
       +--> send outcome chưa rõ
                    |
                    v
             retry an toàn bằng cùng eventId
             + consumer idempotent
~~~

Theo tài liệu Spring, generic `AmqpMessageListenerContainer` có thể khôi phục receiver link sau lỗi `Receiver.receive()` theo `recoveryBackOff` (mặc định dạng `FixedBackOff` theo phiên bản được ghi nhận). Nó không chỉ trông chờ connection reconnect để tự bảo đảm mọi receiver link vẫn còn nguyên.

### 10.2. Vấn đề shared session và SpringAmqpConnectionFactory

Một điểm cần biết khi triển khai **Spring AMQP 4.1.3 trở lên**:

- `SingleAmqpConnectionFactory` dùng connection ProtonJ2 và các links có thể cùng nằm trên default session.
- Nếu peer đóng session do lỗi (ví dụ thiếu quyền), connection TCP có thể vẫn mở nhưng session/links đã mất; ProtonJ2 có trường hợp không tự thay default session đã đóng.
- Spring bổ sung **`SpringAmqpConnectionFactory`** (kế thừa Single, **since 4.1.3**) để quản lý một shared session riêng, thay session đã đóng khi mở link mới; đây là giải pháp tương thích cho tình huống này.

Nếu ứng dụng thường xuyên gặp vấn đề **session bị đóng nhưng connection vẫn sống**, hãy kiểm tra việc dùng lớp này và tài liệu theo phiên bản:

~~~java
import org.springframework.amqp.client.AmqpConnectionFactory;
import org.springframework.amqp.client.SpringAmqpConnectionFactory;
import org.springframework.context.annotation.Bean;

@Bean
AmqpConnectionFactory resilientAmqpConnectionFactory() {
    return new SpringAmqpConnectionFactory()
            .setHost("localhost")
            .setPort(5672);
}
~~~

Ví dụ này chỉ minh họa factory thích hợp khi dùng Spring AMQP 4.1.3+, chưa có credentials/TLS. **Đừng tạo cả `SingleAmqpConnectionFactory` và `SpringAmqpConnectionFactory` cùng lúc rồi để Spring tự đoán bean**. Chọn một implementation theo yêu cầu, cấu hình đầy đủ và thử với broker thật.

Recovery không thay thế việc sửa sai quyền truy cập hoặc topology: nếu session/link bị broker đóng vì truy cập address không được phép, việc khôi phục lặp lại có thể tiếp tục thất bại.

## 11. Độ tin cậy đầu cuối với ProtonJ2 và Spring AMQP 1.0

Đối với message nghiệp vụ quan trọng, phân biệt:

| Điểm đo | Bằng chứng | Chưa chứng minh |
| --- | --- | --- |
| `AmqpClient.to(...).send()` được gọi | App yêu cầu gửi. | Broker đã nhận. |
| Future trả về accepted/success | Remote peer đã settlement theo kết quả API. | Listener đã cập nhật DB đúng. |
| Receiver nhận delivery | Message đã đến receiver link. | Side effect nghiệp vụ commit. |
| Consumer settlement/accept | Delivery được xử lý ở tầng AMQP theo chế độ phù hợp. | Toàn bộ tác vụ downstream đã hoàn thành. |
| Outbox/inbox/task table ghi DONE | Có dấu vết nghiệp vụ cụ thể. | Các side effect ngoài DB đã exactly-once nếu thiếu idempotency. |

**Với RabbitMQ**, gửi tới exchange không có queue phù hợp có thể tạo outcome `Released` thay vì accepted. Đây không phải nguyên văn cơ chế `basic.return`/`mandatory` của 0-9-1. Cần kiểm tra outcome thực tế của broker và topology thay vì chỉ kiểm tra TCP connection còn mở.

Một luồng có khả năng khôi phục nên dùng:

1. **Transactional outbox**: ghi business event trong cùng DB transaction với thay đổi nghiệp vụ; một dispatcher gửi sau.
2. **Business event ID ổn định**: không thay sau timeout/reconnect.
3. **Quan sát settlement và lỗi gửi**: lưu trạng thái delivered/unknown/retry kèm metadata phù hợp.
4. **Idempotent consumer**: lưu dấu eventId vào inbox theo transaction với thay đổi DB để ngăn thực thi trùng.
5. **Retry giới hạn, backoff và dead-letter/failure store**: tùy broker và error handler.
6. **Đối soát đầu cuối**: so sánh event nguồn với kết quả nghiệp vụ; không dừng ở trạng thái future thành công.

Đặc biệt, khi API Java dùng `CompletableFuture.orTimeout(...)`, future có thể kết thúc vì deadline của caller nhưng **không bảo đảm hủy delivery đã được broker nhận**. Hãy coi outcome chưa rõ là một trạng thái cần đối soát và retry an toàn.

## 12. Một ứng dụng kết nối nhiều AMQP 1.0 broker

Vì `Client` ProtonJ2 có thể tạo nhiều connection, ứng dụng có thể dùng một client gốc và nhiều `SingleAmqpConnectionFactory`, mỗi factory trỏ một broker. Tuy nhiên, mỗi factory vẫn đại diện cho **một connection dùng chung của chính broker đó**; việc tạo hai factory không đồng nghĩa một shared connection qua hai broker.

~~~java
import org.apache.qpid.protonj2.client.Client;
import org.springframework.amqp.client.AmqpConnectionFactory;
import org.springframework.amqp.client.SingleAmqpConnectionFactory;
import org.springframework.amqp.client.AmqpClient;
import org.springframework.beans.factory.annotation.Qualifier;
import org.springframework.context.annotation.Bean;

@Bean
AmqpConnectionFactory ordersAmqp10Factory(Client protonClient) {
    return new SingleAmqpConnectionFactory(protonClient)
            .setHost("orders-rmq.internal")
            .setPort(5672);
}

@Bean
AmqpConnectionFactory auditAmqp10Factory(Client protonClient) {
    return new SingleAmqpConnectionFactory(protonClient)
            .setHost("audit-rmq.internal")
            .setPort(5672);
}

@Bean
AmqpClient ordersAmqpClient(
        @Qualifier("ordersAmqp10Factory") AmqpConnectionFactory factory) {
    return AmqpClient.builder(factory).build();
}

@Bean
AmqpClient auditAmqpClient(
        @Qualifier("auditAmqp10Factory") AmqpConnectionFactory factory) {
    return AmqpClient.builder(factory).build();
}
~~~

Đây là đoạn mã **minh họa các bean method**; để chạy, đặt trong lớp `@Configuration` cùng bean `Client` và bổ sung credentials, TLS, routing address. Các endpoint chỉ là giả định; không sử dụng nguyên cấu hình không có bảo mật trong production.

Với nhiều broker, dùng `@Qualifier` cho mọi `AmqpClient`, factory và listener container tương ứng. Thiết kế **metric/log có nhãn broker alias ổn định** để xác định broker nào lỗi; không dùng eventId/customerId làm metric label vì cardinality quá cao. Khả năng một broker gặp sự cố không tự động làm message chuyển sang broker còn lại.

## 13. Quan sát và xử lý sự cố

### 13.1. Metric cần theo dõi

| Metric | Điều phản ánh | Vì sao cần |
| --- | --- | --- |
| Số connection/link và reconnect | Vòng đời ProtonJ2 connection/session/link. | Nhận diện broker không sẵn sàng hoặc link bị đóng. |
| AMQP 1.0 send requests | Lượt ứng dụng cố gửi. | Không nhầm với số message được broker chấp nhận. |
| Send accepted/rejected/released/error | Kết quả settlement hoặc lỗi API. | Phát hiện sai topology, quyền hoặc tài nguyên. |
| Pending `CompletableFuture` và thời gian hoàn tất | Tốc độ phản hồi từ peer. | Phát hiện nghẽn, timeout và quá tải. |
| Listener processed/failed, receiver recovery | Tình trạng xử lý đầu nhận. | Biết link nào cần khôi phục và error handling. |
| Business outbox pending age, DLQ, processing latency | Trạng thái nghiệp vụ. | Kiểm tra độ tin cậy đầu cuối. |

Nên phân loại kết quả gửi theo **broker**, **destination group**, **error category** và **operation**. Không đưa eventId, orderId hoặc raw exception message vào metric tags. Đặt các ID vào **structured logs/traces** để tra cứu cụ thể và bảo vệ thông tin nhạy cảm.

### 13.2. Bảng khắc phục lỗi thường gặp

| Hiện tượng | Nguyên nhân có thể | Cách kiểm tra |
| --- | --- | --- |
| Không tìm được `org.springframework.amqp.client.SingleAmqpConnectionFactory` | Spring AMQP cũ hơn 4.1 hoặc thiếu `spring-amqp-client`. | Kiểm tra dependency tree, Spring Boot BOM và đúng package. |
| Import được factory nhưng constructor yêu cầu `Environment` | Có thể đang import **RabbitMQ-specific** `org.springframework.amqp.rabbitmq.client.SingleAmqpConnectionFactory`. | Kiểm tra import, chọn generic ProtonJ2 hay RabbitMQ native. |
| `@RabbitListener` không nhận message do `AmqpClient` gửi | Listener có thể nằm trên connection/queue khác, hoặc đang cấu hình nhầm hai protocol/factory. | Dùng `@AmqpListener` cho generic AMQP 1.0, kiểm tra destination/vhost và topology. |
| Broker từ chối connection | Không hỗ trợ AMQP 1.0, cổng/TLS/SASL/vhost sai. | Xem server logs, version, protocol header và thông tin kết nối. |
| Gửi tới `/queue/name` nhưng không tới nơi | Cú pháp address v1 cũ hoặc không được broker hỗ trợ. | Trên RabbitMQ 4.x dùng `/queues/name` và `/exchanges/x/key` v2. |
| Gửi tới exchange nhưng receive không có message | Exchange/queue/binding không tồn tại, routing key sai hoặc thiếu quyền. | Kiểm tra topology và settlement/outcome; RabbitMQ có thể trả `Released` khi unroutable. |
| Future không hoàn tất đúng hạn | Broker/link/network chậm, timeout hoặc recovery đang diễn ra. | Đo pending futures, link state, error logs và connection recovery. |
| Connection đã reconnect, listener vẫn không nhận | Receiver link lỗi hoặc session đã bị đóng. | Kiểm tra container recovery; cân nhắc `SpringAmqpConnectionFactory` từ 4.1.3 cho closed session case. |
| Producer nhận thành công nhưng DB đích thiếu bản ghi | Settlement không phải business completion; consumer lỗi sau đó. | Dùng inbox/outbox và đối soát kết quả nghiệp vụ. |
| Retry tạo hai tác vụ | Publish trước đã thành công nhưng client mất outcome. | Giữ eventId gốc, unique constraint và idempotent consumer. |

## 14. Bài thực hành: dùng SingleAmqpConnectionFactory trên RabbitMQ 4.x

**Bối cảnh:** một Spring Boot service phát sự kiện `order.created` qua AMQP 1.0; một consumer nhận sự kiện và lưu dấu vào database. Từ đó bạn kiểm chứng reconnect, settlement và phòng ngừa xử lý trùng.

### 14.1. Chuẩn bị

1. Chọn **Spring AMQP 4.1+** (khuyến nghị dùng BOM của Spring Boot tương thích). Nếu dùng Spring Boot 4.2, thêm `spring-boot-starter-amqp`.
2. Chuẩn bị **RabbitMQ 4.0+** có AMQP 1.0 native, user/vhost phù hợp và connection endpoint hoạt động.
3. Tạo direct exchange `orders.events.x`, durable queue `orders.inbox.q`, binding với routing key `order.created` bằng công cụ quản trị RabbitMQ.
4. Khai báo `SingleAmqpConnectionFactory`, `AmqpClient` và `@AmqpListener` theo các ví dụ trong bài.
5. Xác minh address: producer gửi tới `/exchanges/orders.events.x/order.created`, listener đọc từ `/queues/orders.inbox.q`.

### 14.2. Gửi thử và quan sát future

~~~java
CompletableFuture<Boolean> receipt =
        orderAmqp10Publisher.publishOrderCreated(
                "evt-100", "ORDER-100");

receipt.whenComplete((accepted, error) -> {
    if (error != null) {
        System.err.println("Delivery outcome error: " + error);
    } else {
        System.out.println("Peer accepted: " + accepted);
    }
});
~~~

Chú ý `orderAmqp10Publisher` là instance của service `OrderAmqp10Publisher` ở mục 6. Đo thời điểm gửi, thời điểm future hoàn tất và thời điểm listener xử lý. Khi message đã được peer accepted, **consumer vẫn có thể xử lý muộn hơn** do backlog hoặc lỗi nghiệp vụ.

### 14.3. Các kịch bản nên thử

| Kịch bản | Điều cần quan sát | Kết luận mong đợi |
| --- | --- | --- |
| Gửi đúng exchange/routing key | Future gửi hoàn tất; listener nhận. | Đường định tuyến AMQP 1.0 và binding hoạt động. |
| Gửi tới exchange không có binding | Future/outcome không như trường hợp accepted bình thường. | RabbitMQ có thể trả released; phải theo dõi settlement. |
| Đổi address sang cú pháp cũ | Link không hoạt động hoặc hành vi khác tùy broker. | Cần dùng RabbitMQ v2 syntax. |
| Dừng RabbitMQ trong khi publish | Connection reconnect, future error/timeout hoặc kết quả chưa rõ. | Không kết luận tất cả message đã mất; retry an toàn. |
| Khởi động lại RabbitMQ | Connection/link recovery và listener hoạt động trở lại. | Reconnect cần kết hợp receiver recovery. |
| Giả lập lỗi trong listener | Error handler, settlement và retry tương ứng. | Không để poison message lặp vô hạn. |
| Gửi hai message cùng eventId | Consumer chỉ tạo một side effect theo business ID. | Đảm bảo idempotency dù delivery có thể lặp. |
| Dùng nhầm `spring.rabbitmq.*` | Endpoint cấu hình có thể không áp dụng vào generic client. | Xác minh đúng namespace `spring.amqp.*`. |

### 14.4. Câu hỏi tự kiểm tra

**Câu 1.** `org.springframework.amqp.client.SingleAmqpConnectionFactory` và `org.springframework.amqp.rabbitmq.client.SingleAmqpConnectionFactory` có phải cùng một lớp không?

**Trả lời:** **Không.** Lớp đầu quản lý **ProtonJ2 Connection** và dành cho AMQP 1.0 generic (từ Spring AMQP 4.1); lớp sau quản lý **RabbitMQ native AMQP 1.0 Connection** và dành riêng cho RabbitMQ. Cần xem package và dependency trước khi chọn.

**Câu 2.** Vì sao `SingleAmqpConnectionFactory` vẫn phục vụ nhiều sender/receiver?

**Trả lời:** `Single` chỉ mô tả một shared **connection**; AMQP 1.0 multiplex các sender/receiver **links** trên connection/session. Không cần TCP connection riêng cho mỗi message hoặc listener.

**Câu 3.** Gọi `AmqpClient.to(...).send()` nhận `CompletableFuture<Boolean>` rồi future hoàn tất thành công. Điều đó có chứng minh đơn hàng đã được xử lý tại DB đích?

**Trả lời:** Không. Future biểu thị outcome giao message ở tầng AMQP 1.0. Cần quan sát listener và dữ liệu nghiệp vụ; dùng outbox/inbox/idempotency để bảo đảm phục hồi đầu cuối.

**Câu 4.** Trên RabbitMQ 4.x, để gửi qua exchange `orders.events.x` với routing key `order.created`, nên chọn address nào?

**Trả lời:** `/exchanges/orders.events.x/order.created` theo RabbitMQ address v2. Queue đích phải có binding tương ứng.

**Câu 5.** Producer vừa timeout trong lúc broker restart. Có nên tạo eventId mới khi publish lại?

**Trả lời:** Không. Publish ban đầu có thể đã được broker chấp nhận nhưng outcome không tới producer. Giữ eventId cũ và để consumer chống trùng theo business ID.

**Câu 6.** Broker đóng session nhưng connection còn mở; chỉ bật reconnect có đủ không?

**Trả lời:** Không chắc. ProtonJ2 có trường hợp default session đã đóng mà không tự thay; từ Spring AMQP 4.1.3, `SpringAmqpConnectionFactory` giúp tạo lại shared session khi mở link mới. Vẫn phải sửa nguyên nhân khiến peer đóng session.

## 15. Ghi nhớ

**Qpid ProtonJ2** cung cấp AMQP 1.0 client; **`AmqpConnectionFactory`** thuộc package **`org.springframework.amqp.client`** là contract quản lý kết nối; **`SingleAmqpConnectionFactory`** là implementation giữ một ProtonJ2 connection dùng chung cho nhiều sender và receiver links. Trong **Spring AMQP 4.1+**, bạn có thể gửi qua **`AmqpClient`** trả `CompletableFuture` và nhận bằng **`@AmqpListener`**. Khi dùng RabbitMQ, địa chỉ AMQP 1.0 nên theo **v2 `/exchanges/...` hoặc `/queues/...`**, đồng thời exchange, queue, binding vẫn phải được provision phù hợp. Phải kiểm tra đúng **version/package/dependency**, cấu hình reconnect và receiver recovery, đồng thời bảo đảm idempotency, retry và đối soát: **kết quả settlement của message không phải kết quả nghiệp vụ cuối cùng**.
