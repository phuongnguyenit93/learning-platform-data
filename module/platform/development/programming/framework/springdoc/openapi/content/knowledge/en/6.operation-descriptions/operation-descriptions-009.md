# Hiding Controllers or Operations with @Hidden

In a Spring Boot application, not every registered endpoint needs to appear in the API documentation meant for integrators. There may be internal endpoints, operational endpoints, backward-compatible routes, or methods reserved for special tasks. Springdoc provides the @Hidden annotation to exclude a controller or method from the generated OpenAPI document.

@Hidden affects the API documentation process. It does not remove Spring beans, delete request mappings, or block HTTP requests. If an endpoint requires access restrictions, the application must still use Spring Security and business permission checks. This is the most important boundary when using this annotation.

This lesson explains how to hide an entire controller, hide only one operation, use @Operation(hidden = true) as an alternative, handle @RestControllerAdvice and exception handlers, and distinguish hiding an operation from hiding a parameter or schema. At the end, it shows examples for verifying the OpenAPI document to confirm the right parts are hidden and verifying HTTP behavior still follows security policies.

## 1. What is @Hidden Used For?

@Hidden belongs to Swagger annotations:

~~~java
import io.swagger.v3.oas.annotations.Hidden;
~~~

Springdoc reads this annotation when scanning controllers and generating the OpenAPI document. Depending on where the annotation is placed:

- Placed on a controller to hide that controller's operations.
- Placed on a method to hide only the corresponding operation.
- Placed on @RestControllerAdvice to exclude the advice from descriptions built by Springdoc.
- Placed on an exception handler method to affect how Springdoc builds generic error responses from @ControllerAdvice.

Swagger Core declares @Hidden with runtime retention and targets including TYPE, METHOD, FIELD, and ANNOTATION_TYPE. In Springdoc applications, the most common targets are type and method. For fields or schema properties, @Schema(hidden = true) usually expresses the intent more clearly.

## 2. Hiding an Entire Controller

When @Hidden is placed on a controller class, Springdoc excludes that controller from the documentation:

~~~java
import io.swagger.v3.oas.annotations.Hidden;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

@Hidden
@RestController
@RequestMapping("/internal/maintenance")
public class MaintenanceController {

    @GetMapping("/status")
    public MaintenanceStatus getStatus() {
        return maintenanceService.currentStatus();
    }

    @PostMapping("/rebuild-index")
    public RebuildResult rebuildIndex() {
        return maintenanceService.rebuildIndex();
    }
}
~~~

The operations GET /internal/maintenance/status and POST /internal/maintenance/rebuild-index will not be included in the OpenAPI document generated by Springdoc.

This is the right choice when an entire controller belongs to a group of endpoints not intended for public API consumers. For example:

- Maintenance endpoints intended only for operations teams.
- Internal health or check endpoints called by monitoring systems.
- Endpoints serving migration or data-repair tasks.
- Legacy controllers you do not want published in partner-facing docs.

If only one method in a controller needs to be hidden, use method-level @Hidden so the remaining operations stay documented.

## 3. Hiding a Single Method in a Controller

You can keep the controller and its public operations visible while excluding a single method from OpenAPI:

~~~java
@RestController
@RequestMapping("/api/orders")
@Tag(name = "Orders", description = "Look up and manage orders")
public class OrderController {

    @GetMapping("/{id}")
    @Operation(
        operationId = "getOrderById",
        summary = "Look up order"
    )
    public OrderResponse getById(@PathVariable UUID id) {
        return orderService.getById(id);
    }

    @Hidden
    @PostMapping("/{id}/replay-events")
    public ReplayResult replayEvents(@PathVariable UUID id) {
        return orderService.replayEvents(id);
    }

    @DeleteMapping("/{id}")
    @Operation(
        operationId = "deleteOrder",
        summary = "Delete order"
    )
    public ResponseEntity<Void> delete(@PathVariable UUID id) {
        orderService.delete(id);
        return ResponseEntity.noContent().build();
    }
}
~~~

In the document:

- GET /api/orders/{id} still appears.
- DELETE /api/orders/{id} still appears.
- POST /api/orders/{id}/replay-events is hidden.

Placing the annotation directly on the implementation method makes intent clear to source readers. After adding the annotation, inspect the actual JSON instead of relying only on compilation succeeding.

## 4. @Operation(hidden = true) as Another Way to Hide an Operation

Springdoc also supports the hidden attribute of @Operation:

~~~java
@PostMapping("/internal/reindex")
@Operation(
    operationId = "reindexCatalog",
    summary = "Rebuild search index",
    hidden = true
)
public ReindexResult reindex() {
    return catalogService.reindex();
}
~~~

Two common approaches:

~~~java
@Hidden
@PostMapping("/internal/reindex")
public ReindexResult reindex() {
    return catalogService.reindex();
}
~~~

~~~java
@PostMapping("/internal/reindex")
@Operation(hidden = true)
public ReindexResult reindex() {
    return catalogService.reindex();
}
~~~

Pick one approach per operation to avoid redundant metadata. @Hidden is Swagger's general annotation for marking a resource or method excluded from documentation; @Operation(hidden = true) explicitly expresses that the OpenAPI operation is not published.

## 5. Comparing the Scope of Hiding Approaches

| Declaration | Hidden Target | Other Operations in Controller |
|---|---|---|
| @Hidden on controller | Entire controller | Also hidden |
| @Hidden on method | Corresponding method | Kept |
| @Operation(hidden = true) | Corresponding operation | Kept |
| @Hidden on @RestControllerAdvice | Advice during doc generation | Business controllers kept |
| @Parameter(hidden = true) | One parameter | Operation kept |
| @Schema(hidden = true) | Schema/property where applied | Operation usually kept |

Choose the annotation matching the exact level you want to hide. Misusing @Parameter(hidden = true) will only hide the parameter, not the operation. Using @Schema(hidden = true) is likewise not a way to hide an entire controller.

## 6. Importing the Right @Hidden

The annotation to use is:

~~~java
import io.swagger.v3.oas.annotations.Hidden;
~~~

Do not confuse it with similarly named annotations in internal packages or other libraries. If you add @Hidden and the operation still appears, check the import in source code and the actual Swagger annotations dependency.

Other OpenAPI annotations often used alongside it:

~~~java
import io.swagger.v3.oas.annotations.Operation;
import io.swagger.v3.oas.annotations.Parameter;
import io.swagger.v3.oas.annotations.media.Schema;
~~~

After refactoring Springdoc or Swagger Core dependencies, verify the package and version of the annotation compiled into the application.

## 7. @Hidden Does Not Disable the Endpoint

This is essential to remember when hiding internal endpoints. @Hidden only controls whether Springdoc reads the endpoint to build documentation. Spring MVC or Spring WebFlux can still register the mapping and continue serving requests.

Example:

~~~java
@Hidden
@RestController
@RequestMapping("/internal/diagnostics")
public class DiagnosticsController {

    @GetMapping
    public DiagnosticsSnapshot snapshot() {
        return diagnosticsService.snapshot();
    }
}
~~~

After adding @Hidden:

- /v3/api-docs does not contain the /internal/diagnostics path.
- Spring can still register GET /internal/diagnostics.
- Direct HTTP requests can still execute if they pass security filters and other runtime conditions.

Never treat an endpoint's absence from Swagger UI as proof that the endpoint is secured or unreachable.

## 8. Securing Endpoints with Spring Security

If an endpoint is intended only for administrators, define authorization rules independently of @Hidden:

~~~java
@Configuration
@EnableWebSecurity
public class SecurityConfiguration {

    @Bean
    SecurityFilterChain applicationSecurity(HttpSecurity http) throws Exception {
        return http
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/internal/**").hasRole("ADMIN")
                .requestMatchers("/api/**").authenticated()
                .anyRequest().denyAll()
            )
            .httpBasic(Customizer.withDefaults())
            .build();
    }
}
~~~

This is an illustrative example. Real projects may use OAuth2 Resource Server, JWT, sessions, or other authentication mechanisms. The key rule is that authorization must be enforced at runtime and verified with HTTP tests.

They can be combined:

~~~java
@Hidden
@RestController
@RequestMapping("/internal")
public class InternalAdminController {
    // internal endpoints
}
~~~

@Hidden keeps public documentation tidy and avoids publishing internal operations. Spring Security controls who can call the endpoints. The two mechanisms solve two separate goals.

## 9. Hiding ControllerAdvice

Springdoc supports @Hidden on @RestControllerAdvice:

~~~java
@Hidden
@RestControllerAdvice
public class InternalExceptionAdvice {

    @ExceptionHandler(InternalWorkflowException.class)
    ResponseEntity<InternalErrorResponse> handle(
            InternalWorkflowException exception) {
        return ResponseEntity.internalServerError()
            .body(new InternalErrorResponse("INTERNAL_WORKFLOW_ERROR"));
    }
}
~~~

An advice may contain exception handlers intended solely for internal use or that should not appear in the generic error responses section of the documentation. Placing @Hidden on the advice makes Springdoc skip that advice when generating the corresponding documentation.

Do not place the annotation on a shared advice if its error responses need to be documented in the public API. In that case, keep the advice visible and document the error schema explicitly.

## 10. Hiding a Single Exception Handler Method

You can hide an individual handler method:

~~~java
@RestControllerAdvice
public class ApiExceptionAdvice {

    @ExceptionHandler(ProductNotFoundException.class)
    ResponseEntity<ApiError> handleNotFound(ProductNotFoundException ex) {
        return ResponseEntity.status(HttpStatus.NOT_FOUND)
            .body(new ApiError("PRODUCT_NOT_FOUND"));
    }

    @Hidden
    @ExceptionHandler(InternalWorkflowException.class)
    ResponseEntity<InternalErrorResponse> handleInternal(
            InternalWorkflowException ex) {
        return ResponseEntity.internalServerError()
            .body(new InternalErrorResponse("INTERNAL_WORKFLOW_ERROR"));
    }
}
~~~

Springdoc honors @Hidden on exception handler methods when building generic error responses from @ControllerAdvice. This affects the response metadata aggregated into the OpenAPI document; it does not remove the exception handler from Spring runtime.

If you want API consumers to know about 404 responses without exposing an internal error structure, document 404 with an appropriate public schema. Do not hide the entire advice just to omit one internal response if that drops other public error responses.

## 11. Distinguishing @Hidden from @Parameter(hidden = true)

@Parameter(hidden = true) hides a single parameter from documentation:

~~~java
@GetMapping("/me")
public ProfileResponse getCurrentProfile(
        @Parameter(hidden = true)
        @AuthenticationPrincipal UserPrincipal principal) {
    return profileService.getProfile(principal);
}
~~~

The GET /me operation still appears. The principal parameter is not documented as a value the client must supply, because Spring Security provides it from the security context.

Another example is a technical parameter injected by the framework:

~~~java
@GetMapping("/report")
public ReportResponse report(
        @RequestParam String period,
        @Parameter(hidden = true) HttpServletRequest request) {
    return reportService.create(period, request.getLocale());
}
~~~

period remains a public query parameter; request does not appear in the operation's input list.

If the goal is to hide the entire endpoint, use @Hidden or @Operation(hidden = true).

## 12. Distinguishing @Hidden from @Schema(hidden = true)

@Schema(hidden = true) is suitable for hiding a field or schema property:

~~~java
public class UserResponse {

    private UUID id;

    private String displayName;

    @Schema(hidden = true)
    private String internalRiskMarker;
}
~~~

Operations returning UserResponse are still published, while the internalRiskMarker property is excluded from the schema where applied.

Springdoc also supports hiding a response schema at the operation level:

~~~java
@Operation(
    responses = @ApiResponse(
        responseCode = "200",
        content = @Content(schema = @Schema(hidden = true))
    )
)
@GetMapping("/internal/export")
public InternalExport export() {
    return exportService.create();
}
~~~

In this case, the operation may still exist in the document, while the response schema is hidden. To exclude the whole operation, use @Hidden or @Operation(hidden = true).

## 13. Do Not Confuse Hiding an Operation with Disabling All API Docs

Some mechanisms have a broader scope:

| Mechanism | Scope |
|---|---|
| @Hidden on controller | One controller |
| @Hidden on method | One operation |
| @Operation(hidden = true) | One operation |
| GroupedOpenApi filters | One document group by package/path |
| springdoc.api-docs.enabled=false | Disables Springdoc's OpenAPI endpoints |
| springdoc.swagger-ui.enabled=false | Disables Swagger UI |

If you only need to hide one endpoint, do not disable springdoc.api-docs.enabled. If you still want JSON available without the UI, configure Swagger UI separately.

## 14. When Public and Internal Documents Need to Differ

@Hidden is an annotation-level choice and generally removes the operation from all OpenAPI documents Springdoc generates for the application. It is not a mechanism for hiding only in a single group.

Suppose the same operation must:

- Not appear in the public documentation.
- Still appear in internal documentation for the operations team.

In this case, do not place @Hidden directly on the method because the goal is distinguishing by document group. Configure GroupedOpenApi beans with suitable package/path filters or use group-specific customizers.

Example:

~~~java
@Bean
GroupedOpenApi publicApi() {
    return GroupedOpenApi.builder()
        .group("public")
        .packagesToScan("com.acme.api")
        .pathsToExclude("/internal/**")
        .build();
}

@Bean
GroupedOpenApi internalApi() {
    return GroupedOpenApi.builder()
        .group("internal")
        .packagesToScan("com.acme")
        .pathsToMatch("/internal/**")
        .build();
}
~~~

Inspect each document endpoint, such as /v3/api-docs/public and /v3/api-docs/internal. Ensure the internal document endpoint itself is protected with Spring Security if it is not meant for all users.

## 15. Choosing Between @Hidden and Filters

| Need | Appropriate Approach |
|---|---|
| Hide an entire controller from all documents | @Hidden on controller |
| Hide a single method from all documents | @Hidden on method or @Operation(hidden = true) |
| Exclude a package from the public group | GroupedOpenApi package filter |
| Exclude a path from one group | GroupedOpenApi path filter |
| Apply complex filtering rules per operation | Group-specific customizer |
| Hide a framework-injected parameter | @Parameter(hidden = true) |
| Hide an internal property in a schema | @Schema(hidden = true) |

Do not use @Hidden as a substitute for group filtering if the same operation must be published in another document.

## 16. Placing @Hidden on Interfaces or Overridden Methods

Some controllers declare contracts on interfaces and implement them in classes:

~~~java
public interface AdminOperations {

    @PostMapping("/rebuild")
    RebuildResult rebuild();
}

@RestController
@RequestMapping("/internal/index")
public class IndexAdminController implements AdminOperations {

    @Override
    public RebuildResult rebuild() {
        return indexService.rebuild();
    }
}
~~~

Springdoc can read many annotations from interfaces, yet exact results depend on how Spring resolves handlers, proxies, and the library version. When an operation needs to be hidden, the clearest place is usually the concrete implementation method:

~~~java
@Override
@Hidden
public RebuildResult rebuild() {
    return indexService.rebuild();
}
~~~

If it still appears in the document, check the JSON output, annotations on both interface and implementation, and the proxy structure in use. Do not assume Java automatically inherits every annotation from an interface onto an implementing method.

## 17. Annotation on a Custom Composed Annotation

Swagger Core allows @Hidden to appear on annotation types. This enables creating an internal meta-annotation to mark a group of controllers:

~~~java
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
@Hidden
public @interface InternalApiController {
}
~~~

Then:

~~~java
@InternalApiController
@RestController
@RequestMapping("/internal/cache")
public class CacheAdminController {
}
~~~

This is a meta-annotation technique; verify that your Springdoc and Swagger annotations versions recognize composed annotations in your application setup. If you want the most predictable behavior, place @Hidden directly on the controller or method and verify OpenAPI JSON.

## 18. Checking Imports and Dependencies When @Hidden Has No Effect

If an operation still appears after adding the annotation, check in order:

1. Is the import io.swagger.v3.oas.annotations.Hidden?
2. Is the annotation placed on the exact class or method Spring registers as a handler?
3. Does an interface or proxy cause the method to resolve differently from the source being inspected?
4. Is the application running the latest artifact rather than a stale build?
5. Are there conflicting Swagger annotations or Springdoc dependency versions?
6. Are you viewing the right OpenAPI document and group?
7. Does a customizer re-add the operation after scanning?

Do not look only at Swagger UI because the UI might be reading another document or cache. Query the OpenAPI endpoint directly to verify output.

## 19. Checking Operations in OpenAPI JSON

Suppose a controller has this path:

~~~java
@Hidden
@RestController
@RequestMapping("/internal/maintenance")
public class MaintenanceController {

    @GetMapping("/status")
    public MaintenanceStatus status() {
        return maintenanceService.status();
    }
}
~~~

Fetch the document:

~~~bash
curl --fail --silent --show-error \
  http://localhost:8080/v3/api-docs \
  -o target/openapi.json
~~~

List paths:

~~~bash
jq '.paths | keys' target/openapi.json
~~~

Check directly:

~~~bash
jq '.paths["/internal/maintenance/status"]' target/openapi.json
~~~

If the controller is properly hidden, the last expression returns null. With method-level hiding, the path may remain because another operation on the same path still exists; in that case, inspect individual methods like get, post, and delete inside the path object.

## 20. Checking Multiple HTTP Methods on the Same Path

One path can hold multiple operations:

~~~java
@RestController
@RequestMapping("/api/reports")
public class ReportController {

    @GetMapping("/{id}")
    public ReportResponse get(@PathVariable UUID id) {
        return reportService.get(id);
    }

    @Hidden
    @DeleteMapping("/{id}")
    public void purge(@PathVariable UUID id) {
        reportService.purge(id);
    }
}
~~~

OpenAPI may keep the path /api/reports/{id} with the get operation while omitting the delete operation. Therefore, do not check only the path key; inspect the methods inside it.

~~~bash
jq '.paths["/api/reports/{id}"] | keys' target/openapi.json
~~~

The expected output contains get and not delete.

## 21. Integration Test Verifying an Operation Is Hidden

You can verify the OpenAPI document using MockMvc and Jackson:

~~~java
@SpringBootTest
@AutoConfigureMockMvc
class HiddenOperationTest {

    @Autowired
    MockMvc mockMvc;

    @Autowired
    ObjectMapper objectMapper;

    @Test
    void hiddenControllerDoesNotAppearInOpenApi() throws Exception {
        MvcResult result = mockMvc.perform(get("/v3/api-docs"))
            .andExpect(status().isOk())
            .andReturn();

        JsonNode document = objectMapper.readTree(
            result.getResponse().getContentAsString()
        );

        assertThat(document.path("paths")
            .has("/internal/maintenance/status")).isFalse();
    }
}
~~~

For method-level hiding:

~~~java
@Test
void hiddenMethodIsRemovedButVisibleMethodRemains() throws Exception {
    MvcResult result = mockMvc.perform(get("/v3/api-docs"))
        .andExpect(status().isOk())
        .andReturn();

    JsonNode paths = objectMapper.readTree(
        result.getResponse().getContentAsString()
    ).path("paths");

    JsonNode orderPath = paths.path("/api/orders/{id}");

    assertThat(orderPath.has("get")).isTrue();
    assertThat(orderPath.has("post")).isFalse();
}
~~~

Adjust paths and methods to match your project's actual controllers. If using multiple GroupedOpenApi beans, call each group's exact URL and verify each document separately.

## 22. Verifying Endpoints Still Obey Runtime Policies

An OpenAPI test only proves the operation is absent from documentation. It does not prove the endpoint is locked down.

If an internal endpoint must require the ADMIN role, write a separate HTTP test:

~~~java
@Test
void internalEndpointRejectsAnonymousRequest() throws Exception {
    mockMvc.perform(get("/internal/maintenance/status"))
        .andExpect(status().isUnauthorized());
}

@Test
@WithMockUser(roles = "ADMIN")
void adminCanCallInternalEndpoint() throws Exception {
    mockMvc.perform(get("/internal/maintenance/status"))
        .andExpect(status().isOk());
}
~~~

Exact status codes depend on Spring Security configuration. An application might return 302 with form login or 403 depending on how policies are configured. What matters is that tests reflect the real policy.

If an endpoint is hidden yet still allows anonymous requests, that is its current runtime behavior; the annotation does not change it.

## 23. Hiding a Controller Does Not Replace Disabling Actuator Endpoints

Actuator endpoints have their own exposure and security mechanisms. If an Actuator endpoint should not be exposed, configure Actuator and Spring Security according to operational requirements.

@Hidden on business controllers does not control Actuator. Likewise, hiding an endpoint from OpenAPI does not stop it from being exposed via servlet mappings or the management port.

If the application uses a separate management server port, check both the application port and the management port.

## 24. Caching and Document Groups When Verifying Output

Springdoc may cache OpenAPI descriptions. When modifying annotations in a running environment, confirm the document comes from the right process and configuration. If the application has custom caching or multiple instances, check all instances before concluding an annotation failed to take effect.

For groups:

- /v3/api-docs is the default document.
- /v3/api-docs/{group} is a group's document.
- Swagger UI may be pointing to a different group.

An operation absent from the public group yet present in the internal group can be the result of intentional filtering. Do not add @Hidden if the requirement is simply to differ between groups.

## 25. Common Mistakes

| Symptom | Possible Cause | How to Fix |
|---|---|---|
| Added @Hidden yet operation still appears | Wrong import or annotation placed on a method that is not the actual handler | Check imports, mappings, and implementation |
| Controller disappears from Swagger UI yet route remains accessible | @Hidden only hides documentation | Add Spring Security if the route needs restriction |
| Only a parameter disappears | Used @Parameter(hidden = true) | Use @Hidden or @Operation(hidden = true) to hide the operation |
| Schema property disappears | Used @Schema(hidden = true) | Verify hiding target; the operation may still remain |
| One method disappears along with the whole controller | @Hidden placed on class | Move annotation to the method if hiding only one operation |
| Operation disappears from every group | Used @Hidden when it only needed hiding in the public group | Use GroupedOpenApi filters or a customizer |
| Exception response disappears from document | @Hidden on advice or exception handler | Check generic error responses and declare public responses explicitly |
| Swagger UI unchanged after source edit | UI reads another group/document or cache | Call /v3/api-docs directly and check the right instance |
| Internal endpoint callable without login | Used @Hidden without authorization | Protect runtime with Spring Security |
| Method-level test reports path still exists | Same path has another operation | Check HTTP methods inside the path item |

## 26. Workflow for Applying @Hidden

When deciding to hide part of an API:

1. Identify precisely whether a controller, method, advice, parameter, or schema needs hiding.
2. Determine which documents should hide it: all documents or only one group.
3. Use @Hidden on the controller to hide the entire controller.
4. Use @Hidden or @Operation(hidden = true) on the method to hide one operation.
5. Use @Parameter(hidden = true) for internal parameters.
6. Use @Schema(hidden = true) for properties or schemas to hide.
7. For differing public/internal documents, prefer group filters/customizers.
8. Inspect /v3/api-docs and relevant group documents.
9. Write tests confirming the path/method has disappeared from the document.
10. Write HTTP tests confirming runtime authorization remains accurate.

Do not change multiple mechanisms at once. After each change, inspect OpenAPI JSON and real requests to verify the annotation affects the intended scope.

## 27. Key Takeaways

- @Hidden belongs to io.swagger.v3.oas.annotations.Hidden.
- Place on a controller to hide its operations from documentation.
- Place on a method to hide a single operation.
- @Operation(hidden = true) is an alternative way to hide an operation.
- Springdoc supports @Hidden on @RestController, @RestControllerAdvice, and methods.
- @Hidden on exception handler methods is considered when Springdoc builds generic error responses from ControllerAdvice.
- @Parameter(hidden = true) only hides a parameter.
- @Schema(hidden = true) hides a schema/property where applied.
- @Hidden does not remove routes and does not enforce authentication/authorization.
- When hiding differs per document group, use GroupedOpenApi filters or customizers.
- Inspect OpenAPI JSON directly; for method-level hiding, check HTTP methods as well as paths.
- Test document visibility and HTTP access permissions separately.

@Hidden is a tool for controlling documentation scope. It keeps OpenAPI documents focused on operations the target audience needs to know, while Spring continues managing endpoints per runtime configuration. Choose the right annotation level, inspect the generated document, and maintain independent security tests so hiding documentation is never mistaken for securing an endpoint.
