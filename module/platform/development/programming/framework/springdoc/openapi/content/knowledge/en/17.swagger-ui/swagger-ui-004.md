# Selecting the Default Group and Organizing the Group List

When a Spring Boot application publishes multiple OpenAPI documents, Swagger UI needs to show users which document they are currently viewing and how to switch to another one. springdoc-openapi can generate multiple documents with **GroupedOpenApi**; Swagger UI displays a list of those documents for users to select. When multiple options exist, you should specify a default document and organize the list in an intuitive way.

Two common configurations are **url** when the UI uses only one document and **urls** when the UI needs a list of documents. With multiple documents, the **urls-primary-name** property selects the name of the document opened initially. This list is a list of OpenAPI specifications; it differs from tags and operations inside each specification.

## 1. GroupedOpenApi creates a separate document per group

Each **GroupedOpenApi** bean defines an endpoint scope and a group name. Example:

~~~java
@Configuration
public class OpenApiGroupConfiguration {

    @Bean
    GroupedOpenApi publicApi() {
        return GroupedOpenApi.builder()
            .group("public-api")
            .pathsToMatch("/api/**")
            .pathsToExclude("/api/internal/**")
            .build();
    }

    @Bean
    GroupedOpenApi adminApi() {
        return GroupedOpenApi.builder()
            .group("admin-api")
            .pathsToMatch("/api/admin/**")
            .build();
    }

    @Bean
    GroupedOpenApi partnerApi() {
        return GroupedOpenApi.builder()
            .group("partner-api")
            .packagesToScan("com.example.app.partner")
            .build();
    }
}
~~~

springdoc generates a separate document for each group. With default paths, they are accessible at:

| Group | OpenAPI JSON |
|---|---|
| Default document | /v3/api-docs |
| public-api | /v3/api-docs/public-api |
| admin-api | /v3/api-docs/admin-api |
| partner-api | /v3/api-docs/partner-api |

The group name is used in the document URL. Choose short, recognizable, and stable names because Swagger UI, API gateways, contract testing pipelines, or SDK generators may reference these URLs.

**Group** determines which operations belong to a document. **Tag** organizes operations inside that document. For instance, the public-api group may contain Books, Orders, and Payments tags; the admin-api group may contain Users and Audit tags. Do not use tags as a substitute for groups when the goal is to produce separate OpenAPI documents.

## 2. Selecting a default document with url

If Swagger UI only needs to display one document, configure **springdoc.swagger-ui.url**:

~~~yaml
springdoc:
  swagger-ui:
    url: /v3/api-docs/public-api
~~~

Or in application.properties:

~~~properties
springdoc.swagger-ui.url=/v3/api-docs/public-api
~~~

When opening Swagger UI, the interface loads the document at the specified URL. This works well when the application only wants to provide one document for a specific environment or user group.

If you want to use the default document generated by springdoc, you can point to /v3/api-docs or let springdoc use its default configuration. There is no need to declare a custom URL if the default document already serves the purpose.

**url** is a single document URL. When you need a dropdown for multiple documents, use the **urls** configuration.

## 3. Displaying multiple documents with urls

Swagger UI supports a list of specification URLs. springdoc lets you configure this list with **springdoc.swagger-ui.urls**.

Example application.yml:

~~~yaml
springdoc:
  swagger-ui:
    urls:
      - name: Public API
        url: /v3/api-docs/public-api
      - name: Admin API
        url: /v3/api-docs/admin-api
      - name: Partner API
        url: /v3/api-docs/partner-api
~~~

Or application.properties:

~~~properties
springdoc.swagger-ui.urls[0].name=Public API
springdoc.swagger-ui.urls[0].url=/v3/api-docs/public-api
springdoc.swagger-ui.urls[1].name=Admin API
springdoc.swagger-ui.urls[1].url=/v3/api-docs/admin-api
springdoc.swagger-ui.urls[2].name=Partner API
springdoc.swagger-ui.urls[2].url=/v3/api-docs/partner-api
~~~

Swagger UI will have a document selector. The name in **name** is the label users see; **url** is the address from which Swagger UI loads the specification. Both fields must stay consistent with actual group names and endpoints.

In the configuration above:

- Users select **Public API** to load /v3/api-docs/public-api.
- Users select **Admin API** to load /v3/api-docs/admin-api.
- Users select **Partner API** to load /v3/api-docs/partner-api.

The urls list can reference documents in the same application or documents from other servers. If using a cross-origin URL, the browser must be able to reach that server and the server must allow appropriate CORS.

## 4. Selecting the initially opened group with urls-primary-name

When multiple URLs exist, **springdoc.swagger-ui.urls-primary-name** specifies the document name selected when Swagger UI starts:

~~~yaml
springdoc:
  swagger-ui:
    urls:
      - name: Public API
        url: /v3/api-docs/public-api
      - name: Admin API
        url: /v3/api-docs/admin-api
      - name: Partner API
        url: /v3/api-docs/partner-api
    urls-primary-name: Public API
~~~

In application.properties:

~~~properties
springdoc.swagger-ui.urls[0].name=Public API
springdoc.swagger-ui.urls[0].url=/v3/api-docs/public-api
springdoc.swagger-ui.urls[1].name=Admin API
springdoc.swagger-ui.urls[1].url=/v3/api-docs/admin-api
springdoc.swagger-ui.urls[2].name=Partner API
springdoc.swagger-ui.urls[2].url=/v3/api-docs/partner-api
springdoc.swagger-ui.urls-primary-name=Public API
~~~

The **urls-primary-name** value must match one **name** value in the urls list exactly. This name is the document label in the dropdown; it does not have to equal the group name, though using matching names often makes configuration easier to read.

If you rename Public API to External API in the list, update urls-primary-name accordingly. If the default name does not match any item, Swagger UI may fall back to the first choice or the default behavior of the version in use; do not rely on that fallback in deployed environments.

### Distinguishing urls-primary-name from group name

Suppose GroupedOpenApi is declared as:

~~~java
@Bean
GroupedOpenApi publicApi() {
    return GroupedOpenApi.builder()
        .group("public-api")
        .pathsToMatch("/api/**")
        .build();
}
~~~

The group name is public-api, so the JSON URL is /v3/api-docs/public-api. In Swagger UI, the displayed entry can be named Public API; then:

- **group("public-api")** defines springdoc's group.
- **url: /v3/api-docs/public-api** points to the group's document.
- **name: Public API** sets the label in the selector.
- **urls-primary-name: Public API** selects that label as the default document.

Do not set urls-primary-name to a URL or group name if the name in the list is a different label.

## 5. Organizing the order of groups in the dropdown

When declaring **springdoc.swagger-ui.urls** manually, the element order in the list is the configuration order Swagger UI receives. You can put frequently used documents first:

~~~yaml
springdoc:
  swagger-ui:
    urls:
      - name: Public API
        url: /v3/api-docs/public-api
      - name: Partner API
        url: /v3/api-docs/partner-api
      - name: Admin API
        url: /v3/api-docs/admin-api
    urls-primary-name: Public API
~~~

A user-friendly order is typically:

1. Documentation meant for the majority of integrators.
2. Domain-specific or partner-specific documentation.
3. Administrative or internal documentation for authorized users.

This is a UI organization convention, not an authorization mechanism. If the urls list is declared manually, maintainers must update it whenever groups are added, renamed, or deleted.

### Choosing recognizable labels

Choose labels describing the target audience or scope:

| Prefer | Avoid |
|---|---|
| Public API | Group 1 |
| Partner API | Docs B |
| Administration API | Other |
| Billing API | New API |

Display names can contain spaces and uppercase letters for readability. Group names in GroupedOpenApi should remain stable, simple, and URL-friendly. You can use nicer labels in urls.name without changing the group URL.

## 6. Auto-detecting groups or explicitly declaring urls?

When registering multiple GroupedOpenApi beans, springdoc can populate those groups into the generated Swagger UI configuration. This avoids repeating each group's URL. For applications requiring exact control over the list or display labels, you can declare springdoc.swagger-ui.urls explicitly.

| Organization approach | Best suited when | Considerations |
|---|---|---|
| Using GroupedOpenApi beans | Groups are created and managed entirely within the application | Check /v3/api-docs/swagger-config to see the list the UI actually receives |
| Declaring swagger-ui.urls | Need precise control over documents, URLs, or dropdown labels | Must manually keep in sync with existing groups and URLs |
| Combining internal groups and external URLs | UI needs to aggregate docs from multiple services | Check CORS, HTTPS, reachability, and external URL lifecycle |

Avoid declaring the same document repeatedly across multiple urls entries. When configuring the list manually, ensure every name is unique and every URL points to a valid document.

If a new group is added but does not appear in the dropdown, inspect the Swagger UI configuration and the swagger-config endpoint. Do not check only the GroupedOpenApi bean, because a group existing does not mean a manually managed URL list has been updated.

## 7. Using relative URLs and configuring behind a reverse proxy

Within the same application, prefer relative URLs:

~~~yaml
springdoc:
  swagger-ui:
    urls:
      - name: Public API
        url: /v3/api-docs/public-api
      - name: Orders API
        url: /v3/api-docs/orders
~~~

Relative URLs help documentation work when the application is deployed on another host or domain. If the application runs under a context path, reverse proxy, or prefix such as /service-a, confirm that URLs actually requested by the browser include the right prefix.

If document URLs reside on another server:

~~~yaml
springdoc:
  swagger-ui:
    urls:
      - name: Catalog API
        url: https://api.example.test/catalog/v3/api-docs
      - name: Orders API
        url: https://api.example.test/orders/v3/api-docs
    urls-primary-name: Catalog API
~~~

The browser fetches documents directly from these URLs. Production requires HTTPS, proper CORS if cross-origin, and document access rights matching the user. Do not put tokens or credentials into the query string of document URLs.

## 8. Customizing display inside each document

The group list and operation sorting are two separate layers. **urls** organizes the list of documents; other Swagger UI properties organize content inside the currently selected document.

Example:

~~~yaml
springdoc:
  swagger-ui:
    doc-expansion: none
    tags-sorter: alpha
    operations-sorter: method
    filter: true
~~~

Properties:

| Property | Effect |
|---|---|
| **doc-expansion** | How tags and operations expand when loading the document: none, list, or full |
| **tags-sorter** | Sort tags within the document |
| **operations-sorter** | Sort operations within a tag |
| **filter** | Show the operation search filter |

These properties do not change the default group and do not sort the urls list. For example, tags-sorter: alpha sorts tags inside the open document; it does not change the order of Public API, Admin API, and Partner API in the dropdown.

## 9. Do not confuse default document with Swagger UI's default URL

Swagger UI needs to know which document or document configuration to load. Related properties:

| Property | Role |
|---|---|
| **springdoc.swagger-ui.url** | A single document URL |
| **springdoc.swagger-ui.urls** | A list of document URLs |
| **springdoc.swagger-ui.urls-primary-name** | Name of the list item selected initially |
| **springdoc.swagger-ui.config-url** | URL returning Swagger UI configuration, typically the swagger-config endpoint provided by springdoc |
| **springdoc.swagger-ui.disable-swagger-default-url** | Disables Swagger UI's default Petstore URL when you do not want the UI to use the sample document |

In a springdoc multi-group setup, the configuration endpoint is typically /v3/api-docs/swagger-config. Only change config-url for a specific reason, such as configuration being served via a custom URL or reverse proxy. config-url is neither the OpenAPI JSON URL nor the value of urls-primary-name.

If the UI unexpectedly opens the Petstore sample document, check url/urls and consider:

~~~yaml
springdoc:
  swagger-ui:
    disable-swagger-default-url: true
~~~

This helps avoid mistaking the default demo document for your application's API.

## 10. Complete configuration example

Suppose the application has three GroupedOpenApi beans:

~~~java
@Configuration
public class ApiDocumentationConfiguration {

    @Bean
    GroupedOpenApi publicApi() {
        return GroupedOpenApi.builder()
            .group("public-api")
            .pathsToMatch("/api/**")
            .pathsToExclude("/api/admin/**")
            .build();
    }

    @Bean
    GroupedOpenApi ordersApi() {
        return GroupedOpenApi.builder()
            .group("orders")
            .pathsToMatch("/api/orders/**")
            .build();
    }

    @Bean
    GroupedOpenApi adminApi() {
        return GroupedOpenApi.builder()
            .group("admin-api")
            .pathsToMatch("/api/admin/**")
            .build();
    }
}
~~~

application.yml configuration:

~~~yaml
springdoc:
  swagger-ui:
    urls:
      - name: Public API
        url: /v3/api-docs/public-api
      - name: Orders API
        url: /v3/api-docs/orders
      - name: Administration API
        url: /v3/api-docs/admin-api
    urls-primary-name: Public API
    disable-swagger-default-url: true
    doc-expansion: none
    tags-sorter: alpha
    operations-sorter: method
    filter: true
~~~

Expected results:

- Swagger UI opens the **Public API** document when users first visit.
- The dropdown displays Public API, Orders API, and Administration API.
- Users can switch documents without opening a different Swagger UI URL.
- Within each document, tags are sorted alphabetically, operations are sorted by method, and content groups start collapsed.
- Swagger UI does not use the default Petstore URL.

If you change a group name in Java, update the corresponding URL in application.yml. If you rename a name label, update urls-primary-name when that item is the default document.

## 11. Verifying Swagger UI receives the right group list

Do not look only at the source configuration. Inspect the swagger-config endpoint that Swagger UI actually loads:

~~~bash
curl -i http://localhost:8080/v3/api-docs/swagger-config
~~~

This endpoint returns the configuration used to initialize Swagger UI. Check the URL list, display names, and primary selection as output by your springdoc version.

Verify each document:

~~~bash
curl -i http://localhost:8080/v3/api-docs/public-api
curl -i http://localhost:8080/v3/api-docs/orders
curl -i http://localhost:8080/v3/api-docs/admin-api
~~~

If the API docs path was changed or the application runs under a context path, adjust the URLs accordingly. Each URL must return valid OpenAPI JSON.

You can use jq to list the paths of a group:

~~~bash
curl -s http://localhost:8080/v3/api-docs/orders \
  | jq -r '.paths | keys[]'
~~~

Then open Swagger UI and confirm:

1. The dropdown displays the expected labels and order.
2. The default document is selected properly when loading the UI.
3. Selecting each item loads the corresponding endpoints.
4. Tags and operations inside the document are sorted properly.
5. There are no duplicate URLs, 404 URLs, or unintended sample documents.

## 12. Common errors and how to handle them

| Symptom | Possible cause | Resolution |
|---|---|---|
| Dropdown does not appear | Only a single url is configured, or swagger-config lacks a urls list | Check urls and /v3/api-docs/swagger-config |
| Wrong default group | urls-primary-name does not match name | Synchronize the exact name |
| An item in the dropdown returns 404 | URL does not match group name or API docs path changed | Call the URL directly and fix configuration |
| New group does not appear | Manually declared urls list was not updated | Add the new entry or use an appropriate group discovery mechanism |
| Dropdown has duplicate items | Same document was added multiple times | Remove duplicates and keep names unique |
| Dropdown order is not as expected | Order in urls list is wrong or automatic configuration differs from expectation | Declare the list explicitly and check swagger-config |
| tags-sorter does not change group order | Confusing tag sorter with document list order | Order the urls list |
| Swagger UI opens Petstore | Default demo URL not disabled or URL config not applied | Check url, urls, and disable-swagger-default-url |
| External document fails to load | CORS, HTTPS, DNS, or access permissions | Check browser network requests and server configuration |
| 404 behind reverse proxy | Relative URL missing context path or proxy prefix | Check actual URLs and configure forwarded headers/proxy |
| Group exists in JSON but users cannot access it | API docs endpoint protected by Spring Security | Grant document access according to deployment policy |

## 13. Distinguishing document selection from access permissions

Adding a document to urls only makes it appear in the Swagger UI selector. Setting a group as primary only determines which document opens first. Neither setting grants access permissions to users.

If the admin document is only for administrators:

- Protect the /v3/api-docs/admin-api endpoint using Spring Security or an appropriate access mechanism.
- Protect Swagger UI if needed.
- Verify unauthorized users cannot download JSON/YAML directly.
- Do not rely on hiding a dropdown entry or not setting it as primary to protect a document.

Similarly, an endpoint excluded from documentation is not automatically blocked at runtime. Groups and UI organize the published contract; authorization must be enforced at the application's security layer.

## 14. Checklist for organizing the group list

- [ ] Each GroupedOpenApi has a unique and stable name.
- [ ] Each group returns valid OpenAPI JSON at the expected URL.
- [ ] The urls list contains only documents meant to be shown in this UI.
- [ ] Each item has a unique, clear name and the right URL.
- [ ] urls-primary-name matches one name in the list exactly.
- [ ] The order of urls suits the primary users of Swagger UI.
- [ ] Single url and multi-document urls are not configured overlapping unintentionally.
- [ ] tags-sorter, operations-sorter, and doc-expansion are used only for content inside a document.
- [ ] /v3/api-docs/swagger-config reflects the desired configuration.
- [ ] Every group URL has been tested and does not return 404.
- [ ] Internal documents are protected by appropriate runtime permissions.
- [ ] The list is updated whenever groups are added, renamed, or deleted.

## Conclusion

**GroupedOpenApi** produces scoped OpenAPI documents; **springdoc.swagger-ui.urls** provides the document list in the dropdown; **urls-primary-name** selects the label of the document opened first. For a single document, use **springdoc.swagger-ui.url**. Item order in the urls list controls selection order, whereas tags-sorter and operations-sorter only organize content inside the open document. Keep group names, URLs, and labels synchronized, inspect /v3/api-docs/swagger-config along with every JSON endpoint, and protect internal documents with separate runtime security mechanisms.
