# Describing DTOs with Validation, Enums, Date/Time Types, and Read-Only Properties

A good OpenAPI schema must accurately describe the data an API actually accepts and returns: which fields are required, how long strings can be, what bounds numbers have, which enum values are accepted, what date/time format is used, and which properties are generated only by the server. With Spring Boot, you can combine Jakarta Bean Validation, Java types, Jackson, and Swagger annotations so Springdoc generates schemas for DTOs.

This hands-on exercise builds an order creation API. The request includes an email, quantity, priority level, expected delivery date, request timestamp, and shipping address. The response adds a server-managed order ID, status, and creation timestamp. After declaring the DTOs, we verify both runtime validation and the OpenAPI document to ensure both sides describe the exact same contract.

## 1. Preparing dependencies

The example uses Spring Boot 3, Java 17 or later, Spring MVC, and Springdoc v2. The validation starter is required for Jakarta Bean Validation to actually execute, along with the appropriate Springdoc starter for the application.

Maven:

```xml
<dependencies>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
    </dependency>

    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-validation</artifactId>
    </dependency>

    <dependency>
        <groupId>org.springdoc</groupId>
        <artifactId>springdoc-openapi-starter-webmvc-ui</artifactId>
        <version>${springdoc.version}</version>
    </dependency>
</dependencies>
```

If you only need the OpenAPI JSON/YAML endpoints without Swagger UI, you can replace the `webmvc-ui` starter with `springdoc-openapi-starter-webmvc-api`. For WebFlux applications, use the corresponding WebFlux starter.

## 2. Separating request and response DTOs

In real APIs, you should separate input DTOs from output DTOs. The request contains only the fields the client is allowed to send; the response can contain identifiers, processing statuses, creation timestamps, or server-computed data.

For example:

| DTO | Role | Typical fields |
|---|---|---|
| `CreateOrderRequest` | Data sent by the client to create an order | Email, quantity, priority, delivery date, address |
| `OrderResponse` | Data returned by the server | ID, order data, status, creation timestamp |

Do not put `id`, `createdAt`, or `updatedAt` in the request just to share a single class. Separating DTOs prevents the request schema from accidentally allowing clients to send server-managed data. If the system is forced to share a DTO, you must explicitly document and enforce per-property read/write access as shown in the read-only section below.

## 3. Defining enums for values with a fixed set of choices

Enums restrict valid values in Java and tell Springdoc that the schema only accepts a discrete set of values.

```java
package com.example.orders.api.dto;

import io.swagger.v3.oas.annotations.media.Schema;

@Schema(
    name = "OrderPriority",
    description = "Order processing priority level"
)
public enum OrderPriority {
    STANDARD,
    EXPRESS,
    ECONOMY
}
```

With a standard Java enum, Springdoc typically generates a `string` schema with the corresponding `enum` list:

```yaml
OrderPriority:
  type: string
  description: Order processing priority level
  enum:
    - STANDARD
    - EXPRESS
    - ECONOMY
```

If you want the enum to be reused as a named component schema, the Springdoc FAQ recommends using `@Schema(enumAsRef = true)` on the enum:

```java
@Schema(name = "OrderPriority", enumAsRef = true)
public enum OrderPriority {
    STANDARD,
    EXPRESS,
    ECONOMY
}
```

If Jackson serializes the enum into a string other than the constant name, such as `"standard"` instead of `"STANDARD"`, the OpenAPI schema must reflect the actual JSON wire values. When using `@JsonValue`, `@JsonCreator`, or a custom serializer, inspect the document generated by Springdoc and test serializing/deserializing the DTO with the application's ObjectMapper.

## 4. Defining an address DTO with Bean Validation

The address is a nested object in the request. Use `@Valid` to trigger recursive validation on child fields.

```java
package com.example.orders.api.dto;

import io.swagger.v3.oas.annotations.media.Schema;
import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.Pattern;
import jakarta.validation.constraints.Size;

@Schema(name = "ShippingAddressRequest", description = "Shipping destination address")
public record ShippingAddressRequest(

    @Schema(description = "Recipient name", example = "Nguyen Van An")
    @NotBlank
    @Size(max = 120)
    String recipient,

    @Schema(description = "Address line 1", example = "12 Nguyen Hue")
    @NotBlank
    @Size(max = 200)
    String addressLine1,

    @Schema(description = "Postal code", example = "700000")
    @NotBlank
    @Pattern(regexp = "^[0-9]{5,10}$")
    String postalCode,

    @Schema(description = "ISO 3166-1 alpha-2 country code", example = "VN")
    @NotBlank
    @Pattern(regexp = "^[A-Z]{2}$")
    String countryCode
) {
}
```

Common constraints:

| Constraint | Meaning | How schema can be documented |
|---|---|---|
| `@NotNull` | Value must not be null | Property appears in `required` |
| `@NotBlank` | String must not be null, empty, or whitespace-only | `required`, usually with an appropriate minimum length |
| `@NotEmpty` | String/collection/map must not be empty | `minLength: 1`, `minItems: 1`, or `minProperties: 1` depending on type |
| `@Size(min, max)` | Limits size of string, collection, or map | `minLength`/`maxLength`, `minItems`/`maxItems`, or `minProperties`/`maxProperties` |
| `@Pattern` | Value must match regular expression | `pattern` |
| `@Email` | Value must be formatted as an email per validator | May reflect `format: email` |
| `@Min`, `@Max` | Integer bounds | `minimum`, `maximum` |
| `@Positive`, `@PositiveOrZero` | Positive or non-negative number | Corresponding minimum constraint |
| `@DecimalMin`, `@DecimalMax` | Decimal bounds, optionally exclusive | `minimum`/`maximum` or `exclusiveMinimum`/`exclusiveMaximum` |
| `@Past`, `@Future` | Instant must be in the past or future | Runtime constraint; document temporal semantics in schema if consumers need to know |

Whether a constraint translates into an OpenAPI keyword depends on Springdoc, Swagger Core, and the Bean Validation version. Bean Validation is the rule enforced on the server; the OpenAPI schema is the contract description. Do not assume every runtime constraint translates into a one-to-one OpenAPI keyword.

## 5. Defining a request DTO with validation, enums, and date/time fields

```java
package com.example.orders.api.dto;

import io.swagger.v3.oas.annotations.media.Schema;
import jakarta.validation.Valid;
import jakarta.validation.constraints.Email;
import jakarta.validation.constraints.FutureOrPresent;
import jakarta.validation.constraints.Max;
import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.NotNull;
import jakarta.validation.constraints.Positive;
import jakarta.validation.constraints.Size;

import java.time.LocalDate;
import java.time.OffsetDateTime;

@Schema(name = "CreateOrderRequest", description = "Data for creating an order")
public record CreateOrderRequest(

    @Schema(
        description = "Email address for receiving order notifications",
        example = "buyer@example.com",
        format = "email"
    )
    @NotBlank
    @Email
    @Size(max = 254)
    String customerEmail,

    @Schema(description = "Product quantity", example = "2", minimum = "1", maximum = "1000")
    @NotNull
    @Positive
    @Max(1000)
    Integer quantity,

    @Schema(description = "Processing priority level")
    @NotNull
    OrderPriority priority,

    @Schema(
        description = "Expected delivery calendar date, without timezone",
        type = "string",
        format = "date",
        example = "2099-12-05"
    )
    @NotNull
    @FutureOrPresent
    LocalDate expectedDeliveryDate,

    @Schema(
        description = "Timestamp when the client sent the request, with timezone offset",
        type = "string",
        format = "date-time",
        example = "2099-12-01T09:30:00+07:00"
    )
    @NotNull
    OffsetDateTime requestedAt,

    @Schema(description = "Shipping destination address")
    @NotNull
    @Valid
    ShippingAddressRequest shippingAddress
) {
}
```

In the example:

- `customerEmail` is a required string, formatted as an email, with a length limit.
- `quantity` is a required integer greater than 0 and not exceeding 1000.
- `priority` only accepts one of the `OrderPriority` values.
- `expectedDeliveryDate` is a calendar date without time or timezone.
- `requestedAt` is a timestamp with an offset, such as `+07:00`.
- `shippingAddress` is a required object; `@Valid` enables validation on the address fields.

`@NotNull` and `@NotBlank` cause runtime validation to reject invalid values when the controller uses `@Valid`. `@Schema` adds descriptions, examples, and formats for OpenAPI; it does not replace Bean Validation.

## 6. Distinguishing `LocalDate`, `LocalDateTime`, `OffsetDateTime`, and `Instant`

Choose a temporal type based on data semantics, not just string formatting.

| Java type | Meaning | Common OpenAPI format | JSON example |
|---|---|---|---|
| `LocalDate` | Calendar date, no time/timezone | `date` | `"2026-12-05"` |
| `LocalTime` | Time of day, no date/timezone | `string`; `time` may be used as an extended format if tools support it | `"09:30:00"` |
| `LocalDateTime` | Local date and time, no offset | Often documented as `date-time`, requires explicit semantics note | `"2026-12-05T09:30:00"` |
| `OffsetDateTime` | Date and time with UTC offset | `date-time` | `"2026-12-05T09:30:00+07:00"` |
| `Instant` | An absolute point on the UTC timeline | `date-time` | `"2026-12-05T02:30:00Z"` |

`LocalDateTime` contains neither a timezone nor an offset. Even if tools generate `format: date-time`, that value does not automatically become an RFC 3339 timestamp with an offset. When an API exchanges absolute instants across multiple timezones, prefer `OffsetDateTime` or `Instant`.

For expected delivery dates, birth dates, or effective dates that only carry calendar meaning, `LocalDate` is usually more suitable than `Date` or `OffsetDateTime`. Do not attach a timezone to data that has no instant-in-time semantics.

## 7. Distinguishing `@JsonFormat` and `@DateTimeFormat`

The two annotations serve two different binding flows:

| Annotation | Used for | Example |
|---|---|---|
| `@JsonFormat` | Jackson serializing/deserializing JSON body | `@JsonFormat(pattern = "yyyy-MM-dd")` |
| `@DateTimeFormat` | Spring binding query parameter, path variable, or form value | `@DateTimeFormat(iso = DateTimeFormat.ISO.DATE)` |
| `@Schema` | Documenting type, format, and example in OpenAPI | `@Schema(type = "string", format = "date")` |

Example date query parameter:

```java
@GetMapping("/api/orders")
List<OrderResponse> search(
    @RequestParam
    @DateTimeFormat(iso = DateTimeFormat.ISO.DATE)
    LocalDate fromDate
) {
    return orderService.searchFrom(fromDate);
}
```

Example JSON property:

```java
public record DeliveryWindow(
    @JsonFormat(shape = JsonFormat.Shape.STRING, pattern = "yyyy-MM-dd")
    LocalDate deliveryDate
) {
}
```

If you use a custom pattern, the OpenAPI schema must reflect the actual wire format. A `format: date-time` alone does not fully describe every custom pattern; add `description` and `example`, and inspect the actual JSON requests and responses.

## 8. Defining the status enum and response DTO

Order status is managed by the server:

```java
package com.example.orders.api.dto;

import io.swagger.v3.oas.annotations.media.Schema;

@Schema(name = "OrderStatus", description = "Order processing status")
public enum OrderStatus {
    NEW,
    CONFIRMED,
    PROCESSING,
    SHIPPED,
    CANCELLED
}
```

Response DTO with server-generated properties:

```java
package com.example.orders.api.dto;

import com.fasterxml.jackson.annotation.JsonProperty;
import io.swagger.v3.oas.annotations.media.Schema;

import java.time.Instant;
import java.time.LocalDate;
import java.time.OffsetDateTime;
import java.util.UUID;

@Schema(name = "OrderResponse", description = "Order details returned from the server")
public record OrderResponse(

    @Schema(
        description = "Server-assigned order identifier",
        accessMode = Schema.AccessMode.READ_ONLY,
        example = "a0eebc99-9c0b-4ef8-bb6d-6bb9bd380a11"
    )
    @JsonProperty(access = JsonProperty.Access.READ_ONLY)
    UUID id,

    @Schema(description = "Customer email", format = "email")
    String customerEmail,

    @Schema(description = "Product quantity", example = "2")
    Integer quantity,

    OrderPriority priority,

    OrderStatus status,

    @Schema(type = "string", format = "date", example = "2026-12-05")
    LocalDate expectedDeliveryDate,

    @Schema(
        type = "string",
        format = "date-time",
        example = "2026-12-01T09:30:00+07:00"
    )
    OffsetDateTime requestedAt,

    @Schema(
        description = "UTC timestamp when the server created the order",
        accessMode = Schema.AccessMode.READ_ONLY,
        type = "string",
        format = "date-time",
        example = "2026-12-01T02:30:01Z"
    )
    @JsonProperty(access = JsonProperty.Access.READ_ONLY)
    Instant createdAt
) {
}
```

`OrderResponse` uses the `OrderPriority` and `OrderStatus` enums, calendar date `LocalDate`, offset timestamp `OffsetDateTime`, and UTC timestamp `Instant`. The `id` and `createdAt` fields are marked read-only.

## 9. Distinguishing OpenAPI `readOnly` and Jackson `READ_ONLY`

The two annotations have different effects and must not be confused:

| Annotation | Effect |
|---|---|
| `@Schema(accessMode = Schema.AccessMode.READ_ONLY)` | Marks the property as read-only in the OpenAPI schema so consumers know it belongs to the response direction |
| `@JsonProperty(access = JsonProperty.Access.READ_ONLY)` | Tells Jackson to serialize the property to JSON, while ignoring any value for that property when deserializing input JSON |

OpenAPI `readOnly` is metadata describing the schema's usage direction. It does not by itself prevent a controller from accepting a client-sent value. Jackson `READ_ONLY` controls deserialization/serialization at runtime, yet it also does not replace authorization or permission checks in the service.

For production APIs, the safest and clearest approach is still to use a separate request DTO without `id` or `createdAt`, and a response DTO that includes these fields. If compatibility forces sharing a single DTO, combine `@Schema(accessMode = READ_ONLY)` to document the contract and `@JsonProperty(access = READ_ONLY)` so Jackson does not bind values from requests. Then write tests proving clients cannot overwrite server-managed properties.

OpenAPI 3.0 specifies that a `readOnly: true` property may appear in a response and should not be sent in a request; if a read-only property is listed in `required`, that requirement applies to responses. In OpenAPI 3.1, `readOnly` is treated as a JSON Schema annotation; whether a validator rejects the property in a request depends on how the validator applies read/write direction. Therefore, never rely on `readOnly` as a security mechanism.

## 10. Combining `@Valid` in the controller

The controller must instruct Spring to run Bean Validation on the request body:

```java
package com.example.orders.api;

import com.example.orders.api.dto.CreateOrderRequest;
import com.example.orders.api.dto.OrderResponse;
import jakarta.validation.Valid;
import org.springframework.http.HttpStatus;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.ResponseStatus;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequestMapping("/api/orders")
class OrderController {

    private final OrderService orderService;

    OrderController(OrderService orderService) {
        this.orderService = orderService;
    }

    @PostMapping
    @ResponseStatus(HttpStatus.CREATED)
    OrderResponse create(@Valid @RequestBody CreateOrderRequest request) {
        return orderService.create(request);
    }
}
```

`@Valid` instructs Bean Validation to check the request DTO after Jackson deserializes JSON. `@Valid` on `shippingAddress` in the record triggers nested validation. Without `spring-boot-starter-validation`, annotations may still compile but have no validation provider to execute them.

For constraints placed on method parameters such as `@RequestParam @Min(1) int page`, method validation via `@Validated` and configuration appropriate to your Spring Boot/Spring Framework version may be needed. Do not confuse query/path parameter validation with `@RequestBody` validation.

## 11. Inspecting the OpenAPI schema generated by Springdoc

Start the application and download the document:

```bash
curl --fail --silent --show-error \
  http://localhost:8080/v3/api-docs \
  --output openapi.json
```

Inspect the request schema:

```bash
jq '.components.schemas.CreateOrderRequest' openapi.json
```

Inspect the enums:

```bash
jq '.components.schemas.OrderPriority' openapi.json
jq '.components.schemas.OrderStatus' openapi.json
```

Inspect the response read-only properties:

```bash
jq '.components.schemas.OrderResponse.properties.id' openapi.json
jq '.components.schemas.OrderResponse.properties.createdAt' openapi.json
```

Expected semantic results:

- `customerEmail` has type string, email format, and length limits.
- `quantity` is an integer with lower/upper bounds.
- `priority` and `status` have enum lists.
- `expectedDeliveryDate` is a string with format `date`.
- `requestedAt` and `createdAt` are strings with format `date-time`.
- `id` and `createdAt` are marked `readOnly` in the response schema.
- Required properties appear in `required` according to validation and schema configuration.

Component names may differ if Springdoc names them by generic type or model converter. Use `@Schema(name = "...")` when a stable schema name is needed. Do not only check Swagger UI; inspect the raw JSON/YAML to verify `required`, `enum`, `format`, `pattern`, `minimum`, `maximum`, and `readOnly`.

## 12. Testing runtime validation

A test sending a valid request:

```java
@SpringBootTest
@AutoConfigureMockMvc
class OrderControllerValidationTest {

    @Autowired
    MockMvc mockMvc;

    @Test
    void acceptsValidOrderRequest() throws Exception {
        mockMvc.perform(post("/api/orders")
                .contentType(MediaType.APPLICATION_JSON)
                .content("""
                    {
                      "customerEmail": "buyer@example.com",
                      "quantity": 2,
                      "priority": "EXPRESS",
                      "expectedDeliveryDate": "2099-12-05",
                      "requestedAt": "2099-12-01T09:30:00+07:00",
                      "shippingAddress": {
                        "recipient": "Nguyen Van An",
                        "addressLine1": "12 Nguyen Hue",
                        "postalCode": "700000",
                        "countryCode": "VN"
                      }
                    }
                    """))
            .andExpect(status().isCreated());
    }
}
```

Testing an invalid request:

```java
@Test
void rejectsInvalidOrderRequest() throws Exception {
    mockMvc.perform(post("/api/orders")
            .contentType(MediaType.APPLICATION_JSON)
            .content("""
                {
                  "customerEmail": "not-an-email",
                  "quantity": 0,
                  "priority": "EXPRESS",
                  "expectedDeliveryDate": "2020-01-01",
                  "requestedAt": "2026-12-01T09:30:00+07:00",
                  "shippingAddress": {
                    "recipient": "",
                    "addressLine1": "12 Nguyen Hue",
                    "postalCode": "ABC",
                    "countryCode": "Viet Nam"
                  }
                }
                """))
        .andExpect(status().isBadRequest());
}
```

The example above assumes the application uses Spring MVC's default error handling for `MethodArgumentNotValidException`. If there is a custom `@ControllerAdvice`, the status and error body may differ; write assertions matching the application's actual error contract.

## 13. Testing read-only properties

If a response DTO could be reused as a request, test that Jackson ignores an incoming `id` value from JSON:

```java
import com.fasterxml.jackson.databind.ObjectMapper;
import com.fasterxml.jackson.annotation.JsonProperty;
import io.swagger.v3.oas.annotations.media.Schema;
import org.junit.jupiter.api.Test;
import java.util.UUID;

import static org.assertj.core.api.Assertions.assertThat;

class ReadOnlyDtoTest {

    public record SharedOrderDto(
        @Schema(accessMode = Schema.AccessMode.READ_ONLY)
        @JsonProperty(access = JsonProperty.Access.READ_ONLY)
        UUID id,
        String customerEmail
    ) {
    }

    @Test
    void ignoresClientSuppliedReadOnlyId() throws Exception {
        ObjectMapper objectMapper = new ObjectMapper()
            .findAndRegisterModules();

        SharedOrderDto dto = objectMapper.readValue("""
            {
              "id": "a0eebc99-9c0b-4ef8-bb6d-6bb9bd380a11",
              "customerEmail": "buyer@example.com"
            }
            """, SharedOrderDto.class);

        assertThat(dto.id()).isNull();

        UUID serverId = UUID.fromString("a0eebc99-9c0b-4ef8-bb6d-6bb9bd380a11");
        String responseJson = objectMapper.writeValueAsString(
            new SharedOrderDto(serverId, "buyer@example.com")
        );
        assertThat(responseJson).contains(serverId.toString());
    }
}
```

This is a test for Jackson `@JsonProperty(access = READ_ONLY)`, not a test for `@Schema(accessMode = READ_ONLY)`. When request and response DTOs are separate, tests should verify that the request DTO omits server-managed properties by design, and the response DTO returns the values generated by the service.

Do not treat Jackson ignoring a property as complete access control. The service must still generate IDs, creation timestamps, and statuses itself; never trust client-supplied values for those fields.

## 14. Common mistakes when describing DTOs

| Symptom | Cause | Resolution |
|---|---|---|
| Swagger UI does not mark required fields | Missing `@NotNull`/`@NotBlank`, or overridden by a schema customizer | Check `required` in raw OpenAPI; use `requiredMode` if explicit declaration is needed |
| Validation does not run despite annotations | Missing `spring-boot-starter-validation` or controller missing `@Valid` | Verify the validation provider and annotation on the request body parameter |
| Nested DTO is not validated | Missing `@Valid` on the nested property | Add `@Valid` along with `@NotNull`/`@NotEmpty` as appropriate |
| Enum in Swagger differs from actual JSON | Jackson uses `@JsonValue` or custom serializer | Check wire values and OpenAPI enum together |
| Date/time shifted by timezone | Using `LocalDateTime` for an absolute instant | Use `OffsetDateTime` or `Instant` |
| `format: date-time` but value has no offset | `LocalDateTime` documented as date-time | Clarify semantics or switch to an offset-aware type |
| `@DateTimeFormat` does not change JSON body | Annotation is for Spring conversion, not Jackson body | Use `@JsonFormat` or configure ObjectMapper |
| Read-only property still accepts client input | Only `@Schema(accessMode=READ_ONLY)` is present | Separate request DTO or use Jackson `@JsonProperty(READ_ONLY)` and test |
| Property hidden from schema | Mistakenly used `@Schema(hidden = true)` | Use `accessMode` for read-only; only use `hidden` to exclude from docs |
| `@Schema` has example rejected at runtime | Example does not satisfy constraints or actual format | Sync examples with Bean Validation and Jackson |
| Schema component has unstable name | Auto-generated model name or generic DTO | Set `@Schema(name = "...")` for contracts needing stability |

## 15. DTO design and verification workflow

Follow this order:

1. Identify data clients may send and data the server generates.
2. Separate the request DTO from the response DTO if the two directions have different fields.
3. Choose Java types matching semantics: numbers, enums, calendar dates, UTC instants, or offset timestamps.
4. Place Bean Validation constraints to protect runtime behavior.
5. Use `@Valid` on nested objects and collections whose elements require validation.
6. Use `@Schema` to add names, descriptions, examples, formats, enums, and access modes.
7. Use Jackson annotations when controlling JSON wire format or serialization/deserialization access.
8. Download `/v3/api-docs` and inspect `required`, `enum`, `format`, constraints, and `readOnly`.
9. Write tests for valid requests, invalid requests, and server-managed properties.
10. Run an OpenAPI parser/linter to catch invalid documents before release.

## 16. OpenAPI DTO completion checklist

- [ ] Request DTO contains only properties clients are allowed to send.
- [ ] Response DTO can include server-managed ID, status, and timestamps.
- [ ] `@NotNull`, `@NotBlank`, `@Size`, `@Pattern`, and numeric constraints match semantics.
- [ ] Controller uses `@Valid` for the request body.
- [ ] Nested DTOs have `@Valid` so validation runs recursively.
- [ ] Enum schemas reflect actual serialized JSON values.
- [ ] `LocalDate` is used for calendar dates.
- [ ] `OffsetDateTime` or `Instant` is used for absolute instants.
- [ ] `LocalDateTime` is not misdocumented as a timezone-aware timestamp.
- [ ] `@JsonFormat`, `@DateTimeFormat`, and `@Schema` are each used for their proper purpose.
- [ ] Server-managed properties are marked `readOnly` in OpenAPI.
- [ ] Jackson is configured to ignore read-only values if a DTO can be used for input.
- [ ] Raw OpenAPI document is checked for `required`, `enum`, `format`, bounds, and `readOnly`.
- [ ] Tests cover valid requests, invalid requests, and protection of server-generated IDs/timestamps.

A good DTO must be accurate across three layers simultaneously: Java types express the right data semantics, Bean Validation protects requests at runtime, and the OpenAPI schema accurately describes the contract for consumers. Use enums for finite value sets, `LocalDate` for calendar dates, `OffsetDateTime`/`Instant` for instants, `@Valid` for nested objects, and `@Schema` to document examples, formats, and read-only fields. Separate request and response DTOs whenever possible; if sharing one, combine OpenAPI `readOnly` with Jackson access control and test actual deserialization behavior.
