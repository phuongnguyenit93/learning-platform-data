# Running a Test SMTP Server and Inspecting MIME

In **Spring Framework Mail**, calling **JavaMailSender.send(...)** without an exception is not enough to prove an email was constructed properly. An email can suffer from corrupted Vietnamese encoding, a missing `text/plain` part, broken HTML, an empty attachment, a mismatched `Content-ID`, or incorrectly nested MIME multiparts. Repeatedly testing against production SMTP also risks emailing real users, burning quota, and tying tests to the Internet.

This practice project builds an **SMTP capture environment**: the Spring Boot app sends emails to a test SMTP server, the server captures the message, and we inspect the **raw MIME** to verify the exact structure and content that was transmitted.

You will complete the following steps:

1. Run **Mailpit** via Docker Compose, accepting SMTP on port 1025 and opening its web UI on port 8025.
2. Configure Spring Boot's **JavaMailSender** to target local SMTP without real credentials.
3. Build a **MimeMessage** with `text/plain`, `text/html`, Vietnamese UTF-8 text, and a CSV attachment.
4. Trigger a test send via an endpoint active only under the `local` profile.
5. Open the Mailpit UI, inspect MIME headers, download the **.eml** file, and identify the multipart structure.
6. Write **Jakarta Mail** code to parse the `.eml` file and walk nested parts.
7. Write a **JUnit integration test with GreenMail**, sending over real in-JVM SMTP and reading back the `MimeMessage` without touching the Internet.
8. Experiment with common mistakes around host, port, TLS, charset, attachments, `Content-Disposition`, and HTML.
9. Understand the boundary: a capture server accepting SMTP does not mean the email was delivered to an inbox.

This lesson is part of the **Practice Project** chapter of **Spring Framework Mail**. All example email addresses use the **example.invalid** domain to emphasize they exist strictly for testing, never real recipients.

## 2. What Is an SMTP Capture Server?

An SMTP capture server speaks basic SMTP commands and stores messages for developer inspection:

~~~text
SMTP client                   Capture server
     |--- TCP connect ------------>|
     |<-- 220 greeting ------------|
     |--- EHLO ------------------->|
     |<-- 250 capabilities --------|
     |--- MAIL FROM ------------->|
     |<-- 250 ---------------------|
     |--- RCPT TO --------------->|
     |<-- 250 ---------------------|
     |--- DATA ------------------>|
     |<-- 354 ---------------------|
     |--- MIME body + final dot ->|
     |<-- 250 accepted -----------|
     |--- QUIT ------------------>|
~~~

When the capture server replies **250 accepted**, the application knows the test SMTP server accepted the submission. It does **not** mean the email reached a real recipient mailbox on the Internet.

### 2.1. Why Avoid Production SMTP?

- Prevents accidentally sending personalized emails to real customers.
- Eliminates keeping real credentials on laptops or in CI.
- Avoids provider rate limits and network flakiness.
- Makes tests easy to repeat reliably.
- Lets you inspect full MIME source and attachments.
- Avoids spam filtering and bounce delays.

### 2.2. Capturing Is Not Delivering

A production application may hand off an email to a relay successfully and still receive a bounce later. Capture tests verify only the **application → test SMTP server** segment.

## 3. How Do Mailpit and GreenMail Differ?

| Tool | Role | Best Suited For |
| --- | --- | --- |
| **Mailpit** | SMTP capture, web UI, API | Manual inspection and viewing raw MIME |

Examples target **Spring Boot 3 / Spring Framework 6**, where mail APIs use **jakarta.mail**. Legacy Spring projects using **javax.mail** must choose matching dependencies, imports, and GreenMail artifacts; never mix both namespaces in the same test.

**latest** is used for a concise learning example. In CI or team projects, pin a verified tag or digest for reproducible runs.

### 5.1. Port Meanings

- **1025/TCP:** where `JavaMailSender` sends SMTP traffic.
- **8025/TCP:** where your browser opens the Mailpit UI and tests can query the HTTP API.

Do not confuse the HTTP UI port with the SMTP listener port.

### 5.2. Why Bind 127.0.0.1?

This Docker configuration exposes ports solely on the loopback interface, reducing the risk of other machines reaching the test server. It is not an authenticated Internet-facing service.

### 5.3. Storage

This minimal configuration mounts no persistent volume. Captured messages serve only the lab and must not be treated as durable business storage. If a team retains test history, design proper retention, access control, and storage.

## 8. Local SMTP Configuration

Create **src/main/resources/application-local.yml**:

~~~yaml
spring:
  mail:
    host: 127.0.0.1
    port: 1025
    properties:
      "[mail.smtp.auth]": "false"
      "[mail.smtp.starttls.enable]": "false"
      "[mail.smtp.connectiontimeout]": "3000"
      "[mail.smtp.timeout]": "5000"
      "[mail.smtp.writetimeout]": "5000"
~~~

### 8.1. No SMTP Username/Password Needed in the Lab

Mailpit accepts unauthenticated local SMTP by default under this config. Never place real credentials in `application-local.yml`.

### 8.2. Do Not Require STARTTLS When the Server Does Not Support It

If **mail.smtp.starttls.required=true** is set while the test SMTP server does not advertise STARTTLS, the client will fail to send. That is a config mismatch, not a MIME bug.

### 8.3. Never Copy This to Production

Production SMTP requires TLS, certificate/hostname verification, AUTH, and secret management matching your provider. Plaintext SMTP here is strictly for loopback or isolated test networks.

### 8.4. If Spring Boot Runs Inside a Container

**127.0.0.1** inside the app container refers to that container itself. When both the app and Mailpit share a Docker Compose network, configure **host: mailpit** and **port: 1025** instead of loopback.

## 10. Building a MimeMessage with Text, HTML, and an Attachment

Create **MailDemoSender.java**:

~~~java
package com.example.maildemo;

import java.nio.charset.StandardCharsets;

import jakarta.mail.MessagingException;
import jakarta.mail.internet.MimeMessage;

import org.springframework.core.io.ByteArrayResource;
import org.springframework.mail.MailPreparationException;
import org.springframework.mail.javamail.JavaMailSender;
import org.springframework.mail.javamail.MimeMessageHelper;
import org.springframework.stereotype.Service;

@Service
public class MailDemoSender {

    private final JavaMailSender mailSender;

    public MailDemoSender(JavaMailSender mailSender) {
        this.mailSender = mailSender;
    }

    public void sendSample() {
        MimeMessage message =
                mailSender.createMimeMessage();

        try {
            MimeMessageHelper helper =
                    new MimeMessageHelper(
                            message,
                            MimeMessageHelper.MULTIPART_MODE_MIXED_RELATED,
                            StandardCharsets.UTF_8.name()
                    );

            helper.setFrom("demo-sender@example.invalid");
            helper.setTo("student@example.invalid");
            helper.setSubject(
                    "Bài thực hành MIME: tiếng Việt và tệp đính kèm"
            );

            String plain =
                    "Xin chào!\n"
                  + "Đây là nội dung text/plain.\n"
                  + "Mã ví dụ: LAB-475.\n";

            String html =
                    "<html><body>"
                  + "<h1>Xin chào!</h1>"
                  + "<p>Đây là phần <strong>text/html</strong>.</p>"
                  + "<p>Mã ví dụ: LAB-475.</p>"
                  + "</body></html>";

            helper.setText(plain, html);

            byte[] csv =
                    ("id,status\n"
                   + "LAB-475,READY\n")
                    .getBytes(StandardCharsets.UTF_8);

            helper.addAttachment(
                    "ket-qua.csv",
                    new ByteArrayResource(csv),
                    "text/csv"
            );

        } catch (MessagingException ex) {
            throw new MailPreparationException(
                    "Cannot prepare demo MIME",
                    ex
            );
        }

        mailSender.send(message);
    }
}
~~~

### 10.1. MimeMessage vs. SimpleMailMessage

**SimpleMailMessage** is handy for plain-text emails. **MimeMessage** supports HTML, `multipart/alternative`, attachments, inline resources, and flexible MIME headers.

### 10.2. MULTIPART_MODE_MIXED_RELATED

This mode organizes body parts alongside attachments and related resources. The actual nested layout can include `multipart/mixed`, `multipart/related`, and `multipart/alternative`; never assume every part sits at the root.

### 10.3. setText(plain, html)

These are two **alternative representations of the same content**, not two emails. Some mail clients pick HTML, while others pick plain text.

### 10.4. UTF-8 Charset

The example uses accented Vietnamese text to test MIME encoding and decoding. In raw source, Vietnamese text may appear as quoted-printable or base64; what matters is that decoded content matches.

### 10.5. Attachment Bytes

The CSV is attached via `ByteArrayResource`. For small files, this is easy to test and provides a fresh stream whenever the MIME serializer needs one. Large files require bounded/streaming handling rather than loading every attachment into RAM.

## 11. Local-Profile-Only Endpoint

Create **LocalMailDemoController.java**:

~~~java
package com.example.maildemo;

import org.springframework.context.annotation.Profile;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

@Profile("local")
@RestController
@RequestMapping("/__dev/mail")
public class LocalMailDemoController {

    private final MailDemoSender sender;

    public LocalMailDemoController(MailDemoSender sender) {
        this.sender = sender;
    }

    @PostMapping("/send")
    public ResponseEntity<String> send() {
        sender.sendSample();

        return ResponseEntity.ok(
                "SMTP_SUBMITTED_TO_LOCAL_CAPTURE_SERVER"
        );
    }
}
~~~

### 11.1. Why Doesn't the Endpoint Accept an Arbitrary To?

This lab does not build an HTTP open relay. Both sender and recipient are fixed to `.invalid` test domains so the endpoint cannot send mail arbitrarily.

### 11.2. Why `@Profile("local")`?

Reduces the chance of test routes appearing outside local environments. Even so, a profile controls bean activation only—it does not replace authentication or firewalls on shared machines.

### 11.3. What Does the Response Mean?

**SMTP_SUBMITTED_TO_LOCAL_CAPTURE_SERVER** means only that `JavaMailSender` submitted to the test SMTP capture server without error from the caller's perspective; it provides zero evidence of inbox delivery.

## 14. What Is MIME?

MIME (Multipurpose Internet Mail Extensions) defines how email content is structured with headers and body parts. A message can include:

- `From`/`To`/`Subject` headers.
- `MIME-Version` header.
- `Content-Type`.
- Charset.
- `Content-Transfer-Encoding`.
- Multiple body parts under `multipart`.
- File attachments.
- Inline images with `Content-ID`.
- Nested messages of type `message/rfc822`.

An HTML email is not just an HTML string; it is a structured message enabling receiving systems to interpret each part.

## 15. Inspecting the Raw .eml

A **structurally illustrative** example, not guaranteed literal Jakarta Mail output:

~~~text
From: demo-sender@example.invalid
To: student@example.invalid
Subject: =?UTF-8?B?...?=
MIME-Version: 1.0
Content-Type: multipart/mixed; boundary="outer"

--outer
Content-Type: multipart/related; boundary="related"

--related
Content-Type: multipart/alternative; boundary="alternatives"

--alternatives
Content-Type: text/plain; charset=UTF-8
Content-Transfer-Encoding: quoted-printable

... encoded text ...

--alternatives
Content-Type: text/html; charset=UTF-8
Content-Transfer-Encoding: quoted-printable

... encoded HTML ...

--alternatives--
--related--
--outer
Content-Type: text/csv; name="ket-qua.csv"
Content-Disposition: attachment; filename="ket-qua.csv"
Content-Transfer-Encoding: base64

... encoded attachment bytes ...

--outer--
~~~

### 15.1. Boundary

A boundary delimits multipart sections. Jakarta Mail can generate a different value on every send; never hardcode boundary strings in tests.

### 15.2. Raw Subject

For Unicode, Subject may appear as one or more encoded-words. Jakarta Mail's **MimeMessage.getSubject()** decodes them back to a readable String.

### 15.3. Content-Transfer-Encoding

Base64 and quoted-printable are **encodings**, not encryption. Never rely on them to hide secrets.

### 15.4. Structure Is Not Strictly Fixed

Multipart nesting and headers may vary with Jakarta Mail implementations and settings. Tests should assert **semantics and decoded contents**.

## 16. MIME Headers to Inspect

| Header | Meaning | What to Test |
| --- | --- | --- |
| **From** | Displayed sender identity | Matches sender identity |
| **To** | Displayed recipients | Matches test recipient |
| **Cc/Bcc** | Visible/hidden recipients | Never infer envelope solely from raw |
| **Subject** | Subject line | Decodes Unicode properly |
| **Date** | Message creation/send timestamp | Never hardcode exact value |
| **Message-ID** | Message identifier | Never use as a dedup guarantee |
| **MIME-Version** | MIME version | Normally `1.0` |
| **Content-Type** | Part media type | `multipart`, text, image, file |
| **Content-Transfer-Encoding** | Wire representation | Base64 / quoted-printable / 7bit |
| **Content-Disposition** | Attachment or inline | Distinguishes body from file |
| **Content-ID** | Inline resource ID | Matches `cid:` reference |
| **filename/name** | Filename metadata | Verify Unicode/bytes |

### 16.1. Envelope vs. Headers

SMTP **MAIL FROM/RCPT TO** defines the envelope; MIME **From/To** are headers. A message can have a `Bcc` envelope recipient without any `Bcc` header appearing in the raw `.eml`.

### 16.2. Message-ID Does Not Prevent Duplicates

Sending two emails with the same `Message-ID` can still produce two SMTP submissions. Never substitute `Message-ID` for a transactional outbox or idempotency policy.

### 16.3. Raw Headers Support Line Folding

A long header can wrap across multiple physical lines. Never assert a raw Subject fits on one line; use MIME parsing APIs.

## 17. Three Multipart Subtypes to Understand

**multipart/alternative**:

~~~text
multipart/alternative
    +-- text/plain
    +-- text/html
~~~

Alternative representations of the same content.

**multipart/related**:

~~~text
multipart/related
    +-- text/html with src="cid:brand-logo"
    +-- image/png; Content-ID: <brand-logo>
~~~

Main body paired with referenced related resources.

**multipart/mixed**:

~~~text
multipart/mixed
    +-- multipart/alternative or related
    +-- text/csv; attachment
    +-- application/pdf; attachment
~~~

Commonly used when attaching files.

### 17.1. MIME Trees Can Nest Multiple Levels

Never parse by reading `root.getContent()` once and casting to `String`. The root may be a `Multipart`, and its children may also be `Multipart`.

### 17.2. Content-Disposition Can Be Null

Text bodies often omit `Content-Disposition`. A `null` disposition does not mean the part is broken.

### 17.3. Text Attachments Are Not Plain Bodies

A file like **notes.txt** has `Content-Type: text/plain` yet is an attachment. Parsers must check filename and disposition before treating a part as the email body.

## 18. Charset vs. Content-Transfer-Encoding

Two related headers that mean different things:

~~~text
Content-Type: text/plain; charset=UTF-8
Content-Transfer-Encoding: quoted-printable
~~~

- **charset=UTF-8:** how bytes map to text characters.
- **quoted-printable/base64:** how data is encoded for MIME transport.

A raw `.eml` may show sequences like **=C3=...** or base64 strings instead of readable Vietnamese characters. That is normal as long as Jakarta Mail decodes the right text.

### 18.1. Do Not `grep` Raw Files to Verify UTF-8

Call **Part.getContent()** on text parts and compare decoded `String` values.

### 18.2. Mojibake Errors

If the app decoded input with the wrong charset before building `MimeMessage`, setting `charset=UTF-8` at the MIME layer cannot repair already-corrupted text.

### 18.3. Unicode Filenames Need Separate Testing

Subject decoding working does not prove attachment filenames decode properly. Test **getFileName()** explicitly if using accented filenames.

### 19.1. .eml Files Can Contain Sensitive Data

Bodies, OTPs, reset URLs, and attachments exist inside raw messages even when base64-encoded. Never commit captured production emails to repositories.

### 19.2. Raw Bytes vs. Reserialization

Reading `.eml` from disk reads the raw representation. Creating a `MimeMessage` and calling `writeTo()` may reserialize it; never assume it is a byte-for-byte copy of the original file.

## 20. Writing MimeReader to Parse .eml with Jakarta Mail

Create **MimeReader.java**:

~~~java
package com.example.maildemo;

import java.io.InputStream;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.Arrays;
import java.util.Properties;

import jakarta.mail.Message;
import jakarta.mail.Session;
import jakarta.mail.internet.MimeMessage;

public final class MimeReader {

    public static void main(String[] args)
            throws Exception {

        if (args.length != 1) {
            System.err.println(
                    "Usage: MimeReader <path-to-message.eml>"
            );
            System.exit(2);
        }

        Path file = Path.of(args[0]);

        System.out.println(
                "Raw .eml bytes: " + Files.size(file)
        );

        Session session = Session.getInstance(
                new Properties()
        );

        try (InputStream in = Files.newInputStream(file)) {
            MimeMessage mail = new MimeMessage(
                    session,
                    in
            );

            System.out.println(
                    "From: " + Arrays.toString(
                            mail.getFrom()
                    )
            );

            System.out.println(
                    "To: " + Arrays.toString(
                            mail.getRecipients(
                                    Message.RecipientType.TO
                            )
                    )
            );

            System.out.println(
                    "Subject: " + mail.getSubject()
            );

            System.out.println(
                    "Message-ID: " + mail.getMessageID()
            );

            MimeTreePrinter.print(mail, 0);
        }
    }
}
~~~

### 20.1. No IMAP Required

`MimeMessage(Session, InputStream)` parses the `.eml` file downloaded from the capture server; no mailbox credentials are needed.

### 20.2. Decoded Subject

`getSubject()` returns a `String` with Vietnamese text already decoded from MIME header encoding.

### 20.3. InputStream Lifecycle

`try-with-resources` closes the file handle. When reading attachment parts, close decoded streams as well.

## 21. Walking the MIME Tree Recursively

Create **MimeTreePrinter.java**:

~~~java
package com.example.maildemo;

import java.io.InputStream;
import java.util.Arrays;

import jakarta.mail.Message;
import jakarta.mail.Multipart;
import jakarta.mail.Part;

public final class MimeTreePrinter {

    private MimeTreePrinter() {}

    public static void print(Part part, int depth)
            throws Exception {

        String indent = "  ".repeat(depth);
        String disposition = part.getDisposition();
        String filename = part.getFileName();

        System.out.println(indent + "Part");
        System.out.println(
                indent + "  Type: " + part.getContentType()
        );
        System.out.println(
                indent + "  Disposition: " + disposition
        );
        System.out.println(
                indent + "  Filename: " + filename
        );
        System.out.println(
                indent + "  CID: " + Arrays.toString(
                        part.getHeader("Content-ID")
                )
        );

        Object content = part.getContent();

        if (content instanceof Multipart multi) {
            for (int i = 0; i < multi.getCount(); i++) {
                print(
                        multi.getBodyPart(i),
                        depth + 1
                );
            }
            return;
        }

        if (content instanceof Message nested) {
            print(nested, depth + 1);
            return;
        }

        boolean isAttachment =
                Part.ATTACHMENT.equalsIgnoreCase(
                        disposition
                ) || filename != null;

        if (!isAttachment
                && (part.isMimeType("text/plain")
                    || part.isMimeType("text/html"))
                && content instanceof String text) {

            String preview = text
                    .replace('\r', ' ')
                    .replace('\n', ' ');

            System.out.println(
                    indent + "  Characters: "
                    + text.length()
            );
            System.out.println(
                    indent + "  Preview: "
                    + preview.substring(
                            0,
                            Math.min(preview.length(), 120)
                    )
            );
            return;
        }

        try (InputStream decoded =
                     part.getInputStream()) {

            byte[] buffer = new byte[4096];
            long count = 0;
            int read;

            while ((read = decoded.read(buffer)) != -1) {
                count += read;
            }

            System.out.println(
                    indent + "  Decoded bytes: " + count
            );
        }
    }
}
~~~

### 21.1. Why Use `instanceof Multipart`?

Nested MIME parts are normal. A parser that inspects only one level at the root will miss text bodies or attachments.

### 21.2. Why Not Cast Every Content Object to String?

`Part.getContent()` can return `String`, `Multipart`, `Message`, or another type; unconditional casting to `String` throws `ClassCastException`.

### 21.3. Why Check Filename and Disposition?

A `text/plain` attachment is not a plain-text body. This demo treats any part with a filename as an attachment, fitting the lab's goals.

### 21.4. Limits of the Demo Parser

For MIME from untrusted sources, enforce limits on part count, recursion depth, decoded bytes, stream time, and size. This learning code is not a hardened parser for arbitrary malicious emails.

## 23. Finding Bodies and Attachments with a Utility

A utility for automated tests:

~~~java
package com.example.maildemo;

import jakarta.mail.Message;
import jakarta.mail.Multipart;
import jakarta.mail.Part;

public final class MimePartFinder {

    private MimePartFinder() {}

    public static String findText(
            Part part,
            String mimeType
    ) throws Exception {

        if (part.isMimeType(mimeType)
                && !isAttachment(part)) {
            Object content = part.getContent();

            if (content instanceof String text) {
                return text;
            }
        }

        Object content = part.getContent();

        if (content instanceof Multipart multi) {
            for (int i = 0; i < multi.getCount(); i++) {
                String text = findText(
                        multi.getBodyPart(i),
                        mimeType
                );

                if (text != null) {
                    return text;
                }
            }
        } else if (content instanceof Message nested) {
            return findText(nested, mimeType);
        }

        return null;
    }

    public static Part findAttachment(
            Part part,
            String filename
    ) throws Exception {

        if (filename.equals(part.getFileName())) {
            return part;
        }

        Object content = part.getContent();

        if (content instanceof Multipart multi) {
            for (int i = 0; i < multi.getCount(); i++) {
                Part found = findAttachment(
                        multi.getBodyPart(i),
                        filename
                );

                if (found != null) {
                    return found;
                }
            }
        } else if (content instanceof Message nested) {
            return findAttachment(nested, filename);
        }

        return null;
    }

    private static boolean isAttachment(
            Part part
    ) throws Exception {

        return Part.ATTACHMENT.equalsIgnoreCase(
                part.getDisposition()
        ) || part.getFileName() != null;
    }
}
~~~

### 23.1. Do Not Treat `root.getBodyPart(0)` as Law

`MimeMessageHelper` may create `multipart/mixed` wrapping `related`, which wraps `alternative`. Recursive lookup stays resilient across nesting variations.

### 23.2. This Utility Does Not Verify Magic Bytes

Matching a filename does not prove the attached file is safe or matches its declared content type. For attachment tests, compare decoded bytes.

### 25.3. Reserialization Differs from Original Source

## 29. Writing an SMTP/MIME Round-Trip Integration Test

~~~java
package com.example.maildemo;

import static org.junit.jupiter.api.Assertions.*;

import java.nio.charset.StandardCharsets;

import jakarta.mail.Message;
import jakarta.mail.Multipart;
import jakarta.mail.Part;
import jakarta.mail.internet.MimeMessage;

import com.icegreen.greenmail.util.GreenMail;
import com.icegreen.greenmail.util.ServerSetup;

import org.junit.jupiter.api.Test;
import org.springframework.mail.javamail.JavaMailSenderImpl;

class MimeRoundTripTest {

    @Test
    void canSendAndReadMime() throws Exception {

        GreenMail server = new GreenMail(
                new ServerSetup(
                        3025,
                        "127.0.0.1",
                        ServerSetup.PROTOCOL_SMTP
                )
        );

        server.start();

        try {
            JavaMailSenderImpl sender =
                    new JavaMailSenderImpl();

            sender.setHost("127.0.0.1");
            sender.setPort(3025);

            sender.getJavaMailProperties()
                    .put("mail.smtp.auth", "false");
            sender.getJavaMailProperties()
                    .put("mail.smtp.starttls.enable", "false");

            new MailDemoSender(sender).sendSample();

            MimeMessage[] received =
                    server.getReceivedMessages();

            assertEquals(1, received.length);

            MimeMessage mail = received[0];

            assertEquals(
                    "Bài thực hành MIME: tiếng Việt và tệp đính kèm",
                    mail.getSubject()
            );

            assertEquals(
                    "student@example.invalid",
                    mail.getRecipients(
                            Message.RecipientType.TO
                    )[0].toString()
            );

            assertTrue(
                    mail.getContent() instanceof Multipart
            );

            String plain = MimePartFinder.findText(
                    mail, "text/plain"
            );

            String html = MimePartFinder.findText(
                    mail, "text/html"
            );

            assertNotNull(plain);
            assertNotNull(html);
            assertTrue(
                    plain.contains("Đây là nội dung text/plain")
            );
            assertTrue(
                    html.contains("<strong>text/html</strong>")
            );

            Part csv = MimePartFinder.findAttachment(
                    mail, "ket-qua.csv"
            );

            assertNotNull(csv);

            byte[] actualBytes;

            try (var in = csv.getInputStream()) {
                actualBytes = in.readAllBytes();
            }

            assertEquals(
                    "id,status\nLAB-475,READY\n",
                    new String(
                            actualBytes,
                            StandardCharsets.UTF_8
                    )
            );
        } finally {
            server.stop();
        }
    }
}
~~~

### 29.1. Stronger Than `mock.send()`

This genuinely opens an SMTP connection to the test server and captures the transmitted message, rather than merely verifying the service invoked `sender.send()` once.

### 29.2. Test Uses No Production SMTP

Both server and sender use loopback, zero real credentials, and send nothing onto the Internet.

### 29.3. Do Not Assert Fixed Boundaries or Message-IDs

Generated values can vary. Focus assertions on semantics: recipient, Subject, parsed body, and attachment.

### 29.4. Port 3025 Can Collide in CI

Never run concurrent tests bound to the same port 3025. For parallel suites, allocate ephemeral ports and inject the actual bound port into the sender.

A `Bcc` recipient can receive a message via the SMTP envelope without appearing in raw MIME headers.

### 31.2. Test Using an Appropriate Capture Server

If the port is permanently wrong, retrying every 5 seconds will not fix the server. Fix the configuration.

~~~yaml
spring:

    properties:
      "[mail.smtp.starttls.enable]": "true"
~~~

SMTP submission fails.

### 33.1. Never Disable Production TLS to Fix a Test

Plaintext local SMTP on loopback is strictly for the lab. Production must configure STARTTLS or implicit TLS and hostname verification per provider requirements.

### 33.2. Distinguish the Ports

- `1025`: test port in Docker Compose.
- `587`: standard SMTP submission with STARTTLS.

## 34. Negative Test: Mis-Parsing MIME Structure

A common mistake:

~~~java
Object content = message.getContent();
String html = (String) content;
~~~

When the root is `Multipart`, this cast throws `ClassCastException`.

Another mistake:

~~~java
Multipart multi = (Multipart) message.getContent();
String body = (String) multi.getBodyPart(0).getContent();
~~~

Part 0 may itself be another `Multipart`, not a `String`.

### 34.1. Use Recursion and `isMimeType`

Check `content instanceof Multipart`, then recurse down to `text/plain` and `text/html` parts. Always distinguish attachments from bodies.

### 34.2. Do Not Rely on Fixed Part Counts

Adding an inline image or attachment deepens MIME nesting. Semantic assertions stay resilient across structural changes.

## 35. Negative Test: Broken Attachments

Common bugs:

- Valid filename, zero bytes.
- `Content-Type` claims PDF while bytes are not PDF.
- `InputStream` was already consumed.
- Resource could not be opened during MIME serialization.
- Accented filename decoded incorrectly.
- Attachment accidentally marked inline.
- Payload exceeds provider size limits.

### 35.1. Read Decoded Bytes Instead of Trusting UI Icons

A UI showing an attachment icon proves only that MIME metadata was parsed. Tests must compare file bytes or checksums.

### 35.2. Attachments Can Be Read Late

`MimeMessageHelper` may hold a resource reference and read it only when Jakarta Mail serializes the message during `send`. If the resource disappears before then, the failure surfaces at send time.

### 35.3. Never Save Untrusted Filenames Directly

If extending a parser to write attachments to disk, sanitize filenames/paths and bound sizes; MIME metadata is not a trusted filesystem path.

## 38. Limits When Assessing Delivery and Send Correctness

| Question | Can a Capture Server Answer It? |
| --- | --- |
| Did Spring send to the local SMTP port? | Yes |
| Did the test SMTP server receive the message? | Yes |
| Are MIME headers, UTF-8, HTML, and attachments right? | Yes, with proper assertions |
| Does MIME have matching `Content-ID` and multipart nesting? | Yes |
| Are production provider SMTP AUTH and TLS valid? | Not by default |
| Is domain SPF/DKIM/DMARC configured properly? | No |
| Does the provider enforce different rate limits? | No |
| Will the email avoid spam folders? | No |
| Did the message reach the recipient's inbox? | No |
| Did the recipient read the email? | No |
| Will retries never send duplicates? | No |

### 38.1. SMTP Submission vs. Downstream Delivery

`JavaMailSender.send` completing and Mailpit capturing the message prove only **submission to the test server**. Production delivery tracking requires downstream feedback such as authenticated provider bounce/delivery webhooks.

### 38.2. Never Claim Exactly-Once SMTP

A database outbox and SMTP share no distributed transaction. If a provider accepts `DATA` and the app crashes before recording `SENT`, retries can create duplicates. Capture tests do not eliminate that window of uncertainty.

## 42. Frequently Asked Questions

**1. Does Mailpit send emails onto the Internet?**

With the capture setup in this lesson, it stores messages for inspection instead of delivering to external mailboxes. That is the purpose of a test SMTP server.

**2. Why is the UI on port 8025 while Spring sends to port 1025?**

8025 serves the HTTP web UI and API; 1025 is the SMTP listener. They are distinct protocols and roles.

**3. Are IMAP or POP3 needed to inspect MIME?**

No. You can download `.eml` from Mailpit or retrieve `MimeMessage` via GreenMail's API in tests. IMAP/POP3 serve different mailbox-reading use cases.

**4. Are an SMTP username and password required?**

Not in the local capture lab; production SMTP normally enforces dedicated authentication and security requirements.

**5. Why is the raw Subject encoded?**

MIME uses encoded-words for Unicode headers. `MimeMessage.getSubject()` decodes them into a usable `String`.

**6. Does Base64 protect email contents?**

No. It is merely an encoding; anyone with the bytes can decode it.

**7. Why does MIME have multiple multipart layers?**

Plain/HTML alternatives, inline resources, and attachments have distinct structural semantics, so MIME nests multiple `Multipart` containers.

**8. Why isn't `getContent()` always a `String`?**

A `Part` may hold a `Multipart`, a nested `Message`, binary data, or a `String`. Always check the type before casting.

**9. Why isn't a `text/plain` attachment an email body?**

MIME metadata (`filename` / `disposition`) identifies it as an attached file part rather than the primary body.

**10. Should tests assert raw boundaries?**

No. Boundaries are generated dynamically; assert decoded content and MIME semantics.

**11. Can a mocked `JavaMailSender` replace GreenMail?**

Yes for orchestration unit tests, though mocks do not test real SMTP exchanges or MIME serialization. GreenMail fits integration tests.

**12. Does reusing the same `Message-ID` prevent duplicates?**

There is no guarantee SMTP relays deduplicate automatically by `Message-ID`.

**13. Does `Bcc` appear in `.eml` files?**

Not by default. `Bcc` addresses travel in envelope recipients without appearing in transmitted headers.

**14. If `sender.send` returns normally, has the recipient received it?**

No. That reflects only submission to the test SMTP client/server, proving nothing about downstream inbox delivery.

**15. Why does the GreenMail test use port 3025?**

The example picks a separate port to avoid colliding with Mailpit on 1025. For parallel CI suites, use dynamic/isolated ports.

**16. Why not send test emails to a real Gmail account?**

It adds network/provider dependencies, risks misdirected mail, hits rate limits, and makes raw MIME comparison harder.

**17. Can `.eml` files be committed to Git?**

Only if they are synthetic fixtures containing zero sensitive data and allowed by repository policy.

**18. Why doesn't raw MIME contain literal Vietnamese text?**

Quoted-printable, base64, and encoded-words encode UTF-8 bytes for transport. Use Jakarta Mail to decode.

**19. How do you detect a corrupted attachment?**

Compare filename, content type, and decoded bytes/checksums against expected data.

**20. Does local SMTP testing verify production SPF/DKIM/DMARC?**

No. That requires separate domain and provider configuration and testing.

**21. Why does a message look great in Mailpit yet poorly in Outlook?**

Mail clients use different rendering engines and security policies. MIME capture is only one testing layer.

**22. Should the test endpoint exist in production?**

No. The example restricts it to the `local` profile with fixed test addresses; production SMTP diagnostics require separate workflows and permissions.

**23. How do you test inline attachments?**

Reference `cid:` in HTML, match `Content-ID` on the image MIME part, and inspect decoded image bytes and the `multipart/related` layout.

**24. Why can't Spring reach localhost when running in Docker?**

Inside a container, `localhost` is that app container itself. Use the Mailpit service hostname on the shared network.

**25. Do you need to assert the exact `Content-Transfer-Encoding`?**

Usually not. As long as decoded content, `Content-Type`, and charset are intact, quoted-printable vs. base64 can vary by implementation.

## 43. Takeaways on Running a Test SMTP Server and Inspecting MIME

**A reliable Spring Framework Mail test sends emails to an SMTP capture server rather than production.** Mailpit running via Docker Compose listens for SMTP on **127.0.0.1:1025** and displays captured messages at **127.0.0.1:8025**. Spring Boot uses `JavaMailSender` and `MimeMessageHelper` to build emails with **`text/plain`, `text/html`, UTF-8, and attachments**, submitting cleanly once to the test server.

**Inspecting MIME must go deeper than HTML previews.** Download `.eml` files, examine headers, `Content-Type`, charset, `Content-Transfer-Encoding`, `Content-Disposition`, `Content-ID`, and boundaries, then parse the **`MimeMessage`** with Jakarta Mail and traverse **`Multipart`** trees recursively. Locate the exact body parts, separate text attachments from plain-text bodies, verify decoded `Subject` and file bytes, and never hardcode generated boundaries or `Message-ID`s.

For automated testing, **GreenMail** starts an in-JVM SMTP server, receives messages sent by `JavaMailSenderImpl`, and exposes `MimeMessage` objects to JUnit assertions. Keep composer unit tests, orchestration tests, and SMTP integration tests separate; use synthetic data and isolated environments, never real secrets or real recipients.

Finally, **SMTP capture success confirms only local submission, not inbox delivery**. Production AUTH/TLS, SPF/DKIM/DMARC, spam filtering, provider webhooks, and duplicate handling remain distinct responsibilities. With those boundaries clear, you can validate email content quickly, safely, repeatably, and diagnostically.
