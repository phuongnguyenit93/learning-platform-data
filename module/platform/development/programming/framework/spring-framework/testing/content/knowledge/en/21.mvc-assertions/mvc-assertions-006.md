# Serialized DTOs Differ from In-Memory Objects

## 1. MVC Results Are Serialized HTTP Data

When a controller returns a DTO, Spring MVC does not send the raw Java object over HTTP. For a REST endpoint, the processing flow typically looks like this:

~~~text
Controller
   |
   | returns Java DTO
   v
HandlerMethodReturnValueHandler
   |
   | selects HttpMessageConverter by data type and media type
   v
Jackson HttpMessageConverter
   |
   | ObjectMapper serializes DTO
   v
JSON bytes in HTTP response
   |
   v
MockHttpServletResponse / HTTP client
~~~

For example, a controller may return a Java object containing **note = null**. Jackson may omit that field completely from JSON if **@JsonInclude(NON_NULL)** is configured. Property names can also be renamed via **@JsonProperty** or a naming strategy. A Java **Instant** becomes a date-time string; an enum typically becomes a string; a collection becomes a JSON array.

Therefore, two distinct results must be distinguished:

- **In-memory object:** the Java DTO held by the controller or service, with Java types, values, and state.
- **HTTP representation:** the JSON (or other format) generated by **HttpMessageConverter** and actually sent back to the client.

When testing MVC results, what the client receives is the contract to verify. An assertion on the in-memory DTO does not prove that the JSON response has the right field names, data types, formatting, or content.

## 2. What Can Change When Jackson Serializes a DTO

### Property Names

A DTO has property **orderId**, while the API may expose the name **order_id**:

~~~java
import com.fasterxml.jackson.annotation.JsonProperty;

public record OrderResponse(
        @JsonProperty("order_id") Long orderId,
        String status
) {
}
~~~

The JSON looks like:

~~~json
{
  "order_id": 42,
  "status": "PAID"
}
~~~

Testing **$.orderId** will fail even though the DTO has an **orderId()** accessor and its in-memory value is **42**. Clients must read the property name exposed in the JSON.

Property names can also be affected by a globally configured **PropertyNamingStrategy** or **PropertyNamingStrategies**, such as converting camelCase to snake_case.

### Omitted or Hidden Properties

**@JsonInclude** determines when a property is included in JSON:

~~~java
import com.fasterxml.jackson.annotation.JsonInclude;

@JsonInclude(JsonInclude.Include.NON_NULL)
public record ProfileResponse(
        Long id,
        String displayName,
        String phone
) {
}
~~~

If **phone** is **null**, the JSON may contain only **id** and **displayName**. The Java object still has the **phone()** accessor returning **null**, but the response has no **phone** key.

Distinguish three states:

| JSON | Meaning |
|---|---|
| **{}** | Property is absent |
| **{"phone": null}** | Property is present with null value |
| **{"phone": ""}** | Property is present with empty string |

These three states can have different meanings to clients. **jsonPath("$.phone").doesNotHaveJsonPath()** checks that the key is absent; **jsonPath("$.phone").hasJsonPath()** combined with **value(nullValue())** checks that the key is present with a null value. When exact distinction is needed, you can parse the response into a **JsonNode** and use **has()** / **hasNonNull()**.

Besides **@JsonInclude**, **@JsonIgnore**, **@JsonView**, filters, and visibility configuration can also cause properties to disappear from JSON.

### Java Types Become JSON Types

JSON only has value categories such as object, array, string, number, boolean, and null. It does not have Java types like **Instant**, **BigDecimal**, enum, or **UUID**.

| Type in DTO | Common JSON Representation |
|---|---|
| **String** | JSON string |
| **Long**, **Integer** | JSON number |
| **BigDecimal** | JSON number |
| **Boolean** | JSON boolean |
| **Instant**, **LocalDate** | JSON string per serializer configuration |
| **enum** | Usually enum name as a JSON string |
| **List<T>** | JSON array |
| **Map<K,V>** | JSON object if keys can be suitably represented |
| **byte[]** | Usually Base64-encoded into a JSON string |

For example, **Instant** is no longer a Java object with a **toString()** method in the response; it becomes a string formatted according to the serializer and time configuration. **@JsonFormat**, the Java Time module, and configured timezone can all affect that format.

Do not assume every enum is always serialized by name. Jackson configuration or annotations can alter how enums are represented, such as writing them by ordinal index. Always verify the actual API format.

### Transformed or Formatted Values

Custom serializers, getters, mix-ins, Jackson modules, or **ResponseBodyAdvice** can make values in the response differ from the original Java fields. A getter can also expose a computed value that Jackson treats as a property.

Example:

~~~java
public class PriceResponse {

    private final BigDecimal amount;

    public PriceResponse(BigDecimal amount) {
        this.amount = amount;
    }

    public BigDecimal getAmount() {
        return amount;
    }

    public String getFormattedAmount() {
        return amount.toPlainString() + " VND";
    }
}
~~~

Jackson may include both **amount** and **formattedAmount** in JSON because both are getters recognizable as properties, unless excluded by configuration or annotations. Which fields a DTO declares does not mean the response contains only those fields.

### JSON Ordering and Formatting

A JSON object is a collection of named members; clients should generally not depend on property order or whitespace. Jackson may write properties in different orders depending on configuration, annotations, or version changes.

The following two responses have the same data structure:

~~~json
{"id":42,"status":"PAID"}
~~~

~~~json
{
  "status": "PAID",
  "id": 42
}
~~~

Therefore, JSON assertions should compare structure and values. Only assert verbatim JSON strings when literal text formatting, key ordering, or whitespace is genuinely part of an explicit contract.

## 3. Example DTO and Spring MVC Response

Suppose an API returns order information. The DTO uses the property name **order_id**, omits **note** when null, and includes the order creation timestamp.

### DTO

~~~java
import java.math.BigDecimal;
import java.time.Instant;

import com.fasterxml.jackson.annotation.JsonInclude;
import com.fasterxml.jackson.annotation.JsonProperty;

@JsonInclude(JsonInclude.Include.NON_NULL)
public record OrderResponse(
        @JsonProperty("order_id") Long orderId,
        BigDecimal total,
        OrderStatus status,
        String note,
        Instant createdAt
) {
}
~~~

### Enum

~~~java
public enum OrderStatus {
    PENDING,
    PAID,
    CANCELLED
}
~~~

### Controller

~~~java
import java.math.BigDecimal;
import java.time.Instant;

import org.springframework.http.MediaType;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequestMapping("/api")
public class OrderController {

    @GetMapping(
            value = "/orders/{id}",
            produces = MediaType.APPLICATION_JSON_VALUE
    )
    public OrderResponse getOrder(@PathVariable Long id) {
        return new OrderResponse(
                id,
                new BigDecimal("1250.00"),
                OrderStatus.PAID,
                null,
                Instant.parse("2026-11-13T02:00:00Z")
        );
    }
}
~~~

The Java object created by the controller has five components. The **note** component is **null**. With Jackson configured to honor DTO annotations and the Java Time module, the JSON response may look like:

~~~json
{
  "order_id": 42,
  "total": 1250.00,
  "status": "PAID",
  "createdAt": "2026-11-13T02:00:00Z"
}
~~~

Immediately observable differences:

- **orderId** in the DTO is exposed as **order_id**.
- **note** exists as a record component but does not appear in the JSON.
- **total** is represented as a JSON number, not a **BigDecimal** object.
- **status** is represented as a JSON string.
- **createdAt** is represented as an ISO-8601 string per Java Time configuration.

The example uses a fixed timestamp so test results are deterministic. Avoid using **Instant.now()** in assertions comparing against a fixed time string.

## 4. Verifying Actual JSON with MockMvc

With Spring Boot, **@WebMvcTest** can set up the MVC slice for a controller and configure message converters. Tests should assert status, content type, and properties in the response body.

~~~java
import java.nio.charset.StandardCharsets;

import com.fasterxml.jackson.databind.JsonNode;
import com.fasterxml.jackson.databind.ObjectMapper;

import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.autoconfigure.web.servlet.WebMvcTest;
import org.springframework.http.MediaType;
import org.springframework.test.web.servlet.MockMvc;
import org.springframework.test.web.servlet.MvcResult;

import static org.assertj.core.api.Assertions.assertThat;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.get;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.content;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.jsonPath;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.status;

@WebMvcTest(OrderController.class)
class OrderControllerTest {

    @Autowired
    private MockMvc mockMvc;

    @Autowired
    private ObjectMapper objectMapper;

    @Test
    void shouldReturnTheSerializedOrderDto() throws Exception {
        MvcResult result = mockMvc.perform(get("/api/orders/{id}", 42L)
                        .accept(MediaType.APPLICATION_JSON))
                .andExpect(status().isOk())
                .andExpect(content().contentTypeCompatibleWith(
                        MediaType.APPLICATION_JSON))
                .andExpect(jsonPath("$.order_id").value(42))
                .andExpect(jsonPath("$.total").value(1250.00))
                .andExpect(jsonPath("$.status").value("PAID"))
                .andExpect(jsonPath("$.createdAt")
                        .value("2026-11-13T02:00:00Z"))
                .andExpect(jsonPath("$.note").doesNotHaveJsonPath())
                .andReturn();

        String responseBody = result.getResponse()
                .getContentAsString(StandardCharsets.UTF_8);

        JsonNode json = objectMapper.readTree(responseBody);

        assertThat(json.has("order_id")).isTrue();
        assertThat(json.has("orderId")).isFalse();
        assertThat(json.has("note")).isFalse();
    }
}
~~~

The assertions in this test verify the exact data sent to the client:

- **status().isOk()** verifies the HTTP status.
- **contentTypeCompatibleWith(...)** verifies the response has a compatible JSON media type.
- **jsonPath(...)** verifies property names and values after serialization.
- **doesNotHaveJsonPath()** verifies **note** was omitted from the JSON.
- **MvcResult** lets you extract the raw response body for deeper inspection with **JsonNode**.

If you only inspected the **OrderResponse** object inside the controller or service, the test would miss cases where Jackson writes **order_id** instead of **orderId**, omits **note**, or formats timestamps unexpectedly.

The **ObjectMapper** injected into the test helps parse the JSON response. In applications with custom converter configurations, ensure that the mapper used to read/compare and the mapper used by MVC converters share compatible settings. Injecting the default **ObjectMapper** does not by itself prove that every custom converter uses that exact instance.

## 5. Checking JSON Structurally Instead of String Comparison

### Using jsonPath for Key Properties

**jsonPath** is ideal when you only need to verify parts of the API contract. You can check:

~~~java
mockMvc.perform(get("/api/orders/42"))
        .andExpect(status().isOk())
        .andExpect(jsonPath("$.order_id").value(42))
        .andExpect(jsonPath("$.status").value("PAID"))
        .andExpect(jsonPath("$.items").isArray())
        .andExpect(jsonPath("$.items.length()").value(2));
~~~

Syntax and assertions should match actual JSON types. Examples:

- **isArray()** checks that the property is an array.
- **isMap()** checks that the property is a JSON object.
- **isEmpty()** checks for an empty value according to the corresponding matcher.
- **doesNotHaveJsonPath()** checks that the property does not exist; **hasJsonPath()** confirms the property exists even when its value is null.
- **value(...)** checks the property's value.

Do not use **value("1250.00")** if the response contains a JSON number. The string **"1250.00"** and the number **1250.00** are different JSON types.

### Using JsonNode When Distinguishing Null from Absent

**JsonNode** is useful when the response has nested structures or when you need exact key-presence checks:

~~~java
JsonNode root = objectMapper.readTree(responseBody);

assertThat(root.has("note")).isFalse();
assertThat(root.has("order_id")).isTrue();
assertThat(root.path("order_id").asLong()).isEqualTo(42L);
~~~

If you want to verify a key exists and has a null value:

~~~java
JsonNode root = objectMapper.readTree(responseBody);

assertThat(root.has("note")).isTrue();
assertThat(root.get("note").isNull()).isTrue();
~~~

**has("note")** returns **true** when the key exists, even if its JSON value is null. **hasNonNull("note")** returns **true** only when the key exists and is non-null. **path("missing")** returns a missing node rather than Java **null**, so choose the inspection API that matches your goal.

### Using content().json When Comparing a Full JSON Document

You can assert the entire response structure with a JSON assertion:

~~~java
mockMvc.perform(get("/api/orders/42"))
        .andExpect(status().isOk())
        .andExpect(content().json("""
                {
                  "order_id": 42,
                  "total": 1250.00,
                  "status": "PAID",
                  "createdAt": "2026-11-13T02:00:00Z"
                }
                """));
~~~

JSON comparison normally ignores property order inside objects. This is concise when asserting multiple properties together. However, if the response is large, **jsonPath** for key fields or **JsonNode** for specific structures is often easier to read and diagnose.

Do not convert the entire response to a string and use **contains()** to verify JSON. Substrings can appear in the wrong location, in another property, or inside a string value; that does not prove the JSON structure is valid.

## 6. When Exact Numeric Values Must Be Checked

**BigDecimal** is written by Jackson as a JSON number. Issues can arise when tests or clients parse JSON numbers into floating-point types like **double**, because **double** cannot represent all decimal fractions accurately.

If the API requires exact decimal values, you can parse the JSON tree configured to use **BigDecimal** for floating-point numbers:

~~~java
import java.math.BigDecimal;

import com.fasterxml.jackson.databind.DeserializationFeature;
import com.fasterxml.jackson.databind.JsonNode;

JsonNode root = objectMapper.reader()
        .with(DeserializationFeature.USE_BIG_DECIMAL_FOR_FLOATS)
        .readTree(responseBody);

BigDecimal total = root.get("total").decimalValue();

assertThat(total).isEqualByComparingTo(new BigDecimal("1250.00"));
~~~

**isEqualByComparingTo** compares the numeric value of **BigDecimal** without requiring identical scale. If scale is also part of the contract, assert the scale or the exact JSON representation accordingly.

If the API intentionally exposes monetary amounts as JSON strings, the DTO or serializer should make that contract explicit, and the test should assert a string. Avoid letting tests accidentally accept both numbers and strings when clients expect a single type.

## 7. Testing with the Right HttpMessageConverter Configuration

Serialization output depends on the converter that actually processes the response. Thus, how MockMvc is set up affects test reliability.

### Using WebApplicationContext

When verifying the application's MVC configuration, build MockMvc from **WebApplicationContext**:

~~~java
import org.junit.jupiter.api.BeforeEach;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.test.context.junit.jupiter.web.SpringJUnitWebConfig;
import org.springframework.test.web.servlet.MockMvc;
import org.springframework.test.web.servlet.setup.MockMvcBuilders;
import org.springframework.web.context.WebApplicationContext;

@SpringJUnitWebConfig(classes = WebConfig.class)
class OrderMvcTest {

    @Autowired
    private WebApplicationContext context;

    private MockMvc mockMvc;

    @BeforeEach
    void setUp() {
        mockMvc = MockMvcBuilders
                .webAppContextSetup(context)
                .build();
    }
}
~~~

This uses the MVC components registered in the context, including configured **HttpMessageConverter** beans. In Spring Boot, **@WebMvcTest** or **@SpringBootTest** combined with **@AutoConfigureMockMvc** are common choices depending on test scope.

### Be Careful with standaloneSetup

**MockMvcBuilders.standaloneSetup(controller)** is convenient for small controller tests, but it builds default MVC infrastructure and converters on its own. If production uses a custom **ObjectMapper**, custom serializers, or additional registered converters, a standalone test may not run with that same configuration.

When serialization output is what you need to verify, use **webAppContextSetup** or configure the converters explicitly on standalone MockMvc. Otherwise, tests may pass against the test setup while the real application produces different responses.

### Java Time Configuration

If a DTO includes **Instant**, **LocalDate**, or **LocalDateTime**, you need a Java Time module compatible with your Jackson version and matching format settings. Spring Boot typically auto-registers modules present on the classpath. In a manually configured Spring MVC application, register that module on the **ObjectMapper** used by **MappingJackson2HttpMessageConverter**.

Do not just verify a date-time string generated by an **ObjectMapper** instance in a unit test if the production controller uses a different converter. Test the MockMvc response going through the corresponding MVC configuration.

## 8. Request DTOs Can Also Differ After Deserialization

The request side runs in the reverse direction:

~~~text
HTTP JSON request
   |
   v
HttpMessageConverter
   |
   | Jackson deserializes
   v
Java DTO in controller
~~~

Incoming JSON is converted into a Java object. Differences can occur when:

- A JSON property is missing and a Java constructor or field uses a default value.
- A JSON property is **null**, whereas a Java primitive cannot hold null.
- **@JsonProperty** maps a JSON key to a different component or field name.
- **@JsonAlias** accepts multiple input names.
- Unknown properties are rejected or ignored depending on configuration.
- Custom deserializers convert strings into Java types or normalize values.
- **@JsonCreator** controls how the DTO is instantiated.

Therefore, request-binding tests should send actual JSON through MockMvc and verify the controller receives the right result. Constructing **new RequestDto(...)** directly only tests Java logic after binding, not whether Jackson maps the JSON request properly.

Example:

~~~java
mockMvc.perform(post("/api/orders")
                .contentType(MediaType.APPLICATION_JSON)
                .content("""
                        {
                          "order_id": 42,
                          "status": "PAID"
                        }
                        """))
        .andExpect(status().isCreated());
~~~

If you need to assert the values the controller received, you can mock the service called by the controller and use an **ArgumentCaptor** to inspect the DTO passed to it. That verifies both JSON request binding and the bound values.

## 9. Common Testing Mistakes

| Testing Practice or Symptom | Why It Is Insufficient or Wrong | How to Fix |
|---|---|---|
| Comparing in-memory DTOs and assuming the response is right | Bypasses **HttpMessageConverter** | Send a MockMvc request and inspect the response body |
| Using Java field names in JSONPath | The API may rename keys via **@JsonProperty** or a naming strategy | Use the exact property names exposed in JSON |
| Expecting null when the property is omitted | **@JsonInclude(NON_NULL)** or filters drop properties | Check **hasJsonPath()** / **doesNotHaveJsonPath()** or inspect with **JsonNode** |
| Expecting a string when JSON returns a number | JSON number and JSON string are different types | Assert using the actual data type and API contract |
| Comparing full JSON as a raw string | Property order and whitespace may differ | Use **jsonPath**, **JsonNode**, or **content().json** |
| Using standaloneSetup while skipping custom converters | Test configuration differs from application configuration | Use **webAppContextSetup** or register the exact converters |
| Asserting timestamps with now() | Value changes depending on when the test runs | Use a fixed timestamp and verify format/timezone |
| Deserializing the response back into the same DTO and comparing objects | Re-reading can mask omitted fields or default values | Inspect the JSON tree or properties directly on the response |
| Checking only HTTP 200 | Correct status does not prove the body is right | Assert status, content type, and key properties |

Another common mistake is creating **new ObjectMapper()** inside a test and using it to conclude the MVC response is valid. A fresh mapper does not automatically include the modules, naming strategies, serializers, mix-ins, or settings registered by the application. Use the mapper configured in the context to read the response, and more importantly, let MockMvc run through the exact converters used by the application.

## 10. Choosing Assertions by What Needs Verification

| What to Verify | Appropriate Assertion |
|---|---|
| HTTP status and content type | **status()** and **content()** |
| A single property or nested value | **jsonPath()** |
| Whether a key exists, is null, or absent | **JsonNode.has()**, **hasNonNull()**, **isNull()** |
| Multiple properties in a JSON document | **content().json(...)** |
| Decimals requiring exact precision | Parse JSON with **USE_BIG_DECIMAL_FOR_FLOATS** and compare **BigDecimal** |
| Published date-time string format | **jsonPath()** with a fixed timestamp string |
| Request JSON mapped to DTO correctly | Send JSON via MockMvc and inspect the argument passed to the service |

A reliable MVC test verifies data right at the HTTP boundary. The in-memory DTO is the input to serialization; the JSON response is what the client receives. Only when tests assert the actual JSON representation do they catch changes caused by annotations, Jackson settings, and **HttpMessageConverter**.
