# Spring MVC — Public URLs When Running Behind a Reverse Proxy

## 1. Problem

When deploying Spring Boot on a server or container, the application often does not directly receive the client's public URL. HTTPS may terminate at a reverse proxy/API gateway, while requests to Spring MVC arrive over HTTP on an internal path.

~~~text
Browser:
  https://learn.example.com/java/api/v1/books/42
            |
            v
Reverse proxy:
  TLS termination, public host, strip prefix /java
            |
            v
Spring Boot:
  http://backend:8080/api/v1/books/42
~~~

If the backend reads the internal scheme, host, port, and path to construct links, the response can be wrong:

~~~http
HTTP/1.1 201 Created
Location: http://backend:8080/api/v1/books/42
~~~

The correct public URL must be:

~~~http
HTTP/1.1 201 Created
Location: https://learn.example.com/java/api/v1/books/42
~~~

This affects `201 Created + Location`, `302/303` redirects, HATEOAS links, Swagger/OpenAPI server URLs, OAuth2 callbacks, password reset links, and URLs sent via email.

**Goal:** understand and control public URIs behind a reverse proxy; handle forwarded headers safely; distinguish a proxy prefix from a Servlet context path/API version; use Spring Boot `server.forward-headers-strategy` and `ServletUriComponentsBuilder`; configure Nginx; test HTTP responses, path rewrites, and host-spoofing protection.

Scope: Spring MVC Servlet stack, Java 17+, Spring Boot 3.5.0, and Spring Framework 6.2. WebFlux uses a different mechanism, `ForwardedHeaderTransformer`.

## 2. Public URL, internal URL, and application paths

| Component | Example | Meaning |
| --- | --- | --- |
| Public scheme | `https` | Protocol seen by the browser |
| Public host | `learn.example.com` | Domain served by DNS/TLS/public port |
| Public port | `443` | Effective HTTPS port, usually omitted in URLs |
| Public mount prefix | `/java` | URL branch used by the proxy to mount the application |
| API version path | `/api/v1` | Contract/version of the API itself |
| Resource path | `/books/42` | Specific resource |
| Internal origin | `http://backend:8080` | Proxy target for the backend |
| Spring handler path | `/api/v1/books/{id}` | Actual `@GetMapping` in the Servlet app |
| Servlet context path | `server.servlet.context-path` | Servlet container's own prefix; may be empty |

**Do not conflate** `/java` with `/api/v1`. The proxy prefix is a deployment topology concern; the API version is part of the client contract. If the app moves from `/java` to `/learn`, the version `v1` may stay unchanged, yet public URLs in bookmarks and SDKs are still affected.

### 2.1. Why do URLs go wrong?

With a prefix-stripping proxy:

~~~text
GET https://learn.example.com/java/api/v1/books/42
 -> proxy_pass
GET http://backend:8080/api/v1/books/42
~~~

The backend may see:

~~~text
request.getScheme()      = "http"
request.getServerName()  = "backend"
request.getServerPort()  = 8080
request.getContextPath() = ""
request.getRequestURI()  = "/api/v1/books/42"
~~~

This data is accurate from an internal network perspective, yet **not the canonical address to return to the client**.

A production API needs a trusted protocol to pass the public scheme, host, port, and path prefix from the proxy into Spring.

## 3. What are Forwarded and X-Forwarded-*?

### 3.1. The standard Forwarded header (RFC 7239)

The RFC 7239 header has syntax such as:

~~~http
Forwarded: for=192.0.2.10;proto=https;host=learn.example.com
~~~

It describes request metadata across proxy hops and can contain multiple elements. This RFC does not universally define a path-prefix field replacing `X-Forwarded-Prefix`.

### 3.2. Common headers

| Header | Example value | Effect |
| --- | --- | --- |
| `X-Forwarded-Proto` | `https` | Public scheme of the client |
| `X-Forwarded-Host` | `learn.example.com` | Public host |
| `X-Forwarded-Port` | `443` | Public port |
| `X-Forwarded-Prefix` | `/java` | Public mount prefix rewritten by the proxy |
| `X-Forwarded-For` | `192.0.2.10` | Client/proxy IP chain |
| `X-Forwarded-Ssl` | `on` | A legacy convention for TLS |

Example backend request:

~~~http
GET /api/v1/books/42 HTTP/1.1
Host: backend:8080
X-Forwarded-Proto: https
X-Forwarded-Host: learn.example.com
X-Forwarded-Port: 443
X-Forwarded-Prefix: /java
~~~

If Spring properly processes the headers **generated by a trusted proxy**, it can construct valid public URLs even though the direct upstream uses internal HTTP.

### 3.3. Headers are not inherently trustworthy

A client can send:

~~~http
X-Forwarded-Host: attacker.example
X-Forwarded-Proto: https
X-Forwarded-Prefix: /evil
~~~

A Spring app **cannot tell on its own** whether those headers were set by a trusted reverse proxy or sent by an attacker. If clients can reach the backend directly, trusting these values can cause:

- Host-header injection and links pointing to an attacker domain.
- Open redirects via `Location`.
- Password-reset email link poisoning.
- Tampered OAuth/OIDC `redirect_uri`.
- Log spoofing or incorrect client IP analysis.
- Cache poisoning when a proxy/cache keys on the wrong Host.

**Rule:** the edge proxy must **strip** forwarded headers from the Internet and **overwrite** them with trusted canonical values; the backend must only accept network traffic from the proxy or trusted upstreams.

## 4. server.forward-headers-strategy in Spring Boot

Spring Boot 3.5 supports:

~~~properties
server.forward-headers-strategy=framework
~~~

| Value | Handler | Notes |
| --- | --- | --- |
| `none` | Boot does not enable forwarded-header processing | Fits when there is no trusted proxy or public URLs use separate config |
| `native` | Container handles natively (Tomcat/Jetty) | May suffice for `X-Forwarded-For`/`Proto` depending on container |
| `framework` | Spring Framework, using forwarded-header filter support on Servlet | Often suitable when host/port/proto and `X-Forwarded-Prefix` are needed |

Spring Boot documentation notes that for a proxy sending `X-Forwarded-For` and `X-Forwarded-Proto`, `NATIVE` mode may be enough. If the native implementation does not cover all needed features, especially path prefixes, `FRAMEWORK` mode is commonly used for Spring MVC.

### 4.1. Defaults vary by platform

In some cloud environments detected by Spring Boot, the default may be `NATIVE`, whereas in others it is `NONE`. Set it explicitly in the production profile:

~~~properties
# application-prod.properties
server.forward-headers-strategy=framework
~~~

Do not enable it when Internet clients can call the backend directly and send arbitrary `Forwarded` headers. **This property does not replace a proxy trust policy.**

### 4.2. ForwardedHeaderFilter

In Spring MVC, `org.springframework.web.filter.ForwardedHeaderFilter` is a Servlet filter that processes `Forwarded` and `X-Forwarded-*` so downstream code sees the request from the client's perspective. It wraps the request/response, applies forwarded metadata, removes downstream influence of raw headers, and must run early enough before other URI-dependent filters/handlers.

If Boot is already configured with:

~~~properties
server.forward-headers-strategy=framework
~~~

then you do not need to manually declare an extra `ForwardedHeaderFilter` bean. Avoid accidentally applying native + framework + manual filter simultaneously.

The filter has `setRemoveOnly(true)` if you only want to **strip** untrusted headers without using them. `removeOnly` mode does not restore public scheme/host/prefix — use it when another canonical URL configuration exists or for hardening.

### 4.3. Async or error dispatches

With MVC async `Callable`/`DeferredResult`, Servlets have `REQUEST` and `ASYNC` dispatches; errors can go through `ERROR` dispatch. When registering a forwarded filter manually, use the proper ordering/dispatcher types so request/response stay consistent. In Boot, verify actual registration when using custom filter registration; do not test only a synchronous GET 200.

### 4.4. Tomcat TLS termination

Spring Boot 3.5 guides that when Tomcat sits behind an SSL-terminating proxy, you may need:

~~~properties
server.tomcat.redirect-context-root=false
~~~

so `X-Forwarded-Proto` is processed before certain context-root redirects. Apply only per specific topology/version and test; do not add blindly to cure every redirect loop.

## 5. X-Forwarded-Prefix and three rewrite patterns

### 5.1. Strip prefix

~~~text
Public : https://learn.example.com/java/api/v1/books/42
Backend: http://backend:8080/api/v1/books/42
X-Forwarded-Prefix: /java
~~~

The backend route remains:

~~~java
@GetMapping("/api/v1/books/{id}")
~~~

Without prefix handling, the URI builder would return `https://learn.example.com/api/v1/books/42`, missing `/java`.

### 5.2. Preserve prefix

~~~text
Public : https://learn.example.com/java/api/v1/books/42
Backend: http://backend:8080/java/api/v1/books/42
~~~

You can use `server.servlet.context-path=/java` or include the prefix in routes/mappings if that is the design. When the backend already keeps the prefix, do not add `/java` a second time via both the request builder and custom code.

### 5.3. Replace context path instead of concatenating strings

Spring Framework docs note `X-Forwarded-Prefix` can **override**, **remove**, or **prepend** the original prefix in different topologies:

| Public | Internal | Meaning |
| --- | --- | --- |
| `https://example.com/api/x` | `http://backend:8080/app1/x` | Public prefix `/api` replaces `/app1` |
| `https://app1.example.com/x` | `http://backend:8080/app1/x` | Empty public prefix replaces internal `/app1` |
| `https://example.com/api/app1/x` | `http://backend:8080/app1/x` | Public prefix `/api/app1` |

Do not invent a hardcoded `contextPath + forwardedPrefix` rule for every deployment: it can produce `/java/java` or drop the prefix.

### 5.4. Ownership rule

Choose **one owner** for each part:

- The gateway owns public host, TLS scheme, public port, mount prefix, and rewrites.
- The Servlet container/Spring knows the internal context path and handler mappings.
- The URI builder relies on the normalized request.
- API versioning is a separately designed contract concern.

If both an ingress and an edge gateway set `X-Forwarded-Prefix`, agree on which hop holds the final canonical prefix and who strips old metadata.

## 6. ServletUriComponentsBuilder builds public URLs

Import:

~~~java
import org.springframework.web.servlet.support.ServletUriComponentsBuilder;
~~~

When a Servlet request has already processed forwarded headers:

~~~java
URI location = ServletUriComponentsBuilder
        .fromCurrentContextPath()
        .path("/api/v1/books/{id}")
        .buildAndExpand(book.id())
        .toUri();

return ResponseEntity.created(location).build();
~~~

**Do not** read raw `X-Forwarded-Host`/`Proto` manually and concatenate strings. Spring docs note that since Framework 5.1, `ServletUriComponentsBuilder` does not parse forwarded headers itself; the application needs `ForwardedHeaderFilter` or equivalent container-level handling beforehand.

### 6.1. Factory methods

| API | Contents | Purpose |
| --- | --- | --- |
| `fromCurrentContextPath()` | Scheme/host/port and context path | Build another URI in the same application |
| `fromCurrentRequestUri()` | Address + current request path, no query | Build a self link |
| `fromCurrentRequest()` | Same as current request, including query | Build a self URI with query when genuinely needed |
| `fromContextPath(request)` | Accepts explicit `HttpServletRequest` | When not using the current request holder directly |

For `POST /api/v1/books` creating `GET /api/v1/books/42`, `fromCurrentContextPath().path(...)` is clearer because it does not depend on the POST's path.

### 6.2. URI templates and encoding

~~~java
URI uri = ServletUriComponentsBuilder
        .fromCurrentContextPath()
        .path("/api/documents/{name}")
        .encode()
        .buildAndExpand(documentName)
        .toUri();
~~~

The code above is a fragment; `documentName` needs a contract and validation. Encoding prevents accidental path-splitting, yet does not solve access control or path traversal if business logic permits arbitrary document names.

### 6.3. 201 Location and redirects

A resource-creating HTTP API usually returns:

~~~http
HTTP/1.1 201 Created
Location: https://learn.example.com/java/api/v1/books/42
~~~

In an MVC view controller:

~~~java
@PostMapping("/checkout")
public String complete(RedirectAttributes attrs) {
    long id = createOrder(); // Service illustrative fragment.
    attrs.addAttribute("id", id);
    return "redirect:/orders/{id}";
}
~~~

`302/303` redirects, JSON self links, and HATEOAS links must also use the right public URL, without leaking port 8080 or internal prefixes. A `Location` header can be a relative URI reference, yet **the relative path must still preserve the right public mount prefix**.

## 7. Illustrative Nginx reverse proxy

Public `https://learn.example.com/java/...`, Spring backend `http://127.0.0.1:8080/...`. Nginx strips `/java/` and forwards to the backend:

~~~nginx
server {
    listen 443 ssl;
    server_name learn.example.com;

    # TLS certificate, key, and security settings must be configured separately.

    location /java/ {
        proxy_pass http://127.0.0.1:8080/;

        # The edge must strip Forwarded sent by clients.
        proxy_set_header Forwarded "";
        proxy_set_header X-Forwarded-Ssl "";

        # Canonical metadata; do not trust arbitrary client Host.
        proxy_set_header Host learn.example.com;
        proxy_set_header X-Forwarded-Host learn.example.com;
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header X-Forwarded-Port 443;
        proxy_set_header X-Forwarded-Prefix /java;
        proxy_set_header X-Forwarded-For $remote_addr;
    }
}
~~~

**This is a design fragment**, not ready to deploy on its own: it needs TLS certificates, default-host rejection, firewall/private backend rules, proper redirects, timeouts/headers, HSTS per policy, and handling `/java` without a trailing slash. If Nginx sits behind another CDN, `$remote_addr` may be the CDN IP; design a separate real-IP trusted chain rather than trusting client-added `X-Forwarded-For`.

### 7.1. Watch the trailing slash in proxy_pass

~~~nginx
location /java/ {
    proxy_pass http://127.0.0.1:8080/;
}
~~~

In a normal prefix location, the trailing `/` URI on `proxy_pass` replaces the matched location prefix, yielding:

~~~text
/java/api/v1/books/42 -> /api/v1/books/42
~~~

Without a URI at the end:

~~~nginx
location /java/ {
    proxy_pass http://127.0.0.1:8080;
}
~~~

it can preserve:

~~~text
/java/api/v1/books/42 -> /java/api/v1/books/42
~~~

With controller mapping `/api/v1/books/{id}`, preserving the prefix can result in 404. Do not change Java mappings before knowing whether the actual proxy strips or preserves the prefix.

### 7.2. Fixed Host and forwarded-for

In Nginx, using canonical `learn.example.com` in `Host`/`X-Forwarded-Host` for a single-domain example avoids reflecting an arbitrary host. Handle/deny unknown Hosts in the virtual host/default server. In a multi-domain system, maintain a domain allowlist and a trusted mechanism for determining the canonical host.

Setting `X-Forwarded-For: $remote_addr` at the edge is one way to overwrite rather than forwarding an arbitrarily client-spoofed list. With multi-proxy chains, design trusted proxy hops and client-IP extraction carefully; never use IP headers for authentication.

When the proxy strips `/java`, Spring mappings **do not include** `/java`. Boot configures forwarding via `FRAMEWORK`.

### 8.4. PublicUrlApplication.java

Save **all Java code** in `src/main/java/demo/PublicUrlApplication.java`. One top-level public class; other types are package-private.

~~~java
package demo;

import java.net.URI;
import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.atomic.AtomicLong;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.http.HttpStatus;
import org.springframework.http.MediaType;
import org.springframework.http.ResponseEntity;
import org.springframework.stereotype.Service;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;
import org.springframework.web.server.ResponseStatusException;
import org.springframework.web.servlet.support.ServletUriComponentsBuilder;

@SpringBootApplication
public class PublicUrlApplication {
    public static void main(String[] args) {
        SpringApplication.run(PublicUrlApplication.class, args);
    }
}

record NewBook(String title) {}
record Book(long id, String title) {}

@Service
class BookService {
    private final AtomicLong ids = new AtomicLong(40);
    private final Map<Long, Book> books = new ConcurrentHashMap<>();

    Book create(String title) {
        if (title == null || title.isBlank()) {
            throw new ResponseStatusException(
                    HttpStatus.BAD_REQUEST, "Title required");
        }
        long id = ids.incrementAndGet();
        Book book = new Book(id, title);
        books.put(id, book);
        return book;
    }

    Book find(long id) {
        Book book = books.get(id);
        if (book == null) {
            throw new ResponseStatusException(
                    HttpStatus.NOT_FOUND, "Book not found");
        }
        return book;
    }
}

@RestController
@RequestMapping("/api/v1")
class BookController {
    private final BookService service;

    BookController(BookService service) {
        this.service = service;
    }

    @GetMapping(path = "/self",
                produces = MediaType.APPLICATION_JSON_VALUE)
    Map<String, String> self() {
        URI publicUri = ServletUriComponentsBuilder
                .fromCurrentRequestUri()
                .build()
                .toUri();
        return Map.of("publicUrl", publicUri.toString());
    }

    @PostMapping(path = "/books",
                 consumes = MediaType.APPLICATION_JSON_VALUE)
    ResponseEntity<Void> create(@RequestBody NewBook input) {
        Book book = service.create(input.title());
        URI location = ServletUriComponentsBuilder
                .fromCurrentContextPath()
                .path("/api/v1/books/{id}")
                .buildAndExpand(book.id())
                .toUri();
        return ResponseEntity.created(location).build();
    }

    @GetMapping(path = "/books/{id}",
                produces = MediaType.APPLICATION_JSON_VALUE)
    Book detail(@PathVariable long id) {
        return service.find(id);
    }
}
~~~

The application does not use raw `Forwarded` headers in the controller. Data is stored in RAM for demonstration and does not replace a database/transactions/security.

### 8.6. MockMvc tests

Create `src/test/java/demo/PublicUrlTest.java`:

~~~java
package demo;

import java.net.URI;

import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.autoconfigure.web.servlet.AutoConfigureMockMvc;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.http.HttpHeaders;
import org.springframework.http.MediaType;
import org.springframework.test.web.servlet.MockMvc;
import org.springframework.test.web.servlet.MvcResult;

import static org.junit.jupiter.api.Assertions.assertEquals;
import static org.junit.jupiter.api.Assertions.assertNotNull;
import static org.junit.jupiter.api.Assertions.assertTrue;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.get;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.post;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.jsonPath;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.status;

@SpringBootTest
@AutoConfigureMockMvc
class PublicUrlTest {
    @Autowired MockMvc mvc;

    @Test
    void selfLinkUsesPublicSchemeHostAndPrefix() throws Exception {
        mvc.perform(get("/api/v1/self")
                .header("X-Forwarded-Proto", "https")
                .header("X-Forwarded-Host", "learn.example.com")
                .header("X-Forwarded-Port", "443")
                .header("X-Forwarded-Prefix", "/java"))
            .andExpect(status().isOk())
            .andExpect(jsonPath("$.publicUrl").value(
                    "https://learn.example.com/java/api/v1/self"));
    }

    @Test
    void locationContainsPublicPrefixExactlyOnce() throws Exception {
        MvcResult result = mvc.perform(post("/api/v1/books")
                .header("X-Forwarded-Proto", "https")
                .header("X-Forwarded-Host", "learn.example.com")
                .header("X-Forwarded-Port", "443")
                .header("X-Forwarded-Prefix", "/java")
                .contentType(MediaType.APPLICATION_JSON)
                .content("{\"title\":\"Book\"}"))
            .andExpect(status().isCreated())
            .andReturn();

        String location = result.getResponse()
                .getHeader(HttpHeaders.LOCATION);
        assertNotNull(location);

        URI uri = URI.create(location);
        assertEquals("https", uri.getScheme());
        assertEquals("learn.example.com", uri.getHost());
        assertEquals(-1, uri.getPort());
        assertTrue(uri.getPath().matches(
                "/java/api/v1/books/[0-9]+"));
    }

    @Test
    void internalUriWithoutForwardedHeaders() throws Exception {
        mvc.perform(get("/api/v1/self")
                .with(request -> {
                    request.setScheme("http");
                    request.setServerName("localhost");
                    request.setServerPort(8080);
                    return request;
                }))
            .andExpect(status().isOk())
            .andExpect(jsonPath("$.publicUrl").value(
                    "http://localhost:8080/api/v1/self"));
    }

    @Test
    void invalidInputReturns400() throws Exception {
        mvc.perform(post("/api/v1/books")
                .contentType(MediaType.APPLICATION_JSON)
                .content("{\"title\":\" \"}"))
            .andExpect(status().isBadRequest());
    }
}
~~~

Run:

~~~bash
mvn test
~~~

MockMvc only tests how Spring processes metadata when **supplied with headers simulating a proxy**. It **does not verify that the header source is trusted**. Test in practice that Internet clients cannot reach the backend directly or spoof headers through the edge.

## 9. Links when there is no HTTP request

Some tasks do not run inside a Servlet request thread:

- Background jobs/scheduled tasks.
- Registration confirmation emails, password resets.
- Message queue consumers.
- Webhook callback registration.
- Sitemap/SEO canonical links.
- Static OAuth callback URLs.

You cannot rely on `ServletUriComponentsBuilder.fromCurrentContextPath()` when no request context exists. Use a **canonical public base URL** configuration:

~~~properties
app.public-base-url=https://learn.example.com/java
~~~

In a Spring bean, illustrative fragment:

~~~java
@Value("${app.public-base-url}")
private String publicBaseUrl;

URI uri = UriComponentsBuilder
        .fromUriString(publicBaseUrl)
        .path("/api/v1/books/{id}")
        .buildAndExpand(bookId)
        .toUri();
~~~

Requires imports `org.springframework.beans.factory.annotation.Value`, `org.springframework.web.util.UriComponentsBuilder`, and `java.net.URI`. `bookId` and `publicBaseUrl` follow a trusted contract. Check trailing slash/canonicalization of the property so it does not produce `/java//api`.

In multi-tenant SaaS, obtain the canonical host from validated/allowlisted tenant configuration, never reading raw `Host` or `X-Forwarded-Host` from an arbitrary request to build email reset links.

## 10. Implications for Spring Security and OAuth2

### 10.1. HTTP/HTTPS redirect loop

If the client calls HTTPS yet the Spring backend receives HTTP, a configuration requiring a secure channel may redirect continuously:

~~~text
Browser HTTPS -> Proxy HTTP -> App sees HTTP
App redirects to HTTPS -> Browser HTTPS -> Proxy HTTP -> ...
~~~

Fix trusted `X-Forwarded-Proto`/`Forwarded` proto and Spring's forwarding strategy, coordinated with ingress HTTPS redirects and Security transport policies. Do not disable TLS requirements just to stop the loop.

### 10.2. OAuth2 redirect_uri

The identity provider registers:

~~~text
https://learn.example.com/java/login/oauth2/code/provider
~~~

If Spring generates:

~~~text
http://backend:8080/login/oauth2/code/provider
~~~

a `redirect_uri_mismatch` usually occurs. Check trusted forwarded proto/host/prefix and provider registration, then test the actual browser login flow.

### 10.3. Cookies

Public HTTPS behind a proxy can affect `Secure`, `SameSite`, `HttpOnly`, and `Path` on cookies. If the public app is mounted at `/java`, cookie `Path` must be chosen intentionally rather than accidentally using a wrong upstream prefix. Do not solve this by disabling CSRF/cookie security.

## 11. Implications for API versioning and HATEOAS

An API may emit:

~~~json
{
  "id": 42,
  "_links": {
    "self": {
      "href": "https://learn.example.com/java/api/v1/books/42"
    }
  }
}
~~~

The correct HATEOAS link must match the `Location` of the same resource.

If the backend deployment moves from `backend-a:8080` to `backend-b:9090`, the public API stays the same; that is the purpose of a reverse proxy. However, if the public prefix changes from `/java` to `/learn`, old URLs in emails/SDKs/bookmarks may break even though `/api/v1` is still used. Consider alias/redirect migrations, deprecation docs, OpenAPI servers, and cache/CDN invalidation.

**Do not use `X-Forwarded-Prefix` to replace URI versioning**. Proxy routing and API version lifecycle are two independent decisions.

## 12. Debugging by symptom

| Symptom | Likely cause | How to resolve |
| --- | --- | --- |
| Location is still `http://...` | Trusted proto unhandled or misconfigured by proxy | Check `X-Forwarded-Proto` and strategy |
| Location has `backend:8080` | Forwarded host/port missing or ignored | Check proxy headers, native/framework |
| Public Location misses `/java` | Proxy strips prefix without sending `X-Forwarded-Prefix` | Add trusted prefix header, use framework |
| Location has `/java/java` | Both proxy and Servlet/app prepend prefix | Enforce a single owner for the prefix |
| Internal URL returns 200, public URL returns 404 | Wrong URI rewrite (`proxy_pass` slash) | Compare actual upstream request URI |
| Login redirect loop | App sees HTTP scheme despite public HTTPS | Fix proxy/TLS forwarding/Security |
| OAuth `redirect_uri` mismatch | Public callback has wrong scheme/host/prefix | Check IdP config and forwarding |
| Swagger UI calls `backend:8080` | OpenAPI servers using internal URL | Configure public server URI |
| Client changing `X-Forwarded-Host` alters Location | Broken trust boundary | Edge strips/overwrites headers, private backend |
| Cookie login fails | Cookie `Path`, `Secure`, or `SameSite` | Browser DevTools/proxy scheme |
| `X-Forwarded-For` shows spoofed IP | Proxy trusts client-supplied XFF | Trusted hop policy, overwrite at edge |
| Async/error redirects fail while GET works | Different dispatcher type/filter order | Check forwarding registration on ASYNC/ERROR |

### 12.1. Debugging methodology

1. Record the **exact public URL** in the browser.
2. Record the **URI the backend actually receives** after gateway rewrite.
3. Inspect the public scheme, host, port, and prefix attached by the trusted proxy.
4. Identify the Boot strategy and filter/container forwarding behavior.
5. Check whether controller mappings/context path already include the prefix.
6. Use `curl` to inspect **201 Location, 302/303 Location, and JSON self links**.
7. Test spoofed `Host`/`X-Forwarded-*` headers through the edge.
8. Verify TLS, OAuth, Security, cookie policies, and CORS/mixed content.
9. If a CDN/service mesh exists, designate one hop as canonical authority.
10. Re-test from the external staging URL rather than concluding from MockMvc alone.

## 13. Common mistakes

- Hardcoding `localhost:8080`, backend host, or port into JSON/`Location`.
- Building URLs by string concatenation from raw `Forwarded` headers.
- Enabling forwarded-header support while the backend's direct port remains public.
- Proxy failing to strip client-sent headers.
- Handling only `X-Forwarded-Proto` while omitting Host/Port/Prefix.
- Choosing `NATIVE` and assuming the container handles `X-Forwarded-Prefix` like `Framework`.
- Registering both `ForwardedHeaderFilter` and native handling redundantly.
- Setting `server.servlet.context-path=/java` when the proxy already strips and sends `X-Forwarded-Prefix`.
- Forgetting the trailing slash on Nginx `proxy_pass`, causing backend 404s.
- Putting the API version into `X-Forwarded-Prefix`, breaking the public contract.
- Generating absolute links in scheduled jobs without a Servlet request.
- Using the `Host` header as the source for password-reset links.
- Assuming `X-Forwarded-For` is authenticated.
- Checking only response bodies while ignoring `Location` and HATEOAS.
- Not testing 401/403/500, `ASYNC`/`ERROR` dispatches, and proxy-generated errors.
- Not checking Swagger/OAuth callbacks and cookie `Path`.
- Changing the public prefix without a client compatibility plan.

## 14. Deployment checklist

- [ ] Public origin and prefix are clearly defined per environment.
- [ ] Proxy path rewrites are documented accurately, not guessed.
- [ ] Private backend accepts traffic only from trusted upstreams.
- [ ] Edge strips all client-sent `Forwarded` and `X-Forwarded-*` before setting canonical headers.
- [ ] Public Host/domain is validated or fixed.
- [ ] Boot forwarding strategy is chosen explicitly with no double processing.
- [ ] Servlet context path, `X-Forwarded-Prefix`, and controller routes do not duplicate prefixes.
- [ ] 201 `Location` and 3xx redirects contain the exact HTTPS host/prefix.
- [ ] Self links, OpenAPI servers, and OAuth callbacks use the right public URL.
- [ ] Cookie `Secure`/`SameSite`/`Path` and Spring Security work under TLS termination.
- [ ] Clients cannot spoof forwarded host/proto/prefix through the public proxy.
- [ ] Email/webhook/job URLs use a trusted canonical base config.
- [ ] Integration tests through the real proxy cover errors, async, redirects, and health checks.
- [ ] API path version is independent of the proxy mount prefix; migration exists if public mount changes.

## 16. Takeaways

- Public URLs are **not the same** as internal upstream URLs when an application runs behind a proxy.
- Forwarded metadata conveys the original scheme/host/port/prefix; it is trustworthy only if the proxy acts as a trust boundary.
- Spring Boot offers `none`, `native`, and `framework`; for Servlet MVC needing path prefixes, `FRAMEWORK` is usually the clearest option.
- `X-Forwarded-Prefix` is not an API version and must not be concatenated multiple times.
- `ServletUriComponentsBuilder` uses the **already normalized** request; do not trust raw `X-Forwarded` headers manually.
- `Location`, redirects, self links, Swagger/OpenAPI, and OAuth2 callbacks must use the exact public address.
- When no HTTP request exists, use a trusted canonical `public-base-url`.
- Protect direct backend access, strip spoofed forwarded headers, and test both HTTP link correctness and security.
