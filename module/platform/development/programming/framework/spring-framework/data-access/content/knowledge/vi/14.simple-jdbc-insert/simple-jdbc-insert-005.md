# SimpleJdbcInsert: `executeAndReturnKey()` và `executeAndReturnKeyHolder()`

## 1. Bài toán: vừa INSERT vừa lấy giá trị do cơ sở dữ liệu sinh ra

Trong nhiều bảng, khóa chính không do ứng dụng gửi khi thêm bản ghi mà được database tạo tự động, chẳng hạn cột `id BIGINT GENERATED ... AS IDENTITY` hoặc `AUTO_INCREMENT`. Sau khi thêm một khách hàng, ứng dụng cần chính `id` của bản ghi vừa tạo để tạo quan hệ, trả response API hoặc ghi sự kiện nghiệp vụ.

`SimpleJdbcInsert` thuộc Spring JDBC giúp thực hiện `INSERT` mà không phải tự viết toàn bộ SQL và mã xử lý `PreparedStatement`. Nó sử dụng thông tin bảng qua JDBC metadata (hoặc cấu hình cột tường minh) để dựng câu lệnh. Hai phương thức trọng tâm là:

- **`executeAndReturnKey(...)`:** chèn **một** bản ghi và lấy **một khóa được sinh tự động thuộc kiểu số** qua kiểu trả về `Number`.
- **`executeAndReturnKeyHolder(...)`:** chèn **một** bản ghi và lấy đối tượng `KeyHolder`, cho phép truy cập cấu trúc các giá trị do database/driver trả về, kể cả trường hợp có nhiều cột hoặc giá trị không phải số.

Khái niệm "generated key" là giá trị database tạo/trả thông qua cơ chế JDBC generated keys. Nó **không tự động đồng nghĩa với mọi cột DEFAULT, mọi trigger-generated field hoặc toàn bộ bản ghi sau INSERT**. Những cột thực sự được trả về tùy database, driver và cấu hình `usingGeneratedKeyColumns(...)`.

Ví dụ nghiệp vụ:

~~~sql
CREATE TABLE customer (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    full_name VARCHAR(100) NOT NULL,
    email VARCHAR(160) NOT NULL
);
~~~

Khi thêm khách hàng, chỉ gửi `full_name` và `email`; cơ sở dữ liệu sinh `id`. Kết quả cần lấy là `id` của **đúng thao tác INSERT vừa thực hiện**, không phải `MAX(id)` trong bảng (sai khi có nhiều giao dịch đồng thời).

## 2. Điều kiện cấu hình và cơ chế

Một `SimpleJdbcInsert` thông dụng được tạo như sau:

~~~java
SimpleJdbcInsert insert = new SimpleJdbcInsert(dataSource)
        .withTableName("customer")
        .usingColumns("full_name", "email")
        .usingGeneratedKeyColumns("id");
~~~

Giải thích từng phần:

1. `new SimpleJdbcInsert(dataSource)`: dùng cùng `DataSource` của tầng persistence; Spring quản lý kết nối và chuyển các lỗi JDBC thành hệ `DataAccessException`.
2. `withTableName("customer")`: tên bảng đích. Nếu cần, có thể cấu hình `withSchemaName(...)` hoặc `withCatalogName(...)` để xác định chính xác bảng.
3. `usingColumns("full_name", "email")`: chỉ định **các cột nhận giá trị đầu vào** của INSERT. Không đưa `id` sinh tự động vào danh sách này.
4. `usingGeneratedKeyColumns("id")`: yêu cầu truy xuất khóa mà database sinh ở cột `id`. Đây là bước cần có khi dùng hai phương thức trả generated key.

Về mặt ý tưởng, Spring chuẩn bị SQL tương đương:

~~~sql
INSERT INTO customer (full_name, email) VALUES (?, ?);
~~~

Sau khi thực thi, Spring yêu cầu JDBC driver cung cấp generated keys (thường qua `Statement.getGeneratedKeys()`, hoặc đường xử lý phù hợp metadata của database), rồi trả `Number` hay `KeyHolder`. Ứng dụng không cần tự truy vấn `SELECT MAX(id)` hoặc tự suy đoán ID từ một sequence toàn cục.

**Lưu ý về metadata:** `usingColumns(...)` không phải luôn bắt buộc vì Spring có thể đọc cột bảng; tuy nhiên khai báo tường minh giúp tránh vô tình đưa cột không mong muốn vào INSERT khi schema thay đổi. Nếu dùng `withoutTableColumnMetaDataAccess()`, cần khai báo cột đầu vào và generated key phù hợp, đồng thời kiểm thử với driver thật. Mọi phương thức cấu hình nên được gọi **trước** khi đối tượng được compile/lần đầu dùng. Đối tượng đã cấu hình có thể dùng lại qua nhiều lời gọi.

## 3. Chữ ký phương thức và cách chọn

Những overload cần ghi nhớ của `SimpleJdbcInsert`:

~~~java
Number executeAndReturnKey(Map<String, ?> args);
Number executeAndReturnKey(SqlParameterSource parameterSource);

KeyHolder executeAndReturnKeyHolder(Map<String, ?> args);
KeyHolder executeAndReturnKeyHolder(SqlParameterSource parameterSource);
~~~

| Tiêu chí | `executeAndReturnKey(...)` | `executeAndReturnKeyHolder(...)` |
|---|---|---|
| Kiểu trả về | `java.lang.Number` | `org.springframework.jdbc.support.KeyHolder` |
| Phù hợp nhất | Một khóa sinh tự động có giá trị số, ví dụ ID identity | Cần xem tập khóa trả về, nhiều cột generated, hoặc khóa kiểu phi số |
| Truy cập kết quả | `Number.longValue()` / `intValue()` theo schema | `getKey()`, `getKeyAs(Class<T>)`, `getKeys()`, `getKeyList()` |
| Đầu vào | `Map<String, ?>` hoặc `SqlParameterSource` | `Map<String, ?>` hoặc `SqlParameterSource` |
| Số bản ghi mỗi lời gọi | Một INSERT | Một INSERT |
| Đảm bảo có khóa? | Phụ thuộc hỗ trợ của database/driver/cấu hình | Có `KeyHolder` để kiểm tra; bên trong có thể không có dữ liệu |

Cả hai có thể dùng `Map` nếu dữ liệu đang dạng cặp tên cột → giá trị, hoặc `SqlParameterSource` nếu muốn tận dụng `MapSqlParameterSource`, `BeanPropertySqlParameterSource` và khai báo SQL type. Tên tham số phải khớp tên cột đầu vào; `Map.of(...)` không cho khóa/giá trị null, nên khi cần truyền null hãy dùng `MapSqlParameterSource.addValue("column", null, Types.VARCHAR)` hoặc một `Map` cho phép null.

**Ranh giới quan trọng:** gọi `executeAndReturnKey(...)` rồi gọi tiếp `executeAndReturnKeyHolder(...)` trên cùng dữ liệu sẽ tạo **hai bản ghi khác nhau**, vì mỗi lời gọi thực thi một INSERT độc lập. Chọn một phương thức cho mỗi bản ghi cần thêm.

## 4. Ví dụ Java 17+ chạy độc lập: cả bốn overload

Ví dụ dùng Spring JDBC 6.2.12, H2 2.3.232, Maven và Java 17. Chương trình tạo database in-memory mới mỗi lần khởi động, chèn bốn khách hàng, minh họa mỗi overload một lần, rồi kiểm chứng dữ liệu.

├── pom.xml
└── src/main/java/demo/GeneratedKeysDemo.java
~~~

**`src/main/java/demo/GeneratedKeysDemo.java`**

~~~java
package demo;

import java.util.List;
import java.util.Map;
import java.util.Objects;

import org.h2.jdbcx.JdbcDataSource;
import org.springframework.jdbc.core.JdbcTemplate;
import org.springframework.jdbc.core.namedparam.MapSqlParameterSource;
import org.springframework.jdbc.core.namedparam.SqlParameterSource;
import org.springframework.jdbc.core.simple.SimpleJdbcInsert;
import org.springframework.jdbc.support.KeyHolder;

public class GeneratedKeysDemo {
    public static void main(String[] args) {
        JdbcDataSource dataSource = new JdbcDataSource();
        dataSource.setURL(
                "jdbc:h2:mem:generated_keys_demo;DB_CLOSE_DELAY=-1");
        dataSource.setUser("sa");

        JdbcTemplate jdbc = new JdbcTemplate(dataSource);
        jdbc.execute("""
                CREATE TABLE customer (
                    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
                    full_name VARCHAR(100) NOT NULL,
                    email VARCHAR(160) NOT NULL
                )
                """);

        SimpleJdbcInsert insert = new SimpleJdbcInsert(dataSource)
                .withTableName("customer")
                .usingColumns("full_name", "email")
                .usingGeneratedKeyColumns("id");

        // 1) executeAndReturnKey(Map): trả một Number.
        Number keyFromMap = Objects.requireNonNull(
                insert.executeAndReturnKey(Map.of(
                        "full_name", "An",
                        "email", "an@example.test")),
                "Database did not return the generated key");
        System.out.println("KEY_MAP=" + keyFromMap.longValue());

        // 2) executeAndReturnKey(SqlParameterSource).
        SqlParameterSource binh = new MapSqlParameterSource()
                .addValue("full_name", "Binh")
                .addValue("email", "binh@example.test");
        Number keyFromSource = Objects.requireNonNull(
                insert.executeAndReturnKey(binh),
                "Database did not return the generated key");
        System.out.println("KEY_SOURCE=" + keyFromSource.longValue());

        // 3) executeAndReturnKeyHolder(Map): KeyHolder.
        KeyHolder holderFromMap = insert.executeAndReturnKeyHolder(
                Map.of("full_name", "Chi",
                       "email", "chi@example.test"));
        Number keyFromHolderMap = Objects.requireNonNull(
                holderFromMap.getKey(), "KeyHolder contains no single key");
        System.out.println("HOLDER_MAP=" + keyFromHolderMap.longValue());

        // 4) executeAndReturnKeyHolder(SqlParameterSource).
        SqlParameterSource dung = new MapSqlParameterSource()
                .addValue("full_name", "Dung")
                .addValue("email", "dung@example.test");
        KeyHolder holderFromSource =
                insert.executeAndReturnKeyHolder(dung);

        Number keyFromHolderSource = Objects.requireNonNull(
                holderFromSource.getKey(), "KeyHolder contains no single key");
        Map<String, Object> keyColumns = Objects.requireNonNull(
                holderFromSource.getKeys(), "No generated-key row");

        System.out.println(
                "HOLDER_SOURCE=" + keyFromHolderSource.longValue());
        System.out.println(
                "HOLDER_ROWS=" + holderFromSource.getKeyList().size());
        System.out.println("HOLDER_FIELDS=" + keyColumns.size());

        List<String> names = jdbc.queryForList(
                "SELECT full_name FROM customer ORDER BY id", String.class);
        System.out.println("NAMES=" + names);
    }
}
~~~

**Chạy tại thư mục chứa `pom.xml`:**

~~~bash
mvn -q compile exec:java "-Dexec.mainClass=demo.GeneratedKeysDemo"
~~~

**Đầu ra chương trình trên H2 in-memory mới:**

~~~text
KEY_MAP=1
KEY_SOURCE=2
HOLDER_MAP=3
HOLDER_SOURCE=4
HOLDER_ROWS=1
HOLDER_FIELDS=1
NAMES=[An, Binh, Chi, Dung]
~~~

Giải thích: H2 tạo identity bắt đầu từ 1 trong bảng mới. Mỗi lời gọi thêm một hàng; cả bốn ID đều được đọc từ kết quả INSERT tương ứng. Với `usingGeneratedKeyColumns("id")`, H2 trả về một cột generated key cho mỗi lần INSERT, nên `getKeyList()` của lời gọi cuối chứa một map gồm một cột. Các tên key (ví dụ `ID` hay `id`) và đôi khi kiểu số cụ thể **không có quy tắc duy nhất giữa các driver**, nên ví dụ chỉ in số lượng trường chứ không hard-code cách viết tên cột.

Trong code, `Objects.requireNonNull(...)` giúp phát hiện sớm trường hợp driver không trả khóa. Nếu driver trả nhiều key cho một hàng, `holder.getKey()` không phải API phù hợp; phải dùng `getKeys()` như phần tiếp theo.

## 5. Đọc `KeyHolder` đúng cách

`KeyHolder` mô hình hóa kết quả generated key theo cấu trúc **`List<Map<String, Object>>`**: mỗi phần tử của list là một tập cột được trả về cho một hàng.

| Phương thức | Đặc điểm cần nhớ |
|---|---|
| `holder.getKey()` | Đọc một giá trị **số** khi kết quả chỉ có **một hàng khóa và một cột khóa**; trả `Number` có thể null nếu không có key; ném `InvalidDataAccessApiUsageException` nếu có nhiều giá trị |
| `holder.getKeyAs(MyType.class)` | Tương tự `getKey()` nhưng yêu cầu giá trị đúng kiểu `MyType` (ví dụ `UUID.class` nếu driver thực sự trả `UUID`); không thực hiện chuyển đổi chuỗi thành kiểu đó |
| `holder.getKeys()` | Trả `Map<String, Object>` chứa các cột khóa của **một hàng**; cho phép nhiều cột trong map; có thể null nếu trống, và lỗi nếu list có nhiều hàng |
| `holder.getKeyList()` | Trả `List<Map<String, Object>>` để xem tất cả các hàng khóa do driver trả; bình thường một lời gọi `SimpleJdbcInsert` cho một hàng |

Nếu database có hai trường do nó sinh, ví dụ `id` và `public_token`, và driver có khả năng trả về cả hai khi cấu hình `usingGeneratedKeyColumns("id", "public_token")`, nên truy cập map:

~~~java
// Minh họa: "holder" đến từ executeAndReturnKeyHolder(...).
Map<String, Object> generated = holder.getKeys();
if (generated == null || generated.isEmpty()) {
    throw new IllegalStateException("Driver did not return generated keys");
}

for (Map.Entry<String, Object> item : generated.entrySet()) {
    System.out.println(item.getKey() + " = " + item.getValue());
}
~~~

Đây là **đoạn minh họa đặt trong ngữ cảnh đã có biến `holder`**, không phải một chương trình Java độc lập. Không giả định key của map luôn viết hoa/thường theo một kiểu, không giả định thứ tự duyệt map là thứ tự cột, và không suy ra rằng driver chắc chắn trả mọi cột được đặt DEFAULT hoặc đi qua trigger. Cần kiểm chứng metadata và kết quả thật trên từng hệ DB.

**Các trường hợp dễ nhầm:**

- Nếu `getKeys()` có nhiều phần tử (nhiều cột), `getKey()` sẽ báo lỗi dù có thể có một cột `id` đúng ý; nên lấy đúng entry từ map sau khi xác định tên cột.
- Nếu `getKeyList()` có nhiều map (nhiều hàng), `getKeys()` có thể ném `InvalidDataAccessApiUsageException` vì nó chỉ phục vụ một hàng. Trường hợp nhiều hàng không phải hành vi mặc định của một lời gọi `SimpleJdbcInsert.executeAndReturnKeyHolder(...)` thông thường.
- Với khóa không phải số như UUID, ưu tiên `getKeyAs(UUID.class)` **chỉ nếu** driver trả đối tượng `UUID` đúng kiểu; nếu không, đọc `getKeys()` rồi chuyển đổi bằng logic phù hợp với kiểu dữ liệu thực tế.
- `getKeyAs(Long.class)` không tự chuyển `BigDecimal` hay `BigInteger` thành `Long`; với ID số thông thường, đọc `Number` rồi chuyển theo schema sau khi kiểm tra giới hạn giá trị.

## 6. Ứng dụng trong DAO/service và transaction

Trong ứng dụng Spring, nên cấu hình `SimpleJdbcInsert` một lần ở tầng repository/DAO (constructor hoặc khởi tạo bean), rồi tái sử dụng:

~~~java
// Đoạn minh họa trong lớp CustomerRepository; đã inject DataSource.
private final SimpleJdbcInsert insertCustomer;

public CustomerRepository(DataSource dataSource) {
    this.insertCustomer = new SimpleJdbcInsert(dataSource)
            .withTableName("customer")
            .usingColumns("full_name", "email")
            .usingGeneratedKeyColumns("id");
}

public long create(String name, String email) {
    Number key = insertCustomer.executeAndReturnKey(
            new MapSqlParameterSource()
                    .addValue("full_name", name)
                    .addValue("email", email));
    if (key == null) {
        throw new IllegalStateException(
                "Insert succeeded without a generated id");
    }
    return key.longValue();
}
~~~

Đây là **các thành phần của một lớp** cần đặt trong class đầy đủ cùng các import liên quan, không phải một file có thể chạy riêng. Gọi service:

~~~java
// Đoạn minh họa trong một Spring-managed service.
@Transactional
public long registerCustomer(String name, String email) {
    long newId = customerRepository.create(name, email);
    auditRepository.writeRegistration(newId);
    return newId;
}
~~~

`@Transactional` cần transaction manager cấu hình đúng và lời gọi đi qua Spring proxy; annotation trên method tự gọi nội bộ cùng object thường không kích hoạt transaction proxy. Transaction đảm bảo phạm vi thay đổi dữ liệu theo cấu hình rollback; **ID được sinh có thể không được tái sử dụng sau rollback**, vì sequence/identity không nhất thiết tuân rollback. Trả về ID không chứng minh giao dịch cuối cùng đã commit.

Khóa trả về là kết quả của chính INSERT vừa chạy qua JDBC, giúp xây dựng quan hệ chính xác ngay cả khi nhiều request cùng tạo bản ghi. Tránh dùng `SELECT MAX(id)` hoặc giả định rằng một lần `execute(...)` chỉ trả số hàng ảnh hưởng có thể thay cho generated key.

## 7. Khi nào không nên dùng hoặc cần kiểm tra thêm?

**Khóa do ứng dụng tự tạo:** nếu trước khi insert ứng dụng đã phát sinh UUID/ULID và truyền thẳng vào bảng, có thể dùng `execute(...)` (lấy số hàng ảnh hưởng), không cần nhất thiết dùng generated key. Hai phương thức trong bài dành cho giá trị cần được database/driver trả về.

**Nhiều cột generated:** `executeAndReturnKeyHolder(...)` là lựa chọn phù hợp về cấu trúc dữ liệu, nhưng không bảo đảm driver trả lại mọi cột. Có DB chỉ trả identity; có DB hỗ trợ `RETURNING` hoặc có khác biệt về cách truy xuất. Hãy thử integration test trên **cơ sở dữ liệu đang dùng trong production** và đối chiếu danh sách cột trả về.

**Tên bảng/cột và quyền DB:** cấu hình tên bảng/cột phải khớp schema thực tế. Tên định danh không phải giá trị bind qua `?`, vì vậy không đưa trực tiếp chuỗi bảng/cột từ đầu vào không tin cậy vào cấu hình. Với định danh có chữ hoa/thường nhạy cảm hay từ khóa trùng, cân nhắc `usingQuotedIdentifiers()` và đảm bảo chính xác cách viết identifier.

**Null và kiểu dữ liệu:** khi có giá trị null, `MapSqlParameterSource.addValue("email", null, Types.VARCHAR)` truyền metadata kiểu rõ ràng; đồng thời DB có thể từ chối nếu cột `NOT NULL`. Lỗi nhập liệu hoặc vi phạm constraint là lỗi INSERT, không phải bằng chứng rằng generated keys không hoạt động.

**Batch insert:** `SimpleJdbcInsert.executeBatch(...)` trả số hàng bị ảnh hưởng (`int[]`), **không trả `KeyHolder` cho từng phần tử** qua hai API đang xét. Không giả định gọi batch sẽ cho một danh sách ID tương ứng. Khi phải lấy ID cho nhiều bản ghi, cần chọn API/thiết kế được driver hỗ trợ và kiểm chứng thứ tự, transaction, hiệu năng.

**Hiệu năng:** truy xuất generated keys có thể gây thêm xử lý tại driver/DB. Tối ưu sau khi đo trên hệ thật; khả năng lấy khóa do driver cung cấp quan trọng hơn việc suy diễn hiệu năng từ ví dụ H2.

| Triệu chứng | Nguyên nhân khả dĩ | Hướng kiểm tra |
|---|---|---|
| Không nhận được key / nhận null | Quên `usingGeneratedKeyColumns(...)`, bảng không sinh key, driver không hỗ trợ hoặc trả rỗng | Xem DDL identity/default, cấu hình cột, JDBC driver, và kết quả `KeyHolder.getKeyList()` |
| `InvalidDataAccessApiUsageException` khi gọi `getKey()` | KeyHolder có nhiều cột/hàng hoặc cấu hình trả nhiều khóa | Dùng `getKeys()` (một hàng) hay `getKeyList()` (nhiều hàng), chọn key theo tên |
| Lỗi kiểu khi lấy UUID/string | Dùng `executeAndReturnKey()` hoặc `getKey()` vốn cần giá trị `Number` | Dùng `executeAndReturnKeyHolder()` và `getKeyAs(...)` khi đúng kiểu, hoặc xử lý từ `getKeys()` |
| Map thiếu tham số hoặc INSERT báo cột null | Thiếu `full_name`/`email`, tên cột sai, `usingColumns` không khớp | In và kiểm tra metadata cấu hình, input và constraint của bảng |
| ID không liên tiếp dù insert/rollback | Identity/sequence đã cấp số, transaction rollback hoặc có transaction khác | Coi ID là mã định danh duy nhất, không đặt yêu cầu liên tiếp |
| Cùng dữ liệu xuất hiện hai lần | Đã gọi cả hai phương thức cho cùng đầu vào | Mỗi phương thức đều thực thi INSERT; chỉ chọn một |
| Chạy được trên H2 nhưng sai trên DB thật | Khác biệt schema, kiểu generated key, hỗ trợ `getGeneratedKeys` | Viết integration test bằng driver/DB production |
| Nhầm `getKeys()` trả toàn bộ record | JDBC chỉ trả các cột generated mà driver cung cấp | Dùng `SELECT ... WHERE id = ?` khi cần dữ liệu bản ghi sau insert |

Spring JDBC biến `SQLException` thành hệ `DataAccessException`; ứng dụng phải xử lý lỗi duplicate key, vi phạm constraint, kết nối hoặc thiếu quyền như các thao tác DB khác. Với quy trình nhiều bảng, đặt ranh giới transaction thích hợp để đảm bảo dữ liệu liên quan được commit/rollback nhất quán.

## 9. Checklist và bài tự luyện

**Checklist khi thêm bản ghi và lấy ID:**

1. Bảng thật có cơ chế sinh khóa và driver hỗ trợ đọc generated key.
2. `withTableName`, `usingColumns` và `usingGeneratedKeyColumns` khớp schema; input không tự truyền cột identity.
3. Nghiệp vụ chỉ cần **một khóa số** hay cần **một tập generated values**? Chọn đúng phương thức.
4. Với `Number`/`KeyHolder`, kiểm tra null hoặc số khóa trước khi chuyển kiểu; dùng kiểu dữ liệu phù hợp với schema.
5. Xác định phạm vi transaction và kiểm thử insert lỗi, rollback, null input, concurrency.
6. Dùng integration test với DB và JDBC driver thật để xác nhận cột trả về, kiểu giá trị và chữ hoa/thường.

**Tự luyện tập:**

1. Bỏ `usingGeneratedKeyColumns("id")` trong ví dụ H2; quan sát lỗi/thay đổi hành vi và giải thích yêu cầu cấu hình.
2. Viết lại phần chèn `Chi` để đọc generated key bằng `holder.getKeys()`; quan sát map cột khóa do H2 trả về.
3. Tạo bảng có khóa `UUID` do database sinh (tùy hệ DB), thử `getKeyAs(UUID.class)` và `getKeys()`; nêu rõ kiểu mà driver thực sự trả.
4. Đưa việc tạo customer và ghi audit vào cùng transaction; cố ý gây lỗi ở audit để kiểm chứng rollback dù identity value đã được cấp.
5. Thử thêm hai khách hàng đồng thời; lý giải tại sao không thể dùng `SELECT MAX(id)` thay cho key trả về của từng INSERT.
