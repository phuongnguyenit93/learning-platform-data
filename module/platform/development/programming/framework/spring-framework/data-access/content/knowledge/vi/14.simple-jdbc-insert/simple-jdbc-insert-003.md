# SimpleJdbcInsert: Dùng metadata cơ sở dữ liệu và khi cần khai báo tường minh

## 1. Mục tiêu của bài học

Trong Spring JDBC, `SimpleJdbcInsert` giúp thực hiện thao tác `INSERT` mà không phải tự viết câu SQL và tự quản lý `PreparedStatement` cho các ca đơn giản. Một quyết định quan trọng khi cấu hình nó là: **để Spring suy ra các cột từ metadata của cơ sở dữ liệu**, hay **khai báo rõ các cột mà ứng dụng muốn chèn**.

Sau bài này, bạn cần:
- Hiểu metadata đến từ JDBC driver và được `SimpleJdbcInsert` sử dụng để xây dựng SQL như thế nào.
- Phân biệt ba cách cấu hình: tự dò cột, chỉ định `usingColumns(...)`, và tắt dò metadata cột bằng `withoutTableColumnMetaDataAccess()`.
- Biết khi nào nên khai báo `usingGeneratedKeyColumns(...)`, `withSchemaName(...)`, `withCatalogName(...)`.
- Tránh lỗi phổ biến với cột `DEFAULT`, cột không có trong input, schema trùng tên, định danh có chữ hoa/chữ thường và driver trả metadata thiếu chính xác.
- Chọn cách cấu hình phù hợp, có thể kiểm chứng bằng code Java 17+ và integration test.

**Phạm vi:** bài này tập trung vào **nguồn thông tin cột và cách cấu hình câu INSERT của `SimpleJdbcInsert`**. Việc lấy generated key, transaction và batch insert chỉ được đề cập ở mức liên quan đến lựa chọn metadata/cột.

## 2. Metadata là gì, và SimpleJdbcInsert dùng nó ra sao?

*Database metadata* là thông tin mô tả cấu trúc và khả năng của cơ sở dữ liệu mà JDBC driver trả qua các API như `Connection.getMetaData()` và `DatabaseMetaData`. Để nhận diện cột của một bảng, Spring có thể tra cứu thông tin tương ứng với `DatabaseMetaData.getColumns(...)`: tên cột, SQL type, table/schema/catalog và các thông tin hỗ trợ liên quan.

Cấu hình tối thiểu cho bảng có các ID **được ứng dụng truyền vào**:

```java
SimpleJdbcInsert insert = new SimpleJdbcInsert(dataSource)
        .withTableName("customer");

int affected = insert.execute(Map.of(
        "id", 10L,
        "full_name", "Lan"
));
```

Đây là **đoạn code minh họa** đặt bên trong lớp/phương thức có biến `dataSource` kiểu `javax.sql.DataSource`. `Map` chứa tên cột và giá trị; `execute(...)` trả số dòng bị tác động, không trả ID.

Quy trình khái quát:

```text
DataSource / JDBC Connection
        │
        ▼
SimpleJdbcInsert được cấu hình (bảng, schema, cột, generated key)
        │
        ▼
Lúc compile, Spring đọc metadata cột nếu tính năng này đang bật
        │
        ▼
Tạo/cố định câu INSERT và danh sách tham số theo thứ tự cột
        │
        ▼
execute(Map hoặc SqlParameterSource) → bind tham số → JDBC INSERT
```

`SimpleJdbcInsert` thực hiện bước *compile* ngầm khi cần chạy lần đầu; bạn cũng có thể gọi `compile()` sau khi cấu hình để phát hiện một số lỗi sớm. SQL đã được thiết lập tại thời điểm compile và được tái sử dụng cho những lần thực thi tiếp theo. **Không xem metadata là cơ chế tự động phát hiện thay đổi schema ở mọi lần gọi `execute`.**

Một số điểm dễ hiểu sai:
- Metadata **không lấy giá trị dữ liệu** từ bảng; nó cho biết tên/kiểu/cấu trúc cột để Spring sinh câu lệnh.
- `SimpleJdbcInsert` **không kiểm tra tự động rằng mọi giá trị trong Map đều hợp lệ theo ràng buộc nghiệp vụ**. Ràng buộc `NOT NULL`, `UNIQUE`, foreign key... vẫn do database thực thi.
- Cột tồn tại trong database chưa chắc nên được ghi trong mọi tình huống. Nhiều cột cần dùng `DEFAULT` của DB hoặc được trigger/ứng dụng khác quản lý.
- `SimpleJdbcInsert` là đối tượng có thể tái sử dụng cho nhiều lần insert; nên tạo và cấu hình ở tầng repository khi khởi tạo, thay vì tạo mới trong vòng lặp ghi dữ liệu.

## 3. Ba chế độ cấu hình cần phân biệt

Giả sử có bảng:

```sql
CREATE TABLE catalog_item (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    sku VARCHAR(30) NOT NULL UNIQUE,
    name VARCHAR(100) NOT NULL
);
```

Ứng dụng muốn chèn `sku` và `name`; cột `id` được DB sinh.

### Chế độ A — Tự dò cột nhờ metadata (mặc định)

```java
SimpleJdbcInsert auto = new SimpleJdbcInsert(dataSource)
        .withTableName("catalog_item")
        .usingGeneratedKeyColumns("id");

Number id = auto.executeAndReturnKey(Map.of(
        "sku", "AUTO-001",
        "name", "Sổ tay"
));
```

`withTableName(...)` xác định bảng. Không khai báo `usingColumns(...)` nên Spring dựa vào metadata của bảng để xây dựng danh sách cột insert, loại trừ cột được khai báo là generated key. `usingGeneratedKeyColumns("id")` thông báo cột cần lấy lại sau khi DB sinh; **nó không thay thế `usingColumns(...)`** và **không có tác dụng tự tạo cột identity trong database**.

Với schema này, SQL về mặt logic tương đương:

```sql
INSERT INTO catalog_item (sku, name) VALUES (?, ?);
```

Thứ tự hiển thị và cách quote identifier trong SQL thực tế có thể khác tùy driver/dialect. Giá trị được bind như các tham số JDBC, không ghép trực tiếp vào chuỗi SQL.

**Phù hợp khi:** bảng đơn giản, metadata do driver cung cấp đầy đủ, các cột không được DB sinh thực sự đều có giá trị đầu vào, và việc ứng dụng phụ thuộc vào danh sách cột metadata là chấp nhận được.

### Chế độ B — Chỉ định cột ghi bằng usingColumns, vẫn có thể dùng metadata

```java
SimpleJdbcInsert explicitColumns = new SimpleJdbcInsert(dataSource)
        .withTableName("catalog_item")
        .usingColumns("sku", "name")
        .usingGeneratedKeyColumns("id");

Number id = explicitColumns.executeAndReturnKey(Map.of(
        "sku", "EXPLICIT-001",
        "name", "Bút mực"
));
```

`usingColumns("sku", "name")` là **danh sách cho phép các cột xuất hiện trong `INSERT`**. Nó chủ động loại các cột khác khỏi SQL, kể cả khi bảng có thêm cột mới. Spring vẫn có thể sử dụng metadata để tìm hiểu kiểu SQL và khả năng của driver, bởi vì ta **chưa tắt** tính năng đọc metadata cột.

Đây là lựa chọn thực dụng cho nhiều DAO: code tuyên bố rõ ý định ghi, giữ sự thuận tiện của Spring JDBC, và không vô tình đưa các cột DB-managed vào câu lệnh.

**Phù hợp khi:** chỉ muốn ghi một tập con cột, có `DEFAULT`/trigger, muốn kiểm soát tác động của schema migration, hoặc cần kiểm tra rõ hợp đồng ghi dữ liệu của repository.

### Chế độ C — Tắt dò metadata cột, tự khai báo toàn bộ cột insert

```java
SimpleJdbcInsert noColumnMetadata = new SimpleJdbcInsert(dataSource)
        .withTableName("catalog_item")
        .withoutTableColumnMetaDataAccess()
        .usingColumns("sku", "name")
        .usingGeneratedKeyColumns("id");

Number id = noColumnMetadata.executeAndReturnKey(Map.of(
        "sku", "NO-META-001",
        "name", "Thước kẻ"
));
```

`withoutTableColumnMetaDataAccess()` tắt bước xử lý **metadata về các cột của bảng**. Vì không thể nhờ Spring tự xác định cột, bạn phải cung cấp danh sách `usingColumns(...)` phù hợp và tự chịu trách nhiệm giữ danh sách đó khớp với schema.

**Phân biệt chính xác:** tắt *table-column metadata* không có nghĩa là Spring không bao giờ gọi bất kỳ phương thức `DatabaseMetaData` nào; các tính năng khác, như kiểm tra khả năng hỗ trợ generated key hay quote identifiers, vẫn có thể cần thông tin từ driver.

**Phù hợp khi:** JDBC driver cung cấp metadata cột không đủ hoặc sai, bảng/view/synonym khiến việc dò cột không đáng tin, môi trường hạn chế quyền đọc metadata, hoặc bạn muốn một hợp đồng cột do code kiểm soát chặt.

### Bảng so sánh nhanh

| Tiêu chí | A. Metadata tự dò | B. usingColumns | C. Tắt metadata cột + usingColumns |
| --- | --- | --- | --- |
| Spring tự tìm danh sách cột từ bảng | Có | Không cần để xác định danh sách cột insert | Không |
| Danh sách cột `INSERT` do code chọn rõ | Không | Có | Có |
| Metadata cột JDBC còn được xử lý | Có | Có (mặc định) | Không |
| Phù hợp với cột `DEFAULT` không truyền giá trị | Dễ có vấn đề nếu cột vẫn vào SQL | Tốt, nếu loại cột khỏi usingColumns | Tốt, nếu loại cột khỏi usingColumns |
| Phụ thuộc chất lượng metadata tên/kiểu cột | Cao | Trung bình | Thấp hơn |
| Cần cập nhật code nếu đổi cột bắt buộc phải ghi | Tùy cách metadata nhận biết schema | Có | Có |

**Ghi nhớ:** `usingColumns(...)` và `withoutTableColumnMetaDataAccess()` là **hai công tắc khác nhau**: công tắc thứ nhất chọn **cột ghi**, công tắc thứ hai chọn **có dùng metadata cột để hỗ trợ xử lý hay không**. Bạn có thể dùng `usingColumns(...)` mà không cần tắt metadata; đó thường là điểm khởi đầu tốt.

## 4. Bẫy quan trọng: cột DEFAULT và giá trị không có trong Map

Giả sử bảng phát triển thêm một cột:

```sql
CREATE TABLE audited_item (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    description VARCHAR(100) NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP NOT NULL
);
```

Ứng dụng chỉ cung cấp `description`. Nếu cho `SimpleJdbcInsert` tự dò mọi cột qua metadata mà không khai báo tập cột ghi, nó **có thể tạo INSERT bao gồm cả `created_at` và bind `NULL` cho giá trị không có trong Map**. Database sẽ không áp dụng `DEFAULT CURRENT_TIMESTAMP` như khi cột thực sự bị bỏ khỏi danh sách INSERT; kết quả có thể là lỗi `NOT NULL` hoặc dữ liệu không như mong đợi.

Ví dụ SQL để thấy sự khác nhau:

```sql
-- Cột được bỏ hẳn khỏi INSERT: database áp dụng DEFAULT.
INSERT INTO audited_item (description) VALUES ('Đã tạo');

-- Có truyền NULL cho cột: không đồng nghĩa yêu cầu DEFAULT.
INSERT INTO audited_item (description, created_at)
VALUES ('Đã tạo', NULL);
```

Với schema ở trên, câu thứ hai vi phạm `NOT NULL` trong H2. Cách chủ động tránh rủi ro là:

```java
SimpleJdbcInsert insertAudit = new SimpleJdbcInsert(dataSource)
        .withTableName("audited_item")
        .usingColumns("description")
        .usingGeneratedKeyColumns("id");

insertAudit.executeAndReturnKey(
        Map.of("description", "Đã tạo")
);
```

Sau khi chèn, `created_at` nhận timestamp từ DB vì nó **không xuất hiện trong câu INSERT**.

**Không nhầm lẫn ba trạng thái:** (1) cột không nằm trong `usingColumns` → không có trong SQL; (2) cột có trong danh sách ghi, giá trị ở input là `null` → có thể bind SQL `NULL`; (3) giá trị không tồn tại trong Map nhưng metadata mode vẫn chọn cột → Spring có thể bind `NULL`. Chúng không cùng ý nghĩa, nhất là với `DEFAULT` hoặc cột bắt buộc.

Schema migration cũng có hệ quả: nếu thêm cột `created_at` có `DEFAULT`, đối tượng đã compile có thể tiếp tục dùng SQL đã thiết lập, còn một đối tượng mới compile với metadata mới có thể đưa thêm cột vào danh sách. Vì vậy cần integration test hành vi insert sau migration và nên chọn rõ `usingColumns` nếu bảng có cột do DB quản lý.

## 5. Ví dụ đầy đủ chạy trên Java 17+ (Spring Boot, H2)

Bài mẫu dưới đây tạo hai bảng; thực hiện cả ba chế độ với cùng bảng `catalog_item`, rồi chứng minh cột có `DEFAULT` hoạt động khi được loại khỏi danh sách insert.

Cần JDK 17+, Maven và kết nối Maven Central để tải dependency nếu môi trường chưa cache.

```text
        └── schema.sql
```

**`src/main/java/com/example/insertmeta/InsertMetadataApplication.java`**:

```java
package com.example.insertmeta;

import java.util.Map;
import javax.sql.DataSource;

import org.springframework.boot.CommandLineRunner;
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.context.annotation.Bean;
import org.springframework.jdbc.core.JdbcTemplate;
import org.springframework.jdbc.core.simple.SimpleJdbcInsert;

@SpringBootApplication
public class InsertMetadataApplication {

    public static void main(String[] args) {
        SpringApplication.run(InsertMetadataApplication.class, args);
    }

    @Bean
    CommandLineRunner demo(DataSource dataSource, JdbcTemplate jdbc) {
        return args -> {
            // A: metadata tự dò cột; id được database sinh.
            SimpleJdbcInsert auto = new SimpleJdbcInsert(dataSource)
                    .withTableName("catalog_item")
                    .usingGeneratedKeyColumns("id");

            // B: chỉ hai cột này được đưa vào INSERT; metadata vẫn bật.
            SimpleJdbcInsert explicit = new SimpleJdbcInsert(dataSource)
                    .withTableName("catalog_item")
                    .usingColumns("sku", "name")
                    .usingGeneratedKeyColumns("id");

            // C: không dò metadata cột, buộc chỉ định cột bằng code.
            SimpleJdbcInsert noColumnMeta = new SimpleJdbcInsert(dataSource)
                    .withTableName("catalog_item")
                    .withoutTableColumnMetaDataAccess()
                    .usingColumns("sku", "name")
                    .usingGeneratedKeyColumns("id");

            Number autoId = auto.executeAndReturnKey(
                    Map.of("sku", "AUTO-001", "name", "Sổ tay"));
            Number explicitId = explicit.executeAndReturnKey(
                    Map.of("sku", "EXPLICIT-001", "name", "Bút"));
            Number noMetaId = noColumnMeta.executeAndReturnKey(
                    Map.of("sku", "NO-META-001", "name", "Thước"));

            // Chỉ ghi description, để created_at nhận DEFAULT từ DB.
            SimpleJdbcInsert audit = new SimpleJdbcInsert(dataSource)
                    .withTableName("audited_item")
                    .usingColumns("description")
                    .usingGeneratedKeyColumns("id");
            audit.executeAndReturnKey(
                    Map.of("description", "Đã tạo"));

            int total = jdbc.queryForObject(
                    "SELECT COUNT(*) FROM catalog_item", Integer.class);
            int timestamps = jdbc.queryForObject(
                    "SELECT COUNT(*) FROM audited_item "
                            + "WHERE created_at IS NOT NULL", Integer.class);

            System.out.println("Catalog rows: " + total);
            System.out.println("Generated IDs returned: "
                    + (autoId.longValue() > 0
                    && explicitId.longValue() > 0
                    && noMetaId.longValue() > 0));
            System.out.println("Default timestamp applied: "
                    + (timestamps == 1));
        };
    }
}
```

Từ thư mục `simplejdbc-metadata-demo`:

```bash
mvn -q spring-boot:run
```

**Ba dòng do chương trình in ra** khi chạy với database H2 mới:

```text
Catalog rows: 3
Generated IDs returned: true
Default timestamp applied: true
```

Các log khác (nếu có) phụ thuộc môi trường chạy. Ví dụ dùng ba SKU khác nhau và database trong bộ nhớ được khởi tạo mới để có kết quả xác định; **không giả định ID tự sinh phải là 1, 2, 3 hoặc liên tiếp**. Ở chế độ A, bảng `catalog_item` không có cột default bổ sung, nên việc tự dò cột là an toàn trong phạm vi bài mẫu. Ở bảng `audited_item`, `usingColumns("description")` bảo đảm không ghi đè default của `created_at` bằng `NULL`.

### Chỗ nào trong chương trình quyết định dùng metadata?

- `auto` không có `usingColumns` nên Spring dùng các tên cột đọc được trong metadata, rồi loại trừ `id` vì `usingGeneratedKeyColumns`.
- `explicit` chọn chính xác `sku` và `name` cho SQL insert; metadata cột vẫn bật.
- `noColumnMeta` chọn chính xác `sku` và `name` **và** bỏ quá trình dò metadata cột. Đây là ví dụ minh họa chế độ khai báo đầy đủ.
- `audit` cho thấy lợi ích của whitelist cột: khi SQL không nêu `created_at`, database tự áp dụng `DEFAULT CURRENT_TIMESTAMP`.

Nếu chỉ cần số dòng được thêm, có thể gọi `execute(Map)` thay cho `executeAndReturnKey(Map)`; trường hợp lấy ID số, cần khai báo `usingGeneratedKeyColumns("id")` và dùng overload trả `Number`. Cả hai cách lấy khóa đều còn phụ thuộc driver/DB.

## 6. Khi nào khai báo tường minh schema, catalog, quoted identifier?

### Bảng trùng tên giữa nhiều schema

Nếu kết nối có nhiều schema chứa bảng cùng tên, gọi `withTableName("catalog_item")` có thể không xác định đúng bảng mong muốn, hoặc metadata không tìm được bảng theo search path/default schema.

Cấu hình tường minh:

```java
SimpleJdbcInsert insert = new SimpleJdbcInsert(dataSource)
        .withSchemaName("inventory")
        .withTableName("catalog_item")
        .usingColumns("sku", "name")
        .usingGeneratedKeyColumns("id");
```

Đây là **đoạn cấu hình minh họa**: schema `inventory` chỉ có nếu bạn đã tạo schema đó; không dùng nguyên tên này trong dự án mẫu H2 ở trên. `withCatalogName(...)` cũng có sẵn khi hệ CSDL/JDBC driver phân biệt catalog. Chọn đúng database/schema thực tế, không đoán do tên giống nhau.

### Quoted identifiers và quy tắc chữ hoa/chữ thường

Một số hệ CSDL biến đổi case của tên không quote; tên được quote thì có thể phân biệt case. Với Spring Framework 6.1+, `usingQuotedIdentifiers()` yêu cầu Spring quote table, schema và column identifiers trong SQL được tạo theo quy tắc database.

```java
SimpleJdbcInsert insert = new SimpleJdbcInsert(dataSource)
        .withTableName("CatalogItem")
        .usingColumns("SkuCode", "DisplayName")
        .usingQuotedIdentifiers();
```

Đây là **ví dụ minh họa** cho một bảng thật có các tên được quote chính xác như vậy. Tên cột/tên bảng phải khớp case trong metadata của DB; **khi dùng `usingQuotedIdentifiers()` phải cung cấp `usingColumns(...)`** theo Javadoc Spring. Không bật quoted identifiers để chữa mọi lỗi không tìm thấy cột: hãy kiểm tra DDL, tên thực tế, driver và schema trước.

### View, synonym và giới hạn của driver

Một số driver không trả danh sách cột ổn định cho view, synonym hoặc bảng sau proxy/gateway. Nếu dùng Oracle synonym, `includeSynonymsForTableColumnMetaData()` có thể cần thiết để đưa synonym vào tra cứu. Nếu metadata bảng vẫn không đáng tin, có thể dùng `withoutTableColumnMetaDataAccess()` cùng danh sách `usingColumns(...)` được kiểm chứng. Nhưng **không đồng nghĩa rằng mọi view đều insert được**; điều đó do DB quyết định.

## 7. SQL type, NULL và SqlParameterSource khi tắt metadata

Khi dựa vào metadata, Spring có thể biết kiểu JDBC của các cột. Tắt metadata cột làm giảm thông tin kiểu suy ra được; với giá trị `null` hoặc kiểu database đặc biệt, driver có thể cần type được khai báo rõ.

Ví dụ **đoạn minh họa trong một DAO có sẵn `insert`**:

```java
import java.sql.Types;
import org.springframework.jdbc.core.namedparam.MapSqlParameterSource;

MapSqlParameterSource params = new MapSqlParameterSource()
        .addValue("sku", "PEN-009", Types.VARCHAR)
        .addValue("name", null, Types.VARCHAR);

insert.execute(params);
```

Ở đây `insert` phải là `SimpleJdbcInsert` đã cấu hình cột phù hợp; **đoạn code không độc lập**. Với bảng `catalog_item` trong ví dụ chính, `name` là `NOT NULL` nên câu lệnh trên **sẽ lỗi do ràng buộc DB** dù type `VARCHAR` được cung cấp. Mục đích của đoạn code là chỉ rõ cách chỉ định JDBC type, **không phải một cách hợp thức hóa NULL**. Trong trường hợp thực tế, chọn cột có thể nhận `NULL` nếu muốn thử.

Phân biệt:
- `usingColumns(...)` quyết định **cột nào đi vào SQL**.
- `Map` / `SqlParameterSource` cung cấp **giá trị để bind**.
- `MapSqlParameterSource.addValue(name, value, sqlType)` có thể cung cấp **kiểu SQL** khi driver khó suy luận, nhất là khi `value == null`.
- DDL database vẫn quyết định `NULL`, `DEFAULT`, constraint, identity, trigger.

## 8. Các lỗi thường gặp và hướng xử lý

| Triệu chứng | Nguyên nhân thường gặp | Kiểm tra/cách xử lý |
| --- | --- | --- |
| Báo không tìm thấy metadata cho bảng | Sai schema/catalog, phân biệt case, driver không hỗ trợ đầy đủ, bảng chưa tạo | Kiểm tra DDL, quyền, schema; dùng `withSchemaName` hoặc khai báo cột với `usingColumns` |
| SQL sinh ra chứa cột không muốn ghi | Để auto metadata chọn mọi cột không phải generated key | Dùng `usingColumns(...)` để giới hạn chính xác |
| Lỗi `NOT NULL` cho cột có `DEFAULT` | SQL đưa cột vào nhưng bind `NULL` nên DB không chạy default | Bỏ cột đó khỏi `usingColumns`; thử lại bằng integration test |
| Tắt metadata rồi không biết cột nào cần chèn | Gọi `withoutTableColumnMetaDataAccess()` mà không cung cấp danh sách cột | Khai báo đầy đủ các cột có giá trị bằng `usingColumns(...)` |
| Insert thất bại sau thay đổi schema | Cột mới bắt buộc, cột mặc định bị bind NULL, hoặc cấu hình cũ không khớp schema | Kiểm tra migration; cập nhật `usingColumns`/mapping nếu cần, tạo lại đối tượng được compile |
| Khóa sinh trả `null` hoặc lỗi | Không cấu hình `usingGeneratedKeyColumns`, DB không sinh key, driver không trả key | Kiểm tra DDL và khả năng generated-keys của driver; phân biệt generated key với insert columns |
| Tên cột có dấu quote/case không khớp | Case được chuẩn hóa khác, tên DB có quote đặc biệt | Đọc tên thật trong metadata; dùng `usingQuotedIdentifiers` với `usingColumns` và đúng case khi cần |
| Sai bảng khi nhiều schema | Search path hoặc metadata tự chọn schema khác | Chỉ định đúng `withSchemaName`/`withCatalogName` và kiểm tra connection |
| Giá trị `null` bị driver xử lý kiểu sai | Thiếu thông tin JDBC type, nhất là khi tắt metadata | Dùng `MapSqlParameterSource` và `Types.*` phù hợp |
| Chạy lâu vì khởi tạo `SimpleJdbcInsert` lặp lại | Tạo cấu hình và compile trên mỗi bản ghi | Tái sử dụng đối tượng đã cấu hình; không tạo trong vòng lặp ghi |

### Cách chẩn đoán có hệ thống

1. Đọc lại **DDL thực tế** của bảng: schema, tên, kiểu cột, `DEFAULT`, identity/generated, `NOT NULL`.
2. Ghi rõ **các cột nghiệp vụ mà lệnh INSERT phải đặt giá trị**; các cột do DB quản lý nên được loại khỏi danh sách nếu muốn dùng default/trigger.
3. Nếu dựa metadata, kiểm tra JDBC driver có nhìn thấy đúng bảng và các cột trong schema hiện tại hay không.
4. Bật logging Spring JDBC ở mức phù hợp trong môi trường phát triển để kiểm tra câu SQL và việc bind tham số; tránh log dữ liệu nhạy cảm trong production.
5. Nếu SQL đưa thừa cột, thử `usingColumns` trước. Nếu metadata thực sự lỗi hoặc driver không đủ thông tin, thêm `withoutTableColumnMetaDataAccess` và khai báo rõ type khi cần.
6. Chạy integration test với chính DB/driver production hoặc môi trường tương thích; H2 chỉ chứng minh hành vi cho H2.

## 9. Lựa chọn thiết kế và kiểm thử

### Quy tắc chọn cấu hình

- **Bảng rất đơn giản, đầy đủ input, metadata đáng tin:** bắt đầu với `withTableName` và `usingGeneratedKeyColumns` khi cần ID.
- **Bảng có cột mặc định, audit, trigger, migration thường xuyên:** ưu tiên `usingColumns(...)` để xác định SQL contract; giữ metadata bật nếu nó hoạt động đúng.
- **Metadata bảng có vấn đề hoặc quyền bị hạn chế:** dùng `withoutTableColumnMetaDataAccess()` **kèm** `usingColumns(...)`; kiểm tra generated key và các kiểu dữ liệu cụ thể.
- **Tên bảng không duy nhất giữa nhiều schema:** định rõ schema/catalog trước khi nghĩ đến tắt metadata.
- **Bảng có tên định danh quoted/case-sensitive:** dùng đúng tên theo database; cân nhắc `usingQuotedIdentifiers()` + `usingColumns(...)`.

### Bộ kiểm thử nên có

1. **Metadata mode:** chèn vào bảng đơn giản, xác nhận đúng số dòng, không mất giá trị trường bắt buộc.
2. **usingColumns:** thêm cột tùy chọn trong migration, xác nhận repository chỉ chèn các cột đã khai báo.
3. **DB default:** chèn bản ghi không cung cấp cột `created_at`, đọc lại và xác nhận DB điền timestamp.
4. **No metadata mode:** dùng đúng schema/driver thật; xác nhận cấu hình `usingColumns` đủ và generated key hoạt động nếu cần.
5. **Case/schema:** test trong schema thực tế nếu dùng identifiers được quote hoặc nhiều schema.
6. **NULL và kiểu dữ liệu:** test các trường được phép NULL với type rõ nếu driver cần; không đưa NULL vào cột `NOT NULL`.
7. **Migration:** chạy lại test sau khi thêm/xóa/đổi tên cột; xem đối tượng đã compile có SQL phù hợp không.

**Một câu hỏi thực hành:** Bạn có bảng `orders(id, amount, created_at DEFAULT CURRENT_TIMESTAMP)`, ứng dụng chỉ cung cấp `amount` và muốn nhận `id`. Cấu hình an toàn, dễ hiểu là:

```java
SimpleJdbcInsert insert = new SimpleJdbcInsert(dataSource)
        .withTableName("orders")
        .usingColumns("amount")
        .usingGeneratedKeyColumns("id");
```

Câu lệnh sẽ không ghi đè `created_at` vì `usingColumns("amount")`, và `id` được yêu cầu trả về sau khi DB sinh. Nếu driver không thể cung cấp metadata cột một cách đáng tin, bổ sung `withoutTableColumnMetaDataAccess()`; danh sách cột ghi vẫn là `amount`. Đoạn này minh họa cấu hình trong lớp có `dataSource`, không phải chương trình Java độc lập.

## 10. Tổng kết kiến thức cần nhớ

- `SimpleJdbcInsert` dựa trên JDBC `DatabaseMetaData` để đơn giản hóa việc xây dựng câu `INSERT`.
- **Tự dò metadata** giúp viết ít cấu hình, nhưng danh sách cột do driver trả có thể rộng hơn tập dữ liệu bạn thực sự muốn ghi.
- **`usingColumns(...)`** quyết định rõ những cột xuất hiện trong `INSERT` và có thể giữ metadata bật.
- **`withoutTableColumnMetaDataAccess()`** tắt xử lý metadata cột; cần khai báo `usingColumns(...)`, nhất là khi metadata không đáng tin.
- **`usingGeneratedKeyColumns(...)`** chỉ định generated key cần lấy, khác với danh sách cột ghi.
- Bỏ hẳn cột khỏi `INSERT` mới cho phép DB áp dụng `DEFAULT`; bind `NULL` không tương đương.
- Tái sử dụng cấu hình đã compile, cân nhắc schema/case/driver và kiểm chứng với DB thực tế.
