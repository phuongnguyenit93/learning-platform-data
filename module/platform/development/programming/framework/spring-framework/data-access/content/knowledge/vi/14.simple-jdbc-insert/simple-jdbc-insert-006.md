# Khai báo cột khóa được cơ sở dữ liệu sinh với SimpleJdbcInsert

Khi thêm một bản ghi, ứng dụng thường gửi các thuộc tính như tên và email, còn **cơ sở dữ liệu tự sinh khóa chính** (`id`). Với Spring JDBC, `SimpleJdbcInsert` cho phép khai báo cột khóa này bằng `usingGeneratedKeyColumns("id")` và lấy khóa đã sinh qua `executeAndReturnKey(...)` hoặc `executeAndReturnKeyHolder(...)`.

Mục tiêu của bài là hiểu rõ **khai báo cột khóa sinh tự động**, sự phối hợp giữa định nghĩa bảng và Spring, cách nhận khóa trả về, các trường hợp nhiều khóa/khóa không phải số, cùng những sai sót thường gặp.

## 1. Hai trách nhiệm khác nhau: database sinh khóa, Spring khai báo để đọc khóa

Giả sử có bảng `customers`:

```sql
CREATE TABLE customers (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    full_name VARCHAR(100) NOT NULL,
    email VARCHAR(150) NOT NULL
);
```

Trong ví dụ dùng H2, `GENERATED BY DEFAULT AS IDENTITY` định nghĩa **chính database** sinh giá trị cho `id` khi một câu `INSERT` không cung cấp `id`.

Phía Java khai báo:

```java
SimpleJdbcInsert insertCustomer = new SimpleJdbcInsert(dataSource)
    .withTableName("customers")
    .usingColumns("full_name", "email")
    .usingGeneratedKeyColumns("id");
```

Cần tách bạch:

- `withTableName("customers")`: xác định bảng nhận bản ghi.
- `usingColumns("full_name", "email")`: xác định **các cột sẽ được gửi giá trị** trong lệnh `INSERT`.
- `usingGeneratedKeyColumns("id")`: cho Spring biết **tên cột có giá trị tự sinh cần thu hồi qua JDBC**.
- `executeAndReturnKey(...)`: thực thi chèn một bản ghi và đọc khóa được database trả về.

**Điểm cốt lõi:** `usingGeneratedKeyColumns` **không tạo cột**, không biến `id` thành `IDENTITY` và không tự sinh số ID bằng Java. Nếu schema không có cơ chế sinh khóa (identity, sequence/default, trigger phù hợp...), chỉ gọi phương thức này không khiến database tự tạo giá trị. Tương tự, việc database tự sinh khóa **không tự động bảo đảm** code sẽ nhận được khóa nếu bạn chọn sai API hoặc driver không hỗ trợ truy xuất khóa.

## 2. Cú pháp và cách hoạt động

Khai báo thông dụng nhất:

```java
SimpleJdbcInsert insert = new SimpleJdbcInsert(dataSource)
    .withTableName("customers")
    .usingColumns("full_name", "email")
    .usingGeneratedKeyColumns("id");

Number id = insert.executeAndReturnKey(
    Map.of("full_name", "Lan", "email", "lan@example.test")
);
long customerId = id.longValue();
```

Đoạn trên **chỉ là ví dụ sử dụng API**, giả định bảng đã tồn tại và có `dataSource` hợp lệ; phần 4 có chương trình chạy độc lập.

Các phương thức liên quan:

| API | Chức năng | Kiểu kết quả |
| --- | --- | --- |
| `withTableName(String)` | Chọn tên bảng cần chèn | `SimpleJdbcInsert` để gọi tiếp |
| `withSchemaName(String)` | Xác định schema nếu cần | `SimpleJdbcInsert` |
| `usingColumns(String...)` | Giới hạn các cột xuất hiện trong `INSERT` | `SimpleJdbcInsert` |
| `usingGeneratedKeyColumns(String...)` | Khai báo **một hoặc nhiều** cột có khóa tự sinh cần lấy | `SimpleJdbcInsert` |
| `execute(Map<String, ?>)` | Chèn bản ghi, trả về số hàng bị ảnh hưởng | `int` |
| `executeAndReturnKey(Map<String, ?>)` | Chèn và trả về **một khóa dạng số** | `Number` |
| `executeAndReturnKeyHolder(Map<String, ?>)` | Chèn và trả về các giá trị khóa qua `KeyHolder` | `KeyHolder` |

Các overload của `execute...` cũng nhận `SqlParameterSource` (ví dụ `MapSqlParameterSource`). Hai overload thường dùng:

```java
Number generated = insert.executeAndReturnKey(
    Map.of("full_name", "Lan", "email", "lan@example.test")
);
```

```java
MapSqlParameterSource params = new MapSqlParameterSource()
    .addValue("full_name", "Lan")
    .addValue("email", "lan@example.test");

Number generated = insert.executeAndReturnKey(params);
```

`MapSqlParameterSource` hữu ích khi cần truyền `null` hoặc khai báo SQL type cụ thể bằng `addValue(name, value, sqlType)`. Nếu dùng `Map.of(...)`, nhớ rằng `Map.of` **không cho phép giá trị null**.

### Spring tạo SQL và nhận khóa như thế nào?

Ở mức khái niệm, Spring chuẩn bị lệnh tương đương:

```sql
INSERT INTO customers (full_name, email) VALUES (?, ?)
```

Các bước chính:

1. `SimpleJdbcInsert` dùng cấu hình đã khai báo và, theo mặc định, JDBC metadata để xác định cách chèn. Nó có thể biên dịch cấu hình lúc khởi tạo hoặc tự biên dịch ở lần chạy đầu tiên.
2. Spring bind tham số `full_name` và `email` bằng `PreparedStatement`.
3. Database thực thi `INSERT`, tự sinh `id` theo định nghĩa bảng.
4. Spring yêu cầu và đọc khóa được driver JDBC trả về, dựa trên cột đã khai báo.
5. `executeAndReturnKey` trả về `Number`, hoặc `executeAndReturnKeyHolder` trả về cấu trúc chứa khóa.

Đây là **một lần chèn bản ghi có thu hồi khóa**. Không cần dùng `SELECT MAX(id)` hoặc hỏi "ID lớn nhất" sau khi insert: những cách đó không an toàn khi nhiều transaction cùng thêm dữ liệu. Spring sử dụng khả năng đọc generated keys của JDBC, với chi tiết thực thi có thể khác nhau giữa các database/driver.

## 3. Khai báo cột khóa cho đúng

### 3.1. Không đưa khóa tự sinh vào input khi mong database tạo giá trị

Đúng:

```java
Map<String, Object> params = Map.of(
    "full_name", "Lan",
    "email", "lan@example.test"
);
Number newId = insert.executeAndReturnKey(params);
```

Sai về ý định:

```java
// Nếu mong database tự sinh id, đừng tự đặt id = 0 hoặc null.
Map<String, Object> params = new HashMap<>();
params.put("id", 0L);
params.put("full_name", "Lan");
params.put("email", "lan@example.test");
```

Nếu `usingColumns("full_name", "email")` đã loại `id` khỏi danh sách cột insert, một giá trị `id` dư trong Map có thể không được dùng; tuy vậy vẫn làm code khó hiểu và dễ gây lỗi khi cấu hình thay đổi. Cách rõ ràng nhất là **không truyền `id` khi database phải sinh `id`**.

### 3.2. `usingColumns` và `usingGeneratedKeyColumns` không đồng nghĩa

```java
new SimpleJdbcInsert(dataSource)
    .withTableName("customers")
    .usingColumns("full_name", "email")
    .usingGeneratedKeyColumns("id");
```

`usingColumns` nói các cột nào **được gán giá trị khi INSERT**, còn `usingGeneratedKeyColumns` nói các cột nào **được yêu cầu trả lại sau INSERT**. Đây là hai hướng dữ liệu khác nhau.

Bạn có thể chỉ gọi `withTableName(...).usingGeneratedKeyColumns("id")` và để Spring suy luận danh sách cột từ metadata của database; tuy nhiên `usingColumns` làm ý định rõ ràng hơn, tránh phụ thuộc không cần thiết vào việc suy ra các cột không liên quan. Nó đặc biệt hữu ích khi bảng có nhiều cột default/computed, hoặc khi bạn cần khóa chỉ nằm ở danh sách generated keys.

### 3.3. Tên cột phải khớp database

Sử dụng **tên cột SQL thực tế**, chẳng hạn `customer_id`, không mặc nhiên dùng tên field Java `customerId`:

```java
// Nếu DDL định nghĩa cột customer_id:
.usingGeneratedKeyColumns("customer_id");
```

Với schema khác, khai báo `withSchemaName("...")` khi cần. Tên identifier có dấu ngoặc kép và phân biệt hoa/thường có thể gây vấn đề khác với tên không quote. API `usingQuotedIdentifiers()` giúp trích dẫn identifier theo cú pháp driver, nhưng khi dùng nó phải cung cấp `usingColumns(...)` rõ ràng và bảo đảm cách viết hoa/thường khớp metadata DB. Không dùng `usingQuotedIdentifiers()` chỉ để thử sửa lỗi ngẫu nhiên; trước tiên hãy đối chiếu DDL và metadata thực tế.

### 3.4. Loại khóa phải phù hợp với phương thức nhận kết quả

Với khóa số đơn (`BIGINT`, `INTEGER`...), dùng:

```java
Number generatedId = insert.executeAndReturnKey(params);
long id = generatedId.longValue();
```

`Number` có thể là `Long`, `Integer`, `BigDecimal` hoặc lớp khác tùy database/driver. Không ép kiểu trực tiếp `(Long) generatedId` nếu chưa chắc kiểu cụ thể. `longValue()` phù hợp khi domain dùng `long` và dữ liệu trong khoảng `long`; với kiểu số lớn hoặc yêu cầu không mất thông tin, cần kiểm tra miền giá trị và chuyển đổi chính xác.

Nếu database trả về nhiều generated columns hoặc khóa không phải số (ví dụ UUID), hãy dùng `executeAndReturnKeyHolder` thay vì ép về `Number`.

## 4. Ví dụ hoàn chỉnh chạy với Java 17+, Spring JDBC và H2

Chương trình sau tạo bảng có khóa `IDENTITY`, insert hai bản ghi bằng `SimpleJdbcInsert`, in ID mới được sinh, rồi kiểm chứng dữ liệu trong bảng. Sử dụng H2 in-memory để không cần cài server database.

Cấu trúc:

```text
simple-insert-demo/
├── build.gradle
└── src/main/java/GeneratedKeyDemo.java
```

Nội dung `build.gradle`:

```groovy
plugins {
    id 'application'
}

repositories {
    mavenCentral()
}

dependencies {
    implementation 'org.springframework:spring-jdbc:6.2.12'
    runtimeOnly 'com.h2database:h2:2.3.232'
}

java {
    toolchain {
        languageVersion = JavaLanguageVersion.of(17)
    }
}

application {
    mainClass = 'GeneratedKeyDemo'
}
```

Nội dung `src/main/java/GeneratedKeyDemo.java`:

```java
import java.util.Map;

import org.springframework.jdbc.core.JdbcTemplate;
import org.springframework.jdbc.core.simple.SimpleJdbcInsert;
import org.springframework.jdbc.datasource.DriverManagerDataSource;

public class GeneratedKeyDemo {

    public static void main(String[] args) {
        DriverManagerDataSource dataSource = new DriverManagerDataSource();
        dataSource.setDriverClassName("org.h2.Driver");
        dataSource.setUrl("jdbc:h2:mem:generated_keys;DB_CLOSE_DELAY=-1");
        dataSource.setUsername("sa");
        dataSource.setPassword("");

        JdbcTemplate jdbc = new JdbcTemplate(dataSource);
        jdbc.execute("""
            CREATE TABLE customers (
                id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
                full_name VARCHAR(100) NOT NULL,
                email VARCHAR(150) NOT NULL
            )
            """);

        SimpleJdbcInsert insertCustomer = new SimpleJdbcInsert(dataSource)
            .withTableName("customers")
            .usingColumns("full_name", "email")
            .usingGeneratedKeyColumns("id");

        // Chốt cấu hình và kiểm tra metadata trước khi dùng lại.
        insertCustomer.compile();

        Number id1 = insertCustomer.executeAndReturnKey(
            Map.of("full_name", "An", "email", "an@example.test")
        );
        Number id2 = insertCustomer.executeAndReturnKey(
            Map.of("full_name", "Binh", "email", "binh@example.test")
        );

        System.out.println("First generated id: " + id1.longValue());
        System.out.println("Second generated id: " + id2.longValue());

        Integer count = jdbc.queryForObject(
            "SELECT COUNT(*) FROM customers", Integer.class
        );
        System.out.println("Rows in database: " + count);
    }
}
```

Chạy tại thư mục `simple-insert-demo` bằng Gradle đã cài đặt (nếu dự án có Gradle Wrapper, dùng `./gradlew --quiet run`):

```bash
gradle --quiet run
```

Các dòng chương trình in ra khi chạy với H2 in-memory và bảng mới tạo ở trên:

```text
First generated id: 1
Second generated id: 2
Rows in database: 2
```

Giải thích kết quả:

- H2 tạo identity bắt đầu từ 1 trong bảng mới; hai lệnh insert lần lượt nhận `id=1` và `id=2`.
- Input của `executeAndReturnKey` **chỉ chứa `full_name` và `email`**, không tự truyền `id`.
- `usingGeneratedKeyColumns("id")` hướng dẫn Spring lấy lại giá trị `id` mà H2 đã tạo.
- `COUNT(*)` chứng minh có hai hàng được lưu; giá trị của `id` được lấy từ kết quả JDBC, không phải suy ra từ `COUNT(*)`.
- `compile()` là tùy chọn: Spring có thể tự compile khi gọi lần đầu. Việc compile trước giúp phát hiện một số lỗi cấu hình sớm và dùng một instance đã cấu hình cho các lần insert tiếp theo.

**Lưu ý:** Kết quả `1, 2` là của môi trường H2 với bảng mới và không có thao tác khác. Trong hệ thống thực, ID có thể bị bỏ khoảng do rollback, cấp phát sequence, lỗi hoặc thao tác đồng thời. Không hứa rằng ID luôn liên tiếp, bắt đầu từ 1 hay phản ánh chính xác thứ tự thời gian giữa các transaction.

## 5. Khi cần nhiều khóa hoặc khóa không phải số: KeyHolder

Phương thức `executeAndReturnKey(...)` dành cho tình huống phổ biến là lấy **một khóa số**. Để truy xuất kết quả linh hoạt hơn:

```java
import java.util.Map;
import org.springframework.jdbc.support.KeyHolder;

// Đây là đoạn mở rộng, giả định insertCustomer đã được cấu hình
// và có bảng customers như trong ví dụ ở trên.
KeyHolder holder = insertCustomer.executeAndReturnKeyHolder(
    Map.of("full_name", "Chi", "email", "chi@example.test")
);

Map<String, Object> generated = holder.getKeys();
if (generated == null || generated.isEmpty()) {
    throw new IllegalStateException("Database did not return generated keys");
}

System.out.println(generated);
```

`getKeys()` là `Map<String, Object>` cho hàng kết quả khóa; **tên key và cách viết hoa/thường phụ thuộc driver và metadata**. Không giả định mọi database đều trả Map có key đúng chuỗi `"id"`. Nếu chỉ cần một khóa số, cách đơn giản nhất vẫn là `executeAndReturnKey(...)`.

Nếu bảng thực sự sinh hai giá trị và driver hỗ trợ lấy cả hai, có thể cấu hình:

```java
SimpleJdbcInsert insert = new SimpleJdbcInsert(dataSource)
    .withTableName("documents")
    .usingColumns("title")
    .usingGeneratedKeyColumns("id", "tracking_code");

KeyHolder holder = insert.executeAndReturnKeyHolder(
    Map.of("title", "Spring JDBC guide")
);
Map<String, Object> keys = holder.getKeys();
```

Đoạn này **minh họa API**, không phải chương trình độc lập; cần DDL `documents` có cơ chế tự sinh cả `id` và `tracking_code` cùng driver có hỗ trợ. Việc khai báo tên cột không buộc DB trả về được tất cả. Với kết quả có nhiều cột, gọi `holder.getKey()` hoặc `executeAndReturnKey(...)` có thể không phù hợp vì các API này mong **một khóa số duy nhất**.

Nếu driver trả về nhiều hàng generated keys, `KeyHolder` còn có `getKeyList()` để biểu diễn danh sách hàng khóa. `getKeys()` chỉ phù hợp khi kỳ vọng một hàng; không coi một `KeyHolder` như bảo đảm có đúng một hàng và mọi cột được trả về.

## 6. Thiết kế DAO trong Spring Boot

Trong ứng dụng Spring Boot, `DataSource` thường do Spring cấu hình. Bạn có thể khởi tạo `SimpleJdbcInsert` một lần trong DAO hoặc bean, rồi sử dụng lại:

```java
import java.util.Map;
import javax.sql.DataSource;

import org.springframework.jdbc.core.simple.SimpleJdbcInsert;
import org.springframework.stereotype.Repository;

@Repository
public class CustomerJdbcRepository {

    private final SimpleJdbcInsert insert;

    public CustomerJdbcRepository(DataSource dataSource) {
        this.insert = new SimpleJdbcInsert(dataSource)
            .withTableName("customers")
            .usingColumns("full_name", "email")
            .usingGeneratedKeyColumns("id");
    }

    public long create(String fullName, String email) {
        Number id = insert.executeAndReturnKey(
            Map.of("full_name", fullName, "email", email)
        );
        return id.longValue();
    }
}
```

Đây là **mảnh mã DAO để tích hợp** (chưa có DDL, cấu hình Spring Boot và entry point để tự chạy riêng). Hãy dùng phiên bản Spring JDBC do dự án quản lý; không cần tự tạo `DriverManagerDataSource` trong ứng dụng production.

Cấu hình `SimpleJdbcInsert` trong constructor/khởi tạo, trước khi xử lý các lời gọi song song. Sau khi instance được compile, đừng cố thay đổi `withTableName`, `usingColumns` hay `usingGeneratedKeyColumns` cho từng request; tạo instance khác nếu cần cấu hình khác.

Nếu một nghiệp vụ vừa insert `customers` vừa insert bảng phụ và cả hai phải thành công cùng nhau, dùng ranh giới transaction thích hợp, ví dụ `@Transactional` ở service. Lấy được generated ID **chưa chứng minh transaction đã commit**. Khi rollback, bản ghi có thể không tồn tại mặc dù ứng dụng từng quan sát thấy ID. Nhiều database cũng không hoàn lại số sequence/identity đã cấp khi rollback, nên ID có thể bị nhảy số.

## 7. Khác biệt giữa generated key, giá trị tự sinh khác và mã khóa ở tầng ứng dụng

| Trường hợp | Ai tạo giá trị? | `usingGeneratedKeyColumns` có phù hợp? |
| --- | --- | --- |
| `BIGINT IDENTITY` / auto-increment | Database | Có, nếu driver hỗ trợ đọc khóa. |
| Giá trị lấy từ sequence bằng default SQL | Database | Có thể, tùy database và driver có trả cột đó dưới dạng generated key. |
| UUID được DB sinh qua default/trigger | Database | Có thể dùng `executeAndReturnKeyHolder` nếu driver trả được giá trị này. |
| UUID tạo bằng `UUID.randomUUID()` tại Java | Java application | Không bắt buộc; thường truyền UUID như một tham số input. |
| Khóa do client nhập thủ công | Client/application | Không cần cơ chế generated key; `execute(...)` có thể đủ. |
| Giá trị tính toán/default của cột khác | Database | Chỉ đọc được qua generated keys khi driver/database hỗ trợ; nếu không, truy vấn lại bằng khóa đã biết. |

Cũng cần phân biệt `SimpleJdbcInsert` của **Spring JDBC** với `@GeneratedValue` của **JPA/Hibernate**. Chúng thuộc hai cách thao tác dữ liệu khác nhau. Cấu hình chiến lược sinh ID trên entity JPA không tự thay đổi cách `SimpleJdbcInsert` hoạt động; với JDBC, nguồn sự thật vẫn là schema và cơ chế trả generated keys của driver.

## 8. Những lỗi dễ gặp và cách kiểm tra

### 8.1. Quên `usingGeneratedKeyColumns("id")`

```java
SimpleJdbcInsert insert = new SimpleJdbcInsert(dataSource)
    .withTableName("customers")
    .usingColumns("full_name", "email");

// Không khai báo cột cần lấy khóa:
Number id = insert.executeAndReturnKey(params);
```

Lời gọi lấy khóa đòi hỏi thông tin cột generated key đã được khai báo; cấu hình thiếu có thể gây `InvalidDataAccessApiUsageException`. Thêm đúng tên cột vào `usingGeneratedKeyColumns` trước khi compile/chạy.

### 8.2. Bảng không thực sự sinh giá trị

```sql
-- id chỉ là khóa chính thông thường, chưa được khai báo tự sinh:
CREATE TABLE wrong_customers (
    id BIGINT PRIMARY KEY,
    full_name VARCHAR(100) NOT NULL
);
```

`.usingGeneratedKeyColumns("id")` không sửa được DDL này. Cần định nghĩa `IDENTITY` hoặc cơ chế DB phù hợp, hoặc cung cấp `id` từ ứng dụng theo thiết kế.

### 8.3. Khai báo sai tên cột, schema hoặc case

Thông báo "column not found", metadata không tìm thấy, câu SQL insert sai, hoặc key trả về rỗng có thể xuất phát từ việc mã dùng `id` trong khi schema thật là `customer_id`, bảng nằm trong schema khác, hoặc identifier được quote với case khác. Kiểm tra tên bảng/cột qua DDL và JDBC metadata; khai báo `withSchemaName(...)` khi cần. Không thử biến thể tên theo cảm tính trên dữ liệu thật.

### 8.4. Kỳ vọng khóa `Long` ở mọi DB

```java
// Không an toàn trên mọi JDBC driver:
Long id = (Long) insert.executeAndReturnKey(params);
```

Nên sử dụng `Number` rồi chuyển kiểu theo miền giá trị và loại khóa. Nếu database sinh khóa không phải số, dùng `executeAndReturnKeyHolder`. Nếu có nhiều generated columns, đừng cố ép một `Map` thành `Number`.

### 8.5. Chỉ gọi `execute(...)` rồi mong đọc được ID

`execute(...)` trả về **số hàng bị ảnh hưởng** (thường `1` với insert một hàng), **không phải ID**. Với bản ghi thứ 100, trả `1` không có nghĩa khóa sinh được là `1`. Nếu cần ID, hãy dùng đúng `executeAndReturnKey` hoặc `executeAndReturnKeyHolder`.

### 8.6. Dựa vào kết quả generated keys không được driver hỗ trợ

Chính database và JDBC driver quyết định liệu keys nào có thể trả về, qua kiểu API nào. Một số DB/driver chỉ trả identity column; vài driver hỗ trợ UUID/default/computed columns, vài trường hợp trả thiếu tên cột hoặc nhiều cột ngoài dự kiến. Kiểm thử với **đúng phiên bản driver và DB production**, nhất là khi hệ thống chạy trên nhiều vendor. Không suy luận rằng bảng có trigger là driver chắc chắn trả giá trị được trigger tạo.

### 8.7. Cố gắng lấy generated IDs từ batch insert bằng API khác

`SimpleJdbcInsert.executeBatch(...)` trả về `int[]` các update counts, **không phải danh sách các ID đã sinh**. Nếu nghiệp vụ cần map chính xác từng ID sau batch, phải xem xét riêng API JDBC/driver, cách chèn từng bản ghi hoặc cơ chế trả kết quả được DB hỗ trợ. Không dùng update count để suy ra ID.

### 8.8. Dùng ID để suy luận transaction và độ liên tiếp

ID có thể được cấp phát rồi transaction rollback; sequence/identity có thể bị mất số và các request có thể xen kẽ. Không dùng quy tắc "ID trước + 1" để tính ID mới, không dùng `MAX(id)` để truy lại bản ghi vừa tạo, và không phụ thuộc vào khóa liên tiếp trong logic nghiệp vụ.

## 9. Tình huống kiểm thử nên có

1. **Trường hợp chuẩn:** bảng `IDENTITY` đã được tạo, input chỉ gồm các cột nghiệp vụ, `executeAndReturnKey` nhận khóa hợp lệ; truy vấn theo ID thấy đúng hàng.
2. **Nhiều lần chèn:** các ID không trùng nhau; số hàng tăng tương ứng. Không bắt buộc assert mọi ID liên tiếp ở môi trường nhiều transaction.
3. **Vi phạm constraint:** ví dụ trùng `UNIQUE(email)`; xác nhận có `DataAccessException` phù hợp, không nhận nhầm update count thành ID, và transaction xử lý đúng.
4. **Cột khóa sai tên:** kiểm thử lỗi cấu hình/driver có thông điệp rõ, không "đoán" ID bằng `MAX(id)`.
5. **Khóa UUID hoặc nhiều generated columns:** sử dụng `KeyHolder`, kiểm tra thực tế driver có trả các cột mong đợi hay không.
6. **Rollback:** tạo bản ghi trong transaction rồi buộc rollback; bản ghi không còn tồn tại dù trước đó từng nhận được ID.
7. **Tích hợp DB sản xuất:** xác nhận kiểu giá trị (`Long`, `BigDecimal`, UUID...), tên cột trả về trong `KeyHolder`, schema/case và hành vi default/trigger.

Đặc biệt, một kiểm thử tốt nên **truy vấn lại theo ID vừa nhận được** và so sánh các trường nghiệp vụ. Kiểm thử đó chứng minh ID gắn với đúng hàng vừa insert, thay vì chỉ kiểm tra `id != null`.

## 10. Câu hỏi tự đánh giá

**Câu 1.** Bảng có `id BIGINT GENERATED BY DEFAULT AS IDENTITY`. Muốn insert `name` và nhận ID, nên gọi gì?

- Cấu hình `withTableName(...).usingColumns("name").usingGeneratedKeyColumns("id")`, sau đó gọi `executeAndReturnKey(...)` với input `name`.

**Câu 2.** Vì sao chỉ thêm `usingGeneratedKeyColumns("id")` chưa đủ nếu DDL có `id BIGINT PRIMARY KEY` thông thường?

- Vì Spring chỉ **khai báo cột để nhận khóa**; cơ chế sinh giá trị phải do database hoặc ứng dụng cung cấp.

**Câu 3.** Phương thức `execute(...)` trả `1`. Có kết luận được generated ID là `1` không?

- Không. Giá trị `1` là số hàng ảnh hưởng; ID phải lấy từ generated keys.

**Câu 4.** Bảng có khóa tự sinh dạng UUID hoặc trả về hai cột, có thể ép `executeAndReturnKey(...)` sang `Long` không?

- Không. Dùng `executeAndReturnKeyHolder(...)` và kiểm tra nội dung keys theo kiểu trả thực tế của driver.

**Câu 5.** Vừa nhận ID xong nhưng transaction rollback. Có thể coi bản ghi đã được lưu bền vững không?

- Không. Việc nhận ID xảy ra trong quá trình insert, không chứng minh transaction đã commit.

## 11. Tổng kết kiến thức

- Database tạo khóa thông qua DDL/default/sequence/trigger; **`SimpleJdbcInsert.usingGeneratedKeyColumns(...)` khai báo cột cần truy xuất**, không sinh khóa thay DB.
- Dùng `usingColumns(...)` để chỉ định cột input, không truyền `id` nếu muốn database tự cấp khóa.
- Dùng `executeAndReturnKey(...)` cho **một khóa số**, xử lý giá trị theo kiểu `Number`. Dùng `executeAndReturnKeyHolder(...)` cho nhiều khóa hoặc kiểu không phải số khi DB/driver hỗ trợ.
- Không nhầm `execute(...)` (update count) với generated ID; không truy `MAX(id)` để đoán ID mới.
- Tên cột/schema/case, khả năng JDBC driver trả generated keys, transaction và rollback cần được kiểm chứng bằng integration test với DB thực tế.
