# @Transient và thuộc tính không lưu trong directory với Spring LDAP ODM

## 1. Bài toán: không phải mọi field Java đều là LDAP attribute

Trong ứng dụng **Spring LDAP**, một entity Java có thể chứa cả dữ liệu lưu trong LDAP và dữ liệu chỉ phục vụ màn hình hoặc quy trình xử lý. Ví dụ với hồ sơ nhân viên:

- `uid`, `commonName`, `surname` và `email`: ánh xạ tới `uid`, `cn`, `sn` và `mail` trong directory.
- `displayLabel`: tên hiển thị tạm thời, được xây từ `cn` và `uid`.
- `selectedForExport`: checkbox chỉ tồn tại khi thao tác tại giao diện.
- `validationMessage`: thông báo xử lý của service, không thuộc hồ sơ thư mục.

Nếu các thuộc tính tạm thời này bị ODM xử lý như thuộc tính LDAP, server có thể từ chối vì schema không cho phép, hoặc dữ liệu không nên tồn tại lâu dài sẽ bị ghi sai nơi.

**`@Transient` trong Spring LDAP Object-Directory Mapping (ODM)** được dùng để đánh dấu **field Java không tham gia ánh xạ giữa entity và LDAP attribute**. Field vẫn hiện diện trong object Java và có thể được gán, đọc, tính toán hoặc trả về theo thiết kế ứng dụng, nhưng việc tạo/cập nhật qua ODM không lưu giá trị của field đó vào LDAP.

Đây là bài thuộc chương **ODM** của module **Spring LDAP**: từ DN, schema, filter, tìm kiếm đến thao tác entry bằng `LdapTemplate`, `LdapClient` hoặc ODM, đồng thời xem xét `ContextSource`, quyền truy cập, TLS, pooling, xử lý lỗi và kiểm thử an toàn.

**Sau bài học, bạn có thể:**

1. Phân biệt field của entity Java với attribute tồn tại trên directory server.
2. Sử dụng annotation `org.springframework.ldap.odm.annotations.Transient` đúng mục đích.
3. Xây entity có `@Entry`, `@Id`, `@Attribute` và `@Transient`.
4. Giải thích chu trình tạo, đọc, enrich, update và đọc lại với field transient.
5. Phân biệt Spring LDAP `@Transient` với từ khóa Java `transient`, JPA `@Transient` và JSON `@JsonIgnore`.
6. Nhận diện giới hạn của annotation đối với schema, ACL, bảo mật, concurrency và các API không dùng ODM.
7. Thiết kế kiểm thử chứng minh dữ liệu transient không được lưu, không gây side effect ngoài ý muốn.

## 2. Hình dung đường đi của dữ liệu trong ODM

Giả sử entry LDAP thử nghiệm có dữ liệu:

~~~ldif
dn: uid=alice,ou=people,dc=example,dc=org
objectClass: top
objectClass: person
objectClass: organizationalPerson
objectClass: inetOrgPerson
uid: alice
cn: Alice Nguyen
sn: Nguyen
mail: alice@example.org
~~~

Ứng dụng ánh xạ thành một đối tượng:

~~~text
DirectoryPerson (Java)
├── dn                = uid=alice,ou=people
├── uid               = alice
├── commonName        = Alice Nguyen
├── surname           = Nguyen
├── email             = alice@example.org
├── displayLabel      = "Alice Nguyen (alice)"
└── selectedForExport = true
~~~

Không phải mọi field có trong object đều phải lưu LDAP:

~~~text
LDAP directory                       Java entity
------------------------------------------------------------
DN                                <-> @Id dn
uid: alice                        <-> @Attribute uid
cn: Alice Nguyen                  <-> @Attribute commonName
sn: Nguyen                        <-> @Attribute surname
mail: alice@example.org           <-> @Attribute email

không lưu displayLabel             X  @Transient displayLabel
không lưu selectedForExport        X  @Transient selectedForExport
~~~

Dấu `X` có nghĩa **bị loại khỏi mapping của Spring LDAP ODM**, không có nghĩa Java field bị xóa hoặc tự động cấm truy cập.

### 2.1. Annotation ODM không điều khiển tất cả đường truy cập LDAP

| Thao tác | Có đi qua ODM entity mapping không? | Tác dụng của `@Transient` |
| --- | --- | --- |
| `LdapTemplate.findByDn(dn, DirectoryPerson.class)` | Có | Không nạp field transient từ LDAP |
| `LdapTemplate.create(entity)` | Có | Không tạo attribute từ field transient |
| `LdapTemplate.update(entity)` | Có | Không dùng field transient để cập nhật LDAP |
| `LdapTemplate.lookupContext(dn)` | Không ánh xạ thành class đó | Không dựa vào annotation trên entity |
| `LdapTemplate.modifyAttributes(dn, items)` | Gửi các `ModificationItem` do caller tạo | Không tự xem `@Transient` |
| `DirContextOperations.setAttributeValue(...)` | Thao tác thuộc tính trực tiếp | Không tự bị `@Transient` ngăn |
| Mapper tự viết hoặc API LDAP khác | Tùy cách triển khai | Không thể mặc định có cùng hợp đồng |

**`@Transient` không phải một cơ chế ACL.** Một đoạn code trực tiếp gọi `modifyAttributes` có thể ghi một attribute cùng tên, nếu server cho phép, bất kể field có annotation trên entity khác.

### 2.2. Transient không có nghĩa LDAP server không biết attribute đó

LDAP server có thể đã lưu một attribute tên `description` hoặc một loại dữ liệu khác từ trước. Nếu Java entity không map field đó hoặc đánh dấu `@Transient`, điều đó **không xóa attribute khỏi LDAP** và không ngăn một client khác đọc nó.

Do đó cần phân biệt:

- **Không ánh xạ trên object:** quyết định của ODM.
- **Không có attribute trên server:** trạng thái dữ liệu thực.
- **Không được quyền nhìn/sửa attribute:** do ACL.
- **Không được schema cho phép:** do schema và object class.

Không suy ba kết luận còn lại chỉ từ việc nhìn thấy `@Transient`.

## 3. Dùng đúng annotation Spring LDAP

Import cần dùng:

~~~java
import org.springframework.ldap.odm.annotations.Transient;
~~~

Đánh dấu **field** muốn bỏ qua:

~~~java
@Transient
private String displayLabel;
~~~

Không nhầm với các cơ chế có tên tương tự:

~~~java
// Từ khóa Java serialization:
private transient String displayLabel;

// Annotation của JPA, dành cho ORM quan hệ:
@jakarta.persistence.Transient
private String displayLabel;

// Annotation JavaBeans dùng với bean introspection:
@java.beans.Transient
public String getDisplayLabel() { return displayLabel; }
~~~

| Cơ chế | Công cụ/ngữ cảnh | Có tự thay thế Spring LDAP `@Transient` không? |
| --- | --- | --- |
| Spring LDAP `@Transient` | ODM mapping LDAP | **Đúng công cụ cần dùng** |
| Java keyword `transient` | Java object serialization | Không nên dùng để biểu đạt hợp đồng ODM |
| JPA `@Transient` | JPA entity mapping SQL | Không |
| JavaBeans `@Transient` | Cơ chế mô tả property JavaBeans | Không |
| Jackson `@JsonIgnore` | JSON serialization | Không, và Spring LDAP `@Transient` cũng không tự thay `@JsonIgnore` |
| DTO riêng cho API | Giới hạn dữ liệu nhận/trả | Cần ánh xạ/validation tường minh |

Với các dự án kết hợp JPA và LDAP, **cần đặc biệt chú ý import**: hai annotation tên giống nhau không đồng nghĩa cùng tác dụng. Kiểm tra chính xác thư viện trong source code.

### 3.1. Field transient vẫn sử dụng được trong Java

~~~java
@Transient
private String displayLabel;

public String getDisplayLabel() {
    return displayLabel;
}

public void setDisplayLabel(String displayLabel) {
    this.displayLabel = displayLabel;
}
~~~

Service vẫn có thể gán giá trị. `@Transient` chỉ nói với ODM rằng field này không được ánh xạ thành LDAP attribute.

### 3.2. @Transient không tính giá trị giúp bạn

Sau khi ODM tạo object từ LDAP, `displayLabel` có thể là `null` vì không được nạp. Với một field nguyên thủy:

~~~java
@Transient
private boolean selectedForExport;
~~~

giá trị mặc định Java là `false`. Đó là **giá trị khởi tạo của Java**, không phải một cờ bền vững được đọc từ LDAP. Nếu cần phân biệt “chưa tính” với “false”, hãy dùng `Boolean` hoặc mô hình trạng thái rõ ràng.

## 4. Xây entity ODM hoàn chỉnh

Ví dụ entity cho schema `inetOrgPerson`:

~~~java
import javax.naming.Name;

import org.springframework.ldap.odm.annotations.Attribute;
import org.springframework.ldap.odm.annotations.Entry;
import org.springframework.ldap.odm.annotations.Id;
import org.springframework.ldap.odm.annotations.Transient;

@Entry(
    base = "ou=people",
    objectClasses = {
        "top", "person", "organizationalPerson", "inetOrgPerson"
    }
)
public class DirectoryPerson {

    @Id
    private Name dn;

    @Attribute(name = "uid")
    private String uid;

    @Attribute(name = "cn")
    private String commonName;

    @Attribute(name = "sn")
    private String surname;

    @Attribute(name = "mail")
    private String email;

    @Transient
    private String displayLabel;

    @Transient
    private boolean selectedForExport;

    public DirectoryPerson() {
        // Constructor không tham số cho ODM.
    }

    public Name getDn() { return dn; }
    public void setDn(Name dn) { this.dn = dn; }

    public String getUid() { return uid; }
    public void setUid(String uid) { this.uid = uid; }

    public String getCommonName() { return commonName; }
    public void setCommonName(String commonName) {
        this.commonName = commonName;
    }

    public String getSurname() { return surname; }
    public void setSurname(String surname) {
        this.surname = surname;
    }

    public String getEmail() { return email; }
    public void setEmail(String email) { this.email = email; }

    public String getDisplayLabel() { return displayLabel; }
    public void setDisplayLabel(String displayLabel) {
        this.displayLabel = displayLabel;
    }

    public boolean isSelectedForExport() {
        return selectedForExport;
    }
    public void setSelectedForExport(boolean selectedForExport) {
        this.selectedForExport = selectedForExport;
    }
}
~~~

### 4.1. Ý nghĩa các annotation

| Annotation | Chức năng | Điều không được suy ra |
| --- | --- | --- |
| `@Entry` | Định nghĩa object classes/base cho ODM entity | Không tạo OU cha hoặc bỏ qua schema |
| `@Id` | Định danh DN của entry | Không phải ID tự tăng kiểu SQL |
| `@Attribute(name="uid")` | Map UID Java sang attribute `uid` | Không tự bảo đảm UID duy nhất toàn subtree |
| `@Attribute(name="cn")` | Map commonName sang `cn` | Không bỏ qua thuộc tính MUST |
| `@Attribute(name="sn")` | Map surname sang `sn` | Không tự thay đổi object class |
| `@Attribute(name="mail")` | Map email sang `mail` | Không tự xác minh email tồn tại |
| `@Transient` | Không map field vào LDAP | Không tự loại field khỏi JSON, log hay RAM |

### 4.2. DN là định danh quan trọng, không phải field tạm thời

Giả sử `ContextSource.base = dc=example,dc=org`:

~~~text
DN tương đối khi dùng template: uid=alice,ou=people
DN đầy đủ trên server:          uid=alice,ou=people,dc=example,dc=org
~~~

Dùng `LdapNameBuilder` để dựng DN:

~~~java
import javax.naming.Name;
import org.springframework.ldap.support.LdapNameBuilder;

Name dn = LdapNameBuilder.newInstance("ou=people")
        .add("uid", "alice")
        .build();
~~~

Không tự nối DN từ UID chưa tin cậy. Escaping DN khác escaping LDAP filter. Đồng thời phải validate UID theo chính sách của hệ thống trước khi tạo DN.

**Không đánh dấu `@Transient` trên field `dn` được `@Id` quản lý**, bởi entity ODM cần biết DN để định vị entry.

### 4.3. @Transient không cứu được một entity sai schema

`inetOrgPerson` trong schema thông dụng kế thừa `person`, yêu cầu `cn` và `sn`. Nếu entity thiếu `sn` hoặc ghi attribute không được object class cho phép, LDAP server vẫn có thể từ chối `create`/`update`.

Annotation transient chỉ xử lý việc **một field được bỏ khỏi mapping**. Nó không kiểm tra hết schema, DN, thuộc tính đa trị, ACL và TLS.

## 5. Đọc entity rồi enrich các thuộc tính tạm thời

Sau khi có `LdapTemplate` được cấu hình để dùng ODM:

~~~java
import javax.naming.Name;
import org.springframework.ldap.core.LdapTemplate;
import org.springframework.ldap.support.LdapNameBuilder;

public DirectoryPerson loadAndEnrich(
        LdapTemplate ldapTemplate, String uid) {

    Name dn = LdapNameBuilder.newInstance("ou=people")
            .add("uid", uid)
            .build();

    DirectoryPerson person =
            ldapTemplate.findByDn(dn, DirectoryPerson.class);

    person.setDisplayLabel(
            person.getCommonName() + " (" + person.getUid() + ")"
    );
    person.setSelectedForExport(false);

    return person;
}
~~~

Ví dụ giả định entry tồn tại và lookup thành công. Trong production cần xử lý entry không tồn tại, DN/base không đúng, ACL, TLS và kết nối lỗi theo **hợp đồng của API đang dùng**; không coi mọi exception là kết quả “không tìm thấy”.

Ở đây:

1. ODM nạp những attribute được map như `uid`, `cn`, `sn` và `mail`.
2. `displayLabel` và `selectedForExport` không được nạp từ LDAP.
3. Service **chủ động** tính và gán các giá trị tạm thời.
4. Một object khác đọc lại từ LDAP **không được nhớ** các giá trị transient vừa gán.

### 5.1. Hành vi qua nhiều lần đọc

~~~text
Lần đọc 1:
  LDAP -> DirectoryPerson A
  A.displayLabel = null
  service gán "Alice Nguyen (alice)"

Lần đọc 2:
  LDAP -> DirectoryPerson B
  B.displayLabel = null
  service cần gán lại hoặc tính lại
~~~

Không dùng field transient để lưu nghiệp vụ cần tồn tại sau khi khởi động lại service. Nếu một trạng thái cần được chia sẻ qua directory, phải có attribute hợp schema và mapping bền vững phù hợp.

### 5.2. Getter tính toán có thể tốt hơn field cache

Nếu giá trị luôn suy ra trực tiếp từ dữ liệu đã map, không nhất thiết phải lưu nó vào field:

~~~java
public String formattedLabel() {
    String name = getCommonName() == null
            ? "(unknown)"
            : getCommonName();
    String account = getUid() == null ? "" : getUid();

    return name + " (" + account + ")";
}
~~~

Đây là một phương thức tính toán trong Java. Nếu ODM của phiên bản chỉ map field theo cơ chế annotation, không cần một LDAP attribute tương ứng với phương thức; tuy nhiên không nên suy từ điều đó rằng các công cụ JSON/JavaBeans khác cũng tự bỏ qua getter.

## 6. Tạo entry qua ODM: field @Transient không được lưu

Giả sử muốn tạo người dùng thử nghiệm:

~~~java
import javax.naming.Name;

import org.springframework.ldap.core.LdapTemplate;
import org.springframework.ldap.support.LdapNameBuilder;

public void createTrainingUser(LdapTemplate ldapTemplate) {

    Name dn = LdapNameBuilder.newInstance("ou=people")
            .add("uid", "training-01")
            .build();

    DirectoryPerson person = new DirectoryPerson();
    person.setDn(dn);
    person.setUid("training-01");
    person.setCommonName("Training User");
    person.setSurname("User");
    person.setEmail("training-01@example.org");

    // Chỉ dùng trong Java; không phải attribute cần tạo.
    person.setDisplayLabel("Training User (training-01)");
    person.setSelectedForExport(true);

    ldapTemplate.create(person);
}
~~~

Trong ví dụ:

- `@Entry` xác định object class khi tạo entity theo ODM.
- `@Id` mang DN của entry.
- `@Attribute` xác định dữ liệu được ghi như `uid`, `cn`, `sn`, `mail`.
- `@Transient` khiến `displayLabel` và `selectedForExport` **không trở thành LDAP attribute**.
- LDAP server vẫn kiểm tra parent OU, schema, DN đã tồn tại và ACL.

**`create` không phải upsert.** Nếu DN đã tồn tại, server thường từ chối với code **68 — entryAlreadyExists**. Không tự bắt duplicate rồi ghi đè entry cũ chỉ để cho request tạo hồ sơ “thành công”.

### 6.1. Vì sao điều này ngăn lỗi dữ liệu tạm thời?

Một field Java như:

~~~java
@Transient
private String validationMessage;
~~~

có thể chứa thông báo “Email hợp lệ” trong một request. Nó không phải đặc điểm của LDAP entry và không nên bị chuyển thành attribute. `@Transient` giúp tài liệu hóa chủ đích này.

Tuy nhiên, nếu ứng dụng sử dụng một mapper/`DirContextOperations` khác để trực tiếp ghi attribute `validationMessage`, annotation trên entity **không chặn được thao tác đó**.


## 7. Cập nhật entity: thay field transient không tạo LDAP update cho field đó

Giả sử entry Alice đã tồn tại trong directory:

~~~java
import javax.naming.Name;

Name dn = LdapNameBuilder.newInstance("ou=people")
        .add("uid", "alice")
        .build();

DirectoryPerson person =
        ldapTemplate.findByDn(dn, DirectoryPerson.class);

// Chỉ là hai thay đổi trên object Java:
person.setDisplayLabel("Preview: Alice");
person.setSelectedForExport(true);
~~~

Các dòng trên **không gửi thao tác LDAP Modify**. Nếu muốn sửa email đã được map:

~~~java
person.setEmail("alice.new@example.org");
ldapTemplate.update(person);
~~~

Khi `update(person)` dùng mapping ODM, `displayLabel` và `selectedForExport` **không được chuyển thành LDAP attributes**. Giá trị email được xử lý theo mapping và quy tắc cập nhật của ODM.

Tuy nhiên, **không nên suy rằng ODM chỉ gửi đúng một thay đổi cho email**. Cách công cụ xây yêu cầu cập nhật các field được map phụ thuộc API/phiên bản và cấu trúc entity. Với bài toán cần sửa đúng một attribute hoặc dùng optimistic concurrency, có thể chọn `LdapTemplate.modifyAttributes(dn, items)` và điều kiện LDAP thích hợp, thay vì mặc định một entity update có dirty tracking giống ORM quan hệ.

### 7.1. Đọc lại cho thấy dữ liệu tạm không tồn tại bền vững

~~~text
Object A sau findByDn:
  email = alice@example.org
  displayLabel = null

Thay đổi trên Object A:
  email = alice.new@example.org
  displayLabel = "Preview: Alice"

Gọi ldapTemplate.update(Object A):
  LDAP nhận update của các field được map
  LDAP không nhận field displayLabel

Object B mới sau findByDn:
  email = alice.new@example.org
  displayLabel = null (chưa được service tính/gán lại)
~~~

Đây là hành vi đúng cho một field tạm thời. Nếu cần giữ một giá trị qua nhiều lần đọc, phải thiết kế một attribute bền vững đúng schema hoặc một kho dữ liệu khác phù hợp.

### 7.2. @Transient không sửa xung đột đồng thời

Khoảng thời gian giữa `findByDn` và `update` cho phép client khác thay LDAP entry. `@Transient` không ngăn lost update, không tự khóa DN và không cung cấp transaction nhiều entry.

Nếu nhiều service cùng sửa hồ sơ, cần cân nhắc cập nhật mức attribute, LDAP Assertion Control khi server/provider hỗ trợ hoặc một cơ chế điều phối thích hợp. Không coi annotation này là optimistic locking.

### 7.3. Không đặt @Transient lên thông tin bắt buộc phải lưu

Ví dụ sau **sai ý định** nếu sản phẩm yêu cầu email tồn tại trong LDAP:

~~~java
// Sai nếu email là dữ liệu cần lưu và tra cứu trong directory:
@Transient
private String email;
~~~

Khi đọc lại, field có thể là null; khi tạo/cập nhật, dữ liệu email không được ODM ghi. Nếu `mail` cần persist, giữ mapping `@Attribute(name = "mail")` và giải quyết schema/ACL/validation đúng cách.

## 8. Cách chọn trường nên đánh dấu @Transient

Không có một quy tắc “field nào không xuất hiện trong LDIF thì luôn @Transient” áp dụng cho mọi mô hình. Hãy xét **quyền sở hữu, thời gian sống, người dùng và nguồn dữ liệu**.

| Field Java | Nguồn/ý nghĩa | Lựa chọn thường phù hợp |
| --- | --- | --- |
| `uid` | Định danh tài khoản LDAP | `@Attribute(name="uid")`, DN/RDN nhất quán |
| `commonName` | Tên thực trong LDAP | `@Attribute(name="cn")` |
| `email` | Email LDAP | `@Attribute(name="mail")` |
| `displayLabel` | Tính từ `cn` và `uid` | `@Transient` hoặc getter tính toán |
| `selectedForExport` | Checkbox của một request | `@Transient` hoặc chỉ đặt trong DTO/UI |
| `validationMessage` | Thông báo khi kiểm tra hồ sơ | `@Transient` hoặc response DTO riêng |
| `requestCorrelationId` | Tham chiếu log/job | Thường trong context/job DTO, không ở LDAP entity |
| `rolesShownByUi` | Thông tin tổng hợp từ nhóm/ACL | DTO riêng hoặc `@Transient` với quy tắc làm mới |
| `userPassword` | Dữ liệu xác thực nhạy cảm | Không tự đưa vào model UI; dùng quy trình credential chính thức |
| `entryUUID`, `createTimestamp` | Operational attrs do server quản lý | Không tự tạo/ghi như field business bình thường |

### 8.1. Không nhầm thuộc tính tính toán với attribute “ảo” của server

Một số directory server có operational/virtual attributes được tính bởi chính server. Chúng có thể xuất hiện trong LDAP Search tùy schema, quyền và returning attributes.

**`@Transient` là quyết định phía Java ODM**, không nói gì về việc server có hay không có một thuộc tính ảo hoặc operational attribute. Nếu ứng dụng cần đọc một attribute server cung cấp, hãy tìm đúng mapping/query và quyền truy cập, chứ không giả định “tính toán thì luôn không lưu”.

### 8.2. @Transient không phải cách “bỏ schema validation”

Nếu một field cần persist nhưng object class hiện tại không cho phép, đánh dấu `@Transient` sẽ làm mất dữ liệu khi đọc/ghi qua ODM. Giải pháp đúng có thể là chọn attribute thuộc schema, bổ sung auxiliary object class theo quy trình quản trị hoặc chuyển dữ liệu sang kho khác.

Không dùng `@Transient` để che một lỗi thiết kế dữ liệu dài hạn chỉ vì thao tác LDAP Add/Modify đang bị từ chối.

### 8.3. Tránh dùng transient để giữ trạng thái quyền truy cập lâu dài

Ví dụ `currentUserMayEdit` tính từ quyền của người đang đăng nhập hoặc ACL hiện tại. Nếu đặt trên entity dưới dạng transient, giá trị này chỉ đúng tại thời điểm đánh giá.

Không dùng một `Boolean` transient cũ để quyết định quyền ghi ở request sau. Phải **xác thực và ủy quyền lại** theo context hiện tại; LDAP server vẫn phải thực thi ACL.

## 9. Annotation tương tác ra sao với DTO và JSON?

Một entity ODM thường bị trả về từ service tới controller. Nếu controller trực tiếp trả object Java dưới dạng JSON, các getter của field `@Transient` **vẫn có thể bị JSON serializer đọc và gửi cho client**.

Ví dụ:

~~~java
@Transient
private String displayLabel;

public String getDisplayLabel() {
    return displayLabel;
}
~~~

`@Transient` của Spring LDAP chỉ điều khiển ODM. Nó **không có nghĩa** “ẩn khỏi HTTP response”.

### 9.1. Tách entity LDAP khỏi response DTO

Một lựa chọn rõ ràng là xây DTO:

~~~java
public record PersonResponse(
        String uid,
        String displayName,
        String email
) {
    public static PersonResponse from(DirectoryPerson person) {
        String label = person.getCommonName() + " ("
                + person.getUid() + ")";

        return new PersonResponse(
                person.getUid(),
                label,
                person.getEmail()
        );
    }
}
~~~

Với đoạn này, controller chỉ trả ba field đã chủ động chọn. Nếu tài khoản gọi API không được phép xem email, service còn phải **kiểm tra quyền** và bỏ email/không tạo DTO chứa email; chỉ chọn field trong record không thay thế authorization.

### 9.2. Khi cần ẩn dữ liệu khỏi JSON

Jackson có `@JsonIgnore` để bỏ một property khỏi JSON. Nhưng annotation này **không phải** Spring LDAP `@Transient`:

~~~java
import com.fasterxml.jackson.annotation.JsonIgnore;

@Transient
@JsonIgnore
private String internalPreviewToken;
~~~

Hai annotation phục vụ hai lớp mapping riêng: LDAP ODM và JSON. Vẫn cần đánh giá mức độ nhạy cảm của dữ liệu, logging, caching, authorization và vòng đời object. **Không lưu credential thật vào entity để dựa hoàn toàn vào annotation ẩn nó**.

### 9.3. Không dùng trực tiếp entity cho tất cả request/response

Nếu dùng chính entity ODM làm body của HTTP request, client có thể cố gửi các giá trị như DN, object classes hoặc các field giao diện rồi làm rối logic cập nhật. Sử dụng DTO riêng cho request, validate bằng Bean Validation và **map allowlist** sang những trường LDAP được phép ghi.

Thao tác `LdapTemplate.update` cần được service kiểm tra quyền người gọi, phạm vi OU và những field có thể thay. `@Transient` không phải một whitelist tổng quát cho API public.

## 10. Cấu hình ContextSource và truy cập directory an toàn

Giả sử dùng LDAPS, base DN `dc=example,dc=org` và tài khoản dịch vụ có quyền cần thiết:

~~~java
import org.springframework.beans.factory.annotation.Value;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.ldap.core.LdapTemplate;
import org.springframework.ldap.core.support.LdapContextSource;

@Configuration
public class LdapConfiguration {

    @Bean
    public LdapContextSource ldapContextSource(
            @Value("${app.ldap.url}") String url,
            @Value("${app.ldap.base}") String base,
            @Value("${app.ldap.bind-dn}") String bindDn,
            @Value("${app.ldap.bind-password}") String password) {

        LdapContextSource source = new LdapContextSource();
        source.setUrl(url);
        source.setBase(base);
        source.setUserDn(bindDn);
        source.setPassword(password);
        return source;
    }

    @Bean
    public LdapTemplate ldapTemplate(
            LdapContextSource ldapContextSource) {
        return new LdapTemplate(ldapContextSource);
    }
}
~~~

~~~yaml
# application.yml (LDAP test, secrets từ môi trường)
app:
  ldap:
    url: ${LDAP_URL:ldaps://ldap.example.org:636}
    base: dc=example,dc=org
    bind-dn: ${LDAP_BIND_DN}
    bind-password: ${LDAP_BIND_PASSWORD}
~~~

Nhóm `app.ldap.*` do ứng dụng ví dụ tự định nghĩa. Nếu dùng Spring Boot auto-configuration, các property phổ biến là `spring.ldap.urls`, `spring.ldap.base`, `spring.ldap.username` và `spring.ldap.password` theo phiên bản/dependency.

Cần lưu ý:

- **LDAPS:** xác minh chain chứng chỉ và hostname, không tắt SSL validation để cho demo chạy.
- **StartTLS:** nếu dùng `ldap://`, phải nâng cấp TLS thật trước khi gửi simple-bind password; URL `ldap://` không tự bật StartTLS.
- **Reader/editor identities:** chức năng tra cứu không cần quyền ghi; chức năng tạo/cập nhật phải có quyền tối thiểu phù hợp trên OU.
- **Schema/ACL:** server quyết định field nào có thể lưu và ai có quyền thao tác. `@Transient` không làm thay đổi quyền.
- **Pooling:** có thể giảm chi phí kết nối nhưng không thay đổi mapping, schema hay authorization; cần kiểm soát context lifecycle và bind identity khi dùng pool.

Nếu công cụ cấu hình Spring đang dùng auto-wire các bean khác nhau cho reader/editor, cần `@Qualifier` hoặc cơ chế lựa chọn bean rõ ràng. Không dùng nhầm tài khoản admin chỉ để sửa một email.

## 11. Những sai lầm phổ biến và cách khắc phục

| Sai lầm | Hậu quả | Cách làm đúng |
| --- | --- | --- |
| Import nhầm JPA `@Transient` | ODM không nhất thiết bỏ field như mong đợi | Dùng đúng `org.springframework.ldap.odm.annotations.Transient` |
| Chỉ dùng từ khóa Java `transient` | Trộn ý nghĩa serialization và LDAP mapping | Dùng annotation ODM |
| Tin field transient được tự khôi phục sau `findByDn` | Field null/default, logic nghiệp vụ sai | Tính lại hoặc enrich ở service |
| Đánh dấu `@Transient` lên email cần lưu | Email không được ODM persist | Dùng `@Attribute(name="mail")` |
| Nghĩ annotation sẽ xóa attribute LDAP đang có | Server vẫn có thể giữ attribute | Có quy trình Modify/migration riêng |
| Nghĩ annotation ngăn `modifyAttributes` | Raw LDAP API vẫn có thể ghi | Tách API, kiểm soát ACL/allowlist |
| Nghĩ transient field bị ẩn khỏi JSON | Có thể bị serialize qua getter | DTO, `@JsonIgnore` và authorization |
| Để password hoặc token trong transient field rồi log entity | Rò rỉ dữ liệu nhạy cảm | Không giữ secrets không cần thiết, redaction |
| Chỉ test object Java, không test LDAP | Không phát hiện mapping/schema/ACL thật | Integration test trên directory riêng |
| Dùng field transient để nhớ “đã xác thực” qua request | State không bền, có thể stale | Xác thực/ủy quyền đúng từng thao tác |
| Gọi `update(entity)` và giả định chống lost update | Có thể ghi đè dữ liệu đồng thời | Condition/assertion hoặc update có kiểm soát |

### 11.1. Tránh đặt annotation mâu thuẫn

Không nên dùng cùng một field:

~~~java
@Attribute(name = "mail")
@Transient
private String email;
~~~

Hai annotation thể hiện mục đích đối lập: một bên yêu cầu ánh xạ, bên kia yêu cầu bỏ qua. Dù có phiên bản ODM xử lý theo thứ tự xác định, code sẽ khó hiểu và dễ lỗi khi nâng cấp. Chọn **một hợp đồng duy nhất** phù hợp nghiệp vụ.

### 11.2. Chú ý việc dùng Lombok và kế thừa entity

Lombok có thể sinh getter/setter, nhưng annotation ODM trên **field** phải được giữ đúng vị trí. Khi entity kế thừa nhiều lớp hoặc dùng record/final field, hãy kiểm tra cách ODM của phiên bản đang dùng khám phá constructor, field và hierarchy. Không giả định mọi thư viện reflection có cùng quy tắc.

Cách đơn giản để học và debug là entity có constructor không tham số, field rõ ràng và annotation được đặt trên field như ví dụ.

## 12. Unit test: bảo đảm metadata đúng và không nhầm import

Đầu tiên, kiểm tra những field muốn loại đã gắn **đúng annotation ODM**:

~~~java
import java.lang.reflect.Field;

import org.junit.jupiter.api.Test;
import org.springframework.ldap.odm.annotations.Attribute;
import org.springframework.ldap.odm.annotations.Transient;

import static org.junit.jupiter.api.Assertions.*;

class DirectoryPersonMappingTest {

    @Test
    void uiOnlyFieldsAreMarkedTransient() throws Exception {
        Field label = DirectoryPerson.class
                .getDeclaredField("displayLabel");
        Field selected = DirectoryPerson.class
                .getDeclaredField("selectedForExport");

        assertTrue(label.isAnnotationPresent(Transient.class));
        assertTrue(selected.isAnnotationPresent(Transient.class));

        assertFalse(label.isAnnotationPresent(Attribute.class));
        assertFalse(selected.isAnnotationPresent(Attribute.class));
    }

    @Test
    void persistentEmailHasAttributeMapping() throws Exception {
        Field email = DirectoryPerson.class
                .getDeclaredField("email");

        assertTrue(email.isAnnotationPresent(Attribute.class));
        assertFalse(email.isAnnotationPresent(Transient.class));
        assertEquals("mail",
                email.getAnnotation(Attribute.class).name());
    }
}
~~~

Test này kiểm tra code Java và annotation package, **không** chứng minh LDAP server nhận hay bỏ qua field trên thực tế. Nó giúp phát hiện nhanh trường hợp import nhầm annotation hoặc refactor vô tình làm field persistent thành transient.

### 12.1. Test việc enrich sau khi đọc

Một unit test khác có thể khởi tạo `DirectoryPerson`, đặt `uid`/`commonName` rồi chạy hàm enrich thuần Java:

~~~java
import org.junit.jupiter.api.Test;
import static org.junit.jupiter.api.Assertions.*;

class DisplayLabelTest {

    @Test
    void labelIsComputedFromMappedFields() {
        DirectoryPerson person = new DirectoryPerson();
        person.setUid("alice");
        person.setCommonName("Alice Nguyen");

        person.setDisplayLabel(
                person.getCommonName() + " (" + person.getUid() + ")");

        assertEquals("Alice Nguyen (alice)",
                person.getDisplayLabel());
    }
}
~~~

Điều này chỉ chứng minh công thức tạo nhãn. Không có LDAP operation, nên test không nên được diễn giải thành “transient đã không lưu trên server”.

## 13. Integration test: tạo, đọc lại và xác minh field transient

Kiểm thử tích hợp cần LDAP server **riêng cho test**, schema `inetOrgPerson` thích hợp, OU `ou=people` đã được tạo, credentials editor/reader và TLS hợp lệ.

Một khung test:

~~~java
import javax.naming.Name;

import org.junit.jupiter.api.Test;
import org.springframework.ldap.core.DirContextOperations;
import org.springframework.ldap.core.LdapTemplate;
import org.springframework.ldap.support.LdapNameBuilder;

import static org.junit.jupiter.api.Assertions.*;

class OdmTransientIntegrationTest {

    private final LdapTemplate ldapTemplate;

    // Fixture/Spring Test của dự án cung cấp LdapTemplate.
    OdmTransientIntegrationTest(LdapTemplate ldapTemplate) {
        this.ldapTemplate = ldapTemplate;
    }

    @Test
    void createDoesNotPersistUiOnlyFields() {
        Name dn = LdapNameBuilder.newInstance("ou=people")
                .add("uid", "odm-transient-test-01")
                .build();

        DirectoryPerson person = new DirectoryPerson();
        person.setDn(dn);
        person.setUid("odm-transient-test-01");
        person.setCommonName("ODM Transient Test");
        person.setSurname("Test");
        person.setEmail("odm-transient-test-01@example.org");
        person.setDisplayLabel("LOCAL ONLY");
        person.setSelectedForExport(true);

        boolean created = false;
        try {
            ldapTemplate.create(person);
            created = true;

            DirContextOperations saved =
                    ldapTemplate.lookupContext(dn);

            assertEquals("odm-transient-test-01",
                    saved.getStringAttribute("uid"));
            assertNull(saved.getStringAttribute("displayLabel"));
            assertNull(saved.getStringAttribute("selectedForExport"));

            DirectoryPerson loaded =
                    ldapTemplate.findByDn(
                            dn, DirectoryPerson.class);

            assertNull(loaded.getDisplayLabel());
            assertFalse(loaded.isSelectedForExport());
        } finally {
            if (created) {
                // Chỉ dọn entry do chính test tạo.
                ldapTemplate.unbind(dn);
            }
        }
    }
}
~~~

**Đây là khung test**: Spring Test/fixture còn phải inject template, khởi tạo dữ liệu và bảo đảm DN riêng cho mỗi ca. Nếu Add thành công nhưng response bị mất, cờ `created` không phản ánh chắc trạng thái server; khi cleanup cần thêm bước xác minh sở hữu. Không chạy test tạo/xóa trên dữ liệu production.

Ví dụ kiểm tra hai field tên `displayLabel`/`selectedForExport` không được ghi. Chúng không phải attribute của schema ví dụ; server sẽ từ chối nếu ODM vô tình gửi sai. Để kiểm chứng loại trừ một attribute **được schema cho phép**, có thể dùng một fixture riêng gắn `@Transient` lên field đặt tên trùng một attribute MAY hợp lệ như `description`, sau đó kiểm tra server không nhận giá trị đó. Tránh thay đổi model nghiệp vụ chỉ để chạy test này.

### 13.1. Test cập nhật không ghi field transient

Với một entry test đã có:

~~~java
DirectoryPerson person =
        ldapTemplate.findByDn(dn, DirectoryPerson.class);

person.setDisplayLabel("new local label");
person.setSelectedForExport(true);
person.setEmail("after@example.org");

ldapTemplate.update(person);

DirContextOperations after = ldapTemplate.lookupContext(dn);
assertEquals("after@example.org",
        after.getStringAttribute("mail"));
assertNull(after.getStringAttribute("displayLabel"));
~~~

Các biến `dn`, `ldapTemplate` và `assert...` nằm trong context của test fixture. Test nên đảm bảo email ban đầu khác giá trị mới, server cho phép sửa mail và entry còn thuộc quyền của test. Nếu ODM update chạm các field khác, cần kiểm tra trạng thái không bị mất ngoài ý muốn.

### 13.2. Ma trận kiểm thử nên có

| Ca | Điều kiện | Kết quả mong đợi |
| --- | --- | --- |
| Entity field `@Transient` có giá trị trước Create | Tạo entry ODM | Không xuất hiện attribute transient |
| ODM findByDn một entry đã tồn tại | Field chưa được service enrich | Transient null/default |
| Service gán transient | Object Java hiện tại | Giá trị được giữ trong object đó |
| Đọc entity lần hai | Nạp object mới từ LDAP | Không khôi phục transient đã gán trước |
| ODM update một field persistent | Mail thay đổi | LDAP phản ánh mail mới, transient không được ghi |
| Annotation import nhầm JPA | Unit metadata test | Phát hiện thiếu Spring LDAP annotation |
| Field `@Attribute` bắt buộc bị xóa mapping | Unit/integration | Cần phát hiện lỗi schema/dữ liệu |
| Raw `modifyAttributes` ghi field khác | Không đi qua ODM | Annotation không ngăn thao tác thủ công |
| Reader không được đọc mail | ACL hạn chế | Không suy field null là server không lưu |
| Reader cố Create/Update | ACL chỉ đọc | Server từ chối |
| TLS certificate sai | Truststore/hostname sai | Kết nối thất bại an toàn |
| Two clients update cùng entry | Concurrency test | Không giả định transient ngăn lost update |

## 14. Những gì @Transient không bảo đảm về bảo mật và vòng đời

**Không ghi vào LDAP** chỉ là một phần của bảo vệ dữ liệu. Một field transient vẫn có thể:

- Xuất hiện trong log khi gọi `toString()` hoặc logger ghi object.
- Được Jackson đưa vào JSON nếu có getter và cấu hình serializer tương ứng.
- Nằm trong RAM, cache ứng dụng hoặc dump bộ nhớ.
- Được truyền sang queue/database khác bởi code không dùng ODM.
- Được đọc và tái sử dụng dù đã lỗi thời.

Vì vậy, không đặt thông tin xác thực hoặc token nhạy cảm vào entity rồi coi `@Transient` là đủ. Nếu thật sự cần xử lý dữ liệu nhạy cảm, cần thiết kế retention, redaction, authorization, mã hóa và lifecycle tương ứng.

### 14.1. @Transient không thay đổi quyền LDAP

LDAP server quyết định quyền đọc/ghi theo bind identity, DN, ACL và thuộc tính. Một tài khoản reader không được phép cập nhật `mail` dù field email không transient. Ngược lại, một tài khoản editor có quyền có thể sửa attribute `description` trực tiếp bằng `LdapTemplate.modifyAttributes`, không bị annotation của class khác cấm.

### 14.2. @Transient không thay đổi dữ liệu đã lưu trước đó

Nếu server đang có một attribute và bạn sửa entity Java để đánh dấu field tương ứng `@Transient`, LDAP entry **không tự xóa giá trị cũ**. Để di chuyển/loại bỏ dữ liệu đã có, cần quy trình migration/Modify được phê duyệt, bao gồm backup, ACL, schema và kiểm tra downstream clients.

Không triển khai đổi annotation rồi tự công bố rằng dữ liệu nhạy cảm đã được xóa khỏi toàn bộ directory, backup và replica.

## 15. Bài thực hành: mô hình hóa dữ liệu bền vững và dữ liệu tạm thời

**Bối cảnh:** một trang quản trị cho phép tra cứu hồ sơ LDAP, hiển thị nhãn dạng `"Tên (uid)"`, đánh dấu những user sẽ được xuất báo cáo và cập nhật email khi có quyền.

1. Chuẩn bị LDAP directory test có `ou=people`, schema `inetOrgPerson` và một entry thử nghiệm do bài học sở hữu.
2. Tạo class `DirectoryPerson` với `@Entry`, `@Id`, `@Attribute` cho `uid`, `cn`, `sn`, `mail`.
3. Thêm `@Transient` cho `displayLabel` và `selectedForExport`. Giải thích vì sao hai field không thuộc dữ liệu LDAP.
4. Dựng DN bằng `LdapNameBuilder`, phân biệt DN tương đối với `ContextSource.base` và DN đầy đủ.
5. Dùng `LdapTemplate.findByDn` nạp entity, kiểm tra field transient chưa được enrich.

### Câu hỏi tự kiểm tra

## 16. Tổng kết

**`@Transient` trong Spring LDAP ODM** là annotation dùng để **loại một field khỏi việc ánh xạ entity ↔ LDAP attribute**. Nó giúp mô hình Java chứa được thông tin giao diện, trạng thái tạm thời hoặc kết quả tính toán mà không biến chúng thành dữ liệu bền vững của directory.

Khi dùng `@Entry`, `@Id` và `@Attribute`, hãy xác định rõ đâu là dữ liệu cần lưu theo DN/schema và đâu là field tạm thời cần `@Transient`. Các thao tác `LdapTemplate.create`, `findByDn` và `update` qua ODM sẽ tuân mapping, nhưng annotation này **không** thay thế JSON serialization control, validation, schema, ACL, TLS, concurrency hay các đường LDAP raw API. Kết hợp **DTO rõ ràng, quyền tối thiểu, kiểm thử mapping và integration test** sẽ giúp tránh ghi nhầm dữ liệu tạm thời vào thư mục, đồng thời giữ model dễ hiểu và có thể bảo trì.
