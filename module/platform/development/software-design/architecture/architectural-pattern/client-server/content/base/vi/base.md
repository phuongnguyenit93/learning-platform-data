# Software Design Architecture Architectural Pattern Client Server

Client–Server là mẫu kiến trúc phân chia trách nhiệm giữa **client**, thành phần khởi tạo yêu cầu sử dụng dịch vụ, và **server**, thành phần tiếp nhận, xử lý yêu cầu rồi cung cấp dữ liệu hoặc kết quả. Một ứng dụng có thể sử dụng trình duyệt, ứng dụng di động hay chương trình khác làm client; server thường đảm nhiệm logic nghiệp vụ, kiểm soát truy cập và tương tác với hệ thống lưu trữ. Hai phía giao tiếp qua giao thức có hợp đồng rõ ràng, phổ biến là HTTP. Mẫu Client–Server mô tả mối quan hệ cung cấp dịch vụ, không đồng nghĩa bắt buộc toàn hệ thống chỉ có hai tiến trình hay hai máy chủ.

Roadmap một cấp gồm tám mốc: nhận diện vai trò client và server; theo dõi chu kỳ request–response; xây dựng hợp đồng API; xác định trạng thái phiên và quyền sở hữu dữ liệu. Tiếp đó, người học so sánh cách triển khai hai tầng với nhiều tầng, xem xét reverse proxy, khả năng phục vụ đồng thời, caching và mở rộng quy mô. Các mốc cuối tập trung vào ranh giới bảo mật, kiểm soát lỗi mạng, kiểm thử API và đánh giá điểm mạnh, giới hạn của mô hình. Khi triển khai thực tế, client không được xem là nguồn đáng tin cậy cho xác thực dữ liệu hoặc phân quyền; server vẫn phải kiểm tra mọi yêu cầu quan trọng.

Module phù hợp với developer, QA engineer hoặc người mới học thiết kế hệ thống đã có kiến thức HTTP và lập trình ứng dụng cơ bản. Sau khi hoàn thành, bạn có thể vẽ sơ đồ Client–Server, giải thích vì sao mỗi thành phần chịu trách nhiệm cho một loại dữ liệu hoặc thao tác, thiết kế API nhỏ có kiểm soát lỗi, nhận diện điểm nghẽn và chọn các cải tiến phù hợp mà không làm mô hình trở nên phức tạp quá mức.
